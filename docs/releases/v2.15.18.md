# Looper v2.15.18

This release documents the changes merged since v2.15.17: agent runtimes are chosen only through configuration ([#1417](https://github.com/foolzzz/looper/pull/1417)), task ends are recorded as completion events ([#1431](https://github.com/foolzzz/looper/pull/1431)), and a test-only fix for the parallel Lark message read tests ([#1429](https://github.com/foolzzz/looper/pull/1429)). No new capability is switched on: the completion events change nothing that is sent, and the runtime change only removes a check that was not needed.

## Release Decision

**Who should upgrade:** Anyone who runs Looper without Claude Code (for example with Codex or Pi profiles only) and was blocked or warned by the Claude Code checks, and anyone who registered a Pi runtime with its own executable. Everyone else can stay on v2.15.17; nothing changes for them except one additive database migration.

**What this release solves:** `looper doctor`, the startup checks and `system/status` no longer require the Claude Code CLI and login unless an Agent Profile in use runs on Claude Code. The Pi runner starts the executable of the Pi runtime in use instead of `pi` from PATH. Each task end is now recorded with the notice it stands for (the groundwork for a later release), and a replayed bus message no longer sends a second task-end notice.

**Breaking changes:** No. No API field is removed or changed. There is one additive PostgreSQL migration (see Upgrading). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.18
```

**Contributors:** Maintainer @foolzzz authored [#1417](https://github.com/foolzzz/looper/pull/1417), [#1429](https://github.com/foolzzz/looper/pull/1429) and [#1431](https://github.com/foolzzz/looper/pull/1431); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.17 upgrades directly. Restart the service after upgrading, as for every release.

This release has one additive PostgreSQL migration, applied once at startup:

- `manager_events`: creates the `manager_events` table with its indexes. It is DDL only and changes no row. The table fills as tasks end.

## Behavior changes

### Agent runtimes are chosen only through configuration ([#1417](https://github.com/foolzzz/looper/pull/1417))

- `looper doctor`, the startup checks and `system/status` check the Claude Code CLI and login only while an Agent Profile in use runs on a Claude Code runtime. "In use" covers a profile selected by any layer (system, role, project, task, the Planner's, Manager, session and schedule choices), a task role or template, a workflow preset's profiles, a project's allow-list, the profiles they fall back to, and the built-in `claude-code/opus` while the system layer and some role have no profile of their own. With none in use, both checks are skipped and "Agents cannot run" is no longer logged. With one in use, results and messages are unchanged. If the profiles cannot be read, Claude Code is checked as before.
- `system/status` re-runs the Claude Code probes when the profiles in use flip between "none uses Claude Code" and "one does". A project's empty allow-list (the Planner may choose any profile) does not count as Claude Code being in use; a launch that later picks a Claude Code profile fails with the usual clear message.
- The Pi runner starts the executable of the Pi runtime that the profiles in use launch (`pi` on PATH when none is in use or the registry cannot be read). In-use Pi runtimes with different executables stop the start with a message naming them.
- Real-mode evals require the `claude` binary only when a Claude Code agent runs. New flags: `lark_quote` `--agent` / `--register-agent`, `stop_realpath` `--register-agent` and `--claude-model`, `dsh_consult_replay` `--model` / `--effort`. Each default is the previous fixed choice.
- Unchanged: the built-in `claude-code/opus` default profile, model catalogs and prices, and the built-in `rt-claude-code` runtime, which still runs `claude` from PATH. The DSH runner pool still resolves `dsh` from PATH.

### Task ends are recorded as completion events ([#1431](https://github.com/foolzzz/looper/pull/1431))

- **Nothing sent changes.** The migration `manager_events` adds a table. A row is written for each task end that produces a notice: the Manager's task-end handler (dashboard chat, direct chat, group; only `completed` and `failed`) and a scheduled run's message that is sent to a chat. Every row is recorded as `skipped` with reason `off`, the notice is sent as before and `sent_at` is set. Runs whose message is not sent, and schedules without a chat target, record nothing. A database write failure is logged and the notice is sent anyway. There is no setting to turn on yet; the completion turn that would replace the notice is a later release.
- A replay of the same bus message (or scheduled run) records one row and sends nothing, unless `sent_at` is empty, in which case the notice is retried. Before, a replayed message sent a second notice.
- Housekeeping deletes events older than 30 days; deleting a task or purging a Manager removes its events.
- New operator-only operation `manager_events.summary` (`POST /api/v1/manager_events/summary`): counts of the last 24 hours by state and reason.
- No prompt, tool list or agent command line changes.

### Tests ([#1429](https://github.com/foolzzz/looper/pull/1429))

- The two parallel Lark message read tests no longer depend on how long a process takes to start; they record each call as Looper starts it. No production code changed.

**谁需要升级：**不用 Claude Code（例如只用 Codex 或 Pi 档案）、被 Claude Code 检查拦住或告警的用户，以及注册了自带可执行文件的 Pi 运行时的用户。其他用户可以留在 v2.15.17；除一个可加的数据库迁移外没有变化。

**是否有破坏性变更：**无。没有删除或修改 API 字段，有一个可加的 PostgreSQL 迁移（见升级）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.15.17 上的安装可直接升级。升级后照常重启服务。

本版本有一个可加的 PostgreSQL 迁移，启动时执行一次：

- `manager_events`：创建 `manager_events` 表及其索引，只有 DDL，不改任何行；表随任务结束逐步写入。

### 行为变化与入口

**agent 运行时只经配置选择（[#1417](https://github.com/foolzzz/looper/pull/1417)）**

- `looper doctor`、启动自检和 `system/status` 只在在用的 Agent Profile 运行于 Claude Code 运行时才检查 Claude Code CLI 和登录。「在用」包括任一层（系统、角色、项目、任务、Planner、Manager、会话、定时任务）选中的档案、任务角色和模板、工作流预设的档案、项目的允许列表、它们的回退档案，以及系统层与某个角色都没配档案时的内置 `claude-code/opus`。没有在用时两项检查跳过，不再记「Agents cannot run」；有在用时结果和信息不变；读不到档案时仍按原样检查 Claude Code。
- 在用档案在「无人用 Claude Code」和「有人用」之间切换时，`system/status` 会重新探测。项目的允许列表为空（Planner 可选任意档案）不算在用；之后选到 Claude Code 档案的启动会以通常的清晰信息失败。
- Pi runner 启动在用档案所用的 Pi 运行时的可执行文件（没有在用档案或读不到注册表时用 PATH 里的 `pi`）；在用的 Pi 运行时可执行文件不一致时，启动会停下并指出它们。
- 真实模式评测只在运行 Claude Code agent 时才要求 `claude`。新增参数：`lark_quote` 的 `--agent` / `--register-agent`，`stop_realpath` 的 `--register-agent` 和 `--claude-model`，`dsh_consult_replay` 的 `--model` / `--effort`；默认值都是原来的固定选择。
- 不变：内置默认档案 `claude-code/opus`、模型目录与价格、内置 `rt-claude-code` 运行时（仍从 PATH 运行 `claude`）；DSH runner 池仍从 PATH 解析 `dsh`。

**任务结束作为完成事件入库（[#1431](https://github.com/foolzzz/looper/pull/1431)）**

- **发送内容不变。**迁移 `manager_events` 新增一张表。产生通知的任务结束各写一行：Manager 的任务结束处理（dashboard 聊天、私聊、群聊，只记 `completed` 和 `failed`）以及发到聊天的定时任务运行消息。每行记为 `skipped`、原因 `off`，通知照旧发送并记 `sent_at`。不发送的运行消息和没有聊天目标的定时任务不记录。写库失败只记日志，通知照发。目前没有可打开的设置；用完成回合替换通知是后续版本的事。
- 同一总线消息（或定时任务运行）的重放只记一行且不发送；`sent_at` 为空时重试通知。此前重放会再发一条通知。
- housekeeping 删除 30 天前的事件；删除任务或清理 Manager 时一并删除它们的事件。
- 新增仅限操作员的操作 `manager_events.summary`（`POST /api/v1/manager_events/summary`）：最近 24 小时按状态和原因的计数。
- 没有改动提示词、工具列表和 agent 命令行。

**测试（[#1429](https://github.com/foolzzz/looper/pull/1429)）**

- 两个并行读取飞书消息的测试不再依赖进程启动耗时，改为在 Looper 启动调用时记录。生产代码未改动。
