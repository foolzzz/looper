# Looper v2.14.184

This is the patch release v2.14.184, a hotfix line in which each merged change ships at once. It documents one change: [#1333](https://github.com/foolzzz/looper/pull/1333) (`system.status` answers from cached check state).

## Release Decision

**Who should upgrade:** Operators whose dashboard or API clients poll `system.status` (`/api/v1/system/status`) on a loaded machine, where a slow login probe, proxy health probe or storage scan could make the call take many seconds.

**What this release solves:** [#1333](https://github.com/foolzzz/looper/pull/1333) is part of the API latency series (every API operation under 2 s). `system.status` no longer waits for the Codex login probe, the local proxy health probe or the recorded-request storage scan: it answers from the last known check results and refreshes them in the background.

**Breaking changes:** No. The Telegram and Lark channel protocols, the dashboard and the CLI are unchanged, and there is no database change. The `system.status` response keeps its shape; only the freshness and the wording of some check results change (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.184
```

**Contributors:** Maintainer @foolzzz authored [#1333](https://github.com/foolzzz/looper/pull/1333); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.183 upgrades directly. There is no database change.

## Behavior changes

Read in the diff of [#1333](https://github.com/foolzzz/looper/pull/1333) (`looper/agents/http_server.py`, `looper/agents/self_check.py`, `looper/agents/runtimes/codex_login.py`, `looper/agents/llmrec/control.py` and tests). The PR description calls the behavior changes intended (a maintainer decision).

- **Check refresh in `system.status`** (`looper/agents/http_server.py`, `_checks_now`). Each login or proxy check is refreshed by its own task, kept in `_check_tasks` and shared across polls. The poll waits at most 1 s for it through `asyncio.shield`, so a timeout or a client disconnect does not cancel the refresh. A check still running after 1 s returns its previous result (or the startup snapshot) with " (still checking)" appended to the detail, and a warning is logged. A check that raises returns its last result and is logged. A startup snapshot that has nothing to refresh is returned without any work. Before, the poll awaited every check to completion.
- **Codex login** (`looper/agents/runtimes/codex_login.py`, `looper/agents/self_check.py`). A new `cached_status` returns the last `codex login status` answer at once and starts one daemon thread to refresh a stale answer (30 s TTL, one refresh at a time). `cached_probe` still waits for a current answer and shares that refresh through a lock; `forget_probe` takes the same lock. The Codex check no longer runs in an executor thread. The coco and Cursor checks already had a `cached_status` (unchanged by this PR) and now use it too.
- **First answer is "checking"** (`looper/agents/self_check.py`). When no probe result exists yet, the Codex, coco and Cursor login checks report status `pending` with detail "checking" instead of blocking until the probe returns. The next poll shows the probe result.
- **Proxy health** (`looper/agents/llmrec/control.py`, `self_check.py`). `ProxyControl.status` and `_health` take `cached`. A cached read returns the last health if it is under 15 s old (before: 5 s, then a live probe) and otherwise `None`; it never probes processes or HTTP. The recording and gateway checks use it with one proxy status read per poll, shared by both. The startup check (`run_checks`) passes `cached=False` and still reads live state, so a gateway auth failure is reported live at startup but from cached health in `system.status`.
- **Recorded-request storage** (`looper/agents/self_check.py`, `_llmrec_storage`). The stored size and cap are cached for 60 s per database pool, and one scan is shared across polls and is not cancelled by a request timeout. The live path (a direct database URL, `cached=False`) is not cached.
- **Tests** (`tests/test_system_status_cached.py` new, 292 lines; edits in `tests/test_gateway_self_check.py`, `tests/test_cursor_login.py`, `tests/test_api_v1_llm_requests_db.py`, `tests/test_proc_tree.py`). The new file covers slow probes, the 1 s budget, no duplicate or cancelled refreshes, cached proxy status never falling back to process or HTTP, shared login probes, storage expiry, the HTTP operation and recovery after a failed check. In `tests/test_proc_tree.py`, the refresh-cancel test now avoids probing a synthetic pid and sets the fake agent's return code (a stub change; no production code).
- **Model-visible changes:** No. No prompt, tool description or tool schema changed. The `system.status` check results (status `pending` and the "checking" and "(still checking)" details, possibly older proxy and storage figures) are API and dashboard output, not model input.

**谁需要升级：**仪表盘或 API 客户端会轮询 `system.status`（`/api/v1/system/status`）的运维人员；在高负载机器上，慢速的登录探测、代理健康探测或存储扫描曾使该调用耗时数秒。

**是否有破坏性变更：**无。Telegram 与 Lark 渠道协议、仪表盘和 CLI 均不变，没有数据库变更。`system.status` 响应结构不变，只有部分检查结果的新鲜度和措辞改变（见下）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

### 行为变化与入口

以下在 [#1333](https://github.com/foolzzz/looper/pull/1333) 的差异中可见（`looper/agents/http_server.py`、`looper/agents/self_check.py`、`looper/agents/runtimes/codex_login.py`、`looper/agents/llmrec/control.py` 及测试）。PR 描述称这些行为变化是有意的（维护者决定）。

- **`system.status` 中的检查刷新**（`looper/agents/http_server.py`，`_checks_now`）。每个登录或代理检查由各自的任务刷新，任务保存在 `_check_tasks` 中并在多次轮询间共享。轮询通过 `asyncio.shield` 最多等待 1 秒，因此超时或客户端断开不会取消刷新。超过 1 秒仍在运行的检查返回其上一次结果（或启动快照），并在详情后追加 “ (still checking)”，同时记录一条警告。抛出异常的检查返回其最后结果并记录日志。无需刷新的启动快照不做任何工作直接返回。此前轮询会等待所有检查完成。
- **Codex 登录**（`looper/agents/runtimes/codex_login.py`、`looper/agents/self_check.py`）。新增 `cached_status`，立即返回最近一次 `codex login status` 的结果，并启动一个守护线程刷新过期结果（30 秒 TTL，同一时间只有一个刷新）。`cached_probe` 仍等待当前结果并通过锁共享该刷新；`forget_probe` 使用同一把锁。Codex 检查不再在执行器线程中运行。coco 与 Cursor 检查本来就有（本 PR 未改动的）`cached_status`，现在也改用它。
- **首次答复为“checking”**（`looper/agents/self_check.py`）。尚无探测结果时，Codex、coco 和 Cursor 登录检查报告状态 `pending`、详情 “checking”，而不是阻塞到探测返回；下一次轮询会显示探测结果。
- **代理健康**（`looper/agents/llmrec/control.py`、`self_check.py`）。`ProxyControl.status` 与 `_health` 增加 `cached` 参数。缓存读取在最近的健康数据不足 15 秒时返回它（此前为 5 秒，之后做实时探测），否则返回 `None`；绝不探测进程或 HTTP。记录与网关检查使用它，每次轮询只读取一次代理状态，两者共享。启动检查（`run_checks`）传入 `cached=False`，仍读取实时状态，因此网关认证失败在启动时是实时报告的，而在 `system.status` 中来自缓存的健康数据。
- **已记录请求的存储**（`looper/agents/self_check.py`，`_llmrec_storage`）。已存储大小和上限按数据库连接池缓存 60 秒，一次扫描在多次轮询间共享，且不会被请求超时取消。实时路径（直接数据库 URL、`cached=False`）不缓存。
- **测试**（新增 `tests/test_system_status_cached.py`，292 行；修改 `tests/test_gateway_self_check.py`、`tests/test_cursor_login.py`、`tests/test_api_v1_llm_requests_db.py`、`tests/test_proc_tree.py`）。新文件覆盖慢速探测、1 秒预算、不重复且不被取消的刷新、缓存的代理状态不回退到进程或 HTTP、共享的登录探测、存储过期、HTTP 操作，以及检查失败后的恢复。`tests/test_proc_tree.py` 中 refresh-cancel 测试现在避免探测合成 pid，并设置假 agent 的返回码（仅测试桩，不涉及生产代码）。
- **面向模型的变化：**无。提示词、工具描述和工具 schema 均未改变。`system.status` 的检查结果（状态 `pending`、详情 “checking” 与 “(still checking)”、可能较旧的代理与存储数据）属于 API 和仪表盘输出，不是模型输入。
