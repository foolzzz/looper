# Looper v2.13.55

## Release Decision

**Who should upgrade:** Operators who use `loopercli`, in particular those who paste tokens on its command line or interrupt a chat with Ctrl-C. Maintainers who run the prompt-regression evals or the test suite also gain the guard fixes. Nobody else needs to act.

**What this release solves:** [#448](https://github.com/foolzzz/looper/pull/448) fixes the open review follow-ups of `loopercli` and the eval and test guards (#425, #369, #413, #417): `loopercli` no longer echoes a token in its error output, an interrupted chat turn keeps its conversation id, and the stop and start checks of the prompt-regression dialogs are stricter and more exact.

**Breaking changes:** No. No existing API, configuration or stored data changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#448](https://github.com/foolzzz/looper/pull/448); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.55
```

## Behavior changes

- **Token hidden in every `loopercli` error (`looper/loopercli.py`):** a new `_print_error` replaces any `lpc_…` token in an error message with `lpc_…` before it is written to stderr. It now covers error answers from the server, the "stream ended without a reply" error, the over-long message error in interactive chat, and `CliError` raised in `main`. Before, only argparse usage errors hid it. The global option parser is now the same `Parser` class, and `main` parses the global options inside its error handling, so a token mistaken for an option value (for example `login lpc_…`, `--json=lpc_…`, `chat --file lpc_…`) is not echoed there either.
- **Interrupted chat keeps its conversation (`looper/loopercli.py`):** a Ctrl-C while a reply streams now carries the turn on the interrupt, and interactive chat takes the conversation id from it. The next message continues that conversation and the "stopped reading" hint names it, instead of starting a new conversation when the interrupt came before the first reply finished.
- **Eval stop dialog (`evals/prompt_regression/dialogs.py`):** the claim check "the reply claims the summary was finished" no longer treats "还没有真正查询…" style replies (an offer to do the work) as a claim, and only the words 没/还没/未 with a not-done meaning excuse a reply.
- **Eval start-without-waiting check (`evals/prompt_regression/dialogs.py`):** the check reads tool calls through the Manager's own `_looper_call` (so wrapped calls such as `use_tool` count), and anchors on the first start the trail shows as `ok`, so a refused retry does not move it.
- **Tests (`tests/test_loopercli.py`, `tests/test_prompt_eval.py`, `tests/test_wait_checks.py`):** added or widened cases for the token hiding, the interrupted chat on both turns, the stop-dialog replies, the start checks, and the closed-pull-request wait check. The pull request reports added lines: tests 90, production 23 (fixtures excluded).
- **Model-visible changes:** None. No prompt, tool result or OpenAPI operation changed. The eval changes affect only the regression harness, and the `loopercli` changes only what it prints to a terminal.

## Upgrade and rollback

Re-run `install.sh` once v2.13.55 is published. No data migration. Rolling back to v2.13.54 restores the earlier `loopercli` error output and interrupt handling; nothing is stored differently.

### 行为变化与入口

- 所有 `loopercli` 错误都隐藏令牌：新的 `_print_error` 在写入 stderr 前把 `lpc_…` 令牌替换为 `lpc_…`，覆盖服务器返回的错误、"流在没有回复时结束"错误、交互聊天中的超长消息错误，以及 `main` 中抛出的 `CliError`。此前只有 argparse 用法错误会隐藏。全局选项解析器现在使用同一个 `Parser` 类，`main` 在错误处理内解析全局选项，因此被误当作选项值的令牌（如 `login lpc_…`、`--json=lpc_…`、`chat --file lpc_…`）在此处也不会被回显。
- 被中断的聊天保留会话：回复流式输出时按 Ctrl-C，轮次现在随中断一起带出，交互聊天从中取得会话 id。下一条消息继续该会话，"停止读取"提示也会写出它；此前若中断发生在首个回复完成前，会开启新会话。
- 评测停止对话：检查"回复声称汇总已完成"不再把"还没有真正查询…"这类（提出继续做的）回复当作声称，只有表示未完成含义的 没/还没/未 才能豁免。
- 评测"启动后不等待"检查：通过 Manager 自己的 `_looper_call` 读取工具调用（因此 `use_tool` 等包装调用也被计入），并以轨迹中第一个状态为 `ok` 的启动为锚点，被拒绝的重试不会移动锚点。
- 测试：为令牌隐藏、两个轮次上的聊天中断、停止对话回复、启动检查和已关闭 PR 的等待检查新增或扩展用例。PR 报告新增测试 90 行、生产代码 23 行（不含 fixture）。
- 面向模型的变化：无。提示词、工具结果和 OpenAPI 操作均未改动。评测改动只影响回归工具，`loopercli` 改动只影响其在终端打印的内容。
