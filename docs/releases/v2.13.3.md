# Looper v2.13.3

## Release Decision

**Who should upgrade:** Operators who use the dashboard and want to see which Looper version is running. No one else needs this release for runtime behavior.

**What this release solves:** [#272](https://github.com/foolzzz/looper/pull/272) shows the running Looper version in the dashboard sidebar. `GET /api/overview` carries a new `version` field with the installed `looper.__version__`, and the sidebar shows it next to "Looper" as a small muted label.

**Breaking changes:** No. The overview response gains one field; existing fields, configuration, registry schema, CLI and channels are unchanged from [v2.13.2](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.2.md).

**How to verify:** Check the version, then open the dashboard and read the label next to "Looper" in the sidebar.

**Contributors:** Maintainer @foolzzz authored [#272](https://github.com/foolzzz/looper/pull/272); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.3
```

## Behavior changes

- **API:** `GET /api/overview` (`looper/agents/overview.py`) returns `version`, the installed `looper.__version__`, as the first key. The other fields are unchanged.
- **Dashboard:** The sidebar (`web/src/components/sidebar.tsx`) fetches the overview once on mount and shows `v<version>` next to "Looper", with the version as the tooltip. If the request fails or the server predates the field, no label is shown and nothing else changes. The `Overview` type in `web/src/lib/api.ts` declares `version` as optional.
- **Model-visible changes:** None. No prompt, tool, Manager schema, runtime launch argument or model-facing text changed.

## Entry points

- **Dashboard:** Sidebar version label, as above.
- **CLI, Telegram/Lark channels, Manager tools and prompts:** No change.

## Upgrade and rollback

No action is needed beyond the usual re-run of `install.sh` once v2.13.3 is published; there is no configuration, data or migration change. Rolling back to v2.13.2 is safe for the same reason: the dashboard simply shows no version label against a server that lacks the field.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## Validation

**Retained implementation evidence:** [#272](https://github.com/foolzzz/looper/pull/272) reports the overview API test, the sidebar vitest and `tsc`, the full local suite before the merge, and Codex and Grok reviews that left no P0. This draft did not re-run them.

**CI:** CI runs after the release is drafted; its result is not recorded here.

**Not tested for this draft:** Local test runs, a dashboard build, runtime launches, database migration and restore, and model evals. The release documentation gate checks the body only.

### 行为变化与入口

- `GET /api/overview` 返回 `version`（已安装的 `looper.__version__`），其余字段不变。

- 对模型可见的内容（提示词、工具、Manager schema、运行时启动参数、面向模型的文本）无变化。
- CLI、Telegram/Lark、Manager 工具和提示词均无变化。

### 升级与回退

发布后照常重跑 `install.sh` 即可，无配置、数据或迁移变更；回退到 v2.13.2 同样安全：面对没有该字段的服务端，仪表盘只是不显示版本标签。
