# Looper v2.14.40

This is the patch release v2.14.40, a hotfix line in which each merged change ships at once. It ships the two changes merged since v2.14.39: the dashboard form for command schedules ([#979](https://github.com/foolzzz/looper/pull/979)) and config import refusing a requirement on a command schedule ([#995](https://github.com/foolzzz/looper/pull/995)).

## Release Decision

**Who should upgrade:** Anyone who runs v2.14.39 or earlier and wants to create or edit command schedules from the dashboard, or who imports configuration files that contain command schedules.

**What this release solves:** [#979](https://github.com/foolzzz/looper/pull/979) adds a "Type" selector and the command fields to the form on a project's Schedules tab, so a command schedule no longer needs the API. [#995](https://github.com/foolzzz/looper/pull/995) makes config import skip a command schedule entry that has a non-empty `requirement`, instead of storing it.

**Breaking changes:** No. No API or configuration is removed, and there is no new migration or setting. One recorded field changes shape: see "Behavior changes".

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#979](https://github.com/foolzzz/looper/pull/979) and [#995](https://github.com/foolzzz/looper/pull/995); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.40
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.39 upgrades directly. This release adds no migration and no new setting.

## Behavior changes

- **Command schedule form ([#979](https://github.com/foolzzz/looper/pull/979)).** The Schedules form has a "Type" choice (Agent task, the default, or Command). It can be chosen only when creating; an existing schedule shows its type as text and the edit request does not resend `kind`. A command schedule shows the command (required, at most 2000 characters), work directory, environment, env file, timeout, overlap, catch-up, notifications, the success deadline (`HH:MM`) and the three alert thresholds (failures 1 to 1000, no-success window 5 to 43200 minutes, skipped firings 0 to 10000). The agent-only fields (requirement, owner and template, gate, budgets, profiles, task limits) are hidden. The timeout for a command defaults to no limit, and the cron hint uses the shorter gated minimum interval.
- **Environment text.** The environment is typed as one `KEY=VALUE` per line (comments and blank lines ignored; a duplicate key warns and the last value wins) or as a JSON object with string values. A value containing a line break is shown as JSON. Invalid text blocks saving. Values are shown as written, so secrets belong in the env file, of which only the path is stored.
- **Alert fields on both types.** The success deadline and the alert thresholds also appear for agent schedules. An unchanged default is not sent; clearing a threshold resets it to the default.
- **List and detail.** The schedule list and the detail view show a "Command" badge; the detail view shows the command, environment and env file, and hides the gate and agent-only sections for a command schedule.
- **Config import ([#995](https://github.com/foolzzz/looper/pull/995)).** In `looper/agents/config_transfer.py`, an entry of kind `command` whose `requirement` is a non-empty string, or is not a string, is skipped with the reason "requirement does not apply to a command schedule". `""` is stored only when the field is absent, null or blank.
- **Recorded profile.** In the same pull request, `AgentProfile.record()` (`looper/agents/profile_registry.py`) includes `runtime.launcher` only when the launcher is `ttadk`; for the native launcher the key is absent. A run's settings record is therefore without `"launcher": "native"`. Readers of that record must treat a missing launcher as native. The pull request description does not mention this change.
- **Model-visible changes:** None found. No prompt, skill or tool description changes; the recorded profile is a run record, not prompt text.

**是否有破坏性变更：**否。不移除任何 API 或配置，也没有新的迁移或设置。有一个记录字段的形状变化，见“行为变化与入口”。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.39 上的安装可直接升级。本版本没有新迁移，也没有新设置。

### 行为变化与入口

- **命令调度表单（[#979](https://github.com/foolzzz/looper/pull/979)）。**调度表单新增“类型”（Agent 任务，默认；或命令），只能在创建时选择；已有调度以文本显示类型，编辑请求不再重发 `kind`。命令调度显示命令（必填，最多 2000 字符）、工作目录、环境变量、env 文件、超时、重叠策略、补跑、通知、成功截止时间（`HH:MM`）和三个告警阈值（失败次数 1 到 1000，无成功窗口 5 到 43200 分钟，跳过的触发 0 到 10000）；仅限 Agent 的字段（requirement、所有者与模板、gate、预算、profile、任务限制）被隐藏。命令的超时默认不限，cron 提示使用较短的带 gate 最小间隔。
- **环境变量文本。**环境变量按每行一个 `KEY=VALUE` 输入（忽略注释和空行；重复的键会提示，以最后一个值为准），或输入值均为字符串的 JSON 对象；值含换行时以 JSON 显示。文本无效时无法保存。值按原样显示，密钥应放在 env 文件中，只保存其路径。
- **两种类型都有的告警字段。**成功截止时间和告警阈值也出现在 Agent 调度上。未改动的默认值不会发送；清空阈值即恢复默认。
- **列表与详情。**调度列表和详情显示“Command”徽标；详情显示命令、环境变量和 env 文件，并对命令调度隐藏 gate 与仅限 Agent 的部分。
- **配置导入（[#995](https://github.com/foolzzz/looper/pull/995)）。**在 `looper/agents/config_transfer.py` 中，kind 为 `command` 且 `requirement` 为非空字符串（或不是字符串）的条目会被跳过，原因是“requirement does not apply to a command schedule”；仅当该字段缺失、为 null 或空白时才保存 `""`。
- **记录的 profile。**同一拉取请求中，`AgentProfile.record()`（`looper/agents/profile_registry.py`）仅在 launcher 为 `ttadk` 时包含 `runtime.launcher`；native 时不含该键，因此运行的设置记录不再带 `"launcher": "native"`。读取该记录的代码须把缺失的 launcher 视为 native。拉取请求描述未提及这一改动。
- **面向模型的变化：**未发现。提示词、技能和工具描述均不变；记录的 profile 属于运行记录，不是提示词文本。
