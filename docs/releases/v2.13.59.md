# Looper v2.13.59

## Release Decision

**Who should upgrade:** Operators who run the dashboard or `looper service`, and anyone who scripts the removed `GET /api/status` route or calls `/api/v1/` with the operator credential. Nobody else needs to act.

**What this release solves:** [#457](https://github.com/foolzzz/looper/pull/457) moves the dashboard status to the versioned API as `POST /api/v1/system/status` and adds the v1 domain registry and a shared dashboard transport (`web/src/lib/v1.ts`) that later migrations build on. The dashboard, `looper service status` and the service start-up probe now read status through it. It also fixes process-tree cleanup so that a cancelled stop still reaps the child.

**Breaking changes:** Yes. `GET /api/status` is removed and answers 404; a script or probe that calls it must switch to `POST /api/v1/system/status` with the body `{}` and read the status from `result`. A `high`-risk `/api/v1/` call made with the operator credential now runs in one request; a client token still gets the two-step confirmation. No stored data or configuration changed.

**How to verify:** Check the installed version, then call the new route with the operator token.

**Contributors:** Maintainer @foolzzz authored [#457](https://github.com/foolzzz/looper/pull/457); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.59
```

## Behavior changes

- **Status moves to `POST /api/v1/system/status` (`looper/agents/v1_domains/status.py`, `looper/agents/http_server.py`):** the body is `{}`; the answer is `{"status": "ok", "result": {...}}`, and `result` is the projection `GET /api/status` returned (agents, task counts, web channel health, `checks`, `can_sign_out`, and `turn_binding` or `managers` when present). The route is registered as a read operation with a typed result schema and is part of the OpenAPI document. For an API client token `can_sign_out` is always false; for the operator it is computed from the real request headers. `GET /api/status` is deleted from the dashboard routes.
- **Callers follow (`looper/agents/service.py`, `web/src/lib/api.ts`, `examples/release/agent-serve-wheel-smoke.py`):** `looper service status`, the service start-up wait and the wheel smoke now POST to the v1 route and read `result`; the dashboard's `fetchStatus` does the same. Docstrings, comments and the `service status` help text name the new route.
- **Domain registry (`looper/agents/api_v1.py`, `looper/agents/v1_domains/`):** a domain is a module listed in `MODULES` (now only `status`) that declares `OPERATIONS`, `RESULTS` and `run`, and optionally `stream` and `impact`. Registration refuses a duplicate operation id or route, a domain stream that is not read-only, a `high` domain operation without `impact`, and a credential-write operation that is not operator-only. `validate_arguments` checks a domain operation's body against its declared schema and rejects unknown keys.
- **Operator-only operations (`looper/agents/http_server.py`):** an operation marked `operator_only` answers `forbidden` to a client token before anything runs. Failures of domain operations are mapped to fixed messages (`invalid request`, `the operation failed; try again later`); a credential write returns only `invalid credential request`. Error answers may carry `details` (`manager_id`, `state`, `phase`, `method`), which the OpenAPI `OpError` schema now describes.
- **Operator confirmation (`looper/agents/http_server.py`, `looper/agents/ops/clients.py`):** `ClientOps.call` takes `require_confirmation`; the v1 transport passes true only for client tokens. With the operator credential a `high` operation, including `config.import_apply`, executes in the same request and is still recorded; the dashboard keeps its own confirmation dialog. The `config.import_apply` description now says so.
- **Process cleanup (`looper/agents/proc_tree.py`):** `end` and the turn tree's stop reap the process in a `finally`, so a cancelled wait that sends SIGKILL no longer leaves the child unreaped. Tests were added in `tests/test_proc_tree.py`.
- **Dashboard transport (`web/src/lib/v1.ts`, `web/src/lib/session.ts`):** `callV1`, `confirmV1` and `streamV1` post JSON with a per-call `X-Looper-Session`, treat a 202 as a pending confirmation value that is never confirmed automatically, and honour the session-ended guard (a stream is cancelled when the session ends). `SystemStatus` in `web/src/lib/api.ts` is now the typed projection.
- **Docs and tests:** the client-skill RFC and the long-horizon context plan describe the new rule and list the migration state per domain. New `tests/test_api_v1_v1_transport_status.py` and `web/src/lib/v1.test.ts`; other tests were updated to the new route. `README.md`, `README.zh-CN.md` and `docs/architecture/agent-system.md` still name `GET /api/status` in places; this release does not change them. The pull request reports added lines: tests 300, production 565 (fixtures excluded).
- **Model-visible changes:** None for Manager, Worker, Planner or Reviewer prompts and tools; the status route adds no Manager Tool. What API clients (and an agent skill built on the OpenAPI document) see changes: the document gains the status operation, its `info.description`, the `details` field of `OpError` and the changed `config.import_apply` description.

## Upgrade and rollback

Re-run `install.sh` once v2.13.59 is published. No data migration. Replace any caller of `GET /api/status` before upgrading. Rolling back to v2.13.58 brings `GET /api/status` back and removes the v1 status route; a dashboard and a service from the same version always agree, so do not mix versions.

### 行为变化与入口

- 状态迁到 `POST /api/v1/system/status`（`v1_domains/status.py`、`http_server.py`）：请求体 `{}`，返回 `{"status": "ok", "result": {...}}`，`result` 是原 `GET /api/status` 的投影（Agent、任务计数、web 通道健康、`checks`、`can_sign_out`，有则含 `turn_binding` 或 `managers`）。该路由登记为只读操作，带类型化结果 schema，并进入 OpenAPI 文档。API 客户端令牌的 `can_sign_out` 恒为 false，操作者按真实请求头计算。`GET /api/status` 从控制台路由中删除。
- 调用方跟进（`service.py`、`web/src/lib/api.ts`、wheel smoke）：`looper service status`、服务启动等待和 wheel smoke 改为 POST 到 v1 路由并读取 `result`；Dashboard 的 `fetchStatus` 同样。文档字符串、注释和 `service status` 帮助文字改写新路由。
- 领域注册表（`api_v1.py`、`v1_domains/`）：领域是列在 `MODULES`（目前只有 `status`）里的模块，声明 `OPERATIONS`、`RESULTS`、`run`，可选 `stream` 和 `impact`。注册时拒绝重复的操作 id 或路由、非只读的领域 stream、缺少 `impact` 的 `high` 领域操作、非操作者专用的凭据写操作。`validate_arguments` 按声明的 schema 校验领域操作的请求体，拒绝未知键。
- 操作者专用操作（`http_server.py`）：标为 `operator_only` 的操作对客户端令牌在执行前直接答 `forbidden`。领域操作的失败映射为固定文案（`invalid request`、`the operation failed; try again later`），凭据写操作只返回 `invalid credential request`。错误答案可带 `details`（`manager_id`、`state`、`phase`、`method`），OpenAPI 的 `OpError` 现已描述。
- 操作者确认（`http_server.py`、`ops/clients.py`）：`ClientOps.call` 新增 `require_confirmation`，v1 传输层只对客户端令牌传 true。用操作者凭据时，`high` 操作（含 `config.import_apply`）在同一请求中执行并照常留痕；Dashboard 保留自己的确认弹窗。`config.import_apply` 的描述已同步。
- 进程清理（`proc_tree.py`）：`end` 和进程树停止改在 `finally` 中回收进程，被取消的等待发出 SIGKILL 后不再留下未回收的子进程。`tests/test_proc_tree.py` 新增测试。
- Dashboard 传输层（`web/src/lib/v1.ts`、`session.ts`）：`callV1`、`confirmV1`、`streamV1` 以每次调用独立的 `X-Looper-Session` 发送 JSON，把 202 当作待确认的值、绝不自动确认，并遵守会话结束守卫（会话结束时取消流）。`api.ts` 中的 `SystemStatus` 改为带类型的投影。
- 文档与测试：更新客户端 skill RFC 和长程上下文计划，列出各领域迁移状态。新增 `tests/test_api_v1_v1_transport_status.py` 和 `web/src/lib/v1.test.ts`，其他测试改用新路由。`README.md`、`README.zh-CN.md` 和 `docs/architecture/agent-system.md` 仍有几处写着 `GET /api/status`，本版本未改。PR 报告新增测试 300 行、生产代码 565 行（不含 fixture）。
- 面向模型的变化：Manager、Worker、Planner、Reviewer 的 prompt 和工具均无变化，状态路由不新增 Manager Tool。API 客户端（以及基于 OpenAPI 文档的 agent skill）会看到：文档新增状态操作及 `info.description`，`OpError` 多了 `details` 字段，`config.import_apply` 的描述有变。
