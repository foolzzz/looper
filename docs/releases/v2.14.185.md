# Looper v2.14.185

This is the patch release v2.14.185, a hotfix line in which each merged change ships at once. It documents one change: [#1347](https://github.com/foolzzz/looper/pull/1347) (translated runs without upstream cache usage show a dash, not 0%).

## Release Decision

**Who should upgrade:** Operators who route Claude Code through the local translating proxy (the gateway) to an upstream that reports no cache usage, and who read the cache hit on run cards, per-model task costs or recorded request rows.

**What this release solves:** [#1347](https://github.com/foolzzz/looper/pull/1347) fixes [#1161](https://github.com/foolzzz/looper/issues/1161) and [#1155](https://github.com/foolzzz/looper/issues/1155). A translated run whose upstream never reported cache fields used to store 0 cache tokens (Claude Code synthesizes zeros), so the dashboard showed a cache hit of 0%. The run now stores null cache counts and the dashboard shows a dash. The gateway documentation is corrected to match.

**Breaking changes:** No. The Telegram and Lark channel protocols, the dashboard and the CLI are unchanged, and there is no database change (the cache columns already accept null). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.185
```

**Contributors:** Maintainer @foolzzz authored [#1347](https://github.com/foolzzz/looper/pull/1347); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.184 upgrades directly. There is no database change.

## Behavior changes

Read in the diff of [#1347](https://github.com/foolzzz/looper/pull/1347) (`looper/agents/llmrec/proxy.py`, `looper/agents/llmrec/control.py`, `looper/agents/claude_cli.py`, `docs/architecture/agent-system.md` and tests). The PR description calls the behavior change intended (a maintainer decision).

- **Proxy tracks cache evidence per run** (`looper/agents/llmrec/proxy.py`). For each translated request with a record id, the proxy notes whether the upstream usage carried cache fields (`anthropic_usage` already reported this) and keeps the result per route and record in `_run_cache_usage`, which is true once any request of the run reported them. It is kept in proxy memory (up to 1,024 runs, oldest dropped), independently of whether request recording is on. A new local endpoint `GET /llmrec/cache-usage/<route>/<record>` on the proxy answers `cache_reported` (`true`, `false` or `null` for an unknown run) with the proxy instance id.
- **Run end stores null** (`looper/agents/llmrec/control.py`, `looper/agents/claude_cli.py`). `ProxyControl.cache_reported` reads that endpoint (2 s timeout, no environment proxy) and returns `None` when the proxy is unavailable, restarted (instance mismatch), evicted the run or answers badly. When `ClaudeRunRecorder._write_end` finishes a translated run and the answer is exactly `False`, it stores `cache_read_tokens` and `cache_creation_tokens` as null instead of Claude Code's zeros. Unknown evidence leaves the counts unchanged, as before. Other routes are unaffected.
- **Display**: with null counts the existing cache-hit calculation (`cache_read / (input + cache_read + cache_write)`, none when a count is missing) shows a dash instead of 0%. This PR changes no dashboard code; the dashboard test only adds a case for null counts. Runs already recorded keep their stored zeros.
- **Documentation** (`docs/architecture/agent-system.md`). Corrected: the translated `message_start` estimate omits both cache counts (it said zero); the first-request estimate without an anchor is a byte-based approximation that can run about 15–20% high; the estimate drives Claude Code's own auto-compact; Looper's context-full session switch applies to runtimes that report context (the API runtime). These are text changes only.
- **Tests** (`tests/test_gateway_proxy.py` adds 54 lines; `tests/test_recorder_resume.py` now uses the shared `builtin_launch` helper; `web/src/pages/agent-history.test.tsx` adds a null-counts case).
- **Model-visible changes:** No. No prompt, tool description or tool schema changed, and the translation of requests and responses to Claude Code is unchanged. The only difference is the cache token counts stored for a finished run, which are dashboard and API data.

### 行为变化与入口

以下在 [#1347](https://github.com/foolzzz/looper/pull/1347) 的差异中可见（`looper/agents/llmrec/proxy.py`、`looper/agents/llmrec/control.py`、`looper/agents/claude_cli.py`、`docs/architecture/agent-system.md` 及测试）。PR 描述称该行为变化是有意的（维护者决定）。

- **代理按运行记录缓存证据**（`looper/agents/llmrec/proxy.py`）。对每个带记录 id 的翻译请求，代理记下上游用量是否带有缓存字段（`anthropic_usage` 本就返回该信息），并按路由和记录保存在 `_run_cache_usage` 中；运行中任一请求报告过即为 true。它保存在代理内存中（最多 1,024 个运行，最旧的先丢弃），与是否开启请求记录无关。代理新增本地端点 `GET /llmrec/cache-usage/<route>/<record>`，返回 `cache_reported`（`true`、`false`，未知运行为 `null`）及代理实例 id。
- **运行结束时存入 null**（`looper/agents/llmrec/control.py`、`looper/agents/claude_cli.py`）。`ProxyControl.cache_reported` 读取该端点（2 秒超时，不使用环境代理），代理不可用、已重启（实例不匹配）、已淘汰该运行或应答异常时返回 `None`。`ClaudeRunRecorder._write_end` 结束翻译运行时，若答复恰为 `False`，则将 `cache_read_tokens` 与 `cache_creation_tokens` 存为 null，而不是 Claude Code 的零值。证据未知时计数保持原样（与此前相同）。其他路由不受影响。
- **显示**：计数为 null 时，现有的缓存命中计算（`cache_read / (input + cache_read + cache_write)`，缺少计数则无百分比）显示短横线而非 0%。本 PR 未改动仪表盘代码，仪表盘测试仅新增 null 计数的用例。已记录的运行保留其已存的零值。
- **文档**（`docs/architecture/agent-system.md`）。更正：翻译后的 `message_start` 估算省略两个缓存计数（原文为零）；无锚点的首次请求估算是基于字节的近似，可能偏高约 15–20%；该估算驱动 Claude Code 自身的自动压缩；Looper 的上下文已满会话切换适用于会报告上下文的运行时（API 运行时）。仅为文字变更。
- **测试**（`tests/test_gateway_proxy.py` 新增 54 行；`tests/test_recorder_resume.py` 改用共享的 `builtin_launch` 辅助函数；`web/src/pages/agent-history.test.tsx` 新增 null 计数用例）。
- **面向模型的变化：**无。提示词、工具描述和工具 schema 均未改变，向 Claude Code 的请求与响应翻译也未改变。唯一差异是已结束运行存储的缓存 token 计数，属于仪表盘和 API 数据。
