# Looper v2.13.33

## Release Decision

**Who should upgrade:** Anyone who stops agent turns, in particular Claude turns that no longer answer an interrupt. Since v2.13.31 such a turn took longer to be killed on a stop.

**What this release solves:** [#393](https://github.com/foolzzz/looper/pull/393) reverts the `looper/agents/proc_tree.py` change of [#385](https://github.com/foolzzz/looper/pull/385) (shipped in v2.13.31). #385 added a start-time read to every process-tree refresh, which delayed the first signal of a kill on a loaded machine. `tests/test_resident_claude_interrupt.py::test_a_deaf_claude_is_killed_with_its_whole_tree` took 3.1 to 4.9 s against its 3 s bound and failed on `main`.

**Breaking changes:** No. No CLI command, configuration key, API shape or database schema changed. The behavior change is listed below.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#393](https://github.com/foolzzz/looper/pull/393); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.33
```

## Behavior changes

- **Process-tree end is back to v2.13.30:** `_tree` no longer takes a `skip` set, `_end` no longer takes `reused`, and `_end_all` takes only `exclude`. `TurnTree.refresh` no longer calls `_reused()` before the walk or drops reused pids from the known groups, so a refresh no longer reads start times first. `TurnTree.end` and `end_new` still pass the reused pids as `exclude`, so a reused pid itself is not signalled.
- **Known regression, deferred:** a pid reused by an unrelated process after it left the turn tree has its current children and group walked again when the tree is ended. This is the rare case #385 fixed. It returns to #338, to be redone without the extra read on the kill path.
- **Test-only changes:** `tests/test_proc_tree.py` drops `test_turn_tree_leaves_the_subtree_of_a_reused_pid_alone`, which #385 had added.
- **Model-visible changes:** None. No prompt text, tool schema or tool result changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.33 is published. There is no schema or configuration change. Rolling back to v2.13.32 is safe; the only difference is the slower kill of a deaf Claude and the reused-pid handling described above.

## 中文摘要

### 升级决策

**谁需要升级：**会停止 agent 回合的用户，尤其是不再响应中断的 Claude 回合。自 v2.13.31 起，这类回合在停止时需要更久才会被杀掉。

**解决了什么：**[#393](https://github.com/foolzzz/looper/pull/393) 回退了 [#385](https://github.com/foolzzz/looper/pull/385)（随 v2.13.31 发布）对 `looper/agents/proc_tree.py` 的改动。#385 在每次进程树刷新时增加了一次启动时间读取，在高负载机器上推迟了杀进程的第一个信号。`tests/test_resident_claude_interrupt.py::test_a_deaf_claude_is_killed_with_its_whole_tree` 耗时 3.1 至 4.9 秒，超过 3 秒上限，在 `main` 上失败。

**是否有破坏性变更：**无。CLI、配置项、API 形态、数据库 schema 均未变化，行为变化见下文。

**如何验证：**运行 `looper --version` 核对版本为 2.13.33。

**贡献者：**维护者 @foolzzz 提交 [#393](https://github.com/foolzzz/looper/pull/393)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.33
```

### 行为变化与入口

- 进程树的结束逻辑回到 v2.13.30：`_tree` 不再接受 `skip`，`_end` 不再接受 `reused`，`_end_all` 只接受 `exclude`。`TurnTree.refresh` 不再在遍历前调用 `_reused()`，也不再从已知进程组中剔除被复用的 pid，因此刷新不再先读取启动时间。`TurnTree.end` 与 `end_new` 仍把被复用的 pid 作为 `exclude` 传入，所以被复用的 pid 本身不会被发信号。
- 已知回退，推迟处理：当某个 pid 离开回合进程树后被无关进程复用，结束进程树时会再次遍历它当前的子进程和进程组。这是 #385 修复的罕见情形，退回 #338，待在不增加杀进程路径额外读取的前提下重做。
- 仅测试改动：`tests/test_proc_tree.py` 删除了 #385 新增的 `test_turn_tree_leaves_the_subtree_of_a_reused_pid_alone`。
- 面向模型的变化：无。提示词文本、工具 schema、工具结果均无变化。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.32 安全；区别仅是杀掉无响应 Claude 变慢，以及上述被复用 pid 的处理。
