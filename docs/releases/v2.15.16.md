# Looper v2.15.16

This is the patch release v2.15.16, a hotfix line in which each merged change ships at once. It documents the changes merged since v2.15.15: [#1419](https://github.com/foolzzz/looper/pull/1419) (fixes [#1412](https://github.com/foolzzz/looper/issues/1412)), plus a test-only change, [#1416](https://github.com/foolzzz/looper/pull/1416), and a documentation-only change, [#1415](https://github.com/foolzzz/looper/pull/1415).

## Release Decision

**Who should upgrade:** Anyone whose Manager is bound to a Lark or Telegram group chat.

**What this release solves:** A group chat no longer receives the notice that a task's wait timed out or that its concurrency was changed, and a schedule change in a group is answered with a short confirmation that lists no configuration, directories or commands ([#1419](https://github.com/foolzzz/looper/pull/1419)).

**Breaking changes:** No. There is no API field change and no database migration. Group chats see different messages (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.16
```

**Contributors:** Maintainer @foolzzz authored [#1415](https://github.com/foolzzz/looper/pull/1415), [#1416](https://github.com/foolzzz/looper/pull/1416) and [#1419](https://github.com/foolzzz/looper/pull/1419); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.15 upgrades directly. This release has no database migration. Restart the service after upgrading, as for every release.

## Behavior changes

### Group chats (Lark and Telegram)

- **No wait or concurrency notices.** The group is no longer told that a task's wait timed out or that the Planner changed the task's concurrency. Both are still recorded in the dashboard and the task's journal, and the Planner is woken as before. ([#1419](https://github.com/foolzzz/looper/pull/1419))
- **Short schedule replies.** A schedule update in a group is answered with one line naming the schedule, its project and the names of the changed settings, and whether it is now enabled; it shows no values, directories or fire times. Enabling a schedule, running it once, raising a cap and editing an enabled command each ask one short question without the schedule's settings. ([#1419](https://github.com/foolzzz/looper/pull/1419))
- **Unchanged:** direct chats, the dashboard chat and the CLI. Gate posts and the delete, reset and disable confirmations are unchanged in groups.
- **Known limit.** A task created before v2.15.15 counts as a direct chat, so it keeps its notices.

### Tests and documentation

- The scheduled installed-runtime tests lagged earlier product changes and failed daily; they are updated and no production code changed ([#1416](https://github.com/foolzzz/looper/pull/1416)).
- The message stream and subscriptions RFC is added as a design document; it changes no code or behavior ([#1415](https://github.com/foolzzz/looper/pull/1415)).

### Model-visible changes

Yes, one. In a group chat, the text the Manager's schedule tool returns for an update is the short line described above. Real-mode eval (`evals/lark_group.py --conversations group-schedule`, real Claude CLI), as reported by [#1419](https://github.com/foolzzz/looper/pull/1419): in a group, Sonnet passed 2/2 and an Opus xhigh Manager 1/1 with no settings shown, against 0/2 and 0/1 on the previous release. Direct and dashboard paths have no model-visible change.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## Validation

**Reported by the pull requests:** the new group cases (wait timeout and concurrency notices not posted, schedule replies without settings) fail on the previous `main` and pass; the direct-chat cases pass unchanged. The pull request's full-suite run had failures that also occur on `main` in the same environment (local TLS trust, keeper timeouts and a database-tool version mismatch). The installed-runtime test fixes passed locally against a disposable PostgreSQL and a headless browser.

**Not verified by the pull requests:** real Lark or Telegram groups (only stand-ins) and the wait-timeout and concurrency paths in a running `looper serve`.

**CI:** CI runs after the release is drafted; its result is not recorded here.

**Not tested for this draft:** a local full suite, an upgrade of an existing database, and the built wheel. The release documentation gate checks the body only.

### 升级决策

**谁需要升级：**Manager 绑定了 Lark 或 Telegram 群聊的用户。

**解决了什么：**群聊不再收到任务等待超时或并发被调整的通知；群里修改定时任务时只收到一条简短确认，不列出配置、目录或命令（[#1419](https://github.com/foolzzz/looper/pull/1419)）。

**是否有破坏性变更：**无。API 字段不变，没有数据库迁移。群聊看到的消息会变化（见行为变化）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.15.16。

**贡献者：**维护者 @foolzzz 提交 [#1415](https://github.com/foolzzz/looper/pull/1415)、[#1416](https://github.com/foolzzz/looper/pull/1416) 和 [#1419](https://github.com/foolzzz/looper/pull/1419)；本版本无社区贡献。

```bash
looper --version   # looper 2.15.16
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.15.15 上的安装可直接升级。本版本没有数据库迁移。升级后照常重启服务。

### 行为变化与入口

**群聊（Lark 与 Telegram）**

- **不再有等待或并发通知。**群里不再收到任务等待超时或 Planner 调整并发的通知。两者仍记录在仪表盘和任务日志里，Planner 照常被唤醒。（[#1419](https://github.com/foolzzz/looper/pull/1419)）
- **定时任务回复更短。**群里修改定时任务时，回答只有一行：定时任务名称、项目、被修改的设置名称，以及它现在是否启用；不显示具体值、目录或触发时间。启用、运行一次、提高上限和编辑已启用的命令各自只问一个简短的问题，不列出定时任务的设置。（[#1419](https://github.com/foolzzz/looper/pull/1419)）
- **不变：**私聊、仪表盘聊天和 CLI。gate 消息以及删除、重置、停用的确认在群里不变。
- **已知限制。**v2.15.15 之前创建的任务按私聊处理，因此仍会收到这些通知。

**测试与文档**

- 定时运行的 installed-runtime 测试因落后于此前的产品改动而每天失败，现已更新，生产代码未改动（[#1416](https://github.com/foolzzz/looper/pull/1416)）。
- 新增消息流与订阅 RFC 设计文档，不改动代码或行为（[#1415](https://github.com/foolzzz/looper/pull/1415)）。

**面向模型的变化：**

有一处。在群聊里，Manager 的定时任务工具对修改返回的文本改为上述简短的一行。真实模式评测（`evals/lark_group.py --conversations group-schedule`，真实 Claude CLI），数据来自 [#1419](https://github.com/foolzzz/looper/pull/1419)：群聊中 Sonnet 通过 2/2、Opus xhigh Manager 通过 1/1，均未显示设置，上一版本分别为 0/2 和 0/1。私聊和仪表盘路径没有面向模型的变化。

### 可选能力启用与使用

本版本未新增可选能力启用入口。
