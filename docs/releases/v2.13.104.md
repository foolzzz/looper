# Looper v2.13.104

## Release Decision

**Who should upgrade:** Anyone who restarts stopped, failed, cancelled or ready tasks from the dashboard task page and watches the Sessions tab.

**What this release solves:** [#590](https://github.com/foolzzz/looper/pull/590) makes the task page resume Sessions activity after an asynchronous Start. Before, the page could read the old terminal task right after Start, treat it as the end of the new run and leave the activity stream closed.

**Breaking changes:** No. No API, command or stored data changed; the fix is in the dashboard only.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#590](https://github.com/foolzzz/looper/pull/590); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.104
```

## Behavior changes

- **Sessions resume after Start ([#590](https://github.com/foolzzz/looper/pull/590)):** in `web/src/pages/task-detail.tsx`, `start` records the task as it was before the request. While that record is pending, the task poll does not stop on a terminal status until it observes the new run: a non-terminal status, a different `completed_at`, or a higher `cost.runs`. On observing it, the page bumps an activity generation that `SessionsTab` uses as an effect dependency, so the activity stream is reopened once. `updated_at` and the Planner id are not used, because edits change the former and the latter is reused across runs.
- **Start guards:** a second Start while one is pending is ignored. If the Start request is refused, the pending record is cleared and the error is shown. If the observed run has status `failed`, the task's error or result summary (or "The task failed to start.") is shown. Switching to another task clears the pending record, and a response from the old route is ignored, so task ids do not mix and the old poll and stream are aborted.
- **Model-visible changes:** None. No tool declaration, API schema, prompt or response text changed.
- **Tests:** [#590](https://github.com/foolzzz/looper/pull/590) extends `web/src/pages/task-detail-route.test.tsx` (stale terminal reads, a run that ends at once, double click, abort on route change during the request and during the poll) and adds `tests/test_task_activity_restart_browser.py`, a browser regression against the built dashboard with deterministic responses for the outcomes running, stopped, completed, failed and refused. The pull request reports 113 added test lines and 101 production lines.

## Upgrade and rollback

Re-run `install.sh` once v2.13.104 is published. No data migration and no configuration change. Rolling back to v2.13.103 brings back the closed Sessions stream after an asynchronous Start.

looper --version   # looper 2.13.104

### 行为变化与入口

- **Start 后 Sessions 恢复（[#590](https://github.com/foolzzz/looper/pull/590)）：**在 `web/src/pages/task-detail.tsx` 中，`start` 会记录请求前的任务。记录未清除期间，任务轮询遇到终态不会停止，直到观察到新运行：状态非终态、`completed_at` 变化，或 `cost.runs` 增加。观察到后页面递增活动 generation，`SessionsTab` 以它为 effect 依赖，活动流因此只重开一次。不使用 `updated_at`（编辑也会改变它）和 Planner id（跨运行复用）。
- **Start 保护：**已有 Start 进行中时，再次点击 Start 被忽略。Start 请求被拒绝时清除待定记录并显示错误。观察到的运行状态为 `failed` 时，显示任务的错误或结果摘要（否则显示 "The task failed to start."）。切换到另一个任务会清除待定记录，旧路由的响应被忽略，任务 id 不会混用，旧的轮询与活动流会被中止。
- **面向模型的变化：**无。没有 tool 声明、API schema、提示词或响应文本改变。
- **测试：**[#590](https://github.com/foolzzz/looper/pull/590) 扩展 `web/src/pages/task-detail-route.test.tsx`（过期终态读取、立即结束的运行、重复点击、请求期间与轮询期间切换路由时的中止），并新增 `tests/test_task_activity_restart_browser.py`，针对构建后的仪表盘，用确定性响应覆盖 running、stopped、completed、failed、refused 五种结果。该 PR 报告新增测试 113 行、生产代码 101 行。
