# Looper v2.13.144

## Release Decision

**Who should upgrade:** Operators who import Manager configuration files into a Looper that already stores task templates. Everyone else can stay on v2.13.143.

**What this release solves:** [#689](https://github.com/foolzzz/looper/pull/689) keeps the stored fields of a task template that an import file omits. An existing template is now overlaid with only the keys present in the file; before, a field missing from the file was not carried over from the stored template.

**Breaking changes:** No. Files that name every field import as before; only files that omit fields differ, and they keep the stored values.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#689](https://github.com/foolzzz/looper/pull/689); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.144
```

## Behavior changes

- **Template import overlay (#689):** in the Manager import path of `looper/agents/config_transfer.py`, when the target already stores a template for the same Manager and template key, the stored template is rendered with `manager_template_entry` (profile and project ids mapped back to names) and the file's entry is merged over it (`{**stored, **template}`). The merge runs before project and profile reference resolution and before field validation, so preview and apply see the same merged template. The stored `repoint` marker is dropped, because only the file asks for a directory reminder. The lookup of the stored template moved earlier in the loop; the later checks are unchanged. Templates that do not exist in the target are imported as given.
- **Tests (#689):** `tests/test_manager_config_transfer_db.py` (151 added lines) and `tests/test_api_v1_manager_config_transfer.py` (17 added lines).
- **Description mismatch:** the description says the change covers the Managers API helper too; the diff touches only `looper/agents/config_transfer.py` and the two test files. The API test file exercises the import through the API.
- **Model-visible changes:** none. No prompt, tool declaration or tool result changes. Imported template fields that were kept now reach later runs from the template, as a stored template always did.
- **Line counts:** the description reports tests 168 and production 8 added lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.144 is published. No schema migration. Rolling back to v2.13.143 returns to the earlier import behavior for omitted template fields; templates already imported keep their stored values.

### 升级决策

### 行为变化与入口

- **模板导入叠加（#689）：**在 `looper/agents/config_transfer.py` 的 Manager 导入路径中，目标已存有相同 Manager 和模板 key 的模板时，用 `manager_template_entry` 渲染已存模板（profile 和项目 id 还原为名称），再把文件条目叠加其上（`{**stored, **template}`）。合并发生在项目和 profile 引用解析以及字段校验之前，因此预览和应用看到相同的合并结果。已存的 `repoint` 标记被丢弃，因为只有文件才会要求目录提醒。已存模板的查找在循环中提前，后续检查不变。目标中不存在的模板按原样导入。
- **测试（#689）：**`tests/test_manager_config_transfer_db.py`（新增 151 行）和 `tests/test_api_v1_manager_config_transfer.py`（新增 17 行）。
- **描述不一致：**描述称改动也涉及 Managers API helper；实际 diff 只改了 `looper/agents/config_transfer.py` 和两个测试文件。API 测试文件通过 API 演练导入。
- **面向模型的变化：**无。提示词、tool 声明和工具结果均不变。被保留的导入模板字段会像已存模板一贯那样进入之后的运行。
- **行数：**描述报告新增测试 168 行、生产代码 8 行（不含 fixtures）。

### 升级与回退

v2.13.144 发布后重跑 `install.sh`。无表结构迁移。回退到 v2.13.143 会恢复省略模板字段时的旧导入行为；已导入的模板保留其已存值。
