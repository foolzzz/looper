# Looper v2.13.145

## Release Decision

**Who should upgrade:** Operators who use the api (Model API) runtime and read Settings → Agent Runtimes. Everyone else can stay on v2.13.144.

**What this release solves:** [#696](https://github.com/foolzzz/looper/pull/696) shows the api runtime on the dashboard as an in-process SDK runtime, with the Python package diagnosis visible when the package is missing, and checks the entry points the RFC lists against that runtime.

**Breaking changes:** No. The registry view adds an optional `probe_error` field to the runtime type; nothing is removed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#696](https://github.com/foolzzz/looper/pull/696); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.145
```

## Behavior changes

- **Registry view (#696):** in `looper/agents/profile_registry.py`, `registry_view` builds the runtime type views first; for an in-process type whose runtime is not registered it probes the type and puts the result in the type's `probe_error`. `looper/agents/v1_domains/registry.py` adds `probe_error` (nullable string) to the closed runtime type schema; it is not a required field.
- **Dashboard (#696):** `web/src/components/runtime-cards.tsx` treats an in-process type or runtime specially: the Path row reads "Runs inside looper serve" and is hidden when the type is not detected, the probe error is shown in the card footer instead of the Version row, and a detected card says "Comes with Looper; Re-detect checks its Python package." `web/src/lib/runtime-catalog.ts` lists `api` as "Model API (SDK)" and removes the planned "norma" card; `web/src/lib/api.ts` adds `in_process` and `probe_error` to the types.
- **Documentation (#696):** `docs/architecture/agent-system.md` gains a Model API (SDK) entry and corrects the Re-detect endpoint to `POST /api/v1/runtimes/probe`; `docs/design.md`, the API runtime RFC and a long-horizon plan note are updated to match.
- **Tests (#696):** `tests/test_api_entry_points_db.py` (214 added lines) and updated web tests for the profile form, layer settings and runtime cards. The description also names `tests/test_api_runtime_registry_db.py`, `tests/test_api_v1_registry_db.py`, `tests/test_api_v1_profiles_db.py`, `tests/test_api_stop_db.py` and `tests/test_manager_stop_matrix.py`; the diff does not change them.
- **Model-visible changes:** none. No prompt, tool declaration or tool result changes.
- **Line counts:** the description reports tests 214 and production 203 added lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.145 is published. No schema migration. Rolling back to v2.13.144 returns the earlier Agent Runtimes card; stored data is unaffected.

- **文档（#696）：**`docs/architecture/agent-system.md` 新增 Model API (SDK) 条目，并把 Re-detect 接口更正为 `POST /api/v1/runtimes/probe`；`docs/design.md`、API 运行时 RFC 和一份长程计划笔记同步更新。
- **测试（#696）：**`tests/test_api_entry_points_db.py`（新增 214 行）以及 profile 表单、分层设置和运行时卡片的 web 测试。描述还列出 `tests/test_api_runtime_registry_db.py`、`tests/test_api_v1_registry_db.py`、`tests/test_api_v1_profiles_db.py`、`tests/test_api_stop_db.py` 和 `tests/test_manager_stop_matrix.py`；diff 未修改它们。
