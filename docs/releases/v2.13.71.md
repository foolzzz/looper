# Looper v2.13.71

## Release Decision

**Who should upgrade:** Dashboard users and anyone scripting the schedule read HTTP routes (schedule lists, a schedule, the rule preview, run history or notifications). Dashboard users see no change. Scripts that call the removed routes must move to the `/api/v1/schedule_admin/` routes.

**What this release solves:** [#494](https://github.com/foolzzz/looper/pull/494) moves schedule definitions, the rule preview, run history and notifications to the versioned API (`/api/v1/`) with full typed definitions. The six legacy read routes for them are removed.

**Breaking changes:** Yes. The six legacy routes listed under Behavior changes no longer exist; a client that calls one gets a not-found answer. The schedule write routes (create, update, delete, run now, reset Planner session) and the scheduler settings are unchanged. Stored schedules, runs and notifications are unchanged.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#494](https://github.com/foolzzz/looper/pull/494); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.71
```

## Behavior changes

- **Removed routes (breaking for API clients):** `GET /api/schedules`, `GET /api/projects/{id}/schedules`, `GET /api/schedules/{id}`, `POST /api/schedules/preview`, `GET /api/schedules/{id}/runs` and `GET /api/schedules/{id}/notifications`.
- **Replacements** (all `POST`, all reads, `schedule_admin.<action>` under `/api/v1/schedule_admin/<action>`):
  - `list` takes no arguments and returns every project's schedules.
  - `project_list` takes `project_id` and returns that project's schedules plus the schedule limits.
  - `get` takes `schedule_id` and returns the schedule.
  - `preview` takes `cron` and optional `timezone`, `count` (at most 20) and `gated`; it reads only and returns the rule's description and next fire times, or why it is invalid.
  - `runs` takes `schedule_id` and optional `limit` (1..200), `before` and `skips` (`show` or `hide`); it returns `runs`, `next_before` and `routine_skips`.
  - `notifications` takes `schedule_id` and optional `limit` (1..200) and returns `notifications`.
- **Typed contracts:** the requests are closed, so unknown fields and wrong types are rejected by the request schema before the service runs. The answers declare full Schedule, Run, ScheduleLimits, Preview, RunsPage and Notification definitions. The generated CLI gets the commands from the OpenAPI document.
- **Dashboard and evals:** the dashboard reads schedules, the preview, runs and notifications through the new routes. The prompt-regression runner reads schedules and runs back through them. One eval fixture changed: the `sA` attempt now lasts 20 seconds instead of 3.
- **Docs:** the Looper client skill RFC and the long-horizon context plan describe the new reads.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt changed, and the `looper_schedules` Manager Tool keeps its compact list and get results (get still trims the requirement to 1000 characters). The change touches only HTTP routes, the dashboard, the CLI and the eval runner.

## Upgrade and rollback

Re-run `install.sh` once v2.13.71 is published. No data migration. Update any script or client that called a removed route before upgrading. Rolling back to v2.13.70 restores the legacy routes, with no stored data affected.

## 中文摘要

### 升级决策

**谁需要升级：**仪表盘用户，以及脚本调用定时任务读取 HTTP 路由（定时任务列表、单个定时任务、规则预览、运行历史、通知）的人。仪表盘用户看不到变化；调用已删除路由的脚本需要改用 `/api/v1/schedule_admin/` 路由。

**解决了什么：**[#494](https://github.com/foolzzz/looper/pull/494) 把定时任务定义、规则预览、运行历史和通知迁到版本化 API（`/api/v1/`），使用完整的类型化定义，并删除对应的六个旧读取路由。

**是否有破坏性变更：**是。“行为变化”中列出的六个旧路由不再存在，调用会得到 not found。定时任务的写路由（创建、更新、删除、立即运行、重置 Planner 会话）和调度器设置不变。已存的定时任务、运行记录和通知不变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.71。

**贡献者：**维护者 @foolzzz 提交 [#494](https://github.com/foolzzz/looper/pull/494)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.71
```

### 行为变化与入口

- **已删除的路由（对 API 客户端是破坏性的）：**`GET /api/schedules`、`GET /api/projects/{id}/schedules`、`GET /api/schedules/{id}`、`POST /api/schedules/preview`、`GET /api/schedules/{id}/runs`、`GET /api/schedules/{id}/notifications`。
- **替代路由**（均为 `POST`、只读，即 `/api/v1/schedule_admin/<action>` 下的 `schedule_admin.<action>`）：
  - `list` 无参数，返回所有项目的定时任务。
  - `project_list` 收 `project_id`，返回该项目的定时任务及限制。
  - `get` 收 `schedule_id`，返回该定时任务。
  - `preview` 收 `cron`，可选 `timezone`、`count`（最多 20）、`gated`；只读，返回规则描述与后续触发时间，或无效原因。
  - `runs` 收 `schedule_id`，可选 `limit`（1..200）、`before`、`skips`（`show` 或 `hide`）；返回 `runs`、`next_before`、`routine_skips`。
  - `notifications` 收 `schedule_id`，可选 `limit`（1..200），返回 `notifications`。
- **类型化契约：**请求为闭合 schema，未知字段和错误类型在服务执行前被拒绝；响应声明了完整的 Schedule、Run、ScheduleLimits、Preview、RunsPage、Notification 定义；生成式 CLI 由 OpenAPI 文档得到命令。
- **仪表盘与评测：**仪表盘经新路由读取定时任务、预览、运行和通知；prompt 回归 runner 也经新路由读回定时任务与运行。一个评测夹具有变化：`sA` 尝试耗时由 3 秒改为 20 秒。
- **文档：**Looper 客户端 skill RFC 与长程上下文计划描述了新的读取方式。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 均未改动，`looper_schedules` Manager Tool 保持紧凑的 list 与 get 结果（get 仍把需求裁到 1000 字）；变化只涉及 HTTP 路由、仪表盘、CLI 和评测 runner。

### 升级与回退

v2.13.71 发布后重跑 `install.sh`。无需迁移数据。升级前请更新调用已删除路由的脚本或客户端。回退到 v2.13.70 会恢复旧路由，不影响已存数据。
