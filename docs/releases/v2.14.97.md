# Looper v2.14.97

This is the patch release v2.14.97, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.96: opt-in recording of the model API requests of Claude Code Workers and Reviewers through a local recording proxy ([#1120](https://github.com/foolzzz/looper/pull/1120)). Recording is off by default; with it off, nothing changes except one additive database upgrade.

## Release Decision

**Who should upgrade:** Operators who want to analyze the exact requests and responses that Claude Code Workers and Reviewers exchange with the model API. Everyone else can stay; the upgrade is harmless but adds nothing while recording is off.

**What this release solves:** There was no way to see the model traffic of a run, only its summarized record. [#1120](https://github.com/foolzzz/looper/pull/1120) adds an opt-in global switch (`llmrec.enabled`, off by default) that routes newly launched Claude Code Workers and Reviewers through a loopback recording proxy and stores each exchange in PostgreSQL, readable by operators only through the API and the CLI. A second switch (`llmrec.include_oauth`, off by default) adds Claude subscription (OAuth) runs. A new Settings → Request recording page in the dashboard controls both.

**Breaking changes:** No. One additive database upgrade (`llm_requests`: three new tables), two new dependencies (`h11`, `truststore`), and no change to existing API shapes. With recording off, records, commands and environments of runs are unchanged.

**How to verify:** Check the installed version. In the dashboard, Settings → Request recording shows the switches off and "Proxy: stopped".

```bash
looper --version   # looper 2.14.97
```

**Contributors:** Maintainer @foolzzz authored [#1120](https://github.com/foolzzz/looper/pull/1120); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.96 upgrades directly. The database change is additive: the first start creates `llm_request_routes`, `llm_request_parts` and `llm_requests` (recorded as the upgrade `llm_requests`); no existing table changes. Reinstalling picks up the two new dependencies, `h11` and `truststore`.

## Behavior changes

- **Request recording (opt-in)** (`looper/agents/llmrec/`). When `llmrec.enabled` is on, a Claude Code Worker or Reviewer launched afterwards, kept runs included, gets its `ANTHROPIC_BASE_URL` rewritten to `http://127.0.0.1:<port>/r/<route_id>`, a per-process route on a long-lived Looper process bound to 127.0.0.1 (one per runtime root). The proxy forwards each request unchanged to the real upstream, streams SSE back chunk by chunk, and records the exchange off the forwarding path. The binding, its hash and the cost source are unchanged. Recording failures never fail a request; they are marked `record_gap` and counted. Runs started before a settings change keep their existing route.
- **Proxy lifecycle** (`looper/agents/llmrec/control.py`, `looper/agents/serve.py`). `serve` starts or adopts the proxy at start, replaces it when its code or database configuration changed and no kept run exists, restarts it on the same port, and checks its health every five seconds. It survives control-plane restarts like keepers do. If the proxy cannot be made available at launch, the run goes to its original endpoint, its metadata says `bypassed` (`proxy_unavailable`), one warning is logged, and the task's activity gets an error line "Model requests of this run are not recorded: the recording proxy was unavailable."
- **Coverage** (`looper/agents/runtimes/claude_code.py`, `looper/agents/tiers/worker.py`). Claude Code Workers and Reviewers only, including their subagents and teammates. API-key runs are covered when recording is on; Claude subscription (OAuth) runs also need `llmrec.include_oauth`. Managers, Planners, other runtimes and TTADK launches are not covered: a launch on an uncovered runtime records `llmrec.state = skipped` with `reason = not_covered`; an upstream URL carrying credentials is `skipped` with `credentials_in_url`; an incompatible retained proxy is `skipped` with `proxy_outdated`.
- **Environment of a routed run** (`looper/agents/runtimes/claude_code.py`). Besides the base URL, `127.0.0.1` is appended to `NO_PROXY`/`no_proxy`, and for an `api.anthropic.com` upstream `ENABLE_TOOL_SEARCH=true` is set unless the settings or provider already set it, so first-party tool search keeps working behind the loopback endpoint. Other upstreams get no override. Upstream TLS uses the OS trust store through `truststore`, plus the route's configured CA files; upstream proxy and TLS settings stay isolated per route.
- **Stored data** (`looper/db/schema.sql`, `looper/db/llm_requests.py`). Each exchange keeps method, path with redacted query parameters, allowlisted header values (never Authorization, keys or cookies), the request JSON (system prompt, messages, tools, tool results), the assembled JSON/SSE response, usage, status, timing and any gap. The system prompt, tools and each message are stored once per route by sha256. Requests are attributed to the `llm_records` row bound to the route at the time; requests between runs keep `after_record_id`. NUL characters become literal `\u0000` text with `body_sanitized` set. Bodies are not secret-scrubbed: prompts, code and tool output can contain sensitive data. No retention or pruning is added.
- **Operator API and CLI** (`looper/agents/v1_domains/llm_requests.py`). New operator-token-only operations `llmrec_settings.get`, `llmrec_settings.update`, `llm_requests.list` and `llm_requests.get` (`POST /api/v1/<domain>/<action>`), and the generated `loopercli llmrec-settings get/update` and `loopercli llm-requests list/get`. They are not agent tools.
- **Dashboard** (`web/src/components/llmrec-settings.tsx`, `web/src/pages/settings.tsx`). New Settings → Request recording page with the two switches, a warning that bodies can contain secrets, and the proxy state with recorded, dropped and write-error counts. (The pull request description says the dashboard has no new controls; the merged code adds this page.)
- **Self-check** (`looper/agents/self_check.py`). New advisory check `llmrec`: skipped when recording is off, fails when it is on but the proxy is unavailable, warns on an outdated proxy or on dropped, write-error or gap counts since proxy startup.
- **Unchanged:** the schema of existing tables, existing API shapes, channels (Telegram and Lark), and everything while recording is off.
- **Documentation and tests.** New "Model request recording" section in `docs/architecture/agent-system.md`; new `tests/test_llmrec_*.py`, `tests/test_api_v1_llm_requests_db.py` and `web/src/components/llmrec-settings.test.tsx`; updated `tests/test_claude_cli.py`, `tests/test_bridge_schema_db.py`, `tests/test_serve_startup_checks_db.py` and `web/src/components/vault-settings.test.tsx`.
- **Model-visible changes:** None while recording is off. With it on, a covered Worker or Reviewer sees the loopback base URL, `NO_PROXY` including 127.0.0.1 and possibly `ENABLE_TOOL_SEARCH=true` in its environment. No tool description or prompt text changes, and the recording operations are not exposed to agents.

## Optional Capability Activation & Use

### Model request recording

**Activation:** Off by default. An operator turns it on in Settings → Request recording ("Record model requests"), or with `loopercli llmrec-settings update` (`enabled`), or `POST /api/v1/llmrec_settings/update`. Claude subscription (OAuth) runs additionally need "Also record Claude subscription (OAuth) runs" (`include_oauth`). It applies to Workers and Reviewers launched after the change.

**Validation:** `loopercli llmrec-settings get` (or the settings page) shows the proxy state `running` once a covered run has launched. After a Claude Code Worker or Reviewer run, `loopercli llm-requests list` shows its exchanges, and `llm-requests get` shows one in full. The `llmrec` self-check is OK while the proxy runs and warns on drops, write errors or gaps. A run's record shows `llmrec.state = recording`, or `skipped`/`bypassed` with a reason.

```bash
loopercli llmrec-settings update --enabled
loopercli llmrec-settings get
loopercli llm-requests list --limit 5
```

**Disable / rollback:** Turn `enabled` off; later launches go directly to their provider and are byte-identical to before. A run already routed keeps its route until it ends. The proxy process stays until the next `serve` start finds recording off and no kept run, then stops it. Stored exchanges stay in the database until the operator deletes them; no automatic pruning exists. Downgrading leaves the three added tables unused.

**Authority boundary:** Operator token only for the settings and for reading captures; agents and non-operator clients cannot. The proxy listens on 127.0.0.1 only and forwards requests unchanged. Credential headers, cookies, unknown header values and sensitive query parameters are redacted, and upstream URLs with credentials are refused; bodies are stored as sent, so prompts, code and tool output (including secrets a tool printed) are readable by operators.

**Docs:** [Model request recording](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md#model-request-recording-llmrec) in the agent-system architecture document.

## 中文摘要

本版本是 patch release v2.14.97（热修线，每个合并的改动立即发布）。自 v2.14.96 以来只合并了一项改动：通过本地录制代理，按需记录 Claude Code Worker 和 Reviewer 的模型 API 请求（[#1120](https://github.com/foolzzz/looper/pull/1120)）。录制默认关闭；关闭时除一次增量数据库升级外无变化。

### 升级决策

**谁需要升级：**想分析 Claude Code Worker 和 Reviewer 与模型 API 之间确切请求和响应的运维人员。其他人可不升级；升级无害，但录制关闭时没有新增效果。

**解决了什么：**此前只能看到运行的汇总记录，看不到模型流量。[#1120](https://github.com/foolzzz/looper/pull/1120) 增加一个默认关闭的全局开关（`llmrec.enabled`），让之后启动的 Claude Code Worker 和 Reviewer 经过本机回环录制代理，并把每次交换存入 PostgreSQL，仅运维人员可通过 API 和 CLI 读取。第二个开关（`llmrec.include_oauth`，默认关闭）加入 Claude 订阅（OAuth）运行。仪表盘新增 Settings → Request recording 页面控制这两个开关。

**是否有破坏性变更：**否。一次增量数据库升级（`llm_requests`：三张新表），两个新依赖（`h11`、`truststore`），现有 API 形状不变。录制关闭时，运行的记录、命令和环境不变。

**如何验证：**核对版本为 2.14.97。在仪表盘 Settings → Request recording 中两个开关为关闭，显示 “Proxy: stopped”。

**贡献者：**维护者 @foolzzz 提交 [#1120](https://github.com/foolzzz/looper/pull/1120)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.97
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.96 上的安装可直接升级。数据库变更为增量：首次启动创建 `llm_request_routes`、`llm_request_parts` 和 `llm_requests`（记为升级 `llm_requests`），不改动已有表。重新安装会装上两个新依赖 `h11` 和 `truststore`。

### 行为变化与入口

- **请求录制（按需开启）**（`looper/agents/llmrec/`）。`llmrec.enabled` 开启后，之后启动的 Claude Code Worker 或 Reviewer（含保留运行）的 `ANTHROPIC_BASE_URL` 会改写为 `http://127.0.0.1:<port>/r/<route_id>`，即每个运行根一个、绑定在 127.0.0.1 的长驻 Looper 进程上的按进程路由。代理原样转发到真实上游，SSE 逐块回传，并在转发路径之外记录交换。绑定、其哈希和成本来源不变。录制失败从不使请求失败，只标记 `record_gap` 并计数。设置变更前已启动的运行保留原路由。
- **代理生命周期**（`looper/agents/llmrec/control.py`、`looper/agents/serve.py`）。`serve` 启动时启动或接管代理；其代码或数据库配置变化且没有保留运行时替换它，并在原端口重启；每五秒检查健康。它像 keeper 一样在控制面重启后存活。若启动时无法提供代理，该运行走原端点，元数据记为 `bypassed`（`proxy_unavailable`），记录一条警告，并在任务活动中写一条错误 “Model requests of this run are not recorded: the recording proxy was unavailable.”。
- **覆盖范围**（`looper/agents/runtimes/claude_code.py`、`looper/agents/tiers/worker.py`）。仅 Claude Code 的 Worker 和 Reviewer，含其子代理和队友。录制开启时 API key 运行被覆盖；Claude 订阅（OAuth）运行还需 `llmrec.include_oauth`。Manager、Planner、其他运行时和 TTADK 启动不被覆盖：未覆盖运行时的启动记为 `llmrec.state = skipped`、`reason = not_covered`；上游 URL 带凭据记为 `skipped`（`credentials_in_url`）；保留的代理不兼容记为 `skipped`（`proxy_outdated`）。
- **被路由运行的环境**（`looper/agents/runtimes/claude_code.py`）。除基础 URL 外，`127.0.0.1` 会追加到 `NO_PROXY`/`no_proxy`；上游为 `api.anthropic.com` 时，除非设置或服务商已设置，否则加上 `ENABLE_TOOL_SEARCH=true`，使第一方工具搜索在回环端点后仍可用。其他上游不加覆盖。上游 TLS 通过 `truststore` 使用系统信任库，加上该路由配置的 CA 文件；上游代理和 TLS 设置按路由隔离。
- **存储的数据**（`looper/db/schema.sql`、`looper/db/llm_requests.py`）。每次交换保存方法、已脱敏查询参数的路径、白名单内的头值（从不含 Authorization、密钥或 cookie）、请求 JSON（系统提示、消息、工具、工具结果）、组装后的 JSON/SSE 响应、用量、状态、耗时和缺口。系统提示、工具和每条消息按 sha256 在每个路由内只存一份。请求归属于当时绑定到该路由的 `llm_records` 行；两次运行之间的请求保留 `after_record_id`。NUL 字符变为字面 `\u0000` 文本并设置 `body_sanitized`。正文不做密钥清洗：提示、代码和工具输出可能含敏感数据。没有新增保留期或清理。
- **运维 API 与 CLI**（`looper/agents/v1_domains/llm_requests.py`）。新增仅限运维令牌的操作 `llmrec_settings.get`、`llmrec_settings.update`、`llm_requests.list`、`llm_requests.get`（`POST /api/v1/<domain>/<action>`），以及生成的 `loopercli llmrec-settings get/update` 和 `loopercli llm-requests list/get`。它们不是 agent 工具。
- **仪表盘**（`web/src/components/llmrec-settings.tsx`、`web/src/pages/settings.tsx`）。新增 Settings → Request recording 页面：两个开关、正文可能含密钥的警告，以及代理状态和已记录、丢弃、写入错误计数。（PR 描述称仪表盘没有新控件；合并的代码增加了此页面。）
- **自检**（`looper/agents/self_check.py`）。新增咨询性检查 `llmrec`：录制关闭时跳过；开启但代理不可用时失败；代理过期，或自代理启动以来有丢弃、写入错误或缺口时警告。
- **不变：**已有表的结构、已有 API 形状、渠道（Telegram 和 Lark），以及录制关闭时的一切。
- **文档与测试。**`docs/architecture/agent-system.md` 新增 “Model request recording” 一节；新增 `tests/test_llmrec_*.py`、`tests/test_api_v1_llm_requests_db.py` 和 `web/src/components/llmrec-settings.test.tsx`；更新 `tests/test_claude_cli.py`、`tests/test_bridge_schema_db.py`、`tests/test_serve_startup_checks_db.py` 和 `web/src/components/vault-settings.test.tsx`。
- **面向模型的变化：**录制关闭时无。开启时，被覆盖的 Worker 或 Reviewer 的环境里会看到回环基础 URL、含 127.0.0.1 的 `NO_PROXY`，以及可能的 `ENABLE_TOOL_SEARCH=true`。工具描述和提示文本不变，录制操作也不暴露给 agent。

### 可选能力启用与使用

#### Model request recording

**启用：**默认关闭。运维人员在 Settings → Request recording 勾选 “Record model requests”，或用 `loopercli llmrec-settings update`（`enabled`），或 `POST /api/v1/llmrec_settings/update`。Claude 订阅（OAuth）运行另需 “Also record Claude subscription (OAuth) runs”（`include_oauth`）。对变更之后启动的 Worker 和 Reviewer 生效。

**验证：**`loopercli llmrec-settings get`（或设置页）在被覆盖的运行启动后显示代理状态 `running`。Claude Code Worker 或 Reviewer 运行之后，`loopercli llm-requests list` 列出其交换，`llm-requests get` 显示单条完整内容。代理运行时 `llmrec` 自检为 OK，有丢弃、写入错误或缺口时警告。运行记录显示 `llmrec.state = recording`，或带原因的 `skipped`/`bypassed`。

```bash
loopercli llmrec-settings update --enabled
loopercli llmrec-settings get
loopercli llm-requests list --limit 5
```

**停用 / 回退：**关闭 `enabled`；之后的启动直接连服务商，与以前逐字节一致。已被路由的运行在结束前保持其路由。代理进程保留，直到下次 `serve` 启动发现录制关闭且没有保留运行时才停止。已存的交换留在数据库里直到运维人员删除；没有自动清理。降级后三张新表闲置。

**权限边界：**设置和读取录制内容仅限运维令牌；agent 和非运维客户端不能。代理只监听 127.0.0.1 并原样转发。凭据头、cookie、未知头值和敏感查询参数会被脱敏，带凭据的上游 URL 被拒绝录制；正文按原样存储，因此提示、代码和工具输出（包括工具打印出的密钥）对运维人员可读。

**文档：**agent-system 架构文档中的 [Model request recording](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md#model-request-recording-llmrec)。
