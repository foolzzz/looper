# Looper v2.14.134

This is the patch release v2.14.134, a hotfix line in which each merged change ships at once. It documents one change: [#1232](https://github.com/foolzzz/looper/pull/1232) (coco model-catalog checks move from reads to saves, and `ttadk-coco` warms the right executable).

## Release Decision

**Who should upgrade:** Operators who use the coco runtime or `ttadk-coco`, especially those whose task views failed after a model left coco's catalog. Everyone else gets no change.

**What this release solves:** [#1232](https://github.com/foolzzz/looper/pull/1232) stops a model that left coco's catalog from breaking task, Profile and settings views, checks the catalog when a coco Profile is saved, and makes `ttadk-coco` warm the catalog with the native coco executable.

**Breaking changes:** No. There is no migration and no API removal. Saving a coco Profile with a model that is not in a readable catalog is now refused, as a launch already did. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.134
```

**Contributors:** Maintainer @foolzzz authored [#1232](https://github.com/foolzzz/looper/pull/1232); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.133 upgrades directly. There is no schema change.

## Behavior changes

- **Reads no longer check the coco model catalog** ([#1232](https://github.com/foolzzz/looper/pull/1232)). The coco adapter's `check_pairing` no longer looks up the cached model catalog, so reading a Profile, a task or the settings never runs that check and a task view no longer fails when its model has left the catalog. The structural pairing rules (for example, coco takes no effort level) still apply on reads.
- **Saves check the catalog.** Creating or updating a coco Profile, updating a model, and changing a provider that coco Profiles use now run a save-time check (`check_available_runtime`). It refreshes a missing or expired catalog in a worker thread, off the event loop, and refuses a model the catalog lacks, with the list of models coco has. If the catalog cannot be read, the save is accepted. A launch still refuses an unknown model through the login check.
- **`ttadk-coco` warms the right executable.** The probe and the startup warm-up now use the native coco command that TTADK is configured to run (`traex` by default), not the `ttadk` executable. The login check uses the same helper.
- **`looper doctor`.** The coco login check reports SKIP ("not checked: no Agent Profile uses the coco login"), not OK, when no Profile uses it.
- **Generated Codex-style config comments.** The comments Looper writes into a run's generated config now name the runtime (Coco for coco runs). Codex runs read the same text as before.
- **Unchanged:** the native coco launch path, other runtimes, and the Manager's soft stop, which stays refused for per-turn runtimes. Consults and structured output stay off for coco.
- **Model-visible changes:** None. No tool description, Planner, Worker, Reviewer or Manager prompt or contract text and no run `AGENTS.md` text changes. The only wording change is in comments of the generated coco config file.

### 升级决策

**谁需要升级：**使用 coco 运行时或 `ttadk-coco` 的运维者，尤其是模型从 coco 目录中消失后任务视图报错的用户。其他人无变化。

**解决了什么：**[#1232](https://github.com/foolzzz/looper/pull/1232) 让离开 coco 目录的模型不再破坏任务、Profile 和设置视图，在保存 coco Profile 时检查目录，并让 `ttadk-coco` 用原生 coco 可执行文件预热目录。

**是否有破坏性变更：**否。没有迁移，没有移除 API。保存目录可读但不含该模型的 coco Profile 现在会被拒绝（启动时本来就拒绝）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.14.134。

**贡献者：**维护者 @foolzzz 提交 [#1232](https://github.com/foolzzz/looper/pull/1232)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.134
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.133 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **读取不再检查 coco 模型目录**（[#1232](https://github.com/foolzzz/looper/pull/1232)）。coco 适配器的 `check_pairing` 不再查询缓存的模型目录，因此读取 Profile、任务或设置都不会运行该检查，模型离开目录后任务视图不再报错。结构性配对规则（例如 coco 不接受 effort 级别）在读取时仍然适用。
- **保存时检查目录。**创建或更新 coco Profile、更新模型、修改 coco Profile 所用的提供商时，现在会运行保存时检查（`check_available_runtime`）。它在工作线程中（不占用事件循环）刷新缺失或过期的目录，并拒绝目录中没有的模型，同时列出 coco 拥有的模型。目录无法读取时保存仍被接受。启动时仍通过登录检查拒绝未知模型。
- **`ttadk-coco` 预热正确的可执行文件。**探测和启动预热现在使用 TTADK 配置的原生 coco 命令（默认 `traex`），而不是 `ttadk` 可执行文件；登录检查使用同一个辅助函数。
- **`looper doctor`。**没有 Profile 使用 coco 登录时，该检查报告 SKIP（“not checked: no Agent Profile uses the coco login”），不再是 OK。
- **生成的 Codex 风格配置注释。**Looper 写入运行所生成配置的注释现在写明运行时名称（coco 运行为 Coco）。Codex 运行读到的文本不变。
- **不变：**原生 coco 启动路径、其他运行时，以及 Manager 的软停止（per-turn 运行时仍被拒绝）。coco 的咨询和结构化输出仍保持关闭。
- **面向模型的变化：**无。没有工具描述、Planner、Worker、Reviewer 或 Manager 的提示词与契约文本变化，运行的 `AGENTS.md` 文本也无变化。唯一的措辞变化在生成的 coco 配置文件的注释中。
