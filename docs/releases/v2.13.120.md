# Looper v2.13.120

## Release Decision

**Who should upgrade:** Dashboard users who send a chat message and then open a transcript or a conversation link before the reply arrives. Others do not need it.

**What this release solves:** [#625](https://github.com/foolzzz/looper/pull/625) keeps a pending chat send bound to the Manager and session that made it. Opening a read-only transcript or an unresolved conversation link no longer cancels the send, its reply stream or its queued messages, and the unsent draft is kept per Manager and session.

**Breaking changes:** No. No command, option, route, configuration or stored data format changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#625](https://github.com/foolzzz/looper/pull/625); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.120
```

## Behavior changes

- **Pending send survives navigation to a transcript:** in `web/src/pages/chat.tsx`, the effect that cancelled the in-flight send whenever the URL pointed at another target or conversation is removed. A send is now cancelled only when a different writable owner is adopted (`switchWebSession` or `applyTarget`, for example choosing another Manager). While a transcript is open the composer is hidden, the send and its reply stream continue, and returning to the writable thread resumes following the turn.
- **Drafts are kept per Manager and session:** the composer text is written synchronously to the browser's session storage under `looper-chat-draft:<manager>:<session>` and is read back when that Manager and session are adopted. An empty draft removes the entry; if storage is full or blocked the draft still works for the page's life.
- **Hidden composers keep queued text:** sending is gated by one `canSend` value (the agent takes messages, no transcript is open, no unresolved conversation link), and the same value now gates draining the queue. Queued messages whose composer is hidden stay in their thread's queue instead of being pulled into a draft or sent; when a reply ends without an answer, queued text is returned to the draft only if the composer is available.
- **Model-visible changes:** none. This is dashboard behavior; no tool declaration, prompt, route or text sent to Workers changed.
- **Tests:** `web/src/pages/chat-manager-picker.test.tsx` adds a case for a pending send, stream and rejected send (open a transcript, the send is not aborted; pick another Manager, it is aborted and its late reply is not shown). `tests/test_chat_navigation_browser.py` adds browser cases for a pending submission across transcript navigation, a queue restored to its original draft after an answer arrives while hidden, unsent text surviving hidden completion and a writable detour, and only validated writable adoption cancelling a pending send. [#625](https://github.com/foolzzz/looper/pull/625) reports added lines: tests 127, production 45 (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.120 is published. No data migration and no configuration change. Drafts live in browser session storage and need no cleanup. Rolling back to v2.13.119 restores cancelling a pending send when a transcript is opened.

### 升级决策

**谁需要升级：**在聊天中发送消息后、回复到达前打开记录或会话链接的 Dashboard 用户。其他人无需升级。

**解决了什么：**[#625](https://github.com/foolzzz/looper/pull/625) 让待处理的聊天发送一直绑定到发起它的 Manager 与会话。打开只读记录或未解析的会话链接不再取消该发送、其回复流或排队消息，未发送的草稿也按 Manager 与会话分别保留。

**是否有破坏性变更：**否。命令、选项、路由、配置和存储数据格式均未改变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.120。

**贡献者：**维护者 @foolzzz 提交 [#625](https://github.com/foolzzz/looper/pull/625)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.120
```

### 行为变化与入口

- **待处理发送在打开记录时保留：**`web/src/pages/chat.tsx` 中，原先在 URL 指向其他目标或会话时取消进行中发送的 effect 被移除。现在只有采用不同的可写所有者（`switchWebSession` 或 `applyTarget`，例如选择另一个 Manager）时才取消。打开记录期间输入框隐藏，发送及其回复流继续，回到可写会话后继续跟随该轮。
- **草稿按 Manager 与会话保存：**输入框文字同步写入浏览器 session storage，键为 `looper-chat-draft:<manager>:<session>`，采用该 Manager 与会话时读回。草稿为空则删除该项；存储已满或被禁用时，草稿仍在页面存活期内有效。
- **隐藏的输入框保留排队文字：**发送由统一的 `canSend` 控制（该 agent 可接收消息、未打开记录、无未解析的会话链接），排队消息的发出也使用同一判断。输入框隐藏时，排队消息留在所属会话的队列中，不会被并入草稿或发出；回复未得到答案时，仅当输入框可用才把排队文字退回草稿。
- **面向模型的变化：**无。这是 Dashboard 行为；tool 声明、提示词、路由和发给 Worker 的文本均未改变。
- **测试：**`web/src/pages/chat-manager-picker.test.tsx` 新增待发送、流式、被拒绝三种情形（打开记录时发送不被中止；选择另一个 Manager 则中止，且迟到的回复不显示）。`tests/test_chat_navigation_browser.py` 新增浏览器用例：跨记录导航的待提交、隐藏期间收到答案后队列还原到原草稿、未发送文字在隐藏完成与可写会话绕行后保留、只有经验证的可写采用才取消待发送。[#625](https://github.com/foolzzz/looper/pull/625) 报告新增行数：测试 127、生产代码 45（不含夹具）。
