# Looper v2.13.85

## Release Decision

**Who should upgrade:** Anyone who calls the `/api/projects/{id}/knowledge` routes from a script, or who uses the dashboard's project knowledge page (documents, uploads, edits, lesson drafts). Everyone else gets no change.

**What this release solves:** [#534](https://github.com/foolzzz/looper/pull/534) moves project reference documents and lesson-draft management onto the versioned API, with full typed results, and removes the eight legacy routes.

**Breaking changes:** Yes. The routes `GET` and `POST /api/projects/{id}/knowledge`, `GET`, `PUT` and `DELETE /api/projects/{id}/knowledge/{document_id}`, `GET /api/projects/{id}/knowledge/drafts`, `POST .../drafts/{draft_id}/confirm` and `DELETE .../drafts/{draft_id}` are removed; a script that calls them must use `POST /api/v1/project_knowledge/{action}`. Responses are wrapped in the v1 envelope (`result`), and a client token needs a session confirmation for `delete` and `discard_draft`. The dashboard shipped in this release already uses the new operations.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#534](https://github.com/foolzzz/looper/pull/534); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.85
```

## Behavior changes

- **Eight operations on v1 ([#534](https://github.com/foolzzz/looper/pull/534)):** the new `looper/agents/v1_domains/project_knowledge.py` registers `project_knowledge.list`, `get` and `drafts` (risk `read`), `add`, `update` and `confirm_draft` (risk `write`), and `delete` and `discard_draft` (risk `high`), as `POST /api/v1/project_knowledge/{action}`. Requests are closed objects. `add` takes a `document` that is one of three shapes by `source_kind` (`text` with `content`, `upload` with `filename` and `content_base64`, `path` with `path`); `update` takes a non-empty `fields` object; `confirm_draft` takes optional `fields` (`title`, `summary`, `content`).
- **Same service, new door:** every operation calls the existing `knowledge` service functions the old routes called. Unknown project, document or draft becomes a v1 `not_found`, and a refused request (for example a document over a cap) becomes `invalid`, instead of the old JSON error bodies and status codes. The operations need the server's runtime root and answer `unavailable` without one.
- **Confirmation:** `delete` and `discard_draft` are `high` risk and ask for confirmation. A client token gets `needs_confirmation` with an impact text naming the document or draft, and nothing is removed until the confirmation is accepted; `delete` leaves the original project file and existing agent copies unchanged, and each removes only the selected item. A call from the operator session completes in one call.
- **Not operator-only:** unlike the registry view in v2.13.84, none of these operations is marked `operator_only`, so an API client credential can call them within the usual risk rules.
- **Schemas:** the document, knowledge view (`documents`, `count`, `stored_bytes`, `index`, `index_chars`, `caps`), draft and drafts view are closed schemas published in the OpenAPI document, so the generated CLI gets the `project_knowledge` commands.
- **Removed routes:** the eight `/api/projects/<id>/knowledge...` routes, their five URL patterns and the `_handle_knowledge` handler are removed from `looper/agents/http_server.py`.
- **Dashboard:** the knowledge functions in `web/src/lib/api.ts` (fetch, add, get, update, delete of documents; fetch, confirm and discard of drafts) call the v1 operations. `KnowledgeDocumentUpdate` also accepts `source_kind`.
- **Tests:** `tests/test_api_v1_project_knowledge.py` and `tests/test_api_v1_project_knowledge_db.py` were added, including that each retired method answers 404 while the v1 call succeeds; the existing project knowledge, project documents, task memory, request guard and URL-state tests were moved to the new operations.
- **Model-visible changes:** None found. Manager, Planner, Worker and Reviewer prompts, role recommended prompts and Tool declarations are unchanged; the new operations declare no Tool. The operations appear in the v1 operation catalog that API clients read.
- **Not confirmed in code:** the prose docs (`README.md`, `docs/architecture/agent-system.md`) were not edited by the PR and may still name the removed routes. This draft did not run any test.

## Upgrade and rollback

Re-run `install.sh` once v2.13.85 is published. No data migration; stored documents and drafts are untouched. Update any script that used the removed routes. Rolling back to v2.13.84 restores them together with the old dashboard.

### 行为变化与入口

- **八个 v1 操作（[#534](https://github.com/foolzzz/looper/pull/534)）：**新增 `looper/agents/v1_domains/project_knowledge.py`，注册 `project_knowledge.list`、`get`、`drafts`（风险 `read`），`add`、`update`、`confirm_draft`（风险 `write`），`delete`、`discard_draft`（风险 `high`），路径 `POST /api/v1/project_knowledge/{action}`。请求为封闭对象。`add` 的 `document` 按 `source_kind` 为三种形状之一（`text` 带 `content`，`upload` 带 `filename` 与 `content_base64`，`path` 带 `path`）；`update` 接收非空的 `fields`；`confirm_draft` 的 `fields`（`title`、`summary`、`content`）可选。
- **同一服务，新入口：**每个操作都调用旧路由所用的 `knowledge` 服务函数。项目、文档或草稿不存在转为 v1 `not_found`，被拒绝的请求（例如文档超过上限）转为 `invalid`，不再是旧的 JSON 错误正文和状态码。操作需要服务器的运行时根目录，没有时返回 `unavailable`。
- **确认：**`delete` 与 `discard_draft` 为 `high` 风险并要求确认。客户端令牌会得到带影响说明（点名文档或草稿）的 `needs_confirmation`，确认通过前不会删除任何内容；`delete` 不改动原项目文件和已有的 agent 副本，两者都只删除所选项。操作者会话一次调用即可完成。
- **非仅限操作者：**与 v2.13.84 的注册表视图不同，这些操作都没有标记 `operator_only`，API 客户端凭据可按常规风险规则调用。
- **Schema：**文档、知识视图（`documents`、`count`、`stored_bytes`、`index`、`index_chars`、`caps`）、草稿与草稿视图为封闭 schema，发布在 OpenAPI 文档中，因此生成的 CLI 有 `project_knowledge` 命令。
- **移除的路由：**八条 `/api/projects/<id>/knowledge...` 路由、五个 URL 正则以及 `_handle_knowledge` 处理器已从 `looper/agents/http_server.py` 移除。
- **仪表盘：**`web/src/lib/api.ts` 中的知识函数（文档的获取、添加、读取、更新、删除；草稿的获取、确认、丢弃）调用 v1 操作。`KnowledgeDocumentUpdate` 也接受 `source_kind`。
- **测试：**新增 `tests/test_api_v1_project_knowledge.py` 与 `tests/test_api_v1_project_knowledge_db.py`，包含每个已退役方法返回 404 而 v1 调用成功的检查；现有的项目知识、项目文档、任务记忆、请求守卫和 URL 状态测试已改用新操作。
- **面向模型的变化：**未发现。Manager、Planner、Worker、Reviewer 的 prompt、角色推荐 prompt 以及 Tool 声明均未改动；新操作未声明 Tool。这些操作会出现在 API 客户端读取的 v1 操作目录中。
- **代码中未确认：**PR 没有编辑散文文档（`README.md`、`docs/architecture/agent-system.md`），其中可能仍写着已移除的路由。本草稿未运行任何测试。
