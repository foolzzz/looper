# Looper v2.14.14

This is the patch release v2.14.14. It ships the one change merged since v2.14.13: [#900](https://github.com/foolzzz/looper/pull/900), which lets a schedule opt its tasks into user gates.

## Release Decision

**Who should upgrade:** Operators who want the tasks a schedule starts to be able to ask the user at a user gate (for example to confirm a decision) instead of always running unattended. Installations that do not use schedules, or that want them unattended, see no change. It ships the one change merged since v2.14.13.

**What this release solves:** [#900](https://github.com/foolzzz/looper/pull/900): a task started by a schedule could never open a user gate, because a schedule's run was always treated as unattended. A schedule now has a `user_gates` setting (`off` by default, or `on`) that lets its tasks open gates when its project also allows them, and the gates are delivered to the schedule's notify target, else the dashboard gate target, else the task page.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading). Every existing schedule keeps `off`.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#900](https://github.com/foolzzz/looper/pull/900); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.14
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.13 upgrades directly. This release adds one column, `schedules.user_gates` (`TEXT NOT NULL DEFAULT 'off'`, checked to `off` or `on`). The first start on an existing database adds it once (`looper/db/connection.py`, recorded in `schema_migrations` as `schedule_user_gates`); a fresh database gets it from `schema.sql`. The upgrade is additive and every existing schedule reads `off`. No other stored data or setting changes.

## Behavior changes

Only schedules and the tasks they start change, and only when a schedule is set to `on`. With every schedule `off`, the behavior is that of v2.14.13.

- **Setting:** `user_gates` is a schedule field (`off` or `on`, default `off`) in the schedule API (read and write schemas and the listing), the Manager's schedule tool (`looper/agents/ops/schedules.py`, which also shows it as 用户确认 in the schedule's summaries) and the dashboard schedule form and detail page. The form warns that the gate's wait counts against the run timeout when a run timeout applies.
- **Policy:** in `looper/agents/user_gates.py`, `gate_policy` returns `off` when the project has `user_gates` off; otherwise a scheduled task is `unattended` unless its schedule is `on`. A non-scheduled task is unchanged. The Planner reads the schedule's setting with its project (`looper/db/projects.py`).
- **Delivery:** in `looper/agents/gate_service.py` and `looper/agents/gate_courier.py`, the gates of a scheduled task post to the schedule's notify target, else to the dashboard gate target (`user_gates.dashboard_target`), else only to the task page. A target that the notify settings no longer offer is dropped, so the gate then shows only on the task page. Gates of tasks started by a user are delivered as before. `looper/db/user_gates.py` selects open gates for a chat accordingly.
- **Configuration transfer:** `user_gates` is exported with a schedule; an import that omits it sets `off`.
- **Model-visible changes:** Yes, only for a schedule set to `on`. Its run context (the `## 定时运行上下文` section the scheduler appends to the requirement) says the run allows user gates and that the wait counts against the run timeout, instead of saying the run is unattended. Its Planner is then allowed to open user gate steps, so its refusal text for gates is not shown. The Manager's schedule tool schema gains the `user_gates` field and its schedule listing and configuration text gain a 用户确认 line, for every schedule. For a schedule that is `off`, the run context and the Planner prompt are unchanged.

## 中文摘要

本版本是 patch release v2.14.14。自 v2.14.13 以来只合并了 [#900](https://github.com/foolzzz/looper/pull/900)：让定时任务（schedule）可以选择让其任务使用用户关卡。

### 升级决策

**谁需要升级：**希望定时任务启动的任务能在用户关卡处向用户确认、而不是总是无人值守运行的运维者。不使用定时任务或希望保持无人值守的安装没有变化。包含 v2.14.13 之后合并的唯一改动。

**解决了什么：**[#900](https://github.com/foolzzz/looper/pull/900)：定时任务启动的任务此前无法打开用户关卡，因为定时运行一律按无人值守处理。现在 schedule 有 `user_gates` 设置（默认 `off`，或 `on`），在项目也允许时其任务可打开关卡，关卡发送到 schedule 的通知对象，其次是控制台关卡目标，再次是任务页。

**是否有破坏性变更：**否。受支持的升级路径不变（见升级）。现有的 schedule 都保持 `off`。

**如何验证：**运行 `looper --version` 核对版本为 2.14.14。

**贡献者：**维护者 @foolzzz 提交 [#900](https://github.com/foolzzz/looper/pull/900)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.14
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.13 上的安装可直接升级。本版本新增一列 `schedules.user_gates`（`TEXT NOT NULL DEFAULT 'off'`，限定为 `off` 或 `on`）。已有数据库首次启动时加一次（`looper/db/connection.py`，在 `schema_migrations` 中记为 `schedule_user_gates`），新数据库由 `schema.sql` 创建。升级只增不改，现有 schedule 都读作 `off`。其他已存数据和设置不变。

### 行为变化与入口

只有 schedule 及其启动的任务发生变化，且仅当 schedule 设为 `on`。所有 schedule 为 `off` 时，行为与 v2.14.13 相同。

- **设置：**`user_gates` 是 schedule 的字段（`off` 或 `on`，默认 `off`），出现在 schedule API（读写 schema 与列表）、Manager 的 schedule 工具（`looper/agents/ops/schedules.py`，并在 schedule 摘要中显示为“用户确认”）以及控制台的 schedule 表单和详情页。适用运行超时时，表单提醒关卡的等待计入运行超时。
- **策略：**在 `looper/agents/user_gates.py` 中，项目的 `user_gates` 为 off 时 `gate_policy` 返回 `off`；否则定时任务为 `unattended`，除非其 schedule 为 `on`。非定时任务不变。Planner 随项目一并读取 schedule 的设置（`looper/db/projects.py`）。
- **投递：**在 `looper/agents/gate_service.py` 和 `looper/agents/gate_courier.py` 中，定时任务的关卡发送到 schedule 的通知对象，其次是控制台关卡目标（`user_gates.dashboard_target`），再次只在任务页。通知设置已不再提供的对象会被丢弃，此时关卡只显示在任务页。用户发起的任务的关卡投递不变。`looper/db/user_gates.py` 按此为聊天选取未结束的关卡。
- **配置迁移：**`user_gates` 随 schedule 导出；导入时缺省为 `off`。
- **面向模型的变化：**有，仅针对设为 `on` 的 schedule。其运行上下文（调度器追加到需求后的 `## 定时运行上下文` 一节）改为说明这次运行允许用户关卡、等待计入运行超时，而不是说明无人值守。其 Planner 可以打开用户关卡步骤，因此不再收到关卡的拒绝文本。Manager 的 schedule 工具 schema 增加 `user_gates` 字段，其 schedule 列表和配置文本对所有 schedule 增加一行“用户确认”。对 `off` 的 schedule，运行上下文与 Planner 提示不变。
