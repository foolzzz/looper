# Looper v2.14.108

This is the patch release v2.14.108, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.107: server log lines that name the task of a dispatched run, a log line when a Planner resumes from its saved plan, and a warning when the system was suspended ([#1166](https://github.com/foolzzz/looper/pull/1166)).

## Release Decision

**Who should upgrade:** Operators who search the server log by task id, or who need to explain a restart or a gap in it. Others are not affected: the change is observability only.

**What this release solves:** [#1166](https://github.com/foolzzz/looper/pull/1166). The Worker and Reviewer lines in the server log named the run but not its task or step, so a search for a task id missed its dispatches. A Planner resumed after a restart left only an activity row, and a machine sleep appeared as an unexplained gap. The lines now carry the task and step, a resume is logged, and a suspend is logged.

**Breaking changes:** No. No new dependency, no schema change, no configuration change. Only the text of some log lines changes (see below).

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.108
```

**Contributors:** Maintainer @foolzzz authored [#1166](https://github.com/foolzzz/looper/pull/1166); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.107 upgrades directly. There is no database or configuration change.

## Behavior changes

- **Worker and Reviewer log lines name the task** (`looper/agents/tiers/worker.py`). The INFO lines "dispatching", "starting run" and "run started" now say `worker` or `reviewer` (a verify request is a reviewer) and, when the parent task is known, append ` task=<parent task id> step=<step id>`. The line "waits for room" now reads `<agent> <id> task=… step=… waits: N <agent>s run, its limit L`; it no longer states the task id in its tail. Anything that matches the old text of these lines, for example a log filter, must be updated. The "dispatching" line used to say `worker` for every run.
- **Planner resume is logged** (`looper/agents/tiers/planner.py`). When a Planner resumes from a saved plan after a restart, one INFO line gives the task id, how many steps were re-dispatched (a new Worker or Reviewer run started for a step), how many runs were adopted (carried on across the restart) and how many decisions were resumed. It is written when the resume finishes or stops early (the plan ended, or the budget check refused). The resume logic itself is unchanged; the code was only moved inside a `try`/`finally` to write the line.
- **System suspend is logged** (`looper/agents/serve.py`). The server's existing 5-second check loop compares the wall clock with the monotonic clock at least every 30 seconds. When the wall clock moved ahead by more than 60 seconds, it writes one WARNING that the system was suspended for about N seconds. Nothing else reacts to it.
- **Documentation and tests.** New `tests/test_serve_suspend.py`, and extensions to `tests/test_worker_run_handles.py` and `tests/test_kept_planner_resume.py`.
- **Unchanged:** behavior of runs, dispatch, adoption and timers; dependencies, channels, billing, the database and the API.
- **Model-visible changes:** No. These are server log lines only. No prompt text, tool schema, launch environment or Manager-facing text changed.

## 中文摘要

本版本是 patch release v2.14.108（热修线，每个合并的改动立即发布）。自 v2.14.107 以来只合并了一项改动：服务器日志中标明所派发运行的任务，Planner 从已保存计划恢复时记录一行日志，系统休眠时记录一条警告（[#1166](https://github.com/foolzzz/looper/pull/1166)）。

### 升级决策

**谁需要升级：**按任务 id 搜索服务器日志，或需要解释重启和日志中断的运维人员。其他安装不受影响：该改动仅涉及可观测性。

**解决了什么：**[#1166](https://github.com/foolzzz/looper/pull/1166)。服务器日志中 Worker 和 Reviewer 的行只写运行 id，不写任务和步骤，按任务 id 搜索会漏掉其派发记录；重启后恢复的 Planner 只留下活动记录；机器休眠表现为无法解释的日志空档。现在这些行带有任务和步骤，恢复和休眠均有日志。

**是否有破坏性变更：**否。无新依赖，无数据库变更，无配置变更。只有部分日志行的文字变化（见下）。

**如何验证：**核对版本为 2.14.108。

**贡献者：**维护者 @foolzzz 提交 [#1166](https://github.com/foolzzz/looper/pull/1166)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.108
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.107 上的安装可直接升级。无数据库或配置变更。

### 行为变化与入口

- **Worker 和 Reviewer 日志行标明任务**（`looper/agents/tiers/worker.py`）。INFO 行 “dispatching”、“starting run”、“run started” 现在写明 `worker` 或 `reviewer`（验证请求为 reviewer），并在父任务已知时追加 ` task=<父任务 id> step=<步骤 id>`。“waits for room” 一行现在为 `<agent> <id> task=… step=… waits: N <agent>s run, its limit L`，不再在末尾写任务 id。匹配这些行旧文字的内容（例如日志过滤规则）需要更新。“dispatching” 行以前对所有运行都写 `worker`。
- **记录 Planner 恢复**（`looper/agents/tiers/planner.py`）。Planner 重启后从已保存计划恢复时，写一行 INFO：任务 id、重新派发的步骤数（为该步骤启动了新的 Worker 或 Reviewer 运行）、被接续的运行数（跨重启继续）、恢复的决策数。恢复结束或提前停止（计划已结束，或预算检查拒绝）时写出。恢复逻辑本身不变，代码只是移入 `try`/`finally` 以写这一行。
- **记录系统休眠**（`looper/agents/serve.py`）。服务器现有的 5 秒检查循环至少每 30 秒比较一次墙钟和单调时钟。墙钟领先超过 60 秒时，写一条 WARNING，说明系统休眠了约 N 秒。其他逻辑不对其作出反应。
- **文档与测试。**新增 `tests/test_serve_suspend.py`，并扩展 `tests/test_worker_run_handles.py` 和 `tests/test_kept_planner_resume.py`。
- **不变：**运行、派发、接续和计时器的行为；依赖、渠道、计费、数据库和 API。
- **面向模型的变化：**无。仅为服务器日志行。提示文字、工具 schema、启动环境和面向 Manager 的文字均无变化。
