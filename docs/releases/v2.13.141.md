# Looper v2.13.141

## Release Decision

**Who should upgrade:** Operators who want to try the Manager on a model API through the OpenAI Responses protocol. Everyone else can stay on v2.13.140: no existing profile changes.

**What this release solves:** [#684](https://github.com/foolzzz/looper/pull/684) lets the Manager answer on an api Profile. Until now the API runtime had a codec and a loop (v2.13.139, v2.13.140) but no session; this release adds `ApiSession`, calls the platform tools inside the service process with the same text, confirmation and audit as the MCP bridge, and registers the built-in `api` runtime (`rt-api`) at startup.

**Breaking changes:** No. Existing profiles, commands and APIs are unchanged. The new runtime runs only the Manager role and needs a profile with an API key.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#684](https://github.com/foolzzz/looper/pull/684); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.141
```

## Behavior changes

- **Runtime registration (#684):** `looper/agents/runtimes/__init__.py` adds `ApiRuntime` to `ADAPTERS`. Because the runtime needs no executable, `register_found_runtimes` now also registers the built-in `api` runtime (`rt-api`) once at startup, next to the CLI runtimes (`openai` is a normal dependency). It serves the Manager role only. No existing runtime or profile changes.
- **Session (#684):** `ApiRuntime.resident_session` returns `ApiSession` instead of refusing. It requires the provider key (`LOOPER_PROVIDER_API_KEY`) in the launch environment and refuses to start when `OPENAI_ORG_ID`, `OPENAI_PROJECT_ID`, `OPENAI_ADMIN_KEY`, `OPENAI_CUSTOM_HEADERS`, `ANTHROPIC_CUSTOM_HEADERS`, `OPENAI_LOG` or `ANTHROPIC_LOG` is set in the service environment. Conversation history is kept in memory, per session id, for at most four sessions; it is lost when the service restarts, and resuming an unknown session fails with an error. A turn makes at most 30 model requests; hitting the limit ends it with an error that says earlier tool effects were not undone. Provider errors become short redacted messages (key refused, model not found, API unavailable, context too long, reply truncated, request refused, stream unreadable). Stop is still refused and `interrupt` does nothing; a cancel is handled by the loop.
- **Events and usage (#684):** the loop's events become the internal assistant, tool-result, usage and result events that the Manager reads for the CLI runtimes, including thinking summaries, per-request token usage and an `api` block (protocol, request and retry counts, upstream ids). Usage is marked incomplete when a count is missing. The soft cap applies through the existing stop callback.
- **Platform tools (#684):** `looper/agents/runtimes/api/tools.py` lists tools from `ManagerOps.current_listing` and calls them through `ManagerOps.call` with the turn's binding and call id. Arguments that are not a JSON object are refused without running the tool. A result over 102,400 bytes is cut with a note asking for less. In `looper/agents/tiers/manager.py` the Manager hands these tools to a session that accepts them (`InProcessTools`) and skips the MCP tools probe for in-process runtimes.
- **Failure detail (#684):** `ApiRuntime.failure_detail` reports the first error of a failed turn, redacted and cut to 300 characters.
- **Tests and docs (#684):** new `tests/test_api_session.py`, `tests/test_api_manager_tools_db.py` and `tests/test_api_manager_turns_db.py`; existing registry, runtime-kind, profile-write and project-instruction tests are updated for the new runtime. The API runtime RFC (Chinese) and a long-horizon context plan are updated.
- **Model-visible changes:** for launches on the `api` runtime only, the system prompt gains a note: the model runs on a model API, its only tools are Looper's platform tools (`looper_*`), it cannot read or write files, run commands, browse or use skills, and should offer to create a task when the user needs any of that. The tool declarations it sees are the Manager's platform tools from the live listing; tool results are text capped at 100 KB. Prompts, tools and results of the CLI runtimes are unchanged.
- **Line counts:** the description reports tests 876 and production 318 added lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.141 is published. No schema or configuration change. The `api` runtime appears in the runtime registry after the service restarts; it is used only by a profile that selects it. Rolling back to v2.13.140 removes the session and the adapter registration; the already registered `rt-api` row, if any, cannot start a session there.

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**想在模型 API 上通过 OpenAI Responses 协议试用 Manager 的运维者。其他人可留在 v2.13.140：现有 profile 均不变。

**解决了什么：**[#684](https://github.com/foolzzz/looper/pull/684) 让 Manager 可以在 api Profile 上应答。此前 API 运行时只有编解码器和循环（v2.13.139、v2.13.140），没有会话；本版本加入 `ApiSession`，在服务进程内调用平台工具（文本、确认和审计与 MCP 桥一致），并在启动时注册内置 `api` 运行时（`rt-api`）。

**是否有破坏性变更：**否。现有 profile、命令和 API 均不变。新运行时只运行 Manager 角色，且需要带 API key 的 profile。

**如何验证：**运行 `looper --version` 核对版本为 2.13.141。

**贡献者：**维护者 @foolzzz 提交 [#684](https://github.com/foolzzz/looper/pull/684)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.141
```

### 行为变化与入口

- **运行时注册（#684）：**`looper/agents/runtimes/__init__.py` 把 `ApiRuntime` 加入 `ADAPTERS`。该运行时不需要可执行文件，因此 `register_found_runtimes` 启动时也会一次性注册内置 `api` 运行时（`rt-api`），与 CLI 运行时并列（`openai` 是常规依赖）。只服务 Manager 角色。现有运行时和 profile 不变。
- **会话（#684）：**`ApiRuntime.resident_session` 返回 `ApiSession`，不再拒绝。启动环境需带 provider 密钥（`LOOPER_PROVIDER_API_KEY`）；服务环境中若设置了 `OPENAI_ORG_ID`、`OPENAI_PROJECT_ID`、`OPENAI_ADMIN_KEY`、`OPENAI_CUSTOM_HEADERS`、`ANTHROPIC_CUSTOM_HEADERS`、`OPENAI_LOG` 或 `ANTHROPIC_LOG` 之一则拒绝启动。对话历史按会话 id 保存在内存中，最多 4 个会话，服务重启即丢失；恢复未知会话会报错。每轮最多 30 次模型请求，达到上限时以错误结束，并说明已执行的工具效果不会撤销。provider 错误转为简短的脱敏消息（密钥被拒、模型不存在、API 不可用、上下文过长、回复被截断、请求被拒、流不可读）。stop 仍被拒绝，`interrupt` 不做任何事；取消由循环处理。
- **事件与用量（#684）：**循环事件被转换为 Manager 读取 CLI 运行时时所用的 assistant、工具结果、用量和 result 事件，包括思考摘要、每次请求的 token 用量和 `api` 块（协议、请求与重试次数、上游 id）。计数缺失时用量记为不完整。软上限通过现有的 stop 回调生效。
- **平台工具（#684）：**`looper/agents/runtimes/api/tools.py` 从 `ManagerOps.current_listing` 列出工具，并带本轮 binding 与 call id 通过 `ManagerOps.call` 调用。参数不是 JSON 对象时拒绝且不运行工具。超过 102,400 字节的结果会被截断并附说明，请求缩小范围。`looper/agents/tiers/manager.py` 把这些工具交给接受它们的会话（`InProcessTools`），并对进程内运行时跳过 MCP 工具探测。
- **失败详情（#684）：**`ApiRuntime.failure_detail` 报告失败轮次的第一条错误，已脱敏并截为 300 字符。
- **测试与文档（#684）：**新增 `tests/test_api_session.py`、`tests/test_api_manager_tools_db.py` 和 `tests/test_api_manager_turns_db.py`；现有的注册表、运行时类型、profile 写入和项目说明测试已为新运行时更新。同时更新 API 运行时 RFC（中文）与一份长程上下文计划。
- **面向模型的变化：**仅对 `api` 运行时的启动，系统提示词新增一条说明：模型运行在模型 API 上，唯一的工具是 Looper 的平台工具（`looper_*`），不能读写文件、运行命令、浏览网页或使用 skills，用户需要这些时应提议创建任务。它看到的 tool 声明是实时列表中 Manager 的平台工具；工具结果为文本，上限 100 KB。CLI 运行时的提示词、工具和结果不变。
- **行数：**描述报告新增测试 876 行、生产代码 318 行（不含 fixtures）。

### 升级与回退

v2.13.141 发布后重跑 `install.sh`。无表结构或配置变更。服务重启后 `api` 运行时出现在运行时注册表中，只有选用它的 profile 才会使用。回退到 v2.13.140 会移除会话和适配器注册；已注册的 `rt-api` 行（若有）在该版本上无法启动会话。
