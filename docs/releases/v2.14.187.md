# Looper v2.14.187

This is the patch release v2.14.187, a hotfix line in which each merged change ships at once. It documents one change: [#1350](https://github.com/foolzzz/looper/pull/1350) (keep upstream credentials out of translated Claude settings).

## Release Decision

**Who should upgrade:** Operators who run Claude Code agents through a translated route (an OpenAI-compatible provider reached through Looper's local gateway) and do not want the provider key written into generated Claude Code settings.

**What this release solves:** [#1350](https://github.com/foolzzz/looper/pull/1350) keeps the upstream API key off disk on translated routes. Claude Code now holds only a random per-route local token; the gateway proxy reads the provider key from the provider registry into memory and sets the upstream Authorization header itself. Regenerated private Claude settings left by earlier versions are deleted at service startup. The PR also fixes two startup failures of translated launches (a slow cold proxy start and a first request that arrived before the registry connection was ready).

**Breaking changes:** No. The Telegram and Lark channel protocols and the CLI are unchanged, no new command or dashboard control is added and there is no database schema change. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.187
```

**Contributors:** Maintainer @foolzzz authored [#1350](https://github.com/foolzzz/looper/pull/1350); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.186 upgrades directly. There is no database schema change. Running translated agents should be restarted with the service; the next run regenerates its settings with a local token.

## Behavior changes

Read in the diff of [#1350](https://github.com/foolzzz/looper/pull/1350) (Python under `looper/agents/` and `looper/db/`, tests and architecture docs). The PR description presents these as the intended change.

- **Local route token (translated routes only).** `ProxyControl` gives each translation route a random token (`secrets.token_urlsafe(32)`, field `local_token`). Claude Code's `ANTHROPIC_AUTH_TOKEN` is set to that token, both in the process environment and in the private settings env (`claude_code.py`). The proxy (`proxy.py`, `check_route_token`) answers 401 `authentication_error` ("Invalid route token") to a translated-route request whose Bearer token is missing or wrong; the comparison is constant-time. A launch whose route has no token is refused like a missing gateway (`agent_settings.py`, `claude_code.py`). Direct (non-translated) runs keep their existing process-environment credential path.
- **Upstream key read by the proxy.** For each translated request the proxy calls `route_api_key` (`looper/agents/llmrec/gateway.py`), which reads the provider's key through the proxy's own PostgreSQL pool (new `resolve_route` in `looper/db/gateway.py`) and sets the upstream `Authorization` itself. The client's credential is never forwarded. The key is read per request, so rotation takes effect on the next request. A missing provider or key, a disabled provider, an auth kind other than API key, or a changed endpoint (registry `base_url` differs from the route's upstream) is refused with 403 `permission_error`; an unreachable registry returns 503. An alias-resolved key (`upstream_auth`) still takes precedence where the code already used it.
- **Route format 5.** `ROUTE_FORMAT` goes from 4 to 5 and the route file carries `local_token`. Route files of formats 3 and 4 are still read for lifecycle ownership (stopping and releasing old routes) but not accepted for new requests; a format 5 translated route without a token is rejected on read. Formats below 5 are written without the token.
- **Startup cleanup.** At service startup (after the database pool opens, before the schema step) every file under `.local/prompts/claude-settings` in the runtime root is deleted, including interrupted writes and settings written by older versions that contained the upstream key, and the removed count is logged ("Removed N private Claude settings files"). A startup timing entry `claude_settings_cleanup` is recorded. Settings are regenerated for each run.
- **Cold proxy start.** A translated launch allows up to 15 seconds for the proxy to start (was 3 s, which still applies to the best-effort recorder). A translated request waits for the registry connection within the existing 3-second credential lookup budget; the proxy now signals `pool_ready` when its pool connects, and recording health stays available meanwhile. A registry that stays unavailable still returns 503 without contacting the upstream.
- **Shutdown (not described in the PR).** `serve.py` also clears the managers change listener (`managers_api.set_change_listener(None)`) in its final cleanup. The diff shows no other effect.
- **Docs and tests.** The gateway section of `docs/architecture/agent-system.md` and the long-horizon context plan (zh-CN) describe the above. Tests cover the proxy, route files, control, gateway routes, serve and lifecycle (`test_gateway_proxy`, `test_llmrec_control`, `test_claude_code_gateway`, `test_gateway_routes`, `test_gateway_serve_db`, `test_serve_shutdown` and others).
- **Model-visible changes:** No change to a prompt, tool description or tool schema. The only change the Claude Code process sees is its environment: `ANTHROPIC_AUTH_TOKEN` is a local route token instead of the provider key, on translated routes.

### 行为变化与入口

以下在 [#1350](https://github.com/foolzzz/looper/pull/1350) 的差异中可见（`looper/agents/` 与 `looper/db/` 下的 Python、测试和架构文档）。PR 描述将这些视为有意的改动。

- **本地路由令牌（仅转译路由）。**`ProxyControl` 为每条转译路由生成随机令牌（`secrets.token_urlsafe(32)`，字段 `local_token`）。Claude Code 的 `ANTHROPIC_AUTH_TOKEN` 在进程环境和私有设置 env 中都设为该令牌。代理（`proxy.py` 的 `check_route_token`）对 Bearer 令牌缺失或错误的转译路由请求返回 401 `authentication_error`（"Invalid route token"），比较为常量时间。路由没有令牌的启动像缺少网关一样被拒绝。直接（非转译）运行保留原有的进程环境凭据路径。
- **上游密钥由代理读取。**每个转译请求中，代理调用 `route_api_key`（`looper/agents/llmrec/gateway.py`），通过代理自己的 PostgreSQL 连接池（`looper/db/gateway.py` 新增的 `resolve_route`）读取 provider 密钥，并自行设置上游 `Authorization`；不转发客户端凭据。密钥按请求读取，轮换在下一个请求生效。provider 或密钥缺失、provider 被禁用、认证类型不是 API key、或端点变化（注册表 `base_url` 与路由上游不同）会返回 403 `permission_error`；注册表不可达返回 503。代码原本使用别名解析密钥（`upstream_auth`）的地方，它仍然优先。
- **路由格式 5。**`ROUTE_FORMAT` 由 4 升至 5，路由文件携带 `local_token`。格式 3 和 4 的路由文件仍会为生命周期归属而读取（停止和释放旧路由），但不再接受用于新请求；没有令牌的格式 5 转译路由读取时被拒绝。低于 5 的格式写出时不含令牌。
- **启动清理。**服务启动时（数据库连接池打开之后、schema 步骤之前），运行时根目录下 `.local/prompts/claude-settings` 中的所有文件被删除，包括中断的写入和含上游密钥的旧版本设置，并记录删除数量（"Removed N private Claude settings files"）。启动计时新增 `claude_settings_cleanup` 项。设置在每次运行时重新生成。
- **代理冷启动。**转译启动最多允许代理启动 15 秒（此前为 3 秒，该值仍用于尽力而为的记录器）。转译请求在既有的 3 秒凭据查找预算内等待注册表连接；代理连接池连通时发出 `pool_ready` 信号，期间记录健康检查保持可用。注册表持续不可用时仍返回 503，且不会联系上游。
- **关闭（PR 描述未提及）。**`serve.py` 在最终清理中还清除了 managers 变更监听器（`managers_api.set_change_listener(None)`）。差异中看不到其他影响。
- **文档与测试。**`docs/architecture/agent-system.md` 的网关一节和长程上下文计划（zh-CN）描述了上述内容。测试覆盖代理、路由文件、控制、网关路由、serve 与生命周期（`test_gateway_proxy`、`test_llmrec_control`、`test_claude_code_gateway`、`test_gateway_routes`、`test_gateway_serve_db`、`test_serve_shutdown` 等）。
- **面向模型的变化：**提示词、工具描述和工具 schema 均未改变。Claude Code 进程唯一看到的变化是环境：转译路由上的 `ANTHROPIC_AUTH_TOKEN` 是本地路由令牌而不是 provider 密钥。
