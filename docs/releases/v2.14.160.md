# Looper v2.14.160

This is the patch release v2.14.160, a hotfix line in which each merged change ships at once. It documents one change: [#1286](https://github.com/foolzzz/looper/pull/1286) (room push follow-ups).

## Release Decision

**Who should upgrade:** Operators whose agents receive room messages pushed into their runs (Codex steer, or a Claude run that takes pushed deliveries). Runs that read their room by pull see no change.

**What this release solves:** [#1286](https://github.com/foolzzz/looper/pull/1286) stops push runs from being told that an answer "comes to your inbox". In those runs the answer to asking an ended seat says the reply will be delivered, the inbox tool no longer offers `wait_seconds` where a waiting report is the way to wait, and the watch answer carries unread counts. Unread messages that predate a push run are delivered at its start.

**Breaking changes:** No. There is no API change, no migration and no schema change; behavior changes are listed below. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.160
```

**Contributors:** Maintainer @foolzzz authored [#1286](https://github.com/foolzzz/looper/pull/1286); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.159 upgrades directly. There is no schema change.

## Behavior changes

The PR calls its behavior change an intended maintainer decision. The room input mode of a run is pull, pushed, or pushed with waiting reports; the changes below apply to the two pushed modes unless noted, and pull runs are unchanged.

- **Asking an ended seat** (`looper/agents/room.py`, `_deliver`). When a question goes to a seat with no run, the answer said the reply "comes to your inbox". In pushed runs it now says the reply "will be delivered to your run". With waiting reports it adds "if nothing else is left, use a waiting report"; in plain pushed mode it adds "if nothing else is left, wait with looper_room_inbox and wait_seconds".
- **Inbox tool, waiting-report mode** (`looper/agents/ops/room.py`). The `wait_seconds` property is removed from the tool's input schema, and a call that still passes it is refused with an invalid-argument error pointing to the waiting report. The description ends with "To wait for an answer, use a waiting report."
- **Inbox tool, plain pushed mode.** `wait_seconds` stays. The description keeps the pull text and adds that messages are delivered to the run and that a wait returns at once when a delivery arrives. The earlier line "wait_seconds is not needed" is gone.
- **Watch** (`RoomService.watch`). In pushed runs the watch tool's description says a notice is delivered to the run, and its answer note says "will be delivered to your run" instead of "comes to your inbox". In every mode the answer now also carries the unread counts (`unread`).
- **Unread at the start of a push run** (`looper/agents/tiers/worker.py`, `_room_reminders`). The reminder state starts pending, so messages that were already unread when the run began are delivered at its first tool call or wait without needing a new post.
- **Eval.** `evals/prompt_regression/compare.py` adds a "room inbox calls woken by delivery" column, and the fake Claude runner treats an inbox wait the schema no longer offers as a wait between turns. These are eval tooling and are not shipped behavior.
- **Tests.** Changed `tests/test_room.py`, `tests/test_room_ops.py`, `tests/test_worker_waiting.py`, `tests/test_eval_comparison.py`, `tests/test_prompt_eval.py`, `tests/test_room_db.py` and `tests/test_kept_adopt_db.py`.
- **Model-visible changes:** Yes, for push runs. The tool description of the inbox and watch tools, the inbox input schema (waiting-report mode), the room answers (asking an ended seat, watch note, `unread` in the watch answer), the refusal text for `wait_seconds`, and which unread messages a run is given at its start. The system prompt is not changed. The PR states that the real-mode prompt eval runs before merge; it reports no results.

### 升级决策

**谁需要升级：**其 agent 的房间消息被推送进运行（Codex steer，或接收推送投递的 Claude 运行）的运维者。按拉取方式读房间的运行无变化。

**是否有破坏性变更：**否。没有 API 变更、迁移或结构变更，行为变化见下。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.159 上的安装可直接升级。没有结构变更。

### 行为变化与入口

PR 称该行为变化是维护者的有意决定。运行的房间输入模式分为拉取、推送、推送加等待报告；以下变化适用于两种推送模式，拉取运行不变。

- **向已结束席位提问**（`looper/agents/room.py`，`_deliver`）。问题发给没有运行的席位时，回答原先说答复“进入你的收件箱”；推送运行中现在说答复“会投递到你的运行”。等待报告模式追加“如果没有别的事，用等待报告”；普通推送模式追加“如果没有别的事，用 looper_room_inbox 和 wait_seconds 等待”。
- **收件箱工具，等待报告模式**（`looper/agents/ops/room.py`）。输入 schema 去掉 `wait_seconds`，仍传入该参数的调用会被以无效参数拒绝，并指向等待报告。描述末尾为“等待答复请用等待报告”。
- **收件箱工具，普通推送模式。**保留 `wait_seconds`。描述沿用拉取模式的文字，并补充消息会投递到运行中、投递到达时等待立即返回；原先“不需要 wait_seconds”一句已删除。
- **Watch**（`RoomService.watch`）。推送运行中 watch 工具的描述说通知会投递到运行中，回答的说明由“进入收件箱”改为“会投递到你的运行”。所有模式下，回答现在都带未读计数（`unread`）。
- **推送运行开始时的未读消息**（`looper/agents/tiers/worker.py`，`_room_reminders`）。提醒状态初始为待处理，运行开始前已未读的消息会在第一次工具调用或等待时投递，无需新的发帖。
- **评测。**`evals/prompt_regression/compare.py` 增加“room inbox calls woken by delivery”一列，fake Claude 把 schema 不再提供的收件箱等待视为回合之间的等待。这些是评测工具，不是发布行为。
- **测试。**更新 `tests/test_room.py`、`tests/test_room_ops.py`、`tests/test_worker_waiting.py`、`tests/test_eval_comparison.py`、`tests/test_prompt_eval.py`、`tests/test_room_db.py`、`tests/test_kept_adopt_db.py`。
- **面向模型的变化：**有，限于推送运行：收件箱与 watch 工具的描述、收件箱输入 schema（等待报告模式）、房间回答（向已结束席位提问、watch 说明、watch 回答中的 `unread`）、`wait_seconds` 的拒绝文本，以及运行开始时收到哪些未读消息。系统提示词未改动。PR 称真实模式的提示词评测在合并前运行，但未报告结果。
