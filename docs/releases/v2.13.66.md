# Looper v2.13.66

## Release Decision

**Who should upgrade:** Dashboard users and anyone scripting the catalog acquisition HTTP routes (machine and MCP import, upload, Git preview and import, skill and MCP creation). Dashboard users see no change. Scripts that call the removed routes must move to the `/api/v1/catalog_sources/` routes.

**What this release solves:** [#484](https://github.com/foolzzz/looper/pull/484) moves the catalog's acquisition actions to the versioned API (`/api/v1/`) as seven `catalog_sources` operations with typed requests and results, reusing the existing library, MCP and catalog-source services. The seven legacy POST routes for them are removed.

**Breaking changes:** Yes. The seven legacy routes listed under Behavior changes no longer exist; a client that calls one gets a not-found answer. Stored data and configuration are unchanged.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#484](https://github.com/foolzzz/looper/pull/484); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.66
```

## Behavior changes

- **Removed routes (breaking for API clients):** `POST /api/catalog/import`, `POST /api/catalog/upload`, `POST /api/catalog/git/preview`, `POST /api/catalog/git/import`, `POST /api/catalog/skills`, `POST /api/catalog/mcp` and `POST /api/catalog/mcp/import`.
- **Replacements:** `POST /api/v1/catalog_sources/import_machine`, `import_mcp`, `upload`, `git_preview`, `git_import`, `create_skill` and `create_mcp`.
  - `upload` takes `{filename, content_base64, name?}`; `create_skill` takes `{name, description, content}`; `create_mcp` takes the MCP configuration with `name` and `transport` required.
  - `git_preview` takes `{url, ref?, subpath?}` and only reads; it writes nothing.
  - `git_import` takes `{url, ref?, subpath?, commit, items}`; `commit` (a 40 to 64 character hex id) and a non-empty `items` list of `{path, name?}` are required. If the repository moved since the preview, a client call is refused with a conflict answer.
- **Typed requests and results:** the seven operations declare closed request schemas (unknown fields are rejected) and typed results, including Git preview and import results and the skipped-file entries. In MCP input, `env` and `headers` are marked write-only; output keeps the existing masking.
- **Authority and confirmation:**
  - `import_machine`, `import_mcp` and `create_mcp` are operator-only credential writes: an API client is refused, and an invalid request is answered with a generic "invalid credential request" message.
  - `git_import` is a high-risk operation. An API client must confirm in a second step, and the confirmation covers replacing existing items from that repository, including local edits present at execution time. The operator runs it in one step, and the dashboard keeps its existing confirmation.
  - `git_preview`, `upload` and `create_skill` keep their existing rules: new items are installed nowhere, and the archive and URL safety rules are unchanged.
- **Dashboard:** the catalog import, upload, Git and creation calls use the new routes. The legacy catalog request helper and its handler are removed.
- **Documentation:** the Looper client skill RFC and the long-horizon context plan record the migration.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt changed, and no Manager Tool was added or changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.66 is published. No data migration. Update any script or client that called a removed route before upgrading. Rolling back to v2.13.65 restores the legacy routes, with no stored data affected.

## 中文摘要

### 升级决策

**谁需要升级：**仪表盘用户，以及脚本调用目录获取来源 HTTP 路由（本机与 MCP 导入、上传、Git 预览与导入、创建 skill 与 MCP）的人。仪表盘用户看不到变化；调用已删除路由的脚本需要改用 `/api/v1/catalog_sources/` 路由。

**解决了什么：**[#484](https://github.com/foolzzz/looper/pull/484) 把目录的获取来源操作迁到版本化 API（`/api/v1/`），作为七个带类型化请求与结果的 `catalog_sources` 操作，复用现有的 library、MCP 与目录来源服务，并删除对应的七个旧 POST 路由。

**是否有破坏性变更：**是。“行为变化”中列出的七个旧路由不再存在，调用会得到 not found。存储数据和配置不变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.66。

**贡献者：**维护者 @foolzzz 提交 [#484](https://github.com/foolzzz/looper/pull/484)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.66
```

### 行为变化与入口

- **已删除的路由（对 API 客户端是破坏性的）：**`POST /api/catalog/import`、`/api/catalog/upload`、`/api/catalog/git/preview`、`/api/catalog/git/import`、`/api/catalog/skills`、`/api/catalog/mcp`、`/api/catalog/mcp/import`。
- **替代路由：**`POST /api/v1/catalog_sources/import_machine`、`import_mcp`、`upload`、`git_preview`、`git_import`、`create_skill`、`create_mcp`。
  - `upload` 收 `{filename, content_base64, name?}`；`create_skill` 收 `{name, description, content}`；`create_mcp` 收 MCP 配置，`name` 与 `transport` 必填。
  - `git_preview` 收 `{url, ref?, subpath?}`，只读，不写入。
  - `git_import` 收 `{url, ref?, subpath?, commit, items}`；`commit`（40 到 64 位十六进制）与非空的 `items`（`{path, name?}`）必填。若仓库自预览后已变化，客户端调用会被以冲突拒绝。
- **类型化请求与结果：**七个操作声明了封闭的请求 schema（拒绝未知字段）和类型化结果，包括 Git 预览与导入结果及跳过文件条目。MCP 输入中的 `env` 与 `headers` 标为 writeOnly；输出沿用既有遮罩。
- **权限与确认：**
  - `import_machine`、`import_mcp`、`create_mcp` 为仅操作者的凭据写入：API 客户端被拒绝，无效请求只返回通用的“invalid credential request”。
  - `git_import` 为 high 风险。API 客户端须两步确认，确认范围包括替换该仓库已有条目，也包括执行时存在的本地修改；操作者单次执行，仪表盘保留原有确认。
  - `git_preview`、`upload`、`create_skill` 规则不变：新条目不安装到任何位置，归档与 URL 安全规则不变。
- **仪表盘：**目录的导入、上传、Git 与创建调用改用新路由。旧的目录请求辅助函数及其处理器已删除。
- **文档：**Looper 客户端 skill RFC 与长程上下文计划记录了此次迁移。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 均未改动，未新增或修改 Manager Tool。

### 升级与回退

v2.13.66 发布后重跑 `install.sh`。无需迁移数据。升级前请更新调用已删除路由的脚本或客户端。回退到 v2.13.65 会恢复旧路由，不影响已存数据。
