# Looper v2.13.50

## Release Decision

**Who should upgrade:** Operators who use the web console's Chat page or the User Gates page, in particular those who go Back and Forward between conversations or keep reply drafts on a long gate list. Nobody else needs to act.

**What this release solves:** [#436](https://github.com/foolzzz/looper/pull/436) fixes the open review follow-ups for the web chat address and the User Gates page: a bare chat address now names its thread, Back and Forward restore the matching conversation, and a gate list refresh keeps loaded rows and reply drafts when a gate closes or a new one opens.

**Breaking changes:** No. The `/api/gates` response gains fields and parameters; existing parameters and fields are unchanged.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#436](https://github.com/foolzzz/looper/pull/436); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.50
```

## Behavior changes

- **Gate list API (`looper/agents/gate_service.py`, `looper/db/user_gates.py`):** `GET /api/gates` accepts `cursor=<next_cursor>`, which continues after the previous page, and `through=<next_cursor>`, which returns the rows up to and including the previously loaded last row, even if that gate has since closed. Both are compared in PostgreSQL on `(COALESCE(opened_at, created_at), step_id)`, so ties use the same collation as the list order. A malformed value answers 400 (`<name> must be a gate list cursor`), and `cursor` with a nonzero `offset` answers 400 (`cursor and offset cannot be combined`). The response adds `next_cursor` (an opaque boundary, null for an empty page) and `has_more`. The list reads one extra row to compute `has_more`. For the `open` state, `total` now comes from `counts` (`open`, or `waiting_user` / `waiting_planner` with `waiting_on`) instead of the length of the filtered list.
- **User Gates page (`web/src/pages/gates.tsx`):** the page keeps a cursor instead of a row count. "Show more" requests after the cursor; a refresh requests through the last loaded gate, in pages, so a gate that closed or a gate that opened in front no longer drops loaded rows or displaces open reply drafts.
- **Chat page (`web/src/App.tsx`, `web/src/pages/chat.tsx`):** a bare `#chat` address is rewritten in place (history replace, no new entry) to name the thread in use, so New conversation pushes the next entry and Back restores the earlier conversation. An address naming a `planner-` or channel (`:`) conversation that has no messages shows "Conversation not found." instead of being adopted as a new web conversation. `/new` is matched case-insensitively, and a failed `/new` stays a command reply rather than becoming a retry draft.
- **Session profile label (`web/src/lib/api.ts`):** the label now ends with the effort when the profile has one, for example `Fast — codex · OpenAI / gpt · high`.
- **Task page (`web/src/pages/tasks.tsx`):** selecting Room while already on the Room tab no longer navigates, so its kind and role filters stay.
- **Documentation:** `docs/architecture/agent-system.md` describes the new `/api/gates` parameters and the `?session_id=` read of `/api/chat/sessions`. The server code for that read was not changed by this pull request; the web client already used it.
- **Model-visible changes:** None. No prompt, tool result, OpenAPI document or channel text changed.
- **Tests:** The pull request reports added lines: tests 25, production 206 (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.50 is published. No data migration. Rolling back to v2.13.49 restores offset-only gate paging and the earlier chat address behavior; nothing is stored differently.

### 行为变化与入口

- 关卡列表接口：`GET /api/gates` 新增 `cursor=<next_cursor>`（接续上一页）和 `through=<next_cursor>`（返回直到并包含此前已加载的最后一行，即使该关卡已关闭）。两者在 PostgreSQL 中按 `(COALESCE(opened_at, created_at), step_id)` 比较，与列表排序使用同一排序规则。格式错误返回 400，`cursor` 与非零 `offset` 同用也返回 400。响应新增 `next_cursor`（不透明边界，空页为 null）和 `has_more`；列表多读一行以计算 `has_more`。`open` 状态下 `total` 改取自 `counts`。
- User Gates 页：页面保存游标而非行数。“显示更多”从游标之后读取；刷新读取到最后已加载的关卡为止并分页，因此关卡关闭或前面新增关卡都不再丢失已加载行或挤掉未提交的回复草稿。
- 聊天页：裸 `#chat` 地址会原位（替换历史，不新增条目）改写为当前线程，因此新建对话压入下一条记录，后退可恢复之前的对话。指向没有消息的 `planner-` 或渠道（含 `:`）对话的地址显示“Conversation not found.”，不再当作新的 Web 对话。`/new` 不区分大小写，失败的 `/new` 保持为命令回复而不是重试草稿。
- 会话 Profile 标签：若 Profile 有 effort，标签末尾显示，如 `Fast — codex · OpenAI / gpt · high`。
- 任务页：已在 Room 标签时再次选择 Room 不再跳转，类型和角色筛选得以保留。
- 文档：`docs/architecture/agent-system.md` 补充 `/api/gates` 新参数及 `/api/chat/sessions` 的 `?session_id=` 读取。该读取的服务端代码并非本 PR 修改，Web 客户端此前已在使用。
- 面向模型的变化：无。提示词、工具结果、OpenAPI 文档和渠道文案均未改动。
- 测试：PR 报告新增测试 25 行、生产代码 206 行（不含 fixture）。
