# Looper v2.13.178

## Release Decision

**Who should upgrade:** Maintainers and contributors who run the prompt-regression evals, register eval agent specs or read CI results. It is a hotfix that ships the changes merged since v2.13.177; no runtime code under `looper/` changed.

**What this release solves:** [#786](https://github.com/foolzzz/looper/pull/786) splits the PR Python tests into four parallel CI shards behind one required "Agent system tests" check. [#765](https://github.com/foolzzz/looper/pull/765) makes the eval tooling accept only current formats: explicit-endpoint agent specs, the `looper-prompt-eval/v2` report schema and the current four-tier launch contracts, and retires the pinned historical launch captures.

**Breaking changes:** Yes, for the eval tooling only. No command, configuration format or schema of the product changed. In the eval tooling, an eval agent spec with `agent.model`, `provider.protocols`, `provider.base_url` or `provider.models`, or without a top-level `model`, is now refused, and `compare` refuses reports that are not at the current schema.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#786](https://github.com/foolzzz/looper/pull/786) and [#765](https://github.com/foolzzz/looper/pull/765); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.178
```

## Behavior changes

- **Sharded CI ([#786](https://github.com/foolzzz/looper/pull/786)):** in `.github/workflows/python-tests.yml` the `agent-system` job becomes a four-shard matrix named `Agent system tests (shard N/4)` (`fail-fast: false`, job timeout 15 minutes, down from 20), each setting `LOOPER_TEST_SHARD=N/4`. A new `agent-system-result` job named exactly `Agent system tests` runs with `if: always()` and fails unless every shard succeeded. `tests/conftest.py` reads `LOOPER_TEST_SHARD`: a value that is not `N/TOTAL` with 1 <= N <= TOTAL raises a usage error. In `pytest_collection_modifyitems` it assigns whole test files to shards, largest first and by path on ties, so every xdist worker agrees; `tests/test_prompt_eval.py` counts four times per case. Unset, every test runs as before.
- **Eval specs ([#765](https://github.com/foolzzz/looper/pull/765)):** `register_agent` in `evals/prompt_regression/runner.py` requires a top-level `model`, refuses `agent.model`, `agent.provider_id` and `agent.model_id`, and refuses a provider with `protocols`, `base_url` or `models`. The legacy converter `_legacy_eval_spec` is removed. `evals/agents/*.example.json`, `examples/dsh/agent-spec.json` and `examples/pi/eval-common.sh` use `endpoints` plus a `model` layer.
- **Eval reports ([#765](https://github.com/foolzzz/looper/pull/765)):** new `validate_report` accepts only `looper-prompt-eval/v2` (or `looper-manager-dialogs/v2` for dialogs). `compare` in `evals/prompt_regression/__main__.py` prints the error and returns 2 on any other schema, and `previous_run` and `comparison_base` validate too. `compare.outcome` and `compare.error_class` no longer derive a v1 row's outcome; the rows must carry `outcome`. The committed `baselines/real-sonnet.json` is migrated to v2 (`rep`, `outcome`, `reps`, `aborted`).
- **Launch captures ([#765](https://github.com/foolzzz/looper/pull/765)):** `tests/model_launch_parity.py` now checks current four-tier launch contracts, `tests/test_current_tier_launch_db.py` is new, and `tests/test_model_launch_parity_db.py`, `tests/test_model_launch_capture_db.py` and the `launch-provenance.yml` workflow (scheduled and path-triggered) are deleted.
- **Model-visible changes:** none. No system prompt, tool description, tool schema or runtime prompt changed; the change is in CI, tests and the eval tooling.

## Upgrade and rollback

Re-run `install.sh` once v2.13.178 is published. There is no schema change, so rolling back to v2.13.177 needs nothing else. Eval specs and reports kept in the old format must be rewritten or regenerated before use.

### 升级决策

**谁需要升级：**运行 prompt-regression 评测、注册评测 agent spec 或查看 CI 结果的维护者和贡献者。本版本是随合并即发布的 hotfix；`looper/` 下没有运行时代码改动。

**解决了什么：**[#786](https://github.com/foolzzz/looper/pull/786) 把 PR 的 Python 测试拆成四个并行 CI 分片，并保留一个必需的 “Agent system tests” 检查。[#765](https://github.com/foolzzz/looper/pull/765) 让评测工具只接受当前格式：显式 endpoint 的 agent spec、`looper-prompt-eval/v2` 报告 schema 和当前四层启动契约，并移除固定的历史启动抓取。

**是否有破坏性变更：**有，仅限评测工具；已安装的 Looper 无破坏性变更：产品的命令、配置格式和 schema 均未改变。评测工具：带 `agent.model`、`provider.protocols`、`provider.base_url`、`provider.models` 或缺少顶层 `model` 的评测 agent spec 现在会被拒绝，`compare` 也拒绝非当前 schema 的报告。

**如何验证：**运行 `looper --version` 核对版本为 2.13.178。

**贡献者：**维护者 @foolzzz 提交 [#786](https://github.com/foolzzz/looper/pull/786) 和 [#765](https://github.com/foolzzz/looper/pull/765)；本次 patch release 无社区贡献。

### 行为变化与入口

- **CI 分片（#786）：**`python-tests.yml` 的 `agent-system` 作业变为四分片矩阵 `Agent system tests (shard N/4)`（`fail-fast: false`，作业超时由 20 分钟降为 15 分钟），各自设置 `LOOPER_TEST_SHARD=N/4`。新增的 `agent-system-result` 作业名为 `Agent system tests`，以 `if: always()` 运行，任一分片未成功即失败。`tests/conftest.py` 读取 `LOOPER_TEST_SHARD`：不是 `N/TOTAL`（1 <= N <= TOTAL）则报用法错误；`pytest_collection_modifyitems` 按整文件分配分片，大文件优先、同权重按路径排序，使各 xdist worker 一致；`tests/test_prompt_eval.py` 每个用例按 4 倍计权。未设置时所有测试照常运行。
- **评测 spec（#765）：**`runner.py` 的 `register_agent` 要求顶层 `model`，拒绝 `agent.model`、`agent.provider_id`、`agent.model_id`，也拒绝带 `protocols`、`base_url` 或 `models` 的 provider；移除旧版转换器 `_legacy_eval_spec`。`evals/agents/*.example.json`、`examples/dsh/agent-spec.json` 和 `examples/pi/eval-common.sh` 改用 `endpoints` 加 `model` 层。
- **评测报告（#765）：**新增 `validate_report`，只接受 `looper-prompt-eval/v2`（对话评测为 `looper-manager-dialogs/v2`）。`compare` 遇到其他 schema 时打印错误并返回 2，`previous_run` 和 `comparison_base` 也会校验。`compare.outcome` 与 `compare.error_class` 不再为 v1 行推导结果，行必须带 `outcome`。已提交的 `baselines/real-sonnet.json` 迁移到 v2（`rep`、`outcome`、`reps`、`aborted`）。
- **启动抓取（#765）：**`tests/model_launch_parity.py` 现在检查当前四层启动契约，新增 `tests/test_current_tier_launch_db.py`，删除 `tests/test_model_launch_parity_db.py`、`tests/test_model_launch_capture_db.py` 以及 `launch-provenance.yml` 工作流（定时与按路径触发）。
- **面向模型的变化：**无。没有系统 prompt、工具描述、工具 schema 或运行时 prompt 改动；改动在 CI、测试和评测工具中。
