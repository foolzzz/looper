# Looper v2.13.51

## Release Decision

**Who should upgrade:** Operators who use Stop on a running turn, in particular those who run agent runtimes that leave child processes behind or who use the Grok runtime when it falls back from ACP to its legacy transport. Nobody else needs to act.

**What this release solves:** [#442](https://github.com/foolzzz/looper/pull/442) fixes the open review follow-ups for stopping runtimes (process tree and runtime binding): Stop no longer remembers or signals the children of a process whose pid was reused, and a Grok turn that falls back to the legacy transport rebinds its owner before any tool call.

**Breaking changes:** No. No API, configuration or stored data changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#442](https://github.com/foolzzz/looper/pull/442); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.51
```

## Behavior changes

- **Process tree (`looper/agents/proc_tree.py`):** `_tree` takes a `skip` set of pids. A skipped pid contributes neither its children nor its process group, and when no process listing is available the agent's own group is not added if the agent is skipped. A turn's end now computes the reused leaders first and passes them as `skip` to the refresh, so the unrelated children of a process whose pid was reused are never merged into the seen set. A refresh also drops remembered groups whose leader is no longer listed, and the search for stray processes applies the same exclusion. The end-of-agent member listing uses `skip` in place of filtering the result afterwards, which also stops it from walking into excluded pids' children.
- **Grok runtime and manager binding (`looper/agents/runtimes/grok_acp.py`, `looper/agents/tiers/manager.py`):** when the ACP transport is unavailable and the turn falls back to the legacy transport, the runtime emits a `system` event with subtype `transport` before the legacy turn starts. The manager answers that event by republishing the turn's binding, so the per-turn tool bridge is bound to the transport actually in use before it can call a tool.
- **Stop real-path probe (`evals/stop_realpath.py`):** the write probe waits for the `answer.final` event of the turn's event stream and fails unless its outcome is `answered`, instead of treating any reply message as success. This is an evaluation script, not part of the served product.
- **Tests:** the Claude stop matrix fixture now reports a growing total cost, and the resident-session test checks that a turn's cost is added to the session totals exactly once. New tests cover the process-tree exclusion, the manager's rebinding on the transport event and the probe's outcome check.
- **Model-visible changes:** None. No prompt, tool result, OpenAPI document or channel text changed. The new `system` / `transport` event is internal to the runtime and its owner.
- **Tests added:** The pull request reports added lines: tests 117, production 20 (fixtures excluded).

### 行为变化与入口

- 进程树：`_tree` 新增 `skip` 集合。被跳过的 pid 既不贡献其子进程也不贡献其进程组；无进程列表时，若代理被跳过则不加入其自身进程组。轮次结束时先计算 pid 被复用的领导进程并作为 `skip` 传给刷新，因此其无关子进程不会并入已见集合。刷新还会丢弃领导进程已不在列表中的已记录进程组，散落进程的查找采用同样的排除。代理结束时的成员列表改用 `skip`，不再事后过滤，也不会进入被排除 pid 的子进程。
- Grok 运行时与管理者绑定：ACP 传输不可用并回退到旧传输时，运行时在旧轮次开始前发出 subtype 为 `transport` 的 `system` 事件；管理者收到后重新发布该轮次的绑定，使每轮工具桥在可调用工具前绑定到实际使用的传输。
- 停止真实路径探针（`evals/stop_realpath.py`）：写入探针等待该轮事件流的 `answer.final` 事件，仅当结果为 `answered` 才算通过，而不是只要有回复消息就算成功。这是评估脚本，不属于对外服务。
- 测试：Claude 停止矩阵夹具改为报告递增的总成本，常驻会话测试检查一轮的成本恰好计入会话总计一次。新增测试覆盖进程树排除、管理者对 transport 事件的重新绑定以及探针的结果检查。
- 面向模型的变化：无。提示词、工具结果、OpenAPI 文档和渠道文案均未改动；新的 `system` / `transport` 事件仅在运行时与其所有者之间内部使用。
- 新增测试：PR 报告新增测试 117 行、生产代码 20 行（不含 fixture）。
