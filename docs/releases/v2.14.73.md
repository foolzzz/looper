# Looper v2.14.73

This is the patch release v2.14.73, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.72: an operator can name one directory under which every new project gets its own directory ([#1069](https://github.com/foolzzz/looper/pull/1069)).

## Release Decision

**Who should upgrade:** Operators who want projects created without a directory (by the Manager, the dashboard or the API) to get a default directory automatically. With `[projects] root` unset, nothing changes.

**What this release solves:** a project created without a directory had no default, so the Manager had to ask for one and the dashboard required one. [#1069](https://github.com/foolzzz/looper/pull/1069) adds the file-only ops setting `[projects] root`; with it set, a new project gets its own directory directly under that root, named after the project, and its tasks run there.

**Breaking changes:** No. With the setting unset, behavior and the Manager's prompt and tool texts are unchanged, and there is no migration.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#1069](https://github.com/foolzzz/looper/pull/1069); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.73
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.72 upgrades directly. This release adds no migration.

## Behavior changes

- **Ops file.** A new `[projects] root` (file only, an absolute path; `looper/ops_config.py`). The service logs `projects root=<path>` or `projects root unset` at startup, and a self check (`check_projects_root`) warns when the root is not an existing, writable directory; unset it is skipped. `looper serve` also writes the setting back when it renders an ops file that has one.
- **Project create.** With the root set, a project created without a directory (API, dashboard, Manager, or inside a task create) gets `<root>/<safe name>`, created on disk (mode 0755). The safe name replaces characters outside letters, digits, `.`, `_` and `-` with `-` and is lowercased. A name collision with another project's directory gets a `-2`, `-3`... suffix; an existing directory at that path (a symbolic link included) that no project uses is used as is. Creation is serialized by a table lock on `projects`. A directory the create made is removed again (only if empty) when the create or the enclosing task create fails. An explicit directory and existing projects are unchanged.
- **Task create.** A new project without a directory no longer needs a task work directory when the root is set: the task runs in the allocated directory, and the workspace check runs against it inside the same transaction. The confirmation text for a new project says the directory is assigned under the root.
- **API.** `projects.list` now carries `projects_root` (empty when unset). The Manager's compact `looper_projects` list adds `projects_root` only when it is set.
- **Dashboard.** Tasks → Create New Task → New project can leave both directory fields blank when the root is set, and the server assigns the directory; the project dialog says so under its directory field.
- **Config import.** A project imported without a directory gets one under the root on apply; directories made are removed if the import transaction fails.
- **Evals.** The dialog runner can give a dialog's server a projects root; two new dialogs, `root_new_project` and `root_ask_project`.
- **Telegram, Lark and the CLI** need no change: they create projects and tasks through the Manager and the same API.
- **Size:** per the changed files of the pull request, about 1,100 added lines in total, of which about 820 are tests.
- **Model-visible changes:** Yes, only when the root is set. The Manager's tools contract, the built-in role text, the `looper_projects` and `looper_task_create` descriptions (including the `work_dir` field) and the prompt preview say a new project gets `<root>/<name>` and the Manager need not ask for a directory; an existing project without a default still needs the user to name one. The compact `looper_projects` list result may include `projects_root`. With the root unset these texts and results are unchanged (the pull request reports a byte-identical test).

## Optional Capability Activation & Use

### Projects root ([projects] root)

**Activation:** Add `[projects]` with `root = "<absolute directory>"` to the ops file, create the directory so the user running Looper can write to it, and restart `looper serve`.

```bash
printf '[projects]\nroot = "/absolute/path/to/projects"\n'   # add these lines to the ops file
looper serve --config <ops file> --runtime-root <root>
```

**Validation:** The startup log shows `projects root=<path>` and the self check `Projects root` is OK. Create a project without a directory (dashboard, API or Manager); its directory is `<root>/<name>`.

**Disable / rollback:** Remove the section and restart. Projects already created keep their directories; new ones need a directory again.

**Authority boundary:** The setting is read from the ops file only; no API, dashboard or Manager can change it. Looper creates directories only directly under the root, for new projects without a directory, and removes only an empty directory it made itself when that create fails.

**Docs:** [docs/architecture/agent-system.md](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md).

## 中文摘要

本版本是 patch release v2.14.73（热修线，每个合并的改动立即发布）。自 v2.14.72 以来只合并了一项改动：运维人员可以指定一个目录，每个新项目在其下获得自己的目录（[#1069](https://github.com/foolzzz/looper/pull/1069)）。

### 升级决策

**谁需要升级：**希望未指定目录创建的项目（经 Manager、控制台或 API）自动获得默认目录的运维人员。未设置 `[projects] root` 时没有变化。

**解决了什么：**未指定目录的项目没有默认目录，Manager 必须询问，控制台也要求填写。[#1069](https://github.com/foolzzz/looper/pull/1069) 增加仅限文件的 ops 设置 `[projects] root`；设置后新项目在该根目录下获得以项目命名的独立目录，其任务在该目录运行。

**是否有破坏性变更：**否。未设置时行为以及 Manager 的提示和工具文本不变，没有迁移。

**如何验证：**运行 `looper --version` 核对版本为 2.14.73。

**贡献者：**维护者 @foolzzz 提交 [#1069](https://github.com/foolzzz/looper/pull/1069)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.73
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.72 上的安装可直接升级。本版本没有迁移。

### 行为变化与入口

- **Ops 文件。**新增 `[projects] root`（仅限文件，绝对路径；`looper/ops_config.py`）。服务启动时记录 `projects root=<path>` 或 `projects root unset`，自检（`check_projects_root`）在该目录不存在或不可写时告警；未设置时跳过。渲染含该设置的 ops 文件时也会写回。
- **创建项目。**设置后，未指定目录的项目（API、控制台、Manager，或任务创建中）获得 `<root>/<安全名称>`，并在磁盘上创建（权限 0755）。安全名称把字母、数字、`.`、`_`、`-` 以外的字符替换为 `-` 并转小写。与其他项目目录冲突时加 `-2`、`-3`… 后缀；该路径上已存在且无项目使用的目录（包括符号链接）按原样使用。创建由 `projects` 表锁串行化。创建失败或所在任务创建失败时，本次创建的目录（仅当为空）被删除。显式目录和已有项目不变。
- **创建任务。**设置后，未指定目录的新项目不再要求任务工作目录：任务在分配的目录中运行，工作区检查在同一事务内针对它进行。新项目的确认文本说明目录由该根目录分配。
- **API。**`projects.list` 增加 `projects_root`（未设置时为空）。Manager 的精简 `looper_projects` 列表仅在设置时包含 `projects_root`。
- **控制台。**设置后，任务 → 新建任务 → 新项目可以把两个目录字段都留空，由服务器分配目录；项目对话框在目录字段下说明这一点。
- **配置导入。**导入时未指定目录的项目在应用时获得根目录下的目录；导入事务失败则删除所建目录。
- **评测。**对话运行器可以给对话的服务器指定 projects root；新增两个对话 `root_new_project` 和 `root_ask_project`。
- **Telegram、Lark 和 CLI** 无需改动：它们通过 Manager 和同一 API 创建项目和任务。
- **规模：**据 PR 的改动文件，共新增约 1,100 行，其中约 820 行为测试。
- **面向模型的变化：**有，仅在设置 root 时。Manager 的工具契约、内置角色文本、`looper_projects` 和 `looper_task_create` 的说明（含 `work_dir` 字段）以及提示预览说明新项目获得 `<root>/<name>`，Manager 无需询问目录；没有默认目录的已有项目仍需用户指定。精简的 `looper_projects` 列表结果可能包含 `projects_root`。未设置 root 时这些文本和结果不变（PR 报告有字节一致的测试）。

### 可选能力启用与使用

#### Projects root ([projects] root)

**启用：**在 ops 文件中添加 `[projects]` 段并设置 `root = "<绝对目录>"`，创建该目录并确保运行 Looper 的用户可写，然后重启 `looper serve`。

```bash
printf '[projects]\nroot = "/absolute/path/to/projects"\n'   # add these lines to the ops file
looper serve --config <ops file> --runtime-root <root>
```

**验证：**启动日志显示 `projects root=<path>`，自检 `Projects root` 为 OK。不指定目录创建项目（控制台、API 或 Manager），其目录为 `<root>/<name>`。

**停用 / 回退：**删除该段并重启。已创建的项目保留其目录；之后新建的项目又需要指定目录。

**权限边界：**该设置只从 ops 文件读取，API、控制台和 Manager 都无法修改。Looper 只在该根目录正下方、为未指定目录的新项目创建目录，创建失败时只删除自己创建的空目录。

**文档：**[docs/architecture/agent-system.md](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md)。
