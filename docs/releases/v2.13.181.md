# Looper v2.13.181

## Release Decision

**Who should upgrade:** Operators that run agents through the runner protocol, and maintainers who run the runner tests. It is a hotfix that ships the changes merged since v2.13.180.

**What this release solves:** [#782](https://github.com/foolzzz/looper/pull/782) owns the child processes that a runner starts during initialization before the runner is published, so a runner killed right after it starts no longer leaves such a child behind. It also adds a deterministic fake runner and acceptance tests that prove runner tools and charging on an isolated service.

**Breaking changes:** No. No command, schema or file format changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#782](https://github.com/foolzzz/looper/pull/782); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.181
```

## Behavior changes

- **Initialization children are owned early ([#782](https://github.com/foolzzz/looper/pull/782)):** in `looper/agents/runtimes/runner/supervisor.py`, `RunnerSupervisor` calls `await generation.tree.refresh(force=True)` after `self.connect(...)` returns and before `bridge.on_failure` is set and the generation is published. Children that the runner started during `initialize`, after the launch snapshot, are in the tracked tree when the runner is killed immediately, and are cleaned up on recovery and on shutdown. This is the only product code change (3 lines).
- **Test-only additions:** `runners/fake/main.py` is a deterministic protocol runner with the scripts `ordinary`, `pause-at-boundary`, `tool-error` and `exit-mid-turn`. `tests/runner_support.py`, `tests/test_runner_conformance.py` and `tests/test_runner_serve_db.py` use it; `tests/test_runner_supervisor.py` now covers the startup-child reaping case. None of this runs in a Looper installation. The development plan `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md` gets one status row.
- **Model-visible changes:** none. No prompts, tool schemas or tool descriptions changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.181 is published. There is no schema change, so rolling back to v2.13.180 needs nothing else.

### 行为变化与入口

- **提前接管初始化子进程（#782）：**`looper/agents/runtimes/runner/supervisor.py` 中 `RunnerSupervisor` 在 `self.connect(...)` 返回后、设置 `bridge.on_failure` 并发布 generation 之前调用 `await generation.tree.refresh(force=True)`。runner 在 `initialize` 期间于启动快照之后拉起的子进程，在 runner 被立即杀掉时已在跟踪的进程树中，并在恢复和关闭时被清理。这是唯一的产品代码改动（3 行）。
- **仅测试的新增：**`runners/fake/main.py` 是确定性协议 runner，脚本为 `ordinary`、`pause-at-boundary`、`tool-error`、`exit-mid-turn`。`tests/runner_support.py`、`tests/test_runner_conformance.py`、`tests/test_runner_serve_db.py` 使用它；`tests/test_runner_supervisor.py` 新增覆盖启动子进程回收的用例。这些都不会在 Looper 安装中运行。开发计划文档 `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md` 增加一行状态。
- **面向模型的变化：**无。提示词、工具 schema 和工具描述均无变化。
