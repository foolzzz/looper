# Looper v2.14.18

This is the patch release v2.14.18. It ships the one change merged since v2.14.17: [#910](https://github.com/foolzzz/looper/pull/910), which keeps a newer hash navigation when the Chat page pins its thread to the address.

## Release Decision

**Who should upgrade:** Anyone who uses the dashboard Chat page with more than one Manager and navigates with Back/Forward, links, a typed address or clicks. It ships the one change merged since v2.14.17.

**What this release solves:** [#910](https://github.com/foolzzz/looper/pull/910): the Chat page pins the shown thread to the address with a replace (`the Chat address (target and conversation)`). The replace ran from a stale render and was unconditional, so a navigation made just before it was reverted to the previous Manager's thread. Now the replace applies only while the address is still the one the pin effect saw; a newer navigation is kept.

**Breaking changes:** No. The change is in the dashboard only. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#910](https://github.com/foolzzz/looper/pull/910); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.18
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.17 upgrades directly. This release changes no database schema, stored data or setting.

## Behavior changes

- **Chat pin keeps a newer navigation** (`web/src/App.tsx`, `web/src/pages/chat.tsx`): `navigateSub` takes an optional `from` argument, the query the caller rendered. When a replace carries `from` and the live hash no longer has the same page, sub-path and query, the replace is skipped and the route state is set from the live hash. The Chat pin effect now passes the `query` it saw as `from`. A replace without `from` behaves as before, and so does a push.
- **Model-visible changes:** None. No prompt, tool description, tool schema or runner protocol message changes; the change is limited to the dashboard front end.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## Validation

**Retained implementation evidence:** the description of [#910](https://github.com/foolzzz/looper/pull/910) names the tests that cover the change (a vitest regression in `web/src/url-state.test.tsx`, 31 added lines in the diff), automated reviews and CI before the merge. It reports 43 production lines added and gives no pass counts or local full-suite result; its own "tests 0" count does not match the test file in the diff.

**CI:** CI runs after the release is drafted; its result is not recorded here.

**Not tested for this draft:** a local full suite, a live service, a browser check of Back/Forward on the Chat page, and the built wheel. The release documentation gate checks the body only.

### 升级决策

**谁需要升级：**在仪表盘 Chat 页面使用多个 Manager，并通过前进/后退、链接、手输地址或点击进行导航的人。包含 v2.14.17 之后合并的唯一改动。

**是否有破坏性变更：**否。改动仅在仪表盘。受支持的升级路径不变（见升级）。

**如何验证：**运行 `looper --version` 核对版本为 2.14.18。


桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.17 上的安装可直接升级。本版本不改数据库 schema、已存数据或设置。

### 行为变化与入口

- **Chat 固定操作保留更新的导航**（`web/src/App.tsx`、`web/src/pages/chat.tsx`）：`navigateSub` 新增可选参数 `from`，即调用方渲染时的 query。带 `from` 的 replace 若发现当前 hash 的页面、子路径或 query 已不同，则跳过 replace，并按当前 hash 设置路由状态。Chat 的固定 effect 现在把它所见的 `query` 作为 `from` 传入。不带 `from` 的 replace 以及 push 行为不变。
- **面向模型的变化：**无。没有 prompt、工具描述、工具 schema 或 runner 协议消息的变化；改动仅限仪表盘前端。
