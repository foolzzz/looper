# Looper v2.13.6

## Release Decision

**Who should upgrade:** Operators who give an Agent Profile a separately priced background model and saw a false "unpriced" cost warning, and anyone who reads provider concurrency limits through the Manager's `looper_providers` tool.

**What this release solves:** [#273](https://github.com/foolzzz/looper/pull/273) stops the dashboard and Manager from reporting a background model as unpriced when it has a full price of its own, and adds `max_concurrency` to the Manager's provider answers.

**Breaking changes:** No. The API, configuration, registry schema, CLI, channels and dashboard are unchanged from [v2.13.5](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.5.md), apart from the additions listed below.

**How to verify:** Check the version. For a profile whose background model has its own full price, confirm the profile shows no unpriced model and no cost warning; ask the Manager to list providers and confirm each carries `max_concurrency`.

**Contributors:** Maintainer @foolzzz authored [#273](https://github.com/foolzzz/looper/pull/273); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.6
```

## Behavior changes

- **Profile cost warnings:** `profile_view`, the warnings after a profile write and the `cost.unpriced` list (`looper/agents/profile_registry.py`) now price a profile from every model of the selected model's account and protocol, as a launch does, instead of only the selected model's own catalog entry. A background model with a full price of its own is no longer named as unpriced, which was a false warning. A background model without a price still warns. The registry view, the profile answer and a task's profile overrides (`profile_views`, used by `looper/agents/http_server.py`) load the model catalog once.
- **Manager provider answers:** `_provider_listed` (`looper/agents/ops/config.py`) adds a `max_concurrency` field (null when the provider has no limit set) to the `looper_providers` list, register and update answers.
- **API:** The profile and task profile-override payloads keep their shape; only the cost fields above are computed from the wider catalog.
- **Model-visible changes:** One. The Manager model now sees a `max_concurrency` field in `looper_providers` answers. The tool's schema, description and prompts are unchanged. The cost warnings are shown to users, and to the Manager only where it reads a profile answer.

## Entry points

- **Dashboard and Manager profile views:** Cost warnings and `cost.unpriced`, as above.
- **Manager `looper_providers` tool:** The new `max_concurrency` field in answers.
- **Task detail:** Profile overrides are priced like a launch.
- **CLI, launches, prompts, other tools:** No change.

## Upgrade and rollback

No action is needed beyond the usual re-run of `install.sh` once v2.13.6 is published; there is no configuration, data or migration change. Rolling back to v2.13.5 is safe: the false unpriced warning returns and provider answers omit `max_concurrency` again.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## Validation

**Retained implementation evidence:** [#273](https://github.com/foolzzz/looper/pull/273) reports 131 passing tests in the Manager model-tool and config-tool files against a disposable PostgreSQL database, with the new `max_concurrency` and background-price tests failing without the source change, and 444 passing across the pricing, provider binding, models, Manager tool and task agent tests. The PR description does not report a full local suite or a review. This draft did not re-run them.

**CI:** CI runs after the release is drafted; its result is not recorded here.

**Not tested for this draft:** Local test runs, runtime launches, database migration and restore, and model evals. The release documentation gate checks the body only.

## 中文摘要

### 升级决策

**谁需要升级：**给 Agent Profile 配置了单独定价的后台模型、并遇到“未定价”误报的运维者，以及通过 Manager 的 `looper_providers` 工具读取 provider 并发上限的人。

**解决了什么：**[#273](https://github.com/foolzzz/looper/pull/273) 让仪表盘和 Manager 不再把自带完整价格的后台模型报为未定价，并在 Manager 的 provider 回答中加入 `max_concurrency`。

**是否有破坏性变更：**无。除下列新增外，API、配置、registry schema、CLI、渠道和仪表盘与 [v2.13.5](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.5.md) 相同。

**如何验证：**核对版本。对后台模型自带完整价格的 profile，确认不再显示未定价模型和成本警告；让 Manager 列出 provider，确认每项都带 `max_concurrency`。

**贡献者：**维护者 @foolzzz 提交 [#273](https://github.com/foolzzz/looper/pull/273)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.6
```

### 行为变化与入口

- profile 成本警告：`profile_view`、写入 profile 后的警告和 `cost.unpriced` 列表（`looper/agents/profile_registry.py`）现在与启动时一样，按所选模型所属账号和协议下的全部模型定价，而不再只看所选模型自己的目录项。自带完整价格的后台模型不再被列为未定价（此前是误报）；没有价格的后台模型仍会警告。registry 视图、profile 回答和任务的 profile 覆盖（`looper/agents/http_server.py` 使用的 `profile_views`）只加载一次模型目录。
- Manager 的 provider 回答：`_provider_listed`（`looper/agents/ops/config.py`）在 `looper_providers` 的 list、register、update 回答中新增 `max_concurrency` 字段（未设上限时为 null）。
- API：profile 与任务 profile 覆盖的载荷结构不变，仅成本字段按更完整的目录计算。
- 面向模型的变化有一项：Manager 模型会在 `looper_providers` 回答中看到 `max_concurrency`。工具 schema、描述和提示词无变化。成本警告展示给用户，Manager 仅在读取 profile 回答时可见。
- 入口：仪表盘与 Manager 的 profile 视图（成本警告）、Manager 的 `looper_providers` 工具（新字段）、任务详情（profile 覆盖按启动口径定价）。CLI、启动、提示词和其他工具无变化。

### 升级与回退

发布后照常重跑 `install.sh` 即可，无配置、数据或迁移变更；回退到 v2.13.5 同样安全：误报的未定价警告会回来，provider 回答不再带 `max_concurrency`。

本版本未新增可选能力启用入口。
