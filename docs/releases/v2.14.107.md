# Looper v2.14.107

This is the patch release v2.14.107, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.106: a local gateway endpoint that lets other Anthropic-protocol clients on the same machine use OpenAI Chat models through Looper's translation ([#1160](https://github.com/foolzzz/looper/pull/1160)).

## Release Decision

**Who should upgrade:** Operators who want a hand-run Anthropic client, for example the Claude Code CLI, to use an `openai-chat` model through Looper. The endpoint is off by default, so others are not affected, apart from the changes described below.

**What this release solves:** [#1160](https://github.com/foolzzz/looper/pull/1160). With the endpoint enabled, the local proxy serves `/gw` on 127.0.0.1 only, authenticated by a local key and limited to operator-defined model aliases. `loopercli gateway-env` prints the client environment.

**Breaking changes:** No. No new dependency. One new database table (`gateway_aliases`, additive), one new command (`loopercli gateway-env`) and one new `gateway` section in the configuration file format; all are optional.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.107
```

**Contributors:** Maintainer @foolzzz authored [#1160](https://github.com/foolzzz/looper/pull/1160); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.106 upgrades directly. `ensure_schema` creates the `gateway_aliases` table once (`CREATE TABLE IF NOT EXISTS`, recorded in `schema_migrations`); nothing existing is altered. A local proxy kept alive by running agents from an older version keeps the old behavior until those agents finish; with the gateway enabled, Looper defers replacing it until every route has ended and does not report the endpoint as ready before that.

## Behavior changes

- **Loopback endpoint** (`looper/agents/llmrec/proxy.py`, `looper/agents/llmrec/gateway.py`). Requests under `/gw/` are handled only when the endpoint is enabled (otherwise 404). They are refused when they carry an `Origin` header or a `Host` other than `127.0.0.1:<port>` or `localhost:<port>` (403), and when they lack the local key in `x-api-key` or `Authorization: Bearer` (401, counted as `auth_failures`). Upgrade requests are refused. `HEAD /gw/api/hello` (Claude Code's connectivity probe) is answered without credentials, counters or an upstream call. `GET /gw/v1/models` lists enabled aliases; `POST /gw/v1/messages` resolves the alias and goes through the existing Anthropic-to-Chat translation with the provider key attached inside the proxy; every other path is 404. Unknown alias is 404; a disabled provider or missing key is 403; unreachable configuration is 503. Requests are recorded when recording is on, under the agent id `gateway:<alias>`. Prompt-prefix history for these requests is kept per route and session.
- **Local key** (`looper/agents/llmrec/gateway.py`). Generated on first enable as `lgw_…` and stored in `.local/llmrec/gateway.key` under the runtime root, written atomically with an owner-only directory and file. It can be revealed or rotated; rotation invalidates the old key.
- **Aliases** (`looper/db/gateway.py`, `looper/db/schema.sql`, `looper/db/connection.py`). New table `gateway_aliases` (alias, model reference with cascade delete). An alias is 1–64 characters of letters, digits, `.`, `_`, `:` or `-`, starting with a letter or digit. The target must be an `openai-chat` model on an enabled API-key provider with a saved key, checked in the write itself.
- **Control and port** (`looper/agents/llmrec/control.py`). New settings `gateway.enabled` and `gateway.port`. The endpoint never silently moves to another port: a port change is refused while agent routes are active. The proxy now starts when the gateway is enabled even if recording is off, and a proxy whose code hash differs is treated as outdated. Route files of the previous format are still read for lifecycle ownership (not for new requests), and are written so the v2.14.99 proxy can still read them.
- **API and Settings** (`looper/agents/v1_domains/gateway.py`, `looper/agents/api_v1.py`, `web/src/components/gateway-settings.tsx`). Operator-only operations `gateway.get`, `update`, `alias_set`, `alias_delete`, `key_reveal` and `key_rotate` under `/api/v1/gateway/`, and a **Local gateway** section in Settings. The LLM request status result gains `auth_failures` and `alias_usage`.
- **`loopercli gateway-env --alias NAME`** (`looper/loopercli.py`, `looper/gateway_env.py`). Prints shell-quoted `export` lines for `eval`: base URL, the local key as the auth token, an empty Anthropic API key variable, the alias for every model tier and subagent variable, and `CLAUDE_CODE_ATTRIBUTION_HEADER=0`, `ENABLE_TOOL_SEARCH=false`, `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`. It refuses when the gateway is off or the alias is missing. It reveals the key, so it needs operator identity.
- **Configuration export and import** (`looper/agents/config_transfer.py`, `looper/agents/config_imports.py`). The `looper-config/v4` document gains an optional `gateway.aliases` section (alias plus provider, model name and protocol) and a `gateway.aliases` import section. Import skips an alias whose target is not a valid enabled `openai-chat` API-key model with a saved key, and refuses a file with aliases unless uploaded with an operator token. Files without the section are unchanged.
- **Self-check** (`looper/agents/self_check.py`). The `gateway` check also runs when the endpoint is enabled: it fails if the proxy is not running on the configured port and warns on `auth_failures`.
- **Claude Code runtime** (`looper/agents/runtimes/claude_code.py`). A translated binding now also sets `ANTHROPIC_MODEL`, and the launch takes the model variables from the bound environment.
- **Documentation and tests.** `docs/architecture/agent-system.md` describes the endpoint; new tests `tests/test_gateway_endpoint.py`, `test_gateway_api_db.py`, `test_gateway_local_serve_db.py`, `test_gateway_settings_browser.py`, a web test for the settings component, and extensions to the Claude Code gateway, self-check, lifecycle, `loopercli` and restart-resume tests.
- **Unchanged:** dependencies, channels, billing, and the Worker, Planner and Reviewer prompts. With the endpoint off, nothing is exposed.
- **Model-visible changes:** Yes, one small one. For Claude Code runs on a translated model, the launch environment gains `ANTHROPIC_MODEL` set to the model. No prompt text, tool schema or Manager-facing text changed. Hand-run clients see only the aliases the operator configures.

## Optional Capability Activation & Use

### Local gateway endpoint

**Activation:** Off by default. Enable it in Settings → Local gateway (or `POST /api/v1/gateway/update` with `enabled`, optionally `port`), then add an alias for an enabled API-key `openai-chat` model (`alias_set`). Then run `eval "$(loopercli gateway-env --alias NAME)"` and start the client.

```bash
eval "$(loopercli gateway-env --alias NAME)"
claude
```

**Validation:** With the endpoint on, Settings shows the URL (`http://127.0.0.1:<port>/gw`); the Local gateway self-check passes; `GET /gw/v1/models` with the local key lists the alias; a client request is answered and counted under `alias_usage`. A request without the key returns 401 and raises `auth_failures`.

**Disable / rollback:** Turn the endpoint off in Settings (`update` with `enabled: false`); `/gw` then returns 404. Delete aliases with `alias_delete`. Rotate the key to cut off existing clients. The `gateway_aliases` table is left in place and is harmless.

**Authority boundary:** Loopback only; browser requests (`Origin`) and foreign hosts are refused. A client holding the local key can spend the aliased provider's quota but never sees the provider key. Configuration, key reveal and rotation need operator identity. The endpoint serves only `v1/messages`, `v1/models` and the hello probe.

### 升级决策

**谁需要升级：**希望手动运行的 Anthropic 客户端（例如 Claude Code CLI）通过 Looper 使用 `openai-chat` 模型的运维人员。端点默认关闭，其他安装除下述变化外不受影响。

**是否有破坏性变更：**否。无新依赖。新增一张数据库表（`gateway_aliases`，仅追加）、一个新命令（`loopercli gateway-env`）和配置文件格式中的一个新 `gateway` 段；均为可选。

**如何验证：**核对版本为 2.14.107。

**贡献者：**维护者 @foolzzz 提交 [#1160](https://github.com/foolzzz/looper/pull/1160)；本版本无社区贡献。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.106 上的安装可直接升级。`ensure_schema` 一次性创建 `gateway_aliases` 表（`CREATE TABLE IF NOT EXISTS`，记录在 `schema_migrations`），不改动已有内容。由运行中的 agent 保持存活的旧版本本地代理保持旧行为直到这些 agent 结束；启用网关时，Looper 推迟替换它直到所有路由结束，并且在此之前不报告端点已就绪。

### 行为变化与入口

- **回环端点**（`looper/agents/llmrec/proxy.py`、`looper/agents/llmrec/gateway.py`）。`/gw/` 下的请求仅在端点启用时处理（否则 404）。带 `Origin` 头，或 `Host` 不是 `127.0.0.1:<port>` / `localhost:<port>` 的请求被拒绝（403）；缺少本地密钥（`x-api-key` 或 `Authorization: Bearer`）的请求返回 401，并计入 `auth_failures`。升级请求被拒绝。`HEAD /gw/api/hello`（Claude Code 的连通性探测）无需凭据即可应答，不计数、不调用上游。`GET /gw/v1/models` 列出已启用的别名；`POST /gw/v1/messages` 解析别名后走现有的 Anthropic 到 Chat 转换，提供方密钥只在代理内部附加；其他路径一律 404。别名未知 404；提供方被禁用或缺少密钥 403；配置不可用 503。开启记录时请求被记录，agent id 为 `gateway:<alias>`。这类请求的提示前缀历史按路由和会话保存。
- **本地密钥**（`looper/agents/llmrec/gateway.py`）。首次启用时生成 `lgw_…`，原子写入运行时根目录下的 `.local/llmrec/gateway.key`，目录和文件仅属主可访问。可查看或轮换；轮换使旧密钥失效。
- **别名**（`looper/db/gateway.py`、`looper/db/schema.sql`、`looper/db/connection.py`）。新表 `gateway_aliases`（别名、模型引用，级联删除）。别名为 1–64 个字符，由字母、数字、`.`、`_`、`:`、`-` 组成，以字母或数字开头。目标必须是已启用 API key 提供方上、已保存密钥的 `openai-chat` 模型，并在写入语句中校验。
- **控制与端口**（`looper/agents/llmrec/control.py`）。新增设置 `gateway.enabled` 和 `gateway.port`。端点不会悄悄换端口：有 agent 路由活动时拒绝更改端口。启用网关时，即使未开启记录，代理也会启动；代码哈希不同的代理被视为过期。上一版本格式的路由文件仍会被读取以保持生命周期归属（不用于新请求），且写入方式保证 v2.14.99 的代理仍可读取。
- **API 与设置**（`looper/agents/v1_domains/gateway.py`、`looper/agents/api_v1.py`、`web/src/components/gateway-settings.tsx`）。`/api/v1/gateway/` 下仅限运维的 `gateway.get`、`update`、`alias_set`、`alias_delete`、`key_reveal`、`key_rotate`，以及设置中的 **Local gateway** 区块。LLM 请求状态结果新增 `auth_failures` 和 `alias_usage`。
- **`loopercli gateway-env --alias NAME`**（`looper/loopercli.py`、`looper/gateway_env.py`）。打印可供 `eval` 的带引号 `export` 行：基础 URL、作为 auth token 的本地密钥、空的 Anthropic API key 变量、所有模型档位和子 agent 变量的别名，以及 `CLAUDE_CODE_ATTRIBUTION_HEADER=0`、`ENABLE_TOOL_SEARCH=false`、`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`。网关未启用或别名不存在时拒绝。它会显示密钥，因此需要运维身份。
- **配置导出与导入**（`looper/agents/config_transfer.py`、`looper/agents/config_imports.py`）。`looper-config/v4` 文档新增可选的 `gateway.aliases` 段（别名加提供方、模型名和协议），导入新增 `gateway.aliases` 部分。目标不是已启用、已保存密钥的 `openai-chat` API key 模型时跳过该别名；除非以运维令牌上传，否则拒绝含别名的文件。不含该段的文件不变。
- **自检**（`looper/agents/self_check.py`）。端点启用时 `gateway` 检查同样运行：代理未在配置端口运行则失败，出现 `auth_failures` 则警告。
- **Claude Code 运行时**（`looper/agents/runtimes/claude_code.py`）。转换绑定现在还设置 `ANTHROPIC_MODEL`，启动时模型变量取自绑定的环境。
- **文档与测试。**`docs/architecture/agent-system.md` 说明该端点；新增 `tests/test_gateway_endpoint.py`、`test_gateway_api_db.py`、`test_gateway_local_serve_db.py`、`test_gateway_settings_browser.py`、设置组件的前端测试，并扩展 Claude Code 网关、自检、生命周期、`loopercli` 和重启恢复测试。
- **不变：**依赖、渠道、计费，以及 Worker、Planner、Reviewer 的提示。端点关闭时不暴露任何内容。
- **面向模型的变化：**有一项小改动。转换模型上的 Claude Code 运行，启动环境新增 `ANTHROPIC_MODEL`，值为该模型。提示文字、工具 schema 和面向 Manager 的文字均无变化。手动运行的客户端只能看到运维配置的别名。

### 可选能力启用与使用

#### Local gateway endpoint

**启用：**默认关闭。在 Settings → Local gateway 中启用（或 `POST /api/v1/gateway/update` 传 `enabled`，可选 `port`），再为已启用的 API key `openai-chat` 模型添加别名（`alias_set`）。然后运行 `eval "$(loopercli gateway-env --alias NAME)"` 并启动客户端。

```bash
eval "$(loopercli gateway-env --alias NAME)"
claude
```

**验证：**启用后，设置页显示 URL（`http://127.0.0.1:<port>/gw`）；Local gateway 自检通过；带本地密钥的 `GET /gw/v1/models` 列出别名；客户端请求得到应答并计入 `alias_usage`。无密钥的请求返回 401 并增加 `auth_failures`。

**停用 / 回退：**在设置中关闭端点（`update` 传 `enabled: false`），`/gw` 随即返回 404。用 `alias_delete` 删除别名。轮换密钥可切断现有客户端。`gateway_aliases` 表保留在原处，无害。

**权限边界：**仅限回环；浏览器请求（`Origin`）和外来 Host 被拒绝。持有本地密钥的客户端可消耗对应提供方的额度，但看不到提供方密钥。配置、查看和轮换密钥需要运维身份。端点只提供 `v1/messages`、`v1/models` 和 hello 探测。
