# Looper v2.13.88

## Release Decision

**Who should upgrade:** Anyone who calls `/api/agent-profiles` or its prompt-preview route from a script, or who adds, edits or deletes Agent Profiles or previews a prompt in the dashboard. Everyone else gets no change.

**What this release solves:** [#540](https://github.com/foolzzz/looper/pull/540) moves full Agent Profile management and prompt previews onto the versioned API and removes the four legacy profile routes.

**Breaking changes:** Yes. `POST /api/agent-profiles`, `PUT /api/agent-profiles/{id}`, `DELETE /api/agent-profiles/{id}` and `GET /api/agent-profiles/{id}/prompt-preview` are removed; a script that calls them must use `POST /api/v1/profiles/create`, `/api/v1/profiles/update`, `/api/v1/profiles/delete` or `/api/v1/profiles/prompt_preview`. An update passes `{profile_id, fields}`, a delete `{profile_id}` and a preview `{profile_id, role, project_id?}` in the body, and responses are wrapped in the v1 envelope (`result`). The dashboard shipped in this release already uses the new operations.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#540](https://github.com/foolzzz/looper/pull/540); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.88
```

## Behavior changes

- **New operations ([#540](https://github.com/foolzzz/looper/pull/540)):** the new `looper/agents/v1_domains/profiles.py` registers `profiles.create`, `profiles.update` (risk `write`), `profiles.delete` (risk `high`, so it asks for confirmation with the deletion impact) and `profiles.prompt_preview` (risk `read`) as `POST /api/v1/profiles/...`, all with closed argument schemas. Create takes `name`, `runtime_id` and `model_id` plus optional `effort`, `agent_teams` and `custom_prompt`; update takes at least one of those fields. Create and update return `{profile, warnings}`, delete returns `{deleted}`.
- **Same service checks:** the operations call the existing `profile_registry` create, update and delete and `prompt_preview.preview`; delete repeats its usage checks at execution, also after confirmation. The deletion impact text is now shared with the Manager tools through `profile_deletion_impact` in `looper/agents/ops/config.py`.
- **Typed results:** `agent_profiles.list` now has a closed, typed result (profiles, runtimes, runtime types, models) published by the new domain instead of a loose one in `api_v1.py`; `agent_profiles.create`, `.update` and `.delete` get typed compact results. The compact Manager operations themselves are unchanged.
- **Removed routes:** the four legacy routes and the `_RE_PROFILE` and `_RE_PROFILE_PROMPT_PREVIEW` patterns are removed from `looper/agents/http_server.py`.
- **Dashboard:** `web/src/lib/api.ts` calls the v1 operations for create, update, delete and preview. A pending-confirmation (HTTP 202) answer is raised as an `unavailable` error, and the registry-changed event fires after each create, update and delete.
- **Tooling:** the prompt regression evals (`evals/prompt_regression/dialogs.py`, `runner.py`) and `examples/pi/isolated-smoke.py` create profiles through `/api/v1/profiles/create`.
- **Tests:** `tests/test_api_v1_profiles.py`, `tests/test_api_v1_profiles_db.py` and `web/src/lib/api-profiles.test.ts` were added; many existing tests and `web/src/components/agent-profiles.test.tsx` were moved to the new operations.
- **Model-visible changes:** None found. Manager, Planner, Worker and Reviewer prompts, role recommended prompts and Tool declarations are unchanged; the compact `agent_profiles.*` operations that Manager tools use keep their contract. The new `profiles.*` operations declare no Tool and appear only in the v1 operation catalog that API clients read.
- **Not confirmed in code:** whether prose docs other than this release still name the removed routes, and the operator-only boundary the description names. This draft did not run any test.

## Upgrade and rollback

Re-run `install.sh` once v2.13.88 is published. No data migration; saved profiles are untouched. Update any script that used the removed routes. Rolling back to v2.13.87 restores them together with the old dashboard.

**谁需要升级：**在脚本中调用 `/api/agent-profiles` 或其 prompt-preview 路由的人，或在仪表盘中添加、编辑、删除 Agent Profile 或预览提示词的人。其他人无变化。

**解决了什么：**[#540](https://github.com/foolzzz/looper/pull/540) 把完整的 Agent Profile 管理和提示词预览迁到版本化 API，并删除四条旧的 Profile 路由。

**是否有破坏性变更：**有。`POST /api/agent-profiles`、`PUT /api/agent-profiles/{id}`、`DELETE /api/agent-profiles/{id}` 与 `GET /api/agent-profiles/{id}/prompt-preview` 已移除；调用它们的脚本须改用 `POST /api/v1/profiles/create`、`/api/v1/profiles/update`、`/api/v1/profiles/delete` 或 `/api/v1/profiles/prompt_preview`。更新在请求体中传 `{profile_id, fields}`，删除传 `{profile_id}`，预览传 `{profile_id, role, project_id?}`，响应包在 v1 信封（`result`）里。本版本附带的仪表盘已改用新操作。

**如何验证：**运行 `looper --version` 核对版本为 2.13.88。

**贡献者：**维护者 @foolzzz 提交 [#540](https://github.com/foolzzz/looper/pull/540)；本次 patch release 无社区贡献。

### 行为变化与入口

- **新操作（[#540](https://github.com/foolzzz/looper/pull/540)）：**新增 `looper/agents/v1_domains/profiles.py`，注册 `profiles.create`、`profiles.update`（风险 `write`）、`profiles.delete`（风险 `high`，需确认并显示删除影响）和 `profiles.prompt_preview`（风险 `read`），路径为 `POST /api/v1/profiles/...`，参数均为封闭对象。创建需 `name`、`runtime_id`、`model_id`，可选 `effort`、`agent_teams`、`custom_prompt`；更新至少带其中一个字段。创建与更新返回 `{profile, warnings}`，删除返回 `{deleted}`。
- **服务检查不变：**这些操作调用已有的 `profile_registry` 创建、更新、删除和 `prompt_preview.preview`；删除在执行时重复所有使用检查，确认之后也一样。删除影响文案通过 `looper/agents/ops/config.py` 中的 `profile_deletion_impact` 与 Manager 工具共用。
- **类型化结果：**`agent_profiles.list` 现在有封闭的类型化结果（profiles、runtimes、runtime types、models），由新域发布，不再是 `api_v1.py` 中的宽松结果；`agent_profiles.create`、`.update`、`.delete` 新增类型化的精简结果。Manager 使用的精简操作本身未变。
- **移除的路由：**四条旧路由以及 `_RE_PROFILE`、`_RE_PROFILE_PROMPT_PREVIEW` 正则已从 `looper/agents/http_server.py` 移除。
- **仪表盘：**`web/src/lib/api.ts` 用 v1 操作完成创建、更新、删除和预览。待确认（HTTP 202）的应答会作为 `unavailable` 错误抛出；创建、更新、删除成功后触发注册表变更事件。
- **工具：**提示回归评测（`evals/prompt_regression/dialogs.py`、`runner.py`）和 `examples/pi/isolated-smoke.py` 通过 `/api/v1/profiles/create` 创建 Profile。
- **测试：**新增 `tests/test_api_v1_profiles.py`、`tests/test_api_v1_profiles_db.py` 与 `web/src/lib/api-profiles.test.ts`；许多现有测试和 `web/src/components/agent-profiles.test.tsx` 已改用新操作。
- **面向模型的变化：**未发现。Manager、Planner、Worker、Reviewer 的 prompt、角色推荐 prompt 以及 Tool 声明均未改动；Manager 工具使用的精简 `agent_profiles.*` 操作契约不变。新的 `profiles.*` 操作未声明 Tool，只出现在 API 客户端读取的 v1 操作目录中。
- **代码中未确认：**本版本说明之外的散文文档是否仍写着已移除的路由，以及描述中提到的仅限操作员边界。本草稿未运行任何测试。
