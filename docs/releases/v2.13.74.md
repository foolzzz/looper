# Looper v2.13.74

## Release Decision

**Who should upgrade:** Operators who edit project role templates or read role statistics from the dashboard, and anyone who calls the `/api/projects/{id}/role-templates` or `/role-stats` routes from a script.

**What this release solves:** [#503](https://github.com/foolzzz/looper/pull/503) moves project role-template editing and role statistics onto the v1 API with typed requests and answers, and removes the four legacy routes.

**Breaking changes:** Yes. `GET /api/projects/{id}/role-templates`, `PUT` and `DELETE /api/projects/{id}/role-templates/{key}`, and `GET /api/projects/{id}/role-stats` are removed. Callers must use `POST /api/v1/role_templates/list`, `/put`, `/delete` and `POST /api/v1/project_roles/stats`; the v1 put takes every template field, and the v1 answers wrap their data in `result`. The bundled prompt-regression runner and the dashboard are already updated.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#503](https://github.com/foolzzz/looper/pull/503); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.74
```

## Behavior changes

- **Routes:** `looper/agents/v1_domains/project_roles.py` adds four operations. `project_roles.stats` takes `project_id` and an optional `since` day (YYYY-MM-DD); `role_templates.list` takes `project_id`; `role_templates.put` takes `project_id`, `key`, `kind` (`work` or `review`), `description`, `role_prompt`, `harness`, `profile_id` and `items`; `role_templates.delete` takes `project_id` and `key`. All requests are closed objects, and put requires every field (null for `harness` and `profile_id`, an empty list for `items`). Put, list and delete answer with the project's templates; stats answers with per-role and built-in worker/reviewer numbers.
- **Removed routes:** the four legacy role-template and role-stats routes and their patterns are deleted from `http_server.py`.
- **Confirmation:** `role_templates.delete` is a high-risk operation that asks for confirmation. Its impact text says that future tasks cannot copy the template while task roles already copied from it keep their content and versions; deleting a missing key fails with not-found.
- **Dashboard:** `fetchProjectRoleStats`, `fetchRoleTemplates`, `putRoleTemplate` and `deleteRoleTemplate` in `web/src/lib/api.ts` call the v1 routes; a 202 confirmation answer is raised as an error.
- **Scripts and docs:** `evals/prompt_regression/runner.py` fills missing template fields and posts to `role_templates/put`; the curl examples in `docs/releases/v2.8.0.md` use the v1 routes.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt or Manager Tool changed.
- **Not confirmed in code:** the pull request goal mentions operator-only boundaries, but the four operations are not marked operator-only in the code read for this draft.

## Upgrade and rollback

Re-run `install.sh` once v2.13.74 is published, and move any script that calls the removed routes to the v1 routes. No data migration. Rolling back to v2.13.73 restores the old routes, with no stored data affected.

### 行为变化与入口

- **路由：**`looper/agents/v1_domains/project_roles.py` 新增四个操作。`project_roles.stats` 接受 `project_id` 和可选的 `since`（YYYY-MM-DD）；`role_templates.list` 接受 `project_id`；`role_templates.put` 接受 `project_id`、`key`、`kind`（`work` 或 `review`）、`description`、`role_prompt`、`harness`、`profile_id`、`items`；`role_templates.delete` 接受 `project_id` 和 `key`。请求均为封闭对象，put 要求全部字段（`harness`、`profile_id` 可为 null，`items` 可为空列表）。put、list、delete 返回项目的模板；stats 返回各角色及内置 worker/reviewer 的数据。
- **移除的路由：**`http_server.py` 中四条旧的角色模板与角色统计路由及其匹配规则已删除。
- **确认：**`role_templates.delete` 是高风险操作，需要确认；影响说明指出后续任务将无法复制该模板，已从它复制的任务角色保留内容和版本；删除不存在的 key 返回 not-found。
- **仪表盘：**`web/src/lib/api.ts` 中的 `fetchProjectRoleStats`、`fetchRoleTemplates`、`putRoleTemplate`、`deleteRoleTemplate` 调用 v1 路由；202 确认响应作为错误抛出。
- **脚本与文档：**`evals/prompt_regression/runner.py` 补全缺失的模板字段并调用 `role_templates/put`；`docs/releases/v2.8.0.md` 的 curl 示例改用 v1 路由。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 和 Manager Tool 均未改动。
- **代码中未确认：**PR 目标提到仅限运维的边界，但本草稿所读代码中这四个操作并未标记为 operator-only。
