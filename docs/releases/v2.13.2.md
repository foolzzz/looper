# Looper v2.13.2

## Release Decision

**Who should upgrade:** No operator needs this release for runtime behavior. It matters to maintainers and forks that run the repository's Python test suite on CI, where a shallow checkout and a `/tmp` temporary root made parity tests fail.

**What this release solves:** [#270](https://github.com/foolzzz/looper/pull/270) fixes the follow-ups of [#267](https://github.com/foolzzz/looper/issues/267). The `Agent system tests` job now checks out the full history, which the legacy-checkout parity tests need for their pinned old revisions. The Claude Code launch parity test no longer depends on where the temporary root lives. Both are CI workflow and test-only changes; no product code changed.

**Breaking changes:** No. The wheel contents, configuration, registry schema, CLI, dashboard and channels are unchanged from [v2.13.1](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.1.md).

**How to verify:** Check the version. The change itself is verified by the Python tests workflow, which runs after the release is drafted; local checks cannot reproduce a shallow clone.

**Contributors:** Maintainer @foolzzz authored [#270](https://github.com/foolzzz/looper/pull/270); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.2
```

## Behavior changes

- **Product behavior:** None. The pull request changes `.github/workflows/python-tests.yml` and tests only.
- **Model-visible changes:** None. No prompt, tool, Manager schema, runtime launch argument or model-facing text changed.
- **CI checkout:** The `Agent system tests` job uses `fetch-depth: 0`, so pinned old revisions are available to the legacy-checkout parity tests. `tests/test_ci_environment.py` pins this setting.
- **Launch parity comparison:** `test_resolved_claude_binding_matches_pinned_launches` compares the Claude `--settings` text through a new helper, `above_root_normalized`. It rewrites every `claudeMdExcludes` entry for a directory above the temporary root (such as `/private/tmp`, `/private` or `/` on macOS) to `<above>/<name>`, once each, on both the actual and pinned side. Entries under the root are still compared exactly. A new test covers macOS-style and Linux-style ancestors.

## Entry points

- **CLI, dashboard, Telegram/Lark channels, Manager tools and prompts:** No change.

## Upgrade and rollback

No action is needed beyond the usual re-run of `install.sh` once v2.13.2 is published; there is no configuration, data or migration change. Rolling back to v2.13.1 is safe for the same reason. The v2.13.0 and v2.13.1 backup, migration readback and restore guidance still applies to registry upgrades.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## Validation

**Retained implementation evidence:** [#270](https://github.com/foolzzz/looper/pull/270) reports `tests/test_ci_environment.py` (3 passed, and its full-history test fails with the workflow change reverted), the pinned-launch parity tests on a disposable PostgreSQL (5 passed), and the model launch capture and LLM registry recovery tests on a disposable PostgreSQL with full history (57 passed, 1 skipped). The PR description reports no local full-suite run and no review record.

**CI:** The shallow-clone failures cannot be reproduced locally with full history. The workflow setting and its test cover them, and CI runs after the release is drafted; its result is not recorded here.

**Not tested for this draft:** A full local suite, a shallow-clone run, runtime launches, database migration and restore, and model evals. The release documentation gate checks the body only.

## 中文摘要

### 升级决策

**谁需要升级：**运行时行为方面无需升级。仅对在 CI 上运行本仓库 Python 测试的维护者和 fork 有意义：浅克隆与 `/tmp` 临时目录曾导致一致性测试失败。

**解决了什么：**[#270](https://github.com/foolzzz/looper/pull/270) 修复 [#267](https://github.com/foolzzz/looper/issues/267) 的后续问题。`Agent system tests` 作业改为完整历史检出，供 legacy-checkout 一致性测试获取固定的旧版本；Claude Code 启动一致性测试不再依赖临时目录所在位置。两者均为 CI 工作流与测试改动，未改动产品代码。

**是否有破坏性变更：**无。发布内容、配置、registry schema、CLI、仪表盘和渠道与 [v2.13.1](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.1.md) 相同。

**如何验证：**核对版本。改动本身由 Python tests 工作流验证，该工作流在发布草稿后运行；本地无法复现浅克隆。

**贡献者：**维护者 @foolzzz 提交 [#270](https://github.com/foolzzz/looper/pull/270)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.2
```

### 行为变化与入口

- 产品行为无变化；对模型可见的内容（提示词、工具、Manager schema、运行时启动参数、面向模型的文本）无变化。
- `Agent system tests` 作业使用 `fetch-depth: 0`，由 `tests/test_ci_environment.py` 固定该设置。
- `test_resolved_claude_binding_matches_pinned_launches` 通过新增的 `above_root_normalized` 比较 Claude `--settings`：把临时目录上层目录（如 macOS 的 `/private/tmp`、`/private`、`/`）对应的 `claudeMdExcludes` 条目在实际与固定两侧都改写为 `<above>/<name>`（各一次）；目录之下的条目仍精确比较。新增测试覆盖 macOS 与 Linux 风格的上层目录。
- CLI、仪表盘、Telegram/Lark、Manager 工具和提示词均无变化。

### 升级与回退

发布后照常重跑 `install.sh` 即可，无配置、数据或迁移变更；回退到 v2.13.1 同样安全。v2.13.0、v2.13.1 的备份、迁移读回与恢复指引对 registry 升级继续适用。

### 可选能力启用与使用

本版本未新增可选能力启用入口。
