# Looper v2.11.0

## At a Glance

**Manager and Planner replace the runtime's default system prompt on Codex, Grok and OMP**, as they have on Claude Code since v2.10.0. Worker, Reviewer, Planner-defined role runs and consults still append. Settings → Roles has an append/replace choice for every role, and it applies to every runtime. A task can override its planner, worker or reviewer. The profile-level mode is gone: an Agent Profile no longer stores `append` or `replace`. An older configuration export still imports; that field is ignored and the import records a note. The first start migrates once. A Worker or Reviewer whose effective profile replaced, and whose role layer has no mode yet, keeps `replace` on the role layer. Then the profile column is dropped. Manager and Planner do not copy a profile value. Their built-in value is `replace`, so a Codex, Grok or OMP profile that appended does not keep append.

**The Manager's `looper_task_update` can set that task choice** (`system_prompt_modes`). Null returns the role to the role setting. The same write as the task's Agents tab and `PUT /api/tasks/:id/agents`.

**The dashboard has a Sign out control for a password session.** When the session ends, any `/api/` 401 replaces the page with one screen: "Your session ended. Reload to sign in again." and a Reload button. Every poller and stream stops.

**A failed Planner or Worker turn names the runtime that ran** ("Codex turn did not succeed", "OMP exited ...") instead of always "Claude Code".

**This release has breaking changes.** Manager and Planner launches on Codex, Grok and OMP no longer include that runtime's default system prompt, unless the role or the task is set to append. Saving `system_prompt_mode` on a profile is refused. The first start drops the profile column after the Worker and Reviewer copy. Upgrade by re-running `install.sh`. The first start backs the database up and migrates it. With haiku as the Planner, replace scored lower than append on v2.10.0: run that Planner on opus or sonnet, or set the Planner role to append. The PR-level paired Planner runs on Grok and OMP included timeouts; see Known limits.

### Highlights

- **System prompt mode per role, on every runtime.** Manager and Planner replace by default on Claude Code, Codex, Grok and OMP. Settings → Roles changes a role. The task's Agents tab overrides that task's planner, worker or reviewer. ([#226](https://github.com/foolzzz/looper/pull/226))
- **The profile field is gone.** Create, update, export and the Manager's profile tool have no mode. An older export imports with a note. One migration carries a Worker or Reviewer profile `replace` onto the role layer, then drops the column. ([#226](https://github.com/foolzzz/looper/pull/226))

- **Failure text names the runtime.** "Codex turn did not succeed" and "OMP exited ...", not always "Claude Code". ([#229](https://github.com/foolzzz/looper/pull/229))

## Release Decision

**Who should upgrade:** Everyone running v2.10.0. Before upgrading, read Behavior changes if the Manager or the Planner runs on Codex, Grok or OMP, if a profile on those runtimes is set to replace or to append, or if a task already has its own system prompt mode. If the Planner uses haiku, or Grok or OMP runs the hardest Planner tasks, read Known limits first.

**What this release solves:** v2.10.0 replaced the runtime default for the Manager and the Planner on Claude Code only, and left Codex, Grok and OMP on the Agent Profile's mode. The dashboard did not sign out, and a 401 left the page to be reloaded by hand. A failed turn on another runtime still said "Claude Code". v2.11.0 uses the role's mode on every runtime, removes the profile field, lets the Manager set a task's mode, and shows one session-ended screen.

**Breaking changes:** Yes. Manager and Planner launches on Codex, Grok and OMP replace that runtime's default system prompt. The profile-level mode is removed, and the first start drops that column after copying a Worker or Reviewer profile replace onto the role layer. See Behavior changes, Breaking Changes and Upgrading from v2.10.0.

**How to verify:** After re-running install.sh, looper --version reports looper 2.11.0 and looper doctor passes. The first looper serve logs a pg_dump backup before it migrates. With the server running and no overrides or migrated Worker/Reviewer replace settings, GET /api/agent-settings shows system_prompt_mode replace for manager and planner, and append for worker and reviewer. A profile's JSON has no system_prompt_mode. A password session shows Sign out. After the session ends, the dashboard shows one session-ended screen.

**Contributors:** Release maintainer @foolzzz; no community contribution in the pull requests merged since v2.10.0.

## New capabilities

### System prompt mode per role, on every runtime

- **The mode is the role's, on Claude Code, Codex, Grok and OMP.** `append` adds Looper's prompt to the runtime's default. `replace` sends Looper's prompt in place of that default. Built-in values: Manager and Planner `replace`, Worker and Reviewer `append`. Planner-defined role runs and reviews follow the task's Worker or Reviewer mode. A consult appends. A launch with no role appends. The Manager has no task level. A runtime whose adapter cannot replace still always appends. Today Claude Code, Codex, Grok and OMP can replace. `Launch.system_prompt_mode` is that resolved value on every runtime. ([#226](https://github.com/foolzzz/looper/pull/226))
- **What each runtime sends.** Claude Code: `--append-system-prompt-file`, or `--system-prompt-file` for replace; both modes keep `--system-prompt-snapshot off`. Codex: the generated home's `AGENTS.md` for append; for replace, top-level `model_instructions_file` in `config.toml` points at a content-addressed instructions file and that `AGENTS.md` is empty. Grok: `rules/looper.md` in the generated home for append; for replace, `--agent` points at the home's `agent.md` with `prompt_mode: full` and the rules file's body is empty. OMP: `--append-system-prompt`, or `--system-prompt` for replace, using the same generated prompt file. Codex and Grok include their runtime notes with Looper's prompt in either mode. Replace keeps the runtime's tools and project instruction loading and removes the runtime's default prompt. ([#226](https://github.com/foolzzz/looper/pull/226))
- **Where you set it.** Settings → Roles has a two-way System prompt choice on every role. The line "Only for runs on Claude Code." is gone. `PUT /api/agent-settings/roles/<role>` sets `system_prompt_mode` to `append` or `replace`. Null or an empty value clears the role layer, and the built-in value applies. The shared defaults, a project, and a role inside a project refuse the field (400). `GET /api/agent-settings` shows each role's effective mode. ([#226](https://github.com/foolzzz/looper/pull/226))
- **A task can override its planner, worker or reviewer, on every runtime.** The task's Agents tab shows Append/Replace for whatever runtime that role uses. After a task sets one, the control reads "task setting · reset". `PUT /api/tasks/:id/agents` takes `system_prompt_modes` (`{"planner": "append"}`; null clears that role). Precedence: the task, then the role layer, then the built-in value. The task's `agents` view gives each role's effective value, its source (`task`, `role` or `builtin`) and the runtime type. On v2.10.0 a stored task mode applied to Claude Code only. It now applies to Codex, Grok and OMP as well. ([#226](https://github.com/foolzzz/looper/pull/226))
- **The Manager can set the task mode.** `looper_task_update` accepts `system_prompt_modes` for `planner`, `worker` or `reviewer`: `append`, `replace`, or null. Null returns that role to the role setting. The check and the write are the same as `PUT /api/tasks/:id/agents`, including a call that also sets `profiles`. The Manager has no task-level mode of its own. `looper_task_create` does not take the field. ([#229](https://github.com/foolzzz/looper/pull/229))
- **An Agent Profile does not carry the mode.** The profile editor points at Settings → Roles. Profile create and update reject `system_prompt_mode` as an unknown field (HTTP 400, `unknown field 'system_prompt_mode'`). The Manager's profile tool rejects it as an unknown argument (`invalid`). Configuration export omits it. Configuration import of an older export accepts the field, ignores it, and records `profiles NAME: its system_prompt_mode is ignored; the mode is set per role (Settings → Roles) and applies to every runtime`. The rest of that profile is imported. ([#226](https://github.com/foolzzz/looper/pull/226))
- **Preview.** `GET /api/agent-profiles/<id>/prompt-preview?role=planner|worker|reviewer|manager` returns `system_prompt_mode` (what that launch sends) and `role_system_prompt_mode` (the role's setting) for any runtime. It no longer returns `system_prompt_mode_applies`. Each run's System prompt section shows `replaced default` when the run replaced the default. ([#226](https://github.com/foolzzz/looper/pull/226))
- **One-time migration.** The first start that still sees `agent_profiles.system_prompt_mode` does this, and a later start does not, because the column is gone. For the Worker and the Reviewer, if the effective profile (the role layer's, else the shared defaults', else the built-in `agent-claude-code-opus`, shown as `claude-code/opus`) has `replace`, and that role layer has no mode yet, the role layer is set to `replace`. A mode already stored on the layer is left as it is, including a `replace` or `append` that v2.10.0 wrote when it migrated Claude Code profiles. Then the column and its check are dropped. Manager and Planner do not get a copied row. Their built-in value is already `replace`. ([#226](https://github.com/foolzzz/looper/pull/226))

### Dashboard session and failure text

- **Sign out.** `GET /api/status` includes `can_sign_out`. It is true for a browser signed in with the password and without a token cookie. The sidebar footer then shows Sign out, a form that `POST`s `/logout` and follows the redirect to `/login`. The local browser's automatic sign-in, and a request authenticated only by a Bearer token, report `can_sign_out` false and show no control. ([#229](https://github.com/foolzzz/looper/pull/229))
- **One screen on 401.** Any `/api/` response with status 401 is the session ended. The dashboard then renders only "Your session ended. Reload to sign in again." with a Reload button. Unmounting the pages stops every poller and stream. The call is not retried. A later `/api/` call fails the same way until reload. A 401 that is not an `/api/` call does not raise the screen. Reload shows the sign-in page. ([#229](https://github.com/foolzzz/looper/pull/229))
- **Referrer-Policy.** Dashboard pages send `Referrer-Policy: same-origin` and `Cache-Control: no-store`. On v2.10.0 the referrer policy was `no-referrer`. Under that policy a browser sent `Origin: null` with the Sign out form, and `/logout` answered 403. `same-origin` still does not send the page's address to another site. You do not set the header. ([#229](https://github.com/foolzzz/looper/pull/229))
- **The runtime's name in a failure.** A Planner turn that does not succeed says `{runtime} turn did not succeed`, for example "Codex turn did not succeed". A Planner process that exits first says `{runtime} exited before finishing the turn`. A Worker run that does not succeed says `{runtime} run did not succeed`, for example "Grok run did not succeed". A Worker process that exits with no usable result says `{runtime} exited with code N`, for example "OMP exited with code 1". On v2.10.0 those sentences said "Claude Code". ([#229](https://github.com/foolzzz/looper/pull/229))

## Default and behavior changes

These move on upgrade. Each one says what the operator does. None of them is a new project switch except where the line says so.

1. **Manager and Planner on Codex, Grok and OMP replace that runtime's default system prompt.** On v2.10.0 they appended, unless that Agent Profile was saved as `replace`. To keep appending, open Settings → Roles and set the role to Append. A task can override its planner, worker or reviewer without changing the role: the task's Agents tab, `PUT /api/tasks/:id/agents` with `system_prompt_modes`, or the Manager's `looper_task_update`. Null on a role clears the task's choice and the role setting applies again. The Manager has no task-level mode. Worker, Reviewer and Planner-defined role runs append unless that role layer, or the task, is set to replace. A consult appends even when the seat's role replaces. A launch with no role appends. Claude Code's Manager and Planner already replaced on v2.10.0. With haiku as the Planner, replace scored lower than append on v2.10.0 (31/40 against 50/60 on the Planner tier). Run the Planner on opus or sonnet, or set the Planner role to append when the Planner uses haiku. The PR-level paired Planner runs on Grok and OMP included timeouts; see Known limits. ([#226](https://github.com/foolzzz/looper/pull/226))
2. **The profile-level mode is removed. Old exports import with a note.** `POST /api/agent-profiles` and `PUT /api/agent-profiles/<id>` refuse `system_prompt_mode` with HTTP 400; the text starts `unknown field 'system_prompt_mode'`. The Manager's profile tool rejects it as an unknown argument (`invalid`). Configuration export no longer contains the field. Import of an older file keeps the profile, ignores the field, and records `profiles NAME: its system_prompt_mode is ignored; the mode is set per role (Settings → Roles) and applies to every runtime`. Set the mode in Settings → Roles, or on the task. The profile editor no longer offers the choice. It points at Settings → Roles. ([#226](https://github.com/foolzzz/looper/pull/226))
3. **The first start migrates once, and carries a Worker or Reviewer profile replace onto the role layer.** This runs only while `agent_profiles.system_prompt_mode` still exists. You do not run a separate command. For the Worker and the Reviewer, the effective profile is the role layer's profile, else the shared defaults' profile, else the built-in `claude-code/opus` (`agent-claude-code-opus`). If that profile's mode is `replace`, and the role layer has no mode yet, the role layer is set to `replace`. If the layer already has `append` or `replace`, including a value v2.10.0 copied from a Claude Code profile, that value stays. The column is then dropped, so a second start does not copy again. Manager and Planner are not part of the copy. They replace because the built-in value is `replace`. A Codex, Grok or OMP Manager or Planner profile that was `append` does not keep append: set the role to Append after the first start if that launch should still append. After `looper serve` has migrated, open Settings → Roles and read Worker and Reviewer. Set a role back to Append when the migration wrote Replace and you wanted append. ([#226](https://github.com/foolzzz/looper/pull/226))
4. **A task mode from v2.10.0 now applies on Codex, Grok and OMP.** `task_system_prompt_modes` was already stored, and on v2.10.0 it changed Claude Code launches only. The next launch of that task's planner, worker or reviewer uses it on every runtime. Open the task's Agents tab. Where it reads "task setting", reset the role if the override should not apply to the runtime that role now uses. A null role value in `system_prompt_modes` (for example, `{"planner": null}`) does the same through the API or `looper_task_update`. ([#226](https://github.com/foolzzz/looper/pull/226))
5. **The prompt preview no longer reports `system_prompt_mode_applies`.** It reports `system_prompt_mode` and `role_system_prompt_mode` for every runtime. A client that read `system_prompt_mode_applies` should read `system_prompt_mode` instead. There is no setting to turn the old field back on. ([#226](https://github.com/foolzzz/looper/pull/226))
6. **On 401 the dashboard shows one session-ended screen.** The sentence is "Your session ended. Reload to sign in again." The button is Reload. Every poller and stream stops, because the pages unmount, and the failed call is not retried. On v2.10.0 the page did not handle 401; you reloaded it yourself. Reload to sign in again. You do not enable the screen. A 401 that is not from `/api/` does not raise it. ([#229](https://github.com/foolzzz/looper/pull/229))
7. **A password session can sign out.** The sidebar shows Sign out when `GET /api/status` says `can_sign_out` is true: a password session without a token cookie. The control `POST`s `/logout` and the browser lands on `/login`. The local browser's automatic sign-in shows no Sign out, and neither does a caller that sends the operator token. Set a password with `looper auth set-password` when another machine must sign in, as on v2.10.0. You do not add a setting for the button. ([#229](https://github.com/foolzzz/looper/pull/229))
8. **Dashboard pages send `Referrer-Policy: same-origin`.** On v2.10.0 they sent `no-referrer`. Under `no-referrer` the Sign out form posted `Origin: null` and `/logout` answered 403. You do not configure the header. `same-origin` still withholds the page's address from other sites. `Cache-Control: no-store` is unchanged. ([#229](https://github.com/foolzzz/looper/pull/229))
9. **Planner and Worker failure text names the runtime that ran.** A Planner failure reads "Codex turn did not succeed" or "OMP exited before finishing the turn", and a Worker failure reads "Grok run did not succeed" or "OMP exited with code N". On v2.10.0 the same failures said "Claude Code". Nothing to configure. A log check or a script that matched "Claude Code" in those sentences matches the runtime label instead. ([#229](https://github.com/foolzzz/looper/pull/229))

The role's mode applies to every runtime that can replace. A `vX.Y.Z` tag still publishes this Python release.

## Fixes

- **The dashboard handles a dead session.** On v2.10.0 there was no Sign out control, and after a session ended the page did not handle 401. A password session now has Sign out. Any `/api/` 401 shows one screen, "Your session ended. Reload to sign in again.", with Reload, and every poller and stream stops. The call is not retried. ([#229](https://github.com/foolzzz/looper/pull/229))
- **A failed turn names the runtime that ran it.** Planner and Worker failures on Codex, Grok and OMP said "Claude Code". They now say "Codex turn did not succeed", "OMP exited ...", or "Grok run did not succeed". ([#229](https://github.com/foolzzz/looper/pull/229))
- **Sign out reaches `/login`.** The form POST needs an Origin. Dashboard pages send `Referrer-Policy: same-origin`, so `/logout` accepts the POST. Under the previous `no-referrer` policy the same POST was 403. ([#229](https://github.com/foolzzz/looper/pull/229))

## Breaking Changes

1. **Codex, Grok and OMP Manager and Planner launches replace the runtime's default system prompt.** A launch that appended on v2.10.0, because the profile was `append` or had never been set, now sends Looper's prompt in place of that runtime's default guidance. Scripts do not call a new API for this. The next Manager or Planner turn on those runtimes uses it. To keep append, set the role in Settings → Roles, or set the task's planner on the Agents tab or with `looper_task_update`. The Manager has no task-level override. Claude Code's Manager and Planner already replaced on v2.10.0. ([#226](https://github.com/foolzzz/looper/pull/226))
2. **An Agent Profile no longer has `system_prompt_mode`, and the migration drops the column.** `system_prompt_mode` on `POST /api/agent-profiles` or `PUT /api/agent-profiles/<id>` is HTTP 400 (`unknown field 'system_prompt_mode'`). The Manager's profile tool has no such argument. Export omits the field. Import of an older export ignores it and records the note above. The first start copies a Worker or Reviewer profile `replace` onto the role layer when that layer has no mode yet, then drops `agent_profiles.system_prompt_mode`. A client that saved the mode on the profile must save it on the role. A Manager or Planner profile that appended on Codex, Grok or OMP does not keep append. ([#226](https://github.com/foolzzz/looper/pull/226))
3. **A task's stored mode applies on every runtime.** A `system_prompt_modes` value saved while v2.10.0 applied it to Claude Code only now applies to Codex, Grok and OMP. Clear it if that was not the intent. ([#226](https://github.com/foolzzz/looper/pull/226))

**Also changed, with less authority or a different record.** Consults append even when the seat's role is replace, on every runtime. Planner-defined role runs follow the task's Worker or Reviewer mode. The prompt preview no longer includes `system_prompt_mode_applies`. On 401 the dashboard shows one session-ended screen and stops every poller and stream. Dashboard pages send `Referrer-Policy: same-origin`. `GET /api/status` adds `can_sign_out`. Planner and Worker failure text names the runtime that ran. ([#226](https://github.com/foolzzz/looper/pull/226), [#229](https://github.com/foolzzz/looper/pull/229))

## Upgrading from v2.10.0

1. **Install with `install.sh`.** It installs the latest release wheel. This release adds no Python dependency.
2. **Keep the first-start backup possible.** The schema drops `agent_profiles.system_prompt_mode` after the one-time copy, so the first start writes a `pg_dump` backup before migrating. Keep a `pg_dump` of at least the server's major version on `PATH` (or `LOOPER_PG_DUMP`, or `LOOPER_BACKUP_CMD`). `looper serve --skip-backup` migrates without one.
3. **Start once.** The upgrade copies a Worker or Reviewer profile `replace` onto the role layer when that layer has no mode yet, then drops the profile column. A second start does not copy again. `task_system_prompt_modes` and the role-layer column already exist from v2.10.0. They are not created again.
4. **Decide the mode for Codex, Grok and OMP.** Settings → Roles: without existing role overrides, Manager and Planner are Replace, Worker and Reviewer are Append, unless the migration wrote Replace for a Worker or Reviewer whose effective profile replaced. Set a role to Append to keep v2.10.0's composition for a Manager or Planner that appended because the profile said so. A task's Agents tab overrides its planner, worker or reviewer on every runtime. `looper_task_update` can set the same override.
5. **Read a task that already has a mode.** A mode saved on v2.10.0 now applies on Codex, Grok and OMP. Reset it on the Agents tab when it should not.
6. **Haiku as the Planner.** On v2.10.0, replace scored 31/40 against 50/60 for append on the Planner tier. This release did not rerun that tier. Run the Planner on opus or sonnet, or set the Planner role to append.
7. **Do not set `system_prompt_mode` on a profile.** The API returns 400. Import skips the field and records a note. Set the mode on the role.
8. **Dashboard.** Reload a tab that was open before the upgrade. A password session shows Sign out. After a 401, the page is the session-ended screen; Reload signs in again.
9. **Check.** `looper doctor`, and `looper service status` if you use the service. `GET /api/agent-settings` shows `replace` for manager and planner and `append` for worker and reviewer when there are no overrides or migrated Worker/Reviewer replace settings.

```bash
curl -fsSL https://raw.githubusercontent.com/foolzzz/looper/main/install.sh | bash
looper doctor
looper serve
  # Or, with the service:
looper service restart && looper service status
```

**Rollback to v2.10.0.** Stop Looper (`looper service uninstall` if you installed the service), recreate the database empty and restore the pre-migration backup the first start logged (`pg_restore --no-owner --dbname "$LOOPER_DATABASE_URL" FILE`). Then install the v2.10.0 wheel, for example `uv tool install --force "looper @ https://github.com/foolzzz/looper/releases/download/v2.10.0/looper-2.10.0-py3-none-any.whl"`. `install.sh` always installs the latest release, so it cannot roll back. v2.10.0 still reads `agent_profiles.system_prompt_mode` for Codex, Grok and OMP. A database this version has migrated is not a v2.10.0 database until that backup is restored.

### 新能力

#### 每一种运行时都按角色设置 system prompt 模式

- **在 Claude Code、Codex、Grok 和 OMP 上，模式属于角色。** `append` 把 Looper 的提示词追加到运行时的默认提示词后面。`replace` 用 Looper 的提示词代替该默认提示词。内置值：Manager 和 Planner 为 `replace`，Worker 和 Reviewer 为 `append`。规划者定义的角色的运行和评审跟随该任务的 Worker 或 Reviewer 模式。Consult 追加。没有角色的启动追加。Manager 没有任务级。适配器不能替换的运行时仍一律追加。今天 Claude Code、Codex、Grok 和 OMP 都能替换。`Launch.system_prompt_mode` 在每一种运行时上都是解析后的这个值。（[#226](https://github.com/foolzzz/looper/pull/226)）
- **每种运行时发送什么。** Claude Code：追加用 `--append-system-prompt-file`，替换用 `--system-prompt-file`；两种模式都保留 `--system-prompt-snapshot off`。Codex：追加用生成 home 里的 `AGENTS.md`；替换时，`config.toml` 顶层的 `model_instructions_file` 指向一份按内容寻址的说明文件，那份 `AGENTS.md` 是空的。Grok：追加用生成 home 里的 `rules/looper.md`；替换时，`--agent` 指向 home 里的 `agent.md`，其中 `prompt_mode: full`，规则文件的正文是空的。OMP：追加用 `--append-system-prompt`，替换用 `--system-prompt`，两者使用同一份生成的提示词文件。Codex 和 Grok 在两种模式下都把运行时自己的说明和 Looper 的提示词放在一起。替换保留运行时的工具和项目说明加载，并去掉运行时的默认提示词。（[#226](https://github.com/foolzzz/looper/pull/226)）
- **在哪里设置。** Settings → Roles 的每个角色都有一个双向的 System prompt 选择。“Only for runs on Claude Code.” 这一行没有了。`PUT /api/agent-settings/roles/<role>` 把 `system_prompt_mode` 设成 `append` 或 `replace`。Null 或空值清除角色层，然后使用内置值。共享默认、项目，以及项目里的角色，都拒绝这个字段（400）。`GET /api/agent-settings` 显示每个角色的有效模式。（[#226](https://github.com/foolzzz/looper/pull/226)）
- **任务可以在每一种运行时上覆盖自己的 planner、worker 或 reviewer。** 任务的 Agents 页对该角色使用的任何运行时都显示 Append/Replace。任务设置之后，控件读作 “task setting · reset”。`PUT /api/tasks/:id/agents` 接受 `system_prompt_modes`（`{"planner": "append"}`；null 清除该角色）。优先级：任务，然后角色层，然后内置值。任务的 `agents` 视图给出每个角色的有效值、来源（`task`、`role` 或 `builtin`）和运行时类型。在 v2.10.0 上，已存的任务模式只对 Claude Code 生效。现在对 Codex、Grok 和 OMP 也生效。（[#226](https://github.com/foolzzz/looper/pull/226)）
- **Manager 可以设置任务的模式。** `looper_task_update` 接受 planner、worker 或 reviewer 的 `system_prompt_modes`：`append`、`replace` 或 null。Null 把该角色交回角色层的设置。检查和写入与 `PUT /api/tasks/:id/agents` 相同，包括同一次调用里同时设置 `profiles`。Manager 自己没有任务级模式。`looper_task_create` 不接受这个字段。（[#229](https://github.com/foolzzz/looper/pull/229)）
- **Agent Profile 不承载这个模式。** Profile 编辑器指向 Settings → Roles。Profile 创建和更新把 `system_prompt_mode` 当成未知字段拒绝（HTTP 400，`unknown field 'system_prompt_mode'`）。Manager 的 Profile 工具把它当成未知参数拒绝（`invalid`）。配置导出不再包含它。更旧导出的配置导入接受该字段、忽略它，并记下 `profiles NAME: its system_prompt_mode is ignored; the mode is set per role (Settings → Roles) and applies to every runtime`。该 Profile 的其余部分仍导入。（[#226](https://github.com/foolzzz/looper/pull/226)）
- **预览。** `GET /api/agent-profiles/<id>/prompt-preview?role=planner|worker|reviewer|manager` 对任何运行时返回 `system_prompt_mode`（这次启动发送的模式）和 `role_system_prompt_mode`（角色的设置）。它不再返回 `system_prompt_mode_applies`。一次运行替换了默认提示词时，该运行的 System prompt 一节显示 `replaced default`。（[#226](https://github.com/foolzzz/looper/pull/226)）
- **一次性迁移。** 仍然看得到 `agent_profiles.system_prompt_mode` 的首次启动做下面的事。之后的启动不做，因为这一列已经没有了。对 Worker 和 Reviewer，如果有效 Profile（角色层的，否则共享默认的，否则内置的 `agent-claude-code-opus`，显示为 `claude-code/opus`）是 `replace`，并且该角色层还没有模式，角色层被设为 `replace`。角色层上已经有的模式保持不变，包括 v2.10.0 迁移 Claude Code Profile 时写下的 `replace` 或 `append`。然后这一列和它的检查被删除。Manager 和 Planner 不复制一行。它们的内置值已经是 `replace`。（[#226](https://github.com/foolzzz/looper/pull/226)）

#### Dashboard 会话与失败文本

- **Sign out。** `GET /api/status` 包含 `can_sign_out`。用密码登录、且没有令牌 cookie 的浏览器为 true。侧栏底部于是显示 Sign out，这是一个表单，`POST` `/logout`，并跟随重定向到 `/login`。本机浏览器的自动登录，以及仅通过 Bearer 令牌认证的请求，报告 `can_sign_out` 为 false，不显示这个控件。（[#229](https://github.com/foolzzz/looper/pull/229)）
- **401 时只有一个画面。** 任何状态为 401 的 `/api/` 响应都表示会话结束。Dashboard 于是只渲染 “Your session ended. Reload to sign in again.” 和一个 Reload 按钮。页面卸载后，每一个轮询和流都停止。这次调用不会重试。在重新加载之前，之后的 `/api/` 调用以同样的方式失败。不是 `/api/` 的 401 不会拉起这个画面。重新加载后是登录页。（[#229](https://github.com/foolzzz/looper/pull/229)）
- **Referrer-Policy。** Dashboard 页面发送 `Referrer-Policy: same-origin` 和 `Cache-Control: no-store`。在 v2.10.0 上，referrer 策略是 `no-referrer`。在那个策略下，浏览器为 Sign out 表单发送 `Origin: null`，`/logout` 回答 403。`same-origin` 仍然不会把页面地址发给其他站点。你不用设置这个头。（[#229](https://github.com/foolzzz/looper/pull/229)）
- **失败文本里的运行时名称。** 没有成功的 Planner 回合写 `{runtime} turn did not succeed`，例如 “Codex turn did not succeed”。先退出的 Planner 进程写 `{runtime} exited before finishing the turn`。没有成功的 Worker 运行写 `{runtime} run did not succeed`，例如 “Grok run did not succeed”。没有可用结果就退出的 Worker 进程写 `{runtime} exited with code N`，例如 “OMP exited with code 1”。在 v2.10.0 上，这些句子写的是 “Claude Code”。（[#229](https://github.com/foolzzz/looper/pull/229)）

### 行为变化

下面这些在升级时改变。每一条都写了操作者要做什么。除非该条写了，否则没有新的项目开关。

1. **Codex、Grok 和 OMP 上的 Manager 和 Planner 替换该运行时的默认 system prompt。** 在 v2.10.0 上它们追加，除非该 Agent Profile 被保存成 `replace`。要保持追加，打开 Settings → Roles，把该角色设成 Append。任务可以不改角色就覆盖自己的 planner、worker 或 reviewer：任务的 Agents 页，`PUT /api/tasks/:id/agents` 的 `system_prompt_modes`，或 Manager 的 `looper_task_update`。某个角色上的 null 清除任务的选择，然后重新使用角色层的设置。Manager 没有任务级模式。Worker、Reviewer 和规划者定义的角色运行默认追加，除非该角色层或任务被设成 replace。Consult 即使席位的角色是 replace 也追加。没有角色的启动追加。Claude Code 的 Manager 和 Planner 在 v2.10.0 上已经替换。Planner 使用 haiku 时，v2.10.0 上 replace 的得分低于 append（Planner 层 31/40，append 是 50/60）。把 Planner 放到 opus 或 sonnet 上跑，或在 Planner 使用 haiku 时把 Planner 角色设成 append。Grok 和 OMP 在 PR 级成对 Planner 运行中出现过超时；见“已知限制”。（[#226](https://github.com/foolzzz/looper/pull/226)）
2. **Profile 一级的模式被去掉。旧导出导入时带一条说明。** `POST /api/agent-profiles` 和 `PUT /api/agent-profiles/<id>` 拒绝 `system_prompt_mode`，返回 HTTP 400，文本以 `unknown field 'system_prompt_mode'` 开头。Manager 的 Profile 工具把它当作未知参数拒绝（`invalid`）。配置导出不再包含这个字段。导入更旧的文件时保留 Profile、忽略该字段，并记下 `profiles NAME: its system_prompt_mode is ignored; the mode is set per role (Settings → Roles) and applies to every runtime`。把模式设在 Settings → Roles，或设在任务上。Profile 编辑器不再提供这个选择。它指向 Settings → Roles。（[#226](https://github.com/foolzzz/looper/pull/226)）
3. **首次启动迁移一次，并把 Worker 或 Reviewer 的 Profile replace 带到角色层。** 这只在 `agent_profiles.system_prompt_mode` 还存在时运行。你不用另外跑命令。对 Worker 和 Reviewer，有效 Profile 是角色层的 Profile，否则是共享默认的 Profile，否则是内置的 `claude-code/opus`（`agent-claude-code-opus`）。如果该 Profile 的模式是 `replace`，并且角色层还没有模式，角色层被设为 `replace`。如果该层已经有 `append` 或 `replace`，包括 v2.10.0 从 Claude Code Profile 复制来的值，该值保持不变。然后这一列被删除，因此第二次启动不会再复制。Manager 和 Planner 不在这次复制里。它们替换是因为内置值是 `replace`。原来是 `append` 的 Codex、Grok 或 OMP 的 Manager 或 Planner Profile 不会保持追加：如果这次启动仍应追加，就在首次启动之后把角色设成 Append。`looper serve` 迁移之后，打开 Settings → Roles，看 Worker 和 Reviewer。迁移写下了 Replace 而你要的是 append 时，把角色设回 Append。（[#226](https://github.com/foolzzz/looper/pull/226)）
4. **v2.10.0 存下的任务模式现在对 Codex、Grok 和 OMP 生效。** `task_system_prompt_modes` 当时已经在存，在 v2.10.0 上它只改变 Claude Code 的启动。该任务的 planner、worker 或 reviewer 的下一次启动，在每一种运行时上都使用它。打开任务的 Agents 页。读作 “task setting” 的地方，如果这个覆盖不该作用于该角色现在使用的运行时，就重置该角色。在 API 或 `looper_task_update` 的 `system_prompt_modes` 中把某个角色设为 null（例如 `{"planner": null}`），效果相同。（[#226](https://github.com/foolzzz/looper/pull/226)）
5. **提示词预览不再报告 `system_prompt_mode_applies`。** 它对每一种运行时报告 `system_prompt_mode` 和 `role_system_prompt_mode`。读取 `system_prompt_mode_applies` 的客户端应改为读取 `system_prompt_mode`。没有设置能把旧字段开回来。（[#226](https://github.com/foolzzz/looper/pull/226)）
6. **401 时 dashboard 显示一个会话结束画面。** 句子是 “Your session ended. Reload to sign in again.”。按钮是 Reload。每一个轮询和流都停止，因为页面卸载了，失败的调用也不会重试。在 v2.10.0 上，页面不处理 401；你自己刷新。重新加载即可再次登录。你不用打开这个画面。不是来自 `/api/` 的 401 不会拉起它。（[#229](https://github.com/foolzzz/looper/pull/229)）
7. **密码会话可以退出。** 当 `GET /api/status` 说 `can_sign_out` 为 true 时，侧栏显示 Sign out：这是没有令牌 cookie 的密码会话。控件 `POST` `/logout`，浏览器落到 `/login`。本机浏览器的自动登录不显示 Sign out，发送操作者令牌的调用方也不显示。其他机器要登录时，用 `looper auth set-password` 设置密码，与 v2.10.0 一样。你不用为这个按钮增加设置。（[#229](https://github.com/foolzzz/looper/pull/229)）
8. **Dashboard 页面发送 `Referrer-Policy: same-origin`。** 在 v2.10.0 上它们发送 `no-referrer`。在 `no-referrer` 下，Sign out 表单提交 `Origin: null`，`/logout` 回答 403。你不用配置这个头。`same-origin` 仍然不把页面地址发给其他站点。`Cache-Control: no-store` 不变。（[#229](https://github.com/foolzzz/looper/pull/229)）
9. **Planner 和 Worker 的失败文本写明实际运行的运行时。** Planner 的失败读作 “Codex turn did not succeed” 或 “OMP exited before finishing the turn”，Worker 的失败读作 “Grok run did not succeed” 或 “OMP exited with code N”。在 v2.10.0 上，同样的失败写 “Claude Code”。不用配置。匹配这些句子里 “Claude Code” 的日志检查或脚本，改为匹配运行时的名称。（[#229](https://github.com/foolzzz/looper/pull/229)）

能替换的每一种运行时都使用角色的模式。`vX.Y.Z` 标签仍会发布这个 Python release。

### 修复

- **Dashboard 处理失效的会话。** 在 v2.10.0 上没有 Sign out，会话结束之后页面也不处理 401。密码会话现在有 Sign out。任何 `/api/` 的 401 都显示一个画面，“Your session ended. Reload to sign in again.”，带 Reload，并且每一个轮询和流都停止。这次调用不会重试。（[#229](https://github.com/foolzzz/looper/pull/229)）
- **失败的回合写明运行它的运行时。** Codex、Grok 和 OMP 上的 Planner 和 Worker 失败原来写 “Claude Code”。现在写 “Codex turn did not succeed”、“OMP exited ...” 或 “Grok run did not succeed”。（[#229](https://github.com/foolzzz/looper/pull/229)）
- **Sign out 能到达 `/login`。** 表单 POST 需要 Origin。Dashboard 页面发送 `Referrer-Policy: same-origin`，因此 `/logout` 接受这次 POST。在以前的 `no-referrer` 策略下，同一次 POST 是 403。（[#229](https://github.com/foolzzz/looper/pull/229)）

### 破坏性变更

1. **Codex、Grok 和 OMP 的 Manager 和 Planner 启动替换运行时的默认 system prompt。** 在 v2.10.0 上因为 Profile 是 `append` 或从未设置而追加的启动，现在用 Looper 的提示词代替该运行时的默认指引。脚本不会为此调用新的 API。这些运行时上的下一次 Manager 或 Planner 回合就会使用它。要保持 append，在 Settings → Roles 设置角色，或在 Agents 页或用 `looper_task_update` 设置任务的 planner。Manager 没有任务级覆盖。Claude Code 的 Manager 和 Planner 在 v2.10.0 上已经替换。（[#226](https://github.com/foolzzz/looper/pull/226)）
2. **Agent Profile 不再有 `system_prompt_mode`，迁移会删除这一列。** `POST /api/agent-profiles` 或 `PUT /api/agent-profiles/<id>` 上的 `system_prompt_mode` 返回 HTTP 400（`unknown field 'system_prompt_mode'`）。Manager 的 Profile 工具没有这个参数。导出省略该字段。更旧导出的导入忽略它并记下上面的说明。首次启动在角色层还没有模式时，把 Worker 或 Reviewer 的 Profile `replace` 复制到角色层，然后删除 `agent_profiles.system_prompt_mode`。把模式保存在 Profile 上的客户端，必须改存到角色上。在 Codex、Grok 或 OMP 上追加的 Manager 或 Planner Profile 不会保持追加。（[#226](https://github.com/foolzzz/looper/pull/226)）
3. **任务已存的模式对每一种运行时生效。** 在 v2.10.0 上只对 Claude Code 生效的 `system_prompt_modes`，现在对 Codex、Grok 和 OMP 也生效。如果这不是本意，就清除它。（[#226](https://github.com/foolzzz/looper/pull/226)）

**其他记录或权限上的变化。** 每一种运行时上的 consult 即使席位的角色是 replace 也追加。规划者定义的角色运行跟随任务的 Worker 或 Reviewer 模式。提示词预览不再包含 `system_prompt_mode_applies`。401 时 dashboard 显示一个会话结束画面，并停止每一个轮询和流。Dashboard 页面发送 `Referrer-Policy: same-origin`。`GET /api/status` 增加 `can_sign_out`。Planner 和 Worker 的失败文本写明实际运行的运行时。（[#226](https://github.com/foolzzz/looper/pull/226)、[#229](https://github.com/foolzzz/looper/pull/229)）

### 从 v2.10.0 升级

1. **用 `install.sh` 安装。** 它安装最新 release 的 wheel。本版本不增加 Python 依赖。
2. **保证首次启动能备份。** 表结构在一次性复制之后删除 `agent_profiles.system_prompt_mode`，因此首次启动会先写一份 `pg_dump` 备份再迁移。请在 `PATH` 上保留主版本不低于服务器的 `pg_dump`（或设置 `LOOPER_PG_DUMP`、`LOOPER_BACKUP_CMD`）。`looper serve --skip-backup` 不备份直接迁移。
3. **启动一次。** 升级会在角色层还没有模式时，把 Worker 或 Reviewer 的 Profile `replace` 复制到角色层，然后删除 Profile 上的这一列。第二次启动不会再复制。`task_system_prompt_modes` 和角色层的列在 v2.10.0 就已经存在。它们不会被再次创建。
4. **决定 Codex、Grok 和 OMP 的模式。** Settings → Roles：没有已有角色覆盖时，Manager 和 Planner 是 Replace，Worker 和 Reviewer 是 Append，除非迁移给一个有效 Profile 为 replace 的 Worker 或 Reviewer 写下了 Replace。把角色设成 Append，就能让一个因为 Profile 如此而追加的 Manager 或 Planner 保持 v2.10.0 的拼接方式。任务的 Agents 页在每一种运行时上覆盖它的 planner、worker 或 reviewer。`looper_task_update` 可以设置同样的覆盖。
5. **看已经有模式的任务。** v2.10.0 存下的模式现在对 Codex、Grok 和 OMP 生效。不该生效时，在 Agents 页重置它。
6. **Planner 使用 haiku。** 在 v2.10.0 上，replace 在 Planner 层得分 31/40，append 是 50/60。本版本没有重跑该层。把 Planner 放到 opus 或 sonnet 上跑，或把 Planner 角色设成 append。
7. **不要在 Profile 上设置 `system_prompt_mode`。** API 返回 400。导入会跳过该字段并记一条说明。把模式设在角色上。
8. **Dashboard。** 重新加载升级前开着的标签页。密码会话显示 Sign out。401 之后，页面是会话结束画面；Reload 会再次进入登录。
9. **检查。** 运行 `looper doctor`；使用服务时再运行 `looper service status`。没有覆盖或迁移保留的 Worker/Reviewer replace 设置时，`GET /api/agent-settings` 显示 manager 和 planner 为 `replace`，worker 和 reviewer 为 `append`。

```bash
curl -fsSL https://raw.githubusercontent.com/foolzzz/looper/main/install.sh | bash
looper doctor
looper serve
  # 或者使用服务：
looper service restart && looper service status
```

**回退到 v2.10.0。** 停止 Looper（装了服务就运行 `looper service uninstall`），把数据库重建为空库，并恢复首次启动日志里给出的迁移前备份（`pg_restore --no-owner --dbname "$LOOPER_DATABASE_URL" FILE`）。然后安装 v2.10.0 的 wheel，例如 `uv tool install --force "looper @ https://github.com/foolzzz/looper/releases/download/v2.10.0/looper-2.10.0-py3-none-any.whl"`。`install.sh` 总是安装最新 release，不能用来回退。v2.10.0 仍为 Codex、Grok 和 OMP 读取 `agent_profiles.system_prompt_mode`。本版本迁移过的数据库，在恢复那份备份之前，不是 v2.10.0 的数据库。
