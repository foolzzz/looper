# Looper v2.13.36

## Release Decision

**Who should upgrade:** Operators who use the dashboard chat page and see the Manager session's Agent line read `name — undefined · undefined / undefined / undefined`. Others have nothing to do.

**What this release solves:** [#398](https://github.com/foolzzz/looper/pull/398) fixes the Agent Profile label on the dashboard chat page. The server sent a summary of the profile, the page read it as a registry profile, and three fields came out `undefined`.

**Breaking changes:** No. No CLI command, configuration key, API shape or database schema changed. This is a dashboard fix only.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#398](https://github.com/foolzzz/looper/pull/398); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.36
```

## Behavior changes

- **Chat header and new-session panel:** the Manager session's Agent Profile label reads `name — runtime · provider / model`, with no `undefined`. `GET /api/manager/session` already returned the effective profile as a summary (`profile_id`, `name`, `runtime`, `provider`, `model`, `effort`, all strings); `web/src` typed it as a registry `AgentProfile` and formatted it with `profileLabel`, which reads `runtime_name`, `provider.name` and `model.name`. A `ManagerSessionProfileSummary` type and `sessionProfileLabel` now match what the server sends, and the chat header and the new-session panel use them.
- **Entry points:** the dashboard chat page only. The server, the API and the Settings pages did not change.
- **Model-visible changes:** none. No prompt, tool, per-turn context or eval changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.36 is published. Nothing needs migrating. Rolling back to v2.13.35 is safe and only brings back the `undefined` label.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.
