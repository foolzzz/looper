# Looper v2.14.165

This is the patch release v2.14.165, a hotfix line in which each merged change ships at once. It documents one change: [#1300](https://github.com/foolzzz/looper/pull/1300) (Telegram messages sent just before a stop).

## Release Decision

**Who should upgrade:** Installations that use the Telegram channel and restart it (or the service that runs it). Others need not upgrade for behavior.

**What this release solves:** [#1300](https://github.com/foolzzz/looper/pull/1300) fixes the listed valid item of the review follow-up #989: a Telegram message sent just before the channel stopped is no longer dropped as stale after the restart, and the stop boundary is kept until the message is handled.

**Breaking changes:** No. There is no API change, migration or main-database schema change. The Telegram channel's own inbox file gets one added column (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.165
```

**Contributors:** Maintainer @foolzzz authored [#1300](https://github.com/foolzzz/looper/pull/1300); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.164 upgrades directly. There is no main-database schema change.

## Behavior changes

[#1300](https://github.com/foolzzz/looper/pull/1300) states that its behavior changes follow the triage notes' fixes (maintainer decision, intended). Read in the code, it changes `looper/agents/channels/telegram.py`, `looper/agents/channels/telegram_inbox.py` and `tests/test_telegram_restart.py`:

- **Age fixed at the stop.** An update dated before polling resumed gets an `age_at_stop` value, the time between its date and the saved stop time (at least 0). The stale-backlog check uses that value instead of the wall-clock age, so downtime does not age the update. The earlier check exempted only updates dated inside the downtime window, so one sent just before the stop was dropped. An update older than the backlog limit at the stop is still ignored.
- **Kept until handled.** The value is saved with the update in the channel's inbox file, set when the update is stored and, at polling start, for pending rows saved by an older inbox. It is cleared when the update is finished, so a handler failure followed by another stop and restart still keeps the age.
- **Inbox file.** On opening, the inbox adds an `age_at_stop` column to its `updates` table if it is missing. The column is nullable and the inserts name their columns, so an older version can still read the file.
- **Model-visible changes:** None. No prompt, tool description, schema or answer text changes; the change decides which Telegram updates reach the manager.

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.164 上的安装可直接升级。主数据库没有结构变更。

### 行为变化与入口

[#1300](https://github.com/foolzzz/looper/pull/1300) 声明行为变化遵循分诊记录中的修复（维护者决定，符合预期）。代码中可见，它改动 `looper/agents/channels/telegram.py`、`looper/agents/channels/telegram_inbox.py` 和 `tests/test_telegram_restart.py`：

- **以停止时刻计龄。**发送时间早于轮询恢复时间的更新会得到 `age_at_stop`，即其发送时间与已保存停止时间之差（不小于 0）。过期积压检查用该值而不是当前时钟下的年龄，因此停机时间不会让更新变旧。此前的检查只豁免发送时间落在停机窗口内的更新，停止前不久发送的消息会被丢弃。在停止时就已超过积压上限的更新仍会被忽略。
- **保留到处理完成。**该值与更新一起保存在通道的 inbox 文件中：存入更新时写入，轮询启动时也会为旧版 inbox 保存的待处理行补写。更新处理完成时清除，因此处理失败后再次停止并重启，年龄仍然保留。
- **inbox 文件。**打开时，如果 `updates` 表缺少 `age_at_stop` 列则添加。该列可为空，插入语句也显式列出列名，旧版本仍可读取该文件。
- **面向模型的变化：**无。提示词、工具描述、schema 和回答文本均未改动；改动只决定哪些 Telegram 更新会送达 manager。
