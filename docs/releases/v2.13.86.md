# Looper v2.13.86

## Release Decision

**Who should upgrade:** Anyone who calls `GET /api/config/export` or the `/api/config/imports` routes from a script, or who exports and imports configuration in the dashboard. Everyone else gets no change.

**What this release solves:** [#513](https://github.com/foolzzz/looper/pull/513) moves the dashboard's configuration export, import upload, apply and cancel onto the versioned API and removes the four legacy routes.

**Breaking changes:** Yes. `GET /api/config/export`, `POST /api/config/imports`, `POST /api/config/imports/{id}/apply` and `DELETE /api/config/imports/{id}` are removed; a script that calls them must use `POST /api/v1/config/export`, `/api/v1/config/import_upload`, `/api/v1/config/import_apply` and `/api/v1/config/import_cancel`. Responses are wrapped in the v1 envelope (`result`), and errors use v1 error codes. The dashboard shipped in this release already uses the new operations.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#513](https://github.com/foolzzz/looper/pull/513); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.86
```

## Behavior changes

- **Upload ([#513](https://github.com/foolzzz/looper/pull/513)):** the new `looper/agents/v1_domains/configuration.py` registers `config.import_upload` (risk `read`) as `POST /api/v1/config/import_upload`. The body is the raw portable document and must be sent as `application/json`; it is streamed to the private staging file (not buffered in the request body), checked against the published `ConfigDocument` schema, and previewed. Nothing is written to the configuration. The size cap is the existing import cap. A wrong content type, a document that fails the schema, an unusable file or an interrupted upload answers `invalid`; a staged-import or pending schema-change conflict answers `conflict`; no runtime root answers `unavailable`. Refusals before the body is read (request guard, bad or oversized `Content-Length`) also use v1 errors on this path, with HTTP 413 for an oversized body.
- **Cancel:** `config.import_cancel` (risk `write`) moves into the same domain; an unknown import becomes `not_found` and a conflict becomes `conflict`. It removes only the calling identity's staged file.
- **Apply:** `config.import_apply` is unchanged (risk `high`; a client token needs a session confirmation, an operator session completes in one call). The internal apply helper no longer accepts a request body.
- **Export:** `config.export` is written straight to the response from a read-only repeatable-read snapshot in chunks, instead of being collected and re-parsed in memory. A failure before the first chunk gets a typed JSON error; a failure after the headers leaves a visibly truncated, invalid JSON response.
- **Schemas:** the import plan's `counts` is now a closed object per section (`added`, `changed`, `unchanged`, `skipped`), a change `action` is one of `added`, `changed`, `skipped`, and a `need_secret` target `kind` is one of `provider`, `mcp`, `channel`. `ConfigDocument`, `ConfigAbout` and `ConfigImportPlan` are published in the OpenAPI document.
- **Removed routes:** the four legacy routes, their two URL patterns and the `CONFIG_IMPORTS_PATH` constant are removed from `looper/agents/http_server.py`.
- **Dashboard:** `web/src/lib/api.ts` calls the v1 operations. Export downloads the document from the JSON envelope as `looper-config-<date>.json`, with a disabled, spinning button while it runs and an inline error on failure. Upload sends the file as the raw body; apply reports an error if the plan was not applied; cancel treats an already-gone import as success.
- **CLI:** `looper config` keeps its `export` and `import` parsers; the generated parser may now add further subcommands to it.
- **Docs:** `README.md` and `README.zh-CN.md` list the new routes in the route table.
- **Tests:** `tests/test_api_v1_configuration_ui.py` and `tests/test_api_v1_configuration_ui_db.py` were added; the config import, owner, transfer, operator auth, model dashboard, CLI operation and dashboard transfer tests were moved to the new operations.
- **Model-visible changes:** None found. Manager, Planner, Worker and Reviewer prompts, role recommended prompts and Tool declarations are unchanged; the new operations declare no Tool. They appear in the v1 operation catalog that API clients read.
- **Not confirmed in code:** whether other prose docs still name the removed routes beyond the two README tables. This draft did not run any test.

## Upgrade and rollback

Re-run `install.sh` once v2.13.86 is published. No data migration; staged imports and stored configuration are untouched. Update any script that used the removed routes. Rolling back to v2.13.85 restores them together with the old dashboard.

### 行为变化与入口

- **上传（[#513](https://github.com/foolzzz/looper/pull/513)）：**新增 `looper/agents/v1_domains/configuration.py`，注册 `config.import_upload`（风险 `read`），路径 `POST /api/v1/config/import_upload`。请求体为原始的可移植文档，必须以 `application/json` 发送；它被流式写入私有暂存文件（不进入请求体缓冲），按已发布的 `ConfigDocument` schema 校验后预览，不写入任何配置。大小上限沿用现有导入上限。内容类型错误、不符合 schema、文件不可用或上传中断返回 `invalid`；暂存导入或待处理的 schema 变更冲突返回 `conflict`；没有运行时根目录返回 `unavailable`。在读取请求体之前的拒绝（请求守卫、`Content-Length` 错误或超限）在此路径上同样使用 v1 错误，超限为 HTTP 413。
- **取消：**`config.import_cancel`（风险 `write`）迁入同一个域；导入不存在转为 `not_found`，冲突转为 `conflict`。它只删除调用者自己的暂存文件。
- **应用：**`config.import_apply` 不变（风险 `high`；客户端令牌需要会话确认，操作者会话一次调用即可完成）。内部的应用辅助函数不再接受请求体。
- **导出：**`config.export` 从只读的 repeatable-read 快照分块直接写入响应，不再先在内存中收集并重新解析。第一块之前失败会得到类型化的 JSON 错误；响应头发出后失败会留下明显被截断的无效 JSON。
- **Schema：**导入计划的 `counts` 现在是按段的封闭对象（`added`、`changed`、`unchanged`、`skipped`），变更的 `action` 为 `added`、`changed`、`skipped` 之一，`need_secret` 目标的 `kind` 为 `provider`、`mcp`、`channel` 之一。`ConfigDocument`、`ConfigAbout` 与 `ConfigImportPlan` 发布在 OpenAPI 文档中。
- **移除的路由：**四条旧路由、两个 URL 正则和 `CONFIG_IMPORTS_PATH` 常量已从 `looper/agents/http_server.py` 移除。
- **仪表盘：**`web/src/lib/api.ts` 调用 v1 操作。导出从 JSON 信封下载文档并保存为 `looper-config-<日期>.json`，期间按钮禁用并显示转圈，失败时显示行内错误。上传以原始请求体发送文件；应用在计划未被应用时报错；取消把已不存在的导入视为成功。
- **命令行：**`looper config` 保留 `export` 与 `import` 解析器；生成的解析器现在可以向其添加更多子命令。
- **文档：**`README.md` 与 `README.zh-CN.md` 的路由表列出新路由。
- **测试：**新增 `tests/test_api_v1_configuration_ui.py` 与 `tests/test_api_v1_configuration_ui_db.py`；配置导入、所有者、传输、操作者认证、模型仪表盘、CLI 操作和仪表盘传输测试已改用新操作。
- **面向模型的变化：**未发现。Manager、Planner、Worker、Reviewer 的 prompt、角色推荐 prompt 以及 Tool 声明均未改动；新操作未声明 Tool。它们会出现在 API 客户端读取的 v1 操作目录中。
- **代码中未确认：**两处 README 路由表之外，其他散文文档是否仍写着已移除的路由。本草稿未运行任何测试。
