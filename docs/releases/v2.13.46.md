# Looper v2.13.46

## Release Decision

**Who should upgrade:** Anyone whose Manager creates and starts a task in one turn, in chat or in a channel. Everyone else can stay on v2.13.45: nothing else changed.

**What this release solves:** [#428](https://github.com/foolzzz/looper/pull/428) stops the Manager's reply from ending with "现在开始吗？" (the question whether to start the task) and the "Ready — not started" heading for a task that the same turn already started.

**Breaking changes:** No. Only the text of one reply changes; no route, schema, setting or command changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#428](https://github.com/foolzzz/looper/pull/428); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.46
```

## Behavior changes

- **Manager reply after create and start (`looper/agents/ops/tasks.py`, `looper/agents/ops/__init__.py`):** `looper_task_create` now remembers the configuration block it added to the turn (`Turn.created_task_blocks`). When `looper_task_control` with `start` succeeds for that same task in the same turn, the block is replaced with the heading `任务已创建：` and the configuration lines, without the `Ready — not started` wording and without the start question. The start question is dropped as soon as the start request succeeds, even if the task router has not yet consumed the start.
- **Unchanged cases:** a turn that creates a task and does not start it, a start that fails (for example with a conflict), and a start of a different task than the one just created all keep the heading and the question for the created task.
- **Model-visible changes:** None to the Manager's prompt or tool schemas. The `looper_task_create` result still carries its `shown_to_user` note; only the reply text the user sees, built by Looper after the turn, differs in the create-and-start case.
- **Tests:** `tests/test_manager_task_start_question.py` runs a Manager turn through four cases (same task started, not started, start failed, another task started).

## Upgrade and rollback

Re-run `install.sh` once v2.13.46 is published. No data migration. Rolling back to v2.13.45 needs no step; the older program again asks to start a task that is already running.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**管家在同一轮里创建并启动任务的用户（对话或渠道均可）。其他人可留在 v2.13.45，没有其他改动。

**解决了什么：**[#428](https://github.com/foolzzz/looper/pull/428) 让管家的回复不再对本轮已经启动的任务，还以「现在开始吗？」结尾并写着「Ready — not started」。

**是否有破坏性变更：**无。只改变一类回复的文字，没有路由、schema、设置或命令变化。

**如何验证：**运行 `looper --version` 核对版本为 2.13.46。

**贡献者：**维护者 @foolzzz 提交 [#428](https://github.com/foolzzz/looper/pull/428)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.46
```

### 行为变化与入口

- 创建并启动后的管家回复：`looper_task_create` 记下本轮加入的配置块（`Turn.created_task_blocks`）；同一轮里对该任务的 `looper_task_control` `start` 成功后，该块改为标题「任务已创建：」加配置行，去掉「Ready — not started」和开始提问。启动请求一成功即去掉提问，即使任务路由还没消费该启动。
- 不变的情形：只创建不启动、启动失败（如冲突）、启动的是另一个任务，这几种情况下刚创建的任务仍保留原标题和提问。
- 面向模型的变化：管家的提示词和工具 schema 均未改；`looper_task_create` 的结果仍带 `shown_to_user` 说明，只是本轮结束后由 Looper 生成、用户所见的回复文字在创建并启动的情形下不同。
- 测试：`tests/test_manager_task_start_question.py` 用四种情形（启动同一任务、不启动、启动失败、启动另一任务）跑一轮管家对话。

### 升级与回退

发布后重跑 `install.sh`，无需迁移数据。回退到 v2.13.45 无需额外步骤，旧版本会再次对已运行的任务发出开始提问。
