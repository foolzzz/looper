# Looper v2.14.123

This is the patch release v2.14.123, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.122: for tasks with a workflow, the code-generated delivery summary reaches the Telegram, Lark and web-chat completion notices, Reviews and Verification keep the latest verdicts, and a Cursor run on auto reports the model it was routed to ([#1201](https://github.com/foolzzz/looper/pull/1201), issue #1197).

## Release Decision

**Who should upgrade:** Operators who run tasks with a workflow and read their completion notices in Telegram, Lark or web chat, and those who run the Cursor runtime on auto and read `model_reported`. Tasks without a workflow see no change in behavior.

**What this release solves:** [#1201](https://github.com/foolzzz/looper/pull/1201). The delivery summary of a workflow task now reaches the completion notices intact; a late review or verification failure is no longer dropped from it; and a Cursor run on auto shows the model it was actually routed to.

**Breaking changes:** No. There is no database or API schema change; the `delivery_summary` field is added to the task-end message payload.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.123
```

**Contributors:** Maintainer @foolzzz authored [#1201](https://github.com/foolzzz/looper/pull/1201); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.122 upgrades directly. There is no schema change.

## Behavior changes

- **Delivery summary in completion notices.** For a task with a workflow, the Planner's task-end message carries `delivery_summary` next to `process_record`. The Telegram and Lark notice appends it after the summary's lead and before the worktree line. The web-chat completion message appends it once after the result clip of 2000 characters, so the clip no longer cuts it. The summary is bounded to 1200 characters. Tasks without a workflow carry no `delivery_summary`.
- **Latest verdicts first.** In the summary, Reviews and Verification keep the latest outcome per seat or step, and failed outcomes are listed before passed ones, so a late failure is not the entry dropped when the summary is clipped. A late review verdict that arrives after a decision is recorded in the journal in arrival order.
- **Escalations as a short label.** Escalations in the summary show the step label, the gate and its state, and a clipped reason, instead of the full journal line. The clip now breaks at a word boundary near the limit.
- **Routed model for Cursor on auto.** For runs of the `cursor-agent` runtime, the reported model is the `routed_model` from the run's result when there is one, ahead of `model_reported` and the Auto display label. This applies to `runs.get`, `runs.list` and the summary's Roles line; the process-record query now reads `routed_model` from run metadata.
- **Unchanged:** tasks without a workflow, the stored full process record, the profile settings and the channel commands.
- **Model-visible changes:** None to the Planner, Worker, Reviewer or Manager prompts and contracts. The completion notices, run records and the summary in the process record that users and tools read change as described above.

**如何验证：**核对版本为 2.14.123。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.122 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **完成通知中的交付摘要。**对带工作流的任务，Planner 的任务结束消息在 `process_record` 旁携带 `delivery_summary`。Telegram 和 Lark 通知把它附在摘要开头之后、worktree 行之前。网页聊天的完成消息在 2000 字符的结果截断之后附加一次，因此不会被截断。摘要上限 1200 字符。没有工作流的任务不带 `delivery_summary`。
- **最新结论优先。**摘要中的 Reviews 和 Verification 对每个席位或步骤保留最新结果，失败项排在通过项之前，因此摘要被截断时不会丢掉晚到的失败。决策之后才到达的评审结论按到达顺序记入日志。
- **升级事项为简短标签。**摘要中的升级事项显示步骤标签、关卡及其状态和截短的理由，而不是完整的日志行。截断在接近上限的词边界处进行。
- **Cursor auto 的实际路由模型。**对 `cursor-agent` 运行时的运行，只要运行结果带有 `routed_model`，报告的模型就是它，优先于 `model_reported` 和 Auto 显示标签。适用于 `runs.get`、`runs.list` 和摘要的 Roles 行；过程记录查询现在从运行元数据读取 `routed_model`。
- **不变：**没有工作流的任务、已存储的完整过程记录、profile 设置和渠道命令。
- **面向模型的变化：**Planner、Worker、Reviewer 和 Manager 的提示词与契约无变化。用户和工具读取的完成通知、运行记录和过程记录中的摘要按上述方式变化。
