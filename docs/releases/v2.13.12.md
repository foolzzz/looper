# Looper v2.13.12

## Release Decision

**Who should upgrade:** Operators who use the dashboard and want one place to see every task's user gates and answer them. Everyone else sees no change.

**What this release solves:** [#275](https://github.com/foolzzz/looper/pull/275) adds a User Gates page to the dashboard. Until now a gate showed only on its task page and, for running tasks, in the Dashboard's "Waiting for you" list (at most 10), so there was no view of how many gates exist or which wait for you. The new page lists the gates of all tasks, open ones by default, lets you answer a waiting gate in place, and the sidebar shows how many wait for you.

**Breaking changes:** No. The CLI, configuration, database schema and existing API routes are unchanged from [v2.13.11](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.11.md). One read-only route is added.

**How to verify:** Check the installed version, then open the dashboard and select User Gates in the sidebar.

**Contributors:** Maintainer @foolzzz authored [#275](https://github.com/foolzzz/looper/pull/275); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.12
```

## Behavior changes

- **New User Gates page (`#gates`).** The sidebar gains a "User Gates" entry under Tasks. The page lists the gates of all tasks, newest opened first, with the task (linked), topic, state, opened time, last message, open agenda questions and an action. It shows Open (default), Closed or All, a "Waiting for you only" switch (under Open only) and a project filter; the choices are kept in the address. "Show more" adds 50 rows; the page refreshes every 10 seconds. Each row links to the gate on its task page, and a gate waiting for you has an "Answer" button that opens the existing reply card and sends through the existing gate message route. Loading, error (with Retry) and empty states are handled.
- **Sidebar badge.** The User Gates entry shows the number of gates waiting for you (99+ above 99), only when it is above 0. If the count cannot be read, no badge shows, never a 0. It is read every 10 seconds and again at once when the dashboard changes a gate.
- **New route `GET /api/gates`.** Operator-only like the other `/api/` routes. Query: `state` (`open` default, `closed`, `all`), `waiting_on` (`user` or `planner`, with `state=open` only), `project_id`, `limit` (1 to 200, default 50), `offset`. It answers `{gates, total, counts, limit, offset}`; each gate carries its task, the gate view, the number of open agenda items and the last user or Planner message. Bad values give 400. `open` means a waiting gate in a task that is not completed or cancelled. `waiting_on` follows the task page: when the task is not running, a gate waiting for the Planner counts as waiting for the user.
- **Dashboard reply card exported.** `GateReply` in the Dashboard's gates component is now exported and takes a narrower task type so the new page reuses it. The Dashboard behaves as before.
- **Model-visible changes:** None. No prompt, tool schema or tool contract changed; the route and page are for the operator's browser.

## Entry points

- Dashboard page `#gates` (sidebar "User Gates").
- HTTP route `GET /api/gates` (read-only, operator credentials). No CLI command or configuration key was added.

## Upgrade and rollback

Re-run `install.sh` once v2.13.12 is published. There is no schema or configuration change and no new index. Rolling back to v2.13.11 is safe; it removes the page, the badge and the route only.

No new optional capability activation is introduced in this release.

### 升级决策

**谁需要升级：**使用 dashboard、想在一处查看所有任务的用户关卡并回复的运营者。其他人没有变化。

**解决了什么：**[#275](https://github.com/foolzzz/looper/pull/275) 为 dashboard 新增 User Gates 页。此前关卡只出现在任务页和 Dashboard 的「Waiting for you」（只含运行中任务，最多 10 个），看不到一共有多少关卡、哪些在等你。新页面列出所有任务的关卡，默认只看没关的，可就地回复等你的关卡，侧栏显示等你回复的数量。

**是否有破坏性变更：**无。CLI、配置、数据库 schema 和已有 API 路由与 [v2.13.11](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.11.md) 相同，仅新增一个只读路由。

**如何验证：**运行 `looper --version` 核对版本为 2.13.12；打开 dashboard，点侧栏的 User Gates。

**贡献者：**维护者 @foolzzz 提交 [#275](https://github.com/foolzzz/looper/pull/275)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.12
```

### 行为变化与入口

- 新增 User Gates 页（`#gates`）：侧栏 Tasks 下新增入口。页面按打开时间从新到旧列出所有任务的关卡（任务链接、主题、状态、打开时间、最后一条消息、未决问题数、操作）；可切 Open（默认）、Closed、All，有「Waiting for you only」开关（仅 Open 下）和项目筛选，选择记在地址里。「Show more」每次多取 50 条，页面每 10 秒刷新。每行链到任务页的关卡；等你回复的关卡有「Answer」按钮，就地展开已有的回复卡片，走已有的关卡消息接口。加载、出错（含 Retry）和空状态都有处理。
- 侧栏徽标：User Gates 项显示等你回复的关卡数（超过 99 显示 99+），大于 0 才出现；读取失败时不显示，不会显示成 0。每 10 秒读取一次，Dashboard 改动关卡时立即刷新。
- 新增路由 `GET /api/gates`：与其他 `/api/` 路由一样只给 operator。参数：`state`（`open` 默认、`closed`、`all`）、`waiting_on`（`user` 或 `planner`，仅配 `state=open`）、`project_id`、`limit`（1 到 200，默认 50）、`offset`。返回 `{gates, total, counts, limit, offset}`；取值不对返回 400。`open` 指任务未完成、未取消且关卡在等待。`waiting_on` 与任务页一致：任务不在运行时，等规划者的关卡算作等用户。
- Dashboard 的回复卡片 `GateReply` 改为导出，任务类型收窄以便复用；Dashboard 行为不变。
- 面向模型的变化：无。提示词、工具 schema、工具契约都没有变化；路由和页面只面向 operator 的浏览器。未新增 CLI 命令或配置项。
