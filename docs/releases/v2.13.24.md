# Looper v2.13.24

## Release Decision

**Who should upgrade:** Maintainers who run the prompt-regression evals (`evals/prompt_regression`). Everyone else sees no change; no runtime code is touched.

**What this release solves:** [#361](https://github.com/foolzzz/looper/pull/361) fixes the review follow-ups of #314. The `start_no_wait` dialog check of the prompt-regression evals now also fails a Manager run that calls a native shell tool such as `Bash` (for example `sleep`) after starting a task. Before, it read only the MCP action trail, so such a call was not seen.

**Breaking changes:** No. No CLI command, configuration key, API or database schema changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#361](https://github.com/foolzzz/looper/pull/361); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.24
```

## Behavior changes

- **`start_no_wait` sees native tool calls:** after the start call, the check reads the newest non-autonomous Manager run's `tool_use` events (top-level assistant events only, from `/api/llm-records` and the run's events) and counts every tool whose name does not contain `looper_` as a call made after the start. Such a call fails the check with "the Manager ran [...] after starting the task". Before, only the MCP action trail was read, so a native `Bash` `sleep` passed (`evals/prompt_regression/dialogs.py`).
- **Tests:** a new parametrized test covers a run with no call after the start (passes) and a run with `Bash` `sleep 60` after it (rejected) (`tests/test_prompt_eval.py`).
- **Deferred, not fixed here:** the PR defers two items that stay open in #314: the paid Opus xhigh 2-rep eval evidence for `looper/agents/tiers/manager.py`, and the flaky `test_dsh_installed_run_without_platform_bridge[False-worker]`, which passes alone and has no reproducible root cause.
- **Not in the diff:** the PR description also lists a fix to the constraint count in `test_schema_applies_twice_with_column_and_constraint`, but the PR changes only the two files above, so this release does not claim it.
- **Model-visible changes:** None. No prompt text, tool schema or tool result changed; the change is in the eval harness only.

## Upgrade and rollback

Re-run `install.sh` once v2.13.24 is published. There is no schema or configuration change. Rolling back to v2.13.23 is safe; the eval check then ignores native shell calls again.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 行为变化与入口

- `start_no_wait` 能看到原生工具调用：启动调用之后，该检查读取最新的非自主 Manager 运行的 `tool_use` 事件（仅顶层 assistant 事件，来自 `/api/llm-records` 及该运行的事件），名称不含 `looper_` 的工具都算作启动之后的调用，检查以“the Manager ran [...] after starting the task”失败。此前只读 MCP 动作轨迹，原生 `Bash` 的 `sleep` 能通过（`evals/prompt_regression/dialogs.py`）。
- 测试：新增参数化测试，覆盖启动后无调用（通过）和启动后有 `Bash` `sleep 60`（被拒绝）两种情况（`tests/test_prompt_eval.py`）。
- 延后未修：PR 延后两项，仍在 #314 跟踪：针对 `looper/agents/tiers/manager.py` 的付费 Opus xhigh 2-rep eval 证据，以及不稳定的 `test_dsh_installed_run_without_platform_bridge[False-worker]`（单独运行通过，无可复现根因）。
- 不在 diff 中：PR 描述还列出对 `test_schema_applies_twice_with_column_and_constraint` 约束计数的修复，但该 PR 只改了上述两个文件，因此本版本不声称包含它。
- 面向模型的变化：无。提示词文本、工具 schema、工具结果均无变化；改动仅在 eval 框架内。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.23 安全；此时 eval 检查将再次忽略原生 shell 调用。
