# Looper v2.13.96

## Release Decision

**Who should upgrade:** Anyone who enables several Telegram or Lark bot rows in Settings that may point at the same bot, where one of them can fail to start.

**What this release solves:** [#565](https://github.com/foolzzz/looper/pull/565) stops a bot row whose channel failed to start from reserving that bot's identity. Before, the row was recorded as started before its channel was registered, so a later row for the same bot was refused as a duplicate even though no channel was serving the bot.

**Breaking changes:** No. No API, configuration, prompt or Tool declaration changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#565](https://github.com/foolzzz/looper/pull/565); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.96
```

## Behavior changes

- **Bot identity reservation ([#565](https://github.com/foolzzz/looper/pull/565)):** `_register_bots` in `looper/agents/serve.py` now adds a row to its `started` list only after `_register_optional_channel` reports that the channel started. `_register_optional_channel` now returns a bool: `True` after `registry.register` succeeds, `False` when it raised (the failure is logged and the half-registered channel is unregistered, as before). A failed row therefore no longer counts as the owner of its bot, and the next enabled row of the same bot (same Telegram token or same Lark app) can start; the first row that starts successfully owns the identity and later rows of that bot are still refused.
- **Unchanged:** a failed channel still leaves the web dashboard and the other channels running, and the duplicate-bot refusal for a successfully started owner is unchanged.
- **Model-visible changes:** none for prompts, Tool declarations and Tool results.
- **Tests:** `tests/test_serve_channel_bots_db.py` adds cases for the first successful row owning the identity while a failed listener is stopped and unregistered, and for the channel registries after startup. [#565](https://github.com/foolzzz/looper/pull/565) reports 90 test lines and 5 production lines added.

## Upgrade and rollback

Re-run `install.sh` once v2.13.96 is published. No data migration and no configuration change. Rolling back to v2.13.95 restores the previous reservation behavior.

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**在 Settings 中启用多个可能指向同一个 Telegram 或 Lark bot 的行、且其中某一行可能启动失败的用户。

**解决了什么：**[#565](https://github.com/foolzzz/looper/pull/565) 不再让启动失败的 bot 行占用该 bot 的身份。此前该行在渠道注册之前就被记为已启动，导致同一 bot 的后续行被当作重复而拒绝，而实际上没有任何渠道在服务这个 bot。

**是否有破坏性变更：**否。API、配置、prompt 和 Tool 声明均未改变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.96。

**贡献者：**维护者 @foolzzz 提交 [#565](https://github.com/foolzzz/looper/pull/565)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.96
```

### 行为变化与入口

- **bot 身份的占用（[#565](https://github.com/foolzzz/looper/pull/565)）：**`looper/agents/serve.py` 中的 `_register_bots` 现在只在 `_register_optional_channel` 报告渠道启动成功后，才把该行加入 `started` 列表。`_register_optional_channel` 现在返回布尔值：`registry.register` 成功返回 `True`；抛出异常则返回 `False`（仍记录失败并注销半注册的渠道）。因此失败的行不再算作该 bot 的所有者，同一 bot（相同 Telegram token 或相同 Lark 应用）的下一条已启用行可以启动；第一条成功启动的行拥有该身份，该 bot 之后的行仍被拒绝。
- **不变：**渠道启动失败仍不影响 Web 仪表盘和其他渠道；对已成功启动的所有者，重复 bot 的拒绝逻辑不变。
- **面向模型的变化：**prompt、Tool 声明和 Tool 结果均无变化。
- **测试：**`tests/test_serve_channel_bots_db.py` 新增用例：第一条成功的行拥有身份、失败的监听器被停止并注销，以及启动后各渠道注册表的状态。[#565](https://github.com/foolzzz/looper/pull/565) 报告新增测试 90 行、生产代码 5 行。

### 升级与回退

v2.13.96 发布后重跑 `install.sh`。无需迁移数据，无需改配置。回退到 v2.13.95 会恢复之前的占用行为。
