# Looper v2.13.39

## Release Decision

**Who should upgrade:** Nobody needs to. This patch changes the test suite and CI only; installed behavior is the same as v2.13.38.

**What this release solves:** [#409](https://github.com/foolzzz/looper/pull/409) slims the test suite (step pr1): one PostgreSQL database per xdist worker, long prompt-eval tests split by scenario, and no fixed sleeps in the touched tests.

**Breaking changes:** No. No code under `looper/` changed apart from the version number.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#409](https://github.com/foolzzz/looper/pull/409); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.39
```

## Behavior changes

- **Product behavior:** none. The pull request touches `tests/`, the Python tests workflow and one plan document; the author states "Behavior changes: none".
- **Test databases:** under pytest-xdist, each worker creates a PostgreSQL database of its own, named `<name>_<worker>` after `LOOPER_TEST_DATABASE_URL`, points the variable at it for everything it runs, and drops it when the session ends (`tests/worker_database.py`, hooked in `tests/conftest.py`). Without xdist nothing changes. A crashed run's leftover databases are dropped by a later run only when they carry the worker mark and their owner is gone.
- **Tests:** `tests/test_prompt_eval.py` is split by scenario, and fixed sleeps are removed from a few test files (`test_proc_tree.py`, `test_per_turn_interrupt.py`, `test_manager_turn_binding.py` and others).
- **CI:** the Python tests job runs pytest with `--durations=25`, which only adds a report of the slowest tests.
- **Docs:** the plan document `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md` gains test-writing rules.
- **Model-visible changes:** none. No prompt, tool description or `Channel:` line changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.39 is published. There is no schema change and no data migration. Rolling back to v2.13.38 needs no step.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.
