# Looper v2.14.6

This is the patch release v2.14.6. It ships the one change merged since v2.14.5: [#880](https://github.com/foolzzz/looper/pull/880), which fixes how the DSH runner accounts, cancels and types model requests. It affects only installations that set `[runtimes] dsh = "runner"`.

## Release Decision

**Who should upgrade:** Operators who run DSH roles on the DSH runner (`[runtimes] dsh = "runner"`). Nothing changes for an installation whose ops file does not set it (the default is `cli`). It ships the one change merged since v2.14.5.

**What this release solves:** [#880](https://github.com/foolzzz/looper/pull/880) fixes four faults in the DSH runner: usage was treated as complete even when the provider reported no real token counts; a cancel during a pending authorization could outlast its deadline and lose a late allow; some stream errors were typed as internal errors; and `settled` could be sent before the session reached disk.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#880](https://github.com/foolzzz/looper/pull/880); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.6
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.5 upgrades directly. This release changes no schema, stored data or setting.

## Behavior changes

All changes are in the packaged DSH runner (`runners/dsh/src/`) and are reached only with `[runtimes] dsh = "runner"`.

- **Usage completeness (`provider.ts`):** the runner reads the provider's stream before the SDK translates it. A request's usage counts as complete only when the stream reaches `message_stop` and the usage fields reported so far include real input and output token counts (output is taken from the final message delta). Cache read and write counts are used when present. A successful stream without them is accounted as incomplete instead of as zero usage.
- **Cancel during pending authorization (`turn.ts`, `session.ts`):** the cancel no longer waits for an unanswered authorization before starting its deadline. At the deadline the turn is forced to settle, the session is released in the background, and the authorization wait is abandoned. If a host authorization was still unanswered, the turn is reported with incomplete usage and no `request_end` is invented; otherwise the failure message stays `cancel did not settle; the session was released`. A forced settle that already has a cancel now reports `cancelled` rather than `failed`, unless a failure was recorded. Closing a session whose release already ran does not release it twice.
- **Late authorization (`provider.ts`):** a late allow that arrives after the cancel but before `settled` is accounted as an aborted, complete request with zero tokens, before `settled`. A late deny or authorization error is accounted as no request. A model request started after the turn settled, or while it is settling, is refused as cancelled and never sent.
- **Error types (`turn.ts`):** DSH stream errors with code `AUTH` are reported as `PROVIDER_AUTH`, and `RATE_LIMIT` and `SERVER` as `PROVIDER_UNAVAILABLE`, as the HTTP statuses 401/403, 429 and 5xx already were.
- **Flush before settled (`turn.ts`):** the session is flushed to disk before the `settled` update. If the flush fails, the turn is reported as `failed` with `INTERNAL_ERROR` (`session persistence flush failed`) instead of as completed.
- **Tests (`tests/test_dsh_runner_requests.py`):** new tests for terminal usage counts, error typing, the on-disk session after settle and kill, the cancel and close deadline with a pending authorization, late allow, deny and error, and a failed flush.
- **Model-visible changes:** None. Prompts, tools and model requests are unchanged; a cancelled or failed turn now carries different outcome, error kind and usage-completeness fields on the host side only.

### 行为变化与入口

以下改动都在打包的 DSH runner（`runners/dsh/src/`）中，仅在 `[runtimes] dsh = "runner"` 时生效。

- **用量完整性（`provider.ts`）：**runner 在 SDK 转换之前读取提供方的流。仅当流到达 `message_stop` 且已报告的用量字段包含真实的输入和输出 token 数（输出取自最终的 message delta）时，请求用量才算完整；缓存读写数有则使用。成功的流若缺少这些数，记为不完整，而不是零用量。
- **授权待定时取消（`turn.ts`、`session.ts`）：**取消不再先等待未答复的授权再开始计时。到期限时强制结算，会话在后台释放，放弃等待授权。若宿主授权仍未答复，该回合以不完整用量上报，且不虚构 `request_end`；否则失败信息仍为 `cancel did not settle; the session was released`。已有取消的强制结算现在上报 `cancelled` 而非 `failed`，除非已记录失败。关闭已经释放的会话不再重复释放。
- **迟到的授权（`provider.ts`）：**取消之后、`settled` 之前到达的允许，会在 `settled` 之前记为一次已中止、完整、零 token 的请求。迟到的拒绝或授权错误记为没有请求。回合已结算或正在结算时发起的模型请求按已取消拒绝，不会发出。
- **错误类型（`turn.ts`）：**DSH 流错误码 `AUTH` 上报为 `PROVIDER_AUTH`，`RATE_LIMIT` 和 `SERVER` 上报为 `PROVIDER_UNAVAILABLE`，与 HTTP 状态 401/403、429、5xx 一致。
- **settled 前刷盘（`turn.ts`）：**会话在 `settled` 更新之前刷新到磁盘。刷盘失败时回合上报 `failed` 和 `INTERNAL_ERROR`（`session persistence flush failed`），而不是已完成。
- **测试（`tests/test_dsh_runner_requests.py`）：**新增测试覆盖终态用量计数、错误类型、结算与被杀后磁盘上的会话、授权待定时 cancel 和 close 的期限、迟到的允许/拒绝/错误，以及刷盘失败。
- **面向模型的变化：**无。提示、工具和模型请求都不变；被取消或失败的回合只在宿主侧带有不同的结果、错误类型和用量完整性字段。
