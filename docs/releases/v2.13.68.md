# Looper v2.13.68

## Release Decision

**Who should upgrade:** Dashboard users and anyone scripting the scenario Manager and task template HTTP routes. Dashboard users see no change. Scripts that call the removed routes must move to the `/api/v1/` routes.

**What this release solves:** [#487](https://github.com/foolzzz/looper/pull/487) moves scenario Manager definitions and Manager task templates to the versioned API (`/api/v1/`) as six operations with typed requests and results, reusing the existing Manager service and its checks. The six legacy methods for them are removed.

**Breaking changes:** Yes. The six legacy routes listed under Behavior changes no longer exist; a client that calls one gets a not-found answer. Stored Managers, templates, tasks, threads and bots are unchanged.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#487](https://github.com/foolzzz/looper/pull/487); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.68
```

## Behavior changes

- **Removed routes (breaking for API clients):** `GET /api/managers`, `POST /api/managers`, `PUT /api/managers/{id}`, `DELETE /api/managers/{id}`, `PUT /api/managers/{id}/templates/{key}` and `DELETE /api/managers/{id}/templates/{key}`.
- **Replacements:** `POST /api/v1/managers/list`, `managers/create`, `managers/update`, `managers/delete`, `manager_templates/put` and `manager_templates/delete`.
  - `managers.list` takes an empty object and returns `{managers, max_enabled}`; each Manager carries its task templates, `revision`, timestamps, live synchronization state (`ok` or `pending`, with the error) and spend.
  - `managers.create` takes `{key, name, system_prompt, ...}`; `managers.update` takes `{manager_id, fields}` with at least one field and does not accept a key; `managers.delete` takes `{manager_id}`.
  - `manager_templates.put` takes `{manager_id, key, name, ...}` and `manager_templates.delete` takes `{manager_id, key}`. Omitted template and input fields are still defaulted by the service.
  - Create and update return `{manager}`; delete and the template writes return `{managers, max_enabled}`.
- **Typed requests and results:** the six operations declare closed request schemas (unknown fields and wrong types are rejected at the API boundary) and typed Manager and template results.
- **Create status:** creating a Manager now answers 200 where the legacy route answered 201.
- **Authority and confirmation:** `managers.list` is a read. The five writes are high-risk operations. An API client must confirm in a second step, and the confirmation text describes the change; nothing is changed before it. The operator writes in one step and keeps the dashboard's existing confirmation. Writes still go through `managers_api` at execution, which re-checks project, profile and role-template references and permissions. The existing limits are unchanged.
- **Dashboard:** the Manager settings and template calls use the new routes. The prompt-regression dialogs seed their example Manager through them.
- **Documentation:** the Looper client skill RFC and the long-horizon context plan record the migration.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt changed, and no Manager Tool was added or changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.68 is published. No data migration. Update any script or client that called a removed route before upgrading. Rolling back to v2.13.67 restores the legacy routes, with no stored data affected.

## 中文摘要

### 升级决策

**谁需要升级：**仪表盘用户，以及脚本调用场景 Manager 与任务模板 HTTP 路由的人。仪表盘用户看不到变化；调用已删除路由的脚本需要改用 `/api/v1/` 路由。

**解决了什么：**[#487](https://github.com/foolzzz/looper/pull/487) 把场景 Manager 定义和 Manager 任务模板迁到版本化 API（`/api/v1/`），作为六个带类型化请求与结果的操作，复用现有 Manager 服务及其校验，并删除对应的六个旧方法。

**是否有破坏性变更：**是。“行为变化”中列出的六个旧路由不再存在，调用会得到 not found。已存的 Manager、模板、任务、线程和 bot 不变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.68。

**贡献者：**维护者 @foolzzz 提交 [#487](https://github.com/foolzzz/looper/pull/487)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.68
```

### 行为变化与入口

- **已删除的路由（对 API 客户端是破坏性的）：**`GET /api/managers`、`POST /api/managers`、`PUT /api/managers/{id}`、`DELETE /api/managers/{id}`、`PUT /api/managers/{id}/templates/{key}`、`DELETE /api/managers/{id}/templates/{key}`。
- **替代路由：**`POST /api/v1/managers/list`、`managers/create`、`managers/update`、`managers/delete`、`manager_templates/put`、`manager_templates/delete`。
  - `managers.list` 收空对象，返回 `{managers, max_enabled}`；每个 Manager 带任务模板、`revision`、时间戳、实时同步状态（`ok` 或 `pending`，含错误）和花费。
  - `managers.create` 收 `{key, name, system_prompt, ...}`；`managers.update` 收 `{manager_id, fields}`，至少一个字段，不接受 key；`managers.delete` 收 `{manager_id}`。
  - `manager_templates.put` 收 `{manager_id, key, name, ...}`，`manager_templates.delete` 收 `{manager_id, key}`；省略的模板和输入字段仍由服务补默认值。
  - 创建和更新返回 `{manager}`；删除和模板写返回 `{managers, max_enabled}`。
- **类型化请求与结果：**六个操作声明了封闭的请求 schema（在 API 边界拒绝未知字段和错误类型），以及 Manager 与模板的类型化结果。
- **创建状态码：**创建 Manager 现在返回 200，旧路由为 201。
- **权限与确认：**`managers.list` 为只读。五个写操作为 high 风险。API 客户端须两步确认，确认文本说明变更内容，确认前不改动任何数据；操作者单次写入，保留仪表盘既有确认框。执行时仍经 `managers_api` 重新校验项目、Profile、角色模板引用与权限，既有限制不变。
- **仪表盘：**Manager 设置与模板调用改用新路由；prompt 回归对话用它们种入示例 Manager。
- **文档：**Looper 客户端 skill RFC 与长程上下文计划记录了此次迁移。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 均未改动，未新增或修改 Manager Tool。

### 升级与回退

v2.13.68 发布后重跑 `install.sh`。无需迁移数据。升级前请更新调用已删除路由的脚本或客户端。回退到 v2.13.67 会恢复旧路由，不影响已存数据。
