# Looper v2.14.41

This is the patch release v2.14.41, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.40: `looper service status` uses the unit's address, and the probe units stay consistent ([#992](https://github.com/foolzzz/looper/pull/992)).

## Release Decision

**Who should upgrade:** Anyone who runs v2.14.40 or earlier as a managed service with `server.host = "::"`, or who uses the service probe (`[probe]` in the ops file) and installs, restarts or uninstalls the service.

**What this release solves:** [#992](https://github.com/foolzzz/looper/pull/992) makes `looper service status` and the install and restart reports dial and print the address the unit actually listens on (`[::1]` for `::`). It also keeps the probe units consistent on Linux: a reinstall stops a running probe first, uninstall removes the server unit even when probe cleanup fails, and a failed probe update restores the previous probe instead of deleting it.

**Breaking changes:** No. No API or configuration is removed, and there is no new migration or setting. The text of some service reports and error messages changes: see "Behavior changes".

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#992](https://github.com/foolzzz/looper/pull/992); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.41
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.40 upgrades directly. This release adds no migration and no new setting.

## Behavior changes

- **Address in status and reports ([#992](https://github.com/foolzzz/looper/pull/992)).** `looper service status` reads the ops file for `server.host` and queries the status API at the matching loopback address (`127.0.0.1` for an empty host, `localhost` or `0.0.0.0`; `::1` for `::`; otherwise the host itself). The `api` line, the `serving` line of `looper service install` and the `serving` text of `looper service restart` print that address; an IPv6 address is bracketed (`http://[::1]:<port>`). If the ops file cannot be read, status falls back to `127.0.0.1`.
- **Probe reinstall (Linux).** `install_probe_units` stops the probe timer and service, and waits until they are inactive, when a probe unit file already exists, before it rewrites them. If the stop cannot be confirmed within the wait limit it raises "cannot confirm ... stopped ...; probe units were kept".
- **Probe removal (Linux).** When the probe unit files are already gone, removal still runs `disable --now` on the timer and `stop` on the service by name, so a probe that is still loaded is stopped.
- **Failed probe update.** `_install_probe` (used by install and restart) first snapshots the existing probe unit files. If writing or starting the new probe fails, it deletes any new file, rewrites the old files and starts the old probe again (launchd start on macOS; `daemon-reload` and `enable --now` on Linux), and reports "failed to update: <reason>; kept the previous probe". If restoring fails too, the report says "restoring it failed: <error>". If the snapshot cannot be read, nothing is changed and the report says "kept the previous probe". With no previous probe, the previous behavior (remove the new units) is unchanged.
- **Uninstall.** `looper service uninstall` removes the server unit even when probe cleanup raises a service error. It then raises "uninstalled <label>; probe cleanup failed: <error>; run uninstall again", so the command exits with an error although the server unit is gone. When nothing else is installed and probe cleanup failed, it no longer reports "is not installed".
- **Model-visible changes:** None found. No prompt, skill or tool description changes; the changed text is service command output.

### 行为变化与入口

- **状态与报告中的地址（[#992](https://github.com/foolzzz/looper/pull/992)）。**`looper service status` 读取 ops 文件中的 `server.host`，用对应的回环地址查询状态 API（空、`localhost`、`0.0.0.0` 用 `127.0.0.1`；`::` 用 `::1`；其他则用该主机本身）。`api` 行、`looper service install` 的 `serving` 行和 `looper service restart` 的 `serving` 文本都打印该地址；IPv6 地址加方括号（`http://[::1]:<port>`）。若 ops 文件无法读取，status 回退到 `127.0.0.1`。
- **probe 重装（Linux）。**已存在 probe unit 文件时，`install_probe_units` 会先停止 probe 的 timer 和 service 并等待其变为 inactive，再重写文件；若在等待上限内无法确认已停止，则报错“cannot confirm ... stopped ...; probe units were kept”。
- **probe 移除（Linux）。**probe unit 文件已不存在时，移除仍会按名称对 timer 执行 `disable --now`、对 service 执行 `stop`，因此仍处于加载状态的 probe 会被停止。
- **probe 更新失败。**`_install_probe`（安装与重启使用）先对现有 probe unit 文件做快照。若写入或启动新 probe 失败，则删除新文件、写回旧文件并重新启动旧 probe（macOS 用 launchd start；Linux 用 `daemon-reload` 与 `enable --now`），报告“failed to update: <原因>; kept the previous probe”。若恢复也失败，报告“restoring it failed: <错误>”。若快照无法读取，则不做任何改动，报告“kept the previous probe”。没有旧 probe 时，原有行为（移除新 unit）不变。
- **卸载。**`looper service uninstall` 即使 probe 清理抛出服务错误，也会删除服务 unit，随后抛出“uninstalled <label>; probe cleanup failed: <错误>; run uninstall again”，因此命令虽然退出码为错误，但服务 unit 已删除。其余均未安装而 probe 清理失败时，不再报告“is not installed”。
- **面向模型的变化：**未发现。提示词、技能和工具描述均不变；变化的文字是服务命令的输出。
