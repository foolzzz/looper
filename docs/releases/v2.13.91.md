# Looper v2.13.91

## Release Decision

**Who should upgrade:** Anyone who calls the task list or task detail routes, or the scheduler, wait or knowledge-vault settings routes, from a script. Everyone else gets no change.

**What this release solves:** [#532](https://github.com/foolzzz/looper/pull/532) moves the task list and the full task detail onto versioned API operations. [#549](https://github.com/foolzzz/looper/pull/549) does the same for the scheduler, wait and knowledge-vault Settings. Both remove their legacy routes.

**Breaking changes:** Yes. `GET /api/tasks`, `GET /api/tasks/{id}`, and `GET` and `PUT` on `/api/scheduler-settings`, `/api/wait-settings` and `/api/knowledge-vault` are removed. A script must use `POST /api/v1/tasks/page` (filters in the body), `POST /api/v1/tasks/detail` (`task_id` in the body), `POST /api/v1/scheduler_settings/get` and `/update`, `POST /api/v1/wait_settings/get` and `/update`, or `POST /api/v1/knowledge_vault/get` and `/update`, and read the answer from the v1 envelope (`result`). Errors come in the v1 error shape. A settings update from a client token now asks for confirmation. The dashboard shipped in this release already uses the new operations.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#532](https://github.com/foolzzz/looper/pull/532) and [#549](https://github.com/foolzzz/looper/pull/549); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.91
```

## Behavior changes

- **Task views ([#532](https://github.com/foolzzz/looper/pull/532)):** the new `looper/agents/v1_domains/task_views.py` registers `tasks.page` and `tasks.detail` (risk `read`) as `POST /api/v1/tasks/page` and `/detail`, with closed argument schemas and typed results. `page` takes optional `project_id`, `schedule_id`, `group`, `status`, `before`, `limit` (1 to 200) and `query`, and returns `{tasks, counts, next_before}`; `detail` takes `{task_id}`. They call the same `projects.list_tasks_page` and `projects.task_detail` as the removed routes. The page-size constants moved from `http_server.py` to `looper/agents/projects.py`.
- **Task search:** `query` is new on the task page. `looper/db/tasks.py` matches it as a literal, case-insensitive substring of the id, title, requirement, project name and goal (whitespace collapsed, `%` and `_` not wildcards), before paging, and `count_by_status` applies it too, so the status counts follow the search. The Manager's compact task listing is unchanged.
- **Task routes removed:** `GET /api/tasks`, `GET /api/tasks/{id}` and their handlers are removed from `looper/agents/http_server.py`. A bad `group`, `status` or `limit` is now refused by the operation schema instead of by the old 400 messages.
- **Settings pages ([#549](https://github.com/foolzzz/looper/pull/549)):** the new `looper/agents/v1_domains/settings_pages.py` registers `scheduler_settings.get`, `wait_settings.get` and `knowledge_vault.get` (risk `read`) and `scheduler_settings.update`, `wait_settings.update` and `knowledge_vault.update` (risk `high`, can need confirmation) as `POST /api/v1/...`. The updates take the same bodies as the removed `PUT` routes (`null` restores a fallback; a null vault `path` clears it), have closed schemas, and recheck the filesystem and current limits at execution, also after a client confirms. Their impact is computed with the same confirmation helper as the Manager's `looper_settings` action. The compact `settings.*` results are now typed in the OpenAPI document.
- **Settings routes removed:** the six legacy routes, `schedules.scheduler_settings` and the unused imports are removed from `looper/agents/http_server.py` and `looper/agents/schedules.py`.
- **Dashboard:** `web/src/lib/api.ts` fetches tasks and details and reads and saves scheduler, wait and vault settings through the new operations; a pending confirmation (HTTP 202) is raised as an `unavailable` error, and for task detail as a `TaskDetailError`.
- **Tooling and docs:** the prompt regression evals (`evals/prompt_regression/dialogs.py`, `runner.py`), `examples/dsh/validate.py` and `examples/pi/isolated-smoke.py` use the new operations; `docs/architecture/agent-system.md` and two RFC notes name them.
- **Tests:** `tests/test_api_v1_task_views.py`, `tests/test_api_v1_task_views_db.py`, `tests/test_api_v1_settings_pages.py`, `tests/test_api_v1_settings_pages_db.py`, `web/src/lib/task-views.test.ts` and `web/src/lib/api-settings-pages.test.ts` were added; many existing tests were moved to the new operations.
- **Model-visible changes:** none found. The diff of [#532](https://github.com/foolzzz/looper/pull/532) and [#549](https://github.com/foolzzz/looper/pull/549) touches no Manager, Planner, Worker or Reviewer prompt, role recommended prompt or Tool declaration. The six new operations appear in the v1 operation catalog.
- **Not confirmed in code:** whether client tokens are meant to read task details through `tasks.detail` (it is `read` risk and not operator-only, as the removed route was reachable by the dashboard); and `settings_pages.py` does not mark the settings operations operator-only, although [#549](https://github.com/foolzzz/looper/pull/549) names operator-only boundaries in its goal; the architecture note says clients confirm. This draft did not run any test.

## Upgrade and rollback

Re-run `install.sh` once v2.13.91 is published. No data migration; saved settings and tasks are untouched. Update any script that used the removed routes. Rolling back to v2.13.90 restores them together with the old dashboard.

### 升级决策

**谁需要升级：**在脚本中调用任务列表、任务详情，或调度器、等待、知识库设置路由的人。其他人无变化。

**解决了什么：**[#532](https://github.com/foolzzz/looper/pull/532) 把任务列表和完整任务详情迁到版本化 API；[#549](https://github.com/foolzzz/looper/pull/549) 对调度器、等待和知识库设置做同样的迁移。两者都删除旧路由。

**是否有破坏性变更：**有。`GET /api/tasks`、`GET /api/tasks/{id}`，以及 `/api/scheduler-settings`、`/api/wait-settings`、`/api/knowledge-vault` 的 `GET` 和 `PUT` 已移除；脚本须改用 `POST /api/v1/tasks/page`（筛选条件放请求体）、`POST /api/v1/tasks/detail`（请求体传 `task_id`）、`POST /api/v1/scheduler_settings/get` 与 `/update`、`POST /api/v1/wait_settings/get` 与 `/update`、`POST /api/v1/knowledge_vault/get` 与 `/update`，并从 v1 信封（`result`）读取结果。错误使用 v1 错误格式。client token 发起的设置更新现在需要确认。本版本附带的仪表盘已改用新操作。

**如何验证：**运行 `looper --version` 核对版本为 2.13.91。

**贡献者：**维护者 @foolzzz 提交 [#532](https://github.com/foolzzz/looper/pull/532) 和 [#549](https://github.com/foolzzz/looper/pull/549)；本次 patch release 无社区贡献。

### 行为变化与入口

- **任务视图（[#532](https://github.com/foolzzz/looper/pull/532)）：**新增 `looper/agents/v1_domains/task_views.py`，注册 `tasks.page`、`tasks.detail`（风险 `read`），路径为 `POST /api/v1/tasks/page` 与 `/detail`，参数为封闭对象，结果有类型。`page` 接受可选的 `project_id`、`schedule_id`、`group`、`status`、`before`、`limit`（1 到 200）和 `query`，返回 `{tasks, counts, next_before}`；`detail` 传 `{task_id}`。它们调用与被移除路由相同的 `projects.list_tasks_page` 和 `projects.task_detail`。分页常量从 `http_server.py` 移到 `looper/agents/projects.py`。
- **任务搜索：**`query` 是任务分页的新参数。`looper/db/tasks.py` 在分页前，把它作为字面子串（不区分大小写，空白合并，`%` 与 `_` 不是通配符）匹配任务 id、标题、需求、项目名和目标；`count_by_status` 同样应用，因此状态计数随搜索变化。Manager 的紧凑任务列表不变。
- **移除任务路由：**`GET /api/tasks`、`GET /api/tasks/{id}` 及其处理函数已从 `looper/agents/http_server.py` 移除。无效的 `group`、`status`、`limit` 现在由操作的 schema 拒绝，不再返回旧的 400 文案。
- **设置页（[#549](https://github.com/foolzzz/looper/pull/549)）：**新增 `looper/agents/v1_domains/settings_pages.py`，注册 `scheduler_settings.get`、`wait_settings.get`、`knowledge_vault.get`（风险 `read`）和 `scheduler_settings.update`、`wait_settings.update`、`knowledge_vault.update`（风险 `high`，可能需要确认），路径为 `POST /api/v1/...`。更新使用与被移除 `PUT` 路由相同的请求体（`null` 恢复回退值；知识库 `path` 为 null 即清除），schema 封闭，并在执行时重新检查文件系统和当前限制，client 确认之后也一样。影响判断与 Manager 的 `looper_settings` 动作共用同一个确认辅助函数。紧凑的 `settings.*` 结果现在在 OpenAPI 文档中有类型。
- **移除设置路由：**六条旧路由、`schedules.scheduler_settings` 以及不再使用的导入已从 `looper/agents/http_server.py` 和 `looper/agents/schedules.py` 移除。
- **仪表盘：**`web/src/lib/api.ts` 通过新操作获取任务与详情，读取并保存调度器、等待和知识库设置；待确认应答（HTTP 202）作为 `unavailable` 错误抛出，任务详情则抛出 `TaskDetailError`。
- **工具与文档：**提示回归评测（`evals/prompt_regression/dialogs.py`、`runner.py`）、`examples/dsh/validate.py`、`examples/pi/isolated-smoke.py` 改用新操作；`docs/architecture/agent-system.md` 与两份 RFC 说明已改为新操作。
- **测试：**新增 `tests/test_api_v1_task_views.py`、`tests/test_api_v1_task_views_db.py`、`tests/test_api_v1_settings_pages.py`、`tests/test_api_v1_settings_pages_db.py`、`web/src/lib/task-views.test.ts` 与 `web/src/lib/api-settings-pages.test.ts`；许多现有测试已改用新操作。
- **面向模型的变化：**未发现。[#532](https://github.com/foolzzz/looper/pull/532) 与 [#549](https://github.com/foolzzz/looper/pull/549) 的改动未触及 Manager、Planner、Worker、Reviewer 的 prompt、角色推荐 prompt 或 Tool 声明。六个新操作出现在 v1 操作目录中。
- **代码中未确认：**client token 是否应通过 `tasks.detail` 读取任务详情（它是 `read` 风险且未限定 operator-only，旧路由也可被仪表盘访问）；`settings_pages.py` 未把设置操作标为 operator-only，而 [#549](https://github.com/foolzzz/looper/pull/549) 的描述提到操作员边界，架构文档则写明 client 需确认。本草稿未运行任何测试。
