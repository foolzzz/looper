# Looper v2.14.72

This is the patch release v2.14.72, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.71: a prompt blocked by an organization's hook now fails the turn at once, with that reason ([#1070](https://github.com/foolzzz/looper/pull/1070)).

## Release Decision

**Who should upgrade:** Installations that run Claude Code under an organization policy with a `UserPromptSubmit` hook that can block prompts. Others see no change.

**What this release solves:** when such a hook blocked a prompt, Claude Code emitted a system informational event and no answer, and Looper spent a repair turn and then reported a misleading "no json fenced block" error. [#1070](https://github.com/foolzzz/looper/pull/1070) recognizes the event and fails the turn at once with the hook's reason.

**Breaking changes:** No. Only the failure path of a blocked prompt changes, and there is no migration.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#1070](https://github.com/foolzzz/looper/pull/1070); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.72
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.71 upgrades directly. This release adds no migration.

## Behavior changes

- **Blocked prompt recognized.** A system event of subtype `informational` whose content starts with `UserPromptSubmit operation blocked by hook:` is read as a blocked prompt (`prompt_block` in `looper/agents/claude_cli.py`). Tool-hook failures and assistant text that merely quotes the phrase are not matched. The reason is the text after the prefix, cut before any `Original prompt:` line and clipped to 300 characters, or "no reason given".
- **The turn fails at once.** A resident Claude turn raises the new `TurnBlocked` error even before Claude has emitted `started`, init or a replay, and the Claude process is stopped. A Worker run ends as failed with the same error and a `prompt_blocked` entry (`reason`, `work_dir`) in its result, and records an error activity on its parent task. The error message reads that Claude Code's hook blocked the prompt in the directory, gives the reason, and says this is the organization's policy, not a Looper error, to run the project from a directory the policy allows.
- **Manager.** The turn is recorded as failed with that message and an error activity is written on its task. Its handoff-reading turn records the failure and re-raises, instead of the "wrote no handoff" warning path.
- **Planner.** A blocked step or verify run marks the step failed and fails the plan with the reason. `_fail_plan` gains `model_closeout`; a hook block skips the model-written vault closeout, and a block raised inside a closeout is no longer swallowed as a warning.
- **Prompt echo dropped.** Because hooks can echo the whole input, the event's content is replaced by `UserPromptSubmit operation blocked by hook: <reason>` before it reaches callbacks or run records (`stream_events`).
- **Cancellation.** If a deadline cancels the cleanup of a blocked turn, the block still surfaces.
- **Size:** per the pull request description, 88 added lines of production code and 231 of tests (fixtures excluded).
- **Model-visible changes:** No. No prompt or tool description changed; a blocked turn gets no model reply and the echoed prompt is removed from the event. The new error text appears in run records and activity, not in a prompt.

### 升级决策

**谁需要升级：**在带有可拦截提示的 `UserPromptSubmit` hook 的组织策略下运行 Claude Code 的安装。其他安装没有变化。

**解决了什么：**此类 hook 拦截提示时，Claude Code 只发出一个系统 informational 事件而没有回答，Looper 会多花一个修复回合，然后报出误导性的 “no json fenced block” 错误。[#1070](https://github.com/foolzzz/looper/pull/1070) 识别该事件，立即以 hook 给出的原因使回合失败。

**是否有破坏性变更：**否。只有被拦截提示的失败路径变化，没有迁移。

**如何验证：**运行 `looper --version` 核对版本为 2.14.72。

**贡献者：**维护者 @foolzzz 提交 [#1070](https://github.com/foolzzz/looper/pull/1070)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.72
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.71 上的安装可直接升级。本版本没有迁移。

### 行为变化与入口

- **识别被拦截的提示。**subtype 为 `informational`、内容以 `UserPromptSubmit operation blocked by hook:` 开头的系统事件被视为提示被拦截（`looper/agents/claude_cli.py` 的 `prompt_block`）。工具 hook 的失败和仅引用该短语的助手文本不会匹配。原因取前缀之后的文本，在 `Original prompt:` 行之前截断并限制为 300 个字符，没有时为 “no reason given”。
- **回合立即失败。**常驻 Claude 回合即使在 Claude 发出 `started`、init 或回放之前，也会抛出新的 `TurnBlocked` 错误，并停止 Claude 进程。Worker 运行以失败结束，结果带 `prompt_blocked`（`reason`、`work_dir`），并在其父任务上记录错误活动。错误信息说明 Claude Code 的 hook 在该目录拦截了提示，给出原因，并说明这是组织策略而非 Looper 错误，应在策略允许的目录运行项目。
- **Manager。**该回合记为失败并带上述信息，并在其任务上写入错误活动。读取交接的回合记录失败并重新抛出，不再走 “wrote no handoff” 的警告路径。
- **Planner。**被拦截的步骤或验证运行把步骤标为失败，并以该原因使计划失败。`_fail_plan` 新增 `model_closeout`；hook 拦截时跳过由模型写的 vault 收尾，收尾中抛出的拦截也不再被当作警告吞掉。
- **丢弃提示回显。**hook 可能回显完整输入，因此事件内容在到达回调或运行记录前被替换为 `UserPromptSubmit operation blocked by hook: <reason>`（`stream_events`）。
- **取消。**被拦截回合的清理若被截止时间取消，拦截结果仍会抛出。
- **规模：**据 PR 描述，生产代码新增 88 行，测试新增 231 行（不含 fixture）。
- **面向模型的变化：**无。没有提示或工具说明变化；被拦截的回合没有模型回复，回显的提示从事件中移除。新的错误文本出现在运行记录和活动中，不在提示里。
