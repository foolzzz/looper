# Looper v2.14.2

This is the patch release v2.14.2. It ships the one change merged since v2.14.1: [#870](https://github.com/foolzzz/looper/pull/870), DSH runner `session/new`, `session/load` and `session/close`, which no running code uses yet.

## Release Decision

**Who should upgrade:** Operators on v2.14.1 who want the current main line, and developers who continue the DSH runner work. Nothing an operator can see changes. It ships the one change merged since v2.14.1.

**What this release solves:** [#870](https://github.com/foolzzz/looper/pull/870) adds session management to the packaged DSH runner: open, resume and close sessions, each with its own DeepSeek route and tool allowlist. The runner is still not registered as a runtime, has no setting and has no entry in the Dashboard, Telegram, Lark or CLI.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#870](https://github.com/foolzzz/looper/pull/870); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.2
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 or v2.14.1 upgrades directly. This release changes no schema, configuration format or stored data.

## Behavior changes

- **Session methods (`runners/dsh/src/session.ts`, `runners/dsh/src/main.ts`):** the DSH runner now serves `session/new`, `session/load` and `session/close`, and `runner/health` reports the number of open sessions instead of zero.
  - Parameters are validated before any SDK work and a bad value fails with `-32602`. A session needs a valid `session_key` (letters, digits, `_`, `-`), a role of `manager`, `planner`, `worker` or `reviewer`, absolute directories, an environment map, an `anthropic-messages` provider (base URL, model, API key, account id, effort `null`, `low`, `high` or `max`, optional context window), a prompt, tools with `read` among the built-ins, and positive limits.
  - A prompt mode other than `append`, or a read-only session that enables `write`, `edit` or `bash`, fails with `-32008`. Platform tools and `fork_from` fail with `-32007`.
  - Admission: a session key or session id already owned fails with `-32002`; more than 20 sessions fails with `-32006`.
  - Each session creates (or, for `session/load`, resumes) one DSH agent with its own DeepSeek route named `looper-<session_key>`. The API key is registered as a secret to scrub and lives only in the route's closure in memory. The configured model is kept for budget and pricing; the model sent to the provider drops a trailing `[1m]`.
  - The tool set is restricted to the requested built-ins (`bash` is not offered through the restriction) and a guard refuses any tool outside the allowlist, so a read-only session sees and runs only `read`, `glob` and `grep`.
  - Resume works across runner restarts through the runner's state root. A saved session from another directory, an unknown id and a corrupt or unsupported saved session fail with `-32001`. A failed `session/new` removes the stored session it may have created.
  - `session/close` disposes the agent and route, and deletes the stored session when it was ephemeral (its state directory is under the runner's own `sessions` directory); other sessions are kept for later resume.
  - Shutdown closes the open sessions in parallel, waiting up to 3 seconds for each, then flushes persistence and disposes the context.
- **SDK helper (`runners/dsh/src/sdk.ts`):** exports the launch `environment` snapshot used by the routes. The shutdown hook that disposed the context moved into the session module's ordered shutdown.
- **Tests and plan (`tests/test_dsh_runner_sessions.py`, `tests/dsh_runner_support.py`, `tests/test_dsh_runner.py`, `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`):** new session tests; the skeleton test no longer expects `session/new` to be unknown; the plan entry records the sessions and what is still missing (model requests, bash and path checks, platform tools, steer and fork).
- **Model-visible changes:** None for a running system, because the DSH runner is not reachable from any runtime. Once a host opens a session, the model sees the host's prompt text as a literal appended `looper` section and only the allowed built-in tools.

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次，步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 或 v2.14.1 上的安装可直接升级。本版本不改 schema、配置格式或已存数据。

### 行为变化与入口

- **会话方法（`runners/dsh/src/session.ts`、`runners/dsh/src/main.ts`）：**DSH runner 现提供 `session/new`、`session/load` 和 `session/close`，`runner/health` 报告打开的会话数而不再恒为零。
  - 在任何 SDK 工作之前先校验参数，非法值以 `-32602` 失败。会话需要合法的 `session_key`（字母、数字、`_`、`-`）、`manager`/`planner`/`worker`/`reviewer` 之一的角色、绝对目录、环境变量表、`anthropic-messages` provider（base URL、模型、API key、account id，effort 为 `null`、`low`、`high` 或 `max`，可选上下文窗口）、提示词、内置工具中含 `read` 的工具设置，以及正数限制。
  - 提示词模式不是 `append`，或只读会话启用 `write`、`edit`、`bash`，以 `-32008` 失败；平台工具和 `fork_from` 以 `-32007` 失败。
  - 准入：session key 或 session id 已被占用返回 `-32002`；超过 20 个会话返回 `-32006`。
  - 每个会话创建（`session/load` 则恢复）一个 DSH agent，使用名为 `looper-<session_key>` 的独立 DeepSeek 路由。API key 登记为需要擦除的密钥，只存在于路由闭包的内存中。预算和计价沿用配置的模型名；发给 provider 的模型名去掉末尾的 `[1m]`。
  - 工具集限制为请求的内置工具（限制中不提供 `bash`），守卫拒绝白名单之外的工具，因此只读会话只能看到并执行 `read`、`glob` 和 `grep`。
  - 会话经 runner 的状态根目录持久化，runner 重启后可恢复。保存的会话属于另一目录、id 未知，或已损坏/格式不支持，均以 `-32001` 失败。`session/new` 失败时会清理它可能已写入的存储。
  - `session/close` 释放 agent 和路由；临时会话（状态目录在 runner 自己的 `sessions` 目录下）同时删除存储，其他会话保留以便之后恢复。
  - 退出时并行关闭所有打开的会话，每个最多等 3 秒，然后刷新持久化并释放上下文。
- **SDK 辅助（`runners/dsh/src/sdk.ts`）：**导出路由使用的启动环境快照 `environment`。原先释放上下文的退出钩子并入会话模块的有序退出。
- **测试与计划（`tests/test_dsh_runner_sessions.py`、`tests/dsh_runner_support.py`、`tests/test_dsh_runner.py`、`docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`）：**新增会话测试；骨架测试不再把 `session/new` 当作未知方法；计划文档记录会话及仍缺的部分（模型请求、bash 与路径检查、平台工具、steer 与 fork）。
- **面向模型的变化：**对运行中的系统无，因为任何运行时都无法到达 DSH runner。宿主一旦打开会话，模型会看到宿主提示词作为字面追加的 `looper` 段，以及仅限允许的内置工具。
