# Looper v2.13.45

## Release Decision

**Who should upgrade:** Anyone who wants a coding agent in another session, or a script, to hand work to a Looper Manager and follow its tasks through one documented API. Everyone else can stay on v2.13.44: the dashboard and the existing channels behave as before.

**What this release solves:** [#411](https://github.com/foolzzz/looper/pull/411) adds an OpenAPI-described API (`/api/v1`) with API clients (tokens made in Settings), the `loopercli` command (a pure OpenAPI client with generated commands and a `chat` command that talks to a Manager) and `looper-skill` (a skill, also a Claude Code plugin, that teaches an agent to use only `loopercli`). It is stage 1 of the client-skill RFC.

**Breaking changes:** No. The additions are new routes, a new table and columns added with `IF NOT EXISTS`, and a new command. Existing routes, channels and the dashboard are unchanged.

**How to verify:** Check the installed version and that the new command is present.

**Contributors:** Maintainer @foolzzz authored [#411](https://github.com/foolzzz/looper/pull/411); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.45
loopercli --version
loopercli skill show | head -5
```

## Behavior changes

- **New API (`looper/agents/api_v1.py`, `http_server.py`):** `GET /api/v1/openapi.json` (the OpenAPI document, generated from the ops catalog), `GET /api/v1/whoami`, `POST /api/v1/ops/<tool>/<action>` (one operation per ops tool action), `POST /api/v1/confirm`, and the chat operations `POST /api/v1/chat/send` (a server-sent event stream), `/chat/messages` and `/chat/conversations`. A write of risk `high` answers 202 with a `confirmation_id`; `confirm` runs it only for the same client and session (`X-Looper-Session`) within 10 minutes, and pending confirmations are kept in memory.
- **Authentication (`operator_auth.py`):** the `/api/v1/` path is a new access class. It answers the operator or an API client, and a client token is accepted only from a loopback peer with a loopback `Host`. A client token is refused on every other `/api/` path, and never yields an operator session or cookie.
- **API clients:** Settings → API clients and the operator-only routes `GET` and `POST /api/clients` and `DELETE /api/clients/:id`. A token (`lpc_…`) is shown once and only its SHA-256 is stored; a revoked client keeps its row and its token stops working at once.
- **Client calls (`ops/clients.py`):** a client has the Manager's tools except `looper_task_gate_reply` and the confirmation tool, plus two of its own, `looper_task_pipeline` and `looper_gates`. A write runs at once as the operator's own request; reads are not recorded. An unexpected failure is recorded in the trail as an error.
- **Attribution and storage:** `schema.sql` adds the table `api_clients` and a nullable `client_id` on `chat_threads`, `tasks` and `manager_actions`. A task's `via` reads `client:<name>` for a call made through the API and `manager:loopercli` for one the Manager made in a client conversation; the task page names the client. A conversation belongs to its client and Manager: another client, or the same id on another Manager, finds it unknown.
- **Task reports:** a task created in an API client's conversation reports its acceptance and end into that conversation (`origin_thread`), for the default Manager too. The dashboard's own default-Manager chat keeps its channel's path.
- **`loopercli` (new console script):** each operation of the OpenAPI document becomes a command at run time; `login`, `confirm`, `chat`, `wait` and `skill` are written by hand, with the aliases `list`, `status`, `pipeline`, `start` and `stop`. It keeps its token and URL in a private client file (mode 0600, loopback URL only), reads the token from stdin or a prompt and never from an argument, never follows a redirect, and redacts a token from usage errors. Exit codes: 0 done, 1 error, 2 usage, 3 needs confirmation, 4 unreachable, 6 `wait` timed out.
- **Skill and plugin:** `looper/skill/looper-skill/SKILL.md` ships in the wheel (`pyproject.toml` package data and the `loopercli` entry point); a Claude Code plugin (`plugins/looper`, `.claude-plugin/marketplace.json`) carries the same copy. Looper never writes into another tool's directories.
- **Dashboard:** a Settings page for API clients and the client's name on the task page (`web/`).
- **Docs and evals:** `docs/architecture/agent-system.md`, the RFC `docs/architecture/rfcs/looper-client-skill.zh-CN.md`, and new dialogs in `evals/prompt_regression`.
- **Model-visible changes:** a Manager message that comes through a client carries the line `Channel: loopercli, client "<name>" (the user works in their own coding agent, which writes these messages for them)`, set only from a verified token. No other prompt text changed. The client's tool list is the Manager's catalog less two tools plus two new ones, with schemas generated from the same catalog. `looper-skill` is new text that an agent reads: it lets the agent confirm creating and starting a task, editing its requirement and answering its gates once the user has said to submit, and tells it to relay cancels, deletes and settings changes to the user first.

## Upgrade and rollback

Re-run `install.sh` once v2.13.45 is published. The schema additions are `CREATE TABLE IF NOT EXISTS` and `ADD COLUMN IF NOT EXISTS` and need no data migration. To use the new surface, create a client in Settings → API clients and run `loopercli login`. Rolling back to v2.13.44 needs no step: the older program ignores the table and the columns, and the stored client tokens are not used.

## Optional Capability Activation & Use

### API clients

**Activation:** Off until the operator creates one in Settings → API clients (or `POST /api/clients`). Without a client, `/api/v1` answers only the operator.

**Validation:** `GET /api/clients` lists the client without its token. `loopercli whoami` answers as the client.

**Disable / rollback:** Revoke the client in Settings or with `DELETE /api/clients/:id`; its token stops working at once.

**Authority boundary:** A client can run the Manager's tools through `/api/v1`, with writes running at once and high-risk ones confirmed per client and session. It is accepted only from a loopback peer, cannot manage the operator password or other clients, and gets no operator session.

**Docs:** [Agent system: the public API (v1)](https://github.com/foolzzz/looper/blob/v2.13.45/docs/architecture/agent-system.md#the-public-api-v1).

```bash
loopercli whoami                       # answers as the client
loopercli --json agent-profiles list    # an operation through /api/v1
```

### loopercli

**Activation:** Run `loopercli login` after creating an API client; it reads the token from stdin or a prompt.

**Validation:** `loopercli whoami`; `loopercli chat "text"` talks to the default Manager and prints the conversation id on stderr.

**Disable / rollback:** Remove the client file `loopercli login` wrote, or revoke the client.

**Authority boundary:** It sends the token only to its loopback URL and never follows a redirect. What it may do is what its client may do.

**Docs:** [loopercli and looper-skill](https://github.com/foolzzz/looper/blob/v2.13.45/docs/architecture/agent-system.md#loopercli-and-looper-skill).

```bash
loopercli login                        # token from stdin or a prompt
loopercli chat --list         # list your conversations
```

### looper-skill and the Claude Code plugin

**Activation:** Install the plugin as described in `plugins/looper/README.md`, or point Codex or OMP at the directory `loopercli skill path` prints.

**Validation:** `loopercli skill show` prints the skill; in the agent, ask it to hand work to Looper and check that it runs `loopercli whoami` first.

**Disable / rollback:** Uninstall the plugin or remove the copied skill.

**Authority boundary:** The skill is instructions to an agent, not a permission. It tells the agent to confirm on the user's behalf only what the user authorised in that session (create and start, edit the requirement, answer gates) and to relay cancels, deletes and settings changes to the user. The server does not enforce that split; the client's token does what the client may do.

**Docs:** [plugins/looper/README.md](https://github.com/foolzzz/looper/blob/v2.13.45/plugins/looper/README.md).

```bash
loopercli skill path
loopercli skill show | head -5
```

## 中文摘要

### 升级决策

**谁需要升级：**希望让其他会话中的编码 agent 或脚本，通过一套有文档的 API 把工作交给 Looper 管家并跟进任务的人。其他人可留在 v2.13.44：控制台和现有渠道行为不变。

**解决了什么：**[#411](https://github.com/foolzzz/looper/pull/411) 新增带 OpenAPI 描述的 API（`/api/v1`）、API 客户端（在设置中创建令牌）、`loopercli` 命令（纯 OpenAPI 客户端，命令由文档生成，`chat` 可与管家对话）和 `looper-skill`（也是 Claude Code 插件，教 agent 只用 `loopercli`）。这是 client-skill RFC 的第一阶段。

**是否有破坏性变更：**无。新增的是路由、一张新表和用 `IF NOT EXISTS` 添加的列，以及一个新命令；现有路由、渠道和控制台不变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.45，并确认 `loopercli` 可用。

**贡献者：**维护者 @foolzzz 提交 [#411](https://github.com/foolzzz/looper/pull/411)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.45
loopercli --version
loopercli skill show | head -5
```

### 行为变化与入口

- 新 API：`GET /api/v1/openapi.json`、`whoami`、`POST /api/v1/ops/<tool>/<action>`、`confirm`，以及聊天操作 `chat/send`（服务端事件流）、`chat/messages`、`chat/conversations`。高风险写操作返回 202 和 `confirmation_id`，只有同一客户端、同一会话（`X-Looper-Session`）在 10 分钟内 `confirm` 才执行；待确认项只存在内存中。
- 认证：`/api/v1/` 是新的访问类别，接受操作者或 API 客户端；客户端令牌只被来自回环地址且 `Host` 为回环的请求接受，在其他 `/api/` 路径上一律被拒，也不会换来操作者会话或 cookie。
- API 客户端：设置 → API 客户端，以及仅限操作者的 `GET`/`POST /api/clients` 和 `DELETE /api/clients/:id`。令牌（`lpc_…`）只显示一次，只存 SHA-256；吊销后保留记录，令牌立即失效。
- 客户端调用：客户端拥有管家的工具，但没有 `looper_task_gate_reply` 和确认工具，另有 `looper_task_pipeline` 与 `looper_gates`。写操作立即执行，读操作不记录；意外失败在审计中记为 error。
- 归属与存储：`schema.sql` 新增 `api_clients` 表，并在 `chat_threads`、`tasks`、`manager_actions` 上加可空的 `client_id`。任务的 `via` 对经 API 的调用为 `client:<name>`，对管家在客户端对话中的调用为 `manager:loopercli`；任务页显示客户端名。对话归属于其客户端和管家，其他客户端或另一管家下的同一 id 视为不存在。
- 任务汇报：在客户端对话中创建的任务，把验收和结束消息发回该对话（`origin_thread`），默认管家也一样；控制台自己的默认管家聊天仍走原渠道路径。
- `loopercli`（新控制台脚本）：OpenAPI 文档的每个操作在运行时变成命令；`login`、`confirm`、`chat`、`wait`、`skill` 手写，另有别名 `list`、`status`、`pipeline`、`start`、`stop`。令牌和 URL 存在私有客户端文件中（权限 0600，仅回环地址），令牌只从 stdin 或提示输入、绝不从参数传入，不跟随重定向，用法错误中会遮蔽令牌。退出码：0 完成，1 错误，2 用法，3 需要确认，4 无法连接，6 `wait` 超时。
- 技能与插件：`looper/skill/looper-skill/SKILL.md` 随 wheel 发布；Claude Code 插件（`plugins/looper`、`.claude-plugin/marketplace.json`）带同一份副本。Looper 不会写入其他工具的目录。
- 控制台：API 客户端设置页，任务页显示客户端名。
- 文档与评测：`docs/architecture/agent-system.md`、RFC `looper-client-skill.zh-CN.md`，以及 `evals/prompt_regression` 的新对话用例。
- 面向模型的变化：经客户端进来的管家消息带一行 `Channel: loopercli, client "<name>" (the user works in their own coding agent, which writes these messages for them)`，仅由已验证的令牌设置；其他提示词文本未改。客户端工具列表是管家目录减两个工具再加两个新工具。`looper-skill` 是 agent 读取的新文本：用户已表示提交后，允许 agent 代为确认创建并启动任务、修改需求、回答关卡；取消、删除和设置变更须先转给用户。

### 升级与回退

发布后重跑 `install.sh`。schema 新增均为 `IF NOT EXISTS`，无需迁移数据。要使用新入口，先在设置 → API 客户端创建客户端，再运行 `loopercli login`。回退到 v2.13.44 无需额外步骤：旧版本忽略新表和新列，已存的客户端令牌不再被使用。

### 可选能力启用与使用

#### API clients

**启用：**默认关闭，直到操作者在设置 → API 客户端（或 `POST /api/clients`）创建客户端；没有客户端时 `/api/v1` 只服务操作者。

**验证：**`GET /api/clients` 列出客户端（不含令牌）；`loopercli whoami` 以该客户端身份应答。

**停用 / 回退：**在设置中或用 `DELETE /api/clients/:id` 吊销客户端，令牌立即失效。

**权限边界：**客户端可通过 `/api/v1` 运行管家的工具，写操作立即执行，高风险操作按客户端和会话确认；只接受回环来源，不能管理操作者密码或其他客户端，也得不到操作者会话。

**文档：**[Agent system: the public API (v1)](https://github.com/foolzzz/looper/blob/v2.13.45/docs/architecture/agent-system.md#the-public-api-v1)。

```bash
loopercli whoami                       # answers as the client
loopercli --json agent-profiles list    # an operation through /api/v1
```

#### loopercli

**启用：**创建 API 客户端后运行 `loopercli login`，令牌从 stdin 或提示输入。

**验证：**`loopercli whoami`；`loopercli chat "text"` 与默认管家对话，会话 id 打印在 stderr。

**停用 / 回退：**删除 `loopercli login` 写下的客户端文件，或吊销客户端。

**权限边界：**令牌只发往其回环 URL，不跟随重定向；能做的事等于其客户端能做的事。

**文档：**[loopercli and looper-skill](https://github.com/foolzzz/looper/blob/v2.13.45/docs/architecture/agent-system.md#loopercli-and-looper-skill)。

```bash
loopercli login                        # token from stdin or a prompt
loopercli chat --list         # list your conversations
```

#### looper-skill and the Claude Code plugin

**启用：**按 `plugins/looper/README.md` 安装插件，或让 Codex、OMP 指向 `loopercli skill path` 打印的目录。

**验证：**`loopercli skill show` 打印技能；在 agent 中让它把工作交给 Looper，确认它先运行 `loopercli whoami`。

**停用 / 回退：**卸载插件或删除复制的技能。

**权限边界：**技能是给 agent 的指令，不是权限。它让 agent 只代用户确认该会话中用户已授权的事项（创建并启动、修改需求、回答关卡），取消、删除和设置变更须转给用户；服务端不强制这一划分，令牌能做的事就是客户端能做的事。

**文档：**[plugins/looper/README.md](https://github.com/foolzzz/looper/blob/v2.13.45/plugins/looper/README.md)。

```bash
loopercli skill path
loopercli skill show | head -5
```
