# Looper v2.13.28

## Release Decision

**Who should upgrade:** Anyone who reads the cost basis or the unpriced-model warnings of an Agent Profile in the dashboard or API, and anyone who runs the test suite.

**What this release solves:** [#375](https://github.com/foolzzz/looper/pull/375) fixes review follow-ups of #294. The list of unpriced models in a profile's cost basis is now built from the provider's catalog in launch order, instead of forcing the selected model first, so it matches the price a run gets at launch. It also fixes two flaky `tests/test_pi_steer.py` cases whose setup deadline raced process startup under load.

**Breaking changes:** No. No CLI command, configuration key, API shape or database schema changed. One behavior change is listed below.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#375](https://github.com/foolzzz/looper/pull/375); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.28
```

## Behavior changes

- **Cost view uses launch catalog order:** `_cost_profile` (`looper/agents/profile_registry.py`) now orders the provider's models for the same protocol by `(catalog_order, name, id)`, the selected model among them, instead of putting the selected model first. When two entries share a normalized name, the earlier one now owns it, as at launch. As a result the `unpriced` list of `cost_basis` and the cost warnings of a profile view can differ from before for such a catalog: a model can be reported as unpriced (or priced) where it was not before. Profiles without name collisions in their catalog are unaffected.
- **Test-only change:** the `test_ack_deadlines_include_silent_and_busy_stdout` cases shorten only the deadline under test; no product code changed for this.
- **Model-visible changes:** None. No prompt text, tool schema or tool result changed.
- **Deferred:** the Manager dialogs comparison eval for the changed Manager-visible reply stays open in #294; it needs live model runs and is not part of this release.

## Upgrade and rollback

Re-run `install.sh` once v2.13.28 is published. There is no schema or configuration change. Rolling back to v2.13.27 is safe; the only difference is the previous ordering in the cost view.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 行为变化与入口

- 成本视图按启动目录顺序：`_cost_profile`（`looper/agents/profile_registry.py`）现在把同协议的 provider 模型（含所选模型）按 `(catalog_order, name, id)` 排序，而不是把所选模型放首位。两个条目规范化后同名时，靠前者占有该名，与启动时一致。因此对这类目录，`cost_basis` 的 `unpriced` 列表和 profile 视图的成本警告可能与之前不同；目录中没有同名冲突的 profile 不受影响。
- 仅测试变更：`test_ack_deadlines_include_silent_and_busy_stdout` 只缩短被测的那个超时；产品代码未因此改动。
- 面向模型的变化：无。提示词文本、工具 schema、工具结果均无变化。
- 延后项：#294 中针对 Manager 可见回复的 Manager dialogs 对比 eval 仍保持打开，需要真实模型运行，不在本版本内。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.27 安全；区别仅是成本视图恢复之前的排序。
