# Looper v2.13.179

## Release Decision

**Who should upgrade:** Operators who let a Manager create or change schedules from a task template, and maintainers who run the Manager dialog evals. It is a hotfix that ships the change merged since v2.13.178.

**What this release solves:** [#774](https://github.com/foolzzz/looper/pull/774) completes the Manager schedule tool contract for template selection, static inputs, configuration readback, changes and enable confirmation.

**Breaking changes:** No. The new `looper_schedules` fields are optional, and no command, configuration format or schema changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#774](https://github.com/foolzzz/looper/pull/774); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.179
```

## Behavior changes

- **Template fields on schedules ([#774](https://github.com/foolzzz/looper/pull/774)):** in `looper/agents/ops/schedules.py` the schedule fields accept `template_key` (a string, or null to clear the selection and its inputs) and `template_inputs` (an object of string values that replaces all inputs). Omitted, the selection is kept; a new key resets inherited inputs.
- **Readback:** the schedule list carries `template_key`, `template_name` and `template_inputs`. The configuration shown after creation, and the enable and run confirmation, add the lines 任务模板 and 模板静态输入 when a template is selected. A change reports a template or input change as `before → after`; inputs are shown as `key="value"`, each value clipped to 200 characters.
- **Scoping:** for a scoped Manager, a schedule owned by another Manager has its template key, name and inputs blanked in what it sees. An update, or an enable confirmation that carries such fields, on that schedule is refused with a FORBIDDEN error before anything is written.
- **Dialog evals:** the new `schedule_template_create` dialog (`pr_review` template, create disabled, then 「启用」 and 「确认。」) raises the default dialog selection from 47 to 48; `evals/README.md` is updated.
- **Model-visible changes:** yes. The `looper_schedules` tool schema gains `template_key` and `template_inputs` with their descriptions, and the tool results and confirmation texts shown to the Manager and the user gain the template lines above.

## Upgrade and rollback

Re-run `install.sh` once v2.13.179 is published. There is no schema change, so rolling back to v2.13.178 needs nothing else.

### 行为变化与入口

- **定时任务的模板字段（#774）：**`looper/agents/ops/schedules.py` 的定时任务字段接受 `template_key`（字符串；为 null 则清除选择及其输入）和 `template_inputs`（字符串值对象，整体替换所有输入）。省略则保持原选择；换用新 key 会重置继承的输入。
- **回读：**定时任务列表带 `template_key`、`template_name`、`template_inputs`。创建后展示的配置以及启用、运行确认，在选了模板时增加「任务模板」和「模板静态输入」两行。变更以 `之前 → 之后` 报告模板或输入的变化；输入显示为 `key="value"`，每个值截断到 200 字符。
- **范围：**对受限 Manager，属于其他 Manager 的定时任务，其模板 key、名称和输入会被置空。对这类定时任务带这些字段的修改或启用确认，会在写入任何内容之前以 FORBIDDEN 拒绝。
- **对话评测：**新增 `schedule_template_create` 对话（`pr_review` 模板，先停用创建，再「启用」「确认。」），默认对话选择从 47 增至 48；`evals/README.md` 已同步。
- **面向模型的变化：**有。`looper_schedules` 工具 schema 新增 `template_key` 和 `template_inputs` 及其描述；展示给 Manager 和用户的工具结果与确认文本增加上述模板行。
