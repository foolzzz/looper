# Looper v2.10.0

## At a Glance

On Claude Code, the **Manager and the Planner replace Claude Code's default system prompt**. They appended on v2.9.0. Worker, Reviewer, Planner-defined role runs and consults still append. Settings → Roles has an append/replace choice for every role. A task can override its planner, worker or reviewer on the task's Agents tab. A Claude Code profile can no longer be saved with `replace`; the mode for that runtime is the role's. The first start migrates once: a Worker or Reviewer whose effective profile was a Claude Code profile set to `replace` keeps `replace` on its role layer, and every Claude Code profile is set to `append`. Codex, Grok and OMP keep the mode on the Agent Profile. Per-role mode for those runtimes is planned.

**An empty allowed-profiles list lets a project's Planners choose any registered profile that can run the role**, with no confirmation. The list is empty by default, so this is every project that never set one. On v2.9.0 an empty list meant the Planner chose nothing. Set a list to restrict the choice. Deleting a profile that an open task's Planner, or a role that task defined, has chosen is refused. The message names the task.

**A new gate's agenda item may carry the id Looper assigns** (`q1`, `q2`, …). Any other id is refused, and the message names the id that position must use. Leaving `id` out is unchanged. A Planner that numbered its own items was refused on v2.9.0 (`unknown keys: id`).

**This release has breaking changes.** Claude Code Manager and Planner launches no longer include Claude Code's default system prompt. Saving `replace` on a Claude Code profile is refused. An empty allowed-profiles list no longer blocks the Planner's choice. Upgrade by re-running `install.sh`. The first start backs the database up and migrates it. With haiku as the Planner, replace scored lower than append: run that Planner on opus or sonnet, or set the Planner role to append.

```bash
curl -fsSL https://raw.githubusercontent.com/foolzzz/looper/main/install.sh | bash
looper --version   # looper 2.10.0
looper doctor
```

### Highlights

- **System prompt mode per role, on Claude Code.** Manager and Planner replace by default. Settings → Roles changes a role. The task's Agents tab overrides that task's planner, worker or reviewer. ([#219](https://github.com/foolzzz/looper/pull/219))
- **One migration, then the profile field stops deciding Claude Code.** Worker and Reviewer role layers keep a Claude Code profile's `replace`. Those profiles become `append`. A Claude Code profile refuses `replace`. ([#219](https://github.com/foolzzz/looper/pull/219))
- **Empty allowed-profiles means any capable profile.** A list still restricts. No confirmation either way. Open-task choices block deletion of that profile. ([#220](https://github.com/foolzzz/looper/pull/220))
- **Gate agenda ids.** `q1`, `q2`, … are accepted on a new gate. Anything else is refused with the id Looper assigns. ([#222](https://github.com/foolzzz/looper/pull/222))

## Release Decision

**Who should upgrade:** Everyone running v2.9.0. Before upgrading, read Behavior changes if the Manager or the Planner runs on Claude Code, if a Claude Code profile is set to replace, or if a project's allowed-profiles list is empty. If the Planner uses haiku, read Known limits first.

**What this release solves:** v2.9.0 appended Looper's prompt to Claude Code's default for every role, kept that mode on the Agent Profile, refused a Planner that numbered a new gate's agenda items, and treated an empty allowed-profiles list as "the Planner chooses nothing". v2.10.0 replaces Claude Code's default for the Manager and the Planner, moves that mode to the role (a task can override it), accepts agenda ids that match Looper's numbering, and lets an empty list mean any capable profile.

**Breaking changes:** Yes. Manager and Planner launches on Claude Code replace Claude Code's default system prompt. A Claude Code profile refuses replace, and the first start rewrites those profiles to append. An empty allowed-profiles list allows any capable profile, with no confirmation. See Behavior changes, Breaking Changes and Upgrading from v2.9.0.

**How to verify:** After re-running install.sh, looper --version reports looper 2.10.0 and looper doctor passes. The first looper serve logs a pg_dump backup before it migrates. With the server running and no overrides or migrated Worker/Reviewer replace settings, GET /api/agent-settings shows system_prompt_mode replace for manager and planner, and append for worker and reviewer. A project whose allowed-profiles list is empty reports restricted false.

**Contributors:** Release maintainer @foolzzz; no community contribution in the pull requests merged since v2.9.0.

## New capabilities

### Claude Code system prompt mode per role

- **The mode is the role's, on Claude Code.** `append` adds Looper's prompt to the runtime's default. `replace` sends Looper's prompt in place of that default (`--system-prompt-file`; both modes keep `--system-prompt-snapshot off`). Built-in values: Manager and Planner `replace`, Worker and Reviewer `append`. Planner-defined role runs and reviews follow the task's Worker or Reviewer mode. A consult appends. A launch with no role appends. The Manager has no task level. ([#219](https://github.com/foolzzz/looper/pull/219))
- **Where you set it.** Settings → Roles has a two-way System prompt choice on every role, with "Only for runs on Claude Code." `PUT /api/agent-settings/roles/<role>` sets `system_prompt_mode` to `append` or `replace`. Null or an empty value clears the role layer, and the built-in value applies. The shared defaults, a project, and a role inside a project refuse the field (400). `GET /api/agent-settings` shows each role's effective mode. ([#219](https://github.com/foolzzz/looper/pull/219))
- **A task can override its planner, worker or reviewer.** The task's Agents tab shows Append/Replace only when that role runs on Claude Code. After a task sets one, the control reads "task setting · reset". `PUT /api/tasks/:id/agents` takes `system_prompt_modes` (`{"planner": "append"}`; null clears that role). Precedence on Claude Code: the task, then the role layer, then the built-in value. The task's `agents` view gives each role's effective value, its source (`task`, `role` or `builtin`) and the runtime type. The Manager's task tools do not set this. The dashboard and the HTTP API do. ([#219](https://github.com/foolzzz/looper/pull/219))
- **A Claude Code profile does not carry the mode.** The profile editor shows the per-role line instead of the choice. Create, update and the Manager's profile tool refuse `replace` with `Claude Code's system prompt mode is set per role in Settings → Roles` (400). Configuration import skips that profile and records the reason. Codex, Grok and OMP profiles still store `append` or `replace`, and their launches still use the profile's value. `Launch.system_prompt_mode` is the role's resolved mode on Claude Code and the profile's mode on every other runtime. ([#219](https://github.com/foolzzz/looper/pull/219))
- **Preview and configuration.** `GET /api/agent-profiles/<id>/prompt-preview?role=planner|worker|reviewer|manager` adds `system_prompt_mode` (what that launch sends), `role_system_prompt_mode` (the role's setting) and `system_prompt_mode_applies` (true when the profile's runtime is Claude Code). Configuration export and import carry the role layers' value and the profiles' value. ([#219](https://github.com/foolzzz/looper/pull/219))
- **One-time migration.** The first start that adds `agent_setting_layers.system_prompt_mode` does this in that change, and a later start does not: for the Worker and the Reviewer, if the effective profile (the role layer's, else the shared defaults', else `agent-claude-code-opus`) is a Claude Code profile with `replace`, that role layer is set to `replace`. Then every Claude Code profile is set to `append`. An explicit append you set after that survives. Manager and Planner do not need a copied row: their built-in value is already `replace`. ([#219](https://github.com/foolzzz/looper/pull/219))

### Allowed profiles

- **Empty means any capable profile.** `project_allowed_profiles` stays empty by default. An empty list, and a task with no project, lets the Planner choose any registered Agent Profile that can run the Worker or the Reviewer. A non-empty list restricts the choice to that list. One function decides (`looper.agents.projects.choosable_profiles`), and the Planner's profile tools, task roles and the SQL that reads a stored choice all use it. `GET` and `PUT /api/projects/:id/allowed-profiles` return `restricted` and `choosable`. `restricted` is false when the list is empty. ([#220](https://github.com/foolzzz/looper/pull/220))
- **No confirmation.** A pricier profile does not ask. The list, including the empty list, is the consent. The run budget caps still bound spend. The project's Agent Profiles tab reads "Any profile (no restriction)" when the list is empty. The role editor offers `choosable`. ([#220](https://github.com/foolzzz/looper/pull/220))
- **What a later list does.** `PUT` with `{"profile_ids": []}` lifts the restriction and keeps the Planners' choices. A non-empty list still drops choices it leaves out. A profile that cannot run the Worker or the Reviewer is a 400, and the list does not change. ([#220](https://github.com/foolzzz/looper/pull/220))
- **Deleting a chosen profile.** A profile on a list still cannot be deleted. A profile that is not on a list, but that an open task's Planner chose for its Workers or Reviewers, or that a role the Planner defined still uses, is also refused. The message names the task (up to five) and tells you to clear the choice or wait until the task ends. The check and the delete take one lock on the profile row. Choices of ended tasks are removed with the profile. ([#220](https://github.com/foolzzz/looper/pull/220))
- **What the Planner is told.** The empty-list note and the forbidden errors that said the list was empty are gone. `looper_task_profiles` includes `restricted`. When the list is empty, a profile that cannot be chosen is "not a registered profile that can run a Worker or Reviewer". When the list is set, it is "not on the project's list". The Manager's settings tool says an empty list means Planners may choose any profile. ([#220](https://github.com/foolzzz/looper/pull/220))

### Gate agenda ids

- **A new item may name its own id, only if it matches.** In a `[PLAN]` reply, and in `add_steps` or `replan`, an agenda item of a new gate may include `id`. The first item must be `q1`, the second `q2`, and so on. Leaving `id` out is still accepted: Looper numbers the items. Any other id is refused: `<where>.id must be "qN" or left out: Looper numbers new items q1, q2, …`, with the position's own `qN`. On v2.9.0 the same reply failed earlier, with `unknown keys: id`. ([#222](https://github.com/foolzzz/looper/pull/222))
- **Later replies are unchanged.** An id on an existing gate, in a `[GATE]` reply or in an update, must still name an item that gate already has. This release does not let a Planner renumber an open gate. ([#222](https://github.com/foolzzz/looper/pull/222))
- **No setting.** Every Planner gets this. It is what let a Planner that numbers agenda items itself pass `gate_parallel_branch` (OMP with deepseek-flash on the five gate tasks, 10/10; `gate_parallel_branch`, 0/2 to 2/2). ([#222](https://github.com/foolzzz/looper/pull/222))

## Default and behavior changes

These move on upgrade. Each one says what the operator does. None of them is a new project switch except where the line says so.

1. **Manager and Planner on Claude Code replace Claude Code's default system prompt.** On v2.9.0 every Claude Code launch appended. To keep that for the Manager or the Planner, open Settings → Roles and set the role to Append. A task can override its planner, worker or reviewer without changing the role: the task's Agents tab, or `PUT /api/tasks/:id/agents` with `system_prompt_modes`. Null on a role clears the task's choice. The Manager has no task-level mode. The Manager's task tools do not set it; use the dashboard or the HTTP API. Worker, Reviewer and Planner-defined role runs append unless that role layer, or the task, is set to replace. A consult on Claude Code appends even when the seat's role replaces. With haiku as the Planner, replace scored 31/40 against 50/60 for append on the Planner tier. Run the Planner on opus or sonnet, or set the Planner role to append when the Planner uses haiku. ([#219](https://github.com/foolzzz/looper/pull/219))
2. **The first start migrates once, when the role-layer column is added.** A Worker or Reviewer whose effective profile was a Claude Code profile set to `replace` gets `replace` on its role layer (the role layer's profile, else the shared defaults' profile, else the built-in `claude-code/opus`). Then every Claude Code profile is set to `append`. You do not run a separate command. After `looper serve` has migrated, open Settings → Roles. If Worker or Reviewer shows Replace and you wanted append, set it back to Append. A second start does not repeat the copy, and an append you set afterwards stays. Manager and Planner replace because that is the built-in value, not because a profile row was copied. ([#219](https://github.com/foolzzz/looper/pull/219))
3. **Replace is refused on a Claude Code profile.** `POST` or `PUT /api/agent-profiles`, configuration import, and the Manager's profile tool refuse `system_prompt_mode: replace` when the runtime type is `claude-code`. The API answer is 400 and the text is `Claude Code's system prompt mode is set per role in Settings → Roles`. Import skips that profile and keeps the others. Set the mode in Settings → Roles, or on the task. Codex, Grok and OMP profiles still accept `append` and `replace`. Their launches ignore the role layer's mode. ([#219](https://github.com/foolzzz/looper/pull/219))
4. **An empty allowed-profiles list lets Planners choose any capable profile, without confirmation.** This is the default, and it applies to every project whose list is empty, including projects created before this release. On v2.9.0 the Planner chose nothing until you added profiles. To restrict the choice to selected profiles, set a non-empty list: the project's Agent Profiles tab, row "Profiles the Planner may choose", or `PUT /api/projects/:id/allowed-profiles` with `{"profile_ids": ["PROFILE_ID"]}`. A non-empty list still drops stored choices it leaves out. `{"profile_ids": []}` lifts the restriction and does not drop choices. A profile the Planner could not run is still refused. Spend stays bounded by the run budget caps. There is no extra confirm step for a more expensive profile. ([#220](https://github.com/foolzzz/looper/pull/220))
5. **Deleting a profile an open task chose is refused.** If a task that has not ended has a Planner choice of that profile, or a Planner-defined role that uses it, deletion is refused. The message names the task. Clear the choice (`looper_task_profile_set` with a null `profile_id`, or define the role again without it), or wait until the task ends. The check and the delete lock the profile row. Choices on ended tasks are deleted with the profile. A profile that is on a project's list is still refused until you take it off the list, as on v2.9.0. ([#220](https://github.com/foolzzz/looper/pull/220))
6. **Planner replies that number a new gate `q1`, `q2`, … are accepted.** Any other id is refused, and the error names the id for that position. You do not enable this. Replies that omit `id` behave as on v2.9.0. An update to a gate that is already open must still use that gate's existing ids. ([#222](https://github.com/foolzzz/looper/pull/222))

Codex, Grok and OMP keep the profile-level system prompt mode. Per-role mode for them is planned. The choice in Settings → Roles applies only to runs on Claude Code. A `vX.Y.Z` tag still publishes this Python release.

## Fixes

- **OMP can omit optional MCP arguments on openai-responses.** OMP CLI 18.4.x omitted `strict` for endpoints it did not recognize, such as a local OpenAI-compatible proxy. The Responses API treats a missing `strict` as strict, so the model filled every optional MCP argument; an OMP Planner could not define a custom role without inventing a template. Looper now marks openai-responses models in OMP's launch config with `compat: {supportsStrictMode: true}`, so OMP sends its MCP tools with explicit `strict: false`. Looper's tool schemas, Claude Code, and the openai-chat / anthropic-messages providers are unchanged. ([#223](https://github.com/foolzzz/looper/pull/223))
- **A new gate may carry the agenda ids Looper assigns.** A Planner that sent `"id": "q1"` on a new agenda item was refused with `steps[0].agenda[0] has unknown keys: id`. The repair turn did not remove the id, so the plan failed. The id is now accepted when it equals the id Looper would assign (`q1` at the first item, `q2` at the second, and so on). Any other value is refused with `<where>.id must be "qN" or left out: Looper numbers new items q1, q2, …`. Existing items in a later `[GATE]` reply or an update still have to name an item the gate already has. OMP with deepseek-flash passed the five gate tasks 10/10 (`gate_parallel_branch` 0/2 → 2/2). ([#222](https://github.com/foolzzz/looper/pull/222))

## Breaking Changes

1. **Claude Code's Manager and Planner replace the runtime's default system prompt.** A launch that appended on v2.9.0 now sends Looper's prompt in place of Claude Code's default guidance. Scripts do not call a new API for this; the next Manager or Planner turn on Claude Code uses it. To keep append, set the role in Settings → Roles, or set the task's planner on the Agents tab. The Manager has no task-level override. ([#219](https://github.com/foolzzz/looper/pull/219))
2. **A Claude Code profile refuses `replace`, and the migration rewrites stored profiles.** `system_prompt_mode: replace` on a profile whose runtime type is `claude-code` is 400 on create and update, and that profile is skipped on import. The first start sets every Claude Code profile to `append`. A Worker or Reviewer that was effectively on a Claude Code profile set to `replace` gets `replace` on its role layer, so those runs keep replacing. A client that saved the mode on the profile must save it on the role. ([#219](https://github.com/foolzzz/looper/pull/219))
3. **An empty allowed-profiles list allows any capable profile.** On v2.9.0 the Planner chose nothing until the list had entries, and an empty list was a forbidden choice. A project that left the list empty in order to block that choice now allows every registered profile that can run the Worker or the Reviewer, with no confirmation. Set `profile_ids` to the profiles you want. Run budget caps still apply. ([#220](https://github.com/foolzzz/looper/pull/220))

**Also changed, with less authority or a different record.** Consults on Claude Code append even when the seat's role is replace. Planner-defined role runs follow the task's Worker or Reviewer mode. The prompt preview reports `system_prompt_mode`, `role_system_prompt_mode` and `system_prompt_mode_applies`. Codex, Grok and OMP still take the mode from the profile. A new gate accepts `q1`, `q2`, … on its agenda items. Deleting a profile an open task chose is refused, under a lock on that profile row. ([#219](https://github.com/foolzzz/looper/pull/219), [#220](https://github.com/foolzzz/looper/pull/220), [#222](https://github.com/foolzzz/looper/pull/222))

## Upgrading from v2.9.0

1. **Install with `install.sh`.** It installs the latest release wheel. This release adds no Python dependency.
2. **Keep the first-start backup possible.** The schema adds `agent_setting_layers.system_prompt_mode` and `task_system_prompt_modes`, so the first start writes a `pg_dump` backup before migrating. Keep a `pg_dump` of at least the server's major version on `PATH` (or `LOOPER_PG_DUMP`, or `LOOPER_BACKUP_CMD`). `looper serve --skip-backup` migrates without one.
3. **Start once.** The upgrade adds the role-layer mode, runs the one-time copy from Claude Code profiles onto the Worker and Reviewer role layers, sets those profiles to `append`, and creates `task_system_prompt_modes`. A second start does not copy again.
4. **Decide the Claude Code mode.** Settings → Roles: Manager and Planner are Replace, Worker and Reviewer are Append, unless the migration wrote Replace for a Worker or Reviewer that was on a Claude Code profile set to replace. Set a role to Append to keep v2.9.0's composition for that role. A task's Agents tab overrides its planner, worker or reviewer when that role runs on Claude Code.
5. **Haiku as the Planner.** Replace scored 31/40 against 50/60 for append on the Planner tier. Run the Planner on opus or sonnet, or set the Planner role to append.
6. **Do not set `replace` on a Claude Code profile.** The API returns 400. Import skips the profile. Codex, Grok and OMP are unchanged: set `append` or `replace` on the profile, as on v2.9.0.
7. **Allowed profiles.** To limit which profiles a project's Planners may pick, set a non-empty list before the next task plans. An empty list now means any capable profile, with no confirmation. A list you already set still restricts, and still drops choices it leaves out.
8. **Check.** `looper doctor`, and `looper service status` if you use the service. `GET /api/agent-settings` shows `replace` for manager and planner and `append` for worker and reviewer when there are no overrides or migrated Worker/Reviewer replace settings.

```bash
curl -fsSL https://raw.githubusercontent.com/foolzzz/looper/main/install.sh | bash
looper doctor
looper serve
  # Or, with the service:
looper service restart && looper service status
```

**Rollback to v2.9.0.** Stop Looper (`looper service uninstall` if you installed the service), recreate the database empty and restore the pre-migration backup the first start logged (`pg_restore --no-owner --dbname "$LOOPER_DATABASE_URL" FILE`). Then install the v2.9.0 wheel, for example `uv tool install --force "looper @ https://github.com/foolzzz/looper/releases/download/v2.9.0/looper-2.9.0-py3-none-any.whl"`. `install.sh` always installs the latest release, so it cannot roll back. v2.9.0 does not know the role-layer system prompt mode or `task_system_prompt_modes`. A database this version has migrated is not a v2.9.0 database until that backup is restored.

### 新能力

#### Claude Code 上按角色的 system prompt 模式

- **在 Claude Code 上，模式属于角色。** `append` 把 Looper 的提示词追加到运行时的默认提示词后面。`replace` 用 Looper 的提示词代替该默认提示词（`--system-prompt-file`；两种模式都保留 `--system-prompt-snapshot off`）。内置值：Manager 和 Planner 为 `replace`，Worker 和 Reviewer 为 `append`。规划者定义的角色的运行和评审跟随该任务的 Worker 或 Reviewer 模式。Consult 追加。没有角色的启动追加。Manager 没有任务级。 （[#219](https://github.com/foolzzz/looper/pull/219)）
- **在哪里设置。** Settings → Roles 的每个角色都有一个双向的 System prompt 选择，旁边是 “Only for runs on Claude Code.”。`PUT /api/agent-settings/roles/<role>` 把 `system_prompt_mode` 设成 `append` 或 `replace`。Null 或空值清除角色层，然后使用内置值。共享默认、项目，以及项目里的角色，都拒绝这个字段（400）。`GET /api/agent-settings` 显示每个角色的有效模式。（[#219](https://github.com/foolzzz/looper/pull/219)）
- **任务可以覆盖自己的 planner、worker 或 reviewer。** 任务的 Agents 页只在该角色跑在 Claude Code 上时显示 Append/Replace。任务设置之后，控件读作 “task setting · reset”。`PUT /api/tasks/:id/agents` 接受 `system_prompt_modes`（`{"planner": "append"}`；null 清除该角色）。在 Claude Code 上的优先级：任务，然后角色层，然后内置值。任务的 `agents` 视图给出每个角色的有效值、来源（`task`、`role` 或 `builtin`）和运行时类型。Manager 的任务工具不设置这个。Dashboard 和 HTTP API 可以设置。（[#219](https://github.com/foolzzz/looper/pull/219)）
- **Claude Code 的 Profile 不承载这个模式。** Profile 编辑器显示按角色的那一行，而不是原来的选择。创建、更新和 Manager 的 Profile 工具在运行时类型是 `claude-code` 时拒绝 `replace`，文本是 `Claude Code's system prompt mode is set per role in Settings → Roles`（400）。配置导入跳过该 Profile 并记下原因。Codex、Grok 和 OMP 的 Profile 仍保存 `append` 或 `replace`，它们的启动仍使用 Profile 的值。`Launch.system_prompt_mode` 在 Claude Code 上是角色解析后的模式，在其他运行时上是 Profile 的模式。（[#219](https://github.com/foolzzz/looper/pull/219)）
- **预览和配置。** `GET /api/agent-profiles/<id>/prompt-preview?role=planner|worker|reviewer|manager` 增加 `system_prompt_mode`（这次启动发送的模式）、`role_system_prompt_mode`（角色的设置）和 `system_prompt_mode_applies`（Profile 的运行时是 Claude Code 时为 true）。配置导入导出携带角色层的值和 Profile 的值。（[#219](https://github.com/foolzzz/looper/pull/219)）
- **一次性迁移。** 首次添加 `agent_setting_layers.system_prompt_mode` 的启动做下面的事，之后的启动不做：对 Worker 和 Reviewer，如果有效 Profile（角色层的，否则共享默认的，否则 `agent-claude-code-opus`）是设为 `replace` 的 Claude Code Profile，该角色层被设为 `replace`。然后每一个 Claude Code Profile 被设为 `append`。这之后你显式设下的 append 会留下来。Manager 和 Planner 不需要复制一行：它们的内置值已经是 `replace`。（[#219](https://github.com/foolzzz/looper/pull/219)）

#### 允许的 Profile

- **空表示任何能跑的 Profile。** `project_allowed_profiles` 默认仍是空的。空列表，以及没有项目的任务，让 Planner 选择任何能跑 Worker 或 Reviewer 的已登记 Agent Profile。非空列表把选择限制在这份列表里。由一个函数决定（`looper.agents.projects.choosable_profiles`），Planner 的 Profile 工具、任务角色，以及读取已存选择的 SQL，都使用它。`GET` 和 `PUT /api/projects/:id/allowed-profiles` 返回 `restricted` 和 `choosable`。列表为空时 `restricted` 为 false。（[#220](https://github.com/foolzzz/looper/pull/220)）
- **不确认。** 更贵的 Profile 不再询问。列表本身就是同意，空列表也是。运行的预算上限仍然约束花费。项目的 Agent Profiles 页在列表为空时显示 “Any profile (no restriction)”。角色编辑器提供 `choosable`。（[#220](https://github.com/foolzzz/looper/pull/220)）
- **之后的列表做什么。** `PUT` 的 `{"profile_ids": []}` 取消限制并保留 Planner 的选择。非空列表仍会丢掉它没有留下的选择。不能跑 Worker 或 Reviewer 的 Profile 是 400，列表不变。（[#220](https://github.com/foolzzz/looper/pull/220)）
- **删除已被选择的 Profile。** 在列表上的 Profile 仍不能删除。不在列表上、但被未结束任务的 Planner 选来给 Worker 或 Reviewer 用的 Profile，或仍被 Planner 定义的角色使用的 Profile，也会被拒绝。消息写出任务（最多五个），并告诉你清除选择或等到任务结束。检查和删除对 Profile 行加一把锁。已结束任务的选择随 Profile 一起删除。（[#220](https://github.com/foolzzz/looper/pull/220)）
- **Planner 被告知什么。** 空列表的说明，以及说列表为空的 forbidden 错误，都没有了。`looper_task_profiles` 包含 `restricted`。列表为空时，不能选的 Profile 是 “not a registered profile that can run a Worker or Reviewer”。设置了列表时，是 “not on the project's list”。Manager 的设置工具会说明空列表表示 Planner 可以选择任何 Profile。（[#220](https://github.com/foolzzz/looper/pull/220)）

#### 关卡议程 id

- **新条目可以写自己的 id，但必须对得上。** 在 `[PLAN]` 回复里，以及 `add_steps` 或 `replan` 里，新关卡的议程项可以带 `id`。第一项必须是 `q1`，第二项必须是 `q2`，依此类推。不写 `id` 仍然接受：Looper 给条目编号。其他 id 被拒绝：`<where>.id must be "qN" or left out: Looper numbers new items q1, q2, …`，其中的 `qN` 是该位置自己的。在 v2.9.0 上，同样的回复会更早失败，错误是 `unknown keys: id`。（[#222](https://github.com/foolzzz/looper/pull/222)）
- **之后的回复不变。** 已有关卡上的 id，在 `[GATE]` 回复或更新里，仍必须指向该关卡已经有的条目。本版本不让 Planner 给一个已经打开的关卡重新编号。（[#222](https://github.com/foolzzz/looper/pull/222)）
- **没有设置。** 每个 Planner 都得到这个行为。它让自己给议程项编号的 Planner 能通过 `gate_parallel_branch`（OMP 加 deepseek-flash 的五项关卡任务，10/10；`gate_parallel_branch`，0/2 到 2/2）。（[#222](https://github.com/foolzzz/looper/pull/222)）

### 行为变化

下面这些在升级时改变。每一条都写了操作者要做什么。除非该条写了，否则没有新的项目开关。

1. **Claude Code 上的 Manager 和 Planner 替换 Claude Code 的默认 system prompt。** 在 v2.9.0 上，每一次 Claude Code 启动都是追加。要让 Manager 或 Planner 保持追加，打开 Settings → Roles，把该角色设成 Append。任务可以不改角色就覆盖自己的 planner、worker 或 reviewer：任务的 Agents 页，或 `PUT /api/tasks/:id/agents` 的 `system_prompt_modes`。某个角色上的 null 清除任务的选择。Manager 没有任务级模式。Manager 的任务工具不设置它；用 dashboard 或 HTTP API。Worker、Reviewer 和规划者定义的角色运行默认追加，除非该角色层或任务被设成 replace。Claude Code 上的 consult 即使席位的角色是 replace 也追加。Planner 使用 haiku 时，replace 在 Planner 层得分 31/40，append 是 50/60。把 Planner 放到 opus 或 sonnet 上跑，或在 Planner 使用 haiku 时把 Planner 角色设成 append。（[#219](https://github.com/foolzzz/looper/pull/219)）
2. **首次启动在加上角色层列时迁移一次。** 有效 Profile 是设为 `replace` 的 Claude Code Profile 的 Worker 或 Reviewer，会在其角色层得到 `replace`（先看角色层的 Profile，否则共享默认的 Profile，否则内置的 `claude-code/opus`）。然后每一个 Claude Code Profile 被设成 `append`。你不用另外跑命令。`looper serve` 迁移之后，打开 Settings → Roles。如果 Worker 或 Reviewer 显示 Replace 而你要的是 append，就把它设回 Append。第二次启动不会再复制，你之后设下的 append 会留着。Manager 和 Planner 替换是因为这是内置值，不是因为复制了 Profile 行。（[#219](https://github.com/foolzzz/looper/pull/219)）
3. **Claude Code Profile 上的 replace 被拒绝。** 运行时类型是 `claude-code` 时，`POST` 或 `PUT /api/agent-profiles`、配置导入，以及 Manager 的 Profile 工具，都拒绝 `system_prompt_mode: replace`。API 回答是 400，文本是 `Claude Code's system prompt mode is set per role in Settings → Roles`。导入跳过该 Profile，其他的仍导入。把模式设在 Settings → Roles，或设在任务上。Codex、Grok 和 OMP 的 Profile 仍接受 `append` 和 `replace`。它们的启动忽略角色层的模式。（[#219](https://github.com/foolzzz/looper/pull/219)）
4. **空的 allowed-profiles 列表让 Planner 选择任何能跑的 Profile，且不确认。** 这是默认，对每一个列表为空的项目都生效，包括本版本之前创建的项目。在 v2.9.0 上，你把 Profile 加进列表之前，Planner 什么都不选。要把选择限制在指定 Profile 内，就设置非空列表：项目的 Agent Profiles 页，行 “Profiles the Planner may choose”，或 `PUT /api/projects/:id/allowed-profiles`，正文 `{"profile_ids": ["PROFILE_ID"]}`。非空列表仍会丢掉它没有留下的已存选择。`{"profile_ids": []}` 取消限制，且不丢掉选择。Planner 跑不了的 Profile 仍被拒绝。花费仍受运行预算上限约束。更贵的 Profile 没有额外的确认步骤。（[#220](https://github.com/foolzzz/looper/pull/220)）
5. **删除未结束任务选中的 Profile 会被拒绝。** 如果一个尚未结束的任务有 Planner 对该 Profile 的选择，或有一个 Planner 定义的角色使用它，删除会被拒绝。消息写出任务。清除选择（`looper_task_profile_set` 的 `profile_id` 为 null，或定义角色时不再带它），或等到任务结束。检查和删除锁住 Profile 行。已结束任务上的选择随 Profile 删除。仍在某个项目列表上的 Profile，要先从列表拿掉才会被允许删除，与 v2.9.0 一样。（[#220](https://github.com/foolzzz/looper/pull/220)）
6. **把新关卡编号成 `q1`、`q2` 等的 Planner 回复会被接受。** 其他 id 被拒绝，错误写出该位置的 id。你不用打开这个行为。省略 `id` 的回复与 v2.9.0 一样。对已经打开的关卡的更新，仍必须使用该关卡已有的 id。（[#222](https://github.com/foolzzz/looper/pull/222)）

Codex、Grok 和 OMP 保持 Profile 一级的 system prompt 模式。它们的按角色模式在计划中。Settings → Roles 里的选择只对 Claude Code 上的运行生效。`vX.Y.Z` 标签仍会发布这个 Python release。

### 修复

- **OMP 在 openai-responses 上可以省略可选 MCP 参数。** OMP CLI 18.4.x 对不认识的端点（例如本地 OpenAI 兼容代理）不发送 `strict`。Responses API 将缺失的 `strict` 视为严格模式，因此模型会填满每个可选 MCP 参数；OMP Planner 定义自定义角色时不得不编造模板。Looper 现在在 OMP 启动配置中为 openai-responses 模型设置 `compat: {supportsStrictMode: true}`，使 OMP 显式以 `strict: false` 发送 MCP 工具。Looper 的工具 schema、Claude Code，以及 openai-chat / anthropic-messages provider 均不变。（[#223](https://github.com/foolzzz/looper/pull/223)）
- **新关卡可以带上 Looper 分配的议程 id。** Planner 在新议程项上发送 `"id": "q1"` 时，会被拒绝，错误是 `steps[0].agenda[0] has unknown keys: id`。修复回合不会去掉这个 id，于是计划失败。现在，当 id 等于 Looper 将要分配的 id 时（第一项 `q1`，第二项 `q2`，依此类推），它会被接受。其他值被拒绝，错误是 `<where>.id must be "qN" or left out: Looper numbers new items q1, q2, …`。之后的 `[GATE]` 回复或更新里，已有条目仍必须指向该关卡已经有的项。OMP 加 deepseek-flash 的五项关卡任务通过 10/10（`gate_parallel_branch` 0/2 → 2/2）。（[#222](https://github.com/foolzzz/looper/pull/222)）

### 破坏性变更

1. **Claude Code 的 Manager 和 Planner 替换运行时的默认 system prompt。** 在 v2.9.0 上追加的启动，现在用 Looper 的提示词代替 Claude Code 的默认指引。脚本不会为此调用新的 API；Claude Code 上的下一次 Manager 或 Planner 回合就会使用它。要保持 append，在 Settings → Roles 设置角色，或在 Agents 页设置任务的 planner。Manager 没有任务级覆盖。（[#219](https://github.com/foolzzz/looper/pull/219)）
2. **Claude Code Profile 拒绝 `replace`，迁移会改写已存的 Profile。** 运行时类型是 `claude-code` 的 Profile 上，`system_prompt_mode: replace` 在创建和更新时是 400，导入时该 Profile 被跳过。首次启动把每一个 Claude Code Profile 设成 `append`。有效地使用设为 `replace` 的 Claude Code Profile 的 Worker 或 Reviewer，会在其角色层得到 `replace`，因此这些运行继续替换。把模式保存在 Profile 上的客户端，必须改存到角色上。（[#219](https://github.com/foolzzz/looper/pull/219)）
3. **空的 allowed-profiles 列表允许任何能跑的 Profile。** 在 v2.9.0 上，列表有条目之前 Planner 什么都不选，空列表是一次被禁止的选择。为了挡住这种选择而把列表留空的项目，现在允许每一个能跑 Worker 或 Reviewer 的已登记 Profile，且不确认。把 `profile_ids` 设成你要的 Profile。运行预算上限仍然适用。（[#220](https://github.com/foolzzz/looper/pull/220)）

**其他记录或权限上的变化。** Claude Code 上的 consult 即使席位的角色是 replace 也追加。规划者定义的角色运行跟随任务的 Worker 或 Reviewer 模式。提示词预览报告 `system_prompt_mode`、`role_system_prompt_mode` 和 `system_prompt_mode_applies`。Codex、Grok 和 OMP 仍从 Profile 取模式。新关卡接受议程项上的 `q1`、`q2` 等。删除未结束任务选中的 Profile 会被拒绝，并锁住该 Profile 行。（[#219](https://github.com/foolzzz/looper/pull/219)、[#220](https://github.com/foolzzz/looper/pull/220)、[#222](https://github.com/foolzzz/looper/pull/222)）

### 从 v2.9.0 升级

1. **用 `install.sh` 安装。** 它安装最新 release 的 wheel。本版本不增加 Python 依赖。
2. **保证首次启动能备份。** 表结构增加 `agent_setting_layers.system_prompt_mode` 和 `task_system_prompt_modes`，因此首次启动会先写一份 `pg_dump` 备份再迁移。请在 `PATH` 上保留主版本不低于服务器的 `pg_dump`（或设置 `LOOPER_PG_DUMP`、`LOOPER_BACKUP_CMD`）。`looper serve --skip-backup` 不备份直接迁移。
3. **启动一次。** 升级会加上角色层模式，把 Claude Code Profile 上的模式一次性复制到 Worker 和 Reviewer 的角色层，把这些 Profile 设成 `append`，并创建 `task_system_prompt_modes`。第二次启动不会再复制。
4. **决定 Claude Code 的模式。** Settings → Roles：Manager 和 Planner 是 Replace，Worker 和 Reviewer 是 Append，除非迁移给一个曾使用设为 replace 的 Claude Code Profile 的 Worker 或 Reviewer 写下了 Replace。把角色设成 Append，就能让该角色保持 v2.9.0 的拼接方式。当角色跑在 Claude Code 上时，任务的 Agents 页覆盖它的 planner、worker 或 reviewer。
5. **Planner 使用 haiku。** Replace 在 Planner 层得分 31/40，append 是 50/60。把 Planner 放到 opus 或 sonnet 上跑，或把 Planner 角色设成 append。
6. **不要在 Claude Code Profile 上设置 `replace`。** API 返回 400。导入会跳过该 Profile。Codex、Grok 和 OMP 不变：和 v2.9.0 一样，在 Profile 上设置 `append` 或 `replace`。
7. **允许的 Profile。** 要限制项目的 Planner 可以选择哪些 Profile，就在下一次任务做计划之前设置非空列表。空列表现在表示任何能跑的 Profile，且不确认。你已经设置的列表仍会限制，也仍会丢掉它没有留下的选择。
8. **检查。** 运行 `looper doctor`；使用服务时再运行 `looper service status`。没有覆盖或迁移保留的 Worker/Reviewer replace 设置时，`GET /api/agent-settings` 显示 manager 和 planner 为 `replace`，worker 和 reviewer 为 `append`。

```bash
curl -fsSL https://raw.githubusercontent.com/foolzzz/looper/main/install.sh | bash
looper doctor
looper serve
  # 或者使用服务：
looper service restart && looper service status
```

**回退到 v2.9.0。** 停止 Looper（装了服务就运行 `looper service uninstall`），把数据库重建为空库，并恢复首次启动日志里给出的迁移前备份（`pg_restore --no-owner --dbname "$LOOPER_DATABASE_URL" FILE`）。然后安装 v2.9.0 的 wheel，例如 `uv tool install --force "looper @ https://github.com/foolzzz/looper/releases/download/v2.9.0/looper-2.9.0-py3-none-any.whl"`。`install.sh` 总是安装最新 release，不能用来回退。v2.9.0 不认识角色层的 system prompt 模式，也不认识 `task_system_prompt_modes`。本版本迁移过的数据库，在恢复那份备份之前，不是 v2.9.0 的数据库。
