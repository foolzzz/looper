# Looper v2.13.89

## Release Decision

**Who should upgrade:** Anyone who calls `/api/providers` or its login-problem route from a script, or who adds, edits or deletes provider accounts or clicks "Use the login again" in the dashboard. Everyone else gets no change.

**What this release solves:** [#543](https://github.com/foolzzz/looper/pull/543) moves provider account and credential management onto operator-only versioned API operations and removes the five legacy provider routes.

**Breaking changes:** Yes. `GET /api/providers`, `POST /api/providers`, `PUT /api/providers/{id}`, `DELETE /api/providers/{id}` and `DELETE /api/providers/{id}/login-problem` are removed; a script that calls them must use `POST /api/v1/provider_accounts/list`, `/create`, `/update`, `/delete` or `/clear_login_problem`, and must authenticate as the operator, because API clients are refused. An update passes `{provider_id, fields}`, a delete and a login-problem clear `{provider_id}` in the body, and responses are wrapped in the v1 envelope (`result`). The dashboard shipped in this release already uses the new operations.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#543](https://github.com/foolzzz/looper/pull/543); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.89
```

## Behavior changes

- **New operations ([#543](https://github.com/foolzzz/looper/pull/543)):** the new `looper/agents/v1_domains/providers.py` registers `provider_accounts.list` (risk `read`), `.create`, `.update`, `.clear_login_problem` (risk `write`) and `.delete` (risk `high`, so it asks for confirmation) as `POST /api/v1/provider_accounts/...`, all with closed argument schemas. Create takes `name` and `vendor_type` plus optional `endpoints`, `env`, `max_concurrency` and `api_key`; update takes `{provider_id, fields}` with at least one of those fields. List returns `{providers}`, create and update `{provider, warnings}`, delete `{deleted}`.
- **Operator only, credential-safe:** every operation is declared `operator_only` and `credential_write`, so the server refuses API clients and the existing credential path skips argument and result audit and redacts failures. The operations call the existing `profile_registry` list, create, update, delete and clear-login-problem functions. Registry errors become generic answers: 404 "provider not found", 409 "provider account conflict" and 400 "invalid provider account request"; the earlier detailed validation text is no longer returned. In an update an omitted or `***` key keeps the stored one and `null` clears it.
- **Typed results:** the compact `providers.list`, `providers.register` and `providers.update` operations now publish closed, typed results in the OpenAPI document; the operations themselves are unchanged.
- **Removed routes:** the five legacy routes, the `_RE_PROVIDER` and `_RE_PROVIDER_LOGIN_PROBLEM` patterns and the `_handle_registry` helper are removed from `looper/agents/http_server.py`.
- **Dashboard:** `web/src/lib/api.ts` calls the v1 operations for create, update, delete and clear-login-problem. A pending-confirmation (HTTP 202) answer is raised as an `unavailable` error, and the registry-changed event fires after each. `web/src/components/provider-settings.tsx` uses the new `CreateProviderFields` type.
- **Tooling and docs:** the prompt regression evals (`evals/prompt_regression/dialogs.py`, `runner.py`) and `examples/pi/isolated-smoke.py` create providers through `/api/v1/provider_accounts/create`; `README.md`, `README.zh-CN.md` and `docs/architecture/agent-system.md` name the new operations.
- **Tests:** `tests/test_api_v1_provider_accounts.py` and `tests/test_api_v1_provider_accounts_db.py` were added; `tests/test_api_v1_document.py`, `web/src/components/provider-settings.test.tsx` and many existing tests were moved to the new operations.
- **Model-visible changes:** None found. Manager, Planner, Worker and Reviewer prompts, role recommended prompts and Tool declarations are unchanged; the compact `providers.*` operations that Manager tools use keep their contract, only their result schema is now published. The new `provider_accounts.*` operations are operator-only and appear only in the v1 operation catalog.
- **Not confirmed in code:** that `README.zh-CN.md` and the prose docs are fully free of the removed routes. This draft did not run any test.

## Upgrade and rollback

Re-run `install.sh` once v2.13.89 is published. No data migration; saved providers and credentials are untouched. Update any script that used the removed routes. Rolling back to v2.13.88 restores them together with the old dashboard.

### 行为变化与入口

- **新操作（[#543](https://github.com/foolzzz/looper/pull/543)）：**新增 `looper/agents/v1_domains/providers.py`，注册 `provider_accounts.list`（风险 `read`）、`.create`、`.update`、`.clear_login_problem`（风险 `write`）和 `.delete`（风险 `high`，需确认），路径为 `POST /api/v1/provider_accounts/...`，参数均为封闭对象。创建需 `name`、`vendor_type`，可选 `endpoints`、`env`、`max_concurrency`、`api_key`；更新传 `{provider_id, fields}`，至少带其中一个字段。列表返回 `{providers}`，创建与更新返回 `{provider, warnings}`，删除返回 `{deleted}`。
- **仅限操作员、凭据安全：**所有操作都声明为 `operator_only` 与 `credential_write`，服务器拒绝 API 客户端，并沿用现有凭据路径：不审计参数与结果，失败信息脱敏。操作调用已有的 `profile_registry` 列表、创建、更新、删除和清除登录问题函数。注册表错误变为通用应答：404“provider not found”、409“provider account conflict”、400“invalid provider account request”；不再返回此前详细的校验文本。更新时省略或传 `***` 保留已存密钥，`null` 清除。
- **类型化结果：**精简的 `providers.list`、`providers.register`、`providers.update` 操作现在在 OpenAPI 文档中发布封闭的类型化结果；操作本身未变。
- **移除的路由：**五条旧路由、`_RE_PROVIDER` 与 `_RE_PROVIDER_LOGIN_PROBLEM` 正则以及 `_handle_registry` 辅助函数已从 `looper/agents/http_server.py` 移除。
- **仪表盘：**`web/src/lib/api.ts` 用 v1 操作完成创建、更新、删除和清除登录问题。待确认（HTTP 202）的应答会作为 `unavailable` 错误抛出，每次成功后触发注册表变更事件。`web/src/components/provider-settings.tsx` 使用新的 `CreateProviderFields` 类型。
- **工具与文档：**提示回归评测（`evals/prompt_regression/dialogs.py`、`runner.py`）和 `examples/pi/isolated-smoke.py` 通过 `/api/v1/provider_accounts/create` 创建 Provider；`README.md`、`README.zh-CN.md` 和 `docs/architecture/agent-system.md` 改写为新操作。
- **测试：**新增 `tests/test_api_v1_provider_accounts.py` 与 `tests/test_api_v1_provider_accounts_db.py`；`tests/test_api_v1_document.py`、`web/src/components/provider-settings.test.tsx` 及许多现有测试已改用新操作。
- **面向模型的变化：**未发现。Manager、Planner、Worker、Reviewer 的 prompt、角色推荐 prompt 以及 Tool 声明均未改动；Manager 工具使用的精简 `providers.*` 操作契约不变，仅发布了结果 schema。新的 `provider_accounts.*` 操作仅限操作员，只出现在 v1 操作目录中。
- **代码中未确认：**`README.zh-CN.md` 与其他散文文档是否已完全不含被移除的路由。本草稿未运行任何测试。
