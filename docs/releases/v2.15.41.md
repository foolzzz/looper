# Looper v2.15.41

Contains all of [v2.15.40](v2.15.40.md) at `1d90572f1`, plus exactly [#1818](https://github.com/foolzzz/looper/pull/1818), frozen at `322834fb6`. No main or other branch is merged into this release. Release preparation adds only version, changelog and release files. Main has moved beyond the v2.15.40 freeze: after this pull request merges, the tag belongs on this release pull request's own head, not the main merge commit, as described in [the release procedure](README.md).

This is a source-upgrade build fix. Relative to v2.15.40 there is no product behavior change, migration or setting. All v2.15.40 and v2.15.39 capabilities and defaults are inherited. The release workflow rebuilds the dashboard from source; no generated bundle is committed here.

## Release Decision

**Who should upgrade:** Operators upgrading an installed Looper from a source ref, especially after a failed attempt to target v2.15.39 or v2.15.40. From v2.15.38 or earlier, upgrade straight to v2.15.41 and read both [v2.15.40](v2.15.40.md) and [v2.15.39](v2.15.39.md).

**What this release solves:** Source-ref upgrades failed while building the dashboard because a web test imported a shared fixture outside the exported `web/` directory. The build failed before the service stopped, so the running service was not affected. The unchanged fixture now lives in `web/`, shared by the web and Python tests, with a regression for source imports and file reads.

**Breaking changes:** No. Relative to v2.15.40, there is no product behavior change, migration or setting. Upgrades from v2.15.38 or earlier inherit v2.15.39's two startup migrations and breaking behavior changes described below. Installations older than the bridge must upgrade to v2.13.165 first and start once.

**How to verify:** After the normal upgrade to v2.15.41, check the version and that the dashboard loads. A source-ref upgrade should finish its dashboard build without the missing shared-fixture error. Existing Work and per-turn context settings retain their values. These are post-upgrade checks; the documentation check run here and the source PR's build evidence are distinguished under Validation.

```bash
looper --version   # looper 2.15.41
```

**Contributors:** Maintainer @foolzzz authored [#1818](https://github.com/foolzzz/looper/pull/1818); no community contribution was included in this release interval. Inherited contributor credit is in [v2.15.40](v2.15.40.md) and [v2.15.39](v2.15.39.md).

## Included changes

Only #1818 extends v2.15.40. The merged PRs #1803, #1806, #1807 and #1809 already ship through v2.15.40's two selected branch merges; they are inherited, not excluded or newly added here.

### Work console and task lifecycle

Unchanged from [v2.15.40](v2.15.40.md#included-changes): the optional Work console retains its lifecycle controls, pre-start requirement composition and presentation. Task conversations still use the Planner; the task Manager chain is not included.

### Runtime, delivery and dashboard fixes

- **[#1818](https://github.com/foolzzz/looper/pull/1818):** Fixes the dashboard build used by source-ref upgrades such as `looper service upgrade --to v2.15.39` or `looper service upgrade --to v2.15.40`. The upgrade exports `web/` and the component fingerprint helpers, without the repository's `tests/` directory. A web test's import from `tests/fixtures/attention-redaction.json` therefore failed TypeScript compilation before drain or service stop. The fixture moves unchanged to `web/src/test-fixtures/attention-redaction.json`; web and Python tests read that single copy. No runtime redaction logic changes. The running service was unaffected by this build failure, and installs from the published wheel are not affected.

### Internal foundations and tests

The same #1818 adds `tests/test_web_source_boundary.py`, scanning `web/src` imports and file reads for paths outside `web/`. It covers relative and alias imports, URL/path expressions and unresolved reads, with explicit, reasoned exceptions for existing dynamic manifest-icon and full-checkout documentation-parity test reads. Positive and negative controls exercise the file-read forms. This is build-boundary validation, not a runtime filesystem restriction.

## Upgrading from v2.15.38 or earlier

Upgrade straight to v2.15.41. It contains all of [v2.15.40](v2.15.40.md) and [v2.15.39](v2.15.39.md). The v2.15.39 notes list two startup migrations: `task_drafts` (2050, a constraint on the existing tasks table plus online validation) and `proactive_bodies` (2110, retained-body columns on proactive deliveries). Read [its upgrade requirements](v2.15.39.md#upgrading-from-v21537-or-earlier) for inherited backups, migrations and behavior changes, including proactive text retention independently of metrics. Neither v2.15.40 nor v2.15.41 adds a migration over v2.15.39.

**Known issue in v2.15.39 and v2.15.40:** Source-ref upgrades to those versions fail at the dashboard build before the service stops. Upgrade to v2.15.41 instead; the fix does not alter the older tags. Installs from the published wheel are not affected.

Disabling Work or per-turn context does not undo inherited schema changes or proactive retention. Keep the pre-migration backup for database downgrade; this release provides no down migration. Installations older than v2.13.165 must upgrade to v2.13.165 first and start once.

## Behavior changes

### Without a new switch

No product behavior change, migration or setting is introduced over v2.15.40. The only fix makes the existing source-ref dashboard build self-contained. All inherited behavior, including v2.15.39's two startup migrations and proactive-body retention, remains as documented in [v2.15.39](v2.15.39.md) and [v2.15.40](v2.15.40.md).

### When an existing switch is already on

Work and Manager per-turn context behave exactly as in v2.15.40. Their independent switches remain off by default; this build fix does not activate or change them.

## Entry points

- **Dashboard:** The exported source now builds without the missing test fixture. Dashboard product behavior and UI are unchanged.
- **Telegram and Lark:** No channel, command, prompt or transport change; no companion work is needed for this build-only fix.
- **CLI/API:** The existing source-ref service-upgrade path can complete its dashboard build. There is no new command, operation or setting; installs from the published wheel are unaffected.

### 升级决策

**谁需要升级：** 使用源码 ref 升级已安装 Looper 的操作者，尤其是升级到 v2.15.39 或 v2.15.40 时构建失败的安装。从 v2.15.38 或更早版本直接升级到 v2.15.41，并阅读 [v2.15.40](v2.15.40.md) 和 [v2.15.39](v2.15.39.md) 的说明。

**解决了什么：** 源码升级单独导出 `web/`，但一个前端测试从目录外导入共享 fixture，导致仪表盘构建失败；失败发生在停服前，运行中的服务不受影响。fixture 原样移入 `web/`，前端和 Python 测试共享同一份文件，新增源码导入与文件读取边界回归。

**是否有破坏性变更：** 无。相对 v2.15.40 不改变产品行为，不新增迁移或设置。从 v2.15.38 或更早升级仍继承 v2.15.39 的两项启动迁移与破坏性行为变化。早于桥接版本的安装需先升级到 v2.13.165 并启动一次。

**如何验证：** 正常升级到 v2.15.41 后核对版本并打开仪表盘；源码升级应完成仪表盘构建，不再报告缺少共享 fixture。已有工作台和每回合上下文设置保持原值。这些是升级后验证方法，本次实际运行的文档检查与源 PR 的构建证据在「验证」中分开说明。

```bash

```
