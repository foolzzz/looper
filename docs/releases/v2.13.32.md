# Looper v2.13.32

## Release Decision

**Who should upgrade:** No one needs this for runtime behavior. It matters to contributors and CI runs whose tests and the isolated Pi smoke script failed intermittently under load.

**What this release solves:** [#390](https://github.com/foolzzz/looper/pull/390) fixes the review follow-ups listed in #280. Timing-sensitive tests and the isolated Pi smoke script used waits and deadlines that raced subprocess start-up on a loaded machine. Those limits are widened, so the tests stop failing intermittently. No product code changed.

**Breaking changes:** No. No CLI command, configuration key, API shape or database schema changed, and nothing under `looper/` changed. The behavior change is listed below.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#390](https://github.com/foolzzz/looper/pull/390); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.32
```

## Behavior changes

- **Wider test and smoke timeouts:** `examples/pi/isolated-smoke.py` raises the wait for cancelled processes to be reaped from 15 s to 60 s and the fake-provider `communicate` timeout from 25 s to 120 s. Seventeen test files under `tests/` widen subprocess waits, runner and RPC deadlines and browser action timeouts: the planner worker time-limit test, the DSH runtime, installed and validation tests, the LLM models dashboard flow, the model launch capture and parity tests, the model manager dialogs, the operator token launch test, the Pi eval, packaging, platform tools, runtime, smoke and turn binding tests, the room consult test and the run channel test. Only limits changed; no assertion was added or removed. The smoke script is a development tool and is not part of the installed package.
- **Product behavior:** None. No file under `looper/` changed.
- **Model-visible changes:** None. No prompt text, tool schema or tool result changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.32 is published. There is no schema or configuration change. Rolling back to v2.13.31 is safe; the only difference is the tighter test limits.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**运行时行为无需升级。仅对在高负载下测试或隔离 Pi 冒烟脚本偶发失败的贡献者和 CI 有意义。

**解决了什么：**[#390](https://github.com/foolzzz/looper/pull/390) 处理 #280 列出的评审后续项。对时序敏感的测试和隔离 Pi 冒烟脚本使用的等待与截止时间，在负载较高时会与子进程启动竞争。现已放宽这些限制，测试不再偶发失败。产品代码未改动。

**是否有破坏性变更：**无。CLI、配置项、API 形态、数据库 schema 均未变化，`looper/` 下没有任何改动，行为变化见下文。

**如何验证：**运行 `looper --version` 核对版本为 2.13.32。

**贡献者：**维护者 @foolzzz 提交 [#390](https://github.com/foolzzz/looper/pull/390)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.32
```

### 行为变化与入口

- 放宽测试与冒烟脚本的超时：`examples/pi/isolated-smoke.py` 将等待被取消进程回收的时间从 15 秒放宽到 60 秒，将 fake-provider 的 `communicate` 超时从 25 秒放宽到 120 秒。`tests/` 下 17 个测试文件放宽了子进程等待、runner 与 RPC 截止时间以及浏览器操作超时，涉及 planner worker 时限、DSH 运行时/安装/验证、LLM 模型仪表盘流程、模型启动捕获与对等、模型管理对话框、operator token 启动、Pi eval/打包/平台工具/运行时/冒烟/回合绑定、room consult 和 run channel 测试。只改了限制值，没有增删断言。冒烟脚本是开发工具，不在安装包内。
- 产品行为：无。`looper/` 下没有文件改动。
- 面向模型的变化：无。提示词文本、工具 schema、工具结果均无变化。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.31 安全；区别仅是测试限制恢复为更紧的值。
