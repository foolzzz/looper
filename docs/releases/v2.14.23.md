# Looper v2.14.23

This is the patch release v2.14.23. It ships the one change merged since v2.14.22: [#920](https://github.com/foolzzz/looper/pull/920), which hardens startup failures of the Pi and DSH SDK runners.

## Release Decision

**Who should upgrade:** Anyone running Pi or DSH profiles, which default to their SDK runners, especially where Node is missing, too old or 23.0 to 23.5, or a runner fails to start. It ships the one change merged since v2.14.22.

**What this release solves:** [#920](https://github.com/foolzzz/looper/pull/920) (issue #917): a runner adapter that cannot be built no longer stops `looper serve`, and runner start failures name their cause and the `[runtimes]` `"cli"` opt-out. A cancelled cold start no longer consumes the crash budget.

**Breaking changes:** No. No database schema, stored data, API or default changes. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#920](https://github.com/foolzzz/looper/pull/920); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.23
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.22 upgrades directly. This release changes no database schema or stored data.

## Behavior changes

- **Adapter construction cannot stop startup** (`looper/agents/runtimes/pi_runner.py`, `dsh_runner.py`): building the supervisor now happens inside the guarded block, and `RuntimeUnsupported`, `OSError` and `ValueError` become an unavailable adapter carrying the reason and the opt-out. Before, the Pi supervisor was built outside any guard.
- **Node checks report the real cause** (`pi_runner.py`, `dsh_runner.py`): only a timeout of `node --version` reports "did not finish within 2 seconds"; any other failure reports its own error. Node 23.0 to 23.5 is rejected with "Node 23.0–23.5 cannot run the runner (use 22.19+ or 23.6+)"; 22.19+ and 23.6+ are accepted as before.
- **Failure causes are kept** (`looper/agents/runtimes/runner/supervisor.py`): the supervisor remembers the last failure. When five failures within ten minutes close the kind, the error appends "; last failure: <cause>". A runner that exits records its cause (redacted, single line, at most 512 characters) with the same startup wording.
- **Cancelled cold start is free** (`supervisor.py`): a cancellation during a start disposes the half-started member and re-raises; if the handshake had already succeeded, the unused member is retired without adding to the failure count.
- **Docs and ops file**: `docs/architecture/agent-system.md` and the `looper/ops_config.py` comments (also the text `looper config init-ops` writes) now describe the runner default, the `"cli"` opt-out, 32 session slots per runner and up to four runners per kind (128 slots). The documented limits match the existing code (`SESSION_CAP = 32`); no limit changed.
- **Tests**: `tests/test_runner_startup_failures.py` (new, 163 lines) and `tests/test_runner_supervisor.py` (104 added lines) cover the change.
- **Model-visible changes:** None. Only operator-facing startup and error messages change.

**是否有破坏性变更：**否。不改数据库 schema、已存数据、API 或默认值。受支持的升级路径不变（见升级）。

**如何验证：**运行 `looper --version` 核对版本为 2.14.23。

**贡献者：**维护者 @foolzzz 提交 [#920](https://github.com/foolzzz/looper/pull/920)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.23
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.22 上的安装可直接升级。本版本不改数据库 schema 或已存数据。

### 行为变化与入口

- **构建适配器不会阻止启动**（`pi_runner.py`、`dsh_runner.py`）：supervisor 的构建现在处于受保护的代码块内，`RuntimeUnsupported`、`OSError`、`ValueError` 会变成带原因和退出方式的不可用适配器。此前 Pi 的 supervisor 在保护之外构建。
- **Node 检查报告真实原因**（`pi_runner.py`、`dsh_runner.py`）：只有 `node --version` 超时才报告“未在 2 秒内完成”，其他失败报告各自的错误。Node 23.0 至 23.5 会被拒绝（“Node 23.0–23.5 cannot run the runner”）；22.19+ 与 23.6+ 照旧可用。
- **保留失败原因**（`looper/agents/runtimes/runner/supervisor.py`）：supervisor 记住最近一次失败。十分钟内五次失败而关闭该类型时，错误追加“; last failure: <原因>”。runner 退出时记录其原因（已脱敏、单行、最多 512 字符），措辞与启动失败一致。
- **取消的冷启动不计入崩溃**（`supervisor.py`）：启动期间被取消时，释放未完成的成员并重新抛出取消；若握手已成功，则退役该未使用成员，不增加失败计数。
- **文档与 ops 文件**：`docs/architecture/agent-system.md` 与 `looper/ops_config.py` 的注释（也是 `looper config init-ops` 写出的文字）现在描述 runner 默认值、`"cli"` 退出方式、每个 runner 32 个会话槽、每种类型最多四个 runner（128 槽）。文档所述上限与现有代码（`SESSION_CAP = 32`）一致，未改变任何限制。
- **测试**：`tests/test_runner_startup_failures.py`（新增 163 行）与 `tests/test_runner_supervisor.py`（新增 104 行）覆盖该改动。
- **面向模型的变化：**无。只有面向运维的启动与错误信息变化。
