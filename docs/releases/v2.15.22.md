# Looper v2.15.22

This release documents the changes merged since v2.15.21. Message leads and intent recognition can now run ([#1456](https://github.com/foolzzz/looper/pull/1456), [#1460](https://github.com/foolzzz/looper/pull/1460), [#1461](https://github.com/foolzzz/looper/pull/1461), [#1457](https://github.com/foolzzz/looper/pull/1457), [#1458](https://github.com/foolzzz/looper/pull/1458), [#1462](https://github.com/foolzzz/looper/pull/1462), [#1465](https://github.com/foolzzz/looper/pull/1465)). The default Manager can keep a ledger ([#1451](https://github.com/foolzzz/looper/pull/1451)). A project can turn on the advisor ([#1439](https://github.com/foolzzz/looper/pull/1439), [#1441](https://github.com/foolzzz/looper/pull/1441)). The Message stream page can exclude chats, apply retention and delete stored messages ([#1449](https://github.com/foolzzz/looper/pull/1449)). A bridge pass whose writer session is terminated now ends as a failed pass ([#1466](https://github.com/foolzzz/looper/pull/1466), fixes [#1448](https://github.com/foolzzz/looper/issues/1448)). Gathering task ends into one completion window (CompletionService, [#1463](https://github.com/foolzzz/looper/pull/1463)) is not in this release. The completion turn from v2.15.21 is unchanged.

## Release Decision

**Who should upgrade:** Anyone who will turn on message leads, intent recognition, the Manager ledger tools, or a project's advisor, or who manages stored messages on the Message stream page. An installation that does none of these keeps its schedules, prompts and tool lists. Two changes apply with no new setting: every agent process now carries `LOOPER_AGENT_RUN`, and a terminated bridge writer ends as a failed pass instead of leaking an asyncpg error. Startup applies additive migrations. The dashboard bundle is rebuilt by the release workflow as usual.

**What this release solves:** An operator can extract sourced leads and actionable intents, search leads from the command line and from the operator's own Manager turns, and answer intents with 建 and 驳回. A project can ask the advisor before a critical step. The default Manager can record what is waiting for the user, once the ledger is on. Stored messages can be excluded, retained and deleted without a later import putting the deleted ones back.

**Breaking changes:** No. No API or schedule that exists today changes its result. A push subscription is unchanged, including one with no rules that reads only groups and topics. There are additive PostgreSQL migrations (see Upgrading). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.22
```

**Contributors:** Maintainer @foolzzz authored [#1458](https://github.com/foolzzz/looper/pull/1458), [#1456](https://github.com/foolzzz/looper/pull/1456), [#1466](https://github.com/foolzzz/looper/pull/1466), [#1457](https://github.com/foolzzz/looper/pull/1457), [#1465](https://github.com/foolzzz/looper/pull/1465), [#1449](https://github.com/foolzzz/looper/pull/1449), [#1461](https://github.com/foolzzz/looper/pull/1461), [#1462](https://github.com/foolzzz/looper/pull/1462), [#1467](https://github.com/foolzzz/looper/pull/1467), [#1441](https://github.com/foolzzz/looper/pull/1441), [#1439](https://github.com/foolzzz/looper/pull/1439), [#1451](https://github.com/foolzzz/looper/pull/1451) and [#1460](https://github.com/foolzzz/looper/pull/1460); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.21 upgrades directly. Restart the service after upgrading, as for every release. `web/` changed, so the release workflow rebuilds the dashboard bundle from `web/` into the wheel, as usual. This pull request does not commit that bundle.

This release has additive PostgreSQL migrations, applied once at startup. They write no lead, intent, consult or deletion row. This release adds no online schema step. A database that has not yet finished `run_tree_online` or `step_difficulty_online` still runs those steps, unchanged from v2.15.21.

- `project_advisor`: adds nullable columns on `projects`: `advisor` (`off` or `on`), `advisor_consult_budget_usd` (0.01 to 5), `advisor_budget_usd` (0.01 to 50), `advisor_consults_per_task` (0 to 100), `advisor_consults_per_step` (0 to 10), `advisor_fallback_profile` (1 to 200 characters) and `advisor_internal_domains` (at most 20). No project row is rewritten. Unset means off, 1 USD for one consult, and no limit on the task total or the consult counts.
- `message_stream_deletions`: adds `event_sources.retention_last_at` and `source_runs.skipped_by_deletion` (bigint, default 0); creates `source_deletions` (`scope` `message`, `range` or `chat`, with `message_id`, `chat_id`, `start_at`, `end_at`) and indexes `idx_source_deletions_source`, `idx_source_deletions_message` and `idx_source_deletions_chat`. The migration does not rebuild indexes on `source_events`.

Startup also inserts, if they are absent, the model `claude-sonnet-5-5` and the built-in profile `claude-code/sonnet-5-5` (the `advice_check` judge). The advisor profile remains `claude-code/fable-5-2` on `claude-fable-5-2` with effort `high`. An existing profile of either name is left as it is. A database upgraded from v2.15.21 keeps `claude-code/haiku-5-5`; that profile is no longer the built-in judge.

## Behavior changes

### Message leads and intents, off until each switch is on ([#1456](https://github.com/foolzzz/looper/pull/1456), [#1460](https://github.com/foolzzz/looper/pull/1460), [#1461](https://github.com/foolzzz/looper/pull/1461), [#1457](https://github.com/foolzzz/looper/pull/1457), [#1458](https://github.com/foolzzz/looper/pull/1458), [#1465](https://github.com/foolzzz/looper/pull/1465))

- **Two switches, both off.** `leads.enabled` and `intents.enabled` are on only when the stored value is `true`. No row is off. While leads are off, nothing is extracted, the default Manager's tool list, system prompt and process signature stay as in v2.15.21, and the Message stream page has no 线索 tab. `looper leads search` and `mark` exit 3. Settings, `delete`, and excluding a chat while deleting what was extracted stay available. While intents are off, nothing is extracted or pushed, `建` and `驳回` are not taken before the model, and the sidebar has no Intents entry. Configuration and read operations for intent types stay available. Turning a switch off disables that kind's subscriptions in the same transaction and names them in the dashboard confirm dialog. Turning it back on does not enable those subscriptions.
- **What an operator turns on.** Settings → Roles, on the processor role, shows 消息线索 (有效天数, 1 to 365, default 90) and 意图识别. Create a subscription from the preset (`schedule_admin.subscription_preset`, or the 消息线索 / 意图识别 buttons on the subscription form), enable it, and confirm it. The leads preset is named 消息线索, cron `7 * * * *`, 0.6 USD a run and 10 USD a day. The intents preset is named 意图识别, cron `*/10 * * * *`, 0.3 USD and 3 USD. Both take 500 events, seven days, 500 characters a message, quiet word `NONE`. The Manager's `looper_schedules` refuses either kind. `output_kind` cannot be changed later. A form that was not filled from a preset still omits `output_kind`.
- **Confirmation.** A leads subscription is confirmed with no push target. An intents subscription needs a direct chat, and the private-target guard applies: the target must be the operator's own Lark direct chat, the user its message source is bound to. A group is refused. Rules, `window` `lookback` and `delivery_policy` `daily` are refused for both kinds. Until the subscription is confirmed, a firing is `skipped_gate` (`not confirmed`), no processor starts and the cursor stays. The same happens while that kind's switch is off. Changing the chat lists, the rule, the zone, the source or the processor Profile clears the confirmation.
- **What extraction reads.** Chats included in the stream and included for extraction (`source_chats.inclusion` and `source_chats.extraction` both `included`), the subscription's own include and exclude lists, not Looper's own apps, not imports. Leads read every person's message. Intents read a person's direct-chat message, a message that @-mentions the user, a message the user sent, and the alert bots in `intent_alert_senders`. The scope is fixed by the kind. The stream filter's chat kinds and sender kinds are not what it reads. A full window fires again at once, at most six times. Storing drops an item whose chat was excluded from the stream or from extraction while the processor ran (`chat_excluded`).
- **Backfill.** `looper msgflow leads-backfill --days 30` counts the leads subscription's in-scope events for the last 30 days and writes nothing. It runs only when `--run --budget-usd` is also given. One runner per subscription holds an advisory lock. A second runner exits 1.
- **Cost labels** say the unit prices were measured on 2026-11-20: about 0.005–0.008 USD a run plus about 0.0002 USD an event ([#1465](https://github.com/foolzzz/looper/pull/1465)). The prices themselves are unchanged from the extraction runs.
- **Search.** `looper leads search` reads the database with the service running or stopped. `mark --inaccurate` refuses a promoted lead. Invalid arguments exit 2 before the database is opened. Inside an agent process (`LOOPER_AGENT_RUN` set) every leads command exits 4, including a read. The default Manager's `looper_leads_search` exists only while leads are on, only for the default Manager, and only on an operator turn: the dashboard chat with no API client, or a direct chat whose sender is that bot's `operator_sender_id` (Settings → Channels, My ID, one id from that bot's allowlist). A group, another sender, an API client, a bot with no My ID, and a turn the model runs on its own are `forbidden`. A group reply that repeats 16 letters and digits from a summary returned in the last 24 hours is replaced and not sent. A Manager on the DSH runtime does not get this tool ([#1462](https://github.com/foolzzz/looper/pull/1462), docs only).
- **Intents.** Pushes go to the confirmed operator direct chat about every 10 seconds. Expiry is checked about every 5 minutes. `建 I-NNNN` and `驳回 I-NNNN`, or the same words quoting a push, are handled in code before the model, for the operator only. A task is created and started only after that confirmation. Task notices stay in the operator's direct chat. The Intents page (`#intents`) lists pending intents, builds and rejects them, and edits types, chat bindings and alert senders. The sidebar entry Intents 意图 is shown only while intent recognition is on.

### Manager ledger, off ([#1451](https://github.com/foolzzz/looper/pull/1451))

- **`ledger.enabled` defaults off.** No row, or any value other than `true`, leaves it off. There is still no dashboard switch and no HTTP write. While it is off, the Manager's tool list, prompt and command line do not mention the ledger. `looper ledger` exits 3. The two read operations answer `conflict`.
- **While it is on,** the default Manager gains `looper_ledger_add` and `looper_ledger_update` (list, get, confirm, amend, note, close, cancel, reopen). A scenario Manager does not. Who is speaking comes from the turn: the dashboard chat is the user; a direct chat is the user only when the sender is that bot's My ID; a group, an API client, another sender and an unset My ID are relayed. A turn the model runs on its own can read and cannot write. Gates, tasks that were not made by a schedule, and Manager questions that need confirmation are registered after their own write. A reconciler runs on the first tick after the ledger is turned on and then about every 5 minutes.
- **Visible with the ledger off.** Every agent process now carries `LOOPER_AGENT_RUN` set to its role, or `agent` when the launch has no role. The variable is not shown to the model. `looper ledger` writes, and `looper leads`, refuse when it is set (exit 4).

### Advisor phase 1, off until a project turns it on ([#1439](https://github.com/foolzzz/looper/pull/1439), [#1441](https://github.com/foolzzz/looper/pull/1441))

- **The project switch `advisor` defaults off.** Unset is off. Nothing consults, and the Planner prompt, DECISION messages, contract refusals and the Worker's first turn stay as they were. Settings → Roles now lists Advisor and Advice check. Advice check's built-in profile is `claude-code/sonnet-5-5` (model `claude-sonnet-5-5`). Advisor's is `claude-code/fable-5-2` (model `claude-fable-5-2`, effort `high`). A saved role layer that already names a profile is left as it is. The fallback profile is stored and unused. Internal domains, at most 20, are used by the request checks when set.
- **While a project sets `advisor` to `on`.** Before the first Worker of a step the plan marks `critical`, a DECISION may only ask for a `plan_review`. If that consult returns no answer, the step starts as planned. After a failed Worker or review the Planner may advise. The decision after an answer must carry `advice_adoption`. One consult defaults to 1 USD. The task's total and the consult counts have no limit until the project sets them. The code check's `dangling` rule allows a file name inside a quoted command (a backtick span that contains whitespace). A file name alone in backticks is still dangling when no artifact shows it.
- **The dashboard.** A consult is a dashed node on the Pipeline and a card on the task page. A step that is `consulting` reads 请教中. A checkpoint that ended without an answer is marked 检查点请教未完成. With the advisor on, the task's final summary gains an `## Advisor` line. `runs.for_task` rows add `kind` and `parent_record_id`. Tasks with no consults still omit the `advisor` key.

### Message stream page ([#1449](https://github.com/foolzzz/looper/pull/1449))

- **No source is created or enabled on its own.** Prompts, tools and launch arguments are unchanged.
- **Excluding a chat** (inclusion) stops later ingestion of that chat and removes it from every later subscription selection, push and extraction. **Excluding a chat from extraction** (`source_chats.extraction`, default `included`) leaves it in the stream and in push subscriptions, and leaves it out of leads and intents runs. The first exclusion time is kept until the chat is included again. Excluding with deletion removes that chat's leads and non-tasked intents. Messages stay. An intent merged in from another chat returns to `pending`.
- **Deletion** of one message, a half-open sent-time range, or a whole chat writes a `source_deletions` tombstone. A whole-chat deletion erases the events and the chat name and cannot be included again. Dry-run and real imports skip tombstoned rows and count them as `skipped_by_deletion`. A range end in the future is refused. The preview token lasts 10 minutes or until restart. Deletion does not reach pushed output, processor output, older upgrade backups, the newest 7 daily message backups, or the collector's own files.
- **Retention** of raw bodies runs daily, including a source whose ingestion is off. Human raw bodies stay unlimited unless a policy says otherwise. Bot raw bodies default to 30 days. The message text stays.
- An older version ignores tombstones. Its next import can put deleted messages and ranges back from collector files that still have them. A chat deleted as a whole stays excluded. Rolling back does not restore erased rows.

### Bridge pass ([#1466](https://github.com/foolzzz/looper/pull/1466))

A bridge pass whose writer session is terminated now ends as a failed pass. The committed sequence stays consistent, and the next pass resumes. Previously the detached pooled connection raised an asyncpg interface error out of the pass. Sources remain off until one is configured. The dashboard, Telegram, Lark and the CLI need no change.

## Optional Capability Activation & Use

### Message leads

**Activation:** Off until `leads.enabled` is `true` and a leads subscription has been created from the preset, enabled and confirmed. Set the switch under Settings → Roles, on the processor role (消息线索). There is no environment variable. Create the subscription with `schedule_admin.subscription_preset` for `output_kind` `leads`, or with the 消息线索 button, then confirm it. A leads subscription needs no push target. `looper msgflow leads-backfill --days 30` only counts events. It writes rows only with `--run` and `--budget-usd`. The 线索 tab on Message stream appears only while the switch is on.

**Validation:** With the switch absent, `looper leads search` exits 3 and the Message stream page has no 线索 tab. After the switch is on, a preset subscription is confirmed, and a firing with in-scope events ends `extracted` with rows in `message_leads`. A dry-run backfill prints a count and an estimate dated 2026-11-20 and leaves the tables unchanged. The operator's own dashboard turn can call `looper_leads_search`. A group turn cannot.

**Disable / rollback:** Turn 消息线索 off. The confirm dialog names the leads subscriptions, and those subscriptions are disabled. Turning the switch on again does not enable them. `search` and `mark` refuse again. Rows already stored stay until an operator deletes them. The leads tables are from v2.15.21 and are not dropped.

**Authority boundary:** The operator, or the operator API, manages leads. An API client cannot call the leads operations. The default Manager can search only on the operator's own turn, and the audit row keeps ids and a count, not the text. A group reply that repeats a returned summary is withheld. `looper leads` exits 4 when `LOOPER_AGENT_RUN` is set. Extraction runs with no tools. Logs carry ids and drop reasons, not message text.

**Docs:** https://github.com/foolzzz/looper/blob/v2.15.22/docs/architecture/agent-system.md#message-leads

```bash
looper msgflow leads-backfill --days 30
```

### Intent recognition

**Activation:** Off until `intents.enabled` is `true` and an intents subscription has been created from the preset, enabled and confirmed. Set the switch under Settings → Roles, on the processor role (意图识别). The preset button is 意图识别. Confirmation requires the operator's own Lark direct chat, because the private-target guard applies to intents. Rules, a lookback window and a daily delivery are refused. The sidebar entry Intents 意图 appears only while the switch is on. Set My ID on the bot (Settings → Channels) so a direct-chat sender is recognized as the operator. Answer a push with `建 I-NNNN` or `驳回 I-NNNN`.

**Validation:** With the switch absent, a firing is `skipped_gate` and nothing is pushed. After confirmation, an in-scope window can store `pending` intents, and a push reaches only the confirmed direct chat. `建` creates and starts one task. A group target is refused at confirm time. Turning the switch off disables the intents subscriptions and stops delivery.

**Disable / rollback:** Turn 意图识别 off. The dialog names those subscriptions and disables them. Turning the switch on again does not enable them. Pending intents stay stored. `建` and `驳回` are no longer taken before the model. The intent tables are from v2.15.21 and are not dropped.

**Authority boundary:** Only the operator's own turn, checked by code, can build or reject. Preparation reads. Creating the task, rejecting and editing the push happen after the stop check. Task notices stay in the operator's direct chat. The processor has no tools. A Manager cannot create the subscription.

**Docs:** https://github.com/foolzzz/looper/blob/v2.15.22/docs/architecture/agent-system.md#intents

```bash
loopercli schedule-admin confirm-target --schedule-id SCHEDULE_ID --config-version CONFIG_VERSION
```

### Manager ledger

**Activation:** Off until the system setting `ledger.enabled` is `true`. No row, or any other value, leaves it off. This release still has no dashboard switch and no HTTP write for that setting. Set My ID (Settings → Channels, one allowlisted sender) before treating a direct-chat sender as the user. Until the setting is `true`, the default Manager does not list `looper_ledger_add` or `looper_ledger_update`, and `looper ledger` exits 3.

**Validation:** With the setting absent, the Manager's tool list matches v2.15.21 and `looper ledger list` exits 3. With `ledger.enabled` set to `true`, the default Manager lists the two tools, a dashboard turn can add an item, and `looper ledger list` exits 0 when items exist and 1 when the open list is empty. A group sender is relayed. An agent process still cannot write through `looper ledger` (exit 4), because `LOOPER_AGENT_RUN` is set.

**Disable / rollback:** Delete `ledger.enabled`, or set it to any value other than `true`. The tools leave the default Manager on its next listing, and the command exits 3 again. Items already stored stay. The ledger tables are from v2.15.19 and are not dropped. `LOOPER_AGENT_RUN` stays set on agent processes either way.

**Authority boundary:** The only writer is `db.ledger.apply`. The CLI write is the user, via `cli`, and needs `--session`. It is refused when `LOOPER_AGENT_RUN` is set. Confirming or closing can point only at a user event. A relayed sender can add an item and a note, and cannot confirm or close. The Manager tools are only the default Manager's. Reads are the operator, an API client, or those tools. No prompt mentions the ledger while it is off.

**Docs:** https://github.com/foolzzz/looper/blob/v2.15.22/docs/architecture/agent-system.md#the-ledger

```bash
looper ledger list
```

### Advisor

**Activation:** Off until a project's `advisor` is `on`. Unset is off. There is no system-wide switch. Set it in the project's settings, with the limits left empty for the defaults: 1 USD for one consult, and no limit on the task total or the consult counts. The fallback profile is unused. Nothing consults in a project that leaves the switch off. The judge runs `claude-code/sonnet-5-5` (`claude-sonnet-5-5`) unless Settings → Roles selects another Advice check profile. The advisor runs `claude-code/fable-5-2` (`claude-fable-5-2`, effort `high`) unless its role layer selects another.

**Validation:** With the switch off, a task page has no consult nodes and no `## Advisor` line, and the Planner prompt does not offer `advise`. With the switch on, a critical step asks for a `plan_review` before its first Worker, and the Pipeline shows the consult. A request that only names a file inside a quoted command passes the dangling check. A file name that no artifact shows, outside such a command, is sent back.

**Disable / rollback:** Set the project's `advisor` back to `off`, or clear it. Later tasks do not consult. Consults already stored remain on their task pages. The columns from `project_advisor` stay. The seeded profiles stay. A role layer that selected a profile keeps that selection.

**Authority boundary:** Only the Planner of a project with `advisor` on can open a consult. The advisor and the judge run with no tools, on the request the code already checked. The Worker receives the points the Planner adopted, not the advisor's own text. Internal domains and registered secrets are removed by the checks. No channel command turns the switch on.

**Docs:** https://github.com/foolzzz/looper/blob/v2.15.22/docs/architecture/agent-system.md#consults-of-the-advisor

```bash
looper --version
```

## 中文摘要

本版本说明自 v2.15.21 以来合并的改动。消息线索和意图识别可以运行（[#1456](https://github.com/foolzzz/looper/pull/1456)、[#1460](https://github.com/foolzzz/looper/pull/1460)、[#1461](https://github.com/foolzzz/looper/pull/1461)、[#1457](https://github.com/foolzzz/looper/pull/1457)、[#1458](https://github.com/foolzzz/looper/pull/1458)、[#1462](https://github.com/foolzzz/looper/pull/1462)、[#1465](https://github.com/foolzzz/looper/pull/1465)）。默认 Manager 可以记账（[#1451](https://github.com/foolzzz/looper/pull/1451)）。项目可以打开 advisor（[#1439](https://github.com/foolzzz/looper/pull/1439)、[#1441](https://github.com/foolzzz/looper/pull/1441)）。消息流页面可以排除会话、做保留期和删除已存消息（[#1449](https://github.com/foolzzz/looper/pull/1449)）。写入会话被终止的桥接轮次现在以失败结束（[#1466](https://github.com/foolzzz/looper/pull/1466)，修复 [#1448](https://github.com/foolzzz/looper/issues/1448)）。把多次任务结束收成一个完成窗口（CompletionService，[#1463](https://github.com/foolzzz/looper/pull/1463)）不在本版本。v2.15.21 的收尾回合不变。

### 升级决策

**谁需要升级：**要打开消息线索、意图识别、Manager 账本工具或项目 advisor 的安装，以及要在消息流页面管理已存消息的安装。这些都不做的安装，其定时任务、提示词和工具列表保持原样。没有新开关也会变的有两处：每个 agent 进程都带上 `LOOPER_AGENT_RUN`；桥接的写入会话被终止时，这一轮以失败结束，不再把 asyncpg 错误漏出去。启动时会执行可加的迁移。仪表盘包由发布流程照常重新构建。

**解决了什么：**操作员可以抽取有来源的线索和可执行的意图，用命令行和操作者本人的 Manager 回合检索线索，并用「建」和「驳回」处理意图。项目可以在关键步骤之前请教 advisor。账本打开之后，默认 Manager 可以记下等用户处理的事项。已存消息可以排除、按保留期清理和删除，之后的导入不会把删掉的再写回来。

**是否有破坏性变更：**无。今天已有的 API 和定时任务的结果不变。推送订阅不变，包括没有规则、只读群和话题的订阅。有可加的 PostgreSQL 迁移（见升级）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.15.21 上的安装可直接升级。升级后照常重启服务。`web/` 有改动，发布流程会照常从 `web/` 重新构建仪表盘包并放进 wheel。本拉取请求不提交这份包。

本版本有可加的 PostgreSQL 迁移，启动时执行一次。它们不写线索行、意图行、请教行或删除行。本版本没有新的在线 schema 步骤。还没做完 `run_tree_online` 或 `step_difficulty_online` 的库仍会跑这两步，与 v2.15.21 相同。

- `project_advisor`：给 `projects` 增加可空列 `advisor`（`off` 或 `on`）、`advisor_consult_budget_usd`（0.01 到 5）、`advisor_budget_usd`（0.01 到 50）、`advisor_consults_per_task`（0 到 100）、`advisor_consults_per_step`（0 到 10）、`advisor_fallback_profile`（1 到 200 个字符）和 `advisor_internal_domains`（最多 20 个）。不改写已有项目行。未设置时为关闭；单次请教 1 美元；任务总额和请教次数不设上限。
- `message_stream_deletions`：给 `event_sources` 增加 `retention_last_at`，给 `source_runs` 增加 `skipped_by_deletion`（bigint，默认 0）；创建 `source_deletions`（`scope` 为 `message`、`range` 或 `chat`，含 `message_id`、`chat_id`、`start_at`、`end_at`）以及索引 `idx_source_deletions_source`、`idx_source_deletions_message` 和 `idx_source_deletions_chat`。这次迁移不重建 `source_events` 上的索引。

启动时若还没有，会插入模型 `claude-sonnet-5-5` 和内置 Profile `claude-code/sonnet-5-5`（`advice_check` 的判别）。advisor 的 Profile 仍是 `claude-code/fable-5-2`，模型 `claude-fable-5-2`，effort 为 `high`。同名的已有 Profile 保持原样。从 v2.15.21 升级的库会留下 `claude-code/haiku-5-5`；它不再是内置的判别 Profile。

### 行为变化

**消息线索和意图，两个开关都要打开（[#1456](https://github.com/foolzzz/looper/pull/1456)、[#1460](https://github.com/foolzzz/looper/pull/1460)、[#1461](https://github.com/foolzzz/looper/pull/1461)、[#1457](https://github.com/foolzzz/looper/pull/1457)、[#1458](https://github.com/foolzzz/looper/pull/1458)、[#1465](https://github.com/foolzzz/looper/pull/1465)）**

- **两个开关，默认都关。**`leads.enabled` 和 `intents.enabled` 只有存的值是 `true` 才算打开。没有这一行就是关。线索关闭时不抽取；默认 Manager 的工具列表、系统提示词和进程签名与 v2.15.21 相同；消息流页面没有「线索」标签。`looper leads search` 和 `mark` 退出码为 3。设置、`delete`，以及排除会话并删掉已抽取内容，仍然可以。意图关闭时不抽取、不推送，「建」和「驳回」不会在模型之前被接住，侧栏没有 Intents 入口。意图类型的配置和读取仍可用。关掉一个开关会在同一事务里停用该种类的订阅，仪表盘的确认框会列出它们的名字。再打开不会把这些订阅重新启用。
- **操作员要做的。**Settings → Roles 里 processor 角色下有「消息线索」（有效天数 1 到 365，默认 90）和「意图识别」。用预设创建订阅（`schedule_admin.subscription_preset`，或订阅表单上的「消息线索」「意图识别」按钮），启用，然后确认。线索预设名叫「消息线索」，cron 为 `7 * * * *`，单次 0.6 美元、每天 10 美元。意图预设名叫「意图识别」，cron 为 `*/10 * * * *`，单次 0.3 美元、每天 3 美元。两者都是 500 条、七天、每条 500 字、静默词 `NONE`。Manager 的 `looper_schedules` 拒绝这两种。之后不能再改 `output_kind`。不是从预设填出来的表单仍然不带 `output_kind`。
- **确认。**线索订阅不需要推送目标就能确认。意图订阅必须是私聊，并且私密目标守卫适用：目标必须是操作员自己的飞书私聊，即该消息来源所绑定的用户。群会被拒绝。两种订阅都拒绝规则、`window` 为 `lookback` 和 `delivery_policy` 为 `daily`。确认之前，一次触发是 `skipped_gate`（`not confirmed`），不启动 processor，游标不动。该种类的开关关闭时也一样。改会话列表、时间规则、时区、来源或 processor 的 Profile 会清掉确认。
- **抽取读什么。**流里包含、并且抽取也包含的会话（`source_chats.inclusion` 和 `source_chats.extraction` 都是 `included`），加上订阅自己的包含和排除列表；不含 Looper 自己的应用，不含导入。线索读所有人的消息。意图读私聊里别人的消息、@用户的消息、用户自己发的消息，以及 `intent_alert_senders` 里的告警机器人。范围由种类决定。流筛选里的会话类型和发送者类型不决定它读什么。窗口满了会立刻再触发，连续最多六次。processor 还在跑时，会话被排除出流或排除出抽取，这条结果会被丢掉（`chat_excluded`）。
- **回填。**`looper msgflow leads-backfill --days 30` 只数这条线索订阅最近 30 天范围内的事件，不写行。只有同时给出 `--run` 和 `--budget-usd` 才会跑。每个订阅同时只有一个运行者，持有咨询锁。第二个退出码为 1。
- **费用标注**写明单价在 2026-11-20 测得：每次运行约 0.005–0.008 美元，每条事件约 0.0002 美元（[#1465](https://github.com/foolzzz/looper/pull/1465)）。价格本身与抽取运行时相同。
- **检索。**`looper leads search` 在服务开着或停着时都直接读库。`mark --inaccurate` 拒绝已晋升的线索。非法参数在打开数据库之前以退出码 2 返回。agent 进程里（已设置 `LOOPER_AGENT_RUN`）三条线索命令都是退出码 4，包括读取。默认 Manager 的 `looper_leads_search` 只在线索打开时、只给默认 Manager、只在操作者本人的回合里：没有 API 客户端的仪表盘会话，或发送者是该机器人 `operator_sender_id` 的私聊（Settings → Channels 的 My ID，必须是该机器人允许名单里的一个 id）。群、别人、API 客户端、没有 My ID 的机器人，以及模型自己跑的回合，都是 `forbidden`。群回复若带有过去 24 小时内检索结果摘要里连续 16 个字母或数字，会被换掉并且不发送。跑在 DSH 运行时上的 Manager 没有这个工具（[#1462](https://github.com/foolzzz/looper/pull/1462)，只改文档）。
- **意图。**推送大约每 10 秒查一次，只发到已确认的操作者私聊。过期大约每 5 分钟查一次。`建 I-NNNN` 和 `驳回 I-NNNN`，或引用一条推送再说这两个词，由代码在模型之前处理，并且只认操作者。任务在这次确认之后才创建并启动。任务通知留在操作者的私聊里。意图页（`#intents`）列出待处理意图，可以建任务、驳回，并编辑类型、会话绑定和告警发送者。侧栏的 Intents 意图只在意图识别打开时出现。

**Manager 账本，默认关闭（[#1451](https://github.com/foolzzz/looper/pull/1451)）**

- **`ledger.enabled` 默认关闭。**没有这一行，或取值不是 `true`，都算关闭。仍然没有仪表盘开关，也没有写这个设置的 HTTP 接口。关闭时，Manager 的工具列表、提示词和命令行都不提账本。`looper ledger` 退出码为 3。两个读取操作返回 `conflict`。
- **打开之后，**默认 Manager 得到 `looper_ledger_add` 和 `looper_ledger_update`（list、get、confirm、amend、note、close、cancel、reopen）。场景 Manager 没有。谁在说话由回合决定：仪表盘会话是用户；私聊只有发送者是该机器人的 My ID 时才是用户；群、API 客户端、其他发送者和没设 My ID 都算转述。模型自己跑的回合可以读，不能写。关卡、不是定时任务创建的任务，以及需要确认的 Manager 提问，在各自写入之后登记。对账在账本打开后的第一次节拍跑，之后大约每 5 分钟一次。
- **账本关闭时仍能看见的变化。**每个 agent 进程现在都带 `LOOPER_AGENT_RUN`，值是它的角色；这次启动没有角色时为 `agent`。这个变量不给模型看。`looper ledger` 的写入和 `looper leads` 在它已设置时拒绝（退出码 4）。

**Advisor 第一期，项目打开之前关闭（[#1439](https://github.com/foolzzz/looper/pull/1439)、[#1441](https://github.com/foolzzz/looper/pull/1441)）**

- **项目开关 `advisor` 默认关闭。**未设置就是关。没有请教；规划者提示词、DECISION 消息、契约拒绝和 Worker 的第一回合都与以前相同。Settings → Roles 现在列出 Advisor 和 Advice check。Advice check 的内置 Profile 是 `claude-code/sonnet-5-5`（模型 `claude-sonnet-5-5`）。Advisor 的是 `claude-code/fable-5-2`（模型 `claude-fable-5-2`，effort 为 `high`）。角色层已经选定的 Profile 保持原样。回退 Profile 只存储，请教不用它。内部域名最多 20 个，设置了就会用于请求检查。
- **项目把 `advisor` 设为 `on` 之后。**计划把步骤标成 `critical` 时，该步骤的第一个 Worker 之前，DECISION 只能发起 `plan_review`。这次请教没有回答时，步骤按原计划开始。Worker 或评审失败之后，规划者可以自选请教。回答之后的决定必须带 `advice_adoption`。单次请教默认 1 美元。任务总额和请教次数在项目设置之前没有上限。代码检查的 `dangling` 规则允许出现在引号命令里的文件名（含空白的反引号片段）。只有反引号、没有命令空白、又没有任何产物展示的文件名，仍然算悬空引用。
- **仪表盘。**一次请教在 Pipeline 上是虚线节点，在任务页上是卡片。`consulting` 的步骤显示「请教中」。检查点请教没有回答时标「检查点请教未完成」。advisor 打开时，任务的最终摘要多一行 `## Advisor`。`runs.for_task` 的每行多了 `kind` 和 `parent_record_id`。没有请教的任务仍然不带 `advisor` 字段。

**消息流页面（[#1449](https://github.com/foolzzz/looper/pull/1449)）**

- **不会自行创建或启用来源。**提示词、工具和启动参数不变。
- **排除一个会话**（inclusion）会停止之后对该会话的采集，并把它从之后每一次订阅选取里拿掉，推送和抽取都一样。**把会话排除出抽取**（`source_chats.extraction`，默认 `included`）时，它仍留在流里、仍可被推送订阅读到，但线索和意图的运行不再读它。第一次排除的时间会保留到重新包含。排除时若选择删除，会删掉该会话的线索和尚未建任务的意图。消息还在。从别的会话合并进来的意图回到 `pending`。
- **删除**一条消息、一个半开的发送时间范围，或整个会话，会写一条 `source_deletions` 墓碑。整段会话的删除会擦掉事件和会话名，并且不能再包含回来。试运行和正式导入都会跳过墓碑挡住的行，并计为 `skipped_by_deletion`。结束时间在将来会被拒绝。预览令牌保留 10 分钟，或到重启为止。删除到不了已推出的输出、processor 的输出、更早的升级备份、最新的 7 份每日消息备份，以及采集器自己的文件。
- **保留期**每天清理原始正文，采集关着的来源也跑。人的原始正文默认不限期，除非策略另写。机器人的原始正文默认 30 天。消息文本保留。
- 更早的版本不认墓碑。它下一次导入可能从仍留着这些内容的采集文件里，把删掉的消息和时间范围再写回来。整段删掉的会话仍然排除。回退版本不会把已经擦掉的行恢复出来。

**桥接轮次（[#1466](https://github.com/foolzzz/looper/pull/1466)）**

写入会话被终止的桥接轮次现在以失败的一轮结束。已提交的序号保持一致，下一轮接着读。以前，连接池里已经脱开的连接会把 asyncpg 的接口错误抛出这一轮。来源在配置之前仍然关闭。仪表盘、Telegram、Lark 和 CLI 不用改。

#### Message leads

**启用：**`leads.enabled` 为 `true`，并且已经用预设创建、启用并确认一条线索订阅之前，这项能力是关的。开关在 Settings → Roles 的 processor 角色下（消息线索）。没有环境变量。用 `output_kind` 为 `leads` 的 `schedule_admin.subscription_preset` 创建，或用「消息线索」按钮，然后确认。线索订阅不需要推送目标。`looper msgflow leads-backfill --days 30` 只计数。只有带上 `--run` 和 `--budget-usd` 才写行。消息流页面的「线索」标签只在开关打开时出现。

#### Intent recognition

**启用：**`intents.enabled` 为 `true`，并且已经用预设创建、启用并确认一条意图订阅之前，这项能力是关的。开关在 Settings → Roles 的 processor 角色下（意图识别）。预设按钮是「意图识别」。确认时必须是操作员自己的飞书私聊，因为私密目标守卫适用于意图。规则、回看窗口和按日投递会被拒绝。侧栏的 Intents 意图只在开关打开时出现。先在机器人上设置 My ID（Settings → Channels），私聊发送者才会被认成操作者。用 `建 I-NNNN` 或 `驳回 I-NNNN` 回答一条推送。

**权限边界：**只有代码认定的操作者本人回合可以建任务或驳回。准备阶段只读。创建任务、驳回和修改推送发生在停止检查之后。任务通知留在操作者的私聊。processor 不带工具。Manager 不能创建这种订阅。

#### Manager ledger

**启用：**系统设置 `ledger.enabled` 为 `true` 之前是关的。没有这一行，或其他取值，都算关。本版本仍然没有仪表盘开关，也没有写这个设置的 HTTP 接口。把私聊发送者当成用户之前，先设置 My ID（Settings → Channels，允许名单里的一个发送者）。设置变成 `true` 之前，默认 Manager 不会列出 `looper_ledger_add` 或 `looper_ledger_update`，`looper ledger` 退出码为 3。

**验证：**没有这个设置时，Manager 的工具列表与 v2.15.21 相同，`looper ledger list` 退出码为 3。`ledger.enabled` 为 `true` 时，默认 Manager 列出这两个工具，仪表盘回合可以新增一条，`looper ledger list` 在有条目时退出码为 0，打开的列表为空时为 1。群里的发送者算转述。agent 进程仍然不能经 `looper ledger` 写入（退出码 4），因为 `LOOPER_AGENT_RUN` 已被设置。

**停用 / 回退：**删掉 `ledger.enabled`，或把它设成 `true` 以外的值。工具会在默认 Manager 下一次列出时消失，命令再次以退出码 3 结束。已经存下的条目留着。账本的表来自 v2.15.19，不会被删掉。无论开关如何，agent 进程上的 `LOOPER_AGENT_RUN` 都保持设置。

**权限边界：**唯一写入者是 `db.ledger.apply`。命令行写入记为用户、`via=cli`，并且必须带 `--session`。`LOOPER_AGENT_RUN` 已设置时拒绝。确认或结项只能指向用户事件。转述的发送者可以新增条目和备注，不能确认或结项。Manager 工具只给默认 Manager。读取给操作员、API 客户端或这些工具。关闭时提示词不提账本。

#### Advisor

**启用：**项目的 `advisor` 设为 `on` 之前是关的。未设置就是关。没有全系统开关。在项目设置里打开，限额留空就是默认：单次请教 1 美元，任务总额和请教次数不设上限。回退 Profile 不用。开关关闭的项目不会请教。判别运行 `claude-code/sonnet-5-5`（`claude-sonnet-5-5`），除非 Settings → Roles 为 Advice check 另选了 Profile。advisor 运行 `claude-code/fable-5-2`（`claude-fable-5-2`，effort 为 `high`），除非它的角色层另选了 Profile。

**验证：**开关关闭时，任务页没有请教节点，也没有 `## Advisor` 行，规划者提示词不提供 `advise`。开关打开时，关键步骤会在第一个 Worker 之前发起 `plan_review`，Pipeline 上能看到这次请教。只在引号命令里出现的文件名可以通过 dangling 检查。没有任何产物展示、又不在这种命令里的文件名会被退回。
