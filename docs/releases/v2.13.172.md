# Looper v2.13.172

## Release Decision

**Who should upgrade:** Nobody needs to act. This release adds a runner session class and fixes runner close handling, and nothing in Looper uses either yet. It is a hotfix that ships the changes merged since v2.13.171.

**What this release solves:** [#768](https://github.com/foolzzz/looper/pull/768) adds `RunnerSession`, which lets a Manager or Planner turn run in a resident runner session, and lets `looper serve` own a runner supervisor. [#776](https://github.com/foolzzz/looper/pull/776) keeps a cancelled close settlement local to its session, so the session ends `close_failed` instead of staying `closing` and raising `CancelledError` from the lease release.

**Breaking changes:** No. No database schema, API, Tool declaration or command changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#768](https://github.com/foolzzz/looper/pull/768) and [#776](https://github.com/foolzzz/looper/pull/776); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.172
```

## Behavior changes

- **Resident runner session ([#768](https://github.com/foolzzz/looper/pull/768)):** `looper/agents/runtimes/runner/session.py` adds `RunnerSession` and a `Descriptor` (role `manager` or `planner`, provider id, protocol, base URL, model, effort, context window, system prompt file, request limit, optional saved session and directories). `start` acquires a runner lease and opens a session with the system prompt replaced, no built-in or platform tools, and limits of 30 requests per turn by default, 120 s per tool and 100 KiB of tool output. A saved session id is not resumed: its turn fails with "runner saved session is unavailable". `run_turn` refuses a turn without host tools and budget set, with a provider or model that differs from the descriptor, or while another turn or a close is in progress. Stop and cancel ask the runner to cancel and wait up to 5 s for the turn to settle; if it does not, the runner generation is invalidated. `stop` closes the lease and invalidates the generation if the close was refused or did not settle.
- **Tier wiring ([#768](https://github.com/foolzzz/looper/pull/768)):** the Manager and Planner give a `RunnerSession` its turn budget (provider, model, price and a limits callback reading the run cap, and for the Planner the task cap and spent cost). The Planner also sets its tools on an in-process session. The Manager's handoff turn accepts a `RunnerSession` as well, with the cap stop. A runtime can declare `platform_tools_in_process`, which skips the Manager's Looper tools probe like `in_process` does; the default is false.
- **Serve ownership ([#768](https://github.com/foolzzz/looper/pull/768)):** `_run_agent_system` takes an optional `runner_supervisor`. When given, startup runs under an exit stack that stops the runner supervisor, the agent supervisor and the Manager fleet and closes the database pool if startup fails partway, and normal shutdown stops the runner supervisor. Without one, startup is unchanged.
- **Close settlement ([#776](https://github.com/foolzzz/looper/pull/776)):** in `looper/agents/runtimes/runner/bridge.py`, the wait for settlement after an acknowledged `session/close` is part of the close attempt. If it is cancelled or fails, the session becomes `close_failed`, an active turn is settled locally as failed ("runner session close failed") with its consumer and settlement restored when a rejected prompt had cancelled them, and a tombstone is recorded. If only the internal wait was cancelled and the closing task itself was not, `close_session` returns the `close_failed` state instead of raising; otherwise the error still propagates.
- **Reach:** no production code creates a `RunnerSession` or passes a `runner_supervisor` to `_run_agent_system`, and the API runtime is Manager-only, so the new Planner and Manager branches do not run. No running Looper behavior changes.
- **Model-visible changes:** none for a running Looper. `RunnerSession` sends a replacement system prompt read from the descriptor's file and the host tool list to the runner, but nothing creates one yet. The diff changes no existing prompt, tool description or tool schema.

## Upgrade and rollback

Re-run `install.sh` once v2.13.172 is published. Rolling back to v2.13.171 removes `RunnerSession` and restores the previous close settlement handling.

### 行为变化与入口

- **常驻 runner 会话（#768）：**`session.py` 新增 `RunnerSession` 和 `Descriptor`（角色 `manager` 或 `planner`、提供方 id、协议、base URL、模型、effort、上下文窗口、系统提示文件、请求上限，以及可选的已保存会话和目录）。`start` 获取 runner 租约并打开会话：系统提示被替换，无内置或平台工具，默认每回合 30 次请求、每个工具 120 秒、工具输出 100 KiB。已保存的会话 id 不会被恢复，其回合以 "runner saved session is unavailable" 失败。未设置宿主工具和预算、提供方或模型与描述不符、或已有回合或关闭在进行时，`run_turn` 会拒绝。停止和取消会请求 runner 取消并最多等待 5 秒结算；未结算则使 runner generation 失效。`stop` 关闭租约，若关闭被拒绝或未结算则使 generation 失效。
- **层级接线（#768）：**Manager 和 Planner 为 `RunnerSession` 提供回合预算（提供方、模型、价格，以及读取运行上限的 limits 回调；Planner 还读取任务上限和已花费成本）。Planner 还会为进程内会话设置工具。Manager 的 handoff 回合也接受 `RunnerSession`，并带上限制停止。运行时可声明 `platform_tools_in_process`，与 `in_process` 一样跳过 Manager 的 Looper 工具探测，默认为 false。
- **Serve 持有（#768）：**`_run_agent_system` 新增可选参数 `runner_supervisor`。提供时，启动在退出栈下运行，若启动中途失败会停止 runner supervisor、agent supervisor 和 Manager fleet 并关闭数据库连接池；正常关闭时停止 runner supervisor。未提供时启动不变。
- **关闭结算（#776）：**`bridge.py` 中，`session/close` 被确认后的结算等待属于关闭尝试的一部分。若其被取消或失败，会话变为 `close_failed`，进行中的回合在本地结算为失败（"runner session close failed"）；被拒绝的 prompt 取消了消费者和结算时会将其恢复；并记录墓碑。若只是内部等待被取消、关闭任务本身未被取消，`close_session` 返回 `close_failed` 状态而不抛出；否则错误仍会传播。
- **影响范围：**生产代码不会创建 `RunnerSession`，也不会向 `_run_agent_system` 传入 `runner_supervisor`，且 API 运行时只服务 Manager，因此新增的 Planner 和 Manager 分支不会运行，运行中的 Looper 行为不变。
- **面向模型的变化：**对运行中的 Looper 没有。`RunnerSession` 会向 runner 发送从描述文件读取的替换系统提示和宿主工具列表，但目前没有代码创建它。diff 未改动现有 prompt、工具描述或工具 schema。
