# Looper v2.13.23

## Release Decision

**Who should upgrade:** Users of the Manager session profile (the `/profile` command, the Profile selector in the Chat header, and the Manager's Settings tool). Everyone else sees no change.

**What this release solves:** [#355](https://github.com/foolzzz/looper/pull/355) fixes the review follow-ups of #303. A Manager turn now stops with the settings read error instead of running on a cached or built-in profile, `/profile` followed by a tab or newline is recognized, the Chat header refreshes its Profile after `/profile` and on window focus, Follow Settings asks for the handoff confirmation when it starts a new session, and the "applies from its next session" note appears only when the profile is set.

**Breaking changes:** No. No CLI command, configuration key or database schema changed. The session view response of the Manager gains a `follow_settings` field; no field was removed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#355](https://github.com/foolzzz/looper/pull/355); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.23
```

## Behavior changes

- **No fallback profile on a failed settings read:** when preparing a Manager turn, the agent settings are read without the fallback to the last ones read. If the read fails, the turn stops with that error as a `ProfileUnavailable`, since the session's choice may be among what could not be read. Before, the turn ran on the cached settings, or on the built-in defaults when none had been read. Listings still show the last settings read (`looper/agents/tiers/manager.py`).
- **`/profile` splits on any whitespace:** the first word is split off on any whitespace, so `/profile<tab>2` and `/profile<newline>2` select profile 2 and `/profile<newline>` lists. Before, only a space was recognized and these were sent to the model as ordinary messages (`looper/agents/session_profile.py`).
- **Chat header refresh:** the Profile in the Chat header reloads after any `/profile` command, as it did after `/new`, and when the window regains focus, which covers a switch made from another channel (`web/src/pages/chat.tsx`, `web/src/components/manager-session-profile.tsx`).
- **Follow Settings confirmation:** the session view carries `follow_settings` (the name of the Settings profile and the effect on the saved session; null when that profile cannot launch or the read fails). Choosing Follow Settings now shows the same handoff confirmation as another profile when the effect is a new session. Before, there was no choice to match and the confirmation was skipped (`looper/agents/tiers/manager.py`, `web/src/lib/api.ts`, `web/src/components/manager-session-profile.tsx`).
- **Tests:** new tests cover the no-fallback read, the whitespace forms of `/profile`, the settings note, and the Follow Settings confirmation.
- **Deferred, not fixed here:** the PR defers two flaky tests that pass alone and have no reproducible root cause (`test_dsh_installed_run_without_platform_bridge`, `test_schema_applies_twice_with_column_and_constraint`); they stay open in #303.
- **Model-visible changes:** One. The result of the Manager's Settings tool `set` on the Manager role carries its `note` ("the Manager's current session keeps its own profile ... applies from its next session") only when the change includes `profile_id`; a change to timeout, budget or harness no longer carries it (`looper/agents/ops/settings.py`). Also, a `/profile` followed by a tab or newline is now handled as the command, not delivered to the model as a message. No prompt text or tool schema changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.23 is published. There is no schema or configuration change. Rolling back to v2.13.22 is safe; turns then fall back to cached settings on a failed read again.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**使用 Manager 会话 Profile 的用户（`/profile` 命令、Chat 页头的 Profile 选择器、Manager 的 Settings 工具）。其他人没有变化。

**解决了什么：**[#355](https://github.com/foolzzz/looper/pull/355) 处理 #303 的评审后续项。读取设置失败时，Manager 的回合现在带着读取错误停止，而不是用缓存或内置 Profile 继续；`/profile` 后接制表符或换行也能识别；Chat 页头在 `/profile` 之后以及窗口获得焦点时刷新 Profile；Follow Settings 在会开启新会话时会要求交接确认；“下个会话生效”的提示只在设置了 profile 时出现。

**是否有破坏性变更：**无。CLI、配置项、数据库 schema 均未变化。Manager 的会话视图响应新增 `follow_settings` 字段，未删除任何字段。

**如何验证：**运行 `looper --version` 核对版本为 2.13.23。

**贡献者：**维护者 @foolzzz 提交 [#355](https://github.com/foolzzz/looper/pull/355)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.23
```

### 行为变化与入口

- 设置读取失败时不再回退到其他 Profile：准备 Manager 回合时，读取 agent 设置不再回退到上次读到的设置。读取失败则回合以该错误（`ProfileUnavailable`）停止，因为会话所选的 profile 可能就在读不到的内容里。此前回合会用缓存设置运行，从未读到过则用内置默认值。列表仍显示上次读到的设置（`looper/agents/tiers/manager.py`）。
- `/profile` 按任意空白切分：首个词按任意空白切分，`/profile<制表符>2`、`/profile<换行>2` 会选择 2 号 profile，`/profile<换行>` 列出选项。此前只识别空格，这些输入会当作普通消息发给模型（`looper/agents/session_profile.py`）。
- Chat 页头刷新：任何 `/profile` 命令之后（与 `/new` 一样），以及窗口重新获得焦点时，页头的 Profile 都会重新加载，这覆盖了从其他渠道所做的切换（`web/src/pages/chat.tsx`、`web/src/components/manager-session-profile.tsx`）。
- Follow Settings 确认：会话视图带有 `follow_settings`（Settings 的 profile 名称及对已保存会话的影响；该 profile 无法启动或读取失败时为 null）。当影响是新会话时，选择 Follow Settings 现在与选择其他 profile 一样弹出交接确认。此前没有可匹配的选项，确认被跳过（`looper/agents/tiers/manager.py`、`web/src/lib/api.ts`、`web/src/components/manager-session-profile.tsx`）。
- 测试：新增测试覆盖不回退的读取、`/profile` 的空白形式、设置提示，以及 Follow Settings 确认。
- 延后未修：PR 延后了两个单独运行即通过、无法复现根因的不稳定测试（`test_dsh_installed_run_without_platform_bridge`、`test_schema_applies_twice_with_column_and_constraint`），仍在 #303 跟踪。
- 面向模型的变化：有一处。Manager 的 Settings 工具对 Manager 角色执行 `set` 时，结果中的 `note`（“当前会话保留自己的 profile……下个会话生效”）只在变更包含 `profile_id` 时出现；修改超时、预算或 harness 不再带该提示（`looper/agents/ops/settings.py`）。另外，`/profile` 后接制表符或换行现在按命令处理，不再作为消息交给模型。提示词文本与工具 schema 均无变化。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.22 安全；读取失败时回合将再次回退到缓存设置。
