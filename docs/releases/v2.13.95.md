# Looper v2.13.95

## Release Decision

**Who should upgrade:** Anyone who talks to the Manager through a channel (chat) and relies on `/stop`, or restarts or shuts down the service while a Manager turn is running.

**What this release solves:** [#557](https://github.com/foolzzz/looper/pull/557) preserves Manager turn ownership through startup and shutdown. A `/stop` queued before the Manager starts is now handled by code instead of reaching the model, and a turn cancelled during shutdown no longer loses its attribution or leaves the resident process unmanaged.

**Breaking changes:** No. No API, configuration, prompt or Tool declaration changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#557](https://github.com/foolzzz/looper/pull/557); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.95
```

## Behavior changes

- **Queued messages at startup ([#557](https://github.com/foolzzz/looper/pull/557)):** `ManagerAgent` in `looper/agents/tiers/manager.py` now drains the bus queue after subscribing its consumer and before starting the message loop. Each queued user message addressed to the Manager gets a turn token (`_register_turn`). A queued stop command is completed through `_stop_from_chat` and settled on the bus first, so later messages from the same chat are registered only after it and the stop never reaches the model.
- **Stop in the message loop:** `_handle_user_message` checks `is_stop_command` first and uses the same `_stop_from_chat` path, so a stop that arrives through the loop is also handled by code.
- **Binding lifetime:** `_publish_binding(None)` is no longer called right after `run_turn` returns, where a bridge write during the event drain could lose the user turn. It runs in a `finally` that wraps closing the run record (`end_left_open`), so the binding is cleared once the turn is drained or boundedly abandoned, even if closing the record is cancelled.
- **Cancellation:** a `CancelledError` in the turn now settles the turn, abandons event handling and re-raises. It does not stop the resident process there; `ManagerAgent.stop` owns that on closure, because the supervisor cancels the message task repeatedly and a stop inside it could forget the process and lose its cleanup.
- **Model-visible changes:** none for prompts, Tool declarations and Tool results. The one visible effect is that a `/stop` queued before startup is no longer forwarded to the model as a message.
- **Tests:** `tests/test_manager_stop_command.py` and `tests/test_manager_stop_faults.py` add cases for a stop queued before the Manager starts, startup stop preserving later messages, a stop reaching the message loop, a bridge write during event drain, and a resident read failure still ending the process. [#557](https://github.com/foolzzz/looper/pull/557) reports 275 test lines and 22 production lines added.

## Upgrade and rollback

Re-run `install.sh` once v2.13.95 is published. No data migration and no configuration change. Rolling back to v2.13.94 restores the previous startup and shutdown behavior.

### 行为变化与入口

- **启动时的排队消息（[#557](https://github.com/foolzzz/looper/pull/557)）：**`looper/agents/tiers/manager.py` 中的 `ManagerAgent` 在订阅消费者之后、启动消息循环之前清空总线队列。每条发给 Manager 的排队用户消息都会获得回合令牌（`_register_turn`）。排队的停止命令先经 `_stop_from_chat` 完成并在总线上结算，同一聊天之后的消息才会登记，停止命令不会到达模型。
- **消息循环中的停止：**`_handle_user_message` 先检查 `is_stop_command`，走同样的 `_stop_from_chat` 路径，因此经消息循环到达的停止也由代码处理。
- **绑定的生命周期：**`run_turn` 返回后不再立即调用 `_publish_binding(None)`，那时事件排空期间的桥接写入可能丢失用户回合。现在它在包住关闭运行记录（`end_left_open`）的 `finally` 中执行，回合排空或有界放弃后才清除绑定，即使关闭记录被取消也是如此。
- **取消：**回合中的 `CancelledError` 现在会结算回合、放弃事件处理并重新抛出，不在此处停止常驻进程；关闭时由 `ManagerAgent.stop` 负责，因为 supervisor 会反复取消消息任务，在其中停止可能遗忘进程并丢失清理。
- **面向模型的变化：**prompt、Tool 声明和 Tool 结果均无变化。唯一可见的效果是启动前排队的 `/stop` 不再作为消息转给模型。
- **测试：**`tests/test_manager_stop_command.py` 与 `tests/test_manager_stop_faults.py` 新增用例：Manager 启动前排队的停止、启动时停止保留后续消息、经消息循环到达的停止、事件排空期间的桥接写入、常驻进程读取失败后仍结束进程。[#557](https://github.com/foolzzz/looper/pull/557) 报告新增测试 275 行、生产代码 22 行。
