# Looper v2.14.22

This is the patch release v2.14.22. It ships the one change merged since v2.14.21: [#919](https://github.com/foolzzz/looper/pull/919), which gives a Planner's empty reply the same repair turn as an invalid one.

## Release Decision

**Who should upgrade:** Anyone whose Planner sometimes ends a turn with an empty reply, on any runtime. It ships the one change merged since v2.14.21.

**What this release solves:** [#919](https://github.com/foolzzz/looper/pull/919): a Planner turn that succeeded but returned an empty reply failed the whole task at once ("Planning failed: RUNTIME returned an empty reply"), while an invalid reply got one repair turn. An empty reply now gets the same single repair turn. The Planner's start activity also names the runtime that runs it instead of always "Claude Code".

**Breaking changes:** No. No database schema, stored data, API or default changes. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#919](https://github.com/foolzzz/looper/pull/919); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.22
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.21 upgrades directly. This release changes no database schema or stored data.

## Behavior changes

- **Empty Planner reply gets a repair turn** (`looper/agents/tiers/planner.py`, `looper/agents/tiers/planner_protocol.py`): a turn that succeeds with an empty or whitespace-only reply no longer raises a turn error at once. The turn is still recorded with the error "RUNTIME returned an empty reply", and the reply goes on to the contract parser, which now raises a `ProtocolError` ("the reply was empty") for empty text. The existing path then sends one repair turn, as for an invalid reply; if the repair reply is also invalid, planning fails as it does for an invalid reply. Every other turn failure (a turn that did not succeed, a stop, a cap) is unchanged.
- **Start activity names the runtime** (`planner.py`): the activity line reads "Planner <runtime label> started (...)" instead of "Planner Claude Code started (...)". The pid is shown only when the runtime has one, and the resume note is unchanged.
- **Tests**: `tests/test_planner_agent.py` adds 89 lines covering the change.
- **Model-visible changes:** After an empty Planner reply, the Planner now receives the repair turn that reports an invalid reply ("the reply was empty") instead of the task failing. Nothing else a model sees changes.

## 中文摘要

本版本是 patch release v2.14.22。自 v2.14.21 以来只合并了一项改动：[#919](https://github.com/foolzzz/looper/pull/919)，让 Planner 的空回复和无效回复一样获得一次修复轮次。

### 升级决策

**谁需要升级：**Planner 偶尔以空回复结束一轮的人，不限运行时。包含 v2.14.21 之后合并的这一项改动。

**解决了什么：**[#919](https://github.com/foolzzz/looper/pull/919)：Planner 的一轮成功但返回空回复时，整个任务会立即失败（“Planning failed: RUNTIME returned an empty reply”），而无效回复可获得一次修复轮次。现在空回复同样获得一次修复轮次。Planner 的启动活动也改为显示实际运行它的运行时，而不是固定的 “Claude Code”。

**是否有破坏性变更：**否。不改数据库 schema、已存数据、API 或默认值。受支持的升级路径不变（见升级）。

**如何验证：**运行 `looper --version` 核对版本为 2.14.22。

**贡献者：**维护者 @foolzzz 提交 [#919](https://github.com/foolzzz/looper/pull/919)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.22
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.21 上的安装可直接升级。本版本不改数据库 schema 或已存数据。

### 行为变化与入口

- **空的 Planner 回复获得修复轮次**（`looper/agents/tiers/planner.py`、`looper/agents/tiers/planner_protocol.py`）：成功但回复为空或仅含空白的一轮不再立即抛出轮次错误。该轮仍以“RUNTIME returned an empty reply”记录错误，回复继续交给协议解析器，解析器对空文本抛出 `ProtocolError`（“the reply was empty”）。现有流程随后发送一次修复轮次，与无效回复相同；修复后的回复仍无效时，规划与无效回复一样失败。其他轮次失败（轮次未成功、停止、上限）不变。
- **启动活动显示运行时**（`planner.py`）：活动行为“Planner RUNTIME started (...)”，不再固定为“Planner Claude Code started (...)”。仅当运行时有 pid 时显示 pid，恢复会话的说明不变。
- **测试**：`tests/test_planner_agent.py` 新增 89 行覆盖该改动。
- **面向模型的变化：**Planner 回复为空后，现在会收到报告回复无效的修复轮次（“the reply was empty”），而不是任务直接失败。模型看到的其他内容不变。
