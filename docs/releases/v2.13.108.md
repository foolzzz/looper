# Looper v2.13.108

## Release Decision

**Who should upgrade:** Anyone who runs `loopercli config --help` (or `-h`) to discover the generated configuration commands.

**What this release solves:** [#599](https://github.com/foolzzz/looper/pull/599) makes the help of a command group such as `loopercli config` list the children generated from Looper's API (`import-cancel`, `import-upload`, `import-apply`, `import-preview` and the others), not only the hand-written ones. When the API cannot be reached, the help falls back to the group's hand-written commands with a note.

**Breaking changes:** No. No route, command or stored data changed; only the help output of a command group changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#599](https://github.com/foolzzz/looper/pull/599); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.108
```

## Behavior changes

- **Group help discovers API children ([#599](https://github.com/foolzzz/looper/pull/599)):** in `looper/loopercli.py`, `_needs_document` now also reads Looper's OpenAPI document when the word after a hand-written group is `-h` or `--help`. Before, only a non-flag word that was not a registered child triggered the read.
- **Offline cases unchanged:** a known hand-written child (for example `config export -h`, `confirm --help`, `chat -h`) and other flags (for example `config --unknown`, `chat --file` without a value) still make no request to the API.
- **Fallback:** if the document cannot be read (HTTP error, connection refused, or no client login), `_run` prints the help of the requested group, not the top-level help, with the usage line of that group, then the note that the API-made commands are not shown and the reason. The exit code is 0.
- **Model-visible changes:** None. No Manager tool declaration, prompt, API route or API document changed.
- **Tests:** [#599](https://github.com/foolzzz/looper/pull/599) adds tests in `tests/test_loopercli.py` for the discovery (a single request to the OpenAPI document), the three fallback cases and the offline hand-written children and flags (43 test lines, 5 production lines as reported).

## Upgrade and rollback

Re-run `install.sh` once v2.13.108 is published. No data migration and no configuration change. Rolling back to v2.13.107 restores the earlier group help, which omits the generated children.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 升级决策

**谁需要升级：**使用 `loopercli config --help`（或 `-h`）查看生成的配置命令的使用者。

**解决了什么：**[#599](https://github.com/foolzzz/looper/pull/599) 让 `loopercli config` 这类命令组的帮助列出由 Looper API 生成的子命令（`import-cancel`、`import-upload`、`import-apply`、`import-preview` 等），而不只是手写的子命令。API 不可达时，帮助回退为该组的手写命令并附带说明。

**是否有破坏性变更：**否。路由、命令和存储数据均未改变；只有命令组的帮助输出改变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.108。

**贡献者：**维护者 @foolzzz 提交 [#599](https://github.com/foolzzz/looper/pull/599)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.108
```

### 行为变化与入口

- **组帮助发现 API 子命令（[#599](https://github.com/foolzzz/looper/pull/599)）：**`looper/loopercli.py` 中，当手写命令组后面的词是 `-h` 或 `--help` 时，`_needs_document` 现在也会读取 Looper 的 OpenAPI 文档。此前只有不是标志且不是已注册子命令的词才会触发读取。
- **离线情形不变：**已知的手写子命令（如 `config export -h`、`confirm --help`、`chat -h`）和其他标志（如 `config --unknown`、缺少值的 `chat --file`）仍不向 API 发请求。
- **回退：**文档无法读取（HTTP 错误、连接被拒或没有客户端登录）时，`_run` 打印所请求命令组的帮助（而不是顶层帮助），含该组的 usage 行，随后说明 API 生成的命令未显示及原因，退出码为 0。
- **面向模型的变化：**无。Manager 的 tool 声明、提示词、API 路由和 API 文档均未改变。
- **测试：**[#599](https://github.com/foolzzz/looper/pull/599) 在 `tests/test_loopercli.py` 中新增测试，覆盖发现（对 OpenAPI 文档只发一次请求）、三种回退情形，以及离线的手写子命令与标志（按报告测试 43 行、生产代码 5 行）。

### 升级与回退

v2.13.108 发布后重跑 `install.sh`。无需迁移数据，无需改配置。回退到 v2.13.107 会恢复之前的组帮助，不显示生成的子命令。
