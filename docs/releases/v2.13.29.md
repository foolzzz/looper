# Looper v2.13.29

## Release Decision

**Who should upgrade:** Anyone who answers gates from a chat (`/gates`, `/gate N`, or a reply under a gate's card), and anyone who runs the test suite.

**What this release solves:** [#382](https://github.com/foolzzz/looper/pull/382) fixes review follow-ups of #307. An `end` reply to a gate card that is closed, or that meets a 409, now gets a "no longer waiting" receipt written by code instead of reaching the Manager. `/gates` now lists the gates of stopped and failed tasks too, and is paged. It also fixes three flaky test cases whose deadlines raced process startup under load.

**Breaking changes:** No. No CLI command, configuration key, API shape or database schema changed. The behavior changes are listed below.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#382](https://github.com/foolzzz/looper/pull/382); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.29
```

## Behavior changes

- **`end` to a closed gate is answered by code:** in `looper/agents/gate_routing.py`, a reply under a gate's card whose text is `end` or `/end` now returns a fixed receipt (`ENDED_REPLY`, "this gate is no longer waiting, nothing was ended: it was closed or the task completed") when the gate is no longer waiting, or when posting the reply is refused with a 409. Before, such a reply was handed to the Manager as a message to a closed gate. The reply is not stored in the chat history.
- **Stopped and failed tasks' gates are listed:** `open_gates` (`looper/db/user_gates.py`) now returns the waiting gates of every task that is not completed or cancelled, where it returned only those of tasks in an active status. So `/gates` can list gates of stopped or failed tasks, and they can be answered with `/gate N`. Gates of completed or cancelled tasks are still left out.
- **`/gates` is paged:** `looper/agents/gate_commands.py` lists 20 gates per page. `/gates N` shows page N; the numbers continue across pages (page 2 starts at 21) and stay bound to the snapshot of the last list sent, so `/gate 22 <answer>` refers to the gate shown as 22. A list with more gates ends with a line pointing at the next page. A page past the end answers that the page does not exist. `/gates` followed by anything other than a number answers the usage text, which now reads `/gates [页码]`.
- **Test-only changes:** `tests/test_pi_steer.py` (the setup deadline is no longer shortened in `prompt_timeout`; the 0.15s prompt deadline applies only to `fast_timeout`) and `tests/test_provider_pricing.py` (node cold-start deadlines widened from 10s/20s to 50s/60s). No product code changed for these.
- **Model-visible changes:** An `end` reply to a closed card or after a 409 no longer reaches the Manager's model or chat history; before, the Manager saw it. No prompt text, tool schema or tool result changed. The new receipt, the page hint and the usage text are chat replies written by code.

## Upgrade and rollback

Re-run `install.sh` once v2.13.29 is published. There is no schema or configuration change. Rolling back to v2.13.28 is safe; the only difference is the previous behavior listed above.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 行为变化与入口

- 对已关闭关卡回复 `end` 由代码回答：`looper/agents/gate_routing.py` 中，关卡卡片下文本为 `end` 或 `/end` 的回复，若关卡已不在等待，或提交时被 409 拒绝，现在返回固定回执 `ENDED_REPLY`（“这个关卡已经不在等你了，没有结束它”）。此前这类回复会作为发给已关闭关卡的消息交给 Manager。该回复不进入聊天历史。
- 已停止、已失败任务的关卡会被列出：`open_gates`（`looper/db/user_gates.py`）现在返回所有未完成、未取消任务的等待中关卡，此前只返回处于活跃状态的任务。因此 `/gates` 可列出已停止或失败任务的关卡，并可用 `/gate N` 回答；已完成或已取消任务的关卡仍不列出。
- `/gates` 分页：`looper/agents/gate_commands.py` 每页 20 个；`/gates N` 看第 N 页，编号跨页延续（第 2 页从 21 开始），并绑定到最近一次发送列表的快照，因此 `/gate 22 <回答>` 对应列表中编号 22 的关卡。还有更多时列表末尾提示下一页；超出范围的页码回复该页不存在；`/gates` 后跟非数字时返回用法提示，用法现为 `/gates [页码]`。
- 仅测试变更：`tests/test_pi_steer.py`（`prompt_timeout` 场景不再缩短 setup 超时；0.15 秒 prompt 超时只用于 `fast_timeout`）和 `tests/test_provider_pricing.py`（node 冷启动超时由 10 秒/20 秒放宽到 50 秒/60 秒）；产品代码未因此改动。
- 面向模型的变化：对已关闭卡片或遇 409 的 `end` 回复不再到达 Manager 的模型和聊天历史，此前 Manager 能看到。提示词文本、工具 schema、工具结果均无变化。新的回执、翻页提示和用法文本是由代码写的聊天回复。
