# Looper v2.14.63

This is the patch release v2.14.63, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.62: upgrade recovery after a failed drain poll now decides after the wait for the old process, also when that process still held the port at the first probe ([#1044](https://github.com/foolzzz/looper/pull/1044)).

## Release Decision

**Who should upgrade:** Operators who upgrade the service with `looper service upgrade` or `looper service restart --drain`. Others need not upgrade.

**What this release solves:** Both commands share one recovery path (`_execute_plan`, `looper/agents/service.py`). When a drain poll fails before the stop step, recovery probed the port once. If the old process was mid-exit and still held the listener at that moment, recovery skipped the wait for its exit. Once the PID was gone, the unit not running and the port free, nothing started and the service stayed down, because a clean exit is not restarted by `KeepAlive` or `Restart=on-failure`. [#1044](https://github.com/foolzzz/looper/pull/1044) makes recovery wait up to `_STOP_WAIT_SECONDS` (30 s) for the old PID to exit, unless the process on the port answers status as that PID, which means it still serves. When the wait ends, recovery decides: old PID gone, unit not running, port free: start once; PID gone, unit not running, port held: `port_conflict`; otherwise start nothing.

**Breaking changes:** No. No API or configuration changes and there is no migration.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#1044](https://github.com/foolzzz/looper/pull/1044); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.63
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.62 upgrades directly. This release adds no migration.

## Behavior changes

- **Upgrade recovery waits for the old process whatever the first probe found.** After a failed drain poll, with the stop step not yet attempted, recovery used to wait for the old PID only when the port was already free. It now always waits while the old PID lives, polling the service status each round (`health` system operation); if the answering process reports the old PID, the wait ends and cancelling the drain is the whole recovery. If the wait times out, the report keeps the `recovery_error` "the old service process N is still running; start it with `looper service restart` once it exits". At the end of the wait the decision is: PID gone and unit not running with the port held raises `port_conflict`; with the port free the service is started once.
- **Unchanged:** an exiting process that still answers status after the failed poll is taken as serving, as before; the respawned-unit report wait and the `drain_cancel` error ordering are out of scope.
- **Docs:** `docs/architecture/agent-system.md` describes the wait and the decision in its upgrade section.
- **Size:** per the pull request description, 11 added lines of production code and 66 of tests (`tests/test_service_upgrade_execution.py`); the diff of `looper/agents/service.py` is 15 added and 8 removed lines.
- **Model-visible changes:** No. The Manager prompt, tool documentation and confirmation texts are unchanged.

### 升级决策

**谁需要升级：**使用 `looper service upgrade` 或 `looper service restart --drain` 升级服务的运维者。其他人无需升级。

**解决了什么：**两条命令共用同一恢复路径（`looper/agents/service.py` 的 `_execute_plan`）。停止步骤之前排空轮询失败时，恢复只探测一次端口；若旧进程正在退出、此刻仍占着监听端口，恢复就跳过了等待其退出。之后 PID 消失、单元未运行、端口空闲时没有任何东西启动，服务保持停止，因为正常退出不会被 `KeepAlive` 或 `Restart=on-failure` 重启。[#1044](https://github.com/foolzzz/looper/pull/1044) 让恢复最多等待 `_STOP_WAIT_SECONDS`（30 秒）让旧 PID 退出，除非端口上的进程以该 PID 应答状态（说明它仍在服务）。等待结束后决定：旧 PID 已退出、单元未运行、端口空闲：启动一次；PID 已退出、单元未运行、端口被占：`port_conflict`；其他情况不启动。

**是否有破坏性变更：**否。没有 API 或配置变更，也没有迁移。

**如何验证：**运行 `looper --version` 核对版本为 2.14.63。

**贡献者：**维护者 @foolzzz 提交 [#1044](https://github.com/foolzzz/looper/pull/1044)；本版本无社区贡献。

### 行为变化与入口

- **无论首次探测结果如何，升级恢复都等待旧进程。**排空轮询失败且尚未尝试停止时，恢复过去只在端口已空闲时才等待旧 PID。现在只要旧 PID 还活着就等待，每轮通过 `health` 系统操作查询服务状态；若应答的进程报告的就是旧 PID，则结束等待，取消排空即全部恢复。等待超时时报告仍保留 `recovery_error`：“the old service process N is still running; start it with `looper service restart` once it exits”。等待结束时的决定：PID 已退出且单元未运行，端口被占则抛出 `port_conflict`，端口空闲则启动一次。
- **不变：**失败轮询之后仍应答状态的退出中进程照旧视为仍在服务；重新拉起单元后的报告等待和 `drain_cancel` 的错误顺序不在范围内。
