# Looper v2.13.134

## Release Decision

**Who should upgrade:** Nobody needs to. This release only changes documentation. Everyone can stay on v2.13.133.

**What this release solves:** [#667](https://github.com/foolzzz/looper/pull/667) marks scenario Managers stage 3 as implemented in the scenario-Managers RFC and the long-horizon plan, after the maintainer confirmed the RFC's seven recommended semantics.

**Breaking changes:** No. No code, API, schema or configuration changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#667](https://github.com/foolzzz/looper/pull/667); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.134
```

## Behavior changes

- **Documentation only (#667):** the PR changes two files, `docs/architecture/rfcs/scenario-managers.zh-CN.md` and `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md` (2 added and 2 removed lines each). The RFC status line now says stage 3 is implemented, lists #661, #662 and #665 among its pull requests, and records the maintainer's confirmation of the seven semantics on 2026-10-26; the plan's item 21 marks stage 3 as delivered. Both keep the known gaps: the real-model Codex smoke test was not run for lack of isolated credentials, and a prompt eval does not apply because model-visible bytes are unchanged.
- **Runtime behavior:** none. No Python, web or configuration file is touched by the PR.
- **Model-visible changes:** none found. The diff touches no prompt, tool declaration or tool result.
- **Line counts:** the description reports tests 0 and production 0 added lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.134 is published. No schema or configuration change. Rolling back to v2.13.133 only restores the earlier wording of the two documents.
