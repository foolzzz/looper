# Looper v2.13.208

## Release Decision

**Who should upgrade:** Operators who upgrade a database that last ran a bridge release, who run channel bots with stored allowlists or Lark settings, or who read historical run records in the dashboard. It ships the change merged since v2.13.207.

**What this release solves:** [#857](https://github.com/foolzzz/looper/pull/857) removes startup and stored-input fallbacks for data older than the admitted upgrade path, normalizes surviving historical run records at one read boundary, requires explicit identities in the message journal and renders the canonical record in the run history page.

**Breaking changes:** No. Commands, settings, the database schema and the admitted upgrade path are unchanged; data older than that path, or malformed stored input, is now refused or read as empty instead of repaired (see Behavior changes).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#857](https://github.com/foolzzz/looper/pull/857); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.208
```

## Behavior changes

- **Startup fallbacks removed (`looper/agents/serve.py`, `looper/agents/state_import.py`):** `looper serve` no longer imports the pre-PostgreSQL planner plan files and Manager session file, no longer rewrites Lark channel configuration, and no longer migrates old default Planner and Manager prompts in `role_configs`; `state_import.py` and `db.role_configs.replace_default_prompt` are deleted.
- **Bridge admission (`looper/db/connection.py`, `looper/db/bridge_upgrade.py`):** a bridge-era database is admitted only when its `file_state_import` migration is recorded and its four role default prompts match the bridge's seeded text; otherwise startup is refused with the existing "upgrade to v2.13.165 or a later 2.13 release first" message. The bridge upgrade now needs `role_configs` and `schema_migrations` columns and reads a stored task config with its own bounded unwrap.
- **Stored task config:** `_read_config` decodes the stored JSON once and requires an object, otherwise `{}`. A config wrapped several times as a JSON string is no longer unwrapped at read time.
- **Message journal (`looper/agents/bus.py`):** a journal with an invalid envelope (missing or non-string identities, unknown channel, non-object payload) now raises with its file and line instead of skipping the entry. Once per runtime, `transition()` validates the whole journal, drops undelivered progress messages, fills a missing notice `channel_id` with the built-in one, rejects a notice whose target disagrees with its channel and rewrites the journal and a `notice-identities-v1` marker atomically. `compact` validates before rewriting, and `shutdown` compacts only if the bus started.
- **Notices (`looper/agents/task_notice.py`):** `Notice.channel_id` is required and must be a nonempty string matching its channel type.
- **Channels:** a Lark channel configuration containing `app_id_env` or `app_secret_env` is rejected, and the v1 channel-config schema no longer lists them. Allowlist normalization keeps `null` as `null`; an unsupported type now says it expects a list or a comma-separated string. Configuration export reads `manager_id`, `bound_chats_only` and `channel_bot_seq` directly, without probing older databases.
- **Sessions and settings:** `can_resume` treats a saved session with no runtime type as not resumable (a Claude Code session with no provider still maps to the subscription login), so such a session starts anew. A system harness layer saved with the pre-rename "LoopX" wording no longer follows the built-in harness. `AgentProfile.from_row` and the API-key path accept only the current profile shape.
- **Self-check:** an unsupported registry schema now reports a failed PostgreSQL check with the version error, and missing columns are no longer read as an older server.
- **Run records (`looper/db/llm_records.py`):** records read through the database layer carry `metadata.presentation` (sources, system prompt, library), computed at read and never written back. The subscription-equivalent cost test prefers `metadata.accounting_basis`, then the profile (or historical `agent`) provider auth, and no longer treats a record with neither as subscription.
- **Dashboard (`web/src/lib/api.ts`, `web/src/pages/agent-history.tsx`, `web/src/lib/usage.ts`):** the run history page shows the sources and system prompt from `metadata.presentation`, shows `unknown` for missing fields, and no longer shows per-variable env sources.
- **Tests:** new and changed tests cover journal sealing, record normalization, bridge admission, config export, Lark and allowlist input, session resume and the history page.
- **Model-visible changes:** No prompt, tool or message text of the current release changed. Indirect effects: a session with no saved runtime type starts a new session instead of resuming, a system harness layer with the old LoopX wording is taken as a custom harness, and old default role prompts are no longer migrated at startup.

## Upgrade and rollback

Re-run `install.sh` once v2.13.208 is published. A database must already be on v2.13.165 or a later 2.13 release and have been started once. The release does not change the schema, so a rollback to v2.13.207 needs no database restore; the first startup writes a `notice-identities-v1` marker and rewrites the message journal, which v2.13.207 reads as before.

### 行为变化与入口

- **移除启动兜底（`looper/agents/serve.py`、`looper/agents/state_import.py`）：**`looper serve` 不再导入 PostgreSQL 之前的 Planner 计划文件和 Manager 会话文件，不再改写 Lark 渠道配置，也不再迁移 `role_configs` 中旧的默认 Planner 与 Manager 提示词；`state_import.py` 与 `db.role_configs.replace_default_prompt` 已删除。
- **桥接准入（`looper/db/connection.py`、`looper/db/bridge_upgrade.py`）：**桥接版本的数据库只有在记录了 `file_state_import` 迁移且四个角色默认提示词与桥接版本写入的文本一致时才被接受；否则启动被拒绝，并给出原有的“先升级到 v2.13.165 或更高 2.13 版本”提示。桥接升级现在要求 `role_configs` 与 `schema_migrations` 的列，并自行以有界方式解包存储的任务配置。
- **存储的任务配置：**`_read_config` 只解码一次存储的 JSON 并要求为对象，否则为 `{}`。多层 JSON 字符串包裹的配置不再在读取时解包。
- **消息日志（`looper/agents/bus.py`）：**日志含无效信封（身份缺失或非字符串、未知渠道、payload 非对象）时，现在会带文件与行号报错，而不是跳过。每个运行期一次，`transition()` 校验整个日志，丢弃未送达的进度消息，为缺失的通知补上内置 `channel_id`，拒绝目标与渠道不一致的通知，并以原子方式重写日志和 `notice-identities-v1` 标记。`compact` 先校验再重写，`shutdown` 仅在总线已启动时压缩。
- **通知（`looper/agents/task_notice.py`）：**`Notice.channel_id` 必填，须为与渠道类型匹配的非空字符串。
- **渠道：**含 `app_id_env` 或 `app_secret_env` 的 Lark 渠道配置会被拒绝，v1 渠道配置 schema 也不再列出它们。白名单规范化保持 `null` 为 `null`；不支持的类型现在提示应为列表或逗号分隔字符串。配置导出直接读取 `manager_id`、`bound_chats_only` 和 `channel_bot_seq`，不再探测旧数据库。
- **会话与设置：**`can_resume` 把没有运行时类型的已保存会话视为不可恢复（没有 provider 的 Claude Code 会话仍映射为订阅登录），该会话会重新开始。以改名前的“LoopX”措辞保存的系统 harness 层不再跟随内置 harness。`AgentProfile.from_row` 与 API key 路径只接受当前的 profile 形态。
- **自检：**不受支持的注册表 schema 现在报告 PostgreSQL 检查失败并给出版本错误，缺列不再被读作旧服务。
- **运行记录（`looper/db/llm_records.py`）：**经数据库层读取的记录带有 `metadata.presentation`（来源、系统提示词、库），读取时计算，不写回。订阅等价成本的判断优先用 `metadata.accounting_basis`，其次用 profile（或历史 `agent`）的 provider 认证方式，两者都没有的记录不再按订阅处理。
- **仪表盘（`web/src/lib/api.ts`、`web/src/pages/agent-history.tsx`、`web/src/lib/usage.ts`）：**运行历史页显示 `metadata.presentation` 中的来源和系统提示词，缺失字段显示 `unknown`，不再显示逐个环境变量的来源。
- **测试：**新增和修改的测试覆盖日志封存、记录规范化、桥接准入、配置导出、Lark 与白名单输入、会话恢复和历史页。
- **面向模型的变化：**当前版本的提示词、工具和消息文本均未改变。间接影响：没有已保存运行时类型的会话会新开会话而不是恢复；带旧 LoopX 措辞的系统 harness 层被视为自定义 harness；旧的默认角色提示词不再在启动时迁移。

### 升级与回退

v2.13.208 发布后重新运行 `install.sh`。数据库须已在 v2.13.165 或更高 2.13 版本上并启动过一次。本版本不改变 schema，回退到 v2.13.207 无需恢复数据库；首次启动会写入 `notice-identities-v1` 标记并重写消息日志，v2.13.207 仍可照常读取。

本版本未新增可选能力启用入口。
