# Looper v2.12.3

## Release Decision

**Who should upgrade:** Operators answering user gates from the dashboard, configuring API-key providers through presets or the Manager, or diagnosing failed OMP runs.

**What this release solves:** The dashboard offers inline gate replies in Waiting for you. OpenCode and Sub2API presets use the selected API's model catalog; OpenAI-format presets avoid Claude Code's `[1m]` suffix. DeepSeek gains Responses support, and the Manager can discover presets, register from one and update a provider without handling its key. OMP failures carry the API error, and startup failures name the runtime. See [#255](https://github.com/foolzzz/looper/pull/255), [#257](https://github.com/foolzzz/looper/pull/257) and [#254](https://github.com/foolzzz/looper/pull/254) (fixes [#251](https://github.com/foolzzz/looper/issues/251)).

**Breaking changes:** No. Existing providers and profiles are not rewritten. New preset selections use API-specific model names; existing suffixed names need an explicit edit if their runtime sends them verbatim. The Manager's provider tool description, schema and answers change as listed below.

**How to verify:** Re-run `install.sh`, restart with the existing configuration and runtime root, and check the version below. On a disposable server, answer a user gate from Waiting for you and open its discussion to read back the reply. Select each provider preset's API and check its endpoint and model list. Ask the Manager to list presets, register a DeepSeek Responses provider and update its catalog; read back the provider in Settings. Do not supply a key in chat. Use an intentionally invalid disposable provider to check OMP failure details.

**Contributors:** Release maintainer @foolzzz, author of [#255](https://github.com/foolzzz/looper/pull/255), [#257](https://github.com/foolzzz/looper/pull/257) and [#254](https://github.com/foolzzz/looper/pull/254); thanks to @michaelx1993 for reporting the DeepSeek and Manager provider gaps in [#251](https://github.com/foolzzz/looper/issues/251), fixed by #254.

```bash
looper --version   # looper 2.12.3
looper doctor
```

## Behavior changes

- **Answer a gate from the dashboard.** Waiting for you shows the task, gate topic, first open question and elapsed wait, with an inline reply box and Open the discussion link. It displays at most ten cards from a bounded task read; overflow links lead to the Needs you task list. A sent reply remains visible as You replied while the Planner still owes it an answer. Slow reads are queued; a deleted task does not block other cards from refreshing. End discussion remains on the task page. This uses the existing gate message API; no new backend gate action is added. ([#255](https://github.com/foolzzz/looper/pull/255))
- **Preset models follow the chosen API.** The dashboard and Manager use an API's own model catalog when present, falling back to the preset catalog otherwise. OpenCode's Responses API lists GPT models, Chat Completions lists DeepSeek/GLM/Kimi, and Anthropic Messages lists Claude. These are provider presets, not new agent runtimes. Sub2API is a self-hosted gateway preset, not a gateway installed or started by Looper. ([#257](https://github.com/foolzzz/looper/pull/257))
- **Claude Code's `[1m]` suffix stays on Anthropic-format preset entries.** GLM, Kimi and DeepSeek OpenAI-format catalogs use suffix-free foreground and background names while retaining their context windows. Kimi K3's preset context window is corrected from 1,048,576 to 1,000,000. Saving a provider without Anthropic Messages or a non-Claude-Code profile warns about context-suffixed names, including background models. These are warnings, not rejections or automatic rewrites; the provider form keeps the saved warning visible until acknowledged. ([#257](https://github.com/foolzzz/looper/pull/257), closes [#253](https://github.com/foolzzz/looper/issues/253))
- **DeepSeek's OpenAI-format preset serves Responses and Chat Completions at one base URL.** Its Anthropic-format API remains a separate selection. Existing providers gain no protocol automatically; edit them or register a provider from the updated preset. ([#254](https://github.com/foolzzz/looper/pull/254), fixes [#251](https://github.com/foolzzz/looper/issues/251))
- **The Manager can register from presets and update a provider.** `looper_providers list` includes presets and their per-API catalogs. `register` accepts `preset` and a required `api` protocol, filling the name, protocols, URL, models, context windows, background models and environment defaults; explicit fields override defaults. `update` selects by provider id or name and changes name, protocols, URL, model names or environment through the dashboard's validation. Omitted fields stay; null clears the URL; retained model names keep their price, context, background-model and effort metadata. `preset` and `api` are registration-only. Keys are never accepted by this tool. Unknown models for a recognized preset vendor produce a warning naming known models, independently of price coverage. A missing full price warns that runs record tokens only and spend caps do not apply to those runs. ([#254](https://github.com/foolzzz/looper/pull/254))
- **OMP failures explain the API error.** Failed Manager, Planner and Worker/Reviewer runs carry available provider error text and HTTP status into the failure reason instead of only a generic failure or no reply. Configured keys and common credential forms are redacted before recording error events; displayed failure details are bounded. Adding an RPC error detail preserves session and usage data. A Manager result marked as an error fails even if assistant text already streamed. When Manager, Planner or Worker/Reviewer cannot start a runtime, the error names that runtime. ([#257](https://github.com/foolzzz/looper/pull/257))

## Model-visible changes

The Manager's `looper_providers` tool description now advertises listing providers and presets, registering and updating by id or name, the dashboard-only key boundary, and warnings about unknown models, missing prices and context suffixes. Its schema adds `update`, `provider`, `preset` and `api`, and permits null `base_url`; its answers include presets and warnings. These changes reach dashboard chat, Telegram and Lark through the same Manager tool. The dashboard's gate reply cards reuse the existing gate tools; those channels need no new gate command. There is no new CLI command: preset selection and provider editing remain in Settings or Manager chat. OMP failure details also change the error information available to agents and operators.

## Optional Capability Activation & Use

### Dashboard gate replies

**Activation:** No switch. The dashboard shows Waiting for you when it finds active gates waiting for the user; a bounded read can also show an overflow link to tasks needing attention.

**Validation:** On a disposable server, create a task that opens a user gate. Check the topic and first open question, send a reply, check You replied, and follow Open the discussion to read it back. Check that the section disappears when there is nothing waiting or pending.

```bash
looper --version
looper doctor
```

**Disable / rollback:** Use the task page's discussion instead. There is no separate switch to hide the section; reinstall v2.12.2 to restore the earlier dashboard.

**Authority boundary:** The inline form uses the existing authenticated `POST /api/tasks/<id>/gates/<step>/messages` route. Sending a message does not end the discussion or grant new permissions; End discussion stays on the task page.

**Docs:** [Dashboard gate replies](https://github.com/foolzzz/looper/pull/255).

### Provider presets

**Activation:** In Settings → Providers, add a provider from a preset and select its API, then enter its key in the dashboard and choose it in an Agent Profile. OpenCode uses `https://opencode.ai/inference/openai/v1` for Responses/GPT or Chat Completions/DeepSeek, GLM and Kimi, and `https://opencode.ai/inference/anthropic` for Claude. Sub2API defaults to `http://127.0.0.1:8080/v1` for OpenAI-format APIs and `http://127.0.0.1:8080` for Anthropic Messages; replace the address and catalog to match your gateway. DeepSeek offers Responses plus Chat Completions at `https://api.deepseek.com`, or Anthropic Messages at `https://api.deepseek.com/anthropic`.

**Validation:** Check each selected API's endpoint, protocols and catalog before saving, then read back Settings. GLM, Kimi and DeepSeek OpenAI entries must have no `[1m]` suffix. Check warnings on a deliberately suffixed disposable entry. A successful save does not prove endpoint access, model availability or complete prices; verify those with a disposable run.

```bash
looper --version
looper doctor
```

**Disable / rollback:** Keep existing providers or manually configure a provider instead of using a preset. Clear dependent profile and role selections before removing an unused provider. Reinstalling v2.12.2 restores the old preset choices but does not rewrite providers already saved.

**Authority boundary:** Presets fill editable configuration; they do not authorize access, install a runtime or start a gateway. Keys stay in the dashboard's provider key flow. OpenCode models with built-in prices use vendor list prices, which may differ from gateway billing; some models remain unpriced. Sub2API's served models depend on its configured accounts.

**Docs:** [OpenCode official model/API guide](https://opencode.ai/v2/docs/console/models/), [Sub2API project](https://github.com/Wei-Shaw/sub2api), [DeepSeek Responses guide](https://api-docs.deepseek.com/guides/responses_api/).

### Manager provider management

**Activation:** In dashboard chat, Telegram or Lark, ask the Manager to list provider presets, register one using a chosen API, or update an existing provider. Set its key separately in Settings → Providers. No new switch is required.

**Validation:** On a disposable server, ask for a DeepSeek provider from preset `deepseek` using `openai-responses`; read back that it has both OpenAI protocols and suffix-free models. Update its model names and check retained catalog metadata. Ask for an unknown vendor model and check the warning. Confirm key arguments are rejected rather than sent through chat.

```bash
looper --version
looper doctor
```

**Disable / rollback:** Manage providers in Settings instead. Restore a changed provider there, or ask the Manager to update it again. Reinstall v2.12.2 to restore the earlier list/register-only tool; that does not undo saved provider edits.

**Authority boundary:** Listing is read-only; register and update use the existing write-tool authority and provider validation. The schema has no key field and rejects unknown arguments. The Manager cannot set or change keys. Warnings neither verify model support nor supply missing prices.

**Docs:** [Provider management implementation](https://github.com/foolzzz/looper/pull/254), [Agent registry architecture](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md).

## Validation

These are implementation reports and retained validation artifacts, not runtime checks rerun while drafting this release:

- **Codex reviews:** The rounds for [#255](https://github.com/foolzzz/looper/pull/255#issuecomment-6288686238), [#257](https://github.com/foolzzz/looper/pull/257#issuecomment-6288541843) and [#254](https://github.com/foolzzz/looper/pull/254#issuecomment-6289542101) all ended **not blocking**, after the reported findings were fixed. The final #255 review reports 34 related tests and TypeScript passing; #257 reports 39 in-memory cases, with regular pytest and UI tests unavailable in that review sandbox; #254 reports 74 tests passing and two temporary-directory failures caused by the read-only sandbox.
- **Manager dialogs for #251 / #254:** Opus Manager dialogs passed **54/54**, two repetitions, on `b7500a892`. This predates the final catalog-metadata and model-warning review fixes; it is not a full release-candidate eval on the final merged head.
- **Dashboard #255:** Headless screenshots were captured on a disposable server, including the Waiting for you cards, typed reply, after-send state, empty section and narrow viewport. The final read-only review did not repeat browser validation.

Live calls to OpenCode, Sub2API and DeepSeek, a real provider-backed OMP error run, and a full final-head prompt eval were not rerun for this release draft. A preset or passing documentation gate does not establish those results.

## 中文摘要

### 升级决策

**谁需要升级：**需要在 dashboard 回复用户 gate、通过预设或 Manager 配置 API-key provider，以及排查 OMP 失败的操作者。

**解决了什么：**Waiting for you 支持直接回复 gate；OpenCode 和 Sub2API 新增预设，按所选 API 填模型目录；OpenAI 格式预设不再带 Claude Code 的 `[1m]` 后缀。DeepSeek 新增 Responses；Manager 能列预设、按预设注册和修改 provider，不接触 key。OMP 失败携带 API 错误，启动失败写实际 runtime。见 [#255](https://github.com/foolzzz/looper/pull/255)、[#257](https://github.com/foolzzz/looper/pull/257) 和 [#254](https://github.com/foolzzz/looper/pull/254)（修复 issue [#251](https://github.com/foolzzz/looper/issues/251)）。

**是否有破坏性变更：**无。已有 provider 和 profile 不自动改写。新选预设使用按 API 区分的模型名；已有后缀模型若被 runtime 原样发送，需要主动修改。Manager 工具描述、schema 和返回内容有模型可见变化。

**如何验证：**重跑 `install.sh`，用已有配置和 runtime root 重启并检查版本。在一次性服务上从 Waiting for you 回复 gate，打开讨论读回；逐个选择预设 API 核对地址和模型；让 Manager 列预设、注册 DeepSeek Responses provider 并更新目录，在 Settings 读回。不要在聊天中提供 key；用故意配错的一次性 provider 检查 OMP 错误详情。

**贡献者：**发布维护者 @foolzzz，提交 [#255](https://github.com/foolzzz/looper/pull/255)、[#257](https://github.com/foolzzz/looper/pull/257) 和 [#254](https://github.com/foolzzz/looper/pull/254)；感谢 @michaelx1993 在 [#251](https://github.com/foolzzz/looper/issues/251) 报告 DeepSeek 和 Manager provider 配置问题，由 #254 修复。

### 行为与模型可见变化

- Dashboard 的 Waiting for you 展示任务、gate 主题、首个未决问题和等待时长，最多十张卡片；超出范围链接到 Needs you 列表。发送后保留 You replied 回执，直到 Planner 不再欠该消息的回复；慢读取排队，任务删除不阻塞其他卡片。Open the discussion 直达讨论，End discussion 留在任务页。复用已有消息 API。
- 预设优先使用所选 API 的模型目录，没有时沿用预设目录。OpenCode 的 Responses 对应 GPT，Chat Completions 对应 DeepSeek/GLM/Kimi，Anthropic Messages 对应 Claude。OpenCode 是 provider 预设，不是新增 runtime；Looper 不安装或启动 Sub2API 网关。
- GLM、Kimi、DeepSeek 的 `[1m]` 只留在 Anthropic 格式目录，OpenAI 格式前台及后台模型去后缀、保留 context window；Kimi K3 的窗口由 1,048,576 修正为 1,000,000。保存不含 Anthropic Messages 的 provider，或非 Claude Code 的 profile 时，对带后缀的模型及后台模型给警告，不拒绝、不自动改名；provider 表单保存后保留警告，确认后关闭。#257 关闭 [#253](https://github.com/foolzzz/looper/issues/253)。
- DeepSeek 的 OpenAI 格式 API 在同一地址提供 Responses 和 Chat Completions，Anthropic 格式另选。已有 provider 不自动增加协议。
- `looper_providers list` 返回预设及各 API 目录；`register` 接受 `preset` 和必填 `api` 协议，填默认名称、协议、地址、模型、窗口、后台模型和环境变量，显式字段覆盖默认值。`update` 按 id 或名称修改 provider 的名称、协议、地址、模型名和环境变量，沿用 dashboard 校验。省略字段不改，null 清地址；保留的模型名维持价格、窗口、后台模型及 effort 元数据。`preset`、`api` 仅用于注册，工具不接受 key。识别到预设厂商时，未知模型独立于价格覆盖给出已知模型列表；价格不全警告说明只记 tokens，花费上限不适用于这些运行。
- Manager 的 provider 工具描述新增预设发现、注册、更新和警告说明；schema 增加 `update`、`provider`、`preset`、`api` 及可空地址，返回增加预设和警告。Dashboard chat、Telegram、Lark 共享该工具；gate 卡片沿用已有能力，无新增渠道命令。CLI 无新增命令，入口仍为 Settings 或 Manager chat。
- OMP 的 Manager、Planner、Worker/Reviewer 失败原因携带可用的 API 错误与 HTTP 状态；记录前脱敏配置 key 和常见凭据格式，显示的错误详情有长度限制。RPC 补错误详情保留 session 和 usage；即使已流出 assistant 文本，Manager 的错误结果仍判失败。启动失败写实际 runtime 名称。错误信息变化也影响 agent 和操作者看到的内容。

### 可选能力启用与使用

#### Dashboard gate replies

**启用：**无需开关。发现活跃 gate 等待用户时，dashboard 显示 Waiting for you；有未读取任务时也可显示更多任务入口。

**验证：**在一次性服务创建会打开用户 gate 的任务，核对主题和首个问题，发送回复并检查 You replied，再打开讨论读回；无等待或待处理回复时区块消失。

```bash
looper --version
looper doctor
```

**停用 / 回退：**继续在任务页讨论中回复即可；无单独隐藏开关，回装 v2.12.2 恢复原 dashboard。

**权限边界：**复用已有鉴权的 `POST /api/tasks/<id>/gates/<step>/messages`，发送消息不结束讨论、不增加权限；End discussion 仍在任务页。

**文档：**[Dashboard gate 回复](https://github.com/foolzzz/looper/pull/255)。

#### Provider presets

**启用：**Settings → Providers 按预设新增 provider、选择 API，在 dashboard 输入 key，再由 Agent Profile 选择。OpenCode 的 Responses/GPT 和 Chat Completions/DeepSeek、GLM、Kimi 使用 `https://opencode.ai/inference/openai/v1`，Claude 使用 `https://opencode.ai/inference/anthropic`。Sub2API 的 OpenAI 格式默认 `http://127.0.0.1:8080/v1`，Anthropic 格式默认 `http://127.0.0.1:8080`，按自建网关修改地址和目录。DeepSeek 的 Responses 与 Chat Completions 同用 `https://api.deepseek.com`，Anthropic Messages 使用 `https://api.deepseek.com/anthropic`。

**验证：**核对所选 API 的地址、协议、目录，保存后读回 Settings。GLM、Kimi、DeepSeek 的 OpenAI 格式模型不应带 `[1m]`；用一次性后缀条目检查警告。保存成功不代表接口可访问、模型可用或价格完整，应另用一次性运行验证。

```bash
looper --version
looper doctor
```

**停用 / 回退：**保留已有 provider，或手动填写而不选预设；删除闲置 provider 前先解除 profile 和角色引用。回装 v2.12.2 恢复旧预设，不自动改写已保存的 provider。

**权限边界：**预设只填可编辑配置，不授予访问权、不安装 runtime、不启动网关；key 走 dashboard 的既有入口。OpenCode 命中内置价格表时使用厂商标价，可能与网关账单不同，部分模型仍无价格。Sub2API 的模型取决于其账号配置。

**文档：**[OpenCode 官方模型/API 指南](https://opencode.ai/v2/docs/console/models/)、[Sub2API 项目](https://github.com/Wei-Shaw/sub2api)、[DeepSeek Responses 指南](https://api-docs.deepseek.com/guides/responses_api/)。

#### Manager provider management

**启用：**在 dashboard chat、Telegram 或 Lark 让 Manager 列预设、选择 API 注册 provider，或修改已有 provider；key 单独在 Settings → Providers 设置，无新增开关。

**验证：**在一次性服务用 `deepseek` 预设及 `openai-responses` 注册，读回两个 OpenAI 协议和无后缀模型；更新模型名并核对保留条目的元数据；未知厂商模型应给警告，key 参数应被拒绝。

```bash
looper --version
looper doctor
```

**停用 / 回退：**改用 Settings 管理；在界面或通过 Manager 再次更新以恢复配置。回装 v2.12.2 恢复只有 list/register 的工具，不撤销已保存的修改。

**权限边界：**list 只读，register/update 使用已有写工具权限及 provider 校验。schema 无 key 字段，拒绝未知参数，Manager 不能设置或更换 key。警告不验证模型支持、不补价格。

**文档：**[Provider 管理实现](https://github.com/foolzzz/looper/pull/254)、[Agent 注册架构](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md)。
