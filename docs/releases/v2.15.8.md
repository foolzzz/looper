# Looper v2.15.8

This is the patch release v2.15.8, a hotfix line in which each merged change ships at once. It documents one change: [#1386](https://github.com/foolzzz/looper/pull/1386) (the `room_consult` eval task now has the first step write its value down, and a test pins that the `no_snapshot` reason reaches the asker). The change is in the eval task, its README and the tests only.

## Release Decision

**Who should upgrade:** No one needs this release for its behavior. It is the version that carries the reworked `room_consult` eval task; an installation on v2.15.7 runs the same `looper` package code.

**What this release solves:** [#1386](https://github.com/foolzzz/looper/pull/1386) (fixes #1381) changes the `room_consult` prompt-regression task so that its first step saves the generated code to `generated-code.txt` and commits it, in a git repository, before finishing, and so the second step must ask the first for the code. Until now the code could live only in a process that had ended (an unprinted OMP kernel, a Codex exec session), which no consult could read. The PR also adds a test that a consult refused for lack of a git checkout (`no_snapshot`) tells the asking seat the reason.

**Breaking changes:** No. The CLI, the API and the dashboard are unchanged, no new command or control is added and there is no PostgreSQL schema change. The PR changes no file in the `looper` package. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.8
```

**Contributors:** Maintainer @foolzzz authored [#1386](https://github.com/foolzzz/looper/pull/1386); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.7 upgrades directly. There is no PostgreSQL schema change. Restart the service after upgrading, as for every release.

## Behavior changes

Read in the diff of the PR.

### #1386: The `room_consult` eval task writes its value down

- **Eval task only.** The diff touches `evals/README.md`, `evals/prompt_regression/tasks.py`, `tests/test_prompt_eval.py` and `tests/test_room_consult_db.py`, and nothing under `looper/`. The PR reports production lines added as 0.
- **Task.** `room_consult` now sets `init_git=True`. Its first step saves the code to `generated-code.txt` in its working directory and the SHA-256 to `code.sha256`, and commits both before finishing; it keeps the code out of its report and unsolicited messages. The second step asks the first for the code "rather than reading its saved copy" and writes it to `code.txt`. The scripted fake run saves the code to the file as well. The check (`_code_matches`) and the `min_room_consults` expectation of 1 are unchanged, so the task does not itself fail a run that reads the saved file.
- **Tests.** A new test pins the task's git setup, its requirement wording and that the fake first step writes the consult answer into `generated-code.txt`. A new database test runs an OMP consult whose task directory is not a git checkout and asserts the fallback `no_snapshot` with its detail ("not a git checkout ... cannot be kept from writing"), the notice that reaches the asker (replying to its question, naming `no_snapshot` and the detail, and saying the Planner has it), the escalation to the Planner, no answer message and one recorded LLM call. The detail text is existing production behavior in `looper/agents/consult.py`; the PR adds the test, not the behavior.
- **Behavior change.** None in the shipped package. Running the eval changes: the task now needs a git repository, and a first step must commit its value.

### Model-visible changes

None in the product: prompts, prompt contracts, the consult contract and tool schemas in the `looper` package are unchanged. The only changed model-visible text is the `room_consult` eval task's requirement, which the eval's agents read when the eval runs.

## Validation

**Reported by [#1386](https://github.com/foolzzz/looper/pull/1386):** the tests that cover the change (`tests/test_prompt_eval.py`, `tests/test_room_consult.py`, `tests/test_room_consult_db.py`), automated reviews, and CI before the merge. The PR reports no full-suite run. In a PR comment, the maintainer reports a real-path run of `room_consult` on Codex and on OMP, two repetitions each: 2/2 passed on both, against 1/2 on main; OMP `no_snapshot` went from one per repetition to none; every second-step Worker asked the first step's seat. It also reports one Codex repetition that passed only after a retry, because a consult answered without the code, and that the new `no_snapshot` test passed locally against a disposable PostgreSQL (7 passed) while the three test files were not finished in full locally. The `no_snapshot` reason is covered by the new test only, not by the real runs.

**Review findings left open:** automated reviews of the PR raised that the check still passes if the consult fails and the second step copies the saved file, since only the consult count is required, and that the saved file sits in the checkout the second step shares. The PR was merged with these as follow-ups; this release does not address them. A wording suggestion that the second step, not the first, must not read the saved file is also a follow-up.

**CI:** CI runs after the release is drafted; its result is not recorded here.

**Not tested for this draft:** a local full suite, other runtimes than Codex and OMP (Pi, Grok, Cursor Agent, Claude Code) and the built wheel. The release documentation gate checks the body only.

### 行为变化与入口

以下在该 PR 的差异中可见。

**#1386：`room_consult` 评测任务把值写下来**

- **仅评测任务。**差异涉及 `evals/README.md`、`evals/prompt_regression/tasks.py` 和两个测试文件，`looper/` 下没有任何改动；PR 报告新增生产代码行数为 0。
- **任务。**`room_consult` 现在设置 `init_git=True`。第一步把代码保存到工作目录的 `generated-code.txt`，把 SHA-256 写入 `code.sha256`，并在结束前提交两者；代码不进入其报告和主动消息。第二步向第一步询问代码（“而不是读取其保存的副本”），再写入 `code.txt`。脚本化的假运行也会把代码写入该文件。检查函数 `_code_matches` 和 `min_room_consults` 为 1 的期望不变，因此该任务本身不会让读取保存文件的运行失败。
- **测试。**新测试固定任务的 git 设置、需求措辞，以及假的第一步把咨询答案写入 `generated-code.txt`。新的数据库测试运行一个任务目录不是 git 检出的 OMP 咨询，断言回退为 `no_snapshot` 及其详情、送达提问方的通知（回复其问题、写明 `no_snapshot` 和详情、并说明 Planner 已接手）、向 Planner 的升级、没有答复消息和一条 LLM 记录。该详情文本是 `looper/agents/consult.py` 中已有的生产行为；PR 新增的是测试，而不是行为。
- **行为变化。**已发布的包中没有。运行评测时有变化：任务现在需要 git 仓库，第一步必须提交其值。

**面向模型的变化：**产品中无：`looper` 包内的提示词、提示词契约、咨询契约和工具 schema 不变。唯一变化的面向模型文本是 `room_consult` 评测任务的需求，评测运行时其智能体会读到。
