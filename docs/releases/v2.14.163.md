# Looper v2.14.163

This is the patch release v2.14.163, a hotfix line in which each merged change ships at once. It documents two changes: [#1294](https://github.com/foolzzz/looper/pull/1294) (LLM gateway follow-ups) and [#1295](https://github.com/foolzzz/looper/pull/1295) (service command follow-ups).

## Release Decision

**Who should upgrade:** Installations that use the LLM gateway, run `looper service` upgrade, restart or uninstall (especially with an IPv6 host), or chain `loopercli stop` with `loopercli start`. Others need not upgrade for behavior.

**What this release solves:** [#1294](https://github.com/foolzzz/looper/pull/1294) fixes the listed valid items of the review follow-ups #1155, #1161 and #1163: gateway route ids, upstream URLs with queries, prefix-history grouping and the printed client environment. [#1295](https://github.com/foolzzz/looper/pull/1295) fixes the listed valid items of #1168 and #999: IPv6 hosts in service commands, unit cleanup, uninstall and probe recovery, and `loopercli stop` waiting.

**Breaking changes:** No. There is no API change, migration or schema change. `loopercli stop` now waits up to 30 seconds and can exit 6 (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.163
```

**Contributors:** Maintainer @foolzzz authored [#1294](https://github.com/foolzzz/looper/pull/1294) and [#1295](https://github.com/foolzzz/looper/pull/1295); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.162 upgrades directly. There is no schema change.

## Behavior changes

Both pull requests state that the behavior changes follow the triage notes' fixes (maintainer decision, intended). Read in the code:

[#1294](https://github.com/foolzzz/looper/pull/1294) changes `looper/agents/llmrec/` (`__init__.py`, `gateway.py`, `proxy.py`, `translate.py`), `looper/agents/runtimes/claude_code.py`, `looper/gateway_env.py` and three test files.

- **Route ids.** A gateway route id is hashed from the alias, provider id, upstream URL, upstream model and dialect, not the alias alone, so a changed binding gets a new route id.
- **Upstream URLs with queries.** `/chat/completions` is appended to the URL's path; a query string stays at the end.
- **Prefix-history grouping.** A new `resolve_session_id` takes the `x-claude-code-session-id` header, else the session suffix of `metadata.user_id`. The proxy uses it for the history key of external routes and for the prefix history, so a client that sends the session only in the metadata is grouped per session. The translation uses the same function, so the `prompt_cache_key` derivation is unchanged.
- **Client environment.** `gateway_environment` also sets `CLAUDE_CODE_USE_BEDROCK`, `_VERTEX`, `_FOUNDRY`, `_ANTHROPIC_AWS`, `_ANTHROPIC_GOOGLE_CLOUD`, `_MANTLE` and `_GATEWAY` to `0`. The list moved to `looper/agents/llmrec/__init__.py` (`TRANSLATED_BACKEND_ENV`) and the Claude Code runtime imports it; the runtime's values are unchanged.
- **Alias cache.** The ten-second TTL check compares against the stored time plus ten seconds instead of subtracting timestamps.

[#1295](https://github.com/foolzzz/looper/pull/1295) changes `looper/agents/service.py`, `looper/loopercli.py`, `docs/architecture/agent-system.md` and five test files.

- **IPv6 and configured hosts.** The upgrade and planned-restart paths read the unit's configured host and pass it as `address` to the components, whoami, index, status, drain, health and start-and-wait calls, and to the port-in-use checks, instead of a fixed `127.0.0.1`.
- **Probe units.** `remove_probe_units` no longer returns early when no unit file exists; it always stops the timer and the service and reloads the manager. A failed install rewrites an old file only when its content differs from the saved copy.
- **Uninstall.** `uninstall` also catches `OSError` from probe cleanup, and removes the service unit even when reading its state raises.
- **`loopercli stop TASK`.** After the stop request is accepted it polls `tasks.get` for up to 30 seconds until the task is `init`, `stopped`, `failed`, `completed` or `cancelled`, then prints `TASK: <status>` (or the unchanged JSON answer with `--json`). If it is still stopping it prints a `wait_timeout` error and exits 6. A server without `tasks.get` makes it fail with a usage error.
- **Model-visible changes:** None in either pull request. No prompt, tool description, schema or answer text changes; the upstream request bodies are built as before.

### 行为变化与入口

两个 PR 都声明行为变化遵循分诊记录中的修复（维护者决定，符合预期）。代码中可见：

[#1294](https://github.com/foolzzz/looper/pull/1294) 改动 `looper/agents/llmrec/`（`__init__.py`、`gateway.py`、`proxy.py`、`translate.py`）、`looper/agents/runtimes/claude_code.py`、`looper/gateway_env.py` 及三个测试文件。

- **路由 id。**网关路由 id 由别名、提供方 id、上游 URL、上游模型和方言共同哈希得出，不再只用别名；绑定改变后路由 id 随之改变。
- **带查询串的上游 URL。**`/chat/completions` 追加到 URL 的路径部分，查询串保持在末尾。
- **前缀历史分组。**新增 `resolve_session_id`：优先取 `x-claude-code-session-id` 请求头，否则取 `metadata.user_id` 中的会话后缀。代理用它生成外部路由的历史键和前缀历史，因此只在 metadata 中携带会话的客户端也按会话分组。翻译使用同一函数，`prompt_cache_key` 的推导不变。
- **客户端环境。**`gateway_environment` 还会把 `CLAUDE_CODE_USE_BEDROCK`、`_VERTEX`、`_FOUNDRY`、`_ANTHROPIC_AWS`、`_ANTHROPIC_GOOGLE_CLOUD`、`_MANTLE`、`_GATEWAY` 设为 `0`。该列表移到 `looper/agents/llmrec/__init__.py`（`TRANSLATED_BACKEND_ENV`），Claude Code 运行时改为导入它，运行时的取值不变。
- **别名缓存。**十秒 TTL 的判断改为与“存入时间加十秒”比较，不再用时间戳相减。

[#1295](https://github.com/foolzzz/looper/pull/1295) 改动 `looper/agents/service.py`、`looper/loopercli.py`、`docs/architecture/agent-system.md` 及五个测试文件。

- **IPv6 与配置的主机。**升级和计划重启路径读取单元配置的主机，并把它作为 `address` 传给 components、whoami、index、status、drain、health 和启动等待调用以及端口占用检查，不再固定使用 `127.0.0.1`。
- **探针单元。**`remove_probe_units` 在没有单元文件时不再提前返回，始终停止定时器和服务并重新加载管理器。安装失败回滚时，仅当旧文件内容与保存的副本不同才重写。
- **卸载。**`uninstall` 还会捕获探针清理中的 `OSError`，并且即使读取状态抛错也会移除服务单元。
- **`loopercli stop TASK`。**停止请求被接受后，它轮询 `tasks.get` 最多 30 秒，直到任务为 `init`、`stopped`、`failed`、`completed` 或 `cancelled`，然后打印 `TASK: <status>`（使用 `--json` 时输出原有 JSON 回答）。仍在停止则打印 `wait_timeout` 错误并以退出码 6 结束。服务端没有 `tasks.get` 时以用法错误失败。
- **面向模型的变化：**两个 PR 均无。提示词、工具描述、schema 和回答文本均未改动，上游请求体的构造方式不变。
