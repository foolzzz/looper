# Looper v2.13.63

## Release Decision

**Who should upgrade:** Nobody needs to. This release changes documentation only; maintainers and contributors who plan the API runtime can read the new RFC.

**What this release solves:** [#475](https://github.com/foolzzz/looper/pull/475) adds an approved RFC for an API runtime: an agent runtime that calls model APIs directly through the official Python SDKs instead of driving a CLI, with the Manager as its first and only role. It also adds the development schedule. No code changes.

**Breaking changes:** No. No code, route, stored data or configuration changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#475](https://github.com/foolzzz/looper/pull/475); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.63
```

## Behavior changes

- **None.** The pull request touches two documents only: `docs/architecture/rfcs/api-runtime-v0.zh-CN.md` (new, 408 lines) and `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md` (4 lines added). The version number is the only code change in this release.
- **What the RFC proposes (not implemented):**
  - a new `api` runtime type behind `ResidentSession`, chosen over a Manager-only loop inside the Manager tier and an out-of-process runner;
  - a turn loop that calls `ManagerOps.call` in process, so two-step confirmation, audit and turn binding stay as they are, with at most 30 model requests per turn (decision D10);
  - sessions stored as native transcript items in a new PostgreSQL table, with resume and a context threshold that reuses the existing handoff;
  - the provider layer stays Provider → Endpoint → Model → Agent Profile, with credentials given explicitly and SDK environment variables refused at start; rollout is by Profile selection, with `/profile` as the way back;
  - the schedule (section 12.1): stage 1 is the `openai` SDK with OpenAI Responses on the local proxy, in seven PR-sized steps; stage 2 is the `anthropic` SDK on Anthropic Messages endpoints, plus DeepSeek validation.
- **Plan update:** section 5.0 item 23 of the long-horizon context plan marks the RFC approved and lists stage 1 and stage 2.
- **Model-visible changes:** None. Manager, Worker, Planner and Reviewer prompts and Manager Tools are unchanged; the RFC only describes model-visible content that a later implementation would have to keep.

## Upgrade and rollback

Re-run `install.sh` once v2.13.63 is published. No data migration and nothing to change. Rolling back to v2.13.62 only removes the two documentation changes.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

It reports that SDK claims were checked offline in a throwaway virtual environment (`openai` 3.37.0, `anthropic` 2.3.0), and that a local stub server showed cancelling a streaming request returns at once and the server sees the connection close, with both SDKs. No request with a real key was made; every behavior that needs a real endpoint is marked in the RFC as needing verification. The pull request reports no review verdicts and no local full suite. This draft did not re-run any of it.

### 行为变化与入口

- **无。**该 PR 只改两份文档：`docs/architecture/rfcs/api-runtime-v0.zh-CN.md`（新增，408 行）和 `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`（新增 4 行）。本版本唯一的代码改动是版本号。
- **RFC 的提议（尚未实现）：**
  - 在 `ResidentSession` 之后新增 `api` 运行时类型，而不是放进 Manager 层的独立循环或进程外 runner；
  - 一轮的循环在进程内调用 `ManagerOps.call`，两步确认、审计和轮次绑定不变，每轮最多 30 次模型请求（决定 D10）；
  - 会话以原生 transcript 条目存入 PostgreSQL 新表，支持恢复，上下文阈值沿用现有 handoff；
  - Provider 层仍是 Provider → Endpoint → Model → Agent Profile，凭据显式给出，启动时拒绝 SDK 环境变量；通过选择 Profile 上线，`/profile` 可退回；
  - 排期（12.1 节）：第一阶段用 `openai` SDK，在本地代理上走 OpenAI Responses，分七个 PR 大小的步骤；第二阶段用 `anthropic` SDK 接 Anthropic Messages 接口，并验证 DeepSeek。
- **计划更新：**长程上下文计划 5.0 节第 23 项标记 RFC 已批准，并列出第一、二阶段。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 和 Manager Tool 均不变；RFC 只描述后续实现必须保持的模型可见内容。
