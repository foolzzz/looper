# Looper v2.13.99

## Release Decision

**Who should upgrade:** Anyone who saves Manager task templates through the API or the dashboard and wants a template that takes no inputs.

**What this release solves:** [#576](https://github.com/foolzzz/looper/pull/576) makes an omitted `inputs` field on a Manager template save mean an empty input list. Before, `inputs` was required, so a template with a plain requirement and no placeholders could not be saved without spelling out an empty list.

**Breaking changes:** No. No configuration, prompt or Tool declaration changed. A request that omitted `inputs` was refused before and is accepted now; requests that supplied `inputs` behave as before.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#576](https://github.com/foolzzz/looper/pull/576); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.99
```

## Behavior changes

- **Omitted template inputs default to an empty list ([#576](https://github.com/foolzzz/looper/pull/576)):** `put_template` in `looper/agents/managers_api.py` now calls `parse_inputs(data.get("inputs", []))`. When the request has no `inputs` key, the template is stored with no inputs, for both create and replace. On replace, the previously stored inputs are not kept. The saved template reads back with `inputs` equal to `[]`, both in the save answer and in the manager list.
- **Unchanged refusals:** An explicit `null` is not treated as omitted. `null`, an empty string, an object, a boolean, a number, a list of strings, and items that are empty or lack a `label` are still refused. A requirement that names a placeholder with no matching input (for example `{{nope}}`) is still refused with "names no input", and a refused save leaves the existing definition untouched.
- **Model-visible changes:** none for prompts, Tool declarations and Tool results. The change is one production line in the template save path.
- **Tests:** `tests/test_api_v1_managers_templates_db.py` adds create and replace cases for omitted and empty inputs, a case that an omitted `inputs` still refuses an unresolved placeholder, and extra invalid `inputs` shapes in the validation table. The pull request reports 59 added test lines and 1 production line.

## Upgrade and rollback

Re-run `install.sh` once v2.13.99 is published. No data migration and no configuration change. Rolling back to v2.13.98 makes a template save without `inputs` refused again.

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**通过 API 或仪表盘保存 Manager 任务模板、并希望保存不带输入的模板的用户。

**解决了什么：**[#576](https://github.com/foolzzz/looper/pull/576) 让 Manager 模板保存请求中省略的 `inputs` 字段表示空输入列表。此前 `inputs` 必须提供，需求里没有占位符的模板也必须显式写出空列表才能保存。

**是否有破坏性变更：**否。配置、prompt 和 Tool 声明均未改变。此前省略 `inputs` 的请求会被拒绝，现在被接受；提供了 `inputs` 的请求行为不变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.99。

**贡献者：**维护者 @foolzzz 提交 [#576](https://github.com/foolzzz/looper/pull/576)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.99
```

### 行为变化与入口

- **省略的模板输入默认为空列表（[#576](https://github.com/foolzzz/looper/pull/576)）：**`looper/agents/managers_api.py` 中的 `put_template` 现在调用 `parse_inputs(data.get("inputs", []))`。请求没有 `inputs` 键时，模板以无输入保存，创建和替换都一样。替换时不会保留之前存储的输入。保存应答和 manager 列表读回的模板 `inputs` 都等于 `[]`。
- **不变的拒绝规则：**显式 `null` 不被当作省略。`null`、空字符串、对象、布尔值、数字、字符串列表，以及为空或缺少 `label` 的条目仍被拒绝。需求中的占位符（例如 `{{nope}}`）没有对应输入时仍以 "names no input" 拒绝，被拒绝的保存不改动已有定义。
- **面向模型的变化：**prompt、Tool 声明和 Tool 结果均无变化。改动只是模板保存路径上的一行生产代码。
- **测试：**`tests/test_api_v1_managers_templates_db.py` 新增省略和空输入的创建与替换用例、省略 `inputs` 仍拒绝未解析占位符的用例，并在校验表中增加了更多无效 `inputs` 形态。该 PR 报告新增测试 59 行、生产代码 1 行。

### 升级与回退
