# Looper v2.14.135

This is the patch release v2.14.135, a hotfix line in which each merged change ships at once. It documents one change: [#1234](https://github.com/foolzzz/looper/pull/1234) (SUPERVISE reads each running Worker's newest activity).

## Release Decision

**Who should upgrade:** Operators whose tasks run long enough to log more than 400 activity rows, because the Planner's SUPERVISE turns showed later Workers as having no activity. Everyone else gets no visible change.

**What this release solves:** [#1234](https://github.com/foolzzz/looper/pull/1234) makes a SUPERVISE report read each running Worker's six newest activity rows, instead of filtering the task's oldest 400 rows, so a later Worker no longer shows "(no activity yet)".

**Breaking changes:** No. There is no migration and no API removal. The SUPERVISE message content changes (see Behavior changes), and the Planner's nudge and kill decisions may change with it. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.135
```

**Contributors:** Maintainer @foolzzz authored [#1234](https://github.com/foolzzz/looper/pull/1234); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.134 upgrades directly. There is no schema change.

## Behavior changes

- **SUPERVISE reads each running Worker's newest activity** ([#1234](https://github.com/foolzzz/looper/pull/1234)). The running-Worker report in a `[SUPERVISE]` turn used to read the task's oldest 400 activity rows and keep the last six that belonged to the Worker. On a task with more than 400 activity rows, a later Worker therefore showed "(no activity yet)". It now calls a new query, `list_worker_activity` (`looper/db/activity.py`), which returns that Worker's newest rows for the task (default 6, capped at 50), oldest first, with summary but no detail. The query filters by task and Worker in the database, so it no longer depends on how many rows the task has.
- **Planner decisions may change.** On tasks with more than 400 activity rows, the Planner now sees the running Workers' real recent activity, so its nudge and kill decisions may differ from before. The maintainer decided this change is intended.
- **A step with no Worker id** reports "(no activity yet)" without a query. If the query fails, the report still says "(recent activity is unavailable)".
- **Unchanged:** the rest of the SUPERVISE message, its cadence and its reply contract. The architecture document `docs/architecture/agent-system.md` gains two lines describing the report.
- **Model-visible changes:** Yes. The content of the SUPERVISE message changes: the activity lines under each running step now show the Worker's newest rows. No tool description, prompt template, reply contract or run `AGENTS.md` text changes.

### 升级决策

**谁需要升级：**任务活动记录超过 400 行的运维者，因为 Planner 的 SUPERVISE 轮次会把较晚的 Worker 显示为没有活动。其他人没有可见变化。

**解决了什么：**[#1234](https://github.com/foolzzz/looper/pull/1234) 让 SUPERVISE 报告读取每个运行中 Worker 最新的六行活动，而不是在任务最旧的 400 行中过滤，较晚的 Worker 不再显示“(no activity yet)”。

**是否有破坏性变更：**否。没有迁移，没有移除 API。SUPERVISE 消息内容有变化（见下文），Planner 的提醒与终止决策可能随之变化。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.14.135。

**贡献者：**维护者 @foolzzz 提交 [#1234](https://github.com/foolzzz/looper/pull/1234)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.135
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.134 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **SUPERVISE 读取每个运行中 Worker 的最新活动**（[#1234](https://github.com/foolzzz/looper/pull/1234)）。`[SUPERVISE]` 轮次中的运行中 Worker 报告以前读取任务最旧的 400 行活动，再保留属于该 Worker 的最后六行；活动超过 400 行的任务里，较晚的 Worker 因此显示“(no activity yet)”。现在改用新查询 `list_worker_activity`（`looper/db/activity.py`），返回该 Worker 在任务中最新的行（默认 6，上限 50），按从旧到新排列，只含摘要、不含 detail。过滤在数据库中按任务和 Worker 完成，不再取决于任务有多少行。
- **Planner 决策可能变化。**活动超过 400 行的任务里，Planner 现在看到运行中 Worker 的真实近期活动，其提醒与终止决策可能与以前不同。维护者确认这是预期变化。
- **没有 Worker id 的步骤**不经查询直接报告“(no activity yet)”；查询失败时仍报告“(recent activity is unavailable)”。
- **不变：**SUPERVISE 消息的其余部分、节奏和回复契约。架构文档 `docs/architecture/agent-system.md` 新增两行说明该报告。
- **面向模型的变化：**有。SUPERVISE 消息内容变化：每个运行步骤下的活动行现在显示该 Worker 最新的行。没有工具描述、提示词模板、回复契约或运行 `AGENTS.md` 文本变化。
