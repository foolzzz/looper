# Looper v2.13.196

## Release Decision

**Who should upgrade:** Developers of runner integrations and operators who run the opt-in runner path (`[runtimes] pi = "runner"`) and want the Pi runner to accept Worker, Reviewer and forked sessions. Everyone else sees no difference: no existing session changes, and the default stays on the Pi CLI. It is a hotfix that ships the change merged since v2.13.195.

**What this release solves:** [#835](https://github.com/foolzzz/looper/pull/835) teaches the TypeScript Pi runner the run side of the protocol that v2.13.195 added to the host: the `worker` and `reviewer` roles, a validated per-session tool timeout, and `session/new` with `fork_from`, which opens a new session from a saved one.

**Breaking changes:** No. No command, database schema, file format or setting changed. The runner accepts more values than before (two roles, a positive `tool_timeout_s`, an optional `fork_from`) and reports one more capability (`fork`). Sessions of the existing roles open as before, with one stricter check described under Behavior changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#835](https://github.com/foolzzz/looper/pull/835); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.196
```

## Behavior changes

- **Roles (`runners/pi/src/session.ts`):** `session/new` and `session/load` accept `worker` and `reviewer` besides `manager` and `planner`.
- **Limits (`session.ts`):** the runner now requires `limits` to be an object with `tool_timeout_s` a positive integer and `max_requests_per_turn` a non-negative integer, and refuses the request with the invalid-parameters error otherwise. Both fields are required: a request that omits `limits` or either field is refused. The Python host in v2.13.195 sends both, so existing host traffic is unaffected; a hand-written client that omitted them would now be refused.
- **Fork (`session.ts`, `sdk.ts`, `main.ts`):** `session/new` takes an optional `fork_from` object with a non-empty `session_id`. The runner finds the saved session whose header id equals it in the session's state directory; zero or more than one match is refused with `session not found`. The new session is opened with the SDK's `SessionManager.forkFrom` (source file, working directory, state directory) instead of `create`, and the open fails if the new session reports the source's id. The source is resolved before any session slot or key is reserved, so a refused fork leaves no reservation. `session/load` with `fork_from` is refused as invalid parameters. The pull request's test checks that the original file and other files in the state directory keep their content.
- **Version gate (`sdk.ts`):** loading the Pi SDK now also requires `SessionManager.forkFrom` to be a function; an SDK without it is refused at load with `missing exports: SessionManager.forkFrom`.
- **Capability (`main.ts`):** the `initialize` result reports `fork: true`, which the host (since v2.13.195) requires before it sends `fork_from`.
- **Docs and scope:** 6 files changed, about 260 lines including tests. The runner source changes are small (`runners/pi/src/`: about 16 added lines in three files); the rest is tests, including the new `tests/test_pi_runner_runs.py`. The pull request description reports "tests 246, production 0 (fixtures excluded)"; that "production 0" does not match the TypeScript runner changes above, so this body describes them from the code.
- **Model-visible changes:** None. No prompt, tool description or tool result changed. The runner path is opt-in, and the sessions it newly accepts (Worker, Reviewer, forks) are not started by any host path in this release.

## Upgrade and rollback

Re-run `install.sh` once v2.13.196 is published. There is nothing to configure. To roll back, return to v2.13.195; there is no schema or setting change.

### 升级决策

**谁需要升级：**开发 runner 集成、或使用选择加入的 runner 路径（`[runtimes] pi = "runner"`）并希望 Pi runner 支持 Worker、Reviewer 和分叉会话的运维者；其他用户无差别，现有会话不变，默认仍走 Pi CLI。本版本是随合并即发布的 hotfix，包含 v2.13.195 之后合并的改动。

**解决了什么：**[#835](https://github.com/foolzzz/looper/pull/835) 让 TypeScript Pi runner 支持 v2.13.195 在宿主侧加入的运行协议：`worker` 和 `reviewer` 角色、经过校验的每会话工具超时，以及带 `fork_from` 的 `session/new`（从已保存会话打开新会话）。

**是否有破坏性变更：**无。命令、数据库 schema、文件格式和设置均未改变。runner 接受更多取值（两个角色、正数 `tool_timeout_s`、可选 `fork_from`）并多报告一个能力（`fork`）；既有角色的会话照常打开，仅多一项更严格的检查，见行为变化。

**如何验证：**运行 `looper --version` 核对版本为 2.13.196。

**贡献者：**维护者 @foolzzz 提交 [#835](https://github.com/foolzzz/looper/pull/835)；本次 patch release 无社区贡献。

### 行为变化与入口

- **角色（`runners/pi/src/session.ts`）：**`session/new` 和 `session/load` 除 `manager`、`planner` 外还接受 `worker`、`reviewer`。
- **限制（`session.ts`）：**runner 现在要求 `limits` 为对象，其中 `tool_timeout_s` 为正整数、`max_requests_per_turn` 为非负整数，否则以无效参数错误拒绝。两个字段都必填：缺少 `limits` 或任一字段的请求会被拒绝。v2.13.195 的 Python 宿主两者都会发送，因此现有宿主流量不受影响；省略它们的手写客户端现在会被拒绝。
- **分叉（`session.ts`、`sdk.ts`、`main.ts`）：**`session/new` 可带可选的 `fork_from` 对象，含非空 `session_id`。runner 在该会话的状态目录中查找头部 id 与之相等的已保存会话；零个或多个匹配以 `session not found` 拒绝。新会话用 SDK 的 `SessionManager.forkFrom`（源文件、工作目录、状态目录）而非 `create` 打开；若新会话报告的 id 与源相同则打开失败。源在预留任何会话名额或 key 之前解析，因此被拒绝的分叉不留下预留。带 `fork_from` 的 `session/load` 以无效参数拒绝。PR 的测试检查原文件及状态目录中其他文件内容不变。
- **版本 gate（`sdk.ts`）：**加载 Pi SDK 时现在还要求 `SessionManager.forkFrom` 是函数；缺少时加载即被拒绝，错误为 `missing exports: SessionManager.forkFrom`。
- **能力（`main.ts`）：**`initialize` 结果报告 `fork: true`；宿主（自 v2.13.195 起）要求该能力才会发送 `fork_from`。
- **文档与范围：**共改动 6 个文件，含测试约 260 行。runner 源码改动很小（`runners/pi/src/` 三个文件约新增 16 行），其余是测试，包括新增的 `tests/test_pi_runner_runs.py`。PR 描述写的是“测试 246 行、生产代码 0 行（不含夹具）”，与上述 TypeScript runner 改动不符，因此本文按代码描述。
- **面向模型的变化：**无。提示词、工具描述和工具结果均未改变。runner 路径需主动选择，本版本中没有任何宿主路径会启动它新支持的会话（Worker、Reviewer、分叉）。
