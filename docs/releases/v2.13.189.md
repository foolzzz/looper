# Looper v2.13.189

## Release Decision

**Who should upgrade:** Maintainers and contributors who run Looper's browser tests. Other users see no difference. It is a hotfix that ships the change merged since v2.13.188.

**What this release solves:** [#816](https://github.com/foolzzz/looper/pull/816) makes every browser test serve the staged dashboard (`looper/web/dashboard`) and never a leftover `web/dist` build (issue #811).

**Breaking changes:** No. No command, database schema or file format changed, and the variable the change reads is unset in every install.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#816](https://github.com/foolzzz/looper/pull/816); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.189
```

## Behavior changes

- **Static-directory override ([#816](https://github.com/foolzzz/looper/pull/816)):** `default_static_dir()` in `looper/agents/http_server.py` returns the directory named by the environment variable `PYTEST_LOOPER_STATIC_DIR` when it is set and non-blank. Otherwise it behaves as before: the checkout build when present, else the packaged dashboard. Nothing in Looper sets the variable; an install leaves it unset, so a running Looper serves the same files as in v2.13.188. This is the only production change (3 lines).
- **Tests:** `tests/conftest.py` sets the variable for the whole test session to the staged dashboard, so `looper serve` child processes inherit it. The two cases in `test_catalog_manager_usage_browser.py`, the `looper serve` case in `test_llm_models_dashboard.py` and the installed screenshot smoke in `test_llm_registry_runtime_smoke.py` assert that the served page equals the staged `index.html` (and, where applicable, its title and the variable in the child environment). `test_dashboard_static_dir.py` covers the override and clears it for the existing precedence test.
- **CI:** the Python tests job in `.github/workflows/python-tests.yml` now sets up Node 24 and runs `scripts/stage-dashboard.sh` before pytest; `test_ci_environment.py` checks that order.
- **Scope:** 8 files changed. The pull request reports 25 test lines and 3 production lines (fixtures excluded).
- **Model-visible changes:** None. Looper's prompts, tool descriptions and tool results are unchanged.

## Upgrade and rollback

Re-run `install.sh` once v2.13.189 is published. There is no schema change, so rolling back to v2.13.188 needs nothing else.

### 行为变化与入口

- **静态目录覆盖（#816）：**`looper/agents/http_server.py` 中的 `default_static_dir()` 在环境变量 `PYTEST_LOOPER_STATIC_DIR` 已设置且非空白时返回其指定目录；否则行为不变：有 checkout 构建则用之，否则用打包的 dashboard。Looper 自身不会设置该变量，安装环境中它保持未设置，因此运行中的 Looper 与 v2.13.188 提供相同的文件。这是唯一的生产代码改动（3 行）。
- **测试：**`tests/conftest.py` 在整个测试会话中把该变量设为已编译的 dashboard，使 `looper serve` 子进程继承它。`test_catalog_manager_usage_browser.py` 的两个用例、`test_llm_models_dashboard.py` 的 `looper serve` 用例和 `test_llm_registry_runtime_smoke.py` 的 installed 截图 smoke 都断言所服务的页面与已编译的 `index.html` 一致（并在适用处断言标题与子进程环境中的变量）。`test_dashboard_static_dir.py` 覆盖该覆盖项，并在原有优先级测试中清除它。
- **CI：**`.github/workflows/python-tests.yml` 的 Python 测试作业现在在 pytest 之前设置 Node 24 并运行 `scripts/stage-dashboard.sh`；`test_ci_environment.py` 检查该顺序。
- **范围：**改动 8 个文件。按该 PR 描述，测试 25 行、生产代码 3 行（不含夹具）。
- **面向模型的变化：**无。Looper 的提示词、工具描述和工具结果不变。
