# Looper v2.13.84

## Release Decision

**Who should upgrade:** Anyone who calls `GET /api/registry` or `POST /api/runtimes/{id}/probe` from a script or an eval, or who uses the dashboard's Settings, Agent Profile selectors or runtime Re-detect. Everyone else gets no change.

**What this release solves:** [#530](https://github.com/foolzzz/looper/pull/530) moves the complete runtime registry snapshot and runtime probing onto the versioned API, with full shared result schemas, and removes the two legacy routes.

**Breaking changes:** Yes. `GET /api/registry` and `POST /api/runtimes/{id}/probe` are removed; a script that calls them must use `POST /api/v1/registry/view` or `POST /api/v1/runtimes/probe` with `{"runtime_id": ...}`. Both new responses are wrapped in the v1 envelope (`result`). The dashboard shipped in this release already uses the new operations. The other `/api/providers`, `/api/models` and `/api/agent-profiles` routes are not touched.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#530](https://github.com/foolzzz/looper/pull/530); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.84
```

## Behavior changes

- **Two operations on v1 ([#530](https://github.com/foolzzz/looper/pull/530)):** the new `looper/agents/v1_domains/registry.py` registers `registry.view` (risk `read`, `operator_only`) as `POST /api/v1/registry/view` and `runtimes.probe` (risk `write`, not `operator_only`, no confirmation) as `POST /api/v1/runtimes/probe`. Requests are closed objects: `registry.view` takes none, `runtimes.probe` takes a string `runtime_id`.
- **Registry view:** it returns `profile_registry.registry_view` with the server's configured Claude binary, the same snapshot as the old route (`runtime_types`, `runtimes`, `providers`, `models`, `profiles`, `vendor_types`, `prices`, `limits`). Provider API keys stay masked; provider environment values are returned unchanged, which is why the operation is operator-only: an API client credential is refused with `forbidden` before the snapshot is built or the body is validated.
- **Probe:** it calls `profile_registry.probe_runtime` and returns `{runtime}`. Registry refusals become v1 errors (not found, conflict, invalid) through the shared `answered` wrapper, instead of the old route's JSON error bodies.
- **Schemas:** the result of `registry.view` and its parts (`Registry`, `Runtime`, `RuntimeType`, `Provider`, `Model`, `AgentProfile`, `VendorType`, `RegistryLimits`, and their component schemas) are closed schemas published in the OpenAPI document, so the generated CLI gets `registry view` and `runtimes probe`.
- **Removed routes:** `GET /api/registry` and `POST /api/runtimes/<id>/probe` and the `_RE_RUNTIME_PROBE` pattern are removed from `looper/agents/http_server.py`.
- **Dashboard and tools:** `fetchRegistry` and `probeRuntime` in `web/src/lib/api.ts` call the v1 operations; a successful probe dispatches the registry-changed event. The prompt regression evals (`evals/prompt_regression/dialogs.py`, `runner.py`) and `examples/pi/isolated-smoke.py` read the registry and probe through the new operations.
- **Tests:** `tests/test_api_v1_registry.py`, `tests/test_api_v1_registry_db.py` and `web/src/lib/api-registry.test.ts` were added; about twenty existing registry, provider, model, profile, config-transfer, DSH, prompt-eval and dashboard tests were moved to the new operations.
- **Model-visible changes:** None found. Manager, Planner, Worker and Reviewer prompts, role recommended prompts and Tool declarations are unchanged; the new operations declare no Tool. The operations appear in the v1 operation catalog that API clients read.
- **Not confirmed in code:** the prose docs (`README.md`, `docs/architecture/agent-system.md`) still name the removed routes, because the PR did not edit them. `evals/prompt_regression/runner.py` still reads `provider_presets` from the registry result in `register_provider_agent`; this draft did not check whether the snapshot carries that key. Whether an API client credential with a write scope may call `runtimes.probe` was not traced. This draft did not run any test.

## Upgrade and rollback

Re-run `install.sh` once v2.13.84 is published. No data migration. Update any script that used the removed routes. Rolling back to v2.13.83 restores them together with the old dashboard.

### 行为变化与入口

- **两个 v1 操作（[#530](https://github.com/foolzzz/looper/pull/530)）：**新增 `looper/agents/v1_domains/registry.py`，注册 `registry.view`（风险 `read`，`operator_only`），路径 `POST /api/v1/registry/view`；以及 `runtimes.probe`（风险 `write`，非 `operator_only`，无需确认），路径 `POST /api/v1/runtimes/probe`。请求为封闭对象：`registry.view` 无参数，`runtimes.probe` 接收字符串 `runtime_id`。
- **注册表视图：**使用服务器配置的 Claude 可执行文件调用 `profile_registry.registry_view`，快照与旧路由相同（`runtime_types`、`runtimes`、`providers`、`models`、`profiles`、`vendor_types`、`prices`、`limits`）。Provider API key 仍被掩码；provider 环境变量值原样返回，因此该操作仅限操作者：API 客户端凭据会在构造快照和校验请求体之前被以 `forbidden` 拒绝。
- **探测：**调用 `profile_registry.probe_runtime`，返回 `{runtime}`。注册表的拒绝经共享的 `answered` 包装转为 v1 错误（不存在、冲突、无效），不再是旧路由的 JSON 错误正文。
- **Schema：**`registry.view` 的结果及其各部分（`Registry`、`Runtime`、`RuntimeType`、`Provider`、`Model`、`AgentProfile`、`VendorType`、`RegistryLimits` 及其组件 schema）为封闭 schema，发布在 OpenAPI 文档中，因此生成的 CLI 有 `registry view` 与 `runtimes probe`。
- **移除的路由：**`GET /api/registry`、`POST /api/runtimes/<id>/probe` 以及 `_RE_RUNTIME_PROBE` 已从 `looper/agents/http_server.py` 移除。
- **仪表盘与工具：**`web/src/lib/api.ts` 的 `fetchRegistry`、`probeRuntime` 调用 v1 操作；探测成功后触发注册表变更事件。prompt 回归评测（`evals/prompt_regression/dialogs.py`、`runner.py`）和 `examples/pi/isolated-smoke.py` 通过新操作读取注册表并探测。
- **测试：**新增 `tests/test_api_v1_registry.py`、`tests/test_api_v1_registry_db.py`、`web/src/lib/api-registry.test.ts`；约二十个现有的注册表、provider、模型、profile、配置传输、DSH、prompt 评测和仪表盘测试已改用新操作。
- **面向模型的变化：**未发现。Manager、Planner、Worker、Reviewer 的 prompt、角色推荐 prompt 以及 Tool 声明均未改动；新操作未声明 Tool。这些操作会出现在 API 客户端读取的 v1 操作目录中。
- **代码中未确认：**散文文档（`README.md`、`docs/architecture/agent-system.md`）仍写着已移除的路由，PR 没有修改它们。`evals/prompt_regression/runner.py` 的 `register_provider_agent` 仍从注册表结果读取 `provider_presets`；本草稿未检查快照是否含该键。持写权限范围的 API 客户端凭据能否调用 `runtimes.probe` 未追踪。本草稿未运行任何测试。

v2.13.84 发布后重跑 `install.sh`。无需迁移数据。使用已移除路由的脚本需要更新。回退到 v2.13.83 会连同旧仪表盘一起恢复这些路由。
