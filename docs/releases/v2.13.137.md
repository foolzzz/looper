# Looper v2.13.137

## Release Decision

**Who should upgrade:** Nobody needs to. This release adds an internal module that nothing calls yet, so behavior is unchanged. Everyone can stay on v2.13.136.

**What this release solves:** [#674](https://github.com/foolzzz/looper/pull/674) ports Norma's turn and tool-call cycle into typed asyncio Python (`looper/agents/runtimes/api/loop.py`) behind `AgentLoop`, with protocol-neutral session items. It is the neutral loop (step 2a) of the planned `api` runtime. The first wire codec follows separately.

**Breaking changes:** No. No public API, schema, configuration or prompt changes, and no existing code imports the new module.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#674](https://github.com/foolzzz/looper/pull/674); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.137
```

## Behavior changes

- **Neutral agent loop (#674):** new `looper/agents/runtimes/api/loop.py` (414 lines). A search of `looper/` finds no importer of it, so no running path uses it in this release. It defines:
  - Frozen types: `ModelTarget`, `ToolSpec`, `ToolCall`, `ToolOutcome`, `RequestRecord`, `RequestUsage`, `LoopResult`, the `ErrorKind` and `Outcome` enums, and the `AgentLoop`, `ProtocolCodec`, `CodecStream`, `TurnTools` and `Transcript` protocols.
  - Session items `MessageItem`, `ToolCallItem`, `ToolResultItem` and `ReasoningItem` (a summary plus a minimal `ReplayState`). `item_to_json` and `item_from_json` use `version: 1` with an explicit `kind`; a malformed item raises `TranscriptFormatError`.
  - `NormaAgentLoop(codec).run(...)`: checks that target, transcript and codec protocols match and that `max_requests` (default 30) is positive. It stops with `max_requests`, `capped` (the `over_cap` callback, checked after the first request) or `cancelled` outcomes. It runs tools serially, only after a complete response. Each completed request is appended with its tool results as one batch, and the user text is stored with the first append. A stream that ends without completion is resent at most once per turn; the already displayed text is checked and not shown again, and the resend counts against the request limit. Failed or cancelled requests are recorded with unknown usage. A service shutdown still propagates when a turn was also stopped.
  - `loop_for(protocol)` raises `RuntimeUnsupported` for every protocol, because no codec exists yet.
  - The API key is added to log redaction and masked in error messages (truncated to 300 characters).
- **Notice and packaging:** adds `looper/agents/runtimes/api/THIRD_PARTY_NOTICES.txt` (Norma source revision, derived module, MIT notice; Looper stays Apache-2.0) and lists it as package data in `pyproject.toml`, so the wheel carries it.
- **Documentation:** the API runtime RFC and the long-horizon plan now describe step 2a as implemented on the branch, with the loop contract; Responses codec, sessions and Manager wiring are still not implemented.
- **Runtime behavior:** none for existing flows.
- **Model-visible changes:** none in this release, since the loop is not wired. The new module contains one string a model would see once wired: the tool result for a call skipped after a stop (`{"status": "error", "error": {"code": "stopped", "message": "the user stopped this turn: this call did not run"}}`). No existing prompt, tool declaration or tool result is changed.
- **Line counts:** the description reports tests 395 and production 444 added lines (fixtures excluded).

### 行为变化与入口

- **中性 agent 循环（#674）：**新增 `looper/agents/runtimes/api/loop.py`（414 行）。在 `looper/` 中搜索不到它的导入方，因此本版本没有运行路径使用它。内容：
  - 冻结类型：`ModelTarget`、`ToolSpec`、`ToolCall`、`ToolOutcome`、`RequestRecord`、`RequestUsage`、`LoopResult`，`ErrorKind` 与 `Outcome` 枚举，以及 `AgentLoop`、`ProtocolCodec`、`CodecStream`、`TurnTools`、`Transcript` 协议。
  - 会话条目 `MessageItem`、`ToolCallItem`、`ToolResultItem`、`ReasoningItem`（摘要加最小 `ReplayState`）。`item_to_json` 与 `item_from_json` 使用 `version: 1` 和显式 `kind`，格式错误抛 `TranscriptFormatError`。
  - `NormaAgentLoop(codec).run(...)`：校验 target、transcript、codec 协议一致且 `max_requests`（默认 30）为正；以 `max_requests`、`capped`（`over_cap` 回调，首个请求之后检查）或 `cancelled` 结局停止。工具只在完整响应后串行执行；每个完成的请求连同工具结果作为一批原子追加，用户输入随首次追加保存。断流（未完成即结束）每轮最多重发一次，已显示文本会被校验且不重复展示，重发计入请求上限；失败或取消的请求以未知用量记录。若轮次同时被停止，服务关闭仍会向上传播。
  - `loop_for(protocol)` 对所有协议抛 `RuntimeUnsupported`，因为尚无编解码器。
  - API key 加入日志脱敏，并在错误信息中被遮盖（截断到 300 字符）。
- **notice 与打包：**新增 `looper/agents/runtimes/api/THIRD_PARTY_NOTICES.txt`（Norma 来源版本、派生模块、MIT 声明；Looper 仍为 Apache-2.0），并在 `pyproject.toml` 中列为 package data，wheel 会携带。
- **文档：**API 运行时 RFC 与长程计划改为描述 2a 步已在分支实现并补充循环契约；Responses 编解码器、会话与管家接线仍未实现。
- **运行时行为：**现有流程无变化。
- **面向模型的变化：**本版本无，因为循环尚未接线。新模块含一条接线后模型会看到的字符串：停止后被跳过的调用的工具结果（`{"status": "error", "error": {"code": "stopped", "message": "the user stopped this turn: this call did not run"}}`）。现有提示词、tool 声明和 tool 结果均未改动。
- **行数：**描述报告新增测试 395 行、生产代码 444 行（不含 fixtures）。
