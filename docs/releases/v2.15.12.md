# Looper v2.15.12

This is the patch release v2.15.12, a hotfix line in which each merged change ships at once. It documents one change: [#1394](https://github.com/foolzzz/looper/pull/1394) (delivered-text notifications for agent schedules).

## Release Decision

**Who should upgrade:** Anyone who sends an agent schedule's result to an audience chat (Telegram or Lark) and wants the chat to get only the delivered text, without status, cost or dashboard links; and anyone whose operator reports for schedules are too long.

**What this release solves:** [#1394](https://github.com/foolzzz/looper/pull/1394) adds a typed schedule setting `notify_format` (`report`, the default, or `deliverable`). With `deliverable`, a successful run sends only the `## Delivered` section of its result, and a failed run sends a short reason. Alerts and recoveries for such a schedule stay on the dashboard.

**Breaking changes:** No. The CLI and existing API fields are unchanged, and every existing schedule keeps `report`. Two things change for existing installations: the PostgreSQL schema gains one additive column (see Upgrading), and the default operator report keeps summary line breaks and is limited to 12 lines and 1,200 characters (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.12
```

**Contributors:** Maintainer @foolzzz authored [#1394](https://github.com/foolzzz/looper/pull/1394); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.11 upgrades directly. This release has an additive PostgreSQL migration, applied once at startup (`schedule_notify_format`): `schedules.notify_format TEXT NOT NULL DEFAULT 'report'` with a check for `report` or `deliverable`, and a check that a command schedule keeps `report`. Existing rows read as `report`. Restart the service after upgrading, as for every release.

## Behavior changes

Read in the diff of the PR (23 files, mainly `looper/agents/schedule_notify.py`, `looper/agents/schedules.py`, `looper/db/connection.py`, `looper/db/schema.sql`, `looper/agents/config_transfer.py`, `looper/agents/ops/schedules.py`, `web/src/components/project-schedules.tsx` and four new test files).

### #1394: delivered-text notifications for agent schedules

- **New setting.** `notify_format` is `report` (default) or `deliverable`. It is saved with the schedule, read and written by the HTTP API (`schedule_reads.py`, `schedule_writes.py`), included in configuration export and import (missing in an import means `report`), and listed in the Manager's schedule tools. The dashboard's schedule form gets a "Message format" select beside the notification settings. A command schedule accepts only `report`: `deliverable` is refused with a 400, by the API check and by the database constraint, and the form disables the select for commands.
- **Successful `deliverable` message.** The body of the result's `## Delivered` section, ending at the next level-two heading. Without that section, the whole result after removing leading blank and level-two heading lines. Line breaks are kept; the text is cut at a line boundary with `…` within 4,000 characters. No status, cost, link or other section is added.
- **Failed `deliverable` message.** A short Chinese sentence naming the schedule, then `原因：` and the body of `## Why it ended` (or the run's error, or a placeholder if there is none), with Markdown heading markers removed, cut at a line boundary within 800 characters. Failed means `failed`, `timed_out`, `gate_failed` or `interrupted`.
- **Alerts.** For a `deliverable` schedule, failure, stale, deadline and overlap alerts and their recoveries are recorded as `dashboard` and never sent to the chat, including under `notify=alerts`. `notify` still decides which runs send a message. Lark and Telegram adapters are unchanged: they send the supplied text.
- **Default report change.** For every `report` schedule, the summary in an agent run's message now keeps its line breaks, drops blank lines and is limited to 12 lines and 1,200 characters (`…` when cut), where before it was flattened into one snippet. The status line, cost and dashboard link remain. Command schedule messages are unchanged.
- **Docs.** `docs/architecture/agent-system.md` describes both formats; it also lists `interrupted` among the failures that `notify=failures` sends, which the code already did (`FAILURES` in `looper/db/schedules.py`).

### Model-visible changes

- **Manager tool schema.** The schedule create and update tools gain an optional `notify_format` field (enum `report`, `deliverable`) with a description ("report (default): operator report; deliverable: delivered text only, agent schedules only"). Schedule list results carry `notify_format`.
- **Manager text.** The schedule configuration summary shown to the Manager and the user gets one more line, "通知格式" (运行报告 or 仅交付正文), and the field is named "通知格式" in change summaries.
- **Agent results.** A `deliverable` schedule's chat text is taken from the result's `## Delivered` and `## Why it ended` sections, so those headings in a run's final result now matter for such a schedule. No other prompt text changes.

### 行为变化与入口

以下在该 PR 的差异中可见（23 个文件，主要是 `looper/agents/schedule_notify.py`、`looper/agents/schedules.py`、`looper/db/connection.py`、`looper/db/schema.sql`、`looper/agents/config_transfer.py`、`looper/agents/ops/schedules.py`、`web/src/components/project-schedules.tsx` 和四个新增测试文件）。

**#1394：Agent 定时任务的“仅交付正文”通知**

- **新设置。**`notify_format` 取 `report`（默认）或 `deliverable`。它随定时任务保存，由 HTTP API 读写，包含在配置导出和导入中（导入缺省为 `report`），并出现在 Manager 的定时任务工具中。仪表盘的定时任务表单在通知设置旁新增“Message format”下拉框。命令类定时任务只接受 `report`：`deliverable` 会被 API 校验和数据库约束拒绝（400），表单也会对命令类禁用该下拉框。
- **成功的 `deliverable` 消息。**结果中 `## Delivered` 部分的正文，到下一个二级标题为止；没有该部分时，取去掉开头空行和二级标题行之后的整个结果。保留换行，在行边界截断并加 `…`，不超过 4,000 字符。不附加状态、花费、链接或其他部分。
- **失败的 `deliverable` 消息。**一句点名该定时任务的简短中文，接 `原因：` 和 `## Why it ended` 的正文（没有则用运行的错误，再没有则用占位文字），去掉 Markdown 标题符号，在行边界截断，不超过 800 字符。失败指 `failed`、`timed_out`、`gate_failed` 或 `interrupted`。
- **告警。**对 `deliverable` 定时任务，失败、停滞、截止和重叠告警及其恢复消息一律记为 `dashboard`，不发到聊天，`notify=alerts` 下也一样。`notify` 仍决定哪些运行发送消息。Lark 和 Telegram 适配器不变，照发所给文本。
- **默认报告变化。**对所有 `report` 定时任务，Agent 运行消息中的摘要现在保留换行、去掉空行，并限制为 12 行、1,200 字符（截断加 `…`），此前是压成一行的片段。状态行、花费和仪表盘链接保留。命令类定时任务的消息不变。
- **文档。**`docs/architecture/agent-system.md` 描述了两种格式；还把 `interrupted` 列入 `notify=failures` 会发送的失败状态，代码本来就是如此（`looper/db/schedules.py` 的 `FAILURES`）。

**面向模型的变化：**

- **Manager 工具 schema。**定时任务创建和更新工具新增可选字段 `notify_format`（枚举 `report`、`deliverable`），带描述；定时任务列表结果包含 `notify_format`。
- **Manager 文本。**展示给 Manager 和用户的定时任务配置摘要多一行“通知格式”（运行报告或仅交付正文），变更摘要中该字段也称“通知格式”。
- **Agent 结果。**`deliverable` 定时任务的聊天文本取自结果的 `## Delivered` 和 `## Why it ended` 部分，因此这两个标题在这类定时任务的最终结果中变得重要。其他提示词文本不变。
