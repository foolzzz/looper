# Looper v2.13.77

## Release Decision

**Who should upgrade:** Anyone who reads the versioned API document or calls `POST /api/v1/ops/costs` (the `looper_costs` Tool or `looper costs`) from a script or generated client and wants a typed answer. Everyone else gets no change.

**What this release solves:** [#514](https://github.com/foolzzz/looper/pull/514) declares the result of the existing costs query for its task, project and global scopes, so the API document describes what the Tool returns.

**Breaking changes:** No. The request, the cost arithmetic and the transport are unchanged; only the declared result is added.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#514](https://github.com/foolzzz/looper/pull/514); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.77
```

## Behavior changes

- **Costs result contract ([#514](https://github.com/foolzzz/looper/pull/514)):** the new `looper/agents/v1_domains/costs.py` registers a result for `costs` as one of three closed objects. Task scope: `cost_usd`, `runs`, `running`, `unpriced_runs`, optional `equivalent_runs` and `provider_price_runs`, `by_role` (`planner`, `worker`, `reviewer`, each `cost_usd` and `runs`), `by_model` and `manager_by_model` (per model: `model`, `cost_usd`, and counts of runs, running, unpriced and interrupted runs and of input, output, cache-read and cache-creation tokens), plus `task_id`, `name`, `status` and `note`. Project scope: `project`, `since`, `until`, `total` (`provider_priced_usd`, `equivalent_usd`, `runs`, `running`, `unpriced_runs`), `tasks` (up to the listed limit, with `more_tasks` for the rest) and `note`. Global scope: the same range and `total`, `projects` (`project` may be null for unassigned tasks, with `tasks` counts) and `note_projects`.
- **API document:** `/ops/costs` now carries that result in its 200 response; there is still no 202 response. The operation keeps the `looper_costs` Tool request, risk `read`, no hand-off and no confirmation, so the generated `looper costs` command sends the same requests as before.
- **Tests:** `tests/test_api_v1_cost_result_contract.py` and `tests/test_api_v1_cost_result_contract_db.py` (the latter against a database) cover the document, the generated CLI, the three scopes, time filters, null filters and error answers; `tests/test_api_v1_document.py` lists `costs` among the typed Tool operations.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt and no Manager Tool changed; `OPERATIONS` for the domain is empty, so no operation was added.
- **Not confirmed in code:** this draft did not check every Tool answer against the closed objects, so an answer with a field outside the declared set is the case to watch.

## Upgrade and rollback

Re-run `install.sh` once v2.13.77 is published. No data migration and no caller change. Rolling back to v2.13.76 only removes the declared result.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 行为变化与入口

- **成本结果契约（[#514](https://github.com/foolzzz/looper/pull/514)）：**新增 `looper/agents/v1_domains/costs.py`，为 `costs` 注册结果，为三个封闭对象之一。任务范围：`cost_usd`、`runs`、`running`、`unpriced_runs`，可选的 `equivalent_runs` 与 `provider_price_runs`，`by_role`（`planner`、`worker`、`reviewer`，各含 `cost_usd` 与 `runs`），`by_model` 与 `manager_by_model`（每个模型含 `model`、`cost_usd`，以及运行、进行中、未定价、被中断运行数和输入、输出、缓存读取、缓存创建 token 数），以及 `task_id`、`name`、`status`、`note`。项目范围：`project`、`since`、`until`、`total`（`provider_priced_usd`、`equivalent_usd`、`runs`、`running`、`unpriced_runs`）、`tasks`（限定数量，其余计入 `more_tasks`）和 `note`。全局范围：相同的时间范围与 `total`，`projects`（未归属项目的任务 `project` 可为 null，含 `tasks` 计数）和 `note_projects`。
- **API 文档：**`/ops/costs` 的 200 响应现带上述结果，仍无 202 响应。该操作保持 `looper_costs` 工具的请求、风险 `read`、无手动交接、无需确认，因此生成的 `looper costs` 命令发送的请求与之前相同。
- **测试：**`tests/test_api_v1_cost_result_contract.py` 与 `tests/test_api_v1_cost_result_contract_db.py`（后者使用数据库）覆盖文档、生成的 CLI、三个范围、时间过滤、空过滤和错误答复；`tests/test_api_v1_document.py` 把 `costs` 列入已类型化的工具操作。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 和 Manager Tool 均未改动；该域的 `OPERATIONS` 为空，未新增操作。
- **代码中未确认：**本草稿未逐一核对工具的所有答复是否符合封闭对象，答复若含声明之外的字段是需要留意的情形。
