# Looper v2.13.160

## Release Decision

**Who should upgrade:** Operators who want to manage per-Manager plugins and skills from the dashboard instead of the API or CLI. Everyone else can stay on v2.13.159.

**What this release solves:** [#735](https://github.com/foolzzz/looper/pull/735) adds a "Plugins and skills" section to each Manager in Settings. It shows the inherited global installs and the Manager's own additions, and lets an operator add, enable, disable and remove additions with the `manager_installs` operator API that v2.13.159 introduced.

**Breaking changes:** No. The change is dashboard-only; no API, database, configuration, prompt or Tool declaration changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#735](https://github.com/foolzzz/looper/pull/735); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.160
```

## Behavior changes

- **Manager installs in Settings ([#735](https://github.com/foolzzz/looper/pull/735)):** a new component `web/src/components/manager-installs.tsx` is mounted under each Manager in the Managers settings page (`web/src/components/managers-settings.tsx`). A "Plugins and skills" disclosure lists each row with its kind, whether it is "Inherited globally" or "Added here", and whether it is enabled. Rows added here have an enable switch and a Remove button; inherited rows are read-only, and the page says that disabling or removing an addition does not mask an inherited global install, and that an item inherited and added here loads once.
- **Adding:** a picker offers catalog plugins and skills that are not project-owned and not already added to that Manager. An inherited item can be added explicitly.
- **Read-back:** after every put or delete the component re-reads the list from the server and only then shows "Saved and read back from server; applies next turn." It does not use an optimistic state. Failures show an alert with a "Retry installs" button, and the picker keeps its selection after a failed add.
- **Visibility:** the section is hidden for the built-in default Manager when no other Manager exists, unless that Manager has its own additions or an error to show.
- **Runtime hint:** the section tells the operator whether the Manager's agent profile runtime loads catalog plugins (Claude plugin loading is supported; Pi skips them and records them as skipped) and links to Agent Profiles and to the Runs page for loaded contents.
- **Target changes:** the component is keyed by Manager, so late responses for one Manager cannot change another's rows. Focus returns to the picker, the changed control or the Manager's edit button after a change.
- **API wrapper:** `web/src/lib/manager-installs-api.ts` calls `/api/v1/manager_installs/list`, `put` and `delete`, and rejects a response for another Manager or one that needs confirmation.
- **Model-visible changes:** none. No prompt, tool description or tool schema changed, and the server, database and CLI are untouched; what a Manager loads is governed by the v2.13.159 behavior.
- **Tests:** new `tests/test_manager_installs_browser.py` and `web/src/components/manager-installs.test.tsx`, with small additions to the Managers settings and chat binding tests. The description reports 396 added test lines and 444 production lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.160 is published. There is no migration and no configuration change. Rolling back to v2.13.159 removes only the Settings section; per-Manager installs stay in place and remain reachable through the API and CLI.

## Optional Capability Activation & Use

### Manager plugin and skill installs

**Activation:** The section appears in Settings under each Manager (for the built-in default Manager only once another Manager exists or it has additions). Open "Plugins and skills", choose a global catalog plugin or skill and select "Add install".

**Validation:** Add an item for one Manager, reload the page, and check that the item is listed as "Added here" and enabled, while the shared global installs show as "Inherited globally". A second Manager does not list the item.

**Disable / rollback:** Turn the item's switch off, or select Remove. Both take effect at the Manager's next safe turn.

**Authority boundary:** The section uses the operator-only `manager_installs` API, so it has the same reach as in v2.13.159: it adds global catalog capabilities to one Manager and cannot disable an inherited global install. Project-owned items are not offered.

**Docs:** [Agent system](https://github.com/foolzzz/looper/blob/v2.13.160/docs/architecture/agent-system.md).

```bash
loopercli manager-installs list --manager-id manager
```

### 行为变化与入口

- **设置页中的管家安装（#735）：**新组件 `web/src/components/manager-installs.tsx` 挂在管家设置页每个管家下（`web/src/components/managers-settings.tsx`）。“Plugins and skills”展开区列出每一行的类型、是“Inherited globally”还是“Added here”，以及是否启用。此处添加的行有启用开关和 Remove 按钮；继承行只读，页面说明停用或移除附加项不会屏蔽继承的全局安装，且既继承又在此添加的项只加载一次。
- **添加：**选择器提供非项目私有、且尚未添加到该管家的目录插件和技能。继承项也可显式添加。
- **回读：**每次 put 或 delete 之后，组件从服务器重新读取列表，之后才显示“Saved and read back from server; applies next turn.”，不使用乐观状态。失败时显示提示和“Retry installs”按钮，添加失败后选择器保留所选项。
- **可见性：**内置默认管家在不存在其他管家时隐藏该区块，除非它有自己的附加项或需要显示错误。
- **运行时提示：**区块说明该管家的 agent profile 运行时是否加载目录插件（支持 Claude 插件加载；Pi 会跳过并记录为跳过），并链接到 Agent Profiles 和 Runs 页面的已加载内容。
- **目标切换：**组件按管家作为 key，一个管家的迟到响应不会改动另一个管家的行。变更后焦点回到选择器、被改动的控件或该管家的编辑按钮。
- **API 封装：**`web/src/lib/manager-installs-api.ts` 调用 `/api/v1/manager_installs/list`、`put` 和 `delete`，并拒绝属于其他管家的响应或需要确认的响应。
- **面向模型的变化：**无。prompt、工具描述和工具 schema 均未改变，服务端、数据库和 CLI 不变；管家加载什么由 v2.13.159 的行为决定。
- **测试：**新增 `tests/test_manager_installs_browser.py` 和 `web/src/components/manager-installs.test.tsx`，并少量补充管家设置和聊天绑定测试。描述报告新增测试 396 行、生产代码 444 行（不含 fixture）。
