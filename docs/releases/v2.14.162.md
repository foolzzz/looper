# Looper v2.14.162

This is the patch release v2.14.162, a hotfix line in which each merged change ships at once. It documents one change: [#1293](https://github.com/foolzzz/looper/pull/1293) (request recording follow-ups).

## Release Decision

**Who should upgrade:** Installations that use request recording (the local model-request proxy and its retention housekeeping). Others need not upgrade for behavior.

**What this release solves:** [#1293](https://github.com/foolzzz/looper/pull/1293) fixes the listed valid items of the review follow-ups #1142, #1144 and #1154: queued turns' record ids, recovery of the proxy's database writer, per-variable `NO_PROXY` handling, and `stored_bytes` for old rows.

**Breaking changes:** No. There is no API change, migration or schema change. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.162
```

**Contributors:** Maintainer @foolzzz authored [#1293](https://github.com/foolzzz/looper/pull/1293); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.161 upgrades directly. There is no schema change.

## Behavior changes

The pull request changes `looper/agents/housekeeping.py`, `looper/agents/llmrec/__init__.py`, `__main__.py`, `control.py`, `writer.py`, `looper/db/llm_requests.py` and five test files. It states that the behavior changes follow the triage notes' fixes (maintainer decision, intended). Read in the code:

- **Pending record ids.** `ProxyControl.bind` no longer overwrites a route file that already has a different `record_id`; it remembers the new id in memory and, when the current record is released, writes it into the route file (unless the route ends). Entries for a record that ends first are dropped.
- **Writer recovery.** `DbSink.run` takes `recover`, and the proxy process starts it with `recover=True`. An error outside the known connection errors is logged as "model request write failed" with the error class only, then the same batch is retried after a back-off of 1 to 30 seconds. Without `recover` the writer still stops, as before.
- **`NO_PROXY` per variable.** `no_proxy()` extends each of `NO_PROXY` and `no_proxy` that is present with `127.0.0.1`, `localhost` and `::1` (a lone `*` is kept), instead of deriving both from the lowercase value. If neither is present, both are set to the loopback list.
- **Backfill of `stored_bytes`.** Housekeeping's request-recording prune first runs `fill_missing_stored_bytes` until nothing is left: it sets `stored_bytes` on `llm_requests` and `llm_request_parts` rows where it is 0, in batches of at most 2000, skipping locked rows to keep the writer/GC lock order.
- **Model-visible changes:** None. No prompt, tool description, schema or answer text changes.

### 行为变化与入口

该 PR 改动 `looper/agents/housekeeping.py`、`looper/agents/llmrec/` 下的 `__init__.py`、`__main__.py`、`control.py`、`writer.py`、`looper/db/llm_requests.py` 及五个测试文件，并声明行为变化遵循分诊记录中的修复（维护者决定，符合预期）。代码中可见：

- **待定记录 id。**`ProxyControl.bind` 不再覆盖已带不同 `record_id` 的路由文件，而是在内存中记住新 id，当前记录释放时再写入路由文件（路由结束则不写）。先结束的记录对应的条目被丢弃。
- **写入器恢复。**`DbSink.run` 新增 `recover`，代理进程以 `recover=True` 启动。已知连接错误之外的错误只记录错误类别（“model request write failed”），随后以 1 到 30 秒的退避重试同一批数据。未设 `recover` 时写入器仍如以前一样停止。
- **按变量处理 `NO_PROXY`。**`no_proxy()` 对存在的 `NO_PROXY` 和 `no_proxy` 各自追加 `127.0.0.1`、`localhost`、`::1`（单独的 `*` 保持不变），不再由小写值推出两者。两者都不存在时，都设为回环列表。
- **回填 `stored_bytes`。**保留期清理的请求记录裁剪先反复运行 `fill_missing_stored_bytes` 直到没有剩余：对 `llm_requests` 和 `llm_request_parts` 中 `stored_bytes` 为 0 的行按每批最多 2000 行补值，并跳过被锁定的行以保持写入器/GC 的锁顺序。
- **面向模型的变化：**无。提示词、工具描述、schema 和回答文本均未改动。
