# Looper v2.14.21

This is the patch release v2.14.21. It ships the one change merged since v2.14.20: [#899](https://github.com/foolzzz/looper/pull/899), which makes the SDK runner the default for Pi and DSH profiles.

## Release Decision

**Who should upgrade:** Anyone who runs Pi or DSH agents. After upgrading, those profiles run on their SDK runners unless the ops file opts out. It ships the one change merged since v2.14.20.

**What this release solves:** [#899](https://github.com/foolzzz/looper/pull/899): Pi and DSH profiles needed an explicit `[runtimes]` opt-in to use the SDK runner, and a runner that could not start gave a generic message. The runner is now the default, the per-runner session cap is raised, and a runner that cannot start fails with a message naming the cause and the `cli` opt-out.

**Breaking changes:** Yes, in default behavior only. An installation without a `[runtimes]` setting now runs Pi and DSH on the SDK runner, which needs Node 22.19+ and a Pi 1.3.x or DSH 0.2.1-rc.2 SDK; if these are missing the launch fails until the SDK is installed or `[runtimes] pi = "cli"` / `[runtimes] dsh = "cli"` is set and Looper restarted. No database schema, stored data or API changes. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#899](https://github.com/foolzzz/looper/pull/899); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.21
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.20 upgrades directly. This release changes no database schema or stored data. To keep the previous behavior, set `[runtimes] pi = "cli"` and/or `[runtimes] dsh = "cli"` in the ops file and restart; the setting is read once at startup.

## Behavior changes

- **Runner is the default** (`looper/ops_config.py`): `pi_runtime` and `dsh_runtime` default to `"runner"`. The ops-file template now shows `# pi = "runner"` / `# dsh = "runner"` and writes `pi = "cli"` / `dsh = "cli"` only when opted out. Claude Code, Codex, OMP, Grok and api runtimes are unchanged.
- **Larger session cap and pool** (`looper/agents/runtimes/pi_runner.py`, `dsh_runner.py`, `runners/pi/src`, `runners/dsh/src`): each runner allows 32 sessions (was 10 for Pi and 20 for DSH). The supervisor starts another runner of that kind when all members are full, up to four members (128 sessions per kind); only a full pool fails with `CAPACITY`. Extra runners stop after 300 idle seconds and one stays.
- **Startup failures name the cause and the opt-out** (`pi_runner.py`, `dsh_runner.py`, `runner/supervisor.py`): missing node or executable, node older than 22.19, a `node --version` check that did not finish in 2 seconds, an SDK version outside the gate (Pi `@earendil-works/pi-coding-agent` 1.3.x; DSH `@deepseek-ai/dsh` 0.2.1-rc.2, read from the executable's `package.json` when it is a real file) and a launch executable that changed all fail with a message ending in the `[runtimes] <kind> = "cli"` opt-out. The same applies to a failed first lease after startup and to starting another pool member; causes are redacted, one line and at most 512 characters.
- **Longer first start** (`looper/agents/tiers/manager.py`, `runner/pi_command.py`): a runner-hosted start gets 90 seconds (30 for other runtimes) and the Pi initialize control timeout is 60 seconds for the first call, 10 afterwards. A timeout is reported with the cause and, for Pi and DSH, the opt-out.
- **Start cancellation cleanup** (`runner/supervisor.py`): a runner start that is cancelled or abandoned is awaited so its process is reaped before cleanup finishes.
- **Eval and validation flags** (`evals/prompt_regression/__main__.py`, `examples/dsh/validate.py`): with no flag they use the runner; `--pi-cli` and `--dsh-cli` select the CLI path, `--pi-runner` / `--dsh-runner` still select the runner.
- **Docs and tests**: README, README.zh-CN, `evals/README.md` and the SDK runner RFC are updated; `tests/test_pi_dsh_default_runner.py` and `tests/test_manager_runtime_start.py` are new and `tests/test_runner_supervisor.py` and several runner tests are updated.
- **Model-visible changes:** A Pi or DSH role now runs in the SDK runner, so its platform tools are `looper_*` in process and the run record stores a runner Descriptor. A Manager reply to a failed Pi or DSH start now includes the cause instead of only "check the installation". Claude Code profiles are unchanged.

## 中文摘要

本版本是 patch release v2.14.21。自 v2.14.20 以来只合并了一项改动：[#899](https://github.com/foolzzz/looper/pull/899)，让 Pi 和 DSH profile 默认使用 SDK runner。

### 升级决策

**谁需要升级：**运行 Pi 或 DSH agent 的人。升级后这些 profile 默认在 SDK runner 上运行，除非在 ops 文件中退出。包含 v2.14.20 之后合并的这一项改动。

**解决了什么：**[#899](https://github.com/foolzzz/looper/pull/899)：Pi 和 DSH profile 原先需要在 `[runtimes]` 中显式开启才使用 SDK runner，runner 无法启动时提示也很笼统。现在 runner 为默认，单个 runner 的会话上限提高，runner 无法启动时的报错会指明原因和 `cli` 退出方式。

**是否有破坏性变更：**是，仅限默认行为。未设置 `[runtimes]` 的安装现在默认让 Pi 和 DSH 走 SDK runner，需要 Node 22.19+ 以及 Pi 1.3.x 或 DSH 0.2.1-rc.2 SDK；缺失时启动失败，直到安装 SDK，或设置 `[runtimes] pi = "cli"` / `[runtimes] dsh = "cli"` 并重启 Looper。不改数据库 schema、已存数据或 API。受支持的升级路径不变（见升级）。

**如何验证：**运行 `looper --version` 核对版本为 2.14.21。

**贡献者：**维护者 @foolzzz 提交 [#899](https://github.com/foolzzz/looper/pull/899)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.21
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.20 上的安装可直接升级。本版本不改数据库 schema 或已存数据。若要保留原行为，在 ops 文件中设置 `[runtimes] pi = "cli"` 和/或 `[runtimes] dsh = "cli"` 并重启；该设置只在启动时读取一次。

### 行为变化与入口

- **runner 成为默认**（`looper/ops_config.py`）：`pi_runtime` 和 `dsh_runtime` 默认值为 `"runner"`。ops 文件模板显示 `# pi = "runner"` / `# dsh = "runner"`，仅在退出时写入 `pi = "cli"` / `dsh = "cli"`。Claude Code、Codex、OMP、Grok 和 api 运行时不变。
- **更大的会话上限与 runner 池**（`pi_runner.py`、`dsh_runner.py`、`runners/pi/src`、`runners/dsh/src`）：每个 runner 允许 32 个会话（原 Pi 为 10、DSH 为 20）。当某类 runner 全部满载时 supervisor 会再启动一个，最多四个成员（每类 128 个会话）；只有池满才返回 `CAPACITY`。多余的 runner 空闲 300 秒后停止，保留一个。
- **启动失败会指明原因和退出方式**（`pi_runner.py`、`dsh_runner.py`、`runner/supervisor.py`）：缺少 node 或可执行文件、node 低于 22.19、`node --version` 2 秒内未完成、SDK 版本超出门限（Pi `@earendil-works/pi-coding-agent` 1.3.x；DSH `@deepseek-ai/dsh` 0.2.1-rc.2，可执行文件为真实文件时从其 `package.json` 读取）、以及启动可执行文件发生变化，都会以带有 `[runtimes] <kind> = "cli"` 退出方式的消息失败。启动后首次租约失败和启动其他池成员失败同样适用；原因经过脱敏、压成一行且不超过 512 字符。
- **首次启动更久**（`looper/agents/tiers/manager.py`、`runner/pi_command.py`）：runner 托管的启动给 90 秒（其他运行时为 30 秒），Pi 的 initialize 控制超时首次为 60 秒，之后为 10 秒。超时会报告原因，Pi 和 DSH 还会附带退出方式。
- **启动取消清理**（`runner/supervisor.py`）：被取消或放弃的 runner 启动会被等待，进程回收后才完成清理。
- **评测与验证参数**（`evals/prompt_regression/__main__.py`、`examples/dsh/validate.py`）：不带参数时使用 runner；`--pi-cli` 和 `--dsh-cli` 选择 CLI 路径，`--pi-runner` / `--dsh-runner` 仍选择 runner。
- **文档与测试**：更新 README、README.zh-CN、`evals/README.md` 和 SDK runner RFC；新增 `tests/test_pi_dsh_default_runner.py` 和 `tests/test_manager_runtime_start.py`，更新 `tests/test_runner_supervisor.py` 等 runner 测试。
- **面向模型的变化：**Pi 或 DSH 角色现在在 SDK runner 中运行，其平台工具为进程内的 `looper_*`，运行记录保存 runner Descriptor。Pi 或 DSH 启动失败时 Manager 的回复现在包含原因，而不只是“请检查安装”。Claude Code profile 不变。
