# Looper v2.13.11

## Release Decision

**Who should upgrade:** Operators who talk to the Manager Agent and start tasks through it, especially on runtimes whose models tend to `sleep` or poll after a start (seen on OMP with DeepSeek). Everyone else sees no change.

**What this release solves:** [#279](https://github.com/foolzzz/looper/pull/279) adds one rule to the Manager's tool contract: after starting or changing a task, the Manager does not wait or poll inside the turn (no `sleep`, no repeated status calls) and ends its reply, because Looper brings the task's questions (gates) and its end to the user. It also adds the `start_no_wait` prompt-regression dialog that checks this.

**Breaking changes:** No. The CLI, configuration, database schema and API routes are unchanged from [v2.13.10](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.10.md).

**How to verify:** Check the installed version, then ask the Manager to start a ready task and see that its reply ends after the start.

**Contributors:** Maintainer @foolzzz authored [#279](https://github.com/foolzzz/looper/pull/279); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.11
```

## Behavior changes

- **Manager no longer waits after a start.** The Manager's tool contract (`looper/agents/tiers/manager.py`) gains a rule: after starting or changing a task, do not wait or poll inside the turn (no sleep, no repeated status calls); end the reply, since Looper brings the task's gates and its end to the user. The rule is runtime-neutral. It is guidance to the model, not code that blocks a call: no code path changed.
- **New eval dialog.** The prompt-regression eval gains `start_no_wait` (a ready task and the message "开始"). It passes when the Manager starts the task once, runs no shell command after it, makes at most one further call, and, in real mode, the reply says the task started and that its questions will come to the user. It is listed in `evals/README.md`. This affects the eval harness only.
- **Model-visible changes:** Yes, one. The Manager's tool contract, which ends its system prompt, gains the three-line rule above. No tool schema changed, and no other tier's prompt changed.

## Entry points

None added. No CLI command, HTTP route or configuration key was added.

## Upgrade and rollback

Re-run `install.sh` once v2.13.11 is published. There is no schema or configuration change. Rolling back to v2.13.10 is safe; it only removes the rule from the Manager's contract.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## Validation

**Retained implementation evidence:** [#279](https://github.com/foolzzz/looper/pull/279) reports real Manager dialogs, 2 repetitions each: this branch with sonnet 10/10 and with OMP + DeepSeek 10/10, and main with sonnet 8/8 on the four shared dialogs, so no regression; in `start_no_wait` neither Manager slept or polled after the start. It reports the Manager reply and dialog tests at 71 passed, the full local suite before the merge, and Codex and Grok reviews with no P0. It notes the limit: main has no `start_no_wait`, so the eval shows the rule holds, not how often the Manager waited without it. This draft did not re-run any of it.

**CI:** CI runs after the release is drafted; its result is not recorded here.

**Not tested for this draft:** Local test runs, a real Manager run, and model evals. The release documentation gate checks the body only.

## 中文摘要

### 升级决策

**谁需要升级：**通过 Manager 启动任务的运营者，尤其是模型在启动后爱 `sleep` 或轮询的运行时（OMP + DeepSeek 上出现过）。其他人没有变化。

**解决了什么：**[#279](https://github.com/foolzzz/looper/pull/279) 在 Manager 的工具契约里加一条规则：启动或修改任务后，不在本回合内等待或轮询（不 `sleep`、不反复查状态），直接结束回复，由 Looper 把任务的问题（闸门）和结束通知用户。同时新增 `start_no_wait` 提示词回归对话来检查。

**是否有破坏性变更：**无。CLI、配置、数据库 schema 和 API 路由与 [v2.13.10](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.10.md) 相同。

**如何验证：**运行 `looper --version` 核对版本为 2.13.11；让 Manager 启动一个就绪任务，回复在启动后结束。

**贡献者：**维护者 @foolzzz 提交 [#279](https://github.com/foolzzz/looper/pull/279)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.11
```

### 行为变化与入口

- Manager 启动后不再等待：Manager 工具契约新增规则，启动或修改任务后不在回合内等待或轮询，直接结束回复。规则与运行时无关，只是对模型的指引，没有代码路径阻止调用，代码逻辑未变。
- 新增 eval 对话：`start_no_wait`（就绪任务加「开始」）。通过条件：Manager 只启动一次、之后不执行 shell 命令、最多再调用一次；真实模式下回复还需说明任务已启动、其问题会交给用户。已列入 `evals/README.md`，只影响 eval 工具。
- 面向模型的变化：有一处。Manager 的工具契约（位于其系统提示词末尾）新增上述三行规则；没有工具 schema 变化，其他层级的提示词未变。未新增 CLI 命令、HTTP 路由或配置项。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.10 安全，只是去掉 Manager 契约中的这条规则。

### 可选能力启用与使用

本版本未新增可选能力启用入口。
