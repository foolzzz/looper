## Release Decision

Upgrade from v2.15.33. The product code is main at `a73719f67`. Pulls merged after that commit ship next, including the morning-brief send-started marker in #1707.

**Who should upgrade:** Anyone upgrading a server from v2.15.33, including one that already has stable context, the delivery guard, a turn budget, a Manager persona, the delivery layer with a timezone, morning brief, completion turns, intents, leads, or metrics on. The upgrade applies six migrations and three online steps with every one of those switches off. With intents on, an exact revoke command changes. With morning brief on, a failed schedule's deferred pushes fold into one line. With completion turns on, completion does one extra reservation settlement that returns immediately when this process holds none.

**What this release solves:** A project can propose lesson and project memories at task end, still off until that project switch is on. The operator can install a read-only Claude Code retrieval entry; upgrade does not install it. Message collection, parity and alerts exist and stay off. Task retrospectives can run when lesson settings are already on, and their loop does not call the model while those settings are off. Intent rules can classify and execute only when both the rules switch and intents are on. A failed morning-brief schedule is one needs line with its deferred-push count. A DSH run has a per-call bash deadline. `looper serve` starts even when the DSH runner files are absent.

**Breaking changes:** Yes. With intents enabled, an exact revoke command in a group or someone else's direct chat is refused in code and no longer reaches the model, even with rules off. A custom intent type that already owns the key mr_review and is not the builtin seed fails startup. An incompatible retrospective index fails startup. A DSH run gains a 120 second default and a 600 second maximum per-call bash deadline. With morning brief on, a failed schedule's deferred pushes fold into one needs line. If lesson settings were already stored on and the retrospective role has an explicit valid profile, retrospectives can call the model. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.34
```

**Contributors:** Maintainer @foolzzz authored the pull requests named in this body; no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once. An installation on v2.14.0 to v2.15.33 upgrades directly. Restart the service after upgrading. `web/` changed, so the release workflow rebuilds the dashboard bundle from `web/` into the wheel. This pull request does not commit that bundle.

On an upgrade from a database that has finished v2.15.33, `pending()` reports six new migrations and the online-step list gains three new markers. Migrations 1920, 1930 and 1940 are not in this release. No other migration file in `looper/db/migrations` changed in this range. A database that has not finished an older online step still runs that older step. Older steps with recorded completion markers are skipped and are not counted here. Because these six migrations are pending, startup takes the usual `pg_dump` into the runtime root `backups/` directory before applying them, unless the operator passes `--skip-backup`. Without that bypass, a missing or incompatible `pg_dump`, or a failed backup, aborts startup before the schema is changed. This note does not estimate how long that dump takes.

The six migrations, in `pending_order`:

- `memory_closeout` (1860). No online step. Adds nullable `projects.memory_closeout`, checked as `off` or `on`. Null means off. No settings insert. Pending when the marker is absent and the column is absent. #1665.
- `intent_mr_review_type` (1890). No online step. Inserts builtin `intent_types` key `mr_review` (enabled, version 1) and its `intent_type_versions` row. If a row already exists and `builtin` is false, startup raises `intent type mr_review already exists and is not the builtin seed; rename or remove that type before upgrading. Its versions were not changed.` A finished builtin row is not pending. The rules switch stays off. #1670.
- `intent_rule_execution` (1900). No online step. Creates the discovery, work, MR target, claim, project-day, execution, hit-execution, task-start, notice, verification and preview tables, and widens `intent_rule_hits`, inside the startup transaction. Indexes and constraints are in that transaction. Rules off does not skip it. Pending when a required table, column, constraint or valid index is missing. #1701.
- `message_collection` (1950). Creates `source_collection_settings` (`alerts_enabled` not null, default false; `collect_cron` default `*/10 * * * *`), `source_parity_sessions`, `source_parity_members`, `source_parity_coverage` and `source_stream_alerts`, plus their indexes. Widens `proactive_deliveries` source check to add `message_stream_alert`, not valid inside the transaction. Deletes the online marker `message_collection_online` so the online step runs after commit. `event_sources.ingest_mode` stays default `off`. An incompatible index definition raises `incompatible ... definition`. #1685.
- `memory_retro_role` (1980). Widens `llm_records_run_kind_check` and `agent_setting_layers_role_check` to allow `memory_retro`, not valid inside the transaction. Deletes the online marker `memory_retro_role_online`. #1688.
- `memory_retro_queue` (1990). Adds lease columns on `memory_retro_runs` and creates `memory_retro_cursors`, `memory_retro_task_refs`, `memory_lesson_reinforcements`, `memory_retro_spend` and `memory_retro_activation`. Deletes the online marker `memory_retro_queue_online`. #1688.

The three new online steps:

- `message_collection_online` validates `proactive_deliveries`'s widened source check. That scans `proactive_deliveries`.
- `memory_retro_role_online` validates the two widened checks. That scans `llm_records` and `agent_setting_layers`.
- `memory_retro_queue_online` builds concurrent indexes `idx_intents_retro_task` on `intents (task_id) WHERE task_id IS NOT NULL` and `idx_tasks_retro_terminal` on terminal tasks. This scans `intents` and `tasks`. An incompatible index raises `incompatible retrospective index: ...` and can fail startup.

What still runs with every one of these off: `manager.stable_context`, `manager.delivery_guard.enabled`, `manager.turn_budget_usd`, `manager.persona`, `delivery.enabled` (with or without `user.timezone`), `morning_brief.enabled`, `manager.completion_turns` (`off`), `intents.enabled`, `leads.enabled`, and `manager.metrics.enabled`.

- The six migrations and three online steps above. No feature-setting row is inserted. The existing startup `UPDATE intent_recognitions` still marks `running` rows `failed`, even with intents off; that recovery already shipped in v2.15.33.
- Existing related recovery also continues from v2.15.33: startup settles interrupted `manager_events`, changes `idle_checks` from `sending` to `uncertain` and `running` to `failed`, and records unknown delivery outcomes for recovered idle sends. The completion loop waits up to 5 seconds (plus its 0.5 second batching delay); intent push and the memory write/draft/push services retain 10 second idle waits, idle checks 300 seconds, morning brief 30 seconds and metrics alerts 3600 seconds. These services keep their own gates. The existing memory drafter still opens its dedicated LISTEN connection at startup even while off.
- Startup seeds role `memory_retro` (display "Memory retro", one turn, 90 second timeout) through the existing role seed. An edited prompt is kept. A missing row is inserted; an existing unedited prompt follows the new recommendation. Seed failure can fail startup the same way other role seeds can. This is a role row, not a feature switch. #1688.
- `MemoryRetroService` starts unconditionally. Its loop is named `memory-retro`; when idle it waits up to 10 seconds, can be woken earlier, and processes the next range immediately after work. Startup loads the lesson switch once. While that switch is off, each tick and each finished task return before another database read and before a model call. #1688.
- `IntentRuleService` starts unconditionally. Its loop is named `intent-rules` and waits 2 seconds between passes. Outside drain, every pass runs the start scan and the revoke scan before it reads whether rules are enabled, then returns while rules are off. The start scan updates `intent_rule_task_starts` joined to executions whose revoke state is `none` and whose pending or claimed lease is due, at most 20 rows, with a 30 second lease. An empty table still runs that update. Historical committed start and revoke work can still be recovered with rules off and with intents off. New rule work, notices, the MR verifier and quotas require rules and intents. There is no separate loop switch. #1701.
- `SourceService` start calls `refresh_alerts` once: it reads whether any `source_collection_settings` row has `alerts_enabled`. The result is cached. Idle ticks do not poll alerts while that cache is false. A failed read can fail `SourceService.start`, including while collection and alerts are off. The source loop itself already existed and still ticks about every 15 seconds. It does not collect while `ingest_mode` is `off`. #1705.
- For existing sources, the daily retention pass also checks `source_collection_settings`, even with `ingest_mode = off` and alerts off. If a settings row exists and the source lock is acquired, a 5 second bounded cleanup uses `scheduler.run_retention_days` (default 30) to prune old `source_runs` and old matched `source_parity_sessions` without unresolved alerts; members and coverage cascade. It makes no platform call. #1685.
- When a runtime root is set, HTTP startup tries to lock and write the server-address files. `OSError` or `ValueError` logs a warning and HTTP keeps serving. It does not fail startup. MCP is not installed. #1666.
- Morning brief off: no brief send and no brief consume. The #1704 fold does not run. #1707's send-started marker is not in this tree, so a restart can still lose an unsent claimed brief the same way as v2.15.33. That marker ships next.
- The revoke router is not entered while `intents.enabled` is off, so an exact revoke command still reaches the model. The 2 second recovery scan still runs.
- Each task closeout first reads the stored `memory_write` setting even while off. A read failure falls back to the existing vault closeout. No `[MEMORY]` turn. #1665.
- No message-stream alert section, proactive alert row, or brief alert section. `delivery.enabled`, morning brief and metrics do not bypass the alert gate. #1685.
- The Python deadline helper loads defaults lazily on the first hosted DSH run and caches them; resident runs do not call that helper. The default Claude Code profile does not read it. #1695.
- No change to stable context, the delivery guard, the turn budget, persona text, or metrics recording from these pulls. #1699 moves quota probes and keeps the same probe conditions, suppression and retry. It does not turn `engine.failure_typing` on. Metrics on does not add a notice.

New startup failure modes, including while every named switch is off:

- Migration 1890, when a custom non-builtin type already owns `mr_review`.
- An incompatible retrospective index, or a failed online validation of the widened checks.
- `refresh_alerts` failing during `SourceService.start`, or the new startup read of the `memory_lessons` setting failing.
- Incompatible existing message-collection column types, nullability, defaults, sequences, constraints or indexes; incompatible retrospective-queue columns or constraints (reported as `incompatible memory lessons column` or `incompatible memory lessons constraint`).
- The `memory_retro` role seed failing, the same way another role seed can fail.
- The usual backup abort when `pg_dump` is missing, incompatible, or the backup fails, unless `--skip-backup` is set.

What no longer fails startup: an installation without the DSH runner files. Before #1719, an import-time read made `looper serve` fail to start. The files are read when a DSH run starts. A run without them fails only that run (`RuntimeUnsupported`). The release smoke keeps tracked symlinks, requires `looper/agents/runtimes/runner/dsh_runner/src/main.ts` and `tool-deadlines.json` in the wheel, and prints the serve log when serve does not come up.

Publishing the server address still does not fail startup. A warning is logged and HTTP continues.

## Behavior changes

### Runs even when the named switches are off

- **Migrations, the role seed, the retrospective loop with an idle wait of up to 10 seconds, the 2 second rule recovery scan, the one alert read, and the server-address publish.** See Upgrading. None of these require stable context, the delivery guard, a turn budget, persona, the delivery layer, a timezone, morning brief, completion turns, intents, leads, or metrics to be on. The retrospective loop does not call the model. The recovery scan can update empty or historical start and revoke rows. The alert read does not send. The address publish failure does not abort startup.
- **#1719.** `looper serve` starts without the DSH runner files. A DSH run without those files fails only that run. The wheel smoke keeps tracked symlinks, requires the runner files, and prints the serve log when serve does not come up. No named switch is involved.
- **#1717.** Test only. The root logger starts each test at WARNING and is restored to WARNING. No server behavior.
- **#1711, #1694.** CI only. Main `workflow_dispatch` canaries run the installed-wheel startup smoke without extras, against disposable PostgreSQL, and the existing summary check requires that result. Ordinary pull requests skip that job. The six shards use committed measured durations and xdist work stealing. Not a server loop.
- **#1712, #1702, #1698, #1691.** Tests and the Pi isolated-smoke expected role set. Not called by `looper serve`. No product behavior.
- **#1699.** The quota probe helpers moved to turn admission. The probe conditions, output suppression and retry are the same. No new notice and no migration. Metrics on does not change this.

### When a named switch, or the feature's own switch, is already on

The existing settings are not rewritten. `manager.delivery_guard.enabled`, `manager.stable_context`, `delivery.enabled`, `manager.metrics.enabled`, `morning_brief.enabled`, `intents.enabled`, and `leads.enabled` default off and require the stored string `true`. `morning_brief.time` defaults to `09:15` on weekdays. Persona is the JSON setting `manager.persona` (`name`, `address`, `tone`, `notes` default empty). An empty persona is unset. `manager.profile.enabled` stays a separate switch and defaults off. `manager.turn_budget_usd` null means off. A positive finite USD value enables the cap. `manager.completion_turns` defaults to `off`. `dm_only` covers direct chats and dashboard chat. Groups keep code notices. `user.timezone` is an optional IANA zone. Absent, the server zone is used. None of these enable each other. Lesson settings, the project closeout column, collection `ingest_mode`, collection alerts, and `intents.rules.enabled` are separate and stay off unless already stored on. An upgrade does not turn them on.

### Task retrospectives

**Activation:** The loop and the `memory_retro` role seed start on serve whether or not lesson settings are on. The stored JSON setting is `memory_lessons`; its `enabled` defaults to false. `projects.memory_lessons` is null by default; null or `off` disables the project. Model calls require both gates, an enabled `memory_retro` role and a valid explicitly configured, non-builtin Agent Profile. Without that profile an attempt returns unavailable at zero model cost. First activation records cursors instead of replaying old terminal journals. An upgrade does not write either. v2.15.33 did not start a retro when the project mode was stored `on`. This release can process new terminal ranges once both gates are enabled; it calls the model only with the role and explicit profile above. Injection is not activated here.

**Validation:** Startup loads the lesson switch once. While it is off, an idle tick (after up to 10 seconds, or an earlier wake) and a finished task return before another database read and before a model call. While both gates are on, a completed or failed task can enqueue one retrospective range for the private role. The role is one turn, no tools, at most 90 seconds. Disabling the ten named product switches does not stop the idle loop. Disabling lessons does not stop the loop. It stops the model call. No channel footer, injection, weekly card, or vault write is added.

**验证：** 列为空或 `off` 时，任务结束仍走知识库收尾，不开始 `[MEMORY]`。生效时，活动记提议或跳过；确认写入后该任务增加 `Memory: M-… written to …`。关闭时读取和导出省略该键。

**停用 / 回退：** 把列设回空或 `off`。之后的任务回到知识库收尾。已经生成的未确认候选留着。降级需要迁移前的备份。本版本没有向下迁移。

**权限边界：** 只给操作者。非操作者的配置导入不能改这个开关。`[MEMORY]` 把整段日志当作数据，只列出并执行只读工具，不写已配置的可写目录。提议在操作者确认当前内容之前不会写入。

#### Memory retrieval

**启用：** 升级不安装。操作者运行 `looper claude-code install mcp`，先预览再确认写入。入口把三个读操作转到操作者检索接口。必须有绑定的运行时记录。发布这份记录失败时 HTTP 继续服务。

**验证：** 显式安装之前，操作者的其他 Claude Code 会话不会因为本拉取请求得到检索工具。安装之后，知识库搜索和读取仍只在知识库已配置且 `manager_read` 打开时回答。线索搜索只在 `leads.enabled` 打开时回答。删掉一份被锁记录本身不允许检索。第二个监听者不会认领这份记录。

**停用 / 回退：** 从操作者的 Claude Code 配置里去掉该 MCP 入口并重启那个会话。升级或降级不会替操作者删除它。下一次 serve 启动会重新发布服务器地址。关掉线索只隐藏线索检索，知识库检索仍看它自己的开关。

**权限边界：** 派生凭证只接受三个检索读操作，每次检索都重读当前令牌。该凭证的其他 v1 操作被拒绝。群和其他发送者得不到这些工具。答案与默认管家已有的只读答案相同。本拉取请求不新增管家工具。

**文档：** https://github.com/foolzzz/looper/blob/v2.15.34/docs/architecture/agent-system.md#the-operators-other-claude-code-sessions

#### Message collection

**启用：** 默认关。`event_sources.ingest_mode` 默认 `off`，已有的 `off` 或 `bridge` 保持原值。采集需要操作者确认切换为 `collect`。`alerts_enabled` 默认 false。升级建空表，不插入功能设置。送达层、晨报和度量不会打开采集或告警。

**验证：** `ingest_mode` 仍是 `off` 或 `bridge` 时，来源循环不采集。`alerts_enabled` 为假时，空闲节拍不读告警，也不增加消息流告警段、主动投递行或晨报段。在线标记 `message_collection_online` 在放宽后的来源约束校验完成后记下。打开告警会刷新缓存，下一次来源节拍恢复。

**停用 / 回退：** 用单项回退把 `ingest_mode` 设回 `off` 或 `bridge`，并把 `alerts_enabled` 设为 false。这不删表。降级需要迁移前的备份。索引对不上时启动失败，而不是改写索引。

**权限边界：** 只给操作者。模式切换要操作者确认。对账窗口是 24 小时。告警开关关着时不发送。P4 导出和 P7 管家工具不在本版本。消费游标和抽取规则不变。

#### Task retrospectives

**启用：** 复盘循环和 `memory_retro` 角色种子在 serve 启动时开始，与教训设置是否打开无关。系统设置是 JSON `memory_lessons`，其中 `enabled` 默认 false；`projects.memory_lessons` 默认空，空或 `off` 是关闭。模型调用要系统设置启用，并且项目列为 `on`。升级不写这两项。v2.15.33 在项目模式存成 `on` 时不开始复盘。本版本在两项启用后可以处理新的结束区间；模型调用还要求角色启用并明确配置有效的非内置 Agent Profile，没有该画像时只记不可用、模型费用为零。首次激活记录游标，不重放旧的已结束日志。注入不在这里启用。

**验证：** 启动时读一次教训开关。开关关着时，空闲节拍（最多等 10 秒，也可提前唤醒）和任务结束都在再次读库和调用模型之前返回。两个闸门都开时，完成或失败的任务可以给私有角色排一个复盘区间。该角色一回合、无工具、最多 90 秒。`memory_lessons` JSON 内的单次 `retro_budget_usd` 默认 0.10、每日 `daily_budget_usd` 默认 0.50；额度不打开总开关。在线标记 `memory_retro_role_online` 和 `memory_retro_queue_online` 在约束校验完成且两个索引存在后记下。

**停用 / 回退：** 关掉系统教训设置，或把项目列设回空或 `off`。之后的节拍不调用模型。已经写入的行留着。角色行留着。降级需要迁移前的备份。对不上的复盘索引以 `incompatible retrospective index` 让启动失败。

**权限边界：** 操作者设置。该角色没有内置画像，调用时会拒绝内置画像。开关关着时不会走到那条路径。关掉上面十个产品开关不会停下空转循环。关掉教训也不会停下循环，但会停掉模型调用。不增加渠道页脚、注入、周卡片或知识库写入。

**文档：** https://github.com/foolzzz/looper/blob/v2.15.34/docs/architecture/agent-system.md#project-lesson-retrospectives

#### Intent rule execution

**启用：** 执行要等 `intents.rules.enabled` 和 `intents.enabled` 都是字符串 `true`。自动建任务还要求 `delivery.enabled` 为字符串 `true`；仅分类不要求送达层打开。升级不写这两个键。升级会插入内置 `mr_review`，在两个都打开之前对模型隐藏，并会建执行表。送达层不会打开规则。非排空时开始和撤销的恢复循环在两个都关着时也跑，两次扫描之间等 2 秒。意图开着、规则关着时，群里或别人私聊里的精确撤销拒绝已经生效。关掉规则不会停掉这次拒绝，也不会停掉扫描。

**验证：** 规则关着时，群抽取不增加 MR 段落，也不会做新的规则工作、通知、核验或额度决定。恢复更新仍会跑。两个都开时可以分类；自动执行还要送达层和已配置规则的准入检查通过。自定义的非内置 `mr_review` 会在规则运行前让启动失败。真实分类器对照和真实 Worker 冒烟没有跑。

**停用 / 回退：** 把 `intents.rules.enabled` 存成 `false`，或删掉这一行。新的规则工作停止。恢复扫描继续；意图仍开着时，撤销拒绝也继续。把 `intents.enabled` 存成 false，精确撤销才回到模型。降级需要迁移前的备份。关掉开关不会删掉内置类型行。

**权限边界：** 操作者的规则和操作者自己的私聊。群或其他发送者的精确撤销由代码拒绝，不到达模型。API 客户端令牌没有规则编辑命令。模板契约仍禁止合并和修改 reviewer。配套界面不在本版本。不要把这项当成已经完成生产评分的安装。

**文档：** https://github.com/foolzzz/looper/blob/v2.15.34/docs/architecture/agent-system.md#intents
