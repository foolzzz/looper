# Looper v2.14.136

This is the patch release v2.14.136, a hotfix line in which each merged change ships at once. It documents one change: [#1237](https://github.com/foolzzz/looper/pull/1237) (task confirmation shows a workflow task's own roles, review panel and verification).

## Release Decision

**Who should upgrade:** Operators who start tasks with a workflow, because the confirmation showed the project default Worker and Reviewer instead of the workflow's own roles. Everyone else gets no visible change.

**What this release solves:** [#1237](https://github.com/foolzzz/looper/pull/1237) makes the task confirmation of a workflow task (Manager and dashboard) list the workflow's roles with their profiles and fallbacks, the review panel rule and the read-only verification.

**Breaking changes:** No. There is no migration and no API removal. The confirmation text of a workflow task changes (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.136
```

**Contributors:** Maintainer @foolzzz authored [#1237](https://github.com/foolzzz/looper/pull/1237); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.135 upgrades directly. There is no schema change.

## Behavior changes

- **Workflow task confirmation shows the workflow's own setup** ([#1237](https://github.com/foolzzz/looper/pull/1237)). For a task that runs with a workflow, the confirmation (`configuration_block` in `looper/agents/projects.py`) no longer lists the project default Worker/Reviewer lines. It lists the Planner, each workflow role and the built-in work or review seat where the workflow uses one, each with its profile (runtime, model, effort) and its fallback chain (at most three fallback hops, no profile twice; an unknown profile shows as unavailable). The role chosen as verification is marked "验证：只读，最多 N 轮". A review panel line gives the required seats, the suggested seats and the acceptance rule, scoped to every work step or to the Planner's choice according to the review policy; without a panel the usual review-policy line stays. The task's own profile choices rank ahead of the project's. The workflow's budget cap is read as the task cap. To keep the card short, a workflow task's workspace and settings lines are joined with "；" on fewer lines; workspace warnings and roles are kept.
- **Tasks without a workflow keep today's confirmation.**
- **New read-only operation `workflows/preview`** (`looper/agents/v1_domains/workflows.py`). It takes a workflow key, an optional project id and optional task profiles, creates nothing and returns the same lines as `lines`. It answers not-found for an unknown project and invalid for a bad profile choice or a profile that conflicts with one the workflow sets.
- **Dashboard preview.** The workflow field of the new-task form shows these lines for the selected workflow (project and profile choices included) instead of the one-line summary, and shows the error if the preview fails.
- **Unchanged:** execution of workflows, the review policy semantics and the start question that ends the confirmation.
- **Model-visible changes:** Yes. The confirmation text the Manager shows for a workflow task changes, and the v1 workflows operation list gains `preview` with its description. No prompt template, reply contract or run `AGENTS.md` text changes.

### 升级决策

**谁需要升级：**使用工作流启动任务的运维者，因为确认信息之前显示的是项目默认的 Worker 和 Reviewer，而不是工作流自己的角色。其他人没有可见变化。

**解决了什么：**[#1237](https://github.com/foolzzz/looper/pull/1237) 让工作流任务的确认信息（Manager 和仪表盘）列出工作流的角色及其 profile 与回落、评审面板规则和只读验证。

**是否有破坏性变更：**否。没有迁移，没有移除 API。工作流任务的确认文本有变化（见下文）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.14.136。

**贡献者：**维护者 @foolzzz 提交 [#1237](https://github.com/foolzzz/looper/pull/1237)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.136
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.135 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **工作流任务的确认展示工作流自己的配置**（[#1237](https://github.com/foolzzz/looper/pull/1237)）。对使用工作流的任务，确认信息（`looper/agents/projects.py` 的 `configuration_block`）不再列出项目默认的 Worker/Reviewer 行，而是列出 Planner、每个工作流角色，以及工作流使用内置工作或评审席位时的对应行，每行带 profile（运行时、模型、effort）和回落链（最多三次回落，不重复同一 profile；未知 profile 显示为不可用）。作为验证的角色标注“验证：只读，最多 N 轮”。评审面板行给出必需席位、建议席位和验收规则，范围按评审策略为每个工作步骤或由 Planner 决定；没有面板时保留原来的评审策略行。任务自己选择的 profile 优先于项目的。工作流的预算上限按任务上限读取。为保持卡片简短，工作流任务的工作区与设置行用“；”合并为更少的行；工作区警告和角色都保留。
- **没有工作流的任务保持现有确认信息。**
- **新增只读操作 `workflows/preview`**（`looper/agents/v1_domains/workflows.py`）。输入工作流 key、可选的项目 id 和可选的任务 profile，不创建任何东西，以 `lines` 返回相同的行。项目不存在返回 not-found；profile 选择无效或与工作流已设置的 profile 冲突返回 invalid。
- **仪表盘预览。**新建任务表单的工作流字段对所选工作流（含项目与 profile 选择）显示这些行，取代原来的一行摘要；预览失败时显示错误。
- **不变：**工作流的执行、评审策略语义，以及确认信息末尾的开始提问。
- **面向模型的变化：**有。Manager 展示的工作流任务确认文本变化，v1 workflows 操作列表新增 `preview` 及其描述。没有提示词模板、回复契约或运行 `AGENTS.md` 文本变化。
