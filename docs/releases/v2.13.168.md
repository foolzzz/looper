# Looper v2.13.168

## Release Decision

**Who should upgrade:** No one needs this release for a running-Looper behavior change. [#755](https://github.com/foolzzz/looper/pull/755) changes only the runner supervisor, which nothing else in Looper calls yet. Everyone can stay on v2.13.167.

**What this release solves:** [#755](https://github.com/foolzzz/looper/pull/755) fixes reviewed supervisor defects: a runner's child processes (including ones in their own process groups) are now tracked and reaped so recovery and shutdown cannot hang, only declared file paths among launch arguments are resolved, and a slow initialize is a retryable start failure.

**Breaking changes:** No. No API, database schema, configuration, prompt or Tool declaration changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#755](https://github.com/foolzzz/looper/pull/755); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.168
```

## Behavior changes

- **Child tracking and cleanup ([#755](https://github.com/foolzzz/looper/pull/755)):** each runner generation is tracked with `proc_tree.track` and a ticker, so children that leave the runner's process group are still found. A graceful dispose asks the tracked tree to end first, and the final cleanup ends the tree whether or not the parent has already exited. Without a tracked tree the previous `proc_tree` path is used.
- **Stderr drain bound ([#755](https://github.com/foolzzz/looper/pull/755)):** disposing waits at most `STDERR_DRAIN_TIMEOUT` (1.0 s) for the stderr reader; if it has not finished, a warning is logged, the reader is cancelled and the stderr pipe is closed. Cancelled cleanup tasks are no longer logged as cleanup failures.
- **Launch arguments ([#755](https://github.com/foolzzz/looper/pull/755)):** `RunnerSupervisor` command arguments are now opaque strings, except an argument given as a `pathlib.Path`, which is made absolute against the launch working directory. Previously any string that named an existing file was silently rewritten to an absolute path, which also touched long inline code arguments. The `commands` type is now `Sequence[str | Path]`; a caller that relied on a bare relative script name being resolved must pass a `Path`.
- **Start failures ([#755](https://github.com/foolzzz/looper/pull/755)):** a start failure is terminal only for `ValueError`, `ProtocolError`, the version, params, unsupported and isolation-refused RPC errors, and an `OSError` with `ENOENT`, `EACCES` or `ENOEXEC` before the process exists. Timeouts and other I/O errors during initialize now use the same bounded restart path as a crash instead of being terminal.
- **Model-visible changes:** none. No prompt, tool description or tool schema changed.
- **Tests:** `tests/test_runner_supervisor.py` is extended with cases for launch arguments, terminal and retryable start failures, a reparented child in a separate group, a stalled stderr drain and a reused child identity.
- **Reach:** a search of `looper/` finds `RunnerSupervisor` only in its own module, so running Looper behavior does not change. The description's line counts (30 production, 200 test added) match the file list.

## Upgrade and rollback

Re-run `install.sh` once v2.13.168 is published; there is no migration and no configuration change. Rolling back to v2.13.167 restores the previous supervisor.

### 行为变化与入口

- **子进程跟踪与清理（#755）：**每个 runner generation 用 `proc_tree.track` 和 ticker 跟踪，离开 runner 进程组的子进程也能被找到。优雅 dispose 先让被跟踪的进程树结束，最终清理无论父进程是否已退出都会结束该树。没有被跟踪的树时沿用之前的 `proc_tree` 路径。
- **stderr 排空上限（#755）：**dispose 最多等待 stderr 读取任务 `STDERR_DRAIN_TIMEOUT`（1.0 秒）；超时则记录警告、取消读取任务并关闭 stderr 管道。被取消的清理任务不再记为清理失败。
- **启动参数（#755）：**`RunnerSupervisor` 的命令参数现在是不透明字符串，只有以 `pathlib.Path` 给出的参数会相对于启动工作目录转为绝对路径。此前任何恰好指向已存在文件的字符串都会被悄悄改写为绝对路径，长的内联代码参数也会受影响。`commands` 类型变为 `Sequence[str | Path]`；依赖裸相对脚本名被解析的调用方必须改传 `Path`。
- **启动失败（#755）：**只有 `ValueError`、`ProtocolError`、版本/参数/不支持/隔离拒绝类 RPC 错误，以及进程创建前的 `ENOENT`、`EACCES`、`ENOEXEC` 的 `OSError` 才是终止性失败。initialize 期间的超时和其他 I/O 错误现在走与崩溃相同的有界重启路径，而不再是终止性。
- **面向模型的变化：**无。prompt、工具描述和工具 schema 均未改变。
- **测试：**扩展 `tests/test_runner_supervisor.py`，覆盖启动参数、终止性与可重试的启动失败、处于独立进程组的重新归属子进程、停滞的 stderr 排空以及被复用的子进程标识。
- **影响范围：**在 `looper/` 中搜索，`RunnerSupervisor` 只出现在其自身模块，因此运行中的 Looper 行为不变。描述中的新增行数（生产 30、测试 200）与文件清单一致。
