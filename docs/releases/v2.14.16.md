# Looper v2.14.16

This is the patch release v2.14.16. It ships the one change merged since v2.14.15: [#906](https://github.com/foolzzz/looper/pull/906), which makes the installed Pi runner serve tests find the runner process portably.

## Release Decision

**Who should upgrade:** Nobody needs this release for its behavior. Looper's installed behavior is that of v2.14.15; only the nightly installed Pi runner serve tests change. It ships the one change merged since v2.14.15.

**What this release solves:** [#906](https://github.com/foolzzz/looper/pull/906): the installed Pi runner serve tests (`tests/test_pi_runner_serve_db.py`, nightly only) matched the runner process by its `ps` command line, and on Linux procps `ps` cuts that line at the terminal width, so the match failed with "not enough values to unpack". The lookup no longer depends on the width, and a miss now explains itself.

**Breaking changes:** No. No production code changes. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#906](https://github.com/foolzzz/looper/pull/906); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.16
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.15 upgrades directly. This release changes no database schema, stored data or setting.

## Behavior changes

None for installed Looper. The only change is in a test file (`tests/test_pi_runner_serve_db.py`):

- **Process listing:** the runner lookup runs `ps -A -ww -o pid=,args=`. `-ww` removes the width limit and `args` is the portable column name, so the full command line is matched on Linux procps and on macOS.
- **Diagnostics:** a new helper, `the_runner`, returns the single runner's pid. When it finds none or several, it fails with the count and pids; with agent process records present it adds each record's pid and `ps` line, and without records it adds the serve log lines about an unreadable start time or an unrecorded agent pid.
- **Callers:** four tests (`test_pi_runner_manager_stop_and_restart`, `test_pi_runner_missing_manager_session_records_failed_resume`, `test_pi_runner_task_with_every_role`, `test_pi_runner_worker_cancel_crash_and_budget`) use the helper instead of unpacking `(pid,)`.
- **Model-visible changes:** None. No prompt, tool schema, runner protocol message or production code changes.

### 行为变化与入口

对安装后的 Looper 没有变化。唯一的改动在测试文件（`tests/test_pi_runner_serve_db.py`）中：

- **进程列表：**runner 查找运行 `ps -A -ww -o pid=,args=`。`-ww` 取消宽度限制，`args` 是可移植的列名，因此在 Linux procps 和 macOS 上都匹配完整命令行。
- **诊断：**新增辅助函数 `the_runner`，返回唯一 runner 的 pid。找不到或找到多个时失败并给出数量和 pid；存在 agent 进程记录时附上每条记录的 pid 和 `ps` 行，没有记录时附上 serve 日志中关于无法读取启动时间或无法记录 agent pid 的行。
- **调用方：**四个测试（`test_pi_runner_manager_stop_and_restart`、`test_pi_runner_missing_manager_session_records_failed_resume`、`test_pi_runner_task_with_every_role`、`test_pi_runner_worker_cancel_crash_and_budget`）改用该函数，不再解包 `(pid,)`。
- **面向模型的变化：**无。没有 prompt、工具 schema、runner 协议消息或生产代码的变化。
