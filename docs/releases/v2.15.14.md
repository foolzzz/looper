# Looper v2.15.14

This is the patch release v2.15.14, a hotfix line in which each merged change ships at once. It documents one change: [#1402](https://github.com/foolzzz/looper/pull/1402) (the Manager sees what a Lark message replies to or forwards).

## Release Decision

**Who should upgrade:** Anyone whose Manager answers in Lark chats, in particular where users reply to messages, reply under forwarded topics or send merged forwards to the bot.

**What this release solves:** [#1402](https://github.com/foolzzz/looper/pull/1402) gives the Manager the content a Lark message replies to or forwards. Before, it saw only the sender's own words and answered that it could not see the quoted message or screenshot, and a merged forward in a direct chat got "not supported".

**Breaking changes:** No. There is no schema migration and no API field changes. The Manager's input changes for Lark messages that quote (see Behavior changes and Model-visible changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.14
```

**Contributors:** Maintainer @foolzzz authored [#1402](https://github.com/foolzzz/looper/pull/1402); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.13 upgrades directly. This release has no PostgreSQL migration. Restart the service after upgrading, as for every release. The Lark app needs the `im:message:readonly` scope to read quotes (see below).

## Behavior changes

### [#1402](https://github.com/foolzzz/looper/pull/1402): the Manager sees what a Lark message replies to or forwards

- **Quoted content reaches the Manager.** A reply, a reply in a thread and a merged forward carry a reference. The Manager reads it as part of the message's turn and receives it after the user's words as `<lark_quote>` blocks (one line per message, `[MM-DD HH:MM] name: content`), with the quote's images and files saved beside the message's own attachments. In a thread, the first message and the latest 10 are read too. Caps: 1,500 characters a message, 50 messages and 8,000 characters a block, then "N more not shown". Quoted text cannot open or close a block of its own.
- **Timing.** The read happens while the Manager prepares the turn and takes at most 15 s (about 4-5 s for a plain parent, 5-11 s for a merged forward). Like any turn, it holds the same Manager's later messages, other chats' included. `/stop` cancels the read at once; the next turn is told the user withdrew the message. A `/command` or a gate reply reads nothing.
- **Failure.** A quote that cannot be read (missing scope, time-out, channel not running) appears as `[quoted message om_... could not be read: <why>]` and the turn goes on. A quoted image or file that could not be saved is shown as not received; the user gets no separate notice.
- **Direct chats.** A merged forward in a direct chat is now answered; it used to get "not supported". An @-mention with no words that replies to a message is answered; it used to be dropped.
- **Groups.** A group message that does not @-mention the bot is still ignored, a merged forward included, and nothing is read for it.
- **Bot-token channel.** Answers to a thread message stay in the thread (`thread_id` is kept). A card message is no longer dropped silently: it gets the same "not supported" answer as other unsupported types.
- **Dashboard.** The quote is not stored in the chat's history, so the dashboard's Lark conversation view keeps showing the user's own words. Telegram, web and the CLI are unchanged.
- **Permission.** Reading uses the app's `im:message:readonly`, the scope attachment downloads already need. When it is missing, the quote says "missing permission im:message:readonly".
- **Known limits.** A reply to a thread's first message is a plain reply and does not read the thread's latest replies. Messages the same sender sent just before the @-mention are not read back.

### Model-visible changes

Yes, for Lark messages that quote or forward. The Manager's turn gains, after the user's words, a line marking the content as quoted and not instructions from the user, then `<lark_quote id=... type=... from=... note=...>` blocks and the attachments. Other turns are unchanged. Real-mode eval (`evals/lark_quote.py`, real Claude CLI), as reported by [#1402](https://github.com/foolzzz/looper/pull/1402): on its four quote cases (group reply to a merged forward, merged forward alone in a direct chat, group reply to a text message, group reply whose raw read falls back to `+messages-mget`) the Sonnet Manager passed 2/2 and an Opus xhigh Manager 1/1 each, against 0/2 and 0/1 on `main`. The unaddressed group forward was read 0 times. No run created a task or wrote through the Manager, and each answer that named a forwarded "delete the logs" message said it was not acted on. Cost per turn rose from about $0.03 to $0.04-$0.10 (Sonnet) and from $0.068 to $0.208 (Opus xhigh).

### 升级决策

**谁需要升级：**Manager 在 Lark 聊天里回答的用户，尤其是用户会回复消息、在转发话题下回复，或向机器人发送合并转发的场景。

**是否有破坏性变更：**无。没有 schema 迁移，API 字段不变。带引用的 Lark 消息，Manager 的输入会变化（见行为变化与面向模型的变化）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.15.14。

**贡献者：**维护者 @foolzzz 提交 [#1402](https://github.com/foolzzz/looper/pull/1402)；本版本无社区贡献。

```bash
looper --version   # looper 2.15.14
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.15.13 上的安装可直接升级。本版本没有 PostgreSQL 迁移。升级后照常重启服务。Lark 应用需要 `im:message:readonly` 权限才能读取引用（见下）。

### 行为变化与入口

**[#1402](https://github.com/foolzzz/looper/pull/1402)：Manager 能看到 Lark 消息所回复或转发的内容**

- **引用内容送达 Manager。**回复、话题内回复和合并转发会带一个引用。Manager 在该消息的回合里读取它，并在用户的话之后以 `<lark_quote>` 块收到（每条消息一行，`[MM-DD HH:MM] 姓名: 内容`），引用中的图片和文件保存在消息自身附件旁。在话题中还会读取首条消息和最近 10 条。上限：每条消息 1,500 字符，每块 50 条消息和 8,000 字符，超出显示“N more not shown”。被引用的文字无法自行开启或关闭一个块。
- **耗时。**读取发生在 Manager 准备回合期间，最多 15 秒（普通父消息约 4-5 秒，合并转发约 5-11 秒）。与任何回合一样，它会让同一 Manager 之后的消息等待，其他聊天的也包括在内。`/stop` 会立即取消读取，下一回合会被告知用户撤回了该消息。`/command` 或 gate 回复不读取。
- **失败。**读不到的引用（缺权限、超时、通道未运行）显示为 `[quoted message om_... could not be read: <原因>]`，回合继续。保存失败的引用图片或文件显示为未收到；不会另行通知用户。
- **私聊。**私聊中的合并转发现在会得到回答，此前得到“不支持”。没有文字、只回复某条消息的 @ 提及现在会得到回答，此前被丢弃。
- **群聊。**没有 @ 机器人的群消息（包括合并转发）仍被忽略，且不发起任何读取。
- **Bot token 通道。**对话题消息的回答留在话题里（保留 `thread_id`）。卡片消息不再被静默丢弃：与其他不支持的类型一样得到“不支持”的回答。
- **仪表盘。**引用不写入聊天历史，因此仪表盘的 Lark 会话视图仍只显示用户自己的话。Telegram、web 和 CLI 不变。
- **权限。**读取使用应用的 `im:message:readonly`，即附件下载已需要的权限。缺失时，引用内容会写明“missing permission im:message:readonly”。
- **已知限制。**回复话题首条消息按普通回复处理，不读取话题的最新回复。同一发送者在 @ 之前刚发的消息不会回读。

**面向模型的变化：**

有，限于带引用或转发的 Lark 消息。Manager 的回合在用户的话之后新增一行说明（内容是被引用的，不是用户的指令），然后是 `<lark_quote id=... type=... from=... note=...>` 块和附件。其他回合不变。真实模式评测（`evals/lark_quote.py`，真实 Claude CLI），数据来自 [#1402](https://github.com/foolzzz/looper/pull/1402)：四个引用用例（群里回复合并转发、私聊单独的合并转发、群里回复文本消息、原始读取回退到 `+messages-mget` 的群回复）中，Sonnet Manager 各 2/2、Opus xhigh Manager 各 1/1 通过，`main` 上分别为 0/2 和 0/1。未 @ 的群转发读取次数为 0。没有运行创建任务或通过 Manager 写入，凡提到被转发的“delete the logs”消息的回答都说明未执行。单回合成本从约 $0.03 升至 $0.04-$0.10（Sonnet），Opus xhigh 从 $0.068 升至 $0.208。
