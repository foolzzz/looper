# Looper v2.13.183

## Release Decision

**Who should upgrade:** Operators who install skills or other catalog items on the Manager and ask the Manager (Telegram, Lark or dashboard chat) which items are installed where. It is a hotfix that ships the changes merged since v2.13.182.

**What this release solves:** [#801](https://github.com/foolzzz/looper/pull/801) makes the `looper_catalog` list that a Manager uses report Manager-only installations through a new `manager_install_count` field, as the dashboard catalog already does, so a skill installed only on the Manager no longer looks installed nowhere.

**Breaking changes:** No. No command, schema or file format changed; the tool result gains one field.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#801](https://github.com/foolzzz/looper/pull/801); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.183
```

## Behavior changes

- **The Manager catalog list reports Manager installs ([#801](https://github.com/foolzzz/looper/pull/801)):** `_item_listed` in `looper/agents/ops/config.py` now copies `manager_install_count` from the item view, which `looper/agents/catalog.py` already computed for the dashboard catalog. Manager installs are stored apart from project and global installs, so an item installed only on the Manager has an empty `installs` list and a `manager_install_count` of 1 or more; an item installed nowhere has 0.
- **Result schema:** `COMPACT_ITEM` in `looper/agents/v1_domains/catalog.py` adds `manager_install_count` (integer) as a required field. The same compact item is also used for the `item` in the install, update and uninstall results, so those results carry the field too.
- **Documentation:** the `looper_catalog` row of `docs/architecture/agent-system.md` names the new field.
- **Tests:** `tests/test_manager_config_tools_db.py` adds a case with one skill installed only on the Manager and one installed nowhere, and updates the existing list expectation to include `manager_install_count: 0`.
- **Model-visible changes:** the `looper_catalog` tool results (list, and the item in install, update and uninstall) gain `manager_install_count`, which the Manager can now relay to the user. No prompts, tool descriptions or tool input schemas changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.183 is published. There is no schema change, so rolling back to v2.13.182 needs nothing else.

### 升级决策

**谁需要升级：**在 Manager 上安装技能等目录条目，并通过聊天（Telegram、Lark 或仪表盘）询问 Manager 哪些条目装在哪里的运维者。本版本是随合并即发布的 hotfix，包含 v2.13.182 之后合并的改动。

**解决了什么：**[#801](https://github.com/foolzzz/looper/pull/801) 让 Manager 使用的 `looper_catalog` 列表通过新增的 `manager_install_count` 字段报告仅装在 Manager 上的安装，与仪表盘目录一致，不再把只装在 Manager 上的技能显示成哪里都没装。

**是否有破坏性变更：**无。命令、schema 和文件格式均未改变；工具结果新增一个字段。

**如何验证：**运行 `looper --version` 核对版本为 2.13.183。

### 行为变化与入口

- **Manager 目录列表报告 Manager 安装（#801）：**`looper/agents/ops/config.py` 中的 `_item_listed` 现在从条目视图复制 `manager_install_count`，该值由 `looper/agents/catalog.py` 为仪表盘目录早已计算。Manager 的安装与项目、全局安装分开存放，因此只装在 Manager 上的条目 `installs` 为空而 `manager_install_count` 不小于 1；哪里都没装的条目为 0。
- **结果 schema：**`looper/agents/v1_domains/catalog.py` 中的 `COMPACT_ITEM` 新增必填整数字段 `manager_install_count`。安装、更新、卸载结果中的 `item` 使用同一精简条目，因此这些结果也带该字段。
- **文档：**`docs/architecture/agent-system.md` 中 `looper_catalog` 一行写明了新字段。
- **测试：**`tests/test_manager_config_tools_db.py` 新增一个技能仅装在 Manager、另一个哪里都没装的用例，并把现有列表断言更新为包含 `manager_install_count: 0`。
- **面向模型的变化：**`looper_catalog` 的工具结果（列表，以及安装、更新、卸载中的条目）新增 `manager_install_count`，Manager 可据此告知用户。提示词、工具描述和工具输入 schema 均无变化。
