# Looper v2.15.6

This is the patch release v2.15.6, a hotfix line in which each merged change ships at once. It documents one change: [#1379](https://github.com/foolzzz/looper/pull/1379) (room consults without model prices, and the runtime label of steering runs; fixes [#1374](https://github.com/foolzzz/looper/issues/1374)).

## Release Decision

**Who should upgrade:** Operators who run Coco (or other runtimes whose models carry no full price) with the agent room and consults, and operators who read the runtime name in the init event of steering Coco runs.

**What this release solves:** [#1379](https://github.com/foolzzz/looper/pull/1379) gives a consult that cannot hold its spend cap for lack of a full model price a typed reason, `budget_unavailable`, with the reason surfaced to the Planner and to the asking seat, instead of the misleading `runtime_cannot`. It also makes steering Coco runs report `coco` rather than `codex` in their init event.

**Breaking changes:** No. The CLI, the API and the dashboard are unchanged, no new command or control is added and there is no PostgreSQL schema change. The PR states behavior changes, listed below. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.6
```

**Contributors:** Maintainer @foolzzz authored [#1379](https://github.com/foolzzz/looper/pull/1379); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.5 upgrades directly. There is no PostgreSQL schema change. Restart the service after upgrading, as for every release.

## Behavior changes

Read in the diff of the PR.

### #1379: Room consults without model prices, and the runtime label of steering runs

- **Consult without a full price.** When a consult's model is priced by its provider but lacks a full price, the consult does not start and ends with the new fallback reason `budget_unavailable` (it was `runtime_cannot`). Time and turn limits do not establish a spend cap, so none is used as a substitute. The reason joins the reasons that give up before the run started, so the questions go to the Planner without a consult run.
- **Reason surfaced.** The notice sent to the asking seat now ends with the reason text, and the Planner's escalation carries the typed reason and its detail. The source run's report and session are left intact; no answer or delivery receipt is invented.
- **Runtime label.** The Codex channel now takes the runtime type, so a steering run of a runtime that uses it (Coco) reports that runtime in its init event; it reported `codex` since #1370. The default stays `codex`.
- **Cursor channel.** It raises `BrokenPipeError` when the runtime closed stdin before the first prompt, instead of writing to the closed pipe.
- **Behavior change.** Consults on models without full prices are refused as `budget_unavailable` rather than `runtime_cannot`, with the reason shown to the asker; steering Coco runs show `coco` in run evidence.

### Model-visible changes

Yes, narrowly. The `[ROOM]` escalation the Planner receives for such a consult now names `budget_unavailable`, and the asking seat's notice includes the reason text. Prompt contracts, the consult contract and tool schemas are unchanged.

### 行为变化与入口

以下在该 PR 的差异中可见。

**#1379：没有模型价格时的房间咨询，以及 steer 运行的运行时标签**

- **没有完整价格的咨询。**咨询的模型按 provider 计价但缺少完整价格时，咨询不启动，以新的回退原因 `budget_unavailable` 结束（此前是 `runtime_cannot`）。时间和轮数限制无法保证花费上限，因此不作为替代。该原因归入运行开始前放弃的原因，问题不经咨询运行直接转给规划者。
- **原因可见。**发给提问席位的通知现在以原因文本结尾，规划者的升级消息带有类型化原因及细节。原运行的报告和会话保持完整，不编造回答或投递回执。
- **运行时标签。**Codex 通道现在接收运行时类型，使用该通道的运行时（Coco）的 steer 运行在 init 事件中报告自己的运行时；自 #1370 起它报告的是 `codex`。默认值仍为 `codex`。
- **Cursor 通道。**运行时在首个提示前已关闭 stdin 时，抛出 `BrokenPipeError`，不再写入已关闭的管道。
- **行为变化。**模型没有完整价格的咨询现在以 `budget_unavailable` 而非 `runtime_cannot` 被拒绝，并向提问方展示原因；steer 型 Coco 运行在运行证据中显示 `coco`。

**面向模型的变化：**有，范围很窄。规划者为此类咨询收到的 `[ROOM]` 升级消息现在写明 `budget_unavailable`，提问席位的通知包含原因文本。提示词契约、咨询契约和工具 schema 不变。
