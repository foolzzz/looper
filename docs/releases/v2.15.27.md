# Looper v2.15.27

This release documents the changes merged since the v2.15.26 tag. That tag is on its release commit, so this range also contains four pulls that merged before the v2.15.26 release pull request but are not on that tag ([#1508](https://github.com/foolzzz/looper/pull/1508), [#1567](https://github.com/foolzzz/looper/pull/1567), [#1568](https://github.com/foolzzz/looper/pull/1568), [#1571](https://github.com/foolzzz/looper/pull/1571)). They ship here, with full notes. The v2.15.26 release pull request ([#1573](https://github.com/foolzzz/looper/pull/1573)) is not a change in this release. The headline is the Manager persona, now injected and scoped by who the message is from ([#1569](https://github.com/foolzzz/looper/pull/1569), `manager.persona`, still unset until stored), and the dashboard Status card with `/status` ([#1567](https://github.com/foolzzz/looper/pull/1567), [#1572](https://github.com/foolzzz/looper/pull/1572), `status_card.enabled`, default off). A user turn can record `queued_behind` while Manager metrics are already on ([#1579](https://github.com/foolzzz/looper/pull/1579)). The rest are foundations that stay off until set: session search ([#1501](https://github.com/foolzzz/looper/pull/1501)), leads full text ([#1504](https://github.com/foolzzz/looper/pull/1504)), an operator profile ([#1535](https://github.com/foolzzz/looper/pull/1535)), lead taint for outbound review ([#1508](https://github.com/foolzzz/looper/pull/1508)), event triage tables ([#1538](https://github.com/foolzzz/looper/pull/1538)), intent and ledger card buttons ([#1541](https://github.com/foolzzz/looper/pull/1541)), executable acceptance checks including a sandboxed local mode ([#1552](https://github.com/foolzzz/looper/pull/1552), [#1565](https://github.com/foolzzz/looper/pull/1565)), platform sub-agents and the explorer role ([#1554](https://github.com/foolzzz/looper/pull/1554), [#1566](https://github.com/foolzzz/looper/pull/1566), [#1577](https://github.com/foolzzz/looper/pull/1577)), and cost-guard observation ([#1563](https://github.com/foolzzz/looper/pull/1563)). Project-skill versions are not behind a switch ([#1570](https://github.com/foolzzz/looper/pull/1570)). New leads-check records are stored as `run_kind` `leads_check` ([#1530](https://github.com/foolzzz/looper/pull/1530)). Action categories are declarations only ([#1562](https://github.com/foolzzz/looper/pull/1562)). Tests and CI only: [#1568](https://github.com/foolzzz/looper/pull/1568), [#1571](https://github.com/foolzzz/looper/pull/1571), [#1587](https://github.com/foolzzz/looper/pull/1587), [#1589](https://github.com/foolzzz/looper/pull/1589), [#1590](https://github.com/foolzzz/looper/pull/1590), [#1594](https://github.com/foolzzz/looper/pull/1594). This release is frozen at the commit that contains main through [#1535](https://github.com/foolzzz/looper/pull/1535).

No new switch in this release defaults to on. With every new switch left off, a persona that was already stored is now injected, a project-skill write records a version, a new leads-check record is `leads_check`, and lead-taint marks are still written.

## Release Decision

**Who should upgrade:** Anyone who stored a Manager persona, who will turn on the Status card, session search, leads full text, an operator profile, event triage, acceptance checks, platform sub-agents or cost-guard observation, and anyone who already uses card buttons, outbound review or Manager metrics. An installation that turns none of the new switches on still applies the additive migrations at startup, backfills project-skill versions, and starts labeling new leads-check records. `web/` changed, so the dashboard bundle is rebuilt by the release workflow as usual.

**What this release solves:** The default Manager can speak with the operator's persona, scoped by the message source. The dashboard can show a Status card, and `/status` can be answered by code. A user turn can say what it waited behind, while metrics are on. The operator can search their own earlier chats, match leads by full text, and compile a profile from vault notes. Outbound review can later see which outside content entered a task. Triage, acceptance checks, explorer sub-agents and a cost-guard observation mode can be turned on per setting or per project. Each of those stays off until set. Project skills gain a version history.

**Breaking changes:** No. No existing API drops a field that a caller must send. A persona already stored under `manager.persona` is now injected into the default Manager prompt; v2.15.26 stored it and did not inject it. There are additive PostgreSQL migrations. Seven of them have an online validation or index step. The `skill_versions` upgrade writes a version-1 row for each existing project skill that has `SKILL.md` and no version yet. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older. New operator operations include `status_card_settings.get`, `status_card_settings.update`, `status_card.get`, `session_search.get`, `session_search.update`, `profile.get`, `profile_source.get`, `profile_source.update`, `triage_settings.get`, `triage_settings.update`, `acceptance_checks.get`, `acceptance_checks.update`, `task_evidence.get`, `cost_guard.get`, `cost_guard.update`, `runs.tree`, `project_skills.versions` and `project_skills.rollback`.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.27
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.26 upgrades directly. Restart the service after upgrading, as for every release. `web/` changed, so the release workflow rebuilds the dashboard bundle from `web/` into the wheel, as usual. This pull request does not commit that bundle.

This release has additive PostgreSQL migrations, applied once at startup, inside the schema transaction, in `(order, name)` order. Seven of them have an online step, run after that transaction commits, in `(online_order, name)` order. The others do not. A fresh database creates the same objects from `schema.sql` plus each module's `fresh_ddl`, and does not record a separate migration for a table it already has. A database that has not yet finished an earlier online step still runs that step. `gateway_aliases` is still absent from admission probes.

## Behavior changes

### Persona, injected when stored, scoped by the message source ([#1569](https://github.com/foolzzz/looper/pull/1569))

v2.15.26 stored `manager.persona` and added no prompt section. This release injects it for the default Manager.

- **`manager.persona` is absent until set.** It is one JSON object. `name` is at most 20 characters, `address` 20, `tone` 200, `notes` 400, and the four together at most 600. Empty or whitespace-only text deletes the row. An unreadable stored value adds no section and logs `manager.persona is unreadable` once per payload. No new migration and no new setting.
- **Only the operator can read or set it.** `manager_persona.get` is read, level inside. `manager_persona.update` is write, level inside. It is not listed on `looper_settings`. Settings → Chat has the form. A scenario Manager does not inherit it.
- **Scope follows the message source, not only the session.** `FULL` for the dashboard, an API client, and the operator's own direct chat: the heading is `Persona (set by the operator: your name and tone; Looper's rules still apply):`, then nonempty name, tone and notes. The stored address is not injected. `NAME` for a session that is not `main` (a routed group or another sender's direct chat): the heading is `Persona (set by the operator: your name; Looper's rules still apply):`, then the name only. `OMIT` for a shared group, or a non-operator bot direct chat, that still runs on `main`. An unknown or unreadable operator identity omits the section. An unset, empty, or address-only persona adds no section.
- **While it is unset,** prompts, tools, commands and process signatures match a turn with the setting absent.

### Status card and `/status`, off ([#1567](https://github.com/foolzzz/looper/pull/1567), [#1572](https://github.com/foolzzz/looper/pull/1572))

- **`status_card.enabled` defaults off.** No row, or any value other than the string `true`, leaves it off. A failed read stays off. Only the operator can call `status_card_settings.get`, `status_card_settings.update` and `status_card.get`. The update accepts `true`, `false` or `null`. `null` deletes the row and restores off. `false` stores the string `false`. An API client token gets 403.
- **While it is off,** `status_card.get` returns a conflict (`the status card is not enabled (system setting status_card.enabled)`). `/status` stays an ordinary message. The dashboard polls `status_card.get` every 15 seconds and, after that one conflict, renders nothing.
- **While it is on,** code answers `/status` in the operator's private chat or the console. Anywhere else the reply is exactly `状态只在你本人的私聊和控制台里看。` The snapshot is sections with state `ok`, `error` or `unknown`. An enabled `/status` aimed at a Manager is not stored for a later session or a resume brief.

### Queued behind, only while metrics are on ([#1579](https://github.com/foolzzz/looper/pull/1579))

- **No new setting and no migration.** `queued_behind` is written only on a user turn's `metadata.turn_metrics`, and only while `manager.metrics.enabled` is the string `true`. While metrics are off, `TurnTimes` is not created and nothing is written.
- **The value is `none`, `user` or `background`.** It is what that message waited behind in its own session between arrival and its turn. A background turn that ended at or after arrival wins over a user turn. A user turn alone is `user`. Neither is `none`. A completion turn's metrics record does not include the field.

### Session search, off until routing isolates groups ([#1501](https://github.com/foolzzz/looper/pull/1501))

- **`manager.session_search.enabled` defaults off.** No row, or any value other than the string `true`, leaves it stored off. A failed read counts as off. It takes effect only when the stored value is `true` and `group_sessions()` is `own`. Session routing (`manager.session_routing.enabled` the string `true`) makes `group_isolation()` return `ISOLATED` and `group_sessions()` return `own`. While routing is off, `group_sessions()` is `shared`.
- **Only the operator can call `session_search.get` and `session_search.update`.** `enabled` true, false or null. `null` deletes the row. Turning it on while groups share the Manager session conflicts and stores nothing. The tool `looper_session_search` is listed only for the default Manager, only on the operator's own turns, and only while the search is in effect. Default limit 5 (range 1 to 10). Each passage is at most 300 characters and is fenced as outside content. The audit trail keeps message ids and the count, not the text. A direct chat is the operator's own while `chat_direct_threads.sender_id` is that bot's operator id. Those rows are written only while the search is in effect.
- **While it is off, or stored on while routing is off,** the tool is not listed and nothing is recorded, whatever a hand-written `true` says.

### Leads full text, default `words` ([#1504](https://github.com/foolzzz/looper/pull/1504))

- **`leads.search_mode` defaults to `words`.** No row, or any value other than the exact string `fulltext`, is `words`. A failed read counts as `words`. `fulltext` matches tokens and, when `pg_trgm` is installed, trigram likeness. `leads.settings_get` and `leads.settings_put` still accept only `enabled` and `valid_days`. This release does not add an operation that writes `leads.search_mode`. Store the system setting as the exact string `fulltext` to turn it on, and delete the row or store `words` to turn it off.
- **While it stays `words`,** lead search matches every word as written, as before.

### Operator profile, unset, and not injected ([#1535](https://github.com/foolzzz/looper/pull/1535))

- **`manager.profile.source` is absent until set.** Absent means no compile, no cache row and no prompt section. The folder must be an absolute directory inside the configured knowledge vault. Notes come only from `关于我.md` or `记忆/关于我.md`, plus `偏好/**/*.md`. The rendered text is at most 1500 characters. Only the operator can call `profile.get`, `profile_source.get` and `profile_source.update`. `null` clears the source and the cached block. A stored source that is missing, relative, or not a directory makes `profile.get` fail rather than look unset. The compiled block is not injected into the Manager in this release.

### Lead taint, marks written while review stays off ([#1508](https://github.com/foolzzz/looper/pull/1508))

- **No new setting.** `outbound_review.enabled` is unchanged: no row, or any value other than the string `true`, leaves review off. While review is off, the command, the tool list and prompts are unchanged, and the hook endpoint is not called. The new columns are still written. `tasks.untrusted_inputs` gains `leads` when a Manager session that had found leads creates or extends the task, and `intent` when an intent builds it. Values are only added. `agent_sessions.leads_session_id` records the Manager session in which a leads search found leads.
- **While review is on,** a Worker or Reviewer run of a marked task gets the existing outbound-review hook. A runtime without `tool_hook` fails `review_unsupported_runtime`. A group task and another person's task are blocked by code. Nothing in this release reads the marks while review is off.

### Event triage, off, and execution is not available ([#1538](https://github.com/foolzzz/looper/pull/1538))

- **`subscriptions.triage.enabled` defaults off.** No row, or any value other than the string `true`, leaves it off. Only the operator can call `triage_settings.get` and `triage_settings.update` (`enabled` true, false or null; `null` deletes the row). Public subscription create still accepts `output_kind` `push`, `leads` or `intents` only. The database check also allows `triage`.
- **A subscription whose `output_kind` is already `triage` does not run a processor.** The firing ends `skipped_gate` and does not move the cursor. While the switch is off the error is `subscriptions.triage.enabled is off`. While it is on the error is `triage execution is not available yet`.

### Intent and ledger card buttons, still off ([#1541](https://github.com/foolzzz/looper/pull/1541))

- **`cards.actions.enabled` is unchanged and stays off.** No row, or any value other than the string `true`, leaves it off. No new setting. There is still no dashboard switch and no HTTP write of that setting in this release. While it is off, no card row is written for an intent or a ledger item.
- **While it is on,** a Lark bot chat and a Telegram operator direct chat can show intent buttons 建 and 驳回, and a ledger 确认. The press is checked within `AUTHORIZE_SECONDS` (1.5). The web chat and the lark-cli channel stay text.

### Acceptance checks, off per project ([#1552](https://github.com/foolzzz/looper/pull/1552), [#1565](https://github.com/foolzzz/looper/pull/1565))

- **`projects.acceptance_checks` null is `off`.** The stored values are `local` and `network`. Only the operator can call `acceptance_checks.get` and `acceptance_checks.update` (high risk, confirms) and `task_evidence.get`. It is not on `chat_settings`. An agent project patch cannot change it. While it is off, prompts and contracts stay as they were, and no check runs.
- **While `local` or `network` is set,** checks run after a Worker succeeds and the evidence is stored. Failed or missing evidence does not change the Planner's accept or review decision in this release. At most 12 checks on a step, at most 2 running in the service, 900 cumulative seconds per step attempt, 16 MiB of output, a 4000-character tail. An artifact check has at most 3 files, 2 MiB each, 50 MiB for the task. A command's own timeout defaults to 300 seconds and is at most 1800.
- **`local` is sandboxed, or it does not run.** macOS uses `sandbox-exec -p '(version 1)(allow default)(deny network*)(deny job-creation)'` and then `/bin/sh -c`. Linux uses `unshare -rn --` and then `/bin/sh -c`. The Linux path is not verified on a target host. A failed preflight records `error_kind` `sandbox_unavailable` and never falls back to an unsandboxed command. Neither launcher restricts the service user's file access. `network` permits the network only when a check asks for it. Commands run as the server user.

### Platform sub-agents, off per project, explorer only ([#1554](https://github.com/foolzzz/looper/pull/1554), [#1566](https://github.com/foolzzz/looper/pull/1566), [#1577](https://github.com/foolzzz/looper/pull/1577))

- **`projects.subagents` null is `off`.** `on` enables the tools. The other four columns are null until set, and the code then uses `subagent_budget_usd` 0.50 (0.01 to 5), `subagent_task_budget_usd` 3.0 (0.01 to 50), `subagents_per_run` 4 (0 to 20) and `subagents_per_task` 20 (0 to 100). All five fields are omitted from project reads while null. Only the explorer role is supported. Explorers cannot spawn children. Only a Planner or Worker run may spawn one.
- **[#1554](https://github.com/foolzzz/looper/pull/1554) has no user entry point.** [#1566](https://github.com/foolzzz/looper/pull/1566) adds `looper_agent_spawn`, `looper_agent_wait` and `looper_agent_cancel` on a Worker, and only while that project is `on`. Wait accepts up to 8 spawn ids, or the run's list, and at most 120 seconds. A room message of kind `spawn_result` carries the typed result. [#1577](https://github.com/foolzzz/looper/pull/1577) adds operator-only `runs.tree` and the dashboard run tree. The tab is visible on every task. While sub-agents are off it does not offer a spawn.
- **While `subagents` is unset,** Worker prompts do not gain the explorer tools.

### Cost guard observation, off ([#1563](https://github.com/foolzzz/looper/pull/1563))

- **`cost_guard.mode` defaults to `off`.** No row is `off`. The only accepted modes are `off` and `observe`. Enforcement is refused. `null` clears a stored mode. Caps are `cost_guard.daily_usd` and `cost_guard.daily_equivalent_usd`, each a nonnegative finite number of US dollars, or null for no cap. - **While mode is `off`,** no reservation is written, record fields are unchanged, and prompts, tools and launch inputs match the previous release. While `observe`, reservations and server logs are written and runs continue. A guard error does not stop an ordinary run.

### Project-skill versions, not behind a switch ([#1570](https://github.com/foolzzz/looper/pull/1570))

Operator-only `project_skills.versions` reads history. `project_skills.rollback` restores one version and does not ask for confirmation. Run library records, launch arguments and prompts are unchanged. The upgrade backfill is under Upgrading.

### Leads-check run kind, always, for new records ([#1530](https://github.com/foolzzz/looper/pull/1530))

### Action categories, declarations only ([#1562](https://github.com/foolzzz/looper/pull/1562))

**谁需要升级：**已经存过管家人格的安装，以及要打开状态卡片、会话搜索、线索全文、操作者画像、事件分拣、验收检查、平台子代理或花费观察的安装，还有已经在用卡片按钮、出站复核或管家度量的安装。这些新开关都不打开的安装，启动时仍会执行可加的迁移、回填项目技能版本，并开始给新的线索检查记录打上 `leads_check`。`web/` 有改动，仪表盘包由发布流程照常重新构建。

**解决了什么：**默认管家可以按操作者存下的人格说话，范围随消息来源变化。仪表盘可以显示状态卡片，`/status` 可以由代码回答。度量打开时，用户回合可以记下它排在什么后面。操作者可以搜索自己以前的对话，用全文匹配线索，并从知识库笔记编译一份画像。出站复核以后能看到任务带进了哪类外部内容。分拣、验收检查、explorer 子代理和花费观察可以按设置或按项目打开。这些在设置之前都是关的。项目技能有了版本历史。

**是否有破坏性变更：**无。没有既有 API 去掉调用方必须发送的字段。已经存在 `manager.persona` 的安装，升级后会把它注入默认管家的提示词；v2.15.26 只保存、不注入。有可加的 PostgreSQL 迁移，其中七个有在线校验或建索引步骤。`skill_versions` 的升级会给每个已有、带 `SKILL.md`、还没有版本的项目技能写一条版本 1。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。新增的操作者操作有 `status_card_settings.get`、`status_card_settings.update`、`status_card.get`、`session_search.get`、`session_search.update`、`profile.get`、`profile_source.get`、`profile_source.update`、`triage_settings.get`、`triage_settings.update`、`acceptance_checks.get`、`acceptance_checks.update`、`task_evidence.get`、`cost_guard.get`、`cost_guard.update`、`runs.tree`、`project_skills.versions` 和 `project_skills.rollback`。

### 行为变化

### 人格：存下之后会注入，并按消息来源区分（[#1569](https://github.com/foolzzz/looper/pull/1569)）

v2.15.26 只保存 `manager.persona`，不增加提示词一节。本版本为默认管家注入它。

- **`manager.persona` 未设置之前没有这一行。** 它是一个 JSON 对象。`name` 最多 20 字，`address` 20，`tone` 200，`notes` 400，合计最多 600。空白文本删掉这一行。读不出来时不增加一节，并记一次 `manager.persona is unreadable`。没有新迁移，没有新设置。
- **只有操作者能读和写。** `manager_persona.get` 是读，级别 inside。`manager_persona.update` 是写，级别 inside。`looper_settings` 不列出它。Settings → Chat 有表单。场景管家不继承。
- **范围看消息来源。** 仪表盘、API 客户端和操作者自己的私聊是完整节，标题是 `Persona (set by the operator: your name and tone; Looper's rules still apply):`，然后是非空的名字、语气和备注。存下的 `address` 不注入。不是 `main` 的会话（已路由的群或其他发送者的私聊）只有名字，标题是 `Persona (set by the operator: your name; Looper's rules still apply):`。仍在 `main` 上的共享群，或非操作者的机器人私聊，不注入。认不出操作者时也不注入。未设置、空白或只有称呼时不增加一节。

### 状态卡片和 `/status`，默认关闭（[#1567](https://github.com/foolzzz/looper/pull/1567)、[#1572](https://github.com/foolzzz/looper/pull/1572)）

- **`status_card.enabled` 默认关闭。** 没有这一行，或不是字符串 `true`，都是关。读失败也保持关闭。只有操作者能调用 `status_card_settings.get`、`status_card_settings.update` 和 `status_card.get`。更新接受 `true`、`false` 或 `null`。`null` 删掉这一行并恢复关闭。`false` 存下字符串 `false`。API 客户端令牌得到 403。
- **关闭时** `status_card.get` 返回冲突。`/status` 仍是普通消息。仪表盘每 15 秒请求一次，那一次冲突之后不再渲染。
- **打开后** 代码只在操作者的私聊或控制台里回答 `/status`。其他地方的回复正好是 `状态只在你本人的私聊和控制台里看。`

### 排在什么后面，只在度量打开时（[#1579](https://github.com/foolzzz/looper/pull/1579)）

- **没有新设置，没有迁移。** `queued_behind` 只写在用户回合的 `metadata.turn_metrics` 上，并且只有 `manager.metrics.enabled` 为字符串 `true` 时才写。度量关闭时不创建 `TurnTimes`，什么都不写。取值是 `none`、`user` 或 `background`。完成回合的度量记录不含这个字段。

### 会话搜索，要等路由把群隔开（[#1501](https://github.com/foolzzz/looper/pull/1501)）

- **`manager.session_search.enabled` 默认关闭。** 没有这一行，或不是字符串 `true`，存的就是关。读失败也算关。只有存的是 `true` 且 `group_sessions()` 为 `own` 时才生效。会话路由（`manager.session_routing.enabled` 为字符串 `true`）使 `group_isolation()` 返回 `ISOLATED`，`group_sessions()` 返回 `own`。路由关闭时 `group_sessions()` 是 `shared`。
- **只有操作者能 `session_search.get` 和 `session_search.update`。** 群还共享管家会话时，打开会冲突并且什么都不存。`null` 删掉这一行。工具 `looper_session_search` 只给默认管家、只在操作者自己的回合、只在搜索生效时列出。默认条数 5（1 到 10）。每段最多 300 字，并围成外部内容。私聊算操作者自己的，要看 `chat_direct_threads.sender_id` 是不是该机器人的操作者。这些行只在搜索生效时写入。

### 线索全文，默认 `words`（[#1504](https://github.com/foolzzz/looper/pull/1504)）

- **`leads.search_mode` 默认 `words`。** 没有这一行，或不是精确字符串 `fulltext`，就是 `words`。读失败也算 `words`。`leads.settings_put` 仍只接受 `enabled` 和 `valid_days`。本版本没有写入这个键的操作。把系统设置存成精确字符串 `fulltext` 才打开；删掉这一行或存 `words` 就关上。

### 操作者画像，未设置，且不注入（[#1535](https://github.com/foolzzz/looper/pull/1535)）

- **`manager.profile.source` 未设置之前没有这一行。** 没有它就不编译、不写缓存、不增加提示词。目录必须是配置好的知识库里的绝对路径。笔记只来自 `关于我.md` 或 `记忆/关于我.md`，以及 `偏好/**/*.md`。渲染文本最多 1500 字。只有操作者能 `profile.get`、`profile_source.get` 和 `profile_source.update`。`null` 清掉来源和缓存。存下的路径不存在、是相对路径或不是目录时，`profile.get` 失败，而不是看起来像未设置。本版本不把编译结果注入管家。

### 线索污点，复核关闭时仍写标记（[#1508](https://github.com/foolzzz/looper/pull/1508)）

- **没有新设置。** `outbound_review.enabled` 不变：不是字符串 `true` 就是关。关闭时命令、工具列表和提示词不变，钩子端点不被调用。新列仍会写入。找到过线索的管家会话创建或扩展任务时，`tasks.untrusted_inputs` 加上 `leads`；意图建成任务时加上 `intent`。只加不减。`agent_sessions.leads_session_id` 记下那次找到线索的管家会话。打开复核后，带标记任务的 Worker 或 Reviewer 运行走原来的钩子。没有 `tool_hook` 的运行时失败为 `review_unsupported_runtime`。群任务和别人的任务由代码拦住。复核关闭时没有人读这些标记。

### 事件分拣，默认关闭，执行还不可用（[#1538](https://github.com/foolzzz/looper/pull/1538)）

- **`subscriptions.triage.enabled` 默认关闭。** 不是字符串 `true` 就是关。只有操作者能 `triage_settings.get` 和 `triage_settings.update`。`null` 删掉这一行。公开的订阅创建仍只接受 `output_kind` 为 `push`、`leads` 或 `intents`。数据库约束另外允许 `triage`。已经是 `triage` 的订阅不会跑处理器：这次触发以 `skipped_gate` 结束，游标不动。关闭时错误是 `subscriptions.triage.enabled is off`。打开时错误是 `triage execution is not available yet`。

### 意图和台账的卡片按钮，开关仍默认关闭（[#1541](https://github.com/foolzzz/looper/pull/1541)）

- **`cards.actions.enabled` 不变，仍默认关闭。** 不是字符串 `true` 就是关。没有新设置。本版本仍没有仪表盘开关，也没有这个设置的 HTTP 写入。关闭时意图和台账不写卡片行。打开后，Lark 机器人会话和 Telegram 操作者私聊可以有意图按钮建和驳回，以及台账的确认。按压在 `AUTHORIZE_SECONDS`（1.5）内检查。网页聊天和 lark-cli 渠道仍是文本。

### 验收检查，按项目关闭（[#1552](https://github.com/foolzzz/looper/pull/1552)、[#1565](https://github.com/foolzzz/looper/pull/1565)）

- **`projects.acceptance_checks` 为 null 就是 `off`。** 存值是 `local` 或 `network`。只有操作者能 `acceptance_checks.get`、`acceptance_checks.update`（高风险，要确认）和 `task_evidence.get`。不在 `chat_settings` 上。代理对项目的补丁改不了它。关闭时提示词和契约与以前相同，不跑检查。
- **设为 `local` 或 `network` 后，** Worker 成功之后跑检查并存证据。失败或缺失的证据在本版本不改变 Planner 的接受或评审决定。一步最多 12 条检查，服务同时最多 2 条，每步尝试累计 900 秒，输出 16 MiB，尾巴 4000 字符。产物检查最多 3 个文件，每个 2 MiB，一个任务 50 MiB。单条命令默认超时 300 秒，最多 1800 秒。
- **`local` 进沙箱，否则不跑。** macOS 用 `sandbox-exec -p '(version 1)(allow default)(deny network*)(deny job-creation)'`，然后 `/bin/sh -c`。Linux 用 `unshare -rn --`，然后 `/bin/sh -c`。Linux 这条路径没有在目标主机上验证过。预检失败记下 `error_kind` `sandbox_unavailable`，绝不退回无沙箱。两种启动器都不限制服务用户的文件访问。命令以服务器用户身份运行。

### 平台子代理，按项目关闭，只有 explorer（[#1554](https://github.com/foolzzz/looper/pull/1554)、[#1566](https://github.com/foolzzz/looper/pull/1566)、[#1577](https://github.com/foolzzz/looper/pull/1577)）

- **`projects.subagents` 为 null 就是 `off`。** `on` 才启用工具。另外四列未设置时，代码使用 `subagent_budget_usd` 0.50（0.01 到 5）、`subagent_task_budget_usd` 3.0（0.01 到 50）、`subagents_per_run` 4（0 到 20）、`subagents_per_task` 20（0 到 100）。这五个字段在为 null 时不出现在项目读取里。只支持 explorer。explorer 不能再生子代理。只有 Planner 或 Worker 运行能生成。
- **[#1554](https://github.com/foolzzz/looper/pull/1554) 没有用户入口。** [#1566](https://github.com/foolzzz/looper/pull/1566) 在项目为 `on` 时给 Worker 加上 `looper_agent_spawn`、`looper_agent_wait` 和 `looper_agent_cancel`。等待最多 8 个 id，或该运行的列表，最多 120 秒。房间消息 kind `spawn_result` 携带有类型的结果。[#1577](https://github.com/foolzzz/looper/pull/1577) 加上只给操作者的 `runs.tree` 和仪表盘运行树。每个任务都有这个页。子代理关闭时它不提供生成。

### 花费观察，默认关闭（[#1563](https://github.com/foolzzz/looper/pull/1563)）

**启用：**操作者把该项目的 `subagents` 设为 `on` 之前是关的。null 就是 `off`，五个子代理字段在为 null 时不出现在项目读取里。计数留空时使用的默认是 `subagent_budget_usd` 0.50（0.01 到 5）、`subagent_task_budget_usd` 3.0（0.01 到 50）、`subagents_per_run` 4（0 到 20）、`subagents_per_task` 20（0 到 100）。只接受 explorer 角色。Worker 工具 `looper_agent_spawn`、`looper_agent_wait` 和 `looper_agent_cancel` 只在项目为 `on` 时出现。`runs.tree` 只给操作者，仪表盘页无论开关都在每个任务上可见。

**验证：**为 null 时，Worker 的工具列表没有这三个工具。为 `on` 时，Planner 或 Worker 运行可以生成 explorer，并最多等 120 秒，最多 8 个 id 或该运行的列表。explorer 不能生成子代理。有生成时运行树会显示它。

**停用 / 回退：**把 `subagents` 设回 `off`（存为 null）。下一次运行不再列出这些工具。已经存下的生成行留着。`idx_agent_spawns_key` 留着。

**权限边界：**项目列是操作者的项目设置。工具只在该项目的 Planner 或 Worker 运行里执行。`runs.tree` 不生成。explorer 只读，也不浏览网页。

**文档：** https://github.com/foolzzz/looper/blob/v2.15.27/docs/architecture/agent-system.md#a-workers-explorer-tools

looper --version

#### Cost guard

**启用：**操作者把 `cost_guard.mode` 设为 `observe` 之前是关的。没有这一行、`off` 或 `null` 都是关。`observe` 是另一个唯一接受的模式。强制执行被拒绝。经 `POST /api/v1/cost_guard/update` 设置。上限可选：`daily_usd` 和 `daily_equivalent_usd`，以及 `roles` 下 `processor`、`leads_check`、`advice_check`、`outbound_check`、`advisor` 的同样两项。缺的上限就是不设上限。调用要确认。API 客户端令牌得到 403。Settings → 花费显示模式，不能在那里改。

**验证：**关闭时，模型运行存下的记录不增加预留字段，启动输入与 v2.15.26 相同。`observe` 时运行仍会结束，服务器日志记下预留。存值无效时报告 `Stored cost guard settings are invalid; the guard is off.` 该页近 30 天每日 P95 的 1.5 倍不会被写成上限。

**停用 / 回退：**把 `mode` 设为 `off` 或 `null`。新的运行不再预留。上限可以用 null 清掉。没有新增表。

**权限边界：**只给操作者。`cost_guard.get` 是读，`cost_guard.update` 是写，级别 inside。它不是管家工具，也不在 `chat_settings` 上。观察模式不拒绝、不询问、也不改变重试。

**文档：** https://github.com/foolzzz/looper/blob/v2.15.27/docs/architecture/agent-system.md#cost-guard-observation
