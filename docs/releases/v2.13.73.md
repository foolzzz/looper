# Looper v2.13.73

## Release Decision

**Who should upgrade:** Operators who create tasks from the dashboard, and anyone who calls `POST /api/tasks/create` from a script or smoke test.

**What this release solves:** [#476](https://github.com/foolzzz/looper/pull/476) moves dashboard task creation onto the v1 API and the shared creation core, with the project's full persisted configuration, and removes the old console-only create route.

**Breaking changes:** Yes. `POST /api/tasks/create` is removed. Callers must use `POST /api/v1/tasks/create`, whose answer carries the task fields under `result` and uses status 200 where the old route used 201. The bundled eval and smoke scripts are already updated.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#476](https://github.com/foolzzz/looper/pull/476); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.73
```

## Behavior changes

- **Route:** the v1 operation `tasks.create` (`POST /api/v1/tasks/create`, in `looper/agents/v1_domains/task_create.py`) creates a ready task in an existing project (`project_id`) or a new one (`project`, which also accepts the project's execution fields). It takes `requirement`, `work_dir`, `config`, `goal_id`, `profile_overrides`, `workspace_mode` and `base`, and returns `task_id`, `status`, `created_at`, `project_id` and `workspace`. `/api/tasks/create` and `projects.create_task` are removed from `http_server.py` and `projects.py`.
- **Dashboard:** `createTask` in `web/src/lib/api.ts` calls the v1 route; a 202 confirmation answer is raised as an error. `NewProjectFields` now includes the project's execution fields.
- **Operator audit:** `Operation` gained `audit_operator` (default true). `tasks.create` sets it to false, so an operator's creation skips the Manager/client action trail. The v1 route also serializes domain results before answering.
- **Clients:** a client principal still goes through the confirmed client path; creating a new project asks for confirmation in the same session, with an impact text on the project name, default directory and work directory.
- **Verification:** after creation the task and its profile overrides are read back and compared with the request; a mismatch fails with an `unavailable` error telling the caller to refresh tasks before retrying.
- **Worker input:** in `looper/agents/tiers/worker.py`, the input-ready event is now set even when Claude closes stdin before the prompt is sent. The pull request description does not mention this change.
- **Scripts:** `evals/prompt_regression`, `examples/dsh/validate.py` and `examples/pi/isolated-smoke.py` use the v1 route and read `result`.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt or Manager Tool changed; the code states "no Manager Tool changes".

## Upgrade and rollback

Re-run `install.sh` once v2.13.73 is published, and move any script that calls `/api/tasks/create` to `/api/v1/tasks/create`. No data migration. Rolling back to v2.13.72 restores the old route, with no stored data affected.

### 行为变化与入口

- **路由：**v1 操作 `tasks.create`（`POST /api/v1/tasks/create`，位于 `looper/agents/v1_domains/task_create.py`）在已有项目（`project_id`）或新项目（`project`，同时接受项目执行字段）中创建就绪任务；参数含 `requirement`、`work_dir`、`config`、`goal_id`、`profile_overrides`、`workspace_mode`、`base`，返回 `task_id`、`status`、`created_at`、`project_id`、`workspace`。`http_server.py` 和 `projects.py` 中的 `/api/tasks/create` 与 `projects.create_task` 已删除。
- **仪表盘：**`web/src/lib/api.ts` 的 `createTask` 调用 v1 路由；202 确认响应会作为错误抛出。`NewProjectFields` 现包含项目执行字段。
- **运维审计：**`Operation` 新增 `audit_operator`（默认 true）；`tasks.create` 设为 false，运维人员的创建不进入 Manager/客户端操作记录。v1 路由在响应前也会序列化域结果。
- **客户端：**客户端主体仍走需确认的路径；新建项目须在同一会话中确认，影响说明包含项目名、默认目录和工作目录。
- **校验：**创建后会回读任务及其 profile 覆盖并与请求比对；不一致则返回 `unavailable` 错误，提示重试前先刷新任务。
- **Worker 输入：**`looper/agents/tiers/worker.py` 中，即使 Claude 在收到 prompt 前关闭 stdin，也会置位输入就绪事件。PR 描述未提及此改动。
- **脚本：**`evals/prompt_regression`、`examples/dsh/validate.py`、`examples/pi/isolated-smoke.py` 改用 v1 路由并读取 `result`。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 和 Manager Tool 均未改动；代码注明「no Manager Tool changes」。

### 升级与回退

v2.13.73 发布后重跑 `install.sh`，并把调用 `/api/tasks/create` 的脚本改到 `/api/v1/tasks/create`。无需迁移数据。回退到 v2.13.72 会恢复旧路由，不影响已存数据。
