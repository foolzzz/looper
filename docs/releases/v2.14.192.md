# Looper v2.14.192

This is the patch release v2.14.192, a hotfix line in which each merged change ships at once. It documents one change: [#1354](https://github.com/foolzzz/looper/pull/1354) (DSH materialize, directory removal and knowledge hashing run off the event loop).

## Release Decision

**Who should upgrade:** Operators who run `looper serve` and want directory cleanup, knowledge-document hashing and DSH catalog validation not to block the event loop.

**What this release solves:** [#1354](https://github.com/foolzzz/looper/pull/1354) moves blocking directory removals, the kept-session sweep, knowledge-document hash checks, launch record and command construction to worker threads, and caches the DSH catalog, so these no longer stall the loop.

**Breaking changes:** No. The CLI, the API and the dashboard are unchanged, no new command or control is added and there is no PostgreSQL schema change. The PR states no behavior change besides latency. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.192
```

**Contributors:** Maintainer @foolzzz authored [#1354](https://github.com/foolzzz/looper/pull/1354); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.191 upgrades directly. There is no PostgreSQL schema change. Restart the service after upgrading, as for every release.

## Behavior changes

Read in the diff of [#1354](https://github.com/foolzzz/looper/pull/1354). The PR states: behavior change (maintainer decision, intended): none besides latency.

### #1354: DSH materialize, directory removal and knowledge hashing off the event loop

- **Directory removal.** `shutil.rmtree` of step worktrees (`remove`, `forget_worktree`, `remove_orphan`), the Cursor run temp directory, and `remove_run_sessions` (task deletion, task restart) run via `asyncio.to_thread`. Kept-run `release()` calls (run start failure, adoption failure, worker finish and retry) and the periodic `sweep_run_sessions` also run on a thread.
- **Task deletion order.** In `delete_task`, the run-session removal now happens after the database delete and outside its connection scope, where it used to run inside the scope before the delete.
- **Knowledge hashing.** The check that a materialized knowledge copy matches its hash runs on a thread. Results are cached (up to 1024 entries) by path and file metadata (size, mtime, ctime, device, inode), so an unchanged copy is not read again; a replaced file with the same size and mtime is still detected through ctime and inode.
- **DSH catalog.** `materialize` caches a successful catalog per library and executable. Concurrent callers share one in-flight validation. A failure or interruption is not cached, so the next launch validates again.
- **Launch and command construction.** `launch.record()` and the Claude command builders (manager, planner, worker `run_command`) run on a thread. The manager's turn preparation gains an internal step label, `claude_command`, in `PREPARATION_STEPS`.

### Model-visible changes

None. No prompt, tool description or tool schema changed. The `claude_command` label names a preparation step and is not sent to a model.

### 行为变化与入口

以下在 [#1354](https://github.com/foolzzz/looper/pull/1354) 的差异中可见。PR 声明：除延迟外无行为变化（维护者决定，有意为之）。

**#1354：DSH 物化、目录删除和知识文档哈希移出事件循环**

- **目录删除。**步骤工作树（`remove`、`forget_worktree`、`remove_orphan`）、Cursor 运行临时目录以及 `remove_run_sessions`（删除任务、重启任务）的 `shutil.rmtree` 通过 `asyncio.to_thread` 执行。保留运行的 `release()` 调用（运行启动失败、接管失败、工作进程结束和重试）以及周期性的 `sweep_run_sessions` 也在线程上运行。
- **删除任务的顺序。**`delete_task` 中，运行会话的删除现在发生在数据库删除之后、连接作用域之外；此前在作用域内、删除之前执行。
- **知识文档哈希。**校验已物化的知识副本与其哈希是否一致的步骤在线程上运行。结果按路径和文件元数据（大小、mtime、ctime、设备、inode）缓存（最多 1024 条），未变化的副本不再重复读取；大小和 mtime 相同的替换文件仍可通过 ctime 和 inode 发现。
- **DSH 目录。**`materialize` 按库和可执行文件缓存成功的目录。并发调用方共享一次进行中的校验。失败或中断不缓存，下次启动会重新校验。
- **启动与命令构建。**`launch.record()` 以及 Claude 命令构建（manager、planner、worker 的 `run_command`）在线程上运行。manager 的轮次准备在 `PREPARATION_STEPS` 中新增内部步骤标签 `claude_command`。

**面向模型的变化：**无。未改动提示词、工具描述或工具 schema。`claude_command` 标签仅命名准备步骤，不会发给模型。
