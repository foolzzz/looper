# Looper v2.14.119

This is the patch release v2.14.119, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.118: review panel follow-ups ([#1192](https://github.com/foolzzz/looper/pull/1192)).

## Release Decision

**Who should upgrade:** Operators who use workflows with a review panel, and Telegram or Lark users who ask the Manager about review verdicts. Installations and tasks without a workflow see no change in behavior.

**What this release solves:** [#1192](https://github.com/foolzzz/looper/pull/1192). The verification step of a workflow with a review panel is no longer sent to an extra review; the Manager can read each panel seat's verdict; the Pipeline card shows panel findings instead of `[object Object]`; `on: completed` edges stay on the work node in the Pipeline layout; and a work result saved before review panels still gets the developer runtime check.

**Breaking changes:** No. There is no database change, and tasks without a workflow are unchanged.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.119
```

**Contributors:** Maintainer @foolzzz authored [#1192](https://github.com/foolzzz/looper/pull/1192); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.118 upgrades directly. This release has no database change.

## Behavior changes

- **Review exemptions.** Only for a workflow with a review panel. The verification step is no longer marked for review by `review_all` or an explicit review of its own, and a later plan change clears its review whenever it is the verification step, where before the check compared only its role. A workflow without a panel keeps the ordinary review rules (`review_all` and explicit reviews).
- **Verdicts for the Manager.** In the compact task view of the `looper_tasks` tool, a step that has panel reviews now carries `verdict` (`pass`, `fail` or `pending`), `blocking` and `suggestions` counts, up to 5 findings (`level`, `where`, `text`, clipped to 120 and 200 characters) and, when seats gave adjudication reasons, up to 5 `reasons` (clipped to 300 characters). Steps without panel reviews keep their existing shape.
- **Pipeline card.** The dashboard step card lists panel findings as member, level, location and text instead of `[object Object]`, in the failed-review text and in a new "Findings" section. This section shows a review step's findings, or a step's verification findings when it has no review text.
- **Pipeline layout.** An `on: completed` edge of a node now keeps the work node as its source instead of being moved to the step's acceptance review; other edges are unchanged.
- **Developer runtime check.** A verification review of a work result saved before review panels, which lacks the developer's runtime, now looks up the developer's most recent run record for the task and applies the same-runtime refusal. If no record or runtime is found, the check is skipped as before. The review request now also carries the developer's `worker_id`.
- **Unchanged:** tasks without a workflow, the review panel rules and verification rules themselves, and the database.
- **Model-visible changes:** Yes, small. For workflow tasks with a review panel the `looper_tasks` compact task view gains the verdict fields above, so the Manager model sees them when it reads a task. Verification steps of a panel workflow are no longer reviewed, so no review prompt is sent for them. The Planner's, Worker's and Reviewer's prompts and contracts are otherwise unchanged. Tasks without a workflow see none of this.

**是否有破坏性变更：**否。无数据库变更，没有工作流的任务不变。

**如何验证：**核对版本为 2.14.119。

**贡献者：**维护者 @foolzzz 提交 [#1192](https://github.com/foolzzz/looper/pull/1192)；本版本无社区贡献。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.118 上的安装可直接升级。本版本无数据库变更。

### 行为变化与入口

- **评审豁免。**仅对带评审小组的工作流生效。验证步骤不再因 `review_all` 或自身的显式评审而被标记为需评审；之后的计划变更只要它是验证步骤就会清除其评审（此前只比较角色）。没有评审小组的工作流保持原有评审规则（`review_all` 与显式评审）。
- **给 Manager 的结论。**`looper_tasks` 工具的精简任务视图中，带小组评审的步骤现在有 `verdict`（`pass`、`fail` 或 `pending`）、`blocking` 与 `suggestions` 计数、最多 5 条发现（`level`、`where`、`text`，分别截断到 120 和 200 字符），以及席位给出裁定理由时最多 5 条 `reasons`（截断到 300 字符）。没有小组评审的步骤形状不变。
- **Pipeline 卡片。**仪表盘步骤卡片以成员、级别、位置和文本列出小组发现，不再显示 `[object Object]`，包括未通过评审的文本和新增的“Findings”部分；该部分显示评审步骤的发现，或在步骤没有评审文本时显示其验证发现。
- **Pipeline 布局。**节点的 `on: completed` 边现在保持以工作节点为来源，不再移到该步骤的验收评审；其他边不变。
- **开发者运行时检查。**对评审小组之前保存、缺少开发者运行时的工作结果做验证评审时，现在会查找该开发者在此任务上最近的运行记录并应用“与开发者同一运行时”的拒绝规则；找不到记录或运行时则像以前一样跳过检查。评审请求现在还带有开发者的 `worker_id`。
- **不变：**没有工作流的任务、评审小组与验证规则本身、数据库。
- **面向模型的变化：**有，较小。对带评审小组的工作流任务，`looper_tasks` 精简任务视图新增上述结论字段，Manager 模型读取任务时会看到。小组工作流的验证步骤不再被评审，因此不发送评审提示词。Planner、Worker 和 Reviewer 的提示词与契约其余不变。没有工作流的任务不受影响。
