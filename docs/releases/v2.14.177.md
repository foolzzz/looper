# Looper v2.14.177

This is the patch release v2.14.177, a hotfix line in which each merged change ships at once. It documents one change: [#1327](https://github.com/foolzzz/looper/pull/1327) (`runs.list` returns summaries; the full prompt and result load on expand).

## Release Decision

**Who should upgrade:** Anyone who opens run history in the dashboard, and anyone who calls `runs.list` through the HTTP API or the generated CLI and reads run bodies, system prompts or launch commands from it. Such a caller must now read them with `runs.get`.

**What this release solves:** [#1327](https://github.com/foolzzz/looper/pull/1327) makes `runs.list` a summary-only read, so a list of runs no longer carries every full prompt, result, system prompt and launch command. `runs.get` still returns the full record. The dashboard loads the full run when a card is expanded.

**Breaking changes:** Yes, for direct callers of `runs.list`: list rows no longer contain `input_text`, `output_text`, `metadata.system_prompt`, `metadata.command` or `metadata.presentation.system_prompt.text`. Use `runs.get` for them. There is no database change, and the bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.177
```

**Contributors:** Maintainer @foolzzz authored [#1327](https://github.com/foolzzz/looper/pull/1327); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.176 upgrades directly. There is no database change.

## Behavior changes

Read in the diff of [#1327](https://github.com/foolzzz/looper/pull/1327):

- **`runs.list` returns summaries** (`looper/db/llm_records.py`, `looper/agents/v1_domains/runs.py`). Each row has `input_summary` and `output_summary` holding the first 200 characters of the body (the stored summary for historical rows without a body), plus `input_chars` and `output_chars` counting the full text (0 for null). A new `LlmRecordSummary` schema describes the row. Rows have no `input_text`, `output_text`, `metadata.system_prompt`, `metadata.command` or `metadata.presentation.system_prompt.text`. Other metadata stays, including the evidenced prompt mode and hash; the metadata is normalized before the fields are removed, so historical inline commands still supply the prompt mode. `runs.get` is unchanged and returns the full record.
- **Dashboard run history** (`web/src/pages/agent-history.tsx`). The history page polls summaries every two seconds while any listed run is running, then stops. Collapsed running cards keep their elapsed time and heartbeat age current. Expanding a card loads the full run with `runs.get`, shows a loading line, and caches the body while mounted; an expanded running run keeps polling. When a summary announces completion, a loaded body that was still running is refreshed once so it keeps the final output. Collapsed cards show the input and output previews.
- **Detail errors:** a failed load reads `Could not load this run: <message>` with a Retry button that has a minimum height of 44 px. Card headers gain `aria-expanded`.
- **Task eval runner** (`evals/prompt_regression/runner.py`). After its summary polling settles, it fetches each turn's full record with `runs.get`, so body scoring and command-based runtime evidence are kept.
- **Other readers:** the PR reports that the dashboard's launch-command and system-prompt sections, dialog runtime evidence and stop/DSH validation already use `runs.get`, and that model-request exports use `llm_requests`, so none needed a change. The chat and runs pages only switch to the summary type.
- **Documentation:** the `runs.list` and `runs.get` rows of the HTTP API table in `docs/architecture/agent-system.md` describe the new contract.
- **Model-visible changes:** None. Prompts, tool schemas and `channel_context` are unchanged; the change is to a dashboard and API read. Telegram and Lark messages are unchanged.

### 行为变化与入口

以下在 [#1327](https://github.com/foolzzz/looper/pull/1327) 的差异中可见：

- **`runs.list` 返回摘要。**每行有 `input_summary` 和 `output_summary`（正文的前 200 个字符；没有正文的历史行用已存的摘要），以及完整文本字符数 `input_chars`、`output_chars`（空值为 0）。新增 `LlmRecordSummary` schema。行中没有 `input_text`、`output_text`、`metadata.system_prompt`、`metadata.command` 和 `metadata.presentation.system_prompt.text`。其他元数据保留，包括已取证的提示词模式和哈希；先规范化元数据再移除字段，因此历史内联命令仍能提供提示词模式。`runs.get` 不变，返回完整记录。
- **仪表盘运行历史。**历史页在有运行进行中时每两秒轮询摘要，之后停止。折叠的运行中卡片持续更新已用时间和心跳年龄。展开卡片时用 `runs.get` 加载完整运行，显示加载提示，并在挂载期间缓存正文；展开的运行中任务继续轮询。当摘要宣告完成时，仍为运行中的已加载正文会刷新一次，以保留最终输出。折叠卡片显示输入和输出预览。
- **详情错误：**加载失败显示 `Could not load this run: <message>`，重试按钮最小高度 44 px。卡片标题新增 `aria-expanded`。
- **任务评测运行器。**在摘要轮询结束后，用 `runs.get` 取每一轮的完整记录，因此正文评分和基于命令的运行时证据得以保留。
- **其他读取方：**PR 报告称，仪表盘的启动命令与系统提示词部分、对话运行时证据以及 stop/DSH 校验已经使用 `runs.get`，模型请求导出使用 `llm_requests`，因此无需改动。聊天页和运行页只切换为摘要类型。
- **文档：**`docs/architecture/agent-system.md` 的 HTTP API 表中 `runs.list` 与 `runs.get` 两行描述了新契约。
- **面向模型的变化：**无。提示词、工具 schema 和 `channel_context` 均未改变；改动只涉及仪表盘和 API 读取。Telegram 和 Lark 消息不变。
