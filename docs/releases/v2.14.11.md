# Looper v2.14.11

This is the patch release v2.14.11. It ships the one change merged since v2.14.10: [#887](https://github.com/foolzzz/looper/pull/887), which validates every DSH role on the SDK runner and adds a `--dsh-runner` opt-in to the eval and the DSH validation launcher. It changes no code under `looper/`.

## Release Decision

**Who should upgrade:** Maintainers and operators who validate the DSH runner (`[runtimes] dsh = "runner"`) with the prompt-regression eval or `examples/dsh/validate.py` from a source checkout. Nobody else needs this release: the installed `looper` package behaves as in v2.14.10. It ships the one change merged since v2.14.10.

**What this release solves:** [#887](https://github.com/foolzzz/looper/pull/887): the DSH runner had no end-to-end validation for every role, and the eval and the DSH validation launcher could only check the DSH CLI. Now a new test runs every role on an isolated serve, and `--dsh-runner` lets the eval and the launcher produce runner evidence.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#887](https://github.com/foolzzz/looper/pull/887); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.11
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.10 upgrades directly. This release changes no schema, stored data or setting.

## Behavior changes

No file under `looper/` changed, so the installed runtime behaves as in v2.14.10. The changes are in the eval, the validation launcher, tests and docs, which a source checkout uses.

- **`--dsh-runner` on the eval:** `evals.prompt_regression run` and `dialogs` accept it and pass `dsh_runtime="runner"` to the server they start (`running_server` writes it to the ops file). Without it the value is `cli`, as before.
- **Runner evidence in eval rows:** the runtime evidence of a task or dialog row now carries `runner_kind` when the record's command is a `looper-runner` descriptor (`None` if the descriptor does not parse). Only the kind is exported, not the descriptor's private arguments.
- **`examples/dsh/validate.py --dsh-runner`:** accepted by `task-basic`, `task-review`, `manager` and `smoke`. The evidence checks require the `looper-runner` executable and `runner_kind` `dsh` instead of the `dsh` executable. Eval commands also report `server_log_key_absent`, scanning the run's server logs for the key in memory, and the command passes only when it is `True`. The smoke reports `path: "runner"`, reads each record's cost from the record, requires complete usage on each result, checks the runner descriptor, and requires a consult fork to be a read-only worker forked from the source session with a session of its own (the CLI path still requires the source session). Without the flag the checks are unchanged.
- **Tests and docs:** new `tests/test_dsh_runner_serve_db.py` (a Manager dialog with a platform tool and audit row; stop mid-request and runner kill with a resumed owner session; one task with Planner, two Workers, a Reviewer and a read-only consult fork; budget denial, cancel and kill on Worker runs), a `dsh` option in `tests/runner_support.py`, and extended `tests/test_dsh_validation.py` and `tests/test_prompt_eval.py`. The architecture doc, the runner RFC, the eval README and the plan are updated.
- **Model-visible changes:** None. Prompts, tools and model requests are unchanged.

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.10 上的安装可直接升级。本版本不改 schema、已存数据或设置。

### 行为变化与入口

`looper/` 下没有文件改动，已安装的运行时行为与 v2.14.10 相同。改动位于 eval、验证启动器、测试和文档，仅源码检出会用到。

- **eval 的 `--dsh-runner`：**`evals.prompt_regression run` 和 `dialogs` 接受该开关，并向其启动的服务传入 `dsh_runtime="runner"`（`running_server` 写入 ops 文件）。不加时仍为 `cli`。
- **eval 行中的 runner 证据：**当记录的命令是 `looper-runner` 描述符时，任务或对话行的运行时证据现在带有 `runner_kind`（描述符无法解析时为 `None`）。只导出类型，不导出描述符的私有参数。
- **`examples/dsh/validate.py --dsh-runner`：**`task-basic`、`task-review`、`manager` 和 `smoke` 接受。证据检查要求可执行文件为 `looper-runner` 且 `runner_kind` 为 `dsh`，而不是 `dsh`。eval 命令还会报告 `server_log_key_absent`（在内存中扫描本次运行的服务日志是否含密钥），仅当其为 `True` 时命令才通过。smoke 报告 `path: "runner"`，从记录读取每次成本，要求每个 result 的用量完整，校验 runner 描述符，并要求 consult 分叉是从源会话分叉出的只读 worker 且有自己的会话（CLI 路径仍要求使用源会话）。不加该开关时检查不变。
- **测试与文档：**新增 `tests/test_dsh_runner_serve_db.py`（带平台工具和审计行的 Manager 对话；请求中途停止和 runner 被杀后恢复 owner 会话；含 Planner、两个 Worker、Reviewer 和只读 consult 分叉的一个任务；Worker 运行上的预算拒绝、取消和被杀），在 `tests/runner_support.py` 增加 `dsh` 选项，并扩展 `tests/test_dsh_validation.py` 和 `tests/test_prompt_eval.py`。架构文档、runner RFC、eval README 和计划已更新。
- **面向模型的变化：**无。提示、工具和模型请求都不变。
