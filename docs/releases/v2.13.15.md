# Looper v2.13.15

## Release Decision

**Who should upgrade:** Operators who chat with the Manager in the dashboard, Telegram or Lark and want to type while it replies, recall earlier messages, or stop a reply. Everyone else sees no change.

**What this release solves:** [#292](https://github.com/foolzzz/looper/pull/292) lets the Manager chat box keep working while a reply runs. Messages sent during a reply wait in a staging area and go as one message when the reply ends; ↑ and ↓ recall them and this thread's last 100 messages. Stopping a reply (Esc, a Stop button, `/stop`) is included but experimental and **off by default** behind the system setting `chat.stop_enabled`.

**Breaking changes:** No. No CLI command, configuration key or database schema changed. The new HTTP routes are additions, and `answer.final` events gain an `outcome` field.

**How to verify:** Check the installed version, then send two messages while the Manager is replying.

**Contributors:** Maintainer @foolzzz authored [#292](https://github.com/foolzzz/looper/pull/292); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.15
```

## Behavior changes

- **Queue.** In the Manager chat, Enter during a reply puts the message in a staging area above the box. If the reply ends as `answered`, the staged messages go as one message joined by a blank line; otherwise they return to the box. They survive a reload of the page. The Planner's chat has the staging area and the history but no Stop.
- **History.** ↑ pulls staged messages back into the box, then ↑/↓ walk this thread's last 100 messages.
- **Stop (off by default).** Setting `chat.stop_enabled` (Settings → Chat, experimental; `GET`/`PUT /api/chat-settings`) turns it on. While it is off, `POST /api/chat/stop` answers `409` with `{"state": "disabled"}`, the box has no Stop button, Esc never stops, `/stop` is answered "停止功能暂未开放" without reaching the model, and Telegram's command menu leaves `/stop` out. While it is on, Esc or the Stop button stops the reply, and `GET /api/chat/turn` tells a reloaded page whether a reply is running.
- **`/stop`.** A message that is exactly `/stop` stops the Manager's turn for that chat from the web chat, Telegram (a new command) and Lark. It is answered by Looper outside the Manager's queue, so it does not wait for the turn it stops.
- **How a turn is stopped.** Claude Code is interrupted with a control request and killed if it has not ended within 5 seconds. Grok is interrupted with `session/cancel`. Codex, OMP, Pi and DSH are stopped by ending the turn's process tree; a stopped Codex turn records no usage. The session is kept.
- **Record.** A stopped turn is recorded `interrupted` with the text and usage so far. A confirmation it had asked for is dropped. `answer.final` carries the reply's `outcome`.
- **Model-visible changes:** After a stopped reply, the next user turn gets one `[Looper]` line saying the user stopped the previous reply (with its first line quoted) and that its tool calls were not undone. Only with `chat.stop_enabled` on can a reply be stopped, so otherwise no model-visible change. No tool schema or tool contract changed.

## Entry points

- `POST /api/chat/stop`, `GET /api/chat/turn`, `GET`/`PUT /api/chat-settings`, `/stop` on the web chat, Telegram and Lark, and Esc or the Stop button in the Manager chat.

## Upgrade and rollback

Re-run `install.sh` once v2.13.15 is published. There is no schema or configuration change; the setting is stored as a system setting and is off until set. Rolling back to v2.13.14 is safe: the stored `chat.stop_enabled` is ignored.

## Optional Capability Activation & Use

### Stopping a Manager reply

**Activation:** Off by default. In Settings → Chat turn on the experimental stop, or `PUT /api/chat-settings` with `{"stop_enabled": true}` (`null` returns to the default, off).

```bash
curl -s -X PUT "$LOOPER_URL"/api/chat-settings -d '{"stop_enabled": true}'
```

**Validation:** `GET /api/chat-settings` shows `stop_enabled` true. While the Manager replies, `POST /api/chat/stop` answers a state other than `disabled`, `GET /api/chat/turn` shows the turn running, and the reply is recorded `interrupted`.

**Disable / rollback:** `PUT /api/chat-settings` with `{"stop_enabled": false}`. The Stop button and Esc go away, `/stop` is answered "停止功能暂未开放", and `POST /api/chat/stop` answers `409`. The queue and the history do not depend on the setting.

**Authority boundary:** Stopping ends only the Manager's running turn for that chat, from the dashboard or an allowlisted channel sender. Tool calls it already made are not undone, and a confirmation it had asked for is dropped. No new secret is stored.

**Docs:** [Agent system](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md), [chat composer RFC](https://github.com/foolzzz/looper/blob/main/docs/architecture/rfcs/chat-composer-v0.zh-CN.md).

### 行为变化与入口

- 队列：管家聊天中，回复期间按 Enter 把消息放进输入框上方的暂存区；回复以 `answered` 结束时，暂存消息用空行连成一条发送，否则退回输入框。刷新页面后仍保留。规划者的聊天有暂存和历史，没有 Stop。
- 历史：↑ 把暂存消息取回输入框，之后 ↑/↓ 浏览当前会话最近 100 条消息。
- 停止（默认关闭）：设置 `chat.stop_enabled`（Settings → Chat，实验功能；`GET`/`PUT /api/chat-settings`）开启。关闭时，`POST /api/chat/stop` 返回 `409` 和 `{"state": "disabled"}`，输入框没有 Stop 按钮，Esc 不停止，`/stop` 被回复“停止功能暂未开放”且不到达模型，Telegram 命令菜单不含 `/stop`。开启后，Esc 或 Stop 按钮停止回复，`GET /api/chat/turn` 告诉刷新后的页面是否有回复在跑。
- `/stop`：消息恰为 `/stop` 时，停止管家对该聊天的当前一轮，支持 web 聊天、Telegram（新命令）和 Lark；由 Looper 在管家队列之外回复，不必等被停的那一轮结束。
- 停止方式：Claude Code 用控制请求中断，5 秒内未结束则杀进程；Grok 用 `session/cancel`；Codex、OMP、Pi、DSH 结束该轮的进程树（被停的 Codex 轮不记录用量）。会话保留。
- 记录：被停的一轮记为 `interrupted`，保留已输出的文字和用量；它已请求的确认作废。`answer.final` 带有回复的 `outcome`。
- 面向模型的变化：回复被停止后，下一轮用户消息会收到一行 `[Looper]`，说明用户停止了上一次回复（引用其首行）且工具调用不会撤销。只有开启 `chat.stop_enabled` 才能停止回复，因此否则无面向模型的变化。工具 schema、工具契约没有变化。
- 入口：`POST /api/chat/stop`、`GET /api/chat/turn`、`GET`/`PUT /api/chat-settings`、web 聊天、Telegram、Lark 的 `/stop`，以及管家聊天中的 Esc 或 Stop 按钮。

### 可选能力启用与使用

#### Stopping a Manager reply

**启用：**默认关闭。在 Settings → Chat 打开实验性的停止功能，或 `PUT /api/chat-settings` 传 `{"stop_enabled": true}`（`null` 恢复默认，即关闭）。

```bash
curl -s -X PUT "$LOOPER_URL"/api/chat-settings -d '{"stop_enabled": true}'
```

**验证：**`GET /api/chat-settings` 显示 `stop_enabled` 为 true；管家回复期间 `POST /api/chat/stop` 返回非 `disabled` 的状态，`GET /api/chat/turn` 显示回复在跑，该回复记为 `interrupted`。

**停用 / 回退：**`PUT /api/chat-settings` 传 `{"stop_enabled": false}`。Stop 按钮和 Esc 消失，`/stop` 被回复“停止功能暂未开放”，`POST /api/chat/stop` 返回 `409`。队列和历史不依赖该设置。

**权限边界：**停止只结束管家对该聊天正在运行的一轮，来自 dashboard 或名单内的渠道发送者。已执行的工具调用不会撤销，它已请求的确认作废。不存储新的密钥。
