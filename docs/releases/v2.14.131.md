# Looper v2.14.131

This is the patch release v2.14.131, a hotfix line in which each merged change ships at once. It documents one change: [#1220](https://github.com/foolzzz/looper/pull/1220) (the Planner's `looper_task_profile_set` refuses a profile choice that a task role or the task's own choice would still override).

## Release Decision

**Who should upgrade:** Operators whose Planners choose Agent Profiles with `looper_task_profile_set` and who use task roles or a per-task profile choice. Everyone else gets no change.

**What this release solves:** [#1220](https://github.com/foolzzz/looper/pull/1220) stops the tool from reporting a change that does not apply. When a task role or the task's own choice would still win, the call is refused, nothing is written, and the refusal names the winning layer and profile.

**Breaking changes:** No. There is no migration and no API removal; a call that used to be accepted as a no-op is now refused. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.131
```

**Contributors:** Maintainer @foolzzz authored [#1220](https://github.com/foolzzz/looper/pull/1220); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.130 upgrades directly. There is no schema change.

## Behavior changes

- **`looper_task_profile_set` refuses an overridden choice** ([#1220](https://github.com/foolzzz/looper/pull/1220)). After the profile is validated against the project's allowed list, the tool resolves the profile the role's next run would get with the Planner's choice applied (or removed, for `profile_id: null`). For a step, it does this for the step and for each task role of the same agent kind in its chain, including each role of a work step's review chain. If the winning layer is `task_role` or `task`, the call fails with `forbidden`, names the layer and the profile, and says nothing changed. No choice is stored and no `profile_choice` journal entry or activity line is written. Before, a task role's pin was accepted as a no-op, and only the user's per-task choice was refused.
- **Refusal order.** The per-task refusal now comes after the checks of the profile and the step, so a profile that is not allowed or a step that is unknown is reported first.
- **`next_run` of an accepted choice** comes from the same resolution used for the check, made before the write.
- **Unchanged:** precedence between layers, accepted choices, the other Planner tools, and the dashboard.
- **Model-visible changes:** Yes. The `looper_task_profile_set` tool description changes: it says the call is refused when the task or a task role pins the profile and to ask through a user gate or have the operator change the profile in the dashboard (task → Roles), and that `next_run` gives the resolved profile. The matching paragraph of the Planner prompt changes in the same way, and the architecture document row for the tool is updated. No Worker, Reviewer or Manager prompt or contract text and no run `AGENTS.md` text changes.

## 中文摘要

本版本是 patch release v2.14.131（热修线，每个合并的改动立即发布），只说明一项改动：[#1220](https://github.com/foolzzz/looper/pull/1220)（Planner 的 `looper_task_profile_set` 会拒绝仍被任务角色或任务自身选择覆盖的 Profile 选择）。

### 升级决策

**谁需要升级：**让 Planner 用 `looper_task_profile_set` 选择 Agent Profile，并使用任务角色或按任务指定 Profile 的运维者。其他人无变化。

**解决了什么：**[#1220](https://github.com/foolzzz/looper/pull/1220) 让该工具不再报告并未生效的改动。任务角色或任务自身的选择仍会胜出时，调用被拒绝、不写入任何内容，并指出胜出的层和 Profile。

**是否有破坏性变更：**否。没有迁移，没有移除 API；此前被当作空操作接受的调用现在被拒绝。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.14.131。

**贡献者：**维护者 @foolzzz 提交 [#1220](https://github.com/foolzzz/looper/pull/1220)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.131
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.130 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **`looper_task_profile_set` 拒绝被覆盖的选择**（[#1220](https://github.com/foolzzz/looper/pull/1220)）。在按项目允许列表验证 Profile 之后，工具会解析应用（或移除，`profile_id: null` 时）Planner 选择后该角色下次运行得到的 Profile。对步骤，则对该步骤以及其链中每个同类 Agent 的任务角色都解析一遍，包括工作步骤评审链中的每个角色。若胜出的层是 `task_role` 或 `task`，调用以 `forbidden` 失败，指出层和 Profile，并说明未改动；不存储选择，也不写 `profile_choice` 日志条目或活动行。此前任务角色的固定会被当作空操作接受，只有用户按任务的选择会被拒绝。
- **拒绝顺序。**按任务的拒绝现在排在 Profile 和步骤检查之后，因此不被允许的 Profile 或未知步骤会先被报告。
- **被接受的选择返回的 `next_run`** 来自检查所用的同一次解析，在写入之前完成。
- **不变：**各层之间的优先级、被接受的选择、其他 Planner 工具和仪表盘。
- **面向模型的变化：**有。`looper_task_profile_set` 的工具描述改变：说明任务或任务角色固定了 Profile 时调用被拒绝，应通过用户闸门询问或让运维者在仪表盘（task → Roles）更改，且 `next_run` 给出解析后的 Profile。Planner 提示词中对应的一段同样改变，架构文档中该工具的一行也已更新。Worker、Reviewer 和 Manager 的提示词与契约文本以及运行的 `AGENTS.md` 文本无变化。
