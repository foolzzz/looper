# Looper v2.15.10

This is the patch release v2.15.10, a hotfix line in which each merged change ships at once. It documents one change: [#1391](https://github.com/foolzzz/looper/pull/1391) (a failed Claude Code turn keeps the reason in its error message).

## Release Decision

**Who should upgrade:** Anyone who runs Claude Code as a runtime and wants the reason behind a failed turn (an expired login, a usage limit, an API error) in the error and the operator reply, instead of a bare "did not succeed (success)".

**What this release solves:** [#1391](https://github.com/foolzzz/looper/pull/1391) makes the Claude Code runtime report the reason text of an error result. Before, an error result whose subtype was `success` produced only `Claude Code turn did not succeed (success)`, which hid the cause.

**Breaking changes:** No. The CLI, the API and the dashboard are unchanged, no new command or control is added and there is no PostgreSQL schema change. Only the text of a recorded error changes (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.10
```

**Contributors:** Maintainer @foolzzz authored [#1391](https://github.com/foolzzz/looper/pull/1391); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.9 upgrades directly. There is no PostgreSQL schema change. Restart the service after upgrading, as for every release.

## Behavior changes

Read in the diff of the PR (3 files: `looper/agents/runtimes/claude_code.py`, `looper/agents/tiers/worker.py`, `tests/test_claude_failure_detail.py`).

### #1391: Claude Code failures keep their reason

- **New `failure_detail` for Claude Code.** `ClaudeCodeRuntime.failure_detail` returns nothing for a missing result or a successful one (`is_error` false and subtype `success`). For an error result it takes the result's `result` text and, when the event has a `status_code` (or `status`) between 100 and 599, prefixes `HTTP <status>`. The text is redacted (`Bearer` tokens, `sk-` keys, `api_key`/`access_token`/`secret` assignments, `Authorization` values and the profile's own API key become `[redacted]`) before whitespace is collapsed and the text is cut to 300 characters. Redacting first means a cut credential is never shown. Empty text gives nothing, and the old wording is kept.
- **Message wording.** The Planner and Manager already build `<label> turn did not succeed: <detail>` (capped at 500 characters) when a detail exists; they now get one for Claude Code. The Worker and reviewer path (`judge_result`) gains a `runtime_type` argument and says `Claude Code turn did not succeed: <detail>` for Claude Code. Other runtimes keep `<label> run did not succeed: <detail>` and its 500-character bound (pinned by a test). Without a detail, the message is unchanged: `... did not succeed (<subtype>)`.
- **Where it shows.** The recorded run error, the Planner's "Planning failed: ..." summary, the Manager's reply to the operator, and the Worker's or reviewer's outcome summary and error.
- **Tests.** `tests/test_claude_failure_detail.py` drives a fake Claude executable through the Planner, Manager, Worker and reviewer paths and pins the reason, redaction, whitespace handling, the 300-character cut, the empty-reason fallback, the HTTP status prefix and the unchanged wording for another runtime.
- **Behavior change.** Error text of failed Claude Code turns carries the reason; nothing else about success, failure classification, retries or budgets changes.

### Model-visible changes

No prompt, prompt contract or tool schema changes. The one model-visible effect is indirect: the failure text of a Claude Code turn now carries its reason, and that text is placed in the Planner's failure summary, the Worker or reviewer outcome and the Manager's operator reply, so an agent or an operator that reads these sees the reason. The text is redacted and cut to 300 characters (500 with the prefix).

### 行为变化与入口

以下在该 PR 的差异中可见（3 个文件：`looper/agents/runtimes/claude_code.py`、`looper/agents/tiers/worker.py`、`tests/test_claude_failure_detail.py`）。

**#1391：Claude Code 失败保留原因**

- **Claude Code 新增 `failure_detail`。**结果缺失或成功（`is_error` 为假且子类型为 `success`）时不返回内容；错误结果则取 `result` 文本，若事件带有 100 到 599 之间的 `status_code`（或 `status`），前缀 `HTTP <状态码>`。文本先脱敏（`Bearer` 令牌、`sk-` 密钥、`api_key`/`access_token`/`secret` 赋值、`Authorization` 值以及配置档自己的 API key 都变为 `[redacted]`），再折叠空白并截断到 300 个字符。先脱敏再截断，所以被截断的凭据不会显示。文本为空则不返回内容，沿用旧措辞。
- **消息措辞。**Planner 和 Manager 在有详情时本来就生成 `<label> turn did not succeed: <detail>`（上限 500 字符），现在 Claude Code 也会有详情。Worker 与评审路径（`judge_result`）新增 `runtime_type` 参数，对 Claude Code 写 `Claude Code turn did not succeed: <detail>`。其他运行时保持 `<label> run did not succeed: <detail>` 及 500 字符上限（有测试固定）。没有详情时消息不变：`... did not succeed (<subtype>)`。
- **出现位置。**记录的运行错误、Planner 的“Planning failed: ...”摘要、Manager 给操作员的回复，以及 Worker 或评审的结果摘要和错误。
- **测试。**`tests/test_claude_failure_detail.py` 用假的 Claude 可执行文件走通 Planner、Manager、Worker 和评审路径，固定原因、脱敏、空白处理、300 字符截断、空原因回退、HTTP 状态前缀，以及其他运行时措辞不变。
- **行为变化。**失败的 Claude Code 回合的错误文本带有原因；成功、失败判定、重试和预算均不变。

**面向模型的变化：**提示词、提示词契约和工具 schema 均无改动。唯一的面向模型影响是间接的：Claude Code 回合的失败文本现在带有原因，并出现在 Planner 的失败摘要、Worker 或评审的结果和 Manager 对操作员的回复中，读取这些内容的智能体或操作员会看到原因。文本已脱敏并截断到 300 个字符（加前缀后上限 500）。
