# Looper v2.14.44

This is the patch release v2.14.44, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.43: the Planner keeps the reason of a failed Worker or Reviewer run ([#996](https://github.com/foolzzz/looper/pull/996)).

## Release Decision

**Who should upgrade:** Anyone who runs goals with a Planner, in particular when a Worker or Reviewer run fails with a long error (for example a long TTADK stderr whose last line carries the sign-in or mixed-mode text), or when a Reviewer run ends without a verdict.

**What this release solves:** [#996](https://github.com/foolzzz/looper/pull/996) makes the Planner keep the end of a failed run's text wherever it clips it: the step activity, the work report, the review report and the closing-note outcome line. Before, a long error lost its final line. A Reviewer run that exited non-zero, timed out or raised reached the Planner as "passed: no" with "no reason given"; the verify path now reads the run's `error` when the run has no summary. Native and TTADK runs are both affected.

**Breaking changes:** No. No API or configuration is removed, and there is no new migration or setting.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#996](https://github.com/foolzzz/looper/pull/996); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.44
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.43 upgrades directly. This release adds no migration and no new setting.

## Behavior changes

- **Clipping keeps both ends ([#996](https://github.com/foolzzz/looper/pull/996)).** A new helper `_clip_ends` keeps the first third of the limit and the last two thirds of a flattened text, joined by `…`, instead of cutting the end. It applies only to failed runs: the Worker's step activity line (200 characters), the Reviewer's step activity line (200, was 150) and the role review activity line (200, was 150) when the review did not pass, the closing-note outcome line of a run that did not complete (400), the reason of a failed review (its findings at 200 each, else its summary at 300), the Worker report's summary when the status is `failed` (1000) and its `error` line (500), and the review report's summary when the review did not pass (1000). Passed or completed text is clipped from the end as before.
- **Reviewer run without a verdict.** When a Reviewer run returns no summary, the verify path now uses its `error` as the summary, for the step result (`verify_summary`), for a role review and for the activity line. The review report also gets a line "review run failed: <error>" when the result has no summary but has an `error`, so the Planner no longer sees only "passed: no" and "no reason given".
- **Unchanged.** The VERIFY_RESULT message and the Worker are unchanged. No API, schema or setting changes.
- **Model-visible changes:** Yes. The Planner reads the work report, the review report and the closing-note outcome lines in its prompts, and they now keep the end of a failed run's text (the first third and the last two thirds of the limit, joined by `…`), and the review report can carry a "review run failed: <error>" line. The PR touches no tool description or tool schema.

### 升级决策

**谁需要升级：**使用带 Planner 的目标的人，尤其是 Worker 或 Reviewer 运行以很长的错误失败（例如 TTADK 的长 stderr，最后一行才是登录或混合模式提示），或 Reviewer 运行结束时没有结论的人。

**解决了什么：**[#996](https://github.com/foolzzz/looper/pull/996) 让 Planner 在所有截断处保留失败运行文字的结尾：步骤活动、工作报告、评审报告和收尾说明的结果行。此前长错误会丢掉最后一行；Reviewer 运行以非零退出、超时或抛出异常时，Planner 只看到“passed: no”和“no reason given”。现在验证路径在运行没有 summary 时读取其 `error`。原生与 TTADK 运行都受影响。

**是否有破坏性变更：**否。不移除任何 API 或配置，也没有新的迁移或设置。

**如何验证：**运行 `looper --version` 核对版本为 2.14.44。

**贡献者：**维护者 @foolzzz 提交 [#996](https://github.com/foolzzz/looper/pull/996)；本版本无社区贡献。


### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.43 上的安装可直接升级。本版本没有新迁移，也没有新设置。

### 行为变化与入口

- **截断同时保留首尾（[#996](https://github.com/foolzzz/looper/pull/996)）。**新增 `_clip_ends`：保留上限的前三分之一和后三分之二（压平空白后），中间用 `…` 连接，而不是截掉结尾。只用于失败的运行：Worker 步骤活动行（200 字符）；评审未通过时的 Reviewer 步骤活动行与角色评审活动行（200，原为 150）；未完成运行的收尾说明结果行（400）；评审失败原因（每条 findings 200，否则 summary 300）；状态为 `failed` 时 Worker 报告的 summary（1000）及其 `error` 行（500）；评审未通过时评审报告的 summary（1000）。通过或完成的文字仍从结尾截断。
- **没有结论的 Reviewer 运行。**Reviewer 运行没有 summary 时，验证路径改用其 `error` 作为 summary，用于步骤结果（`verify_summary`）、角色评审和活动行。评审报告在结果没有 summary 但有 `error` 时，增加一行“review run failed: <error>”，Planner 不再只看到“passed: no”和“no reason given”。
- **不变。**VERIFY_RESULT 消息和 Worker 不变。没有 API、schema 或设置变化。
- **面向模型的变化：**有。Planner 在提示词中读取工作报告、评审报告和收尾说明的结果行，这些文字现在保留失败运行的结尾（上限的前三分之一与后三分之二，以 `…` 连接），评审报告还可能带一行“review run failed: <error>”。该 PR 没有改动工具描述或工具 schema。
