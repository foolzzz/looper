# Looper v2.14.176

This is the patch release v2.14.176, a hotfix line in which each merged change ships at once. It documents one change: [#1326](https://github.com/foolzzz/looper/pull/1326) (two maintainer decisions recorded in the plan; docs only).

## Release Decision

**Who should upgrade:** No one needs to upgrade for this release. It changes a plan document only; the installed software behaves as in v2.14.175.

**What this release solves:** [#1326](https://github.com/foolzzz/looper/pull/1326) records two maintainer decisions in the long-horizon plan. It does not change code.

**Breaking changes:** No. There is no API, schema or behavior change. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.176
```

**Contributors:** Maintainer @foolzzz authored [#1326](https://github.com/foolzzz/looper/pull/1326); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.175 upgrades directly. There is no database change.

## Behavior changes

Read in the diff of [#1326](https://github.com/foolzzz/looper/pull/1326), which touches one file, the Chinese long-horizon plan (`docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`):

- **No behavior change.** Only plan text changed.
- **Plan entry: request recording for more runtimes.** A new non-core todo for the Codex, OMP, Pi and DSH runtimes (CLI and runner), which are not covered by model request recording and show `not_covered` today. Recording them needs a local gateway or request proxy per runtime. The maintainer decided on 2026-11-12 to list it as a non-core todo, moved from #1144.
- **Plan entry: keeper default-on.** The todo now also closes #1067 and names its checks before the default turns on: keeper runs surviving a restart under Linux systemd, and a real PostgreSQL cluster restart, run at least once on Linux systemd. The default stays `off` until then.
- **Model-visible changes:** None. Prompts, tool schemas and `channel_context` are unchanged.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 行为变化与入口

以下在 [#1326](https://github.com/foolzzz/looper/pull/1326) 的差异中可见，它只改动一个文件，即中文长程计划（`docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`）：
