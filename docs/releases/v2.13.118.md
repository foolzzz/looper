# Looper v2.13.118

## Release Decision

**Who should upgrade:** Anyone who uses the dashboard Gates page and has seen it stay on "Cannot load gates" after Retry because its saved pagination boundary expired. Others do not need it.

**What this release solves:** [#626](https://github.com/foolzzz/looper/pull/626) makes the Retry button on the Gates page request the list without the saved pagination boundary, so a page that failed because that boundary expired recovers, while a failed Retry keeps the saved boundary and the rows already shown.

**Breaking changes:** No. No route, configuration, request field or stored data format changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#626](https://github.com/foolzzz/looper/pull/626); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.118
```

## Behavior changes

- **Retry on the Gates page:** in `web/src/pages/gates.tsx`, the Retry button in the load-error alert now reads in a new `retry` mode. That mode omits the saved pagination boundary and asks for the first page, where a refresh asked for rows through the saved boundary. The saved boundary is replaced only when the request succeeds; a failed Retry leaves it, and the rows shown, unchanged.
- **Older refreshes:** a refresh that was started before a Retry and finishes after it, whether it succeeds or fails, is ignored (the existing sequence check now covers the Retry request).
- **Open answer editor:** the rows and the id of the gate being answered now live in one state value. When a recovered page does not contain the gate whose answer editor is open, that row is kept in the list so the draft stays mounted until pagination reaches it again.
- **Merging pages:** when a further page is appended, rows with the same key as an incoming row are replaced by the incoming one, so a gate cannot appear twice.
- **Model-visible changes:** none. This is a dashboard change; no tool declaration, prompt, route or text sent to Workers changed.
- **Tests:** new tests in `web/src/pages/gates.test.tsx` (Retry resets pagination and ignores an older refresh, on success and on failure) and `tests/test_gate_pagination_browser.py` (a failed Retry retains the saved boundary; Retry replaces an expired boundary and ignores an older refresh; a draft row survives an inconsistent snapshot until Retry). [#626](https://github.com/foolzzz/looper/pull/626) reports added lines: tests 72, production 64 (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.118 is published. No data migration and no configuration change. Rolling back to v2.13.117 restores the old behavior, where Retry reused the saved pagination boundary.

### 升级决策

**谁需要升级：**使用仪表盘 Gates 页面，且因已保存的分页边界过期而在点击 Retry 后仍显示“Cannot load gates”的用户。其他人无需升级。

**解决了什么：**[#626](https://github.com/foolzzz/looper/pull/626) 让 Gates 页面的 Retry 按钮不带已保存的分页边界去请求列表，因此因该边界过期而失败的页面可以恢复；Retry 失败时则保留原边界和已显示的行。

**是否有破坏性变更：**否。路由、配置、请求字段和存储数据格式均未改变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.118。

**贡献者：**维护者 @foolzzz 提交 [#626](https://github.com/foolzzz/looper/pull/626)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.118
```

### 行为变化与入口

- **Gates 页面的 Retry：**`web/src/pages/gates.tsx` 中，加载错误提示里的 Retry 按钮现在以新的 `retry` 模式读取：不带已保存的分页边界，请求第一页；而普通刷新会请求到已保存边界为止的行。只有请求成功才替换已保存的边界；Retry 失败则边界和已显示的行保持不变。
- **较早的刷新：**在 Retry 之前发起、在 Retry 之后结束的刷新，无论成功或失败都会被忽略（已有的序号检查现在也覆盖 Retry 请求）。
- **打开的回答编辑器：**行列表与正在回答的 gate id 现在放在同一个状态值中。当恢复后的页面不含正在打开回答编辑器的 gate 时，该行会保留在列表里，草稿保持挂载，直到分页再次到达它。
- **合并分页：**追加下一页时，与新到行同 key 的旧行会被新行替换，因此同一个 gate 不会出现两次。
- **面向模型的变化：**无。这是仪表盘改动；tool 声明、提示词、路由和发给 Worker 的文本均未改变。
- **测试：**`web/src/pages/gates.test.tsx` 新增测试（Retry 重置分页并忽略较早的刷新，成功与失败两种情形）；`tests/test_gate_pagination_browser.py` 新增测试（Retry 失败保留已保存边界；Retry 替换过期边界并忽略较早的刷新；快照不一致时草稿行保留到 Retry）。[#626](https://github.com/foolzzz/looper/pull/626) 报告新增行数：测试 72、生产代码 64（不含夹具）。
