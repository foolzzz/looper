# Looper v2.13.186

## Release Decision

**Who should upgrade:** Maintainers and CI that run Looper's scheduled "Installed runtime tests" browser suite. It is a hotfix that ships the changes merged since v2.13.185.

**What this release solves:** [#806](https://github.com/foolzzz/looper/pull/806) makes the nightly installed browser tests pass again after they failed on 10-25, 10-26 and 10-27: the browser tests serve the dashboard that was staged once before pytest instead of rebuilding `web/dist` in each test, and two flaky timing waits and a missing Runtime selection are fixed.

**Breaking changes:** No. No command, schema or file format changed; only tests and the shared test fixture changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#806](https://github.com/foolzzz/looper/pull/806); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.186
```

## Behavior changes

- **Staged dashboard fixture ([#806](https://github.com/foolzzz/looper/pull/806)):** `tests/conftest.py` adds a session-scoped `staged_dashboard_dir` fixture that returns `looper/web/dashboard` and asserts its `index.html` exists, with the message "Run scripts/stage-dashboard.sh before browser tests". It never rebuilds the dashboard.
- **Tests use it:** `test_catalog_manager_usage_browser.py`, `test_chat_navigation_browser.py`, `test_configuration_download_browser.py`, `test_gate_pagination_browser.py`, `test_task_activity_restart_browser.py` and `test_llm_models_dashboard.py` (which now also requires the fixture) serve that directory. The first four no longer run `npm run build` or read `web/dist`.
- **Browser HOME isolation:** in `test_task_activity_restart_browser.py` the browser is launched with `HOME` set in its `env` argument and a 15 s launch timeout, instead of monkeypatching `HOME` and passing `chromium.executable_path` (which names the full browser, not the headless shell).
- **Restart tests wait on the response:** the two restart tests wait for the first `/api/v1/tasks/detail` response after the click and drop the fixed 300 ms sleep. In the refused case the Start click now happens only inside that branch.
- **Runtime selection:** the complete dashboard configuration flow in `test_llm_models_dashboard.py` selects the `rt-claude-code` Runtime when it creates the nested Agent Profile.
- **Scope:** seven files under `tests/` changed (36 lines added, 36 removed). The `looper` package, the host, the runners, the eval harness, `scripts/stage-dashboard.sh` and the workflows are unchanged.
- **Model-visible changes:** None. No prompts, tool descriptions, tool schemas or tool results changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.186 is published. There is no schema change, so rolling back to v2.13.185 needs nothing else.

### 行为变化与入口

- **暂存 dashboard 夹具（#806）：**`tests/conftest.py` 新增 session 级 `staged_dashboard_dir` 夹具，返回 `looper/web/dashboard` 并断言 `index.html` 存在，提示“Run scripts/stage-dashboard.sh before browser tests”；它从不重建 dashboard。
- **使用该夹具的测试：**`test_catalog_manager_usage_browser.py`、`test_chat_navigation_browser.py`、`test_configuration_download_browser.py`、`test_gate_pagination_browser.py`、`test_task_activity_restart_browser.py` 以及 `test_llm_models_dashboard.py`（现在也依赖该夹具）都从该目录提供页面。前四个不再运行 `npm run build`，也不再读取 `web/dist`。
- **浏览器 HOME 隔离：**`test_task_activity_restart_browser.py` 通过启动参数 `env` 设置 `HOME` 并使用 15 秒启动超时，不再 monkeypatch `HOME` 和传入 `chromium.executable_path`（该路径指向完整浏览器而非 headless shell）。
- **重启测试等待响应：**两个重启测试改为等待点击后第一个 `/api/v1/tasks/detail` 响应，并去掉固定 300 毫秒等待；被拒绝的场景中，Start 点击只在该分支内发生。
- **Runtime 选择：**`test_llm_models_dashboard.py` 的完整 dashboard 配置流程在创建嵌套 Agent Profile 时选择 `rt-claude-code` Runtime。
- **范围：**`tests/` 下 7 个文件改动（新增 36 行、删除 36 行）。`looper` 包、宿主、runner、评测工具、`scripts/stage-dashboard.sh` 和 workflow 均未改变。
- **面向模型的变化：**无。提示词、工具描述、工具 schema 和工具结果均无变化。
