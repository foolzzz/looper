# Looper v2.14.183

This is the patch release v2.14.183, a hotfix line in which each merged change ships at once. It documents one change: [#1343](https://github.com/foolzzz/looper/pull/1343) (time zone names are checked from directory listings, not by opening every zone file). The change was merged before v2.14.182 was tagged, so the v2.14.182 tag already contains its code, but the v2.14.182 notes do not list it; this release documents it.

## Release Decision

**Who should upgrade:** Operators who run `looper serve` on a loaded machine, where startup could block the event loop for minutes while the scheduler checked time zone names.

**What this release solves:** [#1343](https://github.com/foolzzz/looper/pull/1343) removes a startup stall: the loop watchdog had logged a 142 s stall in `Scheduler.__init__` → `cron.local_zone_name()` → `cron.zone()` → `zoneinfo.available_timezones()`, which opens each of the roughly 600 zone files. Zone names now come from directory listings only.

**Breaking changes:** No. API responses, the Telegram and Lark channel protocols, the dashboard and the CLI are unchanged, and there is no database change. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.183
```

**Contributors:** Maintainer @foolzzz authored [#1343](https://github.com/foolzzz/looper/pull/1343); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.182 upgrades directly. There is no database change.

## Behavior changes

Read in the diff of [#1343](https://github.com/foolzzz/looper/pull/1343) (`looper/agents/cron.py` and tests). The PR description states no behavior change besides speed.

- **Zone name check** (`looper/agents/cron.py`). `_known_zones` no longer calls `zoneinfo.available_timezones()`. It walks the directories in `zoneinfo.TZPATH`, taking file names only, and adds the zone list of the `tzdata` package when that package is installed (a missing package or an unreadable list is ignored). No zone file is opened. Exact-case names are still required, so a case-insensitive file system does not accept `america/los_angeles`. The accepted and refused names are the same as before, and the check is faster.
- **Zone loading** (`looper/agents/cron.py`). `zone` loads only the named zone through a new `_zone`, cached per name (256 entries). `_zone` now also turns an `OSError` from loading into the same `ValueError` for an unknown time zone, where before only `ZoneInfoNotFoundError` and `ValueError` were converted.
- **Tests** (`tests/test_cron.py`, `tests/test_api_latency_startup_db.py`, `tests/test_proc_tree.py`). A new test runs `zone()` and `local_zone_name()` with `available_timezones` patched to fail, and checks that unknown, wrong-case and path-like names are refused. The startup latency test no longer patches the zone listing. In `tests/test_proc_tree.py`, the fake agent in the refresh-cancel test can now be signalled directly (a stub change that fixed a failure on slower runners; no production code).
- **Model-visible changes:** No. No prompt, tool description or tool schema changed, and no HTTP API result changed. The only observable difference is startup time.

**谁需要升级：**在高负载机器上运行 `looper serve` 的运维人员；此前调度器检查时区名称时，启动可能阻塞事件循环数分钟。

**是否有破坏性变更：**无。API 响应、Telegram 与 Lark 渠道协议、仪表盘和 CLI 均不变，没有数据库变更。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.182 上的安装可直接升级。没有数据库变更。

### 行为变化与入口

以下在 [#1343](https://github.com/foolzzz/looper/pull/1343) 的差异中可见（`looper/agents/cron.py` 及测试）。PR 描述称除速度外没有行为变化。

- **时区名称检查**（`looper/agents/cron.py`）。`_known_zones` 不再调用 `zoneinfo.available_timezones()`，而是遍历 `zoneinfo.TZPATH` 中的目录，只取文件名，并在安装了 `tzdata` 包时加入其时区列表（包缺失或列表不可读则忽略）。不会打开任何时区文件。仍要求大小写完全一致，因此大小写不敏感的文件系统不会接受 `america/los_angeles`。接受和拒绝的名称与之前相同，只是更快。
- **时区加载**（`looper/agents/cron.py`）。`zone` 通过新增的 `_zone` 只加载指定的时区，并按名称缓存（256 项）。`_zone` 现在还会把加载时的 `OSError` 转换为同样的“未知时区” `ValueError`；此前只转换 `ZoneInfoNotFoundError` 和 `ValueError`。
- **测试**（`tests/test_cron.py`、`tests/test_api_latency_startup_db.py`、`tests/test_proc_tree.py`）。新增测试在 `available_timezones` 被打补丁为失败的情况下运行 `zone()` 和 `local_zone_name()`，并检查未知、大小写错误和类路径名称被拒绝。启动延迟测试不再需要给时区列表打补丁。`tests/test_proc_tree.py` 中 refresh-cancel 测试的假 agent 现在可以被直接发信号（修复慢速 runner 上的失败；仅测试桩，不涉及生产代码）。
- **面向模型的变化：**无。提示词、工具描述和工具 schema 均未改变，也没有 HTTP API 结果改变。唯一可观察的差异是启动时间。
