# Looper v2.13.82

## Release Decision

**Who should upgrade:** Anyone who edits global role settings or the shared agent defaults from the dashboard, or who calls the role and agent-settings routes (`GET /api/roles`, `GET` or `PUT /api/roles/{role}`, `POST /api/roles/{role}/reset-prompt`, `GET /api/agent-settings`, `PUT /api/agent-settings/system`, `PUT /api/agent-settings/roles/{role}`) from a script. Everyone else gets no change.

**What this release solves:** [#480](https://github.com/foolzzz/looper/pull/480) moves global role configuration and the system and role setting layers onto seven typed operations in the versioned API, and removes the seven legacy routes.

**Breaking changes:** Yes. The seven legacy routes are removed; a script that calls them must use `POST /api/v1/roles/list`, `get`, `update`, `reset_prompt` or `POST /api/v1/agent_settings/get`, `update_system`, `update_role`. The dashboard shipped in this release already does. The project-level agent-settings routes are not touched.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#480](https://github.com/foolzzz/looper/pull/480); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.82
```

## Behavior changes

- **Seven operations on v1 ([#480](https://github.com/foolzzz/looper/pull/480)):** the new `looper/agents/v1_domains/global_settings.py` registers `roles.list`, `roles.get` (risk `read`), `roles.update`, `roles.reset_prompt` (risk `write`), `agent_settings.get` (`read`), `agent_settings.update_system` (`high`) and `agent_settings.update_role` (`write`), all `POST` at `/api/v1/<domain>/<action>`. Requests are closed objects: `role` is an enum of the agent roles; `roles.update` takes `role` and `fields`; the settings updates take `values` (and `role` for `update_role`).
- **Role patch is stricter:** `roles.update` accepts only `display_name`, `enabled`, `system_prompt`, `max_turns`, `timeout_seconds`, `extra_args` and `metadata`. `role_config_fields` in `looper/agents/agent_settings.py` now rejects any other field as unknown or read-only; the old route ignored them. The messages for removed and moved fields now name the v1 operation instead of the removed route. The server runs a domain's own argument validator, so these explanations appear before the closed-schema error.
- **Confirmation:** `agent_settings.update_system` and `update_role` are declared `confirms=True`. Their impact check asks only for the shared defaults (system layer), for a `max_concurrency` change, or for a change that raises or removes the effective per-run spend cap; other role updates run at once. The change notes of the PR's documentation say the dashboard operator executes directly while API clients are asked first; this draft did not run the confirmation flow, and the code for the operator path was not traced.
- **Concurrency:** after `update_role` with `max_concurrency`, the server rechecks waiting runs once; running work continues (`server._recheck_concurrency()`).
- **Service behavior kept:** execution calls the same `role_configs` and `agent_settings` services as the old routes. Results use the v1 `OpOk.result` envelope and v1 errors rather than legacy `{"error": ...}` bodies.
- **Removed routes:** the seven legacy routes, their dispatch patterns and the role-config handlers are removed from `looper/agents/http_server.py`.
- **Dashboard and callers:** `fetchRoleConfigs`, `fetchRoleConfig`, `updateRoleConfig`, `resetRolePrompt`, `fetchAgentSettings`, `updateSystemSettings` and `updateRoleSettings` in `web/src/lib/api.ts` call the new operations; a confirmation answer is surfaced as an error. The prompt regression evals (`evals/prompt_regression/dialogs.py`, `runner.py`), `evals/stop_realpath.py`, `examples/dsh/validate.py` and `examples/pi/isolated-smoke.py` were moved to the new operations. The eval change also reads the Manager's newest run record before any dialog that stops or withdraws a message.
- **Docs not updated:** the PR changed two Chinese design documents only. `README.md`, `README.zh-CN.md` and `docs/architecture/agent-system.md` still name the removed routes.
- **Tests:** the new `tests/test_api_v1_global_role_settings.py` and `..._db.py` were added; several existing settings, catalog, DSH, profile, prompt-eval and dashboard tests were moved to the new operations.
- **Model-visible changes:** None. The operations declare no Tool, and the `looper_settings` Manager tool, role recommended prompts and Planner, Worker and Reviewer prompts are unchanged. The operations appear in the v1 operation catalog that API clients read.
- **Not confirmed in code:** this draft did not run any test.

## Upgrade and rollback

Re-run `install.sh` once v2.13.82 is published. No data migration. Update any script that used the removed routes. Rolling back to v2.13.81 restores them together with the old dashboard.

### 行为变化与入口

- **七个 v1 操作（[#480](https://github.com/foolzzz/looper/pull/480)）：**新增 `looper/agents/v1_domains/global_settings.py`，注册 `roles.list`、`roles.get`（风险 `read`）、`roles.update`、`roles.reset_prompt`（`write`）、`agent_settings.get`（`read`）、`agent_settings.update_system`（`high`）和 `agent_settings.update_role`（`write`），均为 `POST /api/v1/<domain>/<action>`。请求为封闭对象：`role` 为角色枚举；`roles.update` 接收 `role` 与 `fields`；设置更新接收 `values`（`update_role` 另需 `role`）。
- **角色修改更严格：**`roles.update` 只接受 `display_name`、`enabled`、`system_prompt`、`max_turns`、`timeout_seconds`、`extra_args`、`metadata`。`looper/agents/agent_settings.py` 中的 `role_config_fields` 现在把其他字段当作未知或只读字段拒绝；旧路由会忽略它们。已删除或已移走字段的报错现在指向 v1 操作而不是旧路由。服务器会先用领域自己的参数校验器，所以这些说明先于封闭 schema 的报错出现。
- **确认：**`agent_settings.update_system` 与 `update_role` 声明 `confirms=True`。影响检查只在修改共享默认值（系统层）、修改 `max_concurrency`、或提高/取消生效的单次运行花费上限时要求确认；其他角色更新直接执行。PR 的文档称仪表盘操作者直接执行、API 客户端需先确认；本草稿未运行确认流程，也未追踪操作者路径的代码。
- **并发：**`update_role` 修改 `max_concurrency` 后，服务器重新检查一次等待中的运行；已在运行的继续（`server._recheck_concurrency()`）。
- **服务行为不变：**执行时调用与旧路由相同的 `role_configs` 和 `agent_settings` 服务。结果包在 v1 的 `OpOk.result` 中，错误采用 v1 格式，不再是旧的 `{"error": ...}`。
- **移除的路由：**七条旧路由、其分派正则和角色配置处理函数已从 `looper/agents/http_server.py` 中移除。
- **仪表盘与调用方：**`web/src/lib/api.ts` 中的 `fetchRoleConfigs`、`fetchRoleConfig`、`updateRoleConfig`、`resetRolePrompt`、`fetchAgentSettings`、`updateSystemSettings`、`updateRoleSettings` 调用新操作；确认应答会作为错误抛出。prompt 回归评测（`evals/prompt_regression/dialogs.py`、`runner.py`）、`evals/stop_realpath.py`、`examples/dsh/validate.py`、`examples/pi/isolated-smoke.py` 已改用新操作。评测还会在含停止或撤回消息的对话前读取 Manager 最新的运行记录。
- **文档未全部更新：**该 PR 只改了两份中文设计文档。`README.md`、`README.zh-CN.md` 和 `docs/architecture/agent-system.md` 仍写着已移除的路由。
- **测试：**新增 `tests/test_api_v1_global_role_settings.py` 与 `..._db.py`；多个现有的设置、目录、DSH、Profile、prompt 评测和仪表盘测试改用新操作。
- **面向模型的变化：**无。这些操作未声明 Tool，`looper_settings` Manager 工具、角色推荐 prompt 以及 Planner、Worker、Reviewer 的 prompt 均未改动。它们会出现在 API 客户端读取的 v1 操作目录中。
- **代码中未确认：**本草稿未运行任何测试。
