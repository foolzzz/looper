# Looper v2.13.10

## Release Decision

**Who should upgrade:** Operators who run agents on the DSH runtime (consults, resident Manager or Planner), who select Agent Profiles with an effort level, or who run the prompt-regression evals. Everyone else sees no change.

**What this release solves:** [#300](https://github.com/foolzzz/looper/pull/300) fixes the follow-ups of #262: a failed DSH consult run is no longer delivered as an answer, resident DSH usage is priced by the configured model, an unsupported effort is refused when a profile is selected or launched, resident eval results carry their observed cost, and the `[1m]` suffix warning follows each runtime's real model mapping.

**Breaking changes:** No. The CLI, configuration, database schema and API routes are unchanged from [v2.13.9](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.9.md). A profile whose effort its runtime does not support, which was accepted at selection before, is now refused (see Behavior changes).

**How to verify:** Check the installed version, then select a DSH profile with an unsupported effort (such as `medium`) and see it refused.

**Contributors:** Maintainer @foolzzz authored [#300](https://github.com/foolzzz/looper/pull/300); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.10
```

## Behavior changes

- **Failed DSH consults.** A consult result with `is_error` set, or a `subtype` other than `success`, is rejected before delivery and falls back with a contract reason that names the error (first 300 characters) or the subtype. Before, a valid final kept from a failed run could be delivered as the answer.
- **Effort is checked at selection and launch.** `profile_problem` and the launch-time binding check now pass the profile's effort to the runtime check, so a pairing such as `dsh` with `medium` or `xhigh` is refused when the profile is selected or launched. Config import already passed it.
- **Resident DSH pricing.** The launch patch for a resident DSH turn now records the configured model verbatim (for example `deepseek-v4-pro[1m]`); only the API request model is normalized. The turn's stream reads that configured model, so usage, price and budget stop use it, for the Manager and the Planner alike.
- **Resident DSH cost.** A resident turn's result now carries `observed_cost_usd`, the root spend priced at the provider's prices; it stays unset while no root step could be priced.
- **Evals.** The prompt-regression eval takes the larger of the recorded cost and the sum of the runs' observed root spend, and sets `observed_cost_complete` on the row: false when any run reported none. A missing value is unknown, not zero.
- **`[1m]` warning.** Each runtime adapter now exposes `api_model`, the name it sends to the provider (DSH maps through its model table; Claude Code strips the context suffix; others send it verbatim). A profile warns only about names that still carry a suffix after that mapping, so DSH and Claude Code no longer warn about a suffix they strip; runtimes that pass it through, such as pi, keep the warning.
- **Model-visible changes:** None. No prompt or tool schema changed. A failed consult now falls back instead of delivering its text, which changes what the Manager receives only in that failure case.

## Entry points

None added. No CLI command, HTTP route or configuration key was added.

## Upgrade and rollback

Re-run `install.sh` once v2.13.10 is published. There is no schema or configuration change. Rolling back to v2.13.9 is safe; it restores the earlier behavior listed above. A profile with an unsupported effort needs its effort changed to be selectable on this release.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**使用 DSH 运行时（咨询、常驻 Manager 或 Planner）、为 Agent Profile 选择 effort、或运行 prompt 回归 eval 的运营者。其他人没有变化。

**解决了什么：**[#300](https://github.com/foolzzz/looper/pull/300) 修复 #262 的后续问题：失败的 DSH 咨询不再作为答案交付；常驻 DSH 按配置的模型计价；选择或启动 profile 时拒绝运行时不支持的 effort；常驻 eval 结果带观测成本；`[1m]` 后缀警告按各运行时的真实模型映射给出。

**是否有破坏性变更：**无。CLI、配置、数据库 schema 和 API 路由与 [v2.13.9](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.9.md) 相同。此前选择时可通过、但运行时不支持其 effort 的 profile，现在会被拒绝。

**如何验证：**运行 `looper --version` 核对版本为 2.13.10；DSH 咨询失败回退、effort 拒绝等行为见各自的单元测试。

**贡献者：**维护者 @foolzzz 提交 [#300](https://github.com/foolzzz/looper/pull/300)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.10
```

### 行为变化与入口

- 失败的 DSH 咨询：结果带 `is_error`，或 `subtype` 不是 `success` 时，交付前被拒绝，并以契约原因回退，原因写明错误（前 300 字符）或 subtype。
- effort 校验：`profile_problem` 与启动时的绑定检查现在把 profile 的 effort 传给运行时检查，`dsh` 搭配 `medium` 或 `xhigh` 在选择或启动时即被拒绝；配置导入原本就传了。
- 常驻 DSH 计价：启动补丁原样记录配置的模型（如 `deepseek-v4-pro[1m]`），只有 API 请求模型被规范化；用量、价格和预算停止都用配置的模型，Manager 与 Planner 相同。
- 常驻 DSH 成本：常驻回合结果带 `observed_cost_usd`（按提供方价格计的根花费）；没有可计价的根步骤时保持未设置。
- Eval：prompt 回归 eval 取已记录成本与各次运行观测根花费之和中较大者，并在行上设置 `observed_cost_complete`，任一运行没有观测值时为 false；缺失视为未知而非 0。
- `[1m]` 警告：各运行时适配器新增 `api_model`（实际发给提供方的名称；DSH 查模型表，Claude Code 去掉上下文后缀，其余原样）。profile 只对映射后仍带后缀的名称告警，DSH 和 Claude Code 不再对自己会去掉的后缀告警，pi 等原样透传的运行时保留警告。
- 面向模型的变化：无。提示词和工具 schema 均未变；仅在咨询失败时，Manager 收到的是回退而不是失败运行的文本。未新增 CLI 命令、HTTP 路由或配置项。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.9 安全，会恢复上述旧行为。effort 不受支持的 profile 需改 effort 才能在本版本选择。

### 可选能力启用与使用

本版本未新增可选能力启用入口。
