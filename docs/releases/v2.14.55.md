# Looper v2.14.55

This is the patch release v2.14.55, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.54: a test-only fix that stops the lost-lock database-restart test from failing when an earlier test leaves a connection open ([#1033](https://github.com/foolzzz/looper/pull/1033)). No production code changes.

## Release Decision

**Who should upgrade:** Nobody needs to. The release changes only a test; the installed behavior is identical to v2.14.54.

**What this release solves:** [#1033](https://github.com/foolzzz/looper/pull/1033) makes the lost-lock restart test (`test_a_database_restart_is_a_lost_lock` in `tests/test_control_plane_lock_db.py`) terminate only the connections the system under test opened. Before, the test asserted that exactly one other connection existed (the fixture's schema owner), so a connection left by an earlier test in the same worker made it fail.

**Breaking changes:** No. No API, migration or runtime behavior changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#1033](https://github.com/foolzzz/looper/pull/1033); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.55
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.54 upgrades directly. This release adds no migration.

## Behavior changes

- **Behavior changes:** None. The diff touches only `tests/test_control_plane_lock_db.py` (16 lines added, 7 removed); production code is unchanged.
- **Test change ([#1033](https://github.com/foolzzz/looper/pull/1033)).** The restart helper no longer asserts that exactly one other connection exists. It records the existing connections (the fixture's schema owner and any others) before the system starts and, on restart, terminates every connection not in that set. The restart test is now parametrized with and without an extra idle connection, and with the extra connection it checks that connection is still alive afterwards. The lost-lock assertions are unchanged.
- **Model-visible changes:** No. No prompt, tool description, tool schema or Manager confirmation text changes.
