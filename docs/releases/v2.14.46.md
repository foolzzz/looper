# Looper v2.14.46

This is the patch release v2.14.46, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.45: the command schedule confirmations, the tool description and the client-token API text are finished ([#1005](https://github.com/foolzzz/looper/pull/1005)).

## Release Decision

**Who should upgrade:** Anyone who creates, enables or runs command schedules through the Manager chat or the client-token API and wants the confirmation to show exactly what will execute.

**What this release solves:** [#1005](https://github.com/foolzzz/looper/pull/1005) makes the confirmation for enabling or running a command schedule show the command in a code fence, the directory, the run timeout, the environment keys, the env file, and for enabling the success deadline and alert thresholds, and say that no agent or model spend follows. The tool description no longer says an enabled schedule starts tasks, and the client-token API's confirmations name the shell command.

**Breaking changes:** No. No API or configuration is removed, and there is no new migration or setting. Listed runs and the run-now result gain a `kind` field.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#1005](https://github.com/foolzzz/looper/pull/1005); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.46
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.45 upgrades directly. This release adds no migration and no new setting.

## Behavior changes

- **Manager confirmations ([#1005](https://github.com/foolzzz/looper/pull/1005)).** For a command schedule, the enable and run-now confirmations show the command verbatim in a code fence (a fence longer than any backtick run in the command, so backticks and newlines survive), the directory, the run timeout, the environment keys only (never values), the env file when set, and, for enable, the success deadline and alert thresholds. Both say the run goes through no agent and spends no model quota. An agent schedule keeps its task and spending confirmation.
- **Command display.** The configuration block shown after `create` and the before → after lines of `update` put the command in the same code fence. Every command schedule update reply ends with `不经过 agent，不花模型额度`.
- **Client-token API.** The enable and run confirmations (`impact`) name the shell command and its directory and say no agent or model spend follows. For `run` and `update`, the confirmed call carries the schedule's configuration version read when the confirmation was built, and the server-owned `_schedule_version` is passed to `update_schedule` and `run_now` as `expected_version`; the closed request schema cannot supply it.
- **Run kind.** Listed runs (`looper_schedules` list/get and the v1 `LISTED_RUN` schema) and the run view carry `kind` (`agent` or `command`; `agent` when the row has none). The v1 run schemas list it as an enum, and `kind` is required in `LISTED_RUN`.
- **Docs.** The `looper_schedules` row of `docs/architecture/agent-system.md` describes the above.
- **Model-visible changes:** Yes. The `looper_schedules` tool description changes its enable clause from "its runs then start tasks unattended" to "it then fires unattended: its task, or its command"; the confirmation and update reply texts the Manager shows and reads change as described; listed runs gain `kind`. The prompt-regression dialog checks in `evals/prompt_regression/dialogs.py` are updated to match. No tool schema argument is added.

## 中文摘要

本版本是 patch release v2.14.46（热修线，每个合并的改动立即发布）。自 v2.14.45 以来合并了一项改动：补全命令定时任务的确认文案、工具描述和 client-token API 文案（[#1005](https://github.com/foolzzz/looper/pull/1005)）。

### 升级决策

**谁需要升级：**通过 Manager 对话或 client-token API 创建、启用或立即运行命令定时任务，并希望确认时看到将要执行的确切内容的人。

**解决了什么：**[#1005](https://github.com/foolzzz/looper/pull/1005) 让启用或运行命令定时任务的确认显示代码块中的命令、目录、运行超时、环境变量名、env 文件，启用时还显示最晚成功时间和告警阈值，并说明不经过 agent、不花模型额度。工具描述不再说启用后会启动任务，client-token API 的确认会写明 shell 命令。

**是否有破坏性变更：**否。不移除任何 API 或配置，也没有新的迁移或设置。列出的运行和立即运行的结果新增 `kind` 字段。

**如何验证：**运行 `looper --version` 核对版本为 2.14.46。

**贡献者：**维护者 @foolzzz 提交 [#1005](https://github.com/foolzzz/looper/pull/1005)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.46
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.45 上的安装可直接升级。本版本没有新迁移，也没有新设置。

### 行为变化与入口

- **Manager 确认（[#1005](https://github.com/foolzzz/looper/pull/1005)）。**命令定时任务的启用和立即运行确认，在代码块中原样显示命令（围栏比命令中最长的反引号串更长，反引号和换行不会丢失）、目录、运行超时、仅环境变量名（不含值）、设置时的 env 文件，启用时还有最晚成功时间和告警阈值。两者都说明不经过 agent、不花模型额度。agent 定时任务保持原有的任务与花费确认。
- **命令显示。**`create` 后的配置块和 `update` 的前 → 后行用同样的代码块显示命令。每条命令定时任务的修改回复都带 `不经过 agent，不花模型额度`。
- **Client-token API。**启用和立即运行的确认（`impact`）写明 shell 命令和目录，并说明之后没有 agent 或模型花费。对 `run` 和 `update`，确认时读取的定时任务配置版本随确认后的调用一起传给 `update_schedule` 与 `run_now`（`expected_version`）；封闭的请求 schema 不能自行提供它。
- **运行类型。**列出的运行（`looper_schedules` 的 list/get 与 v1 的 `LISTED_RUN`）和运行视图带 `kind`（`agent` 或 `command`，缺省为 `agent`）；`LISTED_RUN` 中 `kind` 为必填。
- **文档。**`docs/architecture/agent-system.md` 中 `looper_schedules` 一行已同步。
- **面向模型的变化：**有。`looper_schedules` 的工具描述把启用语句从“its runs then start tasks unattended”改为“it then fires unattended: its task, or its command”；Manager 展示和读取的确认与回复文本如上变化；列出的运行新增 `kind`。`evals/prompt_regression/dialogs.py` 中的对话检查已同步更新。没有新增工具参数。
