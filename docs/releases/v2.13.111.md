# Looper v2.13.111

## Release Decision

**Who should upgrade:** Anyone who runs a Telegram channel bot, especially where a bot can fail while starting (a bad token, a network error, a cancelled start) and the server keeps running.

**What this release solves:** [#606](https://github.com/foolzzz/looper/pull/606) releases a Telegram channel's HTTP clients, background task and application when its startup fails part-way, instead of leaving them open.

**Breaking changes:** No. No route, configuration, request field or stored data changed; only the Telegram channel adapter's startup failure and shutdown paths behave differently.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#606](https://github.com/foolzzz/looper/pull/606); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.111
```

## Behavior changes

- **Partial startup is cleaned up ([#606](https://github.com/foolzzz/looper/pull/606)):** in `looper/agents/channels/telegram.py`, `start()` wraps `initialize`, `start` and `start_polling` in a block that catches any failure, including cancellation, calls `stop()` and re-raises the original error. Before, a failure there left the outbound task and the application's connections behind.
- **The adapter owns its HTTP clients:** `start()` now creates two `HTTPXRequest` clients itself, one for polling (pool size 1) and one for other calls (pool size 256), matching the defaults of `ApplicationBuilder`, and hands them to the builder. This is needed because `Application.shutdown` does nothing when `initialize` failed, so the library could not close them.
- **`stop()` is ordered and failure-tolerant:** it cancels the outbound task, stops the reaction tracker, stops the updater and the application only if each is running, shuts down the application, then shuts down both clients. Each step runs even if an earlier one raised; such a failure is logged as a warning naming the channel and the step. Afterwards the adapter clears its application, clients, outbound task and bus handles. `stop()` after a failed start, or twice, is safe.
- **Model-visible changes:** None. No Manager tool declaration, prompt or API route changed, and messages sent and received through Telegram are the same.
- **Tests:** [#606](https://github.com/foolzzz/looper/pull/606) adds `tests/test_telegram_lifecycle.py` (partial-start release, cleanup continuing after a failing step, and a real `Application` closing its HTTP clients after a partial start) and adjusts `tests/test_serve_channel_bots_db.py` for the cleared handles and the builder's new calls (266 test lines, 46 production lines as reported).

## Upgrade and rollback

Re-run `install.sh` once v2.13.111 is published. No data migration and no configuration change. Rolling back to v2.13.110 restores the earlier startup failure behavior.

### 升级决策

**谁需要升级：**运行 Telegram 渠道 bot 的使用者，尤其是 bot 可能在启动时失败（token 错误、网络错误、启动被取消）而服务继续运行的场景。

**是否有破坏性变更：**否。路由、配置、请求字段和存储数据均未改变；只有 Telegram 渠道适配器的启动失败与停止路径行为改变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.111。

**贡献者：**维护者 @foolzzz 提交 [#606](https://github.com/foolzzz/looper/pull/606)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.111
```

### 行为变化与入口

- **启动中途失败会被清理（[#606](https://github.com/foolzzz/looper/pull/606)）：**`looper/agents/channels/telegram.py` 中，`start()` 把 `initialize`、`start` 和 `start_polling` 包在一个捕获任何失败（含取消）的块里，先调用 `stop()` 再重新抛出原错误。此前这里失败会留下出站任务和 application 的连接。
- **适配器自己持有 HTTP 客户端：**`start()` 现在自行创建两个 `HTTPXRequest` 客户端，一个用于轮询（连接池 1），一个用于其他调用（连接池 256），与 `ApplicationBuilder` 默认值一致，并交给 builder。这是因为 `initialize` 失败后 `Application.shutdown` 什么也不做，库无法关闭它们。
- **`stop()` 有序且容错：**依次取消出站任务、停止回应跟踪器、仅在运行时停止 updater 与 application、关闭 application，再关闭两个客户端。前一步抛错也会继续后面各步；该失败以警告记录，注明渠道与步骤。之后适配器清空 application、客户端、出站任务和 bus 句柄。启动失败后或重复调用 `stop()` 都是安全的。
- **面向模型的变化：**无。Manager 的 tool 声明、提示词和 API 路由均未改变，通过 Telegram 收发的消息不变。
- **测试：**[#606](https://github.com/foolzzz/looper/pull/606) 新增 `tests/test_telegram_lifecycle.py`（部分启动后释放资源、某步清理失败时后续清理继续、真实 `Application` 在部分启动后关闭 HTTP 客户端），并调整 `tests/test_serve_channel_bots_db.py` 以适配被清空的句柄和 builder 的新调用（按报告测试 266 行、生产代码 46 行）。
