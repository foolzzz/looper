# Looper v2.13.164

## Release Decision

**Who should upgrade:** Nobody needs to. This release adds the connection layer for future agent SDK runners, which nothing in Looper calls yet. Everyone else can stay on v2.13.163.

**What this release solves:** [#744](https://github.com/foolzzz/looper/pull/744) adds `RunnerBridge`, which carries one runner's stdio connection: it matches requests with responses, keeps a table of sessions, hands tool and budget requests to the turn policy added in v2.13.163, and translates runner updates into the event shape Looper's existing consumers read.

**Breaking changes:** No. No existing API, database, configuration, prompt or Tool declaration changed, and no runtime path imports the new module.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#744](https://github.com/foolzzz/looper/pull/744); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.164
```

## Behavior changes

- **Runtime behavior:** none. `looper/agents/runtimes/runner/bridge.py` is a new file imported only by `tests/test_runner_bridge.py`; no command, API, task or session behaves differently, and no process is started.
- **Connection ([#744](https://github.com/foolzzz/looper/pull/744)):** `RunnerBridge` sends `initialize` once and checks the reply against the protocol version, runner kind and permitted capabilities. Requests carry ids `l-N` and time out after `control_timeout` (default 10 s); a timeout or cancellation of a control request fails the connection. Responses must match a pending request; a stray response, a duplicate runner request id, an unknown update method, malformed stdout, EOF or a closed stdin fails the connection with a bounded message that contains no frame text. A failure marks every open session poisoned, calls `on_failure` once, and closes only this connection's writer; it never terminates the process.
- **Sessions ([#744](https://github.com/foolzzz/looper/pull/744)):** `open_session`, `begin_turn`, `wait_settled`, `cancel_turn`, `steer` and `close_session` keep one state per session (opening, idle, running, closing, closed, poisoned). A session runs one trace at a time and never reuses a trace id; a busy session or a repeated trace id is refused as `SESSION_BUSY`, and `steer` needs the runner to declare in-trace steering. A correlated rejection of a prompt abandons only that prompt and returns the session to idle.
- **Runner requests ([#744](https://github.com/foolzzz/looper/pull/744)):** only `tools/call` and `budget/authorize` are answered, by `RunnerTurn.call_tool` and `RunnerTurn.authorize`. An unknown method gets `METHOD_NOT_FOUND`, a wrong trace gets `TRACE_MISMATCH`, and a stopped, closing or failed session gets a refusal (`allow: false, reason: "stopped"`, or an error result with `ran=False`). An exception in a host callback is answered with a fixed message, not its text. The connection waits for in-flight callbacks when it shuts down instead of cancelling them.
- **Event translation ([#744](https://github.com/foolzzz/looper/pull/744)):** `session/update` messages become the events consumers already read: `system/init`, streamed text deltas, assistant messages, tool results and the final `result`. Consecutive text deltas are merged. Each session queues at most 128 updates (`max_updates`) and a merged delta at most the protocol's frame bound; exceeding either fails the connection. Late text deltas of a finished trace are dropped; any other late update is a protocol error. On settlement the turn is stopped and finished, and the result event reports `cancelled`, `capped` (budget subtype with the cap reason), `max_requests`, a failure (error text redacted and cut to 512 characters) or success, together with usage, `total_cost_usd`, `num_turns` and a `runner` block. A connection that is lost before settlement settles the turn as `lost`.
- **Model-visible changes:** none. No prompt, tool description or tool schema changed, and nothing sends the new events or refusal texts to a model today.
- **Tests:** `tests/test_runner_bridge.py` is new.
- **Description mismatch:** the description of #744 says "approximately 580 changed lines" and "tests 375, production 486"; the file list adds 497 production and 461 test lines, and this draft takes the file list as authoritative.

### 行为变化与入口

- **运行时行为：**无。`looper/agents/runtimes/runner/bridge.py` 是新文件，仅被 `tests/test_runner_bridge.py` 导入；没有命令、API、任务或会话的行为发生变化，也不会启动任何进程。
- **连接（#744）：**`RunnerBridge` 只发送一次 `initialize`，并按协议版本、runner 类型和允许的能力校验回复。请求 id 形如 `l-N`，超过 `control_timeout`（默认 10 秒）即超时；控制请求超时或被取消会使连接失败。响应必须对应未完成的请求；多余的响应、重复的 runner 请求 id、未知的更新方法、格式错误的 stdout、EOF 或 stdin 关闭都会使连接失败，错误信息有长度上限且不含帧内容。失败会把所有打开的 session 标记为 poisoned，调用一次 `on_failure`，且只关闭本连接的 writer，不会终止进程。
- **会话（#744）：**`open_session`、`begin_turn`、`wait_settled`、`cancel_turn`、`steer` 和 `close_session` 为每个 session 维护一个状态（opening、idle、running、closing、closed、poisoned）。一个 session 同时只运行一个 trace，且 trace id 不可复用；session 忙或 trace id 重复时以 `SESSION_BUSY` 拒绝，`steer` 需要 runner 声明支持 trace 内转向。对 prompt 的关联性拒绝只放弃该 prompt，session 回到 idle。
- **runner 请求（#744）：**只应答 `tools/call` 和 `budget/authorize`，分别由 `RunnerTurn.call_tool` 与 `RunnerTurn.authorize` 处理。未知方法返回 `METHOD_NOT_FOUND`，trace 不符返回 `TRACE_MISMATCH`，已停止、正在关闭或已失败的 session 得到拒绝（`allow: false, reason: "stopped"`，或 `ran=False` 的错误结果）。宿主回调抛出的异常以固定文案应答，不含异常原文。连接关闭时会等待进行中的回调完成，而不是取消它们。
- **事件转换（#744）：**`session/update` 被转换为消费者已在读取的事件：`system/init`、流式文本增量、assistant 消息、工具结果和最终的 `result`。连续的文本增量会被合并。每个 session 最多排队 128 条更新（`max_updates`），合并后的增量不超过协议的帧上限；超出任一上限会使连接失败。已结束 trace 的迟到文本增量被丢弃，其他迟到更新属于协议错误。结算时先停止并结束该轮，结果事件报告 `cancelled`、`capped`（预算子类型并带上限原因）、`max_requests`、失败（错误文本经脱敏并截断为 512 字符）或成功，并附带用量、`total_cost_usd`、`num_turns` 和 `runner` 块。在结算前丢失连接时，该轮按 `lost` 结算。
- **面向模型的变化：**无。prompt、工具描述和工具 schema 均未改变，目前没有任何代码把新事件或拒绝文案发送给模型。
