# Looper v2.14.10

This is the patch release v2.14.10. It ships the one change merged since v2.14.9: [#891](https://github.com/foolzzz/looper/pull/891), which records the model on every runner-hosted turn. It affects only installations that run roles on the DSH or Pi runner.

## Release Decision

**Who should upgrade:** Operators who run roles on the DSH runner (`[runtimes] dsh = "runner"`) or the Pi runner and want the runs list and task costs to show the model. Nothing changes for installations that use the CLI or api runtimes. It ships the one change merged since v2.14.9.

**What this release solves:** [#891](https://github.com/foolzzz/looper/pull/891): every record written for a runner-hosted turn had `model` NULL, so the runs list showed no model, task costs grouped under none, and the real DSH smoke failed its readback. Every runner trace now opens with its own `system/init` event carrying the Descriptor's model, as the CLI and api runtimes do.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#891](https://github.com/foolzzz/looper/pull/891); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.10
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.9 upgrades directly. This release changes no schema, stored data or setting.

## Behavior changes

All runtime changes are in `looper/agents/runtimes/runner/bridge.py` and `session.py` and are reached only by runner-hosted turns.

- **Each runner turn opens its own `system/init` with the model:** the bridge resets its per-turn `initialized` flag when a turn starts, so every trace is a record that begins with its own init. The session sets `model` on that init event to the Descriptor's model, which is where the recorder takes a run's model from. Before, the record's model stayed NULL.
- **A failed resume keeps its record identity:** when the runner's saved session is unavailable ("could not be resumed"), no runner turn runs, so the session itself emits one init with the session id, model and trace id before returning the failure. The failed record now carries the session and model.
- **Tests:** `tests/test_runner_session.py` asserts an init with the model per turn and on the failed-resume path; `tests/test_pi_runner_serve_db.py` asserts `model` on records after manager stop and restart and on every role of a task, and adds a missing-saved-session case (failed record, then a recovered record with a new session, with no provider request for the failed load).
- **Model-visible changes:** None. The init event is a host-side recorder event; prompts, tools and model requests are unchanged. The visible effect is the model shown in the runs list and in cost grouping.

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.9 上的安装可直接升级。本版本不改 schema、已存数据或设置。

### 行为变化与入口

运行时改动在 `looper/agents/runtimes/runner/bridge.py` 和 `session.py` 中，仅 runner 托管的回合会触达。

- **每个 runner 回合以带模型的 `system/init` 开头：**回合开始时 bridge 重置每回合的 `initialized` 标志，使每条 trace 都是以自己的 init 开头的记录。session 在该 init 事件上写入 Descriptor 的模型，记录器据此取得运行的模型。此前记录的模型保持为 NULL。
- **恢复失败时保留记录身份：**runner 保存的会话不可用（“could not be resumed”）时没有 runner 回合运行，session 自己在返回失败前发出一条带会话 id、模型和 trace id 的 init。失败记录现在带有会话和模型。
- **测试：**`tests/test_runner_session.py` 断言每个回合及恢复失败路径上的 init 带模型；`tests/test_pi_runner_serve_db.py` 断言 manager 停止重启后和任务每个角色的记录带 `model`，并新增保存会话缺失的用例（失败记录，随后是带新会话的恢复记录，失败的加载不向提供方发请求）。
- **面向模型的变化：**无。init 事件是宿主侧的记录器事件；提示、工具和模型请求都不变。可见影响是运行列表和成本分组中显示模型。
