# Looper v2.14.26

This is the patch release v2.14.26. It ships the one change merged since v2.14.25: [#928](https://github.com/foolzzz/looper/pull/928), which adds the approved hot upgrade v0 RFC. It is documentation only and changes no runtime code.

## Release Decision

**Who should upgrade:** Nobody needs this release for runtime behavior. It matters to maintainers who want the approved design for planned restarts that do not interrupt runs in the released tree. It ships the one change merged since v2.14.25.

**What this release solves:** [#928](https://github.com/foolzzz/looper/pull/928) adds the hot upgrade v0 RFC (`docs/architecture/rfcs/hot-upgrade-v0.zh-CN.md`, in Chinese): planned restarts that do not interrupt runs, upgrading only the changed components. It also records the RFC's stages in the development plan's open todos.

**Breaking changes:** No. No database schema, stored data, API or default changes. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#928](https://github.com/foolzzz/looper/pull/928); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.26
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.25 upgrades directly. This release changes no database schema or stored data.

## Behavior changes

- **None at runtime.** The pull request touches only `docs/architecture/rfcs/hot-upgrade-v0.zh-CN.md` (new, 446 lines) and `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md` (2 added lines); no file under `looper/` changes.
- **The RFC** describes a design only: its status is approved, with stage S0 first and S1 after S0 ships. Nothing it describes (component fingerprints, upgrade plans, drain, per-run keeper processes, `looper service upgrade`) is implemented by this release.

- **Model-visible changes:** None. No prompt, tool, schema or message changes.
