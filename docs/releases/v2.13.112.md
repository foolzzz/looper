# Looper v2.13.112

## Release Decision

**Who should upgrade:** Anyone who runs a Manager on Claude Code, especially where a Manager is cancelled, disabled or closed while a turn is running; and anyone who runs `examples/pi/eval-prompt-comparison.sh` and reads its selected-case cost and repetition totals.

**What this release solves:** [#612](https://github.com/foolzzz/looper/pull/612) keeps a Manager's run record and the text it had already produced, and finishes the resident Claude process cleanup, when the Manager is cancelled mid-turn. [#610](https://github.com/foolzzz/looper/pull/610) makes the Pi prompt comparison recompute total cost and repetitions from the selected rows instead of carrying the whole run's values.

**Breaking changes:** No. No route, configuration, request field or stored data format changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#612](https://github.com/foolzzz/looper/pull/612) and [#610](https://github.com/foolzzz/looper/pull/610); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.112
```

## Behavior changes

- **Cancelled Manager turns keep their record and text ([#612](https://github.com/foolzzz/looper/pull/612)):** in `looper/agents/tiers/manager.py`, when the message task is cancelled, the Manager now closes the run record through `recorder.end_left_open(exc, output_text=...)` after it has abandoned event handling, even if that abandoning raised. The retained output is the assistant text already handled, otherwise the deltas already shown (`token.partial`), otherwise none. Before, the record was closed with no output, or the generic fallback replaced the output with `None`. The same applies when a cancellation arrives while the Manager cleans up after a read failure or a stop: the record is closed with the output kept, then the cancellation propagates.
- **`end_left_open` takes `output_text`:** in `looper/agents/claude_cli.py`, `ClaudeRunRecorder.end_left_open` has a new keyword-only `output_text` argument (default `None`, the previous behavior) that is written to the closed record.
- **Resident cleanup has its own task ([#612](https://github.com/foolzzz/looper/pull/612)):** `ResidentClaude` now runs the stop of a Claude process (`_stop_process`) as a tracked task instead of inline with an event. Cancelling the caller does not cancel the cleanup; a turn or a later `stop()` waits for every cleanup under way (shielded), including one begun after the process was already forgotten. A cleanup that fails is logged as an error (`resident cleanup failed`) instead of being lost.
- **Pi comparison totals follow the selected rows ([#610](https://github.com/foolzzz/looper/pull/610)):** in `examples/pi/eval-prompt-comparison.sh`, the subset written for `compare` now sets `total_cost_usd` to the sum of the selected rows' `cost_usd` (rounded to 6 places) and `reps` to the number of distinct `rep` values among them. Before, it kept the values of the whole Pi run, so a comparison of selected cases showed the cost and repetitions of cases it did not include. This is an example script; the `looper` package is unchanged by it.
- **Model-visible changes:** None. No Manager tool declaration, prompt or API route changed. The text a cancelled Manager turn keeps in its run record is stored output, not something sent to a model.
- **Tests:** [#612](https://github.com/foolzzz/looper/pull/612) renames and extends `tests/test_manager_stop_faults.py` (`test_closing_a_manager_keeps_the_text_it_already_handled_or_showed`); [#610](https://github.com/foolzzz/looper/pull/610) adds `test_comparison_selected_cost_and_reps_match_rows` to `tests/test_pi_eval_commands.py`. Reported added lines: [#612](https://github.com/foolzzz/looper/pull/612) tests 126, production 44; [#610](https://github.com/foolzzz/looper/pull/610) tests 50, production 0.

Re-run `install.sh` once v2.13.112 is published. No data migration and no configuration change. Rolling back to v2.13.111 restores the earlier cancellation record and cleanup behavior and the earlier Pi comparison totals.

**是否有破坏性变更：**否。路由、配置、请求字段和存储数据格式均未改变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.112。

**贡献者：**维护者 @foolzzz 提交 [#612](https://github.com/foolzzz/looper/pull/612) 与 [#610](https://github.com/foolzzz/looper/pull/610)；本次 patch release 无社区贡献。


### 行为变化与入口

- **被取消的 Manager 回合保留记录与文本（[#612](https://github.com/foolzzz/looper/pull/612)）：**`looper/agents/tiers/manager.py` 中，消息任务被取消时，Manager 在放弃事件处理后（即使该步骤抛错）通过 `recorder.end_left_open(exc, output_text=...)` 关闭运行记录。保留的输出依次为已处理的助手文本、已显示的增量（`token.partial`）、无。此前记录以无输出关闭，或被通用兜底路径把输出替换为 `None`。在读取失败或停止后的清理过程中再收到取消时同样处理：先保留输出关闭记录，再继续传播取消。
- **`end_left_open` 新增 `output_text`：**`looper/agents/claude_cli.py` 中 `ClaudeRunRecorder.end_left_open` 新增仅限关键字的 `output_text` 参数（默认 `None`，即原行为），其值写入关闭的记录。
- **常驻清理有独立任务（[#612](https://github.com/foolzzz/looper/pull/612)）：**`ResidentClaude` 现在把停止 Claude 进程（`_stop_process`）作为受跟踪的任务运行，而不是用事件内联处理。取消调用方不会取消清理；回合或之后的 `stop()` 会（经 shield）等待所有进行中的清理，包括进程已被遗忘后才开始的清理。清理失败会以错误日志（`resident cleanup failed`）记录，而不是丢失。
- **Pi 对比总数跟随所选行（[#610](https://github.com/foolzzz/looper/pull/610)）：**`examples/pi/eval-prompt-comparison.sh` 为 `compare` 写出的子集现在把 `total_cost_usd` 设为所选行 `cost_usd` 之和（保留 6 位），`reps` 设为所选行中不同 `rep` 的个数。此前沿用整次 Pi 运行的值，所选用例的对比会显示未包含用例的成本和重复次数。这是示例脚本；`looper` 包不受其影响。
- **面向模型的变化：**无。Manager 的 tool 声明、提示词和 API 路由均未改变。被取消的 Manager 回合保留在运行记录中的文本是存储的输出，不会发送给模型。
- **测试：**[#612](https://github.com/foolzzz/looper/pull/612) 重命名并扩展 `tests/test_manager_stop_faults.py`（`test_closing_a_manager_keeps_the_text_it_already_handled_or_showed`）；[#610](https://github.com/foolzzz/looper/pull/610) 在 `tests/test_pi_eval_commands.py` 新增 `test_comparison_selected_cost_and_reps_match_rows`。按报告新增行数：[#612](https://github.com/foolzzz/looper/pull/612) 测试 126、生产代码 44；[#610](https://github.com/foolzzz/looper/pull/610) 测试 50、生产代码 0。
