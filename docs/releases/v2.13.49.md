# Looper v2.13.49

## Release Decision

**Who should upgrade:** Operators who start tasks in workspaces on a mounted filesystem, such as a container volume or a network mount, where task creation was refused with a Git "mount point" diagnostic. Nobody else needs to act.

**What this release solves:** [#427](https://github.com/foolzzz/looper/pull/427) lets a task start in a workspace whose Git discovery would stop at a filesystem boundary, and restores the Linux Python Tests workflow by pinning its runner and PostgreSQL clients.

**Breaking changes:** No. Tasks in a directory that is not inside any Git repository still run in place, and broken repositories still fail visibly.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#427](https://github.com/foolzzz/looper/pull/427); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.49
```

## Behavior changes

- **Workspace discovery (`looper/agents/task_workspaces.py`):** the repository lookup now runs `git rev-parse` with `GIT_DISCOVERY_ACROSS_FILESYSTEM=1`, so discovery no longer stops at a mount point. A workspace inside a repository on another filesystem is found and isolated like any other, and a workspace with no repository up to the root runs in place. Only the full-discovery message (`not a git repository (or any of the parent directories):`) and `this operation must be run in a work tree` mean "not a repository"; the mount-point diagnostic, an invalid explicit Git directory (`not a git repository: ...`), an unreadable HEAD, a timeout and any other inspection failure still raise a workspace error and never fall back to running in place. The shared check serves dashboard, Telegram, Lark and CLI task creation.
- **CI (`.github/workflows/python-tests.yml`):** the Agent system tests job runs on `ubuntu-24.04` instead of `ubuntu-latest` and installs the PostgreSQL 16 clients, put first on `PATH`, so `pg_dump` and `pg_restore` match the PostgreSQL 16 service. The real archive recovery test is kept.
- **Model-visible changes:** None. No prompt, tool result, OpenAPI document or channel text changed.
- **Tests:** The pull request reports added lines: tests 59, production 5 workspace lines plus 11 workflow lines (the workflow counts are from the pull request file list).

## Upgrade and rollback

Re-run `install.sh` once v2.13.49 is published. No data migration. Rolling back to v2.13.48 restores the earlier refusal at mount boundaries; nothing is stored differently.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## Validation

**Retained implementation evidence:** [#427](https://github.com/foolzzz/looper/pull/427) reports a regression test that failed before the fix, workspace and API tests, vault closeout, operator-token launch isolation and the four-role serve smoke against a disposable PostgreSQL 16, and a Linux Python Tests run with 7,996 Python tests and 590 dashboard tests passing. The local full-archive recovery test was skipped there because `pg_dump` and `pg_restore` were not installed; CI ran it. This draft did not re-run any of it. The merged code sets `GIT_DISCOVERY_ACROSS_FILESYSTEM=1`, which the pull request description does not mention; this body follows the code.

**CI:** CI runs after the release is drafted; its result is not recorded here.

**Not tested for this draft:** Local test runs, real runtimes, a live service and browser checks. The release documentation gate checks the body only.

## 中文摘要

### 升级决策

**谁需要升级：**在挂载文件系统（如容器卷、网络挂载）上的工作区启动任务、此前因 Git "mount point" 诊断被拒绝创建任务的运维者。其他人无需操作。

**解决了什么：**[#427](https://github.com/foolzzz/looper/pull/427) 让 Git 发现会在文件系统边界停止的工作区也能启动任务，并通过固定运行器和 PostgreSQL 客户端恢复 Linux Python Tests 工作流。

**是否有破坏性变更：**无。不在任何 Git 仓库内的目录仍原地运行，损坏的仓库仍会明确报错。

**如何验证：**运行 `looper --version` 核对版本为 2.13.49。

**贡献者：**维护者 @foolzzz 提交 [#427](https://github.com/foolzzz/looper/pull/427)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.49
```

### 行为变化与入口

- 工作区发现：仓库查找现在以 `GIT_DISCOVERY_ACROSS_FILESYSTEM=1` 运行 `git rev-parse`，不再在挂载点停止。位于其他文件系统上的仓库内的工作区会像普通工作区一样被找到并隔离，直到根目录都没有仓库的工作区原地运行。只有完整发现的消息和 `this operation must be run in a work tree` 才表示"不是仓库"；挂载点诊断、无效的显式 Git 目录、无法读取的 HEAD、超时及其他检查失败仍抛出工作区错误，绝不回退为原地运行。该共享检查同时服务 dashboard、Telegram、Lark 和 CLI 的任务创建。
- CI：Agent system tests 作业改用 `ubuntu-24.04`（原为 `ubuntu-latest`），并安装 PostgreSQL 16 客户端且置于 `PATH` 最前，使 `pg_dump`、`pg_restore` 与 PostgreSQL 16 服务一致。真实的归档恢复测试保留。
- 面向模型的变化：无。提示词、工具结果、OpenAPI 文档和渠道文案均未改动。
- 测试：PR 报告新增测试 59 行；生产代码工作区 5 行、工作流 11 行（工作流行数取自 PR 文件列表）。

### 升级与回退

v2.13.49 发布后重跑 `install.sh`，无需迁移数据。回退到 v2.13.48 即恢复在挂载边界处的拒绝行为，存储无差异。

### 可选能力启用与使用

本版本未新增可选能力启用入口。
