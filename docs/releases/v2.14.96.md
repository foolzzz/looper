# Looper v2.14.96

This is the patch release v2.14.96, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.95: follow-ups of provider enable/disable, so a config import cannot switch an Agent Profile to a disabled provider and the disable warning of a scoped Manager stays within what it may see ([#1130](https://github.com/foolzzz/looper/pull/1130)).

## Release Decision

**Who should upgrade:** Operators who disable LLM providers and import configurations, or who run own-scope Managers that can disable providers. Everyone else can stay.

**What this release solves:** A config import could create or switch an Agent Profile to a model of a disabled provider, which the profile API already refused; the warning given when a scoped Manager disabled a provider could describe usage by other Managers; and the built-in profile's warning hid its explicit selections. [#1130](https://github.com/foolzzz/looper/pull/1130) fixes these, and marks profiles of disabled providers in the dashboard role editor. No change while every provider is enabled.

**Breaking changes:** No. No schema change and no API change.

**How to verify:** Check the installed version. In the dashboard, disable a provider and open a role editor: its profiles are marked "provider disabled".

```bash
looper --version   # looper 2.14.96
```

**Contributors:** Maintainer @foolzzz authored [#1130](https://github.com/foolzzz/looper/pull/1130); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.95 upgrades directly. There is no database change.

## Behavior changes

- **Config import refuses disabled-provider bindings** (`looper/agents/config_transfer.py`, `looper/agents/profile_registry.py`). Importing an Agent Profile that is new, or whose model changes, now fails for that profile when the model's provider is disabled ("provider ... is disabled; enable it in Settings → LLM Providers, or choose a model of another provider"). An import that keeps the profile's current model is still allowed. Profile create and update use the same helper (`check_profile_model`); their behavior is unchanged.
- **Disable warning stays in the caller's scope** (`looper/agents/ops/config.py`, `looper/agents/profile_registry.py`). When a scoped Manager disables a provider, the usage lookup is limited to that Manager (its tasks, session, own profile and templates). The disable itself is never refused, and an unscoped caller sees the same warnings as before.
- **Built-in profile warning** (`looper/agents/profile_registry.py`). Disabling the provider of `claude-code/opus` reports its explicit selections as well as the fallback note, in one warning (before, the selections were not listed).
- **Dashboard role editor** (`web/src/components/role-editor.tsx`). A profile whose provider is disabled shows "· provider disabled" after its name.
- **Unchanged:** the schema, the API shape, the CLI, channels, and everything while all providers are enabled.
- **Documentation and tests.** Updated `tests/test_llm_provider_enabled_db.py`; added `web/src/components/role-editor.test.tsx`.
- **Model-visible changes:** Yes, small. The warnings that the provider tool returns to a Manager when it disables a provider are limited to that scoped Manager's own usage, and the built-in profile's warning is joined with its selection note. The error a Manager-run config import returns for a disabled provider's model is new. No tool description or prompt text changes.

## 中文摘要

本版本是 patch release v2.14.96（热修线，每个合并的改动立即发布）。自 v2.14.95 以来只合并了一项改动：服务商启用/停用的后续修复——配置导入不能再把 Agent Profile 切到已停用服务商，受限管家的停用警告也只含其可见范围（[#1130](https://github.com/foolzzz/looper/pull/1130)）。

### 升级决策

**谁需要升级：**停用 LLM 服务商并导入配置的运维人员，或运行可停用服务商的 own 范围管家的人员。其他人可不升级。

**解决了什么：**配置导入可以创建或切换到已停用服务商的模型，而 profile API 本已拒绝；受限管家停用服务商时的警告可能描述其他管家的使用；内置 profile 的警告隐藏了显式选择。[#1130](https://github.com/foolzzz/looper/pull/1130) 修复这几点，并在仪表盘角色编辑器中标出服务商已停用的 profile。所有服务商均启用时无变化。

**是否有破坏性变更：**否。无结构变更，无 API 变更。

**如何验证：**核对版本为 2.14.96。在仪表盘停用某服务商并打开角色编辑器：其 profile 会标注 “provider disabled”。

**贡献者：**维护者 @foolzzz 提交 [#1130](https://github.com/foolzzz/looper/pull/1130)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.96
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.95 上的安装可直接升级。无数据库变更。

### 行为变化与入口

- **配置导入拒绝绑定到已停用服务商**（`looper/agents/config_transfer.py`、`looper/agents/profile_registry.py`）。导入新建的、或模型有变化的 Agent Profile，若模型的服务商已停用，该 profile 导入失败（提示启用该服务商或选择其他服务商的模型）。保持当前模型的导入仍允许。创建和更新 profile 使用同一个函数（`check_profile_model`），行为不变。
- **停用警告限于调用者范围**（`looper/agents/ops/config.py`、`looper/agents/profile_registry.py`）。受限管家停用服务商时，使用情况查询仅限该管家（其任务、会话、自有 profile 和模板）。停用本身从不被拒绝，不受限的调用者看到的警告与之前相同。
- **内置 profile 的警告**（`looper/agents/profile_registry.py`）。停用 `claude-code/opus` 的服务商时，除回退说明外也报告其显式选择，合并为一条警告（原来不列出这些选择）。
- **仪表盘角色编辑器**（`web/src/components/role-editor.tsx`）。服务商已停用的 profile 在名称后显示 “· provider disabled”。
- **不变：**数据库结构、API 形状、CLI、渠道，以及所有服务商均启用时的一切。
- **文档与测试。**更新 `tests/test_llm_provider_enabled_db.py`；新增 `web/src/components/role-editor.test.tsx`。
- **面向模型的变化：**有，较小。管家停用服务商时 provider 工具返回的警告限于该受限管家自身的使用，内置 profile 的警告与选择说明合并；管家运行的配置导入遇到已停用服务商的模型时会返回新的错误。工具描述和提示文本不变。
