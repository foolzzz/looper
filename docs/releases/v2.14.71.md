# Looper v2.14.71

This is the patch release v2.14.71, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.70: fixes found by validating kept runs on an isolated launchd service ([#1066](https://github.com/foolzzz/looper/pull/1066)).

## Release Decision

**Who should upgrade:** Installations that run with the keeper on and upgrade or restart the service with `looper service upgrade` or `looper service restart`, especially on systemd. Others see no change.

**What this release solves:** the validation of kept runs found four reporting and planning gaps: runs ended at startup were not reported, Manager and Planner turns cut at a `CONTROL_PLANE` deadline were not listed, systemd's effective `KillMode` (drop-ins included) was not read, and an incompatible unit got a misleading plan. [#1066](https://github.com/foolzzz/looper/pull/1066) fixes each with a regression test. The default keeper mode stays `off`.

**Breaking changes:** No. The upgrade report and the `kept_runs` check only gain fields and detail text, and there is no migration.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#1066](https://github.com/foolzzz/looper/pull/1066); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.71
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.70 upgrades directly. This release adds no migration.

## Behavior changes

- **Runs ended at startup.** The deployment report of a `CONTROL_PLANE` upgrade adds `ended_at_start` (reason counts from `keepers.ended_at_start`), and a nonzero count adds the P1 alert, as incomplete or failed adoption already did (`looper/agents/service.py`). The `kept_runs` check of `system.status.checks` also fires on runs ended at startup, and its detail adds `ended at start: <n>` (`looper/agents/http_server.py`).
- **Cut turns.** For a `CONTROL_PLANE` upgrade the report adds `cut_turns`, one `{agent_id, role}` entry per Manager or Planner turn still running at the deadline (an empty list when none). Full drains do not get the field.
- **Effective `KillMode` on systemd.** `Systemd.kill_mode_ok` now asks `systemctl --user show <unit> -p KillMode`, so drop-ins count, instead of reading the unit file text. A missing unit file still counts as fine; a failed `systemctl show` counts as incompatible.
- **Upgrade plan for an incompatible unit.** With keeper mode on and a unit whose effective `KillMode` is not `process`, a plan of `CONTROL_PLANE` or `FULL` becomes `FULL` with only the reinstall reason (before, the reinstall reason was appended to the other reasons, and the unit also changed how `decide` ran). Other plan kinds are no longer rewritten.
- **Documentation and evidence.** `docs/architecture/agent-system.md` describes these points. `docs/validation/kept-runs/` adds the launchd validation record with scripted CLI peers.
- **Size:** per the pull request description, 20 added lines of production code and 46 of tests (fixtures excluded).
- **Model-visible changes:** No. No prompt, tool description or tool result changed.

### 升级决策

**谁需要升级：**开启 keeper、并使用 `looper service upgrade` 或 `looper service restart` 升级或重启服务的安装，尤其是 systemd。其他安装没有变化。

**是否有破坏性变更：**否。升级报告和 `kept_runs` 检查只新增字段和详情文字，没有迁移。

**如何验证：**运行 `looper --version` 核对版本为 2.14.71。

**贡献者：**维护者 @foolzzz 提交 [#1066](https://github.com/foolzzz/looper/pull/1066)；本版本无社区贡献。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.70 上的安装可直接升级。本版本没有迁移。

### 行为变化与入口

- **启动时结束的运行。**`CONTROL_PLANE` 升级的部署报告新增 `ended_at_start`（来自 `keepers.ended_at_start` 的原因计数），计数非零时加入 P1 告警，与接管不完整或失败时一致（`looper/agents/service.py`）。`system.status.checks` 的 `kept_runs` 检查也会在有运行于启动时结束时触发，详情新增 `ended at start: <n>`（`looper/agents/http_server.py`）。
- **被打断的回合。**`CONTROL_PLANE` 升级的报告新增 `cut_turns`，每个在截止时仍在运行的 Manager 或 Planner 回合对应一条 `{agent_id, role}`（没有时为空列表）。完整排空不带该字段。
- **systemd 的有效 `KillMode`。**`Systemd.kill_mode_ok` 现在通过 `systemctl --user show <unit> -p KillMode` 读取，drop-in 也算在内，而不再读取 unit 文件文本。unit 文件不存在仍视为正常；`systemctl show` 失败视为不兼容。
- **不兼容 unit 的升级计划。**keeper 模式开启且 unit 的有效 `KillMode` 不是 `process` 时，`CONTROL_PLANE` 或 `FULL` 计划变为 `FULL`，且只带重装原因（此前是在其他原因后追加重装原因，并且该 unit 还会改变 `decide` 的运行方式）。其他计划类型不再被改写。
- **文档与证据。**`docs/architecture/agent-system.md` 描述了这些点。`docs/validation/kept-runs/` 新增使用脚本化 CLI 对端的 launchd 验证记录。
- **规模：**据 PR 描述，生产代码新增 20 行，测试新增 46 行（不含 fixture）。
- **面向模型的变化：**无。没有提示、工具说明或工具结果变化。
