# Looper v2.13.5

## Release Decision

**Who should upgrade:** Operators who run any Looper role (Manager, Planner, Worker, Reviewer) on the OMP runtime, especially those who saw a Manager turn fail with "no reply" after a long shell command. Operators who use only Claude Code or Codex need no change.

**What this release solves:** [#271](https://github.com/foolzzz/looper/pull/271) stops OMP from moving a long `bash` or `eval` command to the background on its own, which could end the turn without its result, and makes the Manager's "no reply" error name the runtime that actually ran.

**Breaking changes:** No. The API, configuration, registry schema, CLI, channels and dashboard are unchanged from [v2.13.4](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.4.md).

**How to verify:** Check the version. On an OMP-backed role, run a command that outlasts omp's background threshold and confirm the turn waits for it and returns its result.

**Contributors:** Maintainer @foolzzz authored [#271](https://github.com/foolzzz/looper/pull/271); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.5
```

## Behavior changes

- **OMP runtime, settings overlay:** `overlay` (`looper/agents/runtimes/omp.py`) now also sets `bash.autoBackground.enabled` and `eval.autoBackground.enabled` to `false`, beside the existing `async.enabled: false`. The overlay applies to every role run on OMP. A long `bash` or `eval` command now blocks its turn until it ends instead of being backgrounded; omp no longer continues the conversation after the turn when a backgrounded command finishes. A command that runs very long therefore holds its turn for that time.
- **OMP runtime, launch home:** The OMP home directory name is derived from the overlay content, so the changed overlay yields a new home directory per launch configuration. The captured launch fixtures were regenerated accordingly. No setting other than the two above changed.
- **Manager failure text:** When a Manager turn returns no content, the error reads `<runtime label> 没有返回内容` (with the exit code when the process exited), taking the label from the launch's runtime, where it always said "Claude Code". For Claude Code the text is unchanged. The PR description also mentions Planner and Worker failure texts; the diff changes only the Manager (`looper/agents/tiers/manager.py`).
- **API:** None.
- **Model-visible changes:** None to prompts, tools, Manager schema or model-facing text. The OMP overlay is a runtime setting, not model text; its effect on the model is that tool calls for long commands return their result in the same turn rather than a background-job notice. The error text above is shown to the user, not the model.

## Entry points

- **OMP-backed roles:** Every launch through the OMP runtime, as above.
- **Manager chat (Telegram/Lark/dashboard):** The "no reply" error text, as above.
- **CLI, Manager tools and prompts, dashboard:** No change.

## Upgrade and rollback

No action is needed beyond the usual re-run of `install.sh` once v2.13.5 is published; there is no configuration, data or migration change. Rolling back to v2.13.4 is safe: OMP again backgrounds long commands on its own and the error text says "Claude Code" for every runtime.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**在 OMP runtime 上运行任一 Looper 角色（Manager、Planner、Worker、Reviewer）的运维者，尤其是遇到 Manager 在长时间 shell 命令后报“没有返回内容”的人。仅使用 Claude Code 或 Codex 的运维者无需变动。

**解决了什么：**[#271](https://github.com/foolzzz/looper/pull/271) 禁止 OMP 自行把耗时较长的 `bash` 或 `eval` 命令转入后台（这可能使该轮结束时没有结果），并让 Manager 的“没有返回内容”错误写出实际运行的 runtime。

**是否有破坏性变更：**无。API、配置、registry schema、CLI、渠道和仪表盘与 [v2.13.4](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.4.md) 相同。

**如何验证：**核对版本。在 OMP 角色上运行一个超过 omp 后台阈值的命令，确认该轮会等待命令结束并返回结果。

**贡献者：**维护者 @foolzzz 提交 [#271](https://github.com/foolzzz/looper/pull/271)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.5
```

### 行为变化与入口

- OMP 设置覆盖层（`looper/agents/runtimes/omp.py` 的 `overlay`）在原有 `async.enabled: false` 之外，新增 `bash.autoBackground.enabled` 与 `eval.autoBackground.enabled` 为 `false`，对 OMP 上的所有角色生效。耗时较长的 `bash`/`eval` 命令现在会阻塞本轮直到结束，不再被转入后台，omp 也不会在该轮结束后因后台命令完成而继续对话。命令运行很久时，该轮会相应被占用更久。
- OMP 的 home 目录名由覆盖层内容派生，因此覆盖层变化后每种启动配置会得到新的 home 目录；已捕获的启动 fixture 随之重新生成。除上述两项外没有其他设置变化。
- Manager 一轮无内容返回时，错误文本为“<runtime 名> 没有返回内容”（进程已退出时附退出码），名称取自本次启动的 runtime，此前一律写“Claude Code”。Claude Code 下文本不变。PR 描述还提到 Planner 与 Worker 的失败文本，但代码差异只改了 Manager（`looper/agents/tiers/manager.py`）。
- API 无变化。提示词、工具、Manager schema 与面向模型的文本无变化；OMP 覆盖层是运行时设置，对模型的影响仅是长命令的工具调用在同一轮内返回结果，而不是后台任务通知。错误文本展示给用户，不给模型。
- CLI、Manager 工具和提示词、仪表盘均无变化。

### 升级与回退

发布后照常重跑 `install.sh` 即可，无配置、数据或迁移变更；回退到 v2.13.4 同样安全：OMP 会重新自行后台化长命令，错误文本对所有 runtime 都写“Claude Code”。
