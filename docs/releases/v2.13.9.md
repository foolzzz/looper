# Looper v2.13.9

## Release Decision

**Who should upgrade:** Operators who talk to the Manager on Lark or Telegram and want to see, answer and end the user gates waiting for them from the same chat. Everyone else sees no change.

**What this release solves:** [#277](https://github.com/foolzzz/looper/pull/277) adds `/gates` and `/gate` so a user gate can be listed, answered and ended from a Lark or Telegram chat, deterministically and without the Manager's model.

**Breaking changes:** No. The CLI, configuration, database schema and API routes are unchanged from [v2.13.8](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.8.md). A message that is not `/gates`, `/gate` or a reply under a gate's card is handled as before.

**How to verify:** Check the version, then send `/gates` to the Manager in a Lark or Telegram chat.

**Contributors:** Maintainer @foolzzz authored [#277](https://github.com/foolzzz/looper/pull/277); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.9
```

## Behavior changes

- **`/gates`.** Looper answers it itself before the Manager's model, and neither the command nor the reply is stored in the Manager's chat history. In a private chat (and the web chat) it lists up to 20 user gates that wait for the user, across chats and tasks; in a group chat it lists that group's. Each entry is numbered and shows the task, the step, the topic, how long it has waited and its open questions with their options.
- **`/gate N <answer>` and `/gate N end`.** `/gate N <answer>` adds the answer to gate N as the user's message; `/gate N end` ends the discussion and asks the Planner to close the gate on what is settled. Both go through the gate service with `via` `command:<channel>`. Telegram's `/gate@bot` form works. Anything else (no number, no answer) gets a usage line.
- **Numbering.** Numbers refer to a snapshot of the last list delivered to that chat for that sender, kept for one hour. A list that the channel failed to deliver never becomes the snapshot. With no snapshot, an unknown number, or a gate that no longer waits (not found or already closed), the reply says so and sends a fresh list.
- **Reply `end`.** A reply under a gate's card with exactly `end` or `/end` ends the gate instead of being added as a message.
- **Receipts.** After an answer or end reaches a gate, code replies with a receipt in Chinese naming the task and step. This now also applies to an ordinary reply under a gate's card, which was silent before. For a task that is not running the receipt says the answer (or request to end) is saved and goes to the Planner when the task continues; the old fixed text is replaced by this one.
- **Authority.** Anyone on the channel's sender allowlist may answer or end a gate; there is no owner check. In a Lark group the @-mention is needed.
- **Telegram.** Registers `/gates` and `/gate` as handlers, in the bot menu and in the `/help` text; the text is forwarded as typed.
- **Model-visible changes:** None. The commands and their replies are intercepted in code and are not shown to the model; no prompt or tool schema changed.

## Entry points

New: `/gates` and `/gate N <answer|end>` in Lark and Telegram Manager chats, and `end` as a reply under a gate's card. No CLI command or HTTP route was added.

## Upgrade and rollback

Re-run `install.sh` once v2.13.9 is published. There is no schema or configuration change. Rolling back to v2.13.8 is safe: the commands simply stop being recognized.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 行为变化与入口

- `/gates`：由 Looper 在 Manager 模型之前自己回答，命令和回复都不存入 Manager 的聊天历史。私聊（和网页聊天）列出跨聊天、跨任务最多 20 个在等用户的关卡，群聊只列该群的。每项带编号、任务、步骤、主题、已等时长和未决问题及选项。
- `/gate N <回答>` 与 `/gate N end`：前者把回答作为用户消息加入第 N 个关卡；后者结束讨论，请规划者按现有结论关闭关卡。均经关卡服务，`via` 为 `command:<渠道>`；Telegram 的 `/gate@bot` 形式可用；缺编号或回答时回复用法。
- 编号：以该聊天、该发送者最近一次成功送达的列表为快照，保留一小时；未送达的列表不会成为快照。没有快照、编号不存在、或关卡已不在等待时，回复原因并附上新列表。
- 回复 `end`：在关卡卡片下回复恰好为 `end` 或 `/end` 时，结束该关卡而不是作为消息。
- 回执：回答或结束送达关卡后，代码回复带任务名和步骤的中文回执；普通的卡片回复现在也有回执（此前无声）。任务未运行时，回执说明回答（或结束请求）已保存、任务继续后交给规划者，取代原先的固定文案。
- 权限：发送者白名单内的任何人都可回答或结束，不检查所有者；飞书群消息需要 @ 机器人。
- Telegram：注册 `/gates`、`/gate` 处理器，加入菜单和 `/help`，文字原样转发。未新增 CLI 命令或 HTTP 路由。
- 面向模型的变化：无。命令及回复由代码拦截，模型看不到；提示词和工具 schema 均未变。
