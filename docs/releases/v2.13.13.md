# Looper v2.13.13

## Release Decision

**Who should upgrade:** Operators who use the dashboard and refresh the page, share its links, or use the browser's Back button. Everyone else sees no change.

**What this release solves:** [#323](https://github.com/foolzzz/looper/pull/323) makes a refresh keep every dashboard page where it was. On a task page, switching to Pipeline, Room or Agents and refreshing returned to Overview; the same held for the task list's status filter and the Chat page's open agent. These choices now live in the address, so a refresh reopens the same place and Back and Forward move between them.

**Breaking changes:** No. The CLI, configuration, database schema and API routes are unchanged from [v2.13.12](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.12.md). Existing dashboard links keep working.

**How to verify:** Check the installed version, then open a task, switch to the Pipeline tab and refresh.

**Contributors:** Maintainer @foolzzz authored [#323](https://github.com/foolzzz/looper/pull/323); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.13
```

## Behavior changes

- **Task page tab in the address.** The tab (Overview, Pipeline, Room, Agents, Sessions, Conversation) is kept as `#tasks/<id>?tab=<tab>`. Overview, the default, is not written. An unknown or missing `tab` shows Overview. Opening a gate from a Pipeline node returns to Overview. The tab buttons now carry `tablist`, `tab` and `aria-selected` roles.
- **Task list status filter in the address.** The status filter is kept as `?status=<value>` next to the existing `project`, `group` and `schedule` filters; `all`, the default, is not written, and an unknown value shows `all`. Changing any filter keeps the others.
- **Chat page in the address.** The open agent is kept as `#chat?target=<agent id>`, and, with the Manager, a read-only Lark or Telegram conversation as `&conversation=<session id>`. The Manager and no conversation are not written. An unknown agent falls back to the Manager once the agents are listed. Choosing an agent or conversation, starting a new chat, a link, Back and a refresh all go through the address.
- **Model-visible changes:** None. No prompt, tool schema or tool contract changed; the change is in the operator's browser only.

## Entry points

- Dashboard addresses `#tasks/<id>?tab=<tab>`, `#tasks?status=<value>` and `#chat?target=<agent id>&conversation=<session id>`. No CLI command, route or configuration key was added.

## Upgrade and rollback

Re-run `install.sh` once v2.13.13 is published. There is no schema or configuration change. Rolling back to v2.13.12 is safe; pages then return to their default tab, filter and agent after a refresh.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 升级决策

**谁需要升级：**会刷新 dashboard 页面、分享其链接或使用浏览器后退按钮的运营者。其他人没有变化。

**解决了什么：**[#323](https://github.com/foolzzz/looper/pull/323) 让刷新后每个 dashboard 页面停在原处。此前在任务页切到 Pipeline、Room 或 Agents 后刷新会回到 Overview；任务列表的状态筛选和 Chat 页打开的 agent 也一样。这些选择现在记在地址里，刷新后回到同一处，后退和前进可在其间切换。

**是否有破坏性变更：**无。CLI、配置、数据库 schema 和 API 路由与 [v2.13.12](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.12.md) 相同；已有的 dashboard 链接仍可用。


### 行为变化与入口

- 任务页标签进地址：标签（Overview、Pipeline、Room、Agents、Sessions、Conversation）记为 `#tasks/<id>?tab=<tab>`，默认的 Overview 不写；未知或缺失的 `tab` 显示 Overview。从 Pipeline 节点打开关卡会回到 Overview。标签按钮新增 `tablist`、`tab`、`aria-selected` 角色。
- 任务列表状态筛选进地址：记为 `?status=<value>`，与已有的 `project`、`group`、`schedule` 并存；默认的 `all` 不写，未知值按 `all` 处理。改变任一筛选时保留其他筛选。
- Chat 页进地址：打开的 agent 记为 `#chat?target=<agent id>`；选 Manager 时，只读的 Lark 或 Telegram 会话记为 `&conversation=<session id>`。Manager 和无会话不写。未知 agent 在 agent 列表加载后回到 Manager。选择 agent 或会话、新建对话、链接、后退、刷新都经由地址。
- 面向模型的变化：无。提示词、工具 schema、工具契约都没有变化，只涉及 operator 的浏览器。未新增 CLI 命令、路由或配置项。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.12 安全，刷新后页面回到默认标签、筛选和 agent。

本版本未新增可选能力启用入口。
