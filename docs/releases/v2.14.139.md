# Looper v2.14.139

This is the patch release v2.14.139, a hotfix line in which each merged change ships at once. It documents two changes: [#1244](https://github.com/foolzzz/looper/pull/1244) (a Grok Planner gets the full plan view, because a Grok session cannot report compaction) and [#1238](https://github.com/foolzzz/looper/pull/1238) (workflow delivery: the completion keeps its open issues, reviews are listed once, notices are not repeated).

## Release Decision

**Who should upgrade:** Operators whose Planner runs on Grok, because the Planner's change view (v2.14.138) was unsafe there after a compaction the session never reported. Operators who receive task completion notices in chat, Lark or the web UI, and whose tasks use review steps, benefit from the delivery changes. Everyone else gets no visible change.

**What this release solves:** [#1244](https://github.com/foolzzz/looper/pull/1244) stops a Grok Planner from receiving only plan changes after its context was compacted without an event. [#1238](https://github.com/foolzzz/looper/pull/1238) keeps the open issues at the end of a long result in a web-thread completion notice, lists each review seat's verdict once per round in the Process record, shows the Planner review rounds as compact lines, renders the Process record line by line with agent text shown literally, and does not post an identical consecutive progress notice twice to the same web thread.

**Breaking changes:** No. There is no migration and no API removal. The message text a Grok Planner and every Planner receives changes (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.139
```

**Contributors:** Maintainer @foolzzz authored [#1244](https://github.com/foolzzz/looper/pull/1244) and [#1238](https://github.com/foolzzz/looper/pull/1238); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.138 upgrades directly. There is no schema change.

## Behavior changes

- **A Grok Planner gets the full plan view** ([#1244](https://github.com/foolzzz/looper/pull/1244), `looper/agents/tiers/planner.py`, `looper/agents/runtimes/grok.py`). The Planner now treats a runtime of type `grok` like a runtime without compaction events: the full plan and progress are sent every turn (reason "no compaction events"), instead of the change view. The headless Grok stream does report compaction, but the ACP resident session does not, so the capability is documented as describing the headless stream only. Other runtimes are unchanged. The Planner's cost on Grok rises back to the full view per turn.
- **The web-thread completion keeps the tail of a long result** ([#1238](https://github.com/foolzzz/looper/pull/1238), `looper/agents/tiers/manager.py`). A result over 2000 characters is no longer cut at 2000; the middle is clipped within the same budget, the last 600 characters are kept, and an omission marker states how many characters were omitted and that the full result is on the task page. The delivery summary appendix is still appended once, outside the clip.
- **No repeated progress notice.** The Manager remembers the last progress text per task and web thread and does not post an identical consecutive one again; the memory is cleared when the task ends or is cancelled.
- **Reviews are listed once** (`looper/agents/workflow_reporting.py`). The Process record lists each review seat's verdict once per step, round and seat; a later entry replaces the earlier line in place.
- **The Process record renders line by line.** The summary is a Markdown heading, then one list item per section (Roles, Reviews, Verification, Escalations), then the pointer line. The full text normalises its items to list items.
- **Agent text is shown literally.** The Lark task-end notice (`looper/agents/channels/lark.py`) and the web Markdown view (`web/src/components/markdown.tsx`) escape Markdown characters in those four Process record lists only, so agent fragments such as `run_cmd` or `*args*` are not formatted. The durable notice text is unchanged.
- **Planner review rounds** (`looper/agents/tiers/journal.py`). The Planner's journal section projects review arrivals and snapshots into the latest verdict per step, round and seat and renders each as a line: step, round (counted from 1), seat, outcome (`passed`, `failed`, `passed_by_adjudication` or pending), blocking count and a summary clipped to 160 characters. Rounds are listed newest first.
- **Unchanged:** reply contracts, decisions and dispatching, the Worker and Reviewer prompts, the Manager prompt, and the storage format of review journal entries.
- **Model-visible changes:** Yes. A Grok Planner receives the full plan view every turn ([#1244](https://github.com/foolzzz/looper/pull/1244)). Every Planner's "Progress and findings" section shows review rounds as the compact lines above, rounds counted from 1 ([#1238](https://github.com/foolzzz/looper/pull/1238)). The Manager's chat completion text is clipped differently. No protocol prompt changes.

## 中文摘要

本版本是 patch release v2.14.139（热修线，每个合并的改动立即发布），说明两项改动：[#1244](https://github.com/foolzzz/looper/pull/1244)（Grok 会话无法上报压缩，Grok Planner 改为收到完整计划视图）和 [#1238](https://github.com/foolzzz/looper/pull/1238)（工作流交付：完成通知保留未决问题、评审只列一次、不重复发送通知）。

### 升级决策

**谁需要升级：**Planner 运行在 Grok 上的运维者，因为 v2.14.138 的变更视图在 Grok 发生未上报的压缩后不安全；在聊天、Lark 或 Web 界面收到任务完成通知且任务使用评审步骤的运维者受益于交付改动。其他人没有可见变化。

**解决了什么：**[#1244](https://github.com/foolzzz/looper/pull/1244) 避免 Grok Planner 在上下文被无事件压缩后只收到计划变更。[#1238](https://github.com/foolzzz/looper/pull/1238) 让 Web 会话的完成通知保留长结果末尾的未决问题，让过程记录对每个评审席位每轮只列一次裁决，让 Planner 以紧凑行看到评审轮次，让过程记录逐行渲染且智能体文本按字面显示，并且不向同一 Web 会话重复发送相同的连续进度通知。

**是否有破坏性变更：**否。没有迁移，没有移除 API。Grok Planner 及所有 Planner 收到的消息文本有变化（见下文）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.14.139。

**贡献者：**维护者 @foolzzz 提交 [#1244](https://github.com/foolzzz/looper/pull/1244) 和 [#1238](https://github.com/foolzzz/looper/pull/1238)；本版本无社区贡献。

```bash

```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.138 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **Grok Planner 收到完整计划视图**（[#1244](https://github.com/foolzzz/looper/pull/1244)，`looper/agents/tiers/planner.py`、`looper/agents/runtimes/grok.py`）。Planner 现在把 `grok` 类型的运行时视同没有压缩事件的运行时：每轮发送完整计划和进展（原因“no compaction events”），而非变更视图。Grok 的无头流会上报压缩，但 ACP 常驻会话不会，所以该能力的注释改为只描述无头流。其他运行时不变。Grok 上 Planner 的每轮成本回到完整视图。
- **Web 会话的完成通知保留长结果的末尾**（[#1238](https://github.com/foolzzz/looper/pull/1238)，`looper/agents/tiers/manager.py`）。超过 2000 字符的结果不再从 2000 处截断；在同一预算内裁掉中间部分，保留最后 600 字符，并以省略标记说明省略的字符数和完整结果在任务页。交付摘要附录仍在裁剪之外追加一次。
- **不重复进度通知。**Manager 按任务和 Web 会话记住上一条进度文本，不再发送相同的连续通知；任务结束或取消时清除该记忆。
- **评审只列一次**（`looper/agents/workflow_reporting.py`）。过程记录对每个步骤、轮次和席位只列一次裁决；后到的条目原位替换先前的行。
- **过程记录逐行渲染。**摘要为 Markdown 标题，随后每个部分（Roles、Reviews、Verification、Escalations）一个列表项，再是指针行。完整文本把各项规范为列表项。
- **智能体文本按字面显示。**Lark 任务结束通知（`looper/agents/channels/lark.py`）和 Web Markdown 视图（`web/src/components/markdown.tsx`）仅对这四个过程记录列表转义 Markdown 字符，使 `run_cmd`、`*args*` 等智能体片段不被格式化。持久化的通知文本不变。
- **Planner 评审轮次**（`looper/agents/tiers/journal.py`）。Planner 的日志章节把评审到达和快照合并为每个步骤、轮次和席位的最新裁决，每条渲染为一行：步骤、轮次（从 1 计）、席位、结果（`passed`、`failed`、`passed_by_adjudication` 或待定）、阻塞数和截断到 160 字符的摘要。轮次按新到旧排列。
- **不变：**回复契约、决策与派发，Worker 和 Reviewer 的提示词，Manager 提示词，以及评审日志条目的存储格式。
- **面向模型的变化：**有。Grok Planner 每轮收到完整计划视图（[#1244](https://github.com/foolzzz/looper/pull/1244)）；所有 Planner 的“Progress and findings”章节以上述紧凑行显示评审轮次，轮次从 1 计（[#1238](https://github.com/foolzzz/looper/pull/1238)）。Manager 的聊天完成文本裁剪方式不同。协议提示词没有变化。
