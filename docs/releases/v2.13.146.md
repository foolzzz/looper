# Looper v2.13.146

## Release Decision

**Who should upgrade:** Operators who import a configuration file whose task template for an already-existing template omits its `name`. Everyone else can stay on v2.13.145.

**What this release solves:** [#697](https://github.com/foolzzz/looper/pull/697) accepts such an import, as the overlay rule from #689 intends, in the HTTP preview and upload paths too; before, the schema check rejected the file.

**Breaking changes:** No. Exports and the `ConfigDocument` schema are unchanged; a new import-only schema is added.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#697](https://github.com/foolzzz/looper/pull/697); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.146
```

## Behavior changes

- **Import schema (#697):** `looper/agents/api_v1.py` turns `MANAGER_CONFIG` into a `_manager_config(template)` builder and adds `CONFIG_IMPORT_DOCUMENT`, whose manager templates require only `key` (the newest document version branch is replaced the same way). `CONFIG_DOCUMENT`, which `config.export` returns, still requires the complete template identity.
- **Upload and preview routes (#697):** `looper/agents/v1_domains/configuration.py` registers `ConfigImportDocument` and uses it as the input schema of `config.import_upload` and in `receive`; `looper/agents/http_server.py` validates the raw upload with it. The tests cover the `import_preview` and `import_upload` routes.
- **Post-merge check (#697):** `looper/agents/config_transfer.py` merges an omitted field from the stored template; after the merge a template whose `name` is missing or blank fails with `ConfigFileError("<manager>/<key>: name must be non-empty")`, so a new template still needs a name and the error names its key.
- **Tests (#697):** `tests/test_api_v1_manager_config_transfer.py` adds three tests (71 lines): the import schema allows an omitted name while export still requires it; an import without a name keeps the stored name; a new template without a name is rejected with the key in the error.
- **Model-visible changes:** none. No prompt, tool declaration or tool result changes. The published API schemas gain `ConfigImportDocument`, which is visible to API clients only.
- **Line counts:** the description reports tests 71 and production 30 added lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.146 is published. No schema migration. Rolling back to v2.13.145 makes such an import fail the schema check again; stored data is unaffected.

### 行为变化与入口

- **导入 schema（#697）：**`looper/agents/api_v1.py` 把 `MANAGER_CONFIG` 改为 `_manager_config(template)` 构造函数，并新增 `CONFIG_IMPORT_DOCUMENT`，其 manager 模板只要求 `key`（最新文档版本分支同样替换）。`config.export` 返回的 `CONFIG_DOCUMENT` 仍要求完整的模板标识。
- **上传与预览路径（#697）：**`looper/agents/v1_domains/configuration.py` 注册 `ConfigImportDocument`，作为 `config.import_upload` 的输入 schema 并用于 `receive`；`looper/agents/http_server.py` 用它校验原始上传。测试覆盖 `import_preview` 和 `import_upload` 两条路径。
- **合并后检查（#697）：**`looper/agents/config_transfer.py` 会从已存模板补全省略字段；合并后 `name` 缺失或为空的模板以 `ConfigFileError("<manager>/<key>: name must be non-empty")` 失败，因此新模板仍需提供名称，错误信息带有其 key。
- **测试（#697）：**`tests/test_api_v1_manager_config_transfer.py` 新增三个测试（71 行）：导入 schema 允许省略名称而导出仍要求；省略名称的导入保留已存名称；缺名称的新模板被拒绝且错误含 key。
- **面向模型的变化：**无。提示词、tool 声明和工具结果均不变。公开的 API schema 新增 `ConfigImportDocument`，仅 API 客户端可见。
- **行数：**描述报告新增测试 71 行、生产代码 30 行（不含 fixtures）。
