# Looper v2.14.137

This is the patch release v2.14.137, a hotfix line in which each merged change ships at once. It documents one change: [#1236](https://github.com/foolzzz/looper/pull/1236) (Workers wait without spending, with the waiting report).

## Release Decision

**Who should upgrade:** Operators whose Workers run on Claude Code and wait for long commands, Monitors or jobs, because such a Worker no longer has to call `looper_room_inbox` with `wait_seconds` over and over, one model request each. Everyone else gets no visible change.

**What this release solves:** [#1236](https://github.com/foolzzz/looper/pull/1236) lets a Claude Code Worker end a turn with a typed waiting report and stay idle, with no model requests, until background work reports, a message arrives or its timer expires.

**Breaking changes:** No. There is no migration and no API removal. A Worker turn on Claude Code that ends with a valid waiting report no longer ends the run (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.137
```

**Contributors:** Maintainer @foolzzz authored [#1236](https://github.com/foolzzz/looper/pull/1236); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.136 upgrades directly. There is no schema change.

## Behavior changes

- **A Worker can wait with a waiting report** ([#1236](https://github.com/foolzzz/looper/pull/1236)). On a runtime that takes run input and runs turns of its own after background work (`waits_without_turns` in `looper/agents/runtimes/__init__.py`; Claude Code), a work (not verification) turn that ends with `{"status": "waiting", "waiting_for": "...", "check_after_seconds": N}` no longer ends the run. `waiting_for` is a text of 1 to 300 characters and `check_after_seconds` an integer from 30 to 1800. Stdin stays open and no model request is made while idle. The next turn starts when a background command, agent or Monitor reports, a room, Planner or user message arrives, or Looper sends a `[Looper]` check when the timer expires. The run ends on a final report, a second invalid turn, the run timeout, a budget cap or a kill, all unchanged.
- **Check and repair messages.** Looper writes a `[Looper]` check into the run when the timer expires. If a waiting report is invalid, or a turn ends without a JSON report while the Worker was waiting, Looper writes one repair message; a second such turn ends the run.
- **Room reminders while waiting.** Reminders are written while a Worker waits, even with no tool call running (`looper/agents/tiers/worker.py`). A reminder-only turn that does not end with a status report keeps the outcome before it. While waiting, the dashboard activity of the task records "Worker waits for: …" and "Worker resumed while waiting".
- **Restart.** An adopted run that was waiting gets an immediate check; if a budget cap was hit meanwhile, the run ends with the capped result.
- **A run that ends while waiting is judged failed:** "the Worker ended while waiting for: …" (`judge_result`), and the failure text of a stopped read adds the same suffix.
- **Unchanged:** `room_wait_max_seconds`, the `looper_room_inbox` tool, Reviewer and verification runs, and the other runtimes.
- **Model-visible changes:** Yes. On Claude Code, the work contract of a Worker's system prompt gains a "Waiting for something that takes a while" section (`WAITING_CONTRACT` in `looper/agents/system_prompt.py`), also shown in the prompt preview; the Worker also receives the `[Looper]` check and repair messages and room reminders described above. The contract of other runtimes, the review contract and the Planner and Manager prompts do not change. The pull request states that the real-mode prompt eval runs before merge.

### 升级决策

**谁需要升级：**Worker 运行在 Claude Code 上并需要等待长命令、Monitor 或任务的运维者，因为这类 Worker 不必再反复调用带 `wait_seconds` 的 `looper_room_inbox`（每次一个模型请求）。其他人没有可见变化。

**解决了什么：**[#1236](https://github.com/foolzzz/looper/pull/1236) 让 Claude Code Worker 以带类型的等待报告结束一轮并保持空闲、不发模型请求，直到后台任务汇报、有消息到达或定时器到期。

**是否有破坏性变更：**否。没有迁移，没有移除 API。Claude Code 上以有效等待报告结束的 Worker 轮次不再结束运行（见下文）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.14.137。

**贡献者：**维护者 @foolzzz 提交 [#1236](https://github.com/foolzzz/looper/pull/1236)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.137
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.136 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **Worker 可用等待报告等待**（[#1236](https://github.com/foolzzz/looper/pull/1236)）。在接受运行输入、且在后台任务后会自行开启轮次的运行时上（`looper/agents/runtimes/__init__.py` 的 `waits_without_turns`；Claude Code），工作（非验证）轮次以 `{"status": "waiting", "waiting_for": "...", "check_after_seconds": N}` 结束时不再结束运行。`waiting_for` 为 1 至 300 个字符，`check_after_seconds` 为 30 至 1800 的整数。stdin 保持打开，空闲时不发模型请求。下一轮在后台命令、agent 或 Monitor 汇报、房间/Planner/用户消息到达，或定时器到期时 Looper 发出 `[Looper]` 检查时开始。运行仍在最终报告、第二次无效轮次、运行超时、预算上限或被终止时结束，均不变。
- **检查与修复消息。**定时器到期时 Looper 向运行写入 `[Looper]` 检查。等待报告无效，或 Worker 等待期间某一轮结束时没有 JSON 报告，Looper 写入一次修复消息；再次出现则结束运行。
- **等待期间的房间提醒。**即使没有工具调用在运行，Worker 等待时也会写入房间提醒（`looper/agents/tiers/worker.py`）。只回应提醒且没有以状态报告结束的轮次保留其之前的结果。等待期间任务的仪表盘活动记录“Worker waits for: …”和“Worker resumed while waiting”。
- **重启。**被接管的等待中运行会立即收到一次检查；若期间已达预算上限，运行以封顶结果结束。
- **等待中结束的运行判为失败：**“the Worker ended while waiting for: …”（`judge_result`），读取中断的失败文本也追加同样的后缀。
- **不变：**`room_wait_max_seconds`、`looper_room_inbox` 工具、Reviewer 与验证运行，以及其他运行时。
- **面向模型的变化：**有。在 Claude Code 上，Worker 系统提示词的工作契约新增“Waiting for something that takes a while”一节（`looper/agents/system_prompt.py` 的 `WAITING_CONTRACT`），提示词预览中同样可见；Worker 还会收到上述 `[Looper]` 检查、修复消息和房间提醒。其他运行时的契约、评审契约以及 Planner 和 Manager 的提示词不变。PR 称真实模式提示词评测在合并前运行。
