# Looper v2.14.146

This is the patch release v2.14.146, a hotfix line in which each merged change ships at once. It documents one change: [#1259](https://github.com/foolzzz/looper/pull/1259) (run errors: key-shaped values are redacted everywhere, a Codex reviewer's refusal reaches its run error, and coco's model refusal falls back like Codex's).

## Release Decision

**Who should upgrade:** Operators who run Codex or coco Workers or Reviewers, or any launcher whose stderr ends up in a run error or a fallback reason, because key-shaped values and terminal escape codes no longer reach those texts and a coco model refusal now moves to the fallback profile. Everyone else gets no visible change.

**What this release solves:** [#1259](https://github.com/foolzzz/looper/pull/1259) passes the stderr that goes into run errors and fallback reasons through both registered-secret redaction and key-pattern masking, strips ANSI codes, keeps a Codex reviewer's refusal in its run error, and decides the Codex refusal rules by runtime family so coco is covered.

**Breaking changes:** No. There is no migration and no API removal. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.146
```

**Contributors:** Maintainer @foolzzz authored [#1259](https://github.com/foolzzz/looper/pull/1259); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.145 upgrades directly. There is no schema change.

## Behavior changes

- **Run errors and fallback reasons are masked for key-shaped values** ([#1259](https://github.com/foolzzz/looper/pull/1259), `looper/agents/tiers/worker.py`). The Worker's failure detail, the fallback reason and the stderr carried by an "ended without a result" error now pass through `redact` and then `safe_error`, on every launcher. `safe_error` masks `sk-` keys, `Bearer` tokens, `Authorization` headers and `api_key`, `access_token` or `secret` assignments, and the clipping happens after masking.
- **ANSI codes are stripped** (`looper/agents/log_redaction.py`, `looper/agents/runtimes/omp.py`). A new `strip_ansi` removes CSI sequences, OSC titles and links, and single-character escapes; `safe_error` applies it first, so every use of `safe_error` (the OMP runtime's own errors included) loses terminal escapes from its text.
- **A Codex reviewer's refusal reaches its run error** (`looper/agents/tiers/worker.py`). For a reviewer run whose result event is an error, the run error is now the outcome summary. Before, only a Worker's failed outcome set the error, and a review run was recorded without it. A review that says "not passed" is still a successful run with no error.
- **coco falls back like Codex** (`looper/agents/tiers/worker.py`). The Codex rules (the error text of an error result becomes the failure detail; an error result without `num_turns` is a launch refusal before any model event) are now chosen by the adapter family, `isinstance(runtime, CodexRuntime)`, instead of the type string `codex`. coco's runtime subclasses `CodexRuntime`, so a coco model refusal now falls back to the next profile in the same step attempt.
- **Unchanged:** the storage format, the ordered fallback chain, the rule that a switch stays in the same step attempt without consuming a retry, and Planner behavior. Dashboard, CLI, Telegram and Lark use the shared records and need no entry-point change.
- **Model-visible changes:** No prompt, tool or message sent to a model changes. Only the failure text shown to operators, the run error recorded for a reviewer and the choice of profile for a coco retry change.

**是否有破坏性变更：**否。没有迁移，没有移除 API。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.145 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **运行错误与回退原因遮蔽形似密钥的值**（[#1259](https://github.com/foolzzz/looper/pull/1259)，`looper/agents/tiers/worker.py`）。Worker 的失败详情、回退原因以及“ended without a result”错误携带的 stderr，现在在所有启动器上先经 `redact` 再经 `safe_error`。`safe_error` 遮蔽 `sk-` 密钥、`Bearer` 令牌、`Authorization` 头以及 `api_key`、`access_token`、`secret` 赋值，并且先遮蔽后截断。
- **去除 ANSI 码**（`looper/agents/log_redaction.py`、`looper/agents/runtimes/omp.py`）。新增 `strip_ansi`，移除 CSI 序列、OSC 标题与链接以及单字符转义；`safe_error` 首先应用它，因此所有使用 `safe_error` 的地方（包括 OMP 运行时自身的错误）文本中都不再含终端转义。
- **Codex 评审者的拒绝进入其运行错误**（`looper/agents/tiers/worker.py`）。评审运行的结果事件为错误时，运行错误现在取结果摘要。此前只有 Worker 的失败结果才设置错误，评审运行记录不带错误。说“未通过”的评审仍是成功运行，没有错误。
- **coco 像 Codex 一样回退**（`looper/agents/tiers/worker.py`）。Codex 规则（错误结果的错误文本成为失败详情；没有 `num_turns` 的错误结果是任何模型事件之前的启动被拒）现在按适配器家族 `isinstance(runtime, CodexRuntime)` 选择，而不是类型字符串 `codex`。coco 运行时继承 `CodexRuntime`，因此 coco 的模型拒绝现在会在同一步骤尝试内回退到下一个 profile。
- **不变：**存储格式、有序回退链、切换留在同一步骤尝试且不消耗重试，以及 Planner 行为。Dashboard、CLI、Telegram 和 Lark 使用共享记录，无需改动入口。
- **面向模型的变化：**无。发给模型的提示词、工具和消息都不变，只有展示给运维者的失败文本、评审者记录的运行错误以及 coco 重试所选的 profile 会变。
