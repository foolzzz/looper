# Looper v2.13.122

## Release Decision

**Who should upgrade:** Nobody needs this release for its behavior. It changes only tests, which pin the existing per-conversation chat draft handling.

**What this release solves:** [#638](https://github.com/foolzzz/looper/pull/638) adds regression coverage showing that an unsent chat draft stays with its own Manager and conversation, and removes a timing race from two existing browser tests. No shipped code changed.

**Breaking changes:** No. No command, option, route, configuration or stored data format changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#638](https://github.com/foolzzz/looper/pull/638); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.122
```

## Behavior changes

- **None in shipped code:** the merged diff of [#638](https://github.com/foolzzz/looper/pull/638) touches only `tests/test_chat_navigation_browser.py` and `web/src/pages/chat-manager-picker.test.tsx`. The behavior the new tests exercise, keeping each unsent draft per Manager and session in the browser's session storage, was released in v2.13.120.
- **New test, browser:** `test_unsent_drafts_belong_to_each_conversation_and_manager` types drafts in two sessions and checks each is restored when switching back. It opens a known Lark link, a known Telegram link and an unknown id and checks the draft returns after going back. It switches to another Manager and checks that Manager's draft is separate and survives a reload, that clearing a draft leaves it empty, and that no `operator_chat/send` call is made.
- **New test, component:** `keeps each Manager's unsent draft separate` in `chat-manager-picker.test.tsx` checks that two Managers keep separate drafts, that the drafts are stored under `looper-chat-draft:<manager>:<session>` session-storage keys, and that the stored chat session id and send calls are untouched. The test setup now also clears session storage.
- **Test race fix:** two existing browser tests (`test_answered_while_hidden_restores_queue_to_original_draft`, `test_unsent_text_survives_hidden_completion_and_writable_detour`) now wait for the history of `session-b` to render before pressing Enter, because the draft is restored before the history request finishes.
- **Model-visible changes:** none. No tool declaration, prompt, route or text sent to Workers changed.
- **Line counts:** the description of [#638](https://github.com/foolzzz/looper/pull/638) reports tests 51 and production 29 (fixtures excluded). The diff has 51 added lines in the browser test file and 29 in the component test file, all test files, so the "production 29" figure counts the component test.

## Upgrade and rollback

Re-run `install.sh` once v2.13.122 is published. No data migration and no configuration change. Rolling back to v2.13.121 removes only the added tests.

### 行为变化与入口

- **发布代码无变化：**[#638](https://github.com/foolzzz/looper/pull/638) 合并的差异只涉及 `tests/test_chat_navigation_browser.py` 和 `web/src/pages/chat-manager-picker.test.tsx`。新测试所覆盖的行为（按 Manager 和会话把未发送草稿保存在浏览器 session storage 中）已在 v2.13.120 发布。
- **新增浏览器测试：**`test_unsent_drafts_belong_to_each_conversation_and_manager` 在两个会话中输入草稿，检查切换回来时各自恢复；打开已知的 Lark 链接、Telegram 链接和未知 id 后返回，检查草稿仍在；切换到另一个 Manager，检查其草稿独立且刷新后保留，清空草稿后保持为空，并且不会发出 `operator_chat/send` 调用。
- **新增组件测试：**`chat-manager-picker.test.tsx` 中的 `keeps each Manager's unsent draft separate` 检查两个 Manager 的草稿互相独立、草稿保存在 `looper-chat-draft:<manager>:<session>` 形式的 session storage 键下，且已存的聊天会话 id 和发送调用均不受影响。测试初始化现在也会清空 session storage。
- **测试竞争修复：**两个现有浏览器测试（`test_answered_while_hidden_restores_queue_to_original_draft`、`test_unsent_text_survives_hidden_completion_and_writable_detour`）现在会先等待 `session-b` 的历史渲染完成再按 Enter，因为草稿在历史请求完成之前就已恢复。
- **面向模型的变化：**无。tool 声明、提示词、路由和发给 Worker 的文本均未改变。
- **行数：**[#638](https://github.com/foolzzz/looper/pull/638) 的描述报告测试 51、生产代码 29（不含夹具）。实际差异中，浏览器测试文件新增 51 行，组件测试文件新增 29 行，均为测试文件，因此“生产代码 29”指的是组件测试。
