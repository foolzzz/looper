# Looper v2.13.194

## Release Decision

**Who should upgrade:** Operators who run the Pi runner (`[runtimes] pi = "runner"`) and want a hung test or build to stop holding the session. Everyone else sees no difference, because the runner is opt-in and the default stays on the Pi CLI. It is a hotfix that ships the change merged since v2.13.193.

**What this release solves:** [#831](https://github.com/foolzzz/looper/pull/831) makes the Pi runner's `bash` tool apply the host tool timeout (120 seconds). Before, Pi treated a missing or non-positive `timeout` as unlimited, so a hung command could hold the session.

**Breaking changes:** No. No command, database schema, file format or setting changed. Only the runner's `bash` tool is affected, and only when the opt-in runner is used.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#831](https://github.com/foolzzz/looper/pull/831); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.194
```

## Behavior changes

- **Runner bash timeout (`runners/pi/src/exec.ts`):** `builtinTools` now takes the session's `limits` and wraps `bash`. The timeout passed to Pi is the model's `timeout` when it is positive, capped at `limits.tool_timeout_s`; when the model gives none, zero or a negative value, it is `limits.tool_timeout_s`. The host sends 120 seconds today (`looper/agents/runtimes/runner/session.py`, fixed by the protocol), so the limit cannot be disabled and a larger model value is capped at 120 seconds. On expiry the command's process group ends, and the model receives an error result `Command timed out after N seconds` together with the stdout and stderr produced before it. Other builtin tools, the CLI path and other runtimes are unchanged.
- **Docs and scope:** 2 files changed: `runners/pi/src/exec.ts` (4 added, 2 deleted lines) and the new `tests/test_pi_runner_bash_timeout.py` (102 added lines). The pull request reports "tests 102, production 0 (fixtures excluded)".
- **Model-visible changes:** With `pi = "runner"` only, a `bash` call that runs past the limit now returns a tool result that is an error reading `Command timed out after N seconds`, with the partial output, instead of running without a limit; a `timeout` argument above the limit is lowered to it and zero or negative values no longer mean unlimited. No prompt or tool description changed, and nothing changes for the default CLI path or other roles and runtimes.

## Upgrade and rollback

Re-run `install.sh` once v2.13.194 is published. There is nothing to configure. To roll back, return to v2.13.193; there is no schema or setting change.

### 行为变化与入口

- **Runner bash 超时（`runners/pi/src/exec.ts`）：**`builtinTools` 现在接收会话的 `limits` 并包装 `bash`。传给 Pi 的超时为模型给出的正数 `timeout`，并以 `limits.tool_timeout_s` 为上限；模型未给、为零或为负时取 `limits.tool_timeout_s`。宿主目前发送 120 秒（`looper/agents/runtimes/runner/session.py`，由协议固定），因此该限制无法关闭，更大的模型值会被压到 120 秒。超时后命令的进程组被结束，模型收到错误结果 `Command timed out after N seconds`，并附带超时前的 stdout 和 stderr。其他内置工具、CLI 路径和其他运行时均未改变。
- **文档与范围：**共改动 2 个文件：`runners/pi/src/exec.ts`（新增 4 行、删除 2 行）和新增的 `tests/test_pi_runner_bash_timeout.py`（新增 102 行）。PR 描述写的是“测试 102 行、生产代码 0 行（不含夹具）”。
- **面向模型的变化：**仅在 `pi = "runner"` 时：超过限制的 `bash` 调用现在返回内容为 `Command timed out after N seconds` 的错误工具结果并附部分输出，而不是无限制运行；高于限制的 `timeout` 参数被降到限制值，零或负值不再表示无限制。提示词和工具描述均未改变，默认 CLI 路径及其他角色和运行时无变化。
