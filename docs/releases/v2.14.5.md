# Looper v2.14.5

This is the patch release v2.14.5. It ships the one change merged since v2.14.4: [#871](https://github.com/foolzzz/looper/pull/871), a file-only ops opt-in `[runtimes] dsh = "runner"` that hosts every DSH role on the packaged DSH runner. The default stays `cli`, so nothing changes unless an operator sets it.

## Release Decision

**Who should upgrade:** Operators on v2.14.4 who want the current main line, and operators who want to try the DSH runner. Nothing changes for an installation whose ops file does not set `[runtimes] dsh = "runner"`. It ships the one change merged since v2.14.4.

**What this release solves:** [#871](https://github.com/foolzzz/looper/pull/871) connects the DSH runner (added in earlier patches, not reachable until now) to the host, the same way `[runtimes] pi = "runner"` does for Pi. With the opt-in, the Manager, Planner, Worker, Reviewer and consult runs use the runner instead of DSH CLI commands.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading). The new setting defaults to `cli`.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#871](https://github.com/foolzzz/looper/pull/871); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.5
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.4 upgrades directly. This release changes no schema or stored data. The ops file gains an optional `dsh` key under `[runtimes]`; a file without it behaves as before.

## Behavior changes

- **Opt-in setting (`looper/ops_config.py`):** `[runtimes] dsh` accepts `cli` (default) or `runner`; any other value is rejected with `must be cli or runner`. Like `pi`, it is read from the ops file only (no environment variable or flag) and a restart is required. The generated ops file template lists it.
- **Startup (`looper/agents/serve.py`):** the Pi and DSH runners are enabled independently, each only when its own setting is `runner`, and every started runner supervisor is stopped at shutdown (and if startup only partly completes). When neither is enabled, no runner child is started. A supplied supervisor still takes precedence over the settings.
- **Availability (`looper/agents/runtimes/dsh_runner.py`):** `enable` needs `node` 22.19 or newer and `dsh` on `PATH`. If either is missing or too old, the version check fails or times out (2 seconds), or the runner cannot initialize, the DSH adapter is installed in an unavailable state and every DSH launch fails with the reason. There is no fallback to the CLI. The runner serves up to 20 sessions. A launch whose `dsh` executable resolves to a different file than the one the runner was started with is refused.
- **Roles:** Manager and Planner run as resident runner sessions. Worker, Reviewer and consult runs are hosted runner runs. Planner and consult runs are read-only (`read`, `glob`, `grep`); the others also get `write`, `edit` and `bash`. A run's request limit is its turn limit (1000 when none) and its bash ceiling is the run timeout (86400 seconds when none). The configured model is kept for pricing. A consult fork passes the source session id to the runner with a private fork directory; the host copies nothing and writes nothing to the source, and the fork directory is removed if the launch fails.
- **Refusals:** under the opt-in, the DSH CLI run, steer and consult commands are refused (`there is no DSH CLI command`), and a Manager or Planner resident command is refused for other roles. A provider with environment variables, or `DSH_ALLOW_WEB_SEARCH`, is refused before anything is written, because the runner cannot apply them. The runner's environment drops `LOOPER_*` and `LOOPX_*` variables and carries the provider key.
- **Launch records:** each launch record shows isolation `dsh-runner/v1`, system prompt mode `append`, web search off, and the request limit. Library items other than the Looper MCP server are listed as skipped, because the runner loads no catalog skills, plugins or MCP servers.
- **Runner messages (`looper/agents/runtimes/runner/channel.py`):** failure and capacity reasons now name the runner kind (`the dsh runner ...`) instead of always `the pi runner`; Pi messages are unchanged in effect.
- **State directory (`looper/agents/runtimes/runner/dsh_command.py`):** the runner state root may now sit below a runtime root that is itself reached through a symlink (for example a temporary directory); symlinks, files and dangling links in the `runners/state/dsh-native` part are still refused.
- **Tests (`tests/test_dsh_runner_opt_in.py` and others):** new opt-in tests; the Pi opt-in, runner channel, wait service and state root tests are adjusted for the renamed setting, messages and symlink rule.
- **Model-visible changes:** None unless the opt-in is set. With it, a hosted DSH role receives its Looper instructions as an appended system prompt (DSH's default prompt is kept) that adds the DSH runtime notes and a line saying Looper's platform tools are named `looper_*`, the tool set above, and no catalog skills, plugins or MCP servers.

## 中文摘要

本版本是 patch release v2.14.5。自 v2.14.4 以来只合并了 [#871](https://github.com/foolzzz/looper/pull/871)：仅限文件的运维开关 `[runtimes] dsh = "runner"`，让所有 DSH 角色由打包的 DSH runner 承载。默认仍为 `cli`，不设置则无任何变化。

### 升级决策

**谁需要升级：**想跟进当前主线的 v2.14.4 运维者，以及想试用 DSH runner 的运维者。运维文件未设置 `[runtimes] dsh = "runner"` 的安装没有任何变化。包含 v2.14.4 之后合并的唯一改动。

**解决了什么：**[#871](https://github.com/foolzzz/looper/pull/871) 把此前补丁加入、至今无法到达的 DSH runner 接入宿主，方式与 Pi 的 `[runtimes] pi = "runner"` 相同。开启后，Manager、Planner、Worker、Reviewer 和 consult 使用 runner，而不是 DSH CLI 命令。

**是否有破坏性变更：**否。受支持的升级路径不变（见升级）。新设置默认 `cli`。

**如何验证：**运行 `looper --version` 核对版本为 2.14.5。

**贡献者：**维护者 @foolzzz 提交 [#871](https://github.com/foolzzz/looper/pull/871)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.5
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.4 上的安装可直接升级。本版本不改 schema 或已存数据。运维文件的 `[runtimes]` 下新增可选键 `dsh`；没有该键的文件行为不变。

### 行为变化与入口

- **开关（`looper/ops_config.py`）：**`[runtimes] dsh` 取 `cli`（默认）或 `runner`，其他值以 `must be cli or runner` 拒绝。与 `pi` 一样只从运维文件读取（无环境变量或命令行参数），需重启。生成的运维文件模板列出该项。
- **启动（`looper/agents/serve.py`）：**Pi 与 DSH runner 各自独立、仅在对应设置为 `runner` 时启用，所有已启动的 runner 监督器在关闭时（以及启动只完成一部分时）都会停止。两者都未启用时不启动 runner 子进程。外部提供的监督器仍优先于设置。
- **可用性（`looper/agents/runtimes/dsh_runner.py`）：**`enable` 需要 `node` 22.19 及以上和 `PATH` 上的 `dsh`。缺失或版本过低、版本检查失败或超时（2 秒）、runner 无法初始化时，DSH 适配器以不可用状态安装，每次 DSH 启动都带原因失败，不回退到 CLI。runner 最多 20 个会话。若启动所用的 `dsh` 可执行文件与 runner 启动时的不是同一文件，则拒绝启动。
- **角色：**Manager 和 Planner 作为常驻 runner 会话；Worker、Reviewer 和 consult 是宿主承载的 runner 运行。Planner 和 consult 只读（`read`、`glob`、`grep`），其余另有 `write`、`edit`、`bash`。运行的请求上限取其 turn 上限（无则 1000），bash 上限取运行超时（无则 86400 秒）。沿用配置的模型用于计价。consult fork 把来源会话 id 和私有 fork 目录交给 runner；宿主不复制、不写来源，启动失败时删除 fork 目录。
- **拒绝：**开启后，DSH CLI 的 run、steer 和 consult 命令被拒绝（`there is no DSH CLI command`），其他角色的 Manager/Planner 常驻命令也被拒绝。带环境变量的 provider 或 `DSH_ALLOW_WEB_SEARCH` 在写入任何内容之前被拒绝，因为 runner 无法应用它们。runner 环境去掉 `LOOPER_*` 和 `LOOPX_*` 变量，并带上 provider 密钥。
- **启动记录：**每条启动记录显示隔离 `dsh-runner/v1`、系统提示模式 `append`、网页搜索关闭和请求上限。除 Looper MCP 服务器外的库条目被列为跳过，因为 runner 不加载目录中的 skill、plugin 或 MCP 服务器。
- **runner 消息（`looper/agents/runtimes/runner/channel.py`）：**失败和容量原因现在写明 runner 类型（`the dsh runner ...`），不再固定为 `the pi runner`；Pi 的消息实际不变。
- **状态目录（`looper/agents/runtimes/runner/dsh_command.py`）：**runner 状态根现在可位于本身经符号链接到达的运行时根之下（如临时目录）；`runners/state/dsh-native` 部分的符号链接、文件和悬空链接仍被拒绝。
- **测试（`tests/test_dsh_runner_opt_in.py` 等）：**新增开关测试；Pi 开关、runner channel、wait service 和状态根测试按改名的设置、消息和符号链接规则调整。
- **面向模型的变化：**不设开关则无。开启后，承载的 DSH 角色收到作为追加系统提示的 Looper 指令（保留 DSH 默认提示），其中加入 DSH 运行时说明和一行 Looper 平台工具名为 `looper_*` 的提示，工具集如上，且没有目录中的 skill、plugin 或 MCP 服务器。
