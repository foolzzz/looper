# Looper v2.13.161

## Release Decision

**Who should upgrade:** Nobody needs to. This release changes documentation and tests only; contributors and operators who read the architecture documents, or who plan work on agent SDK runners, will find the new text. Everyone else can stay on v2.13.160.

**What this release solves:** [#737](https://github.com/foolzzz/looper/pull/737) reconciles the architecture document, the scenario Manager RFC and the long-horizon plan with the scenario Manager behavior already shipped (idle suspension, deleted-Manager cleanup, schedule ownership and templates, Manager installs, configuration transfer v4), and adds one integration regression for it. [#703](https://github.com/foolzzz/looper/pull/703) adds an RFC for driving agent SDKs through native-language runners and records the maintainer's agreement to develop it from stage S0.

**Breaking changes:** No. No code, API, database, configuration, prompt or Tool declaration changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#737](https://github.com/foolzzz/looper/pull/737) and [#703](https://github.com/foolzzz/looper/pull/703); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.161
```

## Behavior changes

- **Runtime behavior:** none. The merged range touches no file under `looper/` or `web/`; it changes `docs/architecture/agent-system.md`, `docs/architecture/rfcs/scenario-managers.zh-CN.md`, `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`, a new RFC and three test files.
- **Scenario Manager documentation ([#737](https://github.com/foolzzz/looper/pull/737)):** `docs/architecture/agent-system.md` now states idle suspension (`idle_timeout_seconds`, default 1800, `0` disables it, the default Manager is exempt, Grok ACP never suspends), deleted-Manager history cleanup (`manager_cleanup.preview` and `purge`, operator-only, 30 to 3650 days), immutable schedule owners with `template_key` and `template_inputs`, per-Manager installs, and the configuration transfer rules (`looper-config/v3` for a default-only installation, `looper-config/v4` otherwise; Manager definitions, templates, added bots and own installs are operator-only import sections; imported new or changed bots stay disabled). The scenario Manager RFC and the plan's item 21 are updated to match, and the RFC records that acceptance of the schedule reporting scope is pending maintainer confirmation.
- **Integration regression ([#737](https://github.com/foolzzz/looper/pull/737)):** new `tests/test_scenario_manager_followups_integration_db.py` imports a v4 document with an owned Manager, template, schedule, bot and install, previews and applies it into a fresh schema, fires the schedule and reads back the task's owner, template snapshot, Manager installs and owner filter. It needs a PostgreSQL test database and is skipped without one. Two browser tests (`tests/test_manager_cleanup_browser.py`, `tests/test_manager_idle_browser.py`) gain a stub for `manager_installs/list`.
- **Agent SDK runner RFC ([#703](https://github.com/foolzzz/looper/pull/703)):** new `docs/architecture/rfcs/agent-sdk-runner-v0.zh-CN.md` (Chinese) proposes Pi and DSH runners in TypeScript and a Norma runner in Go, controlled over one JSON-RPC protocol on stdio, with a shared message bus, Looper-owned budgets and stages S0 to S3. Its status line reads: the maintainer agreed on 2026-10-27 to develop it from S0, open questions follow the recommended defaults. It is a design document; no runner or protocol code exists in this release.
- **Model-visible changes:** none. No prompt, tool description or tool schema changed.
- **Tests:** [#737](https://github.com/foolzzz/looper/pull/737) reports 127 added test lines and 0 production lines (fixtures excluded).

- **运行时行为：**无。合并范围未触及 `looper/` 或 `web/` 下的任何文件；只改动 `docs/architecture/agent-system.md`、`docs/architecture/rfcs/scenario-managers.zh-CN.md`、`docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`、一份新 RFC 和三个测试文件。
