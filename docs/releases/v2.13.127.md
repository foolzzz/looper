# Looper v2.13.127

## Release Decision

**Who should upgrade:** Nobody needs to upgrade for a visible feature. Operators who run more than one Manager and use the stop command in a Telegram or Lark chat should upgrade, because the command now reaches every Manager that is answering that chat.

**What this release solves:** [#650](https://github.com/foolzzz/looper/pull/650) makes the stop command of a bot chat stop the live and queued replies of that chat in all running Managers, not only in the Manager that received the command.

**Breaking changes:** No. No command, option or schema changed. The experimental stop switch and the runtime interruption contract are kept; the acknowledgement text can differ from before when more than one Manager is involved.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#650](https://github.com/foolzzz/looper/pull/650); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.127
```

## Behavior changes

- **Fleet-wide stop:** `ManagerFleet.stop_chat(channel_id, chat_id, via=...)` in `looper/agents/managers.py` returns a `ChatStopSummary` (`ChatStopSummary.state` is `disabled` when the stop switch is off). Otherwise it snapshots, before its first await, every running Manager and that Manager's live turns for the bot and chat, then calls `stop_turn` on each token. It counts turns that are stopping, were already stopping, or cannot be interrupted by their runtime. An exception from one stop is logged and the owning Manager id is recorded as a failure, and the remaining turns are still stopped.
- **Per-Manager lookup:** `ManagerAgent.live_for_chat` in `looper/agents/tiers/manager.py` returns the live turns of a bot and chat by full channel identity. The fleet sets `stop_chat` on each Manager it builds.
- **Stop command handling:** when a Manager has `stop_chat` set, the stop command asks the fleet using the message's channel id (falling back to the channel name), chat and channel, and sends the code-owned acknowledgement from `chat_stop_reply` without persisting it. A Manager without `stop_chat` keeps its previous single-Manager path.
- **Acknowledgement text** (Chinese, shown in the chat): stop switch off gives the existing disabled reply; any failure says the stop was incomplete and asks for a retry; runtimes that cannot be interrupted give the existing unsupported reply, or a partial-stop notice when other turns were stopped; more than one stopped turn in a single Manager reports the stopped reply plus the number of cancelled queued messages; across several Managers it reports the number of stopped replies; one turn gives the existing done reply and none gives the existing idle reply. When no Manager had a matching turn and the receiving runtime cannot interrupt, the unsupported reply is sent instead of the idle reply.
- **Model-visible changes:** none. The acknowledgement is sent to the chat, not stored (`persist=False`) and not added to a prompt; prompts, tool declarations and results are unchanged.
- **Line counts:** the description of [#650](https://github.com/foolzzz/looper/pull/650) reports tests 292 and production 76 added lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.127 is published. No schema or configuration change. Rolling back to v2.13.126 restores the stop that reaches only the receiving Manager.

### 升级决策

**谁需要升级：**无需为可见功能而升级。运行多个 Manager 并在 Telegram 或 Lark 聊天中使用停止命令的操作者应升级，因为该命令现在会作用于所有正在回复该聊天的 Manager。

**解决了什么：**[#650](https://github.com/foolzzz/looper/pull/650) 让 bot 聊天的停止命令停止该聊天在所有运行中 Manager 里的进行中与排队回复，而不只是接收命令的那个 Manager。

**是否有破坏性变更：**否。命令、选项和表结构均未改变。实验性停止开关与运行时中断约定保持不变；涉及多个 Manager 时，确认文案可能与以前不同。

**如何验证：**运行 `looper --version` 核对版本为 2.13.127。

**贡献者：**维护者 @foolzzz 提交 [#650](https://github.com/foolzzz/looper/pull/650)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.127
```

### 行为变化与入口

- **全 Manager 停止：**`looper/agents/managers.py` 的 `ManagerFleet.stop_chat(channel_id, chat_id, via=...)` 返回 `ChatStopSummary`（停止开关关闭时 `state` 为 `disabled`）。否则它在第一次 await 之前对所有运行中的 Manager 及其该 bot 与聊天的进行中 turn 取快照，再对每个 token 调用 `stop_turn`，并统计正在停止、已在停止、运行时无法中断的 turn。单个停止抛出异常时记录日志并把所属 Manager id 记为失败，其余 turn 仍会被停止。
- **按 Manager 查询：**`looper/agents/tiers/manager.py` 的 `ManagerAgent.live_for_chat` 按完整渠道标识返回某 bot 与聊天的进行中 turn。fleet 为其构建的每个 Manager 设置 `stop_chat`。
- **停止命令处理：**Manager 设置了 `stop_chat` 时，停止命令用消息的渠道 id（缺省回退到渠道名）、聊天和渠道询问 fleet，并发送由代码生成、不落库的 `chat_stop_reply` 确认。未设置 `stop_chat` 的 Manager 保持原有的单 Manager 路径。
- **确认文案**（中文，显示在聊天中）：停止开关关闭时沿用原有的关闭提示；出现失败时提示停止不完整并请重试；运行时无法中断时沿用原有的不支持提示，若同时停止了其他 turn 则提示部分停止；单个 Manager 停止多于一个 turn 时报告已停止并给出取消的排队消息数；多个 Manager 时报告停止的回复数；一个 turn 沿用原有完成提示，没有则沿用原有空闲提示。没有任何 Manager 有匹配 turn 且接收命令的运行时无法中断时，发送不支持提示而不是空闲提示。
- **面向模型的变化：**无。确认文案发送到聊天，不落库（`persist=False`），也不加入提示词；提示词、tool 声明和结果均未改变。
- **行数：**[#650](https://github.com/foolzzz/looper/pull/650) 的描述报告新增测试 292 行、生产代码 76 行（不含 fixtures）。
