# Looper v2.13.21

## Release Decision

**Who should upgrade:** Dashboard users who read a task's runs, the Context usage panel, a task's Room tab or a Gate discussion. Everyone else sees no change.

**What this release solves:** [#345](https://github.com/foolzzz/looper/pull/345) fixes the review follow-ups of #329. Compact run rows keep the task role a run ran as, the dashboard's polling requests can be cancelled, and the Gate discussion no longer reads twice at once.

**Breaking changes:** No. No CLI command, configuration key or database schema changed. The task runs endpoint adds a `task_role` field to each row; existing fields are as before.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#345](https://github.com/foolzzz/looper/pull/345); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.21
```

## Behavior changes

- **Run rows keep the task role:** `task_run_rows` returns `task_role` for each run: the role its Planner defined that it ran as (from `metadata.prompt_layers.task_role`), else `null`. The dashboard restores it in `asRecord()`, so slim runs no longer lose it (`looper/db/llm_records.py`, `web/src/lib/api.ts`, `web/src/lib/use-task-runs.ts`).
- **Polling requests carry the abort signal:** the Context usage panel, the task Room and the Gate thread pass the polling `AbortSignal` to `fetchAgentUsage`, `fetchTaskRoom` and `fetchGateThread`, so a stopped poll cancels its request. An aborted Gate read no longer sets an error (`web/src/components/context-usage.tsx`, `web/src/components/task-room.tsx`, `web/src/components/task-gates.tsx`).
- **One Gate thread reader:** one effect owns the reads: when following, it polls (the first read is immediate); otherwise it reads once per change of the thread's signature. Before, the first read and the poll could run at once.
- **Tests:** `tests/test_task_runs_api_db.py` checks the `task_role` field on every row, set for a run whose record has `prompt_layers.task_role` and `None` for the others.
- **Deferred, not fixed here:** the PR defers one flaky fake-mode test (`test_fake_mode_runs_every_task_and_sees_misbehaviour`) whose failure could not be reproduced; it stays open in #329. The PR also lists a flaky schema test as fixed; that change shipped earlier in v2.13.19 (#349) and is not in this release's diff.
- **Model-visible changes:** None. No prompt, tool schema or tool result changed. `task_role` belongs to the dashboard's HTTP API.

## Upgrade and rollback

Re-run `install.sh` once v2.13.21 is published. There is no schema or configuration change. Rolling back to v2.13.20 is safe; run rows then lack `task_role`.

### 行为变化与入口

- 运行行保留任务角色：`task_run_rows` 为每个运行返回 `task_role`，即其 Planner 定义的、该运行所扮演的角色（来自 `metadata.prompt_layers.task_role`），否则为 `null`。Dashboard 在 `asRecord()` 中恢复它，精简运行不再丢失该信息（`looper/db/llm_records.py`、`web/src/lib/api.ts`、`web/src/lib/use-task-runs.ts`）。
- 轮询请求携带中止信号：Context usage 面板、任务 Room 与 Gate 线程把轮询的 `AbortSignal` 传给 `fetchAgentUsage`、`fetchTaskRoom`、`fetchGateThread`，停止轮询即取消请求；被中止的 Gate 读取不再设置错误（`web/src/components/context-usage.tsx`、`web/src/components/task-room.tsx`、`web/src/components/task-gates.tsx`）。
- Gate 线程只有一个读取者：由一个 effect 负责读取，跟随时轮询（首次读取立即进行），否则每次线程签名变化读取一次。此前首次读取与轮询可能同时进行。
- 测试：`tests/test_task_runs_api_db.py` 检查每行的 `task_role`：记录含 `prompt_layers.task_role` 的运行有值，其余为 `None`。
- 延后未修：PR 延后了一个无法复现的不稳定 fake-mode 测试（`test_fake_mode_runs_every_task_and_sees_misbehaviour`），仍在 #329 跟踪。PR 还把不稳定的 schema 测试列为已修；该修复已随 v2.13.19（#349）发布，不在本版本的差异中。
- 面向模型的变化：无。提示词、工具 schema、工具结果均无变化。`task_role` 属于 Dashboard 的 HTTP API。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.20 安全；运行行将不再带 `task_role`。
