# Looper v2.14.159

This is the patch release v2.14.159, a hotfix line in which each merged change ships at once. It documents one change: [#1288](https://github.com/foolzzz/looper/pull/1288) (read marking for steered Codex room messages).

## Release Decision

**Who should upgrade:** Operators who run Codex Workers or Reviewers in a task room with a Codex that supports `turn/steer` (0.162.0 or newer). Everyone else sees no change.

**What this release solves:** [#1288](https://github.com/foolzzz/looper/pull/1288) changes when a room message steered into a Codex run counts as read. It is marked read when the run's `userMessage` history item carrying it appears, not when the app-server acknowledges the steer, so a message the run never received is not marked read.

**Breaking changes:** No. There is no API change, no migration and no schema change; behavior changes are listed below. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.159
```

**Contributors:** Maintainer @foolzzz authored [#1288](https://github.com/foolzzz/looper/pull/1288); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.158 upgrades directly. There is no schema change.

## Behavior changes

- **Read marking moves to the history item** ([#1288](https://github.com/foolzzz/looper/pull/1288), `looper/agents/tiers/worker.py`: `confirm_on_accept` becomes `confirm_on_item`, with `_room_history_item` and `_confirm_room_prefix`). A message steered into a Codex run stays in flight after the acknowledgement and is marked read when an app-server `userMessage` item carrying all of the delivery's message ids appears. The PR calls this an intended maintainer decision.
- **Ordering.** Confirmation advances only past earlier confirmed deliveries, because the room cursor is cumulative.
- **Fallback.** If no item arrives within 30 s (`ROOM_ITEM_TIMEOUT_SEC`) of the acknowledgement while the run is still active, Looper logs a warning and acknowledges that delivery as read. A run that ends before receipt or fallback leaves the messages unread for its next turn or retry; the fallback timers are cancelled when the run's input ends or its reminders are dropped.
- **Unchanged.** A rejection or no active turn leaves messages unread; an unknown acknowledgement advances the in-flight cursor without marking them read or retrying, and logs it. Codex runs without the steer capability, and OMP, Pi and hosted runner runs, are unchanged.
- **Event reading.** `exec_item` and `CodexChannel.events()` in `looper/agents/runtimes/codex_steer.py` now turn a `userMessage` item into an internal `system` event with subtype `codex_user_message` instead of dropping it. Only the Worker pool consumes it; it is not assistant output and is not treated as model work.
- **Tests and docs.** Changed `tests/test_codex_room_push.py` and `tests/test_codex_steer.py`; `docs/architecture/agent-system.md` describes the receipt and fallback, and no longer states the earlier acknowledgement-time caveat.
- **Model-visible changes:** None found. The system prompt, tool descriptions and steered message text are not changed by this PR; the new event is internal. The PR does not report a prompt eval.

## 中文摘要

本版本是 patch release v2.14.159（热修线，每个合并的改动立即发布），说明一项改动：[#1288](https://github.com/foolzzz/looper/pull/1288)（steer 投递的 Codex 房间消息的已读标记）。

### 升级决策

**谁需要升级：**在任务房间中运行 Codex Worker 或 Reviewer、且 Codex 支持 `turn/steer`（0.162.0 或更新）的运维者。其他人无变化。

**解决了什么：**[#1288](https://github.com/foolzzz/looper/pull/1288) 改变被 steer 进 Codex 运行的房间消息何时算已读：不再在 app-server 确认 steer 时标记，而是在带有该消息的 `userMessage` 历史项出现时标记，因此运行未实际收到的消息不会被标为已读。

**是否有破坏性变更：**否。没有 API 变更、迁移或结构变更，行为变化见下。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.14.159。

**贡献者：**维护者 @foolzzz 提交 [#1288](https://github.com/foolzzz/looper/pull/1288)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.159
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.158 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **已读标记移到历史项**（[#1288](https://github.com/foolzzz/looper/pull/1288)，`looper/agents/tiers/worker.py`：`confirm_on_accept` 改为 `confirm_on_item`，新增 `_room_history_item` 与 `_confirm_room_prefix`）。被 steer 进 Codex 运行的消息在确认后仍保持在途，当 app-server 的 `userMessage` 项包含该投递全部消息 id 时才标为已读。PR 称这是维护者的有意决定。
- **顺序。**房间游标是累积的，只有前面的投递都已确认才会继续前进。
- **兜底。**确认后 30 秒（`ROOM_ITEM_TIMEOUT_SEC`）内若运行仍活动却没有出现该项，Looper 记录警告并把该投递按确认标为已读。运行在收到项或兜底之前结束，则消息保持未读，留给下一轮或重试；运行输入结束或提醒状态被丢弃时兜底计时器会取消。
- **不变。**被拒绝或没有活动回合时消息保持未读；确认结果未知时推进在途游标，但不标已读也不重试，并记录日志。没有 steer 能力的 Codex 运行，以及 OMP、Pi 和托管 runner 运行行为不变。
- **事件读取。**`looper/agents/runtimes/codex_steer.py` 的 `exec_item` 与 `CodexChannel.events()` 现在把 `userMessage` 项转成内部 `system` 事件（subtype 为 `codex_user_message`），不再丢弃。仅 Worker 池使用它；它不是助手输出，也不视为模型工作。
- **测试与文档。**更新 `tests/test_codex_room_push.py`、`tests/test_codex_steer.py`；`docs/architecture/agent-system.md` 说明回执与兜底，并删除此前关于确认时机的说明。
- **面向模型的变化：**未发现。该 PR 没有改动系统提示词、工具描述或被送入的消息文本；新事件仅供内部使用。PR 未报告提示词评测。
