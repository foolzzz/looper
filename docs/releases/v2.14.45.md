# Looper v2.14.45

This is the patch release v2.14.45, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.44: the dashboard shows command run history, logs and statistics ([#1000](https://github.com/foolzzz/looper/pull/1000)).

## Release Decision

**Who should upgrade:** Anyone who runs command schedules and wants to see in the dashboard why a run failed, read its log, or follow a run link from a notification.

**What this release solves:** [#1000](https://github.com/foolzzz/looper/pull/1000) makes the run history of a command schedule show each run's status with its exit code or signal, scheduled, started and finished times, duration and trigger (including catch-up runs). Expanding a run shows the last 200 log lines and a button to download the full log. Above the history, 24-hour and 7-day statistics (runs, succeeded, average and maximum duration) appear, and a status filter narrows the list. A run link of the form `#projects/PROJECT/schedules/SCHEDULE/runs/RUN` opens the schedule and expands that run. "Failing now" on the overview page shows the two new alert types.

**Breaking changes:** No. No API or configuration is removed, and there is no new migration or setting.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#1000](https://github.com/foolzzz/looper/pull/1000); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.45
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.44 upgrades directly. This release adds no migration and no new setting.

## Behavior changes

- **Command run history ([#1000](https://github.com/foolzzz/looper/pull/1000)).** For a command schedule, each run row shows the status (with `exit <code>` or `signal <n>` when the run failed, timed out or was interrupted), scheduled, started and finished times in the schedule's time zone, duration (the run's `duration_seconds`, else computed from its times) and trigger. The row expands to the run's error or summary and the last 200 log lines (`tail_lines: 200`), with "Refresh log", a notice when the log was truncated at 50 MiB, and "Still running: the log grows" for an active run. "Download log" fetches the full log in 4 MiB pages with byte progress and saves it as `<run id>.log`; only the preview is decoded as text.
- **Statistics and filter.** Above a command schedule's history, one line gives the last 24 hours and the last 7 days: succeeded/runs, average and maximum duration, or "No runs" for an empty window. A status filter (All, Succeeded, Failed, Timed out, Interrupted, Skipped (overlap)) narrows the list; while a status is chosen the routine-skip checkbox is hidden and skips are requested.
- **Run link.** `#projects/<project>/schedules/<schedule>/runs/<run>` opens the schedule and expands the run, loading older pages until it is found, and shows "This run is no longer kept" when it is gone.
- **Alerts.** The schedule row and "Failing now" on the overview page show "Missed its success deadline since …" and "Skipping: the previous run is still going since …" from the new `deadline_since` and `overlap_since` fields.
- **Unchanged.** Non-command schedules keep their run list. The change reads fields and endpoints (`runs` with `status` and `stats`, `run_log`) through the dashboard client; the PR touches only dashboard code and tests.
- **Model-visible changes:** No. The PR touches no prompt, tool description or tool schema.

本版本是 patch release v2.14.45（热修线，每个合并的改动立即发布）。自 v2.14.44 以来合并了一项改动：仪表盘显示命令运行的历史、日志和统计（[#1000](https://github.com/foolzzz/looper/pull/1000)）。

### 升级决策

**谁需要升级：**运行命令定时任务，并希望在仪表盘中查看失败原因、读取日志或从通知链接跳到某次运行的人。

**解决了什么：**[#1000](https://github.com/foolzzz/looper/pull/1000) 让命令定时任务的运行历史显示每次运行的状态（含退出码或信号）、计划、开始和结束时间、时长与触发方式（含补跑）。展开一次运行可看最后 200 行日志，并可下载完整日志。历史上方显示 24 小时和 7 天的统计（运行数、成功数、平均与最长时长），并可按状态过滤。形如 `#projects/PROJECT/schedules/SCHEDULE/runs/RUN` 的运行链接会打开该定时任务并展开这次运行。概览页的“Failing now”显示两种新的告警。

**是否有破坏性变更：**否。不移除任何 API 或配置，也没有新的迁移或设置。

**如何验证：**运行 `looper --version` 核对版本为 2.14.45。

**贡献者：**维护者 @foolzzz 提交 [#1000](https://github.com/foolzzz/looper/pull/1000)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.45
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.44 上的安装可直接升级。本版本没有新迁移，也没有新设置。

### 行为变化与入口

- **命令运行历史（[#1000](https://github.com/foolzzz/looper/pull/1000)）。**命令定时任务的每行显示状态（失败、超时或中断时附带 `exit <code>` 或 `signal <n>`）、计划/开始/结束时间（按定时任务时区）、时长（优先用运行的 `duration_seconds`，否则由时间计算）和触发方式。展开后显示该运行的错误或摘要与最后 200 行日志，有“Refresh log”；日志在 50 MiB 处被截断时给出提示；运行中显示“Still running: the log grows”。“Download log”按 4 MiB 分页取完整日志并显示字节进度，保存为 `<run id>.log`；只有预览按文本解码。
- **统计与过滤。**命令定时任务历史上方一行给出最近 24 小时和 7 天的成功数/运行数、平均与最长时长，窗口内无运行则显示“No runs”。状态过滤（All、Succeeded、Failed、Timed out、Interrupted、Skipped (overlap)）缩小列表；选了状态时隐藏常规跳过的复选框，并请求包含跳过的运行。
- **运行链接。**`#projects/<project>/schedules/<schedule>/runs/<run>` 打开定时任务并展开该运行，会逐页加载更早的运行直到找到，找不到时显示“This run is no longer kept”。
- **告警。**定时任务行和概览页的“Failing now”根据新字段 `deadline_since` 与 `overlap_since` 显示“Missed its success deadline since …”和“Skipping: the previous run is still going since …”。
- **不变。**非命令定时任务的运行列表不变。该改动通过仪表盘客户端读取字段和端点（带 `status` 与 `stats` 的 `runs`、`run_log`）；PR 只改动仪表盘代码和测试。
- **面向模型的变化：**无。该 PR 没有改动提示词、工具描述或工具 schema。
