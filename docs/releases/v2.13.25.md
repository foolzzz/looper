# Looper v2.13.25

## Release Decision

**Who should upgrade:** Users of the dashboard's task detail page, whose Pipeline and Agents node cards show each agent's runtime, model and effort. Everyone else sees no change.

**What this release solves:** [#365](https://github.com/foolzzz/looper/pull/365) fixes the review follow-ups of #283. A new Planner run that changes no status, instance id or step no longer leaves the hover card on the old model, and two `Agent` rows on a card no longer collide on the renderer's key.

**Breaking changes:** No. No CLI command, configuration key, API or database schema changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#365](https://github.com/foolzzz/looper/pull/365); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.25
```

## Behavior changes

- **Runs refresh on new runs:** the hook that loads a task's runs (`web/src/lib/use-task-runs.ts`) now also includes the task cost's run counts (total runs, running, and runs per role) in the key that triggers a refresh. Before, only the task status, planner id and each step's id, status, worker, reviewer, review stage and retries did, so a new run of the same agent left the hover card on the old model. The PR notes that the hook already makes one compact `/runs` request split by role, so this adds no request per refresh.
- **Unique keys for Agent facts:** a card fact gains an optional `key` (`web/src/lib/node-cards.ts`). `agentFact` takes a key (default `agent`); step cards pass `worker-agent` and `reviewer-agent`, the Planner card passes `planner-agent`. The card renderer uses `fact.key ?? fact.label` (`web/src/components/pipeline-node-card.tsx`). Before, a step with a Worker and a Reviewer produced two rows keyed by the same `Agent` label.
- **Tests:** `web/src/lib/node-cards.test.ts` and `web/src/pages/task-detail-perf.test.tsx` are updated for the keys and the refresh.
- **Already fixed, not part of this change:** the PR lists "use-task-runs.ts issues 3 requests per refresh" as already fixed before it.
- **Model-visible changes:** None. No prompt text, tool schema or tool result changed; the change is in the dashboard only.

## Upgrade and rollback

Re-run `install.sh` once v2.13.25 is published. There is no schema or configuration change. Rolling back to v2.13.24 is safe; the hover card then again can lag behind a new run that changes nothing else.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 行为变化与入口

- 新运行触发刷新：加载任务运行的 hook（`web/src/lib/use-task-runs.ts`）现在把任务成本的运行计数（总数、运行中、各角色运行数）也纳入触发刷新的 key。此前只有任务状态、planner id 以及各步骤的 id、状态、worker、reviewer、评审阶段和重试次数，因此同一 agent 的新运行会让悬浮卡片停留在旧模型。PR 说明该 hook 本就只发一次按角色拆分的紧凑 `/runs` 请求，所以每次刷新不增加请求。
- Agent 事实的唯一 key：卡片事实新增可选 `key`（`web/src/lib/node-cards.ts`）。`agentFact` 接收 key（默认 `agent`）；步骤卡片传 `worker-agent` 与 `reviewer-agent`，Planner 卡片传 `planner-agent`。渲染器使用 `fact.key ?? fact.label`（`web/src/components/pipeline-node-card.tsx`）。此前同时有 Worker 和 Reviewer 的步骤会产生两行以同一 `Agent` 标签为 key 的内容。
- 测试：更新了 `web/src/lib/node-cards.test.ts` 与 `web/src/pages/task-detail-perf.test.tsx`。
- 此前已修复，不属本次改动：PR 列出的“use-task-runs.ts 每次刷新发 3 个请求”在此前已修复。
- 面向模型的变化：无。提示词文本、工具 schema、工具结果均无变化；改动仅在仪表盘内。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.24 安全；此时悬浮卡片可能再次落后于未改变其他字段的新运行。
