# Looper v2.13.190

## Release Decision

**Who should upgrade:** Maintainers and contributors working on the Pi runner. Other users see no difference. It is a hotfix that ships the change merged since v2.13.189.

**What this release solves:** [#818](https://github.com/foolzzz/looper/pull/818) adds `session/new`, `session/close`, `session/prompt` and `session/cancel` to the Pi runner in `runners/pi`, with a pre-request budget check and per-request usage reporting. The runner is not registered with the service, so no running Looper reaches it yet.

**Breaking changes:** No. No command, database schema or file format changed, and no Python code changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#818](https://github.com/foolzzz/looper/pull/818); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.190
```

## Behavior changes

- **Session methods ([#818](https://github.com/foolzzz/looper/pull/818)):** `runners/pi/src/main.ts` registers `session/new`, `session/close`, `session/prompt` and `session/cancel` (in `session.ts` and `turn.ts`). `session/new` validates its parameters (role `manager` or `planner`, absolute existing `cwd` and `state_dir`, protocol `openai-responses` or `openai-chat`, a non-empty base URL, model, key and account id, prompt mode `replace` or `append`) and refuses duplicate session keys and more than 10 sessions. It rejects any builtin or platform tool, so sessions have none. Each session gets its own model runtime with the key held in memory only, in-memory settings, a single `looper` provider, and no extensions, skills, prompt templates, themes or context files; provider retries are set to 0.
- **Budget and usage (`provider.ts`):** every model request first sends `budget/authorize` to the host. A denial stops the turn without sending the request. Each allowed request is reported with one `request_end` (status, uncached input, output, cache read and write tokens, and whether usage was complete).
- **Turns (`turn.ts`):** a prompt is accepted at once, and a second prompt on a busy session is refused. Pi events become `session/update` messages (`text_delta`, `message`, `tool_result`). Each accepted prompt ends with exactly one `settled` whose outcome is `completed`, `cancelled`, `capped`, `max_requests` or `failed`; failures carry a kind (`OUTPUT_TRUNCATED`, `PROVIDER_AUTH`, `CONTEXT_OVERFLOW`, `PROVIDER_UNAVAILABLE` or `INTERNAL_ERROR`) and a scrubbed message of at most 512 characters. Cancel and close abort the turn; if it does not settle within 4 seconds the session is released and the turn fails.
- **Other runner changes:** `runner/health` now reports real session, running-turn and in-flight request counts. `rpc.ts` orders `session/new` calls by session key. `sdk.ts` also requires the `createAssistantMessageEventStream` and `isContextOverflow` exports of `pi-ai`. The Python side only gains tests and support code; one line is added to a design-plan document.
- **Scope:** 11 files changed, about 740 added lines, of which about 350 are test lines and about 340 are TypeScript in `runners/pi`. The pull request reports "tests 386, production 0 (fixtures excluded)", which does not count the runner source.
- **Model-visible changes:** None for any running Looper: the runner is not wired to the service, and no prompt, tool description or tool result Looper sends changed.

Re-run `install.sh` once v2.13.190 is published. There is no schema change, so rolling back to v2.13.189 needs nothing else.

### 行为变化与入口

- **会话方法（#818）：**`runners/pi/src/main.ts` 注册 `session/new`、`session/close`、`session/prompt`、`session/cancel`（实现在 `session.ts`、`turn.ts`）。`session/new` 校验参数（角色为 `manager` 或 `planner`，`cwd` 与 `state_dir` 为已存在的绝对路径，协议为 `openai-responses` 或 `openai-chat`，base URL、模型、密钥、账号 id 非空，提示词模式为 `replace` 或 `append`），拒绝重复的 session key 和超过 10 个会话，并拒绝任何 builtin 或 platform 工具，因此会话没有工具。每个会话有独立的模型运行时：密钥只在内存中，设置在内存中，仅一个 `looper` provider，不加载扩展、技能、提示模板、主题和上下文文件；provider 重试设为 0。
- **预算与用量（`provider.ts`）：**每次模型请求前先向宿主发送 `budget/authorize`。被拒绝时该轮停止且不发出请求。每个被允许的请求恰好上报一次 `request_end`（状态、未缓存输入、输出、缓存读写 token，以及用量是否完整）。
- **轮次（`turn.ts`）：**prompt 立即被接受，会话忙时再来的 prompt 被拒绝。Pi 事件映射为 `session/update`（`text_delta`、`message`、`tool_result`）。每个被接受的 prompt 恰好以一次 `settled` 结束，结果为 `completed`、`cancelled`、`capped`、`max_requests` 或 `failed`；失败带类型（`OUTPUT_TRUNCATED`、`PROVIDER_AUTH`、`CONTEXT_OVERFLOW`、`PROVIDER_UNAVAILABLE`、`INTERNAL_ERROR`）和最长 512 字符的脱敏信息。取消与关闭会中止该轮；若 4 秒内未结算，则释放会话并将该轮判为失败。
- **其他 runner 改动：**`runner/health` 现在报告真实的会话数、运行中轮次数和在途请求数。`rpc.ts` 按 session key 对 `session/new` 排序。`sdk.ts` 额外要求 `pi-ai` 提供 `createAssistantMessageEventStream` 与 `isContextOverflow`。Python 侧只增加测试与支持代码，另在一份设计计划文档中加了一行。
- **范围：**改动 11 个文件，新增约 740 行，其中约 350 行为测试，约 340 行为 `runners/pi` 的 TypeScript。该 PR 描述写的是“测试 386 行、生产代码 0 行（不含夹具）”，未计入 runner 源码。
- **面向模型的变化：**对运行中的 Looper 无：runner 未接入服务，Looper 发送的提示词、工具描述和工具结果均未改变。
