# Looper v2.14.166

This is the patch release v2.14.166, a hotfix line in which each merged change ships at once. It documents one change: [#1301](https://github.com/foolzzz/looper/pull/1301) (project moves and directory changes).

## Release Decision

**Who should upgrade:** Installations that move a project's directory or change its work directory, especially projects containing bare-repo worktrees or submodules, or where command schedules can be enabled during a confirmation. Others need not upgrade for behavior.

**What this release solves:** [#1301](https://github.com/foolzzz/looper/pull/1301) fixes the listed valid items of the review follow-ups #1054 and #1079 (fixes #1054, part of #1079): project moves now handle bare-repo worktrees and submodules, and a directory change confirmation is bound to the previewed state even when the preview showed no command schedules.

**Breaking changes:** No. There is no API change, migration or database schema change. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.166
```

**Contributors:** Maintainer @foolzzz authored [#1301](https://github.com/foolzzz/looper/pull/1301); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.165 upgrades directly. There is no database schema change.

## Behavior changes

[#1301](https://github.com/foolzzz/looper/pull/1301) states that its behavior changes follow the triage notes' fixes (maintainer decision, intended). Read in the code, it changes `looper/agents/project_move.py`, `looper/agents/ops/config.py`, `looper/agents/v1_domains/projects.py` and tests:

- **Confirmation bound to the preview.** The directory-change confirmation (manager config operation and the v1 `project_admin.update` impact) now records the project and directory version even when the preview lists no command schedules (the v1 path only when the directory actually changes). Previously only a preview with schedules was bound, so a command schedule enabled before execution took the project lock was not rechecked; execution now rechecks the version after taking the lock.
- **Bare-repo worktrees.** Repository discovery in a moved tree also finds the bare common repository of a linked worktree under the project and repairs it before linked checkouts. For a bare repository, `git worktree repair` runs with `--git-dir=.` and linked checkouts are matched against the bare repository's `worktrees` directory.
- **Submodules.** A move preview scans the project's repositories' `modules` (and `worktrees/*/modules`) configs. A submodule with a relative `core.worktree` that points outside the project is refused with a 400 error naming the problem (relocate the checkout or use an absolute `core.worktree`). A config that cannot be inspected also fails the preview with a 400 error.
- **Model-visible changes:** None to prompts, tool descriptions or schemas. The refusal and error messages above can appear in a move or directory-change result; a confirmation for a directory change with no schedules is now bound to a version.

### 行为变化与入口

[#1301](https://github.com/foolzzz/looper/pull/1301) 声明行为变化遵循分诊记录中的修复（维护者决定，符合预期）。代码中可见，它改动 `looper/agents/project_move.py`、`looper/agents/ops/config.py`、`looper/agents/v1_domains/projects.py` 及测试：

- **确认绑定到预览。**目录变更确认（manager 配置操作与 v1 `project_admin.update` 的影响预览）现在即使预览中没有命令计划，也会记录项目和目录版本（v1 路径仅在目录确实变化时）。此前只有带计划的预览才会绑定，因此在执行取得项目锁之前启用的命令计划不会被重新检查；现在执行在取得锁后复查该版本。
- **bare 仓库 worktree。**移动树中的仓库发现现在也会找到项目内链接 worktree 的 bare 公共仓库，并在链接检出之前先修复它。对 bare 仓库，`git worktree repair` 以 `--git-dir=.` 运行，链接检出按 bare 仓库的 `worktrees` 目录匹配。
- **submodule。**移动预览会扫描项目仓库的 `modules`（及 `worktrees/*/modules`）配置。submodule 的相对 `core.worktree` 指向项目之外时，预览以 400 错误拒绝并说明原因（迁移该检出或改用绝对 `core.worktree`）；无法检查的配置同样使预览以 400 失败。
- **面向模型的变化：**提示词、工具描述和 schema 均无改动。上述拒绝与错误信息可能出现在移动或目录变更的结果中；无计划的目录变更确认现在会绑定版本。
