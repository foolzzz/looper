# Looper v2.13.195

## Release Decision

**Who should upgrade:** Developers of runner integrations and operators who run the opt-in runner path (`[runtimes] pi = "runner"`) and want the host to be ready for Worker, Reviewer and consult runs. Everyone else sees no difference: no existing session changes, and the default stays on the Pi CLI. It is a hotfix that ships the change merged since v2.13.194.

**What this release solves:** [#834](https://github.com/foolzzz/looper/pull/834) widens the runner protocol and the Python host side so runs, not only the resident Manager and Planner, can use a runner: Worker and Reviewer roles, a session forked from a saved one, and a per-session tool timeout instead of the fixed 120 seconds.

**Breaking changes:** No. No command, database schema, file format or setting changed. The widening only accepts more values (two roles, any positive `tool_timeout_s`, one optional `fork_from` field, one optional `fork` capability); everything the host sent before is still valid.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#834](https://github.com/foolzzz/looper/pull/834); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.195
```

## Behavior changes

- **Protocol (`looper/agents/runtimes/runner/protocol.py`, `runners/protocol/messages.schema.json`, `runners/protocol/cases.json`):** `session/new` and `session/load` accept the roles `worker` and `reviewer` besides `manager` and `planner`. `limits.tool_timeout_s` is any positive integer instead of exactly 120 (zero, negative and boolean values are refused). `session/new` takes an optional `fork_from` object with a `session_id`; `session/load` does not. The `initialize` result may carry a boolean `fork` capability. New protocol cases cover the Worker and Reviewer roles, an unknown role, zero and boolean timeouts, and the fork capability.
- **Supervisor (`supervisor.py`):** `RunnerSupervisor.acquire` takes an optional `state_dir`, which must be absolute and cannot be combined with `owner`; the lease then uses that directory (its parent is created privately) instead of a per-lease or per-owner one, so the state survives the release of the lease. Without it, behavior is unchanged.
- **Session (`session.py`):** `Descriptor` carries the new roles, `tool_timeout_s` (default 120, must be positive when parsed from argv) and `fork_from`; `session` and `fork_from` are mutually exclusive. The host now sends the descriptor's `tool_timeout_s` instead of a constant 120. `RunnerSession` can open a run session without owner state (`owned=False`, with an optional `state_dir`). A descriptor with `fork_from` opens through `session/new` with `fork_from`, and only when the runner reports the `fork` capability; otherwise the open fails with `UNSUPPORTED`. If the runner refuses the fork with `SESSION_NOT_FOUND` or `SESSION_OWNED`, it takes the existing resume-failure path (the lease is released and the session is marked lost) as a failed resume does.
- **Turn (`turn.py`):** `RunnerTurn` accepts `worker` and `reviewer`; the positive `max_requests` cap is kept.
- **Docs and scope:** 9 files changed, all on the Python host side and the protocol files; the pull request reports "tests 149, production 61 (fixtures excluded)". The Pi runner (`runners/pi`) is not changed, so it is not yet shown here to serve these roles or to fork.
- **Model-visible changes:** None. No prompt, tool description or tool result changed, and no existing role or runtime sends different content. The default `tool_timeout_s` stays 120, so the limits sent to a Manager or Planner session are the same as before.

## Upgrade and rollback

Re-run `install.sh` once v2.13.195 is published. There is nothing to configure. To roll back, return to v2.13.194; there is no schema or setting change.

## 中文摘要

### 升级决策

**谁需要升级：**开发 runner 集成、或使用选择加入的 runner 路径（`[runtimes] pi = "runner"`）并希望宿主为 Worker、Reviewer 和 consult 运行做好准备的运维者；其他用户无差别，现有会话不变，默认仍走 Pi CLI。本版本是随合并即发布的 hotfix，包含 v2.13.194 之后合并的改动。

**解决了什么：**[#834](https://github.com/foolzzz/looper/pull/834) 扩展 runner 协议和 Python 宿主侧，使运行（而不只是常驻的 Manager 和 Planner）也能使用 runner：新增 Worker 与 Reviewer 角色、从已保存会话分叉出新会话、以及每会话可配置的工具超时（不再固定 120 秒）。

**是否有破坏性变更：**无。命令、数据库 schema、文件格式和设置均未改变。扩展只是接受更多取值（两个角色、任意正数 `tool_timeout_s`、一个可选的 `fork_from` 字段和一个可选的 `fork` 能力），宿主此前发送的内容仍然有效。

**如何验证：**运行 `looper --version` 核对版本为 2.13.195。

**贡献者：**维护者 @foolzzz 提交 [#834](https://github.com/foolzzz/looper/pull/834)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.195
```

### 行为变化与入口

- **协议（`protocol.py`、`messages.schema.json`、`cases.json`）：**`session/new` 和 `session/load` 除 `manager`、`planner` 外还接受 `worker`、`reviewer`。`limits.tool_timeout_s` 为任意正整数而非恰好 120（零、负数和布尔值被拒绝）。`session/new` 可带可选的 `fork_from` 对象（含 `session_id`），`session/load` 不可。`initialize` 结果可带布尔 `fork` 能力。新增协议用例覆盖 Worker、Reviewer 角色、未知角色、零值和布尔超时以及 fork 能力。
- **Supervisor（`supervisor.py`）：**`RunnerSupervisor.acquire` 新增可选 `state_dir`，必须是绝对路径，且不能与 `owner` 同时使用；租约使用该目录（其父目录以私有权限创建），而不是每租约或每 owner 的目录，因此状态在租约释放后保留。不传时行为不变。
- **Session（`session.py`）：**`Descriptor` 携带新角色、`tool_timeout_s`（默认 120，从 argv 解析时必须为正）和 `fork_from`；`session` 与 `fork_from` 互斥。宿主现在发送描述符中的 `tool_timeout_s`，不再是常量 120。`RunnerSession` 可在没有 owner 状态时打开运行会话（`owned=False`，可选 `state_dir`）。带 `fork_from` 的描述符通过带 `fork_from` 的 `session/new` 打开，且仅当 runner 报告 `fork` 能力；否则以 `UNSUPPORTED` 失败。若 runner 以 `SESSION_NOT_FOUND` 或 `SESSION_OWNED` 拒绝分叉，则与恢复失败一样走既有的恢复失败路径（释放租约并标记会话丢失）。
- **Turn（`turn.py`）：**`RunnerTurn` 接受 `worker` 和 `reviewer`，保留正数 `max_requests` 上限。
- **文档与范围：**共改动 9 个文件，均在 Python 宿主侧和协议文件；PR 描述写的是“测试 149 行、生产代码 61 行（不含夹具）”。Pi runner（`runners/pi`）未改动，因此尚未表明它支持这些角色或分叉。
- **面向模型的变化：**无。提示词、工具描述和工具结果均未改变，现有角色和运行时发送的内容不变。默认 `tool_timeout_s` 仍为 120，Manager 和 Planner 会话收到的限制与之前相同。
