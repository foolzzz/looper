# Looper v2.14.9

This is the patch release v2.14.9. It ships the one change merged since v2.14.8: [#889](https://github.com/foolzzz/looper/pull/889), which makes the DSH runner count a request complete at its validated terminal event instead of waiting for the HTTP body to drain. It affects only installations that set `[runtimes] dsh = "runner"`.

## Release Decision

**Who should upgrade:** Operators who run DSH roles on the DSH runner (`[runtimes] dsh = "runner"`), above all those who saw Manager turns stop with `budget_unverifiable` at about zero cost. Nothing changes for an installation whose ops file does not set it (the default is `cli`). It ships the one change merged since v2.14.8.

**What this release solves:** [#889](https://github.com/foolzzz/looper/pull/889): the runner reported a normal successful request as usage-incomplete when the SDK stopped reading the response after `message_stop` and the HTTP body had not drained yet, which in a real DeepSeek comparison stopped Manager turns with `budget_unverifiable` (the CLI path passed 4/4). A successful stream is now complete once `message_stop` arrives with validated terminal usage.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#889](https://github.com/foolzzz/looper/pull/889); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.9
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.8 upgrades directly. This release changes no schema, stored data or setting.

## Behavior changes

All runtime changes are in the packaged runner source `runners/dsh/src/provider.ts` and are reached only with `[runtimes] dsh = "runner"`.

- **Completeness no longer waits for the HTTP body to drain:** the provider usage observer sees only 2xx streams, and its validated `message_stop` (terminal usage with provider counts) is now authoritative. A request that finishes successfully (`stop`, `tool-calls` or `max-tokens`) with validated terminal usage is complete whether or not the body was read to the end. Before, completeness also required the body-drained signal, which never arrived when the SDK stopped reading after `message_stop`, so the request was recorded as usage-incomplete. A rejection (HTTP status 400 or above) is unchanged: it still counts as complete only when the response body was fully read and no model output was produced.
- **New diagnostic for incomplete requests:** when a request that was sent is still not complete, the runner writes one stderr line `usage_incomplete request_id=... status=... missing=...` naming the missing conditions (`message_stop`, `terminal_usage`, `successful_finish`, `body_drained_on_error`) with the `message_stop`, `terminal_usage` and `body_done` flags. It carries no request content.
- **Tests and docs:** `tests/test_dsh_runner_requests.py` adds cases for completion before a delayed HTTP EOF (immediate and delayed EOF; output counts taken from `message_delta` or `message_stop`) and for the diagnostic (stream drained without `message_stop`, connection dropped before it, truncated rejection); the stand-in server in `tests/dsh_installed_stand_in.py` can delay EOF. `tests/test_pi_packaging.py` now builds its wheel with uv's own dependency cache instead of a cache under the isolated test home, and no longer honors a caller-supplied `UV_CACHE_DIR`. The Chinese long-horizon context plan gains one progress row.
- **Model-visible changes:** None. Prompts, tools and model requests are unchanged. The visible effect is on the host side: the request is recorded complete, so the budget check no longer reports `budget_unverifiable` for it.

## 中文摘要

本版本是 patch release v2.14.9。自 v2.14.8 以来只合并了 [#889](https://github.com/foolzzz/looper/pull/889)：DSH runner 在已校验的终止事件处把请求计为完整，不再等待 HTTP 响应体读完。只影响设置了 `[runtimes] dsh = "runner"` 的安装。

### 升级决策

**谁需要升级：**使用 DSH runner（`[runtimes] dsh = "runner"`）承载 DSH 角色的运维者，尤其是 Manager 回合因 `budget_unverifiable` 在约零成本处停止的用户。运维文件未设置该项（默认 `cli`）的安装没有任何变化。包含 v2.14.8 之后合并的唯一改动。

**解决了什么：**[#889](https://github.com/foolzzz/looper/pull/889)：当 SDK 在 `message_stop` 之后停止读取、HTTP 响应体尚未读完时，runner 把正常成功的请求误报为用量不完整；在真实 DeepSeek 对比中这使 Manager 回合以 `budget_unverifiable` 停止（CLI 路径 4/4 通过）。现在成功的流在 `message_stop` 带着已校验的终止用量到达时即为完整。

**是否有破坏性变更：**否。受支持的升级路径不变（见升级）。

**如何验证：**运行 `looper --version` 核对版本为 2.14.9。

**贡献者：**维护者 @foolzzz 提交 [#889](https://github.com/foolzzz/looper/pull/889)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.9
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.8 上的安装可直接升级。本版本不改 schema、已存数据或设置。

### 行为变化与入口

运行时改动都在打包的 runner 源码 `runners/dsh/src/provider.ts` 中，仅在 `[runtimes] dsh = "runner"` 时生效。

- **完整性不再等待响应体读完：**用量观察器只看 2xx 流，其已校验的 `message_stop`（带提供方计数的终止用量）现在具有权威性。成功结束（`stop`、`tool-calls` 或 `max-tokens`）且终止用量已校验的请求，无论响应体是否读完都算完整。此前完整性还要求响应体读完的信号，而 SDK 在 `message_stop` 后停止读取时该信号永远不会到来，请求因此被记为用量不完整。拒绝（HTTP 状态 400 及以上）不变：仍须响应体完整读完且没有模型输出才算完整。
- **未完成请求的新诊断：**已发送的请求仍不完整时，runner 向 stderr 写一行 `usage_incomplete request_id=... status=... missing=...`，列出缺失条件（`message_stop`、`terminal_usage`、`successful_finish`、`body_drained_on_error`）以及 `message_stop`、`terminal_usage`、`body_done` 标志，不含请求内容。
- **测试与文档：**`tests/test_dsh_runner_requests.py` 新增 HTTP EOF 延迟前完成的用例（立即与延迟 EOF；输出计数取自 `message_delta` 或 `message_stop`）和诊断用例（流读完但无 `message_stop`、`message_stop` 前断流、被截断的拒绝）；`tests/dsh_installed_stand_in.py` 的替身服务可延迟 EOF。`tests/test_pi_packaging.py` 现在用 uv 自身的依赖缓存构建 wheel，而不是隔离测试 home 下的缓存，也不再采用调用方提供的 `UV_CACHE_DIR`。中文长程上下文计划新增一行进展记录。
- **面向模型的变化：**无。提示、工具和模型请求都不变。可见影响在宿主侧：该请求被记为完整，预算检查不再为其报告 `budget_unverifiable`。
