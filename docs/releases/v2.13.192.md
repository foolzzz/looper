# Looper v2.13.192

## Release Decision

**Who should upgrade:** Maintainers and contributors working on the Pi runner. Other users see no difference. It is a hotfix that ships the change merged since v2.13.191.

**What this release solves:** [#823](https://github.com/foolzzz/looper/pull/823) lets Pi runner sessions use Looper platform tools through the host (`tools/call`) and accept `session/steer` messages during a running turn. The runner is not registered with the service, so no running Looper reaches it yet.

**Breaking changes:** No. No command, database schema or file format changed, and no Python code changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#823](https://github.com/foolzzz/looper/pull/823); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.192
```

## Behavior changes

- **Platform tools ([#823](https://github.com/foolzzz/looper/pull/823)):** the new `runners/pi/src/tools.ts` registers the tools in each `session/prompt` snapshot (`name`, `description`, `inputSchema`) with Pi, and the active tool set becomes the session's builtin tools plus the snapshot. Before this change a prompt with any platform tool was refused (`-32007`). The whole snapshot is validated first; an invalid one fails with `-32602` before the turn is accepted. A name must match `[A-Za-z0-9_-]+`, be unique and not collide with a builtin name, and `inputSchema.type` must be absent or `object`. The runner does not add a prefix or rename tools: the names are used as the host sends them. A tool that is in an earlier snapshot but not in the next one stays registered but hidden and is not active.
- **Tool execution (`tools.ts`):** a platform tool call is sent to the host as a reverse `tools/call` request (`session_id`, `trace_id`, `call_id`, `name`, `arguments`), and the host's `text` and `is_error` are returned to the model unchanged. Tools run sequentially. If the turn is already settled, settling, cancelled or aborted, the call returns an error result ("Looper stopped this turn before <name> ran"). If the request is aborted, the result says the call may still have run; any other request failure returns "Looper did not run the tool <name>: …" with the message scrubbed.
- **Steering (`turn.ts`, `main.ts`):** new method `session/steer` (`trace_id`, `message_id`, `text`, `if_idle: "reject"`) queues text into the running turn and returns `status: "queued"`. It fails with `-32004` when no turn is running (or the turn is settling or cancelled), `-32005` on a trace mismatch and `-32602` on invalid parameters. A repeated `message_id` is ignored. `initialize` now declares `steer.in_trace: true` (boundary `after_tool_batch`, `idle_start: false`).
- **Steer reports (`turn.ts`, `provider.ts`):** when a provider request is sent whose context contains the steered user message, the runner emits `steer_applied` with `message_id`, `after_request_id`, `after_tool_batch` and `new_turn: false`. A steer that does not reach a request is reported as `steer_dropped` with reason `turn_ended`, `cancelled` or `session_closed`. A steer already drained into history when dropped is removed from the SDK messages and a context edit omitting it is persisted in the session, so later turns do not see it.
- **Cancellation (`provider.ts`, `turn.ts`):** cancel and close now drop pending steers before aborting, and a provider request started after the turn was cancelled, settled or aborted fails with "request aborted" instead of being sent.
- **Session setup (`session.ts`):** Pi's tool allowlist is now created with `noTools: 'builtin'` plus the custom builtin tools, and an inline extension captures the extension API used for registration. If the extension is not loaded, the session fails with `-32008`. No skill or other extension is loaded.
- **Scope:** 9 files changed, 733 added and 13 deleted lines, of which 563 added lines are in test files (525 in the new `tests/test_pi_runner_tools.py`). The pull request reports "tests 429, production 0 (fixtures excluded)", which does not count the runner source and is lower than the test-file total.
- **Model-visible changes:** None for any running Looper: the runner is not wired to the service, and no prompt, tool description or tool result Looper sends changed. Inside a Pi session, the model sees the platform tools from the snapshot with the host's description and schema, receives the host's tool result text unchanged (or the error texts quoted above), and sees a steer as an extra user message appended after the current tool batch.

### 行为变化与入口

- **平台工具（#823）：**新增的 `runners/pi/src/tools.ts` 把每次 `session/prompt` 快照里的工具（`name`、`description`、`inputSchema`）注册到 Pi，激活的工具集为会话内置工具加快照工具。此前带平台工具的 prompt 会被拒绝（`-32007`）。整个快照先校验，无效则在回合被接受前以 `-32602` 失败。名称须匹配 `[A-Za-z0-9_-]+`、唯一且不与内置工具重名，`inputSchema.type` 须缺省或为 `object`。runner 不加前缀也不改名，按宿主发来的名称使用。出现在旧快照而不在新快照中的工具保持注册但隐藏，且不激活。
- **工具执行（`tools.ts`）：**平台工具调用作为反向 `tools/call` 请求（`session_id`、`trace_id`、`call_id`、`name`、`arguments`）发给宿主，宿主返回的 `text` 与 `is_error` 原样交给模型。工具按顺序执行。若回合已结束、正在结束、已取消或已中止，调用返回错误结果（“Looper stopped this turn before <name> ran”）；请求被中止时结果说明该调用可能已执行；其他请求失败返回“Looper did not run the tool <name>: …”，消息经过脱敏。
- **Steer（`turn.ts`、`main.ts`）：**新方法 `session/steer`（`trace_id`、`message_id`、`text`、`if_idle: "reject"`）把文本排入运行中的回合并返回 `status: "queued"`。无运行中的回合（或回合正在结束、已取消）返回 `-32004`，trace 不匹配返回 `-32005`，参数无效返回 `-32602`。重复的 `message_id` 被忽略。`initialize` 现在声明 `steer.in_trace: true`（边界 `after_tool_batch`，`idle_start: false`）。
- **Steer 报告（`turn.ts`、`provider.ts`）：**当发出的 provider 请求上下文包含被 steer 的用户消息时，runner 发出 `steer_applied`（含 `message_id`、`after_request_id`、`after_tool_batch`、`new_turn: false`）。未进入任何请求的 steer 以 `steer_dropped` 报告，原因为 `turn_ended`、`cancelled` 或 `session_closed`。丢弃时已进入历史的 steer 会从 SDK 消息中移除，并在会话中持久化一条省略它的上下文编辑，后续回合不会看到它。
- **取消（`provider.ts`、`turn.ts`）：**取消与关闭现在在中止前先丢弃待处理的 steer；回合已取消、结束或中止后才开始的 provider 请求会以“request aborted”失败而不再发出。
- **会话创建（`session.ts`）：**Pi 的工具白名单改用 `noTools: 'builtin'` 加自定义内置工具，并用内联扩展获取注册所需的扩展 API；扩展未加载则以 `-32008` 失败。不加载任何技能或其他扩展。
- **范围：**改动 9 个文件，新增 733 行、删除 13 行，其中测试文件新增 563 行（新文件 `tests/test_pi_runner_tools.py` 占 525 行）。该 PR 描述写的是“测试 429 行、生产代码 0 行（不含夹具）”，未计入 runner 源码，也低于测试文件的合计。
- **面向模型的变化：**对运行中的 Looper 无：runner 未接入服务，Looper 发送的提示词、工具描述和工具结果均未改变。在 Pi 会话内，模型会看到快照中的平台工具（宿主给出的描述与 schema），收到宿主原样返回的工具结果文本（或上述错误文本），并在当前工具批之后看到 steer 作为额外的用户消息。
