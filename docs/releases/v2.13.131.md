# Looper v2.13.131

## Release Decision

**Who should upgrade:** Nobody needs to upgrade for existing behavior. Operators who use the Chat bindings section in Channels settings, especially with many observed chats or with Only bound chats on, should upgrade, because the view now re-reads the server after every write.

**What this release solves:** [#661](https://github.com/foolzzz/looper/pull/661) keeps the Channels chat bindings view in step with the server. After a write the view rebuilds its page boundaries from a fresh read instead of reusing old cursors, it re-reads after a refused write too, and the unbind option says what actually happens under the current policy.

**Breaking changes:** No. The change is dashboard-only. No API, schema or configuration changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#661](https://github.com/foolzzz/looper/pull/661); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.131
```

## Behavior changes

- **Page boundaries are rebuilt from each read (#661):** `web/src/components/channel-chat-bindings.tsx` no longer keeps a list of page cursors. It keeps the number of loaded rows and, on each load, fetches pages of 20 from the start, following `next_cursor` until it has at least that many rows or the server has no more. A chat observed after the first load and sorting before an old cursor therefore no longer shifts or duplicates rows. "Load more chats" asks for the loaded row count plus 20; "Refresh chats" asks for 0 rows, which reads only the first page.
- **Every write is followed by a full re-read (#661):** the section reloads chats, bindings and the Manager list after a write whether it succeeded or failed, and the write's error message is kept. This replaces the earlier success-only reload and the special case that refreshed only the Manager list after a 404. The re-read also supersedes the pending readback of an earlier write, so the view settles on confirmed server state.
- **Unbind option wording (#661):** the empty option of each chat's select reads "Leave unbound (silent)" when Only bound chats is on for the bot, and "Use this bot's Manager (no binding)" otherwise.
- **Tests (#661):** three new Vitest cases cover a failed binding superseding a pending readback, a refused unbind keeping its error while reading current state, and reloading from fresh page boundaries without losing or duplicating chats. A new browser test covers a write after "Load more chats" with a new chat inserted ahead of the loaded pages. The keyboard and layout browser test now runs at 390 px instead of 768 px, checks the option wording, and screenshots the section per width.
- **Model-visible changes:** none found. The diff touches only a dashboard component and tests. It changes no prompt, tool declaration or tool result.
- **Line counts:** the description reports tests 32 and production 82 added lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.131 is published. No schema or configuration change. Rolling back to v2.13.130 restores the cursor-based paging and success-only reload; saved bindings are unaffected.

### 升级决策

**谁需要升级：**无需为现有行为而升级。使用 Channels 设置中“Chat bindings”区块的操作者，尤其是已见聊天很多或开启了仅限绑定聊天的，应升级，因为该视图现在在每次写入后都会重读服务端。

**解决了什么：**[#661](https://github.com/foolzzz/looper/pull/661) 让 Channels 聊天绑定视图与服务端保持一致。写入后视图从新读取重建分页边界而不是复用旧游标，写入被拒绝后同样重读，解绑选项也按当前策略说明实际效果。

**是否有破坏性变更：**否。改动只在仪表盘，没有 API、表结构或配置变更。

**如何验证：**运行 `looper --version` 核对版本为 2.13.131。

**贡献者：**维护者 @foolzzz 提交 [#661](https://github.com/foolzzz/looper/pull/661)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.131
```

### 行为变化与入口

- **每次读取都重建分页边界（#661）：**`web/src/components/channel-chat-bindings.tsx` 不再保存分页游标列表，而是记录已加载行数；每次加载从头按每页 20 条读取，沿 `next_cursor` 继续，直到行数足够或服务端没有更多。加载后新出现、排在旧游标之前的聊天不再造成行错位或重复。“Load more chats”请求已加载行数加 20；“Refresh chats”请求 0 行，即只读第一页。
- **每次写入后完整重读（#661）：**无论写入成功还是失败，区块都会重新加载聊天、绑定和 Manager 列表，并保留写入的错误信息。这取代了原先仅成功后重载、以及 404 时只刷新 Manager 列表的特殊处理。重读也会取代之前写入尚未完成的重读，使视图落到已确认的服务端状态。
- **解绑选项文案（#661）：**每个聊天下拉框的空选项在 bot 开启仅限绑定聊天时显示“Leave unbound (silent)”，否则显示“Use this bot's Manager (no binding)”。
- **测试（#661）：**新增三个 Vitest 用例：失败的绑定取代待完成的重读、被拒绝的解绑保留错误并读取当前状态、写入后从新分页边界重载且不丢失不重复聊天。新增浏览器测试覆盖“Load more chats”之后、在已加载页前插入新聊天时的写入。键盘与布局浏览器测试的宽度由 768 px 改为 390 px，检查选项文案，并按宽度截取区块截图。
- **面向模型的变化：**未发现。diff 只触及一个仪表盘组件和测试，不改提示词、tool 声明或 tool 结果。
- **行数：**描述报告新增测试 32 行、生产代码 82 行（不含 fixtures）。
