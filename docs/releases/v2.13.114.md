# Looper v2.13.114

## Release Decision

**Who should upgrade:** Anyone who sends messages to a running Worker (Planner chat forwarding, Planner steering, room reminders) on the Codex, OMP, Pi or stream runtimes. Others do not need it.

**What this release solves:** [#607](https://github.com/foolzzz/looper/pull/607) makes Worker input delivery distinguish accepted, rejected and unknown. Before, a timeout or a bad acknowledgement counted as a failure and the Planner kept the text for its next decision even though the Worker might already have acted on it. Now only a definite rejection is kept; an unknown outcome is not replayed.

**Breaking changes:** No. No route, configuration, request field or stored data format changed. The `delivered` field of the internal Worker input result message may now be `null` as well as `true` or `false`.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#607](https://github.com/foolzzz/looper/pull/607); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.114
```

## Behavior changes

- **Delivery result:** `looper/agents/runtimes/channel.py` adds `DeliveryResult` (`ACCEPTED`, `REJECTED`, `UNKNOWN`; only `ACCEPTED` is truthy) and `delivery_attempt`, a bounded send that marks the outcome unknown if a timeout or broken pipe happens after bytes were written, and rejected if before. `RunChannel.send` now returns a `DeliveryResult`.
- **Runtimes:** the stream channel, Codex steer, OMP steer and Pi steer all use it. An explicit refusal from OMP (`success: false`) or Pi still raises `RuntimeError`; a response for the wrong command, a missing `success`, or (Pi) a disposition other than `queued` or `handled` is now unknown instead of an error. Pi "handled, not queued" still raises.
- **Worker pool:** `send_input` returns a `DeliveryResult`; empty text, no channel, too little time left, a pool timeout and pipe or runtime errors are rejected, and the channel's own result is passed through. The Worker input result message carries `delivered` as `true`, `false` or `null`. Room reminders register their UUID before sending, drop it only on rejection, and an unknown outcome is not retried and does not stop event reading.
- **Planner:** a forwarded user message or a Planner steer that is accepted behaves as before. If rejected, the text is added to the step's `missed_messages` for the Planner's decision, and the user is told the Worker did not accept it. If unknown (including an acknowledgement that never arrives), it is not resent and not added to `missed_messages`; the user is told acceptance is unconfirmed and it will not be resent.
- **Claude CLI:** when a user turn is abandoned by cancellation, the output the killed process still writes is discarded rather than given to a later turn.
- **Model-visible changes:** no tool declaration, prompt or route changed, and the text sent to Workers is unchanged. What changed is which user texts reach the Planner's decision turn: unknown-outcome texts no longer do. The Chinese reply shown to the user after a forwarded message also changed.
- **Tests and docs:** tests for the channel, Codex, OMP, Pi, Planner and Worker input paths were updated or added, and a line was added to the Chinese long-horizon context plan. [#607](https://github.com/foolzzz/looper/pull/607) reports added lines: tests 155, production 122 (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.114 is published. No data migration and no configuration change. Rolling back to v2.13.113 restores the old behavior, where an unknown outcome is treated as failed and its text is kept for the Planner.

## 中文摘要

### 升级决策

**谁需要升级：**在 Codex、OMP、Pi 或 stream 运行时上向运行中的 Worker 发消息（Planner 聊天转发、Planner 纠偏、办公台提醒）的用户。其他人无需升级。

**解决了什么：**[#607](https://github.com/foolzzz/looper/pull/607) 让 Worker 输入投递区分已接受、已拒绝和未知。此前超时或确认格式错误都按失败处理，Planner 会把文本留给下一次决策，而 Worker 可能已经按它行动。现在只有明确拒绝才会保留；结果未知时不再重放。

**是否有破坏性变更：**否。路由、配置、请求字段和存储数据格式均未改变。内部 Worker 输入结果消息的 `delivered` 字段除 `true`、`false` 外现在也可能为 `null`。

**如何验证：**运行 `looper --version` 核对版本为 2.13.114。

**贡献者：**维护者 @foolzzz 提交 [#607](https://github.com/foolzzz/looper/pull/607)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.114
```

### 行为变化与入口

- **投递结果：**`looper/agents/runtimes/channel.py` 新增 `DeliveryResult`（`ACCEPTED`、`REJECTED`、`UNKNOWN`，只有 `ACCEPTED` 为真值）和 `delivery_attempt`：写入字节之后发生超时或管道断开记为未知，之前则记为拒绝。`RunChannel.send` 现在返回 `DeliveryResult`。
- **运行时：**stream 通道、Codex、OMP、Pi 的 steer 均采用。OMP（`success: false`）或 Pi 的明确拒绝仍抛出 `RuntimeError`；命令不符、缺少 `success`，或（Pi）disposition 不是 `queued`/`handled`，现在记为未知而不是错误。Pi 的 “handled, not queued” 仍抛错。
- **Worker 池：**`send_input` 返回 `DeliveryResult`；空文本、无通道、剩余时间不足、池超时以及管道或运行时错误记为拒绝，通道自身的结果原样传递。Worker 输入结果消息的 `delivered` 为 `true`、`false` 或 `null`。办公台提醒先登记 UUID 再发送，仅在拒绝时撤销；结果未知时不重试，也不终止事件读取。
- **Planner：**转发的用户消息或 Planner 纠偏被接受时行为不变。被拒绝时，文本加入该步骤的 `missed_messages` 供 Planner 决策，并告知用户 Worker 未接受。结果未知（包括确认始终未到）时不重发，也不加入 `missed_messages`；告知用户是否被接受尚未确认，且不会自动重发。
- **Claude CLI：**用户轮次因取消被放弃时，被终止的进程之后写出的输出会被丢弃，不再归入后续轮次。
- **面向模型的变化：**tool 声明、提示词和路由均未改变，发给 Worker 的文本不变。变化在于哪些用户文本会进入 Planner 的决策轮：结果未知的文本不再进入。转发消息后显示给用户的中文回复也有改动。
- **测试与文档：**更新或新增了通道、Codex、OMP、Pi、Planner 和 Worker 输入路径的测试，并在中文长程上下文计划中增加一行。[#607](https://github.com/foolzzz/looper/pull/607) 报告新增行数：测试 155、生产代码 122（不含夹具）。

### 升级与回退

v2.13.114 发布后重跑 `install.sh`。无需迁移数据，无需改配置。回退到 v2.13.113 会恢复旧行为：未知结果按失败处理，文本留给 Planner。
