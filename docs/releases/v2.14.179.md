# Looper v2.14.179

This is the patch release v2.14.179, a hotfix line in which each merged change ships at once. It documents one change: [#1334](https://github.com/foolzzz/looper/pull/1334) (session profile reads no longer wait for runtime sign-in probes).

## Release Decision

**Who should upgrade:** Anyone who reads or switches the Manager session's Agent Profile (dashboard profile picker, Telegram or Lark `/profile`) with a TTADK, Cursor or Coco profile, and anyone whose API client reads the session profile choices.

**What this release solves:** [#1334](https://github.com/foolzzz/looper/pull/1334) keeps Manager session reads and profile selection responsive while a runtime sign-in probe is pending. Actual launches still wait for the authentication check and reject known blocking problems.

**Breaking changes:** No. Each session profile choice may carry one new optional field, `checking`, which a strict client sees as one more key; `problem` keeps its meaning. There is no database change, and the bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.179
```

**Contributors:** Maintainer @foolzzz authored [#1334](https://github.com/foolzzz/looper/pull/1334); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.178 upgrades directly. There is no database change.

## Behavior changes

Read in the diff of [#1334](https://github.com/foolzzz/looper/pull/1334):

- **Views read cached sign-in state** (`looper/agents/agent_settings.py`, `looper/agents/runtimes/`). `load_agent_settings`, `profile_launch_problem` and the runtime adapters' `login_problem` take a `wait` argument, default `True`. With `wait=False`, Cursor and Coco return the cached sign-in state and start at most one background refresh per key (`cursor_login.cached_status`, `coco_login.cached_status`); TTADK already had a cached mode. Coco views read only the cached model catalog. Launch and fallback callers keep `wait=True`. The Coco login view now reports `checking`, and `refreshing` while it refreshes, instead of probing inline; `forget_probe` replaces the cache instead of clearing it, so it never waits for a CLI.
- **Profile choices** (`looper/agents/session_profile.py`). `choices` reads the profile rows once and checks the choices concurrently with `wait=False`. Unknown state returns `problem: null` plus `checking: true`. The Manager's session view, `/profile` list, settings profile name and the profile selection paths (`select_session_profile`, `_selectable_profile`, `_record_profile_choice`) use the nonblocking check, so selection accepts an unknown state and rejects a known blocking problem; the next launch checks again.
- **Route registry before listening** (`looper/agents/http_server.py`). The server resolves lazy API route discovery before it accepts requests. Previously cold discovery ran inside the first session HTTP request, which the PR reports delayed the handler and caused a client timeout, and caused the later `pool is closing` warning.
- **Result schema** (`looper/agents/v1_domains/chat_controls.py`). The session profile choice gains an optional boolean `checking`; the other fields stay required.
- **Tests and docs.** A new `tests/test_session_profile_nonblocking_db.py`, a fallback-adoption test double that accepts the keyword-only `wait`, and one line in a Chinese planning document.
- **Model-visible changes:** No. No prompt, tool description or tool schema changed (the PR also states no prompt or UI content changed). The only changed contract is the optional `checking` field of the session profile choice in the HTTP API result; the dashboard, Telegram and Lark use the existing picker and shared list logic, and CLI launch behavior is unchanged.

## Validation

**Reported by the pull request:** [#1334](https://github.com/foolzzz/looper/pull/1334) reports five disposable PostgreSQL regression cases passing (five-second TTADK, Cursor and Coco probes, single-flight views, unknown-state selection, blocking launch rejection, one profile-list query, authenticated HTTP read/select/readback). A unit-only targeted suite gave 250 passed and 43 database cases skipped. A real isolated `looper serve` smoke passed (initial read 748.0 ms, selection/readback 674.0 ms; 100 consecutive reads p99 88.2 ms), reported as controlled samples, not a production SLO.

The PR states that its local full xdist attempt stopped before collection (disposable worker-database creation exceeded a 30-second lock timeout), so no local full-suite pass is claimed. It also reports that the local fallback-adoption retry did not pass and is not counted; its CI reported all shards but the first three still running when the description was written, with the fourth shard, Dashboard and PostgreSQL 18 passing after the test-double fix. The PR lists no review results.

### 行为变化与入口

以下在 [#1334](https://github.com/foolzzz/looper/pull/1334) 的差异中可见：

- **视图读取缓存的登录状态**（`looper/agents/agent_settings.py`、`looper/agents/runtimes/`）。`load_agent_settings`、`profile_launch_problem` 和各运行时适配器的 `login_problem` 新增 `wait` 参数，默认 `True`。`wait=False` 时，Cursor 与 Coco 返回缓存的登录状态，并对每个键最多启动一次后台刷新（`cursor_login.cached_status`、`coco_login.cached_status`）；TTADK 原本已有缓存模式。Coco 视图只读缓存的模型目录。启动与回退调用方保持 `wait=True`。Coco 登录视图现在报告 `checking`（刷新时带 `refreshing`），不再同步探测；`forget_probe` 改为替换缓存而不是清空，因此不会等待 CLI。
- **Profile 选项**（`looper/agents/session_profile.py`）。`choices` 只读取一次 Profile 行，并以 `wait=False` 并发检查各选项。状态未知时返回 `problem: null` 和 `checking: true`。Manager 的会话视图、`/profile` 列表、设置中的 Profile 名称以及选择路径（`select_session_profile`、`_selectable_profile`、`_record_profile_choice`）都使用非阻塞检查，因此选择接受未知状态、拒绝已知的阻塞问题；下次启动会再次检查。
- **监听前注册路由**（`looper/agents/http_server.py`）。服务在接受请求前完成 API 路由的惰性发现。PR 称此前冷发现发生在首个会话 HTTP 请求内，造成处理延迟和客户端超时，并引发之后的 `pool is closing` 警告。
- **结果 schema**（`looper/agents/v1_domains/chat_controls.py`）。会话 Profile 选项新增可选布尔字段 `checking`，其余字段仍为必填。
- **测试与文档。**新增 `tests/test_session_profile_nonblocking_db.py`，fallback-adoption 测试替身接受仅限关键字的 `wait`，并在一份中文规划文档中加一行。
- **面向模型的变化：**无。提示词、工具描述和工具 schema 均未改变（PR 也称没有提示词或 UI 内容改动）。唯一变化的契约是 HTTP API 结果中会话 Profile 选项的可选字段 `checking`；仪表盘、Telegram 和 Lark 使用现有选择器和共用的列表逻辑，CLI 启动行为不变。
