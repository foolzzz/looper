# Looper v2.14.35

This is the patch release v2.14.35, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.34: per-schedule alert thresholds, two new alerts (success deadline and consecutive overlap skips) and command run messages ([#963](https://github.com/foolzzz/looper/pull/963)).

## Release Decision

**Who should upgrade:** Anyone who wants schedule alerts tuned per schedule, a daily success deadline, a warning when a schedule keeps skipping because its previous run has not ended, or run messages for command schedules that carry the exit code and log tail.

**What this release solves:** [#963](https://github.com/foolzzz/looper/pull/963) makes the notifier read each schedule's alert thresholds, adds the deadline and overlap alerts with their recoveries, writes command run messages with the exit code, duration, log tail and a run link, and shows the two new alerts in "Failing now" on the overview.

**Breaking changes:** No. No API, default or configuration is removed, and there is no new migration. The behavior changes are listed below.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#963](https://github.com/foolzzz/looper/pull/963); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.35
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.34 upgrades directly. This release adds no migration: the columns it reads (`alert_failures_after`, `alert_stale_after_seconds`, `alert_overlap_after`, `success_deadline`, `consecutive_overlaps`, `deadline_alert_at`, `overlap_alert_at`) are already in the schema.

## Behavior changes

- **Per-schedule alert thresholds ([#963](https://github.com/foolzzz/looper/pull/963)).** In `looper/agents/schedule_notify.py`, `alert_policy` resolves a schedule's thresholds; a null value keeps the previous behavior.
  - `alert_failures_after` replaces the fixed 3 consecutive failures.
  - `alert_stale_after_seconds`, when set, replaces the period-based stale window (3 periods, at least 15 minutes, at most 24 hours).
  - `alert_overlap_after` is the number of consecutive overlap skips that alerts; null means 10 for a command schedule and no alert for an agent schedule, and 0 disables it.
- **Success deadline alert ([#963](https://github.com/foolzzz/looper/pull/963)).** A schedule's `success_deadline` is `HH:MM` in its time zone; any other value is rejected on create and update. Each scheduler pass checks it: if the latest deadline passed, the schedule fired in the window since the previous deadline (or since it was enabled or its rule or deadline changed), and no run succeeded after the previous deadline, one alert goes out, naming the last success, the run in progress or the latest run. Changing the deadline restarts the counting window. The next OK run sends one recovery.
- **Overlap skip alert ([#963](https://github.com/foolzzz/looper/pull/963)).** Each `skipped_overlap` increments `consecutive_overlaps` in the transaction that records the skip. At the threshold one alert goes out, naming the run that is still going. Any run that starts (a gate, command or agent run) resets the streak and sends one recovery.
- **Command run messages ([#963](https://github.com/foolzzz/looper/pull/963)).** For a command schedule, the run message gives the status with the exit code or signal on a failure, the duration, a note for a catch-up (and how many fires it replaces) or a manual run, the error, the last 1500 characters of the log in a code fence, and a link to the run (`.../schedules/<id>/runs/<run id>`). `succeeded` and `interrupted` now count as runs that ran something, so `notify: always` sends them.
- **Overview ([#963](https://github.com/foolzzz/looper/pull/963)).** "Failing now" in the schedule overview includes schedules with a deadline or overlap alert, with `deadline_since` and `overlap_since`; the v1 overview schema and its `last_status` enum accept them (and `succeeded` and `interrupted`).
- **Model-visible changes:** None. The new alert and run messages are sent to the schedule's notification channel or recorded on the dashboard; no prompt, tool or message text given to a model changes.

### 升级决策

**谁需要升级：**想按定时任务调整告警阈值、设置每日成功截止时间、在任务因上一次运行未结束而持续跳过时得到提醒，或想让命令类定时任务的运行消息带上退出码和日志末尾的人。

**解决了什么：**[#963](https://github.com/foolzzz/looper/pull/963) 让通知器读取每个定时任务的告警阈值，新增截止时间告警和重叠告警及其恢复消息，命令类运行消息带上退出码、耗时、日志末尾和运行链接，并在总览的“Failing now”中显示这两类新告警。

**是否有破坏性变更：**否。不移除任何 API、默认值或配置，也没有新的迁移。行为变化见下。

**如何验证：**运行 `looper --version` 核对版本为 2.14.35。

**贡献者：**维护者 @foolzzz 提交 [#963](https://github.com/foolzzz/looper/pull/963)；本版本无社区贡献。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.34 上的安装可直接升级。本版本没有新迁移：它读取的列（`alert_failures_after`、`alert_stale_after_seconds`、`alert_overlap_after`、`success_deadline`、`consecutive_overlaps`、`deadline_alert_at`、`overlap_alert_at`）已在数据库结构中。

### 行为变化与入口

- **每个定时任务的告警阈值（[#963](https://github.com/foolzzz/looper/pull/963)）。**`looper/agents/schedule_notify.py` 的 `alert_policy` 解析阈值；为空则保持原行为。
  - `alert_failures_after` 取代固定的连续 3 次失败。
  - `alert_stale_after_seconds` 设置后取代按周期计算的无成功窗口（3 个周期，至少 15 分钟，至多 24 小时）。
  - `alert_overlap_after` 是触发告警的连续重叠跳过次数；为空时命令类为 10、智能体类不告警，0 表示关闭。
- **成功截止时间告警（[#963](https://github.com/foolzzz/looper/pull/963)）。**`success_deadline` 为定时任务所在时区的 `HH:MM`，创建和更新时拒绝其他取值。每次调度器检查：最近一个截止时间已过、自上一个截止时间（或启用、规则或截止时间变更）以来窗口内有触发、且上一个截止时间之后没有成功运行，就发出一条告警，写明上次成功时间、仍在运行的那次或最近一次运行。修改截止时间会重新开始计窗口。下一次 OK 运行发一条恢复消息。
- **重叠跳过告警（[#963](https://github.com/foolzzz/looper/pull/963)）。**每次 `skipped_overlap` 在记录跳过的同一事务内使 `consecutive_overlaps` 加一。达到阈值发一条告警，写明仍在运行的那次。任何开始的运行（gate、命令或智能体运行）都会重置计数并发一条恢复消息。
- **命令类运行消息（[#963](https://github.com/foolzzz/looper/pull/963)）。**命令类定时任务的运行消息包含状态（失败时带退出码或信号）、耗时、补跑（及其代替的次数）或手动运行的标注、错误、代码块中的日志末尾 1500 个字符，以及运行链接（`.../schedules/<id>/runs/<run id>`）。`succeeded` 和 `interrupted` 现在算作“运行过”，因此 `notify: always` 会发送它们。
- **总览（[#963](https://github.com/foolzzz/looper/pull/963)）。**定时任务总览的“Failing now”包含有截止时间或重叠告警的任务，带 `deadline_since` 和 `overlap_since`；v1 总览 schema 及其 `last_status` 枚举接受它们（以及 `succeeded` 和 `interrupted`）。
- **面向模型的变化：**无。新的告警和运行消息发送到定时任务的通知渠道或记录在仪表盘上；给模型的提示词、工具和消息文本都不变。
