# Looper v2.13.54

## Release Decision

**Who should upgrade:** Operators who stop Manager turns from a chat (the stop command or the stop button) or who retire a Manager while it answers, in particular with several channels of the same type. Nobody else needs to act.

**What this release solves:** [#446](https://github.com/foolzzz/looper/pull/446) fixes the open review follow-ups of how a Manager turn ends (#406 B, C, F; #419; #404.9): a stop from a chat finds the turns of that channel, a stopped turn answers with the text it already streamed, and the writes at the end of a stopped turn are bounded in time.

**Breaking changes:** No. No existing API, configuration or stored data changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#446](https://github.com/foolzzz/looper/pull/446); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.54
```

## Behavior changes

- **Stop matches the channel id (`looper/agents/tiers/turn_token.py`, `looper/agents/tiers/manager.py`):** a turn token now records the `channel_id` of the message's origin, and the stop command looks up live turns by that id, falling back to the channel type when there is none. Before, it matched the channel type and chat only, so a stop in one channel could also reach a turn of another channel of the same type with the same chat id. `oldest_for` still matches the channel type.
- **Stopped turns answer with the streamed text (`looper/agents/tiers/turn_token.py`, `looper/agents/tiers/manager.py`, `looper/agents/managers.py`):** the text of a turn already sent to the chat as deltas is kept on its token (`partial`). A turn ended by a stop uses the text parts it handled, or this kept text when none were handled, as its partial reply. When the fleet retires a Manager with turns in flight, the stopped reply for a user message carries that kept text instead of an empty one, and a turn whose token was already settled while its record finishes is still answered.
- **Bounded write of a stopped user message (`looper/agents/tiers/manager.py`):** a user message stopped before the model had it is persisted within `STOP_FINISH_SEC`; if the database holds the write longer, a warning is logged and the stopped reply goes out.
- **Cancel escaping the runtime (`looper/agents/tiers/manager.py`):** a `TurnCancelled` raised by the runtime now ends the turn stopped inside the turn's own handling, and a `TurnStopped` no longer counts as a failure: it does not settle the turn as failed and does not kill the Claude process through the failure path. Events still being handled are awaited before the stop decision.
- **Closing the run record (`looper/agents/claude_cli.py`):** `ClaudeRunRecorder` waits for the closing write for at most `CLOSE_TIMEOUT_SEC` even when the database ignores cancellation, and logs a warning on timeout. The write itself continues.
- **Model-visible changes:** None. No prompt, tool result or OpenAPI operation changed. The stopped reply text a chat user sees can now include the partial answer streamed before the stop, in the cases above.
- **Tests added:** The pull request reports added lines: tests 304, production 54 (fixtures excluded). New tests are in `tests/test_manager_stop_faults.py`, `tests/test_manager_stop_command.py`, `tests/test_claude_cli.py` and `tests/test_turn_token.py`.

## Upgrade and rollback

Re-run `install.sh` once v2.13.54 is published. No data migration. Rolling back to v2.13.53 restores the earlier stop matching and stopped replies; nothing is stored differently.

### 升级决策

**谁需要升级：**从聊天中停止 Manager 轮次（停止命令或停止按钮），或在 Manager 回答时将其退役的运维者，尤其是配置了多个同类型渠道的人。其他人无需操作。

**解决了什么：**[#446](https://github.com/foolzzz/looper/pull/446) 修复 Manager 轮次如何结束的评审遗留问题（#406 B、C、F；#419；#404.9）：聊天中的停止能找到该渠道的轮次，被停止的轮次会带上已流式发出的文本作答，停止轮次结尾的写入有时间上限。

**是否有破坏性变更：**无。现有 API、配置和存储数据均未改动。

**如何验证：**运行 `looper --version` 核对版本为 2.13.54。

**贡献者：**维护者 @foolzzz 提交 [#446](https://github.com/foolzzz/looper/pull/446)；本次 patch release 无社区贡献。

### 行为变化与入口

- 停止按渠道 id 匹配：轮次令牌现在记录消息来源的 `channel_id`，停止命令按该 id 查找运行中的轮次，没有时回退到渠道类型。此前只匹配渠道类型和聊天，同类型、同聊天 id 的另一渠道的轮次也可能被停止。`oldest_for` 仍按渠道类型匹配。
- 停止的轮次带已流式文本作答：已作为增量发送到聊天的文本保存在令牌的 `partial` 中。被停止结束的轮次用其已处理的文本片段作为部分回复，若没有处理过片段则用此保存的文本。fleet 在有轮次进行时退役 Manager，用户消息的停止回复会带上保存的文本而不是空文本；令牌已在记录收尾期间结算的轮次仍会回复聊天。
- 停止的用户消息写入有时间上限：模型尚未拿到就被停止的用户消息在 `STOP_FINISH_SEC` 内写入；数据库持有写入更久时记录警告，并发出停止回复。
- 运行时让取消逸出：运行时抛出的 `TurnCancelled` 现在在轮次自身的处理中以停止结束，`TurnStopped` 不再按失败处理：不会把轮次结算为失败，也不会经失败路径杀掉 Claude 进程。仍在处理的事件会在停止判定前等待完成。
- 关闭运行记录：`ClaudeRunRecorder` 即使数据库忽略取消，最多等待 `CLOSE_TIMEOUT_SEC`，超时记录警告；写入本身继续进行。
- 面向模型的变化：无。提示词、工具结果和 OpenAPI 操作均未改动。在上述情形下，聊天用户看到的停止回复可包含停止前已流式发出的部分答案。
- 新增测试：PR 报告新增测试 304 行、生产代码 54 行（不含 fixture）。新测试位于 `tests/test_manager_stop_faults.py`、`tests/test_manager_stop_command.py`、`tests/test_claude_cli.py` 和 `tests/test_turn_token.py`。
