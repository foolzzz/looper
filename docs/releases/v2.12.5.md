# Looper v2.12.5

## Release Decision

**Who should upgrade:** Operators who want pi (the pi coding agent CLI) or DeepSeek Harness (`dsh`) for Manager, Planner, Worker or Reviewer, and operators whose non-Claude runs are interrupted when `claude` is absent from PATH.

**What this release solves:** Two optional runtimes integrate with Agent Profiles, platform tools, sessions, events, usage accounting and dashboard selection: pi in [#252](https://github.com/foolzzz/looper/pull/252), and dsh in [#256](https://github.com/foolzzz/looper/pull/256). Manager and WorkerPool health checks now check their own loop for every runtime, so a missing unrelated binary no longer restarts the pool and cancels active runs.

**Breaking changes:** No. Existing profiles and runtime defaults are unchanged. Shared terminal-result handling, failure reporting, session cleanup and incomplete-usage accounting change as listed below. Pi requires version 1.3.0 or newer with the required launch flags; dsh supports exactly `@deepseek-ai/dsh` 0.2.1-rc.2 and always appends Looper's system instructions.

**How to verify:** Re-run `install.sh`, restart with the existing configuration and runtime root, and check the version. On a disposable server, install and detect the chosen runtime, create a compatible API-key Agent Profile, and select it for the four roles. Run a Manager tool query and a task with review; read back the runtime, final reports, usage and session IDs. Exercise Manager/Planner continuation, a room consult and the runtime-specific checks below. Test a non-Claude profile with `claude` absent from PATH and confirm active runs are not cancelled by health checks.

**Contributors:** Release maintainer @foolzzz, author of [#252](https://github.com/foolzzz/looper/pull/252) and [#256](https://github.com/foolzzz/looper/pull/256); no community contribution was included in this patch.

```bash
looper --version   # looper 2.12.5
looper doctor
```

## Behavior changes

- **Two new runtime choices for all four roles.** Pi and DSH appear in Settings → Agent Runtimes and compatible Agent Profile selections. Existing runtime defaults and saved profile selections remain unchanged. Runtime cards now show probe errors alongside detected versions, including for existing runtimes. DSH profiles filter providers and models by compatibility and show the system-prompt replacement limitation. ([#252](https://github.com/foolzzz/looper/pull/252), [#256](https://github.com/foolzzz/looper/pull/256))
- **Pi binds API-key providers only.** It accepts `openai-responses` (including a CPA-style gateway) and `openai-chat` (including DeepSeek Chat Completions), preferring Responses when both are declared. The configured endpoint, model and thinking level are bound explicitly; unsupported bindings fail before launch. Responses tool requests preserve optional parameters with `strict: false`. Subscription logins are outside this integration. ([#252](https://github.com/foolzzz/looper/pull/252))
- **Pi uses a private agent directory and a bundled tool bridge.** Private homes and separate session storage keep operator configuration out; automatic context, extension and resource discovery, telemetry and cache warming are disabled. The bundled TypeScript extension is explicitly loaded with `-e` while `--no-extensions` disables discovery. It publishes scoped Looper tools through the existing HTTP API, preserving descriptions, schemas, authorization and confirmation behavior, with cancellation and deadlines and no automatic operation replay, proxies or redirects. Catalog MCP servers, skills and plugins remain unloaded and are recorded as skipped. Planner and consult runs use reading-tool allowlists; these are not an OS sandbox. ([#252](https://github.com/foolzzz/looper/pull/252))
- **Pi translates JSON events, usage and sessions.** Messages, tools, compaction and terminal events use Looper's event format; success is finalized on `agent_settled`. Only new usage is counted, priced at provider prices and subject to usage-based soft caps. Manager and Planner resume an exact session file with a process per turn; room sessions are retained, and consults fork read-only copies. RPC Worker steering requires a correlated queued acknowledgement. Private pi storage participates in existing reclamation. ([#252](https://github.com/foolzzz/looper/pull/252))
- **DSH binds DeepSeek through an API-key Messages provider.** It requires `anthropic-messages`, supporting `deepseek-flash`, `deepseek-flash[1m]`, `deepseek-v4-pro` and `deepseek-v4-pro[1m]`. Catalog membership is checked before removing `[1m]` for requests. Effort is `low`, `high` or `max`, defaulting to `high`; explicit provider endpoints are preserved. The bound DeepSeek key is passed to the dsh process environment, not written into the overlay or command arguments or installed as operator login state. ([#256](https://github.com/foolzzz/looper/pull/256))
- **DSH uses private homes and a Looper overlay.** A private `DSH_HOME` and immutable owner-specific configuration avoid importing operator configuration. The overlay pins the model, disables telemetry, session uploads and title-generation requests, and turns web search off unless explicitly opted in. Looper's literal prompt is appended and its stdio MCP bridge is wired to the run's Looper endpoint before model execution, with the role-specific tool contract checked. Compatible catalog skills and external MCP configurations are translated, with omissions recorded. Planner and consult runs permit only `read`, `glob`, `grep` and the exact registered platform tools; shell, mutations, subagents and external catalog MCP are denied or omitted. This is a tool-level guard, not a host sandbox. ([#256](https://github.com/foolzzz/looper/pull/256))
- **DSH has headless events, resume and explicit limits.** JSONL session, text, thinking, tool and usage events feed Looper's records. Success requires a completed turn, final response and verified successful process exit. Separate owner sessions resume with refreshed launch configuration; consults run in place under the read-only guard using a separate snapshot of an ended session. Active-session snapshots are refused. Active-run steering, autonomous turns, structured output and native `max_turns` enforcement are unsupported. ([#256](https://github.com/foolzzz/looper/pull/256))
- **DSH pricing keeps incomplete usage visible.** Reported root steps use provider prices; unknown usage remains unknown. A configured soft cap stops a run when root usage cannot be verified. Observed root spend does not establish the complete bill or a hard billing cap; auxiliary usage can be missing. Shared accounting honors explicit incomplete-usage markers without inventing total cost. The observed-root budget policy applies only when requested by the runtime; existing runtimes retain their previous policy when those markers are absent. ([#256](https://github.com/foolzzz/looper/pull/256))
- **Health checks follow the running component for every runtime.** Manager checks its own task loop and WorkerPool its listener loop, without requiring `claude` on PATH. Runtime availability is checked at launch. This prevents a missing unrelated runtime from restarting the pool and cancelling active Workers or Reviewers. ([#256](https://github.com/foolzzz/looper/pull/256))
- **Shared failures and records become more explicit.** Across runtimes, Manager requires a successful terminal result before treating text as a successful reply; an error result containing text fails the turn. Worker command-preparation errors become explicit work or verification failures, and soft-budget stop results are retained in the transcript. Manager and Planner run records use the materialized resident command when available. ([#256](https://github.com/foolzzz/looper/pull/256))
- **Session-cleanup claim has a code-verification gap.** The #256 description reports managed-parent-path symbolic-link checks, including existing Codex and OMP storage. In the merged implementation, `reclaim_sessions` skips symlinked session entries but does not check managed parent paths. The broader protection is therefore not claimed as delivered. ([Merged cleanup code](https://github.com/foolzzz/looper/blob/0f681505e/looper/agents/read_only_copies.py))
- **Shared eval edit accounting recognizes pi paths.** It accepts the `path` field, deduplicates paths within each tool call and excludes URL targets. ([#252](https://github.com/foolzzz/looper/pull/252))

## Model-visible changes

- **Manager profile tools expose the new runtime names.** The existing `looper_agent_profiles` list response includes detected `pi` and `dsh` runtimes, and profile creation/update can resolve those types. The shared tool schema and role contracts are unchanged.
- **Pi gets runtime-specific system instructions and tool definitions.** Notes require the complete reply/report in the final assistant message and identify the `mcp__looper__` tool prefix. Looper injects project instructions once, preferring `AGENTS.md` over `CLAUDE.md` per directory, while pi context discovery stays disabled. Pi supports both append and replace system-prompt modes and receives scoped platform-tool descriptions and schemas through the bundled bridge. Shared role prompts and contracts are unchanged.
- **DSH always appends literal Looper instructions to its built-in system prompt.** The effective mode is append without rewriting saved role settings. Project instructions prefer `AGENTS.md` over `CLAUDE.md` per directory, and Prompt Preview includes the effective injected content. DSH notes require complete final replies/reports and tell Workers and Reviewers to finish rather than wait for future room questions. Compatible installed skills and role-specific platform tools are exposed through DSH; existing runtimes' prompt content is unchanged.

Dashboard chat, Telegram and Lark share the configured Manager and task adapters; no channel-specific commands or adapter changes are introduced. CLI runtime discovery and existing Agent Profile selection use the same registry, with no new product subcommand or DSH-specific flags. Dedicated pi smoke/eval scripts and a dsh validation launcher are available for disposable validation.

## Optional Capability Activation & Use

### Pi agent runtime

**Activation:** Install pi on the service user's PATH (minimum 1.3.0, with the required launch flags), then use Settings → Agent Runtimes → Re-detect. In Settings, configure an API-key provider with its endpoint, model catalog and prices using `openai-responses` or `openai-chat`; create a Pi Agent Profile and select it for the desired roles or overrides. Enter the key on the dashboard, never in chat. A CPA-style Responses gateway and DeepSeek Chat Completions were exercised in real evals.

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version
looper --version
looper doctor
```

**Validation:** On a disposable server, confirm the detected version and capabilities, then test a Manager platform-tool query, Planner task, Worker edit and Reviewer report. Inspect final events, provider-priced usage and exact session continuation. Test a room consult and a Worker steer, confirming a queued acknowledgement before calling steering accepted. Confirm catalog items are recorded as skipped and unsupported providers are refused before launch. Compare operator-configuration canaries with the private agent directory rather than assuming isolation from a successful model reply.

**Disable / rollback:** Select an existing runtime's compatible profile for every role and override that uses pi. Complete or stop affected tasks before removing pi or reinstalling v2.12.4; a pi session cannot be resumed by another runtime or the older release. Existing default selections are not switched automatically.

**Authority boundary:** The extension uses only the run's scoped Looper endpoint and authorization, retaining existing confirmation requirements. Tool timeouts do not prove an operation had no effect; inspect the result before repeating it. Pi Planner and consult allowlists are tool restrictions, not an OS sandbox; normal runs execute with the service user's authority. API-key providers only; operator subscription logins and catalog MCP/skills/plugins are not loaded.

**Docs:** [Runtime architecture](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md#runtimes-llm-providers-and-agent-profiles), [pi integration and limits](https://github.com/foolzzz/looper/blob/main/docs/architecture/rfcs/pi-runtime-v0.zh-CN.md), [implementation and validation](https://github.com/foolzzz/looper/pull/252).

### DSH agent runtime

**Activation:** Install exactly `@deepseek-ai/dsh` 0.2.1-rc.2 on the service user's PATH and Re-detect in Settings → Agent Runtimes. Configure a DeepSeek API-key provider using `anthropic-messages`, compatible model IDs and prices; create a DSH Agent Profile and select it for the desired roles or overrides. Set the key only on the dashboard. Looper creates the private `DSH_HOME`, pinned overlay, prompt wiring and run-scoped MCP bridge; no operator login/configuration import is needed. Web search is off by default; an explicit `DSH_ALLOW_WEB_SEARCH=true` role environment opts in, while read-only runs still deny web execution.

```bash
npm install -g @deepseek-ai/dsh@0.2.1-rc.2
dsh --version
looper --version
looper doctor
```

**Validation:** On a disposable server, check all four roles through a Manager tool query and a reviewed task. Read back successful final reports, runtime/session metadata and resumed Manager/Planner sessions. Try shell or write access in a Planner or consult and confirm denial; verify a consult snapshot leaves the ended session unchanged. Check Prompt Preview's effective append mode, disabled search/telemetry, and unknown total cost when usage is incomplete. A budget stop on missing root usage is an explicit failure, not proof that the full bill stayed within the cap.

**Disable / rollback:** Switch every DSH role and override to an existing compatible profile, and complete or stop DSH tasks before uninstalling dsh or reinstalling v2.12.4. DSH sessions are runtime-specific. Saved role settings are not rewritten to append, so inspect the effective system-prompt mode when switching runtimes.

**Authority boundary:** The provider key is supplied to the dsh process through its binding; private configuration and command arguments do not contain it. The Looper MCP bridge uses the run's endpoint and scoped authorization. Private homes separate configuration and login state; read-only execution guards do not sandbox the host. Supported catalog tools retain their own authority on ordinary runs. Observed root pricing is incomplete billing evidence, auxiliary coverage remains unknown, and caps are soft. DSH cannot steer an active run or replace its built-in system prompt.

**Docs:** [DSH integration, provider policy and limits](https://github.com/foolzzz/looper/blob/main/docs/architecture/rfcs/dsh-runtime-v0.zh-CN.md), [disposable validation launcher](https://github.com/foolzzz/looper/blob/main/evals/README.md#dsh-validation), [implementation and validation](https://github.com/foolzzz/looper/pull/256).

## Validation

These are retained implementation reports for the two PRs, not runtime checks rerun while drafting this release:

- **Reviews and CI:** Each PR's Codex review rounds ended **not blocking**. Agent system tests and Dashboard tests passed for both [#252](https://github.com/foolzzz/looper/pull/252) and [#256](https://github.com/foolzzz/looper/pull/256).
- **Pi real evals:** `openai-responses` tasks through a CPA-style gateway **18/18**; DeepSeek `openai-chat` tasks **17/18**, with one room-consult case passing **1 of 2 runs** (model variance); Manager dialogs **8/8**. Installed-pi tool-bridge checks used **1.3.0**. The DeepSeek result is partial, not an all-green suite.
- **DSH real smoke:** With a DeepSeek key, the reported smoke covered all four roles, two tasks, two Manager turns, API/database readback and session resume, with approximately **USD 0.02 observed spend**, not a complete bill. Its initial WorkerPool restart/cancel problem led to the shared health-check fix and a regression test.
- **DSH earlier validation error:** A retained task-stage attempt timed out and reported `status: error` and `real_validation: error`, with no outer timeout. Observed cost was unknown, auxiliary cost coverage unknown, and no hard billing cap. Its configured limits were **USD 0.50 per-run soft cap** and **USD 4 total observed cap**; these are limits, not measured spend. This attempt remains an error.
- **DSH later real validation:** Task-basic **4 pass**, task-review **4 pass**, Manager dialogs **4 pass**; each reported **0 fail, 0 error, 0 skipped and 0 untested**. The redacted summaries include two successful `single_step` repetitions, two successful `reviewed_step` repetitions, and two passing Manager `status` repetitions. No per-stage cost is claimed because DSH reports root spend only partly.

The later DSH successes do not turn the earlier timeout into a pass. Auxiliary cost coverage and a complete bill remain unknown, with no hard billing cap. Unsupported pi protocols/subscription logins and unsupported DSH capabilities are not validated support. A full final-head prompt regression suite was not rerun for this draft. The release documentation gate validates the body and activation entries; it does not establish runtime behavior.

### 行为变化

- Pi、DSH 均成为四角色的新运行时选择，已有默认值和 Profile 选择不变。Dashboard 的 Agent Runtimes 和 Agent Profiles 提供选择；所有运行时卡片均可同时显示版本和探测错误。DSH 按运行时兼容性过滤 provider/model，并提示不能替换系统提示。
- Pi 只接 API key 的 `openai-responses`（包括 CPA 风格网关）和 `openai-chat`（包括 DeepSeek Chat Completions），同时声明时优先 Responses。显式绑定 endpoint、model、thinking，不支持的组合在启动前拒绝；Responses 用 `strict: false` 保留工具可选参数。不接订阅登录。
- Pi 使用私有 home、agent 目录与独立 Session 存储，不读取操作者配置，关闭上下文及资源自动发现、遥测和缓存预热。打包的 TypeScript 扩展以 `-e` 显式加载，同时用 `--no-extensions` 关闭发现；通过现有 HTTP API 提供当前运行作用域的平台工具，保留描述、schema、授权和确认行为，处理取消和截止时间，不自动重放操作、不走代理或重定向。目录中的 MCP、skills、plugins 不加载并记录为 skipped。Planner 和咨询仅放行读取工具；这不是 OS 沙箱。
- Pi 将 JSON 消息、工具、压缩和终态转为 Looper 事件，仅在 `agent_settled` 结算；只计新增用量，用 provider 价格和基于用量的软上限。Manager/Planner 每回合起进程并续接精确 Session 文件；房间会话保留，咨询从只读副本 fork。Worker RPC 引导只有收到关联的 queued 确认才算接受；私有存储接入既有回收。
- DSH 需要 API key 的 `anthropic-messages` provider，只接受 `deepseek-flash`、`deepseek-flash[1m]`、`deepseek-v4-pro`、`deepseek-v4-pro[1m]`，先检查目录成员资格再去掉请求中的 `[1m]`。Effort 为 `low/high/max`，默认 `high`，保留显式 endpoint。绑定的 DeepSeek key 通过 dsh 子进程环境传入，不写 overlay、命令参数或操作者登录状态。
- DSH 使用私有 `DSH_HOME` 和按 owner 隔离的不可变配置，不导入操作者配置。Overlay 固定模型，关闭遥测、会话上传和标题生成请求，web search 默认关闭、需显式启用。按字面追加 Looper prompt，在模型执行前通过 stdio MCP 桥连接本次运行的 Looper endpoint 并核对角色工具契约。兼容的 catalog skills、外部 MCP 被翻译，不兼容项记录省略。Planner/咨询仅允许 `read/glob/grep` 和精确注册的平台工具，拒绝 shell、修改、子 agent，省略外部 MCP；工具 guard 不是主机沙箱。
- DSH headless JSONL 的 Session、文本、思考、工具和用量进入运行记录；必须同时具备 completed 回合、最终回答和成功进程退出才算成功。各 owner 独立 Session，续接时刷新配置；咨询在原工作目录用已结束会话的独立快照和只读 guard，拒绝活动 Session 快照。不支持运行中引导、自主回合、结构化输出和原生 `max_turns` 强制限制。
- DSH 按 provider 价格计算已报告 root 步骤，不完整用量保持未知；配置软上限后，root 用量无法验证会停止运行。观测 root 金额不等于完整账单或硬扣费上限，辅助用量可能缺失。共享计费尊重显式 incomplete 标记，不编造总费用；仅运行时请求时启用 observed-root 预算策略，没有这些标记的已有运行时保持原策略。
- 所有运行时的 Manager/WorkerPool 健康检查仅检查自身任务循环/监听循环，二进制可用性在启动时判断，不再要求 PATH 中有 `claude`，避免无关运行时缺失导致池重启并取消活动 Worker/Reviewer。
- 跨运行时，Manager 只有成功终态才能把文本当作成功回答；错误终态即使含文本也失败。Worker 命令准备错误成为明确的 work/verification 失败，软预算停止结果写入 transcript。Manager/Planner 运行记录优先保存物化后的 resident 命令。
- Session 清理存在描述与代码的差异：#256 描述称受管父路径有符号链接检查，包含原有 Codex/OMP 存储；合并后的 `reclaim_sessions` 只跳过符号链接会话项，没有检查受管父路径，因此不能将更广的保护声称为已交付。见[合并代码](https://github.com/foolzzz/looper/blob/0f681505e/looper/agents/read_only_copies.py)。
- 共享 eval 文件编辑统计支持 `path`，单次工具调用内去重，排除 URL 目标。

### 模型可见变化

- Manager 的 `looper_agent_profiles` 列表回答包含已探测的 `pi`、`dsh` 名称，创建/修改 Profile 可解析对应类型；共享工具 schema 和角色契约不变。
- Pi 专属 runtime notes 要求把完整回答/报告放入最后一条 assistant 消息，并说明 `mcp__looper__` 前缀。Looper 每目录优先注入 `AGENTS.md`、否则 `CLAUDE.md`，只注入一次，pi 自身上下文发现保持关闭。支持 append/replace，通过桥提供当前作用域的工具描述和 schema；共享角色 prompt 与契约不变。
- DSH 向内置 system prompt 按字面追加 Looper 指令，有效模式始终 append，不改写保存的角色设置。项目说明每目录优先 `AGENTS.md`、否则 `CLAUDE.md`，Prompt Preview 包含实际注入内容。专属说明要求完整最终回答/报告，Worker/Reviewer 完工即结束，不等待未来房间提问。兼容的已安装 skills 和角色平台工具对 DSH 可见；已有运行时 prompt 内容不变。

Dashboard chat、Telegram、Lark 共用已选 Manager 和任务 adapter，无渠道专属命令或适配修改。CLI 沿既有 registry 探测和 Profile 选择，无新增产品子命令或 DSH 专属参数；提供 pi smoke/eval 脚本与 dsh 一次性验证 launcher。
