# Looper v2.13.58

## Release Decision

**Who should upgrade:** Operators who run Planners on the Claude Code runtime, especially goals whose steps run in their own isolated worktrees or whose documents are reached through a symbolic link. Nobody else needs to act.

**What this release solves:** [#461](https://github.com/foolzzz/looper/pull/461) fixes the follow-ups of #459 for the read-only Claude Code Planner. The Planner can now read the isolated worktrees of the steps its task still uses, which the read-only rule did not cover before. A document reached through a symbolic link is allowed too. The Planner can no longer create a worktree, and its recommended prompt tells it to inspect with Read, Glob and Grep and leave commands to Workers.

**Breaking changes:** No. No stored data or configuration changed. One behavior is narrower: a read-only Claude Code Planner can no longer use `EnterWorktree`. A role prompt line that an operator edited is kept as written.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#461](https://github.com/foolzzz/looper/pull/461); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.58
```

## Behavior changes

- **Read rules cover both spellings of a directory (`looper/agents/claude_cli.py`):** `read_only_args` now allows `Read`, `Glob` and `Grep` for each root in two forms, the resolved real path and the absolute path as written (for the repository root and every extra directory). A document reached through a symbolic link, including one above the working directory inside a repository, is therefore allowed. Paths outside these roots are not allowed.
- **Worktrees of the task's steps are readable (`looper/agents/agent_settings.py`, `looper/agents/tiers/planner.py`, `looper/agents/runtimes/claude_code.py`):** `Launch` gains `read_dirs`. The Planner fills it with the workspace path of every step in the plan that runs isolated and has a workspace, and the Claude Code runtime adds these to the knowledge directories when it builds the read-only rules. The set is computed for each turn, so a step that has left the plan is no longer granted.
- **`EnterWorktree` is disallowed:** it joins `Bash`, `Edit`, `Write` and `NotebookEdit` in `--disallowedTools` for a read-only Planner, so it cannot create a branch or worktree.
- **Planner prompt (`looper/agents/tiers/planner.py`):** the recommended read-only line now says to use Read, Glob and Grep on the project and each step's worktree, and to leave commands, tests and file changes to Workers. It no longer suggests read-only git commands, which the Planner has not had since v2.13.57. A role configuration line the operator never edited follows the new recommendation; an edited one is kept, per the RFC.
- **What other runtimes do:** unchanged. Only the Claude Code launch uses `read_dirs`.
- **Docs and tests:** the read-only Planner RFC (tool table, 4.2, the worktree paragraph, the recommended prompt and decisions D2 and D3) and the long-horizon context plan describe the new rule. Tests cover the launch arguments (`tests/test_claude_cli.py`), the Planner (`tests/test_planner_agent.py`), Planner workspaces, and the launch parity checks. The pull request reports added lines: tests 76, production 19 (fixtures excluded).
- **Model-visible changes:** Yes, for a Claude Code Planner only. Its system prompt line about read-only work changes as described above; its tool list loses `EnterWorktree`; and it can read the files of its steps' worktrees and of directories reached through symbolic links. Its decision turn already names each step's worktree, branch and start commit; the code comment now notes that the launch permits reading it. Manager, Worker and Reviewer launches are not changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.58 is published. No data migration. Rolling back to v2.13.57 gives the Planner `EnterWorktree` again and takes away its read access to step worktrees and to symbolic-link spellings of its directories; nothing is stored differently.

## 中文摘要

### 升级决策

**谁需要升级：**在 Claude Code 运行时上运行 Planner 的运维者，尤其是步骤在独立 worktree 中运行、或文档经符号链接访问的目标。其他人无需操作。

**解决了什么：**[#461](https://github.com/foolzzz/looper/pull/461) 修复 #459 在只读 Claude Code Planner 上的后续问题。Planner 现在可以读取当前任务仍在使用的步骤的独立 worktree（此前只读规则不覆盖）；经符号链接访问的文档同样放行。Planner 不能再创建 worktree，其推荐 prompt 也改为用 Read、Glob、Grep 检查，命令交给 Worker。

**是否有破坏性变更：**无。存储数据和配置均未改动。一处行为收窄：只读的 Claude Code Planner 不能再使用 `EnterWorktree`。操作者改过的角色 prompt 行保持原样。

**如何验证：**运行 `looper --version` 核对版本为 2.13.58。

**贡献者：**维护者 @foolzzz 提交 [#461](https://github.com/foolzzz/looper/pull/461)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.58
```

### 行为变化与入口

- 目录的两种写法都放行（`claude_cli.py`）：`read_only_args` 对仓库根目录和每个额外目录，同时放行 `Read`、`Glob`、`Grep` 的解析后真实路径和原样的绝对路径。经符号链接访问的文档（包括仓库内、工作目录上级的文档）因此可读；这些根目录之外的路径仍不放行。
- 任务步骤的 worktree 可读（`agent_settings.py`、`tiers/planner.py`、`runtimes/claude_code.py`）：`Launch` 新增 `read_dirs`。Planner 把计划里每个独立运行且有工作区的步骤的路径填入，Claude Code 运行时在生成只读规则时把它们加到知识目录之后。这个集合每轮重新计算，已离开计划的步骤不再获得授权。
- 禁用 `EnterWorktree`：与 `Bash`、`Edit`、`Write`、`NotebookEdit` 一同进入只读 Planner 的 `--disallowedTools`，不能再创建分支和 worktree。
- Planner prompt（`tiers/planner.py`）：推荐的只读一行改为用 Read、Glob、Grep 检查项目和各步骤的 worktree，命令、测试和改文件交给 Worker；不再提只读 git 命令（v2.13.57 起 Planner 已没有 Bash）。没改过的角色配置行跟随新推荐，改过的按 RFC 保留。
- 其他运行时：不变。只有 Claude Code 启动使用 `read_dirs`。
- 文档与测试：更新只读 Planner RFC（工具表、4.2、worktree 段、推荐 prompt、D2 和 D3）和长程上下文计划。测试覆盖启动参数、Planner、Planner 工作区和启动一致性检查。PR 报告新增测试 76 行、生产代码 19 行（不含 fixture）。
- 面向模型的变化：有，仅限 Claude Code 的 Planner。系统提示中的只读一行如上改动；工具列表不再含 `EnterWorktree`；可读取各步骤 worktree 的文件和经符号链接访问的目录。决策回合本来就写明各步骤的 worktree、分支和起点提交，代码注释现改为说明本轮启动允许读取它。Manager、Worker、Reviewer 的启动不变。

### 升级与回退

v2.13.58 发布后重跑 `install.sh`，无需迁移数据。回退到 v2.13.57 会让 Planner 重新拥有 `EnterWorktree`，同时失去对步骤 worktree 和符号链接写法目录的读取权限；存储无差异。

### 可选能力启用与使用

本版本未新增可选能力启用入口。
