# Looper v2.14.106

This is the patch release v2.14.106, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.105: the dashboard shows cache hit rates for model requests ([#1159](https://github.com/foolzzz/looper/pull/1159)).

## Release Decision

**Who should upgrade:** Operators who read cache behavior in the dashboard, especially those running models through the local gateway. Others are not affected, apart from the changes to translated usage described below.

**What this release solves:** [#1159](https://github.com/foolzzz/looper/pull/1159). Run cards, the per-model task cost table and recorded request rows now show a cache hit rate. Translated request rows also show a prefix reuse rate, so a broken prompt prefix can be told apart from a provider cache miss.

**Breaking changes:** No. No new dependency, command or database change. The task-cost API result gains four fields.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.106
```

**Contributors:** Maintainer @foolzzz authored [#1159](https://github.com/foolzzz/looper/pull/1159); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.105 upgrades directly. There is no schema change. A local proxy kept alive by running agents from an older version keeps the old behavior until those agents finish and it is replaced.

## Behavior changes

- **Cache hit in the dashboard** (`web/src/lib/cache-hit.ts`, `web/src/components/task-cost.tsx`, `web/src/pages/agent-history.tsx`). Run cards, the **By model** table of the task cost and recorded request rows show cache hit as `cache_read / (input + cache_read + cache_write)`. A missing count or an empty prompt shows no percentage; the tooltip says "this runtime does not report cache usage", or "partial" with the number of covering runs.
- **Prefix reuse for translated requests** (`looper/agents/llmrec/proxy.py`). Request rows show **prefix reuse**: the unchanged prefix of the previous prompt divided by that previous prompt's total, estimated at four UTF-8 bytes per token. The proxy compares system, tools, then whole messages and stops at the first change, independently of JSON key order; a model change invalidates the prefix. History is scoped to route and session (previously per route) and uses the existing bounded in-memory LRU. First requests, evictions and recordings made before this release have no prefix percentage. A red **no usage** badge marks translated requests without upstream usage. The captured translation record gains `common_prefix_tokens` and `previous_prompt_tokens`; `common_prefix_bytes` stays as diagnostic data. The gateway log's `prefix_pct` is now `common_prefix_tokens / previous_prompt_tokens`.
- **Cache counts omitted when not reported** (`looper/agents/llmrec/translate.py`, `looper/agents/llmrec/translate_stream.py`). `anthropic_usage` now returns the usage together with whether the upstream reported cache fields. When it did not, the translated `usage` omits `cache_read_input_tokens` and `cache_creation_input_tokens` instead of reporting `0`, in non-streaming responses and in the `message_start` usage of streams; captured usage then has no cache counts, so the dashboard shows no hit rate rather than 0%. Upstreams that report cache fields are unchanged.
- **Task cost API** (`looper/agents/v1_domains/costs.py`, `looper/db/llm_records.py`). Each `by_model` and `manager_by_model` entry gains `cache_reported_runs`, `cache_missing_runs`, `cache_hit_prompt_tokens` and `cache_hit_read_tokens`. The hit numerator and denominator sum only runs with all of input, cache read and cache write reported; the existing token totals are unchanged.
- **Documentation** (`docs/architecture/agent-system.md`, `docs/design.md`). Describe the cache hit and prefix reuse displays.
- **Tests.** Extended `tests/test_gateway_proxy.py`, `test_gateway_stream.py`, `test_gateway_translate.py`, `test_llm_records_db.py`, `test_llm_requests_browser.py` and `test_api_v1_cost_result_contract_db.py`; web tests for task cost, agent history and the new `cache-hit` helper.
- **Unchanged:** dependencies, commands, channels, the database schema, billing, and the Worker, Planner and Reviewer prompts.
- **Model-visible changes:** Yes, one. For a Claude Code run on a translated model, the `usage` the client receives omits the cache token counts when the upstream reported no cache fields (previously `0`). No prompt text, tool schema or Manager-facing text changed. Runs on direct profiles see no change.

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.105 上的安装可直接升级。无数据库结构变更。由运行中的 agent 保持存活的旧版本本地代理，在这些 agent 结束并被替换之前保持旧行为。

### 行为变化与入口

- **仪表盘缓存命中**（`web/src/lib/cache-hit.ts`、`web/src/components/task-cost.tsx`、`web/src/pages/agent-history.tsx`）。运行卡片、任务花费的 **By model** 表和请求记录行按 `cache_read / (input + cache_read + cache_write)` 显示缓存命中。计数缺失或提示为空时不显示百分比；提示文字为“this runtime does not report cache usage”，或带覆盖运行数的“partial”。
- **转换请求的前缀复用**（`looper/agents/llmrec/proxy.py`）。请求行显示 **prefix reuse**：上一次提示中未变的前缀除以上一次提示的总量，按每 token 4 个 UTF-8 字节估算。代理依次比较 system、tools 和整条 messages，遇到第一处变化即停止，与 JSON 键顺序无关；模型变化使前缀失效。历史按路由加会话划分（此前仅按路由），沿用现有有界内存 LRU。首次请求、被淘汰的记录以及本版本之前的记录没有前缀百分比。红色 **no usage** 标记表示没有上游用量的转换请求。捕获的转换记录新增 `common_prefix_tokens` 和 `previous_prompt_tokens`；`common_prefix_bytes` 仍作为诊断数据保留。网关日志的 `prefix_pct` 现为 `common_prefix_tokens / previous_prompt_tokens`。
- **未上报时省略缓存计数**（`looper/agents/llmrec/translate.py`、`looper/agents/llmrec/translate_stream.py`）。`anthropic_usage` 现在同时返回用量和上游是否上报了缓存字段。未上报时，转换后的 `usage` 省略 `cache_read_input_tokens` 和 `cache_creation_input_tokens`（此前为 `0`），非流式响应和流的 `message_start` 用量均如此；捕获的用量也不含缓存计数，因此仪表盘不显示命中率而不是 0%。上报缓存字段的上游不变。
- **任务花费 API**（`looper/agents/v1_domains/costs.py`、`looper/db/llm_records.py`）。`by_model` 和 `manager_by_model` 的每一项新增 `cache_reported_runs`、`cache_missing_runs`、`cache_hit_prompt_tokens` 和 `cache_hit_read_tokens`。命中率的分子和分母只对 input、cache read、cache write 都已上报的运行求和；既有 token 总数不变。
- **文档**（`docs/architecture/agent-system.md`、`docs/design.md`）。说明缓存命中与前缀复用的展示。
- **测试。**扩展 `tests/test_gateway_proxy.py`、`test_gateway_stream.py`、`test_gateway_translate.py`、`test_llm_records_db.py`、`test_llm_requests_browser.py` 和 `test_api_v1_cost_result_contract_db.py`；新增任务花费、agent 历史和 `cache-hit` 辅助函数的前端测试。
- **不变：**依赖、命令、渠道、数据库结构、计费，以及 Worker、Planner、Reviewer 的提示。
- **面向模型的变化：**有一项。转换模型上的 Claude Code 运行，在上游未上报缓存字段时，客户端收到的 `usage` 省略缓存 token 计数（此前为 `0`）。提示文字、工具 schema 和面向 Manager 的文字均无变化。直连 profile 的运行不受影响。
