# Looper v2.13.105

## Release Decision

**Who should upgrade:** Anyone who uses the dashboard Gates page or its open-gate badge, especially with many gates or while typing an answer during a refresh.

**What this release solves:** [#586](https://github.com/foolzzz/looper/pull/586) bounds the gate reads the dashboard makes and keeps a loaded draft answer when a refresh crosses pages or returns an empty page. Before, even the badge's single row read the whole ordered gate list.

**Breaking changes:** No. No API, command or stored data changed; the fix is in the dashboard only.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#586](https://github.com/foolzzz/looper/pull/586); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.105
```

## Behavior changes

- **Bounded gate reads ([#586](https://github.com/foolzzz/looper/pull/586)):** in `web/src/lib/api.ts`, `fetchGates` reads only the window `offset + limit` when the request has neither a `cursor` nor a `through` boundary, with a request limit of `min(200, window - offset read so far)`. The first request stays at limit 200 for the first page of a larger window, so a request for offset 199 and limit 3 makes two calls (limit 200 at offset 0, then limit 2 at offset 200). Reads with a saved boundary still read the complete ordered list, because the boundary is recovered from it and the server's order (including ties on `opened_at`) is kept.
- **Consistency checks:** a bounded read must return `min(window, total)` rows with no duplicate `[task_id, step]` key and no `has_more` page that returns no new row; otherwise it fails with "The gate list changed while loading. Retry the request." `has_more` in the result now means rows remain beyond the returned page (`end < total`), not beyond a `through` boundary.
- **Show more and drafts:** in `web/src/pages/gates.tsx`, "Show more" appears when the server reports `has_more`, not when loaded rows are fewer than `total`. An empty "show more" page keeps the saved cursor. A refresh across several windows stops with an error when `total` changes between windows or a row appears twice; the rows and the draft answer stay on the page until Retry.
- **Model-visible changes:** None. No tool declaration, API schema, prompt or response text changed; the gate list Tool is called with the same fields and a smaller `limit`.
- **Tests:** [#586](https://github.com/foolzzz/looper/pull/586) extends `web/src/lib/task-interactions.test.ts` (bounded first read, refresh after the known prefix disappears, partial paging rejected for offset and `through` reads) and `web/src/pages/gates.test.tsx` (duplicate and total changes keep the draft, bounded offset read keeps filters and counts), and adds `tests/test_gate_pagination_browser.py`, a browser regression against the built dashboard. The pull request reports 205 added test lines and 60 production lines.

## Upgrade and rollback

Re-run `install.sh` once v2.13.105 is published. No data migration and no configuration change. Rolling back to v2.13.104 brings back full-list reads for the badge and ordinary pages.

### 行为变化与入口

- **有界的 gate 读取（[#586](https://github.com/foolzzz/looper/pull/586)）：**在 `web/src/lib/api.ts` 中，请求既无 `cursor` 也无 `through` 边界时，`fetchGates` 只读取 `offset + limit` 的窗口，每次请求的 limit 为 `min(200, 窗口 - 已读行数)`。较大窗口的第一次请求仍为 limit 200，因此 offset 199、limit 3 的请求会发出两次调用（offset 0 取 200 条，offset 200 取 2 条）。带保存边界的读取仍读取完整有序列表，因为边界要从中恢复，同时保留服务端排序（包括 `opened_at` 相同时的顺序）。
- **一致性检查：**有界读取必须返回 `min(窗口, total)` 行，没有重复的 `[task_id, step]`，且 `has_more` 页不得没有新行；否则报错 "The gate list changed while loading. Retry the request."。结果中的 `has_more` 现在表示返回页之后还有行（`end < total`），而不是 `through` 边界之后。
- **Show more 与草稿：**在 `web/src/pages/gates.tsx` 中，"Show more" 依据服务端的 `has_more` 显示，而不是已加载行数小于 `total`。"show more" 返回空页时保留已保存的游标。跨多个窗口的刷新在 `total` 变化或出现重复行时停止并报错，页面上的行和草稿回答保留到重试。
- **面向模型的变化：**无。没有 tool 声明、API schema、提示词或响应文本改变；gate 列表 Tool 的字段不变，只是 `limit` 更小。
- **测试：**[#586](https://github.com/foolzzz/looper/pull/586) 扩展 `web/src/lib/task-interactions.test.ts`（有界首次读取、已知前缀消失后的刷新、offset 与 `through` 读取的部分分页被拒绝）和 `web/src/pages/gates.test.tsx`（重复与 total 变化时保留草稿，有界 offset 读取保留过滤条件与计数），并新增 `tests/test_gate_pagination_browser.py`，针对构建后的仪表盘做浏览器回归。该 PR 报告新增测试 205 行、生产代码 60 行。
