# Looper v2.13.47

## Release Decision

**Who should upgrade:** Maintainers who run or read the nightly installed-tests workflow. Users of the installed program can stay on v2.13.46: no shipped code changed.

**What this release solves:** [#433](https://github.com/foolzzz/looper/pull/433) makes the nightly installed-tests workflow build the dashboard (`scripts/stage-dashboard.sh`, as the release workflow does) before it runs the installed tests, so the browser tests find the dashboard.

**Breaking changes:** No. Only a CI workflow file changed; no route, schema, setting, command or packaged file changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#433](https://github.com/foolzzz/looper/pull/433); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.47
```

## Behavior changes

- **Nightly installed tests (`.github/workflows/installed-tests.yml`):** a new step, "Build the dashboard", runs `scripts/stage-dashboard.sh` after the dependencies are installed and before "Run installed tests against local stand-ins".
- **Also in the workflow diff:** the `actions/setup-node` reference is `v6` (was `v7`) and `node-version` is written `"24"` (was `'24'`, same value). The pull request description does not mention these two lines.
- **Program behavior:** None. No file under `looper/` changed, so the installed program behaves as in v2.13.46.
- **Model-visible changes:** None. No prompt, tool schema or tool result changed.
- **Tests:** The pull request adds no test lines (tests 0, production 0).

## Upgrade and rollback

Re-run `install.sh` once v2.13.47 is published. No data migration. Rolling back to v2.13.46 needs no step; the program is the same, only the nightly workflow loses the dashboard build.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## Validation

**Retained implementation evidence:** [#433](https://github.com/foolzzz/looper/pull/433) reports its targeted check (parsing every `.github/workflows/*.yml` with a YAML loader), Codex and Grok reviews, and the full local suite before the merge. This draft did not re-run any of it.

**CI:** CI runs after the release is drafted; its result is not recorded here.

**Not tested for this draft:** Local test runs, a nightly workflow run, real runtimes and browser checks. The release documentation gate checks the body only.
