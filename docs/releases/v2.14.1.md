# Looper v2.14.1

This is the patch release v2.14.1. It ships the one change merged since v2.14.0: [#867](https://github.com/foolzzz/looper/pull/867), a DSH runner skeleton that no running code uses yet.

## Release Decision

**Who should upgrade:** Operators on v2.14.0 who want the current main line, and developers who continue the DSH runner work. Nothing an operator can see changes. It ships the one change merged since v2.14.0.

**What this release solves:** [#867](https://github.com/foolzzz/looper/pull/867) adds the packaged TypeScript DSH runner process and its Python launch helper as groundwork. It is not registered as a runtime, has no setting and has no entry in the Dashboard, Telegram, Lark or CLI. The Pi runner now shares its stdio transport with the DSH runner.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#867](https://github.com/foolzzz/looper/pull/867); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.1
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 upgrades directly. This release changes no schema, configuration format or stored data.

## Behavior changes

- **DSH runner process (`runners/dsh/src/main.ts`, `runners/dsh/src/sdk.ts`, `runners/dsh/package.json`):** a new runner that speaks protocol 0.1. `initialize` requires protocol 0.1 and the host capabilities `tools_call` and `budget_authorize`, then loads the installed DSH and boots it. The installed `@deepseek-ai/dsh`, each `@deepseek-ai` package the runner uses and the exports later work needs must be exactly version `0.2.1-rc.2` (`cordis` must be `4.0.x`) on Node 22.19.0 or later; otherwise `initialize` fails with error `-32009`. The runner boots one `headless` profile with an overlay that disables the headless driver, the environment-key DeepSeek route and retry, and the native bash, jobs, subagent, workflow, web and skill tools; it persists under a given state root, with sandbox `danger-full-access` and approval `never`. It also answers `runner/health` and shuts down on SIGTERM, SIGINT, SIGHUP or stdin EOF. It reports no sessions and advertises authorization for `turn` and `compaction` only.
- **Python launch helper (`looper/agents/runtimes/runner/dsh_command.py`):** `entry`, `state_root`, `command` and `connect`. `state_root` creates `<runtime root>/runners/state/dsh-native` one level at a time with mode 0700 and refuses a symlink or non-directory; `command` requires an absolute Node path; `connect` allows 30 seconds for `initialize`, then 10 seconds for later control calls. Nothing in `looper` imports this module yet, so no runtime, setting or entry point uses it.
- **Shared transport (`runners/common/rpc.ts`, `runners/pi/src/*.ts`):** the Pi runner's stdio transport moved unchanged to `runners/common/rpc.ts`, used by both runners. Only the Pi import specifiers changed.
- **Packaging (`pyproject.toml`, `looper/agents/runtimes/runner/common`, `looper/agents/runtimes/runner/dsh_runner`):** the wheel's package data now includes `common/` and `dsh_runner/` through symlinks, next to `pi_runner/`.
- **Tests and plan (`tests/test_dsh_runner.py`, `tests/dsh_runner_support.py`, the Pi runner and packaging tests, `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`):** new DSH runner tests, Pi tests pointed at the shared transport, and a plan entry recording the skeleton and its limits.
- **Model-visible changes:** None. No prompt, tool or message text of a running system changed, because the DSH runner is not reachable from any runtime.

### 行为变化与入口

- **DSH runner 进程（`runners/dsh/src/main.ts`、`runners/dsh/src/sdk.ts`、`runners/dsh/package.json`）：**新的 runner，使用 protocol 0.1。`initialize` 要求 protocol 0.1 以及宿主能力 `tools_call` 和 `budget_authorize`，然后加载并启动已安装的 DSH。已安装的 `@deepseek-ai/dsh`、runner 用到的每个 `@deepseek-ai` 包以及后续工作需要的导出必须正好是 `0.2.1-rc.2`（`cordis` 须为 `4.0.x`），Node 须为 22.19.0 或更高，否则 `initialize` 以错误 `-32009` 失败。runner 以一个 `headless` profile 启动，覆盖层禁用 headless 驱动、环境变量密钥的 DeepSeek 路由、重试，以及原生 bash、jobs、subagent、workflow、web 和 skill 工具；持久化在给定的状态根目录下，沙箱为 `danger-full-access`，审批为 `never`。它还响应 `runner/health`，并在 SIGTERM、SIGINT、SIGHUP 或 stdin EOF 时退出。它报告零个 session，且只声明对 `turn` 和 `compaction` 授权。
- **Python 启动辅助（`looper/agents/runtimes/runner/dsh_command.py`）：**`entry`、`state_root`、`command` 和 `connect`。`state_root` 以 0700 权限逐级创建 `<运行时根目录>/runners/state/dsh-native`，拒绝符号链接或非目录；`command` 要求 Node 为绝对路径；`connect` 给 `initialize` 30 秒，之后的控制调用 10 秒。`looper` 中尚无代码导入该模块，因此没有运行时、设置或入口使用它。
- **共用 transport（`runners/common/rpc.ts`、`runners/pi/src/*.ts`）：**Pi runner 的 stdio transport 原样移到 `runners/common/rpc.ts`，由两个 runner 共用。Pi 只改了 import 路径。
- **打包（`pyproject.toml`、`looper/agents/runtimes/runner/common`、`looper/agents/runtimes/runner/dsh_runner`）：**wheel 的包数据现通过符号链接在 `pi_runner/` 之外包含 `common/` 和 `dsh_runner/`。
- **测试与计划（`tests/test_dsh_runner.py`、`tests/dsh_runner_support.py`、Pi runner 与打包测试、`docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`）：**新增 DSH runner 测试，Pi 测试改指向共用 transport，计划文档记录该骨架及其限制。
- **面向模型的变化：**无。运行中系统的提示词、工具和消息文本均未改变，因为任何运行时都无法到达 DSH runner。
