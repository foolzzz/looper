# Looper v2.13.207

## Release Decision

**Who should upgrade:** Operators who run the opt-in Pi runner with a run or task cost cap. A retry after a provider's 429 or 5xx answer could be refused as `budget_unverifiable`. It ships the change merged since v2.13.206.

**What this release solves:** [#862](https://github.com/foolzzz/looper/pull/862) (fixing #860) reports a sent request that the provider rejected with HTTP status 400 or higher, after the error body was read to a clean end and with no streamed model output, as zero usage and complete, so Pi's retry is no longer refused.

**Breaking changes:** No. Commands, settings, the database schema and the admitted upgrade path are unchanged.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#862](https://github.com/foolzzz/looper/pull/862); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.207
```

## Behavior changes

- **Provider rejections count as zero spend (`runners/pi/src/provider.ts`):** when the response status is 400 or higher, the runner passes the body through a pass-through transform whose `flush` marks the rejection as read; `flush` is not called when the body errors or is cancelled. A request is treated as rejected when its status is 400 or higher, its body was read to a clean end and no stream event other than `start` was produced. A rejected request reports no usage and is complete, both when the stream ends with a terminal event and when it throws. Before, a sent request answered with an error status was reported incomplete, which under a run or task cap made the turn `budget_unverifiable` and refused Pi's retry. The request status is still reported as `http_<status>`.
- **Still incomplete:** a rejection whose body was truncated or cancelled, and an error after any streamed model output, remain incomplete and keep usage unverified.
- **Chat endings without a trailing blank line:** the goal of the pull request includes a Chat stream that ends with `data: [DONE]` followed by one newline or none. The pull request does not change `chatEnd`; the end-of-stream flush that terminates the last event was already in v2.13.206. This release changes no code for it.
- **Tests:** `tests/test_pi_runner_turns.py` gains a retry test under run and task caps for both protocols, for 429 and 500, with a complete and a truncated error body, and a test that a response failure after output keeps usage incomplete. `tests/fake_model_api.py` gains an `error_body_bytes` option to truncate a scripted error body.
- **Model-visible changes:** None. No prompt, tool or message text changed, and request bodies and headers are the same as in v2.13.206.

## Upgrade and rollback

Re-run `install.sh` once v2.13.207 is published. No data or schema change is involved, so a rollback to v2.13.206 needs no database restore.

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**使用可选 Pi runner 且设置了运行或任务成本上限的运维者。此前 provider 返回 429 或 5xx 后，Pi 的重试可能被当作 `budget_unverifiable` 拒绝。包含 v2.13.206 之后合并的改动。

**解决了什么：**[#862](https://github.com/foolzzz/looper/pull/862)（修复 #860）把 provider 以 HTTP 400 及以上状态拒绝、错误响应体已完整读完且没有流式模型输出的已发送请求，按零用量且完成上报，因此 Pi 的重试不再被拒绝。

**是否有破坏性变更：**否。命令、设置、数据库 schema 和允许的升级路径均不变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.207。

**贡献者：**维护者 @foolzzz 提交 [#862](https://github.com/foolzzz/looper/pull/862)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.207
```

### 行为变化与入口

- **provider 拒绝按零花费计（`runners/pi/src/provider.ts`）：**响应状态为 400 及以上时，runner 让响应体经过一个透传转换，其 `flush` 把该拒绝标记为已读完；响应体出错或被取消时不会调用 `flush`。状态为 400 及以上、响应体已干净读完、且除 `start` 外没有产生任何流事件的请求，被视为被拒绝。被拒绝的请求不报告用量且为完成，无论流以终止事件结束还是抛出错误。此前，已发送但收到错误状态的请求被报告为未完成，设置了运行或任务上限时会使回合 `budget_unverifiable` 并拒绝 Pi 的重试。请求状态仍报告为 `http_<状态码>`。
- **仍为未完成：**响应体被截断或取消的拒绝，以及出现任何流式模型输出之后的错误，仍为未完成，用量保持未验证。
- **没有结尾空行的 Chat 结束：**该拉取请求的目标包含以 `data: [DONE]` 加一个换行或无换行结束的 Chat 流。该拉取请求没有修改 `chatEnd`；终止最后一个事件的流结束 flush 在 v2.13.206 中已存在。本版本没有为此改动代码。
- **测试：**`tests/test_pi_runner_turns.py` 新增在运行和任务上限下的重试测试（两种协议、429 和 500、完整和被截断的错误体），以及输出后响应失败保持用量未完成的测试。`tests/fake_model_api.py` 新增 `error_body_bytes` 选项以截断脚本化的错误体。
- **面向模型的变化：**无。提示词、工具和消息文本均未改变，请求体和请求头与 v2.13.206 相同。

### 升级与回退

v2.13.207 发布后重新运行 `install.sh`。不涉及数据或 schema 变化，回退到 v2.13.206 无需恢复数据库。
