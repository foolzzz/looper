# Looper v2.13.180

## Release Decision

**Who should upgrade:** Operators and API clients that import Looper configuration files, and maintainers who run the Manager dialog evals. It is a hotfix that ships the changes merged since v2.13.179.

**What this release solves:** [#790](https://github.com/foolzzz/looper/pull/790) refuses a configuration file that still carries retired fields before an import touches the target, and lets an API client import a file it exported. [#793](https://github.com/foolzzz/looper/pull/793) makes the dialog eval readback fail when no completed API turn is found for a dialog that needed the model.

**Breaking changes:** Yes, for imports of old files. A configuration file with the retired fields `model` or `effort` in `settings.layers[]` or a project's `layers[]`, or `protocols`, `base_url` or `models` in `providers[]`, is now refused as a whole; before, the retired entry was skipped. No command, schema or other file format changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#790](https://github.com/foolzzz/looper/pull/790) and [#793](https://github.com/foolzzz/looper/pull/793); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.180
```

## Behavior changes

- **Retired fields are refused ([#790](https://github.com/foolzzz/looper/pull/790)):** `validate_document` in `looper/agents/config_transfer.py` raises a `ConfigFileError` such as `settings.layers[0].model: retired configuration field` for `model` or `effort` in `settings.layers[]` and in each project's `layers[]`, and for `protocols`, `base_url` or `models` in `providers[]`. It runs when the file is read and again in `import_config`, so the refusal comes before any target read, confirmation or write. The test that expected such entries to be skipped now covers only the other invalid layer fields, which are still skipped.
- **Client import of an exported file:** in `looper/agents/config_imports.py`, `authorize` is now async. For a client identity, a `managers` list holding only the default Manager `manager` with at most `id`, `name`, `description` and `idle_timeout_seconds` is accepted if each value equals the current default Manager; the list is then removed from what is previewed and applied, so a target change after the check is not overwritten. A differing default Manager, any other Manager, added bots or Manager installs still raise FORBIDDEN, including at confirmation. Operator identity is unchanged.
- **Dialog eval readback ([#793](https://github.com/foolzzz/looper/pull/793)):** `evals/prompt_regression/dialogs.py` counts the steps that need the model and `_api_session_check` fails with `expected at least N completed API Manager turns, read back M` when fewer are read back. A step marked `code_only` (the `/profile` steps of `session_profile_switch`), or one with `stop` or `withdraw`, is not counted. This changes the eval tooling only.
- **Model-visible changes:** none to prompts, tool schemas or tool descriptions. Only the new refusal text of a configuration import is new, and it is shown to whoever runs the import, including a Manager that does so through its tools.

## Upgrade and rollback

Re-run `install.sh` once v2.13.180 is published. Before importing an older exported file, remove the retired fields from it. There is no schema change, so rolling back to v2.13.179 needs nothing else.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**导入 Looper 配置文件的运维者和 API 客户端，以及运行 Manager 对话评测的维护者。本版本是随合并即发布的 hotfix，包含 v2.13.179 之后合并的改动。

**解决了什么：**[#790](https://github.com/foolzzz/looper/pull/790) 在导入触碰目标之前拒绝仍带已退役字段的配置文件，并让 API 客户端能导入自己导出的文件。[#793](https://github.com/foolzzz/looper/pull/793) 让对话评测回读在需要模型的对话找不到已完成的 API 回合时失败。

**是否有破坏性变更：**有，针对旧文件的导入。`settings.layers[]` 或项目 `layers[]` 中带已退役字段 `model`、`effort`，或 `providers[]` 中带 `protocols`、`base_url`、`models` 的配置文件，现在整体被拒绝；之前是跳过该条目。命令、schema 和其他文件格式均未改变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.180。

**贡献者：**维护者 @foolzzz 提交 [#790](https://github.com/foolzzz/looper/pull/790) 和 [#793](https://github.com/foolzzz/looper/pull/793)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.180
```

### 行为变化与入口

- **已退役字段被拒绝（#790）：**`looper/agents/config_transfer.py` 的 `validate_document` 对 `settings.layers[]` 和各项目 `layers[]` 中的 `model`、`effort`，以及 `providers[]` 中的 `protocols`、`base_url`、`models` 抛出 `ConfigFileError`，例如 `settings.layers[0].model: retired configuration field`。读取文件时和 `import_config` 中都会检查，因此在读取目标、确认或写入之前就拒绝。原先期望跳过这些条目的测试现在只覆盖其他仍被跳过的无效层字段。
- **客户端导入自己导出的文件：**`looper/agents/config_imports.py` 的 `authorize` 改为异步。对 client 身份，`managers` 列表只含默认 Manager `manager`、且只有 `id`、`name`、`description`、`idle_timeout_seconds` 中的字段时，若各值与当前默认 Manager 相同则被接受；该列表随后从预览和应用的内容中移除，因此检查之后目标变化不会被旧定义覆盖。默认 Manager 有差异、任何其他 Manager、新增 bot 或 Manager 安装仍以 FORBIDDEN 拒绝，确认时同样。operator 身份不变。
- **对话评测回读（#793）：**`evals/prompt_regression/dialogs.py` 统计需要模型的步骤，`_api_session_check` 在回读的已完成回合更少时以 `expected at least N completed API Manager turns, read back M` 失败。标记为 `code_only` 的步骤（`session_profile_switch` 的 `/profile` 步骤）以及带 `stop` 或 `withdraw` 的步骤不计入。仅影响评测工具。
- **面向模型的变化：**提示词、工具 schema 和工具描述均无变化。只有配置导入新增的拒绝文本，它展示给运行导入的人，包括通过工具执行导入的 Manager。

### 升级与回退

v2.13.180 发布后重新运行 `install.sh`。导入旧的导出文件前，先从中删去已退役字段。无 schema 变更，回退到 v2.13.179 无需其他操作。

### 可选能力启用与使用

本版本未新增可选能力启用入口。
