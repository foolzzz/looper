# Looper v2.15.42

Contains everything merged to main after what [v2.15.41](v2.15.41.md) shipped, up to and including `0ad334847` (the merge of [#1804](https://github.com/foolzzz/looper/pull/1804)): 16 pull requests plus the six members of merge batch #1834. Release pull requests are not changes. Release preparation adds only version, changelog and release files. If main has moved beyond this freeze when the pull request merges, the tag belongs on this release pull request's own head, as described in [the release procedure](README.md).

Two behavior changes apply without any switch: the main Manager session now delivers autonomous and completion replies only to the operator, and a routed completion fallback is recorded and delivered. Startup adds three migrations, each widening an existing check. The task Manager foundations and Work console changes stay behind `tasks.conversations.enabled`, off by default.

## Release Decision

**Who should upgrade:** Operators whose Manager is reachable from groups, other people's direct chats or API clients and who want its autonomous and completion replies kept to the operator; operators using the Manager's resident operator profile; and operators who want shutdown, dashboard static-path and stable-context fixes. From v2.15.38 or earlier, upgrade straight to v2.15.42 and read [v2.15.41](v2.15.41.md), [v2.15.40](v2.15.40.md) and [v2.15.39](v2.15.39.md).

**What this release solves:** The default Manager's main session no longer sends autonomous follow-ups or task-completion replies to a group, another sender's direct chat or an API client's thread; it records the withheld reply and, for completions, sends the code notice. A routed completion that hit the session allowlist used to fail its reason write and leave the event `running`; it now falls back and delivers the notice. Operator profile facts appear under About instead of as standing rules. Stable context resends a whole block after an isolated turn. Shutdown no longer waits forever on a stuck connection, and an unresolvable dashboard static path answers 404 instead of 500. The default-off task Manager gains its launch, turn and profile foundations, and the Work page gets clearer labels and states.

**Breaking changes:** No removed operation or setting. Behavior does change without a switch, so read the Behavior changes section before upgrading: main-session replies are withheld from non-operator audiences ([#1824](https://github.com/foolzzz/looper/pull/1824)), a routed completion fallback now delivers its notice ([#1830](https://github.com/foolzzz/looper/pull/1830)), and startup adds migrations 2090, 2130 and 2140. Upgrades from v2.15.38 or earlier also inherit v2.15.39's migrations and behavior changes. Installations older than the bridge must upgrade to v2.13.165 first and start once.

**How to verify:** Check the version and that the service starts and applies the three migrations. As a non-operator in a disposable group or direct chat, trigger a background job in the main session with routing off and confirm no autonomous follow-up arrives and a `manager_events` row of kind `autonomous` records `withheld_not_operator`. The operator's own chat should still get its reply. With Work on, a draft or ready task shows the neutral changes message rather than an error. The checks run for this document are listed under Validation.

```bash
looper --version   # looper 2.15.42
```

**Contributors:** Maintainer @foolzzz authored every pull request in this release; no community contribution was included in this release interval. Inherited contributor credit is in [v2.15.41](v2.15.41.md), [v2.15.40](v2.15.40.md) and [v2.15.39](v2.15.39.md).

## Included changes

### Manager delivery to non-operators

- **[#1824](https://github.com/foolzzz/looper/pull/1824):** The main session sends an autonomous reply (what the Manager says on its own after a background job) only when the last turn was the operator's own: the dashboard without an API client, or the operator's direct chat on a bot, decided by operator identity. Otherwise the reply stays on its run record and a `manager_events` row of kind `autonomous` records `skipped` with `withheld_not_operator`. Completion turns for an API client's dashboard thread, another person's direct chat, or a schedule whose direct-chat target is not the operator end `skipped` with the same reason; the existing code notice is delivered and no main-session model reply is written. Migration `main_session_egress` (2130) widens the `manager_events` kind and reason checks. Only the default Manager is affected; no prompt, tool list or model-visible text changes.
- **[#1830](https://github.com/foolzzz/looper/pull/1830):** With session routing on and completion turns `dm_only`, a task asked in another sender's own session reaches the fallback with reason `session_allowlist`, and the recorded code notice is delivered. Before, the reason update failed and the event stayed `running`. Schedule runs claimed in such a session take the same path. The reason is not counted among those that mark completion turns as a failing feature. Migration `completion_session_allowlist` (2140) adds the value, `NOT VALID` first and validated in the online step.

### Manager context and profile

- **[#1730](https://github.com/foolzzz/looper/pull/1730):** With profile injection on, inline `kind: fact` entries compile into an `About:` group after `Standing rules:` instead of appearing as standing rules. About entries are dropped before standing rules when the 1500-character cap is exceeded. The profile block version advances only when compiled text changes. Profiles without facts keep their compiled bytes, and disabled injection keeps the fixed prompt.
- **[#1732](https://github.com/foolzzz/looper/pull/1732):** With stable context on, operator turn A, then an isolated turn B (a shared chat or an API client), then operator turn C now renders C as a whole block with the current persona and profile sections. Without an isolated turn, and with stable context off, behavior and bytes are unchanged.

### Task Manager foundations, off by default

- **[#1768](https://github.com/foolzzz/looper/pull/1768):** Launch and resident-pool foundations behind `tasks.conversations.enabled`: direct sessions with the fixed task instructions and a bounded task brief, fail-closed checks for outbound review, hook-disabling settings and unverified CLI versions, an independent `task_manager` role defaulting to Sonnet, task profile overrides, and the resident cap `tasks.managers.max_resident` (default 6, range 1-20) with idle reclamation. Migration `task_manager_role` (2090) allows the new role in existing role and profile checks. Constructing the pool starts no model process.
- **[#1770](https://github.com/foolzzz/looper/pull/1770):** Task-owned turns with one-turn-per-task FIFO scheduling, a shared task spend gate, streamed text and bounded tool records, saved sessions that resume after mode or model changes, per-turn commits for owned worktrees, and stop with kill fallback. Background start and profile switching wait while a turn runs.
- **[#1804](https://github.com/foolzzz/looper/pull/1804):** Operator-only `tasks.task_manager_profile_get` and `tasks.task_manager_profile_set` return the override, the effective profile and its source, and the role-compatible choices. A busy turn returns HTTP 409 `task_manager_busy` before any write; an unsupported runtime returns `task_manager_runtime_unsupported`. `tasks.create_draft` accepts `task_manager_profile_id` and returns `task_manager_profile`. The operations are new in this release. No migration is added.

No conversation transport or UI uses these foundations yet; task conversations still go to the Planner.

### Work console

- **[#1817](https://github.com/foolzzz/looper/pull/1817), [#1823](https://github.com/foolzzz/looper/pull/1823), [#1827](https://github.com/foolzzz/looper/pull/1827):** Draft, ready, pending and assigned tasks show a neutral changes message without a request or retry; `running` and later statuses still show the unreadable-workspace alert. `handing_back` reads 交回中. The pre-start composer hint and every other task-conversation hint name the Planner (规划者) from one answerer value; sending is unchanged.

### Runtime and delivery fixes

- **[#1826](https://github.com/foolzzz/looper/pull/1826):** The recording proxy and the HTTP server abort connections that outlive the shutdown grace period, including ones accepted during stop, and bound cleanup instead of waiting forever. Grace durations are unchanged; the proxy logs a new abort warning.
- **[#1828](https://github.com/foolzzz/looper/pull/1828):** A dashboard static path that cannot be resolved, because it is overlong or contains a NUL byte, answers 404 instead of a 500 or the dashboard page.

### Internal foundations and tests

Tests, evals and docs with no product behavior change: keeper, outbox and Grok steering test races ([#1800](https://github.com/foolzzz/looper/pull/1800), [#1801](https://github.com/foolzzz/looper/pull/1801), [#1805](https://github.com/foolzzz/looper/pull/1805)); a separate budget for database test schema setup ([#1833](https://github.com/foolzzz/looper/pull/1833)); every import form covered by the web source boundary test ([#1821](https://github.com/foolzzz/looper/pull/1821)); a synthetic path in a test fixture ([#1829](https://github.com/foolzzz/looper/pull/1829)); nightly browser fixtures for the Work sidebar probe ([#1813](https://github.com/foolzzz/looper/pull/1813)); corrected resident-profile eval checks with an offline rescore ([#1808](https://github.com/foolzzz/looper/pull/1808)); hardened private-details eval checks ([#1814](https://github.com/foolzzz/looper/pull/1814)); and the browser and desktop RFC ([#1810](https://github.com/foolzzz/looper/pull/1810)).

From a database that has completed v2.15.41, startup adds these three migrations even with all optional features off, using the existing pre-migration backup path:

| Order | Migration | What changes |
| --- | --- | --- |
| 2090 | `task_manager_role` | Allows the `task_manager` role in the existing role and profile checks. No table is added. |
| 2130 | `main_session_egress` | Widens the `manager_events` kind and reason checks with the autonomous kind and `withheld_not_operator`. |
| 2140 | `completion_session_allowlist` | Widens the `manager_events` reason check with `session_allowlist`, `NOT VALID` first, validated in the online step. |

## Behavior changes

### Without a new switch

- **Main-session replies are operator-only (#1824).** With session routing off, a group no longer receives the Manager's autonomous follow-up after a background job started in the main session; neither does another sender's direct chat or an API client's dashboard thread. Each is recorded as `withheld_not_operator`. A bot with no `operator_sender_id` cannot tell, so its direct chats count as not the operator's for the main session; configure the operator identity to keep follow-ups there.
- **Completion turns follow the same rule (#1824).** With `manager.completion_turns` at `dm_only` and routing off, another person's direct chat, an API client's dashboard thread and a schedule run whose direct-chat target is not the operator get the code notice and no main-session model reply. A routed session's own chat, the operator's chats and groups' own completion handling are unchanged.
- **Routed completion fallback delivers its notice (#1830).** The reason is recorded as `session_allowlist`; previously the event stayed `running` and no notice was sent. The reason does not count toward marking completion turns as failing.
- **Profile facts move under About (#1730)** when profile injection is on. Profiles without facts keep their bytes.
- **A whole block after an isolated turn (#1732)** when stable context is on.
- **Shutdown and static paths (#1826, #1828):** stuck connections are aborted after the grace period; an unresolvable static path answers 404.
- **Three startup migrations (2090, 2130, 2140).**

### When an existing switch is already on

With `tasks.conversations.enabled` on, the Work page shows the label, neutral-state and Planner-hint changes, and the new task Manager operations answer instead of `conflict`. The Work console still sends task conversations to the Planner, and no turn is started without a conversation transport. With it off, none of this is reachable. `manager.turn_context.enabled` behaves as in v2.15.40.

## Entry points

- **Dashboard:** Work labels and neutral states (#1817, #1823, #1827) and the 404 for unresolvable static paths (#1828). Withheld replies are visible to the operator through `manager_events`. No new page.
- **Telegram and Lark:** The operator-only rule for autonomous and completion replies applies through the same Manager path. A bot needs `operator_sender_id` configured to keep main-session follow-ups in its direct chats. No command or transport change.
- **CLI/API:** New operator-only `tasks.task_manager_profile_get` and `tasks.task_manager_profile_set`, the optional `task_manager_profile_id` on `tasks.create_draft`, and the `tasks.managers.max_resident` setting, all inert while Work is off. The generated operator CLI discovers the operations. No existing operation is removed.

## 中文摘要

包含 [v2.15.41](v2.15.41.md) 之后合入 main、至 `0ad334847`（#1804 的合并）为止的全部改动：16 个 PR 加合并批次 #1834 的六个成员。发布 PR 不算改动。若 PR 合入时 main 已越过冻结点，tag 应打在本发布 PR 自己的 head 上。无开关即生效的行为变化有两项：主 Manager 会话的自主回复与任务完成回复只投递给操作者；路由会话的完成回退会记录并投递通知。启动新增三项迁移，均为放宽已有约束。任务 Manager 基础与工作台改动仍在默认关闭的 `tasks.conversations.enabled` 之后。

### 升级决策

**谁需要升级：** Manager 可被群、其他人的私聊或 API 客户端触达、希望其自主与完成回复只给操作者的操作者；使用 Manager 常驻操作者画像的操作者；以及需要关停、静态路径与稳定上下文修复的操作者。从 v2.15.38 或更早版本直接升级到 v2.15.42，并阅读 [v2.15.41](v2.15.41.md)、[v2.15.40](v2.15.40.md)、[v2.15.39](v2.15.39.md)。

**解决了什么：** 主会话不再把自主跟进或完成回复发给群、他人私聊或 API 客户端线程，而是记录被拦下的回复，完成场景改发代码通知。路由会话命中会话白名单的完成回退此前原因写入失败、事件卡在 `running`，现在会回退并投递通知。画像中的背景事实归入 About，不再冒充常驻规则。稳定上下文在隔离回合后重发完整块。关停不再被卡住的连接无限拖住，无法解析的仪表盘静态路径返回 404 而不是 500。默认关闭的任务 Manager 获得启动、回合与画像基础，工作台标签与状态更清晰。

**是否有破坏性变更：** 无删除的操作或设置，但无开关的行为会变化，升级前请阅读「行为变化」：主会话回复不再发给非操作者（#1824）、路由完成回退现在会投递通知（#1830），启动时新增迁移 2090、2130、2140。从 v2.15.38 或更早升级还会继承 v2.15.39 的迁移与行为变化。早于桥接版本的安装需先升级到 v2.13.165 并启动一次。

**如何验证：** 核对版本，确认服务启动并应用三项迁移。在一次性的群或私聊中以非操作者身份、路由关闭时触发主会话后台任务，应收不到自主跟进，且 `manager_events` 出现 kind 为 `autonomous`、原因为 `withheld_not_operator` 的记录；操作者自己的对话仍照常收到。开启工作台时，草稿或就绪任务的改动面板显示中性提示而非错误。本次实际运行的检查见「验证」。

```bash
looper --version   # looper 2.15.42
```

### 从 v2.15.38 或更早版本升级

直接升级到 v2.15.42，本版包含 v2.15.41、v2.15.40 与 v2.15.39。v2.15.39 的 `task_drafts`（2050）、`proactive_bodies`（2110）迁移与行为变化继承。对已完成 v2.15.41 的数据库，启动会新增三项迁移，即使可选功能全部关闭，并沿用迁移前备份：2090 `task_manager_role` 允许 `task_manager` 角色；2130 `main_session_egress` 放宽 `manager_events` 的 kind 与 reason 约束；2140 `completion_session_allowlist` 为 reason 约束加入 `session_allowlist`（先 `NOT VALID`，在线步骤校验）。降级需保留迁移前备份，无 down migration。早于 v2.13.165 的安装需先升级到 v2.13.165 并启动一次。

### 行为变化

- **主会话回复仅限操作者（#1824）：** 路由关闭时，主会话后台任务的自主跟进不再发给群、他人私聊或 API 客户端线程，均记为 `withheld_not_operator`。未配置 `operator_sender_id` 的 bot，其私聊对主会话视为非操作者，需配置操作者身份才能保留跟进。
- **完成回合同理（#1824）：** `manager.completion_turns` 为 `dm_only` 且路由关闭时，他人私聊、API 客户端线程、以及直聊目标不是操作者的定时运行，只收到代码通知，不再写主会话模型回复。路由会话自己的聊天、操作者的聊天、群的完成处理不变。
- **路由完成回退投递通知（#1830）：** 原因记为 `session_allowlist`；此前事件停在 `running` 且不发通知。该原因不计入完成回合失败判定。
- **画像事实归入 About（#1730）**（画像注入开启时）；无事实的画像字节不变。
- **隔离回合后重发完整块（#1732）**（稳定上下文开启时）。
- **关停与静态路径（#1826、#1828）：** 宽限期后中止卡住的连接；无法解析的静态路径返回 404。
- **三项启动迁移（2090、2130、2140）。**
- **已开启工作台时：** 标签、中性状态与规划者提示生效，新的任务 Manager 操作可用，但任务对话仍走 Planner，没有对话入口会启动任务 Manager 回合；关闭时均不可达。
- **入口：** 仪表盘有工作台标签与状态、静态路径 404；Telegram/Lark 沿用同一 Manager 路径，无命令或 transport 变化；CLI/API 新增仅限操作者的 `tasks.task_manager_profile_get/set`、`tasks.create_draft` 的 `task_manager_profile_id` 与 `tasks.managers.max_resident`，工作台关闭时无效。
