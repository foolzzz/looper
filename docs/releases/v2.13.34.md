# Looper v2.13.34

## Release Decision

**Who should upgrade:** Anyone who wants to rename a task, from the task page or by asking the Manager (dashboard chat, Telegram or Lark).

**What this release solves:** [#389](https://github.com/foolzzz/looper/pull/389) lets a task be renamed in any status, an ended one included. Before, a task's title was set once and could not be changed.

**Breaking changes:** No. No existing CLI command, configuration key, API shape or database schema changed; the additions are listed below.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#389](https://github.com/foolzzz/looper/pull/389); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.34
```

## Behavior changes

- **New endpoint `PUT /api/tasks/:id/title`:** takes `{title}`, normalises it to one line of at most 60 characters and answers `{task_id, title}`. It answers 400 for a missing, non-string or empty title and 404 for an unknown task. Any task status is accepted.
- **Task history note:** a change of title adds a supplement to the task's history, already marked delivered so the Planner needs no turn for it, with `via` `task_page` or `manager:<channel>`. Setting the title it already has writes nothing.
- **`looper_task_update` takes `title`:** accepted for a task in any status, alone or with `requirement`, `work_dir`, `profiles` or `system_prompt_modes`. A call with none of the fields is refused, and its message now lists `title`.
- **Task page:** the heading has a pencil that edits the title in place (Enter or Save stores it, Esc cancels, a refusal is shown beside the input).
- **Task detail API:** `GET /api/tasks/:id` documents `title` (the task's own, empty when it has none; `name` is what the task is shown by).
- **Known gaps, reported by the review of #389 and not changed in this release:** the live task router keeps the title loaded at start, so end notices and the running-planner list of a running task can show the old name; the rename note is stored as a supplement, so a later Planner, Worker or Reviewer turn may list it among the user's instructions; `looper_task_update` lists `title` in `changed` even when the title was unchanged. The review reported these for a follow-up issue after the merge.
- **Model-visible changes:** The `looper_task_update` tool schema and description now include `title` (a string of 1 to 60 characters: "a few words naming the task, in the user's language"). The Manager's tool documentation in `docs/architecture/agent-system.md` is updated to match. The eval suite gains a `rename_task` dialog. No Planner, Worker or Reviewer prompt text changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.34 is published. There is no schema or configuration change. Rolling back to v2.13.33 is safe; titles already changed stay as they are, and the rename notes stay in the task history.

### 升级决策

**谁需要升级：**想给任务改名的用户，无论是在任务页还是通过 Manager（仪表盘聊天、Telegram、Lark）。

**解决了什么：**[#389](https://github.com/foolzzz/looper/pull/389) 支持在任何状态下给任务改名，已结束的任务也可以。此前任务标题只能设置一次。

**是否有破坏性变更：**无。现有 CLI、配置项、API 形态、数据库 schema 均未变化，新增内容见下文。

**如何验证：**运行 `looper --version` 核对版本为 2.13.34。

**贡献者：**维护者 @foolzzz 提交 [#389](https://github.com/foolzzz/looper/pull/389)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.34
```

### 行为变化与入口

- 新增接口 `PUT /api/tasks/:id/title`：接收 `{title}`，规整为单行且不超过 60 个字符，返回 `{task_id, title}`。标题缺失、非字符串或为空返回 400，任务不存在返回 404。任何任务状态都可改名。
- 任务历史记录：改名会在任务历史中加一条补充说明，已标记为送达，Planner 无需为此开启回合，`via` 为 `task_page` 或 `manager:<channel>`。设置为已有标题时不写入。
- `looper_task_update` 新增 `title`：任何状态的任务都可用，可单独使用，也可与 `requirement`、`work_dir`、`profiles`、`system_prompt_modes` 同时使用。一个字段都不给会被拒绝，提示信息现在包含 `title`。
- 任务页：标题旁有铅笔图标，可原地编辑（Enter 或 Save 保存，Esc 取消，被拒绝的原因显示在输入框旁）。
- 任务详情 API：`GET /api/tasks/:id` 文档化了 `title`（任务自己的标题，没有时为空；`name` 是显示用的名称）。
- 已知缺口（#389 的评审报告，本版本未改动）：运行中的任务路由器保留启动时加载的标题，因此运行中任务的结束通知和运行中 Planner 列表可能仍显示旧名；改名记录以补充说明保存，之后的 Planner、Worker、Reviewer 回合可能把它列在用户指令中；标题未变化时 `looper_task_update` 仍在 `changed` 中列出 `title`。评审将这些列为合并后的后续 issue。
- 面向模型的变化：`looper_task_update` 的工具 schema 与描述新增 `title`（1 至 60 个字符的字符串，“用用户的语言写几个词来命名任务”）。`docs/architecture/agent-system.md` 中 Manager 工具文档同步更新。评测集新增 `rename_task` 对话。Planner、Worker、Reviewer 的提示词文本未变。

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.33 安全；已改的标题保持不变，改名记录仍留在任务历史中。
