# Looper v2.13.72

## Release Decision

**Who should upgrade:** Contributors who add or change v1 API domain modules. Operators, dashboard users and API clients see no change.

**What this release solves:** [#495](https://github.com/foolzzz/looper/pull/495) replaces the shared, hand-edited list of v1 domain modules with module discovery, so parallel v1 domain changes stop conflicting on that list.

**Breaking changes:** No. The generated OpenAPI document and every operation keep their behavior and order; the pull request names a change to either as its P0 risk.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#495](https://github.com/foolzzz/looper/pull/495); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.72
```

## Behavior changes

- **Discovery:** `looper/agents/v1_domains/__init__.py` imports every public module of the package (names not starting with `_`) at load, in place of the explicit `MODULES` tuple. `api_v1.domains()` returns the discovered modules. `MODULES` remains, derived from them.
- **Order:** an optional integer `ORDER` in a module fixes its place in the OpenAPI document. Modules without it follow the ordered ones, by name. The eleven existing domain modules gained an `ORDER` that keeps the previous order, and a test checks the operation ids against the list on main.
- **Load-time checks:** a domain module that lacks `OPERATIONS` or `RESULTS`, has a non-integer `ORDER`, lacks the `run` callback (or `stream` for a streaming operation), or repeats an operation id or a method and path now fails with a named error when the domains load, which is at serve start.
- **Operations:** none added, removed or changed. No HTTP route, request or answer differs.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt or Manager Tool changed; the change is internal to the API registry.

## Upgrade and rollback

Re-run `install.sh` once v2.13.72 is published. No data migration. Rolling back to v2.13.71 restores the explicit module list, with no stored data affected.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 行为变化与入口

- **发现机制：**`looper/agents/v1_domains/__init__.py` 在加载时导入包内所有公开模块（名称不以 `_` 开头），取代显式的 `MODULES` 元组。`api_v1.domains()` 返回发现的模块；`MODULES` 仍保留，由它们派生。
- **顺序：**模块可选的整数 `ORDER` 决定其在 OpenAPI 文档中的位置；没有 `ORDER` 的模块排在有序模块之后，按名称排序。现有的十一个域模块都新增了保持原顺序的 `ORDER`，测试会对照 main 上的列表检查 operation id。
- **加载期检查：**域模块缺少 `OPERATIONS` 或 `RESULTS`、`ORDER` 不是整数、缺少 `run` 回调（流式操作则为 `stream`），或重复使用 operation id、方法加路径时，域加载（即服务启动）会以带模块名的错误失败。
- **操作：**没有新增、删除或修改任何操作；HTTP 路由、请求和响应均无差异。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 和 Manager Tool 均未改动；变化仅限 API 注册表内部。
