# Looper v2.14.138

This is the patch release v2.14.138, a hotfix line in which each merged change ships at once. It documents two changes: [#1235](https://github.com/foolzzz/looper/pull/1235) (Planner turns carry plan changes instead of the whole plan) and [#1240](https://github.com/foolzzz/looper/pull/1240) (SUPERVISE accepts the review steps it lists, the final answers in the user's language).

## Release Decision

**Who should upgrade:** Operators whose tasks run a long Planner session, because each Planner turn no longer adds the whole plan and progress section to the resident session. Operators whose tasks use review steps benefit from the SUPERVISE fix. Everyone else gets no visible change.

**What this release solves:** [#1235](https://github.com/foolzzz/looper/pull/1235) shrinks every Planner turn after the first from the whole `Plan:` and "Progress and findings" sections (about 36K tokens per turn in the pull request's measurement) to a change view. [#1240](https://github.com/foolzzz/looper/pull/1240) makes a SUPERVISE reply able to name every step its prompt lists as running, including review steps, and has the final report written in the user's language.

**Breaking changes:** No. There is no migration and no API removal. The Planner's reply contracts, decisions and dispatching are unchanged; the message text a Planner receives changes (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.138
```

**Contributors:** Maintainer @foolzzz authored [#1235](https://github.com/foolzzz/looper/pull/1235) and [#1240](https://github.com/foolzzz/looper/pull/1240); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.137 upgrades directly. There is no schema change.

## Behavior changes

- **Planner turns carry a change view** ([#1235](https://github.com/foolzzz/looper/pull/1235), `looper/agents/tiers/plan_view.py`, `looper/agents/tiers/planner.py`). A Planner turn message after the first carries: every step's label grouped by status; the full lines of steps that changed or are new ("Changed or new:", or "No step changed."); removed step ids ("Removed:"); and the progress section only as "New progress:" lines when it changed.
- **When the full view is sent.** The full plan and progress are sent on the first view, on a new session or process, after a compaction event, after a failed or autonomous turn, after 20 change turns (`PLAN_FULL_EVERY_TURNS`), and when the change view is longer than half the full view. A runtime without compaction events receives the full view every turn. A restart (RESTART) always starts with the full view, and dropping the saved session or a new plan resets it.
- **Room turns** keep their bounded plan context (a third of the room batch limit); when it is clipped, the saved view is discarded so the next turn starts full.
- **Message order.** In WAIT and GATE messages the "Running now" line moves before the plan view. The condition CHAT turn carries the progress section when it receives a full view. RESTART and CHAT turns for task changes carry the journal separately from the plan view.
- **Run records** of Planner turns gain the annotations `plan_view` (`full` or `changes`) and `plan_view_reason`.
- **SUPERVISE names the steps it lists** ([#1240](https://github.com/foolzzz/looper/pull/1240)). The steps a SUPERVISE prompt lists as running are exactly the steps its reply may name; before, the reply was checked against the work steps of the plan view only, so a review step the prompt listed could not be named. If the Planner stops a running step that has reviews, the stopped Reviewer is recorded as a failed review and goes through its panel; a stopped work step still goes through the normal decision path.
- **Final report language.** The Planner protocol adds that `final` is written in the user's language; headings may stay as the protocol defines them.
- **Unchanged:** reply contracts, decisions and dispatching, the Worker and Reviewer prompts and the Manager prompt.
- **Model-visible changes:** Yes, both. Planner turn messages carry the change view, the changed order of "Running now", the full-view rule and the plan text described above; the Planner's protocol prompt gains the final-report language line (`looper/agents/tiers/planner_protocol.py`). Both pull requests state that the real-mode prompt eval runs before merge.

## 中文摘要

本版本是 patch release v2.14.138（热修线，每个合并的改动立即发布），说明两项改动：[#1235](https://github.com/foolzzz/looper/pull/1235)（Planner 每轮携带计划变更而非整份计划）和 [#1240](https://github.com/foolzzz/looper/pull/1240)（SUPERVISE 接受其列出的评审步骤，最终报告使用用户的语言）。

### 升级决策

**谁需要升级：**任务运行较长 Planner 会话的运维者，因为每个 Planner 轮次不再把整份计划和进展章节加入常驻会话；使用评审步骤的任务受益于 SUPERVISE 修复。其他人没有可见变化。

**解决了什么：**[#1235](https://github.com/foolzzz/looper/pull/1235) 把第一轮之后每个 Planner 轮次从整份 `Plan:` 和“Progress and findings”章节（PR 中约每轮 36K token）缩减为变更视图。[#1240](https://github.com/foolzzz/looper/pull/1240) 让 SUPERVISE 回复可以指名其提示词列出的所有运行中步骤（含评审步骤），并让最终报告使用用户的语言。

**是否有破坏性变更：**否。没有迁移，没有移除 API。Planner 的回复契约、决策和派发不变；Planner 收到的消息文本有变化（见下文）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.14.138。

**贡献者：**维护者 @foolzzz 提交 [#1235](https://github.com/foolzzz/looper/pull/1235) 和 [#1240](https://github.com/foolzzz/looper/pull/1240)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.138
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.137 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **Planner 轮次携带变更视图**（[#1235](https://github.com/foolzzz/looper/pull/1235)，`looper/agents/tiers/plan_view.py`、`looper/agents/tiers/planner.py`）。第一轮之后的 Planner 消息包含：按状态分组的每个步骤标签；变更或新增步骤的完整行（“Changed or new:”，或“No step changed.”）；被移除的步骤 id（“Removed:”）；进展章节仅在变化时以“New progress:”行出现。
- **何时发送完整视图。**首次视图、新会话或新进程、压缩事件之后、失败或自主轮次之后、20 个变更轮次之后（`PLAN_FULL_EVERY_TURNS`），以及变更视图长于完整视图一半时，发送完整计划和进展。没有压缩事件的运行时每轮都收到完整视图。重启（RESTART）总以完整视图开始，丢弃已保存会话或出现新计划也会重置。
- **房间轮次**保留有界的计划上下文（房间批次上限的三分之一）；被截断时丢弃已保存的视图，下一轮从完整视图开始。
- **消息顺序。**WAIT 和 GATE 消息中“Running now”行移到计划视图之前。条件 CHAT 轮次在收到完整视图时同时携带进展章节。任务变更的 RESTART 和 CHAT 轮次把日志与计划视图分开携带。
- **运行记录：**Planner 轮次的运行记录新增注释 `plan_view`（`full` 或 `changes`）和 `plan_view_reason`。
- **SUPERVISE 可指名其列出的步骤**（[#1240](https://github.com/foolzzz/looper/pull/1240)）。SUPERVISE 提示词列为运行中的步骤，正是其回复可指名的步骤；此前回复只按计划视图中的工作步骤校验，提示词列出的评审步骤无法被指名。Planner 停止带评审的运行中步骤时，被停止的 Reviewer 记为失败评审并走其评审组；被停止的工作步骤仍走常规决策路径。
- **最终报告语言。**Planner 协议新增：`final` 使用用户的语言；标题可保持协议定义。
- **不变：**回复契约、决策与派发，Worker 和 Reviewer 的提示词以及 Manager 提示词。
- **面向模型的变化：**有，两项都有。Planner 轮次消息携带变更视图、调整后的“Running now”顺序和上述完整视图规则；Planner 协议提示词新增最终报告语言一行（`looper/agents/tiers/planner_protocol.py`）。两个 PR 都称真实模式提示词评测在合并前运行。
