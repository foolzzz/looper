# Looper v2.13.102

## Release Decision

**Who should upgrade:** Anyone whose clients (including agent clients) create tasks in a new project through the v1 API and must confirm the effect before it is created.

**What this release solves:** [#581](https://github.com/foolzzz/looper/pull/581) makes the confirmation for creating a task in a new project disclose the project's effective execution settings. Before, it named only the project, its default directory and the task's working directory, so a confirmer could not see privileges and limits such as shell commands in wait steps, vault access or the spend cap.

**Breaking changes:** No. The request and response schemas, validation and the confirmation flow are unchanged. Only the text of the `impact` field is longer; a client that parses it as a single line should read its first line.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#581](https://github.com/foolzzz/looper/pull/581); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.102
```

## Behavior changes

- **Confirmation lists execution settings ([#581](https://github.com/foolzzz/looper/pull/581)):** in `looper/agents/v1_domains/task_create.py`, the impact of `tasks.create` for a request with a `project` object now has the existing first line (new project, default directory, task working directory) followed by one line per project execution control, in the order of the execution schema fields. Each line reads `- <field>（<meaning>）：<value>`. Booleans show as `on` or `off`; no budget shows as unlimited; the budget action, step review policy, lesson distillation, step and task workspaces, workspace links, retries, role text limit, gate reminder interval and every room limit are shown with their effective values. The line carries a default marker when the request left that field unset or blank. The supervise interval is never marked, because an unset value inherits the Planner configuration and is shown as such. Dynamic agent settings are not resolved.
- **Unchanged:** the impact is still computed after the project fields, profile overrides and workspace are validated and before any project or task row exists. A request for an existing project (`project_id`) still has no impact. The confirmation still has to come from the same client and session; the test confirms from another session returns 404 and that no project or task row exists before confirmation.
- **Model-visible changes:** yes, one. The `impact` text that a client receives for a new-project task creation is longer, as described above. Tool declarations, request arguments and the saved project and task are unchanged; the test checks that every submitted setting is saved as before.
- **Tests:** [#581](https://github.com/foolzzz/looper/pull/581) adds a test in `tests/test_api_v1_task_create_db.py` with four cases (enabled, off and zero, inherit, omitted) that checks every field is disclosed in order, the shown values, the default markers, the saved settings and the absence of rows before confirmation. It also adds four invalid-request cases: a zero task budget, a mistyped `wait_commands`, a zero room post rate and a zero consult budget. The pull request reports 85 added test lines and 50 production lines.

## Upgrade and rollback

Re-run `install.sh` once v2.13.102 is published. No data migration and no configuration change. Rolling back to v2.13.101 restores the shorter confirmation text.

## 中文摘要

### 升级决策

**谁需要升级：**通过 v1 API 在新项目中创建任务、并需要在创建前确认影响的客户端（包括 agent 客户端）的使用者。

**解决了什么：**[#581](https://github.com/foolzzz/looper/pull/581) 让“在新项目中创建任务”的确认信息披露项目生效的执行设置。此前确认信息只写项目名、默认目录和任务工作目录，确认者看不到等待步骤执行 shell 命令、知识库访问、花费上限等权限与限制。

**是否有破坏性变更：**否。请求与响应 schema、校验和确认流程均未改变，只是 `impact` 字段文本变长；把它当单行解析的客户端应读取第一行。

**如何验证：**运行 `looper --version` 核对版本为 2.13.102。

**贡献者：**维护者 @foolzzz 提交 [#581](https://github.com/foolzzz/looper/pull/581)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.102
```

### 行为变化与入口

- **确认信息列出执行设置（[#581](https://github.com/foolzzz/looper/pull/581)）：**`looper/agents/v1_domains/task_create.py` 中，带 `project` 对象的 `tasks.create` 的 impact 现在在原有第一行（新建项目、默认目录、任务工作目录）之后，按执行 schema 字段顺序逐行列出每个项目执行控制项，格式为 `- <字段>（<含义>）：<值>`。布尔值显示为 `on` 或 `off`；无预算显示为无上限；预算到达后的动作、步骤评审策略、经验沉淀、步骤与任务工作区、workspace 链接、重试次数、角色文本上限、门提醒间隔以及全部房间限额都显示生效值。请求未设置或留空的字段会带“默认”标记。监督间隔不会标记，因为未设置时继承 Planner 配置，并按此显示。动态 agent 设置不会被解析。
- **不变：**impact 仍在项目字段、profile overrides 和工作区校验之后、任何项目或任务行创建之前计算。针对已有项目（`project_id`）的请求仍没有 impact。确认仍须来自同一客户端和同一会话；测试验证其他会话确认返回 404，且确认前没有项目或任务行。
- **面向模型的变化：**有一项。客户端在新项目创建任务时收到的 `impact` 文本变长，如上所述。Tool 声明、请求参数以及保存的项目和任务均未改变；测试检查每个提交的设置仍按原样保存。
- **测试：**[#581](https://github.com/foolzzz/looper/pull/581) 在 `tests/test_api_v1_task_create_db.py` 新增一个含四种情形（启用、关闭与零值、继承、省略）的测试，检查每个字段按顺序披露、显示的值、默认标记、已保存的设置以及确认前无行。另新增四个无效请求用例：预算为零、`wait_commands` 类型错误、房间发送速率为零、咨询预算为零。该 PR 报告新增测试 85 行、生产代码 50 行。
