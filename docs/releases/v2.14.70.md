# Looper v2.14.70

This is the patch release v2.14.70, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.69: the Agent API bridge of kept runs now reconnects and retries calls that are safe to repeat ([#1062](https://github.com/foolzzz/looper/pull/1062)).

## Release Decision

**Who should upgrade:** Installations that run with the keeper on, whose kept runs call Looper's room or vault tools across a control-plane restart. Others see no change.

**What this release solves:** a kept run survives a restart, but its `looper mcp-server` bridge failed a tool call as soon as the control plane was briefly unreachable. [#1062](https://github.com/foolzzz/looper/pull/1062) makes the bridge of kept runs retry for up to 120 seconds, and never repeats a write that may have run.

**Breaking changes:** No. The only API change is the additive `retry_safety` field in the tools listing for kept runs' tokens, and there is no migration.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#1062](https://github.com/foolzzz/looper/pull/1062); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.70
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.69 upgrades directly. This release adds no migration. Runs already kept before the upgrade have an MCP entry without the reconnect variable, so they keep today's behavior; the retry applies to runs started by this release.

## Behavior changes

- **Reconnect window.** Kept runs' MCP entries set `LOOPER_AGENT_RECONNECT_SECONDS=120` (`looper/agents/ops/service.py`, `looper/agents/tiers/worker.py`). `looper mcp-server` (`looper/agents/mcp_server.py`) reads it as a non-negative number, capped at 600; an invalid value makes it exit with an error. The window starts at the first failure. Backoff starts at 0.5 s and doubles to 5 s; `Retry-After` is clamped to that range. One `agent api retry` summary line per retried call goes to stderr. With the variable unset or empty, a request makes one attempt as before.
- **What is retried.** Refused connections and HTTP 503 with an integer `Retry-After` always retry, because neither executed the call. Other connection failures retry only `GET /tools` or a call whose tool the grant declares safe to repeat: `looper_room_roster`, `looper_room_read`, `looper_vault_search`, `looper_vault_read`, and `looper_room_inbox` only with `peek=true`. Timeouts never retry, and writes (`looper_room_post`, `looper_vault_write` and the rest) are never repeated once sent. A retried inbox wait is capped at the reconnect time left minus 2 s.
- **Agent API.** For kept runs' tokens, `GET /api/agent/v1/tools` adds a `retry_safety` map (`looper/agents/http_server.py`, `looper/agents/ops/room.py`). It is kept in separate maps, not in the `Tool` declaration, so the previous release's upgrade probe can still read the declarations. Manager and Planner tokens and runs that are not kept get no map and no reconnect variable. The Pi extension is not changed.
- **Room presence.** A kept run that ends through the candidate path or fails adoption after a restart now revokes its token and also announces that it left its task's room, as an ordinary run end already did (`WorkerPool._end_room_run`).
- **Housekeeping.** `docs/architecture/agent-system.md` describes the flow.
- **Size:** per the pull request description, 126 added lines of production code and 526 of tests (fixtures excluded).
- **Model-visible changes:** Yes, in tool results of kept runs only. When a `looper_room_inbox` call without `peek=true` loses its response with reconnect enabled, the error result now says that messages may have been marked read, and tells the agent to call `looper_room_inbox` with `peek=true` and `looper_room_read`. Timeout and other unavailable errors keep their text. The `retry_safety` field is read by the bridge, not shown to the model. No prompt or tool description changed.

## 中文摘要

本版本是 patch release v2.14.70（热修线，每个合并的改动立即发布）。自 v2.14.69 以来只合并了一项改动：保留运行的 Agent API 桥接现在会重连，并重试可安全重复的调用（[#1062](https://github.com/foolzzz/looper/pull/1062)）。

### 升级决策

**谁需要升级：**开启 keeper、且保留运行在控制面重启期间调用 Looper 房间或 vault 工具的安装。其他安装没有变化。

**解决了什么：**保留运行能熬过重启，但其 `looper mcp-server` 桥接在控制面短暂不可达时会立即让工具调用失败。[#1062](https://github.com/foolzzz/looper/pull/1062) 让保留运行的桥接最多重试 120 秒，并且不会重复可能已执行的写操作。

**是否有破坏性变更：**否。唯一的 API 变化是保留运行令牌的工具列表新增 `retry_safety` 字段，没有迁移。

**如何验证：**运行 `looper --version` 核对版本为 2.14.70。

**贡献者：**维护者 @foolzzz 提交 [#1062](https://github.com/foolzzz/looper/pull/1062)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.70
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.69 上的安装可直接升级。本版本没有迁移。升级前已保留的运行，其 MCP 条目不带重连变量，行为不变；重试只对本版本启动的运行生效。

### 行为变化与入口

- **重连窗口。**保留运行的 MCP 条目设置 `LOOPER_AGENT_RECONNECT_SECONDS=120`（`looper/agents/ops/service.py`、`looper/agents/tiers/worker.py`）。`looper mcp-server`（`looper/agents/mcp_server.py`）将其读为非负数，上限 600；无效值使其报错退出。窗口从第一次失败起算。退避从 0.5 秒起翻倍至 5 秒；`Retry-After` 被限制在该范围内。每个被重试的调用向 stderr 输出一行 `agent api retry` 摘要。变量未设置或为空时，请求仍只尝试一次。
- **重试范围。**连接被拒绝和带整数 `Retry-After` 的 HTTP 503 总会重试，因为两者都没有执行调用。其他连接失败只重试 `GET /tools`，或授权声明可安全重复的工具：`looper_room_roster`、`looper_room_read`、`looper_vault_search`、`looper_vault_read`，以及仅在 `peek=true` 时的 `looper_room_inbox`。超时从不重试，写操作（`looper_room_post`、`looper_vault_write` 等）一旦发出就不会重复。重试的收件箱等待上限为剩余重连时间减 2 秒。
- **Agent API。**对保留运行的令牌，`GET /api/agent/v1/tools` 新增 `retry_safety` 映射（`looper/agents/http_server.py`、`looper/agents/ops/room.py`）。它放在独立的映射里而不是 `Tool` 声明中，使上一版本的升级探针仍能读取声明。Manager 和 Planner 令牌以及非保留运行没有该映射，也没有重连变量。Pi 扩展未改动。
- **房间在线状态。**保留运行经候选路径结束，或重启后接管失败时，现在除撤销令牌外，还会像普通运行结束一样宣告已离开其任务的房间（`WorkerPool._end_room_run`）。
- **其他。**`docs/architecture/agent-system.md` 描述了该流程。
- **规模：**据 PR 描述，生产代码新增 126 行，测试新增 526 行（不含 fixture）。
- **面向模型的变化：**有，仅限保留运行的工具结果。启用重连时，不带 `peek=true` 的 `looper_room_inbox` 调用丢失响应，错误结果现在会说明消息可能已被标记为已读，并提示用 `peek=true` 调用 `looper_room_inbox` 和 `looper_room_read`。超时和其他不可用错误的文字不变。`retry_safety` 字段由桥接读取，不展示给模型。没有提示或工具说明变化。
