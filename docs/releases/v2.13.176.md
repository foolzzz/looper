# Looper v2.13.176

## Release Decision

**Who should upgrade:** Operators who create tasks from Manager templates that list role templates, and operators who import configuration files that contain schedules. It is a hotfix that ships the change merged since v2.13.175.

**What this release solves:** [#779](https://github.com/foolzzz/looper/pull/779) restores the fallback for an interactive task created from a template whose role templates name an Agent Profile or items that are no longer usable, while a schedule still refuses them. It also makes configuration import preview and apply reject a schedule whose role or profile dependencies it could not run.

**Breaking changes:** No. No command, API route, configuration format or schema changed. An import that used to accept a schedule with unusable dependencies can now skip it with a reason.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#779](https://github.com/foolzzz/looper/pull/779); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.176
```

## Behavior changes

- **Interactive fallback ([#779](https://github.com/foolzzz/looper/pull/779)):** `template_roles` in `looper/agents/task_template_execution.py` takes `interactive` and `fallbacks`, and the role checks moved into the new `validate_role_dependencies`. When a task is created from a template through `looper_task_create` (`looper/agents/ops/tasks.py`), a role template whose Agent Profile is off the project's list or fails the capability check is used without a profile, so the built-in profile for its kind applies. Items that are no longer installed for Planner-defined roles are dropped from the role. A missing role template, a duplicated key, Planner-defined roles switched off and a malformed definition still fail.
- **Scheduled execution stays strict ([#779](https://github.com/foolzzz/looper/pull/779)):** without `interactive`, every one of those conditions still raises `TemplateError`, so a schedule is not run with a substituted role.
- **Import validation ([#779](https://github.com/foolzzz/looper/pull/779)):** `looper/agents/config_transfer.py` checks each imported schedule with the new `_schedule_dependencies` against the import's final graph, including projects and profiles that exist only in the file and so are not yet saved in a preview. It checks the fixed profiles, the project's profile list, the profiles' runtime and roles, and the role templates and installed items. A schedule that fails is skipped with the reason.
- **Import order ([#779](https://github.com/foolzzz/looper/pull/779)):** `import_config` now processes installs before schedules, in preview as well as apply, instead of after them. The project, install and role-template values are kept in memory for the checks.
- **Model-visible changes:** when a fallback is used, the configuration block that `looper_task_create` returns to the Manager turn gains a line `- 模板角色回退：` that lists each fallback, clipped to 1000 characters. The task's stored roles are the fallback roles. No prompt text, tool description or tool schema changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.176 is published. There is no schema change, so rolling back to v2.13.175 needs nothing else.

## 中文摘要

### 升级决策

**谁需要升级：**用 Manager 模板（含角色模板）创建任务的运维人员，以及导入含 schedule 的配置文件的运维人员。本版本是随合并即发布的 hotfix。

**解决了什么：**[#779](https://github.com/foolzzz/looper/pull/779) 恢复交互式创建任务时的回退：模板的角色模板所指的 Agent Profile 或条目不可用时回退，而 schedule 仍然拒绝。同时配置导入的预览和应用会拒绝依赖无法运行的 schedule。

**是否有破坏性变更：**无。命令、API 路由、配置格式和 schema 均未改变。此前被接受的含不可用依赖的 schedule，导入时现在可能被跳过并给出原因。

**如何验证：**运行 `looper --version` 核对版本为 2.13.176。

**贡献者：**维护者 @foolzzz 提交 [#779](https://github.com/foolzzz/looper/pull/779)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.176
```

### 行为变化与入口

- **交互式回退（#779）：**`task_template_execution.py` 的 `template_roles` 新增 `interactive` 与 `fallbacks`，角色检查移入新的 `validate_role_dependencies`。通过 `looper_task_create` 从模板创建任务时，角色模板的 Agent Profile 不在项目列表中或未通过能力检查，则不带 profile 使用（采用对应类型的内置 profile）；不再安装的条目从角色中移除。角色模板缺失、key 重复、Planner 自定义角色关闭、定义格式错误仍然失败。
- **定时执行保持严格（#779）：**未设置 `interactive` 时，上述情形仍抛出 `TemplateError`，schedule 不会用替代角色运行。
- **导入校验（#779）：**`config_transfer.py` 用新的 `_schedule_dependencies` 对导入的最终图校验每个 schedule，包括只存在于文件中、预览时尚未保存的项目与 profile；检查固定 profile、项目 profile 列表、profile 的运行时与角色、角色模板与已安装条目。不通过的 schedule 被跳过并给出原因。
- **导入顺序（#779）：**`import_config` 现在先处理 installs 再处理 schedules（预览与应用一致），此前在其后。项目、install 与角色模板的值保存在内存中供检查使用。
- **面向模型的变化：**使用回退时，`looper_task_create` 返回给 Manager 回合的配置块新增一行 `- 模板角色回退：`，列出各项回退（截断到 1000 字符）；任务保存的角色为回退后的角色。没有 prompt 文本、工具描述或工具 schema 改动。
