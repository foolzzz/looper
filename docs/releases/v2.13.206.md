# Looper v2.13.206

## Release Decision

**Who should upgrade:** Operators who run the opt-in Pi runner. Whether a request counted as sent was inferred from connection error codes, and usage from a stream that dropped could be trusted. It ships the change merged since v2.13.205.

**What this release solves:** [#851](https://github.com/foolzzz/looper/pull/851) (fixing #846) makes the Pi runner decide whether a request was sent from the HTTP client's own event, reports every unsent failure as zero usage and complete, and trusts usage only from a validated terminal event, so a stream that drops after a non-terminal usage object is reported incomplete.

**Breaking changes:** No. Commands, settings, the database schema and the admitted upgrade path are unchanged.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#851](https://github.com/foolzzz/looper/pull/851); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.206
```

## Behavior changes

- **Sent or not (`runners/pi/src/provider.ts`):** the set of pre-request error codes (`ECONNREFUSED`, `ENOTFOUND`, certificate errors and others) is removed. The module subscribes once to Node's `undici:client:sendHeaders` diagnostics event. The runner's `fetch` adds an `x-looper-request-id` header carrying the admitted request id, and the event marks that request as sent when the raw headers contain it. A request never marked sent ends as complete with no usage, whatever the error. The runner's own abort before dispatch is unchanged.
- **Provider-visible request header:** every request the Pi runner makes now carries `x-looper-request-id: <request id>`. It is an identifier generated by the runner and holds no prompt, credential or path. Providers and proxies that log headers will see it.
- **Usage trusted only from a terminal event:** for Responses, only `response.completed` supplies usage; `response.incomplete` and `response.failed` no longer do. For Chat, usage is taken from the chunk whose choices all carry a `finish_reason`, or from the empty-choices usage chunk that follows it. A Chat stream is complete only if `[DONE]` was seen; the runner passes the response through a pass-through transform that watches the SSE data lines, and also treats a clean end of stream as terminating the last event. Bytes are forwarded unchanged.
- **Completeness of sent requests:** a sent request is complete only when the stream ended with `done`, was not aborted, usage was validated, and (for Chat) `[DONE]` was observed. Previously a request that received an HTTP error status (400 or above) before any stream event, or an error with an unsent connection failure, could be reported complete; now a sent request that fails is incomplete, which with a run or task cap makes the turn `budget_unverifiable`.
- **Tests:** `tests/test_pi_runner_turns.py` gains cases for unsent failures, interim usage, dropped streams and SSE edge cases; `tests/fake_model_api.py`, `tests/pi_runner_support.py` and `tests/test_pi_runner_tools.py` are adjusted for the fixtures.
- **Model-visible changes:** None. No prompt, tool or message text changed; the model sees the same request bodies. Only an HTTP header is added.

## Upgrade and rollback

Re-run `install.sh` once v2.13.206 is published. No data or schema change is involved, so a rollback to v2.13.205 needs no database restore.

### 升级决策

**谁需要升级：**使用可选 Pi runner 的运维者。此前请求是否已发送由连接错误码推断，且中途断开的流的用量可能被采信。包含 v2.13.205 之后合并的改动。

**解决了什么：**[#851](https://github.com/foolzzz/looper/pull/851)（修复 #846）让 Pi runner 依据 HTTP 客户端自身事件判断请求是否已发送，把所有未发送的失败按零用量且完成上报，并且只采信经过校验的终止事件中的用量，因此在非终止用量对象之后断开的流会被报告为未完成。

**是否有破坏性变更：**否。命令、设置、数据库 schema 和允许的升级路径均不变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.206。

**贡献者：**维护者 @foolzzz 提交 [#851](https://github.com/foolzzz/looper/pull/851)；本次 patch release 无社区贡献。

### 行为变化与入口

- **是否已发送（`runners/pi/src/provider.ts`）：**移除预请求错误码集合（`ECONNREFUSED`、`ENOTFOUND`、证书错误等）。模块一次性订阅 Node 的 `undici:client:sendHeaders` 诊断事件。runner 的 `fetch` 添加携带已放行请求 id 的 `x-looper-request-id` 头，原始头中含该 id 时事件将该请求标记为已发送。从未标记为已发送的请求，无论何种错误，都以完成且无用量结束。runner 在派发前自身的中止行为不变。
- **对 provider 可见的请求头：**Pi runner 发出的每个请求现在都带 `x-looper-request-id: <请求 id>`。这是 runner 生成的标识，不含提示词、凭据或路径。记录请求头的 provider 或代理会看到它。
- **只采信终止事件的用量：**Responses 只有 `response.completed` 提供用量，`response.incomplete` 和 `response.failed` 不再提供。Chat 的用量取自所有 choice 都带 `finish_reason` 的分块，或其后 choices 为空的用量分块。Chat 流只有在见到 `[DONE]` 时才算完成；runner 让响应经过一个透传转换来观察 SSE data 行，并把干净的流结束视为最后一个事件的终止。字节原样转发。
- **已发送请求的完成判定：**已发送的请求只有在流以 `done` 结束、未中止、用量通过校验且（Chat）观察到 `[DONE]` 时才算完成。此前在任何流事件之前收到 HTTP 错误状态（400 及以上）的请求，或未发送的连接失败，可能被报告为完成；现在已发送但失败的请求为未完成，设置了运行或任务上限时会使该回合 `budget_unverifiable`。
- **测试：**`tests/test_pi_runner_turns.py` 新增未发送失败、中间用量、断流和 SSE 边界用例；`tests/fake_model_api.py`、`tests/pi_runner_support.py`、`tests/test_pi_runner_tools.py` 调整了夹具。
- **面向模型的变化：**无。提示词、工具和消息文本均未改变，模型看到的请求体相同，仅增加一个 HTTP 头。
