# Looper v2.14.94

This is the patch release v2.14.94, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.93: adding a Custom provider in the dashboard is described by API format and one base URL, and a new model's price defaults to 0 ([#1115](https://github.com/foolzzz/looper/pull/1115)).

## Release Decision

**Who should upgrade:** Operators who add Custom providers (an Anthropic- or OpenAI-compatible gateway) or models through the dashboard. Everyone else can stay.

**What this release solves:** Adding a Custom provider asked for three raw protocol checkboxes and URLs, and Add model left an unknown price empty with a "no full price" warning. [#1115](https://github.com/foolzzz/looper/pull/1115) asks for an API format and one base URL, and an empty model price becomes the built-in price when Looper knows the model, otherwise 0 (counted as free).

**Breaking changes:** No. No schema change and no API change.

**How to verify:** Check the installed version. In the dashboard, add a Custom provider: the form shows "API format" and "Base URL". Add a model without prices: its row shows "0 (free)" for an unknown model.

**Contributors:** Maintainer @foolzzz authored [#1115](https://github.com/foolzzz/looper/pull/1115); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.94
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.93 upgrades directly. There is no database change.

## Behavior changes

- **Custom provider form** (`web/src/components/provider-settings.tsx`). Adding a Custom provider asks for an API format (Anthropic or OpenAI, from the registry's `limits.api_formats`) and a base URL. Anthropic saves an `anthropic-messages` endpoint; OpenAI saves `openai-responses` and `openai-chat` at that URL, or only one when "OpenAI APIs it serves" says Chat Completions only or Responses only. Only this form drops a trailing `/v1` from an Anthropic base URL, and it says so under the field. "Set a URL per protocol instead" opens the per-protocol editor, and "Describe it by API format instead" returns when all URLs agree. Editing a provider keeps the per-protocol editor; the server stores URLs as entered.
- **Add model** (`web/src/components/model-settings.tsx`, `web/src/lib/api.ts`). Creating a model calls `models.add_many`; a price left empty becomes the built-in price when Looper knows the model, otherwise 0 (counted as free, no "no full price" warning). A typed price, including 0, is kept. Adding a model that already exists on the provider shows an error. Editing a model is unchanged (empty clears the override). Model rows show a zero price as "0 (free)", and the protocol choice shows its label.
- **Saved provider shown at once** (`web/src/lib/api.ts`, `web/src/lib/use-registry.ts`). After a provider update, the registry cache uses the saved account while the full refresh is pending, so a reopened editor shows the saved values.
- **Provider model listing** (`looper/agents/model_listing.py`). A listing is marked truncated when the endpoint reports more pages but gives no next cursor; an HTTP or invalid-URL error is reported as a bad response; and a failure on one endpoint no longer fails the others (logged by type only, no response text).
- **Unchanged:** the API, `models.create`, the Manager tools, config transfer, the CLI, channels, the schema.
- **Documentation and tests.** Updated `tests/test_model_listing.py`, `tests/test_provider_model_listing_db.py`, `tests/test_llm_models_dashboard.py`, `tests/test_config_transfer_db.py`, `tests/test_llm_provider_writes_db.py`, `tests/test_manager_config_tools_db.py`, `web/src/components/provider-settings.test.tsx`, `web/src/components/model-settings.test.tsx` and other fixtures.
- **Model-visible changes:** None. No tool description, prompt text or tool output changes; the changes are dashboard text, the model-listing result and one log line.

## 中文摘要

本版本是 patch release v2.14.94（热修线，每个合并的改动立即发布）。自 v2.14.93 以来只合并了一项改动：仪表盘添加 Custom provider 时按 API 格式和一个 base URL 描述，新模型的价格默认为 0（[#1115](https://github.com/foolzzz/looper/pull/1115)）。

### 升级决策

**谁需要升级：**通过仪表盘添加 Custom provider（兼容 Anthropic 或 OpenAI 的网关）或模型的运维人员。其他人可不升级。

**解决了什么：**添加 Custom provider 原先要填三个协议复选框和 URL，添加模型时未知价格留空会出现“无完整价格”警告。[#1115](https://github.com/foolzzz/looper/pull/1115) 改为询问 API 格式和一个 base URL；模型价格留空时，Looper 认识该模型则用内置价格，否则为 0（按免费计）。

**是否有破坏性变更：**否。无结构变更，无 API 变更。

**如何验证：**核对版本为 2.14.94。在仪表盘添加 Custom provider：表单显示 “API format” 和 “Base URL”。不填价格添加模型：未知模型的价格显示 “0 (free)”。

**贡献者：**维护者 @foolzzz 提交 [#1115](https://github.com/foolzzz/looper/pull/1115)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.94
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.93 上的安装可直接升级。无数据库变更。

### 行为变化与入口

- **Custom provider 表单**（`web/src/components/provider-settings.tsx`）。添加 Custom provider 时询问 API 格式（Anthropic 或 OpenAI，来自注册表 `limits.api_formats`）和 base URL。Anthropic 保存一个 `anthropic-messages` 端点；OpenAI 在该 URL 保存 `openai-responses` 和 `openai-chat`，若在 “OpenAI APIs it serves” 选择仅 Chat Completions 或仅 Responses，则只保存其一。只有此表单会去掉 Anthropic base URL 末尾的 `/v1`，并在字段下说明。“Set a URL per protocol instead” 打开按协议编辑器，所有 URL 一致时可用 “Describe it by API format instead” 返回。编辑 provider 仍用按协议编辑器；服务器按输入原样存储 URL。
- **添加模型**（`web/src/components/model-settings.tsx`、`web/src/lib/api.ts`）。创建模型改走 `models.add_many`；价格留空时，Looper 认识该模型则用内置价格，否则为 0（按免费计，无“无完整价格”警告）。填写的价格（含 0）保留。添加该 provider 上已存在的模型会显示错误。编辑模型不变（留空清除覆盖）。模型行把零价格显示为 “0 (free)”，协议选项显示其标签。
- **保存的 provider 立即可见**（`web/src/lib/api.ts`、`web/src/lib/use-registry.ts`）。更新 provider 后，注册表缓存在完整刷新完成前先使用已保存的账户，重新打开的编辑器显示已保存的值。
- **Provider 模型列表**（`looper/agents/model_listing.py`）。端点报告还有更多页但未给出下一游标时，列表标记为已截断；HTTP 或无效 URL 错误报告为 bad response；一个端点失败不再使其他端点失败（只按类型记录日志，不含响应文本）。
- **不变：**API、`models.create`、Manager 工具、配置传输、CLI、渠道、数据库结构。
- **文档与测试。**更新 `tests/test_model_listing.py`、`tests/test_provider_model_listing_db.py`、`tests/test_llm_models_dashboard.py`、`tests/test_config_transfer_db.py`、`tests/test_llm_provider_writes_db.py`、`tests/test_manager_config_tools_db.py`、`web/src/components/provider-settings.test.tsx`、`web/src/components/model-settings.test.tsx` 及其他夹具。
- **面向模型的变化：**无。工具描述、提示文本和工具输出均不变；变化只在仪表盘文本、模型列表结果和一行日志。
