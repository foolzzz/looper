# Looper v2.15.7

This is the patch release v2.15.7, a hotfix line in which each merged change ships at once. It documents one change: [#1382](https://github.com/foolzzz/looper/pull/1382) (stabilizing the recurring CI flakes). The change is in the tests only.

## Release Decision

**Who should upgrade:** No one needs this release for its behavior. It is the version that carries the stabilized tests; an installation on v2.15.6 runs the same code.

**What this release solves:** [#1382](https://github.com/foolzzz/looper/pull/1382) makes the recurring flaky CI tests deterministic (Planner waits and extensions, the process-tree stand-in, the Cursor exit-before-prompt fallback matrix, the Pi platform fixture and the DSH runner stop check) without weakening their deadline, cancellation, confirmation, exit-diagnostic and Profile fallback assertions.

**Breaking changes:** No. The CLI, the API and the dashboard are unchanged, no new command or control is added and there is no PostgreSQL schema change. The PR changes no file in the `looper` package, so there is no behavior change. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.7
```

**Contributors:** Maintainer @foolzzz authored [#1382](https://github.com/foolzzz/looper/pull/1382); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.6 upgrades directly. There is no PostgreSQL schema change. Restart the service after upgrading, as for every release.

## Behavior changes

Read in the diff of the PR.

### #1382: Stabilize the recurring CI flakes

- **Test-only.** The diff against v2.15.6 touches `tests/test_dsh_runner_serve_db.py`, `tests/test_pi_platform_tools.py`, `tests/test_planner_waits.py`, `tests/test_proc_tree.py` and `tests/test_worker_profile_fallback.py`, and nothing under `looper/`. The PR text mentions two production lines; they are the Cursor stdin guard that #1379 already shipped in v2.15.6, so they are not new here.
- **Tests.** Planner timeout and extension tests wait for complete startup and use a frozen clock; the process-tree stand-in keeps its identity lookups consistent; the exit-before-prompt matrix covers Cursor and Codex, both launchers, exit 0 and 1, with and without a model event, and checks the recorded diagnostic and the fallback policy; the Pi fixture completes its database boundary; the DSH helper keeps waiting for the exact stopped PID when argv is gone, and still rejects other executables.
- **Behavior change.** None in the shipped package.

### Model-visible changes

None. Prompts, prompt contracts, the consult contract and tool schemas are unchanged.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## Validation

**Reported by [#1382](https://github.com/foolzzz/looper/pull/1382):** targeted repeated runs of the affected tests (20 repetitions per branch). The final repeated selection passed 1,020/1,020 instances with zero skips, including 20 real-service DSH stop/restart runs, and a companion selection passed 135/135. Ruff and `git diff --check` passed. The PR reports no full-suite run and no stress run. It states that four other `tests/test_proc_tree.py` tests still fail intermittently under heavy local load, on main as well, and are not addressed. It also states that the Linux `ps` transition was replayed from its observed shape, and that Cursor was tested with stand-in executables and no authenticated model CLI.

**CI:** CI runs after the release is drafted; its result is not recorded here.

**Not tested for this draft:** a local full suite, a Linux run of the DSH case and the built wheel. The release documentation gate checks the body only.
