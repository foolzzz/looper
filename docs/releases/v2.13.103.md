# Looper v2.13.103

## Release Decision

**Who should upgrade:** Anyone who runs the generated `looper config import-*` subcommands (`import-upload`, `import-preview`, `import-apply`, `import-cancel`) from the command line.

**What this release solves:** [#583](https://github.com/foolzzz/looper/pull/583) makes `looper config` generated subcommands load the service's OpenAPI document. Before, `config` was registered as a hand-written command, so the command line never fetched the document for it and the generated children were not found.

**Breaking changes:** No. The hand-written `config export` and `config import` keep their parsers and requests; the generated commands are only newly reachable from the main entry point.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#583](https://github.com/foolzzz/looper/pull/583); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.103
```

## Behavior changes

- **Generated `config` subcommands are discovered ([#583](https://github.com/foolzzz/looper/pull/583)):** in `looper/loopercli.py`, a new `_needs_document` decides whether the command line fetches `/api/v1/openapi.json` before parsing. For a command that is not hand-written it still does. For a hand-written command, it now also does when the first argument after the command name is a word (not starting with `-`) that is not one of the command's registered hand-written children, such as `config import-cancel`. A hand-written command with a registered child, with only flags, or with no further argument is parsed as before. The generated subcommands then send the same operation requests with the `x-looper-session` header and the arguments as the JSON body.
- **Unchanged:** `config export`, `config import` (file or `-`) and `config import --cancel` keep their hand-written parsers and request bodies. A usage error, such as a missing flag value, an unknown flag or a stray positional, exits with code 2 and prints usage; it sends no operation request, and the error output does not echo the argument, so a token-shaped value is not leaked. An unreachable API still exits with code 4 and a hint to check that `looper serve` is running.
- **Model-visible changes:** None. No tool declaration, API schema, prompt or response text changed; the change is in the command-line client only.
- **Tests:** [#583](https://github.com/foolzzz/looper/pull/583) adds cases in `tests/test_loopercli.py` for the four generated children (OpenAPI fetch then the operation, body and session header), for the hand-written commands keeping their parsers, for usage errors that send no operation and do not leak a token, and for exit code 4 with an unreachable API. In `tests/test_api_v1_configuration_ui.py` it adds `import-apply` and `import-preview` to the raw-JSON cases and an end-to-end case that uploads then cancels an import over HTTP through the main entry point. The pull request reports 93 added test lines and 11 production lines.

## Upgrade and rollback

Re-run `install.sh` once v2.13.103 is published. No data migration and no configuration change. Rolling back to v2.13.102 makes the generated `config import-*` subcommands unreachable from the command line again.

## 中文摘要

### 升级决策

**谁需要升级：**在命令行使用生成的 `looper config import-*` 子命令（`import-upload`、`import-preview`、`import-apply`、`import-cancel`）的使用者。

**解决了什么：**[#583](https://github.com/foolzzz/looper/pull/583) 让 `looper config` 的生成子命令 加载服务的 OpenAPI 文档。此前 `config` 注册为手写命令，命令行不会为它获取文档，生成的子命令因此找不到。

**是否有破坏性变更：**否。手写的 `config export` 与 `config import` 保持原有解析器和请求；生成的命令只是现在可从主入口访问。

**如何验证：**运行 `looper --version` 核对版本为 2.13.103。

**贡献者：**维护者 @foolzzz 提交 [#583](https://github.com/foolzzz/looper/pull/583)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.103
```

### 行为变化与入口

- **发现生成的 `config` 子命令（[#583](https://github.com/foolzzz/looper/pull/583)）：**`looper/loopercli.py` 新增 `_needs_document`，决定解析前是否获取 `/api/v1/openapi.json`。非手写命令仍然获取；对手写命令，当命令名后的第一个参数是不以 `-` 开头、且不是该命令已注册手写子命令的词（如 `config import-cancel`）时，现在也会获取。带已注册子命令、仅带选项或没有后续参数的手写命令仍按原样解析。生成的子命令随后发送同样的操作请求，带 `x-looper-session` 头，参数作为 JSON 请求体。
- **不变：**`config export`、`config import`（文件或 `-`）和 `config import --cancel` 保持手写解析器和请求体。用法错误（缺少选项值、未知选项、多余位置参数）以退出码 2 退出并打印用法，不发送任何操作请求，错误输出也不回显该参数，因此形似令牌的值不会泄露。API 不可达仍以退出码 4 退出，并提示检查 `looper serve` 是否在运行。
- **面向模型的变化：**无。没有 tool 声明、API schema、提示词或响应文本改变；变化仅在命令行客户端。
- **测试：**[#583](https://github.com/foolzzz/looper/pull/583) 在 `tests/test_loopercli.py` 新增用例，覆盖四个生成子命令（先取 OpenAPI 再发操作、请求体与会话头）、手写命令保持解析器、用法错误不发操作也不泄露令牌、API 不可达时退出码 4。在 `tests/test_api_v1_configuration_ui.py` 中把 `import-apply` 和 `import-preview` 加入原始 JSON 用例，并新增一个通过主入口经 HTTP 上传再取消导入的端到端用例。该 PR 报告新增测试 93 行、生产代码 11 行。
