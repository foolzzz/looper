# Looper v2.15.39

Cut from main at `6aa7f3474`. This release contains all of v2.15.38 and the 23 pull requests listed below: every first-parent merge in `4ad331978..6aa7f3474`, except the release pull requests #1784 and #1786 and the already-shipped #1785. The release preparation adds only version, changelog and release files. Main has moved after the freeze: after this pull request merges, the tag belongs on this release pull request's own head, not the main merge commit, as described in [the release procedure](README.md).

No optional feature turns itself on. Work is now activatable, but remains off by default; its task conversation still talks to the Planner, not a task Manager. Independently of switches, startup applies two migrations and one online validation step, proactive send text begins to be retained, and HTTP, shutdown and diagnostic handling change. The release workflow rebuilds the dashboard from source; this pull request commits no generated bundle.

## Release Decision

**Who should upgrade:** Operators who want to inspect proactive sends, use the optional Work console, install the dashboard as a browser app, or receive fixes for HTTP client races, shutdown hangs, drain handover, static-file containment and acknowledgement timing.

**What this release solves:** Work's previously hidden shell can now be enabled and gains task context panels and conversation state. Proactive send history becomes inspectable by the operator. HTTP responses advertise their existing close behavior, shutdown closes active connections before waiting, static paths are confined to the dashboard directory, and diagnostics redact credential-like text before returning it.

**Breaking changes:** Yes. Proactive bodies and delivery rows are now recorded regardless of the metrics switch, with no separate capture switch; static links resolving outside the dashboard directory now return 404, and diagnostic text may be redacted. Startup changes the schema even with Work off. Existing settings are not enabled by the upgrade. See Behavior changes and the inherited upgrade requirements below. Installations older than the bridge must upgrade to v2.13.165 first and start once.

**How to verify:** Check the version, read back `task_conversations.get` as the operator and confirm Work stays hidden while disabled. After a normal proactive send, inspect `proactive_sends.list` for its bounded text and receipt even with metrics off. Check that the manifest is reachable without sign-in while the dashboard itself still requires configured operator sign-in. These are post-upgrade checks, not claims that this release preparation ran a service.

```bash
looper --version   # looper 2.15.39
```

## Upgrading from v2.15.37 or earlier

This release contains all of v2.15.38, including its missing-Work-operation polling fix. Read [the v2.15.38 notes](v2.15.38.md) and, when coming from v2.15.36 or earlier, [v2.15.37's upgrade notes](v2.15.37.md#upgrading) for inherited migrations, backup requirements and breaking changes. Unlike v2.15.38's server, this server registers `task_conversations.get`: its disabled response keeps the sidebar's normal polling active, but Work stays hidden until enabled.

From a database that has completed v2.15.37 or v2.15.38, startup adds these two migrations even with all optional features off, using the existing pre-migration backup path:

| Order | Migration | What changes |
| --- | --- | --- |
| 2050 | `task_drafts` | Adds `tasks_draft_shape` on the existing `tasks` table: a draft has neither `schedule_id` nor `completed_at`. Adds the check as `NOT VALID`, then `task_drafts_online` validates it after the schema transaction; validation scans existing tasks. No table is created. |
| 2110 | `proactive_bodies` | Adds nullable `body TEXT`, `body_truncated BOOLEAN NOT NULL DEFAULT false` and nullable `body_stored_at TIMESTAMPTZ` to the existing `proactive_deliveries` table. No online step and no historical body backfill. |

Keep the pre-migration backup for downgrade; this release supplies no down migration. Turning Work off leaves schema and draft rows in place and does not disable proactive retention. Installations older than v2.13.165 must upgrade to v2.13.165 first and start once.

## Behavior changes

### Without a new switch

- **Startup:** Both migrations and the task constraint's online validation above run independently of Work or metrics. Neither migration enables a feature setting.
- **Proactive storage:** Typed proactive sends, including registry posts, bus notices/completion replies, morning briefs and reminders, save their rendered channel input before sending. This runs whether metrics is on or off and has no separate switch. UTF-8 text is bounded to 32 KiB without splitting a character; truncation is marked and sent text is unchanged. The existing hourly housekeeping pass clears bodies after 14 days and purges rows after 90 days. Historical bodies stay null. Storage is best effort with a one-second timeout before transport: failures warn and sending continues, but a slow database can add up to that wait. Retries reuse the delivery identity and latest attempted body; older receipts cannot overwrite a newer sent receipt. A missing receipt is not proof of a failed send. No retained body is injected into agent context.
- **Public dashboard assets:** `/manifest.webmanifest`, `/icon-192.png`, `/icon-512.png` and `/icon-maskable-512.png` are available without sign-in, with public one-hour caching. They contain app metadata and icons, not operator data. The sign-in page links the manifest; its CSP now permits `manifest-src 'self'` and `img-src 'self'`. Dashboard HTML still follows configured operator sign-in. The manifest uses `application/manifest+json`.
- **Static containment:** A static file or symlink resolving outside the dashboard root now returns 404, including a sibling directory whose name merely shares the root's prefix. Installations relying on such outward links must move the assets inside the root.
- **HTTP close signaling:** Responses explicitly advertise `Connection: close`. This states the existing one-request-per-connection policy and fixes a client race; it does not introduce additional connection churn.
- **Diagnostic redaction:** Attention `detail` and `fix` values and relevant self-check diagnostics redact credential-like text on the server without a new switch. The existing Needs you page and Work summary also use shared display redaction. Long opaque diagnostic strings may consequently appear as `[redacted]`; attention visibility still follows its existing switch.
- **Shutdown and handover:** Keeper and recording-proxy connections close before their listening servers are awaited. HTTP handlers get a one-second grace period, then remaining transports are aborted and handlers cancelled with a further one-second cleanup budget. Worker dispatch waits out drain; kept-run detach waits for initial input readiness. These change shutdown/drain windows, not ordinary serving admission.
- **Restart and backup edges:** Restart eligibility, cleanup and claiming share a row-locked transaction to avoid lifecycle races. Custom backup/verification commands tolerate absent source labels; the default dump path is unchanged.
- **API inventory:** The catalog gains `tasks.create_draft`, `task_conversations.get/update`, `tasks.done` and `proactive_sends.list`. These are operator-only operations, not Manager tools. `tasks.create_draft` and `tasks.done` return a conflict while Work is off; the proactive read is independent of that switch.

### When an existing switch is already on

With `manager.metrics.enabled` on, `ack_ms` now measures from receipt (`ack_received_at` when available, otherwise turn receipt) to the actual acknowledgement timestamp and never goes below zero. This corrects historical negative samples from channel acknowledgement preceding Manager-envelope construction; new and historical timing series therefore differ in meaning. With metrics off, turn metrics stay off, but proactive receipts and bodies are still recorded. With attention on, the existing Needs you page gains the display redaction described above; Work's additional summary requires both Work and attention. Existing morning-brief, reminder and delivery-policy switches keep their settings; retaining their typed proactive output does not enable those features.

## Entry points

- **Dashboard:** Work is now an optional visible entry with Planner/default-Manager conversations, requirement editing and task context panels; browser installation and shared Needs you redaction also affect the existing dashboard.
- **Telegram and Lark:** Proactive text/receipt recording and drain/shutdown fixes apply to their existing paths; Lark acknowledgement timing uses its actual ingress baseline. No new channel command is needed because Work and history controls are operator-only API/dashboard concerns.
- **CLI/API:** The generated operator client discovers the five new operations above. Scoped routing, task Manager chat and network pause are not made available by this release.

## Optional Capability Activation & Use

The API examples use the reserved example origin; replace it with your installation and an authenticated operator cookie file. They are reads, not automatic activation. Existing optional capabilities not changed here retain [v2.15.37's instructions](v2.15.37.md#optional-capability-activation--use).

### Work console

**Activation:** Off by default. The operator reads `task_conversations.get` and sets `{"enabled":true}` through `task_conversations.update`, completing the returned confirmation through `POST /api/v1/confirm`. The stored key is `tasks.conversations.enabled`; null restores off. Enabled readback exposes Work in the sidebar and allows the `#/work` route. The enabling control is an operator API operation, not a new Settings form.

**Validation:** Read back enabled, open Work and select a task. Check its Planner conversation, default-Manager column, editable requirement, plan, files, gates and costs. New task creates a draft in an existing project, but its Planner conversation cannot send before starting; this page has no writable draft-conversation composer or lifecycle buttons. `tasks.done` is an API operation. The task model selector is unsupported on this frozen page, and no task-bound Manager conversation is available.

**Disable / rollback:** Update enabled to false or null and confirm. Work hides and its URL returns to Dashboard. Tasks and schema remain; disabling is not database downgrade and does not disable proactive storage.

**Authority boundary:** The setting and draft/direct-completion operations are operator-only; API clients cannot enable them. Draft creation starts no agent. `tasks.done` rejects tasks owned by active background work and is idempotent for a completed task. For a worktree task, finishing commits uncommitted work on its branch before removing the worktree; a finish failure is returned as a warning. It does not merge the task branch or run the task-end listener. Existing Planner send eligibility and gate permissions remain authoritative. Work adds no task Manager runtime or scoped-chat authority.

**Docs:** https://github.com/foolzzz/looper/blob/v2.15.39/docs/architecture/agent-system.md

```bash
curl --fail --cookie operator-cookies.txt --json '{}' https://looper.example/api/v1/task_conversations/get
```

### Proactive send history

**Activation:** Explicit operator read through `POST /api/v1/proactive_sends/list`; there is no capture activation step or separate capture switch. Storage already runs by default, independently of metrics and Work. No dashboard history page is added.

**Validation:** Read a recent send's text, `body_truncated`, `body_stored_at` and receipt. Filter by typed `source` or operator-timezone `local_date`; limit defaults to 50, ranges from 1 to 100, and `next_before` supplies the next page's `before` value. An old or historical record may have a null body.

**Disable / rollback:** Stop querying to stop using the read. This does not stop capture; there is no per-feature capture rollback switch. Bodies expire after 14 days and rows after 90 days. Database downgrade requires the pre-migration backup.

**Authority boundary:** Read-only and operator-only, rejected for API clients before storage access. It is not a Manager tool and retained bodies are not supplied to models. A stored body describes an attempted send, while the receipt separately describes its outcome.

**Docs:** https://github.com/foolzzz/looper/blob/v2.15.39/docs/architecture/agent-system.md

```bash
curl --fail --cookie operator-cookies.txt --json '{"source":"morning_brief","limit":10}' https://looper.example/api/v1/proactive_sends/list
```

### Installable dashboard

**Activation:** No server switch. On a browser-supported secure origin, use Chrome or Edge's install action to open the dashboard in a standalone window. No service worker, offline cache or new browser authority is introduced.

**Validation:** Check the manifest and icons without sign-in, then verify that opening the installed app still follows the dashboard's configured sign-in boundary. Installation availability depends on the browser and origin.

**Disable / rollback:** Uninstall the browser app and use the dashboard in a tab. This does not remove the publicly served metadata/icons or change server authentication.

**Authority boundary:** Anonymous access covers app metadata and icons; installation grants no API or operator access. The installed window uses the same dashboard authentication.

**Docs:** https://github.com/foolzzz/looper/blob/v2.15.39/docs/design.md#web

```bash
curl --fail https://looper.example/manifest.webmanifest
```

### 行为变化

- **无开关自动生效：** 两项启动迁移与在线校验；主动发送前尽力存储正文，32 KiB UTF-8 上限且不切断字符，14 天后由既有每小时清理清空正文，90 天后删投递行，不依赖 metrics，无独立开关。失败最多等待一秒后继续发送；发送文案不变，正文不注入模型。重试复用投递身份并更新尝试正文，旧回执不能覆盖较新的已发送回执；没有回执不等于发送失败。
- **浏览器与 HTTP：** manifest 和三个图标免登录、一小时公开缓存；登录页 CSP 增加 `manifest-src 'self'` 和 `img-src 'self'`，控制台 HTML 仍按配置登录。静态资源解析到目录外一律 404。`Connection: close` 只是明确已有的一请求一关闭策略，修复复用竞态，不增加连接周转。

- **已有 metrics 开：** `ack_ms` 从接收时刻量到实际确认时刻，起点优先 `ack_received_at`，否则用回合接收时间，且不小于零；修复飞书先确认后构造 Manager 信封造成的负值，历史曲线口径因此不同。关 metrics 仍不写回合指标，但主动投递行和正文照常记录。
- **Work 开：** 控制台提供 Planner/默认管家对话、活动/关卡回复与导航；各对话的未发/暂存输入与阅读位置存入浏览器 session storage，消息缓存只放内存。需求在草稿、就绪与活动状态可编辑，保留版本和 Planner 读取状态；计划、文件与费用为只读。attention 摘要还需要原有 attention 开关。New task 可创建草稿，但草稿的 Planner 对话不能发送，尚无可写的草稿对话输入与生命周期按钮，模型选择显示不支持。
- **入口：** 控制台新增可选 Work 与浏览器安装；Telegram、Lark 沿既有主动发送路径记正文/回执，飞书确认延迟口径修正，无需新增聊天命令；生成式操作者客户端可发现五项新操作，它们不是管家工具。

### 可选能力启用与使用

以下 API 示例需替换为自己的站点并提供操作者登录 cookie 文件，只读示例不会自动开启能力。

#### Work console

**启用：** `tasks.conversations.enabled` 默认关闭。操作者通过 `task_conversations.update` 提交 `{"enabled":true}`，再用 `POST /api/v1/confirm` 完成返回的确认；null 恢复关闭。读回开启后侧栏显示 Work，`#/work` 可进入；没有新增 Settings 表单。

**验证：** 读回开启并选择任务，检查 Planner/默认管家对话、需求编辑与上下文面板。New task 在已有项目下创建草稿，但草稿的 Planner 对话不能发送。任务 Manager 链未合入，模型切换不可用，没有可写的草稿对话输入或生命周期按钮。

**停用 / 回退：** 更新为 false/null 并确认，入口隐藏、Work URL 回 Dashboard。任务与 schema 保留；不关闭主动正文留存，数据库降级需备份。

**权限边界：** 设置、草稿创建和 `tasks.done` 仅限操作者，API client 不可用。草稿不启动 agent；直接完成拒绝后台仍持有的任务，对已完成任务幂等。worktree 任务收尾会先把未提交工作提交到任务分支再移除 worktree，收尾失败返回 warning；不合并任务分支、不跑 task-end listener。既有 Planner 可发送状态与关卡权限仍生效，不新增任务 Manager 或 scoped 权限。

**文档：** https://github.com/foolzzz/looper/blob/v2.15.39/docs/architecture/agent-system.md

```bash
curl --fail --cookie operator-cookies.txt --json '{}' https://looper.example/api/v1/task_conversations/get
```

#### Proactive send history

**启用：** 操作者显式调用 `POST /api/v1/proactive_sends/list`；留存已默认执行，不需启用、不依赖 Work/metrics，也没有独立开关或新增历史页面。

**验证：** 检查正文、截断标记、存储时间与回执；可按 source、本地日期过滤，limit 默认 50、范围 1–100，以 `next_before` 作为下一页 before。历史或过期正文可为 null。

**停用 / 回退：** 停止查询仅停止使用读取功能，不会停止留存；正文 14 天后清空、行 90 天后删除，无独立回退开关。数据库降级需迁移前备份。

**权限边界：** 仅限操作者只读，API client 在存储访问前被拒；不是管家工具，正文不进入模型。正文代表发送尝试，回执单独表示结果。

**文档：** https://github.com/foolzzz/looper/blob/v2.15.39/docs/architecture/agent-system.md

```bash
curl --fail --cookie operator-cookies.txt --json '{"source":"morning_brief","limit":10}' https://looper.example/api/v1/proactive_sends/list
```

#### Installable dashboard

**启用：** 无服务端开关；在浏览器支持的安全来源上使用 Chrome/Edge 安装入口，可独立窗口打开，不增加 service worker 或离线模式。

**验证：** 免登录读取 manifest/图标，安装后确认控制台仍遵循既有登录要求；安装入口是否出现取决于浏览器与来源。

**停用 / 回退：** 卸载浏览器应用，改用标签页；不会移除公开元数据/图标，也不改变服务端认证。

**权限边界：** 匿名可读的只是应用元数据和图标；安装不授予 API 或操作者权限，独立窗口沿用控制台认证。

**文档：** https://github.com/foolzzz/looper/blob/v2.15.39/docs/design.md#web

```bash
curl --fail https://looper.example/manifest.webmanifest
```
