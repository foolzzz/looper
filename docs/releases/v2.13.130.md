# Looper v2.13.130

## Release Decision

**Who should upgrade:** Nobody needs to upgrade for existing behavior. Operators who bind native Telegram or Lark chats to Managers, or who set the bound-chats-only policy, and who want to do it in the dashboard instead of the v1 API should upgrade, because Settings now has those controls.

**What this release solves:** [#657](https://github.com/foolzzz/looper/pull/657) lists each Manager's explicit chat bindings in Managers settings, with saved move and unbind actions. [#658](https://github.com/foolzzz/looper/pull/658) lets operators bind observed bot chats and save the bound-only switch from Channels settings. Both use the v1 operations and the client library that v2.13.129 added.

**Breaking changes:** No. Both changes are dashboard-only. No API, schema or configuration changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#657](https://github.com/foolzzz/looper/pull/657) and [#658](https://github.com/foolzzz/looper/pull/658); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.130
```

## Behavior changes

- **Managers settings lists chat bindings (#657):** the new `web/src/components/manager-chat-bindings.tsx` adds a "Chats" section to each Manager row, built from `fetchChatBindings` over all channels and grouped by `manager_id`. Each row shows the chat name (or id), channel type, bot name, channel id, chat id, and the bound Manager with "Deleted" or "Off" markers. The section shows "No explicit chat bindings." when empty and "Explicit chat bindings have not loaded." before the first successful read. The page gains a "Refresh chats" button (labelled "Retry chats" after an error) and a "Loading chats…" status. The Manager list's Retry button now reloads Managers and bindings together; reads are versioned so a stale response is dropped.
- **Move and unbind (#657):** "Move to Manager" picks a target (Managers marked deleted by the binding data are excluded; a vanished target shows as a disabled "Unavailable Manager") and "Move" calls `putChatBinding`. "Unbind" first reads the bot's policy with `fetchChannelChats(channel_id, {limit: 1})` and explains the result: with bound-chats-only on the bot stays silent in that chat, otherwise the chat returns to the bot's default Manager (shown with "· Off" when disabled). "Confirm unbind" then calls `deleteChatBinding`. One write runs at a time; a write invalidates earlier reads, and after it the page re-reads the bindings from the server. If the write succeeded but the re-read fails, the error says "Change saved; readback failed." A `not_found` error reloads Managers and bindings. After a successful write, focus moves to the section heading.
- **Channels settings binds observed chats (#658):** the new `web/src/components/channel-chat-bindings.tsx` adds a "Chat bindings" section to each Telegram and Lark channel card (those with a sender allowlist; the diff does not show other channel types getting it). It loads observed chats 20 per page from `fetchChannelChats` (with "Load more chats" and "Refresh chats"), the channel's bindings and the Manager list. Each chat shows a Bound, Silenced or Bot Manager badge, seen count, last-seen time, recent suppressed count and the effective Manager, with a note when the bound Manager is off or unavailable (no fallback Manager is used). A select per chat binds it to a Manager, or choosing "Use this bot's Manager (no binding)" unbinds it; the change is saved at once through `putChatBinding` or `deleteChatBinding`, with no confirm step. Suppressed chats outside the loaded pages are added from the first page's `unbound_chats`. The state is keyed by channel id; a 404 refreshes the Manager list without applying the refused choice.
- **Bound-only switch (#658):** an "Only bound chats" switch saves immediately through `setBoundChatsOnly` and then reloads the section. Its text says that when on, unbound new messages are silent (no Manager, reply, reaction or status).
- **Wording (#658):** the channel card footer and the Channels page description now say that bot connection, credential and allowlist changes take effect after the server restarts, while chat bindings and Only bound chats apply immediately. The saved badge reads "Saved — restart to apply bot settings" instead of "Saved — restart to apply".
- **Model-visible changes:** none found. Both diffs touch only dashboard components, the settings page text and tests. They change no prompt, tool declaration or tool result.
- **Line counts:** the descriptions report tests 278 and production 406 added lines for [#657](https://github.com/foolzzz/looper/pull/657), and tests 333 and production 410 for [#658](https://github.com/foolzzz/looper/pull/658) (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.130 is published. No schema or configuration change. Rolling back to v2.13.129 removes the dashboard controls; bindings already saved stay in place and remain manageable through the v1 operations.

### 升级决策

**谁需要升级：**无需为现有行为而升级。需要把原生 Telegram/Lark 聊天绑定到 Manager、或设置仅限绑定聊天策略，并希望在仪表盘而不是 v1 API 中完成的操作者应升级，因为设置页现在有这些控件。

**解决了什么：**[#657](https://github.com/foolzzz/looper/pull/657) 在 Managers 设置中列出每个 Manager 的显式聊天绑定，并支持保存的改绑和解绑。[#658](https://github.com/foolzzz/looper/pull/658) 让操作者在 Channels 设置中绑定已见的 bot 聊天并即时保存仅限绑定开关。两者都使用 v2.13.129 新增的 v1 操作和客户端库。

**是否有破坏性变更：**否。两项改动都只在仪表盘，没有 API、表结构或配置变更。

**如何验证：**运行 `looper --version` 核对版本为 2.13.130。

**贡献者：**维护者 @foolzzz 提交 [#657](https://github.com/foolzzz/looper/pull/657) 和 [#658](https://github.com/foolzzz/looper/pull/658)；本次 patch release 无社区贡献。


### 行为变化与入口

- **Managers 设置列出聊天绑定（#657）：**新增 `web/src/components/manager-chat-bindings.tsx`，在每个 Manager 行加入“Chats”区块，数据来自对所有渠道的 `fetchChatBindings`，按 `manager_id` 分组。每行显示聊天名（或 id）、渠道类型、bot 名、渠道 id、聊天 id，以及绑定的 Manager 和“Deleted”“Off”标记。为空时显示“No explicit chat bindings.”，首次读取成功前显示“Explicit chat bindings have not loaded.”。页面新增“Refresh chats”按钮（出错后为“Retry chats”）和“Loading chats…”状态。Manager 列表的 Retry 现在同时重载 Manager 与绑定；读取带版本号，过期响应被丢弃。
- **改绑与解绑（#657）：**“Move to Manager”选择目标（绑定数据标记为已删除的 Manager 被排除；已消失的目标显示为禁用的“Unavailable Manager”），“Move”调用 `putChatBinding`。“Unbind”先用 `fetchChannelChats(channel_id, {limit: 1})` 读取 bot 策略并说明结果：仅限绑定聊天开启时 bot 在该聊天保持沉默，否则该聊天回到 bot 的默认 Manager（已停用时带“· Off”）。“Confirm unbind”再调用 `deleteChatBinding`。同一时间只运行一个写入；写入使之前的读取失效，之后页面从服务端重读绑定。写入成功但重读失败时，错误提示“Change saved; readback failed.”。`not_found` 错误会重载 Manager 与绑定。写入成功后焦点移到区块标题。
- **Channels 设置绑定已见聊天（#658）：**新增 `web/src/components/channel-chat-bindings.tsx`，在每个有发送者白名单的 Telegram 和 Lark 渠道卡片中加入“Chat bindings”区块（diff 未显示其他渠道类型获得它）。它从 `fetchChannelChats` 每页 20 条加载已见聊天（带“Load more chats”和“Refresh chats”），并加载该渠道的绑定和 Manager 列表。每个聊天显示 Bound、Silenced 或 Bot Manager 徽标、已见次数、最后出现时间、近期被抑制次数和生效的 Manager；绑定的 Manager 已停用或不可用时有说明，且不使用回退 Manager。每个聊天一个下拉框：选择 Manager 即绑定，选择“Use this bot's Manager (no binding)”即解绑；改动通过 `putChatBinding` 或 `deleteChatBinding` 立即保存，无确认步骤。已加载页之外的被抑制聊天从第一页的 `unbound_chats` 补入。状态以渠道 id 为键；404 会刷新 Manager 列表，但不会应用被拒绝的选择。
- **仅限绑定开关（#658）：**“Only bound chats”开关通过 `setBoundChatsOnly` 立即保存并重载该区块。文案说明开启时未绑定的新消息保持沉默（无 Manager、回复、反应或状态）。
- **文案（#658）：**渠道卡片页脚和 Channels 页面说明现在写明：bot 连接、凭据和白名单的改动在服务重启后生效，而聊天绑定和 Only bound chats 立即生效。保存徽标由“Saved — restart to apply”改为“Saved — restart to apply bot settings”。
- **面向模型的变化：**未发现。两个 diff 只触及仪表盘组件、设置页文案和测试，不改提示词、tool 声明或 tool 结果。
- **行数：**描述报告 [#657](https://github.com/foolzzz/looper/pull/657) 新增测试 278 行、生产代码 406 行，[#658](https://github.com/foolzzz/looper/pull/658) 新增测试 333 行、生产代码 410 行（不含 fixtures）。
