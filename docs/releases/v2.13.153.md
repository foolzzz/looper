# Looper v2.13.153

## Release Decision

**Who should upgrade:** Operators who use scheduled tasks with Managers that have task templates, or whose Manager policy is "templates only". Everyone else can stay on v2.13.152.

**What this release solves:** [#711](https://github.com/foolzzz/looper/pull/711) lets a schedule select its owner Manager's task template and static inputs, so a scheduled run is created from the template with its roles and profiles.

**Breaking changes:** No. The schedule columns and API fields are additive and optional; schedules without a template behave as before.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#711](https://github.com/foolzzz/looper/pull/711); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.153
```

## Behavior changes

- **Schedule template selection (#711):** `schedules` gains `template_key` (nullable) and `template_inputs` (JSONB object, default `{}`), with a foreign key to the owner Manager's templates (`ON DELETE RESTRICT`). The v1 schedule read and write schemas carry `template_key`, `template_inputs` and `template_name`; `template_key` must match `^[a-z][a-z0-9_-]{0,31}$` or be null, and inputs are strings of at most 2000 characters. Setting `template_key` to null clears the inputs; inputs without a key are refused.
- **Validation on save and fire (#711):** `looper/agents/schedule_templates.py` resolves the selection once for create, update, import and firing: the owner and its policy, the template's inputs, a fixed project or work directory that conflicts with the schedule, profile conflicts with the template, the project's profile list, role templates (Planner-defined roles on, items installed) and the rendered requirement length. Save failures return 400 (missing work directory) or 409 (other conflicts). A work directory may now come from the template. Deleting a template that a schedule uses is refused with 409 naming the schedule.
- **Task creation (#711):** a firing creates the task inside a savepoint, with the template snapshot (including input values), the merged Agent Profile overrides, and each template role stored as a first role version (`via` template) with a journal entry. A failure creates no partial task.
- **Gates (#711):** the gate runs in the effective work directory. A fingerprint of the schedule and effective template is taken before the gate and rechecked afterwards; if either changed, the run fails with "schedule/template configuration changed" and the gate output is not carried to the next run.
- **Policy (#711):** an owner with the templates-only policy accepts a schedule that names a template; a schedule without one is still refused. Configuration import no longer skips every schedule of such an owner, only those without a valid template.
- **Configuration transfer (#711):** schedule entries export and import `template_key` and `template_inputs`, and import checks them against the imported templates. The export tool's description and note name `looper-config/v4`, and its result adds `bots_left_out`.
- **Dashboard (#711):** the schedule form adds a task template picker and input fields for the selected owner, requires the template's required inputs, and the detail view shows the template and inputs. The work directory is no longer required when the template sets one.
- **Model-visible changes:** a scheduled task created from a template gets the template's rendered requirement, its snapshot and its role definitions; schedules without a template are unchanged. The configuration export tool's description and note text change. Nothing else sent to the model changes. The prompt evaluation gains `schedule_template_report` and `template_config_export`.
- **Tests (#711):** adds `tests/test_schedule_task_templates_db.py`, `tests/test_schedule_template_transfer_db.py` and `tests/test_schedule_template_browser.py`, and updates `tests/test_prompt_eval.py`.

## Upgrade and rollback

Re-run `install.sh` once v2.13.153 is published. Startup applies the additive schema change to `schedules`. Rolling back to v2.13.152 leaves the new columns unused, and schedules that name a template then run as plain schedules.

### 升级决策

**谁需要升级：**在带任务模板的 Manager 下使用定时任务、或 Manager 策略为“仅模板”的运维者。其他人可留在 v2.13.152。

**是否有破坏性变更：**否。新增的列和 API 字段都是可选的；不用模板的定时任务行为不变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.153。

**贡献者：**维护者 @foolzzz 提交 [#711](https://github.com/foolzzz/looper/pull/711)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.153
```

### 行为变化与入口

- **定时任务选择模板（#711）：**`schedules` 新增 `template_key`（可空）和 `template_inputs`（JSONB 对象，默认 `{}`），并外键到所属 Manager 的模板（`ON DELETE RESTRICT`）。v1 定时任务读写 schema 带 `template_key`、`template_inputs` 和 `template_name`；`template_key` 须匹配 `^[a-z][a-z0-9_-]{0,31}$` 或为 null，输入为不超过 2000 字符的字符串。`template_key` 设为 null 会清空输入；有输入而无 key 会被拒绝。
- **保存与触发时校验（#711）：**`looper/agents/schedule_templates.py` 在创建、更新、导入和触发时统一解析：所属 Manager 及其策略、模板输入、模板固定的项目或工作目录与定时任务冲突、profile 与模板冲突、项目 profile 列表、角色模板（已开启 Planner 定义角色、条目已安装）以及渲染后的需求长度。保存失败返回 400（缺工作目录）或 409（其他冲突）。工作目录现在可以来自模板。删除仍被定时任务使用的模板会以 409 拒绝并指出该定时任务。
- **创建任务（#711）：**触发时在 savepoint 内创建任务，写入模板快照（含输入值）、合并后的 Agent Profile 覆盖，以及每个模板角色作为首个角色版本（`via` 为 template）和一条日志。失败不会留下半成品任务。
- **Gate（#711）：**gate 在生效的工作目录运行。gate 前取定时任务与生效模板的指纹，gate 后重新核对；若有变化，该次运行以“schedule/template configuration changed”失败，gate 输出不会带入下一次运行。
- **策略（#711）：**“仅模板”策略的 Manager 接受指定了模板的定时任务；未指定模板的仍被拒绝。配置导入不再跳过该 Manager 的全部定时任务，只跳过没有有效模板的。
- **配置迁移（#711）：**定时任务条目导出和导入 `template_key`、`template_inputs`，导入时对照导入的模板检查。导出工具的描述和说明改为 `looper-config/v4`，结果新增 `bots_left_out`。
- **Dashboard（#711）：**定时任务表单新增任务模板选择和所选模板的输入框，必填输入会校验，详情页显示模板和输入。模板指定了工作目录时不再要求填写。
- **面向模型的变化：**由模板创建的定时任务会收到模板渲染后的需求、快照和角色定义；不用模板的定时任务不变。配置导出工具的描述和说明文字有变化。其余发给模型的内容不变。提示词评测新增 `schedule_template_report` 和 `template_config_export`。
- **测试（#711）：**新增 `tests/test_schedule_task_templates_db.py`、`tests/test_schedule_template_transfer_db.py`、`tests/test_schedule_template_browser.py`，并更新 `tests/test_prompt_eval.py`。

### 升级与回退

v2.13.153 发布后重跑 `install.sh`。启动时会应用对 `schedules` 的增量 schema 变更。回退到 v2.13.152 后新列不再使用，指定了模板的定时任务会按普通定时任务运行。
