# Looper v2.13.167

## Release Decision

**Who should upgrade:** No one needs this release for a running-Looper behavior change. [#725](https://github.com/foolzzz/looper/pull/725) changes only the prompt-regression evaluation CLI, and [#754](https://github.com/foolzzz/looper/pull/754) fixes the runner protocol, bridge and turn policy, which nothing else in Looper calls yet. Everyone can stay on v2.13.166.

**What this release solves:** [#725](https://github.com/foolzzz/looper/pull/725) adds `dialogs --manager-agent SPEC.json` so the Manager can be evaluated alone on a supplied agent while other roles keep their profiles. [#754](https://github.com/foolzzz/looper/pull/754) fixes reviewed defects in the runner code: frame-read bounds, authorization coverage, session cleanup, per-session failures and tool timeouts.

**Breaking changes:** No. No API, database schema, configuration, prompt or Tool declaration changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#725](https://github.com/foolzzz/looper/pull/725) and [#754](https://github.com/foolzzz/looper/pull/754); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.167
```

## Behavior changes

- **Manager-only eval entry point ([#725](https://github.com/foolzzz/looper/pull/725)):** in `evals/prompt_regression`, `dialogs --manager-agent SPEC.json` registers the spec once per case and selects it at the Manager role layer; the other roles keep `--model`/`--agent`. It requires `--mode real` and is rejected together with `--manager-model`, `--manager-effort` or `--register-agent`. Example specs `evals/agents/api-cpa.example.json` and `evals/agents/codex-cpa.example.json` are added.
- **Eval profile switch ([#725](https://github.com/foolzzz/looper/pull/725)):** a real `session_profile_switch` dialog now creates the switch profile from the selected Manager's runtime, model, effort, agent-teams and custom-prompt options, instead of a fixed `haiku` subscription profile, and raises an error if no Manager profile is known. An explicit `--switch-agent` still replaces it. The switch check now compares profile ids rather than names.
- **Runner frames ([#754](https://github.com/foolzzz/looper/pull/754)):** `read_frame` narrows the stream reader's limit to the remaining frame budget, so a frame cannot exceed the maximum size across partial reads; the bridge's unknown-method envelope check applies only to a complete, newline-terminated frame. `initialize` now permits every request kind by default rather than only `turn`.
- **Runner authorization ([#754](https://github.com/foolzzz/looper/pull/754)):** a `budget/authorize` for a kind outside the runner's `authorize_covers` is refused as unsupported. An allowed reservation is recorded and no longer rewritten to a denial by a concurrent stop. A `request_end` without a matching authorization of the same kind, or for an uncovered kind, cancels the turn and settles it as `failed` (or `lost`) with `usage_complete` false and error kind `INVALID_REQUEST`.
- **Runner sessions ([#754](https://github.com/foolzzz/looper/pull/754)):** a prompt rejected by a schema or encoding error before anything was written abandons only that prompt; after the prompt was sent, the connection is failed. Updates for a rejected prompt are dropped, and a new turn clears stale updates and authorizations. `close_session` is idempotent for an unknown session, restores the prior state if the close is rejected, waits for settlement without a timeout (so a slow admitted tool no longer fails the shared connection) and removes the session. The supervisor's lease release tolerates a session already removed.
- **Runner turn policy ([#754](https://github.com/foolzzz/looper/pull/754)):** `max_requests` must now be a positive integer, otherwise `ValueError` (it previously fell back to 30). A `looper_room_inbox` call with `wait_seconds` gets a tool timeout of at least that wait plus 20 s (default 120 s), and the timeout message reports the actual value. When a turn finishes, the run and task caps are checked against actual cost as well as unverifiable budgets.
- **Model-visible changes:** none. No prompt, tool description or tool schema changed. The only text change a model could see is the timeout message of a runner tool call, and the runner path is not called by Looper yet.
- **Tests:** `tests/test_eval_manager_agent.py` is added; `tests/test_model_manager_dialogs.py`, `tests/test_runner_protocol.py`, `tests/test_runner_bridge.py`, `tests/test_runner_turn.py` and `tests/test_runner_supervisor.py` are extended. Documentation for the RFC and the long-horizon plan is updated; RFC sections 8.4 and 15 stay open.
- **Reach:** a search of `looper/` finds no caller of the runner modules outside their own directory, so running Looper behavior does not change. The added line counts in the description of #754 (101 production, 413 test) match its file list.

## Upgrade and rollback

Re-run `install.sh` once v2.13.167 is published; there is no migration and no configuration change. Rolling back to v2.13.166 restores the previous eval CLI and runner code.

### 行为变化与入口

- **仅 Manager 的评测入口（#725）：**在 `evals/prompt_regression` 中，`dialogs --manager-agent SPEC.json` 按用例注册该 spec 并在 Manager 角色层选用，其他角色保持 `--model`/`--agent`。它要求 `--mode real`，与 `--manager-model`、`--manager-effort`、`--register-agent` 同用会被拒绝。新增示例 spec `evals/agents/api-cpa.example.json` 与 `evals/agents/codex-cpa.example.json`。
- **评测的 profile 切换（#725）：**真实的 `session_profile_switch` 对话现在按所选 Manager 的 runtime、模型、effort、agent-teams 和自定义 prompt 创建切换 profile，不再使用固定的 `haiku` 订阅 profile；未知 Manager profile 时报错。显式的 `--switch-agent` 仍会替换它。切换检查改为比较 profile id 而非名称。
- **Runner 帧（#754）：**`read_frame` 把流读取器的上限收窄到帧剩余额度，分段读取也无法超过最大帧；bridge 对未知方法的信封检查仅适用于完整且以换行结尾的帧。`initialize` 默认允许所有请求类型，而不再只允许 `turn`。
- **Runner 授权（#754）：**对不在 runner `authorize_covers` 内的类型发起 `budget/authorize` 会被拒绝为不支持。已允许的预留会被记录，并发的 stop 不再将其改写为拒绝。没有同类型匹配授权、或类型未被覆盖的 `request_end` 会取消该轮次，并将其结算为 `failed`（或 `lost`），`usage_complete` 为 false，错误类型 `INVALID_REQUEST`。
- **Runner 会话（#754）：**在写入任何内容之前因 schema 或编码错误被拒绝的 prompt 只放弃该 prompt；prompt 已发送后则使连接失败。被拒绝 prompt 的更新会被丢弃，新轮次会清除过期的更新和授权。`close_session` 对未知会话幂等，close 被拒绝时恢复先前状态，等待结算时不再设超时（慢工具不再使共享连接失败），并移除该会话。supervisor 释放 lease 时能容忍会话已被移除。
- **Runner 轮次策略（#754）：**`max_requests` 现在必须是正整数，否则抛出 `ValueError`（此前回退为 30）。带 `wait_seconds` 的 `looper_room_inbox` 调用，其工具超时至少为该等待时间加 20 秒（默认 120 秒），超时消息报告实际值。轮次结束时，除不可验证的预算外，还按实际费用检查运行和任务上限。
- **面向模型的变化：**无。prompt、工具描述和工具 schema 均未改变。模型唯一可能看到的文字变化是 runner 工具调用的超时消息，而 Looper 尚未调用 runner 路径。
- **测试：**新增 `tests/test_eval_manager_agent.py`；扩展 `tests/test_model_manager_dialogs.py`、`tests/test_runner_protocol.py`、`tests/test_runner_bridge.py`、`tests/test_runner_turn.py` 和 `tests/test_runner_supervisor.py`。RFC 与长程计划文档已更新；RFC 第 8.4、15 节仍未关闭。
- **影响范围：**在 `looper/` 中搜索，runner 模块自身目录之外没有调用方，因此运行中的 Looper 行为不变。#754 描述中的新增行数（生产 101、测试 413）与其文件清单一致。
