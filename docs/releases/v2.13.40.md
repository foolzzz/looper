# Looper v2.13.40

## Release Decision

**Who should upgrade:** Nobody needs to. This patch changes the prompt-regression eval dialogs and their tests only; installed behavior is the same as v2.13.39.

**What this release solves:** [#410](https://github.com/foolzzz/looper/pull/410) fixes two false failures of the real-mode prompt-regression dialogs: `withdraw_then_continue` failed a correct answer because it demanded a tool call, and `stop_then_continue` flagged a reply that was not a false claim.

**Breaking changes:** No. No code under `looper/` changed apart from the version number.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#410](https://github.com/foolzzz/looper/pull/410); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.40
```

## Behavior changes

- **Product behavior:** none. The pull request touches `evals/prompt_regression/dialogs.py` and `tests/test_prompt_eval.py`; the author states "Behavior changes: none in the product". No user entry point (dashboard, Telegram, Lark, CLI) is affected.
- **`withdraw_then_continue`, first turn:** every Manager message starts with the existing projects, so a real Manager can count them without a tool call. The new check `_projects_counted` passes in real mode when the reply names every project from `/api/projects`. In fake mode it still checks the stand-in Manager's scripted read. The withdraw turn and the follow-up turn are unchanged.
- **`stop_then_continue`, follow-up check (`_knows_it_was_stopped`):** a reply containing "汇总" is a false claim only when the turn made no `looper_tasks list` read of a single project and the reply does not say the work was not done. "还没" now counts as saying so. Listing the projects alone, or all tasks at once, does not back a summary. The withdraw dialog's own follow-up check is unchanged.
- **Eval helpers:** `Look` gains `turn_since` and `turn_actions()`, so a check can look at the calls of the turn its reply answers; `_reads(look)` and `_project_task_reads(look)` sit next to `_writes`, and `_answered_by_reading` uses `_reads`. The dialog runner records the trail position before each turn from the latest action of any agent.
- **Tests:** `tests/test_prompt_eval.py` gains unit tests for both checks.
- **Model-visible changes:** none. No prompt, tool description or `Channel:` line changed; only the checks that grade a Manager's replies in the eval dialogs.

## Upgrade and rollback

Re-run `install.sh` once v2.13.40 is published. There is no schema change and no data migration. Rolling back to v2.13.39 needs no step.

No new optional capability activation is introduced in this release.

### 升级决策

**谁需要升级：**无需升级。本次 patch 只改 prompt 回归评测的对话及其测试，已安装版本的行为与 v2.13.39 相同。

### 行为变化与入口

- 产品行为：无变化。该 PR 只改 `evals/prompt_regression/dialogs.py` 和 `tests/test_prompt_eval.py`；作者声明产品无行为变化。仪表盘、Telegram、Lark、CLI 等用户入口均不受影响。
- `withdraw_then_continue` 第一轮：每条 Manager 消息都以现有项目开头，真实 Manager 无需调用工具即可数出项目数。新检查 `_projects_counted` 在真实模式下，回复点出 `/api/projects` 中的每个项目即通过；假模式下仍检查替身 Manager 的脚本化读取。撤回轮和后续轮不变。
- `stop_then_continue` 后续检查（`_knows_it_was_stopped`）：回复含「汇总」时，只有本轮没有对单个项目的 `looper_tasks list` 读取、且回复没有说明工作未完成，才算虚假声明。「还没」现在也算说明未完成。只列出项目或一次性列出全部任务，不足以支撑汇总。撤回对话自己的后续检查不变。
- 评测辅助：`Look` 新增 `turn_since` 和 `turn_actions()`，检查可只看回复所属那一轮的调用；`_reads(look)` 与 `_project_task_reads(look)` 紧邻 `_writes`，`_answered_by_reading` 改用 `_reads`。对话运行器在每轮前记录任意 agent 的最新动作位置。
- 测试：`tests/test_prompt_eval.py` 为两个检查新增单元测试。
- 面向模型的变化：无。提示词、工具描述和 `Channel:` 行均未改变，只改评测对话中给 Manager 回复打分的检查。
