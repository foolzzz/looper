# Looper v2.13.107

## Release Decision

**Who should upgrade:** Anyone who restarts a stopped, failed or finished task from the dashboard task page with Start or Start over.

**What this release solves:** [#601](https://github.com/foolzzz/looper/pull/601) makes the task page confirm that a restart really began before it stops polling. A late Stop write, or a detail read that mixes a new run count with the old terminal status, can no longer be taken for the new run, so the Sessions activity resumes reliably.

**Breaking changes:** No. No route, command or stored data changed; the change is in the dashboard task page.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#601](https://github.com/foolzzz/looper/pull/601); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.107
```

## Behavior changes

- **Restart is confirmed before polling ends ([#601](https://github.com/foolzzz/looper/pull/601)):** in `web/src/pages/task-detail.tsx`, `start` first reads the task detail, then sends Start (or Start over). The read is the baseline, so a Stop that completes after the page loaded is not mistaken for the requested run, nor is a run that finishes before its first detail read.
- **Acknowledgement rule:** while the request is in flight, polling results are ignored. Once it is accepted, a non-terminal task acknowledges the restart immediately. A terminal task must differ from the baseline in status, `completed_at` or run count (`cost.runs`), have no run counted as running, and show the same snapshot in two consecutive reads, because a detail read is not atomic. On acknowledgement the page reopens the activity stream once; a `failed` result shows the task's error.
- **Controls:** Start and Start over are disabled while the request or the confirmation is pending, and the Start over confirmation closes when it is sent. A refused request clears the pending state, re-enables both buttons and shows its error. Leaving the task aborts the pending read.
- **Model-visible changes:** None. No Manager tool declaration, prompt, API route or API document changed.
- **Tests:** [#601](https://github.com/foolzzz/looper/pull/601) extends `tests/test_task_activity_restart_browser.py` with the mixed-snapshot, late-Stop, Start over and refused Start over cases, and `web/src/pages/task-detail-route.test.tsx` (41 test lines, 159 production lines as reported).

## Upgrade and rollback

Re-run `install.sh` once v2.13.107 is published. No data migration and no configuration change. Rolling back to v2.13.106 restores the earlier restart detection, which can end polling on a stale terminal snapshot.

No new optional capability activation is introduced in this release.

### 升级决策

**谁需要升级：**在仪表盘任务页对已停止、失败或已完成的任务使用 Start 或 Start over 重新启动的使用者。

**解决了什么：**[#601](https://github.com/foolzzz/looper/pull/601) 让任务页在停止轮询之前先确认重启确实已开始。迟到的 Stop 写入，或把新的运行次数与旧的终态状态混在一起的详情读取，不会再被误认为新一轮运行，Sessions 活动因此能可靠恢复。

**是否有破坏性变更：**否。路由、命令和存储数据均未改变；改动仅在仪表盘任务页。

**如何验证：**运行 `looper --version` 核对版本为 2.13.107。

**贡献者：**维护者 @foolzzz 提交 [#601](https://github.com/foolzzz/looper/pull/601)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.107
```

### 行为变化与入口

- **轮询结束前先确认重启（[#601](https://github.com/foolzzz/looper/pull/601)）：**`web/src/pages/task-detail.tsx` 中，`start` 先读取一次任务详情，再发送 Start（或 Start over）。该次读取作为基线，因此页面加载后才完成的 Stop，或在首次详情读取前就已结束的运行，都不会被误认为所请求的运行。
- **确认规则：**请求进行中，轮询结果被忽略。请求被接受后，非终态任务立即确认重启。终态任务必须在状态、`completed_at` 或运行次数（`cost.runs`）上与基线不同，没有运行仍被计为运行中，并且连续两次读取得到相同快照，因为详情读取不是原子的。确认后页面只重新打开一次活动流；结果为 `failed` 时显示任务的错误。
- **控件：**请求或确认进行期间，Start 与 Start over 保持禁用，发送时 Start over 的确认框关闭。请求被拒绝时清除等待状态、重新启用两个按钮并显示错误。离开该任务会中止未完成的读取。
- **面向模型的变化：**无。Manager 的 tool 声明、提示词、API 路由和 API 文档均未改变。
- **测试：**[#601](https://github.com/foolzzz/looper/pull/601) 扩展 `tests/test_task_activity_restart_browser.py`（混合快照、迟到 Stop、Start over、被拒绝的 Start over）和 `web/src/pages/task-detail-route.test.tsx`（按报告测试 41 行、生产代码 159 行）。
