# Looper v2.15.15

This is the patch release v2.15.15, a hotfix line in which each merged change ships at once. It documents the changes merged since v2.15.14: [#1409](https://github.com/foolzzz/looper/pull/1409), [#1410](https://github.com/foolzzz/looper/pull/1410) and [#1411](https://github.com/foolzzz/looper/pull/1411), plus two test-only changes, [#1408](https://github.com/foolzzz/looper/pull/1408) and [#1413](https://github.com/foolzzz/looper/pull/1413).

## Release Decision

**Who should upgrade:** Anyone whose Manager is bound to a Lark or Telegram group chat, and anyone whose Lark users reply to messages in threads.

**What this release solves:** A group chat no longer receives the task's local configuration or its progress posts, and its end notice carries the whole conclusion without a link the group cannot open ([#1410](https://github.com/foolzzz/looper/pull/1410), [#1411](https://github.com/foolzzz/looper/pull/1411)). A Lark reply to a thread's first message now reads the thread, and a quoted message is read faster ([#1409](https://github.com/foolzzz/looper/pull/1409)).

**Breaking changes:** No. There is no API field change, and the one PostgreSQL migration is additive. Group chats see different messages (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.15
```

**Contributors:** Maintainer @foolzzz authored [#1408](https://github.com/foolzzz/looper/pull/1408), [#1409](https://github.com/foolzzz/looper/pull/1409), [#1410](https://github.com/foolzzz/looper/pull/1410), [#1411](https://github.com/foolzzz/looper/pull/1411) and [#1413](https://github.com/foolzzz/looper/pull/1413); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.14 upgrades directly. The release adds one additive PostgreSQL migration, `task_chat_group` (column `tasks.chat_group`, default false), applied at startup. Restart the service after upgrading, as for every release.

## Behavior changes

### Group chats (Lark and Telegram)

- **No task configuration in the answer.** After a task or schedule is created in a group, the Manager's answer carries only the question whether to start (or enable) it. The directory, Agent Profiles, review policy, spend cap and concurrency are no longer listed. Starting the task in the same turn leaves nothing appended. ([#1410](https://github.com/foolzzz/looper/pull/1410))
- **No process messages.** The group no longer gets the task breakdown, progress updates or phase reports. The end notice, gates and the Manager's own answers are unchanged. ([#1410](https://github.com/foolzzz/looper/pull/1410))
- **The end notice carries the whole conclusion.** The whole summary or closing note replaces the first section cut at about 300 characters. A notice over 4,000 characters is sent as ordered messages, cut between lines; a code block cut in the middle is closed and reopened. The first message keeps the head line and the Lark @-mention. If a part fails to send, the notice ends there and earlier parts are not resent. ([#1411](https://github.com/foolzzz/looper/pull/1411))
- **No unreachable link.** The task link is attached only when `public_url` is configured. The wait timeout, concurrency and gate messages drop the link the same way. ([#1411](https://github.com/foolzzz/looper/pull/1411))
- **Unchanged:** direct chats, the dashboard chat and the CLI. Schedule messages keep their links, because they record no group fact.
- **Known limits.** A task created before the upgrade counts as a direct chat, so a group task already running keeps posting progress until it ends. A schedule update in a group still shows its before and after lines.

### Lark quotes

- **A reply to a thread's first message reads the thread.** The Manager gets the first message and the latest 10 other messages, as for any reply in a thread. When the thread cannot be listed, the reply renders as before, with the first message alone. ([#1409](https://github.com/foolzzz/looper/pull/1409))
- **Faster quote reads.** The batch read runs beside the single read and answers first when it returns the message on its own. Measured through the real lark-cli, reading one message went from a median of about 4.3 s to about 3.7 s; the rendered quote was identical. Recalled messages, merged forwards and cards still use the previous path. The `lark_quote` log line now ends with `read=… names=… files=…` timings and still logs no content. ([#1409](https://github.com/foolzzz/looper/pull/1409))

### Model-visible changes

Yes. The Manager's tool contract and default prompt gain a short clause that, in a group chat, only the start question is added and the configuration is not to be listed. Lark thread replies add the thread's messages to the quote content described in v2.15.14. Real-mode eval (`evals/lark_group.py`, real Claude CLI), as reported by [#1410](https://github.com/foolzzz/looper/pull/1410): in a group, Sonnet passed 2/2 and an Opus xhigh Manager 1/1, showing no configuration and no progress posts, against 0/2 and 0/1 on the previous release; direct chats passed on both sides with the configuration shown. Dashboard dialog evals were unchanged (Sonnet 2/2, Opus xhigh 1/1 per dialog, before and after).

## Validation

**Reported by the pull requests:** the new group tests (the Lark stand-in and Telegram fakes, the splitter, schema upgrade of a database without the column) fail on the previous `main` and pass; the files importing the changed modules passed against a disposable PostgreSQL (6,937 passed, with a few failures that also occur on `main` or come from the local environment); the thread and quote-read changes were timed against the real lark-cli with read-only calls; the ticker-gap tests passed 50 of 50 runs under CPU load, and a negative control still fails them when the code blocks.

### 升级决策

**谁需要升级：**Manager 绑定了 Lark 或 Telegram 群聊的用户，以及 Lark 用户会在话题里回复消息的场景。

**解决了什么：**群聊不再收到任务的本地配置和进度消息，任务结束通知带完整结论，且不再带群里打不开的链接（[#1410](https://github.com/foolzzz/looper/pull/1410)、[#1411](https://github.com/foolzzz/looper/pull/1411)）。回复 Lark 话题首条消息时会读取该话题，引用消息的读取也更快（[#1409](https://github.com/foolzzz/looper/pull/1409)）。

**是否有破坏性变更：**无。API 字段不变，唯一的 PostgreSQL 迁移是增量的。群聊看到的消息会变化（见行为变化）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.15.15。

**贡献者：**维护者 @foolzzz 提交 [#1408](https://github.com/foolzzz/looper/pull/1408)、[#1409](https://github.com/foolzzz/looper/pull/1409)、[#1410](https://github.com/foolzzz/looper/pull/1410)、[#1411](https://github.com/foolzzz/looper/pull/1411) 和 [#1413](https://github.com/foolzzz/looper/pull/1413)；本版本无社区贡献。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.15.14 上的安装可直接升级。本版本增加一个增量 PostgreSQL 迁移 `task_chat_group`（列 `tasks.chat_group`，默认 false），启动时自动应用。升级后照常重启服务。

### 行为变化与入口

**群聊（Lark 与 Telegram）**

- **回答里不再有任务配置。**在群里创建任务或定时任务后，Manager 的回答只带“是否开始（或启用）”的提问，不再列出目录、Agent Profile、评审策略、花费上限和并发。同一回合内启动任务则不追加任何内容。（[#1410](https://github.com/foolzzz/looper/pull/1410)）
- **不再有过程消息。**群里不再收到任务分解、进度更新和阶段报告。结束通知、gate 和 Manager 自己的回答不变。（[#1410](https://github.com/foolzzz/looper/pull/1410)）
- **结束通知带完整结论。**用完整的总结或结语取代截断到约 300 字符的第一节。超过 4,000 字符的通知按顺序拆成多条消息，在行之间切分；被切开的代码块会关闭并重新开启。第一条保留标题行和 Lark @ 提及。某一段发送失败时通知到此为止，已发送的部分不重发。（[#1411](https://github.com/foolzzz/looper/pull/1411)）
- **不再带打不开的链接。**仅在配置了 `public_url` 时附带任务链接。等待超时、并发和 gate 消息同样去掉链接。（[#1411](https://github.com/foolzzz/looper/pull/1411)）
- **不变：**私聊、仪表盘聊天和 CLI。定时任务消息没有群聊记录，保留链接。
- **已知限制。**升级前创建的任务按私聊处理，因此正在运行的群任务会继续发进度，直到结束。群里的定时任务更新仍显示前后对比行。

**Lark 引用**

- **回复话题首条消息会读取话题。**Manager 会得到首条消息和最近 10 条其他消息，与话题内任何回复一样。话题无法列出时，按原样只显示首条消息。（[#1409](https://github.com/foolzzz/looper/pull/1409)）
- **引用读取更快。**批量读取与单条读取并行，能单独返回该消息时由它先回答。用真实 lark-cli 测得，读取一条消息的中位数从约 4.3 秒降到约 3.7 秒，渲染结果一致。已撤回消息、合并转发和卡片仍走原路径。`lark_quote` 日志行末尾新增 `read=… names=… files=…` 耗时，仍不记录内容。（[#1409](https://github.com/foolzzz/looper/pull/1409)）

**面向模型的变化：**

有。Manager 的工具契约和默认提示词新增一句短说明：在群聊里只追加开始的提问，不要列出配置。Lark 话题回复会把话题的消息加入 v2.15.14 所述的引用内容。真实模式评测（`evals/lark_group.py`，真实 Claude CLI），数据来自 [#1410](https://github.com/foolzzz/looper/pull/1410)：群聊中 Sonnet 通过 2/2、Opus xhigh Manager 通过 1/1，没有配置也没有进度消息，上一版本分别为 0/2 和 0/1；私聊两边都通过，配置照常显示。仪表盘对话评测不变（每个对话 Sonnet 2/2、Opus xhigh 1/1，前后一致）。
