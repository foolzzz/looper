# Looper v2.15.9

This is the patch release v2.15.9, a hotfix line in which each merged change ships at once. It documents one change: [#1389](https://github.com/foolzzz/looper/pull/1389) (the `room_consult` eval task says who may read the saved copy, and the eval's consult count is renamed `room_consults_replied`). The change is in the eval, its README and the tests only.

## Release Decision

**Who should upgrade:** No one needs this release for its behavior. It is the version that carries the reworded `room_consult` eval task and the renamed metric; an installation on v2.15.8 runs the same `looper` package code.

**What this release solves:** [#1389](https://github.com/foolzzz/looper/pull/1389) (fixes #1387) closes two gaps seen in the real-mode `room_consult` check. The task requirement did not say who must not read the saved code, so a consult could refuse to answer without reading the file and the step passed only on a retry; it now says the second step must not read the saved copy itself and the first step may read its own copy to answer. The eval's `room_consults_answered` also counted consults that replied without the requested value; the metric is now named `room_consults_replied`.

**Breaking changes:** No. The CLI, the API and the dashboard are unchanged, no new command or control is added and there is no PostgreSQL schema change. The PR changes no file in the `looper` package. The one renamed name is an eval result key (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.9
```

**Contributors:** Maintainer @foolzzz authored [#1389](https://github.com/foolzzz/looper/pull/1389); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.8 upgrades directly. There is no PostgreSQL schema change. Restart the service after upgrading, as for every release.

## Behavior changes

Read in the diff of the PR.

### #1389: `room_consult` eval wording and the replied count

- **Eval only.** The diff touches `evals/README.md`, `evals/prompt_regression/metrics.py`, `evals/prompt_regression/tasks.py`, `tests/test_eval_room_metrics.py` and `tests/test_prompt_eval.py`, and nothing under `looper/`. The PR reports production lines added as 0.
- **Task wording.** The requirement no longer says the second step asks "rather than reading its saved copy". It says the second step asks the first step for the code, "must not read the saved copy itself", and that "the first step may read its own saved copy to answer". The check (`_code_matches`), `init_git` and the `min_room_consults` expectation of 1 are unchanged.
- **Metric rename.** `room_metrics` reports `room_consults_replied` instead of `room_consults_answered`; both read the API's `answered` consult state, which records a reply, including one that omits the requested value, and not that the asker used it. `room_consults` is unchanged. No count of answers the asker used is reported, because consult records have no reliable usage signal (stated in `evals/README.md`). The committed real-run baselines under `evals/prompt_regression/baselines/` still carry the old key `room_consults_answered`; the PR does not change them.
- **Tests.** A new parametrized test pins that `room_consults_replied` is reported (0 for no consults, 2 for two replied of three) and that `room_consults_answered` is absent. The task test now pins the two new requirement sentences and the `min_room_consults` expectation, and the eval's room keys use the new name.
- **Behavior change.** None in the shipped package. Running the eval changes: the requirement text differs, and results carry `room_consults_replied`, so tooling that reads `room_consults_answered` from new results must use the new key.

### Model-visible changes

None in the product: prompts, prompt contracts, the consult contract and tool schemas in the `looper` package are unchanged. The only changed model-visible text is the `room_consult` eval task's requirement, which the eval's agents (including the consult's system prompt, which carries the requirement) read when the eval runs.

### 行为变化与入口

以下在该 PR 的差异中可见。

**#1389：`room_consult` 评测措辞与 replied 计数**

- **仅评测。**差异涉及 `evals/README.md`、`evals/prompt_regression/metrics.py`、`evals/prompt_regression/tasks.py` 和两个测试文件，`looper/` 下没有任何改动；PR 报告新增生产代码行数为 0。
- **任务措辞。**需求不再写第二步“而不是读取其保存的副本”地询问，而是写明：第二步向第一步询问代码，“不得自己读取保存的副本”，第一步“可以读取自己保存的副本来作答”。检查函数 `_code_matches`、`init_git` 和 `min_room_consults` 为 1 的期望不变。
- **指标改名。**`room_metrics` 报告 `room_consults_replied`，不再报告 `room_consults_answered`；两者读取的都是 API 的 `answered` 咨询状态，它只记录有答复（包括没有所需值的答复），不表示提问方用了该答复。`room_consults` 不变。评测不报告提问方用了的答复数，因为咨询记录没有可靠的使用信号（见 `evals/README.md`）。`evals/prompt_regression/baselines/` 下已提交的真实运行基线仍使用旧键 `room_consults_answered`，PR 未修改它们。
- **测试。**新的参数化测试固定：报告 `room_consults_replied`（无咨询为 0，三次中两次有答复为 2），且不含 `room_consults_answered`。任务测试现在固定两句新的需求措辞和 `min_room_consults` 期望，评测的 room 键也改用新名称。
- **行为变化。**已发布的包中没有。运行评测时有变化：需求文本不同，结果带有 `room_consults_replied`，因此从新结果读取 `room_consults_answered` 的工具须改用新键。

**面向模型的变化：**产品中无：`looper` 包内的提示词、提示词契约、咨询契约和工具 schema 不变。唯一变化的面向模型文本是 `room_consult` 评测任务的需求，评测运行时其智能体（包括携带该需求的咨询系统提示词）会读到。
