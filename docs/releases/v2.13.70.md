# Looper v2.13.70

## Release Decision

**Who should upgrade:** Dashboard users and anyone scripting the task activity, activity detail, conversation or activity stream HTTP routes. Dashboard users see no change. Scripts that call the removed routes must move to the `/api/v1/tasks/` routes.

**What this release solves:** [#488](https://github.com/foolzzz/looper/pull/488) moves task activity history, the task conversation window and the live activity stream to the versioned API (`/api/v1/`) with typed event contracts. The four legacy GET routes for them are removed.

**Breaking changes:** Yes. The four legacy routes listed under Behavior changes no longer exist; a client that calls one gets a not-found answer. Stored tasks, activity rows, versions, steps, plans and Planner sessions are unchanged.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#488](https://github.com/foolzzz/looper/pull/488); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.70
```

## Behavior changes

- **Removed routes (breaking for API clients):** `GET /api/tasks/{id}/activity`, `GET /api/tasks/{id}/activity/{seq}`, `GET /api/tasks/{id}/activity/stream` and `GET /api/tasks/{id}/conversation`.
- **Replacements** (all `POST`, all reads, body takes `task_id`; an unknown task answers not found):
  - `/api/v1/tasks/activity` takes optional `after`, `since`, `before` and `limit`. With `after` or `since` (`after` wins) it returns the rows after that sequence, ignoring `before` (default limit 100, at most 500). Otherwise it returns a backward window, oldest first, with `has_more`, `oldest_seq` and `latest_seq` (limit clamped to 1..1000, default 1000).
  - `/api/v1/tasks/activity_detail` takes `{task_id, seq}` and returns that event with its detail. An event that belongs to another task answers not found.
  - `/api/v1/tasks/conversation` takes `before` and `limit` and returns a window of `rows` (only text, phase, error and user_message kinds, with seq, worker, kind, summary and created_at) plus the same window fields. The legacy answer called this list `conversation`; it is now `rows`.
  - `/api/v1/tasks/activity_stream` takes `since` (default 0) and streams server-sent events: `activity` events carry the full event with the SSE id equal to its `seq`, `done` carries `{}`, and idle streams send heartbeat comments.
- **Failures:** a database failure on the reads now answers `unavailable` instead of an empty successful list (`{"activity": []}` or `{"conversation": []}`). A non-integer cursor or limit is rejected by the request schema.
- **Stream:** replay and live events are joined by sequence number; live events are read from the database, so a thin bus notification can no longer reach a client as a partial event. The stream subscribes before it replays, so events during replay are queued. A task that is already finished replays and then sends `done`. A client disconnect now ends the stream and unsubscribes.
- **Typed contracts:** `ActivityEvent`, `ConversationEvent` and `ActivityDone` are declared in the OpenAPI document; the generated CLI reads the stream's media type, and `loopercli tasks activity-stream --task-id ID --since SEQ` prints each event (one `{event, data}` JSON line with `--json`).
- **Dashboard, evals and docs:** the dashboard reads history and conversation through the new routes and follows the stream with a cursor, reconnecting after a server error and subscribing again when a finished task resumes. The prompt-regression runner, the DSH validation script, the Looper client skill RFC and the long-horizon context plan follow.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt changed, and no Manager Tool schema or result changed. The change touches only HTTP routes, the dashboard and the CLI.

## Upgrade and rollback

Re-run `install.sh` once v2.13.70 is published. No data migration. Update any script or client that called a removed route before upgrading. Rolling back to v2.13.69 restores the legacy routes, with no stored data affected.

### 行为变化与入口

- **已删除的路由（对 API 客户端是破坏性的）：**`GET /api/tasks/{id}/activity`、`GET /api/tasks/{id}/activity/{seq}`、`GET /api/tasks/{id}/activity/stream`、`GET /api/tasks/{id}/conversation`。
- **替代路由**（均为 `POST`、只读，请求体带 `task_id`；未知任务返回 not found）：
  - `/api/v1/tasks/activity` 可带 `after`、`since`、`before`、`limit`。带 `after` 或 `since`（`after` 优先）时返回该序号之后的行并忽略 `before`（默认 limit 100，最多 500）；否则返回向后窗口（旧到新），含 `has_more`、`oldest_seq`、`latest_seq`（limit 夹到 1..1000，默认 1000）。
  - `/api/v1/tasks/activity_detail` 收 `{task_id, seq}`，返回含 detail 的该事件；属于其他任务的事件返回 not found。
  - `/api/v1/tasks/conversation` 收 `before` 与 `limit`，返回 `rows` 窗口（仅 text、phase、error、user_message 类，含 seq、worker、kind、summary、created_at）及同样的窗口字段。旧响应中的 `conversation` 键现为 `rows`。
  - `/api/v1/tasks/activity_stream` 收 `since`（默认 0），以 SSE 推流：`activity` 事件带完整事件，SSE id 等于 `seq`；`done` 携带 `{}`；空闲时发送心跳注释。
- **失败：**读取时数据库失败现在返回 `unavailable`，不再伪装成空的成功列表（`{"activity": []}`、`{"conversation": []}`）。非整数的游标或 limit 被请求 schema 拒绝。
- **流：**回放与实时事件按序号衔接；实时事件从数据库读取，不会再把总线上的精简通知当作不完整事件发给客户端。流先订阅再回放，回放期间的事件排队不丢。已结束的任务回放后发送 `done`。客户端断开现在会结束流并取消订阅。
- **类型化契约：**OpenAPI 文档声明了 `ActivityEvent`、`ConversationEvent`、`ActivityDone`；生成式 CLI 识别流的媒体类型，`loopercli tasks activity-stream --task-id ID --since SEQ` 逐个打印事件（`--json` 时每行一个 `{event, data}`）。
- **仪表盘、评测与文档：**仪表盘经新路由读取历史和对话，并带游标跟随流，服务器错误后重连，已结束任务恢复运行时重新订阅。prompt 回归 runner、DSH 验证脚本、Looper 客户端 skill RFC 及长程上下文计划随之更新。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 均未改动，Manager Tool 的 schema 与结果不变；变化只涉及 HTTP 路由、仪表盘和 CLI。
