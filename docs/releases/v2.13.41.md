# Looper v2.13.41

## Release Decision

**Who should upgrade:** Nobody needs to. This patch changes tests only; installed behavior is the same as v2.13.40.

**What this release solves:** [#415](https://github.com/foolzzz/looper/pull/415) is test-suite slimming, step pr4: validation parametrizations keep one value per branch, and the PostgreSQL tests share one DB helper instead of copies of it.

**Breaking changes:** No. No code under `looper/` changed apart from the version number.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#415](https://github.com/foolzzz/looper/pull/415); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.41
```

## Behavior changes

- **Product behavior:** none. All 136 files in the range since v2.13.40 are under `tests/` apart from the release files; the pull request states "Behavior changes: none". No user entry point (dashboard, Telegram, Lark, CLI) is affected.
- **Shared test helpers:** `tests/db_support.py` (new) holds the disposable database's URL, a fresh schema per test (`fresh_schema`) and a wait; the `*_db` test modules import it instead of defining their own copies. `tests/schedule_support.py` (new) holds the scheduler tests' environment. `tests/conftest.py` gains two lines.
- **Validation tests:** `tests/test_schedule_validation.py` (new) checks schedule request validation without a database; `tests/test_schedule_gate_budget_alerts_db.py` is renamed from an existing schedule test module and shortened. `tests/test_agent_db_matches_database.py` is new. Parametrizations in `tests/test_operator_auth.py`, `tests/test_reported_files.py`, `tests/test_prompt_eval.py` and others keep one value per branch.
- **Model-visible changes:** none. No prompt, tool description or `Channel:` line changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.41 is published. There is no schema change and no data migration. Rolling back to v2.13.40 needs no step.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.
