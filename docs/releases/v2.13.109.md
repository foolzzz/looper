# Looper v2.13.109

## Release Decision

**Who should upgrade:** Anyone who saves channel bots (Telegram or Lark) through the API, the dashboard or a Manager, and anyone who needs to switch off a Lark bot whose authentication is broken.

**What this release solves:** [#600](https://github.com/foolzzz/looper/pull/600) keeps the error class of a failed channel save (a fixed validation reason is reported as `invalid`, a service failure as `unavailable`, not a blanket 400) and lets an explicit disable of an unchanged Lark bot succeed without the Lark identity check.

**Breaking changes:** No. No route, request field or stored data changed; only the error code and message of some failed channel saves, and the admission of a disable.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#600](https://github.com/foolzzz/looper/pull/600); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.109
```

## Behavior changes

- **Fixed validation reasons ([#600](https://github.com/foolzzz/looper/pull/600)):** in `looper/agents/channels/bot_api.py`, the messages for a missing Telegram token, a missing Lark `app_id`, a missing app secret, a missing lark-cli profile and a Manager reassignment are now the members of `BotValidationReason`, raised as `BotValidationRefusal`. `looper/agents/v1_domains/channel_configs.py` maps that to the public `invalid` error with the fixed text. The text is chosen by the service, not built from the request.
- **Service failures keep their class:** in `_save`, a wrapped `RequestError` with a 5xx status that has no public mapping is now raised as `unavailable` with the message `invalid credential request`. The raw exception text stays private. Before, the transport turned it into a 400.
- **Same 404 with `config`:** the channel lookup that precedes a config update now runs through `_save`, so a missing channel gives the same public error whether or not the update carries `config`.
- **Lark disable without authentication:** in `update_bot`, a save with `enabled` set to false skips `refuse_same_bot` for a Lark bot when the stored secret, `profile`, `app_id`, `bot_token_env` and `domain` (default `feishu`) are unchanged, compared under the lock against the stored row. Any other Lark save, and any save that changes one of those, still revalidates. Empty and missing values compare equal.
- **Model-visible changes:** Error codes and messages that a Manager or API caller receives from a failed channel save change as above. No Manager tool declaration, prompt or API route changed.
- **Tests:** [#600](https://github.com/foolzzz/looper/pull/600) adds or extends tests in `tests/test_api_v1_catalog_errors.py`, `tests/test_api_v1_channel_configs.py`, `tests/test_api_v1_channel_configs_db.py` and `tests/test_channel_bots_api_db.py` for the fixed reasons, private service failures (including a read-only database), the missing-channel 404, and the disable admission including a change raced under the lock (212 test lines, 38 production lines as reported).

## Upgrade and rollback

Re-run `install.sh` once v2.13.109 is published. No data migration and no configuration change. Rolling back to v2.13.108 restores the earlier error mapping and the identity check on every Lark save.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**通过 API、仪表盘或 Manager 保存渠道机器人（Telegram 或 Lark）的使用者，以及需要关闭认证已失效的 Lark 机器人的使用者。

**解决了什么：**[#600](https://github.com/foolzzz/looper/pull/600) 让失败的渠道保存保留错误类别（固定的校验原因返回 `invalid`，服务故障返回 `unavailable`，不再一律 400），并允许对未改动的 Lark 机器人显式停用而不做 Lark 身份校验。

**是否有破坏性变更：**否。路由、请求字段和存储数据均未改变；只有部分失败的渠道保存的错误码与消息，以及停用的准入条件改变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.109。

**贡献者：**维护者 @foolzzz 提交 [#600](https://github.com/foolzzz/looper/pull/600)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.109
```

### 行为变化与入口

- **固定的校验原因（[#600](https://github.com/foolzzz/looper/pull/600)）：**`looper/agents/channels/bot_api.py` 中，缺少 Telegram token、缺少 Lark `app_id`、缺少应用密钥、缺少 lark-cli profile 以及更换 Manager 的提示，现在是 `BotValidationReason` 的成员，以 `BotValidationRefusal` 抛出。`looper/agents/v1_domains/channel_configs.py` 将其映射为带固定文本的公开 `invalid` 错误。文本由服务选定，不由请求内容拼出。
- **服务故障保留类别：**`_save` 中，没有公开映射的 5xx `RequestError` 现在以 `unavailable` 抛出，消息为 `invalid credential request`，原始异常文本仍不公开。此前传输层会把它变成 400。
- **带 `config` 时 404 一致：**配置更新前的渠道查询现在也经过 `_save`，因此渠道不存在时，无论更新是否带 `config`，公开错误相同。
- **无需认证即可停用 Lark：**`update_bot` 中，`enabled` 设为 false 的保存，若存储的密钥、`profile`、`app_id`、`bot_token_env` 和 `domain`（默认 `feishu`）均未改变（在锁内与存储行比较），则对 Lark 机器人跳过 `refuse_same_bot`。其他 Lark 保存以及改动上述任一项的保存仍会重新校验。空值与缺失值视为相等。
- **面向模型的变化：**Manager 或 API 调用方从失败的渠道保存收到的错误码和消息按上述方式改变。Manager 的 tool 声明、提示词和 API 路由均未改变。
- **测试：**[#600](https://github.com/foolzzz/looper/pull/600) 在 `tests/test_api_v1_catalog_errors.py`、`tests/test_api_v1_channel_configs.py`、`tests/test_api_v1_channel_configs_db.py` 和 `tests/test_channel_bots_api_db.py` 中新增或扩展测试，覆盖固定原因、私有的服务故障（含只读数据库）、渠道不存在的 404，以及停用准入（含锁内竞态改动）（按报告测试 212 行、生产代码 38 行）。

### 升级与回退

v2.13.109 发布后重跑 `install.sh`。无需迁移数据，无需改配置。回退到 v2.13.108 会恢复之前的错误映射，以及每次 Lark 保存都做身份校验。
