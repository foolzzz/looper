# Looper v2.13.8

## Release Decision

**Who should upgrade:** Operators who want the Manager to run a different Agent Profile for one conversation (for example Claude Code, then OMP with DeepSeek, then back) without editing the Manager role's settings. Everyone else sees no change until they use `/profile`.

**What this release solves:** [#287](https://github.com/foolzzz/looper/pull/287) lets the operator choose the Manager session's Agent Profile when starting a new session on the dashboard, and switch it from the conversation with `/profile` (dashboard chat, Telegram and Lark) or from the chat header.

**Breaking changes:** No. The CLI, configuration export and import, and existing API routes are unchanged from [v2.13.7](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.7.md). A session with no choice resolves its profile exactly as before. The schema gains one nullable column, added idempotently at startup.

**How to verify:** Check the version, then send `/profile` to the Manager.

**Contributors:** Maintainer @foolzzz authored [#287](https://github.com/foolzzz/looper/pull/287); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.8
```

## Behavior changes

- **Session choice.** `agent_sessions.selected_profile_id` (new nullable column, foreign key to `agent_profiles` with `ON DELETE RESTRICT`, allowed only on the `manager` row) stores the Agent Profile chosen for the Manager's current session. Resolution gains a last layer, `session`, for the Manager only: session choice, then the manager role layer, then shared defaults, then the built-in profile. Runs record `"source": "session"`. `save_session` never writes the column, so the Manager's in-memory state cannot overwrite a choice.
- **`/profile` command.** Looper answers it itself, like `/new`, without calling the model. `/profile` lists the profiles that can run the Manager (numbered, with what choosing each does: current, resumes, new session, starts); `/profile <number|id|name>` selects; `/profile 0` follows the Settings again. `/profiles` and similar are not the command. A choice with a missing key, login or model binding is refused with the reason. Selecting the current choice answers "no change".
- **When a switch takes effect.** On the next user message, never inside a running turn, from any channel (the session is global). The same runtime and provider resumes the session with full context; otherwise the old session writes a handoff first (up to 5 minutes) and a new session starts with the handoff and recent chat excerpts, not the old conversation text. Each switch is recorded as a Runs entry (`metadata.session_profile`, cost 0).
- **`/new`.** Clears the choice (back to following the Settings). The dashboard's new-session panel can start the new session with a chosen profile; `POST /api/chat/send` accepts `new_session_profile_id`, valid only with `/new` to the Manager (otherwise 400), validated before and again when applied; if invalid nothing is reset.
- **Profile errors.** If the Manager's profile cannot launch, the turn still answers with an error and never falls back to another profile; when the profile came from the session or the role layer the error now adds a hint to send `/profile` (or `/profile 0`).
- **Registry.** Deleting a profile that a Manager session selects is refused, and the refusal names "the Manager's current session"; editing it so it can no longer run the Manager is refused.
- **HTTP API.** New `GET /api/manager/session` (active session, runtime, selected, effective profile and source, problem, choices; no session id) and `PUT /api/manager/session/profile` (`{"profile_id": id|null}`; 400 for unknown or unusable profiles, 503 when the Manager is not running). Both are operator routes.
- **Channels.** Telegram registers `/profile` (menu entry and help text) and forwards it as `/profile [choice]`; Lark text is forwarded unchanged and a test pins it. Both stay behind the sender allowlist.
- **Dashboard.** The chat header shows the Manager session's profile and switches it (with a confirmation where choosing starts a new session); the new-session panel picks a profile.
- **Model-visible changes:** Two. The Manager's tools contract gains a paragraph: the user switches the conversation's profile with `/profile` and starts a new one with `/new`, Looper answers both, the model cannot switch and should tell the user to send `/profile`, and setting the manager role's profile with `looper_settings` applies to later sessions when this one has its own choice. `looper_settings` gains the sentence "The Manager's current session may run its own profile (/profile)." in its description, and its `view` (role `manager`) and `set` (manager role, no project) answers carry `manager_session.selected` (profile id and name, or null), plus a `note` after `set` when a choice exists. No other prompt or tool schema changed.

## Entry points

New: `/profile` in Manager chats (dashboard, Telegram, Lark), the chat header selector, the new-session panel, `GET /api/manager/session`, `PUT /api/manager/session/profile`, and `new_session_profile_id` on `POST /api/chat/send`. Evals gain Manager dialogs for switching and an example `omp-deepseek` agent file. No CLI command was added.

## Upgrade and rollback

Re-run `install.sh` once v2.13.8 is published. The column and its check constraint are added at startup and existing rows stay empty, so behavior is unchanged until a choice is made. Rolling back to v2.13.7 is safe: the older program ignores the column, but deleting a selected profile there may fail on the foreign key (an error, no data loss).

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 升级决策

**谁需要升级：**想让 Manager 在某一次会话里改用别的 Agent Profile（例如 Claude Code、OMP + DeepSeek、再切回）而不改 Manager 角色设置的运营者。其他人在使用 `/profile` 之前没有变化。

**解决了什么：**[#287](https://github.com/foolzzz/looper/pull/287) 让运营者在控制台新建 Manager 会话时选择 Agent Profile，并可在对话中用 `/profile`（控制台聊天、Telegram、飞书）或聊天页头部切换。

**是否有破坏性变更：**无。CLI、配置导入导出和现有 API 路由与 [v2.13.7](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.7.md) 相同；没有选择的会话解析 Profile 的方式不变。schema 新增一个可空列，启动时幂等添加。

**如何验证：**核对版本，再向 Manager 发送 `/profile`。

**贡献者：**维护者 @foolzzz 提交 [#287](https://github.com/foolzzz/looper/pull/287)；本次 patch release 无社区贡献。

### 行为变化与入口

- 会话选择：新增可空列 `agent_sessions.selected_profile_id`（外键指向 `agent_profiles`，`ON DELETE RESTRICT`，只允许 `manager` 行非空）。管家的解析链新增最后一层 `session`：会话选择 > 角色层 > 系统层 > 内置；运行记录写 `"source": "session"`。`save_session` 不写该列。
- `/profile` 命令：由 Looper 自己回答，不调用模型。无参数列出能跑 Manager 的 Profile（带编号和选择后的效果：当前、续接、新会话、新开）；`/profile <编号|id|名称>` 选择；`/profile 0` 恢复跟随设置。key、登录或模型绑定有问题的选项会被拒绝并说明原因；选当前项回复"没有变化"。
- 生效时机：下一条用户消息，从不打断进行中的一轮，任何渠道均可（会话是全局的）。同运行时同 provider 续接，上下文完整；否则旧会话先写交接（至多 5 分钟），新会话只拿到交接和最近对话摘录。每次切换记一条 Runs（`metadata.session_profile`，费用 0）。
- `/new` 清除选择；控制台新建会话面板可带 Profile。`POST /api/chat/send` 接受 `new_session_profile_id`，只在发给 Manager 的 `/new` 上有效（否则 400），前后各校验一次，不合格则什么都不重置。
- Profile 报错：Manager 的 Profile 无法启动时仍以错误回复、从不回退到其他 Profile；来自会话层或角色层时，错误末尾新增发送 `/profile`（或 `/profile 0`）的提示。
- 注册表：被 Manager 会话选中的 Profile 不能删除（提示"the Manager's current session"），也不能改成跑不了 Manager。
- HTTP API：新增 `GET /api/manager/session`（不含会话 id）和 `PUT /api/manager/session/profile`（`{"profile_id": id|null}`；未知或不可用为 400，Manager 未运行为 503），均为操作者路由。
- 渠道：Telegram 注册 `/profile`（菜单与帮助）并转发为 `/profile [选项]`；飞书文字原样转发，由测试钉住；均受发送者白名单限制。
- 控制台：聊天页头部显示并切换会话 Profile（会开新会话的选项先确认），新建会话面板可选 Profile。evals 新增 Manager 切换对话和 `omp-deepseek` 示例。未新增 CLI 命令。
- 面向模型的变化：两处。Manager 的工具契约新增一段：用户用 `/profile` 切换、`/new` 新开，Looper 自己回答，模型不能切换，被要求时请用户发送 `/profile`；本会话有自己的选择时，用 `looper_settings` 设置 manager 角色的 Profile 只对之后的会话生效。`looper_settings` 的描述新增一句 "The Manager's current session may run its own profile (/profile)."，其 `view`（role 为 manager）与 `set`（manager 角色、不带项目）的结果带 `manager_session.selected`（Profile id 与名称，或 null），有选择时 `set` 另带 `note`。其余提示词与工具 schema 未变。

### 升级与回退

发布后重跑 `install.sh`。该列及其约束在启动时添加，已有行为空，未做选择前行为不变。回退到 v2.13.7 安全：旧版本忽略该列，但在旧版本删除被选中的 Profile 时可能撞上外键（报错，不丢数据）。

本版本未新增可选能力启用入口。
