# Looper v2.14.12

This is the patch release v2.14.12. It ships the one change merged since v2.14.11: [#895](https://github.com/foolzzz/looper/pull/895), which gives a DSH runner consult the same default context as the CLI consult.

## Release Decision

**Who should upgrade:** Operators who run the DSH runner (`[runtimes] dsh = "runner"`) and use room consults. Installations on the DSH CLI path, or without DSH, see no change. It ships the one change merged since v2.14.11.

**What this release solves:** [#895](https://github.com/foolzzz/looper/pull/895): a room consult forked on the DSH runner dropped the DSH default system guidance and tool declarations that the CLI consult carries, and was reported to answer in the Worker report format about 1 time in 11 on the runner against 0 in 9 on the CLI path. The fork now carries the same guidance and declarations. The format failure itself was not reproduced in the validation sample, so this release does not claim it is cured.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#895](https://github.com/foolzzz/looper/pull/895); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.12
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.11 upgrades directly. This release changes no schema, stored data or setting.

## Behavior changes

Only a consult on the DSH runner changes. Worker, Reviewer and CLI-path runs behave as in v2.14.11.

- **Default guidance and tool declarations in the fork:** the runner builds a declaration-only copy of the installed DSH composition (`runners/dsh/src/sdk.ts`, which now also loads `dsh-system-prompt`), takes its assembled system prompt and tool declarations, and releases the copy before the normal runner boots. A forked session (`runners/dsh/src/session.ts`) puts that default text before Looper's consult prompt and registers the default declarations it does not already have.
- **Execution stays read-only:** the added declarations that are not `read`, `glob` or `grep` are inert; calling one returns an error containing `LOOPER_READ_ONLY`, and the existing path guard and read-only admission still apply to every call. A new test declares `write`, `bash`, `subagent` and `web_fetch`, calls each, and checks that all are refused and no file is created.
- **Fork seed boundary:** the seed now ends after standalone events that follow `turn/end` (for example a session title), stopping at the next `turn/start`, inbox splice or appended user message. Before, a standalone event between `turn/end` and a dropped-steer replacement cut the seed off, so the replacement was missed. Tests cover an unfinished next turn staying out of the consult.
- **Runtime notes:** for a consult, `looper/agents/runtimes/dsh_runner.py` no longer appends the line that tells the model Looper's platform tools are named `looper_*`; other runs keep it.
- **Cost:** the first consult request is larger. In the synthetic measurement in the plan (a fixed ended Worker history, `deepseek-flash`), the system text grew from 11,887 to 13,720 bytes, the declarations from 3 to 24, and the first request from 4,035 to 8,621 input tokens, about 114% more.
- **Tooling and docs:** `evals/dsh_consult_replay.py` is an opt-in replay of a captured consult against a real model, never run in the default tests; the plan `docs/plans/2026-10-29-dsh-consult-validation.md` and the eval README describe it.
- **Model-visible changes:** Yes, for a DSH runner consult only. Its system prompt now includes the DSH default guidance ahead of the consult prompt, its request declares the default tool set (24 declarations in the measurement) instead of 3, its history includes standalone events kept by the new seed boundary, and it no longer sees the `looper_*` naming note. Other prompts, tools and requests are unchanged.

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.11 上的安装可直接升级。本版本不改 schema、已存数据或设置。

### 行为变化与入口

只有 DSH runner 上的 consult 发生变化。Worker、Reviewer 和 CLI 路径的运行与 v2.14.11 相同。

- **分叉中的默认指导与工具声明：**runner 构建一个只含声明的已安装 DSH composition 副本（`runners/dsh/src/sdk.ts`，现在还会加载 `dsh-system-prompt`），取出其组装好的系统提示和工具声明，并在正常 runner 启动前释放该副本。分叉会话（`runners/dsh/src/session.ts`）把这段默认文本放在 Looper 的 consult 提示之前，并注册它还没有的默认声明。
- **执行仍为只读：**新增的、不是 `read`、`glob`、`grep` 的声明不会执行；调用它们返回含 `LOOPER_READ_ONLY` 的错误，原有路径检查和只读准入仍然作用于每次调用。新测试声明了 `write`、`bash`、`subagent` 和 `web_fetch`，逐个调用，检查全部被拒绝且没有创建文件。
- **分叉种子边界：**种子现在包含 `turn/end` 之后的独立事件（例如会话标题），直到下一个 `turn/start`、inbox 拼接或追加的用户消息为止。此前 `turn/end` 与被丢弃 steer 的替换事件之间若有独立事件，种子会被截断，漏掉替换。测试覆盖了未完成的下一轮不进入 consult。
- **运行时说明：**consult 时 `looper/agents/runtimes/dsh_runner.py` 不再追加“Looper 平台工具名为 `looper_*`”那一行；其他运行保留。
- **成本：**第一个 consult 请求变大。在计划文档的合成测量中（固定的已结束 Worker 历史，`deepseek-flash`），系统文本从 11,887 字节增至 13,720 字节，声明从 3 个增至 24 个，首请求从 4,035 增至 8,621 输入 token，约增加 114%。
- **工具与文档：**`evals/dsh_consult_replay.py` 是对已捕获 consult 用真实模型重放的可选工具，默认测试不会运行；计划文档 `docs/plans/2026-10-29-dsh-consult-validation.md` 和 eval README 对其作了说明。
- **面向模型的变化：**有，仅限 DSH runner 的 consult。其系统提示在 consult 提示之前包含 DSH 默认指导，请求声明默认工具集（测量中为 24 个）而不是 3 个，历史包含新种子边界保留的独立事件，并且不再看到 `looper_*` 命名说明。其他提示、工具和请求不变。
