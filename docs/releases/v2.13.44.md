# Looper v2.13.44

## Release Decision

**Who should upgrade:** No one needs to. This release changes tests and CI only; the installed program is the same as v2.13.43 apart from its version number.

**What this release solves:** [#422](https://github.com/foolzzz/looper/pull/422) slims the test suite (step pr3): the stop-matrix tests run each shared stop and runtime code path once, and the tests that need an installed runtime CLI or a browser move to a nightly workflow.

**Breaking changes:** No. Nothing under `looper/` changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#422](https://github.com/foolzzz/looper/pull/422); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.44
```

## Behavior changes

- **Runtime behavior:** none. The pull request touches no file under `looper/`, and its description states "Behavior changes: none".
- **Tests** (`tests/`): `test_stop_matrix.py` runs each shared code path on one runtime. Codex runs every window of the per-turn-process path; OMP, pi and DSH run only the streaming and tool windows that read their own event streams. The manager-level matrix runs the phases that do not touch a runtime on one runtime. Overlapping cases in `test_manager_stop.py`, `test_resident_claude_interrupt.py`, `test_grok_acp.py`, `test_dsh_runtime.py` and the Pi tests are removed or trimmed, and `stop_matrix_support.py` is adjusted to match. Tests that need an installed runtime CLI or a browser carry the new `installed` marker.
- **CI** (`.github/workflows/`): a new workflow `installed-tests.yml` runs the tests marked `installed` nightly and on manual dispatch, against a PostgreSQL service with Chromium, the pinned Pi package and, when it installs, the pinned DSH package; it writes a summary of skipped tests. `python-tests.yml` now runs the main suite with `-m "not installed and not provenance"`. `pyproject.toml` registers the `installed` pytest marker.
- **Docs:** the Chinese stop RFC (`docs/architecture/rfcs/chat-stop-v2.zh-CN.md`) updates its test table and the stop-matrix description to the new coverage.
- **Model-visible changes:** none. No prompt text, tool description, tool schema or `Channel:` line changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.44 is published. There is no schema change and no data migration. Rolling back to v2.13.43 needs no step.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.
