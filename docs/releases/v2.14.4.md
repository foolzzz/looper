# Looper v2.14.4

This is the patch release v2.14.4. It ships the one change merged since v2.14.3: [#876](https://github.com/foolzzz/looper/pull/876), DSH runner platform tools over reverse `tools/call`, an isolated session bash, path confinement, in-trace steer and consult forks, which no running code uses yet.

## Release Decision

**Who should upgrade:** Operators on v2.14.3 who want the current main line, and developers who continue the DSH runner work. Nothing an operator can see changes. It ships the one change merged since v2.14.3.

**What this release solves:** [#876](https://github.com/foolzzz/looper/pull/876) completes the packaged DSH runner's session behavior: platform tools run only through the host, the session's bash and file tools are confined to the task directory, a running turn can be steered, and a read-only consult can be forked from a completed turn. The runner is still not registered as a runtime, has no setting and has no entry in the Dashboard, Telegram, Lark or CLI.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#876](https://github.com/foolzzz/looper/pull/876); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.4
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0, v2.14.1, v2.14.2 or v2.14.3 upgrades directly. This release changes no schema, configuration format or stored data.

## Behavior changes

- **Platform tools (`runners/dsh/src/tools.ts`, `runners/dsh/src/turn.ts`):** `session/prompt` now accepts a platform tool list instead of failing with `-32007` for a non-empty one.
  - Each prompt's list is a snapshot. A name must match `[A-Za-z0-9_-]+`, be unique, not be a built-in (`read`, `glob`, `grep`, `write`, `edit`, `bash`) or `run_code`, and carry a description and an object input schema; otherwise the prompt fails with `-32602`. Tools whose definition changed or that left the snapshot are unregistered; the allowed set becomes the built-ins plus the snapshot.
  - A platform tool executes only by a reverse `tools/call` to the host with the session, trace, call id, name and arguments. A host `is_error` answer becomes a tool failure with the host's text. A transport failure or an abort becomes a tool failure (an abort says the call may still have run); no `rpc/cancel` is sent. A call that starts after the turn is settled, settling, cancelled or aborted fails without calling the host.
- **Session bash (`runners/dsh/src/exec.ts`, `runners/dsh/src/session.ts`):** a `bash` tool is registered when the session enables it.
  - It runs `/bin/bash --noprofile --norc -c` in a detached process group, started by a separate executor process, with exactly the session's environment plus the session's private `HOME`, in the session cwd (or a `workdir` that passes the path check).
  - Every call is clamped to the session's `tool_timeout_s` (a smaller `timeoutMs` is honored). Output keeps the last 100 KiB, marked as truncated, followed by the exit code, signal or timeout.
  - Timeout and cancel send SIGTERM to the group and SIGKILL after 2 seconds. Cancel settle, forced release, session close and shutdown kill the group; the executor kills its group if the runner disappears. `runner/health` reports the live process groups as `tool_processes`.
  - The SDK's own output-spill policy is disabled so the host's result is not rewritten a second time (`runners/dsh/src/sdk.ts`).
- **Path confinement (`runners/dsh/src/exec.ts`):** `read`, `write`, `edit`, `glob` and `grep` calls are checked before they run. The target is resolved through symlinks (the longest existing prefix for new files) and must lie in the cwd or an added directory. A path starting with `~`, an empty path, a symlink that escapes, a dangling link, and an absolute or `..` glob or include pattern are denied with `LOOPER_PATH`.
- **Steer (`runners/dsh/src/turn.ts`, `runners/dsh/src/provider.ts`, `runners/dsh/src/main.ts`):** `initialize` now declares `steer` (`in_trace`, boundary `next_step`, `idle_start` false) and `fork`. The runner serves `session/steer`.
  - It needs a running turn (`-32004` otherwise), the same trace (`-32005`), `if_idle` of `reject`, and a non-empty message id and text (`-32602`); it answers `queued`. A repeated message id is ignored.
  - The steer is forwarded to the agent once the turn has started and runs. `steer_applied` is emitted only when a request that was actually sent carries the steer message, with the preceding request id and whether it followed a tool batch.
  - A steer not applied by the end of the turn, or at cancel or close, is removed and `steer_dropped` is emitted with reason `turn_ended`, `cancelled` or `session_closed`. A steer already claimed by the agent is replaced in the saved history by an empty message so the dropped text is not kept.
- **Consult fork (`runners/dsh/src/session.ts`):** `session/new` accepts `fork_from`.
  - It requires a `worker` or `reviewer` role and a read-only tool set (`-32008`), and a source session id (`-32602`). `session/load` refuses a fork (`-32602`).
  - The source is opened read-only and the new session id is seeded with the source's history up to its last completed turn (`-32001` when it has none). The source is unchanged. Closing the fork deletes its stored copy.
- **Tests and plan (`tests/test_dsh_runner_tools.py`, `tests/test_dsh_runner.py`, `tests/test_dsh_runner_sessions.py`, `tests/test_dsh_runner_turns.py`, `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`):** new tool, bash, path, steer and fork tests; the existing tests are adjusted for the changed failures; the plan records the work and what is still missing.
- **Model-visible changes:** None for a running system, because the DSH runner is not reachable from any runtime. Once a host runs a turn, the model sees the host's platform tools under their names, a `bash` tool with the description above, `LOOPER_PATH` denials for paths outside the task directory, and a steer text as an additional user message at the next step.

### 行为变化与入口

- **平台工具（`runners/dsh/src/tools.ts`、`runners/dsh/src/turn.ts`）：**`session/prompt` 现接受平台工具列表，不再对非空列表返回 `-32007`。
  - 每个 prompt 的列表是一份快照。名称须匹配 `[A-Za-z0-9_-]+`、唯一、不是内置工具（`read`、`glob`、`grep`、`write`、`edit`、`bash`）或 `run_code`，并带描述和对象类型的输入 schema，否则 prompt 以 `-32602` 失败。定义变化或离开快照的工具会被注销；允许集合为内置工具加快照。
  - 平台工具只通过向宿主的反向 `tools/call` 执行，带会话、trace、调用 id、名称和参数。宿主返回 `is_error` 时成为带宿主文本的工具失败；传输失败或中止成为工具失败（中止的提示说明调用可能已经执行）；不发送 `rpc/cancel`。turn 已结算、结算中、已取消或已中止后才开始的调用直接失败，不再调用宿主。
- **会话 bash（`runners/dsh/src/exec.ts`、`runners/dsh/src/session.ts`）：**会话启用时注册 `bash` 工具。
  - 由独立的执行器进程以 `/bin/bash --noprofile --norc -c` 在分离的进程组中运行，环境严格为会话环境加会话私有 `HOME`，工作目录为会话 cwd（或通过路径检查的 `workdir`）。
  - 每次调用都被限制在会话的 `tool_timeout_s` 内（更小的 `timeoutMs` 生效）。输出保留最后 100 KiB 并标注截断，随后是退出码、信号或超时。
  - 超时和取消先对进程组发 SIGTERM，2 秒后发 SIGKILL。取消结算、强制释放、会话关闭和退出都会杀进程组；runner 消失时执行器会杀掉其进程组。`runner/health` 的 `tool_processes` 报告存活的进程组数。
  - 关闭 SDK 自身的输出落盘策略，避免宿主结果被二次改写（`runners/dsh/src/sdk.ts`）。
- **路径限制（`runners/dsh/src/exec.ts`）：**`read`、`write`、`edit`、`glob` 和 `grep` 在执行前检查。目标经符号链接解析（新文件取最长已存在前缀），必须位于 cwd 或附加目录内。以 `~` 开头、空路径、逃逸的符号链接、悬空链接，以及绝对路径或含 `..` 的 glob/include 模式，均以 `LOOPER_PATH` 拒绝。
- **Steer（`runners/dsh/src/turn.ts`、`runners/dsh/src/provider.ts`、`runners/dsh/src/main.ts`）：**`initialize` 现声明 `steer`（`in_trace`，边界 `next_step`，`idle_start` 为 false）和 `fork`；runner 提供 `session/steer`。
  - 需要运行中的 turn（否则 `-32004`）、相同 trace（`-32005`）、`if_idle` 为 `reject`、非空的消息 id 和文本（`-32602`）；返回 `queued`。重复的消息 id 被忽略。
  - turn 启动并运行后才转交给 agent。仅当一个真正发出的请求带有该 steer 消息时才发出 `steer_applied`，含上一请求 id 及是否紧随工具批次。
  - turn 结束、取消或关闭时仍未应用的 steer 被移除并发出 `steer_dropped`，原因为 `turn_ended`、`cancelled` 或 `session_closed`。已被 agent 取走的 steer 在已保存历史中替换为空消息，不保留被丢弃的文本。
- **Consult fork（`runners/dsh/src/session.ts`）：**`session/new` 接受 `fork_from`。
  - 要求角色为 `worker` 或 `reviewer` 且为只读工具集（否则 `-32008`），并要有来源会话 id（`-32602`）；`session/load` 拒绝 fork（`-32602`）。
  - 以只读方式打开来源，新会话 id 以来源最后一个已完成 turn 之前的历史为种子（没有则 `-32001`）。来源不变。关闭 fork 会删除其保存的副本。
- **测试与计划（`tests/test_dsh_runner_tools.py`、`tests/test_dsh_runner.py`、`tests/test_dsh_runner_sessions.py`、`tests/test_dsh_runner_turns.py`、`docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`）：**新增工具、bash、路径、steer 和 fork 测试；既有测试按变化的失败行为调整；计划文档记录了这项工作及仍缺的部分。
- **面向模型的变化：**对运行中的系统无，因为任何运行时都无法到达 DSH runner。宿主一旦运行 turn，模型会看到宿主平台工具（按其名称）、上述 `bash` 工具、对任务目录之外路径的 `LOOPER_PATH` 拒绝，以及下一步中作为额外用户消息出现的 steer 文本。
