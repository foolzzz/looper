# Looper v2.14.157

This is the patch release v2.14.157, a hotfix line in which each merged change ships at once. It documents one change: [#1265](https://github.com/foolzzz/looper/pull/1265) (room guidance for runs that get deliveries).

## Release Decision

**Who should upgrade:** Operators who run Claude Code Workers or Reviewers in a task room. Everyone else sees only the changed `looper_room_inbox` tool description.

**What this release solves:** [#1265](https://github.com/foolzzz/looper/pull/1265) aligns the room guidance with the push delivery already merged: a run that receives room messages already has their text and should not poll the inbox.

**Breaking changes:** No. There is no API change, no migration and no schema change; behavior changes are listed below. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.157
```

**Contributors:** Maintainer @foolzzz authored [#1265](https://github.com/foolzzz/looper/pull/1265); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.156 upgrades directly. There is no schema change.

## Behavior changes

- **Guidance follows the run's delivery** ([#1265](https://github.com/foolzzz/looper/pull/1265), `looper/agents/room.py`: new `RoomInput` with `PULL`, `PUSHED`, `PUSHED_WAITS`; `looper/agents/tiers/worker.py`: `room_input`). A run whose runtime gets room messages as user turns while it runs (Claude Code) is told that messages for it, interface posts and answers arrive with their text in a `[Looper room]` message after a tool result, to use `looper_room_inbox` only when a delivery says more are waiting, and `looper_room_read` for earlier ones. Other runs keep the old guidance: read the inbox at a milestone, before the report and before building on another step's interface.
- **Workers and waiting.** A pushed Worker whose runtime can wait idle is told to go on with independent work and, when it needs an answer and has nothing else left, to wait with a waiting report; deliveries can arrive as a turn of their own while it waits. A pushed Worker without that capability is told to wait with `looper_room_inbox` and `wait_seconds`; a pull Worker, to use them only when it cannot go on without the answer, and that it is not a timer. Reviewers do not use waiting reports; a pushed Reviewer reads with `looper_room_read`.
- **Tool description and first turn.** The `looper_room_inbox` description says every room tool's answer carries the unread counts and that `wait_seconds` is for a message the run cannot go on without, not a timer. For a delivered run it is replaced by a shorter text: messages are delivered, `wait_seconds` is not needed, use the inbox only when a delivery says more are waiting (plus "use a waiting report" for waiting Workers). The first turn's Unread line ends "They will be delivered to you." instead of "Read them with looper_room_inbox." for delivered runs.
- **Grant mode.** The room token grant records the input mode (`mode`, default `pull`); an invalid value in a stored grant is rejected, and a grant without it reads as `pull`.
- **Planner guide.** One addition: do not tell steps to check, poll or wait on `looper_room_inbox`, since Looper delivers to steps that can receive and tells the others how to read; a seat whose step ended still answers questions from its session. The Planner's first turn and waiting report contract are unchanged.
- **Eval metric.** `evals/prompt_regression/metrics.py` counts inbox waits woken by a delivery as `room_inbox_woken_by_delivery`, and no longer counts them in `room_inbox_empty`.
- **Tests and docs.** Changed tests: `tests/test_room.py`, `test_room_db.py`, `test_room_ops.py`, `test_mcp_server.py`, `test_worker_run_handles.py`, `test_eval_room_metrics.py`; `docs/architecture/agent-system.md` describes delivery and guidance in one place. Dashboard, Telegram/Lark and CLI are unchanged.
- **Model-visible changes:** Yes. Worker and Reviewer room sections of the system prompt (by delivery mode), the "Unread" line of the first turn, the `looper_room_inbox` tool description (on every runtime) and the Planner's room guide changed. The PR states that a real-mode prompt eval is still pending.

### 升级

### 行为变化与入口

- **指引随运行的投递方式变化**（[#1265](https://github.com/foolzzz/looper/pull/1265)，`looper/agents/room.py` 新增 `RoomInput`：`PULL`、`PUSHED`、`PUSHED_WAITS`；`looper/agents/tiers/worker.py` 的 `room_input`）。运行期间能以用户回合接收房间消息的运行时（Claude Code）被告知：发给它的消息、接口帖子和答复会连同正文，在工具结果之后以 `[Looper room]` 消息到达；仅当投递提示还有更多待读时才用 `looper_room_inbox`，更早的消息用 `looper_room_read`。其他运行保持原指引：在里程碑、写报告前、依赖其他步骤接口前读收件箱。
- **Worker 与等待。**能空闲等待的推送 Worker 被告知先做独立工作，需要答复且无事可做时用等待报告；等待期间投递可作为单独回合到达。无此能力的推送 Worker 用 `looper_room_inbox` 与 `wait_seconds` 等待；拉取式 Worker 仅在离不开答复时使用，且它不是计时器。Reviewer 不用等待报告；推送式 Reviewer 用 `looper_room_read` 读取。
- **工具描述与首轮。**`looper_room_inbox` 描述说明每个房间工具的答复都带未读计数，`wait_seconds` 只用于离不开的消息，不是计时器。对有投递的运行，描述换成更短的文字：消息会投递给你，不需要 `wait_seconds`，仅当投递提示还有更多时才用收件箱（等待型 Worker 另加“用等待报告”）。有投递的运行，首轮的 Unread 行以“They will be delivered to you.”结尾，取代“Read them with looper_room_inbox.”。
- **授权模式。**房间令牌授权记录输入模式（`mode`，默认 `pull`）；已存授权中的无效值会被拒绝，缺省按 `pull` 读取。
- **Planner 指南。**新增一条：不要让步骤检查、轮询或等待 `looper_room_inbox`，因为 Looper 会向能接收的步骤投递，并告诉其他步骤如何读取；步骤已结束的席位仍会从其会话回答问题。Planner 的首轮和等待报告约定不变。
- **评测指标。**`evals/prompt_regression/metrics.py` 把由投递唤醒的收件箱等待计为 `room_inbox_woken_by_delivery`，不再计入 `room_inbox_empty`。
- **测试与文档。**`tests/test_room.py`、`test_room_db.py`、`test_room_ops.py`、`test_mcp_server.py`、`test_worker_run_handles.py`、`test_eval_room_metrics.py` 更新；`docs/architecture/agent-system.md` 将投递与指引合并为一处说明。仪表盘、Telegram/Lark 和 CLI 不变。
- **面向模型的变化：**有。Worker 和 Reviewer 系统提示词的房间部分（按投递方式）、首轮的 Unread 行、`looper_room_inbox` 工具描述（所有运行时）以及 Planner 的房间指南已改动。PR 说明真实模式的提示词评测尚未运行。
