# Looper v2.13.166

## Release Decision

**Who should upgrade:** No one needs this release for a behavior change. It adds a runner supervisor that nothing in Looper calls yet, and changes how a lost runner turn is settled inside the runner code. Everyone can stay on v2.13.165.

**What this release solves:** [#751](https://github.com/foolzzz/looper/pull/751) adds `RunnerSupervisor`, which owns runner processes and bounds how many sessions each may hold, and lets a turn settle as `lost` when its runner goes away.

**Breaking changes:** No. No API, database schema, configuration, prompt or Tool declaration changed, and no existing code path uses the new supervisor.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#751](https://github.com/foolzzz/looper/pull/751); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.166
```

## Behavior changes

- **Runner supervisor ([#751](https://github.com/foolzzz/looper/pull/751)):** the new `looper/agents/runtimes/runner/supervisor.py` defines `RunnerSupervisor`. A search of `looper/` finds no caller outside that file, so no running Looper behavior changes yet. When used, it:
  - starts each configured kind as one process with an absolute argv, an environment limited to `PATH`, locale and `TZ` variables plus a private `HOME` and `TMPDIR`, in a `0700` directory under `<runtime root>/runners/<kind>-<n>`;
  - admits sessions through leases, each with private `home`, `native` and `agent` directories, up to the smaller of the configured cap (default 4) and the runner's `max_sessions` (1 unless the runner reports `per_session_isolation`); a full runner raises `ProtocolError(CAPACITY)`;
  - restarts a crashed runner with backoff from 1 s doubling to 60 s, and stops restarting after five failures within ten minutes; configuration or protocol-version errors are final;
  - on `stop()`, releases leases, closes stdin and waits up to 5 s before ending the process tree. Runner stderr is redacted, capped at 8 KiB retained, and logged at most 10 lines per second.
- **Lost turns ([#751](https://github.com/foolzzz/looper/pull/751)):** `Outcome` in `turn.py` gains the host-owned value `lost`, which the wire protocol does not carry. A lost settlement accepts a `requests` count that may be below the number of started requests, never sets `usage_complete`, drops cost, is not turned into `capped` or `max_requests` by a cap, and does not re-read settings. Settlement now clears outstanding request reservations. `bridge.py` counts completed `request_end` callbacks (`requests_ended`) and reports that count when it settles a turn as lost after a connection failure.
- **Model-visible changes:** none. No prompt, tool description or tool schema changed.
- **Tests:** `tests/test_runner_supervisor.py` is added and `tests/test_runner_bridge.py` is extended.
- **Description mismatch:** the description of #751 says "approximately 530 changed lines" and then "tests 561, production 469"; the file list shows 469 added production lines and 561 added test lines, which this draft takes as authoritative.

## Upgrade and rollback

Re-run `install.sh` once v2.13.166 is published; there is no migration and no configuration change. Rolling back to v2.13.165 removes the unused supervisor.

### 行为变化与入口

- **Runner supervisor（#751）：**新增 `looper/agents/runtimes/runner/supervisor.py` 中的 `RunnerSupervisor`。在 `looper/` 中搜索，该文件之外没有调用方，因此运行中的 Looper 行为暂无变化。使用时它会：
  - 每种已配置的 kind 只启动一个进程，使用绝对路径 argv，环境仅保留 `PATH`、语言环境和 `TZ` 变量，外加私有的 `HOME` 与 `TMPDIR`，位于 `<runtime root>/runners/<kind>-<n>` 下权限为 `0700` 的目录；
  - 通过 lease 准入会话，每个 lease 有私有的 `home`、`native`、`agent` 目录，数量上限为配置的上限（默认 4）与 runner 的 `max_sessions` 中的较小者（除非 runner 报告 `per_session_isolation`，否则为 1）；已满时抛出 `ProtocolError(CAPACITY)`；
  - runner 崩溃后按 1 秒起翻倍至 60 秒的退避重启，十分钟内失败五次后不再重启；配置或协议版本错误为终态；
  - `stop()` 时释放 lease、关闭 stdin 并最多等待 5 秒，然后结束进程树。runner 的 stderr 经脱敏，最多保留 8 KiB，日志每秒最多 10 行。
- **丢失的轮次（#751）：**`turn.py` 中的 `Outcome` 新增由主机持有的取值 `lost`，线路协议不携带它。丢失结算接受可低于已开始请求数的 `requests` 计数，永不置 `usage_complete`，丢弃费用，不会被上限改为 `capped` 或 `max_requests`，也不再读取设置。结算现在会清除未完成的请求预留。`bridge.py` 统计已完成的 `request_end` 回调（`requests_ended`），并在连接失败后将轮次结算为丢失时上报该计数。
- **面向模型的变化：**无。prompt、工具描述和工具 schema 均未改变。
- **测试：**新增 `tests/test_runner_supervisor.py`，扩展 `tests/test_runner_bridge.py`。
- **描述不符：**#751 的描述先写“approximately 530 changed lines”，又写“tests 561, production 469”；文件清单显示新增 469 行生产代码、561 行测试，本草稿以文件清单为准。
