# Looper v2.13.188

## Release Decision

**Who should upgrade:** Maintainers and integrators who build or run runner-protocol runners. Other users see no difference. It is a hotfix that ships the changes merged since v2.13.187.

**What this release solves:** [#814](https://github.com/foolzzz/looper/pull/814) adds a Pi runner skeleton: a TypeScript runner process under `runners/pi` that is packaged in the wheel, performs the `initialize` handshake behind a version gate, and answers `runner/health`. No runtime launches it yet and it answers no session methods.

**Breaking changes:** No. No command, database schema or file format changed, and nothing starts the new runner.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#814](https://github.com/foolzzz/looper/pull/814); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.188
```

## Behavior changes

- **Pi runner process ([#814](https://github.com/foolzzz/looper/pull/814)):** `runners/pi` (`package.json`, `src/main.ts`, `src/rpc.ts`, `src/sdk.ts`) reads line-delimited JSON-RPC from stdin and writes through one ordered stdout writer. Frames above 4 MiB, invalid UTF-8 or JSON, malformed envelopes, reused request ids and unknown response ids end the process; `console` output is redirected to stderr and known secrets are scrubbed. Requests for one session run in order; the runner can issue reverse requests. `initialize` runs once and every other method is refused until it succeeds. SIGTERM, SIGINT, SIGHUP and end of input shut it down within 4 seconds.
- **Version gate:** `initialize` requires protocol version `0.1` and the host capabilities `tools_call` and `budget_authorize`. It then loads the Pi SDK from the `--pi <path>` executable: Node must be 22.19.0 or later, the executable must sit inside `@earendil-works/pi-coding-agent` 1.3.x, `@earendil-works/pi-ai` must be 1.3.x, and the required SDK exports must exist, otherwise it fails with code -32009 and a message that carries no path or credential. On success it reports kind `pi`, runner version `0.1.0`, `max_sessions` 10 and `authorize_covers` of `turn`, `retry` and `compaction`.
- **`runner/health`:** a new protocol method (`protocol.py`, `messages.schema.json`, `cases.json`) returning non-negative integers `sessions`, `running`, `inflight_requests`, `tool_processes`, `rss_bytes` and `event_loop_lag_ms` (a fractional lag is rejected). `RunnerBridge.health()` sends it. The skeleton reports zero sessions, running requests and tool processes.
- **Packaging:** the package symlink `looper/agents/runtimes/runner/pi_runner` points to `runners/pi`, and `pyproject.toml` adds `pi_runner/package.json` and `pi_runner/src/*.ts` to the package data so the wheel carries them.
- **Launch helper:** `pi_command.py` provides `entry()`, `command(node, pi)` (an absolute Node path is required, otherwise `RuntimeUnsupported`; the Pi path is resolved), `connect(process, kind)` (initializes with permitted `turn`, `retry`, `compaction` and closes the bridge on failure) and the fixed environment `PI_OFFLINE=1`, `PI_TELEMETRY=0`, `PI_SKIP_VERSION_CHECK=1`. It does not register a runtime, so nothing calls it in a running Looper.
- **Per-kind environment:** `RunnerSupervisor(..., env={kind: {NAME: value}})` adds fixed variables to that kind's runner process on top of the allow-listed inherited ones, before `HOME` and `TMPDIR` are set. It refuses a kind that is not configured, names that are not upper-case identifiers, `PATH`, `HOME`, `TMPDIR`, `TZ`, `LANG*` and `LC_*`, and values that are not strings or contain NUL, with `ValueError`. Without `env` nothing changes.
- **Scope:** 17 files changed. The pull request reports 485 test lines and 62 production lines (fixtures excluded). No dashboard, API route, database or workflow file changed.
- **Model-visible changes:** None. Looper's prompts, tool descriptions and tool results are unchanged, and the new runner is not launched by any shipped runtime.

### 行为变化与入口

- **Pi runner 进程（#814）：**`runners/pi`（`package.json`、`src/main.ts`、`src/rpc.ts`、`src/sdk.ts`）从 stdin 读取按行分隔的 JSON-RPC，并通过单一有序 stdout 写入器输出。超过 4 MiB 的帧、非法 UTF-8 或 JSON、格式错误的信封、重复的请求 id 和未发出过的响应 id 都会终止进程；`console` 输出被重定向到 stderr，已知密钥会被抹除。同一会话的请求按序执行，runner 可发起反向请求。`initialize` 只能运行一次，成功前其他方法一律被拒绝。SIGTERM、SIGINT、SIGHUP 和输入结束会在 4 秒内关闭进程。
- **版本门：**`initialize` 要求协议版本 `0.1` 以及宿主能力 `tools_call` 和 `budget_authorize`，然后通过 `--pi <path>` 可执行文件加载 Pi SDK：Node 须为 22.19.0 或更高，可执行文件须位于 `@earendil-works/pi-coding-agent` 1.3.x 内，`@earendil-works/pi-ai` 须为 1.3.x，且所需 SDK 导出须存在，否则以错误码 -32009 失败，消息不含路径或凭据。成功时报告 kind 为 `pi`、runner 版本 `0.1.0`、`max_sessions` 为 10、`authorize_covers` 为 `turn`、`retry`、`compaction`。
- **`runner/health`：**新的协议方法（`protocol.py`、`messages.schema.json`、`cases.json`），返回非负整数 `sessions`、`running`、`inflight_requests`、`tool_processes`、`rss_bytes` 和 `event_loop_lag_ms`（小数延迟会被拒绝）。`RunnerBridge.health()` 发送该请求。骨架报告会话、运行中请求和工具进程均为零。
- **打包：**包内符号链接 `looper/agents/runtimes/runner/pi_runner` 指向 `runners/pi`，`pyproject.toml` 把 `pi_runner/package.json` 和 `pi_runner/src/*.ts` 加入 package data，使 wheel 携带它们。
- **启动辅助：**`pi_command.py` 提供 `entry()`、`command(node, pi)`（要求 Node 为绝对路径，否则抛出 `RuntimeUnsupported`；Pi 路径会被解析）、`connect(process, kind)`（以 `turn`、`retry`、`compaction` 为许可范围初始化，失败时关闭 bridge）以及固定环境变量 `PI_OFFLINE=1`、`PI_TELEMETRY=0`、`PI_SKIP_VERSION_CHECK=1`。它不注册运行时，因此运行中的 Looper 不会调用它。
- **按 kind 的环境变量：**`RunnerSupervisor(..., env={kind: {NAME: value}})` 在允许继承的变量之上、设置 `HOME` 和 `TMPDIR` 之前，为该 kind 的 runner 进程加入固定变量。未配置的 kind、非大写标识符的名称、`PATH`、`HOME`、`TMPDIR`、`TZ`、`LANG*`、`LC_*`，以及非字符串或含 NUL 的值，都会抛出 `ValueError`。不传 `env` 时行为不变。
- **范围：**改动 17 个文件。按该 PR 描述，测试 485 行、生产代码 62 行（不含夹具）。dashboard、API 路由、数据库和 workflow 文件均未改变。
- **面向模型的变化：**无。Looper 的提示词、工具描述和工具结果不变，且任何已发布的运行时都不会启动新 runner。
