# Looper v2.13.76

## Release Decision

**Who should upgrade:** Operators who use the dashboard's run history, usage, chat Stop, chat Settings or Manager session profile selection, and anyone who calls the legacy run-record or chat-control routes from a script. Everyone else gets a dashboard build that works again.

**What this release solves:** [#506](https://github.com/foolzzz/looper/pull/506) moves run records and usage to operator-only v1 reads, and [#507](https://github.com/foolzzz/looper/pull/507) does the same for Manager sessions and chat controls. [#512](https://github.com/foolzzz/looper/pull/512) fixes the dashboard build and type-checks it in CI, and [#515](https://github.com/foolzzz/looper/pull/515) restores green agent system tests.

**Breaking changes:** Yes. Removed: `GET /api/tasks/{id}/runs`, `GET /api/llm-records`, `GET /api/llm-records/{id}`, `GET /api/llm-records/{id}/events`, `GET /api/agents/{id}/usage`, `GET /api/manager/session`, `PUT /api/manager/session/profile`, `GET /api/chat/turn`, `POST /api/chat/stop`, `GET /api/chat-settings` and `PUT /api/chat-settings`. Callers must use the `POST /api/v1/v1 operations` operations listed below; answers are wrapped in `result`. The dashboard and the prompt-regression and example scripts are already updated.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#506](https://github.com/foolzzz/looper/pull/506), [#507](https://github.com/foolzzz/looper/pull/507), [#512](https://github.com/foolzzz/looper/pull/512) and [#515](https://github.com/foolzzz/looper/pull/515); no community contribution was included in this patch release.


## Behavior changes

- **Run records ([#506](https://github.com/foolzzz/looper/pull/506)):** `looper/agents/v1_domains/runs.py` adds `runs.for_task` (`task_id`), `runs.list` (`agent_id`, `task_id`, `role`, `limit` 1–500, `offset`), `runs.get` (`record_id`), `runs.events` (`record_id`, `after`, `limit` 1–5000) and `runs.usage` (`agent_id`, `turns` 1–1000). Requests are closed objects, and all five are declared `operator_only`, so an API client token is refused. A database failure answers `unavailable`; task run and record lists no longer hide it as an empty list. Records still carry the historical `task_role` projection, and metadata and transcript events are not rewritten.
- **Chat controls ([#507](https://github.com/foolzzz/looper/pull/507)):** `looper/agents/v1_domains/chat_controls.py` adds `manager_session.get`, `manager_session.select_profile` (`profile_id`, null follows Settings), `operator_chat.turn` (`session_id`), `operator_chat.stop` (`message_id`), `chat_settings.get` and `chat_settings.update` (`stop_enabled`, null restores the built-in default). `operator_chat.turn` and `operator_chat.stop` are `operator_only`. `chat_settings.update` is high risk and asks for confirmation, showing that it immediately enables or disables stopping Manager replies from the dashboard, Telegram and Lark. A stop while the setting is off answers a conflict with state `disabled`; a stop that cannot proceed answers a conflict with the stop state. `select_profile` stays open to API clients, and the audit origin is taken from the caller, not from the request.
- **Removed routes:** the eleven legacy routes above, their handlers and the run-record id patterns are deleted from `http_server.py`.
- **Dashboard:** `web/src/lib/api.ts` calls the v1 operations; [#512](https://github.com/foolzzz/looper/pull/512) removes the unused `managerJson` helper that failed `tsc`.
- **CI:** the Dashboard job in `python-tests.yml` now runs `npx tsc -b` between `npm ci` and `npm test`.
- **Scripts and docs:** `evals/`, `examples/dsh/validate.py` and `examples/pi/isolated-smoke.py` use the v1 routes; README, `docs/design.md` and `docs/architecture/agent-system.md` describe them.
- **Tests only ([#515](https://github.com/foolzzz/looper/pull/515)):** the fake Planner Claude in `tests/conftest.py` gains `sessions_by_cwd`, and two tests are adjusted; no production line changed.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt or Manager Tool changed; the new operations are dashboard and API reads and controls, not Manager tools.
- **Not confirmed in code:** this draft did not check whether any removed route had been open to an API client token before, so the operator-only reads may newly refuse a client that used them.

## Upgrade and rollback

Re-run `install.sh` once v2.13.76 is published, and move any script that calls a removed route to its v1 operation. No data migration. Rolling back to v2.13.75 restores the old routes, with no stored data affected.

### 行为变化与入口

- **运行记录（[#506](https://github.com/foolzzz/looper/pull/506)）：**`looper/agents/v1_domains/runs.py` 新增 `runs.for_task`（`task_id`）、`runs.list`（`agent_id`、`task_id`、`role`、`limit` 1–500、`offset`）、`runs.get`（`record_id`）、`runs.events`（`record_id`、`after`、`limit` 1–5000）、`runs.usage`（`agent_id`、`turns` 1–1000）。请求均为封闭对象，五个操作都声明为 `operator_only`，拒绝 API 客户端令牌。数据库故障返回 `unavailable`，任务运行列表和记录列表不再把故障当作空列表。记录仍带历史的 `task_role` 投影，元数据与 transcript 事件不被改写。
- **聊天控制（[#507](https://github.com/foolzzz/looper/pull/507)）：**`looper/agents/v1_domains/chat_controls.py` 新增 `manager_session.get`、`manager_session.select_profile`（`profile_id`，null 表示跟随设置）、`operator_chat.turn`（`session_id`）、`operator_chat.stop`（`message_id`）、`chat_settings.get`、`chat_settings.update`（`stop_enabled`，null 恢复内置默认）。`operator_chat.turn` 与 `operator_chat.stop` 为 `operator_only`。`chat_settings.update` 为高风险操作并需确认，提示会立即启用或停用仪表盘、Telegram 和 Lark 对 Manager 回复的停止。设置关闭时 stop 返回冲突，状态为 `disabled`；无法停止时返回带停止状态的冲突。`select_profile` 仍对 API 客户端开放，审计来源取自调用者而非请求。
- **移除的路由：**上述十一条旧路由及其处理函数、运行记录 id 匹配规则已从 `http_server.py` 删除。
- **仪表盘：**`web/src/lib/api.ts` 调用 v1 操作；[#512](https://github.com/foolzzz/looper/pull/512) 删除导致 `tsc` 失败的未使用 `managerJson`。
- **CI：**`python-tests.yml` 的 Dashboard 任务在 `npm ci` 与 `npm test` 之间新增 `npx tsc -b`。
- **脚本与文档：**`evals/`、`examples/dsh/validate.py`、`examples/pi/isolated-smoke.py` 改用 v1 路由；README、`docs/design.md`、`docs/architecture/agent-system.md` 已同步。
- **仅测试（[#515](https://github.com/foolzzz/looper/pull/515)）：**`tests/conftest.py` 中的假 Planner Claude 新增 `sessions_by_cwd`，并调整两个测试；生产代码无改动。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 和 Manager Tool 均未改动；新操作是仪表盘和 API 的读取与控制，不是 Manager 工具。
- **代码中未确认：**本草稿未核实被移除的路由此前是否对 API 客户端令牌开放，因此仅限操作者的读取可能让原先使用它们的客户端被拒绝。

v2.13.76 发布后重跑 `install.sh`，并把调用已移除路由的脚本改到对应的 v1 操作。无需迁移数据。回退到 v2.13.75 会恢复旧路由，不影响已存数据。
