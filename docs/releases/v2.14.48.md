# Looper v2.14.48

This is the patch release v2.14.48, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.47: a keeper process that holds one agent run's child ([#1011](https://github.com/foolzzz/looper/pull/1011)). Nothing in Looper calls the keeper yet, so this release changes no behavior for a running installation.

## Release Decision

**Who should upgrade:** Anyone who wants to stay on the latest patch line. There is no user-facing change; the new code is groundwork that a later release connects to the control plane.

**What this release solves:** [#1011](https://github.com/foolzzz/looper/pull/1011) adds the package `looper/agents/keeper/`, whose entry point holds one child process for the child's whole life, and a helper `proc_tree.own_records` that lets a process which is not a server own the agents it spawns.

**Breaking changes:** No. No API or configuration is removed or changed, and there is no new migration or setting.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#1011](https://github.com/foolzzz/looper/pull/1011); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.48
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.47 upgrades directly. This release adds no migration and no new setting.

## Behavior changes

- **Keeper process ([#1011](https://github.com/foolzzz/looper/pull/1011)).** The new package `looper/agents/keeper/` has an isolated entry point (`python -I -c ... --dir <run dir> --runtime-root <root> --cwd <dir> -- <child command>`). Nothing in Looper starts it yet, so no existing run uses it. When started, it:
  - refuses a run directory that is not owned by its user with mode 0700 (exit code 2);
  - starts the child in its own session through `proc_tree.spawn`, with the keeper recorded as owner so `proc_tree.sweep` ends the child once the keeper is gone;
  - appends the child's stdout and stderr bytes to `stdout.log` and `stderr.log` in the run directory (and opens `stdin.log`), and keeps its own state in `keeper.json` (starting, running or exited, with pids, start times, exit code or signal, end time and end reason);
  - ends the child on SIGTERM (reason `ended`), when no controller has connected for the orphan timeout (reason `orphaned`; default 1800 s), and when stdout passes its cap (reason `log_limit`; default 512 MiB; stderr is capped at 64 MiB and is not a reason to end). The orphan timeout and stdout cap can be set in the run's `manifest.json`; a missing or invalid manifest falls back to the defaults with a warning;
  - ignores SIGINT and SIGHUP, records a failure to start the child as `start_failed` (exit code 3) and an internal error as `keeper_error` (exit code 1), then exits.
  - Because no control socket exists yet, no controller can connect, so the orphan timeout is the only automatic end besides the child exiting, SIGTERM and the stdout cap.
- **Import isolation.** The package imports only the standard library, `looper` (for `__version__`), `looper.agents.proc_tree` and `looper.child_env`, all at module top level, so a running keeper never loads code that an in-place install has replaced. A `--check` mode prints the `looper` modules the keeper loads.
- **`proc_tree.own_records(runtime_root)`.** A new helper that records agents for a process that owns agents but is not a server, without sweeping. Existing `spawn` and `sweep` behavior is unchanged.
- **Model-visible changes:** No. No prompt, tool description, tool schema or Manager confirmation text changes.

### 行为变化与入口

- **Keeper 进程（[#1011](https://github.com/foolzzz/looper/pull/1011)）。**新包 `looper/agents/keeper/` 有独立的入口。目前 Looper 中没有任何代码启动它，因此现有运行都不使用它。启动后它会：
  - 拒绝不属于当前用户或权限不是 0700 的运行目录（退出码 2）；
  - 通过 `proc_tree.spawn` 在独立会话中启动子进程，并把 keeper 记为所有者，这样 keeper 消失后 `proc_tree.sweep` 会结束该子进程；
  - 把子进程的 stdout 和 stderr 追加写入运行目录中的 `stdout.log` 和 `stderr.log`（并打开 `stdin.log`），把自身状态写入 `keeper.json`（starting、running 或 exited，含 pid、启动时间、退出码或信号、结束时间和结束原因）；
  - 在收到 SIGTERM（原因 `ended`）、孤儿超时内没有控制器连接（原因 `orphaned`，默认 1800 秒）、stdout 超过上限（原因 `log_limit`，默认 512 MiB；stderr 上限为 64 MiB，超出不会结束子进程）时结束子进程。孤儿超时和 stdout 上限可在运行的 `manifest.json` 中设置；清单缺失或无效时回退为默认值并记录警告；
  - 忽略 SIGINT 和 SIGHUP；子进程启动失败记为 `start_failed`（退出码 3），内部错误记为 `keeper_error`（退出码 1），然后退出。
  - 由于还没有控制套接字，没有控制器可以连接，因此除子进程自行退出、SIGTERM 和 stdout 上限外，孤儿超时是唯一的自动结束条件。
- **导入隔离。**该包只导入标准库、`looper`（取 `__version__`）、`looper.agents.proc_tree` 和 `looper.child_env`，且都在模块顶层导入，因此运行中的 keeper 不会加载被原地安装替换的代码。`--check` 模式会打印 keeper 加载的 `looper` 模块。
- **`proc_tree.own_records(runtime_root)`。**新的辅助函数，为拥有 agent 但不是服务器的进程记录 agent，不执行清扫。现有 `spawn` 和 `sweep` 的行为不变。
- **面向模型的变化：**无。没有 prompt、工具描述、工具 schema 或 Manager 确认文本的变化。
