# Looper v2.14.8

This is the patch release v2.14.8. It ships the one change merged since v2.14.7: [#885](https://github.com/foolzzz/looper/pull/885), which makes the DSH runner drop an authorization reply that arrives after its turn settled. It affects only installations that set `[runtimes] dsh = "runner"`.

## Release Decision

**Who should upgrade:** Operators who run DSH roles on the DSH runner (`[runtimes] dsh = "runner"`). Nothing changes for an installation whose ops file does not set it (the default is `cli`). It ships the one change merged since v2.14.7.

**What this release solves:** [#885](https://github.com/foolzzz/looper/pull/885) fixes issue #884: an authorization reply that arrived after its turn had settled (possibly after the same session was resumed for a new turn) is now consumed without sending any update for the old trace, so the host bridge is not disconnected and the new turn is unaffected.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#885](https://github.com/foolzzz/looper/pull/885); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.8
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.7 upgrades directly. This release changes no schema, stored data or setting.

## Behavior changes

All changes are in the packaged runner sources (`runners/`) and are reached only with `[runtimes] dsh = "runner"`.

- **Late reply dropped after `settled` (`runners/dsh/src/provider.ts`, `turn.ts`):** each pending authorization now records the trace that issued it, and is removed from the turn's pending set when its RPC is consumed. A reply that arrives after the turn has settled, or whose owner is no longer the turn's trace, yields a denial for the agent and emits no update. A late allow is therefore no longer accounted after `settled`: v2.14.7 accounted it as an aborted, complete, zero-token `request_end`; v2.14.8 emits none. A late allow that arrives while the turn is still settling is still accounted once, before `settled`. The expired request is never sent to the model.
- **Unknown response ids ignored (`runners/common/rpc.ts`, `runners/dsh/src/main.ts`):** the DSH runner now ignores a response whose id it has no waiter for, such as a replayed or never-issued id, and writes one diagnostic line (`runner ignored unknown response id=...`) the first time. Before, this was a fatal protocol violation that ended the runner. The check is opt-in (`start({ ignoreUnknownResponses: true })`); the other runner (`runners/pi`) keeps the fatal behavior. Malformed responses are still fatal.
- **Tests:** the new `tests/test_dsh_runner_bridge.py` drives real DSH and the production bridge with an old trace's authorization reply held back, released before or after `settled`, while the session is resumed for a new turn. It checks that the new turn completes, nothing disconnects the bridge, replayed and never-issued ids are ignored with a single diagnostic, and no old-trace update follows. `tests/test_dsh_runner_requests.py` now expects no update after a late reply following the cancel deadline (allow, deny and error).
- **Model-visible changes:** None. Prompts, tools and model requests are unchanged; a late allowed authorization no longer produces a host-side `request_end` after `settled`.

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.7 上的安装可直接升级。本版本不改 schema、已存数据或设置。

### 行为变化与入口

以下改动都在打包的 runner 源码（`runners/`）中，仅在 `[runtimes] dsh = "runner"` 时生效。

- **结算之后的迟到回复被丢弃（`runners/dsh/src/provider.ts`、`turn.ts`）：**每个待处理授权现在记录发起它的 trace，并在其 RPC 被消费时从回合的待处理集合中移除。回合结算之后到达、或所属 trace 已不是当前回合 trace 的回复，对 agent 返回拒绝，且不发出任何更新。因此迟到的允许不再在 `settled` 之后记账：v2.14.7 将其记为已中止、完整、零 token 的 `request_end`，v2.14.8 不再发出。回合仍在结算期间到达的迟到允许仍在 `settled` 之前记账一次。过期的请求不会发送给模型。
- **未知响应 id 被忽略（`runners/common/rpc.ts`、`runners/dsh/src/main.ts`）：**DSH runner 现在忽略没有对应等待者的响应（例如重放或从未发出的 id），并在首次出现时写一行诊断（`runner ignored unknown response id=...`）。此前这属于致命的协议违规，会结束 runner。该检查为按需开启（`start({ ignoreUnknownResponses: true })`）；另一个 runner（`runners/pi`）保持致命行为。格式错误的响应仍然是致命的。
- **测试：**新增 `tests/test_dsh_runner_bridge.py`，用真实 DSH 和生产桥扣住旧 trace 的授权回复，在 `settled` 之前或之后释放，同时把会话恢复为新回合；检查新回合完成、桥未断开、重放与从未发出的 id 只产生一次诊断、旧 trace 之后无更新。`tests/test_dsh_runner_requests.py` 现在期望取消期限之后的迟到回复（允许、拒绝、错误）不产生任何更新。
- **面向模型的变化：**无。提示、工具和模型请求都不变；迟到的允许授权不再在 `settled` 之后产生宿主侧的 `request_end`。
