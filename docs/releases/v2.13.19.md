# Looper v2.13.19

## Release Decision

**Who should upgrade:** Maintainers and contributors who run the prompt-regression evals (`evals/prompt_regression`). Everyone else sees no change.

**What this release solves:** [#349](https://github.com/foolzzz/looper/pull/349) fixes the review follow-ups of #310. The eval harness costs a dialog correctly when some runs report an observed root spend and others only a recorded cost, and its running spending check now counts the observed root spend of finished runs.

**Breaking changes:** No. No CLI command, configuration key, API or database schema changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#349](https://github.com/foolzzz/looper/pull/349); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.19
```

## Behavior changes

- **Dialog cost in the evals:** `observed_cost` returns the recorded sum plus, run by run, the amount by which a run's observed root spend exceeds that run's recorded cost (never below zero). It used to return the larger of the recorded sum and the sum of observed spends, which undercounted mixed-role runs. Runs that report no observed spend still make the second value `False`. The runtime evidence of each run now also carries its `cost_usd`. The change is in `evals/prompt_regression/dialogs.py`.
- **Running spending check:** while a dialog runs, the check compares the cap with the database usage plus the observed root overrun of finished runs (read once per run from the LLM records and their `result` event). The dialog stops with the spending-cap error as before. The change is in `evals/prompt_regression/dialogs.py`.
- **Tests only:** a failed Pi consult run holding a valid final is asserted not to be delivered and to fall back with the contract reason (`tests/test_room_consult.py`); the cost cases and the running check are covered in `tests/test_dsh_validation.py`. The PR also reports a fix for a flaky schema test whose constraint count was not scoped to the test schema; that file is not in the PR's changed files, so this draft did not verify it.
- **Model-visible changes:** None. No prompt, tool schema or tool result changed, and no shipped runtime code changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.19 is published. There is no schema or configuration change. Rolling back to v2.13.18 is safe.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 行为变化与入口

- eval 中的对话成本：`observed_cost` 返回“记录成本之和 + 逐个运行中观测 root 花费超出该运行记录成本的部分（不小于零）”。此前取记录之和与观测之和中的较大者，会低估混合角色的运行。有运行未报告观测花费时，第二个返回值仍为 `False`。每个运行的 runtime evidence 现在也带 `cost_usd`。改动在 `evals/prompt_regression/dialogs.py`。
- 运行中的花费检查：对话运行时，检查把上限与数据库用量加上已完成运行的 root 超出部分比较（每个运行只从 LLM 记录及其 `result` 事件读取一次），超限时仍以花费上限错误停止。改动在 `evals/prompt_regression/dialogs.py`。
- 仅测试：断言带有效 final 的失败 Pi consult 运行不被投递，并以 contract 原因回退（`tests/test_room_consult.py`）；成本用例与运行中检查由 `tests/test_dsh_validation.py` 覆盖。PR 还报告修复了一个不稳定的 schema 测试（约束计数未限定到测试 schema），该文件不在 PR 的改动文件内，本草稿未核实。
- 面向模型的变化：无。提示词、工具 schema、工具结果均无变化，也没有改动随产品发布的运行时代码。
