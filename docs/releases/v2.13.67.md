# Looper v2.13.67

## Release Decision

**Who should upgrade:** Dashboard users and anyone scripting the Lark identity, people-search and gate notification settings HTTP routes. Dashboard users see no change. Scripts that call the removed routes must move to the `/api/v1/` routes.

**What this release solves:** [#481](https://github.com/foolzzz/looper/pull/481) moves Lark channel discovery (identity status and people search for the `lark` and `lark_bot` channels) and the dashboard gate notification settings to the versioned API (`/api/v1/`) as four operations with typed requests and results, reusing the existing Lark settings and gate services. The six legacy methods for them are removed.

**Breaking changes:** Yes. The six legacy routes listed under Behavior changes no longer exist; a client that calls one gets a not-found answer. Stored data and configuration, including the saved gate target, are unchanged.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#481](https://github.com/foolzzz/looper/pull/481); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.67
```

## Behavior changes

- **Removed routes (breaking for API clients):** `GET /api/channels/lark/status`, `GET /api/channels/lark/people`, `GET /api/channels/lark_bot/status`, `GET /api/channels/lark_bot/people`, `GET /api/gate-settings` and `PUT /api/gate-settings`.
- **Replacements:** `POST /api/v1/channels/status`, `channels/people`, `gate_settings/get` and `gate_settings/update`.
  - `channels.status` takes `{channel_type, channel_id?}`; `channel_type` is `lark` or `lark_bot`, and `channel_id` defaults to the built-in channel.
  - `channels.people` takes `{channel_type, channel_id?, q}`; `q` is required and limited in length. The result is `{people, complete}`.
  - `gate_settings.get` takes an empty object; `gate_settings.update` takes `{dashboard_target}`, where the target is `{channel, chat}` (channel `telegram`, `lark` or `lark_bot`) or `null` to clear it.
- **Typed requests and results:** the four operations declare closed request schemas (unknown fields are rejected) and typed results for the bot status, the people list and the gate settings.
- **Error answers:** an unknown channel is answered as not found, an invalid query or target as invalid, and a failed `lark-cli` or Lark platform call as unavailable. The legacy "bad gateway" answer for a failed search is gone.
- **Authority and confirmation:** `gate_settings.update` is a high-risk operation. An API client must confirm in a second step, and the request is refused if the target is not offered by an enabled channel's sender allowlist. The operator writes in one step, with the service's existing validation. The service still checks the current targets before it writes. `channels.status`, `channels.people` and `gate_settings.get` are reads.
- **Dashboard:** the Lark status, people search and gate settings calls use the new routes.
- **Documentation:** the agent system overview and the Lark bot, scenario manager, user gate and Looper client skill RFCs record the migration, and the long-horizon context plan is updated; earlier release bodies (v2.7.0, v2.8.0, v2.9.0) now name the new routes.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt changed, and no Manager Tool was added or changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.67 is published. No data migration. Update any script or client that called a removed route before upgrading. Rolling back to v2.13.66 restores the legacy routes, with no stored data affected.

## 中文摘要

### 升级决策

**谁需要升级：**仪表盘用户，以及脚本调用 Lark 身份、人员搜索和 gate 通知设置 HTTP 路由的人。仪表盘用户看不到变化；调用已删除路由的脚本需要改用 `/api/v1/` 路由。

**解决了什么：**[#481](https://github.com/foolzzz/looper/pull/481) 把 Lark 渠道发现（`lark` 与 `lark_bot` 的身份状态和人员搜索）以及仪表盘 gate 通知设置迁到版本化 API（`/api/v1/`），作为四个带类型化请求与结果的操作，复用现有的 Lark 设置与 gate 服务，并删除对应的六个旧方法。

**是否有破坏性变更：**是。“行为变化”中列出的六个旧路由不再存在，调用会得到 not found。存储数据和配置（包括已保存的 gate 目标）不变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.67。

**贡献者：**维护者 @foolzzz 提交 [#481](https://github.com/foolzzz/looper/pull/481)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.67
```

### 行为变化与入口

- **已删除的路由（对 API 客户端是破坏性的）：**`GET /api/channels/lark/status`、`GET /api/channels/lark/people`、`GET /api/channels/lark_bot/status`、`GET /api/channels/lark_bot/people`、`GET /api/gate-settings`、`PUT /api/gate-settings`。
- **替代路由：**`POST /api/v1/channels/status`、`channels/people`、`gate_settings/get`、`gate_settings/update`。
  - `channels.status` 收 `{channel_type, channel_id?}`；`channel_type` 为 `lark` 或 `lark_bot`，`channel_id` 缺省为内置渠道。
  - `channels.people` 收 `{channel_type, channel_id?, q}`；`q` 必填且有长度上限，结果为 `{people, complete}`。
  - `gate_settings.get` 收空对象；`gate_settings.update` 收 `{dashboard_target}`，目标为 `{channel, chat}`（channel 为 `telegram`、`lark` 或 `lark_bot`），或用 `null` 清除。
- **类型化请求与结果：**四个操作声明了封闭的请求 schema（拒绝未知字段），以及机器人状态、人员列表和 gate 设置的类型化结果。
- **错误应答：**未知渠道返回 not found，无效的查询或目标返回 invalid，`lark-cli` 或 Lark 平台调用失败返回 unavailable；搜索失败时旧的 bad gateway 应答不再出现。
- **权限与确认：**`gate_settings.update` 为 high 风险。API 客户端须两步确认，且目标不在已启用渠道的发送者白名单所提供的范围内时会被拒绝；操作者单次写入，沿用服务既有校验。服务写入前仍会检查当前目标。`channels.status`、`channels.people`、`gate_settings.get` 为只读。
- **仪表盘：**Lark 状态、人员搜索和 gate 设置调用改用新路由。
- **文档：**agent 系统概览，以及 Lark bot、场景 Manager、用户 gate 与 Looper 客户端 skill 的 RFC 记录了此次迁移，长程上下文计划已更新；早先的发布正文（v2.7.0、v2.8.0、v2.9.0）改为指向新路由。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 均未改动，未新增或修改 Manager Tool。

### 升级与回退

v2.13.67 发布后重跑 `install.sh`。无需迁移数据。升级前请更新调用已删除路由的脚本或客户端。回退到 v2.13.66 会恢复旧路由，不影响已存数据。
