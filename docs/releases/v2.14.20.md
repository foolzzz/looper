# Looper v2.14.20

This is the patch release v2.14.20. It ships the one change merged since v2.14.19: [#915](https://github.com/foolzzz/looper/pull/915), which makes the DSH runner retry transient provider errors, each attempt authorized.

## Release Decision

**Who should upgrade:** Anyone who runs agents on the DSH runner and sees turns fail at once on a transient provider error (HTTP 429 or 5xx, or a DeepSeek "Service is too busy" overload). It ships the one change merged since v2.14.19.

**What this release solves:** [#915](https://github.com/foolzzz/looper/pull/915): the DSH SDK runner disables the SDK's `llm-retry` plugin, because its retries would bypass Looper's per-request budget authorization, so a transient provider error failed the turn immediately. The runner now retries inside its `llm/stream` hook, only when the failed attempt produced no model output, with bounded backoff, and each attempt is authorized through `budget/authorize` and accounted as its own request.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#915](https://github.com/foolzzz/looper/pull/915); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.20
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.19 upgrades directly. This release changes no database schema, stored data or setting.

## Behavior changes

- **Transient provider errors are retried** (`runners/dsh/src/provider.ts`): the `llm/stream` hook makes up to 4 attempts per model request (the first plus 3 retries). An attempt is retried only when it ended in an error, produced no model output (no block, text, reasoning or tool-call chunk), and is retryable: the HTTP status is one of 408, 409, 425, 429, 500, 502, 503, 504 or 529, or the SDK failure code is one of `EMPTY_RESPONSE`, `RATE_LIMIT`, `SERVER`, `TIMEOUT` or `TRANSPORT`, or the request was sent and failed without an HTTP status. There are no message-text heuristics; the code comments state that the pinned SDK normalizes DeepSeek overload errors to `SERVER`. Output that was already produced is never retried.
- **Backoff** (`runners/dsh/src/provider.ts`): the wait before retry n is 1, 2 or 4 seconds plus up to 20% random jitter. A `Retry-After` header (seconds or an HTTP date) or the SDK's retry-after hint raises the wait up to a cap of 30 seconds, never below the local backoff.
- **Every attempt is authorized and accounted** (`runners/dsh/src/provider.ts`): each attempt gets its own request id, its own `budget/authorize` call and its own request accounting. The failed attempt is ended, releasing its reservation, before the next is authorized. A denied or unverifiable authorization on a retry ends the turn as it does on a first attempt. A retried attempt without authoritative usage counts as zero-token and settles even when the HTTP error body was truncated; authoritative usage reported by the provider is kept.
- **Cancel, close and settle interrupt the wait** (`runners/dsh/src/provider.ts`, `runners/dsh/src/turn.ts`): the turn holds a `retryDelay` controller that `settle` and `cancelTurn` abort, so a retry wait ends at once and the request finishes as aborted. The abort signal is also checked before each retry.
- **Exhausted retries keep the last error** (`runners/dsh/src/provider.ts`): after the last attempt the final provider failure is returned unchanged except that, when more than one attempt was made, its message is scrubbed, reduced to one line, truncated to 512 characters and suffixed with ` (after N attempts)`.
- **Diagnostics** (`runners/dsh/src/provider.ts`): each retry emits `provider_retry request_id=... status=... code=... attempt=... delay_ms=...`. The code is one of the retryable codes or `OTHER`; the line carries no provider message or credential.
- **Tests and docs**: `tests/test_dsh_runner_retries.py` is new (22 tests per the plan note); `tests/dsh_installed_stand_in.py` gains reply options for error type and message, headers and disconnects; `tests/test_dsh_runner_requests.py` and `tests/test_dsh_runner_turns.py` are updated, including the truncated-response fixture, which now retries as `TRANSPORT`. A status line is added to the Chinese long-horizon context plan.
- **Python side:** no Python production file changes; the `budget/authorize` request and the runner protocol messages are unchanged, but a single model call may now produce several `budget/authorize` requests with distinct request ids.
- **Model-visible changes:** No prompt, tool description or tool schema changes. The only model-visible text is the ` (after N attempts)` suffix on the failure message of a request that failed after retrying.

## 中文摘要

本版本是 patch release v2.14.20。自 v2.14.19 以来只合并了一项改动：[#915](https://github.com/foolzzz/looper/pull/915)，让 DSH runner 重试瞬态的 provider 错误，且每次尝试都经过授权。

### 升级决策

**谁需要升级：**在 DSH runner 上运行 agent、且在遇到瞬态 provider 错误（HTTP 429 或 5xx，或 DeepSeek 的 “Service is too busy” 过载）时回合立即失败的人。包含 v2.14.19 之后合并的这一项改动。

**解决了什么：**[#915](https://github.com/foolzzz/looper/pull/915)：DSH SDK runner 关闭了 SDK 的 `llm-retry` 插件（其重试会绕过 Looper 的逐请求预算授权），因此瞬态 provider 错误会让回合立即失败。现在 runner 在 `llm/stream` 钩子内重试，仅当失败的尝试没有产生任何模型输出时才重试，退避有上限，且每次尝试都经过 `budget/authorize` 并单独计量。

**是否有破坏性变更：**否。受支持的升级路径不变（见升级）。

**如何验证：**运行 `looper --version` 核对版本为 2.14.20。

**贡献者：**维护者 @foolzzz 提交 [#915](https://github.com/foolzzz/looper/pull/915)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.20
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.19 上的安装可直接升级。本版本不改数据库 schema、已存数据或设置。

### 行为变化与入口

- **瞬态 provider 错误会被重试**（`runners/dsh/src/provider.ts`）：`llm/stream` 钩子对每个模型请求最多尝试 4 次（首次加 3 次重试）。仅当尝试以错误结束、没有产生模型输出（无 block、文本、推理或工具调用片段），且错误可重试时才重试：HTTP 状态为 408、409、425、429、500、502、503、504 或 529；或 SDK 失败码为 `EMPTY_RESPONSE`、`RATE_LIMIT`、`SERVER`、`TIMEOUT`、`TRANSPORT`；或请求已发出但没有 HTTP 状态就失败。不使用消息文本启发式；代码注释说明固定版本的 SDK 会把 DeepSeek 过载错误归一为 `SERVER`。已产生输出的请求不会重试。
- **退避**（`runners/dsh/src/provider.ts`）：第 n 次重试前等待 1、2 或 4 秒，外加至多 20% 的随机抖动。`Retry-After` 头（秒数或 HTTP 日期）或 SDK 的重试提示可把等待延长，上限 30 秒，且不低于本地退避。
- **每次尝试都授权并计量**（`runners/dsh/src/provider.ts`）：每次尝试有独立的 request id、独立的 `budget/authorize` 调用和独立的请求计量。失败的尝试先结束并释放预留，再授权下一次。重试时授权被拒或无法验证，与首次尝试一样结束回合。没有权威用量的重试尝试按零 token 计，即使 HTTP 错误体被截断也会结算；provider 给出的权威用量予以保留。
- **取消、关闭与结算会打断等待**（`runners/dsh/src/provider.ts`、`runners/dsh/src/turn.ts`）：回合持有 `retryDelay` 控制器，`settle` 和 `cancelTurn` 会将其中止，重试等待立即结束，请求以 aborted 结束。每次重试前也会检查中止信号。
- **重试耗尽时保留最后的错误**（`runners/dsh/src/provider.ts`）：最后一次尝试后返回最终的 provider 失败；若尝试超过一次，其消息会被清洗、压成一行、截断到 512 字符，并加上后缀 ` (after N attempts)`，其余不变。
- **诊断**（`runners/dsh/src/provider.ts`）：每次重试输出 `provider_retry request_id=... status=... code=... attempt=... delay_ms=...`。code 为可重试码之一或 `OTHER`；该行不含 provider 消息或凭据。
- **测试与文档**：新增 `tests/test_dsh_runner_retries.py`（计划说明记 22 项）；`tests/dsh_installed_stand_in.py` 增加错误类型与消息、响应头和断开连接的回复选项；更新 `tests/test_dsh_runner_requests.py` 和 `tests/test_dsh_runner_turns.py`，其中截断响应夹具现按 `TRANSPORT` 重试；中文长程上下文计划新增一行状态记录。
- **Python 侧：**没有 Python 生产文件变化；`budget/authorize` 请求与 runner 协议消息不变，但一次模型调用现在可能产生多个带不同 request id 的 `budget/authorize` 请求。
- **面向模型的变化：**没有 prompt、工具描述或工具 schema 的变化。唯一面向模型的文本是重试后失败的请求，其失败消息带有 ` (after N attempts)` 后缀。
