# Looper v2.15.11

This is the patch release v2.15.11, a hotfix line in which each merged change ships at once. It documents one change: [#1392](https://github.com/foolzzz/looper/pull/1392) (OMP and Pi CLI room push is confirmed by receipt only).

## Release Decision

**Who should upgrade:** Anyone who runs OMP or Pi CLI as a runtime and receives room messages during a running turn, and wants a message marked read only after the model has seen it.

**What this release solves:** [#1392](https://github.com/foolzzz/looper/pull/1392) removes the 30 s fallback read for OMP and Pi CLI room deliveries. A steer can wait for a later tool call to end, so the fallback could mark a message read before the model received it. Now only the runtime's user-message receipt confirms it.

**Breaking changes:** No. The CLI, the API and the dashboard are unchanged, no new command or control is added and there is no PostgreSQL schema change. Only when a room delivery counts as read changes (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.11
```

**Contributors:** Maintainer @foolzzz authored [#1392](https://github.com/foolzzz/looper/pull/1392); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.10 upgrades directly. There is no PostgreSQL schema change. Restart the service after upgrading, as for every release.

## Behavior changes

Read in the diff of the PR (5 files: `looper/agents/runtimes/omp.py`, `looper/agents/runtimes/pi.py`, `tests/test_codex_room_push.py`, `docs/architecture/agent-system.md`, `docs/architecture/rfcs/worker-steering-v0.zh-CN.md`).

### #1392: OMP and Pi CLI room push is confirmed by receipt only

- **No fallback read.** `OmpRuntime` and `PiRuntime` now set `room_receipt_fallback = False`, the flag the Worker passes to the room delivery tracker as `receipt_fallback` (`looper/agents/tiers/worker.py`). Grok already sets it. Before, both runtimes kept the default `True`, so a delivery with no receipt 30 s after acceptance was logged and marked read.
- **What confirms a delivery.** A user-message receipt event from the runtime that carries the delivery's message ids. Receipts advance the seat's read cursor only past earlier confirmed deliveries.
- **Without a receipt.** The delivery stays unread for the next run or the seat's inbox. Codex is unchanged and keeps its 30 s fallback.
- **Docs and tests.** `docs/architecture/agent-system.md` and the Chinese steering RFC describe the rule. `tests/test_codex_room_push.py` gains 66 lines (16 removed) for the new behavior.
- **Behavior change.** For OMP and Pi CLI runs, room messages are marked read later or not at all in a run, never early. Nothing else about steering, acceptance or retries changes.

### Model-visible changes

No prompt, prompt contract or tool schema changes. The one indirect effect: a room message that the OMP or Pi CLI runtime never confirmed is not marked read, so it can be delivered again in the next run or shown in the inbox, where before it was marked read after 30 s.

### 行为变化与入口

以下在该 PR 的差异中可见（5 个文件：`looper/agents/runtimes/omp.py`、`looper/agents/runtimes/pi.py`、`tests/test_codex_room_push.py`、`docs/architecture/agent-system.md`、`docs/architecture/rfcs/worker-steering-v0.zh-CN.md`）。

**#1392：OMP 和 Pi CLI 的 room 推送只凭回执确认**

- **没有兜底已读。**`OmpRuntime` 和 `PiRuntime` 现在设置 `room_receipt_fallback = False`，Worker 把它作为 `receipt_fallback` 传给 room 投递跟踪（`looper/agents/tiers/worker.py`）；Grok 早已如此。此前两者沿用默认的 `True`，接受后 30 秒内没有回执的投递会记录日志并标为已读。
- **什么算确认。**运行时发出的、带有该投递消息 id 的用户消息回执事件。回执只会把席位的已读游标推进到更早已确认的投递之后。
- **没有回执时。**该投递保持未读，留给下次运行或席位的 inbox。Codex 不变，仍保留 30 秒兜底。
- **文档和测试。**`docs/architecture/agent-system.md` 与中文 steering RFC 描述了该规则；`tests/test_codex_room_push.py` 为新行为增加 66 行（删除 16 行）。
- **行为变化。**对 OMP 和 Pi CLI 运行，room 消息在一次运行内会更晚被标为已读或不被标记，不会提前。steer 的其他行为、接受和重试均不变。

**面向模型的变化：**提示词、提示词契约和工具 schema 均无改动。唯一的间接影响：OMP 或 Pi CLI 运行时未确认的 room 消息不再被标为已读，因此可能在下次运行中再次投递或出现在 inbox 中，而此前 30 秒后会被标为已读。
