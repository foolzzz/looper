# Looper v2.13.187

## Release Decision

**Who should upgrade:** Maintainers and integrators who build or run runner-protocol runners (the fake runner, a Pi runner). Other users see no difference. It is a hotfix that ships the changes merged since v2.13.186.

**What this release solves:** [#813](https://github.com/foolzzz/looper/pull/813) extends the runner protocol and the Python host so a runner can resume a saved session through `session/load`, receive the provider account id and a reasoning flag, be given named builtin tools, and report a steer that has no preceding request. It is the host side only.

**Breaking changes:** No for installed users and data: no command, database schema or file format changed. The runner protocol itself changed (see Behavior changes): a runner must now read `provider.account_id` and `provider.reasoning`, and a runner descriptor written by v2.13.186 or earlier no longer parses.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#813](https://github.com/foolzzz/looper/pull/813); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.187
```

## Behavior changes

- **`session/load` ([#813](https://github.com/foolzzz/looper/pull/813)):** `protocol.py` and `messages.schema.json` add the `session/load` method. Its params are the `session/new` params plus `session_id`; its result is `{session_id, resumed: true}`. `RunnerBridge.load_session` refuses a session id the bridge already owns with `SESSION_OWNED`, clears that id's tombstone on success, and treats a result that names another session as a protocol error that fails the connection.
- **Provider fields:** `provider` now requires `account_id` and `reasoning` (boolean) in both the Python types and the schema. The fake runner reads the authorize `provider` from `provider.account_id` instead of the `LOOPER_PROVIDER_ACCOUNT_ID` environment variable, which `RunnerSession` no longer sets.
- **Builtin tools:** `tools.builtin` is a list of non-empty names instead of an array that must be empty. `RunnerSession` passes the descriptor's `builtin` names.
- **Steer position:** `steer_applied.after_request_id` may be `null`.
- **Stable state directory:** `RunnerSupervisor.acquire(kind, owner=...)` places the lease's `state_dir` under `state/<kind>/<owner>` in the supervisor root instead of the per-lease `native` directory, so it survives release and restarts. The owner name is mapped to a safe directory name, and an empty, unmappable or dot-leading owner raises `ValueError`. Without `owner` the old per-lease directory is used. `RunnerSession` passes its label as the owner.
- **Resume:** `RunnerSession.start` acquires a lease and calls `session/load` when the descriptor carries a session id, otherwise `session/new`. If the runner answers `SESSION_NOT_FOUND` or `SESSION_OWNED`, the lease is released and the session reports "runner saved session is unavailable; could not be resumed" on its next turn, as before; any other error is raised. Previously a saved session id never reached the runner.
- **Tool environment:** the `env` sent to the runner is the caller's environment minus the API-key variable (the key travels in `provider.api_key`).
- **Descriptor:** `Descriptor` gains `reasoning`, `system_prompt_mode` (`replace` or `append`, default `replace`, forwarded as the system prompt mode instead of the fixed `replace`) and repeatable `--builtin <name>` arguments (names match `[a-z][a-z_]*`). `to_argv` always emits the two new flags, and `parse` requires them, so an argv produced by an earlier release is rejected as "not a runner session description".
- **Scope:** 11 files changed (322 lines added, 73 removed; 85 production lines and 214 test lines per the pull request, fixtures excluded). No dashboard, API route, database or workflow file changed.
- **Model-visible changes:** None to Looper's prompts, tool descriptions or tool results. The runner protocol now carries `provider.account_id`, `provider.reasoning`, `tools.builtin` names and the descriptor's system prompt mode to the runner, which can change what a runner sends to its model once a runner uses them; no shipped runner does.

## Upgrade and rollback

Re-run `install.sh` once v2.13.187 is published. There is no schema change, so rolling back to v2.13.186 needs nothing else. A runner session description saved by a newer version does not parse on v2.13.186.

### 行为变化与入口

- **`session/load`（#813）：**`protocol.py` 与 `messages.schema.json` 新增 `session/load`，参数为 `session/new` 参数加 `session_id`，结果为 `{session_id, resumed: true}`。`RunnerBridge.load_session` 对 bridge 已持有的会话 id 返回 `SESSION_OWNED`，成功后清除该 id 的墓碑，若结果指向另一会话则视为协议错误并使连接失败。
- **提供方字段：**`provider` 现在必须包含 `account_id` 和 `reasoning`（布尔值），Python 类型与 schema 均如此。fake runner 从 `provider.account_id` 读取 authorize 的 provider，不再读取环境变量 `LOOPER_PROVIDER_ACCOUNT_ID`；`RunnerSession` 也不再设置该变量。
- **内置工具：**`tools.builtin` 由必须为空的数组改为非空名称列表；`RunnerSession` 传入描述符的 `builtin` 名称。
- **Steer 位置：**`steer_applied.after_request_id` 可为 `null`。
- **稳定状态目录：**`RunnerSupervisor.acquire(kind, owner=...)` 把租约的 `state_dir` 放在 supervisor 根目录下的 `state/<kind>/<owner>`，而不是每个租约的 `native` 目录，因此可跨释放和重启保留。owner 名会被映射为安全目录名；为空、无法映射或以点开头时抛出 `ValueError`。不传 `owner` 时仍用原来的每租约目录。`RunnerSession` 以其 label 作为 owner。
- **恢复：**描述符带会话 id 时，`RunnerSession.start` 获取租约并调用 `session/load`，否则调用 `session/new`。runner 返回 `SESSION_NOT_FOUND` 或 `SESSION_OWNED` 时释放租约，下一轮仍报“runner saved session is unavailable; could not be resumed”（与之前一致）；其他错误则抛出。此前已保存的会话 id 不会发给 runner。
- **工具环境：**发给 runner 的 `env` 为调用方环境去掉 API key 变量后的结果（密钥通过 `provider.api_key` 传递）。
- **描述符：**`Descriptor` 新增 `reasoning`、`system_prompt_mode`（`replace` 或 `append`，默认 `replace`，作为系统提示模式转发，不再固定为 `replace`）以及可重复的 `--builtin <name>` 参数（名称匹配 `[a-z][a-z_]*`）。`to_argv` 总会输出这两个新标志，`parse` 要求它们存在，因此早期版本生成的 argv 会被拒绝，提示“not a runner session description”。
- **范围：**改动 11 个文件（新增 322 行、删除 73 行；按该 PR 描述，生产代码 85 行、测试 214 行，不含夹具）。dashboard、API 路由、数据库和 workflow 文件均未改变。
- **面向模型的变化：**Looper 的提示词、工具描述和工具结果无变化。runner 协议现在向 runner 传递 `provider.account_id`、`provider.reasoning`、`tools.builtin` 名称和描述符的系统提示模式；runner 使用这些字段后可能改变它发给模型的内容，目前发布的 runner 均未使用。
