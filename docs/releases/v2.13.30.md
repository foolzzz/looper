# Looper v2.13.30

## Release Decision

**Who should upgrade:** Anyone who sets `backup.command` to a `docker exec ... pg_dump` command with boolean options written as `-t=false` or `-i=false`, and anyone who runs the test suite.

**What this release solves:** [#381](https://github.com/foolzzz/looper/pull/381) fixes review follow-ups of #268. The verifier derived from a `docker exec` backup command now accepts short boolean options written with a value (`-t=false`, `-i=false`). The documentation no longer claims that `LOOPX_BACKUP_VERIFY_CMD` is read. It also widens the deadlines of five timing-sensitive tests.

**Breaking changes:** No. No CLI command, configuration key, API shape or database schema changed. The behavior changes are listed below.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#381](https://github.com/foolzzz/looper/pull/381); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.30
```

## Behavior changes

- **Short boolean options with a value are accepted:** `docker_exec_container` (`looper/agents/db_backup.py`) derives the container of a `docker exec [options] <container> pg_dump ...` backup command, so the verifier can run `pg_restore --list` in that container. A short option cluster such as `-t=false`, `-i=false` or `-it=true` made it give up (return no container), so no verifier was derived. It now treats the `=` as the start of the option's value and carries on. Commands without `=` parse as before.
- **Documentation:** `README.md`, `README.zh-CN.md` and `docs/architecture/agent-system.md` now say that `LOOPER_BACKUP_VERIFY_CMD` and the notes root take only the `LOOPER_` prefix; their `LOOPX_*` names are not read. This matches the code (`looper/ops_config.py` sets `legacy_prefix=False` for both). No code changed for this.
- **Test-only changes:** `tests/test_dsh_installed.py` (the shared process wait goes from 25s to 90s), `tests/test_dsh_runtime.py` (readback wait 45s to 120s, server startup 30s to 90s), `tests/test_gate_channels_db.py` (the retry-delay lower bound allows 60s of slack instead of 5s) and `tests/test_db_backup.py` (a new case for the short booleans with values). No product code changed for these.
- **Model-visible changes:** None. No prompt text, tool schema or tool result changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.30 is published. There is no schema or configuration change. Rolling back to v2.13.29 is safe; the only difference is the previous behavior listed above.

No new optional capability activation is introduced in this release.

### 行为变化与入口

- 接受带值的短布尔选项：`looper/agents/db_backup.py` 的 `docker_exec_container` 从 `docker exec [选项] <容器> pg_dump ...` 备份命令中取出容器，以便在该容器里运行 `pg_restore --list` 校验。此前 `-t=false`、`-i=false`、`-it=true` 会让它放弃（不返回容器），因而推导不出校验命令；现在把 `=` 视为选项值的开始并继续解析。不含 `=` 的命令解析不变。
- 文档：`README.md`、`README.zh-CN.md`、`docs/architecture/agent-system.md` 现明确 `LOOPER_BACKUP_VERIFY_CMD` 与笔记根目录只认 `LOOPER_` 前缀，不读取其 `LOOPX_*` 名称，与代码一致（`looper/ops_config.py` 对二者设置 `legacy_prefix=False`）。此项未改代码。
- 仅测试变更：`tests/test_dsh_installed.py`（进程等待由 25 秒放宽到 90 秒）、`tests/test_dsh_runtime.py`（回读等待 45 秒到 120 秒，服务启动 30 秒到 90 秒）、`tests/test_gate_channels_db.py`（重试延迟下界容差由 5 秒放宽到 60 秒）和 `tests/test_db_backup.py`（新增带值短布尔选项用例）；产品代码未因此改动。
- 面向模型的变化：无。提示词文本、工具 schema、工具结果均无变化。
