# Looper v2.13.115

## Release Decision

**Who should upgrade:** Anyone who uses the dashboard's Gates list with unread markers or paging, and anyone who stops or cancels a running Planner. Others do not need it.

**What this release solves:** [#618](https://github.com/foolzzz/looper/pull/618) keeps the first unread gate's boundary when the Gates list is refreshed with a bounded window, so closed rows cannot erase it, and makes a lost boundary fail visibly rather than restart silently. It also makes a cancelled Planner stop hurry and join the resident Claude cleanup.

**Breaking changes:** No. No route, configuration, request field or stored data format changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#618](https://github.com/foolzzz/looper/pull/618); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.115
```

## Behavior changes

- **Gates list window:** `fetchGates` in `web/src/lib/api.ts` requests `offset + limit + 1` rows for ordinary bounded reads (also the badge's single-row read), so the first unread identity after the loaded window is kept.
- **Saved boundaries:** the boundary lookup now always prefers the nearest surviving key before the saved end, then the nearest one after it. With no surviving key, a "through" refresh restarts from the current list only if the saved window had been exhausted (`end` equals the number of saved keys); otherwise it throws "The gate list changed while loading. Retry the request."
- **Cursor:** a page with no rows but with more rows to load (`end < total`) now returns a continuation cursor instead of `null`.
- **Planner stop:** in `looper/agents/tiers/planner.py`, if the stop is cancelled while the resident Claude is being stopped, Claude is stopped again with `kill=True` and the cancellation is re-raised; the token files are removed in every case.
- **Claude cleanup:** in `looper/agents/claude_cli.py`, a stop with `kill=True` now signals pending cleanups to skip the rest of their stdin-close grace wait, and each cleanup waits for either the process to exit or that signal, whichever comes first, with its helper tasks cancelled and joined.
- **Model-visible changes:** none. No tool declaration, prompt, route or text sent to Workers changed.
- **Tests:** a Planner cancellation test, a browser gate-pagination test and dashboard unit tests for the list and task interactions were updated or added. [#618](https://github.com/foolzzz/looper/pull/618) reports added lines: tests 32, production 83 (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.115 is published. No data migration and no configuration change. Rolling back to v2.13.114 restores the old gate boundary lookup and the old Planner stop cleanup.

### 行为变化与入口

- **Gates 列表窗口：**`web/src/lib/api.ts` 中的 `fetchGates` 对普通有界读取请求 `offset + limit + 1` 行（含徽标的单行读取），从而保留已加载窗口之后的第一条未读标识。
- **已保存边界：**边界查找先取保存位置之前最近的幸存键，再取之后最近的。没有幸存键时，“through”刷新仅在保存的窗口已读尽（`end` 等于保存的键数）时才用当前列表重新开始；否则抛出 “The gate list changed while loading. Retry the request.”。
- **游标：**没有行但仍有更多行可加载（`end < total`）的页面现在返回续页游标，而不是 `null`。
- **Planner 停止：**`looper/agents/tiers/planner.py` 中，若停止在常驻 Claude 被停止期间被取消，则以 `kill=True` 再次停止 Claude 并重新抛出取消；token 文件在任何情况下都会被清理。
- **Claude 清理：**`looper/agents/claude_cli.py` 中，`kill=True` 的停止会通知待处理的清理跳过剩余的 stdin 关闭宽限等待；每个清理等待进程退出或该信号（先到者），其辅助任务会被取消并回收。
- **面向模型的变化：**无。tool 声明、提示词、路由和发给 Worker 的文本均未改变。
- **测试：**更新或新增了 Planner 取消测试、浏览器 gate 分页测试以及仪表盘列表与任务交互的单元测试。[#618](https://github.com/foolzzz/looper/pull/618) 报告新增行数：测试 32、生产代码 83（不含夹具）。
