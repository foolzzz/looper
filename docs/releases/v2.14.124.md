# Looper v2.14.124

This is the patch release v2.14.124, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.123: a Profile that only a workflow references now counts as used and cannot be deleted, and editing a workflow role keeps the Profile the workflow granted ([#1205](https://github.com/foolzzz/looper/pull/1205), issue #1179).

## Release Decision

**Who should upgrade:** Operators who run tasks with a workflow, delete Agent Profiles, or edit a workflow role's prompt or harness in the dashboard. Tasks without a workflow see no change in behavior.

**What this release solves:** [#1205](https://github.com/foolzzz/looper/pull/1205). A Profile referenced only by a workflow is no longer deletable unnoticed, and editing a workflow role no longer loses its granted Profile when that Profile is outside the project's allowed list.

**Breaking changes:** No. There is no database schema change; the Profile usage record gains a `workflows` list (names of the presets that select the Profile).

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.124
```

**Contributors:** Maintainer @foolzzz authored [#1205](https://github.com/foolzzz/looper/pull/1205); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.123 upgrades directly. There is no schema change.

## Behavior changes

- **Workflow references count as Profile usage.** Profile usage (`profile_usage`) gains `workflows`, the names of the operator presets whose Profile map or roles, custom roles included, select the Profile. The usage text names them (`workflow '<name>'`), and the dashboard lists them as `workflow <name>` linking to the workflow settings.
- **Deletion is refused while a workflow selects the Profile.** Deleting a Profile rechecks the preset references under a row lock and raises the same in-use foreign-key error as other references, so it cannot race with saving a workflow.
- **Saving a workflow checks its Profiles.** Saving a preset locks the Profiles it names; if one was removed meanwhile, the save fails with a conflict ("a workflow's Agent Profile was removed meanwhile; reload the profiles") instead of storing a dangling reference.
- **Editing a workflow role keeps its grant.** When a task role's prompt or harness is edited, the Profile the task's workflow snapshot granted that role (matched by key and kind) is accepted by id or name even if the project's allowed list does not include it, and still checked against the role's runtime. New role versions are treated as allowed on the same exact grant, whoever edited them, in the role versions, the role's `task_role` setting layer and `profile_allowed`; a Profile outside both the grant and the project list is still refused.
- **Unchanged:** tasks without a workflow, the project's allowed list and the Planner's choices.
- **Model-visible changes:** None to the Planner, Worker, Reviewer or Manager prompts and contracts. The Profile usage record, the delete refusal, the role-edit result and the dashboard's usage list change as described above.

### 升级决策

**谁需要升级：**运行带工作流的任务、删除 Agent Profile，或在看板中编辑工作流角色提示词或 harness 的运维者。没有工作流的任务行为无变化。

**解决了什么：**[#1205](https://github.com/foolzzz/looper/pull/1205)。只被工作流引用的 Profile 不再会被悄悄删除；当 Profile 不在项目允许列表内时，编辑工作流角色也不再丢失其被授予的 Profile。

**是否有破坏性变更：**否。没有数据库结构变更；Profile 使用记录新增 `workflows` 列表（选用该 Profile 的预设名称）。

**如何验证：**核对版本为 2.14.124。

**贡献者：**维护者 @foolzzz 提交 [#1205](https://github.com/foolzzz/looper/pull/1205)；本版本无社区贡献。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.123 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **工作流引用计入 Profile 使用。**Profile 使用记录（`profile_usage`）新增 `workflows`，即其 Profile 映射或角色（含自定义角色）选用该 Profile 的运维者预设名称。使用说明会列出它们（`workflow '<name>'`），看板显示为 `workflow <name>` 并链接到工作流设置。
- **工作流选用时拒绝删除。**删除 Profile 时在行锁下重新检查预设引用，并抛出与其他引用相同的“仍在使用”外键错误，因此不会与保存工作流竞争。
- **保存工作流时检查 Profile。**保存预设会锁定其引用的 Profile；若其中之一已被同时删除，保存以冲突失败（“a workflow's Agent Profile was removed meanwhile; reload the profiles”），而不是存下悬空引用。
- **编辑工作流角色保留授权。**编辑任务角色的提示词或 harness 时，任务的工作流快照授予该角色（按 key 与 kind 匹配）的 Profile，即使不在项目允许列表中，也可按 id 或名称接受，并仍按角色运行时检查。新的角色版本无论由谁编辑，都按同一精确授权视为允许，体现在角色版本、角色的 `task_role` 设置层和 `profile_allowed` 中；既不在授权内也不在项目列表内的 Profile 仍被拒绝。
- **不变：**没有工作流的任务、项目允许列表和 Planner 的选择。
- **面向模型的变化：**Planner、Worker、Reviewer 和 Manager 的提示词与契约无变化。Profile 使用记录、删除拒绝、角色编辑结果和看板的使用列表按上述方式变化。
