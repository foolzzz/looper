# Looper v2.14.168

This is the patch release v2.14.168, a hotfix line in which each merged change ships at once. It documents one change: [#1306](https://github.com/foolzzz/looper/pull/1306) (Dashboard follow-ups).

## Release Decision

**Who should upgrade:** Installations that use the dashboard's agent history, LLM-request export, project deletion or Cursor login status, or that run TTADK profiles. Others need not upgrade for behavior.

**What this release solves:** [#1306](https://github.com/foolzzz/looper/pull/1306) fixes the listed valid items of the review follow-ups #1076, #1127, #1132 and #1140 (fixes #1140, #1127, #1076, part of #1132): agent history refreshes its Model requests, the dashboard export has a size limit, a TTADK sign-in check that could not finish is shown, project deletion shows its impact first, and the Cursor login status refreshes.

**Breaking changes:** No. There is no migration or database schema change. One additive API change: a new read operation `project_admin.preview_delete`, and an optional `refreshing` field on a provider's login. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.168
```

**Contributors:** Maintainer @foolzzz authored [#1306](https://github.com/foolzzz/looper/pull/1306); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.167 upgrades directly. There is no database schema change.

## Behavior changes

The pull request states that its behavior changes follow the triage notes' fixes (maintainer decision, intended). Read in the code of [#1306](https://github.com/foolzzz/looper/pull/1306):

- **Agent history** (`web/src/pages/agent-history.tsx`). Opening the Model requests section re-fetches its rows. A run card shows a warning, "TTADK sign-in check before this run started", when the run's launch record carries a `ttadk_check` note.
- **TTADK launch note** (`looper/agents/runtimes/ttadk.py`). For an inconclusive check the note recorded in the launch record is now "timed out or failed; the run started anyway" instead of "could not finish (…)". The check itself is unchanged.
- **LLM-request export** (`web/src/lib/api.ts`). The dashboard export fails with an error once it would exceed 256 MiB, pointing to `loopercli llm-requests export` for larger exports. Smaller exports are unchanged.
- **Project deletion** (`looper/agents/v1_domains/projects.py`, `web/src/components/project-settings.tsx`). The new read operation `project_admin.preview_delete` returns the same impact text that deletion confirms with, changing nothing. The dashboard's Delete button now calls it and shows that impact instead of a generic "cannot be undone" line; Cancel takes focus, and a delete or preview error is shown next to the button. Deleting itself is unchanged.
- **Cursor login status** (`looper/agents/runtimes/cursor_login.py`, `looper/agents/v1_domains/registry.py`, `web/src/lib/use-registry.ts`). While a background probe runs, the login view carries `refreshing: true` next to the last known state, and the dashboard re-polls every second while any login is checking or refreshing. The field is optional in the schema.
- **Model-visible changes:** None to prompts or tool descriptions for Planner, Worker or Reviewer. The new operation's description ("Preview deleting a project and its Manager-scope impact without changing anything.") appears in the v1 operation catalog that API clients read.

### 行为变化与入口

该 PR 声明行为变化遵循分诊记录中的修复（维护者决定，符合预期）。[#1306](https://github.com/foolzzz/looper/pull/1306) 在代码中可见：

- **Agent 历史**（`web/src/pages/agent-history.tsx`）。展开 Model requests 时会重新获取其行。启动记录带有 `ttadk_check` 说明时，运行卡片显示 “TTADK sign-in check before this run started” 警告。
- **TTADK 启动说明**（`looper/agents/runtimes/ttadk.py`）。检查未得出结论时，启动记录中的说明由 “could not finish (…)” 改为 “timed out or failed; the run started anyway”。检查本身不变。
- **LLM 请求导出**（`web/src/lib/api.ts`）。dashboard 导出超过 256 MiB 时报错，并指向 `loopercli llm-requests export` 做更大的导出。较小的导出不变。
- **项目删除**（`looper/agents/v1_domains/projects.py`、`web/src/components/project-settings.tsx`）。新增只读操作 `project_admin.preview_delete`，返回删除确认所用的同一影响文本，不做任何改动。dashboard 的删除按钮现在调用它并显示该影响，而不再是通用的“无法撤销”提示；焦点落在取消按钮，删除或预览的错误显示在按钮旁。删除本身不变。
- **Cursor 登录状态**（`looper/agents/runtimes/cursor_login.py`、`looper/agents/v1_domains/registry.py`、`web/src/lib/use-registry.ts`）。后台探测运行期间，登录视图在最近已知状态之外带有 `refreshing: true`，dashboard 在有登录处于 checking 或 refreshing 时每秒重新拉取。该字段在 schema 中是可选的。
- **面向模型的变化：**Planner、Worker、Reviewer 的提示词和工具描述没有变化。新操作的描述（“Preview deleting a project and its Manager-scope impact without changing anything.”）会出现在 API 客户端读取的 v1 操作目录中。
