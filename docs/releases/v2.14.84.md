# Looper v2.14.84

This is the patch release v2.14.84, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.83: a source-checkout upgrade now builds the dashboard before it drains and stops the service, so the build is no longer downtime ([#1100](https://github.com/foolzzz/looper/pull/1100)).

## Release Decision

**Who should upgrade:** Operators who upgrade a source checkout of Looper with `looper service upgrade` and whose upgrades change the dashboard, because the service stays down for the whole dashboard build today. Wheel installs and everyone else can stay.

**What this release solves:** A source-checkout upgrade stopped the service and only then ran `npm ci` and `npm run build`, so the build was downtime; the pull request reports one deploy down 9 min 24 s on a loaded machine, and typically 2-4 min with a dashboard change against under 1 min without one. [#1100](https://github.com/foolzzz/looper/pull/1100) builds the dashboard first, while the service keeps serving.

**Breaking changes:** No. No setting, operation or field is removed and there is no schema change. The upgrade report only gains a field.

**How to verify:** Check the installed version. After a source-checkout upgrade that changes the dashboard, the upgrade report shows a `prepare_seconds` value next to `gap_seconds`, and `gap_seconds` no longer contains the build.

**Contributors:** Maintainer @foolzzz authored [#1100](https://github.com/foolzzz/looper/pull/1100); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.84
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.83 upgrades directly. There is no database change.

## Behavior changes

- **Dashboard built before the drain** (`looper/agents/service.py`). When the plan rebuilds the dashboard (the `web` component changed) for a source checkout, the upgrade first exports the target commit's `web/`, `looper/components.py` and `looper/components.toml` with `git archive` into a temporary directory inside `web/`, runs `npm ci` and the build there with the output in a staging directory next to `web/dist`, checks that `index.html` exists and records the web fingerprint. The service keeps serving meanwhile and the live `web/dist` is untouched. The exported fingerprint hook is needed because the build calls it.
- **A failed build aborts early.** A failing build raises before the drain and the stop, so the service keeps running and the checkout is unchanged. The temporary directory is removed in every case.
- **Shorter downtime.** The stopped interval now holds the git fast-forward merge, the Python dependency sync and the atomic swap of the already built `web/dist`; the checks after the start are unchanged. Installing the checkout without a prepared dashboard when one is needed is refused with an error.
- **Upgrade report** (`looper/agents/service.py`). The report gains `prepare_seconds` (the time spent building before the drain, also recorded when the build fails) next to `gap_seconds`.
- **Unchanged:** wheel installs, upgrades that do not change the dashboard, the plan, drain and keeper behavior, and the API.
- **Documentation and tests.** The upgrade paragraph of `docs/architecture/agent-system.md` describes the new order. `tests/test_service_upgrade_execution.py` covers the build running before the drain and the stop and then merge, sync, swap and start; a failing build leaving the service running with no stop; and `prepare_seconds` being reported.
- **Model-visible changes:** None. No tool schema, instruction or prompt a model receives changes.

## 中文摘要

本版本是 patch release v2.14.84（热修线，每个合并的改动立即发布）。自 v2.14.83 以来只合并了一项改动：源码检出的升级现在在排空和停止服务之前先构建仪表盘，构建不再计入停机时间（[#1100](https://github.com/foolzzz/looper/pull/1100)）。

### 升级决策

**谁需要升级：**用 `looper service upgrade` 升级源码检出、且升级涉及仪表盘改动的运维人员，因为目前整个仪表盘构建期间服务都处于停机。wheel 安装和其他人可不升级。

**解决了什么：**源码检出的升级曾先停止服务，再运行 `npm ci` 和 `npm run build`，构建因此成为停机时间；PR 报告在负载较高的机器上一次部署停机 9 分 24 秒，有仪表盘改动的部署通常停机 2-4 分钟，无改动的不到 1 分钟。[#1100](https://github.com/foolzzz/looper/pull/1100) 在服务继续提供服务的同时先构建仪表盘。

**是否有破坏性变更：**否。没有移除设置、操作或字段，也没有数据库结构变更。升级报告只新增一个字段。

**如何验证：**核对版本为 2.14.84。在改动仪表盘的源码检出升级后，升级报告在 `gap_seconds` 旁显示 `prepare_seconds`，且 `gap_seconds` 不再包含构建时间。

**贡献者：**维护者 @foolzzz 提交 [#1100](https://github.com/foolzzz/looper/pull/1100)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.84
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.83 上的安装可直接升级。没有数据库变更。

### 行为变化与入口

- **排空前构建仪表盘**（`looper/agents/service.py`）。当计划需要重建仪表盘（`web` 组件有变化）且为源码检出时，升级先用 `git archive` 把目标提交的 `web/`、`looper/components.py` 和 `looper/components.toml` 导出到 `web/` 内的临时目录，在其中运行 `npm ci` 和构建，输出到 `web/dist` 旁的暂存目录，检查 `index.html` 存在并记录 web 指纹。期间服务继续运行，现有 `web/dist` 不被改动。导出指纹钩子是因为构建会调用它。
- **构建失败提前中止。**构建失败会在排空和停止之前报错，服务继续运行，检出不变。临时目录在任何情况下都会被清理。
- **停机更短。**停机区间现在只包含 git 快进合并、Python 依赖同步和对已构建 `web/dist` 的原子目录替换；启动后的检查不变。需要仪表盘却没有预先构建时，安装检出会报错拒绝。
- **升级报告**（`looper/agents/service.py`）。报告在 `gap_seconds` 旁新增 `prepare_seconds`（排空前构建所用时间，构建失败时也会记录）。
- **不变：**wheel 安装、不涉及仪表盘改动的升级、计划、排空与 keeper 行为，以及 API。
- **文档与测试。**`docs/architecture/agent-system.md` 的升级段落描述了新的顺序。`tests/test_service_upgrade_execution.py` 覆盖：构建先于排空和停止，随后合并、同步、替换和启动；构建失败时服务保持运行且不停止；以及 `prepare_seconds` 被报告。
- **面向模型的变化：**无。模型收到的工具模式、指令和提示均不变。
