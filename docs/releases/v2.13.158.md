# Looper v2.13.158

## Release Decision

**Who should upgrade:** Operators who run Managers on the Claude Code runtime and use background Agents. Everyone else can stay on v2.13.157.

**What this release solves:** [#729](https://github.com/foolzzz/looper/pull/729) clears the untracked background-job marker when a Claude Code background Agent fails to start, so the Manager process can be suspended when idle. Before, a failed launch left the marker set and the process was never judged idle.

**Breaking changes:** No. No API, configuration, schema, prompt or Tool declaration changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#729](https://github.com/foolzzz/looper/pull/729); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.158
```

## Behavior changes

- **Failed background Agent launch no longer blocks idle suspension ([#729](https://github.com/foolzzz/looper/pull/729)):** in `looper/agents/claude_cli.py`, when the Claude CLI stream carries a `user` event with a `tool_result` block whose `is_error` is true, the output parser now removes that `tool_use_id` from its set of untracked background jobs. A launch that fails has no `task_started` event, so nothing else would clear the marker. A job that already started stays tracked: the tests cover an error result after start, a success result without a task id, and a started job that is still running as not suspendable, and a failed launch and a finished job as suspendable.
- **Scope:** only the Claude CLI event parsing changes (8 production lines). Other runtimes, the idle policy itself and stored data are untouched.
- **Model-visible changes:** none. No prompts, tool descriptions, tool schemas or tool results change; only the host's decision on when an idle process may be suspended.
- **Tests:** `tests/test_resident_idle.py` gains a parametrized test over five states of the recorded background Agent stream. The description reports 35 added test lines and 8 production lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.158 is published. No data migration and no configuration change. Rolling back to v2.13.157 restores the previous behavior, where a failed background Agent launch keeps the process from being suspended.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 升级决策

### 行为变化与入口

- **后台 Agent 启动失败不再阻止空闲挂起（[#729](https://github.com/foolzzz/looper/pull/729)）：**在 `looper/agents/claude_cli.py` 中，当 Claude CLI 流里出现 `user` 事件，其 `tool_result` 块的 `is_error` 为 true 时，输出解析器现在会把该 `tool_use_id` 从未跟踪后台任务集合中移除。启动失败没有 `task_started` 事件，没有其他路径会清除标记。已经启动的任务仍保持被跟踪：测试覆盖了启动后的错误结果、没有任务 id 的成功结果、仍在运行的已启动任务（均不可挂起），以及启动失败和已完成的任务（可挂起）。
- **范围：**只改变 Claude CLI 的事件解析（8 行生产代码）。其他运行时、空闲策略本身和已存数据均不受影响。
- **面向模型的变化：**无。提示词、工具描述、工具 schema 和工具结果均未变化；只改变宿主判断空闲进程何时可以挂起。
- **测试：**`tests/test_resident_idle.py` 新增一个参数化测试，覆盖已记录的后台 Agent 流的五种状态。描述报告新增测试 35 行、生产代码 8 行（不含 fixture）。
