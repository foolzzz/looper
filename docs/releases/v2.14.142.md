# Looper v2.14.142

This is the patch release v2.14.142, a hotfix line in which each merged change ships at once. It documents one change: [#1246](https://github.com/foolzzz/looper/pull/1246) (profile fallbacks also cover a run that exits before any model event).

## Release Decision

**Who should upgrade:** Operators whose Worker or Reviewer profiles use a fallback chain with Claude Code, Codex, coco, Cursor Agent or Grok, because a run that exits before any model event now moves to the next profile of the chain. Everyone else gets no visible change.

**What this release solves:** [#1246](https://github.com/foolzzz/looper/pull/1246) makes a Worker or Reviewer run that exits non-zero, or is refused at launch for its model, before any model event fall back to the next profile of its chain, recorded like other fallbacks. A run that produced any model event never falls back.

**Breaking changes:** No. There is no migration and no API removal. The pull request calls the fallback change intended (a maintainer decision), and timeouts no longer trigger this detection (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.142
```

**Contributors:** Maintainer @foolzzz authored [#1246](https://github.com/foolzzz/looper/pull/1246); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.141 upgrades directly. There is no schema change.

## Behavior changes

- **A run that exits before any model event falls back** ([#1246](https://github.com/foolzzz/looper/pull/1246), `looper/agents/tiers/worker.py`). When a Worker or Reviewer run exits non-zero, or ends with an error result reporting zero turns (a model refusal, even with exit code 0), and no model event was seen, the run is not a success, and the failure is not a spend-cap error, the fallback reason is `exited before any model event: <first line of the error>`. The error is the failure detail, else the first result error, else stderr, else "<runtime> exited with code <n>". The switch stays in the same step attempt, consumes no retry, and is recorded like other profile fallbacks. A run that produced any model event never falls back.
- **Timeouts no longer trigger this detection** (`looper/agents/tiers/worker.py`). The earlier `no_model_events` reason set when a run timed out before any model event is removed.
- **Which adapters** (`looper/agents/runtimes/`). `first_event_known` is now enabled for Claude Code, Codex (and coco, which builds on it), Cursor Agent (native and TTADK) and Grok. OMP, Pi, DSH and API keep it disabled, so their behavior is unchanged.
- **What counts as a model event** (`looper/agents/runtimes/__init__.py`, `claude_code.py`, `codex.py`, `codex_steer.py`, `cursor_agent.py`). A launcher initialization naming a model is no longer one. Responses, tool calls, partial model output and nonzero token usage are. Claude Code counts stream message and content-block events and an init event carrying request tokens; Codex counts non-error items, including partial ones the stream now surfaces as a `codex_item` event, and early token usage through a new `codex_usage` event; Cursor Agent counts non-empty thinking deltas and partial messages, which its stream now surfaces as `cursor_event`. The adapters' event streams gain these internal events.
- **Documentation** (`docs/architecture/agent-system.md`) describes the above. The Planner still follows a chain only for a profile configuration error.
- **Unchanged:** the storage format of runs and journal entries, and the Planner, Worker, Reviewer and Manager prompts.
- **Model-visible changes:** No. The pull request changes which profile runs after a failed start, not any prompt text. The agent that runs next may differ from before.

### 升级决策

**谁需要升级：**Worker 或 Reviewer 档案配置了回退链、且使用 Claude Code、Codex、coco、Cursor Agent 或 Grok 的运维者，因为在任何模型事件之前退出的运行现在会转到链中的下一个档案。其他人没有可见变化。

**解决了什么：**[#1246](https://github.com/foolzzz/looper/pull/1246) 让在任何模型事件之前以非零退出、或因模型被拒而在启动时失败的 Worker 或 Reviewer 运行回退到链中的下一个档案，并与其他回退一样记录。产生过任何模型事件的运行不会回退。

**是否有破坏性变更：**否。没有迁移，没有移除 API。PR 称该回退变化是维护者的有意决定；超时不再触发这一检测（见下文）。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.141 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **在任何模型事件之前退出的运行会回退**（[#1246](https://github.com/foolzzz/looper/pull/1246)，`looper/agents/tiers/worker.py`）。Worker 或 Reviewer 运行以非零退出，或以报告 0 轮的错误结果结束（模型被拒，即使退出码为 0），且没有见到模型事件、运行不算成功、失败也不是花费上限错误时，回退原因为 `exited before any model event: <错误的第一行>`。错误取失败详情，其次是结果中的第一条错误，其次是 stderr，最后是“<运行时> exited with code <n>”。切换发生在同一步骤尝试内，不消耗重试，并与其他档案回退一样记录。产生过任何模型事件的运行不会回退。
- **超时不再触发这一检测**（`looper/agents/tiers/worker.py`）。运行在任何模型事件之前超时时设置的 `no_model_events` 原因被移除。
- **适用的适配器**（`looper/agents/runtimes/`）。`first_event_known` 现已对 Claude Code、Codex（及基于它的 coco）、Cursor Agent（原生与 TTADK）和 Grok 启用。OMP、Pi、DSH 和 API 仍为关闭，行为不变。
- **什么算模型事件**（`looper/agents/runtimes/__init__.py`、`claude_code.py`、`codex.py`、`codex_steer.py`、`cursor_agent.py`）。仅声明模型名的启动器初始化不再算。响应、工具调用、部分模型输出和非零 token 用量算。Claude Code 计入流式消息与内容块事件，以及带请求 token 的 init 事件；Codex 计入非错误条目（包括流现在以 `codex_item` 事件给出的部分条目），以及通过新的 `codex_usage` 事件给出的早期 token 用量；Cursor Agent 计入非空的思考增量和部分消息，其流现在以 `cursor_event` 给出。适配器的事件流因此新增这些内部事件。
- **文档**（`docs/architecture/agent-system.md`）描述了上述内容。Planner 仍只在档案配置错误时沿链回退。
- **不变：**运行与日志条目的存储格式，以及 Planner、Worker、Reviewer 和 Manager 提示词。
- **面向模型的变化：**无。PR 改变的是启动失败后由哪个档案运行，而不是任何提示词文本。接下来运行的代理可能与以前不同。
