# Looper v2.14.125

This is the patch release v2.14.125, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.124: the private copy of declared runtime state that a workflow verification role works in now keeps internal symbolic links as links inside the copy, so Node toolchain commands and strict editable Python imports work from it ([#1202](https://github.com/foolzzz/looper/pull/1202), issue #1199).

## Release Decision

**Who should upgrade:** Operators who run tasks with a workflow that has a verification role and declares runtime state (for example `node_modules` or a virtualenv) for that role to copy. Tasks without a workflow see no change in behavior.

**What this release solves:** [#1202](https://github.com/foolzzz/looper/pull/1202). Copying declared runtime state used to dereference or break internal links such as `node_modules/.bin` entries, and generated source links did not resolve on macOS, where `/var` and `/private/var` are the same place. A Node toolchain command and a strict editable Python import now work from the copy.

**Breaking changes:** No. There is no database schema change and no API change.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.125
```

**Contributors:** Maintainer @foolzzz authored [#1202](https://github.com/foolzzz/looper/pull/1202); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.124 upgrades directly. There is no schema change.

## Behavior changes

- **Internal links stay links.** When the verification copy takes a declared runtime path, a symbolic link whose target lies inside the declared tree is recreated as a relative link to the private copy of that target, rather than being dereferenced. A link that points at another declared path is relocated to that path's private copy; a link into the repository checkout is relocated to the matching file in the private checkout when it exists there.
- **Canonical paths.** The source and target roots are resolved to their canonical paths before copying, so relocated links resolve where a path such as `/var` is an alias of `/private/var`.
- **Links outside the declared paths.** An external link to a regular file is copied as a private file (as for a virtualenv interpreter that lives outside the environment). An external link to a directory is skipped with a logged warning that names the link's path relative to the copy, instead of failing the copy.
- **Declaration order.** Declared paths are resolved first, and a path covered by another declared path is not treated as its own root, so an external virtualenv interpreter is not mapped back onto itself.
- **Bytecode caches.** `__pycache__` directories inside declared runtime paths are not copied, so Python recompiles from the private sources instead of accepting bytecode left by the old location. Stale `.pyc` links are skipped as before.
- **Unchanged:** tasks without a workflow, the rules that reject absolute or `..` paths, repository metadata (`.git`), special files and replacing repository files, and the Planner's choices.
- **Model-visible changes:** None to the Planner, Worker, Reviewer or Manager prompts and contracts. The only change is the content of the private copy a workflow verification role works in; commands there now find the toolchain links they expect.

**解决了什么：**[#1202](https://github.com/foolzzz/looper/pull/1202)。复制已声明的运行时状态时，`node_modules/.bin` 等内部链接以前会被解引用或失效；在 macOS 上 `/var` 与 `/private/var` 是同一位置，生成的源码链接也无法解析。现在 Node 工具链命令和严格的可编辑 Python 导入都能在副本中工作。

**是否有破坏性变更：**否。没有数据库结构变更，也没有 API 变更。

**如何验证：**核对版本为 2.14.125。

**贡献者：**维护者 @foolzzz 提交 [#1202](https://github.com/foolzzz/looper/pull/1202)；本版本无社区贡献。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.124 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **内部链接保持为链接。**验证副本复制已声明的运行时路径时，目标位于已声明目录树内的符号链接会重建为指向该目标私有副本的相对链接，而不是被解引用。指向另一个已声明路径的链接会重定位到该路径的私有副本；指向仓库检出的链接，若私有检出中存在对应文件，则重定位到该文件。
- **规范化路径。**复制前先把源与目标根解析为规范路径，因此在 `/var` 是 `/private/var` 别名的系统上，重定位后的链接也能解析。
- **已声明路径之外的链接。**指向普通文件的外部链接会作为私有文件复制（如位于环境之外的虚拟环境解释器）。指向目录的外部链接会被跳过，并记录一条警告（给出该链接相对副本的路径），而不是让复制失败。
- **声明顺序。**先解析已声明的路径；被另一个已声明路径覆盖的路径不会成为独立的根，因此外部虚拟环境解释器不会被映射回自身。
- **字节码缓存。**已声明运行时路径内的 `__pycache__` 目录不再复制，Python 会从私有源码重新编译，而不是接受旧位置留下的字节码。过期的 `.pyc` 链接仍与以前一样被跳过。
- **不变：**没有工作流的任务；拒绝绝对路径或 `..` 路径、仓库元数据（`.git`）、特殊文件和覆盖仓库文件的规则；Planner 的选择。
- **面向模型的变化：**Planner、Worker、Reviewer 和 Manager 的提示词与契约无变化。唯一变化是工作流验证角色所用私有副本的内容；其中的命令现在能找到它们期望的工具链链接。
