# Looper v2.13.92

## Release Decision

**Who should upgrade:** Anyone who runs the Planner on the Claude Code runtime from a working directory that is a symlink. Everyone else gets no change.

**What this release solves:** [#552](https://github.com/foolzzz/looper/pull/552) stops a Planner whose working directory is a symlink into a non-repository tree from receiving read permission for the unrelated repository that contains the link.

**Breaking changes:** No. Reads inside the resolved repository, in supplied directories and through the link's own path keep working.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#552](https://github.com/foolzzz/looper/pull/552); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.92
```

## Behavior changes

- **Planner read scope ([#552](https://github.com/foolzzz/looper/pull/552)):** `read_only_args` in `looper/agents/claude_cli.py` builds the read allow rules of a read-only run (a Planner's) from the repository root of the resolved working directory, the repository root of its lexical spelling, and the supplied directories. The lexical root is now kept only if it resolves to the same repository as the real root; otherwise the working directory's own spelling is used instead of the outer repository's root. So a symlink inside an unrelated repository no longer grants that outer tree, while documents through the link are still allowed. Rules still escape literal special characters in paths, and `add_dirs` are not expanded to their repositories.
- **Model-visible changes:** none found in prompt text or Tool declarations. The permission rules passed to the Claude Code CLI for a read-only run change in the symlink case above, so a Planner can no longer read files there that it could read before.
- **Tests:** four tests were added to `tests/test_system_prompt.py` (symlink to a non-repository never grants the outer repository; reads above the working directory stay inside the actual repository; special path characters stay escaped; explicit `add_dirs` stay exact).

## Upgrade and rollback

Re-run `install.sh` once v2.13.92 is published. No data migration. Rolling back to v2.13.91 restores the wider read scope.

### 升级决策

**谁需要升级：**在 Claude Code 运行时下，从符号链接目录运行 Planner 的人。其他人无变化。

**解决了什么：**[#552](https://github.com/foolzzz/looper/pull/552) 避免工作目录是指向非仓库目录的符号链接时，Planner 获得链接所在的无关仓库的读取权限。

**是否有破坏性变更：**无。已解析仓库内、额外提供的目录内以及通过链接自身路径的读取照常工作。

**如何验证：**运行 `looper --version` 核对版本为 2.13.92。

**贡献者：**维护者 @foolzzz 提交 [#552](https://github.com/foolzzz/looper/pull/552)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.92
```

### 行为变化与入口

- **Planner 读取范围（[#552](https://github.com/foolzzz/looper/pull/552)）：**`looper/agents/claude_cli.py` 中的 `read_only_args` 为只读运行（Planner）生成读取允许规则，依据已解析工作目录的仓库根、其字面路径的仓库根，以及额外提供的目录。字面路径的仓库根现在仅在与真实根指向同一仓库时保留；否则使用工作目录自身的路径，而不是外层仓库的根。因此位于无关仓库中的符号链接不再授予该外层目录，而通过链接访问文档仍被允许。规则仍会转义路径中的特殊字符，`add_dirs` 不会扩展到其所在仓库。
- **面向模型的变化：**prompt 文本和 Tool 声明未发现变化。上述符号链接场景下，传给 Claude Code CLI 的只读运行权限规则有变化，Planner 不能再读取之前可读的那些文件。
- **测试：**在 `tests/test_system_prompt.py` 新增四个测试（指向非仓库的符号链接不授予外层仓库；工作目录之上的读取限于实际仓库；特殊路径字符保持转义；显式 `add_dirs` 保持精确）。
