# Looper v2.14.7

This is the patch release v2.14.7. It ships the one change merged since v2.14.6: [#882](https://github.com/foolzzz/looper/pull/882), which releases the DSH session lock when a cancel times out during authorization. It affects only installations that set `[runtimes] dsh = "runner"`.

## Release Decision

**Who should upgrade:** Operators who run DSH roles on the DSH runner (`[runtimes] dsh = "runner"`). Nothing changes for an installation whose ops file does not set it (the default is `cli`). It ships the one change merged since v2.14.6.

**What this release solves:** [#882](https://github.com/foolzzz/looper/pull/882) fixes issue #881: when a cancel deadline expired while a DSH runner turn still waited for `budget/authorize`, the session write lock was not released, so resuming the same session right after `settled` could fail.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#882](https://github.com/foolzzz/looper/pull/882); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.7
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.6 upgrades directly. This release changes no schema, stored data or setting.

## Behavior changes

All changes are in the packaged DSH runner (`runners/dsh/src/`) and are reached only with `[runtimes] dsh = "runner"`.

- **Authorization wait ends with the cancel deadline (`provider.ts`):** the agent's wait for `budget/authorize` is raced against the turn's authorization-expiry signal. When the cancel deadline forces the turn, the wait ends as a denial, so the agent can finish and the SDK session writer closes.
- **Session released before `settled` (`turn.ts`):** a forced settle now releases the session itself, before the flush and before `settled`; cancel no longer releases it in the background and awaits it afterwards. The session lock is therefore free when `settled` is sent, and the same session can be loaded or resumed right after it.
- **Late authorization reply (`provider.ts`):** the authorization RPC stays alive after the wait expires. A late allow is accounted once, as an aborted, complete request with zero tokens. A late deny or authorization error is accounted as no request. `endRequest` no longer ignores requests that end after the turn has settled, so this `request_end` can arrive after `settled`; in v2.14.6 a late allow was accounted before `settled`. The expired request is never sent to the model.
- **Tests (`tests/test_dsh_runner_requests.py`):** the cancel-deadline test now covers allow, deny and error replies for both cancel and close, loads the same session before the reply, checks accounting, and resumes the session for a normal turn.
- **Model-visible changes:** None. Prompts, tools and model requests are unchanged; a late allowed authorization now yields its `request_end` on the host side after `settled`.

### 行为变化与入口

以下改动都在打包的 DSH runner（`runners/dsh/src/`）中，仅在 `[runtimes] dsh = "runner"` 时生效。

- **授权等待随取消期限结束（`provider.ts`）：**agent 对 `budget/authorize` 的等待与回合的授权过期信号竞争。取消期限强制结算时，等待以拒绝结束，agent 得以收尾，SDK 的会话写入器随之关闭。
- **`settled` 之前释放会话（`turn.ts`）：**强制结算现在自行在刷盘和 `settled` 之前释放会话；取消不再在后台释放并事后等待。因此发出 `settled` 时会话锁已释放，之后可立即加载或恢复同一会话。
- **迟到的授权回复（`provider.ts`）：**授权 RPC 在等待过期后仍保持存活。迟到的允许记为一次已中止、完整、零 token 的请求（仅一次）；迟到的拒绝或授权错误记为没有请求。`endRequest` 不再忽略回合结算之后才结束的请求，因此该 `request_end` 可能在 `settled` 之后到达；v2.14.6 中迟到的允许是在 `settled` 之前记账。过期的请求不会发送给模型。
- **测试（`tests/test_dsh_runner_requests.py`）：**取消期限测试现覆盖 cancel 与 close 下的允许、拒绝、错误三种回复，回复前加载同一会话，检查记账，并恢复该会话执行正常回合。
- **面向模型的变化：**无。提示、工具和模型请求都不变；迟到的允许授权现在在宿主侧于 `settled` 之后产生其 `request_end`。
