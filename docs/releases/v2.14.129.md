# Looper v2.14.129

This is the patch release v2.14.129, a hotfix line in which each merged change ships at once. It documents three changes: [#1217](https://github.com/foolzzz/looper/pull/1217) (the `coco` runtime can run the Manager and Planners), [#1219](https://github.com/foolzzz/looper/pull/1219) (web chat tasks of the default Manager report into their chat) and [#1221](https://github.com/foolzzz/looper/pull/1221) (Worker reports and reviewer verdicts with stray backslash escapes are accepted).

## Release Decision

**Who should upgrade:** Operators who want Coco (TRAE CLI) to run the Manager or Planners; anyone who creates tasks from the dashboard chat with the default Manager and wants progress in that chat; anyone whose Workers or Reviewers sometimes end with JSON that carries stray backslashes (for example Windows paths). Everyone else gets no change.

**What this release solves:** [#1217](https://github.com/foolzzz/looper/pull/1217) adds the Manager and Planner roles to the `coco` runtime. [#1219](https://github.com/foolzzz/looper/pull/1219) saves phase notices, gate notices and completion of a default-Manager dashboard-chat task into that chat. [#1221](https://github.com/foolzzz/looper/pull/1221) stops a report or verdict from failing on stray backslash escapes alone, and names the parse error when a JSON block still does not parse.

**Breaking changes:** No. There is no migration and no API removal. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.129
```

**Contributors:** Maintainer @foolzzz authored [#1217](https://github.com/foolzzz/looper/pull/1217), [#1219](https://github.com/foolzzz/looper/pull/1219) and [#1221](https://github.com/foolzzz/looper/pull/1221); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.128 upgrades directly. There is no schema change.

## Behavior changes

- **Coco runs the Manager and Planners** ([#1217](https://github.com/foolzzz/looper/pull/1217), a maintainer decision). The `coco` runtime gains the resident-session and resume capabilities. A Manager or Planner turn is one `coco exec` process, and later turns run `resume <thread> -`. Sessions live under `<runtime_root>/.local/coco/sessions/<label>` and receive the run home's configuration, instructions and login link before each turn; the Planner's MCP servers set `default_tools_approval_mode = "approve"`. Per-turn usage is the difference of the session's token totals. Unused coco session homes are reclaimed unless a saved session or running process names them.
- **Stopping a Coco Manager turn** is the per-turn kill, as for Codex: the user's stop is refused (`can_interrupt=False`), and cancellation by another caller ends the turn's process tree and keeps the thread id. Steer, consult, effort and structured output stay off for coco.
- **Default-Manager dashboard-chat tasks report into their chat** ([#1219](https://github.com/foolzzz/looper/pull/1219)). A task created from a web chat with a known session records that session as `origin_thread`, now also for the default Manager without an API client. Its acceptance, phase and user-gate notices and its end, including the workflow delivery summary, are saved as messages in that chat and reach an open dashboard through the session subscription. A progress envelope with no phase text but a summary now posts the summary. Tasks created without a chat session (CLI or direct API) record no `origin_thread` and post no web chat message.
- **Stray backslash escapes in JSON reports are repaired** ([#1221](https://github.com/foolzzz/looper/pull/1221), a maintainer decision). When a Worker status report or a reviewer verdict fails to parse only because of invalid backslash escapes, those backslashes are doubled and the report is accepted; the run records `report_repaired`. Valid escape pairs are left alone. Nothing else is repaired.
- **Parse errors are named.** A report or verdict whose JSON block still does not parse now fails with "<Worker or Reviewer> ended with a JSON <status report or verdict> that does not parse: <error> (line N column M)" instead of "did not end with the JSON ...". When no JSON block carries the key, the earlier message is kept.
- **Unchanged:** all other runtimes, Coco Workers and Reviewers, and tasks without a dashboard chat session.
- **Model-visible changes:** No Planner, Worker, Reviewer or Manager prompt or contract text changes. A coco Manager or Planner reads a run `AGENTS.md` whose runtime notes name Coco (TRAE CLI), as coco Workers already do. The notices saved into the chat by [#1219](https://github.com/foolzzz/looper/pull/1219) are new chat messages in that session's history. The failure text of an unparseable report or verdict changes as above, and a repaired report is read by the judge as the parsed report.

## Optional Capability Activation & Use

### Coco runtime

**Activation:** Opt-in and operator-only. Sign in with `coco login` on the server's machine, have `coco` on the server's PATH, then create an Agent Profile that pairs it with the `coco login` provider and a model from `coco models`, and assign it to the Manager, a Planner, the Worker or the Reviewer role (the Manager and Planner roles are new in this release).

**Validation:** The runtime's probe in Settings shows the `coco --version` output; `looper doctor` shows the `coco_login` check. A run with no login or an unknown model is refused before the process starts. See the Coco section of the agent system document.

**Disable / rollback:** Move the Manager, Planner, Worker and Reviewer roles back to another Agent Profile and delete the coco profile or runtime. Removing `coco` from PATH makes coco profiles unusable with a clear refusal.

**Authority boundary:** The operator's coco login stays in the operator's account; Looper links it into a private run home without reading it. Coco's own sandbox and permissions apply to the agent. TRAE's servers receive the model requests, and Looper's recording proxy does not record them. The Planner's coco MCP servers auto-approve their tools within the Looper platform bridge. Client tokens cannot select the runtime.

### 升级决策

**谁需要升级：**想让 Coco（TRAE CLI）运行 Manager 或 Planner 的运维者；在仪表盘聊天中用默认 Manager 创建任务、希望进度出现在该聊天的用户；Worker 或 Reviewer 的 JSON 偶尔带有多余反斜杠（例如 Windows 路径）的用户。其他人无变化。

**解决了什么：**[#1217](https://github.com/foolzzz/looper/pull/1217) 为 `coco` 运行时加入 Manager 和 Planner 角色。[#1219](https://github.com/foolzzz/looper/pull/1219) 把默认 Manager 的仪表盘聊天任务的阶段通知、门禁通知和完成信息保存到该聊天。[#1221](https://github.com/foolzzz/looper/pull/1221) 让报告或结论不再仅因多余的反斜杠转义而失败，JSON 仍无法解析时会指出解析错误。

**是否有破坏性变更：**否。没有迁移，没有移除 API。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.128 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **Coco 运行 Manager 和 Planner**（[#1217](https://github.com/foolzzz/looper/pull/1217)，维护者的决定）。`coco` 运行时新增常驻会话和 resume 能力。Manager 或 Planner 的一轮是一个 `coco exec` 进程，之后的轮次执行 `resume <thread> -`。会话位于 `<runtime_root>/.local/coco/sessions/<label>`，每轮前接收运行主目录的配置、指令和登录链接；Planner 的 MCP 服务设置 `default_tools_approval_mode = "approve"`。每轮用量由会话 token 总数相减得出。未使用的 coco 会话目录会被回收，除非有已保存的会话或运行中的进程仍在使用。
- **停止 Coco 的 Manager 轮次**与 Codex 相同，是按轮次终止：用户的停止被拒绝（`can_interrupt=False`），其他调用方的取消会结束该轮的进程树并保留 thread id。steer、consult、effort 和结构化输出对 coco 仍然关闭。
- **默认 Manager 的仪表盘聊天任务回报到所在聊天**（[#1219](https://github.com/foolzzz/looper/pull/1219)）。在已知会话的网页聊天中创建的任务会把该会话记为 `origin_thread`，现在默认 Manager 且没有 API 客户端时也是如此。其接受、阶段和用户门禁通知以及结束（含工作流交付摘要）会作为消息保存到该聊天，并通过会话订阅到达已打开的仪表盘。没有阶段文本但带摘要的进度信封现在会发出摘要。没有聊天会话创建的任务（CLI 或直接 API）不记录 `origin_thread`，也不向网页聊天发消息。
- **修复 JSON 报告中多余的反斜杠转义**（[#1221](https://github.com/foolzzz/looper/pull/1221)，维护者的决定）。Worker 状态报告或 Reviewer 结论仅因无效反斜杠转义而无法解析时，这些反斜杠会被加倍并接受该报告，运行记录 `report_repaired`。合法的转义对不受影响。除此之外不做任何修复。
- **解析错误会被指明。**报告或结论的 JSON 块仍无法解析时，现在以“<Worker 或 Reviewer> ended with a JSON <status report 或 verdict> that does not parse: <错误> (line N column M)”失败，取代“did not end with the JSON ...”。没有带该键的 JSON 块时保持原消息。
- **不变：**其他所有运行时、Coco 的 Worker 和 Reviewer，以及没有仪表盘聊天会话的任务。
- **面向模型的变化：**Planner、Worker、Reviewer 和 Manager 的提示词与契约文本无变化。coco 的 Manager 或 Planner 读到的运行 `AGENTS.md` 中运行时说明写 Coco (TRAE CLI)，与 coco Worker 已有的相同。[#1219](https://github.com/foolzzz/looper/pull/1219) 保存到聊天的通知是该会话历史中的新消息。无法解析的报告或结论的失败文本如上变化，被修复的报告按解析后的报告交给判定。

### 可选能力启用与使用

#### Coco runtime

**启用：**需主动启用，且仅限运维人员。在服务器上执行 `coco login` 登录，让 `coco` 在服务器 PATH 上，然后创建把它与 `coco login` 提供方和 `coco models` 中某个模型配对的 Agent Profile，并分配给 Manager、Planner、Worker 或 Reviewer 角色（Manager 和 Planner 角色为本版本新增）。

**验证：**设置中运行时的探测显示 `coco --version` 的输出；`looper doctor` 显示 `coco_login` 检查。没有登录或模型未知的运行在进程启动前即被拒绝。详情见 agent system 文档中的 Coco 一节。

**停用 / 回退：**把 Manager、Planner、Worker 和 Reviewer 角色改回其他 Agent Profile，并删除 coco Profile 或运行时。把 `coco` 从 PATH 移除会让 coco Profile 无法使用，并给出明确的拒绝信息。

**权限边界：**运维者的 coco 登录留在运维者的账户中；Looper 把它链接进私有的运行目录而不读取它。Coco 自己的沙箱和权限对 agent 生效。模型请求由 TRAE 的服务器接收，Looper 的记录代理不会记录。Planner 的 coco MCP 服务在 Looper 平台桥内自动批准其工具。客户端令牌不能选用该运行时。
