# Looper v2.13.48

## Release Decision

**Who should upgrade:** Operators who set or clear the sign-in password, run the self checks, or export and import configuration from the command line, and anyone who scripts `looper config export` or `looper config import`: those two commands are gone.

**What this release solves:** [#430](https://github.com/foolzzz/looper/pull/430) moves `auth`, `doctor` and `config` into `loopercli`, through new v1 operations of the running service (stage 2a of the client-skill RFC), and removes the offline `looper config export` and `looper config import`.

**Breaking changes:** Yes. `looper config export` and `looper config import` were removed; `looper config` keeps only `init-ops`. Use `loopercli config export` and `loopercli config import` with a file; apply a preview with `loopercli config import --apply` and the import id, then `loopercli confirm` with the confirmation id. They need the running service.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#430](https://github.com/foolzzz/looper/pull/430); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.48
```

## Behavior changes

- **New v1 operations (`looper/agents/api_v1.py`, `looper/agents/http_server.py`):** `auth.set_password` and `auth.clear_password` accept only an operator identity; an API client token gets 403 `forbidden` before any argument is read, and an invalid credential request answers a fixed message that never echoes a value. Both end existing password sessions. `system.check` runs the doctor's self checks, including pg_dump, and needs the server's ops settings. `config.export` (optional `include_projects`, `include_secrets`) returns the document from a read-only repeatable-read transaction. `config.import_preview` stages a document and returns an `import_id`; `config.import_apply` is high risk and answers `needs_confirmation` until confirmed in the same client and session.
- **Import ownership (`looper/agents/config_imports.py`):** a staged import records the caller that staged it, and `apply` of another caller's `import_id` answers not found. The preview upload of `/api/v1/config/import_preview` is capped at the dashboard import limit (`UPLOAD_MAX_BYTES`), which `receive` now also enforces for any body.
- **`loopercli` (`looper/loopercli.py`):** new `auth set-password|clear-password` (operator token from a 0600 file or stdin, passwords prompted twice and never taken as arguments; a client token is refused), `doctor` (exit code is an error when any check fails) and `config export|import`. `config export` writes the file with mode 0600 and refuses to overwrite one; `-` writes to stdout.
- **`looper` (`looper/cli.py`):** `looper config export` and `looper config import` exit with an error that names the `loopercli` replacement. `looper auth` and `looper doctor` are unchanged and still work offline.
- **Model-visible changes:** The `note` in the `looper_config_export` tool result now names the `loopercli config export` / `import` / `confirm` commands instead of `looper config ...`. The OpenAPI document lists six more operations (`auth.set_password`, `auth.clear_password`, `system.check`, `config.export`, `config.import_preview`, `config.import_apply`), the first two marked `x-looper-operator-only`. No prompt changed.
- **Tests:** The pull request reports added lines: tests 451, production 331 (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.48 is published. No data migration. Replace any script that calls `looper config export` or `looper config import` with the `loopercli` commands, which need the service to be running. Rolling back to v2.13.47 restores the offline commands; nothing is stored differently.

### 行为变化与入口

- 新 v1 操作：`auth.set_password`、`auth.clear_password` 只接受操作员身份，API client token 在读取任何参数前得到 403 `forbidden`；无效的凭据请求返回固定消息，不回显任何值；两者都会结束现有密码会话。`system.check` 运行 doctor 的自检（含 pg_dump），需要服务带有 ops 设置。`config.export`（可选 `include_projects`、`include_secrets`）在只读 repeatable-read 事务中返回文档。`config.import_preview` 暂存文档并返回 `import_id`；`config.import_apply` 为高风险，在同一 client 和会话确认前返回 `needs_confirmation`。
- 导入归属：暂存的导入记录暂存者，其他调用者 apply 该 `import_id` 返回 not found。`/api/v1/config/import_preview` 的上传受 dashboard 导入上限（`UPLOAD_MAX_BYTES`）限制，`receive` 现在对任何请求体也强制该上限。
- `loopercli`：新增 `auth set-password|clear-password`（操作员 token 来自 0600 文件或 stdin，密码交互输入两次、绝不作为参数；client token 被拒绝）、`doctor`（任一检查失败则退出码为错误）和 `config export|import`。`config export` 以 0600 写文件且不覆盖已有文件；`-` 写到 stdout。
- `looper`：`looper config export` 和 `looper config import` 报错退出并指出 `loopercli` 的替代命令。`looper auth` 和 `looper doctor` 不变，仍可离线使用。
- 面向模型的变化：`looper_config_export` 工具结果里的 `note` 现在指向 `loopercli config export` / `import` / `confirm`，不再是 `looper config ...`。OpenAPI 文档多出六个操作（`auth.set_password`、`auth.clear_password`、`system.check`、`config.export`、`config.import_preview`、`config.import_apply`），前两个标注 `x-looper-operator-only`。提示词未改。
- 测试：PR 报告新增行数 tests 451、production 331（不含 fixtures）。
