# Looper v2.14.3

This is the patch release v2.14.3. It ships the one change merged since v2.14.2: [#872](https://github.com/foolzzz/looper/pull/872), DSH runner `session/prompt` and `session/cancel` with budget authorization before every model request, which no running code uses yet.

## Release Decision

**Who should upgrade:** Operators on v2.14.2 who want the current main line, and developers who continue the DSH runner work. Nothing an operator can see changes. It ships the one change merged since v2.14.2.

**What this release solves:** [#872](https://github.com/foolzzz/looper/pull/872) lets the packaged DSH runner run a turn: it accepts a prompt, asks the host to authorize every model request before it is sent, reports exact per-request usage, streams the assistant's messages and tool results, and settles once. A turn can be cancelled. The runner is still not registered as a runtime, has no setting and has no entry in the Dashboard, Telegram, Lark or CLI.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#872](https://github.com/foolzzz/looper/pull/872); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.3
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0, v2.14.1 or v2.14.2 upgrades directly. This release changes no schema, configuration format or stored data.

## Behavior changes

- **Turns (`runners/dsh/src/turn.ts`, `runners/dsh/src/main.ts`):** the DSH runner now serves `session/prompt` and `session/cancel`, and `runner/health` reports the running turns and the in-flight requests instead of zero.
  - `session/prompt` needs a non-empty `trace_id`, a text and a tools list; bad values fail with `-32602`. A non-empty platform tool list fails with `-32007`. A second prompt while a turn runs fails with `-32003`. The prompt is accepted first and the turn starts after the acceptance frame.
  - `session/cancel` fails with `-32004` when no turn is running and `-32005` for another trace.
  - The turn maps DSH events to `session/update`: assistant messages (text and tool calls, with unparsable tool arguments sent as an empty object), tool results, text deltas of the main request, a `request_end` per request and one `settled` update.
  - `settled` carries a typed outcome (`completed`, `cancelled`, `capped`, `max_requests` or `failed`), the final text, the request count and whether usage is complete. A failure carries an error kind: `PROVIDER_AUTH`, `CONTEXT_OVERFLOW`, `PROVIDER_UNAVAILABLE`, `OUTPUT_TRUNCATED` or `INTERNAL_ERROR`, with the message scrubbed, on one line and cut at 512 characters.
  - Cancel and close settle within 4 seconds; otherwise the session is released with a bounded dispose and the turn settles as failed. A cancel before the turn starts removes the prompt from the inbox.
- **Model requests (`runners/dsh/src/provider.ts`, `runners/dsh/src/session.ts`):** one `llm/stream` listener handles every request of a session.
  - Only loop requests and compaction on the session's own route are attributed. Anything else, a second request while one is active, or a request after the turn ended or was cancelled is refused with `LOOPER_UNATTRIBUTED` and logged as `usage_unattributed`.
  - Before each request the runner sends `budget/authorize` with the session, trace, request id, kind, account, model, an estimated input size and the output limit. A denial is never sent to the provider: the turn is cancelled and settles `max_requests`, `cancelled` (reason `stopped`) or `capped`. A failed authorization settles the turn as failed.
  - The route's `resolveAuth` throws `LOOPER_UNAUTHORIZED` unless a request is authorized, and adds an `x-looper-request-id` header to the authorized one, so nothing can bypass the listener.
  - Each authorized request ends in exactly one `request_end` with its status, uncached input, output, cache read and write tokens and reasoning tokens. Sending is detected from the HTTP client's send-headers event. Usage is marked complete only when a successful terminal reply carries valid usage and the body was read to its end; a complete error response with no model output is complete with zero usage. Requests still open when the turn settles are ended as aborted and incomplete.
  - A turn that sees a second `turn/start` is marked overflowed and further requests are refused.
  - `session/close` now takes the trace of a running turn (a different trace fails with `-32005`), cancels it first, and returns the trace. Shutdown cancels running turns, waiting up to 3 seconds, then releases each session within 1 second.
- **SDK helper (`runners/dsh/src/sdk.ts`):** the type declarations add `LlmError`, `CONTEXT_WINDOW_EXCEEDED_CODE`, the default output limit and the context's `on`.
- **Tests and plan (`tests/test_dsh_runner_turns.py`, `tests/dsh_installed_stand_in.py`, `tests/test_dsh_runner.py`, `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`):** new turn tests; the Messages stand-in gains scripted error, cut and held replies; the plan records the turns and what is still missing (bash and path checks, platform tools, steer and fork).
- **Model-visible changes:** None for a running system, because the DSH runner is not reachable from any runtime. Once a host runs a turn, the model receives the host's prompt text as a user message, and a request is sent only after the host authorizes it.

### 行为变化与入口

- **Turn（`runners/dsh/src/turn.ts`、`runners/dsh/src/main.ts`）：**DSH runner 现提供 `session/prompt` 和 `session/cancel`，`runner/health` 报告运行中的 turn 和在途请求数而不再恒为零。
  - `session/prompt` 需要非空 `trace_id`、文本和工具列表，非法值以 `-32602` 失败；非空平台工具列表以 `-32007` 失败；已有 turn 运行时再次提示以 `-32003` 失败。先返回接受，turn 在确认帧之后启动。
  - `session/cancel` 在没有运行中的 turn 时返回 `-32004`，trace 不符返回 `-32005`。
  - turn 把 DSH 事件映射为 `session/update`：助手消息（文本和工具调用，无法解析的工具参数发为空对象）、工具结果、主请求的文本增量、每个请求一条 `request_end`，以及唯一一条 `settled`。
  - `settled` 带有类型化结果（`completed`、`cancelled`、`capped`、`max_requests` 或 `failed`）、最终文本、请求数和用量是否完整。失败带错误类别：`PROVIDER_AUTH`、`CONTEXT_OVERFLOW`、`PROVIDER_UNAVAILABLE`、`OUTPUT_TRUNCATED` 或 `INTERNAL_ERROR`，消息经擦除、折成一行并截断到 512 字符。
  - 取消和关闭在 4 秒内结算；否则以有限时间的释放强制释放会话，turn 以 failed 结算。turn 启动前取消会把提示词从收件箱移除。
- **模型请求（`runners/dsh/src/provider.ts`、`runners/dsh/src/session.ts`）：**一个 `llm/stream` 监听器处理会话的全部请求。
  - 只有会话自己路由上的循环请求和压缩请求会被归属；其他请求、已有请求在途时的第二个请求，以及 turn 结束或取消之后的请求，都以 `LOOPER_UNATTRIBUTED` 拒绝并记录 `usage_unattributed`。
  - 每次请求前，runner 发送 `budget/authorize`，带会话、trace、请求 id、类别、账户、模型、估算输入大小和输出上限。被拒绝的请求绝不发给 provider：turn 被取消并以 `max_requests`、`cancelled`（原因 `stopped`）或 `capped` 结算；授权调用本身失败则以 failed 结算。
  - 路由的 `resolveAuth` 在没有已授权请求时抛出 `LOOPER_UNAUTHORIZED`，对已授权请求附加 `x-looper-request-id` 头，因此无法绕过监听器。
  - 每个已授权请求恰好以一条 `request_end` 结束，含状态、未缓存输入、输出、缓存读写和推理 token。是否已发送由 HTTP 客户端的 send-headers 事件判定。只有成功的终止回复带有效用量且响应体读到末尾时，用量才算完整；无模型输出的完整错误响应记为零用量且完整。turn 结算时仍未结束的请求按 aborted 且不完整收尾。
  - 出现第二个 `turn/start` 的 turn 被标记为溢出，之后的请求被拒绝。
  - `session/close` 现在需要带上运行中 turn 的 trace（不同 trace 以 `-32005` 失败），先取消再关闭并返回该 trace。退出时取消运行中的 turn（最多等 3 秒），再在 1 秒内释放各会话。
- **SDK 辅助（`runners/dsh/src/sdk.ts`）：**类型声明新增 `LlmError`、`CONTEXT_WINDOW_EXCEEDED_CODE`、默认输出上限和上下文的 `on`。
- **测试与计划（`tests/test_dsh_runner_turns.py`、`tests/dsh_installed_stand_in.py`、`tests/test_dsh_runner.py`、`docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md`）：**新增 turn 测试；Messages 替身增加脚本化的错误、截断和挂起回复；计划文档记录 turn 及仍缺的部分（bash 与路径检查、平台工具、steer 与 fork）。
- **面向模型的变化：**对运行中的系统无，因为任何运行时都无法到达 DSH runner。宿主一旦运行 turn，模型收到宿主提示词作为用户消息，且请求只在宿主授权后才发送。
