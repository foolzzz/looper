# Looper v2.13.163

## Release Decision

**Who should upgrade:** Nobody needs to. This release adds the host-side turn policy for future agent SDK runners, which nothing in Looper calls yet, and refactors shared Manager tool helpers without changing their output. Everyone else can stay on v2.13.162.

**What this release solves:** [#743](https://github.com/foolzzz/looper/pull/743) adds `RunnerTurn`, which admits platform tool calls and enforces request counts and money caps for one runner trace, and reuses the existing platform tool adapter for Manager and Planner calls.

**Breaking changes:** No. No existing API, database, configuration, prompt or Tool declaration changed, and no runtime path uses the new class.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#743](https://github.com/foolzzz/looper/pull/743); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.163
```

## Behavior changes

- **Runtime behavior:** none. `looper/agents/runtimes/runner/turn.py` is imported only by tests; no command, API, task or session behaves differently. The Manager's tool adapter (`ManagerTurnTools`, used by `looper/agents/tiers/manager.py`) returns the same results as before.
- **Tool helpers ([#743](https://github.com/foolzzz/looper/pull/743)):** `api/tools.py` extracts `object_arguments`, `invalid_arguments` and `tool_outcome` from `ManagerTurnTools.call` (non-object arguments give the same `invalid` error with `ran=False`; results over 102,400 bytes are cut with the same note). It adds `PlannerTurnTools`, which lists and calls Planner tools with a bearer token through `PlannerOps`; no runtime uses it yet.
- **Tool admission ([#743](https://github.com/foolzzz/looper/pull/743)):** `RunnerTurn.call_tool` checks the session and trace ids, refuses calls once the turn is stopped, requires string `call_id` and `name`, and treats non-object `arguments` as the invalid-arguments result. Binding, role and token fields sent by a runner are ignored; the host's own tool adapter decides. A call that has not answered after 120 s returns an error saying it may still have run; the call is kept and drained at finish rather than cancelled.
- **Budgets ([#743](https://github.com/foolzzz/looper/pull/743)):** `authorize` allows a request only if it is within `max_requests` (default 30), the run cap and (for Planner) the task cap, counting spent cost, reserved estimates of requests still open, and the new estimate (output capped at 8192 tokens). It denies with `max_requests`, `run_cap`, `task_cap` or `budget_unverifiable` (a cap is set but a price, cost or task spend is unknown or a usage report was incomplete), closes admission and calls the cancel callback once. `request_end` validates and records usage, prices it, re-checks the caps and caps the turn at or above them. `finish` waits for admitted tool work, checks the request count, reports `capped` or `max_requests` when a cap applied and drops the cost when any usage is incomplete. Manager turns have no task cap.
- **Model-visible changes:** none. No prompt, tool description or tool schema changed. The only text added is the timeout message above, which a future runner could pass to a model; nothing sends it today.
- **Tests:** `tests/test_runner_turn.py` is new, and `tests/test_api_manager_tools_db.py` now runs its Manager tool cases against both the API adapter and the runner entry, plus a Planner case.
- **Description mismatch:** the description of #743 says "approximately 590 changed lines" and "tests 357, production 299"; the diff adds 299 production and 357 test lines, and this draft takes the file list as authoritative.

## Upgrade and rollback

Re-run `install.sh` once v2.13.163 is published; there is no migration and no configuration change. Rolling back to v2.13.162 removes only the unused class and restores the inline Manager helpers.

### 行为变化与入口

- **运行时行为：**无。`looper/agents/runtimes/runner/turn.py` 仅被测试导入，没有命令、API、任务或会话的行为发生变化。Manager 的工具适配器（`ManagerTurnTools`，由 `looper/agents/tiers/manager.py` 使用）返回与之前相同的结果。
- **工具辅助函数（#743）：**`api/tools.py` 从 `ManagerTurnTools.call` 中抽出 `object_arguments`、`invalid_arguments` 和 `tool_outcome`（非对象参数仍得到相同的 `invalid` 错误且 `ran=False`；超过 102,400 字节的结果以相同提示截断）。新增 `PlannerTurnTools`，通过 `PlannerOps` 以 bearer token 列出并调用 Planner 工具；目前没有运行时使用它。
- **工具准入（#743）：**`RunnerTurn.call_tool` 检查 session 与 trace id，轮次停止后拒绝调用，要求 `call_id` 和 `name` 为字符串，非对象 `arguments` 按无效参数结果处理。runner 发送的 binding、role 和 token 字段被忽略，由宿主自己的工具适配器决定。调用 120 秒未应答时返回错误，说明它可能已经运行；该调用被保留并在结束时等待完成，而不是被取消。
- **预算（#743）：**`authorize` 仅在未超过 `max_requests`（默认 30）、运行上限和（Planner 的）任务上限时放行，计入已花费费用、未结束请求的预留估算以及新的估算（输出上限 8192 token）。否则以 `max_requests`、`run_cap`、`task_cap` 或 `budget_unverifiable`（设置了上限但价格、费用或任务花费未知，或用量报告不完整）拒绝，关闭准入并调用一次取消回调。`request_end` 校验并记录用量、计价、重新检查上限，达到或超过上限即终止本轮。`finish` 等待已准入的工具工作完成，检查请求数，上限生效时报告 `capped` 或 `max_requests`，用量不完整时丢弃费用。Manager 轮次没有任务上限。
- **面向模型的变化：**无。prompt、工具描述和工具 schema 均未改变。唯一新增的文本是上述超时提示，未来 runner 可能把它交给模型；目前没有任何代码发送。
- **测试：**新增 `tests/test_runner_turn.py`；`tests/test_api_manager_tools_db.py` 现在让 Manager 工具用例同时针对 API 适配器和 runner 入口运行，并新增一个 Planner 用例。
- **描述不符：**#743 的描述写“approximately 590 changed lines”和“tests 357, production 299”；diff 新增 299 行生产代码、357 行测试，本草稿以文件清单为准。
