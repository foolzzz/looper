# Looper v2.14.92

This is the patch release v2.14.92, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.91: dashboard startup warnings appear without a reload, and TTADK runtime cards give TTADK hints ([#1123](https://github.com/foolzzz/looper/pull/1123)).

## Release Decision

**Who should upgrade:** Operators who use the dashboard, especially with the Claude Code CLI or a runtime login (Codex, Grok, Cursor, TTADK) that may be missing, or who run TTADK launchers. Everyone else can stay.

**What this release solves:** The advisory startup checks finish after the server listens, but the dashboard read them once, so a page opened right after a restart missed Claude and login warnings until reloaded. Separately, an undetected TTADK runtime card showed the native CLI install command, and when TTADK was missing at the first start there was no TTADK card or Re-detect entry. [#1123](https://github.com/foolzzz/looper/pull/1123) lets the dashboard re-read pending checks and gives TTADK cards their own hint and Re-detect. It closes #1099 and #1108.

**Breaking changes:** No. No schema change. The status API adds one value, `pending`, to `checks[].status`; a client that only expects `ok`, `warn`, `fail` and `skip` should treat it as "not finished yet".

**How to verify:** Check the installed version. Restart `looper serve` and open the dashboard at once: a Claude or login problem appears within a few seconds without a reload. With TTADK not installed, Settings → Agent Runtimes lists `ttadk-codex` and `ttadk-cursor-agent` as Not detected with "Install TTADK and sign in (ttadk auth login sso), then Re-detect." and a Re-detect button.

**Contributors:** Maintainer @foolzzz authored [#1123](https://github.com/foolzzz/looper/pull/1123); no community contribution was included in this release.


## Behavior changes

- **Startup checks are listed as pending** (`looper/agents/serve.py`, `self_check.py`). The status snapshot starts with the database check plus one `pending` entry ("Startup check in progress") for each advisory check: Claude CLI and login, Codex, Grok, Cursor, TTADK, Lark, git and the projects root. Each probe replaces its entries as it finishes, and the snapshot keeps its order. A probe that raises becomes a `warn` ("Startup check failed", fix: check the service log and restart `looper serve`) instead of leaving the entry out. The final log of problems is unchanged. How the checks run is unchanged.
- **Status API** (`looper/agents/v1_domains/status.py`, `http_server.py`). `checks[].status` may now be `pending`. The login re-read made on each status request skips checks that are still pending, so it cannot replace a pending entry with a result before the startup probe finishes.
- **Dashboard re-reads** (`web/src/lib/use-startup-checks.ts`, new). The banner (`claude-check-banner.tsx`) and the Agent Profiles Claude login line (`agent-profiles.tsx`) share one hook that reads the status and, while any check is pending, reads again every 3 seconds without overlapping requests; it stops on unmount, and a failed read keeps the last result and keeps polling while a check was pending. The banner still shows only failed checks; the Claude login line shows "checking the login…" while pending.
- **TTADK runtime cards** (`web/src/components/runtime-cards.tsx`). An undetected TTADK row shows "Install TTADK and sign in (ttadk auth login sso), then Re-detect." and the command `ttadk`, not the native CLI's. When the registry has no `rt-ttadk-codex` or `rt-ttadk-cursor-agent` row, a Not detected card for `ttadk-codex` or `ttadk-cursor-agent` is listed with Re-detect, which probes that runtime.
- **Unchanged:** how checks run, the schema, other API fields, runtimes.
- **Documentation and tests.** Updated `tests/test_serve_startup_checks_db.py`, `tests/test_self_check.py`, `tests/test_runtime_cards_browser.py`; new frontend tests in `agent-profiles.test.tsx` and `runtime-cards.test.tsx`.
- **Model-visible changes:** None. No tool description, prompt text or tool output changes. Only the dashboard and the `system/status` response, which the agents do not read, change.

## 中文摘要

本版本是 patch release v2.14.92（热修线，每个合并的改动立即发布）。自 v2.14.91 以来只合并了一项改动：仪表盘的启动警告无需刷新即可出现，TTADK 运行时卡片给出 TTADK 自己的提示（[#1123](https://github.com/foolzzz/looper/pull/1123)）。

### 升级决策

**谁需要升级：**使用仪表盘的运维人员，尤其是 Claude Code CLI 或运行时登录（Codex、Grok、Cursor、TTADK）可能缺失的情况，或使用 TTADK 启动器的情况。其他人可不升级。

**解决了什么：**启动时的建议性检查在服务开始监听之后才完成，而仪表盘只读取一次，所以重启后立刻打开的页面会漏掉 Claude 和登录警告，直到刷新。另外，未检测到的 TTADK 运行时卡片显示的是原生 CLI 的安装命令；首次启动时缺少 TTADK 的话，既没有 TTADK 卡片也没有重新检测入口。[#1123](https://github.com/foolzzz/looper/pull/1123) 让仪表盘重新读取未完成的检查，并为 TTADK 卡片提供自己的提示和重新检测。关闭 #1099 和 #1108。

**是否有破坏性变更：**否。无结构变更。状态 API 在 `checks[].status` 中新增一个值 `pending`；只预期 `ok`、`warn`、`fail`、`skip` 的客户端应把它当作“尚未完成”。

**如何验证：**核对版本为 2.14.92。重启 `looper serve` 并立即打开仪表盘：Claude 或登录问题在几秒内出现，无需刷新。未安装 TTADK 时，设置 → Agent Runtimes 把 `ttadk-codex` 和 `ttadk-cursor-agent` 列为未检测到，显示 “Install TTADK and sign in (ttadk auth login sso), then Re-detect.” 和重新检测按钮。

**贡献者：**维护者 @foolzzz 提交 [#1123](https://github.com/foolzzz/looper/pull/1123)；本版本无社区贡献。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.91 上的安装可直接升级。无数据库变更。

### 行为变化与入口

- **启动检查先列为待定**（`looper/agents/serve.py`、`self_check.py`）。状态快照一开始包含数据库检查，以及每项建议性检查的一条 `pending` 条目（“Startup check in progress”）：Claude CLI 与登录、Codex、Grok、Cursor、TTADK、Lark、git 和项目根目录。每个探测完成时替换自己的条目，快照顺序保持不变。探测抛出异常时变为 `warn`（“Startup check failed”，修复：查看服务日志并重启 `looper serve`），而不是丢掉条目。最终的问题日志不变。检查的运行方式不变。
- **状态 API**（`looper/agents/v1_domains/status.py`、`http_server.py`）。`checks[].status` 现在可以是 `pending`。每次状态请求时对登录的重新读取会跳过仍待定的检查，因此不会在启动探测完成前用结果替换待定条目。
- **仪表盘重新读取**（新增 `web/src/lib/use-startup-checks.ts`）。横幅（`claude-check-banner.tsx`）和 Agent Profiles 的 Claude 登录行（`agent-profiles.tsx`）共用一个 hook：读取状态，只要有检查待定就每 3 秒再读一次，请求不重叠；卸载后停止；读取失败时保留上次结果，并在此前有待定检查时继续轮询。横幅仍只显示失败的检查；Claude 登录行在待定时显示 “checking the login…”。
- **TTADK 运行时卡片**（`web/src/components/runtime-cards.tsx`）。未检测到的 TTADK 行显示 “Install TTADK and sign in (ttadk auth login sso), then Re-detect.” 和命令 `ttadk`，而不是原生 CLI 的命令。注册表中没有 `rt-ttadk-codex` 或 `rt-ttadk-cursor-agent` 行时，会列出 `ttadk-codex` 或 `ttadk-cursor-agent` 的“未检测到”卡片及重新检测按钮，其探测对应该运行时。
- **不变：**检查的运行方式、数据库结构、其他 API 字段、运行时。
- **文档与测试。**更新 `tests/test_serve_startup_checks_db.py`、`tests/test_self_check.py`、`tests/test_runtime_cards_browser.py`；`agent-profiles.test.tsx` 和 `runtime-cards.test.tsx` 新增前端测试。
- **面向模型的变化：**无。工具描述、提示文本和工具输出均不变。只有仪表盘和 agent 不会读取的 `system/status` 响应发生变化。
