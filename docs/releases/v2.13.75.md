# Looper v2.13.75

## Release Decision

**Who should upgrade:** Operators who create or revoke API client tokens from the dashboard Settings or from `loopercli`, and anyone who calls the `/api/clients` routes from a script.

**What this release solves:** [#472](https://github.com/foolzzz/looper/pull/472) moves API client administration onto operator-only v1 operations, adds `loopercli clients`, and removes the three legacy client routes.

**Breaking changes:** Yes. `GET /api/clients`, `POST /api/clients` and `DELETE /api/clients/{id}` are removed. Callers must use `POST /api/v1/clients/list`, `/create` and `/revoke`; create now answers 200 with the data wrapped in `result` instead of a bare 201 object, and the list no longer returns the always-null `revoked_at`. The dashboard and the prompt-regression runner are already updated.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#472](https://github.com/foolzzz/looper/pull/472); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.75
```

## Behavior changes

- **Routes:** `looper/agents/v1_domains/clients.py` adds `clients.list` (empty request), `clients.create` (`name`, 1–40 characters after whitespace is stripped) and `clients.revoke` (`client_id`). All requests are closed objects. A client answers with `id`, `name`, `created_at` and `last_used_at` (nullable); create also returns the token, which is shown once.
- **Operator only:** the three operations are declared `operator_only` and `credential_write`: an API client token is refused, and their arguments and results bypass the action audit and failures are redacted. An invalid name fails as invalid, a duplicate active name as 409, and an unknown or already revoked id as 404.
- **Removed routes:** the three legacy client routes, their handlers and the client-id pattern are deleted from `http_server.py`.
- **CLI:** `loopercli clients list|create|revoke` takes `--url` and `--operator-token-file` (default: one line from stdin), uses the token for that call only, and refuses an API client token. Usage errors under `clients` no longer echo arguments; the `auth` message now reads "invalid credential arguments".
- **Dashboard:** `fetchApiClients`, `createApiClient` and `revokeApiClient` in `web/src/lib/api.ts` call the v1 routes; a 202 confirmation answer is raised as an error.
- **Scripts and docs:** `evals/prompt_regression/dialogs.py` creates and revokes its eval client through v1; the client-skill RFC and a plan note are updated.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt or Manager Tool changed; the new operations are not Manager tools.
- **Not confirmed in code:** the old create route set `Cache-Control: no-store`; this draft did not check that the v1 dispatcher does the same.

## Upgrade and rollback

Re-run `install.sh` once v2.13.75 is published, and move any script that calls the removed routes to the v1 routes. No data migration; existing client tokens keep working. Rolling back to v2.13.74 restores the old routes, with no stored data affected.

### 升级决策

**谁需要升级：**在仪表盘设置页或通过 `loopercli` 创建、吊销 API 客户端令牌的运维人员，以及在脚本中调用 `/api/clients` 路由的人。

**解决了什么：**[#472](https://github.com/foolzzz/looper/pull/472) 把 API 客户端管理迁到仅限操作者的 v1 操作，新增 `loopercli clients`，并移除三条旧路由。

**是否有破坏性变更：**有。`GET /api/clients`、`POST /api/clients`、`DELETE /api/clients/{id}` 已移除；调用方须改用 `POST /api/v1/clients/list`、`/create`、`/revoke`。创建现在返回 200 且数据包在 `result` 下（原为 201 裸对象），列表不再返回恒为 null 的 `revoked_at`。仪表盘和 prompt 回归脚本已更新。

**如何验证：**运行 `looper --version` 核对版本为 2.13.75。

**贡献者：**维护者 @foolzzz 提交 [#472](https://github.com/foolzzz/looper/pull/472)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.75
```

### 行为变化与入口

- **路由：**`looper/agents/v1_domains/clients.py` 新增 `clients.list`（空请求）、`clients.create`（`name`，去首尾空白后 1–40 个字符）、`clients.revoke`（`client_id`）。请求均为封闭对象。客户端返回 `id`、`name`、`created_at`、`last_used_at`（可为 null）；创建还返回只显示一次的令牌。
- **仅限操作者：**三个操作声明为 `operator_only` 与 `credential_write`：拒绝 API 客户端令牌，参数与结果不进入操作审计，失败信息脱敏。名称无效按 invalid 报错，活跃名称重复返回 409，未知或已吊销的 id 返回 404。
- **移除的路由：**`http_server.py` 中三条旧客户端路由、处理函数和 client-id 匹配规则已删除。
- **CLI：**`loopercli clients list|create|revoke` 使用 `--url` 与 `--operator-token-file`（默认从标准输入读一行），令牌只用于该次调用，并拒绝 API 客户端令牌。`clients` 下的用法错误不再回显参数；`auth` 的提示改为 “invalid credential arguments”。
- **仪表盘：**`web/src/lib/api.ts` 中的 `fetchApiClients`、`createApiClient`、`revokeApiClient` 调用 v1 路由；202 确认响应作为错误抛出。
- **脚本与文档：**`evals/prompt_regression/dialogs.py` 通过 v1 创建和吊销评测用客户端；客户端 skill RFC 和一份计划文档已更新。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 和 Manager Tool 均未改动；新操作不是 Manager 工具。
- **代码中未确认：**旧创建路由设置了 `Cache-Control: no-store`；本草稿未核实 v1 分发器是否同样设置。

### 升级与回退

v2.13.75 发布后重跑 `install.sh`，并把调用已移除路由的脚本改到 v1 路由。无需迁移数据，已有客户端令牌继续有效。回退到 v2.13.74 会恢复旧路由，不影响已存数据。
