# Looper v2.14.133

This is the patch release v2.14.133, a hotfix line in which each merged change ships at once. It documents two changes: [#1225](https://github.com/foolzzz/looper/pull/1225) (a second coco runtime, `ttadk-coco`, that starts coco through TTADK) and [#1222](https://github.com/foolzzz/looper/pull/1222) (consult runs record their own usage and cost, not the forked session's).

## Release Decision

**Who should upgrade:** Operators who use coco through TTADK, and operators who use Claude Code consults (or a Claude Code Worker or Reviewer started with `--resume`) and read their recorded cost or spend cap. Everyone else gets no change.

**What this release solves:** [#1225](https://github.com/foolzzz/looper/pull/1225) adds a `ttadk-coco` runtime, because TTADK 1.0.37 retired `-t coco`. [#1222](https://github.com/foolzzz/looper/pull/1222) stops a forked Claude session's cumulative totals from being recorded as the consult's own usage and cost.

**Breaking changes:** No. There is no migration and no API removal; the native coco runtime is unchanged and fresh runs record as before. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.133
```

**Contributors:** Maintainer @foolzzz authored [#1225](https://github.com/foolzzz/looper/pull/1225) and [#1222](https://github.com/foolzzz/looper/pull/1222); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.132 upgrades directly. There is no schema change.

## Behavior changes

- **A `ttadk-coco` runtime** ([#1225](https://github.com/foolzzz/looper/pull/1225)). The coco adapter now also supports the TTADK launcher. The runtime row `rt-ttadk-coco` (name `ttadk-coco`) is registered when `ttadk` and `coco` are found and starts `ttadk code -t trae-cli --skip-check -- exec --json …`. Coco keeps its isolated home and login. TTADK adds its sign-in check, banner lines and launch event. The model is passed as Coco's `-m` after `--`, because TTADK ignores its own `-m` for `trae-cli`. All four roles are available. The dashboard's runtime cards list the new row.
- **Checks for `ttadk-coco`.** Only the `coco-login` provider pairs with it; another provider is refused with a message to use `coco-login`. The login check runs TTADK's sign-in check first, then Coco's login and model-catalog checks against TTADK's configured single-word `trae-cli` command (`traex` by default; a multi-word command falls back to `traex` with a note). Version detection reports `ttadk <version> / <coco version>`. Run metadata records `launcher: {kind: ttadk, version, tool: trae-cli}`. Request recording marks these runs `not_covered` ("TTADK manages its own provider"). The adapter methods `check_pairing` and `login_problem` take a `launcher` argument (default native) in every runtime.
- **Consult usage and cost** ([#1222](https://github.com/foolzzz/looper/pull/1222)). A Claude Code consult forks another run's session, so its result totals include that history. Its record now sums only this run's streamed requests, deduplicated by message id (an assistant message's usage is used when no partial events arrive), priced at the launch's frozen model prices, with `cost_source: provider_price` (also with Claude Code login). A standalone Worker or Reviewer started with `--resume`, `--continue` or `--fork-session` follows the same rule. Missing request usage or prices stay unknown, never filled from the inherited totals; side requests that the stream does not show (compaction, subagents) leave the cost unknown. The consult spend cap uses that recorded cost, and a Claude consult with an unknown cost cannot pass the cap check.
- **Unchanged:** the native coco runtime, fresh Worker and Reviewer runs (their result totals are their own), and non-Claude consults. The change to `pyproject.toml` only adds `playwright` to the `test` extra, and the installed-tests workflow stops installing it separately; the installed package's runtime dependencies are unchanged.
- **Model-visible changes:** None. No tool description, Planner, Worker, Reviewer or Manager prompt or contract text and no run `AGENTS.md` text changes.

**谁需要升级：**通过 TTADK 使用 coco 的运维者，以及使用 Claude Code consult（或用 `--resume` 启动的 Claude Code Worker/Reviewer）并关注其记录成本或花费上限的运维者。其他人无变化。

**是否有破坏性变更：**否。没有迁移，没有移除 API；原生 coco 运行时不变，新建运行的记录照旧。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.14.133。

**贡献者：**维护者 @foolzzz 提交 [#1225](https://github.com/foolzzz/looper/pull/1225) 和 [#1222](https://github.com/foolzzz/looper/pull/1222)；本版本无社区贡献。

```bash

```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.132 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **新增 `ttadk-coco` 运行时**（[#1225](https://github.com/foolzzz/looper/pull/1225)）。coco 适配器现在也支持 TTADK 启动器。运行时行 `rt-ttadk-coco`（名称 `ttadk-coco`）在找到 `ttadk` 和 `coco` 时注册，启动 `ttadk code -t trae-cli --skip-check -- exec --json …`。Coco 仍使用其隔离的主目录和登录。TTADK 会增加登录检查、横幅行和启动事件。模型作为 Coco 的 `-m` 放在 `--` 之后，因为 TTADK 对 `trae-cli` 忽略自己的 `-m`。四个角色都可用。仪表盘的运行时卡片列出新增的行。
- **`ttadk-coco` 的检查。**只有 `coco-login` 提供商可与之配对，其他提供商会被拒绝并提示使用 `coco-login`。登录检查先做 TTADK 的登录检查，再对 TTADK 配置的单词 `trae-cli` 命令（默认 `traex`；多词命令会回退到 `traex` 并附说明）做 Coco 的登录和模型目录检查。版本探测报告 `ttadk <版本> / <coco 版本>`。运行元数据记录 `launcher: {kind: ttadk, version, tool: trae-cli}`。请求记录将这些运行标为 `not_covered`（“TTADK 自行管理提供商”）。所有运行时的适配器方法 `check_pairing` 和 `login_problem` 新增 `launcher` 参数（默认 native）。
- **consult 的用量与成本**（[#1222](https://github.com/foolzzz/looper/pull/1222)）。Claude Code consult 从其他运行的会话 fork，其 result 总计包含历史用量。现在其记录只累加本次流中的请求，按 message id 去重（没有部分事件时使用 assistant 消息的用量），按启动时冻结的模型价格计费，`cost_source` 为 `provider_price`（使用 Claude Code 登录时同样如此）。用 `--resume`、`--continue` 或 `--fork-session` 启动的独立 Worker/Reviewer 同样处理。缺失的请求用量或价格保持未知，不会用继承的总计补齐；流中看不到的旁路请求（压缩、子 agent）会使成本保持未知。consult 的花费上限使用该记录的成本，Claude consult 成本未知时无法通过上限检查。
- **不变：**原生 coco 运行时、新建的 Worker/Reviewer 运行（其 result 总计就是自己的）以及非 Claude 的 consult。`pyproject.toml` 的改动只是把 `playwright` 加入 `test` 额外依赖，installed-tests 工作流不再单独安装它；已安装包的运行时依赖不变。
- **面向模型的变化：**无。没有工具描述、Planner、Worker、Reviewer 或 Manager 的提示词与契约文本变化，运行的 `AGENTS.md` 文本也无变化。
