# Looper v2.14.99

This is the patch release v2.14.99, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.98: hardening of the model request recording proxy ([#1138](https://github.com/foolzzz/looper/pull/1138)). It only matters when request recording (`llmrec.enabled`) is on; with recording off nothing changes.

## Release Decision

**Who should upgrade:** Operators who record model requests (`llmrec.enabled`), especially behind a corporate proxy, with an upstream URL that has a path or query, or with a pinned proxy port. Everyone else can stay.

**What this release solves:** [#1138](https://github.com/foolzzz/looper/pull/1138) fixes the follow-ups of the recording proxy so that turning recording on changes nothing for a model call except that it is recorded: upstream URLs with a path or query, same-origin redirects, `NO_PROXY` handling, relative TLS trust paths, concatenated or padded gzip responses, the 600-second read timeout, a proxy port that silently changed, a stalled capture writer, the `llmrec` self-check and the reads of stored requests.

**Breaking changes:** No. No database change, no new dependency, no new setting. Records, commands and environments are unchanged while recording is off.

**How to verify:** Check the installed version. With recording on, Settings → Request recording shows the proxy as running.

```bash
looper --version   # looper 2.14.99
```

**Contributors:** Maintainer @foolzzz authored [#1138](https://github.com/foolzzz/looper/pull/1138); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.98 upgrades directly. There is no database change. The recording proxy is a long-lived process; one running from an earlier version is replaced when the code changes.

## Behavior changes

All of these apply only while recording is on.

- **Upstream URLs and redirects** (`looper/agents/llmrec/proxy.py`). The upstream's own query string is kept and merged with the request's query. A `Location` header that points to the same origin as the upstream is rewritten to `/r-origin/<route>/...`, so the follow-up request goes through the recording route and is recorded; other redirects are passed through unchanged.
- **Proxies and TLS** (`looper/agents/runtimes/claude_code.py`, `looper/agents/llmrec/control.py`). `NO_PROXY` and `no_proxy` always gain `127.0.0.1`, `localhost` and `::1`, except that a lone `*` is left as it is; an explicitly empty lowercase value overrides the uppercase one. Relative TLS trust paths (`TLS_ENV` values) are resolved against the agent's working directory before they are given to the proxy, which has its own. `attach` takes a new `cwd` argument, which the Worker passes.
- **Gzip and capture** (`looper/agents/llmrec/proxy.py`, `looper/agents/llmrec/capture.py`). Concatenated gzip members and zero padding between or after them are decoded in full for the capture. A truncated compressed body is not decoded, and a streamed response with an unknown content-block delta fails assembly (the raw text is kept) instead of being silently reduced. The forwarded bytes are untouched.
- **Timeouts** (`looper/agents/llmrec/proxy.py`). The proxy no longer applies the 600-second read-idle timeout to upstream responses (`read_idle_s` defaults to none); the connect timeout of 10 seconds stays.
- **Stable port** (`looper/agents/llmrec/__main__.py`, `looper/agents/llmrec/control.py`). If the pinned port cannot be bound, the proxy no longer picks another port (running agents hold routes to the old one); it fails and the controller retries the same port on its next tick. The health endpoint answers 503 with `writer_healthy: false` after the capture writer has stopped, the writer then refuses new captures, and the controller replaces that proxy on the same port, keeping its counters visible until the replacement publishes its state. Stopping a proxy now escalates to SIGKILL after the grace period and only after confirming that the state file, PID and start time still belong to the process.
- **Self-check and Settings** (`looper/agents/self_check.py`). The `llmrec` check reads the setting through the database URL when no controller is running, and when the proxy is unavailable it also reports `write_errors` since proxy startup.
- **Reads and storage** (`looper/db/llm_requests.py`, `looper/db/llm_records.py`). Reading stored requests fetches only the body parts that the requests reference. NUL characters in strings of recorded events (which PostgreSQL JSONB rejects) are stored as the text `\u0000` and the event is marked `body_sanitized: true`.
- **Unchanged:** the database schema, the dependencies, settings, the API and CLI, the dashboard, channels (Telegram and Lark) and agent-facing tools. With recording off, records, commands and environments are unchanged.
- **Documentation and tests.** New `tests/test_llmrec_proxy_hardening.py`, `tests/test_llmrec_launch_hardening.py` and `tests/test_llmrec_writer_db.py`; updated `tests/test_llmrec_control.py`, `tests/test_llmrec_lifecycle_db.py`, `tests/test_llmrec_store_db.py`, `tests/test_llmrec_worker_db.py`, `tests/test_llm_records_db.py` and `tests/test_claude_cli.py`.
- **Model-visible changes:** None to prompts, tool descriptions or agent state. With recording on, a Claude Code process sees a longer `NO_PROXY`/`no_proxy` (it gains `localhost` and `::1` as well as `127.0.0.1`); no other environment value changes.

## Optional Capability Activation & Use

### Recording proxy hardening

**Activation:** Nothing new. The fixes apply to runs launched after the upgrade while `llmrec.enabled` is on (Settings → Request recording); a running proxy of an older version is replaced.

**Validation:** After a recorded run, the request is listed on the agent's history page. Settings → Request recording shows the proxy state `running` with its port, and the `llmrec` self-check does not fail.

```bash
loopercli llm-requests list --operator-token-file operator-token
```

**Disable / rollback:** Turn recording off in Settings → Request recording; stored requests stay. Downgrading restores the previous proxy behavior; stored data is untouched.

**Authority boundary:** Unchanged: operator token only for settings and stored captures; agents and API-client tokens cannot read them. Bodies are stored as sent and can contain secrets printed by tools.

**Docs:** [Model request recording](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md#model-request-recording-llmrec) in the agent-system architecture document.

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.98 上的安装可直接升级。无数据库变更。录制代理是长期运行的进程；旧版本的代理在代码变化后会被替换。

### 行为变化与入口

以下变化仅在录制开启时生效。

- **上游 URL 与重定向**（`looper/agents/llmrec/proxy.py`）。保留上游自带的查询串并与请求的查询串合并。指向与上游同源的 `Location` 头会被改写为 `/r-origin/<route>/...`，使后续请求仍经录制路由并被记录；其他重定向原样透传。
- **代理与 TLS**（`looper/agents/runtimes/claude_code.py`、`looper/agents/llmrec/control.py`）。`NO_PROXY` 和 `no_proxy` 总会加入 `127.0.0.1`、`localhost`、`::1`，单独的 `*` 保持不变；显式设置为空的小写值会覆盖大写值。相对的 TLS 信任路径（`TLS_ENV` 的值）按 agent 的工作目录解析后再交给代理（代理有自己的工作目录）。`attach` 新增 `cwd` 参数，由 Worker 传入。
- **Gzip 与捕获**（`looper/agents/llmrec/proxy.py`、`looper/agents/llmrec/capture.py`）。拼接的 gzip 成员以及其间或其后的零填充会被完整解码用于捕获。被截断的压缩正文不会被解码；流式响应中出现未知的 content-block delta 时组装失败（保留原始文本），而不是被悄悄简化。转发的字节不变。
- **超时**（`looper/agents/llmrec/proxy.py`）。代理不再对上游响应施加 600 秒读取空闲超时（`read_idle_s` 默认无）；10 秒连接超时保留。
- **稳定端口**（`looper/agents/llmrec/__main__.py`、`looper/agents/llmrec/control.py`）。固定端口无法绑定时，代理不再另选端口（运行中的 agent 持有指向旧端口的路由）；它会失败，控制器在下一个周期重试同一端口。捕获写入器停止后，健康端点返回 503 和 `writer_healthy: false`，写入器随后拒绝新的捕获，控制器在同一端口上替换该代理，并在替换者发布状态前继续显示其计数。停止代理时，宽限期后升级为 SIGKILL，且仅在确认状态文件、PID 和启动时间仍属于该进程后才执行。
- **自检与设置**（`looper/agents/self_check.py`）。没有控制器运行时，`llmrec` 自检通过数据库 URL 读取设置；代理不可用时还会报告代理启动以来的 `write_errors`。
- **读取与存储**（`looper/db/llm_requests.py`、`looper/db/llm_records.py`）。读取已存请求时只取这些请求引用的正文片段。已记录事件字符串中的 NUL 字符（PostgreSQL JSONB 不接受）以文本 `\u0000` 存储，并给事件标记 `body_sanitized: true`。
- **不变：**数据库结构、依赖、设置、API 和 CLI、仪表盘、渠道（Telegram 和 Lark）以及面向 agent 的工具。录制关闭时，记录、命令和环境均不变。
- **文档与测试。**新增 `tests/test_llmrec_proxy_hardening.py`、`tests/test_llmrec_launch_hardening.py` 和 `tests/test_llmrec_writer_db.py`；更新 `tests/test_llmrec_control.py`、`tests/test_llmrec_lifecycle_db.py`、`tests/test_llmrec_store_db.py`、`tests/test_llmrec_worker_db.py`、`tests/test_llm_records_db.py` 和 `tests/test_claude_cli.py`。
- **面向模型的变化：**提示、工具描述和 agent 状态均无变化。录制开启时，Claude Code 进程看到更长的 `NO_PROXY`/`no_proxy`（除 `127.0.0.1` 外还加入 `localhost` 和 `::1`）；其他环境值不变。
