# Looper v2.13.152

## Release Decision

**Who should upgrade:** Operators who run a Manager on an api runtime (a model reached over its HTTP API rather than a CLI) and read its request logs or press Stop. Everyone else can stay on v2.13.151.

**What this release solves:** [#713](https://github.com/foolzzz/looper/pull/713) writes the api runtime's per-request log fields into the formatted log line, and lets Stop end a Manager turn that is still waiting for the platform tool list.

**Breaking changes:** No. The log message text changes (see below); no API, schema or configuration changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#713](https://github.com/foolzzz/looper/pull/713); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.152
```

## Behavior changes

- **Request log line (#713):** in `looper/agents/runtimes/api/session.py`, each api request is now logged as `api_request key=value ...` (previously the fixed message `api request`, with the fields only in the record's `api_request` extra). The formatted text is passed through `log_redaction.redact`. The structured `api_request` extra gains two fields, `request` (the request's index within the turn) and `outcome` (the turn's outcome: `answered`, `failed` or `cancelled`). Anything that matched the exact message `api request` must match the `api_request ` prefix instead.
- **Stop while loading tools (#713):** loading the Manager's platform tool list now races the turn's cancel. If Stop is requested while it is loading, the turn ends as stopped before any request is sent, instead of waiting for the load to finish. A tool-list failure still fails the turn with "Looper's platform tools are unavailable".
- **Model-visible changes:** none. Prompts, tools and requests sent to the model are unchanged.
- **Tests (#713):** `tests/test_api_session.py` adds coverage for the log line and for stopping during the tool load; `tests/test_api_usage_records_db.py` is updated for the new message and fields.

## Upgrade and rollback

Re-run `install.sh` once v2.13.152 is published. There are no schema changes. Rolling back to v2.13.151 restores the previous log message and the wait for the tool list.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 升级决策

**谁需要升级：**运行 api runtime（通过 HTTP API 访问模型而非 CLI）Manager、并读取其请求日志或使用停止按钮的运维者。其他人可留在 v2.13.151。

**解决了什么：**[#713](https://github.com/foolzzz/looper/pull/713) 把 api runtime 每次请求的日志字段写入格式化后的日志行，并让“停止”能结束仍在等待平台工具列表的 Manager 回合。

**是否有破坏性变更：**否。仅日志消息文本变化（见下）；无 API、schema 或配置变更。

**如何验证：**运行 `looper --version` 核对版本为 2.13.152。

### 行为变化与入口

- **请求日志行（#713）：**每次 api 请求现在记录为 `api_request key=value ...`（此前是固定消息 `api request`，字段只在记录的 `api_request` extra 中）。格式化文本经过 `log_redaction.redact`。结构化 extra 新增 `request`（请求在回合内的序号）和 `outcome`（回合结果：`answered`、`failed` 或 `cancelled`）。原先匹配完整消息 `api request` 的处理需改为匹配 `api_request ` 前缀。
- **加载工具时停止（#713）：**加载 Manager 平台工具列表现在与回合的取消竞争。加载期间请求停止，回合在发出任何请求之前以已停止结束，而不是等待加载完成。工具列表加载失败仍以“Looper's platform tools are unavailable”使回合失败。
- **面向模型的变化：**无。发给模型的提示词、工具和请求均不变。
- **测试（#713）：**`tests/test_api_session.py` 新增日志行和加载工具时停止的覆盖；`tests/test_api_usage_records_db.py` 按新消息和字段更新。

### 升级与回退

v2.13.152 发布后重跑 `install.sh`。无 schema 变更。回退到 v2.13.151 会恢复原日志消息和对工具列表的等待。
