# Looper v2.14.158

This is the patch release v2.14.158, a hotfix line in which each merged change ships at once. It documents one change: [#1285](https://github.com/foolzzz/looper/pull/1285) (room deliveries for steering Codex runs).

## Release Decision

**Who should upgrade:** Operators who run Codex Workers or Reviewers in a task room with a Codex that supports `turn/steer` (0.162.0 or newer). Everyone else sees no change.

**What this release solves:** [#1285](https://github.com/foolzzz/looper/pull/1285) delivers room messages into steering Codex runs, which were pull-only: they now receive messages addressed to them and interface posts while a tool call runs, instead of having to poll the inbox.

**Breaking changes:** No. There is no API change, no migration and no schema change; behavior changes are listed below. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.158
```

**Contributors:** Maintainer @foolzzz authored [#1285](https://github.com/foolzzz/looper/pull/1285); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.157 upgrades directly. There is no schema change.

## Behavior changes

- **Steering Codex runs get deliveries** ([#1285](https://github.com/foolzzz/looper/pull/1285), `looper/agents/runtimes/__init__.py`: new `RoomPush.STEER`, returned by `room_push()` when the runtime opts in and the launch steers; `looper/agents/runtimes/codex.py`: `CodexRuntime.room_push`). A Codex run with the probed steering capability receives room message bodies when a message names it or an interface post reaches it, steered into its turn with `turn/steer` only while a tool call runs. Other posts ride along in the usual oldest-first prefix. The PR calls this an intended maintainer decision.
- **Guidance.** Such runs get the `PUSHED` room section (`room_input` in `looper/agents/tiers/worker.py` now follows `room_push()`), never a waiting report, and read earlier messages with `looper_room_read`.
- **Read marking.** The Worker pool marks a steering run's messages read when the app-server acknowledges the steer (`confirm_on_accept` in `looper/agents/tiers/worker.py`). A rejection or no active turn leaves them unread. An unknown acknowledgement advances the in-flight cursor without marking them read or retrying, and logs the uncertainty. A run killed after the acknowledgement but before its next model request can leave an accepted delivery unseen (stated in `docs/architecture/agent-system.md`).
- **Event reading.** `CodexChannel.events()` in `looper/agents/runtimes/codex_steer.py` now reads app-server messages in a separate task and queues the events, so a consumer that awaits `send()` while handling an event still receives the steer acknowledgement. Event order and content are unchanged.
- **Unchanged.** Codex runs without the steer capability, and OMP, Pi and hosted runner runs, keep their behavior. Dashboard, Telegram/Lark and CLI are unchanged.
- **Tests and docs.** Added `tests/test_codex_room_push.py`; changed `tests/test_codex_steer.py` and `tests/test_room.py`; `docs/architecture/agent-system.md` describes the steering delivery.
- **Model-visible changes:** Yes. For steering Codex Workers and Reviewers, the room section of the system prompt now uses the pushed guidance, the first turn's "Unread" line ends "They will be delivered to you.", and the `looper_room_inbox` description is the shorter delivered-run text; the steered `[Looper room]` messages are new model input. Prompts of other runs are unchanged. The PR does not report a prompt eval.

### 升级决策

**是否有破坏性变更：**否。没有 API 变更、迁移或结构变更，行为变化见下。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.157 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **支持 steer 的 Codex 运行获得投递**（[#1285](https://github.com/foolzzz/looper/pull/1285)，`looper/agents/runtimes/__init__.py` 新增 `RoomPush.STEER`，运行时选择加入且启动支持 steer 时由 `room_push()` 返回；`looper/agents/runtimes/codex.py` 的 `CodexRuntime.room_push`）。具备探测到的 steer 能力的 Codex 运行，在消息点名它或接口帖子到达它时收到消息正文，仅在工具调用期间通过 `turn/steer` 送入当前回合；其他帖子按常规的最早优先前缀附带。PR 称这是维护者的有意决定。
- **指引。**此类运行使用 `PUSHED` 房间部分（`looper/agents/tiers/worker.py` 的 `room_input` 现在随 `room_push()`），不用等待报告，更早的消息用 `looper_room_read`。
- **已读标记。**Worker 池在 app-server 确认 steer 时把消息标为已读（`confirm_on_accept`）。被拒绝或没有活动回合时消息保持未读；确认结果未知时推进在途游标，但不标已读也不重试，并记录日志。运行在确认之后、下一次模型请求之前被终止，可能使已接受的投递未被看到（`docs/architecture/agent-system.md` 已说明）。
- **事件读取。**`looper/agents/runtimes/codex_steer.py` 的 `CodexChannel.events()` 现在在单独任务中读取 app-server 消息并排队，因此在处理事件时等待 `send()` 的消费者仍能收到 steer 确认。事件顺序与内容不变。
- **不变。**没有 steer 能力的 Codex 运行，以及 OMP、Pi 和托管 runner 运行行为不变。仪表盘、Telegram/Lark 和 CLI 不变。
- **测试与文档。**新增 `tests/test_codex_room_push.py`；更新 `tests/test_codex_steer.py`、`tests/test_room.py`；`docs/architecture/agent-system.md` 说明 steer 投递。
- **面向模型的变化：**有。对支持 steer 的 Codex Worker 和 Reviewer，系统提示词的房间部分改用推送式指引，首轮 Unread 行以“They will be delivered to you.”结尾，`looper_room_inbox` 描述换成投递运行的较短文字；被送入的 `[Looper room]` 消息是新的模型输入。其他运行的提示词不变。PR 未报告提示词评测。
