# Looper v2.13.121

## Release Decision

**Who should upgrade:** Dashboard users who page through the Gates list ("Show more") and press Retry after a refresh fails. Others do not need it.

**What this release solves:** [#636](https://github.com/foolzzz/looper/pull/636) keeps the loaded gate pages and their paging boundary intact when a Retry request fails. The list is replaced, together with its boundary, only when the Retry succeeds.

**Breaking changes:** No. No command, option, route, configuration or stored data format changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#636](https://github.com/foolzzz/looper/pull/636); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.121
```

## Behavior changes

- **Paging boundary is committed with the rows:** in `web/src/pages/gates.tsx`, the cursor of the loaded list is now part of the same view state as the rows (`{ rows, answering, cursor }`) and is applied in one state update. A layout effect mirrors it to the ref that timer refreshes and "Show more" read, so those reads follow the boundary of the rows on screen. The previous code assigned the ref separately after the state update.
- **A failed Retry changes nothing on screen:** a Retry that fails leaves the loaded rows, the boundary and the error message as they were; the next "Show more" continues from the previous boundary. A successful Retry replaces the rows and the boundary together with the first page, and clears the error. Changing the filter still starts over with an empty list and no boundary.
- **Model-visible changes:** none. This is dashboard behavior; no tool declaration, prompt, route or text sent to Workers changed.
- **Tests:** `web/src/pages/gates.test.tsx` adds a case where a failed Retry keeps the loaded rows and cursor (the next "Show more" uses the earlier cursor) and a later successful Retry replaces both. `tests/test_gate_pagination_browser.py` adds a browser case covering the same sequence over 120 rows: unchanged links and error text after a failed Retry, continued paging without duplicates, and a fresh first page after a successful Retry. [#636](https://github.com/foolzzz/looper/pull/636) reports added lines: tests 40, production 49 (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.121 is published. No data migration and no configuration change. Rolling back to v2.13.120 restores the previous handling of the paging boundary after a failed Retry.

### 行为变化与入口

- **翻页边界与行一同提交：**`web/src/pages/gates.tsx` 中，已加载列表的 cursor 现在与行同属一个视图状态（`{ rows, answering, cursor }`），一次状态更新即生效；布局 effect 把它同步到定时刷新和“Show more”读取的 ref，使这些读取以屏幕上行的边界为准。此前该 ref 是在状态更新之后单独赋值的。
- **Retry 失败不改变界面：**Retry 失败时，已加载的行、边界和错误信息都保持原样，下一次“Show more”从原边界继续。Retry 成功则把行和边界连同第一页一起替换，并清除错误。切换筛选条件仍会清空列表和边界重新开始。
- **面向模型的变化：**无。这是 Dashboard 行为；tool 声明、提示词、路由和发给 Worker 的文本均未改变。
- **测试：**`web/src/pages/gates.test.tsx` 新增用例：Retry 失败时保留已加载行和 cursor（下一次“Show more”使用先前的 cursor），之后 Retry 成功则两者一并替换。`tests/test_gate_pagination_browser.py` 新增浏览器用例，在 120 行数据上覆盖同一流程：Retry 失败后链接与错误文字不变、继续翻页无重复、Retry 成功后得到新的第一页。[#636](https://github.com/foolzzz/looper/pull/636) 报告新增行数：测试 40、生产代码 49（不含夹具）。
