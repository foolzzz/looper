# Looper v2.13.31

## Release Decision

**Who should upgrade:** Anyone whose agent turns can end while a process id recorded earlier in the turn has since been reused by an unrelated process.

**What this release solves:** [#385](https://github.com/foolzzz/looper/pull/385) fixes a review follow-up of #338. When a process id seen earlier in a turn had been reused by an unrelated process, the walk of the turn's process tree still followed that process's current children and process group, merged them into the turn tree and ended them. Reused ids are now skipped in the walk, dropped from the known groups, and not walked when the tree ends.

**Breaking changes:** No. No CLI command, configuration key, API shape or database schema changed. The behavior change is listed below.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#385](https://github.com/foolzzz/looper/pull/385); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.31
```

## Behavior changes

- **The subtree of a reused pid is left alone:** `looper/agents/proc_tree.py` already spared a reused pid itself (a pid whose recorded start time no longer matches), but `_tree` still walked its current children and group and `TurnTree.refresh` merged them into the turn tree, so `TurnTree.end` and `end_new` could kill them. `_tree` now takes a `skip` set and leaves those pids out together with what only they reach; `refresh` computes the reused pids before the walk and drops them from the known groups; `_end` takes `reused` and passes it on, and `_end_all`, `end` and `end_new` supply it. Turns without a reused pid behave as before.
- **Test-only changes:** `tests/test_proc_tree.py` adds `test_turn_tree_leaves_the_subtree_of_a_reused_pid_alone`.
- **Deferred, not changed:** the load-dependent test flakes listed in #385 stay open in #338; no code or test changed for them.
- **Model-visible changes:** None. No prompt text, tool schema or tool result changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.31 is published. There is no schema or configuration change. Rolling back to v2.13.30 is safe; the only difference is the previous behavior listed above.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**一个回合内先前记录的进程 id 后来被无关进程复用、而该回合又会结束的用户。

**解决了什么：**[#385](https://github.com/foolzzz/looper/pull/385) 处理 #338 的评审后续项。回合早先见过的进程 id 若已被无关进程复用，进程树遍历仍会沿着该进程当前的子进程和进程组走，并把它们并入回合进程树后结束。现在遍历时跳过被复用的 id，从已知进程组中移除，结束时也不再遍历。

**是否有破坏性变更：**无。CLI、配置项、API 形态、数据库 schema 均未变化，行为变化见下文。

**如何验证：**运行 `looper --version` 核对版本为 2.13.31。

**贡献者：**维护者 @foolzzz 提交 [#385](https://github.com/foolzzz/looper/pull/385)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.31
```

### 行为变化与入口

- 被复用 pid 的子树不再被动：`looper/agents/proc_tree.py` 此前只放过被复用的 pid 本身（记录的启动时间不再匹配），但 `_tree` 仍会遍历它当前的子进程与进程组，`TurnTree.refresh` 将其并入回合进程树，`TurnTree.end` 与 `end_new` 因此可能杀掉它们。现在 `_tree` 接受 `skip` 集合，把这些 pid 连同只经由它们可达的进程一并排除；`refresh` 在遍历前先算出被复用的 pid 并从已知进程组中移除；`_end` 接受 `reused` 并向下传递，`_end_all`、`end`、`end_new` 负责提供。没有被复用 pid 的回合行为不变。
- 仅测试变更：`tests/test_proc_tree.py` 新增 `test_turn_tree_leaves_the_subtree_of_a_reused_pid_alone`。
- 推迟、未改动：#385 中列出的依赖负载的测试偶发失败仍保留在 #338，未为其改动代码或测试。
- 面向模型的变化：无。提示词文本、工具 schema、工具结果均无变化。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.30 安全；区别仅是恢复上述之前的行为。
