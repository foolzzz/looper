# Looper v2.15.38

This patch contains exactly v2.15.37 (release commit `0a15c47d3`) plus [#1785](https://github.com/foolzzz/looper/pull/1785), frozen at `e98913682`, and the version bump, changelog and release documentation. Main received other merges after the v2.15.37 freeze. As described in [the release procedure](README.md), the release tag belongs on this release pull request's own head, after it merges, rather than on the main merge commit.

## Release Decision

**Who should upgrade:** Dashboard users on v2.15.37 or earlier who want the sidebar to stop repeatedly requesting an unavailable Work operation.

**What this release solves:** The sidebar probed `task_conversations/get` every 30 seconds indefinitely while the dashboard was visible on servers that do not register that operation. Every released server through v2.15.37 lacks it. The sidebar now probes once per page load, stops polling when the operation is absent and keeps Work hidden (#1785). When the operation exists, behavior is unchanged: disabled and enabled responses keep polling, and transient errors hide Work while polling continues for recovery.

**Breaking changes:** No. Compared with v2.15.37, this is frontend only: no new migration, setting or server change. Upgrades from v2.15.36 or earlier also inherit v2.15.37's breaking changes, migrations and backup requirements; read [the v2.15.37 release notes](v2.15.37.md) first. Installations older than the bridge must upgrade to v2.13.165 first and start once.

**How to verify:** Check the installed version, then open the dashboard with browser developer tools recording network requests. On this release's server, `task_conversations/get` is requested once and reports the missing operation; Work stays hidden. Keep the page visible for more than 30 seconds and confirm there is no second request. Reloading the page allows one new probe.

```bash
looper --version   # looper 2.15.38
```

**Contributors:** Maintainer @foolzzz authored #1785; no community contribution was included in this patch. Contributor credit for inherited changes is in the v2.15.37 notes.

## Upgrading

From v2.15.37, there is no additional migration or backup requirement introduced by this patch. The release workflow rebuilds the dashboard bundle from the frozen source; this release pull request commits no generated bundle.

From v2.15.36 or earlier, v2.15.38 includes all of v2.15.37. Read [v2.15.37's upgrade notes](v2.15.37.md#upgrading) before upgrading, including its migrations, pre-migration backup and breaking changes. This frontend fix does not remove any of those requirements. Installations older than v2.13.165 must upgrade to v2.13.165 first and start once.

## Entry points

- **Dashboard:** Only the sidebar's missing-operation polling changes. Work remains hidden on released servers, and behavior is unchanged when the operation exists.
- **Telegram and Lark:** No change is needed because their channel handlers do not run the browser sidebar poll.
- **CLI:** No change is needed because no command or server operation changes and the CLI does not run the sidebar poll.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release. Existing optional capabilities and their activation instructions remain as documented in [v2.15.37](v2.15.37.md#optional-capability-activation--use). Work cannot be enabled on this tree because its enabling operation is absent.

The v2.15.37 exclusions below are retained verbatim and describe the frozen tree:

The following pull requests and their dependent work are outside the frozen tree. Follow-up references identify work not shipped here, rather than asserting that every referenced pull request was open at the freeze:

Other open pull requests, including the three older standalone changes (#1730, #1731, #1732), are likewise not part of this release. None of the absent work changes this tree: an upgrade still inserts no feature-setting row, the Work console and the routed chat task tools stay off by default, the morning brief, attention, metrics and vault switches keep their current defaults, and no model-visible byte changes on a default path.

## 中文摘要

本补丁严格包含 v2.15.37（发布提交 `0a15c47d3`）加 #1785，冻结在 `e98913682`，另加版本号、变更日志和发布文档。main 在 v2.15.37 冻结后合入了其他改动；按[发布流程](README.md)，PR 合入后应在本发布 PR 自己的 head 上打 tag，而不是 main 的合并提交。

### 升级决策

**谁需要升级：** 使用 v2.15.37 或更早版本控制台、希望侧栏停止反复请求不存在的 Work 操作的用户。

**解决了什么：** 服务端未注册 `task_conversations/get` 时，侧栏以前在页面可见时每 30 秒无限探测一次；截至 v2.15.37，所有已发布服务端都没有这个操作。现在每次页面加载只探测一次，确认操作缺失后停止轮询，Work 继续隐藏（#1785）。操作存在时行为不变：关闭和开启状态都继续轮询，暂时错误时隐藏 Work 并继续轮询以恢复。

**是否有破坏性变更：** 无。相对 v2.15.37，本补丁只有前端修复，无新增迁移、设置或服务端改动。从 v2.15.36 或更早版本升级仍包含 v2.15.37 的全部迁移、备份要求和破坏性变更，请先阅读 [v2.15.37 发布说明](v2.15.37.md)。早于桥接版本的安装需先升级到 v2.13.165 并启动一次。

**如何验证：** 查看安装版本，再打开控制台和浏览器网络面板。此版本服务端的 `task_conversations/get` 只请求一次并报告操作缺失，Work 不显示；保持页面可见超过 30 秒后确认没有第二次请求。重新加载页面后会再探测一次。

```bash
looper --version   # looper 2.15.38
```

**贡献者：** #1785 由维护者 @foolzzz 提交，本补丁没有社区贡献；继承改动的致谢见 v2.15.37 说明。

### 升级与入口

- 从 v2.15.37 升级：本补丁不新增迁移或备份要求；发布工作流照常重建控制台，本 PR 不提交生成的 bundle。
- 从 v2.15.36 或更早版本升级：v2.15.38 包含 v2.15.37 的全部内容，请先读[其升级说明](v2.15.37.md#upgrading)，包括迁移、迁移前备份和破坏性变更；本修复不取消这些要求。早于 v2.13.165 的安装需先升级到 v2.13.165 并启动一次。

### 未包含及原因

#1778、#1779、#1780、#1782 的 Work 页面面板改动已在 v2.15.37 冻结后合入 main，留到下个版本发布，不进入本补丁。这些面板依赖 Work 启用操作，而所有已发布服务端都没有该操作。下面原样保留 v2.15.37 对冻结树的排除说明：

以下 PR 及其依赖工作不在冻结树中；后续引用表示本版本未发布的工作，不代表每个引用的 PR 在冻结时都已开放：

- **#1742（类型化聊天范围与运行时启动模式）：** 堆叠在它上面的开放类型化范围系列（#1746、#1747、#1748、#1749、#1752、#1755、#1758、#1760、#1763、#1765）一并缺席。本版本只包含该系列将依赖的 #1743 休眠存储；`scoped` 路由仍只存储、被操作者操作拒绝。
- **#1753（默认关闭的草稿任务状态与操作者生命周期控制）：** 正是它会提供 Work 控制台的启用操作 `task_conversations.get/update`。堆叠在它上面的开放工作模式系列（#1761、#1768、#1770、#1771、#1773）一并缺席，后续 Work 面板工作（#1775、#1778、#1779、#1780、#1781、#1782）也必须等启用操作先行，因此 Work 控制台在本版本保持隐藏且无法开启。
- **#1757（按迁移和在线步骤输出启动耗时日志）：** 没有其他 PR 堆叠在它上面；在它合入前，启动日志保持现有的汇总形式。

其他开放 PR（包括三个较早的独立改动 #1730、#1731、#1732）同样不属于本版本。这些缺席的工作都不影响本棵树：升级仍不写入任何设置行，Work 控制台和路由聊天任务工具默认关闭，晨报、attention、指标和 vault 开关保持现有默认值，默认路径上没有任何模型可见字节变化。
