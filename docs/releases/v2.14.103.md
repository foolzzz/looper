# Looper v2.14.103

This is the patch release v2.14.103, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.102: a translating route kind in the local model proxy that turns Anthropic Messages requests into OpenAI Chat Completions requests for an upstream and translates the responses back ([#1147](https://github.com/foolzzz/looper/pull/1147)). Nothing creates such a route yet.

## Release Decision

**Who should upgrade:** Operators who use the request recorder and want the groundwork for the Anthropic-to-OpenAI gateway, and everyone who keeps runs in kept directories. Everyone else can stay.

**What this release solves:** [#1147](https://github.com/foolzzz/looper/pull/1147). The proxy can now serve a route that accepts Anthropic Messages (streaming and not), calls an OpenAI-compatible `/chat/completions` upstream and answers in Anthropic form. This release has no user-visible entry point; the routes come from the next change.

**Breaking changes:** No. No new dependency, setting, command or dashboard control. Existing recording routes are not translated. The database gains one nullable column, and the recorder route format moves from 3 to 4 (see Behavior changes).

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.103
```

**Contributors:** Maintainer @foolzzz authored [#1147](https://github.com/foolzzz/looper/pull/1147); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.102 upgrades directly. The schema change is additive: `ensure_schema` adds the nullable `translation` column to `llm_requests` once.

## Behavior changes

- **Translating routes** (`looper/agents/llmrec/__init__.py`, `proxy.py`, `translate.py`, `translate_stream.py`). A route file has a `kind`, `record` or `translate`, and a `record` flag. A `translate` route requires `api` = `openai-chat`, a known `dialect` and a non-empty `models` map; a route file that does not satisfy this is ignored, as is a `record` route that carries those fields. For a translate route the proxy converts a `POST /v1/messages` request to Chat Completions, sends it to the route's upstream `/chat/completions` (one retry only when the connection could not be established), and converts the answer back; streaming answers are converted as SSE events, with a ping after 15 seconds without output and an Anthropic error event if the upstream stream fails. Upstream error statuses are mapped to Anthropic errors. Request bytes are a pure function of the input (compact JSON, fixed order, no timestamps or random ids) so automatic prefix caching keeps hitting; upstream cached-token usage is returned as Anthropic cache-read fields. Content the upstream cannot take is dropped or replaced by a placeholder and counted (documents, images for models without image input, unknown block types); `tool_reference` blocks and invalid tool arguments are rejected with a 400.
- **Local answers.** On a translate route the proxy answers `HEAD`/`GET /api/hello` and `GET /v1/models` (the route's model names) itself; `POST /v1/messages/count_tokens` answers 404 `not_found_error`; other paths answer 404.
- **Dialect table** (`looper/agents/llmrec/dialects.py`). Ten dialects (generic, openai, deepseek, moonshot, zhipu, qwen, vllm, minimax, ark, openrouter) describe per model the max-token field, reasoning field and replay, thinking switches, rejected parameters, usage fields and image support. minimax, ark and openrouter are marked unverified and use the generic settings. `default_dialect` maps the DeepSeek, Kimi and GLM vendors to their dialects, others to generic.
- **Recording.** Translated requests are recorded when the route's `record` is true; the new `translation` object (dialect, upstream model, status, request id, finish reason, upstream usage, request size and hash, common-prefix bytes, dropped/degraded/clamped notes) is stored in `llm_requests.translation`, returned by the LLM requests API and counted in the capture size. The proxy health response gains `features: {"translate": 1}`, and its stats a `translate` block with counters.
- **Route format 4** (`looper/agents/llmrec/__init__.py`, `control.py`). `ROUTE_FORMAT` moves from 3 to 4. A route file in format 3 is no longer read, and a running recorder that reports another format is treated as outdated by the controller. The pull request description does not mention this.
- **Cache write tokens on recording routes** (`looper/agents/llmrec/capture.py`). For Chat Completions usage, `cache_write_tokens` is now read from `prompt_tokens_details.cache_write_tokens` when present; it was always 0. This also applies to existing recording routes and is not mentioned in the pull request description.
- **Schema** (`looper/db/connection.py`, `schema.sql`, `llm_requests.py`, `v1_domains/llm_requests.py`). `llm_requests` gains a nullable `translation` JSONB column, added to existing databases by `ensure_schema` and recorded as pending schema change until then; the row schema of the API accepts it.
- **Kept runs** (`looper/agents/kept_dirs.py`). Ending a kept run no longer stops waiting as soon as the child state file reads `exited`; it waits for the keeper process to exit (at most 10 seconds) before cleaning up the child. The pull request description does not mention this; `tests/test_kept_run_dirs.py` covers it.
- **Tests.** New `tests/test_gateway_translate.py`, `test_gateway_stream.py`, `test_gateway_prefix.py`, `test_gateway_proxy.py`, `test_gateway_routes.py` and a session fixture; `test_llmrec_store_db.py` and `test_kept_run_dirs.py` extended.
- **Unchanged:** dependencies, settings, commands and their options, the dashboard, the Manager's tools, channels, and the behavior of recording routes apart from the cache-write field above.
- **Model-visible changes:** None for existing runs: no prompt, tool description or agent environment changes. Only on a future translate route would the upstream model see the translated request; this release creates none.

本版本是 patch release v2.14.103（热修线，每个合并的改动立即发布）。自 v2.14.102 以来只合并了一项改动：本地模型代理新增“翻译”路由类型，把 Anthropic Messages 请求翻译成 OpenAI Chat Completions 发给上游，并把响应翻译回来（[#1147](https://github.com/foolzzz/looper/pull/1147)）。目前还没有任何入口会创建这种路由。

**谁需要升级：**使用请求记录器并想获得 Anthropic 到 OpenAI 网关基础能力的运维人员，以及使用保留目录（kept）运行的用户。其他人可不升级。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.102 上的安装可直接升级。数据库变更为增量：`ensure_schema` 一次性为 `llm_requests` 增加可空列 `translation`。

### 行为变化与入口

- **翻译路由**（`looper/agents/llmrec/__init__.py`、`proxy.py`、`translate.py`、`translate_stream.py`）。路由文件有 `kind`（`record` 或 `translate`）和 `record` 标志。`translate` 路由要求 `api` 为 `openai-chat`、`dialect` 已知且 `models` 非空；不满足的路由文件会被忽略，带有这些字段的 `record` 路由同样被忽略。代理把 `POST /v1/messages` 转为 Chat Completions，发往路由上游的 `/chat/completions`（仅在连接未建立时重试一次），再把应答转换回来；流式应答按 SSE 事件转换，15 秒无输出时发 ping，上游流失败时发 Anthropic 错误事件。上游错误状态被映射为 Anthropic 错误。请求字节是输入的纯函数（紧凑 JSON、固定顺序、无时间戳或随机 id），以便自动前缀缓存持续命中；上游缓存命中 token 以 Anthropic 的 cache-read 字段返回。上游无法接收的内容会被丢弃或替换为占位符并计数（文档、不支持图片输入的模型的图片、未知块类型）；`tool_reference` 块和无效的工具参数以 400 拒绝。
- **本地应答。**在翻译路由上，代理自己应答 `HEAD`/`GET /api/hello` 和 `GET /v1/models`（路由的模型名）；`POST /v1/messages/count_tokens` 返回 404 `not_found_error`；其他路径返回 404。
- **方言表**（`looper/agents/llmrec/dialects.py`）。十种方言（generic、openai、deepseek、moonshot、zhipu、qwen、vllm、minimax、ark、openrouter）按模型描述最大 token 字段、推理字段与回放、思考开关、被拒参数、用量字段和图片支持。minimax、ark、openrouter 标注为未验证，沿用 generic 设置。`default_dialect` 将 DeepSeek、Kimi、GLM 厂商映射到对应方言，其余为 generic。
- **记录。**路由的 `record` 为 true 时记录翻译请求；新的 `translation` 对象（方言、上游模型、状态、请求 id、结束原因、上游用量、请求大小与哈希、公共前缀字节数、dropped/degraded/clamped 说明）存入 `llm_requests.translation`，由 LLM 请求 API 返回并计入捕获大小。代理健康响应新增 `features: {"translate": 1}`，统计新增 `translate` 计数块。
- **路由格式 4**（`looper/agents/llmrec/__init__.py`、`control.py`）。`ROUTE_FORMAT` 由 3 变为 4。格式 3 的路由文件不再被读取，上报其他格式的运行中记录器会被控制器视为过期。PR 描述未提及此项。
- **记录路由上的 cache write token**（`looper/agents/llmrec/capture.py`）。对 Chat Completions 用量，`cache_write_tokens` 现在在存在时读取 `prompt_tokens_details.cache_write_tokens`；此前恒为 0。这也适用于现有记录路由，PR 描述未提及。
- **数据库结构**（`looper/db/connection.py`、`schema.sql`、`llm_requests.py`、`v1_domains/llm_requests.py`）。`llm_requests` 新增可空 JSONB 列 `translation`，由 `ensure_schema` 加到现有数据库，在此之前被视为待处理的结构变更；API 的行 schema 接受该列。
- **保留运行（kept）**（`looper/agents/kept_dirs.py`）。结束保留运行时，不再因子进程状态文件显示 `exited` 就停止等待，而是等 keeper 进程退出（最多 10 秒）后再清理子进程。PR 描述未提及；`tests/test_kept_run_dirs.py` 覆盖此项。
- **测试。**新增 `tests/test_gateway_translate.py`、`test_gateway_stream.py`、`test_gateway_prefix.py`、`test_gateway_proxy.py`、`test_gateway_routes.py` 和会话 fixture；扩展 `test_llmrec_store_db.py` 与 `test_kept_run_dirs.py`。
- **不变：**依赖、设置、命令及选项、仪表盘、Manager 工具、渠道，以及除上述 cache-write 字段外记录路由的行为。
- **面向模型的变化：**对现有运行无：提示、工具描述和 agent 环境均无变化。只有未来的翻译路由上，上游模型才会看到翻译后的请求；本版本不创建任何此类路由。
