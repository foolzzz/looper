# Looper v2.13.17

## Release Decision

**Who should upgrade:** Anyone running a per-turn runtime whose process can leave a grandchild holding stderr open. Everyone else sees no change.

**What this release solves:** [#346](https://github.com/foolzzz/looper/pull/346) makes the CI tests that failed only on the CI runner pass. It also fixes one product behavior they exposed: a per-turn runtime turn waited for the child through `Process.wait()`, which also waits for every pipe to close, so a grandchild holding stderr open kept the turn waiting after the child had exited. The turn now waits only for the child's exit.

**Breaking changes:** No. No CLI command, configuration key, API or database schema changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#346](https://github.com/foolzzz/looper/pull/346); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.17
```

## Behavior changes

- **Per-turn runtimes:** once the turn's output has ended, the turn waits for the child's own exit (its status is set as soon as the child is reaped) instead of `Process.wait()`, so a grandchild that still holds a pipe no longer delays the turn. This applies whether or not `chat.stop_enabled` is on. The change is in `looper/agents/runtimes/per_turn.py`.
- **Tests only:** the remaining changes of #346 touch tests and test helpers: a database check that counted a constraint once per schema the shared CI database holds, the model launch parity check on temp-root ancestors such as `/private/tmp`, and timing races in the Pi steer, per-turn interrupt and Grok fallback stop-matrix tests.
- **Model-visible changes:** None. No prompt, tool schema, tool result or `[Looper]` line changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.17 is published. There is no schema or configuration change. Rolling back to v2.13.16 is safe.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

### 升级决策

**谁需要升级：**所使用的按回合运行时中，子进程可能留下持有 stderr 的孙进程的运营者。其他人没有变化。

**解决了什么：**[#346](https://github.com/foolzzz/looper/pull/346) 让只在 CI 运行器上失败的测试通过，并修复了它们暴露的一处产品行为：按回合运行时过去通过 `Process.wait()` 等待子进程，而它还会等所有管道关闭，因此孙进程持有 stderr 时，子进程退出后回合仍在等待。现在回合只等待子进程自身退出。

**是否有破坏性变更：**无。CLI、配置项、API、数据库 schema 均未变化。

**如何验证：**运行 `looper --version` 核对版本为 2.13.17。

**贡献者：**维护者 @foolzzz 提交 [#346](https://github.com/foolzzz/looper/pull/346)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.17
```

### 行为变化与入口

- 按回合运行时：回合输出结束后，等待子进程自身退出（回收后立即设置状态），不再用 `Process.wait()`，因此仍持有管道的孙进程不会再拖延回合。无论 `chat.stop_enabled` 是否开启都适用。改动在 `looper/agents/runtimes/per_turn.py`。
- 仅测试：#346 其余改动只涉及测试与测试辅助：共享 CI 数据库中按 schema 重复的约束计数、临时目录上级（如 `/private/tmp`）下的模型启动一致性检查，以及 Pi steer、per-turn interrupt 与 Grok 回退 stop-matrix 测试的时序竞争。
- 面向模型的变化：无。提示词、工具 schema、工具结果与 `[Looper]` 行均未变化。
