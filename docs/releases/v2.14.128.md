# Looper v2.14.128

This is the patch release v2.14.128, a hotfix line in which each merged change ships at once. It documents one change, [#1213](https://github.com/foolzzz/looper/pull/1213): a native `coco` runtime (Coco, the TRAE CLI) for Workers and Reviewers.

## Release Decision

**Who should upgrade:** Operators who want to run Workers or Reviewers on Coco (TRAE CLI) with the coco login. Everyone else gets no change: Codex and the other runtimes behave as before, and nothing uses Coco until an Agent Profile selects it.

**What this release solves:** [#1213](https://github.com/foolzzz/looper/pull/1213) adds the runtime type `coco` (label "Coco (TRAE CLI)", registered as `rt-coco` when `coco` is on the server's PATH) for the Worker and Reviewer roles, paired only with the built-in `coco login` provider added in v2.14.126, which had no runtime until now.

**Breaking changes:** No. There is no migration and no API removal. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.128
```

**Contributors:** Maintainer @foolzzz authored [#1213](https://github.com/foolzzz/looper/pull/1213); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.127 upgrades directly. There is no schema change.

## Behavior changes

- **A new runtime, `coco`** ([#1213](https://github.com/foolzzz/looper/pull/1213)). It runs Workers and Reviewers through the Codex adapter's `exec --json` path, with its own home layout (`coco-home/v1`): Looper sets `TRAE_HOME` to a private run directory with its own `traecli.toml` and `AGENTS.md`, and a link to the operator's coco login, which Looper does not read or copy. The operator's own coco configuration, hooks, skills, plugins and memories are not loaded. `TRAE_HOME` and `TRAECLI_HOME` in the Agent settings' or the provider's variables are refused.
- **Pairing and refusals.** Coco pairs only with the `coco login` provider and one resolved model matching the launch model. It takes no effort level: a profile with one is refused. Before a process starts, Looper checks `coco login status` and the cached `coco models --json` catalog and refuses a missing login or a model the machine does not have, naming the models it has. The probe uses `coco --version` in a temporary home and does not apply Codex's version gate.
- **Not supported in this version.** Manager and Planner roles, structured output, steering and consulting a run, and effort levels are refused with a clear message.
- **Commit attribution.** Workers' commits keep Coco's own `Co-authored-by: TRAE CLI` trailer (a maintainer decision); runs record `commit_attribution: trae` in their launch record.
- **Reporting.** Coco runs report no model, so `model_reported` is empty in run records and workflow reports, and usage is unpriced (built-in prices are not applied to the coco login). The recording proxy lists coco as `not_covered`, because TRAE's servers make the model requests.
- **Login probes per executable.** The coco login probe cache is now kept per executable path, and the executable of the profile's runtime is passed to the login check and the pairing check. Other runtimes ignore the new argument.
- **Other:** a run's `AGENTS.md` runtime notes name the runtime ("Coco (TRAE CLI)" for coco, "Codex" as before); the Codex usage parser also accepts `cache_creation_input_tokens` as the cache-write count when `cache_write_input_tokens` is absent.
- **Unchanged:** Codex, Claude Code, OMP, Grok, Cursor Agent, Pi, dsh and API runtimes, and tasks without a coco profile.
- **Model-visible changes:** None to the Planner, Worker, Reviewer or Manager prompts and contracts of existing runtimes. A coco Worker or Reviewer reads a run `AGENTS.md` whose runtime notes say "Runtime notes (Coco (TRAE CLI))" and "Looper runs you through Coco (TRAE CLI)" in place of the Codex wording; the rest of the notes are the Codex notes.

## Optional Capability Activation & Use

### Coco runtime

**Activation:** Opt-in and operator-only. Sign in with `coco login` on the server's machine, have `coco` on the server's PATH (the `rt-coco` runtime is registered when it is found; re-detect it from Settings), then create an Agent Profile that pairs it with the `coco login` provider and a model from `coco models`, and assign it to the Worker or Reviewer role.

**Validation:** The runtime's probe in Settings shows the `coco --version` output; `looper doctor` shows the `coco_login` check. A run with no login or an unknown model is refused before the process starts. See the Coco section of the agent system document for the details.

**Disable / rollback:** Move the Worker and Reviewer roles back to another Agent Profile and delete the coco profile or runtime. Removing `coco` from PATH makes coco profiles unusable with a clear refusal.

**Authority boundary:** The operator's coco login stays in the operator's account; Looper links it into a private run home without reading it, and the agent's shell gets a separate home without the link. Coco's own sandbox and permissions apply to the agent. TRAE's servers receive the model requests, and they are not recorded by Looper's recording proxy. The Planner and the client tokens cannot select the runtime.

### 行为变化与入口

- **新运行时 `coco`**（[#1213](https://github.com/foolzzz/looper/pull/1213)）。它通过 Codex 适配器的 `exec --json` 路径运行 Worker 和 Reviewer，使用自己的主目录布局（`coco-home/v1`）：Looper 把 `TRAE_HOME` 指向私有的运行目录，其中有自己的 `traecli.toml` 和 `AGENTS.md`，以及指向运维者 coco 登录的链接（Looper 不读取也不复制它）。运维者自己的 coco 配置、hooks、skills、插件和记忆不会加载。Agent 设置或提供方变量中的 `TRAE_HOME`、`TRAECLI_HOME` 会被拒绝。
- **配对与拒绝。**Coco 只与 `coco login` 提供方以及与启动模型一致的唯一已解析模型配对。它不接受 effort 等级，带 effort 的 Profile 会被拒绝。进程启动前，Looper 检查 `coco login status` 和缓存的 `coco models --json` 目录，对缺少登录或本机没有的模型予以拒绝，并列出本机有的模型。探测在临时主目录中运行 `coco --version`，不套用 Codex 的版本门槛。
- **本版本不支持。**Manager 和 Planner 角色、结构化输出、对运行的 steer 和 consult、effort 等级，均会被明确拒绝。
- **提交署名。**Worker 的提交保留 Coco 自带的 `Co-authored-by: TRAE CLI` 尾注（维护者的决定）；运行的 launch 记录写入 `commit_attribution: trae`。
- **报告。**Coco 运行不报告模型，因此运行记录和工作流报告中的 `model_reported` 为空，用量不计价（coco 登录不套用内置价格）。记录代理把 coco 标为 `not_covered`，因为模型请求由 TRAE 的服务器发出。
- **按可执行文件区分登录探测。**coco 登录探测缓存现在按可执行文件路径保存，Profile 运行时的可执行文件会传给登录检查和配对检查。其他运行时忽略这个新参数。
- **其他：**运行的 `AGENTS.md` 中运行时说明会写出运行时名称（coco 为 “Coco (TRAE CLI)”，Codex 仍为 “Codex”）；Codex 用量解析在没有 `cache_write_input_tokens` 时也接受 `cache_creation_input_tokens` 作为缓存写入数。
- **不变：**Codex、Claude Code、OMP、Grok、Cursor Agent、Pi、dsh 和 API 运行时，以及没有 coco Profile 的任务。
- **面向模型的变化：**现有运行时的 Planner、Worker、Reviewer 和 Manager 提示词与契约无变化。coco 的 Worker 或 Reviewer 读到的运行 `AGENTS.md` 中，运行时说明写 “Runtime notes (Coco (TRAE CLI))” 和 “Looper runs you through Coco (TRAE CLI)”，取代 Codex 的措辞；其余说明与 Codex 相同。

### 可选能力启用与使用

#### Coco runtime

**启用：**需主动启用，且仅限运维人员。在服务器上执行 `coco login` 登录，并让 `coco` 在服务器 PATH 上（找到后会注册 `rt-coco` 运行时；可在设置中重新检测），然后创建把它与 `coco login` 提供方和 `coco models` 中某个模型配对的 Agent Profile，并分配给 Worker 或 Reviewer 角色。

**验证：**设置中运行时的探测显示 `coco --version` 的输出；`looper doctor` 显示 `coco_login` 检查。没有登录或模型未知的运行在进程启动前即被拒绝。详情见 agent system 文档中的 Coco 一节。

**停用 / 回退：**把 Worker 和 Reviewer 角色改回其他 Agent Profile，并删除 coco Profile 或运行时。把 `coco` 从 PATH 移除会让 coco Profile 无法使用，并给出明确的拒绝信息。

**权限边界：**运维者的 coco 登录留在运维者的账户中；Looper 把它链接进私有的运行目录而不读取它，agent 的 shell 得到不含该链接的独立主目录。Coco 自己的沙箱和权限对 agent 生效。模型请求由 TRAE 的服务器接收，Looper 的记录代理不会记录。Planner 和客户端令牌不能选用该运行时。
