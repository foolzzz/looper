## Release Decision

Upgrade from v2.15.36. The code is main at `4ad331978`.

**Who should upgrade:** Anyone on v2.15.36 or earlier who already uses default-Manager session routing, the morning brief, vault memory writes, or the dashboard task list; operators who want routed group chats to gain bounded task tools; operators preparing the new Work console; and operators who want interrupted Worker and Reviewer work to appear in spend totals and cost caps.

**What this release solves:** The default Manager's group and other-sender direct-chat sessions now run on a typed default-deny allowlist, and a separately switched, default-off tool set can give those chats their own task reads and operator-only writes (#1708, #1710). A missed morning brief no longer arrives late in the day: catch-up stops at a configurable cutoff, 12:00 local by default, and the brief always respects quiet hours, with unconsumed digests folding into the next workday (#1740). Vault memory writes commit through a shared, verified worktree transaction whose blocked merges surface in Needs you, and an explicit, dry-run-first command can export a project's documents into the vault (#1700). A Worker or Reviewer run interrupted by a drain or restart now checkpoints the usage it already reported, so spend totals and cost caps include that work (#1728). Long Manager turns keep editing the chat status line on a widening schedule that covers about 55 minutes, and the initial status appears before quoted-thread reads (#1735). Proven own-replies in the same resident session are rendered from the send copy instead of being read back remotely, with identical model-facing bytes (#1738). The dashboard gains a direct "Talk to this task" entry to a task's live Planner (#1736), the status card names terminal reminders properly in both languages (#1756), and stored turn metrics gain Lark inbound timing under the existing default-off metrics switch (#1737). A dormant chat-scope schema (#1743) and three operator-only work-list, selection and file-change reads plus the operator-only `tasks.mark_seen` watermark write (#1754, #1762, #1774) lay the storage and API foundation for the Work console, whose default-off shell, Planner conversation pane and default-Manager conversation pane ship in this release but stay hidden until their enabling operation exists in a later change (#1764, #1772, #1776).

**Breaking changes:** Yes. With default-Manager session routing on, the default Manager's non-main sessions (group chats and other senders' direct chats) now receive only the public chat prompt, their own chat data and session-local state, register zero Manager tools, and reject guessed global reads; incompatible saved context for those restricted sessions is reset, while scenario Managers keep their existing prompt, profile, tools and library and the main session is unchanged (#1708). Routing off changes nothing. With the morning brief enabled, a missed send only catches up before `morning_brief.cutoff` (default 12:00 local, the cutoff itself excluded), no brief is sent during quiet hours even after a recent reply, and unconsumed digest content moves to the next workday instead of being sent late (#1740). Vault writes now run through an owned git worktree and a fast-forward-only merge; the default worktree root moves to a `worktrees/looper-vault` directory under the operator's home, a blocked merge leaves the main checkout untouched and raises a persistent Needs you item, and non-git vaults keep their confined file writes (#1700). Interrupted Worker and Reviewer runs now record the usage reported before the interruption as a typed partial bill, which raises recorded spend and can make daily spend caps trigger where interrupted work was previously missing (#1728). Chat status edits on long turns follow a widening gap schedule instead of the previous fixed cadence, while staying inside the channel edit limit and sending no extra messages (#1735). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version, then read an existing engine setting without changing it.

```bash
looper --version   # looper 2.15.37
loopercli engine-settings get
```

**Contributors:** Maintainer @foolzzz authored the pull requests named in this body; no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged. An installation older than v2.13.165 must upgrade to v2.13.165 first and be started once. An installation on v2.14.0 through v2.15.36 upgrades directly. Restart the service after upgrading.

On a database that has finished v2.15.36, `pending()` reports seven new migrations and the online-step list gains four new markers. No existing migration file changed in this range, and `schema.sql` gains only the `tasks.origin_session` column and its partial index, which fresh installs create directly. `ensure_schema` applies the migrations in one startup transaction under the schema advisory lock, then runs the online steps after commit, outside any transaction, serialized by the online advisory lock. A busy lock for 5 seconds defers them to the lock owner or the next start with a warning. Because migrations are pending, startup first takes the usual verified `pg_dump` into the runtime root `backups/` directory unless the operator passes `--skip-backup`; a missing or incompatible `pg_dump`, or a failed backup, aborts startup before the schema changes. This note does not promise how long the steps take. After a complete start, the next start has nothing pending.

The seven migrations, in `pending_order`:

- `project_knowledge_dir` (1970), #1700. No online step. Adds nullable `projects.knowledge_dir`. An unset field preserves existing behavior.
- `manager_session_context_policy` (2000), #1708. No online step. Adds `manager_sessions.context_policy_version`, integer, not null, default 0, identifying routed histories recorded before the allowlist.
- `task_origin_session` (2010), #1710. No online step. Adds nullable `tasks.origin_session` with a pattern check and a partial index. Legacy tasks are not backfilled and stay unassigned.
- `chat_scopes` (2040), #1743. Adds the capability-set tables and versions, binding scope fields and principal overrides, session scope metadata with fingerprint-aware keys, and message provenance fields; widens the large `chat_messages` sender-kind check and the routing check as `NOT VALID`, so no history scan happens under the schema lock. Existing bindings are backfilled once as `legacy` when `legacy_allowed` is first added; a later repair that finds this column already present does not mark bindings legacy; existing sessions keep their data with null scope metadata. The typed routing value `scoped` is stored and rejected by operator operations until a later activation change, and existing `per_chat` Managers keep their behavior.
- `task_work_list` (2060), #1754. Creates the `task_seen` watermark table and adds two partial task indexes, built concurrently on upgrade and directly on fresh installs.
- `task_select_reads` (2070), #1762. Adds two time-window indexes, built concurrently.
- `task_select_directories` (2080), #1762. Adds canonical realpath columns to `tasks` and `task_worktrees`, three stored generated recheck flags, a backfill and six partial indexes built concurrently, and drops `idx_tasks_select_work_dir`, `idx_tasks_select_workspace_dir` and `idx_task_worktrees_select_path` if present. Neither v2.15.36 nor migration 2070 creates those three names, so their deletion is a no-op on this upgrade. The stored generated columns require a one-time rewrite of those tables inside the startup transaction, followed by the backfill; on a large database this is the dominant schema-change step.

The four online steps:

- `chat_scopes_online` validates the two widened checks, scanning `chat_messages` and `managers` without blocking their reads or writes.
- `task_work_list_online`, `task_select_reads_online` and `task_select_directories_online` build their indexes with `CREATE INDEX CONCURRENTLY`. A failed validation or index build fails startup.

What runs with every optional switch off. This covers session routing and the new session tools, the morning brief, attention, metrics, vault memory writing and the Work console switch all off, with other existing switches at their defaults:

- The migrations, online steps and backup above. No feature-setting row is inserted.
- The new operator-only operations exist and answer only operator identities: `session_tools.get/update`, `manager_sessions.assign_task`, `tasks.work_list`, `tasks.mark_seen`, `tasks.select`, `tasks.changes`, and the extended `morning_brief.get/update`. Nothing calls them on its own, and API-client identities are refused.
- With session routing off, prompts, tool lists, launch arguments and model-visible bytes are unchanged. The allowlist code and the dormant scope tables are not read on a main-session turn.
- The Work console's frontend code, including its Planner and default-Manager conversation panes, is present but hidden: it shows only when `task_conversations.get` answers enabled, and that operation is not served by this tree, so off, 404, unknown-operation and failed reads all leave the existing console pages unchanged.
- The metrics switch off, no Lark ingress observation is recorded and the structured ingress log is not emitted.
- The vault commit transaction is used only when a vault write actually happens; non-git vaults keep their previous confined writes.
- Model-visible bytes are unchanged on every default path: no prompt, contract, tool declaration or tool description changes unless an explicitly named switch is on.

New startup failure modes, including while every switch is off:

- A failed online check validation or concurrent index build in any of the four online steps.
- The table rewrite or backfill in migration 2080 failing inside the startup transaction, which rolls the whole transaction back and leaves the v2.15.36 schema startable.
- The usual backup abort when `pg_dump` is missing or incompatible, or the backup fails, unless `--skip-backup` is set.

## Behavior changes

### Without a new switch

- **#1735.** Channel status lines for Lark (both transports) and Telegram keep the 3-second edit cadence for the first 30 seconds of a Manager turn, then space edits by at least 0.8 times the elapsed time at the previous edit: ten initial edits plus eight growing gaps cover about 55 minutes inside the channel edit limit, the last progress edit explicitly says the turn is still running and how many whole minutes have elapsed, and the initial thinking status is emitted before quoted-thread preparation. No extra status messages are sent; phase labels, reactions, filtering, caps, failure handling and closing text are unchanged.
- **#1738.** A Manager turn no longer reads back the bot's own earlier Lark reply when a delivery record proves that reply was delivered, unmodified, into the same resident session: the raw item captured while sending is rendered through the unchanged quote builder, so the model-facing quoted bytes are identical. The in-memory records are capped at 1,000 and bound to bot, chat, Manager, session and resident session. Other senders, other sessions, edits, attachments, threads, group roots, incomplete receipts and channel restarts keep the normal read path. The content-free quote log records the typed `decision` values `read` and `skip_own_in_session`.
- **#1728.** A Worker or Reviewer run interrupted by a drain or restart checkpoints its cumulative reported usage on the live record, marked `partial` (or `unreported` with `no_usage_reported_before_interruption` when nothing was reported), and the adopted completion settles the same row once. Ordinary completed records keep their existing settlement and carry no interruption marker. No schema change is involved.
- **#1700.** `looper_vault_write` commits through an owned git worktree with explicit-path staging, hook and byte/mode/message verification and a fast-forward-only merge. A failed git commit leaves the main checkout unchanged and consumes no write quota; a blocked fast-forward merge keeps the owned branch and worktree for operator recovery and raises a persistent Needs you item while that existing summary is enabled, and housekeeping retains the attempt until the commit merges or the branch is removed. The default worktree root is the `worktrees/looper-vault` directory under the operator's home, and the operator vault setting accepts `worktree_root`. Non-git vaults retain their confined file writes. Agent prompts, knowledge indexes and tool declarations are unchanged.
- **#1736.** Dashboard only: every task row and the task detail header gain "Talk to this task", a deep link to the existing Planner chat preselected through the server-authoritative `can_send` read, refreshed every 10 seconds while visible. Unavailable Planners show a disabled, focusable entry with a reason. No backend routing changes.
- **#1743.** Dormant storage only. Existing bindings are marked `legacy` when `legacy_allowed` is first added, which nothing reads until a later change activates `scoped` routing; rebinding to a different Manager now also resets the not-yet-read scope fields in the same transaction.
- **#1766, #1767.** Behavior-preserving frontend extractions: the task detail Live Activity feed becomes a reusable component, and Chat reply streaming moves into a `useReplyStream` hook. DOM, fetch parameters, subscriptions, cancellation and visible Chat behavior are unchanged.
- **#1776.** Dashboard only, and unreachable until the Work console is enabled in a later release: the Work Manager column gains a default-Manager conversation pane that shares the existing Chat thread and its reply stream, merges stored history, autonomous reports and streamed replies by message id, and follows Chat's Stop setting, turn recovery and staged-input rules. Content stays hidden and sending disabled until Manager-scoped ownership is confirmed; a foreign pointer starts a new thread and a read failure offers Retry with sending disabled. The change adds no backend operation, migration, CLI or channel behavior, and while the Work gate is closed no existing page changes.

### When an existing switch is already on

The stored settings are not rewritten, and none of these switches enables another.

- **Default-Manager session routing on (#1708).** The default Manager's non-main sessions are restricted to the public chat prompt, the chat's own data and session-local state, register zero Manager tools, and reject unbound or guessed global reads before schema or state access; incompatible saved context for those sessions is reset once. Scenario Managers, including `per_chat` scenario groups, keep their own prompt, Agent Profile, library and full tool set. With routing off, inputs, tools and launch flags are unchanged.
- **Morning brief on (#1740).** Catch-up sends only before `morning_brief.cutoff`, a nullable `HH:MM` setting in the operator's timezone. A null cutoff is derived from the effective send time: 12:00 when the send time is before noon, otherwise three hours after the send time, or `{"kind":"end_of_day"}` on readback when that reaches midnight. The default send time of 09:15 therefore derives 12:00. An update atomically requires a stored cutoff to be strictly later than the send time; null restores derivation. The brief is treated as a scheduled delivery that always respects quiet hours, including after a recent reply, while remaining exempt from the daily proactive cap. Quiet or expired ticks preserve the first unread date and consume no digest or triage ids and no attempt; quiet hours ending before the cutoff allow a same-day send, otherwise the unconsumed digest folds into the next workday's brief and is consumed once. The Settings → Chat form can enable the brief and configure both times with explicit confirmation. The brief body and the send-started crash recovery are unchanged.
- **Attention on.** The status card's needs-you line now renders the terminal-reminder kind as `未确认送达的提醒 N` in the backend card and `N reminders not confirmed delivered` in the dashboard card instead of the raw key (#1756). Blocked vault commits appear as persistent Needs you items (#1700).
- **Turn metrics on (#1737).** Each Lark inbound message records platform send time and consumer stdout receipt timestamps, ingress-lock wait, sender-name lookup and attachment-download durations, plus `route_decided_at` when routing is reached into `llm_records.metadata.turn_metrics.lark_ingress`, and emits one structured `lark_ingress` log containing only channel and message ids plus timing fields. Unavailable timestamps are omitted; ordering, locking, retries, admission, routing decisions and sent content are unchanged, and no schema migration is involved.
- **Vault memory writing on (#1700).** Writes use the worktree transaction described above, and the optional `projects.knowledge_dir` field is honored after path validation that rejects absolute, traversal, hidden, file and symlink components.
- **Reminders, the status card beyond the label above, and the other existing switches.** No included pull changes their paths beyond the items already named.

## Optional Capability Activation & Use

### Routed chat task tools

**Activation:** Off by default. The switch is `manager.session_tools.enabled`, read and written only through the operator-only `session_tools.get` and `session_tools.update` operations; `null` restores off, the write is high risk and needs confirmation, and session routing must also be enabled for the tools to appear. An upgrade writes no setting row.

**Validation:**
- `session_tools.get` reads the value back. With both routing and the switch on, a routed group or other-sender direct chat gains four `looper_chat_*` tools that list and read only that chat's own tasks and let the authenticated operator create, start, stop, restart and instruct them; another session's task, a main-session task, an unknown id and a malformed id all return the same typed `not_found`.
- Another sender's writes are refused with the fixed operator-only text and create no request; missing operator identity fails closed.
- The operator-only `manager_sessions.assign_task` operation can expose one unassigned legacy task to a session exactly once, with explicit acknowledgement and an atomic audit; an assigned task cannot move again.
- With routing on and the switch off, the session keeps its zero-tool allowlist from #1708; with routing off, prompts and tools are byte-identical to before.

**Disable / rollback:** Store `false` or null through `session_tools.update` with confirmation. Routed sessions return to zero tools without a context-policy version change; existing tasks and their origin provenance remain in place. The migration's column and partial index are additive; downgrade needs the pre-migration backup, and this release ships no down migration.

**Authority boundary:** Operator only. Tool calls are bound to the channel-written sender and a fresh operator-id read, never enter the global scope or authorization path, and are recorded in the operator action audit. Routing removes shell and file access from these sessions even when the operator speaks in a group. The change is deliberately kept off until private approval support ships; the paid real-model comparison recorded in the pull request was not run.

**Docs:** https://github.com/foolzzz/looper/blob/v2.15.37/docs/architecture/agent-system.md#manager-session-routing

```bash
loopercli session-tools get
loopercli session-tools update --enabled true
loopercli confirm CONFIRMATION_ID
```

### Work console

**Activation:** Off by default, and not yet activatable on this tree. The dashboard shows the Work entry only when the `task_conversations.get` operation answers enabled; that enabling operation is deliberately not served in this release, so off, 404, unknown-operation and failed reads all hide Work and redirect Work URLs to the dashboard. The switch name reserved by the work-mode design is `tasks.conversations.enabled`. No setting row is inserted by an upgrade.

**Validation:**
- The frozen tree defines a 123-case full-DOM freeze across every existing route, settings page and detail variant for the hidden state; this release pull request did not rerun that frontend suite.
- Once enabled in a later release, Work presents the paginated work list from `tasks.work_list` (open, ended and schedules sections, page size 50, maximum 100), the per-operator unseen watermark from `tasks.mark_seen`, deterministic task resolution through `tasks.select`, the bounded changed-file read from `tasks.changes` (default limit 100, hard maximum 200, no file contents or patches), a Planner conversation pane that sends only when the Planner target's `can_send` is true, and a default-Manager conversation pane that shares the Chat thread, merges stored history, autonomous reports and streamed replies by message id, and keeps content hidden and sending disabled until Manager-scoped ownership is confirmed (#1776).
- The default-Manager pane is covered by 255 frontend tests across seven files, including 29 new adapter cases for ownership, duplicate messages, saved finals, dropped streams, Stop refusals and stale callbacks, alongside the default-off page freezes; headless-browser checks at four viewports covered data, empty, read-error and ownership-pending states, and one synthetic autonomous report against a disposable database rendered a single bubble and read back one stored row without any model call. With the enabling operation absent, the real unavailable-operation path still returns to the dashboard and mounts no Work pane.
- The backing operations were measured on a 2,000-task disposable database: every list and selection section returns in roughly 2 milliseconds at the median, below the 100-millisecond target.

**Disable / rollback:** With the operation absent, the console cannot be turned on, so there is nothing to disable on this tree; when the enabling operation ships, turning the switch off restores the current dashboard, and the additive `task_seen` table, columns and indexes remain unused. Downgrade needs the pre-migration backup.

**Authority boundary:** Every backing operation is operator-only: API-client identities receive a 403 before any work happens, none of them is an agent tool, and none calls a model. `tasks.changes` is a read-risk, machine-level operation that runs the existing Git runner with index locks, external diffs and text conversion disabled and returns typed unavailable reasons without raw diagnostics. The default-Manager pane confirms ownership through Manager-scoped history before showing stored content, watching the thread or allowing a send; a foreign pointer starts a new thread instead of continuing an existing one, and a read failure leaves sending disabled. It reuses the existing shared Manager transport, adds no backend operation and calls no model (#1776). The Work file-list user interface and the task Manager itself remain follow-up work.

### Project knowledge export to the vault

**Activation:** Explicit and off by default; nothing runs on its own. Both preview and execution require a configured knowledge vault and `projects.knowledge_dir`. The operator previews an export with `looper knowledge migrate --project NAME`, which changes nothing, and only adding `--execute` performs the export after writing a private JSON backup and printing its checksum. `projects.knowledge_dir` names a project-relative vault directory through the operator project API or the settings form; the field rejects absolute, traversal, hidden, file and symlink components, and leaving it unset preserves existing readers but makes both preview and execution refuse.

**Validation:**
- The dry-run report lists target filenames, sizes, an over-8-KiB flag and original metadata; path documents become reference notes without reading the original file.
- Execution uses one vault worktree transaction, then reads back and verifies every exported file; different existing content is reported and refused rather than overwritten, and source rows are never modified or deleted.
- A repeat execution reports no new work, and the backup row carries its sha256 checksum.

**Disable / rollback:** Do not pass `--execute`; a configured preview changes nothing, while missing vault or `knowledge_dir` configuration makes it refuse. After an export, remove the exported notes through the normal vault review flow and restore from the printed backup; the source project rows are untouched by design. Unset `knowledge_dir` to restore the previous layout. The additive column stays in place; downgrade needs the pre-migration backup.

**Authority boundary:** Operator-only local command and operator-only project field. The shared vault transaction keeps explicit-path staging, hook verification, fast-forward-only merges and the existing writable-directory rules, including an empty writable list; blocked merges retain the owned branch and surface in Needs you instead of touching another editor's changes. Reading project knowledge back from the vault, retiring the old read paths and deleting source columns are explicitly later parts and are not in this release.

```bash
looper knowledge migrate --project PROJECT_NAME
looper knowledge migrate --project PROJECT_NAME --execute
```

### 升级决策

从 v2.15.36 升级。

**谁需要升级：** 已经在用默认管家会话路由、晨报、vault 记忆写入或控制台任务列表的用户；想给路由群聊加受限任务工具的操作者；准备启用新 Work 控制台的操作者；以及希望中断的 Worker 和 Reviewer 工作量也计入花费总额和成本上限的操作者。

**解决了什么：** 默认管家的群聊和其他发送者私聊会话现在走类型化的默认拒绝允许清单，另有一个独立的、默认关闭的开关可以给这些会话开放各自的任务读取和仅限操作者的写入（#1708、#1710）。错过的晨报不再在当天晚些时候补发：补发在可配置的截止时间（默认本地 12:00）前停止，且始终遵守免打扰，未消费的摘要并入下一工作日（#1740）。vault 记忆写入改为通过共享的、带校验的 worktree 事务提交，被挡住的合并会出现在「需要你处理」里，并提供显式的、先 dry-run 的项目文档导出命令（#1700）。被排空或重启打断的 Worker 和 Reviewer 运行会把已上报的用量落盘，花费总额和成本上限因此包含这部分工作（#1728）。长管家回合的聊天状态行按逐渐拉大的节奏持续编辑约 55 分钟，且初始状态在读引用线程之前就发出（#1735）。同一常驻会话里已送达的自有回复直接用发送时的副本渲染，不再远程回读，模型可见字节不变（#1738）。控制台任务行新增直达任务 Planner 的「Talk to this task」入口（#1736），状态卡片在中英文下都能正确命名终态提醒（#1756），回合指标在现有默认关闭的指标开关下新增飞书入站计时（#1737）。休眠的 chat-scope schema（#1743）和三个仅限操作者的工作列表、任务选择、文件变更只读操作，加上写入已读水位的 `tasks.mark_seen`（#1754、#1762、#1774）为 Work 控制台铺好存储和 API 基础；默认关闭的 Work 外壳、Planner 对话面板和默认管家对话面板本版本已发布，但在后续变更提供启用操作之前保持隐藏（#1764、#1772、#1776）。

**是否有破坏性变更：** 是。默认管家会话路由打开时，默认管家的非 main 会话（群聊和其他发送者私聊）现在只收到公开聊天提示词、本聊数据和会话本地状态，不注册任何管家工具，并拒绝猜测式全局读取；这些受限会话不兼容的已存上下文会被重置；场景管家保留原有提示词、画像、工具和库，main 会话不变（#1708）；路由关闭时无变化。晨报打开时，错过的发送只在 `morning_brief.cutoff`（默认本地 12:00，不含截止时刻本身）之前补发，免打扰时段内即使最近有回复也不发送，未消费摘要顺延到下一工作日而不是当天晚发（#1740）。vault 写入改为通过自有 git worktree 和仅快进合并，默认 worktree 根目录移到操作者 home 下的 `worktrees/looper-vault`，合并被挡时主检出保持不动并产生持久的「需要你处理」条目，非 git vault 保留原有受限文件写入（#1700）。被中断的 Worker 和 Reviewer 运行现在把中断前已上报的用量记为类型化的部分账单，记录的花费会上升，每日花费上限可能因此在以前漏计的位置触发（#1728）。长回合的聊天状态编辑改为渐增间隔节奏，但仍在渠道编辑上限内且不额外发消息（#1735）。桥接版本边界不变：更旧的安装需先升级到 v2.13.165。

```bash

loopercli engine-settings get
```

### 升级

早于 v2.13.165 的安装需先升级到 v2.13.165 并启动一次；v2.14.0 到 v2.15.36 可直接升级，升级后重启服务。

在已完成 v2.15.36 的库上，`pending()` 报告七个新迁移，在线步骤多四个 marker。迁移在持 schema advisory lock 的同一个启动事务里执行，在线步骤在提交后、事务外执行，由在线锁串行化，争用 5 秒会推迟。有待执行迁移时，启动前照常做经过校验的 `pg_dump` 到运行根目录的 `backups/`，除非传了 `--skip-backup`。本说明不承诺具体耗时；完整启动一次后再次启动无待执行项。

**七个迁移**，按 `pending_order`：
- `project_knowledge_dir`（1970，#1700）：加可空 `projects.knowledge_dir`，无在线步骤。
- `manager_session_context_policy`（2000，#1708）：加 `manager_sessions.context_policy_version`，默认 0，无在线步骤。
- `task_origin_session`（2010，#1710）：加可空 `tasks.origin_session`、模式检查和部分索引，旧任务不回填。
- `chat_scopes`（2040，#1743）：能力集合、绑定范围、会话范围和消息来源字段；大表 `chat_messages` 的检查以 NOT VALID 方式放宽，不持锁扫历史；首次添加 `legacy_allowed` 列时，已有绑定一次性标记为 `legacy`；之后修复时若该列已存在，就不再把绑定标记为 legacy；`scoped` 路由值在后续激活前被操作拒绝，已有 `per_chat` 行为不变。
- `task_work_list`（2060，#1754）：建 `task_seen` 表和两个部分索引，升级时 CONCURRENTLY 建索引。
- `task_select_reads`（2070，#1762）：两个时间窗口索引，CONCURRENTLY。
- `task_select_directories`（2080，#1762）：realpath 列、三个存储生成列、回填和六个部分索引，若存在则删除 `idx_tasks_select_work_dir`、`idx_tasks_select_workspace_dir`、`idx_task_worktrees_select_path` 这三个名字；v2.15.36 和 2070 都不会创建它们，因此本次升级中这三次删除为空操作；存储生成列要求在启动事务内对相关表做一次性重写，大库上这是主要的 schema 变更步骤。

**四个在线步骤：** `chat_scopes_online` 校验两个放宽的检查，扫描 `chat_messages` 和 `managers`，不阻塞读写；另外三个分别以 CONCURRENTLY 方式建各自的索引。校验或建索引失败会导致启动失败。

**所有开关都关时：** 只执行迁移、在线步骤和备份，不写任何设置行；新增的仅限操作者的操作存在但无人自动调用；路由关闭时提示词、工具和模型可见字节不变；Work 前端代码（含 Planner 和默认管家两个对话面板）存在但隐藏（后端本版本不提供 `task_conversations.get`）；指标关时不记录入站计时；vault 提交事务只在实际写入时使用。

- #1736：仅控制台，任务行和详情页新增「Talk to this task」深链，可用性以服务端 `can_send` 为准、可见时每 10 秒刷新，不可用时显示带原因的禁用入口。
- #1743：仅休眠存储，首次添加 `legacy_allowed` 时已有绑定标记为 `legacy`，在后续激活前没有任何行为读取它；换绑管家时会在同一事务重置新范围字段。

- #1776：仅控制台，且在后续版本启用 Work 之前不可达：Work 管家列新增默认管家对话面板，复用 Chat 现有线程和回复流，按消息 ID 合并历史、自主报告和流式回复，并沿用 Chat 的 Stop 设置、回合恢复和暂存输入规则；管家范围归属确认前内容隐藏、禁止发送，外部指针会开新线程，读取失败时提供重试且保持禁发。无后端操作、无迁移、无 CLI 或渠道改动，Work 门关闭时现有页面不变。

**已有开关打开时：**
- **会话路由开（#1708）：** 默认管家非 main 会话限定为公开提示词、本聊数据和会话本地状态，零管家工具，拒绝越界全局读取，不兼容的已存上下文一次性重置；场景管家（含 `per_chat` 群）能力不变；路由关时字节不变。
- **晨报开（#1740）：** 补发只在 `morning_brief.cutoff` 之前；设置可为 `HH:MM` 或 null，null 按生效的发送时间推导：早于本地 12:00 时取 12:00，否则加三小时，达到午夜时读回 `{"kind":"end_of_day"}`；默认发送时间 09:15 对应 12:00，存储的截止时刻必须严格晚于发送时间，null 恢复推导；晨报始终遵守免打扰（含最近有回复的情形），但不占每日主动消息额度；免打扰或过期 tick 保留首次未读日期、不消费 ID、不耗尝试；免打扰在截止前结束则当天可发，否则摘要顺延下一工作日并只消费一次；Settings → Chat 表单可配置两个时间并需显式确认；晨报正文和 send-started 崩溃恢复不变。
- **attention 开：** 状态卡片「等你」行的终态提醒在后端显示为「未确认送达的提醒 N」、控制台英文卡显示为 `N reminders not confirmed delivered`，不再露出原始 key（#1756）；被挡住的 vault 合并显示为持久条目（#1700）。
- **指标开（#1737）：** 每条飞书入站消息把平台发送和 stdout 接收时刻、入站锁等待/发送者查询/附件下载耗时，以及到达路由阶段时的路由时刻 `route_decided_at` 记入 `llm_records.metadata.turn_metrics.lark_ingress`，并打一条只含渠道/消息 ID 和计时字段的结构化日志；缺失时间戳省略；排序、锁、重试、准入和发送内容不变，无迁移。
- **vault 记忆写入开（#1700）：** 走上述 worktree 事务；可选的 `projects.knowledge_dir` 经路径校验后生效，拒绝绝对路径、穿越、隐藏项、文件和符号链接组件。

### 可选能力启用与使用

#### Routed chat task tools

**启用：** 默认关。开关是 `manager.session_tools.enabled`，只能通过仅限操作者的 `session_tools.get` / `session_tools.update` 读写；`null` 恢复关闭，写入为高风险且需要确认，并且会话路由也打开时工具才会出现。升级不写设置行。

**验证：** `session_tools.get` 读回值。路由和开关都开时，路由群聊或其他发送者私聊获得四个 `looper_chat_*` 工具，只能列出和读取本聊任务，操作者可以创建、启动、停止、重启和 instruct；其他会话的任务、main 任务、未知 ID 和畸形 ID 都返回同一个类型化 `not_found`。其他发送者的写入以固定的操作者专属文案被拒绝且不产生请求；操作者身份缺失时失败关闭。`manager_sessions.assign_task` 可在显式确认后把一个未分配的旧任务一次性暴露给某会话，审计原子落库，分配后不可再改。路由开、工具关时保持 #1708 的零工具允许清单；路由关时与之前字节一致。

**停用 / 回退：** 通过 `session_tools.update` 存回 `false` 或 null 并确认。路由会话回到零工具，不改上下文策略版本；任务和来源信息保留。迁移的列和索引是附加的；降级需要迁移前备份，本版本不提供 down 迁移。

**权限边界：** 仅限操作者。工具调用绑定渠道写入的发送者和每次新鲜读取的操作者 ID，不进入全局 scope/授权路径，记入操作者操作审计。路由会话即使操作者本人在群里发言也没有 shell 和文件访问。该能力在私密审批能力交付前刻意保持关闭；PR 中规划的付费真实模型对照没有跑。

**启用：** 默认关，且本版本尚无法开启。控制台只在 `task_conversations.get` 返回 enabled 时显示 Work 入口；该启用操作本版本刻意不提供，因此关闭、404、未知操作和读取失败都会隐藏 Work，并把 Work URL 重定向回 Dashboard。工作模式设计预留的开关名是 `tasks.conversations.enabled`。升级不插入设置行。

**验证：** 冻结树为隐藏状态定义了覆盖全部现有路由、设置页和详情变体的 123 例全 DOM 冻结；本发布 PR 未重跑该前端测试。后续启用后，Work 提供来自 `tasks.work_list` 的分页工作列表（open/ended/schedules 三段，页大小 50、上限 100）、`tasks.mark_seen` 的按操作者未读水位、`tasks.select` 的确定性任务解析、`tasks.changes` 的有界文件变更读取（默认 100、硬上限 200，不含文件内容或补丁）、只在 Planner 目标 `can_send` 为真时可发送的 Planner 对话面板，以及默认管家对话面板：后者与 Chat 共用线程，按消息 ID 合并历史、自主报告和流式回复，管家范围归属确认前内容隐藏、禁止发送（#1776）。默认管家面板由七个前端测试文件共 255 个用例覆盖，其中 29 个新增适配用例覆盖归属、重复消息、已存终态、流中断、Stop 拒绝和过期回调；四个视口的无头浏览器检查覆盖有数据、空、读取失败和归属待定状态；一次性库上的一条合成自主报告只渲染一个气泡并读回一行存储，全程不调用模型。启用操作缺失时，真实的不可用操作路径仍回到 Dashboard 且不挂载任何 Work 面板。后端操作在 2,000 任务的一次性库上实测：各列表和选择段中位数约 2 毫秒，低于 100 毫秒目标。

**停用 / 回退：** 本版本没有启用操作，无可停用项；后续启用操作交付后，关掉开关即恢复现有控制台，附加的 `task_seen` 表、列和索引保留但无人使用。降级需要迁移前备份。

**权限边界：** 所有后端操作均仅限操作者：API 客户端身份在任何动作前收到 403；它们都不是 agent 工具，也不调用模型。`tasks.changes` 是 read 风险、机器级操作，复用现有 Git 运行器且禁用索引锁、外部 diff 和 textconv，失败返回类型化原因、不泄露原始诊断。默认管家面板在展示存储内容、订阅线程或允许发送前，先通过管家范围历史确认归属；外部指针会开新线程而不是续写旧线程，读取失败时保持禁发；它复用现有共享管家传输，不新增后端操作、不调用模型（#1776）。Work 的文件列表界面和任务管家本身仍在后续工作中。

#### Project knowledge export to the vault

**启用：** 显式触发，默认关，没有任何自动执行。预览和执行都要求已配置知识 vault 和 `projects.knowledge_dir`。操作者先用 `looper knowledge migrate --project NAME` 预览，不改动任何内容；只有加 `--execute` 才会在写出私有 JSON 备份并打印校验和之后执行导出。通过操作者项目 API 或设置表单填写项目相对的 `projects.knowledge_dir`；该字段拒绝绝对路径、穿越、隐藏项、文件和符号链接组件，不填仍保持现有读取行为，但预览和执行都会拒绝。

**验证：** dry-run 报告列出目标文件名、大小、超过 8 KiB 标记和原始元数据；路径类文档转为引用笔记且不读原文件。执行使用一次 vault worktree 事务，随后读回并校验每个导出文件；目标位置已有不同内容时报告并拒绝，绝不覆盖；源行永不修改或删除。重复执行报告无新工作，备份行带 sha256 校验和。

**停用 / 回退：** 不传 `--execute` 即可；配置齐全时预览不改内容，缺少 vault 或 `knowledge_dir` 时直接拒绝。导出后可按正常 vault 评审流程移除导出笔记并用打印的备份恢复；源项目行按设计保持不动。清空 `knowledge_dir` 即恢复原有布局。附加列保留；降级需要迁移前备份。

**权限边界：** 仅限操作者的本地命令和项目字段。共享 vault 事务保留显式路径暂存、钩子校验、仅快进合并和现有可写目录规则（包括空可写列表）；合并被挡时保留自有分支并在「需要你处理」呈现，绝不替其他编辑者改东西。从 vault 读回项目知识、旧路径退役和源列删除属于明确的后续部分，不在本版本。

**文档：** https://github.com/foolzzz/looper/blob/v2.15.37/docs/architecture/agent-system.md#the-knowledge-vault-the-operators-notes-read-and-written-through-looper
