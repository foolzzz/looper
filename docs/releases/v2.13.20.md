# Looper v2.13.20

## Release Decision

**Who should upgrade:** Dashboard users who open Chat conversations or a task's Room tab from a link, a refresh or the browser's Back and Forward buttons. Everyone else sees no change.

**What this release solves:** [#350](https://github.com/foolzzz/looper/pull/350) fixes the review follow-ups of #325. The Chat page keeps the open conversation in its address, reads a conversation by its own id so an old one opens by link, and the task Room tab keeps its message-kind and role filters in the address.

**Breaking changes:** No. No CLI command, configuration key or database schema changed. `GET /api/chat/sessions` gains an optional `session_id` query parameter; without it the response is as before.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#350](https://github.com/foolzzz/looper/pull/350); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.20
```

## Behavior changes

- **Web conversation in the address:** the Chat page writes the open Web conversation to `?conversation=<id>` and restores it from there, so a link, a refresh, Back and Forward reopen the same one. Choosing a conversation and starting a new chat both update the address. An id with no messages yet is treated as a new Web thread (`web/src/pages/chat.tsx`).
- **Conversations read by id:** `GET /api/chat/sessions` accepts `session_id` and then returns only that conversation, however long ago it was active (an empty list when it has no messages). The list is still limited to the newest 50 without it. The Chat page reads the conversation named in the address through this, so a deep link beyond the newest 50 opens, an open read-only Lark or Telegram conversation stays read-only when the list moves on, and the page shows "Loading the conversation…" or "Could not load the conversation: …" (retried on the polling cadence) instead of the empty-chat greeting. The changes are in `looper/db/chat.py`, `looper/agents/http_server.py`, `web/src/lib/api.ts` and `web/src/pages/chat.tsx`.
- **Room filters in the address:** the task Room tab keeps its kind filter and role filter in `?tab=room&filter=<interface|unanswered>&role=<role>`; "all" and no role are left out, and any other `filter` value reads as all. A refresh, a link, Back and Forward keep them. "re #N" and "Show all" clear the filters through the address and then scroll to the message. Where the tab is used without the address handler it keeps its filters locally as before (`web/src/components/task-room.tsx`, `web/src/lib/room.ts`, `web/src/pages/task-detail.tsx`, `web/src/pages/tasks.tsx`).
- **Tests:** `tests/test_chat_sessions_api.py` covers finding a conversation by id past the newest 50 and an unknown id; `web/src/url-state.test.tsx` covers the address state.
- **Deferred, not fixed here:** the PR defers one flaky installed-`dsh` test that fails only under CPU contention, and reports that the flaky schema test was already fixed (#349). Both stay tracked in #325.
- **Model-visible changes:** None. No prompt, tool schema or tool result changed. The `session_id` parameter belongs to the dashboard's HTTP API.

## Upgrade and rollback

Re-run `install.sh` once v2.13.20 is published. There is no schema or configuration change. Rolling back to v2.13.19 is safe; addresses with `?conversation=` or `filter=` then fall back to the earlier behavior.

### 行为变化与入口

- 地址中的 Web 对话：Chat 页把当前 Web 对话写入 `?conversation=<id>` 并从中恢复，链接、刷新、后退、前进都会重新打开同一对话；选择对话和新建对话也会更新地址。尚无消息的 id 视为新的 Web 线程（`web/src/pages/chat.tsx`）。
- 按 id 读取对话：`GET /api/chat/sessions` 接受 `session_id`，此时只返回该对话，无论它多久前活跃过（无消息则返回空列表）；不带时列表仍限于最新 50 个。Chat 页借此读取地址中的对话，因此超出最新 50 个的深链接可以打开，已打开的只读 Lark/Telegram 对话在列表更新后仍保持只读，并显示“Loading the conversation…”或“Could not load the conversation: …”（按轮询节奏重试），而不是空聊天提示。改动在 `looper/db/chat.py`、`looper/agents/http_server.py`、`web/src/lib/api.ts`、`web/src/pages/chat.tsx`。
- 地址中的 Room 过滤：任务 Room 标签页把类型过滤和角色过滤保存在 `?tab=room&filter=<interface|unanswered>&role=<role>`；“all”和无角色不写入，其他 `filter` 值按 all 处理。刷新、链接、后退、前进都会保留。“re #N”和“Show all”通过地址清除过滤后再滚动到该消息。未提供地址处理函数时，标签页仍像以前一样在本地保存过滤（`web/src/components/task-room.tsx`、`web/src/lib/room.ts`、`web/src/pages/task-detail.tsx`、`web/src/pages/tasks.tsx`）。
- 测试：`tests/test_chat_sessions_api.py` 覆盖超出最新 50 个的按 id 查找与未知 id；`web/src/url-state.test.tsx` 覆盖地址状态。
- 延后未修：PR 延后了一个仅在 CPU 争用下失败的已安装 `dsh` 不稳定测试，并报告不稳定的 schema 测试已在 #349 修复。两者仍在 #325 跟踪。
- 面向模型的变化：无。提示词、工具 schema、工具结果均无变化。`session_id` 参数属于 Dashboard 的 HTTP API。

### 升级与回退

发布后重跑 `install.sh`。无 schema 或配置变更。回退到 v2.13.19 安全；带 `?conversation=` 或 `filter=` 的地址会回到早先的行为。
