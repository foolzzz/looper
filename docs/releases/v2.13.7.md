# Looper v2.13.7

## Release Decision

**Who should upgrade:** Nobody needs to for runtime behavior. This patch only changes two tests; contributors and CI runners on loaded machines benefit from fewer spurious failures.

**What this release solves:** [#288](https://github.com/foolzzz/looper/pull/288) removes two load-dependent failures in the test suite of #261 (the eval deadline kill test and the pi Responses wire test) without weakening what they check.

**Breaking changes:** No. The API, configuration, registry schema, CLI, channels and dashboard are unchanged from [v2.13.6](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.6.md).

**How to verify:** Check the version. Nothing else changes at runtime.

**Contributors:** Maintainer @foolzzz authored [#288](https://github.com/foolzzz/looper/pull/288); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.7
```

## Behavior changes

- **Runtime behavior:** None. The change touches only `tests/test_pi_packaging.py` and `tests/test_pi_runtime.py`; the product code was correct.
- **Eval deadline test:** `test_eval_deadline_kills_term_ignoring_child` now has the fake runner record its start time and asserts the kill latency from the deadline (runner start plus the 2 s deadline) is under `proc_tree.TERM_GRACE_SEC` plus 3 s. The 8 s bound from the script launch is gone; the outer subprocess timeout is 60 s (was 10 s) and only guards a hang. The process-death assertions are unchanged.
- **pi Responses wire test:** `test_pi_responses_wire_preserves_optional_tool_parameters` raises the in-node abort from 10 s to 60 s and the subprocess timeout from 20 s to 120 s. Request assertions are unchanged.
- **Model-visible changes:** None. No prompt, tool schema, tool description or model-facing text changed.

## Entry points

No entry point changes: CLI, API, dashboard, Manager tools, launches and prompts are the same as in v2.13.6.

## Upgrade and rollback

No action is needed beyond the usual re-run of `install.sh` once v2.13.7 is published; there is no configuration, data or migration change. Rolling back to v2.13.6 is safe.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## Validation

**Retained implementation evidence:** [#288](https://github.com/foolzzz/looper/pull/288) reports `pytest tests/test_pi_packaging.py -k term_ignoring` (12 passed) and `pytest tests/test_pi_runtime.py -k optional_tool_parameters` (4 passed). The PR description does not report a full local suite or a review. This draft did not re-run them.

**CI:** CI runs after the release is drafted; its result is not recorded here.

**Not tested for this draft:** Local test runs, runtime launches, database migration and restore, and model evals. The release documentation gate checks the body only.

### 行为变化与入口

- 运行时行为：无变化。仅改动 `tests/test_pi_packaging.py` 与 `tests/test_pi_runtime.py`，产品代码本身是正确的。
- eval 截止时间测试：`test_eval_deadline_kills_term_ignoring_child` 现在由假 runner 记录启动时间，并断言从截止时间（runner 启动时间加 2 秒截止）起算的击杀延迟小于 `proc_tree.TERM_GRACE_SEC` 加 3 秒；不再以脚本启动起算 8 秒。外层 subprocess 超时为 60 秒（原 10 秒），仅用于防止挂死。进程死亡断言不变。
- pi Responses wire 测试：`test_pi_responses_wire_preserves_optional_tool_parameters` 将 node 内中止时间由 10 秒提高到 60 秒，subprocess 超时由 20 秒提高到 120 秒。请求断言不变。
- 面向模型的变化：无。提示词、工具 schema、工具描述和面向模型的文本均未改动。
- 入口：无变化，CLI、API、仪表盘、Manager 工具、启动和提示词与 v2.13.6 相同。
