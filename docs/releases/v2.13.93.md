# Looper v2.13.93

## Release Decision

**Who should upgrade:** Anyone who calls the project routes `GET`/`POST /api/projects` and `PUT`/`DELETE /api/projects/{id}` from a script or client of their own. The bundled dashboard already uses the new operations, so dashboard-only users get no visible change.

**What this release solves:** [#523](https://github.com/foolzzz/looper/pull/523) moves project management (list, create, update, delete) to the v1 API as the `project_admin` operations and removes the legacy routes. [#555](https://github.com/foolzzz/looper/pull/555) aligns the living operator API documentation (READMEs, the agent-system architecture page, the design document) with the v1 routes.

**Breaking changes:** Yes. `GET /api/projects`, `POST /api/projects`, `PUT /api/projects/{id}` and `DELETE /api/projects/{id}` now answer 404. Use `POST /api/v1/project_admin/{list,create,update,delete}`; results come inside `OpOk.result` (create and update return `{project}`, not a bare object or a 201). Project knowledge routes are not part of this change.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#523](https://github.com/foolzzz/looper/pull/523) and [#555](https://github.com/foolzzz/looper/pull/555); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.93
```

## Behavior changes

- **Project management in v1 ([#523](https://github.com/foolzzz/looper/pull/523)):** `looper/agents/v1_domains/projects.py` adds four operations: `project_admin.list` (`read`, body `{}`, returns `{projects}`), `project_admin.create` (`write`, project fields with `name` required), `project_admin.update` (`write`, `{project_id, fields}` with at least one field) and `project_admin.delete` (`high` risk, `{project_id}`, returns `{deleted}`; a client token needs confirmation). The project view carries the execution settings and the task, active and schedule counts. Execution budgets accept numbers or numeric strings, and a template that uses the project, or a project with work in flight, still blocks deletion with a conflict (the delete impact check reuses the compact operation's). An update that changes nothing is rejected as invalid. The compact `projects` operations now declare typed result schemas (`projects.list`, `projects.get`, `projects.create`, `projects.update`, `projects.delete`); their request shape is unchanged.
- **Legacy routes removed ([#523](https://github.com/foolzzz/looper/pull/523)):** the project routes and their handlers are deleted from `looper/agents/http_server.py`; the route table now answers 404 for them. The dashboard (`web/src/lib/api.ts`), the prompt-regression evals, the DSH and Pi smoke examples and the wheel smoke call the v1 operations instead.
- **Documentation ([#555](https://github.com/foolzzz/looper/pull/555)):** `README.md`, `README.zh-CN.md`, `docs/architecture/agent-system.md` and `docs/design.md` now name the v1 routes for system status, roles, agent settings, project agent settings, allowed profiles and Agent Profiles, describe the `OpOk` and `OpError` shapes, and add rows for role templates, project role statistics, gates, task roles, waits, the room view and API clients. The HTTP API section of the README still lists the legacy project paths in its Projects row. No production code changed; `tests/test_documented_v1_routes.py` checks that the documented routes exist in the generated OpenAPI document and that removed paths are not advertised.
- **Model-visible changes:** none found in prompt text or Tool declarations. The compact `projects` Tool keeps its contract; only the operator HTTP API and its OpenAPI result schemas change.
- **Tests:** [#523](https://github.com/foolzzz/looper/pull/523) adds `tests/test_api_v1_projects.py`, `tests/test_api_v1_projects_db.py` and `web/src/lib/api-projects.test.ts`, and moves existing tests to the new routes. [#555](https://github.com/foolzzz/looper/pull/555) adds `tests/test_documented_v1_routes.py`.

## Upgrade and rollback

Re-run `install.sh` once v2.13.93 is published. No data migration; projects are stored as before. Move any script that called the legacy project routes to the `project_admin` operations before upgrading. Rolling back to v2.13.92 restores the legacy routes.

### 行为变化与入口

- **v1 项目管理（[#523](https://github.com/foolzzz/looper/pull/523)）：**`looper/agents/v1_domains/projects.py` 新增四个操作：`project_admin.list`（`read`，请求体 `{}`，返回 `{projects}`）、`project_admin.create`（`write`，`name` 必填）、`project_admin.update`（`write`，`{project_id, fields}`，至少一个字段）、`project_admin.delete`（`high` 风险，`{project_id}`，返回 `{deleted}`；客户端令牌需确认）。项目视图包含执行设置以及任务数、活跃数、定时计划数。执行预算接受数字或数字字符串；被模板使用或仍有任务在进行的项目照旧因冲突而不能删除（删除影响检查沿用精简操作的检查）。没有任何变化的修改会被判为无效。精简的 `projects` 操作新增了带类型的结果 schema（`projects.list`、`projects.get`、`projects.create`、`projects.update`、`projects.delete`），请求形态不变。
- **旧路由移除（[#523](https://github.com/foolzzz/looper/pull/523)）：**`looper/agents/http_server.py` 删除了项目路由及其处理函数，这些路径现在返回 404。Dashboard（`web/src/lib/api.ts`）、prompt 回归评测、DSH 与 Pi 冒烟示例以及 wheel 冒烟改用 v1 操作。
- **文档（[#555](https://github.com/foolzzz/looper/pull/555)）：**`README.md`、`README.zh-CN.md`、`docs/architecture/agent-system.md`、`docs/design.md` 现在写明系统状态、角色、Agent 设置、项目 Agent 设置、允许的 Profile 和 Agent Profile 的 v1 路由，说明 `OpOk` 与 `OpError` 的形态，并新增角色模板、项目角色统计、gate、任务角色、等待、房间视图和 API 客户端的条目。README 的 HTTP API 一节中“项目”一行仍列着旧的项目路径。生产代码无变化；`tests/test_documented_v1_routes.py` 检查文档中的路由存在于生成的 OpenAPI 文档，且已移除的路径不再被宣传。
- **面向模型的变化：**prompt 文本和 Tool 声明未发现变化。精简的 `projects` Tool 契约不变，变化的只有操作者 HTTP API 及其 OpenAPI 结果 schema。
- **测试：**[#523](https://github.com/foolzzz/looper/pull/523) 新增 `tests/test_api_v1_projects.py`、`tests/test_api_v1_projects_db.py`、`web/src/lib/api-projects.test.ts`，并把已有测试改到新路由。[#555](https://github.com/foolzzz/looper/pull/555) 新增 `tests/test_documented_v1_routes.py`。
