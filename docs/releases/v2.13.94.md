# Looper v2.13.94

## Release Decision

**Who should upgrade:** Maintainers who run the prompt-regression evals (`evals/prompt_regression`). Product users get no visible change.

**What this release solves:** [#553](https://github.com/foolzzz/looper/pull/553) fixes the "start without waiting" dialog check in the prompt-regression evals. It no longer lets a subagent's `looper_task_control` start outcome shift which start counts as the Manager's, and no longer counts a subagent's native tools as the Manager waiting.

**Breaking changes:** No. Only the eval harness and its tests changed; no production code, API, prompt or Tool declaration.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#553](https://github.com/foolzzz/looper/pull/553); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.94
```

## Behavior changes

- **Start audit matching ([#553](https://github.com/foolzzz/looper/pull/553)):** `_native_calls_after_start` in `evals/prompt_regression/dialogs.py` is replaced by `_manager_starts_and_native_calls`. The audit trail carries no stream call ids and includes subagent calls, so the check now pairs every `looper_task_control` start in the newest Manager run with the audit entries in order, then keeps only starts whose event has no `parent_tool_use_id` and whose audit status is `ok`. The first such start is the anchor, so a subagent start (failed or successful) or a refused Manager retry no longer moves it. Native tools called after the anchor count as waiting only when the Manager itself called them; subagent `Bash` or terminal calls no longer do. `_started_without_waiting` takes both the start count and the native calls from this helper. Wrapped starts (`use_tool` around `looper_task_control`) are still normalized.
- **Model-visible changes:** none. No prompt text, Tool declaration or Tool result changed; this is test-harness logic only.
- **Tests:** `tests/test_prompt_eval.py` extracts a `start_no_wait_look` fixture and adds `test_start_no_wait_matches_child_and_parent_audit_outcomes` with 13 cases: subagent failure or success before and after the Manager start, parent conflict, repeated success, Manager retry, status-read polling, subagent native tools, and wrapped starts. [#553](https://github.com/foolzzz/looper/pull/553) reports 84 test lines and 0 production lines added.

## Upgrade and rollback

Re-run `install.sh` once v2.13.94 is published. No data migration and no configuration change. Rolling back to v2.13.93 restores the previous eval check.

### 行为变化与入口

- **启动审计匹配（[#553](https://github.com/foolzzz/looper/pull/553)）：**`evals/prompt_regression/dialogs.py` 中的 `_native_calls_after_start` 被 `_manager_starts_and_native_calls` 取代。审计记录没有流式调用 id 且包含子 agent 的调用，因此检查先把最新 Manager 运行中的所有 `looper_task_control` 启动与审计条目按顺序配对，再只保留事件没有 `parent_tool_use_id` 且审计状态为 `ok` 的启动。第一次这样的启动作为锚点，子 agent 的启动（无论成败）或被拒绝的 Manager 重试都不会移动它。锚点之后只有 Manager 自己调用的原生工具才算等待，子 agent 的 `Bash` 或终端调用不再计入。`_started_without_waiting` 的启动次数和原生调用都来自这个函数。包在 `use_tool` 里的启动仍会被规范化。
- **面向模型的变化：**无。prompt 文本、Tool 声明和 Tool 结果均未改变，仅是测试框架逻辑。
- **测试：**`tests/test_prompt_eval.py` 抽出 `start_no_wait_look` fixture，新增 `test_start_no_wait_matches_child_and_parent_audit_outcomes`，共 13 个用例：子 agent 在 Manager 启动前后失败或成功、Manager 冲突、重复成功、Manager 重试、状态轮询、子 agent 原生工具、包装的启动。[#553](https://github.com/foolzzz/looper/pull/553) 报告新增测试 84 行、生产代码 0 行。
