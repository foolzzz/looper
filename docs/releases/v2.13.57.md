# Looper v2.13.57

## Release Decision

**Who should upgrade:** Operators who run Planners on the Claude Code runtime and point a Planner at a document by path (for example a design file in the repository or a mounted knowledge directory). Nobody else needs to act.

**What this release solves:** [#452](https://github.com/foolzzz/looper/pull/452) fixes a read-only Claude Code Planner being refused when it reads a document it was given. The Planner chose a `Bash cat` command, the read-only run refused it, and the Planner gave up on the document. The Planner now reads files with the Read, Glob and Grep tools, which are allowed for its repository and mounted knowledge directories, and Bash is no longer available to it.

**Breaking changes:** No. No stored data or configuration changed. One behavior is narrower: a read-only Claude Code Planner no longer has the Bash tool, including read-only commands such as `git diff`.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#452](https://github.com/foolzzz/looper/pull/452); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.57
```

## Behavior changes

- **Read-only Planner launch (`looper/agents/claude_cli.py`, `looper/agents/runtimes/claude_code.py`):** `read_only_args` now takes the run's working directory and its extra knowledge directories. It allows `Read`, `Glob` and `Grep` for the repository root and each extra directory (absolute path rules, with glob characters in directory names escaped so they match literally), and adds `Bash` to the disallowed tools next to `Edit`, `Write` and `NotebookEdit`. Skills, web reads and the Planner's MCP servers stay allowed as before. The runtime passes the working directory to `launch_args` for both the start and the resume command lines.
- **Planner has no shell:** before, Claude Code's own judgment decided which Bash commands a Planner could run, and a project's `permissions.allow` could open a writing command to it. Now the Planner has no Bash at all, so it cannot run read-only git commands or tests either; running commands is left to the Worker. The "known gap" about project allow rules for Bash is removed from the read-only RFC.
- **What other runtimes do:** unchanged. Codex, OMP, Pi, Grok and DSH already have read tools or a read-only sandbox, and a consult run keeps its own reading-only tool set.
- **Docs and tests:** the read-only Planner RFC (sections 4.1 and 4.2) and the long-horizon context plan describe the new rule. Tests cover the launch arguments (`tests/test_claude_cli.py`), the Planner (`tests/test_planner_agent.py`), provider binding and the launch parity checks. The pull request reports added lines: tests 67, production 9 (fixtures excluded); the file list also shows larger test additions than that figure.
- **Model-visible changes:** Yes, for a Claude Code Planner only. Its tool list no longer contains Bash, and Read, Glob and Grep are explicitly allowed for the repository and mounted directories. A path outside those directories, or one that reaches outside through `..` or a symbolic link, is still refused and recorded in `permission_denials`, according to the notes the pull request adds to the docs. The Planner's prompt text is not changed. Manager, Worker and Reviewer launches are not changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.57 is published. No data migration. Rolling back to v2.13.56 gives the Claude Code Planner its Bash tool back, with the original refusal of document reads through `cat`; nothing is stored differently.

## 中文摘要

### 升级决策

**谁需要升级：**在 Claude Code 运行时上运行 Planner，并按路径把文档（例如仓库里的设计文件或挂载的知识目录）交给 Planner 的运维者。其他人无需操作。

**解决了什么：**[#452](https://github.com/foolzzz/looper/pull/452) 修复只读的 Claude Code Planner 读取指定文档时被拒绝的问题：Planner 选了 `Bash cat`，只读运行拒绝该命令，Planner 便放弃读取文档。现在 Planner 用 Read、Glob、Grep 读文件，这三个工具对其仓库和挂载的知识目录放行，同时不再提供 Bash。

**是否有破坏性变更：**无。存储数据和配置均未改动。一处行为收窄：只读的 Claude Code Planner 不再有 Bash 工具，包括 `git diff` 这类只读命令。

**如何验证：**运行 `looper --version` 核对版本为 2.13.57。

**贡献者：**维护者 @foolzzz 提交 [#452](https://github.com/foolzzz/looper/pull/452)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.57
```

### 行为变化与入口

- 只读 Planner 的启动参数（`claude_cli.py`、`runtimes/claude_code.py`）：`read_only_args` 现在接收运行的工作目录和额外的知识目录，对仓库根目录和每个额外目录放行 `Read`、`Glob`、`Grep`（绝对路径规则，目录名中的 glob 字符会转义，按字面匹配），并把 `Bash` 加入禁用工具，与 `Edit`、`Write`、`NotebookEdit` 并列。技能、联网读取和 Planner 的 MCP 服务器照旧放行。运行时在启动和续跑两条命令行里都传入工作目录。
- Planner 没有 shell：此前由 Claude Code 自己判断 Planner 能跑哪些 Bash 命令，项目的 `permissions.allow` 还可能向它放开写文件的命令。现在 Planner 完全没有 Bash，不能执行只读 git 命令或测试，执行命令交给 Worker。只读 RFC 中关于项目放行规则的「已知缺口」随之删除。
- 其他运行时：不变。Codex、OMP、Pi、Grok、DSH 本来就有读取工具或只读沙箱；consult 运行保持自己的只读工具集。
- 文档与测试：更新只读 Planner RFC（4.1、4.2 节）和长程上下文计划。测试覆盖启动参数、Planner、供应方绑定和启动一致性检查。PR 报告新增测试 67 行、生产代码 9 行（不含 fixture）；文件列表显示的测试增量大于该数字。
- 面向模型的变化：有，仅限 Claude Code 的 Planner。其工具列表不再含 Bash，Read、Glob、Grep 对仓库和挂载目录显式放行。按该 PR 新增的文档记述，目录之外的路径、经 `..` 或符号链接越界的路径仍被拒绝，并记入 `permission_denials`。Planner 的 prompt 文本未改。Manager、Worker、Reviewer 的启动不变。

### 升级与回退

v2.13.57 发布后重跑 `install.sh`，无需迁移数据。回退到 v2.13.56 会让 Claude Code 的 Planner 重新拥有 Bash 工具，也恢复经 `cat` 读文档被拒的问题；存储无差异。
