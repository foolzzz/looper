# Looper v2.13.52

## Release Decision

**Who should upgrade:** Operators who import configuration through `loopercli config import` or the v1 API, in particular those who share one server between several callers. Nobody else needs to act.

**What this release solves:** [#440](https://github.com/foolzzz/looper/pull/440) fixes the open review follow-ups of the `loopercli` auth, doctor and config commands (#437): a staged configuration import can now be cancelled from the command line and the API, the limit of four pending imports applies per caller instead of to the whole server, the import preview prints the full plan, and a failed export write no longer leaves a partial file behind.

**Breaking changes:** No. No existing API, configuration or stored data changed; the new operation and the `--cancel` option are additions.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#440](https://github.com/foolzzz/looper/pull/440); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.52
```

## Behavior changes

- **Cancel a staged import (`looper/agents/api_v1.py`, `looper/agents/http_server.py`, `looper/agents/config_imports.py`, `looper/loopercli.py`):** the v1 API gains the operation `config.import_cancel` (`POST /config/import_cancel`, body `{"import_id": ...}`, result `{"deleted": <import_id>}`), and `loopercli config import` gains `--cancel IMPORT_ID`. `--apply` and `--cancel` are mutually exclusive, and neither takes a FILE. The server cancels only an import staged by the same caller (`ConfigImports.cancel` now takes the owner), and refuses with a conflict while the import is being applied.
- **Pending imports per caller (`looper/agents/config_imports.py`):** the limit `PENDING_MAX` (4) counts the pending and the arriving uploads of the calling principal instead of those of the whole server, so one caller can no longer fill the slots of the others. The arriving uploads are counted per owner.
- **Import preview output (`looper/loopercli.py`):** for a config import result the `plan` is printed as indented JSON, so every change, missing credential and migration note stays visible, instead of the generic table or summary.
- **Export file write (`looper/loopercli.py`):** the export file is written as UTF-8. When writing fails after the file was created (an I/O or encoding error), the partial file is removed and the command reports `cannot write the export file`. An existing destination is still never overwritten and symlinks are not followed.
- **Model-visible changes:** The generated OpenAPI document of the v1 API lists one more operation, `config.import_cancel`. No prompt, tool result or channel text changed.
- **Tests added:** The pull request reports added lines: tests 239, production 41 (fixtures excluded). New tests cover per-caller limits and owner-checked cancel (`tests/test_config_import_owners.py`), the CLI cancel and plan output (`tests/test_loopercli_ops.py`) and the API operation list (`tests/test_api_v1_cli_ops_db.py`).

## Upgrade and rollback

Re-run `install.sh` once v2.13.52 is published. No data migration. Rolling back to v2.13.51 removes the cancel operation and restores the server-wide limit of pending imports; nothing is stored differently.

### 升级决策

**谁需要升级：**通过 `loopercli config import` 或 v1 API 导入配置的运维者，尤其是多个调用方共用一台服务器的人。其他人无需操作。

**解决了什么：**[#440](https://github.com/foolzzz/looper/pull/440) 修复 `loopercli` 的 auth、doctor 和 config 命令（#437）的评审遗留问题：已暂存的配置导入现在可从命令行和 API 取消；最多 4 个待处理导入的限制改为按调用方计算，而非整台服务器；导入预览打印完整计划；导出写入失败不再留下残缺文件。

**是否有破坏性变更：**无。现有 API、配置和存储数据均未改动；新增的操作与 `--cancel` 选项都是增量。

**如何验证：**运行 `looper --version` 核对版本为 2.13.52。

**贡献者：**维护者 @foolzzz 提交 [#440](https://github.com/foolzzz/looper/pull/440)；本次 patch release 无社区贡献。

### 行为变化与入口

- 取消已暂存的导入：v1 API 新增操作 `config.import_cancel`（`POST /config/import_cancel`，请求体 `{"import_id": ...}`，返回 `{"deleted": <import_id>}`），`loopercli config import` 新增 `--cancel IMPORT_ID`。`--apply` 与 `--cancel` 互斥，且都不接受 FILE。服务器只允许取消同一调用方暂存的导入（`ConfigImports.cancel` 现需要所有者），导入正在应用时拒绝并返回冲突。
- 按调用方限制待处理导入：`PENDING_MAX`（4）统计的是当前调用方的待处理与正在上传的导入，而非整台服务器，因此一个调用方不能再占满其他调用方的名额。上传中的数量按所有者分别计数。
- 导入预览输出：配置导入结果中的 `plan` 以缩进 JSON 打印，使每项变更、缺失凭据和迁移说明都可见，而不是通用表格或摘要。
- 导出文件写入：导出文件以 UTF-8 写入。文件创建后写入失败（I/O 或编码错误）时，残缺文件会被删除，命令报告 `cannot write the export file`。已存在的目标文件仍不会被覆盖，也不会跟随符号链接。
- 面向模型的变化：v1 API 生成的 OpenAPI 文档多了一个操作 `config.import_cancel`。提示词、工具结果和渠道文案均未改动。
- 新增测试：PR 报告新增测试 239 行、生产代码 41 行（不含 fixture）。新测试覆盖按调用方的限制与校验所有者的取消（`tests/test_config_import_owners.py`）、CLI 取消与计划输出（`tests/test_loopercli_ops.py`）以及 API 操作列表（`tests/test_api_v1_cli_ops_db.py`）。
