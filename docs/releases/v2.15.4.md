# Looper v2.15.4

This is the patch release v2.15.4, a hotfix line in which each merged change ships at once. It documents one change: [#1371](https://github.com/foolzzz/looper/pull/1371) (room push for OMP RPC runs and Pi CLI RPC runs).

## Release Decision

**Who should upgrade:** Operators who run OMP (18.4.3 or later) or Pi Workers or Reviewers and want room messages to reach a run while it works instead of waiting to be pulled.

**What this release solves:** [#1371](https://github.com/foolzzz/looper/pull/1371) delivers room messages to OMP RPC runs and Pi CLI RPC runs by steering, as Codex, Coco and Grok runs already do. Before, these runtimes pulled room messages through the room tools.

**Breaking changes:** No. The CLI, the API and the dashboard are unchanged, no new command or control is added and there is no PostgreSQL schema change. The PR states a behavior change, listed below. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.4
```

**Contributors:** Maintainer @foolzzz authored [#1371](https://github.com/foolzzz/looper/pull/1371); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.3 upgrades directly. There is no PostgreSQL schema change. Restart the service after upgrading, as for every release.

## Behavior changes

Read in the diff of the PR.

### #1371: Room push for OMP RPC runs and Pi CLI RPC runs

- **Room push.** `OmpRuntime` and `PiRuntime` declare `room_push = RoomPush.STEER`. A run gets room push only when its launch steers: OMP needs detected steering (version 18.4.3 or later, and `--help` showing `--no-ui` and `rpc`) and Pi needs its steer capability. Other runs keep `PULL`. Existing registrations keep their saved capabilities until Re-detect.
- **Receipt event.** The OMP and Pi streams now translate a user message into a `system` event with subtype `user_message_receipt` (before, OMP and Pi dropped it). Codex's subtype `codex_user_message` is renamed to the same name, and the Worker reads receipts from that one subtype. The Worker uses the receipt to confirm a delivery, never as model output.
- **Fallback timing.** The 30 second receipt fallback is armed only after Looper's room delivery is accepted and no tool is running, and at most once per delivery. When tools are still running at acceptance, it is armed when the last tool result arrives. Before, it started at acceptance.
- **Tool-call turns.** For steered runs, a tool call now schedules the reminder flush as a retry instead of awaiting it, because the RPC acknowledgement is read by the same event iterator.
- **Cleanup.** At the end of a run, a pending reminder retry is cancelled together with the room fallbacks.
- **Docs.** The PR adds one line to the Chinese steering RFC (known gaps) saying that Codex, OMP 18.4.3+ RPC and Pi CLI RPC runs receive room pushes, that the receipt is a user message with `[Looper room]` and the batch ids, and that the Pi SDK runner does not use this path.

### Model-visible changes

Yes, for OMP and Pi Workers and Reviewers whose launch steers. `room_input` gives them the pushed room guidance (`PUSHED`) instead of the pull guidance (`PULL`), so the room section of their prompts changes, and room message bodies arrive as steered input in the run's turn. OMP and Pi runs without steering, the Pi SDK runner and other runtimes are unchanged. No tool schema was changed by this PR.

### 行为变化与入口

以下在该 PR 的差异中可见。

**#1371：OMP RPC 运行和 Pi CLI RPC 运行的房间推送**

- **房间推送。**`OmpRuntime` 和 `PiRuntime` 声明 `room_push = RoomPush.STEER`。只有启动时具备 steer 的运行才获得房间推送：OMP 需要检测到 steer（版本 18.4.3 及以上，且 `--help` 含 `--no-ui` 和 `rpc`），Pi 需要其 steer 能力。其他运行保持 `PULL`。现有注册在 Re-detect 之前保留原有能力。
- **回执事件。**OMP 和 Pi 的事件流现在把用户消息翻译为子类型 `user_message_receipt` 的 `system` 事件（此前两者丢弃该消息）。Codex 的子类型 `codex_user_message` 改名为同一名称，Worker 只从这一个子类型读取回执。Worker 用回执确认投递，从不把它当作模型输出。
- **兜底时机。**30 秒回执兜底仅在 Looper 的房间投递被接受且没有工具在运行时启动，且每条投递最多一次；接受时若仍有工具在运行，则在最后一个工具结果到达时启动。此前在接受时就开始计时。
- **工具调用轮次。**对 steer 运行，工具调用现在把提醒的刷新安排为重试而不是等待，因为 RPC 确认由同一个事件迭代器读取。
- **清理。**运行结束时，待处理的提醒重试与房间兜底一起被取消。
- **文档。**PR 在中文 steer RFC 的已知差距中加了一行，说明 Codex、OMP 18.4.3+ RPC 和 Pi CLI RPC 运行接收房间推送，回执是带 `[Looper room]` 和批次 id 的用户消息，Pi SDK runner 不走此路径。

**面向模型的变化：**有，针对启动时具备 steer 的 OMP 和 Pi Worker 与 Reviewer。`room_input` 为它们给出推送式房间指引（`PUSHED`）而不是拉取式（`PULL`），因此其提示词中的房间部分会变化，房间消息正文作为 steer 输入进入运行的当前轮次。没有 steer 的 OMP 和 Pi 运行、Pi SDK runner 和其他运行时不变。该 PR 未改动工具 schema。
