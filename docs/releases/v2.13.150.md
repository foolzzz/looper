# Looper v2.13.150

## Release Decision

**Who should upgrade:** Operators who keep the dashboard Tasks page open on a busy or slow service. Everyone else can stay on v2.13.149.

**What this release solves:** [#708](https://github.com/foolzzz/looper/pull/708) keeps the dashboard task list updating when a list request takes longer than the three-second refresh interval, and keeps Show more from dropping rows when a poll lands first. It also covers the issue #706 named in the description.

**Breaking changes:** No. The change is confined to the dashboard Tasks page; no API, schema or storage changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#708](https://github.com/foolzzz/looper/pull/708); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.150
```

## Behavior changes

- **Polling (#708):** `web/src/pages/tasks.tsx` no longer refreshes on a fixed three-second interval. It polls again three seconds after the previous request settles (success or failure), so requests no longer overlap. The timer is cleared when the filter changes or the page unmounts.
- **Slow responses (#708):** a refresh response is applied unless the page has left its filter or a newer refresh has already been applied. A newer request still in flight no longer starves a usable older response.
- **Show more (#708):** the page records the cursor (`next_before`) synchronously. A Show more response is applied only if its filter is still current and the cursor it was requested with is still the current one; otherwise it is dropped, including its error. If a poll keeps the cursor, the older page is accepted, deduplicated and kept on later polls.
- **Tests (#708):** `web/src/pages/tasks.test.tsx` is new and covers slow initial and refresh responses, retry after a slow failure, overlapping manual refreshes in both orders, a pending older page when polling changes the cursor, and late responses after a filter change (including returning to the filter).
- **Model-visible changes:** none. No tool, prompt, schema or declaration changed.
- **Line counts:** the description reports 0 added test lines and 199 production lines, and targets 60–160 changed lines. Its file list shows 173 added test lines (`tasks.test.tsx`) and 26 added and 10 deleted lines in `tasks.tsx`; the 199 matches the total added, so the description's split is inconsistent with its files.

## Upgrade and rollback

Re-run `install.sh` once v2.13.150 is published. There is no schema change. Rolling back to v2.13.149 restores the fixed-interval refresh; nothing is stored.

### 行为变化与入口

- **轮询（#708）：**`tasks.tsx` 不再按固定 3 秒间隔刷新，而是在上一次请求结束（成功或失败）3 秒后再次轮询，请求不再重叠。过滤条件变化或页面卸载时清除定时器。
- **慢响应（#708）：**刷新响应只要页面未离开其过滤、且没有更新的刷新已被应用就会生效。仍在进行的更新请求不再让可用的旧响应被饿死。
- **Show more（#708）：**页面同步记录游标（`next_before`）。Show more 响应仅在其过滤仍是当前、且请求时的游标仍是当前游标时才被应用，否则连同错误一起丢弃。若轮询保持游标不变，则接受旧页、去重，并在之后的轮询中保留。
- **测试（#708）：**新增 `tasks.test.tsx`，覆盖慢的初始与刷新响应、慢失败后的重试、两种顺序的重叠手动刷新、轮询改变游标时挂起的旧页，以及过滤切换后（含切回）的迟到响应。
- **面向模型的变化：**无。没有工具、提示词、schema 或声明变化。
- **行数：**描述报告新增测试 0 行、生产代码 199 行，目标为 60–160 行改动。其文件列表显示 `tasks.test.tsx` 新增 173 行，`tasks.tsx` 新增 26 行、删除 10 行；199 实为总新增行数，描述中的拆分与文件列表不一致。
