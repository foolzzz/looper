# Looper v2.14.149

This is the patch release v2.14.149, a hotfix line in which each merged change ships at once. It documents one change: [#1270](https://github.com/foolzzz/looper/pull/1270) (Lark rich-text posts reach the Manager as text; other message types are answered).

## Release Decision

**Who should upgrade:** Operators who connect Looper to Lark (the `lark` channel through lark-cli, or the `lark_bot` channel) and whose users send rich-text posts, images, files or other non-text messages. Everyone else gets no visible change.

**What this release solves:** [#1270](https://github.com/foolzzz/looper/pull/1270) hands an admitted sender's rich-text post to the Manager as text instead of ignoring it, and answers other message types with one short reply instead of silence.

**Breaking changes:** No. There is no migration and no API removal. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.149
```

**Contributors:** Maintainer @foolzzz authored [#1270](https://github.com/foolzzz/looper/pull/1270); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.148 upgrades directly. There is no schema change.

## Behavior changes

- **Rich-text posts reach the Manager** ([#1270](https://github.com/foolzzz/looper/pull/1270), `looper/agents/channels/lark.py`, `looper/agents/channels/lark_content.py`, `docs/architecture/agent-system.md`, `docs/design.md`). A `post` from an admitted sender, in a direct message or as a group @-mention of the bot, is now published to the Manager; before, any message type other than `text` was dropped. The text is lark-cli's rendering: title, paragraphs, `[text](url)` links and fenced code, other mentions as `@name`, and the bot's own mention removed (`@name`, `@@name`, its placeholder key or an `<at>` tag). The adapter's former plain-text mention removal moved to `lark_content.py` unchanged for `text` messages.
- **Images and files in posts.** Inline images and attached files become numbered `[image N]` and `[file N: name]` placeholders; videos, voice messages and folders become `[video: not supported yet]`, `[voice message: not supported yet]` and `[folder: not supported yet]`. When a post has an image or file, the text ends with one line: "(Looper cannot receive images or files yet: <placeholders> not received.)" The resources themselves are not downloaded.
- **Other message types are answered.** After admission and routing, an admitted sender's message of any type other than `text` or `post` (image, file, audio, media, sticker, share_chat, share_user, location, merge_forward, folder, an unknown type) gets one reply, 「暂不支持这类飞书消息（<type>），请发文字或富文本。」: a reply to the message in a group (only messages that @-mention the bot get this far), a message in a direct chat. It adds no reaction and starts no Manager turn. A failed send is logged. A silent chat gets nothing, and a chat whose Manager is turned off gets only the usual turned-off reply. Before, these were silent.
- **`lark_bot` flat event** (`looper/agents/channels/lark_stream.py`). The bot-token channel renders non-text content into lark-cli's notation (`[Image: key]`, `<file key=... name=.../>`, rich-text markdown, `[Sticker]`, `[<type>]` for other types) instead of the message's raw JSON, so the shared adapter reads both channels alike. It drops `interactive` cards at the stream. Only the adapter reads this field.
- **Unchanged:** bots' messages, unlisted senders, group messages that do not @-mention the bot, empty messages, and `text` handling. The `interactive` filter is in the `lark_bot` stream only; this draft found no equivalent filter in the lark-cli adapter, where a type other than `text` or `post` takes the reply path above.
- **Model-visible changes:** Yes. A post's rendered text, with the trailing "Looper cannot receive images or files yet" line when it has images or files, now reaches the Manager as the user's message; before, such messages never reached a model. Nothing else sent to a model changes. The unsupported-type reply goes to the user, not to a model.

## 中文摘要

本版本是 patch release v2.14.149（热修线，每个合并的改动立即发布），说明一项改动：[#1270](https://github.com/foolzzz/looper/pull/1270)（飞书富文本消息作为文本交给 Manager，其他消息类型会得到回复）。

### 升级决策

**谁需要升级：**接入飞书（经 lark-cli 的 `lark` 通道或 `lark_bot` 通道）且用户会发送富文本、图片、文件或其他非文字消息的运维者。其他人没有可见变化。

**解决了什么：**[#1270](https://github.com/foolzzz/looper/pull/1270) 把已准入发送者的富文本 `post` 作为文本交给 Manager，而不是忽略；其他消息类型得到一条简短回复，而不是沉默。

**是否有破坏性变更：**否。没有迁移，没有移除 API。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

**如何验证：**核对版本为 2.14.149。

**贡献者：**维护者 @foolzzz 提交 [#1270](https://github.com/foolzzz/looper/pull/1270)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.149
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.148 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **富文本交给 Manager**（[#1270](https://github.com/foolzzz/looper/pull/1270)，`looper/agents/channels/lark.py`、`looper/agents/channels/lark_content.py`、`docs/architecture/agent-system.md`、`docs/design.md`）。已准入发送者的 `post`，在私聊或群里 @ 机器人时，现在发布给 Manager；此前 `text` 以外的类型都被丢弃。文本为 lark-cli 的渲染：标题、段落、`[文字](链接)` 和围栏代码，其他提及显示为 `@名字`，移除机器人自己的提及（`@名字`、`@@名字`、占位 key 或 `<at>` 标签）。原有的纯文本提及移除逻辑原样移到 `lark_content.py`，用于 `text` 消息。
- **富文本里的图片和文件。**内联图片和附件变为编号的 `[image N]`、`[file N: 名称]`；视频、语音和文件夹变为 `[video: not supported yet]`、`[voice message: not supported yet]`、`[folder: not supported yet]`。含图片或文件时，文本末尾加一行 “(Looper cannot receive images or files yet: <占位符> not received.)”。资源本身不会下载。
- **其他类型会得到回复。**在准入和路由之后，已准入发送者发来的 `text`、`post` 以外的任何类型（图片、文件、音频、媒体、表情包、share_chat、share_user、location、merge_forward、folder 及未知类型）得到一条回复「暂不支持这类飞书消息（<type>），请发文字或富文本。」：群里回复原消息（只有 @ 机器人的消息才会走到这里），私聊直接发送。不加表情，不启动 Manager 回合。发送失败会记日志。静默的聊天什么都不发，Manager 关闭的聊天只收到既有的关闭回复。此前这些消息无任何反应。
- **`lark_bot` 扁平事件**（`looper/agents/channels/lark_stream.py`）。机器人令牌通道把非文本内容渲染成 lark-cli 的格式（`[Image: key]`、`<file key=... name=.../>`、富文本 markdown、`[Sticker]`，其他类型为 `[<type>]`），而不是消息的原始 JSON，使共享适配器对两个通道一视同仁；在事件流处丢弃 `interactive` 卡片。只有适配器读取这个字段。
- **不变：**机器人的消息、未列入白名单的发送者、未 @ 机器人的群消息、空消息和 `text` 的处理。`interactive` 过滤只在 `lark_bot` 事件流中；本草稿在 lark-cli 适配器里没有找到对应过滤，其中 `text`、`post` 以外的类型走上面的回复路径。
- **面向模型的变化：**有。富文本渲染后的文本（含图片或文件时末尾带 “Looper cannot receive images or files yet” 一行）现在作为用户消息到达 Manager；此前这类消息从未到达模型。发给模型的其他内容不变。不支持类型的回复发给用户，不发给模型。
