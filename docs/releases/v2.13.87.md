# Looper v2.13.87

## Release Decision

**Who should upgrade:** Anyone who calls `/api/models` from a script or who adds, edits or deletes saved models in the dashboard Settings. Everyone else gets no change.

**What this release solves:** [#537](https://github.com/foolzzz/looper/pull/537) moves the dashboard's model management onto the versioned API, adds a lookup for one saved model and removes the five legacy model routes.

**Breaking changes:** Yes. `GET /api/models`, `POST /api/models`, `GET /api/models/{id}`, `PUT /api/models/{id}` and `DELETE /api/models/{id}` are removed; a script that calls them must use `POST /api/v1/ops/models/list`, `/api/v1/ops/models/create`, `/api/v1/ops/models/update` and `/api/v1/ops/models/delete`, or `POST /api/v1/models/get` for one model. The provider of a new model is passed as `provider` (not `provider_id`), the model of an update or delete as `model`, and responses are wrapped in the v1 envelope (`result`). The dashboard shipped in this release already uses the new operations.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#537](https://github.com/foolzzz/looper/pull/537); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.87
```

## Behavior changes

- **Lookup ([#537](https://github.com/foolzzz/looper/pull/537)):** the new `looper/agents/v1_domains/models.py` registers `models.get` (risk `read`) as `POST /api/v1/models/get` with the closed argument `{model}`. It returns `{model, warnings}`, with `warnings` an empty list when there are none.
- **Typed results:** `models.list` (`{models}`), `models.create` and `models.update` (`{model, warnings}`) and `models.delete` (`{deleted}`) now have closed result schemas in the OpenAPI document. The operations themselves already existed.
- **Removed routes:** the five legacy routes and the `_RE_MODEL` URL pattern are removed from `looper/agents/http_server.py`.
- **Dashboard:** `web/src/lib/api.ts` calls the v1 operations for create, update and delete. Numeric fields typed as text (context window and the four per-million-token prices) are converted to numbers before sending, a pending-confirmation (HTTP 202) answer is raised as an `unavailable` error, and the registry-changed event fires after each success.
- **Tooling:** the prompt regression evals (`evals/prompt_regression/dialogs.py`, `runner.py`) and `examples/pi/isolated-smoke.py` create models through `/api/v1/ops/models/create`.
- **Tests:** `tests/test_api_v1_models.py` and `tests/test_api_v1_models_db.py` were added and `web/src/components/model-settings.test.tsx` was extended; many existing tests were moved to the new operations.
- **Model-visible changes:** None found. Manager, Planner, Worker and Reviewer prompts, role recommended prompts and Tool declarations are unchanged. `models.get` declares no Tool; it appears in the v1 operation catalog that API clients read.
- **Not confirmed in code:** whether prose docs other than this release still name the removed routes. This draft did not run any test.

## Upgrade and rollback

Re-run `install.sh` once v2.13.87 is published. No data migration; saved models are untouched. Update any script that used the removed routes. Rolling back to v2.13.86 restores them together with the old dashboard.

## 中文摘要

### 升级决策

**谁需要升级：**在脚本中调用 `/api/models` 的人，或在仪表盘设置中添加、编辑、删除已保存模型的人。其他人无变化。

**解决了什么：**[#537](https://github.com/foolzzz/looper/pull/537) 把仪表盘的模型管理迁到版本化 API，新增单个已保存模型的查询，并删除五条旧的模型路由。

**是否有破坏性变更：**有。`GET /api/models`、`POST /api/models`、`GET /api/models/{id}`、`PUT /api/models/{id}` 与 `DELETE /api/models/{id}` 已移除；调用它们的脚本须改用 `POST /api/v1/ops/models/list`、`/api/v1/ops/models/create`、`/api/v1/ops/models/update`、`/api/v1/ops/models/delete`，读取单个模型用 `POST /api/v1/models/get`。新建模型的提供方参数由 `provider_id` 改为 `provider`，更新与删除用 `model` 指定模型，响应包在 v1 信封（`result`）里。本版本附带的仪表盘已改用新操作。

**如何验证：**运行 `looper --version` 核对版本为 2.13.87。

**贡献者：**维护者 @foolzzz 提交 [#537](https://github.com/foolzzz/looper/pull/537)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.87
```

### 行为变化与入口

- **查询（[#537](https://github.com/foolzzz/looper/pull/537)）：**新增 `looper/agents/v1_domains/models.py`，注册 `models.get`（风险 `read`），路径 `POST /api/v1/models/get`，参数为封闭对象 `{model}`。返回 `{model, warnings}`，没有警告时 `warnings` 为空列表。
- **类型化结果：**`models.list`（`{models}`）、`models.create` 与 `models.update`（`{model, warnings}`）、`models.delete`（`{deleted}`）现在在 OpenAPI 文档中有封闭的结果 schema。这些操作本身已存在。
- **移除的路由：**五条旧路由和 `_RE_MODEL` URL 正则已从 `looper/agents/http_server.py` 移除。
- **仪表盘：**`web/src/lib/api.ts` 用 v1 操作完成创建、更新和删除。以文本形式输入的数值字段（上下文窗口和四个每百万 token 价格）发送前转为数字；待确认（HTTP 202）的应答会作为 `unavailable` 错误抛出；成功后触发注册表变更事件。
- **工具：**提示回归评测（`evals/prompt_regression/dialogs.py`、`runner.py`）和 `examples/pi/isolated-smoke.py` 通过 `/api/v1/ops/models/create` 创建模型。
- **测试：**新增 `tests/test_api_v1_models.py` 与 `tests/test_api_v1_models_db.py`，扩充 `web/src/components/model-settings.test.tsx`；许多现有测试已改用新操作。
- **面向模型的变化：**未发现。Manager、Planner、Worker、Reviewer 的 prompt、角色推荐 prompt 以及 Tool 声明均未改动；`models.get` 未声明 Tool，只出现在 API 客户端读取的 v1 操作目录中。
- **代码中未确认：**本版本说明之外的散文文档是否仍写着已移除的路由。本草稿未运行任何测试。

### 升级与回退

v2.13.87 发布后重跑 `install.sh`。无需迁移数据，已保存的模型不受影响。使用已移除路由的脚本需要更新。回退到 v2.13.86 会连同旧仪表盘一起恢复这些路由。
