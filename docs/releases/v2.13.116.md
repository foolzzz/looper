# Looper v2.13.116

## Release Decision

**Who should upgrade:** Anyone who stops or cancels running agent turns or a resident Claude and needs their child processes gone afterwards. Others do not need it.

**What this release solves:** [#620](https://github.com/foolzzz/looper/pull/620) makes ending a process tree wait for SIGKILLed descendants to exit, keeps a cancelled stop or refresh from leaving processes behind or excluded, and stabilises the per-turn stop test of the process tree.

**Breaking changes:** No. No route, configuration, request field or stored data format changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#620](https://github.com/foolzzz/looper/pull/620); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.116
```

## Behavior changes

- **Wait after SIGKILL:** in `looper/agents/proc_tree.py`, after sending SIGKILL, ending a tree polls the process table for up to `REAP_SEC` (2 s) until the processes it signalled (same pid and group) are gone. It does not expand the tree or signal again. If some remain, it logs a warning listing their pids and goes on.
- **Cancelled tree end:** the three parts of a tree end (agent, strays, agent end) now run as tasks, and on cancellation the call waits for all of them to finish their own cleanup before the cancellation propagates.
- **Cancelled refresh:** `TurnTree.refresh` now looks up start times for the observed and already seen pids before it publishes anything, then records the new pids and their identities together. A refresh cancelled at a lookup no longer leaves new pids permanently excluded as unknown.
- **Resident Claude stop:** in `looper/agents/claude_cli.py`, `stop` no longer shields its callers. A cancelled caller sets the hurry signal of the pending cleanups (skipping the stdin-close grace), waits until they are done and then re-raises the cancellation; otherwise it re-raises a cleanup's error. `kill=True` still hurries the pending cleanups; the cleanup reads that signal instead of a `kill` argument, which `_stop_process` no longer takes.
- **Model-visible changes:** none. No tool declaration, prompt, route or text sent to Workers changed.
- **Tests:** new process-tree tests cover waiting for killed descendants after the agent is reaped, a hurried resident stop waiting for its tree, and a cancelled refresh keeping new descendants; a comment in a Planner test explains why it cancels after cleanup has started. [#620](https://github.com/foolzzz/looper/pull/620) reports added lines: tests 124, production 35 (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.116 is published. No data migration and no configuration change. Rolling back to v2.13.115 restores the old stop behavior, where descendants killed by SIGKILL are not waited for.

### 行为变化与入口

- **SIGKILL 后等待：**`looper/agents/proc_tree.py` 中，发送 SIGKILL 后，结束进程树会轮询进程表，最多等待 `REAP_SEC`（2 秒），直到已发信号的进程（pid 与进程组均匹配）消失。不会扩展进程树，也不会再次发信号。若仍有残留，记录列出其 pid 的警告后继续。
- **取消的进程树结束：**进程树结束的三个部分（agent、游离进程、agent 结束）现在作为任务运行；被取消时，调用会等它们各自完成清理后再传播取消。
- **取消的刷新：**`TurnTree.refresh` 现在先查询已观察和已见 pid 的启动时间，再统一发布新 pid 及其身份。在查询处被取消的刷新不再让新 pid 永久被当作未知而排除。
- **常驻 Claude 停止：**`looper/agents/claude_cli.py` 中，`stop` 不再对调用方做 shield。被取消的调用方会触发待处理清理的加速信号（跳过 stdin 关闭宽限），等它们结束后再重新抛出取消；否则重新抛出清理中的错误。`kill=True` 仍会加速待处理的清理；清理读取该信号，`_stop_process` 不再接收 `kill` 参数。
- **面向模型的变化：**无。tool 声明、提示词、路由和发给 Worker 的文本均未改变。
- **测试：**新增进程树测试，覆盖 agent 被回收后等待被杀后代、加速的常驻停止等待其进程树、以及取消的刷新保留新后代；一个 Planner 测试加了注释说明为何在清理开始后才取消。[#620](https://github.com/foolzzz/looper/pull/620) 报告新增行数：测试 124、生产代码 35（不含夹具）。
