# Looper v2.14.178

This is the patch release v2.14.178, a hotfix line in which each merged change ships at once. It documents one change: [#1329](https://github.com/foolzzz/looper/pull/1329) (the Manager can view the local gateway and change it with confirmation).

## Release Decision

**Who should upgrade:** Anyone who manages the local LLM gateway (enablement, port, model aliases) through the Manager in the dashboard, Lark or Telegram, and anyone whose Manager prompt or tool-schema tooling reads the `looper_settings` tool.

**What this release solves:** [#1329](https://github.com/foolzzz/looper/pull/1329) (fixes #1163) lets the Manager read the local gateway's configuration and change it, with the user confirming every write. Gateway keys stay dashboard-only.

**Breaking changes:** No. The `looper_settings` tool gains an action and a view field, and the global settings view result gains a required `gateway` field, so a strict client of that result sees one more key. There is no database change, and the bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.178
```

**Contributors:** Maintainer @foolzzz authored [#1329](https://github.com/foolzzz/looper/pull/1329); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.177 upgrades directly. There is no database change.

## Behavior changes

Read in the diff of [#1329](https://github.com/foolzzz/looper/pull/1329). The PR calls the first item a maintainer decision and intended behavior change:

- **The Manager reads the gateway** (`looper/agents/ops/settings.py`). The global `looper_settings` `view` (no project) now includes `gateway` with `enabled`, `port` and `aliases`. It carries no key, URL, client environment or proxy fields. Without a runtime root the view still answers and reports no key.
- **The Manager changes the gateway after confirmation.** `looper_settings` has a new `gateway` action. One call sets `enabled` and/or `port`, or one `alias_set` (`alias`, `model_id`), or one `alias_delete`; any other mix is refused. Every change first shows a confirmation with the before → after values (for an alias, the current binding or "未设置" → the new model or "未设置") and waits for the user. A changed port keeps the current `enabled` value when none is given. Before asking, the call validates the change, including that an alias target is an `openai-chat` model on an enabled API-key provider with a saved key; `alias_set` checks the target again atomically when it is written.
- **Keys stay out of the Manager** (`looper/agents/v1_domains/gateway.py`). Key reveal and rotation remain dashboard/API-only; the tool offers no key operation, and the Manager receives neither keys nor client environment commands.
- **Shared write path.** The gateway API's update, alias set and alias delete now use `check_change` and `apply_change`, shared with the Manager's confirmed writes (`looper/db/gateway.py` gains `check_binding`, a read-only preflight). The docs state that the generated `loopercli settings gateway` command uses the same action, with confirmation for API clients and the existing direct-write behavior for authenticated operators; I did not run that command for this draft.
- **Result schemas** (`looper/agents/v1_domains/settings_pages.py`). A new `settings.gateway` result and a `gateway` member of `settings.view`.
- **Worker start fix** (`looper/agents/runtimes/channel.py`). Not described in the PR body; it came with the merged "Fix the CI failure" commit. If a runtime has closed stdin before the first prompt, `start()` raises `BrokenPipeError`, and a new test checks that a model event before prompt delivery never triggers a profile fallback.
- **Dialog evals and documentation.** A `gateway_settings` Manager dialog is added (the dialog total goes from 61 to 62 in `evals/README.md`); `docs/architecture/agent-system.md` describes the gateway workflow; `docs/validation/manager-gateway-settings.md` records the PR's validation.
- **Model-visible changes:** Yes. The `looper_settings` tool description and input schema change: the `action` enum gains `gateway`, a `gateway` object argument is added (`enabled`, `port`, `alias_set`, `alias_delete`), and the description says `view` includes the gateway and that key operations are dashboard-only. Its result for the global `view` gains `gateway`. The confirmation text the user sees is new. `channel_context` and the Telegram and Lark message formats are unchanged; the Manager can now be asked about the gateway from either channel.

**是否有破坏性变更：**无。`looper_settings` 工具新增一个 action 和一个视图字段，全局设置视图结果新增必填字段 `gateway`，严格校验该结果的客户端会多看到一个键。没有数据库变更，桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.177 上的安装可直接升级。没有数据库变更。

### 行为变化与入口

以下在 [#1329](https://github.com/foolzzz/looper/pull/1329) 的差异中可见。PR 称第一项是维护者的决定，属有意的行为变化：

- **Manager 读取网关**（`looper/agents/ops/settings.py`）。全局 `looper_settings` 的 `view`（不带项目）现在包含 `gateway`，有 `enabled`、`port` 和 `aliases`，不含密钥、URL、客户端环境或代理字段。没有运行时根目录时视图仍可返回，并显示没有密钥。
- **Manager 在确认后修改网关。**`looper_settings` 新增 `gateway` action。一次调用可设置 `enabled` 和/或 `port`，或一个 `alias_set`（`alias`、`model_id`），或一个 `alias_delete`；其他组合会被拒绝。每次修改先显示修改前 → 修改后的确认（alias 显示当前绑定或「未设置」→ 新模型或「未设置」）并等待用户。只改端口时沿用当前的 `enabled`。请求确认前会先校验，包括 alias 目标必须是已启用 API-key 提供商下、已保存密钥的 `openai-chat` 模型；`alias_set` 写入时再原子地检查一次目标。
- **密钥不进入 Manager**（`looper/agents/v1_domains/gateway.py`）。密钥的查看和轮换仍只在仪表盘/API；工具没有任何密钥操作，Manager 也拿不到密钥或客户端环境命令。
- **共享写入路径。**网关 API 的 update、alias set、alias delete 现在使用与 Manager 确认写入共用的 `check_change` 和 `apply_change`（`looper/db/gateway.py` 新增只读预检 `check_binding`）。文档称生成的 `loopercli settings gateway` 命令使用同一 action：API 客户端需确认，已认证的操作员保持现有的直接写入行为；本次草稿未运行该命令。
- **结果 schema**（`looper/agents/v1_domains/settings_pages.py`）。新增 `settings.gateway` 结果，以及 `settings.view` 的 `gateway` 成员。
- **Worker 启动修复**（`looper/agents/runtimes/channel.py`）。PR 描述未提及，来自合并的 "Fix the CI failure" 提交。若运行时在首个提示词前已关闭 stdin，`start()` 抛出 `BrokenPipeError`；新增测试确认首个提示词送达前出现的模型事件不会触发 profile 回退。
- **对话评测与文档。**新增 `gateway_settings` Manager 对话（`evals/README.md` 中对话总数由 61 变为 62）；`docs/architecture/agent-system.md` 描述网关流程；`docs/validation/manager-gateway-settings.md` 记录 PR 的验证。
- **面向模型的变化：**有。`looper_settings` 工具的描述和输入 schema 改变：`action` 枚举新增 `gateway`，新增 `gateway` 对象参数（`enabled`、`port`、`alias_set`、`alias_delete`），描述说明 `view` 包含网关、密钥操作仅限仪表盘；全局 `view` 的结果新增 `gateway`；用户看到的确认文本是新的。`channel_context` 以及 Telegram、Lark 的消息格式不变；现在可在这两个渠道向 Manager 询问网关。
