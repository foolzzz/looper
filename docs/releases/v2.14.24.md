# Looper v2.14.24

This is the patch release v2.14.24. It ships the one change merged since v2.14.23: [#924](https://github.com/foolzzz/looper/pull/924), which updates two installed test fixtures. It changes no runtime code.

## Release Decision

**Who should upgrade:** Nobody needs this release for runtime behavior. It matters to maintainers and packagers who run the nightly installed tests (`tests/test_pi_smoke.py`, `tests/test_pi_platform_tools.py`). It ships the one change merged since v2.14.23.

**What this release solves:** [#924](https://github.com/foolzzz/looper/pull/924): two installed tests failed on main because their fixtures predated intended changes. The installed Pi smoke assumed the Pi CLI, but the runner is now the default ([#899](https://github.com/foolzzz/looper/pull/899)); the smoke now pins `[runtimes] pi = "cli"`. The `platform` fixture of `tests/test_pi_platform_tools.py` did not stub the two storage calls the project delete cascade ([#905](https://github.com/foolzzz/looper/pull/905)) makes; it now stubs `schedules.list_schedules` and `tasks.project_tasks`.

**Breaking changes:** No. No database schema, stored data, API or default changes. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#924](https://github.com/foolzzz/looper/pull/924); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.24
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.23 upgrades directly. This release changes no database schema or stored data.

## Behavior changes

- **None at runtime.** The pull request touches only `examples/pi/isolated-smoke.py` (5 added, 2 removed lines) and `tests/test_pi_platform_tools.py` (3 added, 1 removed line); no file under `looper/` changes.
- **Installed Pi smoke pins the CLI path** (`examples/pi/isolated-smoke.py`): the smoke's `server.toml` now carries `[runtimes]` with `pi = "cli"`, and its docstring states that the smoke covers the Pi CLI opt-out, whose evidence (`.local/mcp` grant files, `mcp__looper__` names, `.local/agent-processes`) exists only on the CLI path. Installed coverage of the runner default is a separate change.
- **Delete-cascade stubs** (`tests/test_pi_platform_tools.py`): the `platform` fixture imports `schedules` and stubs `schedules.list_schedules` and `tasks.project_tasks` to return empty lists.
- **Model-visible changes:** None. No prompt, tool, schema or message changes.
