# Looper v2.13.139

## Release Decision

**Who should upgrade:** Nobody needs to for behavior. This patch adds an internal codec that nothing in Looper calls yet; everyone can stay on v2.13.138. Upgrade only to follow the API runtime work.

**What this release solves:** [#677](https://github.com/foolzzz/looper/pull/677) adds the OpenAI Responses codec, the first protocol codec for the API runtime loop, and a scripted local model server for its tests. It is groundwork: no Manager, session or entry point uses it in this release.

**Breaking changes:** No. Nothing calls the new codec, and no existing format, command or API changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#677](https://github.com/foolzzz/looper/pull/677); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.139
```

## Behavior changes

- **Codec (#677):** the new `looper/agents/runtimes/api/responses.py` defines `ResponsesCodec` for the `openai-responses` protocol.
  - Transport: the official async OpenAI SDK over `httpx2`, which does not read proxy environment variables. The API key and base URL are passed explicitly, and the key is registered with the log redaction.
  - Request: the full neutral history is sent every time (`store=false`, `parallel_tool_calls=false`, `prompt_cache_key` set to the session id, `max_output_tokens`, the system prompt as `instructions`, tools as non-strict `function` tools with their schemas). When an effort is set, `reasoning.effort` is sent and `reasoning.encrypted_content` is requested.
  - Reasoning replay: a reasoning item is replayed only when its stored state came from the same protocol and model; otherwise it is left out of the request, and the stored history is kept.
  - Response: output is tracked by output index and item id, and the ordered `output` of `response.completed` decides the final messages, tool calls and reasoning summary. A `response.failed`, a `response.incomplete`, a stream that ends without a terminal event, or an inconsistent event raises a typed error, and no tool runs. Unknown event types are ignored and logged once per request, as names only (at most 8, no payloads).
  - Errors: HTTP 401 and 403 map to auth, 404 to not found, 429 to rate limited, 408 and 5xx to unavailable; otherwise the error code or type maps to context overflow, not found, rate limited, unavailable, auth or invalid request. `response.incomplete` maps to truncated and an invalid stream to protocol.
  - Usage: uncached, output, cache-read and cache-write tokens per request; a value that does not add up is recorded as incomplete.
  - Timeouts and retries: connect 10 s, idle 120 s between chunks, 600 s for a whole request, counted as an absolute deadline over SDK retries and reads. The SDK retries up to 2 times on status; a provider's `x-should-retry` header is removed. The number of retries is counted from the actual HTTP attempts.
  - Lifecycle: the client is created on first use, shared by repeated turns, and closing it can be repeated.
- **Loop (#677):** `loop_for` in `looper/agents/runtimes/api/loop.py` returns `NormaAgentLoop(ResponsesCodec())` for `openai-responses`, importing the codec lazily. Other protocols still raise `RuntimeUnsupported`. Nothing else in `looper/` calls `loop_for`, and the API runtime adapter is unchanged, so this is not reachable from a running Looper.
- **Docs and notices (#677):** `THIRD_PARTY_NOTICES.txt` lists `responses.py` as derived from Norma and names the extra source modules; the API runtime RFC and the long-horizon plan (both Chinese) record the codec as step 2b.
- **Tests (#677):** `tests/fake_model_api.py` is a scripted local HTTP/SSE server; `tests/test_api_responses.py` exercises the real SDK against it; `tests/test_api_loop.py` now checks that every protocol other than the test one is refused.
- **Runtime behavior:** none visible. No change to running Managers, tasks, the database, the API, the command line or the dashboard.
- **Model-visible changes:** none to Looper's existing prompts, tool declarations or tool results. The codec would send a system prompt, tool schemas and history to a provider only once something calls it; no caller exists in this release.
- **Line counts:** the description reports tests 509 and production 354 added lines (fixtures excluded).

### 行为变化与入口

- **编解码器（#677）：**新增 `looper/agents/runtimes/api/responses.py`，为 `openai-responses` 协议定义 `ResponsesCodec`。
  - 传输：官方异步 OpenAI SDK，经 `httpx2`，不读取代理环境变量。API key 与 base URL 显式传入，key 登记到日志脱敏。
  - 请求：每次发送完整的中性历史（`store=false`、`parallel_tool_calls=false`、`prompt_cache_key` 为会话 id、`max_output_tokens`、系统提示词作为 `instructions`、工具为非 strict 的 `function` 工具及其 schema）。设置了 effort 时发送 `reasoning.effort` 并请求 `reasoning.encrypted_content`。
  - 推理重放：仅当保存的状态来自相同协议和模型时才重放推理条目，否则不放入请求，保存的历史不变。
  - 响应：按输出索引与条目 id 跟踪，以 `response.completed` 的有序 `output` 决定最终消息、工具调用与推理摘要。`response.failed`、`response.incomplete`、无终态的断流或不一致的事件会抛出类型化错误，且不执行任何工具。未知事件类型被忽略，每个请求只记一条仅含名称的日志（最多 8 个，不含载荷）。
  - 错误：HTTP 401、403 归为认证，404 未找到，429 限流，408 与 5xx 不可用；其余按错误 code 或 type 归为上下文溢出、未找到、限流、不可用、认证或无效请求。`response.incomplete` 归为截断，非法流归为协议错误。
  - 用量：每次请求的未缓存、输出、缓存读与缓存写 token；数值对不上时记为不完整。
  - 超时与重试：连接 10 秒，数据块间空闲 120 秒，单次请求 600 秒（对 SDK 重试与读流计绝对截止时间）。SDK 按状态最多重试 2 次，并移除 provider 的 `x-should-retry` 头。重试次数按实际 HTTP 尝试计数。
  - 生命周期：客户端首次使用时创建，重复轮次共用，关闭可重复执行。
- **循环（#677）：**`looper/agents/runtimes/api/loop.py` 中的 `loop_for` 对 `openai-responses` 懒加载并返回 `NormaAgentLoop(ResponsesCodec())`，其他协议仍抛 `RuntimeUnsupported`。`looper/` 中没有其他地方调用 `loop_for`，API 运行时适配器未改，因此运行中的 Looper 无法触达。
- **文档与声明（#677）：**`THIRD_PARTY_NOTICES.txt` 将 `responses.py` 列为 Norma 派生并补充来源模块；API 运行时 RFC 与长程计划（均为中文）将该编解码器记为步骤 2b。
- **测试（#677）：**`tests/fake_model_api.py` 是脚本化本地 HTTP/SSE 服务；`tests/test_api_responses.py` 用真实 SDK 对其测试；`tests/test_api_loop.py` 现检查除测试协议外的所有协议都被拒绝。
- **运行时行为：**无可见变化。运行中的 Manager、任务、数据库、API、命令行与仪表盘均无变化。
- **面向模型的变化：**Looper 现有的提示词、tool 声明和 tool 结果均无变化。只有当有调用方使用该编解码器时，才会向 provider 发送系统提示词、工具 schema 与历史；本版本没有调用方。
- **行数：**描述报告新增测试 509 行、生产代码 354 行（不含 fixtures）。
