# Looper v2.14.143

This is the patch release v2.14.143, a hotfix line in which each merged change ships at once. It documents one change: [#1252](https://github.com/foolzzz/looper/pull/1252) (the adjudication repair message names the adjudicated accept when it was offered).

## Release Decision

**Who should upgrade:** Operators who run the Planner with review adjudication on, because a refused accept reply now gets a repair message that lists the adjudicated accept and names the blocking findings. Everyone else gets no visible change.

**What this release solves:** [#1252](https://github.com/foolzzz/looper/pull/1252) makes the repair message, sent when a Planner reply to a decision turn that offered the adjudicated accept is refused, list that accept among the allowed decisions and name the findings still blocking, so the Planner can repair the reply in one turn.

**Breaking changes:** No. There is no migration and no API removal. The pull request calls the change intended (a maintainer decision). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.143
```

**Contributors:** Maintainer @foolzzz authored [#1252](https://github.com/foolzzz/looper/pull/1252); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.142 upgrades directly. There is no schema change.

## Behavior changes

- **The repair message names the adjudicated accept** ([#1252](https://github.com/foolzzz/looper/pull/1252), `looper/agents/tiers/planner.py`, `looper/agents/tiers/planner_protocol.py`). When the decision turn offered the adjudicated accept (adjudication on, a review that failed, and downgrades could let it pass) and the reply is refused, the refusal lists the adjudicated accept first among the allowed decisions. For a refused plain accept it also says the step still has blocking findings, names them as `<member> finding <n>` (those still blocking after any downgrades the reply proposed) and asks for downgrades to suggestion with a reason each in `adjudications`. Without the offer, the refusal text is unchanged.
- **The allowed-decisions list separates entries unambiguously** (`looper/agents/tiers/planner.py`). When the adjudicated accept is offered, the entries of "Allowed decisions now" are separated by `; ` because the adjudicated accept contains a comma; otherwise they stay comma separated.
- **The adjudication rules appear once** (`looper/agents/tiers/planner.py`). The decision message no longer appends the adjudication rules; the reply contract carries them, once.
- **Prompt eval** (`evals/prompt_regression/tasks.py`). The `panel_adjudicate` flow check accepts a repaired accept after a refused one and reports a missing offer only when no turn accepted correctly.
- **Unchanged:** the storage format of runs and journal entries, what the adjudication accepts, and the Worker, Reviewer and Manager prompts.
- **Model-visible changes:** Yes. The Planner's decision message changes as above: the allowed-decisions separator, the adjudication rules no longer repeated in it, and the refusal text that repairs a refused accept. The pull request states that the real-mode prompt eval runs before merge.

### 升级决策

**谁需要升级：**开启评审裁决的 Planner 运维者，因为被拒绝的 accept 回复现在会收到列出裁决式 accept 并点明仍阻塞的发现的修复消息。其他人没有可见变化。

**解决了什么：**[#1252](https://github.com/foolzzz/looper/pull/1252) 让决策回合提供了裁决式 accept、而 Planner 回复被拒绝时发送的修复消息，在允许的决策中列出该 accept 并点明仍阻塞的发现，使 Planner 能在一个回合内修复回复。

**是否有破坏性变更：**否。没有迁移，没有移除 API。PR 称该改动是维护者的有意决定。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

```bash
looper --version   # looper 2.14.143
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.142 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **修复消息点明裁决式 accept**（[#1252](https://github.com/foolzzz/looper/pull/1252)，`looper/agents/tiers/planner.py`、`looper/agents/tiers/planner_protocol.py`）。决策回合提供了裁决式 accept（已开启裁决、评审未通过、降级后可通过）而回复被拒绝时，拒绝信息把裁决式 accept 列在允许的决策之首。对被拒绝的普通 accept，还会说明该步骤仍有阻塞发现，以 `<member> finding <n>` 点明它们（即回复提出的降级之后仍阻塞的发现），并要求在 `adjudications` 中给出降级为 suggestion 且各附理由。未提供该 accept 时，拒绝文本不变。
- **允许的决策列表分隔明确**（`looper/agents/tiers/planner.py`）。提供裁决式 accept 时，“Allowed decisions now”的各项以 `; ` 分隔（因为裁决式 accept 自带逗号），否则仍以逗号分隔。
- **裁决规则只出现一次**（`looper/agents/tiers/planner.py`）。决策消息不再追加裁决规则，由回复契约只写一次。
- **提示词评测**（`evals/prompt_regression/tasks.py`）。`panel_adjudicate` 的流程检查接受被拒后修复的 accept，仅在没有任何回合正确 accept 时才报告缺少提供。
- **不变：**运行与日志条目的存储格式、裁决接受的条件，以及 Worker、Reviewer 和 Manager 提示词。
- **面向模型的变化：**有。Planner 的决策消息按上述方式变化：允许决策的分隔符、不再重复裁决规则，以及修复被拒 accept 的拒绝文本。PR 称合并前会运行真实模式提示词评测。
