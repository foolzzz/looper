# Looper v2.13.126

## Release Decision

**Who should upgrade:** Nobody needs to upgrade for a visible feature. This patch release makes the stored history of Telegram and Lark conversations check which Manager owns the conversation, and it changes what a Manager does when it cannot store a turn.

**What this release solves:** [#645](https://github.com/foolzzz/looper/pull/645) preserves the identity of a bot conversation across Manager changes and writes each stored message together with an ownership check, so a Manager cannot add messages to a conversation that belongs to another Manager.

**Breaking changes:** No. No command, option or schema changed. A stored message from a Manager that does not own the conversation is now rejected, but with the default setup (a single Manager, no pinned thread identity) every write is accepted as before.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#645](https://github.com/foolzzz/looper/pull/645); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.126
```

## Behavior changes

- **Thread identity helpers:** `looper/agents/message.py` adds `ChannelThreadId`, `parse_channel_thread_id` and `channel_thread_id`. A bot conversation is named `<type>:<chat>` for a built-in bot or `<channel_id>:<chat>` for an added bot, with a `#manager` or `#manager-<key>` suffix only when the destination Manager differs from the bot's own Manager. Malformed ids, suffixes or chat ids (Telegram: digits with an optional minus; Lark: no `#`, `:` or whitespace) parse to None, and `channel_thread_id` raises `ValueError` for them. In this release no production code builds a suffixed id, so every conversation keeps its existing unsuffixed id.
- **Atomic ownership check on write:** `save_channel_message` in `looper/db/chat.py` runs in one transaction: it claims the conversation for the writing Manager (a conversation that already has messages but no owner row belongs to the default Manager `manager`), reads the stored owner, and raises `ValueError` without writing if the owner is another Manager. `save_message` also accepts an open connection.
- **Manager turn persistence:** in `looper/agents/tiers/manager.py` a Manager now stores Telegram and Lark turns through `save_channel_message` with its own id. The separate, best-effort `claim_thread` call after the write is gone, so a turn from a non-owner is no longer stored and the failure is logged as a warning instead.
- **Session key:** `_session_key` uses the web `session_id` only for web chats; it no longer applies to a Telegram or Lark message that carries one. When the routing envelope carries a `channel_thread_id` pin, the key is that pin, and a pin that does not match the envelope's bot, chat, source, target and Manager raises `ValueError` (the turn is then not stored). Without a pin the key is the unsuffixed id as before.
- **Reply recording:** `record_reply` in `looper/agents/channels/chat_history.py` now stores an answer only when the envelope's source is a Manager, and stores it through `save_channel_message` under that Manager's id.
- **Model-visible changes:** none. Prompts, tool declarations and results are unchanged.
- **Line counts:** the description of [#645](https://github.com/foolzzz/looper/pull/645) reports tests 440 and production 120 added lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.126 is published. No schema or configuration change. Rolling back to v2.13.125 restores the previous write path; stored messages stay valid.

### 升级决策

**谁需要升级：**无需为可见功能而升级。本次 patch release 让 Telegram 与 Lark 会话的历史存储检查会话归属的 Manager，并改变了 Manager 无法存储某一轮对话时的行为。

**解决了什么：**[#645](https://github.com/foolzzz/looper/pull/645) 在 Manager 变更时保留 bot 会话的标识，并把每条存储消息与归属检查放在同一次写入中，避免 Manager 向属于其他 Manager 的会话追加消息。

**是否有破坏性变更：**否。命令、选项和表结构均未改变。来自非归属 Manager 的消息现在会被拒绝，但默认配置（单个 Manager、无固定会话标识）下所有写入照常接受。

**如何验证：**运行 `looper --version` 核对版本为 2.13.126。

**贡献者：**维护者 @foolzzz 提交 [#645](https://github.com/foolzzz/looper/pull/645)；本次 patch release 无社区贡献。

looper --version   # looper 2.13.126

### 行为变化与入口

- **会话标识辅助函数：**`looper/agents/message.py` 新增 `ChannelThreadId`、`parse_channel_thread_id` 和 `channel_thread_id`。bot 会话内置 bot 为 `<type>:<chat>`，新增 bot 为 `<channel_id>:<chat>`；仅当目标 Manager 不同于 bot 自身的 Manager 时才加 `#manager` 或 `#manager-<key>` 后缀。格式错误的 id、后缀或聊天 id（Telegram：数字，可带负号；Lark：不含 `#`、`:` 和空白）解析为 None，`channel_thread_id` 对其抛出 `ValueError`。本版本没有生产代码构造带后缀的 id，所有会话仍沿用原有无后缀 id。
- **写入时的原子归属检查：**`looper/db/chat.py` 的 `save_channel_message` 在同一事务中认领会话（已有消息但无归属记录的会话属于默认 Manager `manager`）、读取已存归属，若归属是其他 Manager 则抛出 `ValueError` 且不写入。`save_message` 也接受已打开的连接。
- **Manager 对话落库：**`looper/agents/tiers/manager.py` 中 Manager 通过 `save_channel_message` 以自身 id 存储 Telegram 与 Lark 的对话轮次。写入后单独的尽力而为 `claim_thread` 调用已移除，因此非归属者的对话不再被存储，失败以警告记录。
- **会话键：**`_session_key` 仅对 web 聊天使用 web 的 `session_id`，不再用于携带该字段的 Telegram 或 Lark 消息。路由信封带有 `channel_thread_id` 固定值时，会话键即该值；若它与信封的 bot、聊天、来源、目标和 Manager 不符则抛出 `ValueError`（该轮不存储）。无固定值时仍为原有的无后缀 id。
- **回复记录：**`looper/agents/channels/chat_history.py` 的 `record_reply` 现在仅当信封来源是 Manager 时才存储回复，并通过 `save_channel_message` 以该 Manager 的 id 存储。
- **面向模型的变化：**无。提示词、tool 声明和结果均未改变。
- **行数：**[#645](https://github.com/foolzzz/looper/pull/645) 的描述报告新增测试 440 行、生产代码 120 行（不含 fixtures）。
