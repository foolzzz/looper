# Looper v2.13.100

## Release Decision

**Who should upgrade:** Anyone who adds, edits or imports Lark bot channels (lark-cli or bot token), and anyone whose client validates the gate objects in task-detail responses against the published schema.

**What this release solves:** [#562](https://github.com/foolzzz/looper/pull/562) makes saving or importing a Lark bot channel refuse when the app it acts as cannot be established or collides with another channel, instead of admitting an ambiguous identity. [#573](https://github.com/foolzzz/looper/pull/573) corrects the task-detail gate schema so it describes what the gate projection actually returns.

**Breaking changes:** No. No configuration, prompt or Tool declaration changed. Behavior is stricter in one case: a Lark (lark-cli) channel whose profile cannot be resolved to an app is now refused on save and import; see Behavior changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#562](https://github.com/foolzzz/looper/pull/562) and [#573](https://github.com/foolzzz/looper/pull/573); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.100
```

## Behavior changes

- **Lark identity must be known before a bot channel is saved ([#562](https://github.com/foolzzz/looper/pull/562)):** `refuse_same_bot` in `looper/agents/channels/bot_api.py` now resolves the app of the candidate through `_admission_app_id`. For a `lark` (lark-cli) channel whose profile does not resolve to an app, the request is refused with HTTP 409 "cannot verify Lark app identity; check the configured lark-cli profiles and authentication, then retry saving or importing". The message carries no CLI error text and no profile value. The same check applies to every stored Lark row compared against the candidate, so one unresolved lark-cli row also refuses the save, because different profile names cannot prove the apps differ. A `lark_bot` channel takes its app from its `app_id` and is not affected by this refusal.
- **Metadata edits of Lark channels are re-checked ([#562](https://github.com/foolzzz/looper/pull/562)):** `update_bot` now takes the bots lock and runs the same-bot check for every update of a `lark` or `lark_bot` channel, even when the request changes neither token nor config, because a lark-cli profile can change its app outside Looper. Telegram updates keep the earlier condition.
- **Intentional built-in pairing is kept ([#562](https://github.com/foolzzz/looper/pull/562)):** the new `builtin_lark_pair` in `looper/agents/channels/bots.py` skips the comparison between the two built-in rows (`channel-lark` and `channel-lark_bot`), which share one app on purpose. The skip applies to the stored row compared against; the candidate's own identity is still resolved first.
- **Config import follows the same rule ([#562](https://github.com/foolzzz/looper/pull/562)):** `_refuse_same_bot` in `looper/agents/config_transfer.py` takes the bots lock, and a refusal is converted as before. When the database has no `channel_secrets` table yet (a preview), it has no other rows to compare, but a lark-cli candidate with an unknown identity is still refused. The tests cover that an unknown-identity import refuses without partial writes.
- **Task-detail gate schema matches the projection ([#573](https://github.com/foolzzz/looper/pull/573)):** in `looper/agents/v1_domains/task_views.py`, a gate's `summary` is now nullable object with `decisions`, `assumptions` and `open` string arrays, and `plan_change` a nullable object with `added`, `dropped` and `stopped` string arrays; both were nullable strings. Each agenda item's `options` is now an array of strings instead of an array of `{id, label}` objects. The change is to the declared schema only; the response data and persisted gates are not changed. A client that validated against the old schema would have rejected real gates with these fields set.
- **Model-visible changes:** none for prompts and Tool results. The only Tool-adjacent change is refusal text returned to the caller of the channel save API; no Tool declaration changed.
- **Tests:** [#562](https://github.com/foolzzz/looper/pull/562) adds cases in `tests/test_channel_bots_api_db.py` (unknown identity refuses writes until recovery, identity admission over HTTP, Lark bot apps added once), `tests/test_config_transfer_channel_bots_db.py` (import refuses unknown identity without partial writes, preview without the channel schema), and small updates to three other channel and config-transfer tests. The pull request reports 220 added test lines and 30 production lines. [#573](https://github.com/foolzzz/looper/pull/573) extends `tests/test_api_v1_task_views_db.py` with a full-detail case; it reports 84 added test lines and 5 production lines.

## Upgrade and rollback

Re-run `install.sh` once v2.13.100 is published. No data migration and no configuration change. If a Lark channel save or import is refused as unverifiable, fix the lark-cli profiles and authentication, then retry. Rolling back to v2.13.99 restores the earlier admission rules and the earlier gate schema.

## 中文摘要

### 升级决策

**谁需要升级：**添加、编辑或导入 Lark 机器人渠道（lark-cli 或 bot token）的用户，以及按公开 schema 校验任务详情中 gate 对象的客户端。

**解决了什么：**[#562](https://github.com/foolzzz/looper/pull/562) 让保存或导入 Lark 机器人渠道时，若无法确定其所对应的应用，或与其他渠道冲突，就直接拒绝，而不再放行含糊的身份。[#573](https://github.com/foolzzz/looper/pull/573) 修正任务详情的 gate schema，使其与 gate 投影的实际输出一致。

**是否有破坏性变更：**否。配置、prompt 和 Tool 声明均未改变。有一种情形更严格：lark-cli 渠道的 profile 无法解析出应用时，保存和导入现在会被拒绝，见行为变化。

**如何验证：**运行 `looper --version` 核对版本为 2.13.100。

**贡献者：**维护者 @foolzzz 提交 [#562](https://github.com/foolzzz/looper/pull/562) 和 [#573](https://github.com/foolzzz/looper/pull/573)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.100
```

### 行为变化与入口

- **保存 Lark 机器人渠道前必须确定其身份（[#562](https://github.com/foolzzz/looper/pull/562)）：**`looper/agents/channels/bot_api.py` 中的 `refuse_same_bot` 现在通过 `_admission_app_id` 解析候选渠道的应用。`lark`（lark-cli）渠道的 profile 无法解析出应用时，请求以 HTTP 409 拒绝，提示 "cannot verify Lark app identity; check the configured lark-cli profiles and authentication, then retry saving or importing"。提示中不含 CLI 错误文本和 profile 值。与候选比较的每个已存储 Lark 行也适用同一检查，因此只要有一个无法解析的 lark-cli 行，保存也会被拒绝，因为不同的 profile 名称不能证明应用不同。`lark_bot` 渠道的应用取自其 `app_id`，不受此拒绝影响。
- **Lark 渠道的元数据修改也会重新检查（[#562](https://github.com/foolzzz/looper/pull/562)）：**`update_bot` 现在对每次 `lark` 或 `lark_bot` 渠道的更新都加 bots 锁并执行同 bot 检查，即使请求没有改动 token 或 config，因为 lark-cli profile 的应用可能在 Looper 之外改变。Telegram 的更新保持原条件。
- **保留内置渠道的有意配对（[#562](https://github.com/foolzzz/looper/pull/562)）：**`looper/agents/channels/bots.py` 中新增的 `builtin_lark_pair` 跳过两个内置行（`channel-lark` 与 `channel-lark_bot`）之间的比较，它们有意共用同一应用。该跳过针对被比较的已存储行；候选渠道自身的身份仍会先被解析。
- **配置导入遵循同一规则（[#562](https://github.com/foolzzz/looper/pull/562)）：**`looper/agents/config_transfer.py` 中的 `_refuse_same_bot` 现在加 bots 锁，拒绝的转换方式不变。数据库还没有 `channel_secrets` 表时（预览），没有其他行可比较，但身份未知的 lark-cli 候选仍被拒绝。测试覆盖了身份未知的导入被拒绝且没有部分写入。
- **任务详情 gate schema 与投影一致（[#573](https://github.com/foolzzz/looper/pull/573)）：**`looper/agents/v1_domains/task_views.py` 中，gate 的 `summary` 现为可空对象，含 `decisions`、`assumptions`、`open` 字符串数组；`plan_change` 为可空对象，含 `added`、`dropped`、`stopped` 字符串数组；此前两者都是可空字符串。议程项的 `options` 现为字符串数组，而不是 `{id, label}` 对象数组。改动只涉及声明的 schema，响应数据和已持久化的 gate 均未改变。按旧 schema 校验的客户端会拒绝这些字段有值的真实 gate。
- **面向模型的变化：**prompt 和 Tool 结果均无变化。唯一与 Tool 相邻的变化是渠道保存 API 返回给调用方的拒绝文本；没有 Tool 声明变化。
- **测试：**[#562](https://github.com/foolzzz/looper/pull/562) 在 `tests/test_channel_bots_api_db.py` 新增用例（身份未知时拒绝写入直到恢复、经 HTTP 的身份准入、Lark bot 应用只能添加一次），在 `tests/test_config_transfer_channel_bots_db.py` 新增用例（身份未知的导入拒绝且无部分写入、无渠道 schema 的预览），并小幅更新另外三个渠道与配置传输测试。该 PR 报告新增测试 220 行、生产代码 30 行。[#573](https://github.com/foolzzz/looper/pull/573) 在 `tests/test_api_v1_task_views_db.py` 新增一个完整详情用例，报告新增测试 84 行、生产代码 5 行。
