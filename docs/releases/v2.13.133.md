# Looper v2.13.133

## Release Decision

**Who should upgrade:** Operators who run chat-bound Managers and need the logs to show why a chat message reached a Manager or stayed silent. Everyone else can stay on v2.13.132.

**What this release solves:** [#665](https://github.com/foolzzz/looper/pull/665) logs chat binding and routing decisions at their boundaries: the Telegram and Lark admission points, binding and policy writes, refused operator-only calls, and native stop. It closes the logging gap recorded in the scenario-Managers RFC.

**Breaking changes:** No. Routing, API responses, schema and configuration are unchanged. New log lines are added; a failing logging handler cannot affect a routing decision.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#665](https://github.com/foolzzz/looper/pull/665); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.133
```

## Behavior changes

- **New `chat_route` log line (#665):** `looper/agents/channels/chat_routing.py` adds `log_route`, which logs `channel_id`, `chat_id`, `manager_id`, `action`, `reason` and `outcome`. The reason is `only_bound_chats` for a silenced chat, `explicit_binding` or `bot_manager` for an admitted one, and `disabled_target` when the target Manager is off and the chat is told so (outcome `answered` or `answer_failed`). The Telegram adapter logs on silence, on `/start`, `/help` and ordinary messages; the Lark adapter logs on silence, on admission and on the disabled-target answer.
- **New `chat_routing_write` log line (#665):** binding put, binding delete and the bound-chats-only policy write log `committed` after the commit and publication, with the old and new Manager (or old and new policy), the action and the principal kind (`client` or `operator`). Operator-only calls to those three operations that are refused (forbidden, or an error from the operation) log `refused` with the reason, in `looper/agents/http_server.py`.
- **New `chat_stop` log line (#665):** `ManagerFleet.stop_chat` logs the owners, the stopped, cannot-interrupt and failed counts, and the outcome `disabled`, `completed` or `partial`.
- **Logging cannot change a decision (#665):** `boundary_log` swallows any exception from the logging call.
- **Routing write path (#665):** the snapshot read before the write now runs inside the write, after the channel lock and before the change (a `before_write` callback in `looper/db/chat_bindings.py`), and the snapshot published to the registry is derived from it plus the change, instead of a second read after the write. The bind, unbind and policy functions take a new optional `principal_kind`, defaulting to `operator`; the v1 chat-bindings domain passes the caller's kind. Publication to the registry is unchanged in order.
- **Documentation (#665):** the scenario-Managers RFC acceptance note and two status lines (that RFC and the chat-stop v2 RFC) and one line of the long-horizon plan no longer point at implementation card files outside the repository.
- **Model-visible changes:** none found. The diff touches no prompt, tool declaration or tool result; the log lines are not sent to a model.
- **Line counts:** the description reports tests 123 and production 110 added lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.133 is published. No schema or configuration change. Rolling back to v2.13.132 only removes the log lines and restores the earlier write path.

### 行为变化与入口

- **新增 `chat_route` 日志（#665）：**`chat_routing.py` 新增 `log_route`，记录 `channel_id`、`chat_id`、`manager_id`、`action`、`reason`、`outcome`。静默为 `only_bound_chats`，放行为 `explicit_binding` 或 `bot_manager`，目标 Manager 已停用并回复聊天时为 `disabled_target`（结果 `answered` 或 `answer_failed`）。Telegram 适配器在静默、`/start`、`/help` 和普通消息时记录；Lark 适配器在静默、放行和停用目标回复时记录。
- **新增 `chat_routing_write` 日志（#665）：**绑定写入、绑定删除和仅限绑定策略写入在提交并发布后记录 `committed`，含新旧 Manager（或新旧策略）、操作和主体类型（`client` 或 `operator`）。这三个操作中被拒绝的仅限 operator 调用（forbidden 或操作返回错误）记录 `refused` 及原因，位于 `http_server.py`。
- **新增 `chat_stop` 日志（#665）：**`ManagerFleet.stop_chat` 记录 owner、已停止、无法中断、失败的数量，以及结果 `disabled`、`completed` 或 `partial`。
- **日志不改变决策（#665）：**`boundary_log` 吞掉日志调用的任何异常。
- **路由写路径（#665）：**写入前的快照读取现在在写入过程中、取得 channel 锁之后、改动之前执行（`chat_bindings.py` 中的 `before_write` 回调），发布给 registry 的快照由它加上改动推导，不再在写入后第二次读取。绑定、解绑和策略函数新增可选参数 `principal_kind`（默认 `operator`），v1 chat-bindings 域传入调用者的类型。向 registry 发布的顺序不变。
- **文档（#665）：**场景 Manager RFC 的验收说明及两处状态行（该 RFC 与 chat-stop v2 RFC），以及长程计划的一行，不再指向仓库之外的实现卡片文件。
- **面向模型的变化：**未发现。diff 不改提示词、tool 声明或 tool 结果；日志行不会发给模型。
- **行数：**描述报告新增测试 123 行、生产代码 110 行（不含 fixtures）。
