# Looper v2.14.87

This is the patch release v2.14.87, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.86: a Cursor run is retried once when Cursor's CLI gives up after reconnecting ([#1104](https://github.com/foolzzz/looper/pull/1104)).

## Release Decision

**Who should upgrade:** Operators who run the Cursor Agent runtime (directly or through TTADK) on unstable networks. Everyone else can stay.

**What this release solves:** Cursor's CLI reconnects up to three times, then exits 1 with `RetriableError: WritableIterable is closed` and no result event (through TTADK it can exit 0), which failed the run or turn. [#1104](https://github.com/foolzzz/looper/pull/1104) retries such a run or turn once from a fresh process and records the retry.

**Breaking changes:** No. No setting, operation, field or database column changes. Only this one error signature retries; any other failure behaves as before.

**How to verify:** Check the installed version. A Cursor run that hit the error shows a `cursor_run_retry` event in its record; if the retry also fails, the error carries both attempts' stderr tails.

**Contributors:** Maintainer @foolzzz authored [#1104](https://github.com/foolzzz/looper/pull/1104); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.87
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.86 upgrades directly. There is no database change.

## Behavior changes

- **One retry for a transient Cursor failure** (`looper/agents/runtimes/cursor_agent.py`). When a Cursor process exits (code 0 or 1) without a result and its stderr contains `RetriableError: WritableIterable is closed`, Looper starts a fresh process once, also when TTADK exits zero. The retry does not happen after a stop or cancellation, and the shared worker-server helper of the exited CLI is left alone.
- **Workers and Reviewers** (`looper/agents/tiers/worker.py`). The retry reuses the prepared prompt and input directories; only the process and its channel are new, and it is still one run. It respects the run's timeout deadline. The run records a `cursor_run_retry` event (`attempt: 1`, `reason: transient_backend`, with a stderr tail) and the parent task's activity shows "Cursor's CLI gave up after reconnecting; retried once". If the retry also ends without a result, the error and the returned stderr contain both attempts.
- **Managers and Planners** (`looper/agents/tiers/manager.py`, `looper/agents/tiers/planner.py`). The turn is retried with the same text and resumes the recorded chat, if any. A transient Cursor failure is no longer reported as a lost session ("could not be resumed; retried in a new session"). A Cursor turn that ends without a result now includes the stderr tail in its error (`ended without a result`, without "through TTADK" when TTADK is not used), using both attempts when it was retried. The Planner's activity shows the retry summary.
- **Stderr capture** (`looper/agents/runtimes/per_turn.py`, `looper/agents/claude_cli.py`). Stderr bytes read before a cancelled or timed-out drain are retained, and the drain task is awaited. `ResidentTurn` gains `stderr_detail`, the diagnostics across attempts.
- **Unchanged:** other failures, stops, cancellations, timeouts and missing logins are not retried; the API, `loopercli`, the database, the dashboard, and wheel and source upgrades.
- **Documentation and tests.** `docs/architecture/agent-system.md` describes the retry. The pull request adds `tests/test_cursor_retry.py` and adjusts `tests/test_stop_matrix.py`.
- **Model-visible changes:** A retried Manager or Planner turn sends the same turn text to the runtime a second time (resuming the same chat), so the model can see that turn twice if the first attempt had reached it; no prompt, tool text or tool result wording changes.

### 升级决策

**谁需要升级：**在不稳定网络上使用 Cursor Agent 运行时（直接或经 TTADK）的运维人员。其他人可不升级。

**解决了什么：**Cursor 的 CLI 重连最多三次后以 `RetriableError: WritableIterable is closed` 退出 1 且没有 result 事件（经 TTADK 时可能退出 0），导致运行或回合失败。[#1104](https://github.com/foolzzz/looper/pull/1104) 对这类运行或回合用新进程重试一次，并记录重试。

**是否有破坏性变更：**否。没有设置、操作、字段或数据库列变化。只有这一种错误特征会重试，其他失败的行为不变。

**如何验证：**核对版本为 2.14.87。遇到该错误的 Cursor 运行，其记录中有 `cursor_run_retry` 事件；若重试也失败，错误信息包含两次尝试的 stderr 尾部。

**贡献者：**维护者 @foolzzz 提交 [#1104](https://github.com/foolzzz/looper/pull/1104)；本版本无社区贡献。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.86 上的安装可直接升级。没有数据库变更。

### 行为变化与入口

- **对 Cursor 瞬时失败重试一次**（`looper/agents/runtimes/cursor_agent.py`）。Cursor 进程以 0 或 1 退出、没有 result，且 stderr 含 `RetriableError: WritableIterable is closed` 时，Looper 用新进程重试一次，TTADK 退出 0 时同样。停止或取消后不重试，已退出 CLI 的共享 worker-server 辅助进程不动。
- **Worker 与 Reviewer**（`looper/agents/tiers/worker.py`）。重试复用已准备好的提示和输入目录，只有进程和通道是新的，仍是同一次运行；遵守运行的超时截止时间。运行记录 `cursor_run_retry` 事件（`attempt: 1`、`reason: transient_backend`，带 stderr 尾部），父任务活动显示 "Cursor's CLI gave up after reconnecting; retried once"。若重试仍没有 result，错误和返回的 stderr 包含两次尝试。
- **Manager 与 Planner**（`looper/agents/tiers/manager.py`、`looper/agents/tiers/planner.py`）。用相同文本重试该回合，并恢复已记录的会话（如有）。Cursor 的瞬时失败不再被报告为会话丢失（"could not be resumed; retried in a new session"）。没有 result 就结束的 Cursor 回合，其错误现在带 stderr 尾部（未使用 TTADK 时不写"through TTADK"），重试过则用两次尝试的内容。Planner 活动显示重试摘要。
- **stderr 采集**（`looper/agents/runtimes/per_turn.py`、`looper/agents/claude_cli.py`）。被取消或超时的读取之前已读到的 stderr 字节会保留，且会等待读取任务结束。`ResidentTurn` 新增 `stderr_detail`，记录跨尝试的诊断。
- **不变：**其他失败、停止、取消、超时和未登录都不重试；API、`loopercli`、数据库、仪表盘，以及 wheel 与源码升级。
- **文档与测试。**`docs/architecture/agent-system.md` 描述了重试。该 PR 新增 `tests/test_cursor_retry.py`，并调整 `tests/test_stop_matrix.py`。
- **面向模型的变化：**被重试的 Manager 或 Planner 回合会把相同的回合文本再发给运行时一次（恢复同一会话），若第一次已到达模型，模型可能看到该回合两次；提示、工具文本和工具结果的措辞不变。
