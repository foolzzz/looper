# Looper v2.14.27

This is the patch release v2.14.27. It ships the one change merged since v2.14.26: [#931](https://github.com/foolzzz/looper/pull/931), which corrects the hot upgrade v0 RFC after its review. It is documentation only and changes no runtime code.

## Release Decision

**Who should upgrade:** Nobody needs this release for runtime behavior. It matters to maintainers who follow the hot upgrade design for planned restarts that do not interrupt runs. It ships the one change merged since v2.14.26.

**What this release solves:** [#931](https://github.com/foolzzz/looper/pull/931) corrects `docs/architecture/rfcs/hot-upgrade-v0.zh-CN.md` (in Chinese) with the six review findings of issue #929: it separates the control plane's loaded fingerprint from the served web fingerprint, stops the old control plane before installing after a drain, defines what a control plane does when it loses the database lock, keeps a Manager's bus message unacknowledged while a drain holds its turn, keeps keepers out of the startup sweep, and uses the v1 API conventions (POST operations, no DELETE, 200 for an operator call, whoami for the version).

**Breaking changes:** No. No database schema, stored data, API or default changes. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#931](https://github.com/foolzzz/looper/pull/931); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.27
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.26 upgrades directly. This release changes no database schema or stored data.

## Behavior changes

- **None at runtime.** The pull request touches only `docs/architecture/rfcs/hot-upgrade-v0.zh-CN.md` (37 lines added, 25 removed); no file under `looper/` changes.
- **The RFC** is still a design only. The corrections change what it specifies, not what ships: the component endpoint becomes `POST /api/v1/system/components`, which reports a loaded snapshot plus a web fingerprint read per request; drain operations become `system.drain`, `system.drain_cancel` and `system.drain_status`, all POST and all returning 200; after a drain (including a drain timeout) the old control plane stops and exits before the install; losing the database lock ends that instance; keepers are not registered as owned by the control plane, so its startup sweep leaves them alone. None of this is implemented by this release.
- **Model-visible changes:** None. No prompt, tool, schema or message changes. The RFC's statement that a Manager's bus message stays unacknowledged during a drain describes planned behavior, not current behavior.

- **运行时无变化。**该 PR 只改动 `docs/architecture/rfcs/hot-upgrade-v0.zh-CN.md`（新增 37 行，删除 25 行）；`looper/` 下没有文件变化。
