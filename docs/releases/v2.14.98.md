# Looper v2.14.98

This is the patch release v2.14.98, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.97: a dashboard viewer for recorded model requests and an operator-only JSONL export ([#1139](https://github.com/foolzzz/looper/pull/1139)). It builds on the opt-in request recording of v2.14.97 and is only useful when that recording is on or captures already exist.

## Release Decision

**Who should upgrade:** Operators who record model requests (`llmrec.enabled`) and want to read or export them. Everyone else can stay; with no captures the upgrade changes only the Settings page.

**What this release solves:** Recorded exchanges could only be read with `loopercli llm-requests list/get`. [#1139](https://github.com/foolzzz/looper/pull/1139) adds a "Model requests" section to each run card on an agent's history page with a request viewer, a confirmation before recording is turned on, proxy counters on Settings → Request recording, and an operator-only `llm_requests.export` operation with a matching `loopercli llm-requests export` that writes complete requests as JSONL.

**Breaking changes:** No. No database change, no new dependency, no change to the recording itself. Existing operations keep their fields; `llm_requests.get` gains the fields `new_from_index` and `route`, and an unreconstructable request now answers HTTP 500 (`internal`) instead of a partial body.

**How to verify:** Check the installed version. In the dashboard, Settings → Request recording shows the proxy state with its port and counters.

```bash
looper --version   # looper 2.14.98
```

**Contributors:** Maintainer @foolzzz authored [#1139](https://github.com/foolzzz/looper/pull/1139); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.97 upgrades directly. There is no database change.

## Behavior changes

- **Dashboard viewer** (`web/src/pages/agent-history.tsx`). Each run card on an agent's history page gets a "Model requests · N" section with one row per request: time, kind, model, status, outcome, time to first byte, duration, the four token counts and a `record_gap` badge. Requests received after the turn ended appear under the run they follow ("After the turn ended"). The list refreshes every two seconds while the run is running. Opening a row shows the system prompt, tools and messages with a divider at the first message the previous request on the same route did not have, the other parameters, the headers with redacted values marked, the assembled response with usage (or the raw text when assembly failed), and every gap and outcome.
- **Settings → Request recording** (`web/src/components/llmrec-settings.tsx`). The "Record model requests" checkbox is now a switch; turning it on first asks for confirmation that prompts, code, tool output and model replies will be stored in the database. Turning it off asks nothing and keeps stored requests. The page shows the proxy state as a badge with its port and the requests, recorded, dropped and write-error counts.
- **Export in the dashboard** (`web/src/components/llm-request-export.tsx`). "Export JSONL" on a run, and "Export model requests" on an agent's history and on a task's Agents tab (the last two appear only when recording is on or the scope has captures). The export shows progress and can be cancelled before download.
- **API** (`looper/agents/v1_domains/llm_requests.py`, `looper/db/llm_requests.py`). New operator-only `llm_requests.export` (`POST /api/v1/llm_requests/export`): complete requests in ascending id order, at most 50 per page, with `after_id` and `next_after_id` cursors, for a `task_id`, `agent_id` or `record_id` (at most one) and optional `since`/`until` ISO 8601 timestamps (naive times are UTC; `until` must be after `since`); at least one scope or `since` is required. `llm_requests.get` and the export return `new_from_index`, the server-computed index of the first message (`messages`, or `input` for the Responses API) that differs from the previous request on the same route, or null for the first request or an unsplit body, and a `route` object (agent, task, step, role, runtime, provider, protocol, model, upstream host and path). Both read in a repeatable-read transaction. If a stored body part is missing, the request fails with its id (new error code `internal`, HTTP 500) instead of returning a partial body.
- **CLI** (`looper/loopercli.py`). New hand-written `loopercli llm-requests export` with one of `--task`, `--agent`, `--record` (or `--since` alone), optional `--since`/`--until`, `--out FILE` (`-` for stdout) and the operator token options. It pages the API into JSONL: a header line (`type: llmrec_export`, `format: 1`, `exported_at`, `filter`, the redaction rule) followed by one request per line, with nothing removed silently. The file is created with mode 0600, never overwrites an existing file or follows a symlink, and is deleted if the export fails; the count goes to stderr. `llm-requests list/get` are unchanged.
- **Unchanged:** the recording proxy, what is stored, the database schema, the dependencies, channels (Telegram and Lark: these are operator diagnostics) and agent-facing tools. Captures, settings and exports stay operator-only; API-client tokens receive 403. Export bodies are exactly as stored, so they can contain secrets printed by tools.
- **Documentation and tests.** `docs/architecture/agent-system.md` describes the viewer, the export and the file format; new `tests/test_llm_requests_browser.py` and `tests/test_loopercli_llm_requests_export.py`; updated `tests/test_api_v1_llm_requests_db.py`, `tests/test_api_v1_catalog_errors.py`, `tests/test_api_v1_document.py`, `tests/test_loopercli.py`, `tests/db_support.py`, `web/src/pages/agent-history.test.tsx` and `web/src/components/llmrec-settings.test.tsx`.
- **Model-visible changes:** None. No prompt, tool description or agent environment changes, and the export operation is not exposed to agents.

## Optional Capability Activation & Use

### Model request viewer and export

**Activation:** Nothing to enable beyond v2.14.97's recording. Open an agent's history page and expand "Model requests" on a run; use "Export JSONL" or "Export model requests" in the dashboard, or `loopercli llm-requests export` with an operator token. The viewer and export read what is stored, so they work on existing captures even when recording is now off.

**Validation:** After a recorded run, the run card lists its requests and a row opens the viewer. The CLI writes a file whose first line has `"type":"llmrec_export"` and whose later lines are requests; the count is printed on stderr.

```bash
loopercli llm-requests export --record 123 --out run.jsonl --operator-token-file operator-token
head -c 300 run.jsonl
```

**Disable / rollback:** Do not use the viewer or export; nothing runs in the background. Turn recording off in Settings → Request recording to stop new captures (stored ones stay). Downgrading removes the viewer, the export and the added `llm_requests.get` fields; stored data is untouched.

**Authority boundary:** Operator token only for reading, listing and exporting captures and for the settings; agents and API-client tokens cannot. Bodies are exported as stored and are not secret-scrubbed. An export file is created readable by its owner only, and is the operator's to protect.

**Docs:** [Model request recording](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md#model-request-recording-llmrec) in the agent-system architecture document.

## 中文摘要

本版本是 patch release v2.14.98（热修线，每个合并的改动立即发布）。自 v2.14.97 以来只合并了一项改动：仪表盘中的模型请求查看器，以及仅限运维人员的 JSONL 导出（[#1139](https://github.com/foolzzz/looper/pull/1139)）。它建立在 v2.14.97 的按需录制之上，仅在录制开启或已有记录时有用。

### 升级决策

**谁需要升级：**开启了模型请求录制（`llmrec.enabled`）并想查看或导出记录的运维人员。其他人可不升级；没有记录时只有 Settings 页面有变化。

**解决了什么：**此前只能用 `loopercli llm-requests list/get` 读取录制的交换。[#1139](https://github.com/foolzzz/looper/pull/1139) 在 agent 历史页的每个运行卡片中加入 “Model requests” 区块和请求查看器，开启录制前需确认，Settings → Request recording 显示代理计数，并新增仅限运维的 `llm_requests.export` 操作及对应的 `loopercli llm-requests export`，把完整请求写成 JSONL。

**是否有破坏性变更：**否。无数据库变更、无新依赖，录制本身不变。已有操作的字段不变；`llm_requests.get` 新增 `new_from_index` 和 `route` 字段，无法完整还原的请求现在返回 HTTP 500（`internal`），而不是部分内容。

**如何验证：**核对版本为 2.14.98。在仪表盘 Settings → Request recording 中显示代理状态、端口和计数。

**贡献者：**维护者 @foolzzz 提交 [#1139](https://github.com/foolzzz/looper/pull/1139)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.98
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.97 上的安装可直接升级。无数据库变更。

### 行为变化与入口

- **仪表盘查看器**（`web/src/pages/agent-history.tsx`）。agent 历史页的每个运行卡片新增 “Model requests · N” 区块，每个请求一行：时间、类型、模型、状态、结果、首字节时间、耗时、四项 token 数和 `record_gap` 标记。回合结束后收到的请求显示在其所跟随的运行下（“After the turn ended”）。运行中每两秒刷新。展开一行可看到系统提示、工具和消息（在与同一路由上前一个请求不同的第一条消息处有分隔线）、其他参数、标出脱敏值的头、组装后的响应及用量（组装失败时为原始文本），以及每个缺口和结果。
- **Settings → Request recording**（`web/src/components/llmrec-settings.tsx`）。“Record model requests” 由复选框改为开关；开启前先确认提示、代码、工具输出和模型回复将存入数据库。关闭无需确认，已存请求保留。页面以徽章显示代理状态，并显示端口及请求、已记录、丢弃、写入错误计数。
- **仪表盘导出**（`web/src/components/llm-request-export.tsx`）。运行上的 “Export JSONL”，以及 agent 历史页和任务 Agents 标签页上的 “Export model requests”（后两者仅在录制开启或该范围已有记录时出现）。导出显示进度，下载前可取消。
- **API**（`looper/agents/v1_domains/llm_requests.py`、`looper/db/llm_requests.py`）。新增仅限运维令牌的 `llm_requests.export`（`POST /api/v1/llm_requests/export`）：按 id 升序返回完整请求，每页至多 50 条，用 `after_id` 和 `next_after_id` 游标；范围为 `task_id`、`agent_id`、`record_id`（至多一个），可加 `since`/`until` ISO 8601 时间（无时区按 UTC；`until` 须晚于 `since`）；至少需要一个范围或 `since`。`llm_requests.get` 和导出返回 `new_from_index`（服务端计算的、与同一路由上前一个请求相比第一条不同的消息下标，Responses API 用 `input`；首个请求或未拆分正文为 null）和 `route` 对象（agent、任务、步骤、角色、运行时、服务商、协议、模型、上游主机和路径）。二者都在可重复读事务中读取。若存储的正文片段缺失，请求会带着其 id 失败（新错误码 `internal`，HTTP 500），而不是返回部分内容。
- **CLI**（`looper/loopercli.py`）。新增手写的 `loopercli llm-requests export`，需 `--task`、`--agent`、`--record` 之一（或仅 `--since`），可选 `--since`/`--until`、`--out FILE`（`-` 为标准输出）及运维令牌选项。它把 API 分页写成 JSONL：先一行头（`type: llmrec_export`、`format: 1`、`exported_at`、`filter`、脱敏规则），之后每行一个请求，不会静默删除任何内容。文件权限为 0600，不覆盖已有文件、不跟随符号链接，导出失败时删除；条数输出到 stderr。`llm-requests list/get` 不变。
- **不变：**录制代理、存储内容、数据库结构、依赖、渠道（Telegram 和 Lark：这些是运维诊断）和面向 agent 的工具。记录、设置和导出仍仅限运维；API 客户端令牌得到 403。导出的正文与存储一致，可能含工具打印出的密钥。
- **文档与测试。**`docs/architecture/agent-system.md` 描述查看器、导出和文件格式；新增 `tests/test_llm_requests_browser.py` 和 `tests/test_loopercli_llm_requests_export.py`；更新 `tests/test_api_v1_llm_requests_db.py`、`tests/test_api_v1_catalog_errors.py`、`tests/test_api_v1_document.py`、`tests/test_loopercli.py`、`tests/db_support.py`、`web/src/pages/agent-history.test.tsx` 和 `web/src/components/llmrec-settings.test.tsx`。
- **面向模型的变化：**无。提示、工具描述和 agent 环境都不变，导出操作也不暴露给 agent。

### 可选能力启用与使用

#### Model request viewer and export

**启用：**除 v2.14.97 的录制外无需开启任何东西。打开 agent 历史页，展开运行上的 “Model requests”；在仪表盘用 “Export JSONL” 或 “Export model requests”，或用运维令牌运行 `loopercli llm-requests export`。查看器和导出读取已存数据，因此即使现在录制已关闭，也可用于已有记录。

**验证：**录制过的运行之后，运行卡片列出其请求，点击一行打开查看器。CLI 写出的文件首行含 `"type":"llmrec_export"`，之后各行为请求；条数输出在 stderr。

```bash
loopercli llm-requests export --record 123 --out run.jsonl --operator-token-file operator-token
head -c 300 run.jsonl
```

**停用 / 回退：**不使用查看器和导出即可；没有后台任务。在 Settings → Request recording 关闭录制以停止新记录（已存的保留）。降级会去掉查看器、导出和 `llm_requests.get` 新增的字段；已存数据不受影响。

**权限边界：**读取、列出和导出记录以及设置仅限运维令牌；agent 和 API 客户端令牌不能。正文按存储原样导出，不做密钥清洗。导出文件仅所有者可读，保护它是运维人员的责任。

**文档：**agent-system 架构文档中的 [Model request recording](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md#model-request-recording-llmrec)。
