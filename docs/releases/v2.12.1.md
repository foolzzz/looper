# Looper v2.12.1

## Release Decision

**Who should upgrade:** Operators using v2.12.0's optional knowledge vault, especially when multiword searches miss notes or a vault sits below a directory the server can enter but cannot list.

**What this release solves:** Vault search accepts any query word and ranks notes by matched query words before repeated hits. Writes can pass search-only ancestor directories, and saving an inaccessible vault setting returns HTTP 400 instead of accepting a setting that fails on write or returning HTTP 500. These fixes are in [#245](https://github.com/foolzzz/looper/pull/245).

**Breaking changes:** No. Existing settings remain compatible. Search deliberately returns more matches, adds a `words` count to each result and changes its model-visible tool description. Invalid path permissions are rejected earlier, when settings are saved.

**How to verify:** After upgrading with `install.sh`, restart the service using its existing configuration and runtime root. Check the version below. In a disposable vault, search with several words when a note lacks one: it should still appear, with notes matching more words ahead of notes repeating fewer words. Check that inaccessible paths are refused when saving, and that an allowed-folder write works through an ancestor with enter-only permission on macOS or Linux.

**Contributors:** Release maintainer @foolzzz; no community contribution in [#245](https://github.com/foolzzz/looper/pull/245).

```bash
looper --version   # looper 2.12.1
looper doctor
```

## Fixes

- **Search no longer requires every query word.** `looper_vault_search` matches any whitespace-separated word, ignoring case, in a Markdown note's path or text. Results rank by how many query words match, then text hit count, then path; each includes `words`. Matching more distinct query words takes priority over repeating one word many times. Previously, adding a word absent from a note could hide it entirely. The tool description now explains the new ranking. ([#245](https://github.com/foolzzz/looper/pull/245))
- **Directory permissions are checked before a task needs to write.** The write's walk to the vault uses `O_SEARCH` on macOS or `O_PATH` on Linux, retaining the no-symlink walk. Ancestor directories need search (enter) permission rather than read/list permission. Saving through `PUT /api/knowledge-vault` refuses with HTTP 400 a path the server cannot pass, a vault it cannot read and search, or a configured writable folder it cannot reach. ([#245](https://github.com/foolzzz/looper/pull/245))

## Optional Capability Activation & Use

### Knowledge vault

**Activation:** No new switch. In Settings → Knowledge vault, configure the vault path, writable folders and optional rules file; select On for the project's Knowledge vault. It remains off by default; an empty writable-folder list is read only.

**Validation:** Run the version check below, then use a disposable vault and task to check partial-word matches, ranking, save-time permission errors, a permitted write and refusal outside writable folders. Task activity should record the note and its git commit, or its uncommitted status.

```bash
looper --version
```

**Disable / rollback:** Set the project's Knowledge vault to Off to stop task-agent vault access. Reinstall v2.12.0 to roll back the fixes, restoring its all-words search and ancestor-read restriction.

**Authority boundary:** Writable folders still constrain tool writes; enabled agents can read throughout the vault, including personal notes. Shell access is not constrained by these tools. The dashboard's existing settings page now reports permission errors when saving. Telegram and Lark use the Manager's existing confirmed `knowledge_vault` settings action and receive the same save-time validation; the Manager still has no vault search/read/write tools. No new CLI command is needed because the fixes apply to the shared settings and task tools.

**Docs:** [Knowledge vault architecture](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md#obsidian-knowledge-vault).

## Validation

- **Real end-to-end run on v2.12.0 vault code:** A disposable server with a sonnet Planner and haiku Workers completed the task. The Planner closeout committed one note in a writable folder; a Worker's tool write to a personal-notes folder was refused. Seven dashboard screenshots were checked. This run exposed the all-words search miss; it did not rerun the new search behavior with a real Planner.
- **Opus Planner closeout on #245 code, two reps:** `vault_closeout_keeps` 2/2 and `vault_closeout_nothing` 2/2.
- **Opus Manager dialogs on v2.12.0's merged code:** This includes the `knowledge_vault` action added to the Manager's settings tool in v2.12.0, even with the vault off.

- **Opus Manager at xhigh, all dialogs, two reps, on v2.12.0's merged code** (the Manager's settings tool gained the `knowledge_vault` action in v2.12.0): 54/54.

## Remaining limits

- The v2.12.0 requirement to read every ancestor directory no longer applies on macOS/Linux with `O_SEARCH`/`O_PATH`. The server still needs to enter every ancestor and read and search the vault itself; writable folders must be reachable and actual writes still need filesystem write permission. Systems with neither flag fall back to opening readable directories.
- Search remains bounded plain-text matching without an index. The broader search was not rerun with a real Planner; the real end-to-end run above used v2.12.0 code. Vault tools on Codex, Grok and OMP, concurrent Obsidian edits, and network or other case-insensitive filesystems remain unverified. A failed git commit can leave a note written but uncommitted; task activity reports it.

## 中文摘要

### 升级决策

**谁需要升级：**使用 v2.12.0 可选知识库的操作者，尤其是多词搜索漏掉笔记，或知识库上层目录允许进入但不允许列举内容的安装。

**解决了什么：**搜索改为任一查询词命中，先按命中词数再按出现次数排序；写入可经过只有进入权限的上层目录；无法到达的知识库路径、不可读或不可进入的知识库、无法到达的可写目录在保存设置时返回 HTTP 400，避免写入时才失败或返回 HTTP 500。修复见 [#245](https://github.com/foolzzz/looper/pull/245)。

**是否有破坏性变更：**无。已有设置保持兼容；搜索会返回更多结果，每条新增 `words`，模型可见的工具描述同步调整；权限不满足的设置会更早被拒绝。

**如何验证：**重跑 `install.sh` 升级，使用原配置和 runtime root 重启服务，运行下方检查。在临时知识库确认缺少一个查询词的笔记仍能搜到、命中更多词的笔记优先，以及保存不可达路径返回 400；macOS/Linux 上通过只有进入权限的祖先目录完成一次允许范围内的写入。

**贡献者：**发布维护者 @foolzzz；[#245](https://github.com/foolzzz/looper/pull/245) 无社区贡献。

```bash
looper --version   # looper 2.12.1
looper doctor
```

### 可选能力启用与使用

#### Knowledge vault

**启用：**没有新增开关。在 Settings → Knowledge vault 配置路径、可写目录和可选规则文件，再把项目的 Knowledge vault 设为 On；默认仍关闭，可写目录为空时只读。

**验证：**检查版本后，用临时知识库和任务验证任一词命中、排序、保存时的权限错误、允许写入和越界拒绝；任务动态应记录笔记及 git 提交，或未提交状态。

```bash
looper --version
```

**停用 / 回退：**把项目的 Knowledge vault 设为 Off；回装 v2.12.0 会恢复全部词命中和祖先目录需可读的限制。

**权限边界：**工具仍只能写可写目录，但启用后的 agent 可以读整个知识库，包括个人笔记；shell 不受工具限制。Dashboard 沿用现有设置页，保存时提前检查权限；飞书和 Telegram 经 Manager 原有、需确认的 `knowledge_vault` 设置动作获得相同校验。Manager 仍无知识库搜索、读写工具；共用设置与任务工具的修复无需新增 CLI 命令。

**文档：**[知识库架构](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md#obsidian-knowledge-vault)。

### 验证与剩余限制

- v2.12.0 知识库代码上，临时服务使用 sonnet Planner、haiku Workers 完成端到端任务；收尾在可写目录提交一篇笔记，Worker 向个人笔记目录的工具写入被拒绝，检查了七张 Dashboard 截图。这次运行发现了全部词命中的搜索缺陷，没有用真实 Planner 重跑新搜索。
- #245 代码上的 opus Planner 收尾评测各两轮：`vault_closeout_keeps` 2/2，`vault_closeout_nothing` 2/2。v2.12.0 合并代码上的 opus Manager 对话结果见上方待补行；该版本的设置工具已包含 `knowledge_vault` 动作，即使知识库关闭也会列出。
- macOS/Linux 使用 `O_SEARCH`/`O_PATH` 后不再要求每个祖先目录可读，仍需逐级可进入，知识库本身可读、可进入，可写目录可达且实际写入具备文件系统写权限；没有这两个 flag 的系统仍回退到打开可读目录。
- 搜索仍是有扫描上限的纯文本匹配。Codex/Grok/OMP 真实工具调用、Obsidian 并发编辑、网络或其他大小写不敏感文件系统仍未验证。git 提交失败可能留下已写入但未提交的笔记，任务动态会说明。
