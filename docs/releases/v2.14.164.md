# Looper v2.14.164

This is the patch release v2.14.164, a hotfix line in which each merged change ships at once. It documents two changes: [#1298](https://github.com/foolzzz/looper/pull/1298) (worker waits and Cursor session directories) and [#1296](https://github.com/foolzzz/looper/pull/1296) (keeper identities, rejected metadata diagnostics and upgrade stop budgets).

## Release Decision

**Who should upgrade:** Installations that use the Cursor Agent runtime, run workers with a run timeout, or run kept (keeper) runs under a launchd or systemd service and upgrade or restart it. Others need not upgrade for behavior.

**What this release solves:** [#1298](https://github.com/foolzzz/looper/pull/1298) fixes the listed valid items of the review follow-ups #1091 and #1110: a worker's waits after its output ends now respect the run timeout, and a Cursor session resumes in its saved directory. [#1296](https://github.com/foolzzz/looper/pull/1296) fixes #1048 and addresses items of #1276 and #1224: the keeper records its child's identity reliably, rejected keeper metadata is logged and preserved, and shutdown is bounded before the service manager forces the process to exit.

**Breaking changes:** No. There is no API change, migration or schema change. The generated service units change (see Behavior changes); an existing installation applies them by running `looper service install` again. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.164
```

**Contributors:** Maintainer @foolzzz authored [#1298](https://github.com/foolzzz/looper/pull/1298) and [#1296](https://github.com/foolzzz/looper/pull/1296); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.163 upgrades directly. There is no schema change. To apply the new stop timeouts to an installed service, run `looper service install` again.

## Behavior changes

[#1298](https://github.com/foolzzz/looper/pull/1298) states that its behavior changes follow the triage notes' fixes (maintainer decision, intended). [#1296](https://github.com/foolzzz/looper/pull/1296) does not use that wording. Read in the code:

[#1298](https://github.com/foolzzz/looper/pull/1298) changes `looper/agents/runtimes/cursor_agent.py`, `looper/agents/tiers/worker.py` and two test files.

- **Worker waits.** After a worker's output ends, waiting for the process to exit and reading its stderr are bounded by the run's deadline (`asyncio.wait_for` with the time left), not unbounded. Stderr is read with `stderr_tail` and a one-second drain (`STDERR_DRAIN_SEC`) instead of reading to EOF, and it is read for every run that has no successful result, not only for Cursor retries.
- **Cursor resume directory.** When a resident Cursor session resumes, it uses the working directory saved with that session id. If the saved directory no longer exists, a warning is logged and a new chat starts with fresh totals. The turn restores the previous working directory when it ends.
- **Chat cleanup.** The cleanup of interrupted replacement chats now looks only in the chat partition for the process's physical working directory (an MD5 of its real path), not in every partition.

[#1296](https://github.com/foolzzz/looper/pull/1296) changes `looper/agents/keeper/process.py`, `looper/agents/kept_dirs.py`, `looper/agents/serve.py`, `looper/agents/service.py`, `looper/agents/tiers/worker.py`, `docs/architecture/agent-system.md`, a plan note and six test files.

- **Keeper identities.** The keeper reuses the child's start time that `proc_tree.spawn` already recorded. A keeper or child whose start time cannot be read ends with `START_FAILED` instead of publishing a `RUNNING` state; an already-exited child can finish normally. On such a failure a spawned child is ended.
- **Rejected metadata.** A rejected keeper state, manifest, detach or grant file is logged with run, file, field and value. At startup its small JSON files (state, manifest, detach, grant; at most 64 KiB each) are copied privately to `<runtime root>/.local/kept-run-quarantine/` before the keeper is ended, and only the newest 20 copies are kept. A failed copy leaves the run directory in place and does not block startup. A detach file that exists but cannot be read, or a grant file that exists but is invalid, is now rejected as bad files.
- **Service stop budget.** New launchd plists carry `ExitTimeOut` 30 and new systemd units `TimeoutStopSec=30`, above serve's 15-second shutdown deadline. Installed services keep the old settings until `looper service install` is run again.
- **Detach budget.** `detach_kept` has one eight-second budget (`KEPT_DETACH_BUDGET_SEC`) covering the detach calls and the cleanup of finishing runs. A detach that outruns it is cancelled and reported as `BUSY`, or as `DETACHED` when the durable detach had already happened. Outcomes are logged.
- **Model-visible changes:** None in either pull request. No prompt, tool description, schema or answer text changes. The Cursor resume change affects which directory and chat the CLI process uses, not what the model is sent.

### 行为变化与入口

[#1298](https://github.com/foolzzz/looper/pull/1298) 声明行为变化遵循分诊记录中的修复（维护者决定，符合预期）；[#1296](https://github.com/foolzzz/looper/pull/1296) 没有这样的声明。代码中可见：

[#1298](https://github.com/foolzzz/looper/pull/1298) 改动 `looper/agents/runtimes/cursor_agent.py`、`looper/agents/tiers/worker.py` 及两个测试文件。

- **worker 等待。**worker 输出结束后，等待进程退出和读取 stderr 都受运行截止时间约束（用剩余时间调用 `asyncio.wait_for`），不再无限等待。stderr 改用 `stderr_tail` 读取并最多排空一秒（`STDERR_DRAIN_SEC`），不再读到 EOF；并且对每个没有成功结果的运行都会读取，而不只是 Cursor 重试。
- **Cursor 恢复目录。**常驻 Cursor 会话恢复时使用随该会话 id 保存的工作目录。若保存的目录已不存在，则记录警告并以全新的对话和用量开始。本轮结束时恢复原来的工作目录。
- **对话清理。**清理被中断的替换对话时，只查看该进程物理工作目录（其真实路径的 MD5）对应的对话分区，不再遍历所有分区。

[#1296](https://github.com/foolzzz/looper/pull/1296) 改动 `looper/agents/keeper/process.py`、`looper/agents/kept_dirs.py`、`looper/agents/serve.py`、`looper/agents/service.py`、`looper/agents/tiers/worker.py`、`docs/architecture/agent-system.md`、一份计划文档及六个测试文件。

- **keeper 身份。**keeper 复用 `proc_tree.spawn` 已记录的子进程启动时间。读不到启动时间的 keeper 或子进程以 `START_FAILED` 结束，而不是发布 `RUNNING` 状态；已退出的子进程可以正常结束。此类失败时，已启动的子进程会被结束。
- **被拒元数据。**被拒绝的 keeper 状态、manifest、detach 或 grant 文件会连同运行、文件、字段和值一起记录。启动时，在结束 keeper 之前，把它的小 JSON 文件（状态、manifest、detach、grant，每个最多 64 KiB）私密复制到 `<runtime root>/.local/kept-run-quarantine/`，只保留最新 20 份。复制失败会保留运行目录，且不阻塞启动。存在但无法读取的 detach 文件，或存在但无效的 grant 文件，现在按坏文件处理。
- **服务停止预算。**新生成的 launchd plist 带 `ExitTimeOut` 30，新生成的 systemd 单元带 `TimeoutStopSec=30`，高于 serve 15 秒的关闭期限。已安装的服务在重新运行 `looper service install` 之前保持旧设置。
- **脱离预算。**`detach_kept` 有一个八秒的总预算（`KEPT_DETACH_BUDGET_SEC`），涵盖脱离调用和收尾中运行的清理。超时的脱离会被取消并报告为 `BUSY`；若持久的脱离标记已写入，则报告为 `DETACHED`。结果会被记录。
- **面向模型的变化：**两个 PR 均无。提示词、工具描述、schema 和回答文本均未改动。Cursor 恢复的改动影响 CLI 进程使用的目录和对话，不影响发给模型的内容。
