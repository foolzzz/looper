# Looper v2.13.106

## Release Decision

**Who should upgrade:** Anyone who saves provider accounts, skills or channel bots from the dashboard or the API and needs the error to say what to fix, and anyone who reads the API document at `/api/v1/openapi.json`.

**What this release solves:** [#572](https://github.com/foolzzz/looper/pull/572) keeps actionable public errors on credential-bearing operations without exposing submitted values. [#591](https://github.com/foolzzz/looper/pull/591) completes the dashboard move to `/api/v1`: every operation declares a concrete result schema and unused legacy adapters are removed.

**Breaking changes:** No. No route, command or stored data changed; error text on the affected operations is more specific, and the API document is more precise.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#572](https://github.com/foolzzz/looper/pull/572) and [#591](https://github.com/foolzzz/looper/pull/591); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.106
```

## Behavior changes

- **Public errors on credential operations ([#572](https://github.com/foolzzz/looper/pull/572)):** `looper/agents/ops/__init__.py` adds `PublicOpError`, a domain refusal safe to show even for an operation that accepts credentials. In `http_server.py` such an error is re-raised and answered with its own message; any other `OpError` on a credential write is still answered "invalid credential request".
- **Providers:** `v1_domains/providers.py` answers not found ("provider not found"), conflict ("provider account conflict") and invalid ("invalid provider account request") with those fixed messages and the matching status.
- **Channels:** `v1_domains/channel_configs.py` checks the sender allowlist first and answers "invalid sender allowlist: " plus the format hint, never the submitted entry. On create and update, a 400 from the bot service becomes "invalid channel configuration; check the sender allowlist and bot settings", a 404 "Manager not found" (create) or "channel not found", a 409 "this bot is already added; update the existing bot instead". A Lark identity failure (`BotIdentityUnavailable` in `channels/bot_api.py`) keeps its fixed 409 message. Other statuses, such as a 500 with raw exception text, stay private.
- **Skills:** in `v1_domains/catalog.py`, `catalog_items.update` first reads the item; for a skill it calls the skill service directly, which rechecks the kind under lock, and returns its errors as public. Project-skill errors are also mapped. An empty skill patch is no longer rejected by the schema (`minProperties` removed for skills) so the service can explain what to enter; MCP patches keep it.
- **Complete v1 schemas ([#591](https://github.com/foolzzz/looper/pull/591)):** in `looper/agents/api_v1.py`, the untyped result fallback is removed; building the operation list raises "missing concrete result schema" for any operation without one. `confirm` is now registered after all others, with a result `anyOf` the results of operations that need confirmation; `openapi` and the operator chat streams have concrete results.
- **Legacy code removed:** `registryCall`, `putJson`, `failed` and `API_BASE` in `web/src/lib/api.ts`; `_handle_config_export`, `_handle_config_import`, `_answer` and two route patterns in `http_server.py`. The README, architecture and plan documents now name the `/api/v1` routes.
- **Model-visible changes:** None to Manager tool declarations or prompts. The API document served by `/api/v1/openapi.json` changes: its description, the `confirm`, `openapi` and operator chat results, and the client chat stream event schemas (`heartbeat` carries `{}`). A client or model that reads that document sees these; the error messages above are also what a client now receives.
- **Tests:** [#572](https://github.com/foolzzz/looper/pull/572) adds `tests/test_api_v1_catalog_errors.py` and extends the channel, provider, catalog, profile and Manager config tests (279 added test lines, 64 production lines as reported). [#591](https://github.com/foolzzz/looper/pull/591) adds `tests/test_api_v1_migration.py`, `tests/test_api_v1_stage_two_audit.py` and `web/src/lib/v1-migration.test.ts` (202 test lines, 86 production lines as reported).

## Upgrade and rollback

Re-run `install.sh` once v2.13.106 is published. No data migration and no configuration change. Rolling back to v2.13.105 brings back the generic "invalid credential request" on those operations and the untyped result schemas.

## 中文摘要

### 升级决策

**谁需要升级：**在仪表盘或 API 中保存 provider 账户、skill 或渠道 bot、需要错误信息说明如何修正的使用者，以及读取 `/api/v1/openapi.json` 的使用者。

**解决了什么：**[#572](https://github.com/foolzzz/looper/pull/572) 在涉及凭据的操作上保留可操作的公开错误，同时不暴露提交的值。[#591](https://github.com/foolzzz/looper/pull/591) 完成仪表盘向 `/api/v1` 的迁移：每个操作都声明具体的结果 schema，并移除未使用的旧适配器。

**是否有破坏性变更：**否。路由、命令和存储数据均未改变；相关操作的错误文本更具体，API 文档更精确。

**如何验证：**运行 `looper --version` 核对版本为 2.13.106。

**贡献者：**维护者 @foolzzz 提交 [#572](https://github.com/foolzzz/looper/pull/572) 和 [#591](https://github.com/foolzzz/looper/pull/591)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.106
```

### 行为变化与入口

- **凭据操作的公开错误（[#572](https://github.com/foolzzz/looper/pull/572)）：**`looper/agents/ops/__init__.py` 新增 `PublicOpError`，表示即使操作接收凭据也可安全展示的领域拒绝。`http_server.py` 会原样抛出并以其自身消息作答；凭据写入上的其他 `OpError` 仍答复 "invalid credential request"。
- **Provider：**`v1_domains/providers.py` 对未找到、冲突、无效分别返回固定消息（"provider not found"、"provider account conflict"、"invalid provider account request"）和对应状态码。
- **渠道：**`v1_domains/channel_configs.py` 先检查发送者白名单，返回 "invalid sender allowlist: " 加格式提示，不含提交的条目。创建与更新时，bot 服务的 400 变为 "invalid channel configuration; check the sender allowlist and bot settings"，404 变为 "Manager not found"（创建）或 "channel not found"，409 变为 "this bot is already added; update the existing bot instead"。Lark 身份验证失败（`channels/bot_api.py` 的 `BotIdentityUnavailable`）保留固定的 409 消息。其他状态（例如带原始异常文本的 500）仍保持私有。
- **Skill：**`v1_domains/catalog.py` 中，`catalog_items.update` 先读取条目；若为 skill，则直接调用 skill 服务（它在锁内重新检查类型），其错误作为公开错误返回。项目 skill 的错误也做了映射。空的 skill patch 不再被 schema 拒绝（skill 去掉了 `minProperties`），以便服务说明需要填写什么；MCP patch 保持不变。
- **完整的 v1 schema（[#591](https://github.com/foolzzz/looper/pull/591)）：**`looper/agents/api_v1.py` 移除了无类型结果的回退；任何缺少具体结果 schema 的操作都会让构建操作列表抛出 "missing concrete result schema"。`confirm` 现在最后注册，其结果为需要确认的各操作结果的 `anyOf`；`openapi` 和 operator chat 流有了具体结果。
- **移除旧代码：**`web/src/lib/api.ts` 中的 `registryCall`、`putJson`、`failed`、`API_BASE`；`http_server.py` 中的 `_handle_config_export`、`_handle_config_import`、`_answer` 和两个路由正则。README、架构与计划文档现在写明 `/api/v1` 路由。
- **面向模型的变化：**Manager 的 tool 声明和提示词无变化。`/api/v1/openapi.json` 返回的 API 文档有变化：描述、`confirm`、`openapi` 与 operator chat 的结果，以及客户端 chat 流的事件 schema（`heartbeat` 携带 `{}`）。读取该文档的客户端或模型会看到这些；上述错误消息也是客户端现在收到的内容。
- **测试：**[#572](https://github.com/foolzzz/looper/pull/572) 新增 `tests/test_api_v1_catalog_errors.py`，并扩展渠道、provider、catalog、profile 和 Manager 配置测试（按报告新增测试 279 行、生产代码 64 行）。[#591](https://github.com/foolzzz/looper/pull/591) 新增 `tests/test_api_v1_migration.py`、`tests/test_api_v1_stage_two_audit.py` 和 `web/src/lib/v1-migration.test.ts`（按报告测试 202 行、生产代码 86 行）。
