# Looper v2.13.193

## Release Decision

**Who should upgrade:** Operators who want to try the Pi runner for the Manager and Planner of a Pi profile. Everyone else sees no difference, because the default stays on the Pi CLI. It is a hotfix that ships the change merged since v2.13.192.

**What this release solves:** [#829](https://github.com/foolzzz/looper/pull/829) adds the ops-file setting `[runtimes] pi = "runner"`, which puts the Manager and Planner of a Pi profile on the shared Pi runner. Until now the runner was not registered with the service.

**Breaking changes:** No. The default is `pi = "cli"`, so nothing changes without the opt-in. No command, database schema or file format changed; the ops file only gains an optional `[runtimes]` table.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#829](https://github.com/foolzzz/looper/pull/829); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.193
```

## Behavior changes

- **Ops setting (`looper/ops_config.py`):** new key `[runtimes] pi`, `"cli"` (default) or `"runner"`; any other value stops the command with a message naming the key. It is file only: there is no environment variable, flag or dashboard control, and it is read once at startup, so changing it needs a restart. `looper config init-ops` now writes a `[runtimes]` table with the commented `# pi = "cli"` default, or `pi = "runner"` when opted in.
- **Serve wiring (`looper/agents/serve.py`):** when `pi = "runner"` and no runner supervisor was supplied, `_run_agent_system` calls `pi_runner.enable(runtime_root)` and owns the returned supervisor. With the default, nothing is built.
- **Runner adapter (`looper/agents/runtimes/pi_runner.py`, new):** `PiRunnerRuntime` replaces the `pi` adapter and handles only the Manager and Planner; Worker, Reviewer and consults keep the CLI behavior. The runner is one shared process with 10 session slots; further acquisition returns `CAPACITY`, with no runner pool. The Manager and Planner get Pi's default prompt plus the Looper prompt (or the Looper prompt alone in replace mode), written to a private file named by its content hash. Builtin tools are `read, grep, find, ls` for read-only launches and `read, bash, edit, write` otherwise. A provider with environment entries is refused with a message pointing to the CLI path, because they would change process-wide settings. The launch executable must resolve to the same `pi` the runner uses.
- **No CLI fallback (`pi_runner.enable`):** if `node` or `pi` is missing from `PATH`, `node --version` cannot be checked within 2 seconds, or Node is older than 22.19.0, the adapter is installed in an unavailable state and Pi Manager and Planner turns fail with that reason. Nothing falls back to the CLI.
- **Planner errors (`looper/agents/tiers/planner.py`):** a launch rejected before the command exists (`OSError`, `RuntimeUnsupported`) and a start that fails with a runner protocol or RPC error now end the turn as `cannot start <runtime>: …`, recorded in the task's run history, instead of escaping as an unhandled error.
- **Evals (`evals/prompt_regression`):** `run` and `talk` accept `--pi-runner`, which writes `pi = "runner"` into the ops file of the isolated eval server. The default is unchanged.
- **Docs and scope:** `docs/architecture/agent-system.md`, the agent SDK runner RFC and the long-horizon context plan describe the opt-in. 17 files changed, with 825 added and 47 deleted lines; the pull request reports "tests 562, production 144 (fixtures excluded)".
- **Model-visible changes:** None with the default. With `pi = "runner"`, the Pi Manager and Planner system prompt gains the note "Looper's platform tools are named looper_* (for example looper_tasks)" and the model sees the platform tools as `looper_*` directly, without Manager MCP setup or probing; a Planner is offered read, grep, find and ls plus those tools. No prompt, tool description or tool result changed for any other runtime or role.

## Upgrade and rollback

Re-run `install.sh` once v2.13.193 is published. To use the runner, add `[runtimes]` with `pi = "runner"` to the ops file and restart Looper. To roll back, remove the line (or set `pi = "cli"`) and restart; there is no schema change, so returning to v2.13.192 needs nothing else.

## 中文摘要

### 升级决策

**谁需要升级：**想为 Pi profile 的 Manager 和 Planner 试用 Pi runner 的运维者；其他用户无差别，因为默认仍走 Pi CLI。本版本是随合并即发布的 hotfix，包含 v2.13.192 之后合并的改动。

**解决了什么：**[#829](https://github.com/foolzzz/looper/pull/829) 新增 ops 文件设置 `[runtimes] pi = "runner"`，可把 Pi profile 的 Manager 和 Planner 放到共享的 Pi runner 上。此前该 runner 尚未注册到服务。

**是否有破坏性变更：**无。默认值为 `pi = "cli"`，不选择加入则无任何变化。命令、数据库 schema、文件格式均未改变，ops 文件只是多了一个可选的 `[runtimes]` 表。

**如何验证：**运行 `looper --version` 核对版本为 2.13.193。

**贡献者：**维护者 @foolzzz 提交 [#829](https://github.com/foolzzz/looper/pull/829)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.193
```

### 行为变化与入口

- **Ops 设置（`looper/ops_config.py`）：**新增键 `[runtimes] pi`，取值 `"cli"`（默认）或 `"runner"`，其他值会终止命令并提示键名。仅限文件配置：没有环境变量、命令行参数或仪表盘控件，启动时读取一次，修改后需重启。`looper config init-ops` 现在会写入 `[runtimes]` 表，默认为注释掉的 `# pi = "cli"`，已选择加入时为 `pi = "runner"`。
- **服务接线（`looper/agents/serve.py`）：**当 `pi = "runner"` 且未传入 runner supervisor 时，`_run_agent_system` 调用 `pi_runner.enable(runtime_root)` 并接管返回的 supervisor；默认情况下不构建任何东西。
- **Runner 适配器（`looper/agents/runtimes/pi_runner.py`，新文件）：**`PiRunnerRuntime` 取代 `pi` 适配器，只处理 Manager 和 Planner；Worker、Reviewer 和 consult 仍走 CLI。runner 是一个共享进程，有 10 个会话槽位，超出时返回 `CAPACITY`，没有 runner 池。Manager 和 Planner 使用 Pi 默认提示词加 Looper 提示词（replace 模式下只用 Looper 提示词），写入以内容哈希命名的私有文件。只读启动的内置工具为 `read, grep, find, ls`，否则为 `read, bash, edit, write`。带环境变量的 provider 会被拒绝并提示改用 CLI 路径，因为这些变量会改变进程级设置。启动用的可执行文件必须解析为 runner 所用的同一个 `pi`。
- **不回退到 CLI（`pi_runner.enable`）：**`PATH` 中缺少 `node` 或 `pi`、2 秒内无法检查 `node --version`、或 Node 低于 22.19.0 时，适配器以不可用状态安装，Pi 的 Manager 和 Planner 回合带着原因失败，不会回退到 CLI。
- **Planner 错误（`looper/agents/tiers/planner.py`）：**命令生成前被拒绝的启动（`OSError`、`RuntimeUnsupported`）以及以 runner 协议或 RPC 错误失败的启动，现在以 `cannot start <runtime>: …` 结束回合并记入任务的运行历史，而不是作为未处理错误抛出。
- **评测（`evals/prompt_regression`）：**`run` 与 `talk` 接受 `--pi-runner`，在隔离评测服务的 ops 文件中写入 `pi = "runner"`；默认不变。
- **文档与范围：**`docs/architecture/agent-system.md`、agent SDK runner RFC 和长程上下文计划记录了该选项。共改动 17 个文件，新增 825 行、删除 47 行；PR 描述写的是“测试 562 行、生产代码 144 行（不含夹具）”。
- **面向模型的变化：**默认无。启用 `pi = "runner"` 后，Pi 的 Manager 和 Planner 系统提示词多了一句“Looper's platform tools are named looper_* (for example looper_tasks)”，模型直接看到 `looper_*` 平台工具，无需 Manager MCP 配置或探测；Planner 获得 read、grep、find、ls 加这些工具。其他运行时和角色的提示词、工具描述、工具结果均未改变。

### 升级与回退

v2.13.193 发布后重新运行 `install.sh`。要使用 runner，在 ops 文件加入 `[runtimes]` 与 `pi = "runner"` 并重启。回退时删除该行（或设为 `pi = "cli"`）并重启；无 schema 变更，回到 v2.13.192 无需其他操作。
