# Looper v2.14.33

This is the patch release v2.14.33, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.32: command schedules keep firing while the service drains for a planned upgrade ([#962](https://github.com/foolzzz/looper/pull/962)).

## Release Decision

**Who should upgrade:** Anyone who runs command schedules and performs planned hot upgrades with a drain, or who uses "Run now" on a schedule during a drain. Installations without command schedules see only the clearer "Run now" error for agent schedules.

**What this release solves:** [#962](https://github.com/foolzzz/looper/pull/962) opens an exception in the drain's schedule gate. While the service is draining, agent schedules stay paused, but command schedules fire as usual and their starts no longer count toward the `starting` that the drain waits for.

**Breaking changes:** No. No API, default or configuration is removed, and there is no database migration. The one visible change is the status and message of a refused "Run now" during a drain (see below).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#962](https://github.com/foolzzz/looper/pull/962); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.33
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.32 upgrades directly. This release adds no migration.

## Behavior changes

- **Command schedules are exempt from the upgrade drain ([#962](https://github.com/foolzzz/looper/pull/962)).** While the service is `draining` or `drained`:
  - **Scheduler tick.** Queued runs and due fires are still handled, but only for schedules of kind `command`. `lock_next_due` and `schedules_with_queued_runs` in `looper/db/schedules.py` take an optional `kinds` filter for this. Outside a drain the filter is not set and every kind is handled as before.
  - **Admission.** `_admit_start` takes the schedule kind; a command start is always admitted and is not counted in `starting`, so the drain does not wait for it. Agent starts are refused while draining, as before.
  - **Run now.** An agent schedule that is refused during a drain now returns 409 with "the service is draining for an upgrade: run it after the restart". Before, `run_now` returned nothing and the API answered 404 "not found". An unknown schedule still returns 404. Run now on a command schedule works during a drain.
  - **Agent schedules** keep their due times and queued runs for catch-up after the restart or after the drain is cancelled.
  - **Docs.** `docs/architecture/agent-system.md` describes the rule.
- **Model-visible changes:** None. No prompt, tool or message text given to a model changes. The new 409 text appears only in the schedules API response.

## 中文摘要

本版本是 patch release v2.14.33（热修线，每个合并的改动立即发布）。自 v2.14.32 以来只合并了一项改动：服务为计划升级而排空（drain）时，命令类定时任务继续触发（[#962](https://github.com/foolzzz/looper/pull/962)）。

### 升级决策

**谁需要升级：**运行命令类定时任务并用 drain 做计划热升级的人，或在 drain 期间使用“立即运行”的人。没有命令类定时任务的安装，只会看到 agent 定时任务“立即运行”被拒时更清楚的错误。

**解决了什么：**[#962](https://github.com/foolzzz/looper/pull/962) 在 drain 的定时任务闸门上开了一个例外：排空期间 agent 定时任务仍然暂停，但命令类定时任务照常触发，其启动不再计入 drain 所等待的 `starting`。

**是否有破坏性变更：**否。不移除任何 API、默认值或配置，也没有数据库迁移；唯一可见的变化是 drain 期间被拒的“立即运行”的状态码与提示。

**如何验证：**运行 `looper --version` 核对版本为 2.14.33。

**贡献者：**维护者 @foolzzz 提交 [#962](https://github.com/foolzzz/looper/pull/962)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.33
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.32 上的安装可直接升级。本版本没有迁移。

### 行为变化与入口

- **命令类定时任务不受升级 drain 影响（[#962](https://github.com/foolzzz/looper/pull/962)）。**服务处于 `draining` 或 `drained` 时：
  - **调度 tick。**排队的运行和到期的触发仍会处理，但只针对 `command` 类定时任务。`looper/db/schedules.py` 中的 `lock_next_due` 和 `schedules_with_queued_runs` 为此新增可选的 `kinds` 过滤；非 drain 时不设过滤，所有类型照旧处理。
  - **准入。**`_admit_start` 接收定时任务类型；命令类启动总是被允许，且不计入 `starting`，所以 drain 不会等它。agent 类启动在 drain 期间仍被拒绝，与之前一致。
  - **立即运行。**drain 期间被拒的 agent 定时任务现在返回 409，提示 “the service is draining for an upgrade: run it after the restart”。此前 `run_now` 返回空，API 回答 404 “not found”。不存在的定时任务仍返回 404。命令类定时任务在 drain 期间可以立即运行。
  - **agent 定时任务**保留到期时间和排队的运行，在重启后或取消 drain 后补跑。
  - **文档。**`docs/architecture/agent-system.md` 描述了这条规则。
- **面向模型的变化：**无。给模型的提示词、工具或消息文本都不变；新的 409 文本只出现在定时任务 API 的响应中。
