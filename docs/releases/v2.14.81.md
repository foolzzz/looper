# Looper v2.14.81

This is the patch release v2.14.81, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.80: Cursor's CLI can run through TTADK as the new runtime `ttadk-cursor-agent` ([#1085](https://github.com/foolzzz/looper/pull/1085)).

## Release Decision

**Who should upgrade:** Operators who have `ttadk` and `cursor-agent` installed and want Cursor work counted by TTADK like the Codex runs already are. Everyone else can stay.

**What this release solves:** Cursor Agent runs could only start the native `cursor-agent` binary, so TTADK did not see them. [#1085](https://github.com/foolzzz/looper/pull/1085) adds the runtime `ttadk-cursor-agent`, which launches Cursor's CLI with `ttadk code -t cursor-cli`, with the same Cursor Agent behavior otherwise.

**Breaking changes:** No. No setting, schema or operation is removed. The native `cursor-agent` runtime and existing Agent Profiles are unchanged; the new runtime is used only when an Agent Profile selects it.

**How to verify:** Check the installed version. On a machine with `ttadk` and `cursor-agent` on PATH, Agent Runtimes lists `ttadk-cursor-agent` (launcher TTADK); nothing uses it until an Agent Profile does.

**Contributors:** Maintainer @foolzzz authored [#1085](https://github.com/foolzzz/looper/pull/1085); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.81
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.80 upgrades directly. This release has no schema change.

## Behavior changes

- **New runtime `ttadk-cursor-agent`** (`looper/agents/runtimes/cursor_agent.py`, `looper/agents/runtimes/ttadk.py`). The `cursor-agent` runtime type accepts the TTADK launcher; the runtime is named `ttadk-cursor-agent` (id `rt-ttadk-cursor-agent`) by the same rule as `ttadk-codex`, with the capabilities and roles of the native runtime. It is registered when `ttadk` and `cursor-agent` are both on PATH; its detection reports `ttadk <version> / cursor-agent <version>` and keeps the native tool's probe error. The tests expect the row to be created even when `cursor-agent` is missing, carrying that error.
- **Command.** `ttadk code -t cursor-cli --skip-check -- <the native arguments>`; Looper's instructions and the turn prompt still arrive on stdin. The run's launch record gains `launcher` (`kind` ttadk, version, tool `cursor-cli`, mode null).
- **Shim named `agent`** (`write_ttadk_shim`). TTADK runs its `cursor-cli` command, `agent`. Looper writes a shim named `agent` under `<runtime_root>/.local/cursor-agent/ttadk-bin` and puts it first on the run's own `PATH` (Agent settings' variables included). It runs the resolved `cursor-agent`, refuses to run (exit 2) unless `CURSOR_CONFIG_DIR` and `CURSOR_DATA_DIR` are set, and unsets `TTADK_JWT_TOKEN` so Cursor and its shell do not inherit it. It refuses to point at itself. The operator's `HOME` and login are kept.
- **Wrong tool refused.** When TTADK's settings make `cursor-cli` run something other than `agent`, the launch is refused with `WRONG_TOOL` before any login check or process; the message names the configured command. The Agent Profile login check (`agent_settings.py`) and the detection probe apply the same test (new `RuntimeAdapter.ttadk_problem`).
- **Sign-in check for `cursor-cli`** (`ttadk.py`). It runs `ttadk models -t cursor-cli -f json` with the shim first on `PATH` and throwaway Cursor directories, with a 45 s timeout (20 s for other tools). Launches wait for a current answer, with one check per executable and tool at a time. Status views (the TTADK self check) return the cached result and refresh in a background thread; before any result exists they report a new state `checking`, which counts as a warning, not a failure.
- **Hidden failures.** The new test with a stand-in `ttadk` that exits 0 without a `result` event expects the run to fail with Cursor's stderr in the detail, and TTADK's non-JSON stdout preamble (a greeting naming the signed-in account) to appear nowhere Looper stores. No runner code changed for this; the existing runner behavior is now covered for the TTADK launcher.
- **Documentation and tests.** `docs/architecture/agent-system.md` describes the TTADK path; the TTADK launch RFC, `evals/README.md` and a long-horizon plan note are updated. Tests are in `tests/test_ttadk_cursor_agent.py`, `tests/test_ttadk_sign_in.py`, `tests/test_ttadk_doctor.py`, `tests/test_ttadk_registry_db.py`, `tests/test_ttadk_runtime.py` and `tests/test_cursor_agent.py`.
- **Unchanged:** the native `cursor-agent` runtime, `ttadk-codex`, stored data and schema, and Dashboard, Telegram, Lark and CLI runtime selection.
- **Model-visible changes:** None. The instructions and prompt a Cursor run receives are the ones the native runtime sends; the shim, command line and records are not shown to models.

## Validation

It also reports a manual run with the installed `ttadk` and `cursor-agent`: TTADK started Cursor through the shim and passed its stream-json through unchanged; one run returned `pong` with usage, others ended without a result after Cursor's own reconnects, as native runs did at the same time; the sign-in check returned signed in in 8-12 s, and one call hit the 45 s timeout.

### 行为变化与入口

- **新运行时 `ttadk-cursor-agent`**（`looper/agents/runtimes/cursor_agent.py`、`looper/agents/runtimes/ttadk.py`）。`cursor-agent` 运行时类型接受 TTADK 启动器；运行时名称为 `ttadk-cursor-agent`（id `rt-ttadk-cursor-agent`），命名规则与 `ttadk-codex` 相同，能力与角色同原生运行时。PATH 中同时有 `ttadk` 和 `cursor-agent` 时注册；检测结果为 `ttadk <版本> / cursor-agent <版本>`，并保留原生工具的探测错误。测试预期即使缺少 `cursor-agent` 也会创建该行并带上该错误。
- **命令。**`ttadk code -t cursor-cli --skip-check -- <原生参数>`；Looper 的指令和本轮提示仍经 stdin 传入。运行的启动记录新增 `launcher`（`kind` 为 ttadk、版本、工具 `cursor-cli`、mode 为 null）。
- **名为 `agent` 的 shim**（`write_ttadk_shim`）。TTADK 运行其 `cursor-cli` 命令 `agent`。Looper 在 `<runtime_root>/.local/cursor-agent/ttadk-bin` 下写入名为 `agent` 的 shim，并把它放在本次运行自身 `PATH` 的最前（含 Agent settings 的变量）。它运行解析出的 `cursor-agent`；未设置 `CURSOR_CONFIG_DIR` 和 `CURSOR_DATA_DIR` 时拒绝运行（退出码 2）；并取消设置 `TTADK_JWT_TOKEN`，避免 Cursor 及其 shell 继承。它拒绝指向自身。保留操作者的 `HOME` 和登录。
- **拒绝错误的工具。**TTADK 的设置让 `cursor-cli` 运行 `agent` 以外的命令时，启动在任何登录检查或进程之前以 `WRONG_TOOL` 被拒绝，消息写明所配置的命令。Agent Profile 登录检查（`agent_settings.py`）和检测探测使用同一判断（新增 `RuntimeAdapter.ttadk_problem`）。
- **`cursor-cli` 的登录检查**（`ttadk.py`）。以 shim 置于 `PATH` 最前和一次性 Cursor 目录运行 `ttadk models -t cursor-cli -f json`，超时 45 秒（其他工具 20 秒）。启动时等待最新结果，同一可执行文件和工具同一时刻只检查一次。状态视图（TTADK 自检）返回缓存结果并在后台线程刷新；尚无结果时报告新状态 `checking`，按警告而非失败处理。
- **被隐藏的失败。**新测试用一个退出码为 0 但没有 `result` 事件的 `ttadk` 替身：预期该运行失败，详情含 Cursor 的 stderr，TTADK 在 stdout 上的非 JSON 前导（含已登录账号的问候语）不出现在 Looper 保存的任何位置。为此没有修改 runner 代码；已有的 runner 行为现在对 TTADK 启动器也有测试覆盖。
- **文档与测试。**`docs/architecture/agent-system.md` 描述了 TTADK 路径；TTADK 启动 RFC、`evals/README.md` 和一份长程计划笔记也已更新。测试在 `tests/test_ttadk_cursor_agent.py`、`tests/test_ttadk_sign_in.py`、`tests/test_ttadk_doctor.py`、`tests/test_ttadk_registry_db.py`、`tests/test_ttadk_runtime.py` 和 `tests/test_cursor_agent.py`。
- **不变：**原生 `cursor-agent` 运行时、`ttadk-codex`、已存数据和数据库结构，以及 Dashboard、Telegram、Lark 和 CLI 的运行时选择。
- **面向模型的变化：**无。Cursor 运行收到的指令和提示与原生运行时发送的相同；shim、命令行和记录不会展示给模型。
