# Looper v2.13.184

## Release Decision

**Who should upgrade:** Developers and CI that run Looper's fake runner (`runners/fake`) to exercise runner conformance and host close handling. It is a hotfix that ships the changes merged since v2.13.183.

**What this release solves:** [#807](https://github.com/foolzzz/looper/pull/807) makes the fake runner settle a turn exactly once when `session/close` arrives right after a `session/prompt` whose turn has not started yet, so the host's close wait completes (fixes #799).

**Breaking changes:** No. No command, schema or file format changed; only the fake test runner changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#807](https://github.com/foolzzz/looper/pull/807); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.184
```

## Behavior changes

- **The fake runner settles a turn exactly once ([#807](https://github.com/foolzzz/looper/pull/807)):** `runners/fake/main.py` moves the settle step (dropping queued steers, sending the `settled` update, clearing the task and authorizing flag) from the `finally` block of `Fake.turn` into a new `Fake.settle`, guarded by a new `Session.settled` flag. `session/prompt` sets the flag to false when it accepts a turn.
- **Close right after a prompt:** `session/close` now calls `settle` with outcome `cancelled` after cancelling the turn task. A task cancelled before its first step never runs its `finally` block, so previously no `settled` was sent; now exactly one is sent, either by the turn or by the close. Steers still queued are dropped with reason `session_closed`.
- **Scope:** only `runners/fake/main.py` changed in production code. The real runners, the host and the tool surface are unchanged.
- **Tests:** `tests/test_fake_runner.py` is new (107 added lines) and covers a close that follows a prompt at different timings, asserting one `settled` per turn.
- **Model-visible changes:** None. No prompts, tool descriptions, tool schemas or tool results changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.184 is published. There is no schema change, so rolling back to v2.13.183 needs nothing else.

### 升级决策

**解决了什么：**[#807](https://github.com/foolzzz/looper/pull/807) 让 fake runner 在 `session/close` 紧跟在尚未开始的 `session/prompt` 之后到达时，对该回合恰好发出一次 `settled`，使宿主的关闭等待得以完成（修复 #799）。

### 行为变化与入口

- **fake runner 恰好结算一次（#807）：**`runners/fake/main.py` 把结算步骤（丢弃排队的 steer、发送 `settled` 更新、清除任务和授权标志）从 `Fake.turn` 的 `finally` 移到新的 `Fake.settle`，并由新的 `Session.settled` 标志保护。`session/prompt` 接受回合时将该标志置为 false。
- **prompt 之后立即 close：**`session/close` 在取消回合任务后以 `cancelled` 调用 `settle`。在首个步骤之前被取消的任务不会执行 `finally`，因此此前不会发出 `settled`；现在由回合或 close 恰好发出一次。仍在排队的 steer 以 `session_closed` 原因丢弃。
- **范围：**生产代码只改了 `runners/fake/main.py`。真实 runner、宿主和工具接口均未改变。
- **测试：**新增 `tests/test_fake_runner.py`（107 行），覆盖 prompt 之后在不同时机 close 的情形，断言每个回合只有一次 `settled`。
- **面向模型的变化：**无。提示词、工具描述、工具 schema 和工具结果均无变化。
