# Looper v2.13.65

## Release Decision

**Who should upgrade:** Dashboard users and anyone scripting the task gate, wait, role or room HTTP routes. Dashboard users see no change. Scripts that call the removed routes must move to the `/api/v1/` routes.

**What this release solves:** [#474](https://github.com/foolzzz/looper/pull/474) moves the task page's gate list and discussion, wait resume and cancel, task role edits and the task room view to the versioned API (`/api/v1/`), reusing the existing gate, wait, role and room cores. The eight legacy HTTP methods for them are removed.

**Breaking changes:** Yes. The eight legacy methods listed under Behavior changes no longer exist; a client that calls one gets a not-found answer. Stored data and configuration are unchanged.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#474](https://github.com/foolzzz/looper/pull/474); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.65
```

## Behavior changes

- **Removed routes (breaking for API clients):** `GET /api/gates`, `GET /api/tasks/{id}/gates/{step}/messages`, `POST /api/tasks/{id}/gates/{step}/messages`, `POST /api/tasks/{id}/gates/{step}/end`, `POST /api/tasks/{id}/waits/{step}/resume`, `POST /api/tasks/{id}/waits/{step}/cancel`, `PUT /api/tasks/{id}/roles/{key}` and `GET /api/tasks/{id}/room`.
- **Replacements:**
  - Gates use the existing gate operations: `POST /api/v1/ops/gates/list`, `/messages` (takes `task_id` and `gate`), `/reply` and `/end`.
  - Waits: `POST /api/v1/waits/resume` and `/api/v1/waits/cancel`, body `{task_id, step}`.
  - Role edit: `POST /api/v1/tasks/role_update`, body `{task_id, key, role_prompt, harness, profile_id, items?}`; the result still reports `via: "user"`.
  - Room: `POST /api/v1/tasks/room_view`, body `{task_id, kind?, from?, unanswered?, after?, limit?}`; the result is the full room view including consults.
- **Typed results:** the wait, role and room operations declare request and result schemas (closed request schemas reject unknown fields). `tasks.room` has a compact typed result for the existing Manager Tool.
- **Attribution:** a gate message posted through the gates operation without an API client is now sent from the web address and recorded as `dashboard`; with an API client it keeps the Manager address and its own `via`. Wait and role writes take their source from the authenticated principal: the operator uses the web address, an API client its own channel address.
- **Dashboard:** gate list, discussion, wait, role and room calls use the new routes. The gate list is read from the Tool's offset pages (200 rows per request) and paged, and cursors, `through` boundaries and refreshes are computed in the browser; if the list changes while loading, the request fails with a retry message.
- **Scripts:** the prompt-regression runner and dialogs and the DSH validation script use the new routes; `evals/README.md` names the new resume route.
- **Documentation:** the Looper client skill RFC and the long-horizon context plan record the migration.
- **Model-visible changes:** None. No Manager, Worker, Planner or Reviewer prompt changed, and existing Manager Tool schemas are unchanged.

## Upgrade and rollback

Re-run `install.sh` once v2.13.65 is published. No data migration. Update any script or client that called a removed route before upgrading. Rolling back to v2.13.64 restores the legacy routes, with no stored data affected.

### 升级决策

**谁需要升级：**仪表盘用户，以及脚本调用任务关卡、等待、角色或办公台 HTTP 路由的人。仪表盘用户看不到变化；调用已删除路由的脚本需要改用 `/api/v1/` 路由。

**解决了什么：**[#474](https://github.com/foolzzz/looper/pull/474) 把任务页的关卡列表与讨论、等待的恢复与取消、任务角色编辑和任务办公台视图迁到版本化 API（`/api/v1/`），复用现有的关卡、等待、角色和办公台核心，并删除对应的八个旧 HTTP 方法。

**是否有破坏性变更：**是。“行为变化”中列出的八个旧方法不再存在，调用会得到 not found。存储数据和配置不变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.65。

**贡献者：**维护者 @foolzzz 提交 [#474](https://github.com/foolzzz/looper/pull/474)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.65
```

### 行为变化与入口

- **已删除的路由（对 API 客户端是破坏性的）：**`GET /api/gates`、`GET /api/tasks/{id}/gates/{step}/messages`、`POST /api/tasks/{id}/gates/{step}/messages`、`POST /api/tasks/{id}/gates/{step}/end`、`POST /api/tasks/{id}/waits/{step}/resume`、`POST /api/tasks/{id}/waits/{step}/cancel`、`PUT /api/tasks/{id}/roles/{key}`、`GET /api/tasks/{id}/room`。
- **替代路由：**
  - 关卡使用现有关卡操作：`POST /api/v1/ops/gates/list`、`/messages`（参数 `task_id`、`gate`）、`/reply`、`/end`。
  - 等待：`POST /api/v1/waits/resume` 与 `/api/v1/waits/cancel`，请求体 `{task_id, step}`。
  - 角色编辑：`POST /api/v1/tasks/role_update`，请求体 `{task_id, key, role_prompt, harness, profile_id, items?}`；结果仍报告 `via: "user"`。
  - 办公台：`POST /api/v1/tasks/room_view`，请求体 `{task_id, kind?, from?, unanswered?, after?, limit?}`；结果是含咨询的完整办公台视图。
- **类型化结果：**等待、角色、办公台操作声明了请求与结果 schema（封闭的请求 schema 拒绝未知字段）。`tasks.room` 为现有 Manager Tool 提供紧凑的类型化结果。
- **归属：**不带 API 客户端经关卡操作发送的关卡消息，现在以 web 地址发出并记为 `dashboard`；带 API 客户端时仍用 Manager 地址和其自身的 `via`。等待与角色的写入来源取自已认证主体：操作员用 web 地址，API 客户端用其自己的通道地址。
- **仪表盘：**关卡列表、讨论、等待、角色、办公台调用改用新路由。关卡列表按 Tool 的偏移分页读取（每次 200 行），游标、`through` 边界和刷新在浏览器中计算；加载期间列表变化则请求失败并提示重试。
- **脚本：**提示回归的 runner 与 dialogs、DSH 验证脚本改用新路由；`evals/README.md` 写明新的恢复路由。
- **文档：**Looper 客户端 skill RFC 与长程上下文计划记录了此次迁移。
- **面向模型的变化：**无。Manager、Worker、Planner、Reviewer 的 prompt 均未改动，现有 Manager Tool 的 schema 不变。

### 升级与回退

v2.13.65 发布后重跑 `install.sh`。无需迁移数据。升级前请更新调用已删除路由的脚本或客户端。回退到 v2.13.64 会恢复旧路由，不影响已存数据。
