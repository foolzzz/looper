# Looper v2.13.202

## Release Decision

**Who should upgrade:** Nobody needs to upgrade for behavior: this hotfix ships tests and documentation only. Maintainers and operators who try `[runtimes] pi = "runner"` should read the updated documentation. It ships the change merged since v2.13.201.

**What this release solves:** [#848](https://github.com/foolzzz/looper/pull/848) adds an acceptance test for the Pi SDK runner with every role, and updates the documentation to say that the opt-in covers Planner, Worker, Reviewer and consults, not only Manager and Planner.

**Breaking changes:** No. There is no production code change, and commands, settings and the database schema are unchanged.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#848](https://github.com/foolzzz/looper/pull/848); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.202
```

## Behavior changes

- **Runtime behavior:** none. The description of #848 reports "production 0" added lines, and the changed files are one test file, three documents and `evals/README.md`.
- **Test (`tests/test_pi_runner_serve_db.py`, 287 added lines):** two new tests run against an isolated `looper serve` with installed pi 1.3.0, a loopback Responses provider, a throwaway runtime root and a disposable database. `test_pi_runner_task_with_every_role` runs one task with the Planner, two Workers, a Reviewer and a read-only consult on the runner, and asserts the in-trace steer into a running Worker through the Planner chat (`steer_applied` event with the run's trace id), the consult's answered state and its fork directory, and per-role request counts. `test_pi_runner_worker_cancel_crash_and_budget` covers cancel, a runner SIGKILL and a Worker `run_budget_usd` denial. Both skip unless a disposable `LOOPER_TEST_DATABASE_URL` is set.
- **Documentation (`docs/architecture/agent-system.md`, the runner RFC, the plan):** with `[runtimes] pi = "runner"`, the text now says the runner runs Manager, Planner, Worker, Reviewer and consults; all roles share 10 session slots and a further acquisition fails like any start failure; Worker and Reviewer keep read, bash, edit and write, with file tools confined to the task directory and its added directories (bash is not path-confined and is capped by `timeout_seconds`); `max_turns` limits model requests (1000 when unset, `RUN_MAX_REQUESTS` in `looper/agents/runtimes/pi_runner.py`) and run and task spend caps are checked before every request; consults fork a read-only copy of the kept run session and remove the fork afterwards. These describe the existing code; they do not change it.
- **Evals (`evals/README.md`):** documents `run --pi-runner` and `dialogs --pi-runner` (both flags exist in `evals/prompt_regression/__main__.py`) and a nine-task, two-repetition comparison of the Pi CLI path against the runner through a local Responses endpoint. The README states the comparison is prepared and has not been run, and that no real-model gate is claimed.
- **Model-visible changes:** None. No prompt, tool or message text in the product changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.202 is published. There is no data or schema change; rolling back to v2.13.201 needs nothing special.

### 行为变化与入口

- **运行时行为：**无。#848 描述写明新增生产代码 0 行，改动文件为一个测试文件、三份文档和 `evals/README.md`。
- **测试（`tests/test_pi_runner_serve_db.py`，新增 287 行）：**两个新测试在隔离的 `looper serve` 上运行，使用已安装的 pi 1.3.0、loopback Responses provider、一次性运行时根目录和一次性数据库。`test_pi_runner_task_with_every_role` 让 Planner、两个 Worker、Reviewer 和只读咨询都跑在 runner 上，并断言经 Planner 对话引导运行中的 Worker（`steer_applied` 事件带同一 trace id）、咨询的 answered 状态及其分叉目录、各角色请求数。`test_pi_runner_worker_cancel_crash_and_budget` 覆盖取消、runner SIGKILL 和 Worker `run_budget_usd` 拒绝。两者在未设置一次性 `LOOPER_TEST_DATABASE_URL` 时跳过。
- **文档（`docs/architecture/agent-system.md`、runner RFC、计划）：**设置 `[runtimes] pi = "runner"` 后，文档改为说明 runner 运行 Manager、Planner、Worker、Reviewer 和咨询；所有角色共用 10 个会话槽，超出时与其他启动失败一样使步骤失败；Worker 和 Reviewer 保留 read、bash、edit、write，文件工具限制在任务目录及其附加目录内（bash 不限路径，超时受 `timeout_seconds` 限制）；`max_turns` 限制模型请求数（未设置时为 1000，即 `looper/agents/runtimes/pi_runner.py` 的 `RUN_MAX_REQUESTS`），运行与任务花费上限在每次请求前检查；咨询分叉保留运行会话的只读副本并在结束后删除。这些描述现有代码，并不改变它。
- **评测（`evals/README.md`）：**记录 `run --pi-runner` 与 `dialogs --pi-runner`（两个参数均存在于 `evals/prompt_regression/__main__.py`），以及通过本地 Responses 端点对 Pi CLI 路径与 runner 做九任务、每个两次的对照。README 写明该对照已准备但未运行，不声称任何真实模型 gate。
- **面向模型的变化：**无。产品的提示词、工具和消息文本均未改变。
