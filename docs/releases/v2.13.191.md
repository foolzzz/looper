# Looper v2.13.191

## Release Decision

**Who should upgrade:** Maintainers and contributors working on the Pi runner. Other users see no difference. It is a hotfix that ships the change merged since v2.13.190.

**What this release solves:** [#824](https://github.com/foolzzz/looper/pull/824) gives Pi runner sessions builtin tools with path and environment boundaries, adds `session/load` to resume a session from its state directory, and tags retry and compaction requests. The runner is not registered with the service, so no running Looper reaches it yet.

**Breaking changes:** No. No command, database schema or file format changed, and no Python code changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#824](https://github.com/foolzzz/looper/pull/824); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.191
```

## Behavior changes

- **Builtin tools ([#824](https://github.com/foolzzz/looper/pull/824)):** the new `runners/pi/src/exec.ts` builds Pi's `read`, `grep`, `find`, `ls`, `edit`, `write` and `bash` tools for a session. An unknown tool name is refused (`-32602`), and a session with `tools.read_only` set refuses `bash`, `edit` and `write` (`-32008`), so read-only sessions get only `read`, `grep`, `find` and `ls`. Platform tools are still refused at `session/new`.
- **File tool boundary (`exec.ts`):** for every tool except `bash`, the path is resolved against `cwd`, and a path starting with `~` is refused. The canonical path (symlinks resolved, a dangling symlink refused, a new file judged by its resolved parent) must lie inside `cwd` or one of `add_dirs`, which also rejects `..` escapes. The path Pi's own resolver would open is checked again, and the tool then runs on the checked absolute path, so Pi cannot reinterpret `@` or `file:` prefixes. A refused call fails with "Looper blocked <tool>: … is outside the task directory and its added directories".
- **Bash environment (`exec.ts`):** `bash` runs with exactly the session's `env` plus a `HOME` set to the session's `home`. The code does not check the paths a bash command touches, so the path boundary above covers the file tools only; the session's own working directory and environment are what constrain `bash`. `runner/health` now reports the live number of running bash commands as `tool_processes` (it was always 0).
- **Stricter `session/new` (`session.ts`):** besides the earlier checks it now requires an existing absolute `home` and existing absolute `add_dirs`, an `env` object of string values with valid names, a boolean `tools.read_only`, and a `state_dir` and `home` that are not symlinks. The session must hold exactly the requested builtin tools.
- **Resume (`session.ts`, `main.ts`, `rpc.ts`):** new method `session/load` takes the same parameters as `session/new` plus `session_id`. It finds the single `.jsonl` session file in `state_dir` whose header has that id (symlinks are not followed, headers over 64 KiB are skipped) and opens it. No match or several matches fail with `-32001` (session not found); an id already held by this runner fails with `-32002` (session is already owned); a file whose id differs after opening fails with `-32603`. The result carries `resumed: true`. `rpc.ts` orders `session/load` calls by session key, like `session/new`.
- **Request kinds (`provider.ts`, `turn.ts`):** `budget/authorize` and `request_end` now carry `kind` / `request_kind` `compaction` while Pi compacts, `retry` for the request after an automatic retry, and `turn` otherwise (it was always `turn`).
- **Other runner changes:** `sdk.ts` also loads Pi's `path-utils` module and requires its `resolveToCwd` and `resolveReadPathAsync` exports.
- **Scope:** 10 files changed, 518 added and 19 deleted lines, of which 368 added lines are tests. The pull request reports "tests 319, production 0 (fixtures excluded)", which does not count the runner source.
- **Model-visible changes:** None for any running Looper: the runner is not wired to the service, and no prompt, tool description or tool result Looper sends changed. Inside a Pi session, a file tool blocked by the boundary returns the error text quoted above.

### 行为变化与入口

- **内置工具（#824）：**新增的 `runners/pi/src/exec.ts` 为会话构建 Pi 的 `read`、`grep`、`find`、`ls`、`edit`、`write`、`bash` 工具。未知工具名被拒绝（`-32602`）；设置了 `tools.read_only` 的会话拒绝 `bash`、`edit`、`write`（`-32008`），因此只读会话只有 `read`、`grep`、`find`、`ls`。平台工具在 `session/new` 时仍被拒绝。
- **文件工具边界（`exec.ts`）：**除 `bash` 外，路径相对 `cwd` 解析，以 `~` 开头的路径被拒绝。解析符号链接后的规范路径（悬空符号链接被拒绝，新文件按其解析后的父目录判断）必须位于 `cwd` 或某个 `add_dirs` 之内，因此 `..` 逃逸也被拒绝。Pi 自身解析器实际会打开的路径会再检查一次，随后工具以检查过的绝对路径执行，Pi 无法重新解释 `@` 或 `file:` 前缀。被拒绝的调用报错“Looper blocked <工具>: … is outside the task directory and its added directories”。
- **Bash 环境（`exec.ts`）：**`bash` 只带会话的 `env` 加上设为会话 `home` 的 `HOME` 运行。代码不检查 bash 命令访问的路径，因此上述路径边界只覆盖文件工具；约束 `bash` 的是会话自己的工作目录与环境。`runner/health` 的 `tool_processes` 现在报告正在运行的 bash 命令数（此前恒为 0）。
- **更严格的 `session/new`（`session.ts`）：**除原有检查外，现在要求存在的绝对路径 `home` 与 `add_dirs`、值均为字符串且名称合法的 `env` 对象、布尔值 `tools.read_only`，且 `state_dir` 与 `home` 不是符号链接。会话必须恰好持有所请求的内置工具。
- **恢复（`session.ts`、`main.ts`、`rpc.ts`）：**新方法 `session/load` 参数同 `session/new` 并加 `session_id`。它在 `state_dir` 中查找头部 id 匹配的唯一 `.jsonl` 会话文件（不跟随符号链接，跳过超过 64 KiB 的头部）并打开。无匹配或多个匹配返回 `-32001`（会话不存在）；该 id 已被本 runner 持有返回 `-32002`（会话已被占用）；打开后 id 不一致返回 `-32603`。结果带 `resumed: true`。`rpc.ts` 像 `session/new` 一样按 session key 对 `session/load` 排序。
- **请求类型（`provider.ts`、`turn.ts`）：**`budget/authorize` 与 `request_end` 的 `kind` / `request_kind` 现在在 Pi 压缩期间为 `compaction`，自动重试后的请求为 `retry`，其余为 `turn`（此前恒为 `turn`）。
- **其他 runner 改动：**`sdk.ts` 额外加载 Pi 的 `path-utils` 模块，并要求其导出 `resolveToCwd` 与 `resolveReadPathAsync`。
- **范围：**改动 10 个文件，新增 518 行、删除 19 行，其中新增的 368 行为测试。该 PR 描述写的是“测试 319 行、生产代码 0 行（不含夹具）”，未计入 runner 源码。
- **面向模型的变化：**对运行中的 Looper 无：runner 未接入服务，Looper 发送的提示词、工具描述和工具结果均未改变。在 Pi 会话内，被边界拦下的文件工具会返回上述错误文本。
