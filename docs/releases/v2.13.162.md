# Looper v2.13.162

## Release Decision

**Who should upgrade:** Nobody needs to. This release adds an internal wire-contract module that nothing in Looper calls yet, plus a test-only dependency; contributors who plan work on agent SDK runners will find the contract. Everyone else can stay on v2.13.161.

**What this release solves:** [#740](https://github.com/foolzzz/looper/pull/740) defines the typed core wire messages and the bounded line-feed framing for the agent SDK runner protocol (version 0.1), with a small JSON Schema and positive and negative test vectors, as the first code of stage S0 of the runner RFC.

**Breaking changes:** No. No existing API, database, configuration, prompt or Tool declaration changed, and no runtime path imports the new module.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#740](https://github.com/foolzzz/looper/pull/740); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.162
```

## Behavior changes

- **Runtime behavior:** none. The merged range adds `looper/agents/runtimes/runner/` (`__init__.py` and `protocol.py`), which no other module under `looper/` imports, so no command, API, task or session behaves differently.
- **Runner wire contract ([#740](https://github.com/foolzzz/looper/pull/740)):** `protocol.py` declares protocol version `0.1` and typed shapes for the JSON-RPC 2.0 messages between Looper and a runner: `initialize`, `session/new`, `session/prompt`, `session/steer`, `session/cancel`, `session/close`, the `session/update` notification (text delta, message, tool result, request end, steer applied or dropped, settled), and the runner-to-host `tools/call` and `budget/authorize` requests. Decoding rejects unknown methods, missing or mistyped fields, negative counts, empty names, malformed ids (`l-N` for host requests, `r-N` for runner requests) and a request sent in the wrong direction; errors carry one of the defined codes (the JSON-RPC codes plus -32001 to -32013 such as `SESSION_BUSY`, `TRACE_MISMATCH`, `VERSION_MISMATCH`). Decoded payloads print as a placeholder so credentials and tool input stay out of logs and error messages. `validate_initialize` requires cancel support, per-request usage and the requested `authorize_covers` kinds.
- **Framing ([#740](https://github.com/foolzzz/looper/pull/740)):** a frame is one UTF-8 JSON object ended by a line feed, at most 4 MiB. `encode_frame` refuses NaN, oversized and invalid messages; `read_frame` reads from an asyncio stream, signals clean end of input with `EOFError`, and raises `ProtocolError` for truncated, oversized, non-JSON or invalid frames. The docstring states that owners close the connection on any `ProtocolError`.
- **Schema and vectors ([#740](https://github.com/foolzzz/looper/pull/740)):** `runners/protocol/messages.schema.json` and `runners/protocol/cases.json` are shared vectors for future non-Python runners. `tests/test_runner_protocol.py` checks each vector against the schema and the Python decoder, through real operating-system pipes with the frame split across writes.
- **Dependency:** `pyproject.toml` adds `jsonschema>=4.23,<5` to the `test` extra only. The runtime dependencies are unchanged.
- **Model-visible changes:** none. No prompt, tool description or tool schema changed; the platform tool shapes in the contract are declarations for a future runner and are not sent to any model.
- **Tests:** the description of [#740](https://github.com/foolzzz/looper/pull/740) reports "Added lines: tests 0, production 0 (fixtures excluded)", which does not match the diff (138 test lines and 322 production lines added); this draft takes the file list as authoritative.

### 行为变化与入口

- **运行时行为：**无。合并范围新增 `looper/agents/runtimes/runner/`（`__init__.py` 和 `protocol.py`），`looper/` 下没有其他模块导入它，因此没有命令、API、任务或会话的行为发生变化。
- **Runner 线路协议（#740）：**`protocol.py` 声明协议版本 `0.1`，并为 Looper 与 runner 之间的 JSON-RPC 2.0 消息定义带类型的结构：`initialize`、`session/new`、`session/prompt`、`session/steer`、`session/cancel`、`session/close`、`session/update` 通知（文本增量、消息、工具结果、请求结束、steer 已应用或已丢弃、settled），以及 runner 向宿主发起的 `tools/call` 和 `budget/authorize` 请求。解码会拒绝未知方法、缺失或类型错误的字段、负数计数、空名称、格式错误的 id（宿主请求用 `l-N`，runner 请求用 `r-N`）以及方向错误的请求；错误使用已定义的错误码（JSON-RPC 标准码加 -32001 至 -32013，如 `SESSION_BUSY`、`TRACE_MISMATCH`、`VERSION_MISMATCH`）。解码后的载荷打印为占位符，凭据和工具输入不会进入日志和错误信息。`validate_initialize` 要求支持取消、逐请求用量以及所请求的 `authorize_covers` 类型。
- **分帧（#740）：**一帧是以换行符结尾的一个 UTF-8 JSON 对象，最大 4 MiB。`encode_frame` 拒绝 NaN、超长和无效消息；`read_frame` 从 asyncio 流读取，输入正常结束时抛出 `EOFError`，帧被截断、超长、不是 JSON 或无效时抛出 `ProtocolError`。文档字符串说明持有方遇到任何 `ProtocolError` 都应关闭连接。
- **Schema 与向量（#740）：**`runners/protocol/messages.schema.json` 和 `runners/protocol/cases.json` 是供未来非 Python runner 共用的向量。`tests/test_runner_protocol.py` 用真实操作系统管道（帧被拆成多次写入）把每个向量同时对照 schema 和 Python 解码器检查。
- **依赖：**`pyproject.toml` 仅在 `test` extra 中增加 `jsonschema>=4.23,<5`，运行时依赖不变。
- **面向模型的变化：**无。prompt、工具描述和工具 schema 均未改变；协议中的平台工具结构是为未来 runner 准备的声明，不会发给任何模型。
- **测试：**[#740](https://github.com/foolzzz/looper/pull/740) 的描述写“Added lines: tests 0, production 0 (fixtures excluded)”，与 diff（新增 138 行测试、322 行生产代码）不符；本草稿以文件清单为准。
