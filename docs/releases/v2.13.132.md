# Looper v2.13.132

## Release Decision

**Who should upgrade:** Nobody needs to upgrade for existing behavior. Operators and contributors who work with chat-bound Managers and want the architecture documents to match what is merged should upgrade, because the documents now describe it.

**What this release solves:** [#662](https://github.com/foolzzz/looper/pull/662) adds end-to-end tests for chat-bound Managers (rebinding, bound-only silence, the generated operator CLI, native stop, client-token refusal, and the two Settings pages) and brings the agent-system document, the scenario-Managers RFC and the long-horizon plan up to date with the merged behavior.

**Breaking changes:** No. The change is documentation and tests only. No production code, API, schema or configuration changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#662](https://github.com/foolzzz/looper/pull/662); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.132
```

## Behavior changes

- **No runtime behavior change (#662):** the description reports production 0 added lines, and the file list contains only three documents and two test files. Nothing under `looper/` or `web/` changes.
- **New database-backed tests (#662):** `tests/test_chat_binding_delivery_db.py` adds tests, run for Telegram, Lark and Lark bot transports where parametrized, that cover: a rebind keeping an in-flight reply, task reports and history with the original owner; hot bound-only silence and explicit owner admission; the generated operator CLI discovering and running all five binding and policy operations; native stop reaching every owner even when the new destination is off; and a real client being unable to request or confirm the operator binding operations.
- **New browser tests (#662):** `tests/test_chat_binding_settings_browser.py` covers both Settings pages sharing binding readback, and a real settings restart with an encoded history link keeping the stored owner. They skip when Playwright or Chromium is missing.
- **Architecture document (#662):** `docs/architecture/agent-system.md` now describes the stable thread rule (`<type>:<chat_id>` for built-in bots, `<channel_id>:<chat_id>` for added bots, `#<manager_id>` for a destination other than the bot's owner), stop through `ManagerFleet.stop_chat` across all Managers for the exact bot and chat, the new tables (`manager_chat_bindings`, `channel_seen_chats`, `channel_unbound_chats`) and the top-level `bound_chats_only` column, the five operator operations, which settings apply immediately versus after a restart, and downgrade guidance.
- **RFC and plan (#662):** the scenario-Managers RFC (Chinese) records the merged stage 3 behavior and the plan lists the stage 3 pull requests. Both state that final stage 3 acceptance stays pending: the routing and control paths still lack the required channel, chat and destination log fields, seven recommended semantics await maintainer confirmation, and a real-model Codex smoke test was not run for lack of isolated credentials.
- **Model-visible changes:** none found. The diff touches no prompt, tool declaration or tool result.
- **Line counts:** the description reports tests 525 and production 0 added lines (fixtures excluded).
