# Looper v2.13.136

## Release Decision

**Who should upgrade:** Nobody needs to. This release only changes documentation. Everyone can stay on v2.13.135.

**What this release solves:** [#673](https://github.com/foolzzz/looper/pull/673) points the long-horizon plan's M9d milestone (table row and section) at the approved Norma loop for the `api` runtime, instead of the earlier "wait for a Norma SDK" wording.

**Breaking changes:** No. No code, API, schema or configuration changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#673](https://github.com/foolzzz/looper/pull/673); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.136
```

## Behavior changes

- **Documentation only (#673):** the PR changes one file, `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md` (3 added, 3 removed lines). None of it is implemented by this release:
  - The M9d row is renamed "SDK 运行时与 Norma 循环移植" and its status changes from "待定（norma 就绪后）" to delivery under §5.0 item 23: the `api` runtime, with stage 1 porting the Norma loop (linked to the API runtime RFC).
  - The M9d section heading is renamed the same way, and its scope now says there is one `api` runtime, stage 1 ports the Norma loop to typed asyncio Python, and the only later upstream is the copy of the Go port at `loopgo-main:go/internal/norma`. No `norma` runtime type is added and nothing waits for a separate Norma SDK.
- **Runtime behavior:** none. No Python, web or configuration file is touched.
- **Model-visible changes:** none found. The diff touches no prompt, tool declaration or tool result.
- **Line counts:** the description reports tests 0 and production 0 added lines (fixtures excluded).

## Upgrade and rollback

Re-run `install.sh` once v2.13.136 is published. No schema or configuration change. Rolling back to v2.13.135 only restores the earlier wording of the M9d row and section.
