# Looper v2.13.171

## Release Decision

**Who should upgrade:** Nobody needs to act. This release changes the runner bridge that nothing in Looper calls yet, and a release check script. It is a hotfix that ships the changes merged since v2.13.170.

**What this release solves:** [#769](https://github.com/foolzzz/looper/pull/769) gives runner session close one explicit state machine, so a close that fails, is rejected or times out stays local to its session and keeps its capacity until cleanup completes. [#771](https://github.com/foolzzz/looper/pull/771) stops the release wheel smoke from running the removed `loopx` command, which blocked the v2.13.170 release.

**Breaking changes:** No. No database schema, API, Tool declaration or command changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#769](https://github.com/foolzzz/looper/pull/769) and [#771](https://github.com/foolzzz/looper/pull/771); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.171
```

## Behavior changes

- **Runner close state ([#769](https://github.com/foolzzz/looper/pull/769)):** `looper/agents/runtimes/runner/bridge.py` adds `CloseState` (`open`, `closing`, `closed`, `close_failed`, `poisoned`) per session, and `State` now only describes turn activity (`opening`, `idle`, `running`). Transitions are checked; `poisoned` is irreversible. Starting a turn, cancelling or steering is refused unless the session is `open`.
- **Close attempts ([#769](https://github.com/foolzzz/looper/pull/769)):** `close_session` runs the close as a task owned by the bridge, so a caller that stops waiting does not abandon it, and returns the resulting `CloseState`. A failed close marks the session `close_failed`, settles an active turn locally as failed ("runner session close failed") and can be retried; the session stays registered and keeps its capacity. A successful close settles the active turn before the session is removed.
- **Tombstones ([#769](https://github.com/foolzzz/looper/pull/769)):** a closed session leaves a tombstone, kept for up to 128 entries and 600 seconds. Late updates for a tombstoned session are dropped, and a new session reusing a tombstoned id is treated as a duplicate session id and fails the connection.
- **Abandoned controls ([#769](https://github.com/foolzzz/looper/pull/769)):** the bounded abandoned-request table, previously for `session/cancel`, now also covers `session/close` (limit 128 together), so a timed-out or cancelled close no longer fails the connection and its late response is dropped.
- **Supervisor ([#769](https://github.com/foolzzz/looper/pull/769)):** releasing a lease whose close was rejected, failed or timed out now keeps the lease and its directory, so release can be retried; the directory is removed once the close succeeds or the generation has failed. `release` can be called again after a failed attempt.
- **Release smoke ([#771](https://github.com/foolzzz/looper/pull/771)):** `examples/release/agent-serve-wheel-smoke.py` no longer calls `loopx --version`; it asserts the wheel does not install `bin/loopx`. The `looper --version` check stays. Only the release workflow runs it.
- **Reach:** nothing outside the runner package imports the runner bridge or supervisor, so no running Looper behavior changes.
- **Model-visible changes:** none found. The diff changes no prompt, tool description or tool schema.

## Upgrade and rollback

Re-run `install.sh` once v2.13.171 is published. Rolling back to v2.13.170 restores the previous runner close handling and the smoke check that fails on the removed `loopx` command.

**贡献者：**维护者 @foolzzz 提交 [#769](https://github.com/foolzzz/looper/pull/769) 和 [#771](https://github.com/foolzzz/looper/pull/771)；本次 patch release 无社区贡献。

### 行为变化与入口

- **runner 关闭状态（#769）：**`bridge.py` 为每个会话新增 `CloseState`（`open`、`closing`、`closed`、`close_failed`、`poisoned`），`State` 只描述回合活动（`opening`、`idle`、`running`）。状态转换受检查，`poisoned` 不可逆。会话不是 `open` 时，开始回合、取消和 steer 均被拒绝。
- **关闭尝试（#769）：**`close_session` 把关闭作为由 bridge 持有的任务运行，调用方不再等待也不会放弃它，并返回结果 `CloseState`。关闭失败会把会话标为 `close_failed`，在本地把进行中的回合结算为失败（"runner session close failed"），可重试；会话保持登记并保留容量。关闭成功时先结算进行中的回合，再移除会话。
- **墓碑（#769）：**已关闭会话留下墓碑，最多保留 128 条、600 秒。对墓碑会话的迟到更新被丢弃；新会话复用墓碑中的会话 id 会被视为重复 id 并使连接失败。
- **被放弃的控制请求（#769）：**原本只覆盖 `session/cancel` 的有界放弃请求表现在也覆盖 `session/close`（合计上限 128），因此超时或被取消的关闭不再使连接失败，其迟到响应被丢弃。
- **Supervisor（#769）：**释放租约时若关闭被拒绝、失败或超时，会保留租约及其目录以便重试；关闭成功或该 generation 已失败后才删除目录。失败后可再次调用 `release`。
- **发布冒烟检查（#771）：**`examples/release/agent-serve-wheel-smoke.py` 不再调用 `loopx --version`，改为断言 wheel 未安装 `bin/loopx`；`looper --version` 检查保留。仅发布工作流运行它。
- **影响范围：**runner 包之外没有代码导入 runner bridge 或 supervisor，运行中的 Looper 行为不变。
- **面向模型的变化：**未发现。diff 未改动 prompt、工具描述或工具 schema。
