# Looper v2.13.173

## Release Decision

**Who should upgrade:** Anyone who exports or imports Looper configuration, or who still sets the deprecated `LOOPER_SCHEDULE_MIN_INTERVAL_SECONDS` variable. Files older than `looper-config/v4` are no longer accepted. It is a hotfix that ships the change merged since v2.13.172.

**What this release solves:** [#761](https://github.com/foolzzz/looper/pull/761) makes `looper-config/v4` the only configuration format Looper writes and reads, rejects older documents and unknown top-level fields before any work begins, and keeps only the persisted scheduler minimum interval setting.

**Breaking changes:** Yes. Configuration files in `looper-config/v1`, `loopx-config/v1`, `looper-config/v2` and `looper-config/v3` are refused, and so are files with a `loopx_version` or other unknown top-level field. The `LOOPER_SCHEDULE_MIN_INTERVAL_SECONDS` and `LOOPX_SCHEDULE_MIN_INTERVAL_SECONDS` variables no longer apply. No database schema or command changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#761](https://github.com/foolzzz/looper/pull/761); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.173
```

## Behavior changes

- **Only v4 is accepted ([#761](https://github.com/foolzzz/looper/pull/761)):** in `looper/agents/config_transfer.py`, `FORMAT` is `looper-config/v4`. `validate_format` refuses any other `format` with "supplied format ...; required format looper-config/v4. Import old files on v2.13.165, upgrade that installation/database, then export v4 with the new release." `validate_document` also refuses a top-level field outside `format`, `looper_version`, `exported_at`, `secrets`, `runtimes`, `providers`, `models`, `profiles`, `settings`, `channels`, `catalog`, `installs`, `projects` and `managers`, and `managers` must be a list. `read_file` and `import_config` both run the check. The v1 `agents` to `profiles` conversion, the pre-Agent-Profile layer `model` and `effort` conversion, the legacy registry conversion of providers and profiles, and the `loopx_version` fallback are removed. A layer with a `model` or `effort` field is now an unknown-field skip.
- **Export always v4 ([#761](https://github.com/foolzzz/looper/pull/761)):** the export format is always `looper-config/v4`, and each channel entry always carries `manager_id`. The `managers` section is still written only when the install has a non-default Manager, a non-built-in channel or Manager installs.
- **Import validation timing ([#761](https://github.com/foolzzz/looper/pull/761)):** the HTTP schema `CONFIG_DOCUMENT` in `looper/agents/api_v1.py` is a single closed v4 object instead of a union of versions. In `looper/agents/config_imports.py`, a pending import whose file fails validation (`ConfigFileError`) is discarded instead of staying pending; other failures still leave it pending without writing configuration.
- **Layer environment ([#761](https://github.com/foolzzz/looper/pull/761)):** the Claude Code agent teams switch is dropped from the environment of a layer on export and on import, because only the Agent Profile owns it.
- **Runtimes on import ([#761](https://github.com/foolzzz/looper/pull/761)):** the module documents runtimes as destination-local: a referenced runtime resolves by name and type, else the built-in runtime of its type with a note, and an import never creates a runtime or changes its executable. An in-process runtime is skipped only when its probe reports an error.
- **Scheduler minimum interval ([#761](https://github.com/foolzzz/looper/pull/761)):** `looper/agents/scheduler_settings.py` no longer reads the environment variable or logs its deprecation warning. Without a stored value the minimum interval is the built-in 300 seconds, and the reported source is `setting` or `built-in`; `env` is removed from the settings page schema, from `web/src/lib/api.ts` and from the Scheduler settings page text. Resetting the value to the built-in no longer checks the variable first.
- **Model-visible changes:** none. The diff changes no prompt, tool description or tool schema sent to a model.

## Upgrade and rollback

Re-run `install.sh` once v2.13.173 is published. Before upgrading, export configuration that must survive from an older Looper as `looper-config/v4`; to convert an older file, import it on v2.13.165, upgrade that installation, then export again. Replace any use of the scheduler variable with the minimum interval in Settings, Scheduler. Rolling back to v2.13.172 restores the older formats and the variable.

## 中文摘要

### 升级决策

**谁需要升级：**导出或导入 Looper 配置的用户，以及仍在设置已弃用的 `LOOPER_SCHEDULE_MIN_INTERVAL_SECONDS` 变量的用户。早于 `looper-config/v4` 的文件不再被接受。本版本是随合并即发布的 hotfix。

**解决了什么：**[#761](https://github.com/foolzzz/looper/pull/761) 让 `looper-config/v4` 成为 Looper 唯一读写的配置格式，在开始工作前拒绝旧文档和未知顶层字段，并只保留持久化的调度器最小间隔设置。

**是否有破坏性变更：**是。`looper-config/v1`、`loopx-config/v1`、`looper-config/v2`、`looper-config/v3` 文件会被拒绝，带 `loopx_version` 或其他未知顶层字段的文件也是。`LOOPER_SCHEDULE_MIN_INTERVAL_SECONDS` 和 `LOOPX_SCHEDULE_MIN_INTERVAL_SECONDS` 变量不再生效。数据库 schema 和命令未改变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.173。

**贡献者：**维护者 @foolzzz 提交 [#761](https://github.com/foolzzz/looper/pull/761)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.173
```

### 行为变化与入口

- **只接受 v4（#761）：**`FORMAT` 为 `looper-config/v4`。`validate_format` 拒绝其他 `format`，提示在 v2.13.165 上导入旧文件、升级该安装或数据库后再用新版本导出 v4。`validate_document` 还拒绝不在白名单内的顶层字段，且 `managers` 必须是列表。`read_file` 和 `import_config` 都会检查。v1 的 `agents` 到 `profiles` 转换、Agent Profile 之前的层 `model`/`effort` 转换、provider 与 profile 的旧注册表转换以及 `loopx_version` 回退均被移除；带 `model` 或 `effort` 的层现在作为未知字段被跳过。
- **导出始终为 v4（#761）：**导出格式始终是 `looper-config/v4`，每个渠道条目始终带 `manager_id`。仅当安装有非默认 Manager、非内置渠道或 Manager 安装项时才写 `managers` 部分。
- **导入校验时机（#761）：**`api_v1.py` 中的 HTTP schema `CONFIG_DOCUMENT` 是单一封闭的 v4 对象，而非多版本联合。`config_imports.py` 中，文件校验失败（`ConfigFileError`）的待处理导入会被丢弃；其他失败仍保持待处理且不写入配置。
- **层环境变量（#761）：**导出和导入时，从层的环境变量中去掉 Claude Code agent teams 开关，因为只有 Agent Profile 拥有它。
- **导入时的运行时（#761）：**运行时按目标机器本地处理：按名称和类型匹配，否则用同类型内置运行时并附说明；导入不会创建运行时或更改其可执行文件。进程内运行时仅在探测报错时才被跳过。
- **调度器最小间隔（#761）：**`scheduler_settings.py` 不再读取环境变量，也不再记录弃用警告。没有存储值时最小间隔为内置的 300 秒，来源为 `setting` 或 `built-in`；`env` 已从设置页 schema、`web/src/lib/api.ts` 和调度器设置页文本中移除。把值重置为内置值时不再先检查该变量。
- **面向模型的变化：**无。diff 未改动任何发给模型的 prompt、工具描述或工具 schema。

### 升级与回退

在 v2.13.173 发布后重新运行 `install.sh`。升级前，请把需要保留的旧版配置导出为 `looper-config/v4`；转换旧文件需先在 v2.13.165 上导入、升级该安装后再导出。请用「设置 → 调度器」中的最小间隔替代该环境变量。回退到 v2.13.172 会恢复旧格式和该变量。
