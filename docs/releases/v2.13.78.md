# Looper v2.13.78

## Release Decision

**Who should upgrade:** Anyone who runs the dashboard Chat page, or who calls the removed `/api/chat/targets`, `/api/chat/sessions` or `/api/chat/messages` routes from a script. Everyone else gets no change.

**What this release solves:** [#510](https://github.com/foolzzz/looper/pull/510) moves the Chat page's target list, conversation list, message history and message saving onto four typed operator-only operations in the versioned API, and removes the five legacy methods behind them.

**Breaking changes:** Yes. `GET /api/chat/targets`, `GET /api/chat/sessions`, `GET /api/chat/messages` and `POST /api/chat/messages` are removed; a script that calls them must use `POST /api/v1/operator_chat/{targets,sessions,messages,save_message}` with an operator credential. The dashboard shipped in this release already does.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#510](https://github.com/foolzzz/looper/pull/510); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.78
```

## Behavior changes

- **Chat history on v1 ([#510](https://github.com/foolzzz/looper/pull/510)):** the new `looper/agents/v1_domains/operator_chat_history.py` registers `operator_chat.targets`, `operator_chat.sessions`, `operator_chat.messages` (risk `read`) and `operator_chat.save_message` (risk `write`), all `POST /api/v1/operator_chat/<action>` and all operator-only, so an API client or a Manager cannot reach them. `targets` returns a closed list of Manager, Planner, Worker and Reviewer targets. `sessions` takes optional `manager` and `session_id`; `messages` requires `session_id`; `save_message` takes `session_id`, `message_id`, `role` and `content`. Their results are closed objects.
- **Removed routes:** the five legacy methods in `looper/agents/http_server.py` (targets, sessions, messages, save message, and their `GET`/`POST` routes on `/api/chat/targets`, `/api/chat/sessions`, `/api/chat/messages`) are deleted. `/api/chat/send` and `/api/chat/events` are unchanged.
- **Ownership is kept:** a thread that belongs to another Manager still answers a conflict that names the owner (now a v1 `CONFLICT` error with `manager_id` in its details, no longer a bare 409 body); an unknown Manager still answers not found for `sessions`.
- **Failures are no longer hidden:** per the module's own description, a database read failure now answers unavailable instead of an empty history, and a failed save answers unavailable instead of `ok`. The legacy `messages` read returned an empty list on any error and the legacy save always returned `ok`. In the dashboard, `saveChatMessage` now throws when the save fails instead of ignoring it.
- **Dashboard:** `web/src/lib/api.ts` calls the four operations (`fetchChatTargets`, `fetchChatMessages`, `fetchChatSessions`, `fetchChatSession`, `saveChatMessage`) and turns a 202 or a conflict into the same errors the page already handled.
- **Docs and tests:** `README.md`, `README.zh-CN.md`, `docs/architecture/agent-system.md` and `docs/design.md` name the new routes; the new `tests/test_api_v1_operator_chat_history.py` and `..._db.py` and the updated chat, prompt-evaluation, DSH and dashboard tests cover them.
- **Model-visible changes:** None. The operations declare no Tool, so no Manager, Worker, Planner or Reviewer prompt and no Manager Tool changed.
- **Not confirmed in code:** this draft did not run the failure paths; the unavailable answers come from the module description, not from a test run here.

## Upgrade and rollback

Re-run `install.sh` once v2.13.78 is published. No data migration; stored conversations and messages are unchanged. Update any script that used the removed `/api/chat/targets`, `/api/chat/sessions` or `/api/chat/messages` routes. Rolling back to v2.13.77 restores them together with the old dashboard.

### 升级决策

**谁需要升级：**使用仪表盘 Chat 页面的人，或在脚本中调用已移除的 `/api/chat/targets`、`/api/chat/sessions`、`/api/chat/messages` 路由的人。其他人无变化。

**解决了什么：**[#510](https://github.com/foolzzz/looper/pull/510) 把 Chat 页面的目标列表、会话列表、消息历史和消息保存迁到版本化 API 中四个带类型、仅限操作员的操作，并删除其背后的五个旧方法。

**是否有破坏性变更：**有。`GET /api/chat/targets`、`GET /api/chat/sessions`、`GET /api/chat/messages` 和 `POST /api/chat/messages` 已移除；调用它们的脚本须改用带操作员凭据的 `POST /api/v1/operator_chat/{targets,sessions,messages,save_message}`。本版本附带的仪表盘已改用新操作。

**如何验证：**运行 `looper --version` 核对版本为 2.13.78。

**贡献者：**维护者 @foolzzz 提交 [#510](https://github.com/foolzzz/looper/pull/510)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.78
```

### 行为变化与入口

- **Chat 历史迁到 v1（[#510](https://github.com/foolzzz/looper/pull/510)）：**新增 `looper/agents/v1_domains/operator_chat_history.py`，注册 `operator_chat.targets`、`operator_chat.sessions`、`operator_chat.messages`（风险 `read`）和 `operator_chat.save_message`（风险 `write`），均为 `POST /api/v1/operator_chat/<action>` 且仅限操作员，API 客户端和 Manager 都无法调用。`targets` 返回封闭的 Manager、Planner、Worker、Reviewer 目标列表。`sessions` 可选 `manager` 和 `session_id`；`messages` 必须带 `session_id`；`save_message` 接收 `session_id`、`message_id`、`role`、`content`。结果均为封闭对象。
- **移除的路由：**`looper/agents/http_server.py` 中的五个旧方法（targets、sessions、messages、保存消息，及 `/api/chat/targets`、`/api/chat/sessions`、`/api/chat/messages` 上的 `GET`/`POST` 路由）已删除。`/api/chat/send` 和 `/api/chat/events` 不变。
- **归属保持：**属于另一个 Manager 的线程仍返回指明所有者的冲突（现为 v1 的 `CONFLICT` 错误，所有者 `manager_id` 在 details 中，不再是裸 409 响应体）；`sessions` 对未知 Manager 仍返回未找到。
- **失败不再被掩盖：**按该模块自身说明，数据库读取失败现返回 unavailable 而非空历史，保存失败返回 unavailable 而非 `ok`。旧的 `messages` 读取在任何错误时返回空列表，旧的保存总是返回 `ok`。在仪表盘中，`saveChatMessage` 保存失败时现会抛出错误，不再忽略。
- **仪表盘：**`web/src/lib/api.ts` 调用这四个操作（`fetchChatTargets`、`fetchChatMessages`、`fetchChatSessions`、`fetchChatSession`、`saveChatMessage`），并把 202 或冲突转成页面原本处理的同类错误。
- **文档与测试：**`README.md`、`README.zh-CN.md`、`docs/architecture/agent-system.md`、`docs/design.md` 改用新路由；新增 `tests/test_api_v1_operator_chat_history.py` 与 `..._db.py`，并更新聊天、prompt 评测、DSH 和仪表盘测试。
- **面向模型的变化：**无。这些操作未声明 Tool，因此 Manager、Worker、Planner、Reviewer 的 prompt 和 Manager Tool 均未改动。
- **代码中未确认：**本草稿未运行失败路径；unavailable 的答复来自模块说明，而非本次运行的测试。

### 升级与回退

v2.13.78 发布后重跑 `install.sh`。无需迁移数据，已存的会话和消息不变。使用已移除的 `/api/chat/targets`、`/api/chat/sessions`、`/api/chat/messages` 路由的脚本需要更新。回退到 v2.13.77 会连同旧仪表盘一起恢复这些路由。
