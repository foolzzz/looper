# Looper v2.13.135

## Release Decision

**Who should upgrade:** Nobody needs to. This release only changes documentation. Everyone can stay on v2.13.134.

**What this release solves:** [#669](https://github.com/foolzzz/looper/pull/669) updates the API runtime RFC and the long-horizon plan with the maintainer's decisions of 2026-10-26: a Norma-derived Python loop, protocol-neutral session storage, a retained MIT notice, an original Looper handoff prompt, and the tool boundary for future tools.

**Breaking changes:** No. No code, API, schema or configuration changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#669](https://github.com/foolzzz/looper/pull/669); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.135
```

## Behavior changes

- **Documentation only (#669):** the PR changes two files, `docs/architecture/rfcs/api-runtime-v0.zh-CN.md` (80 added, 63 removed lines) and `docs/plans/2026-10-13-long-horizon-agent-context.zh-CN.md` (8 added, 2 removed lines). It records these design decisions, none of them implemented:
  - Stage 1 ports the Norma agentcore turn/tool cycle to typed asyncio Python behind `AgentLoop`, with Responses as the first `ProtocolCodec`. There is still one `api` runtime kind, Manager only.
  - Sessions are stored in a protocol-neutral form: `api_sessions` holds one metadata row per session including its protocol, and `api_session_items` holds versioned neutral items. The wire format is translated at request time.
  - The MIT notice for the Norma-derived code is retained and the `THIRD_PARTY_NOTICES.txt` file is to be created when the loop is implemented; Looper stays Apache-2.0.
  - The handoff summary prompt is original to Looper and is not copied from Norma.
  - Stage 1 adds no model-callable file or process tools. Any future such tool must stay within the task cwd and explicit `add_dirs`, use an allowlisted environment and a per-runtime private HOME. This is a tool boundary, not an OS sandbox. `noa` is out of scope.
  - The RFC's code baseline moves to v2.13.133, and a stale line reference and a line count are updated.
- **Runtime behavior:** none. No Python, web or configuration file is touched by the PR, and the description says it delivers no loop, session table, prompt or notice.
- **Model-visible changes:** none found. The diff touches no prompt, tool declaration or tool result; the handoff prompt it describes is not added.
- **Line counts:** the description reports tests 0 and production 0 added lines (fixtures excluded).
