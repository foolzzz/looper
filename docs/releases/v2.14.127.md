# Looper v2.14.127

This is the patch release v2.14.127, a hotfix line in which each merged change ships at once. It documents one change, [#1206](https://github.com/foolzzz/looper/pull/1206) (issue #1190): review panel edge cases for force-added files, continuing after the spend cap and git errors in shared mode. Its code was already merged in the `v2.14.126` tag but the v2.14.126 release body does not describe it; this release adds no other code, only the version bump and these notes.

## Release Decision

**Who should upgrade:** Operators of tasks with a review panel, especially those whose repositories force-add ignored files, continue runs after the spend cap, or run in shared mode. Tasks without a panel are unchanged.

**What this release solves:** [#1206](https://github.com/foolzzz/looper/pull/1206) makes the review snapshot include files staged with `git add -f`, keeps the original snapshot when a run continues after the spend cap so the remaining reviews do not report `head_moved`, and turns checkout git errors (detached HEAD, merge in progress, oversized checkout in shared mode) into a clear gate instead of a failed step.

**Breaking changes:** No. There is no migration and no API removal. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.127
```

**Contributors:** Maintainer @foolzzz authored [#1206](https://github.com/foolzzz/looper/pull/1206); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.126 upgrades directly. There is no schema change.

## Behavior changes

- **Force-added files are reviewed** ([#1206](https://github.com/foolzzz/looper/pull/1206)). The review snapshot selects tracked and non-ignored files as before, and now also the paths in the real index, including new files staged with `git add -f` under ignored paths. A new staged file that was removed from disk keeps its staged blob and mode in the snapshot.
- **Continue after the spend cap.** A round that already has its review snapshot (a recorded `worker_head`) keeps it, together with the finished seats and their checkouts, instead of freezing again. A new Worker result starts a new round with a new snapshot.
- **Checkout errors open a gate.** If freezing the snapshot fails with a git error (in shared mode, a detached HEAD, a merge in progress or an oversized checkout), or a seat's checkout cannot be opened, Looper keeps the successful work and opens a gate "Restore the checkout for review of <step>" with the problem in its findings. Previously the first case failed the attempt ("Cannot freeze review workspace") and the second recorded a `snapshot_unavailable` verdict. Replying to the gate resumes review; until it is closed no verdict settles the reviews, and the reviewed step is left pending.
- **Seat order.** A seat's checkout is now opened before its reviewer is created, so a checkout problem leaves no reviewer behind.
- **Other:** `_git` accepts input on stdin (used only to restore staged entries); a comment in the worker's verification copy is reworded, with no behavior change.
- **Unchanged:** tasks without a review panel, and the dispatch of seats in the normal case.
- **Model-visible changes:** None to the Planner, Worker, Reviewer or Manager prompts and contracts. What changes is data: the review snapshot can contain more files, and a task can show a new "Restore the checkout for review" gate with its question and findings text, which the operator or Manager sees like any other gate.

**谁需要升级：**使用评审小组的任务运维者，尤其是仓库中强制添加被忽略文件、花费上限后继续运行或使用共享模式的情况。没有评审小组的任务无变化。

**是否有破坏性变更：**否。没有迁移，没有移除 API。桥接边界不变：早于 v2.13.165 的安装须先升级到 v2.13.165。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.126 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **强制添加的文件会被评审**（[#1206](https://github.com/foolzzz/looper/pull/1206)）。评审快照照旧选取已跟踪和未被忽略的文件，现在还包含真实索引中的路径，包括在被忽略路径下用 `git add -f` 暂存的新文件。已暂存但在磁盘上被删除的新文件，其暂存的 blob 和文件模式保留在快照中。
- **花费上限后继续。**已有评审快照（记录了 `worker_head`）的一轮会保留该快照以及已完成的席位和检出目录，不再重新冻结。Worker 的新结果会开始新的一轮并生成新快照。
- **检出错误打开 gate。**冻结快照时出现 git 错误（共享模式下的 detached HEAD、合并进行中或检出过大），或无法打开某席位的检出目录时，Looper 保留已成功的工作，并打开 gate “Restore the checkout for review of <step>”，问题写在其 findings 中。此前前一种情况会让尝试失败（“Cannot freeze review workspace”），后一种会记录 `snapshot_unavailable` 判定。回复该 gate 后评审继续；gate 关闭前，任何判定都不会结算评审，被评审的步骤保持 pending。
- **席位顺序。**现在先打开席位的检出目录再创建评审者，因此检出问题不会留下评审者。
- **其他：**`_git` 支持通过 stdin 传入输入（仅用于恢复暂存条目）；worker 验证副本中的一处注释措辞调整，行为无变化。
- **不变：**没有评审小组的任务，以及正常情况下席位的派发。
- **面向模型的变化：**Planner、Worker、Reviewer 和 Manager 的提示词与契约无变化。变化的是数据：评审快照可能包含更多文件，任务中可能出现新的 “Restore the checkout for review” gate 及其问题和 findings 文本，运维者或 Manager 会像看其他 gate 一样看到它。
