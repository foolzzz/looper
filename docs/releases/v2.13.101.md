# Looper v2.13.101

## Release Decision

**Who should upgrade:** Anyone who runs Planners on a runtime other than Claude Code (for example Codex), or who relies on the Planner reading a step's worktree.

**What this release solves:** [#577](https://github.com/foolzzz/looper/pull/577) rewrites the read-only inspection guidance in the Planner role prompt so it fits each runtime. The old text named only Read, Glob and Grep and told the Planner to leave commands to Workers, which contradicted runtimes whose reading tools are a read-only shell.

**Breaking changes:** No. No configuration or Tool declaration changed, and the Planner gains no write access. The default Planner prompt text changes; see Behavior changes.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#577](https://github.com/foolzzz/looper/pull/577); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.101
```

## Behavior changes

- **Planner inspection guidance is runtime-neutral ([#577](https://github.com/foolzzz/looper/pull/577)):** in `looper/agents/tiers/planner.py`, the default Planner prompt now says the Planner runs read-only and should use its runtime's available reading tools: Read, Glob and Grep in Claude Code, or the equivalent tools in other runtimes. When the runtime exposes a shell for reading (as Codex does), it should use read-only shell inspection such as `cat`, `ls` and `rg` under the existing sandbox, must not seek broader permissions or bypass the sandbox, and leaves builds, tests, file changes and other state-changing commands to Workers. The line that Looper refuses or reports tool calls that would change files is kept. The old text said to leave "commands, tests and file changes" to Workers.
- **Prompt is composed after the launch is resolved ([#577](https://github.com/foolzzz/looper/pull/577)):** the Planner turn now builds its system prompt after the `Launch` is created, passing the harness and custom role prompt from the launch settings and profile instead of the earlier agent settings. The code comment states the intent: the runtime keeps its reading tools and read-only controls, and a saved custom role prompt is still loaded unchanged. No permission is added by this change.
- **Comment only:** the comment on the isolated-worktree note now says the launch permits read-only inspection of the worktree, instead of "without a shell". No behavior.
- **Model-visible changes:** yes, one. The default Planner system prompt text changed as described above, for every runtime. A Planner with a saved custom role prompt keeps that prompt; the new test asserts the default text is not mixed into it. Tool declarations and Tool results are unchanged.
- **Tests:** [#577](https://github.com/foolzzz/looper/pull/577) adds `tests/test_planner_runtime_guidance.py` (the captured Planner launch prompt and command per runtime, with and without a saved prompt and a step worktree) and a case in `tests/test_prompt_preview.py` that checks the prompt preview matches the launch prompt for Claude Code and Codex, default and custom. The pull request reports 149 added test lines and 14 production lines.

## Upgrade and rollback

Re-run `install.sh` once v2.13.101 is published. No data migration and no configuration change. Rolling back to v2.13.100 restores the earlier Planner prompt text.

## 中文摘要

### 升级决策

**谁需要升级：**在 Claude Code 以外的运行时（例如 Codex）上运行 Planner 的用户，或依赖 Planner 读取步骤 worktree 的用户。

**解决了什么：**[#577](https://github.com/foolzzz/looper/pull/577) 重写 Planner 角色 prompt 中的只读检查指引，使其适配各运行时。旧文本只提 Read、Glob、Grep，并要求把命令留给 Worker，这与以只读 shell 作为读取工具的运行时相矛盾。

**是否有破坏性变更：**否。配置和 Tool 声明均未改变，Planner 也没有获得写权限。默认 Planner prompt 文本有变化，见行为变化。

**如何验证：**运行 `looper --version` 核对版本为 2.13.101。

**贡献者：**维护者 @foolzzz 提交 [#577](https://github.com/foolzzz/looper/pull/577)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.101
```

### 行为变化与入口

- **Planner 检查指引与运行时无关（[#577](https://github.com/foolzzz/looper/pull/577)）：**`looper/agents/tiers/planner.py` 中，默认 Planner prompt 现在说明 Planner 以只读方式运行，应使用其运行时可用的读取工具：Claude Code 中是 Read、Glob、Grep，其他运行时用等价工具。运行时提供用于读取的 shell 时（如 Codex），应在现有沙箱内使用 `cat`、`ls`、`rg` 等只读 shell 检查，不得申请更大权限或绕过沙箱，构建、测试、文件修改及其他改变状态的命令仍留给 Worker。Looper 拒绝或报告会修改文件的工具调用这一句保留。旧文本是把“命令、测试和文件修改”留给 Worker。
- **prompt 在 launch 解析后再组装（[#577](https://github.com/foolzzz/looper/pull/577)）：**Planner 回合现在在创建 `Launch` 之后才构建系统 prompt，harness 和自定义角色 prompt 取自 launch 的 settings 与 profile，而不是之前的 agent settings。代码注释写明意图：运行时保留其读取工具和只读控制，已保存的自定义角色 prompt 仍原样加载。此改动不增加任何权限。
- **仅注释：**隔离 worktree 说明处的注释改为“launch 允许对 worktree 做只读检查”，替换了“无需 shell”。无行为变化。
- **面向模型的变化：**有一项。所有运行时的默认 Planner 系统 prompt 文本按上文改变。保存了自定义角色 prompt 的 Planner 保持该 prompt；新测试断言默认文本不会混入其中。Tool 声明和 Tool 结果均未改变。
- **测试：**[#577](https://github.com/foolzzz/looper/pull/577) 新增 `tests/test_planner_runtime_guidance.py`（按运行时捕获 Planner 启动的 prompt 与命令，覆盖有无已保存 prompt、有无步骤 worktree），并在 `tests/test_prompt_preview.py` 新增用例，检查 Claude Code 与 Codex、默认与自定义下 prompt 预览与 launch prompt 一致。该 PR 报告新增测试 149 行、生产代码 14 行。
