# Looper v2.13.169

## Release Decision

**Who should upgrade:** No one needs this release for a running-Looper behavior change. [#763](https://github.com/foolzzz/looper/pull/763) changes only the runner bridge, its turn accounting and the runner supervisor, which nothing else in Looper calls yet. Everyone can stay on v2.13.168.

**What this release solves:** [#763](https://github.com/foolzzz/looper/pull/763) (covering #756) keeps one session's close or cancel failure, a failing request-end callback and late updates after a close local to that session, instead of failing the runner generation or the shared connection.

**Breaking changes:** No. No API, database schema, configuration, prompt or Tool declaration changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#763](https://github.com/foolzzz/looper/pull/763); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.169
```

## Behavior changes

- **Cancel timeouts ([#763](https://github.com/foolzzz/looper/pull/763)):** when a `session/cancel` request times out or is abandoned, the bridge no longer fails the whole connection. It keeps the request's correlation state and, when the late response arrives, validates and drops it (debug log only). Other methods still fail the connection as before, because a late acceptance must not make an abandoned prompt runnable. At most `MAX_ABANDONED_CANCELS` (128) cancels may be outstanding or abandoned; one more is refused with a `CAPACITY` protocol error.
- **Late updates ([#763](https://github.com/foolzzz/looper/pull/763)):** an update for a session that no longer exists, or for a poisoned or already summarized session, is dropped with a debug log instead of raising `SESSION_NOT_FOUND` or `INVALID_REQUEST` and failing the connection. A trace mismatch or an update after the settled one on a live session still raises, except stale text deltas, which are ignored as before.
- **Request-end failures ([#763](https://github.com/foolzzz/looper/pull/763)):** if processing a `request_end` update fails (the turn callback, or the cancel for an unapproved request), that session is poisoned, its queued updates are cleared, the turn is stopped and a cancel is requested once, and the trace settles as `failed` with an `INTERNAL_ERROR` ("runner request_end processing failed"). A usage record already accepted still counts toward `requests`, and `usage_complete` is true only if the request was approved. If the connection itself is already failed, that error is raised instead. A session left poisoned stays poisoned after settlement.
- **Failed settlement accounting ([#763](https://github.com/foolzzz/looper/pull/763)):** in `RunnerTurn`, when a trace settles as `failed` and the current limits cannot be read, the turn marks usage incomplete, drops the cost and still releases its reservations and settles, rather than raising. A failed settlement no longer calls the cancellation callback again.
- **Session close in the supervisor ([#763](https://github.com/foolzzz/looper/pull/763)):** a rejected `close_session` (an RPC failure) is logged as a warning with its code and no longer marks the generation failed; the turn's tools are drained either way. Only a lost connection (`ConnectionLost`) fails the generation, and other exceptions are no longer swallowed there.
- **Model-visible changes:** none. No prompt, tool description or tool schema changed.
- **Tests:** `tests/test_runner_bridge.py` and `tests/test_runner_supervisor.py` are extended; the description names these and `tests/test_runner_protocol.py` and `tests/test_runner_turn.py` as the covering tests.
- **Reach:** a search of `looper/` finds the runner bridge and supervisor only in their own package, so running Looper behavior does not change. The description lists `bridge.py` and `supervisor.py`; the diff also changes `turn.py`, and its stated counts (78 production, 202 test added) differ from the file list's additions (91 production, 292 test).

**如何验证：**运行 `looper --version` 核对版本为 2.13.169。

**贡献者：**维护者 @foolzzz 提交 [#763](https://github.com/foolzzz/looper/pull/763)；本次 patch release 无社区贡献。

### 行为变化与入口

- **取消超时（#763）：**`session/cancel` 请求超时或被放弃时，bridge 不再使整个连接失败，而是保留该请求的关联状态，迟到的响应到达后校验并丢弃（仅调试日志）。其他方法仍照旧使连接失败，因为迟到的接受不能让被放弃的 prompt 重新可运行。未完成或已放弃的取消最多 `MAX_ABANDONED_CANCELS`（128）个，再多会以 `CAPACITY` 协议错误拒绝。
- **迟到更新（#763）：**针对已不存在的 session、已 poisoned 或已有 summary 的 session 的更新，现在记调试日志后丢弃，不再抛出 `SESSION_NOT_FOUND` 或 `INVALID_REQUEST` 而使连接失败。存活 session 上 trace 不匹配或在 settled 之后的更新仍会抛错，过期的 text delta 仍照旧忽略。
- **request-end 失败（#763）：**处理 `request_end` 更新失败（turn 回调，或未获批准请求的取消）时，该 session 被置为 poisoned，队列中的更新被清空，turn 被停止并只请求一次取消，该 trace 以 `failed` 结算，错误为 `INTERNAL_ERROR`（"runner request_end processing failed"）。已接受的用量记录仍计入 `requests`，仅当请求已获批准时 `usage_complete` 才为 true。若连接本身已失败，则抛出该连接错误。结算后 poisoned 的 session 保持 poisoned。
- **失败结算的记账（#763）：**`RunnerTurn` 在 trace 以 `failed` 结算而当前限额无法读取时，将用量标记为不完整、丢弃成本，并仍释放预留和结算，而不是抛错。失败的结算不再次调用取消回调。
- **supervisor 的 session 关闭（#763）：**被拒绝的 `close_session`（RPC 失败）记录带错误码的警告，不再使该 generation 失败；无论如何都会排空该 turn 的工具。只有连接丢失（`ConnectionLost`）才使 generation 失败，其他异常不再被吞掉。
- **面向模型的变化：**无。prompt、工具描述和工具 schema 均未改变。
- **测试：**扩展 `tests/test_runner_bridge.py` 和 `tests/test_runner_supervisor.py`；描述列出的覆盖测试还包括 `tests/test_runner_protocol.py` 和 `tests/test_runner_turn.py`。
- **影响范围：**在 `looper/` 中搜索，runner bridge 和 supervisor 只出现在其自身包内，因此运行中的 Looper 行为不变。描述列出 `bridge.py` 和 `supervisor.py`，实际 diff 还改动了 `turn.py`；其声明的行数（生产 78、测试 202）与文件清单的新增行数（生产 91、测试 292）不一致。
