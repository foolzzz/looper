# Looper v2.14.77

This is the patch release v2.14.77, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.76: the native `cursor-agent` runtime, which runs Workers and Reviewers on Cursor's CLI with the operator's existing Cursor login ([#1078](https://github.com/foolzzz/looper/pull/1078)).

## Release Decision

**Who should upgrade:** Operators who have the Cursor CLI (`cursor-agent`) installed and want a project's Workers and Reviewers to use Cursor's models through an Agent Profile. Everyone else can stay: nothing uses the new runtime until an Agent Profile does.

**What this release solves:** Cursor's models could not be used as a Worker or Reviewer runtime. [#1078](https://github.com/foolzzz/looper/pull/1078) adds the runtime `Cursor Agent`, paired with the existing `cursor-login` provider.

**Breaking changes:** No. The runtime is new and opt-in; no existing runtime, setting, schema or operation changes. The runtime type API gains one boolean field, `loads_operator_config`.

**How to verify:** Check the installed version. On a machine with `cursor-agent` on PATH, the runtime `Cursor Agent` is listed under Agent Runtimes.

**Contributors:** Maintainer @foolzzz authored [#1078](https://github.com/foolzzz/looper/pull/1078); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.77
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.76 upgrades directly. This release has no schema change.

## Behavior changes

- **New runtime `cursor-agent`** (`looper/agents/runtimes/cursor_agent.py`, label "Cursor Agent"), registered as `rt-cursor-agent` when `cursor-agent` is on PATH. Capabilities: `run`, `mcp`, `add_dirs`. It serves Workers and Reviewers; the Manager and Planners are refused with a clear error ("cannot run the Manager or a Planner yet"). It accepts only the `cursor-login` provider.
- **One headless process per run:** `cursor-agent -p --output-format stream-json --force --trust --sandbox disabled --disable-auto-update --model <model> --plugin-dir <run>/looper-plugin …`, with a run directory of Looper's own holding `config/` (`CURSOR_CONFIG_DIR`) and `data/` (`CURSOR_DATA_DIR`). The run keeps the operator's `HOME` (Cursor's keychain login). `CURSOR_API_KEY`, `CURSOR_AUTH_TOKEN`, `CURSOR_API_ENDPOINT` and `AGENT_CLI_CREDENTIAL_STORE` are removed from the environment, and an Agent Profile or provider that sets `HOME` or either Cursor directory is refused.
- **The operator's configuration applies.** Because runs keep the operator's `HOME`, the operator's personal Cursor and Claude Code configuration (hooks, MCP servers, skills, rules, plugins) applies to Cursor runs and cannot be turned off, unlike Claude Code, Codex and Grok. The runtime type reports it as `loads_operator_config` (new field in the runtime type view and its API schema, also in `web/src/lib/api.ts`), and each run's launch record lists `personal_config`.
- **Events.** Cursor's stream-json is translated to Looper's run events (tool calls such as `shell`, `edit`, `glob`, `mcp__<server>__<tool>`; MCP results; usage). After a network retry (`connection/*`, `retry/*` events) the report is the last attempt's final message, without Cursor's "Auto routed" line (kept as `routed_model` in the run's notes). The run's model column holds the profile's model id.
- **Run recorder.** `ClaudeRunRecorder` records the `model_display` value of a run's `init` event in the run metadata when the event has one (`looper/agents/claude_cli.py`). This shared-code change is not described by the pull request; the Cursor translator sets the field.
- **MCP wait cap.** `looper-mcp` reads `LOOPER_MCP_MAX_WAIT_SECONDS` (a positive integer; otherwise it exits with an error). When set, `wait_seconds` of `looper_room_inbox` is clamped to it, in the advertised schema and in the forwarded call, including retries. Cursor runs set it to 50, below Cursor's 60 s MCP request timeout. Other runtimes do not set it.
- **Shared plumbing.** `run_channel` takes an optional `prompt_file`, passed through by `ProcessRun` in the Worker (`looper/agents/tiers/worker.py`); the other runtimes accept and ignore it.
- **Documentation and tests.** The architecture doc, evals README and two plan/RFC notes describe the runtime; about 1,300 lines are added, mostly tests and a recorded stream fixture.
- **Model-visible changes:** Yes, for Cursor runs only. (1) Looper's instructions arrive on stdin in a `<looper_instructions>` block before the turn prompt, because Cursor CLI 2026.10.22 does not apply `--plugin-dir` rules in headless mode and has no system-prompt option; the generated plugin carries only the run's MCP servers. (2) For Cursor runs, the `looper_room_inbox` tool description gains "This runtime caps wait_seconds at 50 seconds." and its `wait_seconds` schema maximum is at most 50. No other runtime's tool descriptions, schemas, role text or prompts change.

### Known limits

- After a network retry, Cursor's `result.usage` appears to cover only the resumed part, so a run's recorded tokens can be low (reported by the pull request).
- Cursor's `worker-server` helper outlives a run by minutes and is shared by runs in the same working directory (reported by the pull request).
- A real-mode prompt eval comparison was not run: the eval runner puts every role on one agent and the Planner cannot run on Cursor yet.

## Optional Capability Activation & Use

### Cursor Agent runtime

**Activation:** Install the Cursor CLI so `cursor-agent` is on PATH, log in to Cursor as the operator, and add the `cursor-login` provider. Looper then registers `Cursor Agent` under Agent Runtimes. Create an Agent Profile on it and assign the profile to a Worker or Reviewer.

```bash
looper --version   # looper 2.14.77
```

**Validation:** The runtime appears under Agent Runtimes with its capabilities `run`, `mcp` and `add_dirs`. A run's launch record lists `personal_config`, and its first message to Cursor starts with the `<looper_instructions>` block.

**Disable / rollback:** Remove the Agent Profile assignment (or the profile) to stop using it; without `cursor-agent` on PATH the runtime is not registered. Downgrading removes the runtime type; no schema changed.

**Authority boundary:** Cursor runs use the operator's own Cursor login and `HOME`, so the operator's personal Cursor and Claude Code configuration applies and cannot be disabled; Cursor runs with `--force --trust --sandbox disabled`. Looper's own state is kept in a run directory it owns, and Looper does not write the operator's own Cursor configuration files. API keys and tokens for Cursor are removed from the run's environment. Only Workers and Reviewers are supported.

**Docs:** [docs/architecture/agent-system.md](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md).

## Validation

**Retained implementation evidence:** the description of [#1078](https://github.com/foolzzz/looper/pull/1078) reports `tests/test_cursor_agent.py` (command, run directory, stdin layout, event translation over a recorded stream with paths and ids replaced, retries, MCP result shapes) plus registry, provider, MCP server, Worker and signature tests. It reports two real runs on a fresh database with an isolated `looper serve`, Worker and Reviewer on `cursor-agent`, Planner on Claude Code. The first showed that the plugin rule never reached the model, which moved the instructions to stdin. In the second, every Cursor run started with the instructions block, Workers ended with their JSON report, the Reviewer returned `passed: true`, both tasks committed only their files, all 6 MCP results had content, every run had at least one network retry without duplicated report text, there was no MCP timeout, the operator's Cursor configuration files were unchanged, and all processes ended within about 3 minutes.

**Not validated by the pull request:** a local full suite; automated reviews are not reported in its description; a real-mode prompt eval; the built wheel.

**CI:** CI runs again after the release is drafted; its result is not recorded here.

**Not tested for this draft:** a local full suite and the built wheel. The release documentation gate checks the body only.

## 中文摘要

本版本是 patch release v2.14.77（热修线，每个合并的改动立即发布）。自 v2.14.76 以来只合并了一项改动：原生 `cursor-agent` 运行时，让 Worker 和 Reviewer 使用操作者已有的 Cursor 登录在 Cursor CLI 上运行（[#1078](https://github.com/foolzzz/looper/pull/1078)）。

### 升级决策

**谁需要升级：**已安装 Cursor CLI（`cursor-agent`）、希望通过 Agent Profile 让项目的 Worker 和 Reviewer 使用 Cursor 模型的运维人员。其他人可不升级：在有 Agent Profile 使用之前，新运行时不会被用到。

**解决了什么：**此前 Cursor 的模型无法作为 Worker 或 Reviewer 的运行时。[#1078](https://github.com/foolzzz/looper/pull/1078) 新增运行时 `Cursor Agent`，与已有的 `cursor-login` provider 配合。

**是否有破坏性变更：**否。运行时是新增且需主动启用的；现有运行时、设置、数据库结构和操作均无变化。运行时类型 API 新增一个布尔字段 `loads_operator_config`。

**如何验证：**核对版本为 2.14.77。在 PATH 中有 `cursor-agent` 的机器上，Agent Runtimes 下会列出运行时 `Cursor Agent`。

**贡献者：**维护者 @foolzzz 提交 [#1078](https://github.com/foolzzz/looper/pull/1078)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.77
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.76 上的安装可直接升级。本版本没有数据库结构变更。

### 行为变化与入口

- **新运行时 `cursor-agent`**（`looper/agents/runtimes/cursor_agent.py`，标签「Cursor Agent」），PATH 中有 `cursor-agent` 时注册为 `rt-cursor-agent`。能力：`run`、`mcp`、`add_dirs`。服务于 Worker 和 Reviewer；Manager 和 Planner 会被明确拒绝。只接受 `cursor-login` provider。
- **每次运行一个无头进程：**`cursor-agent -p --output-format stream-json --force --trust --sandbox disabled --disable-auto-update --model <model> --plugin-dir <run>/looper-plugin …`，使用 Looper 自己的运行目录，内含 `config/`（`CURSOR_CONFIG_DIR`）和 `data/`（`CURSOR_DATA_DIR`）。运行保留操作者的 `HOME`（Cursor 的钥匙串登录）。`CURSOR_API_KEY`、`CURSOR_AUTH_TOKEN`、`CURSOR_API_ENDPOINT` 和 `AGENT_CLI_CREDENTIAL_STORE` 会从环境中移除；Agent Profile 或 provider 若设置 `HOME` 或任一 Cursor 目录会被拒绝。
- **操作者的配置会生效。**由于运行保留操作者的 `HOME`，操作者个人的 Cursor 和 Claude Code 配置（hooks、MCP 服务器、skills、rules、插件）会作用于 Cursor 运行且无法关闭，这与 Claude Code、Codex、Grok 不同。运行时类型以 `loads_operator_config`（运行时类型视图及其 API schema 的新字段，亦见 `web/src/lib/api.ts`）报告这一点，每次运行的启动记录列出 `personal_config`。
- **事件。**Cursor 的 stream-json 被翻译为 Looper 的运行事件（`shell`、`edit`、`glob`、`mcp__<server>__<tool>` 等工具调用，MCP 结果，用量）。网络重试（`connection/*`、`retry/*` 事件）之后，报告取最后一次尝试的最终消息，不含 Cursor 的「Auto routed」行（保存在运行备注的 `routed_model` 中）。运行的模型列保存 profile 的模型 id。
- **运行记录器。**`ClaudeRunRecorder` 在运行的 `init` 事件带有 `model_display` 时，把它记录到运行元数据（`looper/agents/claude_cli.py`）。这是共享代码的改动，PR 描述未提及；Cursor 翻译器会设置该字段。
- **MCP 等待上限。**`looper-mcp` 读取 `LOOPER_MCP_MAX_WAIT_SECONDS`（正整数，否则报错退出）。设置后，`looper_room_inbox` 的 `wait_seconds` 会被限制在该值以内，包括公布的 schema 和转发的调用（含重试）。Cursor 运行将其设为 50，低于 Cursor 的 60 秒 MCP 请求超时。其他运行时不设置。
- **共享代码。**`run_channel` 新增可选的 `prompt_file`，由 Worker 中的 `ProcessRun` 传入（`looper/agents/tiers/worker.py`）；其他运行时接受并忽略。
- **文档与测试。**架构文档、evals README 和两份计划/RFC 说明了该运行时；新增约 1300 行，主要是测试和一份录制的流样本。
- **面向模型的变化：**有，仅限 Cursor 运行。（1）Looper 的指令通过 stdin 放在 `<looper_instructions>` 块中，位于本轮提示之前，因为 Cursor CLI 2026.10.22 在无头模式下不应用 `--plugin-dir` 规则，也没有系统提示选项；生成的插件只携带该运行的 MCP 服务器。（2）Cursor 运行中，`looper_room_inbox` 的工具说明增加「This runtime caps wait_seconds at 50 seconds.」，其 `wait_seconds` 的 schema 上限不超过 50。其他运行时的工具说明、schema、角色文本和提示词均无变化。

#### 已知限制

- 网络重试之后，Cursor 的 `result.usage` 似乎只覆盖恢复后的部分，因此运行记录的 token 可能偏低（PR 报告）。
- Cursor 的 `worker-server` 辅助进程在运行结束后还会存活数分钟，并被同一工作目录下的运行共享（PR 报告）。
- 未运行真实模式的提示词评测对比：评测运行器把所有角色放在同一个 agent 上，而 Planner 目前还不能在 Cursor 上运行。

### 可选能力启用与使用

#### Cursor Agent runtime

**启用：**安装 Cursor CLI 使 `cursor-agent` 在 PATH 中，以操作者身份登录 Cursor，并添加 `cursor-login` provider。Looper 随后在 Agent Runtimes 下注册 `Cursor Agent`。基于它创建 Agent Profile，并分配给 Worker 或 Reviewer。

```bash
looper --version   # looper 2.14.77
```

**验证：**运行时出现在 Agent Runtimes 下，能力为 `run`、`mcp`、`add_dirs`。运行的启动记录列出 `personal_config`，发给 Cursor 的第一条消息以 `<looper_instructions>` 块开头。

**停用 / 回退：**取消 Agent Profile 的分配（或删除该 profile）即停止使用；PATH 中没有 `cursor-agent` 时运行时不会注册。降级会移除该运行时类型；没有数据库结构变更。

**权限边界：**Cursor 运行使用操作者自己的 Cursor 登录和 `HOME`，因此操作者个人的 Cursor 和 Claude Code 配置会生效且无法关闭；Cursor 以 `--force --trust --sandbox disabled` 运行。Looper 自己的状态放在它拥有的运行目录中，不会写入操作者自己的 Cursor 配置文件。Cursor 的 API 密钥和令牌会从运行环境中移除。仅支持 Worker 和 Reviewer。

**文档：**[docs/architecture/agent-system.md](https://github.com/foolzzz/looper/blob/main/docs/architecture/agent-system.md)。
