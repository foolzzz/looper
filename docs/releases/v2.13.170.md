# Looper v2.13.170

## Release Decision

**Who should upgrade:** Anyone who still relies on the `loopx` command, the `~/.loopx` directory move, the `com.loopx.serve` service replacement, `serve --format`, `looper config export`/`import` hints, or the old browser links and `loopx-chat-*` browser storage keys should read the behavior changes below before upgrading. Everyone else can upgrade normally; current deployments and routing are preserved.

**What this release solves:** [#762](https://github.com/foolzzz/looper/pull/762) removes entry points and fallbacks that were kept for the rename from LoopX to Looper: the `loopx` command, installer cleanup of the old `loopx` package, the `~/.loopx` migration, the old service unit replacement, old dashboard hash redirects and old chat storage keys. It also simplifies how the service install and `init-ops` read deployment settings.

**Breaking changes:** Yes. The `loopx` command, the automatic `~/.loopx` to `~/.looper` move, the `com.loopx.serve` unit replacement, `looper serve --format`, the old dashboard hash redirects and the `loopx-chat-*` browser keys are removed. No database schema, API or Tool declaration changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#762](https://github.com/foolzzz/looper/pull/762); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.170
```

## Behavior changes

- **`loopx` command removed ([#762](https://github.com/foolzzz/looper/pull/762)):** `pyproject.toml` no longer declares the `loopx` script, and `legacy_main` with its deprecation note is gone. Use `looper`.
- **`serve --format` removed ([#762](https://github.com/foolzzz/looper/pull/762)):** the hidden `--format` option of `looper serve` is no longer accepted. `looper version --format` is unchanged.
- **`config export`/`import` message removed ([#762](https://github.com/foolzzz/looper/pull/762)):** `looper config export` and `import` no longer get the special "was removed; use loopercli" error; they fail as unknown subcommands. `init-ops` no longer prints the closing advice to remove variables and run `service install` again.
- **Installer ([#762](https://github.com/foolzzz/looper/pull/762)):** `install.sh` no longer uninstalls an old `loopx` package with uv, pipx or pip before installing.
- **Runtime root ([#762](https://github.com/foolzzz/looper/pull/762)):** `looper serve`, `service install` and `init-ops` no longer move `~/.loopx` to `~/.looper`, leave a link, or warn when both exist; `settle_runtime_root`, `legacy_home_runtime_root`, `configured_runtime_root` and `RUNTIME_ROOT_ENV` are removed from `looper/paths.py`. The root is `--runtime-root`, else `LOOPER_RUNTIME_ROOT` or `LOOPX_RUNTIME_ROOT`, else `~/.looper`. An installation whose data is only in `~/.loopx` must move it or pass `--runtime-root`.
- **Service ([#762](https://github.com/foolzzz/looper/pull/762)):** `service install` no longer stops and removes the `com.loopx.serve` unit, and `status` and `doctor` no longer mention it. The runtime root written into the unit is made absolute without any move. When no port flag or ops-file port is given, an explicit `--port` of the installed unit is kept; a port the unit gets only from its ops file is no longer carried over. The refusal for settings that still come from the environment is reworded and no longer lists variable names from the ops sources' labels.
- **Environment ([#762](https://github.com/foolzzz/looper/pull/762)):** `looper.env` keeps only the `LOOPX_*` fallback for a missing `LOOPER_*` name; the deprecation log, the reverse mapping and `counterpart` are removed. The scheduler minimum-interval variable still reads the `LOOPX_` name as a fallback.
- **Ops file ([#762](https://github.com/foolzzz/looper/pull/762)):** the warning that a variable is set but shadowed by the ops file is gone, and the deprecation warnings no longer say the variable stops being read "until the next release". `init-ops` writes the sample database URL `postgresql://localhost:5432/loopx` when nothing names one, with a reworded note.
- **Dashboard ([#762](https://github.com/foolzzz/looper/pull/762)):** the redirects from `#agents/...`, `#settings/provider|mcp|channel|defaults/...` to the current pages are removed; an unknown settings page still goes to the default settings page. The chat no longer reads the `loopx-chat-session-id` and `loopx-chat-messages-*` browser keys. The Runtimes page labels hand-registered runtimes "custom" instead of "custom (legacy)", and a runtime's in-process flag now comes from the runtime itself when it is registered.
- **Internal ([#762](https://github.com/foolzzz/looper/pull/762)):** `PLANNER_ADDRESS` is removed from `looper/agents/message.py`; `read_dotenv` takes its path explicitly; test fixtures changed.
- **Model-visible changes:** none found. The diff changes no prompt, tool description or tool schema.

## Upgrade and rollback

Re-run `install.sh` once v2.13.170 is published. Before upgrading, move any data still in `~/.loopx` yourself, remove an old `com.loopx.serve` unit and an old `loopx` package if present. Rolling back to v2.13.169 restores the removed entry points.

### 升级决策

**谁需要升级：**仍依赖 `loopx` 命令、`~/.loopx` 自动迁移、`com.loopx.serve` 服务替换、`serve --format`、旧的浏览器链接或 `loopx-chat-*` 存储键的用户，升级前请先阅读下方行为变化。其他人可正常升级，当前部署和路由保持不变。

**解决了什么：**[#762](https://github.com/foolzzz/looper/pull/762) 移除了为 LoopX 改名 Looper 而保留的入口和回退：`loopx` 命令、安装器对旧 `loopx` 包的清理、`~/.loopx` 迁移、旧服务单元替换、旧仪表盘 hash 跳转和旧聊天存储键，并简化了服务安装和 `init-ops` 读取部署设置的方式。

**是否有破坏性变更：**是。`loopx` 命令、`~/.loopx` 到 `~/.looper` 的自动迁移、`com.loopx.serve` 单元替换、`looper serve --format`、旧仪表盘 hash 跳转和 `loopx-chat-*` 浏览器键均被移除。数据库 schema、API 和 Tool 声明未改变。

**如何验证：**运行 `looper --version` 核对版本为 2.13.170。

**贡献者：**维护者 @foolzzz 提交 [#762](https://github.com/foolzzz/looper/pull/762)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.170
```

### 行为变化与入口

- **移除 `loopx` 命令（#762）：**`pyproject.toml` 不再声明 `loopx`，`legacy_main` 及其弃用提示被删除。请使用 `looper`。
- **移除 `serve --format`（#762）：**`looper serve` 不再接受隐藏的 `--format`；`looper version --format` 不变。
- **`config export`/`import` 提示移除（#762）：**这两个子命令不再有"已移除，请用 loopercli"的专门报错，而是按未知子命令失败。`init-ops` 不再打印末尾的"移除变量并重新 `service install`"建议。
- **安装器（#762）：**`install.sh` 在安装前不再用 uv、pipx 或 pip 卸载旧 `loopx` 包。
- **运行时根目录（#762）：**`looper serve`、`service install` 和 `init-ops` 不再把 `~/.loopx` 移到 `~/.looper`、留链接或在两者并存时告警；`settle_runtime_root` 等从 `looper/paths.py` 删除。根目录为 `--runtime-root`，否则 `LOOPER_RUNTIME_ROOT` 或 `LOOPX_RUNTIME_ROOT`，否则 `~/.looper`。数据只在 `~/.loopx` 的安装需自行迁移或传 `--runtime-root`。
- **服务（#762）：**`service install` 不再停止并删除 `com.loopx.serve`，`status` 和 `doctor` 也不再提及它。写入单元的运行时根目录转为绝对路径，不再移动。未给出端口参数且 ops 文件无端口时，保留已安装单元中显式的 `--port`；仅来自 ops 文件的端口不再被带入单元。对仍来自环境的设置的拒绝信息已改写。
- **环境变量（#762）：**`looper.env` 只保留缺少 `LOOPER_*` 时回退读取 `LOOPX_*`；弃用日志、反向映射和 `counterpart` 被删除。调度最小间隔变量仍回退读取 `LOOPX_` 名称。
- **ops 文件（#762）：**"变量已设置但被 ops 文件覆盖"的警告被删除，弃用警告不再写"直到下个版本"。无任何来源指定数据库时，`init-ops` 写入示例 URL `postgresql://localhost:5432/loopx`，提示语已改写。
- **仪表盘（#762）：**`#agents/...` 和 `#settings/provider|mcp|channel|defaults/...` 的跳转被移除，未知设置页仍回到默认设置页。聊天不再读取 `loopx-chat-session-id` 和 `loopx-chat-messages-*`。Runtimes 页将手工注册的运行时标为"custom"而非"custom (legacy)"，已注册运行时的 in-process 标志取自运行时本身。
- **内部（#762）：**删除 `looper/agents/message.py` 的 `PLANNER_ADDRESS`；`read_dotenv` 须显式传路径；测试夹具有调整。
- **面向模型的变化：**未发现。diff 未改动 prompt、工具描述或工具 schema。

### 升级与回退

在 v2.13.170 发布后重新运行 `install.sh`。升级前请自行迁移仍在 `~/.loopx` 的数据，并移除旧的 `com.loopx.serve` 单元和旧 `loopx` 包。回退到 v2.13.169 会恢复被移除的入口。
