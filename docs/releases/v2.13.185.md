# Looper v2.13.185

## Release Decision

**Who should upgrade:** Developers and CI that run Looper's prompt-regression evals (`evals/prompt_regression`) against an API Manager. It is a hotfix that ships the changes merged since v2.13.184.

**What this release solves:** [#804](https://github.com/foolzzz/looper/pull/804) makes the eval's API Manager session readback expect one completed API turn per user turn that the API runtime answered, instead of a bare count, so a dialog that switches to a non-API runtime is not a false failure and `[HANDOFF]` or autonomous turns can no longer stand in for a missing user-turn record (fixes #796).

**Breaking changes:** No. No command, schema or file format changed; only the eval harness and its tests changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#804](https://github.com/foolzzz/looper/pull/804); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.185
```

## Behavior changes

- **Per-turn readback ([#804](https://github.com/foolzzz/looper/pull/804)):** in `evals/prompt_regression/dialogs.py`, `run_dialog` now records one `(number, text, preceding run id)` entry for each user turn the API runtime is expected to answer. `_api_session_check` takes that list instead of a count and fails with `no completed API Manager record for user turn N` when a turn has no record.
- **What counts as a record:** a completed `llm_records` row of the agent, with API runtime, that is not a session-profile record, not autonomous and whose input does not start with `[HANDOFF]`. Its input must equal the user text or end with it after a resume brief or gate note. Each record must fall between the run id before that turn and the run id before the next turn, so a later answer to identical text cannot fill a missing earlier one.
- **Runtime switches:** a new `Say.profile_after` field (`switch` or `settings`) marks the code-only `/profile` steps of the `session_profile_switch` dialog. The runner tracks which runtime answers each turn, using the registered switch profile's resolved `runtime_type` (`_make_switch_profile` now returns that profile when given a spec). Turns answered by a non-API runtime, code-only steps, stops and withdrawals expect no API record.
- **Active transcript check:** the existing neutral-history and protocol-metadata check of the current API session runs only when the last model turn was API-answered; after a switch away, the earlier answer records must still exist but the retired transcript is not required to be current. The readback now runs whenever any API turn is expected, not only when the Manager profile is API.
- **Scope:** only `evals/prompt_regression/dialogs.py` and tests changed. The `looper` package, the host, the runners and the tool surface are unchanged.
- **Tests:** `tests/test_eval_manager_agent.py`, `tests/test_model_manager_dialogs.py` and `tests/test_model_eval_registration.py` (the registry stand-in now returns `runtime_type` on created profiles) are updated; the PR reports 107 added test lines and no production lines.
- **Model-visible changes:** None. No prompts, tool descriptions, tool schemas or tool results changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.185 is published. There is no schema change, so rolling back to v2.13.184 needs nothing else.

## 中文摘要

### 升级决策

**谁需要升级：**针对 API Manager 运行 Looper 提示词回归评测（`evals/prompt_regression`）的开发者与 CI。本版本是随合并即发布的 hotfix，包含 v2.13.184 之后合并的改动。

**解决了什么：**[#804](https://github.com/foolzzz/looper/pull/804) 让评测中 API Manager 会话回读按“每个由 API 运行时回答的用户回合各有一条已完成的 API 回合”来检查，而不是只比较总数；切换到非 API 运行时的对话不再误报失败，`[HANDOFF]` 或自主回合也不能再顶替缺失的用户回合记录（修复 #796）。

**是否有破坏性变更：**无。命令、schema 和文件格式均未改变；只改了评测工具和测试。

**如何验证：**运行 `looper --version` 核对版本为 2.13.185。

**贡献者：**维护者 @foolzzz 提交 [#804](https://github.com/foolzzz/looper/pull/804)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.185
```

### 行为变化与入口

- **逐回合回读（#804）：**`evals/prompt_regression/dialogs.py` 中 `run_dialog` 为每个预期由 API 运行时回答的用户回合记录 `(序号, 文本, 此前的 run id)`。`_api_session_check` 接收该列表而非计数，回合缺记录时以 `no completed API Manager record for user turn N` 失败。
- **什么算记录：**该 agent 的已完成 `llm_records`，运行时为 API，非会话 profile 记录、非自主回合，输入不以 `[HANDOFF]` 开头；输入须等于用户文本，或在恢复简报/门控说明之后以该文本结尾。记录须落在该回合前后的 run id 区间内，因此对相同文本的后续回答不能填补更早缺失的记录。
- **运行时切换：**新增 `Say.profile_after` 字段（`switch` 或 `settings`），标记 `session_profile_switch` 对话中纯代码处理的 `/profile` 步骤。运行器跟踪每个回合由哪个运行时回答，使用已注册切换 profile 解析出的 `runtime_type`（`_make_switch_profile` 在给定 spec 时现在返回该 profile）。由非 API 运行时回答的回合、纯代码步骤、stop 和 withdraw 不要求 API 记录。
- **当前转录检查：**对当前 API 会话的中性历史与协议元数据检查，仅在最后一个模型回合由 API 回答时执行；切换离开后，此前的回答记录仍须存在，但已退役的转录不要求是当前的。只要预期有 API 回合就会回读，不再仅限于 Manager profile 为 API 时。
- **范围：**只改了 `evals/prompt_regression/dialogs.py` 和测试。`looper` 包、宿主、runner 和工具接口均未改变。
- **测试：**更新 `tests/test_eval_manager_agent.py`、`tests/test_model_manager_dialogs.py` 和 `tests/test_model_eval_registration.py`（注册表替身创建 profile 时返回 `runtime_type`）；PR 报告新增测试行 107，生产代码行 0。
- **面向模型的变化：**无。提示词、工具描述、工具 schema 和工具结果均无变化。
