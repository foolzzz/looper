# Looper v2.14.145

This is the patch release v2.14.145, a hotfix line in which each merged change ships at once. It documents one change: [#1256](https://github.com/foolzzz/looper/pull/1256) (profile fallbacks through TTADK: a launch that ends without a result falls back even when TTADK exits 0).

## Release Decision

**Who should upgrade:** Operators who configure profile fallbacks for Workers or Reviewers that run Codex, coco or Cursor Agent through TTADK, or Codex natively, because a launcher that refuses the selected model now moves to the fallback profile instead of failing the step. Everyone else gets no visible change.

**What this release solves:** [#1256](https://github.com/foolzzz/looper/pull/1256) keeps a profile fallback within the same step attempt when a launcher refuses the selected model, including when TTADK exits 0 without a result, and keeps the failure diagnostics useful while redacting registered secrets.

**Breaking changes:** No. There is no migration and no API removal. The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.145
```

**Contributors:** Maintainer @foolzzz authored [#1256](https://github.com/foolzzz/looper/pull/1256); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.144 upgrades directly. There is no schema change.

## Behavior changes

- **TTADK launches that end without a result fall back** ([#1256](https://github.com/foolzzz/looper/pull/1256), `looper/agents/tiers/worker.py`). For a launcher whose exit code is not reliable (Codex, coco and Cursor Agent through TTADK), a run with no result event, no model event and no successful result now sets the fallback reason even at exit code 0. Before, only a nonzero exit or a zero-turn error result did.
- **Codex error results without a turn count are launch refusals** (`looper/agents/tiers/worker.py`). A Codex error result that has no `num_turns` qualifies as a refusal before any model event, with the native or the TTADK launcher, even at exit 0. Model events still prevent fallback, and a budget error is not treated as a refusal. The error text of such a result becomes the failure detail, redacted and clipped to 500 characters.
- **Diagnostics are redacted and bounded** (`looper/agents/tiers/worker.py`). Stderr fragments and the first line of the fallback reason are redacted before clipping; the reason (`exited before any model event: <first line>`) stays within 299 characters including the prefix. A failure without a result carries the redacted stderr: a native runtime that exits 0 without a result now fails early with "<runtime> ended without a result" and the stderr head (up to 500 characters); a nonzero exit carries the head as well; TTADK keeps the head and tail. A native exit 0 alone does not trigger fallback. A successful result still survives a nonzero teardown exit.
- **Activity line for a TTADK failure** (`looper/agents/tiers/worker.py`). The diff removes the direct activity entry that the TTADK "ended without a result" branch wrote for a parent task; the pull request describes one activity line per fallback switch and does not mention this removal.
- **Unchanged:** the storage format, the ordered fallback chain in run metadata and the task journal, the rule that a switch stays in the same step attempt without consuming a retry, and Planner behavior. Dashboard, CLI, Telegram and Lark use the shared Worker/Profile records and need no entry-point change. `docs/architecture/agent-system.md` documents the exact runtime and launcher coverage.
- **Model-visible changes:** No prompt, tool or message sent to a model changes. Only the failure text shown to operators and the choice of profile for a retry change.

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.144 上的安装可直接升级。没有结构变更。

### 行为变化与入口

- **TTADK 启动后无结果即回退**（[#1256](https://github.com/foolzzz/looper/pull/1256)，`looper/agents/tiers/worker.py`）。对退出码不可靠的启动器（经 TTADK 的 Codex、coco、Cursor Agent），没有结果事件、没有模型事件且没有成功结果的运行，现在即使退出码为 0 也会设置回退原因。此前只有非零退出或零轮次错误结果才会。
- **没有轮次数的 Codex 错误结果视为启动被拒**（`looper/agents/tiers/worker.py`）。没有 `num_turns` 的 Codex 错误结果，无论原生或 TTADK 启动器、即使退出码为 0，都在任何模型事件之前被视为拒绝。出现模型事件仍会阻止回退，预算错误不视为拒绝。此类结果的错误文本成为失败详情，经脱敏并截断到 500 字符。
- **诊断脱敏并限长**（`looper/agents/tiers/worker.py`）。stderr 片段和回退原因的首行先脱敏再截断；原因（`exited before any model event: <首行>`）含前缀不超过 299 字符。没有结果的失败携带脱敏后的 stderr：原生运行时退出码为 0 而无结果时现在提前失败，报 “<runtime> ended without a result” 和 stderr 开头（至多 500 字符）；非零退出同样携带开头；TTADK 保留开头与结尾。仅原生退出码为 0 不触发回退。成功结果仍可在非零收尾退出时保留。
- **TTADK 失败的活动记录**（`looper/agents/tiers/worker.py`）。diff 移除了 TTADK “ended without a result” 分支为父任务直接写入的活动条目；PR 描述的是每次回退切换记录一条活动，未提及此移除。
- **不变：**存储格式、运行元数据和任务日志中的有序回退链、切换留在同一步骤尝试且不消耗重试，以及 Planner 行为。Dashboard、CLI、Telegram 和 Lark 使用共享的 Worker/Profile 记录，无需改动入口。`docs/architecture/agent-system.md` 记录了确切的运行时与启动器覆盖范围。
- **面向模型的变化：**无。发给模型的提示词、工具和消息都不变，只有展示给运维者的失败文本和重试所选的 profile 会变。
