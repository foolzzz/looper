# Looper v2.14.105

This is the patch release v2.14.105, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.104: Claude Code roles can use OpenAI-protocol (Chat Completions) models through the local gateway ([#1153](https://github.com/foolzzz/looper/pull/1153)).

## Release Decision

**Who should upgrade:** Operators who want to run a model that only has an OpenAI Chat Completions endpoint under the Claude Code runtime. Installations that do not pair such a model with Claude Code are not affected, apart from the schema column and the additional startup check described below.

**What this release solves:** [#1153](https://github.com/foolzzz/looper/pull/1153). An Agent Profile may now pair the native Claude Code runtime with an `openai-chat` model. Manager, Planner, Worker, Reviewer and consult runs on it go through a translating route of the local proxy, with request recording on or off. When the gateway is unavailable the run is refused with a specific reason; there is no direct fallback. Models get an optional `chat_dialect`, defaulting by vendor. The dashboard, the Manager tools and the self-check show the new pairing.

**Breaking changes:** No. No new dependency or command. Profiles of existing protocols are unchanged. The database gains one nullable `chat_dialect` column on `llm_models`.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.105
```

**Contributors:** Maintainer @foolzzz authored [#1153](https://github.com/foolzzz/looper/pull/1153); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.104 upgrades directly. The schema change is additive: `ensure_schema` adds a nullable `chat_dialect TEXT` column to `llm_models` once (checked to be set only for `openai-chat` models). Until then the change is reported as a pending schema change. A local proxy kept alive by running agents from an older version is reported as outdated for translated runs until those agents finish and it is replaced.

## Behavior changes

- **Claude Code can use `openai-chat` models** (`looper/agents/runtimes/claude_code.py`, `looper/agents/runtimes/__init__.py`, `looper/agents/profile_registry.py`). The Claude Code adapter declares `translated_protocols = {openai-chat}`. A new `model_path` is `direct` when the runtime speaks the model's protocol and `translated` when it reaches it only through the gateway. Pairing is accepted only for an API-key provider with the native launcher: login (OAuth) providers and TTADK launchers are refused with a reason. A provider without a base URL, without an API key, or whose catalog is not exactly the launch model is refused. Responses-protocol models are not supported by this path.
- **Translating route and refusal instead of fallback** (`looper/agents/llmrec/control.py`, `looper/agents/llmrec/gateway.py`). A translated launch starts the loopback proxy on demand and attaches a translation route with recording on or off; Claude Code receives only that route's URL. A missing, unavailable or outdated gateway, or an upstream URL carrying credentials (userinfo or a secret-looking query parameter), refuses the run with a specific reason, and an activity entry records that the run could not start. Resident Manager and Planner sessions reuse their route; a change of model, provider or dialect changes the binding and restarts the resident process on its next turn. Planner, Worker and consult launches prepare the route before the process starts; a Worker that fails to prepare is reported as a failed run with the reason. Existing direct profiles and recording routes keep their behavior.
- **Chat dialect** (`looper/agents/llmrec/dialects.py`, `looper/agents/llmrec/translate.py`, `looper/db/schema.sql`, `looper/db/connection.py`). A model's optional `chat_dialect` selects the upstream's conventions: `generic`, `openai`, `deepseek`, `moonshot`, `zhipu`, `qwen`, `vllm`, `minimax`, `ark` or `openrouter`. Null uses the vendor default (`deepseek` for DeepSeek, `moonshot` for Kimi, `zhipu` for GLM, otherwise `generic`). Only `openai-chat` models accept it. Dialects now carry the effort values they accept; an effort outside them is rejected, and for `openai` `xhigh` and `max` are clamped to `high` (counted in the translation notes). A `refusal` field from the upstream is now returned as text, in streams too.
- **Settings pinned for translated runs** (`looper/agents/claude_cli.py`, `looper/agents/runtimes/claude_code.py`). For a translated launch the process environment and the `--settings` file both carry the route URL, the provider key as the auth token (the Anthropic API key is cleared), the Bedrock, Vertex, Foundry, Anthropic AWS, Anthropic Google Cloud, Mantle and gateway switches set to `0`, `CLAUDE_CODE_ATTRIBUTION_HEADER=0`, `ENABLE_TOOL_SEARCH=false` and `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`, so project settings cannot override them. Because the file contains a credential, it is written to a private directory (mode 0700, file 0600, named by content hash, atomically replaced) and only its path is passed in the command line. Other runs still receive the inline settings as before.
- **Context estimates and usage** (`looper/agents/llmrec/proxy.py`, `looper/agents/llmrec/translate_stream.py`, `looper/agents/llmrec/capture.py`). `message_start` of a translated stream now carries an estimate in `input_tokens` (both cache counts zero): the previous request's exact total prompt tokens on the same route plus appended message bytes at four UTF-8 bytes per token, rounded up, or the whole translated request's byte size when there is no anchor or the prefix changed. Anchors live in proxy memory only (up to 1,024 routes); a restart or eviction loses them. Billing still uses the upstream's exact cumulative `message_delta` usage. Captures record `translation.start_usage_estimated` and `translation.start_input_tokens`. A client that closes the connection is recorded as outcome `client_closed`. Cache-write tokens are now subtracted from the incoming count in captured usage. The proxy is considered outdated unless it advertises the translate feature.
- **Self-check and startup** (`looper/agents/self_check.py`, `looper/agents/serve.py`). A new `gateway` check, "Local gateway", is skipped when no Agent Profile needs translation, reports OK when the gateway is running or will start on the first translated run, fails when it is unavailable or outdated, and warns when upstream usage was missing since proxy startup (spend is then understated). It appears in `looper doctor` and the startup checks; the `llmrec_settings.get` result gains a `translate` counters object.
- **Dashboard** (`web/src/components/agent-profiles.tsx`, `web/src/components/model-settings.tsx`, `web/src/lib/api.ts`). Profiles that use the gateway show a **via local gateway** badge. The profile editor lists the runtimes that reach a model through the gateway and gives the reason when a pairing is refused. The model form has a **Chat dialect** selector for `openai-chat` models (Auto shows the vendor default).
- **API and registry** (`looper/agents/v1_domains/registry.py`, `looper/agents/v1_domains/profiles.py`). Runtime types return `translated_protocols`; models return `chat_dialect` and `effective_chat_dialect`; profiles return `model_path`.
- **Documentation** (`docs/architecture/agent-system.md`). New section "Translated models (local gateway)".
- **Tests.** New `tests/test_claude_code_gateway.py`, `test_gateway_self_check.py`, `test_gateway_serve_db.py` and `test_translated_profiles_browser.py`; extended gateway, llmrec, model, profile, manager-tool and web component tests.
- **Unchanged:** dependencies, commands, channels, the direct Anthropic path, and profiles of existing protocols.
- **Model-visible changes:** Yes. (1) The Manager's model tools gain a `chat_dialect` field (enum of the dialects or null, `openai-chat` models only) in their schema, and its description is longer; profile views returned to the Manager include `model_path`. Every Manager turn that lists those tools sees the longer schema. (2) A Claude Code run on a translated model receives the environment and settings listed above, its requests are translated to Chat Completions for the upstream model, and its context accounting uses the estimates described above. No Worker, Planner or Reviewer prompt text changed; runs on existing protocols see no change.

## 中文摘要

本版本是 patch release v2.14.105（热修线，每个合并的改动立即发布）。自 v2.14.104 以来只合并了一项改动：Claude Code 角色可以通过本地网关使用 OpenAI 协议（Chat Completions）的模型（[#1153](https://github.com/foolzzz/looper/pull/1153)）。

### 升级决策

**谁需要升级：**想在 Claude Code 运行时下使用只提供 OpenAI Chat Completions 端点的模型的运维人员。未把此类模型与 Claude Code 搭配的安装不受影响，仅多一个数据库列和一项启动检查。

**解决了什么：**[#1153](https://github.com/foolzzz/looper/pull/1153)。Agent Profile 现在可以把原生 Claude Code 运行时与 `openai-chat` 模型搭配。Manager、Planner、Worker、Reviewer 和 consult 运行经本地代理的转换路由，无论请求记录开启与否。网关不可用时运行会被拒绝并给出明确原因，不会回退直连。模型新增可选的 `chat_dialect`，默认按厂商选择。仪表盘、Manager 工具和自检都会显示新的搭配。

**是否有破坏性变更：**否。无新依赖、无新命令。现有协议的 profile 不变。数据库在 `llm_models` 上新增一个可空的 `chat_dialect` 列。

**如何验证：**核对版本为 2.14.105。

**贡献者：**维护者 @foolzzz 提交 [#1153](https://github.com/foolzzz/looper/pull/1153)；本版本无社区贡献。

```bash
looper --version   # looper 2.14.105
```

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.104 上的安装可直接升级。数据库变更为增量：`ensure_schema` 一次性为 `llm_models` 增加可空的 `chat_dialect TEXT` 列（约束为仅 `openai-chat` 模型可设置）。在此之前该变更被视为待处理的结构变更。由运行中的 agent 保持存活的旧版本本地代理，在这些 agent 结束并被替换之前，对转换运行报告为过期。

### 行为变化与入口

- **Claude Code 可使用 `openai-chat` 模型**（`looper/agents/runtimes/claude_code.py`、`looper/agents/runtimes/__init__.py`、`looper/agents/profile_registry.py`）。Claude Code 适配器声明 `translated_protocols = {openai-chat}`。新的 `model_path` 在运行时直接支持模型协议时为 `direct`，只能经网关到达时为 `translated`。仅接受 API key 提供方加原生启动器的搭配：登录（OAuth）提供方和 TTADK 启动器会被拒绝并给出原因。没有 base URL、没有 API key、或目录不恰好等于启动模型的提供方也会被拒绝。此路径不支持 Responses 协议模型。
- **转换路由，拒绝而非回退**（`looper/agents/llmrec/control.py`、`looper/agents/llmrec/gateway.py`）。转换运行按需启动回环代理并挂接转换路由，无论记录开启与否；Claude Code 只收到该路由的 URL。网关缺失、不可用或过期，或上游 URL 带有凭据（用户信息或形似密钥的查询参数）时，运行被拒绝并给出具体原因，同时写入一条活动记录说明运行无法启动。常驻的 Manager 和 Planner 会话复用其路由；模型、提供方或方言变化会改变绑定，常驻进程在下一回合重启。Planner、Worker 和 consult 在进程启动前准备路由；Worker 准备失败时按失败运行报告并附原因。现有直连 profile 和记录路由行为不变。
- **聊天方言**（`looper/agents/llmrec/dialects.py`、`looper/agents/llmrec/translate.py`、`looper/db/schema.sql`、`looper/db/connection.py`）。模型的可选 `chat_dialect` 选择上游约定：`generic`、`openai`、`deepseek`、`moonshot`、`zhipu`、`qwen`、`vllm`、`minimax`、`ark` 或 `openrouter`。为空时按厂商默认（DeepSeek 用 `deepseek`，Kimi 用 `moonshot`，GLM 用 `zhipu`，其余 `generic`）。仅 `openai-chat` 模型接受该字段。方言现在带有其接受的 effort 值；超出范围的 effort 被拒绝，`openai` 方言下 `xhigh` 和 `max` 被收敛为 `high`（计入转换备注）。上游的 `refusal` 字段现在会作为文本返回，流式也是如此。
- **转换运行的固定设置**（`looper/agents/claude_cli.py`、`looper/agents/runtimes/claude_code.py`）。转换启动时，进程环境和 `--settings` 文件都带有路由 URL、作为认证令牌的提供方密钥（Anthropic API key 被清空）、值为 `0` 的 Bedrock、Vertex、Foundry、Anthropic AWS、Anthropic Google Cloud、Mantle 和 gateway 开关，以及 `CLAUDE_CODE_ATTRIBUTION_HEADER=0`、`ENABLE_TOOL_SEARCH=false`、`CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1`，项目设置无法覆盖。因文件含凭据，它写入私有目录（目录 0700、文件 0600、以内容哈希命名、原子替换），命令行只传路径。其他运行仍按原样接收内联设置。
- **上下文估算与用量**（`looper/agents/llmrec/proxy.py`、`looper/agents/llmrec/translate_stream.py`、`looper/agents/llmrec/capture.py`）。转换流的 `message_start` 现在在 `input_tokens` 中给出估算值（两个缓存计数为零）：同一路由上一次请求的精确总提示 token 数，加上追加消息的字节数（每 token 按 4 个 UTF-8 字节、向上取整）；没有锚点或前缀变化时，使用整个转换后请求的字节大小。锚点仅存于代理内存（最多 1,024 条路由），重启或淘汰后丢失。计费仍使用上游精确的累计 `message_delta` 用量。捕获记录 `translation.start_usage_estimated` 和 `translation.start_input_tokens`。客户端关闭连接记为 outcome `client_closed`。捕获的用量中，输入计数现在会减去缓存写入 token。代理若未声明 translate 特性即视为过期。
- **自检与启动**（`looper/agents/self_check.py`、`looper/agents/serve.py`）。新的 `gateway` 检查“Local gateway”：没有 Agent Profile 需要转换时跳过；网关在运行或将在首次转换运行时启动则为 OK；不可用或过期则失败；自代理启动以来缺失上游用量则警告（花费会被低估）。它出现在 `looper doctor` 和启动检查中；`llmrec_settings.get` 的结果新增 `translate` 计数对象。
- **仪表盘**（`web/src/components/agent-profiles.tsx`、`web/src/components/model-settings.tsx`、`web/src/lib/api.ts`）。使用网关的 profile 显示 **via local gateway** 标记。Profile 编辑器列出经网关到达模型的运行时，并在搭配被拒绝时给出原因。模型表单为 `openai-chat` 模型增加 **Chat dialect** 选择器（Auto 显示厂商默认值）。
- **API 与注册表**（`looper/agents/v1_domains/registry.py`、`looper/agents/v1_domains/profiles.py`）。运行时类型返回 `translated_protocols`；模型返回 `chat_dialect` 和 `effective_chat_dialect`；profile 返回 `model_path`。
- **文档**（`docs/architecture/agent-system.md`）。新增“Translated models (local gateway)”一节。
- **测试。**新增 `tests/test_claude_code_gateway.py`、`test_gateway_self_check.py`、`test_gateway_serve_db.py` 和 `test_translated_profiles_browser.py`；扩展网关、llmrec、模型、profile、Manager 工具和前端组件测试。
- **不变：**依赖、命令、渠道、直连 Anthropic 路径，以及现有协议的 profile。
- **面向模型的变化：**有。（1）Manager 的模型工具在 schema 中新增 `chat_dialect` 字段（方言枚举或 null，仅限 `openai-chat` 模型），描述变长；返回给 Manager 的 profile 视图包含 `model_path`。每个列出这些工具的 Manager 回合都会看到更长的 schema。（2）转换模型上的 Claude Code 运行会收到上述环境和设置，其请求被转换为 Chat Completions 发给上游模型，上下文统计使用上述估算。Worker、Planner、Reviewer 的提示文字无变化；现有协议上的运行不受影响。
