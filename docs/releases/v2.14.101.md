# Looper v2.14.101

This is the patch release v2.14.101, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.100: a control-plane upgrade now measures `--turns-timeout` from when only Manager and Planner turns block ([#1148](https://github.com/foolzzz/looper/pull/1148)). It only matters for `looper service upgrade` of a control-plane change.

## Release Decision

**Who should upgrade:** Operators who run `looper service upgrade` with `--no-force` on a busy service, where the upgrade was cancelled although the only thing left to wait for was a turn. Everyone else can stay.

**What this release solves:** [#1148](https://github.com/foolzzz/looper/pull/1148). The turns timeout was measured from the start of the drain. When a non-keepable run finished after more than `--turns-timeout`, any turn still running at that moment made `--no-force` cancel the deployment at once. The timeout is now measured from the first drain status in which no non-keepable run is waiting, capped by `--drain-timeout` overall.

**Breaking changes:** No. No database change, no new dependency, no new setting, no new API or dashboard control. The `--turns-timeout` option keeps its name and default (180); the upgrade report gains one field.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.14.101
```

**Contributors:** Maintainer @foolzzz authored [#1148](https://github.com/foolzzz/looper/pull/1148); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.100 upgrades directly. There is no database change.

## Behavior changes

- **Turns clock** (`looper/agents/service.py`). During the drain of a `CONTROL_PLANE` upgrade, the turns clock starts at the first drain status with no non-keepable run waiting, that is, when only turns block. If a non-keepable run reappears, the clock is reset and starts again once only turns block. The drain is cancelled (with `--no-force`) or forced when either `--drain-timeout`, counted from the start of the drain, or `--turns-timeout`, counted on the turns clock, has passed. Full upgrades and other plan kinds are not changed by this.
- **Upgrade report** (`looper/agents/service.py`). The report gains `turns_wait_seconds`: the time since the turns clock started, or 0 while it is unset. It starts at 0.0 in every report.
- **CLI help** (`looper/cli.py`). The help of `--turns-timeout` now says it counts from when only turns block, resets if a non-keepable run reappears and is capped by `--drain-timeout`. The default (180) is unchanged.
- **Documentation and tests.** The agent-system architecture document describes the new clock; `tests/test_service_upgrade_execution.py` has new cases.
- **Unchanged:** the database schema, the dependencies, settings, the HTTP API, the dashboard, the Manager's tools, channels (Telegram and Lark).
- **Model-visible changes:** None. No prompt, tool description or agent environment changes.

本版本是 patch release v2.14.101（热修线，每个合并的改动立即发布）。自 v2.14.100 以来只合并了一项改动：control-plane 升级现在从只剩 Manager/Planner 轮次阻塞时开始计算 `--turns-timeout`（[#1148](https://github.com/foolzzz/looper/pull/1148)）。仅影响 control-plane 变更的 `looper service upgrade`。

### 升级决策

**谁需要升级：**在繁忙服务上使用 `looper service upgrade --no-force`，且升级在只剩轮次需要等待时仍被取消的运维人员。其他人可不升级。

**解决了什么：**[#1148](https://github.com/foolzzz/looper/pull/1148)。此前 turns 超时从排空开始时计时；当某个不可保留的运行在超过 `--turns-timeout` 后才结束，此时仍在运行的任何轮次会使 `--no-force` 立即取消部署。现在从首个没有不可保留运行在等待的排空状态开始计时，并受 `--drain-timeout` 总体限制。

**是否有破坏性变更：**否。无数据库变更、无新依赖、无新设置、无新的 API 或仪表盘控件。`--turns-timeout` 名称和默认值（180）不变；升级报告新增一个字段。

**如何验证：**核对版本为 2.14.101。

**贡献者：**维护者 @foolzzz 提交 [#1148](https://github.com/foolzzz/looper/pull/1148)；本版本无社区贡献。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.100 上的安装可直接升级。无数据库变更。

### 行为变化与入口

- **Turns 计时**（`looper/agents/service.py`）。`CONTROL_PLANE` 升级排空期间，计时从首个没有不可保留运行在等待的排空状态（即只剩轮次阻塞）开始。若不可保留运行再次出现，计时被重置，待只剩轮次阻塞时重新开始。当 `--drain-timeout`（从排空开始计）或 `--turns-timeout`（按 turns 计时计）任一超时，排空即被取消（带 `--no-force`）或强制结束。完整升级及其他计划类型不受此影响。
- **升级报告**（`looper/agents/service.py`）。报告新增 `turns_wait_seconds`：自 turns 计时开始的时长，未开始时为 0。每份报告初始为 0.0。
- **CLI 帮助**（`looper/cli.py`）。`--turns-timeout` 的帮助说明其从只剩轮次阻塞时开始计时、不可保留运行再次出现时重置，并受 `--drain-timeout` 限制。默认值（180）不变。
- **文档与测试。**agent-system 架构文档描述了新的计时；`tests/test_service_upgrade_execution.py` 新增用例。
- **不变：**数据库结构、依赖、设置、HTTP API、仪表盘、Manager 工具、渠道（Telegram 和 Lark）。
- **面向模型的变化：**无。提示、工具描述和 agent 环境均无变化。
