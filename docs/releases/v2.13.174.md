# Looper v2.13.174

## Release Decision

**Who should upgrade:** Only maintainers who run the prompt-regression dialogs evaluation (`evals/prompt_regression/dialogs.py`) with `--manager-agent`. Nothing in the installed product changes. It is a hotfix that ships the change merged since v2.13.173.

**What this release solves:** [#764](https://github.com/foolzzz/looper/pull/764) makes the dialogs evaluation apply its run budget to the selected Manager profile and adds a readback check that an api Manager dialog persisted neutral session items with the session's protocol.

**Breaking changes:** No. No command, API, database schema or configuration format changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#764](https://github.com/foolzzz/looper/pull/764); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.174
```

## Behavior changes

- **Run budget on the Manager profile ([#764](https://github.com/foolzzz/looper/pull/764)):** in `run` in `evals/prompt_regression/dialogs.py`, the `update_role` call for the Manager with `--manager-agent` now sends `run_budget_usd` (the `--max-budget-usd` value, `None` when unset) next to `profile_id`.
- **Api session readback ([#764](https://github.com/foolzzz/looper/pull/764)):** the new `_api_session_check` runs after the turns of a dialog whose Manager profile has runtime type `api`. For completed api runs of that Manager after the dialog started (excluding runs with `session_profile` metadata), it requires the Manager's current session to exist, `api_sessions.protocol` to equal the `llm_model` protocol recorded on those runs, and stored `api_session_items` covering every completed turn. Any miss is appended to the dialog's `problems` and the dialog fails.
- **Dialog bookkeeping ([#764](https://github.com/foolzzz/looper/pull/764)):** `run_dialog` now resolves the Manager agent id once and takes the "newest run" marker for api Managers too (before, only for stop, withdraw and profile-switch dialogs). `passed` is computed from the per-turn problems plus the readback problems.
- **Scope:** the diff touches only the evaluation module and its tests (`tests/test_eval_manager_agent.py`, `tests/test_model_manager_dialogs.py`); the `looper` package has no production change.
- **Model-visible changes:** none. The diff changes no prompt, tool description or tool schema sent to a model.

## Upgrade and rollback

Re-run `install.sh` once v2.13.174 is published; the installed product is unchanged. Rolling back to v2.13.173 restores the evaluation without the budget and readback.

### 行为变化与入口

- **Manager profile 上的运行预算（#764）：**`dialogs.py` 的 `run` 中，使用 `--manager-agent` 时对 Manager 的 `update_role` 调用现在在 `profile_id` 之外还发送 `run_budget_usd`（即 `--max-budget-usd`，未设置时为 `None`）。
- **api 会话回读（#764）：**新增的 `_api_session_check` 在 Manager profile 运行时类型为 `api` 的对话结束后运行。对该 Manager 在对话开始后已完成的 api 运行（不含带 `session_profile` 元数据的），要求其当前会话存在、`api_sessions.protocol` 等于这些运行记录的 `llm_model` 协议，且已存储的 `api_session_items` 覆盖每个已完成的轮次。任何不满足都会加入该对话的 `problems` 并使其失败。
- **对话内部处理（#764）：**`run_dialog` 现在只解析一次 Manager agent id，并对 api Manager 也记录“最新运行”标记（此前只有停止、撤回和切换 profile 的对话会记录）。`passed` 由各轮问题加回读问题共同决定。
- **范围：**diff 只涉及评测模块及其测试（`tests/test_eval_manager_agent.py`、`tests/test_model_manager_dialogs.py`），`looper` 包没有生产代码改动。
- **面向模型的变化：**无。diff 未改动任何发给模型的 prompt、工具描述或工具 schema。
