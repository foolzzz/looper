# Looper v2.14.51

This is the patch release v2.14.51, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.50: hardening of `looper service upgrade` before deploys use it ([#977](https://github.com/foolzzz/looper/pull/977)). The only new setting is the `--turns-timeout` option of that command.

## Release Decision

**Who should upgrade:** Anyone who wants to stay on the latest patch line, and anyone who upgrades a running service with `looper service upgrade`.

**What this release solves:** [#977](https://github.com/foolzzz/looper/pull/977) fixes the problems found when rehearsing `looper service upgrade` on a real install: dependencies are no longer synced for a no-op or web-only checkout upgrade, the dashboard build uses the service's Python, the swapped `web/dist` is readable by the server, a failed start after the stop and install is recovered instead of leaving the unit down, `--turns-timeout` exists and a control-plane upgrade uses it, untracked files that the fingerprints hash are refused before the drain, and a web-only wheel upgrade installs the rest of the package.

**Breaking changes:** No. No API or migration is added or removed. A checkout upgrade can now refuse because of untracked component files (see Behavior changes).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#977](https://github.com/foolzzz/looper/pull/977); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.51
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.50 upgrades directly. This release adds no migration.

## Behavior changes

- **`--turns-timeout` ([#977](https://github.com/foolzzz/looper/pull/977)).** `looper service upgrade` takes `--turns-timeout` (default 180 seconds). For a control-plane plan it replaces `--drain-timeout` as the drain limit; a full plan still uses `--drain-timeout`. `--timeout`, `--drain-timeout` and `--turns-timeout` must be positive finite numbers, otherwise the command stops with an error.
- **Dependencies in a checkout.** `uv sync` now runs only for full and control-plane plans, as `uv sync --extra test --inexact`, which keeps the deploy's test extra and other packages already in the environment. A no-op or web-only plan syncs nothing.
- **Dashboard build.** `npm run build` runs with `PYTHON` set to the service's interpreter. Before the build is swapped into `web/dist`, directories are set to 0755 and files to 0644, so the swapped directory stays readable by the server.
- **Untracked files.** Before the drain, a checkout upgrade refuses, and lists the files, when untracked files match a component's include or verify patterns (the files the fingerprints hash). `uv.lock`, `__pycache__`, `node_modules` and Git-ignored files are not counted.
- **Start failure.** If the start after the stop and install fails or times out, the upgrade stops any partial process, starts the current install once more, cancels the drain, and still reports the failure. The report (a JSON line) gains `serving`: true on success, otherwise whether the service answered a status request.
- **Web-only wheel.** A web-only wheel upgrade installs the rest of the wheel (without dependencies) and publishes the dashboard atomically.
- **Docs.** The hot-upgrade RFC (Chinese) now describes these rules.
- **Known limits.** The review of [#977](https://github.com/foolzzz/looper/pull/977) noted, without a fix in this release: an upgrade run from an install other than the one the service unit runs can update the wrong install and report success; Git-ignored files under `web/src` (for example `.DS_Store`) are hashed by the fingerprint but not refused, so the post-upgrade component check can fail; a stop that raises during recovery leaves the unit down; and after a recovered start failure the report shows the old code fingerprint.
- **Model-visible changes:** No. No prompt, tool description, tool schema or Manager confirmation text changes.

### 升级决策

**谁需要升级：**希望保持在最新补丁线的人，以及用 `looper service upgrade` 升级运行中服务的人。

**解决了什么：**[#977](https://github.com/foolzzz/looper/pull/977) 修复了在真实安装上演练 `looper service upgrade` 时发现的问题：checkout 的 NOOP 和 WEB_ONLY 升级不再同步依赖；控制台构建使用服务的 Python；替换后的 `web/dist` 对服务器可读；停止和安装之后启动失败时会恢复而不是让服务单元停着；新增 `--turns-timeout` 且 CONTROL_PLANE 使用它；指纹所哈希的未跟踪文件在排空前被拒绝；WEB_ONLY 的 wheel 升级会安装包的其余部分。

**是否有破坏性变更：**否。不新增或移除 API 或迁移。checkout 升级现在可能因未跟踪的组件文件而拒绝（见行为变化）。

**如何验证：**运行 `looper --version` 核对版本为 2.14.51。

**贡献者：**维护者 @foolzzz 提交 [#977](https://github.com/foolzzz/looper/pull/977)；本版本无社区贡献。

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.50 上的安装可直接升级。本版本没有新迁移。

### 行为变化与入口

- **`--turns-timeout`（[#977](https://github.com/foolzzz/looper/pull/977)）。**`looper service upgrade` 新增 `--turns-timeout`（默认 180 秒）。CONTROL_PLANE 计划用它代替 `--drain-timeout` 作为排空上限；FULL 计划仍用 `--drain-timeout`。`--timeout`、`--drain-timeout` 和 `--turns-timeout` 必须是有限正数，否则命令报错停止。
- **checkout 的依赖。**`uv sync` 现在只在 FULL 和 CONTROL_PLANE 计划中运行，命令为 `uv sync --extra test --inexact`，保留部署的测试依赖和环境中已有的其他包。NOOP 或 WEB_ONLY 计划不同步任何依赖。
- **控制台构建。**`npm run build` 以服务解释器设置 `PYTHON` 运行。构建结果换入 `web/dist` 之前，目录设为 0755、文件设为 0644，保证服务器可读。
- **未跟踪文件。**排空之前，若未跟踪文件匹配某组件的 include 或 verify 模式（即指纹所哈希的文件），checkout 升级会拒绝并列出这些文件。`uv.lock`、`__pycache__`、`node_modules` 和 Git 忽略的文件不计入。
- **启动失败。**停止和安装之后的启动失败或超时时，升级会结束残留进程，用当前安装再启动一次，取消排空，并仍报告失败。报告（一行 JSON）新增 `serving`：成功时为 true，否则表示服务是否响应了状态请求。
- **WEB_ONLY 的 wheel。**WEB_ONLY 的 wheel 升级会安装 wheel 的其余部分（不含依赖），并原子发布控制台。
- **文档。**热升级 RFC（中文）已写明这些规则。
- **已知局限。**[#977](https://github.com/foolzzz/looper/pull/977) 的评审指出但本版本未修复：从服务单元所用安装之外的安装运行升级，可能更新错误的安装却报告成功；`web/src` 下被 Git 忽略的文件（如 `.DS_Store`）会被指纹哈希但不会被拒绝，升级后的组件检查可能失败；恢复时停止若抛出错误，服务单元会保持停止；启动失败恢复后，报告仍显示旧的代码指纹。
- **面向模型的变化：**无。没有 prompt、工具描述、工具 schema 或 Manager 确认文本的变化。
