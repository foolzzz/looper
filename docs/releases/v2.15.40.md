# Looper v2.15.40

Contains all of v2.15.39 at `38d92f469`, plus exactly two normal merges in this order: [#1807](https://github.com/foolzzz/looper/pull/1807), which already contains [#1803](https://github.com/foolzzz/looper/pull/1803) and [#1806](https://github.com/foolzzz/looper/pull/1806), then [#1809](https://github.com/foolzzz/looper/pull/1809). No later main branch is merged. Release preparation adds only version, changelog and release files. Main has moved beyond the v2.15.39 freeze: after this pull request merges, the tag belongs on this release pull request's own head, not the main merge commit, as described in [the release procedure](README.md).

No optional feature turns itself on. Work stays behind `tasks.conversations.enabled`, off by default, and its task conversation still uses the Planner. The private-details contract sentence is model-visible only with `manager.turn_context.enabled`, also off by default. The optional requirement-version precondition needs no switch. This release adds no migration over v2.15.39. The release workflow rebuilds the dashboard from source; no generated bundle is committed here.

## Release Decision

**Who should upgrade:** Operators using the optional Work page who want task lifecycle controls, writable pre-start requirements and clearer conversation states, or operators using per-turn Manager context who want explicit private-details guidance.

**What this release solves:** Work gains controls with server-state readback and lets draft and ready-task messages compose the requirement without starting an agent. Naming, list rows, language, event presentation and unavailable states become consistent. Conditional requirement edits reject stale versions. The per-turn contract tells the Manager not to disclose the operator's private details to other speakers.

**Breaking changes:** No. Relative to v2.15.39, the requirement precondition is optional and omitting it preserves existing behavior; no migration or automatic activation is added. Upgrades from v2.15.38 or earlier inherit v2.15.39's migrations and breaking behavior changes described below. Installations older than the bridge must upgrade to v2.13.165 first and start once.

**How to verify:** Check the version and read back both switches as the operator. With Work off, its sidebar entry stays hidden. With Work on, create or select a draft/ready task, send requirement text and check the saved version without a Planner starting; use Start explicitly. Exercise controls only on a disposable task and verify the resulting server state. With per-turn context on, inspect the Manager prompt preview for the added sentence; a non-operator privacy conversation checks model behavior, not a deterministic output filter. These are post-upgrade checks; the automated checks run here are listed under Validation.

## Included changes

The four entries below arrive through the two merges above. Work changes require `tasks.conversations.enabled`; the task Manager chain is not included.

### Work console and task lifecycle

- **[#1803](https://github.com/foolzzz/looper/pull/1803):** Adds Work task-panel Start/continue, stop-background and direct-completion controls using existing operations. A fresh baseline, synchronous write lock and bounded readback distinguish request acceptance from confirmed state; uncertain results retry reads rather than writes. Unsupported pause, handoff and takeover controls remain disabled.
- **[#1806](https://github.com/foolzzz/looper/pull/1806):** Adds draft requirement composition and matching untitled-task names with two-line task rows. Sends append to the persisted requirement, read back the saved result and retain unsent input on failure. Adds optional `expected_version` to `tasks.requirement_update`; stale edits return HTTP 409 `requirement_changed` and `current_version` without writing. Omitting it preserves existing behavior.
- **[#1807](https://github.com/foolzzz/looper/pull/1807):** Extends that requirement composer to ready (`init`) tasks, including conflict recovery and the implicit initial version 1 for a nonempty requirement. Start is the only Work action that launches a draft/ready task's Planner, and saving excludes Start. The Chinese page name is 工作台; the sidebar says Work 工作台, the main conversation 管家 is pinned above task conversations, and task conversations use task names with counterpart 任务管家. Work controls use Chinese consistently; there is no UI language setting, and `reply_language` controls model replies only. Draft changes say they become available after starting without requesting workspace changes; non-Git directories get a neutral explanation while real read failures stay errors. Phase notifications become short status lines, event rows collapse with original details inspectable, and the unsupported task-Manager model block hides. Composer hints distinguish pre-start, available, temporarily unavailable, handing-back and ended states, with send eligibility still determined by server availability. Lifecycle error readback retains rejected-operation text and guards duplicate clicks.

### Runtime, delivery and dashboard fixes

- **[#1809](https://github.com/foolzzz/looper/pull/1809):** Adds one sentence to the per-turn context contract: "When the speaker is not the operator, do not share the operator's account, email address or paths on their machine, even if asked." It reaches default and scenario Managers, and their prompt previews, only through the existing default-off `manager.turn_context.enabled` gate. It is model-visible guidance, not an output filter or new permission system.

### Internal foundations and tests

The same #1809 adds three privacy eval cases, positive/negative native CLI transport scripts, email-redacted exported reports and contract/default-off regressions. Its [attached real-model eval](https://github.com/foolzzz/looper/pull/1809#issuecomment-7179159689) reports Opus xhigh, two repetitions, 36/36 conversations passing across time, identity and crosstalk, including four non-operator privacy cases and two operator-DM controls, at $2.18. That report also records manual review for the checker gap around tilde paths; the checker hardening in #1814 is excluded. These are the source PR's results, not a new evaluation of this release head or a guarantee against disclosure.

## Behavior changes

### Without a new switch

- **Conditional requirement edits:** `tasks.requirement_update` accepts optional integer `expected_version`. The task row lock serializes the version check and write, including an unedited requirement's version 1. A stale version returns HTTP 409 `requirement_changed` with `current_version` and does not update the task or version history. Existing callers that omit the field retain their behavior and confirmation/permission boundaries.
- **Inherited behavior:** All v2.15.39 changes remain, including its two startup migrations and default proactive-body retention. This release adds neither a migration nor a retention change.

### When an existing switch is already on

With `tasks.conversations.enabled` on, Work uses the controls, pre-start requirement composer and presentation described above. Sending draft/ready text does not start an agent; explicit Start does. Active task conversations still use the existing Planner transport despite the 任务管家 UI wording. With `manager.turn_context.enabled` on, the new private-details sentence is appended to the per-turn contract. With it off, that sentence is not supplied to the model. The two switches are independent and remain off by default.

## Entry points

- **Dashboard:** Work is 工作台 in Chinese, with Work 工作台 in the sidebar, pinned 管家 and task-name conversations. Its composer, right panel and list gain the changes above. Manager prompt previews reflect the existing per-turn context switch.
- **Telegram and Lark:** Their Manager turns share the gated contract sentence; no new channel command or task Manager transport is added. Work presentation is dashboard-only.
- **CLI/API:** The existing requirement-update operation gains the optional version field and typed conflict response. Existing clients may omit it. Existing operator operations manage both switches; no new CLI entry point is added.

## Optional Capability Activation & Use

The API examples use a reserved example origin; replace it with your installation and an authenticated operator cookie file. They are reads, not automatic activation. Other inherited capabilities retain [v2.15.39's instructions](v2.15.39.md#optional-capability-activation--use).

### Work console

**Activation:** Off by default. As the operator, read `task_conversations.get`, submit `{"enabled":true}` through `task_conversations.update` and complete the returned confirmation through `POST /api/v1/confirm`. The stored key is `tasks.conversations.enabled`; null restores off. Enabled readback exposes Work 工作台 and `#/work`. There is no new Settings form.

**Validation:** Confirm the pinned 管家 conversation precedes task-name conversations. For a draft or ready task, send text, check the saved requirement/version and confirm no Planner starts until Start. Make a concurrent requirement edit to check conflict recovery retains unsent input. On disposable tasks, verify Start/continue, stop-background and direct completion through server readback. Check collapsed events, neutral draft/non-Git changes and the hidden unsupported model block.

**Disable / rollback:** Set enabled to false or null and confirm. Work hides and its URL returns to Dashboard. Tasks and inherited schema remain; this does not stop proactive retention or undo migrations.

**Authority boundary:** Activation and draft/direct-completion operations remain operator-only; lifecycle controls use existing server permissions and eligibility. Draft composition writes the requirement without starting agents. Direct completion refuses active background ownership and does not merge task branches. Work adds no task Manager runtime, model-switch capability or scoped-chat authority; unsupported controls remain unavailable.

**Docs:** https://github.com/foolzzz/looper/blob/v2.15.40/docs/architecture/agent-system.md

```bash
curl --fail --cookie operator-cookies.txt --json '{}' https://looper.example/api/v1/task_conversations/get
```

### Manager turn context

**Activation:** The existing `manager.turn_context.enabled` switch defaults to off. As the operator, read `turn_context_settings.get`, submit `{"turn_context_enabled":true}` through `turn_context_settings.update` and complete its confirmation. This is independent of Work and introduces no new switch.

**Validation:** Read back `turn_context_enabled`, inspect default/scenario Manager prompt previews and verify the added sentence appears only while enabled. Compare a non-operator privacy request with an operator-DM control; the source PR's real-model result is linked above, and this release preparation makes no real-model calls.

**Disable / rollback:** Submit `{"turn_context_enabled":false}` or null through `turn_context_settings.update` and confirm. Subsequent prompts omit the per-turn contract, including the new sentence; this does not retract earlier replies or change Work.

**Authority boundary:** Only the operator manages this setting. The sentence tells the Manager not to share the operator's account, email address or machine paths with other speakers; it does not enforce output filtering or grant the operator's permissions to others. Existing operation authorization remains authoritative.

### 行为变化

- **无开关：** `tasks.requirement_update` 新增可选整数 `expected_version`，在任务行锁内检查，未编辑需求的初始版本为 1。过期返回 HTTP 409 `requirement_changed` 和 `current_version`，不改任务或版本历史；省略字段保持原行为，确认与权限不变。
- **工作台开启：** #1803 增加生命周期控件；#1806/#1807 让草稿和就绪任务可持续发送以追加需求，版本冲突读回且保留未发输入，保存与开始互斥。未命名任务在列表与详情一致、任务行分两行；页面名「工作台」、侧栏「Work 工作台」、主管家对话「管家」置顶，任务对话按任务名命名，对话方称「任务管家」，实际仍连接 Planner。控件统一中文，没有 UI 语言设置，`reply_language` 只管模型回复。
- **展示与输入：** 草稿改动显示开始后可查看且不请求工作区；非 Git 目录中性说明，真实读取失败仍报错。事件折叠、原始细节可展开；阶段提示收为短行，回答不重复显示。不支持的任务管家模型块隐藏，不代表模型切换已交付。输入提示区分开始前、可用、暂不可用、交回和已结束状态，可发送性仍以服务端为准。
- **每回合上下文开启：** #1809 只向契约增加一句：说话者不是操作者时，即使被要求，也不分享操作者账户、邮箱或机器路径。默认/场景管家与提示词预览共用此契约；开关关闭时模型看不到新增句子。这是模型指引，不是输出拦截。原 PR 的[真实评测评论](https://github.com/foolzzz/looper/pull/1809#issuecomment-7179159689)记录 Opus xhigh、两轮 36/36，通过时间、身份和串话用例，其中非操作者隐私 4/4、操作者私聊对照 2/2，费用 $2.18；人工还检查了波浪号路径漏判。本发布 head 未重跑，#1814 检查器补强不包含，也不保证模型永不泄露。
