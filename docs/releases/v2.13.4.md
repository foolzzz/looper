# Looper v2.13.4

## Release Decision

**Who should upgrade:** Operators who use the dashboard's task Pipeline tab and want to see which runtime and model each Planner, Worker and Reviewer run used. No one else needs this release for runtime behavior.

**What this release solves:** [#274](https://github.com/foolzzz/looper/pull/274) adds an Agent line (runtime, model, effort) to the Pipeline node cards shown on hover, taken from the latest run of that role.

**Breaking changes:** No. The change is dashboard-only; the API, configuration, registry schema, CLI and channels are unchanged from [v2.13.3](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.3.md).

**How to verify:** Check the version, then open a task that has run, go to its Pipeline tab and hover a Planner, Worker or Reviewer node.

**Contributors:** Maintainer @foolzzz authored [#274](https://github.com/foolzzz/looper/pull/274); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.4
```

## Behavior changes

- **Dashboard, Pipeline cards:** `stepCard` and `plannerCard` (`web/src/lib/node-cards.ts`) add an `Agent` fact under the Worker, Reviewer and Planner lines of the "Runs" section. Its value is the runtime name, the model and the effort joined by " · ", read from the latest run (by `created_at`, then id) of that role. For a step the run is the latest one whose `metadata.step_id` is that step. The model is the record's `model`, falling back to `metadata.model_choice.model`. The line appears only when the step has a Worker or Reviewer (or the task a Planner) and such a run exists; otherwise the card is unchanged.
- **Dashboard, run loading:** The task page (`web/src/pages/task-detail.tsx`) now reads the task's runs through a new `useTaskRuns` hook (`web/src/lib/use-task-runs.ts`): the Planner, Worker and Reviewer records from `GET /api/llm-records`, up to 500 per role. They are read again when the task status, the Planner or a step's status, Worker, Reviewer, review stage or retries change. The Agents tab used to read Worker and Reviewer records itself, only while it was open; it now shares the page's read, so the task page makes these requests (now three, with the Planner) whether or not that tab is open. The Agents tab's contents are unchanged.
- **API:** None. `GET /api/llm-records` is called with the same parameters and no server code changed.
- **Model-visible changes:** None. No prompt, tool, Manager schema, runtime launch argument or model-facing text changed.

## Entry points

- **Dashboard:** Task page, Pipeline tab node cards, as above.
- **CLI, Telegram/Lark channels, Manager tools and prompts:** No change.

## Upgrade and rollback

No action is needed beyond the usual re-run of `install.sh` once v2.13.4 is published; there is no configuration, data or migration change. Rolling back to v2.13.3 is safe: the cards simply lose the Agent line.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.

## 中文摘要

### 升级决策

**谁需要升级：**使用仪表盘任务 Pipeline 标签页、希望看到 Planner、Worker、Reviewer 各次运行所用 runtime 和模型的运维者。运行时行为方面其他人无需升级。

**解决了什么：**[#274](https://github.com/foolzzz/looper/pull/274) 在 Pipeline 节点悬停卡片中新增 Agent 一行（runtime、模型、effort），取自该角色最近一次运行。

**是否有破坏性变更：**无。仅涉及仪表盘；API、配置、registry schema、CLI 和渠道与 [v2.13.3](https://github.com/foolzzz/looper/blob/main/docs/releases/v2.13.3.md) 相同。

**如何验证：**核对版本，然后打开一个已运行过的任务，进入 Pipeline 标签页，悬停 Planner、Worker 或 Reviewer 节点。

**贡献者：**维护者 @foolzzz 提交 [#274](https://github.com/foolzzz/looper/pull/274)；本次 patch release 无社区贡献。

```bash
looper --version   # looper 2.13.4
```

### 行为变化与入口

- Pipeline 卡片在 “Runs” 部分的 Worker、Reviewer、Planner 行下新增 `Agent` 一项，值为 runtime 名、模型、effort（以 “ · ” 连接），取自该角色最近一次运行（按 `created_at`，再按 id）；步骤取 `metadata.step_id` 为该步骤的最近一次。模型取记录的 `model`，缺失时回退到 `metadata.model_choice.model`。仅当对应运行存在时显示，否则卡片不变。
- 任务页通过新的 `useTaskRuns` 一次性读取 Planner、Worker、Reviewer 的运行记录（每角色最多 500 条），任务状态、Planner 或步骤的状态、Worker、Reviewer、评审阶段、重试次数变化时重新读取。此前 Agents 标签页只在打开时自行读取 Worker 和 Reviewer 记录；现在与页面共享，无论该标签页是否打开，任务页都会发出这些请求（加上 Planner 共三个）。Agents 标签页内容不变。
- API 无变化；服务端代码未改动。
- 对模型可见的内容（提示词、工具、Manager schema、运行时启动参数、面向模型的文本）无变化。
- CLI、Telegram/Lark、Manager 工具和提示词均无变化。

### 升级与回退

发布后照常重跑 `install.sh` 即可，无配置、数据或迁移变更；回退到 v2.13.3 同样安全：卡片只是少了 Agent 一行。

### 可选能力启用与使用

本版本未新增可选能力启用入口。
