# Looper v2.13.26

## Release Decision

**Who should upgrade:** Contributors and CI runners that run Looper's test suite. Users of the installed product see no change.

**What this release solves:** [#368](https://github.com/foolzzz/looper/pull/368) fixes the review follow-ups of #298. It removes a flaky test, `test_a_failed_wait_turn_retries_twice_then_again_on_a_later_event`, whose first retry wait was only 0.4s, so under load the automatic retry could fall due during the test's 0.05s pause.

**Breaking changes:** No. No CLI command, configuration key, API or database schema changed.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#368](https://github.com/foolzzz/looper/pull/368); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.26
```

## Behavior changes

- **Test timing only:** in `tests/test_planner_waits.py` the test sets the retry waits to `(1.5, 0.3)` seconds (was `(0.4, 0.4)`) and the planner's gate idle check to 1.0s (was 0.3s). It adds a 0.5s pause before counting turns, so a retry event queued while the last retry ran can still be handled, and lengthens the stalled-check pause from 0.5s to 1.3s. A comment in the test explains why the first wait is long next to the 0.05s pause.
- **No runtime change:** the only file changed is the test; `looper/` code is untouched.
- **Model-visible changes:** None. No prompt text, tool schema or tool result changed.

## Upgrade and rollback

Re-run `install.sh` once v2.13.26 is published. There is no schema or configuration change. Rolling back to v2.13.25 is safe; the installed behavior is identical, and only the test suite is flakier under load.

## Optional Capability Activation & Use

No new optional capability activation is introduced in this release.
