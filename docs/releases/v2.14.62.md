# Looper v2.14.62

This is the patch release v2.14.62, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.61: a gated firing that a drain deferred now starts before a later Run now of a parallel schedule ([#1047](https://github.com/foolzzz/looper/pull/1047)).

## Release Decision

**Who should upgrade:** Operators who run `parallel` schedules with a gate and upgrade or drain the service while such a schedule fires. Others need not upgrade.

**What this release solves:** A gated firing of a `parallel` schedule may commit just as a drain begins. It is then requeued with `deferred_by_drain` and its gate unstarted. After the restart or the cancelled drain, the next scheduler pass resumes it first, but a Run now made between the end of the drain and that pass saw no gating run and a free slot and started a new gate. The newer firing took the slot, and the deferred firing waited until a slot freed with no gate running. [#1047](https://github.com/foolzzz/looper/pull/1047) makes the deferred firing start first: when `Scheduler._fire` finds such a queued run, no gating run and a free slot, it records the newer firing as `skipped_overlap` with the error "an earlier firing that a drain deferred starts first" and, once the transaction commits, resumes the deferred run through `_start_queued`. This is the state the tick path already reaches.

**Breaking changes:** No. No API or configuration changes and there is no migration.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#1047](https://github.com/foolzzz/looper/pull/1047); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.62
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.61 upgrades directly. This release adds no migration.

## Behavior changes

- **Parallel schedules, deferred gate first.** On a `parallel` schedule, when a queued run with `deferred_by_drain` exists, no run is gating and a slot is free, a Run now or due fire no longer launches the newer firing. It is recorded as `skipped_overlap` with the error "an earlier firing that a drain deferred starts first", and the deferred run starts its gate through `_start_queued` after the transaction commits (`resume_queued` on `_Launched`, `looper/agents/scheduler.py`). When the slot is full the existing "N runs are in progress" skip reason is kept and the deferred run stays queued.
- **Unchanged:** non-deferred queued runs of a parallel schedule, `queue` and `skip` schedules, and command schedules (never deferred).
- **Docs:** `docs/architecture/agent-system.md` describes the new ordering in its drain section.
- **Size:** 9 added lines of production code, 71 of tests (`tests/test_drain_services_db.py`).
- **Model-visible changes:** No. The Manager prompt, tool documentation and confirmation texts are unchanged. The new skip error text appears only in the run record.

### 升级决策

**谁需要升级：**运行带门控的 `parallel` 计划、并在其触发时升级或排空服务的运维者。其他人无需升级。

**解决了什么：**`parallel` 计划的门控触发可能恰在排空开始时提交，随后以 `deferred_by_drain` 重新排队且门控未启动。重启或取消排空后，下一轮调度会优先恢复它，但在排空结束与该轮调度之间执行的 Run now 看到没有门控中的运行且有空闲槽位，于是启动了新的门控，较新的触发占用槽位，被推迟的触发要等到槽位空出且无门控运行。[#1047](https://github.com/foolzzz/looper/pull/1047) 让被推迟的触发先启动：`Scheduler._fire` 发现这样的排队运行、无门控运行且有空闲槽位时，把较新的触发记为 `skipped_overlap`（错误信息为 “an earlier firing that a drain deferred starts first”），并在事务提交后通过 `_start_queued` 恢复被推迟的运行。这与定时 tick 路径本来就会到达的状态一致。

**是否有破坏性变更：**否。没有 API 或配置变更，也没有迁移。

**如何验证：**运行 `looper --version` 核对版本为 2.14.62。

### 行为变化与入口

- **parallel 计划中被推迟的门控优先。**在 `parallel` 计划上，存在 `deferred_by_drain` 的排队运行、没有门控中的运行且有空闲槽位时，Run now 或到期触发不再启动较新的触发：它被记为 `skipped_overlap`，错误为 “an earlier firing that a drain deferred starts first”，被推迟的运行在事务提交后通过 `_start_queued` 启动门控（`looper/agents/scheduler.py` 中 `_Launched` 的 `resume_queued`）。槽位已满时沿用原有的 “N runs are in progress” 跳过原因，被推迟的运行保持排队。
- **不变：**parallel 计划中非推迟的排队运行、`queue` 和 `skip` 计划、命令计划（从不被推迟）。
- **文档：**`docs/architecture/agent-system.md` 的排空一节描述了新的顺序。
- **规模：**生产代码新增 9 行，测试新增 71 行（`tests/test_drain_services_db.py`）。
