# Looper v2.15.13

This is the patch release v2.15.13, a hotfix line in which each merged change ships at once. It documents six changes: [#1397](https://github.com/foolzzz/looper/pull/1397) (running agent processes with tokens per minute), [#1398](https://github.com/foolzzz/looper/pull/1398), [#1400](https://github.com/foolzzz/looper/pull/1400) and [#1401](https://github.com/foolzzz/looper/pull/1401) (the dashboard on phones, three steps), [#1399](https://github.com/foolzzz/looper/pull/1399) (Lark messages that start with an @-mention) and [#1403](https://github.com/foolzzz/looper/pull/1403) (the Tasks list hides schedule-created tasks by default).

## Release Decision

**Who should upgrade:** Anyone who opens the dashboard on a phone or tablet; anyone whose Manager answers in a Lark chat can start with an @-mention; anyone whose project Tasks list is flooded by tasks that agent schedules create; and anyone who wants to see which agent processes run now and how many tokens per minute they use.

**What this release solves:** [#1397](https://github.com/foolzzz/looper/pull/1397) lists every running agent process with its TPM on the dashboard. [#1398](https://github.com/foolzzz/looper/pull/1398), [#1400](https://github.com/foolzzz/looper/pull/1400) and [#1401](https://github.com/foolzzz/looper/pull/1401) fix what blocked the dashboard at phone widths (New project dialog, drawer scrolling, Chat header, sideways panning, task header, tab bars, touch sizing, pipeline zoom). [#1399](https://github.com/foolzzz/looper/pull/1399) delivers Lark messages whose body starts with `@`, which lark-cli used to reject. [#1403](https://github.com/foolzzz/looper/pull/1403) hides schedule-created tasks on the dashboard's Tasks list by default.

**Breaking changes:** No. There is no schema migration and no existing API field changes; `tasks.page` and the system overview only gain fields, and the `tasks.page` default is unchanged. Two dashboard defaults change (see Behavior changes). The bridge boundary is unchanged: upgrade to v2.13.165 first if the installation is older.

**How to verify:** Check the installed version.

```bash
looper --version   # looper 2.15.13
```

**Contributors:** Maintainer @foolzzz authored [#1397](https://github.com/foolzzz/looper/pull/1397), [#1398](https://github.com/foolzzz/looper/pull/1398), [#1399](https://github.com/foolzzz/looper/pull/1399), [#1400](https://github.com/foolzzz/looper/pull/1400), [#1401](https://github.com/foolzzz/looper/pull/1401), [#1403](https://github.com/foolzzz/looper/pull/1403); no community contribution was included in this release.

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.15.12 upgrades directly. This release has no PostgreSQL migration. Restart the service after upgrading, as for every release.

## Behavior changes

### [#1397](https://github.com/foolzzz/looper/pull/1397): running agent processes with tokens per minute

- **Process table.** "Agents running now" on the dashboard lists each running Manager or Planner turn and Worker, Reviewer or consult run with runtime, model, PID, time and TPM (the four token kinds on hover), then the step runs waiting for room. The header shows the total TPM of all agents. Managers without a row (busy before their turn's run starts, or idle) are named below the table.
- **API.** `/api/v1/system/overview` gains `processes` and `tpm` (tokens in the last `window_seconds`, runs that ended within it included), filtered by the same Manager and project scope as the rest. `agents` is unchanged, so the Manager tool `looper_overview` and `loopercli overview` keep their result.
- **TPM.** It counts input, output, cache read and cache write tokens over a 60 s window. Claude Code, OMP, Grok, DSH, Pi and the API runtime stream usage per request, message or step. Codex, Coco and Cursor report usage only when a turn ends: their rows show "—" and what they report still counts in the total. A resumed kept run's replay is not counted again. The run list is in memory only.
- **Listing.** Only runs going on now are listed: a Planner or Manager between turns has no row.

### [#1398](https://github.com/foolzzz/looper/pull/1398), [#1400](https://github.com/foolzzz/looper/pull/1400), [#1401](https://github.com/foolzzz/looper/pull/1401): the dashboard on phones

- **New project dialog.** It rendered 223 px wide inside the sidebar, on desktop too; it now renders on `document.body`. Escape closes only the dialog. Before, Escape on a dialog opened from the drawer closed the drawer and left the dialog open. Behavior change: Escape no longer closes the drawer behind the dialog.
- **Drawer.** When it is taller than the screen, the whole column scrolls; Import / Export stay reachable.
- **Touch sizing (#1400).** Under `pointer: coarse` only, form text is 16 px (no iOS focus zoom) and Button, Input, selects, sidebar items and the Switch hit area are 44 px. Full-height layouts use `dvh`. Desktop with a mouse is unchanged.
- **Task detail header (#1401).** Below `lg`, the task id, project selector, schedule badge, "continues the schedule's Planner session" and "Created by" are behind a **Details** toggle; title, status, phase and Stop / Start / Start over stay visible.
- **Tab bars.** The project and task tabs are one row that scrolls sideways, with edge fades, and the selected tab is scrolled into view when the strip overflows.
- **Chat.** The conversation list is an aside from `lg` (it was `md`), so on 768 to 1023 px it is behind the Conversations toggle. The raw session id shows only from `lg`. Below `sm` the header no longer shows the "Online" dot. The header row wraps so New conversation and New session stay on screen.
- **Pipeline.** In a Pipeline narrower than 640 px, every fit zooms to at least 10/12, so a node name stays at least 10 px; wider Pipelines fit as before.
- **Other layout.** The project Overview, task Overview work directory and the History `cwd:` line no longer pan the page sideways. Tasks rows move their actions under the title below `sm`; the Delete button has an accessible name. Registry card headers and Runs role cards are rearranged below `sm` or `lg`. The Tasks Manager filter is 32 px with a mouse at every width and 44 px on touch.
- **Not verified:** a real phone (iOS Safari rendering of the tab mask, momentum scrolling, touch panning of the Pipeline).

### [#1399](https://github.com/foolzzz/looper/pull/1399): Lark messages that start with an @-mention

- A body that starts with `@` made lark-cli read it as `@path` and fail, so the reply was recorded as undelivered. `send_command`, `reply_command` and `edit_command` in `looper/agents/channels/lark_cli.py` now pass such a body with one more `@` (lark-cli takes `@@` for a literal `@`), so the chat shows it as written. Every other body is unchanged. Only the Lark channel is affected.
- Known limit: a body that is exactly `-` still makes lark-cli read stdin.

### [#1403](https://github.com/foolzzz/looper/pull/1403): the Tasks list hides schedule-created tasks by default

- **Dashboard.** The Tasks list and the project Overview "Tasks" preview hide tasks that an agent schedule created. A checkbox "Hide tasks from schedules" (checked by default) shows "N hidden" beside it; unchecking writes `scheduled=include` to the address, and a link without the parameter hides them. With `schedule=<id>` the box is disabled. The Dashboard's group counts and needs-you links open the list with `scheduled=include`.
- **API.** `tasks.page` (`POST /api/v1/tasks/page`) gains the optional `exclude_scheduled` (default false) and returns `hidden_scheduled`. `exclude_scheduled` together with `schedule_id` is a 400 `invalid`. The API default is unchanged: Manager tools, `loopercli` and other clients see every task unless they pass it.
- Tasks that a command schedule's script creates through `loopercli task-create` carry no schedule link and stay visible.

### Model-visible changes

None. No prompt text or Manager tool schema changes. Operation schemas for `tasks.page` gain `exclude_scheduled` and `hidden_scheduled`.

### 行为变化与入口

**[#1397](https://github.com/foolzzz/looper/pull/1397)：运行中的 Agent 进程与 TPM**

- **进程表。**仪表盘“Agents running now”列出每个运行中的 Manager 或 Planner 回合和 Worker、Reviewer、咨询运行，含运行时、模型、PID、时间和 TPM（悬停显示四类 token），之后是等待空位的步骤运行。表头显示所有 Agent 的 TPM 总和。没有行的 Manager（回合的运行尚未开始时忙碌，或空闲）在表格下方点名。
- **API。**`/api/v1/system/overview` 新增 `processes` 和 `tpm`（最近 `window_seconds` 内的 token，窗口内已结束的运行也计入），按与其余内容相同的 Manager 和项目范围过滤。`agents` 不变，因此 Manager 工具 `looper_overview` 和 `loopercli overview` 的结果不变。
- **TPM。**统计 60 秒窗口内的输入、输出、缓存读和缓存写 token。Claude Code、OMP、Grok、DSH、Pi 和 API 运行时按请求、消息或步骤上报用量；Codex、Coco 和 Cursor 只在回合结束时上报：其行显示“—”，所报的 token 仍计入总数。恢复的保留运行的回放不会重复计数。运行列表只在内存中。
- **列表范围。**只列出正在进行的运行：回合之间的 Planner 或 Manager 没有行。

**[#1398](https://github.com/foolzzz/looper/pull/1398)、[#1400](https://github.com/foolzzz/looper/pull/1400)、[#1401](https://github.com/foolzzz/looper/pull/1401)：仪表盘手机适配**

- **新建项目对话框。**此前它在侧栏内只有 223 px 宽（桌面也是）；现在渲染在 `document.body` 上。Escape 只关闭对话框；此前从抽屉打开的对话框按 Escape 会关掉抽屉而对话框仍开着。行为变化：Escape 不再关闭对话框背后的抽屉。
- **抽屉。**高于屏幕时整列可滚动，Import / Export 可以到达。
- **触控尺寸（#1400）。**仅在 `pointer: coarse` 下，表单文字为 16 px（避免 iOS 聚焦缩放），Button、Input、select、侧栏项和 Switch 点击区为 44 px。整屏高度布局使用 `dvh`。使用鼠标的桌面不变。
- **任务详情头部（#1401）。**`lg` 以下，任务 id、项目选择器、定时任务标记、“沿用定时任务的 Planner 会话”和“Created by”收在 **Details** 开关后；标题、状态、阶段和 Stop / Start / Start over 始终可见。
- **标签栏。**项目和任务标签栏为一行，可横向滚动，两端有渐隐提示，溢出时自动滚到所选标签。
- **Chat。**会话列表从 `lg` 起为侧栏（此前是 `md`），因此 768 到 1023 px 时收在 Conversations 开关后。原始会话 id 仅从 `lg` 起显示。`sm` 以下头部不再显示“Online”圆点。头部行会换行，New conversation 和 New session 保持在屏内。
- **流水线。**宽度小于 640 px 的流水线，每次适配缩放至少为 10/12，节点名至少 10 px；更宽的流水线与之前一样适配。
- **其他布局。**项目概览、任务概览的工作目录和 History 的 `cwd:` 行不再使页面横向拖动。`sm` 以下 Tasks 行的操作移到标题下方，Delete 按钮有了可访问名称。Registry 卡片头部和 Runs 角色卡片在 `sm` 或 `lg` 以下重新排布。Tasks 的 Manager 筛选在鼠标下任何宽度均为 32 px，触屏为 44 px。
- **未验证：**真机（iOS Safari 对标签遮罩的渲染、惯性滚动、流水线触摸拖动）。

**[#1399](https://github.com/foolzzz/looper/pull/1399)：以 @ 开头的 Lark 消息**

- 以 `@` 开头的正文会被 lark-cli 读作 `@path` 而失败，回复因此被记为未送达。`looper/agents/channels/lark_cli.py` 的 `send_command`、`reply_command` 和 `edit_command` 现在对这类正文多加一个 `@`（lark-cli 用 `@@` 表示字面 `@`），聊天里显示原文。其他正文不变。只有 Lark 通道受影响。
- 已知限制：正文恰为 `-` 时，lark-cli 仍会读取 stdin。

**[#1403](https://github.com/foolzzz/looper/pull/1403)：Tasks 列表默认隐藏定时任务创建的任务**

- **仪表盘。**Tasks 列表和项目概览的 “Tasks” 预览隐藏 Agent 定时任务创建的任务。复选框 “Hide tasks from schedules”（默认勾选）旁显示 “N hidden”；取消勾选会在地址中写入 `scheduled=include`，不带该参数的链接则隐藏。带 `schedule=<id>` 时复选框禁用。仪表盘的分组计数和待处理链接以 `scheduled=include` 打开列表。
- **API。**`tasks.page`（`POST /api/v1/tasks/page`）新增可选的 `exclude_scheduled`（默认 false），并返回 `hidden_scheduled`。`exclude_scheduled` 与 `schedule_id` 同时给出是 400 `invalid`。API 默认不变：Manager 工具、`loopercli` 和其他客户端看到全部任务，除非传该参数。
- 命令类定时任务的脚本通过 `loopercli task-create` 创建的任务没有定时任务链接，仍然可见。

**面向模型的变化：**

无。提示词文本和 Manager 工具 schema 都不变。`tasks.page` 的操作 schema 新增 `exclude_scheduled` 和 `hidden_scheduled`。
