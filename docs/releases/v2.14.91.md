# Looper v2.14.91

This is the patch release v2.14.91, a hotfix line in which each merged change ships at once. It ships the one change merged since v2.14.90: Cursor runs show each message once in the activity and use a private helper per run ([#1119](https://github.com/foolzzz/looper/pull/1119)).

## Release Decision

**Who should upgrade:** Operators who run the Cursor Agent runtime (native or TTADK), especially with concurrent runs in one working directory. Everyone else can stay.

**What this release solves:** After Cursor's network retries, the discarded attempts' assistant text still reached the task activity, so one report could appear several times. Cursor also put its `worker-server` socket under a `TMPDIR` path shared per working directory, so ending one run could end the helper of another concurrent run. [#1119](https://github.com/foolzzz/looper/pull/1119) holds assistant text per attempt and gives each run a private `TMPDIR`. It closes #1083.

**Breaking changes:** No. No API or schema change; other runtimes are unchanged.

**How to verify:** Check the installed version. Run a Cursor task: its activity shows each assistant message once, including after a retry. While it runs, a directory named `looper-cur-` plus 12 hex characters exists under `/tmp` and is removed when the run ends.

**Contributors:** Maintainer @foolzzz authored [#1119](https://github.com/foolzzz/looper/pull/1119); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.91
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first (upgrade to v2.13.165 first) and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.90 upgrades directly. There is no database change.

## Behavior changes

- **One message once** (`looper/agents/runtimes/cursor_agent.py`). `CursorStream` buffers assistant text events and emits them when a tool call or the result commits them, in transcript order with the tool events. A `retry/starting` event drops the uncommitted text, so a retried message appears once. The report logic is unchanged.
- **Private `TMPDIR` per run.** Native and TTADK Cursor runs (`run_command`) get `TMPDIR=/tmp/looper-cur-<12 hex of the run directory hash>`, mode 0700, created before launch and removed after the run (`after_run`). The short path keeps Cursor's `worker-server` socket under the 104-byte limit and separates concurrent runs in one working directory. The retry of a run reuses the same directory.
- **Per-run input directory.** Worker and Reviewer launches copy the cached inputs into a fresh directory with a random 64-hex name, so identical prompts have separate execution state. Idle run directories are now cleaned on every launch, including a cache hit.
- **Manager and Planner turns** (`ResidentCursor`) use a private `TMPDIR` derived from the session directory, kept across turns; `reclaim_sessions` (`looper/agents/read_only_copies.py`) removes it with the session directory.
- **Unchanged:** other runtimes, the API, the schema, the report and token handling.
- **Documentation and tests.** `docs/architecture/agent-system.md` describes both changes; new `tests/test_cursor_activity_and_helper.py` and updated `tests/test_cursor_agent.py`, `tests/test_cursor_retry.py`, `tests/test_ttadk_cursor_agent.py`.
- **Model-visible changes:** No tool description, prompt text or tool output changes. The agent's shell commands inherit the new `TMPDIR`, so a Cursor agent that prints or uses `TMPDIR` sees the private path; files there are removed with the run.

### 行为变化与入口

- **每条消息只出现一次**（`looper/agents/runtimes/cursor_agent.py`）。`CursorStream` 先缓存助手文本事件，在工具调用或结果提交时与工具事件按转录顺序发出。`retry/starting` 事件丢弃未提交的文本，因此重试的消息只出现一次。报告逻辑不变。
- **每次运行的私有 `TMPDIR`。**原生和 TTADK 的 Cursor 运行得到 `TMPDIR=/tmp/looper-cur-<运行目录哈希的 12 位十六进制>`，权限 0700，启动前创建，运行结束后删除。短路径使 Cursor 的 `worker-server` 套接字不超过 104 字节限制，并隔离同一工作目录下的并发运行。同一运行的重试复用该目录。
- **每次运行独立的输入目录。**Worker 和 Reviewer 启动时把缓存的输入复制到随机 64 位十六进制名的新目录，因此相同提示词也有各自的执行状态。空闲运行目录现在每次启动都会清理，包括缓存命中时。
- **Manager 和 Planner 轮次**（`ResidentCursor`）使用由会话目录派生的私有 `TMPDIR`，跨轮次保留；`reclaim_sessions`（`looper/agents/read_only_copies.py`）在回收会话目录时一并删除。
- **不变：**其他运行时、API、数据库结构、报告和 token 处理。
- **文档与测试。**`docs/architecture/agent-system.md` 描述了两项改动；新增 `tests/test_cursor_activity_and_helper.py`，更新 `tests/test_cursor_agent.py`、`tests/test_cursor_retry.py`、`tests/test_ttadk_cursor_agent.py`。
- **面向模型的变化：**工具描述、提示文本和工具输出均不变。agent 的 shell 命令会继承新的 `TMPDIR`，因此 Cursor agent 打印或使用 `TMPDIR` 时会看到私有路径；其中的文件随运行一起删除。
