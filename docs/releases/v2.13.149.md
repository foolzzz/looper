# Looper v2.13.149

## Release Decision

**Who should upgrade:** Operators who run scenario Managers besides the default one and want to list tasks by Manager in the dashboard Tasks page, the v1 task page operation or the client task tool. Everyone else can stay on v2.13.148.

**What this release solves:** [#705](https://github.com/foolzzz/looper/pull/705) adds an optional Manager filter to the task lists. The dashboard Tasks page gets a Manager select, the v1 `tasks.page` operation accepts `manager_id`, and the client's task tool can list one Manager's tasks. Status counts and pagination follow the same filter.

**Breaking changes:** No. The filter is optional; without it every task list returns what it returned before.

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#705](https://github.com/foolzzz/looper/pull/705); no community contribution was included in this patch release.

```bash
looper --version   # looper 2.13.149
```

## Behavior changes

- **Task counts (#705):** `looper/db/tasks.py` `count_by_status` takes `manager_id` and counts only that Manager's tasks when given, matching the filter `list_tasks` already had.
- **Task page (#705):** `list_tasks_page` in `looper/agents/projects.py` passes `manager_id` to both the list and the counts, so the page, its counts and its cursor agree. A `manager_id` that names no Manager returns an empty result (`{"tasks": [], "more": False}` in compact form, otherwise empty `tasks`, `counts` and `next_before: null`) instead of querying.
- **v1 API (#705):** the `tasks.page` operation (`POST /api/v1/tasks/page`) in `looper/agents/v1_domains/task_views.py` accepts an optional `manager_id` (a nonempty string). Generated CLI arguments follow the schema.
- **Dashboard (#705):** `web/src/pages/tasks.tsx` adds a Manager select ("All Managers", "Default Manager", Manager names, disabled ones marked "(disabled)"), shown when a non-default Manager exists or a Manager filter is set. The filter and a `query` search live in the page URL (`manager`, `query`). A Manager that is unavailable, or a failed Manager load, shows a notice with "Remove Manager filter" while the filter stays applied. `web/src/lib/api.ts` `fetchTasks` sends `manager_id` and `query`.
- **List refresh (#705):** changing a filter now clears the list, counts and cursor before loading, drops responses for a filter the page has left (including A → B → A), ignores a refresh older than the latest, and `loadMore` does nothing while a load is running.
- **Tests (#705):** three new files (`tests/test_task_manager_filter_db.py`, `tests/test_api_v1_task_manager_filter.py`, `tests/test_task_manager_filter_browser.py`).
- **Model-visible changes:** yes, in the client-only copy of the task tool (`looper_tasks`, `looper/agents/ops/clients.py`). Its schema gains `manager_id` (a nonempty string), valid only for `action: list`; other actions refuse it with an invalid-argument error, and `null` is refused. A client-scoped call lists only its own Manager's tasks: a different `manager_id` returns an empty list. The Manager's own task tool, its prompts and its declarations are unchanged. The client's `list` now runs through `list_tasks_page`, resolving `project` by name (an unknown project is a not-found error).
- **Line counts:** the description reports 508 added test lines and 148 production lines (fixtures excluded); its file list shows 508 test lines and 148 production lines (web pages and `api.ts` included).

## Upgrade and rollback

Re-run `install.sh` once v2.13.149 is published. There is no schema change. Rolling back to v2.13.148 removes the Manager filter and the client tool's `manager_id`; nothing is stored.

**谁需要升级：**运行默认之外的场景 Manager，并希望在仪表盘任务页、v1 任务分页操作或客户端任务工具中按 Manager 列出任务的运维者。其他人可留在 v2.13.148。

**是否有破坏性变更：**否。过滤是可选的；不使用时各任务列表的返回与之前相同。

**如何验证：**运行 `looper --version` 核对版本为 2.13.149。

### 行为变化与入口

- **任务计数（#705）：**`count_by_status` 接受 `manager_id`，给定时只统计该 Manager 的任务，与 `list_tasks` 已有的过滤一致。
- **任务分页（#705）：**`list_tasks_page` 把 `manager_id` 同时传给列表和计数，使页面、计数与游标一致。`manager_id` 不对应任何 Manager 时直接返回空结果（紧凑形式为 `{"tasks": [], "more": False}`，否则为空的 `tasks`、`counts` 和 `next_before: null`）。
- **v1 API（#705）：**`tasks.page`（`POST /api/v1/tasks/page`）接受可选的 `manager_id`（非空字符串）。生成的 CLI 参数随 schema 变化。
- **仪表盘（#705）：**`tasks.tsx` 新增 Manager 选择（“All Managers”“Default Manager”、Manager 名称，停用的标注“(disabled)”），存在非默认 Manager 或已设置 Manager 过滤时显示。过滤条件和 `query` 搜索保存在页面 URL（`manager`、`query`）。Manager 不可用或加载失败时显示提示和“Remove Manager filter”，过滤仍然生效。`fetchTasks` 发送 `manager_id` 与 `query`。
- **列表刷新（#705）：**切换过滤时先清空列表、计数和游标再加载；丢弃已离开的过滤的响应（包括 A → B → A），忽略比最新一次更旧的刷新；加载进行中 `loadMore` 不再执行。
- **测试（#705）：**新增三个测试文件（DB、v1、浏览器）。
- **面向模型的变化：**有，位于仅客户端使用的任务工具副本（`looper_tasks`，`looper/agents/ops/clients.py`）。其 schema 新增 `manager_id`（非空字符串），仅对 `action: list` 有效；其他 action 带它会返回参数无效错误，`null` 也会被拒绝。限定范围的客户端调用只列出自己 Manager 的任务：传入其他 `manager_id` 返回空列表。Manager 自己的任务工具、提示词和声明不变。客户端的 `list` 现在经 `list_tasks_page` 执行，按名称解析 `project`（未知项目返回 not-found 错误）。
- **行数：**描述报告新增测试 508 行、生产代码 148 行（不含 fixture）；其文件列表显示测试 508 行、生产代码 148 行（含网页与 `api.ts`）。
