# Looper v2.14.13

This is the patch release v2.14.13. It ships the one change merged since v2.14.12: [#896](https://github.com/foolzzz/looper/pull/896), which records the model on a failed runner start and classifies a refused consult fork as `session_gone`.

## Release Decision

**Who should upgrade:** Operators who run a runner runtime (for example the DSH or Pi runner) and want failed runner starts to carry a model in their failure record, or who use room consults and want a refused fork reported as `session_gone`. Installations without a runner runtime see no change. It ships the one change merged since v2.14.12.

**What this release solves:** [#896](https://github.com/foolzzz/looper/pull/896) (fixes #892): a runner turn that failed before its prompt was accepted (timeout or refusal) emitted no init, so its failure record had no model; and a room consult whose fork was refused (`SESSION_NOT_FOUND` or `SESSION_OWNED`) was classified `contract` instead of `session_gone`.

**Breaking changes:** No. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#896](https://github.com/foolzzz/looper/pull/896); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.13
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.12 upgrades directly. This release changes no schema, stored data or setting.

## Behavior changes

Only runner-runtime turns and room consults change. CLI-path runs behave as in v2.14.12.

- **Init on a failed start:** in `looper/agents/runtimes/runner/session.py`, every early failure of a runner turn (saved session lost on resume, missing host tools or budget, budget not matching the bound provider/model, generation lost, prompt rejected, generation lost before prompting) now first emits an init event with the Descriptor's model, the current session id and `session_started: false`. Before, only the lost-resume case did. A result that settles before the prompt was accepted also gets an init first. Each turn emits at most one such init.
- **`session_started` on runner events:** every event of a runner turn now carries `session_started`, read from the bridge session entry, so it turns true only once the runner has accepted the prompt.
- **Consult classification:** in `looper/agents/consult.py`, a consult counts as started only when its init event names a session id. A refused fork (`SESSION_NOT_FOUND` or `SESSION_OWNED`) is therefore classified `session_gone`, not `contract`.
- **Session saving in the Manager and Planner:** `looper/agents/tiers/manager.py` and `looper/agents/tiers/planner.py` ignore the session id of an init whose `session_started` is `false`, so a failed start does not overwrite the saved session. The Planner now builds its resume brief for a plan under way before checking whether its process is already running, so the brief keeps being sent until the runtime accepts it, even when the session is already open. The pull request description does not mention this part; it is taken from the code.
- **Model-visible changes:** Yes, narrowly. When a plan under way has no saved session and the process is already running, the Planner's first turn now includes the resume brief where it previously did not. Otherwise prompts, tools and requests are unchanged; the new init events are internal records.

### 升级

桥接边界不变：早于 v2.13.165 的安装必须先升级到 v2.13.165 并启动一次（upgrade to v2.13.165 first 即先升级到 v2.13.165），步骤与回退见 v2.14.0 发布说明的升级一节。v2.14.0 至 v2.14.12 上的安装可直接升级。本版本不改 schema、已存数据或设置。

### 行为变化与入口

只有 runner 运行时的回合和房间 consult 发生变化。CLI 路径的运行与 v2.14.12 相同。

- **失败启动时的 init：**在 `looper/agents/runtimes/runner/session.py` 中，runner 回合的每种提前失败（恢复时保存的会话丢失、缺少宿主工具或预算、预算与绑定的 provider/model 不符、generation 丢失、prompt 被拒绝、prompting 前 generation 丢失）现在都会先发出 init 事件，带有 Descriptor 的模型、当前会话 id 和 `session_started: false`。此前只有恢复丢失一种情况会发。在 prompt 被接受之前就结算的 result 也会先得到 init。每个回合最多发一次。
- **runner 事件上的 `session_started`：**runner 回合的每个事件现在都带有取自 bridge 会话条目的 `session_started`，只有 runner 接受 prompt 之后才为 true。
- **consult 归类：**在 `looper/agents/consult.py` 中，只有 init 事件指明了会话 id，consult 才算已启动。被拒绝的分叉（`SESSION_NOT_FOUND` 或 `SESSION_OWNED`）因此归为 `session_gone`，而不是 `contract`。
- **Manager 与 Planner 的会话保存：**`looper/agents/tiers/manager.py` 和 `looper/agents/tiers/planner.py` 忽略 `session_started` 为 `false` 的 init 中的会话 id，失败的启动不会覆盖已保存的会话。Planner 现在在检查进程是否已在运行之前就为进行中的计划构建恢复简报，因此即使会话已打开，也会持续发送简报直到运行时接受。PR 描述没有提到这一部分，此处依据代码。
- **面向模型的变化：**有，范围很窄。当进行中的计划没有保存的会话且进程已在运行时，Planner 的第一个回合现在包含恢复简报，此前没有。其他提示、工具和请求不变；新的 init 事件是内部记录。
