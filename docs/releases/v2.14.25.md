# Looper v2.14.25

This is the patch release v2.14.25. It ships the one change merged since v2.14.24: [#926](https://github.com/foolzzz/looper/pull/926), which makes the installed Pi smoke cover the Pi runner default as well as the CLI opt-out. It changes no runtime code.

## Release Decision

**Who should upgrade:** Nobody needs this release for runtime behavior. It matters to maintainers and packagers who run the nightly installed tests (`tests/test_pi_smoke.py`). It ships the one change merged since v2.14.24.

**What this release solves:** [#926](https://github.com/foolzzz/looper/pull/926): since [#899](https://github.com/foolzzz/looper/pull/899) Pi runs on its SDK runner by default, but the installed Pi smoke pinned the CLI, so no nightly test drove the default runner path through an installed `looper serve` with all four roles. The smoke now takes `--pi-runtime cli|runner` and the installed fixture runs in both modes.

**Breaking changes:** No. No database schema, stored data, API or default changes. The supported upgrade path is unchanged (see Upgrading).

**How to verify:** Check the installed version.

**Contributors:** Maintainer @foolzzz authored [#926](https://github.com/foolzzz/looper/pull/926); no community contribution was included in this release.

```bash
looper --version   # looper 2.14.25
```

## Upgrading

The bridge boundary is unchanged: an installation older than v2.13.165 must upgrade to v2.13.165 first and be started once; see the Upgrading section of the v2.14.0 release for the steps and rollback. An installation on v2.14.0 to v2.14.24 upgrades directly. This release changes no database schema or stored data.

## Behavior changes

- **None at runtime.** The pull request touches only `examples/pi/isolated-smoke.py` (65 added, 48 removed lines) and `tests/test_pi_smoke.py` (10 added, 6 removed lines); no file under `looper/` changes.
- **Runner mode in the installed Pi smoke** (`examples/pi/isolated-smoke.py`): a new `--pi-runtime` option accepts `cli` (default) or `runner`. The value is written to the smoke's `server.toml` as `[runtimes] pi`. In runner mode the fake provider uses unprefixed platform tool names, and the smoke skips the checks that exist only on the CLI path: grant-file collection, the scoped-token and catalog assertions, the agent-process leader files and the post-cancel run-token check. Cancellation instead checks that the tool child is alive before the cancel and gone after it. In both modes the smoke asserts that each role's records share one session id, and it checks that `serve.log` contains "Pi runner pool enabled" exactly when the mode is `runner`.
- **Installed fixture runs in both modes** (`tests/test_pi_smoke.py`): the `installed_session_evidence` fixture is parametrized over `cli` and `runner`, `assert_role_evidence` receives the mode, and the explicit fake-provider test is parametrized over the default, `--pi-runtime cli` and `--pi-runtime runner`.
- **Model-visible changes:** None. No prompt, tool, schema or message changes.
